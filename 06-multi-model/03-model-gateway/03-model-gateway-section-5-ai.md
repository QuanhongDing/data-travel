## 5. 前沿演进（AI 时代）

### 5.1 先分清三类「前沿」

1. **机制变了**：接入层里某个部件换了工作原理（例如缓存从"精确匹配"变成"语义匹配"、路由从"静态规则"变成"按成本与质量动态选"）。**这类变化影响架构决策。**
2. **接口标准变了**：工具 / 资源 / 提示的接入转向协议化（规范与实现可按规范当前版本核验【公开】）；模型侧的结构化输出、流式事件也开始有跨厂商的约定形态。**这类变化影响"自研还是消费生态"。**
3. **只多了产品**：同一套能力换个包装。**只在选型表里体现。**

判别方法仍然是那一句：**"换一家厂商，这条结论还成立吗？"**——不成立的是第 3 类。

### 5.2 判据与分级

沿用三条 L1 判据：**① 已 GA 且有正式文档 / 发布条目**；**② 有第三方（非厂商）公开的生产案例**；**③ 接口稳定、可预期**。

| 演进方向 | 级别 | 机制变了什么 | 判据落点（可否自行核验） |
| --- | --- | --- | --- |
| 统一接入层的归一化 | **L2** | 从"每个应用各自适配"变成"一层归一化 + 配置化路由" | ① 成立（开源网关与云厂商接入层都有正式文档条目）；② **核不到**（第三方非厂商的生产细节极少公开）；③ 成立（配置接口稳定） |
| 工具 / 资源 / 提示协议化 | **L2** | 工具接入从平台私有格式变成跨平台协议 | ① 成立（规范与实现公开，Anthropic 2024 年公开【公开】）；② **核不到**；③ 部分成立（规范仍在演进） |
| 语义缓存 | **L2** | 缓存键从"请求原文"变成"语义向量 + 条件" | ① 成立（多家接入层的正式功能条目）；② **核不到**（公开的正确性数据几乎都来自建设方）；③ 部分成立（判定阈值各家不同） |
| 成本感知路由 | **L3** | 路由从"静态规则"变成"按预算与质量动态选" | ① 只有产品功能与演示；② 核不到；③ 不成立（质量估计依赖各自评测集，无法跨组织比较） |
| 模型降级链 | **L2** | 从"单端点"变成"多档位有序退让" | ① 成立（接入层与平台产品都有此功能）；② 核不到；③ 成立 |
| 能力矩阵自动探测 | **L3** | 从"按文档维护"变成"自动探测模型能力" | ① 只有自研脚本与演示；② 核不到；③ 不成立（探测方法与判定标准无通行做法） |
| 多模态输入的归一 | **L2** | 图片 / 文件在请求中的表达从各家私有变成约定形态 | ① 成立（各厂商文档均有条目）；② 核不到；③ 部分成立（引用方式仍有差异） |

**本节没有一行达到 L1**——卡点同样在 ②：**接入层的生产细节（归一化边界、缓存正确性、路由质量）几乎都由建设方自述**。因此这一层的成熟度应按"机制可验证、生产未被第三方验证"理解：你可以核验它的**接口形态**，但无法核验它的**效果**（效果取决于你自己的评测集与流量分布）。

### 5.3 演进方向逐条拆解（核心节）

#### 5.3.1 归一化：换的是"适配代码的位置"，不是模型能力

**机制**：适配代码从"每个应用各存一份"上收到"一层里的一份"。

**对架构决策的影响**：**换模型不改代码**从一句愿望变成可验证的事实；随之而来的是"归一化层成为必须长期维护的对象"——厂商接口演进在季度尺度上可预期发生，**这是一笔持续成本，不是一次性投入**。

**边界**：归一化只能覆盖"约定俗成"的字段；厂商私有参数仍然需要透传通道——**判据**是"必归字段清单 + 透传白名单"两份文档是否都在，缺任一份，接入层迟早变成瓶颈。

#### 5.3.2 协议化：集成成本从平台转移到协议层

**机制**：工具 / 资源 / 提示按协议描述，第三方工具一次实现、多处可用。

**对架构决策的影响**：接入层的重心从"支持多少工具"转向"治理做得多严"（权限、配额、审计、幂等）——**价值重心的迁移**，与 [Ch5 §02 §5.3.2](../../05-agent-platform/02-agent-platform-architecture/02-agent-platform-architecture-section-5-ai.md) 的判断同源。

**边界**：协议不替代治理；资源还要按租户做可见性裁剪，提示只允许引用已发布版本。

#### 5.3.3 语义缓存：收益明显，但必须带条件

**机制**：把缓存键从"请求原文"换成"语义表示 + 条件"，让相近问题复用答案。

**对架构决策的影响**：缓存从"工程优化"变成"必须与任务类型绑定的策略"——**带数值或时间条件的任务必须禁用**，否则错误会静默传播（§3.5 的反模式）。

**边界**：语义缓存的公开数字几乎都来自建设方自述；正确性只能靠你自己的抽检（**可执行的动作**：每周抽 20 条命中记录，人工核对是否"同义"）。

#### 5.3.4 成本感知路由：为什么停在 L3

**机制**：按预算与质量动态选端点。**卡点在"质量"没有可比较的口径**：质量估计依赖各组织自己的评测集，跨组织不可比；因此"动态路由"目前仍属自证有效的范畴。

**给读者的动作**：先把**静态档位 + 评测集**做扎实（这是可验证的），再谈动态。

#### 5.3.5 能力矩阵自动探测：为什么停在 L3

**机制**：靠调用探测模型能力（是否能工具调用、是否支持并行、上下文长度等），替代人工维护矩阵。**卡点**：探测方法（探什么、怎么判成功）没有通行做法，且厂商可能把"半支持"表现为"有时成功"。

**给读者的动作**：矩阵**按文档维护 + 抽检验证**（CI 里跑少数几个关键能力探针），不要指望自动维护。

#### 5.3.6 多模态归一与降级链：两件"看起来新、其实是加固"的事

多模态归一（图片 / 文件在请求里的表达）是**归一化字段的扩充**，不是新机制；降级链是**韧性实现**，也不是新机制。把它们当"新方向"会低估工作量（两者都在细节里：引用方式、大小限制、降级后的质量标注）。

### 5.4 与本主题既有栈的接口在哪

| 既有栈 | 接口 | 谁改 |
| --- | --- | --- |
| Agent 平台（[Ch5 §02](../../05-agent-platform/02-agent-platform-architecture/02-agent-platform-architecture.md)） | 平台把模型调用交给网关；平台传租户与版本标签；配额在出口统一扣 | 平台传标签；网关回传用量与 `degraded` |
| 数据资产与检索（[Ch4](../../04-data-assetization/README.md)） | RAG 的生成侧走网关；检索缓存与语义缓存分开管 | 网关只负责生成侧计量 |
| AI 治理（[Ch8](../../08-ai-governance/01-ai-data-governance/01-ai-data-governance.md)） | 出网策略与分级保密对齐；内容策略拒绝的语义要进错误分类 | 网关按租户分级实现出网判定 |
| 成本与可观测（[Ch11](../../11-cross-cutting/README.md)） | 计量流水进成本口径；Trace 的模型调用段由网关产生 | 网关输出统一的 span 字段 |
| 高可用（[Ch12](../../12-architecture/README.md)） | 网关多副本与容量规划；端点故障演练 | 网关侧做熔断与半开 |

### 5.5 被过度宣传的部分

1. **"一个网关解决所有模型治理"**：网关解决归一化、计量、降级；**不解决"谁能调哪个工具"**（那在平台出口）。
2. **"语义缓存能省一半成本"**：省多少取决于重复率与任务类型；**公开的百分比几乎都来自建设方自述**，且未计入错误复用的代价。
3. **"动态路由自动省钱"**：没有评测集就没有质量口径，所谓"自动"只会退化成"按单价排序"。

### 5.6 未来 3–5 年：可证伪的预测

| 预测 | 被证伪的信号 |
| --- | --- |
| 归一化会成为接入层的标准职责，而不是某个产品的卖点 | 两年后主流应用仍各自维护厂商适配代码，且没有统一接口 |
| 工具协议化会与接入层合流（工具与模型调用共用一套出口与计量） | 两年后工具调用仍在平台侧独立计量，与模型计量两套账 |
| 语义缓存会收敛为"按任务类型开关"的形态，而不是全局默认 | 主流产品仍把语义缓存做成全局开关且无禁用清单 |
| 成本归因的粒度会成为接入层采购的硬指标 | 采购仍只看"单 token 单价"，不问能否按租户 / 会话归因 |

**这四条全部是【经验】档**：它们是对机制与采购行为的判断，无具名出处、无推导链——**请按"可被证伪"使用，而不是当结论**。

### 5.7 给架构师的行动建议

1. **今年就该做**：能力矩阵 + 凭证托管 + 计量记账点（不依赖任何前沿判断）。
2. **可以试点**：语义缓存（先在解释类任务上开，带禁用清单与每周抽检）；降级链（每跳带质量损失估计与标注）。
3. **先别投**：成本感知动态路由与能力自动探测——等出现可比较的质量口径与通行探测方法。
4. **无论哪条**：把"计量口径与厂商账单的差异"作为接入层的第一条 KPI（它同时是成本、治理与采购谈判的共同语言）。

### 5.8 小结

> 本节小结：AI 时代对接入层的改变**只有一条是机制性的**——**归一化的位置从"应用内"上收到"一层里"**（其余方向：协议化、语义缓存、降级链、多模态归一都是在这条之上的接口与加固）。接入层没有一行达到 L1，卡点全在"第三方非厂商生产案例"；因此请按"**接口可核验、效果不可核验**"来理解它——效果必须用你自己的评测集与流量分布去量。**给读者的动作**：先把不依赖前沿判断的三件事（能力矩阵、凭证托管、计量记账点）做完，再谈缓存与动态路由。

> 💡 **思考锚点**：把你的模型调用按"任务类型"分一次组，标出哪些任务带数值或时间条件、哪些是解释性问答。然后回答：如果今天给解释性问答开语义缓存，你打算用什么动作来发现"错误复用"？答不出这个动作，就说明缓存还不该开——你打算先建抽检流程，还是先只做精确缓存？
