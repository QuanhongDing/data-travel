## 5. 前沿演进（AI 时代）

### 5.1 先分清三类「前沿」

趋势清单的根本问题是**没有时间维度**。同一个清单里，「平台产品已经上线、有对外文档与版本化行为」的能力，和「只有一篇论文提出、还没有任何产品把它做成能力项」的机制，被并列成八个方向。读者据此做架构假设时，两种方向的失败方式完全不同：前者最多是接口会变，后者可能根本不存在。

第二个问题是「记忆」这个词在三个层次上被混用。它可以是**产品功能**（跨会话记住偏好）、**存储机制**（写路径与读路径怎么落地）、**算法研究**（重要性衰减、自我编辑）。三者可规划性差一个量级：产品功能的成熟度写在厂商的发布说明里；存储机制写在开源仓库与 schema 里；算法研究写在论文里，而论文里的原型与产品里的实现经常不是一回事。本节要评估的方向里，只有前两类能被核验。

第三个问题是没有反方观点。清单里不会出现「这条方向今天不值得投」，于是「多模态记忆」「记忆联邦」这类还停在研究阶段的条目，会和「向量库 + 顶 k 检索」这类早就有成熟工程做法的条目排在同一个列表里。

本节用三级划分，三条判据必须可核验：

- **L1 生产可用**：三条全中才算。① 已 GA 且有正式 release note（或版本化发布的规范与文档）；② 有**第三方（非厂商）公开的生产案例**；③ 接口稳定、可预期（写路径与读路径的语义不随版本翻烧饼）。
- **L2 可试点**：①③ 大体满足、② 不满足；或能力可用而判定标准尚未形成共识。可以做 PoC，不要做核心依赖。
- **L3 观望**：仅路线图、论文、厂商演示或预览特性。记录即可，不要在架构里为它预留假设。

**判据声明（只对 ① 生效）**：本主题对 L1 的判据做如下修正——**① 的核验入口放宽为「正式 release note，或版本化发布的规范与文档（开源仓库里的写操作定义、产品的官方文档）」**；理由是记忆这一族还没有跨厂商的产品标准，能被第三方直接定位的版本化材料主要就是这两类，而本节要评估的写路径与读路径语义本来也不写在功能 release note 里（那些只覆盖「跨会话记忆」这类开关）。修正只改 ① 的入口、不改它的强度，② 与 ③ 一字未动。

判据 ② 在本主题尤其难过，原因值得先说清：**记忆领域几乎全部公开材料都是建设方自述**。产品的对外文档由厂商写，案例由厂商发布，开源项目的能力说明由项目自己维护。「第三方（非厂商）公开生产案例」意味着一个既不卖这套东西、也不靠它立论的团队，公开描述了自己在生产里的用法与失败。本节的口径是：**② 只有「满足」与「降为 L2」两种命运**——不能改成「有公开生产记录」，不能靠「本节只评估写路径」缩小适用范围来绕过，也不存在「准 L1」、「L1 的边界案例」这类说法。

另有一条评级规则，全节通用：**按机制分族，一族一行；族的级别取族内最弱子项**。这不是放宽判据，而是读者做规划时的实际含义——族里只要有一个子项不能依赖，这一族的架构就不能整体依赖。族内每个子方向的名字都列在「方向」列里，5.2 逐族拆解，两处级别与判据必须一致。

| 演进方向（族内子方向） | 级别 | 判据 | 现在该做什么 |
| --- | :---: | --- | --- |
| **写路径**：自动记忆提取 / 记忆冲突解决 / Self-Edit Memory / 记忆 + 本体建模的融合（主谓由谁定义） | L2 | ① 满足：Mem0 开源仓库与其写操作定义、Zep 官方文档可核验；② 不满足：公开案例皆建设方自述；③ 不满足：写动作的命名与语义各家不一（ADD / UPDATE / DELETE 只是一种约定） | 只对低风险偏好类事实开写；每条带 source 与 confidence，读时降权 |
| **读路径**：记忆 + 文档双索引 / 混合检索路由 / 记忆驱动的 RAG / Memory-Augmented Generation / 分页与分层（MemGPT、Letta）/ 知识图谱记忆（GraphRAG 记忆、Cognee 路线）/ 记忆 + 本体建模的融合（实体同一性）/ 记忆与上下文缓存融合（边界项） | L2 | ① 满足：向量检索与图谱存储各有可核验的公开实现与文档；② 不满足；③ 大体满足于检索接口，但「何时换页、何时查记忆」由模型自主决定，无契约 | 记忆与文档放同一检索通道但分命名空间；路由先靠规则兜底，再让模型参与 |
| **保留策略**：记忆重要性评分 / 时间衰减 / 主动遗忘 / 自适应记忆压缩 | L3 | ① 不满足：只有实现说明，无跨版本稳定语义；② 不满足；③ 不满足：衰减参数与重要性权重无公开可比的评估口径 | 只做上界：保留期上限 + 可删除接口；不假设衰减能自动分出好坏 |
| **共享与模态**：跨 Agent 共享记忆 / 记忆联邦 / 记忆即服务（所有权上提的产品形态）/ 多模态记忆（图像、语音、视频） | L3 | ① 不满足：跨 Agent 共享与记忆联邦只有研究性描述与路线图，记忆即服务的公开文档也不含跨 Agent 语义；② 不满足；③ 不满足 | 记录；不要在架构里假设跨 Agent 的记忆一致 |

**本节没有一行达到 L1。** 四行里最高的两行（写路径、读路径）都卡在判据 ② 上：拿不出第三方（非厂商）的生产案例。两者的差别在 ③——**读路径**是「③ 大体满足、② 缺失」，它的 ①③ 大体干净（开源仓库与产品文档可查、检索接口形态已基本固定），缺的是「何时换页、何时查记忆」的契约；**写路径**则 ③ 也不满足（写动作的命名与语义各家不一，ADD / UPDATE / DELETE 只是一种约定，不是标准），即卡在 ②③ 两条上。真正的缺口是「谁在生产里用了、错了多少、怎么回滚」这类材料。而**记忆还有一个 RAG 没有的困难：它的效果没有公开可比的度量口径**。检索有命中率，记忆没有——一条记忆被读到了不等于它有用（可能这轮本来不需要它），没被读到也不等于它没用。没有度量，第三方就无法证明自己的用法可复制，采购方也无法判断它值不值得排进路线图。

给读者的核验动作——拿到任何一条方向，按顺序问三句：

1. 它的正式 release note 或版本化文档能不能找到？找不到 → L3。
2. 厂商或项目方之外的证据能不能找到？找不到 → L2。
3. 写路径与读路径的语义明年会不会变？会变 → 至多 L2。

第 3 句在本主题特别容易失手：**同一个词在不同实现里指的不是同一件事**。Mem0 的 ADD / UPDATE / DELETE 是写路径动作，MemGPT 的换页是上下文预算动作，而「时间衰减」在不同实现里有的绑在事实的写入与比对阶段、有的只参与检索排序——三者在宣传语里都可能被叫作「记忆管理」。判定方法是查该实现的 schema 与接口，看它落在写路径、读路径还是排序权重上，而不是看功能列表。具体到 Zep，按 5.1 落点表给出的核验方式，去官方文档里看时间与衰减落在「写路径比对」还是「读路径排序」上——本节不对它下断言。

三个常见误判，排路线图时最容易踩：

- **把「有记忆功能」误当成「有可编程的记忆存储」**：能不能让程序写入、读取、按条目删除，是三个不同的问题；只提供「开启 / 关闭记忆」「清除全部」的产品，不构成可依赖的存储接口。
- **把「记得多」误当成「表现好」**：长期使用后，检索空间里的噪声随写入量上升，读命中的那几条是否相关才是决定项。
- **把「能跨会话」误当成「能跨 Agent」**：单 Agent 的会话连续性编排一下就有，跨 Agent 的一致性是另一件事（5.2.4 的 L3）。

### 5.2 演进方向逐条拆解（核心节）

四族按「谁决定记忆的内容」排序：写路径决定什么被记下来，读路径决定什么被送进上下文窗口，保留策略决定什么被删掉，共享与模态决定记忆能跨多远。四族的级别不同，但失效模式是同一个：**记忆的写入通道没有复核者，而读路径默认它是真的**。

#### 5.2.1 写路径：自动记忆提取、冲突解决与 Self-Edit Memory

- **旧做法与它的卡点**：要么把对话原文切块入向量库（§3.2.2 的 Vector RAG 记忆），要么让人手写「要记什么」的规则。前者是纯追加：体积与噪声随使用时长上升，且无法定位删除单条事实（要删就得重建整个集合）；后者写不全——人对自己的偏好也说不清，更写不成规则。真正难的不是「存下来」，而是「同一件事有两个说法时，以哪个为准」。
- **AI 改变了什么机制**：把「什么值得记」和「新值是否取代旧值」从人写规则换成一次模型判断：抽取事实 → 与已有记忆比对 → 执行 ADD / UPDATE / DELETE（无需变更时不动作），并把冲突解决从读路径（靠模型分辨新旧）挪到写路径（任一时刻每个主谓只有一条当前值）。Self-Edit Memory 是同一机制的第二段：让模型回过头来复检已写入的条目并修正。
- **由此得到的**：因为写路径做的是「抽取 + 比对 + 更新」而不是纯追加，**所以**读的时候不需要模型自己分辨新旧，同一个问题在不同轮次会得到同一个答案——这是跨会话一致性的来源；**又因为**条目变成结构化的（主谓宾 + 置信度 + 来源），**所以**「用户改地址」这类冲突可以在写入这一刻收敛，而不是留给下一次检索去猜。
- **由此付出的**：准确性被整体压在抽取器身上——错的事实一旦落库，就获得与用户亲述同等的权重，而读路径不区分二者；去重与冲突解决的阈值要长期调参，且没有可比的公开评测能证明调对了；原文若丢弃则失去可复盘性，若另存则回到体积问题；Self-Edit 把修正也交给模型，等于让同一个判断源既产生错误又判定错误。这一类代价可以浓缩成一句话：**写路径是故障发生地，读路径是故障暴露地**。
- **证据与来源**：【公开】提取式与更新式写路径的公开实现与文档（Mem0 开源项目及其论文，arXiv 2504.19413，2025 年 4 月提交；Zep 的时序知识图谱论文与官方文档，2025；arXiv 编号前四位即提交年月，可自证时间——注意与「项目开源时间」区分，Mem0 项目 2024 年即开源，论文晚于开源）；写路径的公开失败率与回滚机制：无公开可核验来源。
- **成熟度**：**L2**（与 5.1 表「写路径」行一致：① 满足、② 不满足、③ 不满足）。本条覆盖的事是同一族的三段：自动记忆提取、记忆冲突解决、Self-Edit Memory，外加 5.1 表里归到写路径一侧的「记忆 + 本体建模的融合」（主谓由谁定义）。

写路径的设计只有三个待定项，而它们决定后续全部代价：

```text
写路径要把三件事定下来（定不下来，读路径就得替它猜）
   ① 抽取粒度   一问一事实 / 一轮一事实 / 一轮多事实
                粒度越细，检索越准；越粗，上下文越全
   ② 冲突判定   新值无条件覆盖 / 比 confidence / 比时间戳 / 送人工复核
                覆盖 ⇒ 简单但会丢正确信息；送复核 ⇒ 准但引入人力路径
   ③ 原文留否   只留事实（省空间、丢复盘）/ 事实 + 原文引用（贵、可复盘）

判定方法：翻一次生产里的错误记忆，看能不能回答「它从哪句对话来、谁写的、怎么删」
   三个都答不出 ⇒ 你现在只有记忆功能，没有记忆存储
```

- **失效条件**：当用户的语言习惯里充满反事实与假设（「如果我下周出差，帮我订靠窗的座位」）时，抽取器会把假设写成事实，而写路径没有任何机制能识别出来。此时要补的不是更聪明的抽取，而是「来源类型」这一列——把 `user_msg` / `inferred` / `external` 分开，并让读路径按来源降权，而不是让不同来源的条目在检索里同权竞争。
- **自验方法**：任取一条正在生效的记忆，试着回答三件事——它由哪句原文产生、写入时是新值还是更新、删掉它要动几处存储（条目表、向量索引、派生摘要）。三件事都答得出，写路径才算建起来了；答不出其中任何一件，说明你目前拥有的是「记忆」这个概念，而不是一套可运维的写路径。

#### 5.2.2 读路径：上下文预算的分配（分页、分层、双索引、混合路由）

- **旧做法与它的卡点**：把历史全塞进上下文窗口，或纯顶 k 相似度检索。全量塞入受窗口硬上限约束，且成本随 token 线性上升；纯相似度检索在「用户这次问的和上次问的不是一回事」时会把无关记忆一起召回，挤掉真正有用的 token——**上下文预算是零和的**，调进来的每一条都在挤掉别的。
- **AI 改变了什么机制**：把「哪些内容进入上下文」从固定截断（最近 N 轮、顶 k）变成一次由模型参与的调度判断。MemGPT 与 Letta 走的是分页路线：把上下文窗口当物理内存、外部存储当虚拟内存，由模型通过函数调用决定换页（主文件 §2.1 的「记忆分页 Core / Archived」）；混合检索路由走的是判定「这次该查知识库还是查用户记忆」；Memory-Augmented Generation 把记忆与检索结果并列为生成器的输入。
- **由此得到的**：因为进入上下文的内容从「按位置截断」变成「按需调度」，**所以**同一个窗口预算能覆盖更长的历史——这是「无限上下文」这类宣传语背后真实的机制；**又因为**记忆与文档被分成两个命名空间（记忆是关于这个人，文档是关于这件事），**所以**「用户问过 X 所以相关文档是 Y」这种以人为条件的检索才成立，而这也是知识图谱记忆（实体 + 关系 + 时间）被引入的原因：多跳问题（同一个项目里的人最近在问什么）靠相似度给不出答案。
- **由此付出的**：调度本身要花 token 与一次模型调用，每次问答多一轮判断，成本与延迟都上升；**调度错误比检索错误更贵**——该调进来的没调进来，表现与「没有记忆」完全一样，而且不可观测（用户只会觉得 Agent 又忘了，日志里看不出是一次漏召还是一条本就不该存在的记忆）；「何时换页」由模型自主决定意味着没有稳定契约，升级版本就可能改变行为。另有一条容易混淆的边界：**上下文缓存（prompt cache）优化的是同一段前缀的重复计算成本，不承担业务连续性**——把记忆做成缓存命中率优化，会在缓存失效时表现为整体失忆。
- **证据与来源**：【公开】分页与分层记忆的公开描述（MemGPT，arXiv 2312.08194，2023 年 12 月提交）；【公开】图谱与向量混合检索的公开实现（Cognee 的官方文档与《Cognee: Knowledge Graph Memory》一文，2024–2025，可按题名检索核验其当前版本与年份；与 [§3.2.5 知识图谱记忆](01-long-term-memory-section-3-sec3.md) 是同一机制的不同视角）；检索路由与 MAG 的生产效果：无公开可核验来源。
- **成熟度**：**L2**（与 5.1 表「读路径」行一致：① 满足、② 不满足、③ 大体满足于检索接口，「何时换页、何时查记忆」无契约）。本条覆盖：记忆 + 文档双索引、混合检索路由、记忆驱动的 RAG、Memory-Augmented Generation、分页与分层、知识图谱记忆、记忆 + 本体建模的融合（实体同一性一侧）、记忆与上下文缓存融合（边界项）。

读路径要自建的部分比想象中少，但**每一条都要能回答「没调进来时会发生什么」**：

| 读路径的决策 | 可核验的现有件 | 必须自建的部分 |
| --- | --- | --- |
| 记忆与文档怎么分家 | 向量库的多集合 / 多租户命名空间 | 分家规则谁定、跨集合去重怎么做 |
| 这次该查哪里 | 无标准件 | 路由规则与兜底（规则优先于模型，模型不可用时退回关键字） |
| 分页与分层怎么切 | 无标准件 | 分层的边界（什么进 Core、什么留 Archived）与换页触发条件 |
| 漏召怎么发现 | 无标准件 | 一个可观测信号：用户重复交代同一件事的次数 |

- **失效条件**：当上下文窗口本身足够大（长窗口模型）时，调度带来的收益下降而成本照付——每轮多一次判断、多一轮延迟。此时正确的做法是退回「全量注入 + 去重排序」这类简单策略，把预算花在提高召回精度上，而不是继续加调度层。判据是：你的记忆总量是否真的超过了窗口能容纳的量，而不是模型宣传的窗口有多大。
- **自验方法**：构造一个「必须用到三个月前某条记忆」的问题，看它能不能被召回并出现在上下文里；再构造一个「与历史无关」的问题，看有没有无关记忆被召回。前一个测漏召，后一个测噪声——**两者必须一起测**，因为把顶 k 调大能改善前者、恶化后者，只测一头的调参会把问题推到另一边。

#### 5.2.3 保留策略：重要性评分、时间衰减、主动遗忘与压缩

- **旧做法与它的卡点**：无差别保留，或按时间先进先出。无差别保留让检索空间随使用时长线性膨胀、精度随噪声下降；先进先出则把「一年前确认过的过敏史」和「上周随口说的口味」同等对待——两者的价值与时间的关系正好相反。
- **AI 改变了什么机制**：把「该留多久」从时间排序换成一次模型打分的价值估计（重要性 f: E → [0,1]），再叠加时间衰减（recency(e) = exp(-λ·Δt)）与访问计数这类隐式反馈；主动遗忘与自适应压缩是同一个函数的另一端——低于阈值的条目被建议删除，或压缩成更粗的粒度。
- **由此得到的**：因为保留决策不再由「什么时候写入的」决定，**所以**长期记忆的存储增长可以不完全跟随使用时长，这是这一族唯一的硬收益，也是它被反复宣传的原因。一次性说清单位口径（按 1 MB = 10⁶ B、1 TB = 10⁶ MB 的十进制口径）：【推算】一个用户平均每天产生的候选事实按 **20–30 条**估【经验】，本账取下限 20 条；每条事实文本 100 token 上下【经验】，按 1024 维 float32 向量计，每条 embedding = 1024 × 4 B = 4 KB；一个用户一年 ≈ 20 × 365 ≈ 7,300 条 ≈ 7,300 × 4 KB ≈ 29 MB（仅向量，不含原文与索引）；10 万活跃用户 ≈ 29 MB × 10⁵ ≈ 2.9 TB。换成上限 30 条同理可复算：30 × 365 ≈ 10,950 条 ≈ 44 MB / 用户 / 年，10 万用户约 4.4 TB。**链路是纯乘法，读者可复算**——结论是长期记忆的存储不是零成本项，它随用户数线性增长，这才是保留策略存在的理由。
- **由此付出的**：评分没有可比口径——重要性的定义在各实现里不同，也没有公开的评测能证明「被删掉的确实是不重要的」；**删除是不可逆的**，判错的代价是永久丢失，而检索失败只是这一次回答变差，两者的风险等级不同。更关键的一条边界：合规删除（GDPR、个保法下的删除请求，见主文件 §1.2 的可遗忘诉求）是义务——用户要求就必须删，不能由分数决定；所以**主动遗忘不能替代删除接口，只能叠加在它之上**。
- **证据与来源**：【公开】把遗忘曲线引入记忆保留策略的公开论文（MemoryBank 路线，2023，可按题名自行检索核验收录会议与年份）；【公开】时序事实与时间衰减的公开实现（Zep，2025）；衰减参数与重要性权重的公开可比评估：无公开可核验来源。
- **成熟度**：**L3**（与 5.1 表「保留策略」行一致）。① 只有实现说明、② 不满足、③ 不满足。本条覆盖：记忆重要性评分、时间衰减、主动遗忘、自适应记忆压缩。

保留策略只有四个可调旋钮，而**每个旋钮的两侧都有代价**——这就是它至今停在 L3 的原因：

| 旋钮 | 调大的一侧 | 调小的一侧 | 可核验的现有件 |
| --- | --- | --- | --- |
| 重要性阈值 θ | 噪声留下，检索精度随使用时长下降 | 丢掉低频但关键的事实（过敏史、禁用项） | 无标准件，须自建抽查机制 |
| 衰减系数 λ | 近期偏好主导，长期事实被压到检索末尾 | 历史与当下同权，衰减形同没有 | 无标准件；λ 没有可比基准 |
| 压缩粒度 | 细节丢失，事后无法复盘当时说了什么 | 体积降不下来，成本不改善 | 无标准件；可核验的只有压缩后能否追回原文 |
| 保留期上限 | 存储与合规风险同时上升 | 合规上更安全，业务上可能丢掉争议证据 | 存储策略与法规要求本身可核验 |

```text
两类删除必须分开走（把它们合并是最常见的错误）
  合规删除（用户 / 监管要求）
     入口：用户行使删除权
     范围：条目 + 向量 + 派生摘要（日志中的内容是否要删，以法规对「个人数据」的定义为准）
     时限：由法规与对外承诺决定；必须可核验、可举证
     判据：不依赖任何模型判断
  自动遗忘（成本与精度治理）
     入口：重要性 × 衰减低于阈值，或长期未被访问
     范围：条目与其索引
     时限：可调、可回滚（先软删，再物理清理）
     判据：模型判断 + 阈值；允许出错，出错只影响回答质量
  → 两者合并的后果：自动遗忘的阈值一旦调错，会连带删掉本应受合规保护的记忆，
     而这笔删除无法举证「是模型判的」——举证责任在你，不在模型
```

**失效条件与自验方法**：当业务本身要求「永不遗忘」（审计、医疗记录、争议留证）时，衰减函数一个都不该开；此时该做的是分层——把这类记忆放进不允许过期的类别，而不是调 λ。自验方法是随机抽 20 条被自动删掉的记忆【经验】，逐条回答「如果它还在，本周的哪次对话会用到」：答不出任何一条，说明阈值过松；能答出多条，说明删除策略正在替你丢业务信息。

#### 5.2.4 共享与模态：跨 Agent 共享记忆、记忆联邦、记忆即服务与多模态记忆

- **旧做法与它的卡点**：每个 Agent 实例各持一份用户记忆。多 Agent 协作时同一用户的事实被写入 N 份，更新后出现 N 个版本；换成另一套 Agent 框架就得重建记忆；跨组织场景（供应商的 Agent 与客户的 Agent 协作）根本没有共享通道。
- **AI 改变了什么机制**：把记忆的所有权从「Agent 实例」提到「用户 / 组织」一级，记忆变成一个独立的服务，Agent 通过接口读写它（这也是「记忆即服务」这个产品形态成立的前提）。多模态记忆则是把载体从文本扩到图像、语音、视频或其摘要。
- **由此得到的**：因为记忆与 Agent 实例解耦，**所以**换框架不必重建记忆，多个 Agent 能读同一份关于这个用户的事实；**又因为**载体扩到图像与语音，**所以**「上次我们说的那个」这类指代不再只能靠文本描述。
- **由此付出的**：写入者变多之后，冲突解决从「同一主谓的新旧替换」上升为「多方对同一事实的不同说法」，而 5.2.1 的写路径机制只管新旧、不管权威排序——谁的说法更可信，需要业务规则（客服记录优先于用户随口一说，还是反过来）；共享范围一旦跨组织，隐私与合规的边界不是技术问题：**加密保护的是传输与存储的内容，不保护「谁有权让对方的 Agent 记住我」**——授权、存储地、用户向谁主张删除权，都要在合同与法律层面先定。多模态还有一层工程代价：向量空间不统一（图像与文本各自编码），跨模态检索要么先转文本、要么维护两套索引与一个对齐层。
- **证据与来源**：跨 Agent 共享与记忆联邦目前可核到的公开材料是研究性描述与产品路线图；多模态记忆可核到的是演示与预览；三者的公开生产记录均无公开可核验来源。
- **成熟度**：**L3**（与 5.1 表「共享与模态」行一致）。① 不满足、② 不满足、③ 不满足。本条覆盖：跨 Agent 共享记忆、记忆联邦、记忆即服务（所有权上提的产品形态）、多模态记忆。

把「共享」按范围摊开，可以看到每一档要新增的前置条件——**它们的数量是递增的，而技术只是其中一项**：

| 共享范围 | 谁写得进、谁读得到 | 必须先在业务侧定下来的事 | 现状 |
| --- | --- | --- | --- |
| 单个 Agent（含跨会话） | 一个 Agent 读写 | 无（本节主要评估对象） | L2 |
| 同一用户的多个 Agent | 多写多读，按 user_id 隔离 | 同一事实多方写入时，谁的说法优先 | L3 |
| 同一组织的多个用户 | 团队记忆，按 org_id 隔离 | 谁能看见谁的记忆（含上下级与离职场景） | L3 |
| 跨组织 | 双向读写 | 授权、存储地、用户向谁主张删除权 | L3，研究阶段 |

- **失效条件**：当共享范围跨过「同一用户」这一档，5.2.1 的冲突解决机制就不再适用——它比较的是新旧，不比较来源的权威。此时唯一的稳妥做法是把共享范围**先钉在最小可用档**（同一用户的多个 Agent），并对跨档的读写做显式授权，而不是靠「都放在一个库里，谁都能查」。

### 5.3 与本主题既有栈的接口在哪

记忆不是新的一层数据，它是**挂在既有存储之上的一套读写协议**。下表写清谁调用谁、数据以什么形态穿过边界、失败时谁负责。

| 结合点 | 接口形态 | 谁负责失败 | 现状 |
| --- | --- | --- | --- |
| 写路径 ↔ [§2.5.1 事实三元组模型](01-long-term-memory.md) | 抽取器输出结构化条目（主谓宾 + confidence + source）写入 memory 表；抽取失败时写什么 | 抽取器（写路径）负责精度；读路径不设二次校验 | L2（5.2.1）；schema 可复用，判定标准需自建 |
| 读路径 ↔ [§2.5.4 物理存储选择](01-long-term-memory.md) | query → 顶 k 候选 → 重排 → 注入上下文；记忆与文档走不同集合 | 调度方（检索路由）负责漏召；漏召无法归因到单个组件 | L2（5.2.2）；检索接口成熟，路由需自建 |
| 保留策略 ↔ 合规删除接口（主文件 §1.2 的可遗忘诉求） | 用户行使删除权 → 物理删除条目及其向量与派生摘要 | 合规侧负责；模型评分不参与这条路径 | 义务性接口，必须自建；与 L3 的自动遗忘分开 |
| 记忆层 ↔ 可审计（主文件 §1.2：每笔记忆的写入 / 读取 / 修改留日志） | 写路径与读路径都发事件到同一份日志 | 平台侧；审计缺失时「为什么 Agent 这么说」不可复盘 | L2 能力、缺标准件：关系库与向量库都能记，记忆级事件模型未标准化 |
| 跨会话边界 ↔ [§3.2.1 Session Memory](01-long-term-memory-section-3-sec3.md) | 会话内消息序列（键为 session_id）→ 抽取器 → 跨会话条目（键为 user_id） | 边界处最容易丢：会话结束到抽取完成之间有一个窗口 | L2；窗口内崩溃即丢一批记忆，需要落盘队列 |
| 记忆 ↔ 模型上下文 | 记忆只是上下文的一路来源，与其他上下文竞争预算 | 编排方；把记忆当唯一事实源会让漏召变成错误答案 | 需自建优先级规则（5.2.2 的零和预算） |

这张表里只有两行是「有现成件可用」：一是记忆条目落了关系库 schema，二是检索接口。其余四行**都要自建或自测**，而且失败几乎都落在平台团队之外——写路径的精度归业务方（他们定义什么算事实），删除义务归合规方，会话边界的窗口归应用方。把它写进接口表的用处不是分工好看，而是**事故发生时不必现场决定谁负责**；如果这张表在你们那里画不出来，说明记忆还没有人认领。

**判定这张表有没有被用起来**：每个季度核两个数——这一季用户重复交代同一件事的次数（读路径漏召），以及被删除请求覆盖的条目是否真的从向量与摘要里都消失了（合规路径）。两个数一个都不看，记忆就还停留在功能层。

**这张表还有一个反向用法**：它的每一行都能对应到主文件 §2.4 里的一组边界（长期记忆 vs RAG / Session Storage / 微调 / 知识图谱 / 上下文缓存）。表里画得出来的行，边界已经清楚；画不出来的行，通常是因为两条边的职责还没分开——最常见的是把记忆当成「缓存的升级版」：缓存的键是前缀，记忆的键是用户；前者失效只影响成本，后者失效影响业务连续性。**先分清键是什么，再决定它归谁管**，这是本节所有接口判断里成本最低的一条。

### 5.4 公开进展与文献

- **论文**【公开】：MemGPT（arXiv 2312.08194，2023 年 12 月提交）把上下文窗口类比为操作系统物理内存，由模型通过函数调用换页；Mem0 的论文（arXiv 2504.19413，2025 年 4 月提交）把写路径定义为抽取 + 比对 + ADD / UPDATE / DELETE；Zep 团队的《Zep: A Temporal Knowledge Graph Architecture》（2025，可按题名检索核验）把时间做成事实的一等属性并叠加衰减；MemoryBank（2023）把遗忘曲线引入保留策略；A-Mem（2025）提出 Agent 自编辑记忆。**引用纪律**：arXiv 编号前四位是提交年月，可自证时间；论文里的原型与产品里的实现是两件事，不要把论文结论当作产品能力。
- **官方 release note / 产品文档（判据 ① 的核验入口）**【公开】：Mem0 开源仓库的写操作定义与 Letta 的记忆分层说明（以各自官方文档当前版本为准）；Anthropic 与 OpenAI 在 2025 年先后公开的跨会话记忆能力——核这类能力时看的是**有没有可编程的写入 / 按条目删除接口与版本化行为说明**，而不是有没有「记住我」这个开关。
- **第三方（非厂商）公开生产案例**：无公开可核验来源。这是本节没有任何方向被评为 L1 的直接原因（判据 ②）。
- **引用方式的调整**：本节列出的条目中，给过 arXiv 编号的有四条——MemGPT（2312.08194）、Mem0（2504.19413）、MemoryBank（2405.18470）、A-Mem（2502.12110）。本节只保留前两条的编号，因为编号前四位（提交年月）与题名、时间三者可以互相印证，读者能自证；MemoryBank 与 A-Mem 两条只留题名、年份与核心思想，不再锚定编号——编号一旦记错就会指向另一篇论文，写错比省略更贵。判定方法是按题名检索，并核对论文页上的提交年月是否与你预期的一致。另需说明一处年份差异：**MemoryBank 的年份本节写 2023，另一口径为 2024**，差别在取论文的提交年还是取会议收录年，读者可用题名核对论文页的提交年月与其收录会议，两者都能自证。
- **值得注意的空白**：公开材料里能查到「用了哪种架构」，查不到「用了多久、错了多少、怎么回滚」。这不是因为它们不重要，而是因为记忆的失败通常是静默的（回答了、但基于错的事实），不容易被写成一份可引用的报告。它同时意味着：**这类判断只能自己测**。

**引用纪律**：本节涉及的项目迭代快，最容易出错的三类引用是——

| 引用类型 | 常见错误 | 核验方式 |
| --- | --- | --- |
| 「某项目在某年发表论文」 | 把开源时间当论文时间，或用二手解读代替原文 | 查 arXiv 编号前四位（即提交年月）或对应会议论文集 |
| 「某产品支持某记忆能力」 | 把演示里出现过的能力当成已发布能力 | 查官方文档里该能力的标记（GA / 预览）与适用版本 |
| 「某方案让效果提升 X%」 | 把厂商自述数字当作可比较结论 | 看评测集、指标定义，以及有没有第三方复现 |

### 5.5 被过度宣传的部分

**「记忆让 Agent 越用越懂你」**

- *实际是什么*：把「记得更多」当成「表现更好」。决定体感的是读命中的那几条是否恰好相关，而写入量上升会同时抬高检索空间里的噪声。
- *为什么会这样*：提取式记忆的写入通道无人复核（5.2.1 的代价），而读路径默认条目为真；同时「提取错误率」没有公开口径能算（5.2.3）。
- *什么时候它才会成真*：写路径带可回滚版本与来源引用，且出现被多方复用的记忆评测口径时。附带一个至今没有稳定判据的边界：什么该写进记忆、什么该留在上下文里（记忆与推理的边界）。

**「记忆即服务（Memory-as-a-Service）即插即用」**

- *实际是什么*：外部服务能替你存条目、做相似检索、按用户隔离，但不能替你决定「哪些实体是同一个」。
- *为什么会这样*：记忆的语义正确性依赖业务本体——同一个人、同一个订单、同一个项目在各种说法下的同一性，这层只有业务方有。
- *什么时候它才会成真*：跨系统的实体标识可交换（同一个 ID 用在多处），或服务方接受由业务方提供的本体。

**「记忆联邦（跨组织共享）已经可以规划」**

- *实际是什么*：跨组织的记忆共享先是授权问题，再是加密问题。同态加密一类技术解决的是「算的时候看不见明文」，不解决「谁有权让对方的 Agent 记住我的用户」。
- *为什么会这样*：存储地、跨境传输、用户向谁主张删除权，属于法律与合同层面，不能用密码学消除；而记忆一旦跨境，「删除」是否真的覆盖了所有副本，需要可审计的证明。
- *什么时候它才会成真*：出现明确的跨境记忆委托标准与责任划分。同时留在这个清单上的开放问题还有：跨语种记忆如何归并、多 Agent 的记忆一致性、能不能从记忆做反事实推理、医疗与金融场景下记忆保留的法律边界。

这三条有一个共同结构：它们都把「机制已经就位」说成「能力已经就位」。记忆的写路径与读路径确实已经就位（这也是它们能评 L2 的原因），但「就位」指的是**实现存在**，不是**效果可证**。所以判断它们何时成真的办法是同一个——看公开材料里有没有出现可核验的判断依据（来源字段、评测口径、授权模型），而不是看产品页上有没有多一个带「Memory」的名字。

### 5.6 未来 3–5 年：可证伪的预测

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| 记忆写入变成可审计、可回滚的写路径（每条能回答「从哪句对话来、谁写的、怎么删」） | 主流平台文档里出现记忆条目的来源字段、批量撤销接口，审计日志成为默认开启项 | 三年后平台文档仍只有「开启 / 关闭记忆」与「清除全部记忆」两个动作 |
| 记忆出现可比的公开评估口径（至少能算写入精度与读命中） | 出现被多方引用的公开评测集与排行榜，厂商不再只报自述数字 | 评估仍停留在各家自述，或只有借通用问答基准的间接指标 |
| 多模态记忆长期停在「原文外挂 + 文本摘要」，不进入统一向量空间 | 图像与语音记忆的检索入口仍是先转文本再检索 | 出现跨模态统一检索在长周期用户记忆上的公开生产案例，且比转文本更准 |
| 记忆与上下文缓存长期分层，不合并 | 基础设施层继续分别演进：缓存按 token 计费优化、记忆按条目治理与授权 | 出现把两者合并计价与合并语义的主流产品，且缓存冷启动不影响记忆可用性 |

四条预测都能靠**公开文档**证实或证伪，不需要内部数据：

- 第 1 条看平台文档里的接口清单，一到两年见分晓。
- 第 2 条看有没有出现第三方维护的评测口径，两到三年。
- 第 3 条看多模态检索的入口形态（先转文本，还是直接跨模态），两到三年。
- 第 4 条看基础设施产品的计费与语义划分，三到五年。

最值得先盯的是第 1 条：它是本节唯一一条**不依赖任何新模型发布**就能观察到的信号——写路径的可审计性由接口设计决定，不由模型能力决定；它也是把记忆从「功能」变成「可依赖资产」的那一步。

第 2 条的影响面最大：一个可比的评测口径一旦出现，本节四行里最高两行的评级就可能同时改变（② 会第一次有材料可用）。反过来说，如果你在三年内都没看到这样的口径出现，那么「长期记忆已经成熟」这个判断就始终缺少公开依据，架构上应当继续按「可以有、不能依赖」来对待。

### 5.7 给架构师的行动建议

| 你的处境 | 现在就该做 | 一年内观察 | 明确不要做 |
| --- | --- | --- | --- |
| 客服 / 助手类 Agent，用户抱怨「每次都要重说」 | 先做会话内的一致性（[§3.2.1 Session Memory](01-long-term-memory-section-3-sec3.md) + TTL）与显式的「记住这条」入口，让用户主动写入 | 平台记忆接口是否出现可编程的按条目删除 | 不要让自动提取的记忆驱动对外承诺（退款、赔付、资格判定） |
| 个性化 / 内容 Agent，记忆是核心差异 | 把条目做成结构化事实（主谓宾 + confidence + source），冲突在写路径收敛（5.2.1） | 是否出现可比的记忆评测口径 | 不要把原文全量入库当记忆（体积与按条目删除都不可控） |
| 合规敏感（医疗 / 金融 / 教育） | 先建删除接口与保留期上限，让「用户要求删除」是一条最短路径 | 自动遗忘与合规删除的边界是否形成行业共识 | 不要等自动遗忘成熟再建删除——评分不能替代义务 |
| 多 Agent 协作平台 | 每个 Agent 读同一份记忆服务，但按 Agent 划命名空间与写权限 | 跨 Agent 一致性是否出现标准 | 不要在架构里假设记忆天然一致（跨 Agent 共享是 L3） |
| 想采购记忆服务 | 先定义验收口径：写入精度、删除时延、隔离粒度 | 是否出现第三方生产案例 | 不要按「支持的记忆类型数量」选型——类型多不等于语义对 |

「明确不要做」那一列的共用逻辑只有一句：**本节真正变了的是「什么值得记」的判断方式，没变的是「判断错了谁来负责」**。所以预算该投在写路径的可回滚、删除路径的可验证、读路径的可观测三件确定性工程上；在这三件之前，任何「记忆联邦」「多模态记忆」的规划都不会带来可度量的收益。

如果只能排一个顺序，按这条走：

1. **先定写路径的边界**：哪些事实允许自动写入、哪些必须用户确认、原文留不留（5.2.1 的三个待定项）。这一步不需要新采购。
2. **再把删除路径打通**：条目、向量、派生摘要三处一起删，并留下可核验的记录。它是合规义务，越晚做越贵。
3. **然后给读路径加一个可观测信号**：用户重复交代同一件事的次数，用来发现漏召。
4. **最后才谈共享与多模态**：它们会改变所有权与授权边界，回滚成本高于前三步。

最后一条提醒：本节所有「现在就能做」的动作都不需要新的模型能力——条目 schema、删除路径、漏召观测，全是工程与流程。这也解释了本节为什么没有 L1：真正已经就位的那部分（检索与存储）不需要被宣传，而需要被宣传的那部分（自动提取、联邦、多模态），还没有成熟到能被第三方核验。两者之间的落差，就是本节四行评级全部停在 L2 与 L3 的原因。

### 5.8 小结

> 本节小结：长期记忆里 AI 真正改变的只有一条机制——**把「什么值得记、什么时候该调进来、什么时候该删」从人写规则换成一次模型判断**，因此记忆第一次可以不靠人工登记而持续增长；它没有改变的是**判断的正确性来源**：写路径默认无人复核，读路径默认条目为真，而记忆的价值至今没有公开可比的度量口径。所以本节没有 L1 方向：能排进路线图的是写路径可回滚、删除可验证、漏召可观测这三件工程，而不是「记忆联邦」或「越用越懂你」。
