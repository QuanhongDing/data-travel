# 影响力建设（Influence）

> **核心定位**：技术好是基础，但 P7+ 需要「行业影响力」—— 这决定了 P8 / 数据架构师能不能上。

## 影响力的 4 个层级

### Level 1：团队内影响力（默认）

- 你的同事在技术评审时会问「X 怎么想？」
- 你的代码被同事主动 reference
- 你的 bug 修复被同事感谢

### Level 2：公司内影响力（P6+）

- 跨团队 / 跨 BU 找你咨询
- 公司内部技术大会分享
- 公司内部技术博客作者
- 公司技术雷达 / 选型目录被引用

### Level 3：行业影响力（P7+）

- 公开技术大会分享（KubeCon / QCon / ArchSummit / Strata / OSC / Data + AI Summit）
- 公开技术博客（公司博客 / 个人 blog / Medium / 知乎 / InfoQ）
- 开源项目贡献（Apache / CNCF / Linux Foundation）
- 行业标准 / 白皮书 参与（信通院 / DAMA / 全国信标委）

### Level 4：跨行业影响力（P8 / 数据架构师）

- 跨行业被参考（如「Netflix 的 Iceberg 迁移」「Uber 的 Hudi 起源」被反复引用）
- 在 SIGMOD / VLDB / OSDI 等顶级会议发表论文
- 在 Apache 顶级项目做 Committer / Maintainer / PMC
- 被其他公司 / 同行主动来咨询

## 影响力建设的 4 个路径

### 路径 1：技术博客

**为什么重要**：
- 沉淀思考 / 提升写作能力
- 建立个人品牌 / 行业认知
- 被动流量（搜索引擎 / 公众号 / 知乎）

**写什么**：
- **你做过的项目**：背景 / 挑战 / 方案 / 结果 / 反思
- **你读过的论文 / 书**：笔记 / 启发 / 应用
- **你思考的问题**：技术决策 / 选型 / 架构 / 行业

**写哪里**：
- 公司技术博客（最优先）
- 个人 blog（Medium / 知乎 / 公众号）
- 行业平台（InfoQ / 掘金 / 思否）

**频率**：
- 起步：每月 1 篇
- 进阶：每 2 周 1 篇
- 高产：每周 1 篇

**质量**：
- 有具体案例（不要纯理论）
- 有数据 / 数字（不要纯形容词）
- 有反思（不要纯成功）
- 2500-5000 字（不是越长越好）

### 路径 2：公开技术大会

**为什么重要**：
- 建立行业人脉 / 影响力
- 倒逼自己总结 / 思考
- 给团队 / 公司带来外部曝光

**去哪讲**：
- **国内**：QCon / ArchSummit / OSC / 阿里云栖 / GMTC / DataFun
- **国外**：KubeCon / Strata / Spark + AI Summit / Re:Invent
- **行业**：DAMA 中国 / 信通院 / 各地技术沙龙

**讲什么**：
- 你的技术实践（必须有真实案例）
- 你的技术思考（不要纯介绍）
- 你的踩坑经验（更受欢迎）

**怎么准备**：
- 选题：先从你的项目 / blog 中提炼
- 摘要（CFP）：150-200 字，先投摘要
- 完整讲稿：30-45 分钟讲 + 10-15 分钟 Q&A
- 试讲：至少 3 次（团队 / 朋友 / 自己录音）

### 路径 3：开源贡献

**为什么重要**：
- 直接影响全球数百万开发者
- 在简历上是硬通货
- 与世界级工程师直接协作

**怎么开始**：
- **第 1 步**：选 1 个你用的开源项目（Apache Iceberg / Flink / Milvus / ...）
- **第 2 步**：从「修 typo / 改 doc」开始
- **第 3 步**：提 1 个小 PR（修 bug / 加 feature）
- **第 4 步**：提 1 个有规模的 PR（解决 issue / 设计 feature）
- **第 5 步**：成为 Committer（半年到 1 年）
- **第 6 步**：成为 Maintainer（1-3 年）

**国内大厂的开源**：
- 阿里：Apache Dubbo / RocketMQ / Druid / Iceberg (Paimon) / 各种
- 字节：Apache KubeRay / DOP 各种
- 美团 / 京东：各种
- 华为：openEuler / MindSpore / 各种

### 路径 4：专利 / 论文

**为什么重要**：
- 公司需要（申请高新 / 评奖 / 资质）
- 个人晋升加分项
- 长期技术沉淀

**专利怎么写**：
- 选有真实应用的（不要纯理论）
- 重点在「问题 + 方案 + 效果」
- 找公司专利部门 / 律师协助

**论文怎么发**：
- 工业界论文：SIGMOD Industrial / VLDB Industrial / OSDI / NSDI
- 国内期刊：计算机学报 / 软件学报
- 难度：需要「足够新的贡献 + 实验数据 + 写作」
- 适合：博士 / 研究员 / 大厂资深工程师

## 影响力的 5 个常见误区

### 误区 1：只做技术，不写不分享

- 写不出 → 写 100 字就发 → 越写越快
- 写太多 → 写 2500 字就好 → 重点在「让人看懂」

### 误区 2：追热点，没有积累

- 追热点没积累 → 在 1 个领域深耕 3-5 年 → 才有积累

### 误区 3：只输出，不输入

- 只分享不学习 → 1 年后没新东西可写
- 每周 5 小时学习（读书 / 听课 / 跟人交流）

### 误区 4：包装过度，失去信任

- 包装 → 一旦被识破 → 失去行业信任
- 真实 + 实用 = 长期口碑

### 误区 5：单打独斗

- 一个人写 1 篇 → 10 篇 10 年 = 没积累
- 团队一起写 → 1 年 30 篇 = 团队影响力

## 影响力建设的「3 年计划」

### Year 1：起步（每周 1 小时）

- 选 1 个领域深耕
- 每月 1 篇内部 / 公开 blog
- 参加 1-2 次公司内部技术大会

### Year 2：扩展（每周 2-3 小时）

- 每月 1-2 篇公开 blog
- 参加 1-2 次公司外部技术大会
- 1 个开源项目的活跃贡献者

### Year 3：深入（每周 3-5 小时）

- 每月 1-2 次公开技术大会
- 1 个开源项目 Committer / Maintainer
- 1-2 份专利 / 1 篇论文
- 行业标准 / 白皮书 参与
