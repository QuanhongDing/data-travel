# P7 → P8 路径（技术专家 → 资深架构师）

> **核心定位**：从「一个方向的技术专家」到「跨方向 + 跨团队的资深架构师」—— 这是 90% 的 P7 卡住 3-5 年上不去 P8 的核心原因。

## P7 → P8 的本质跃迁

不是「**多学 1-2 个技术**」（很多 P7 学了一堆技术但还是 P7）。

而是「**改变工作模式**」：
- P7 = **给别人交付**：你交付高质量的技术产出
- P8 = **让整个组织变得更好**：你交付的是「组织能力的提升」（平台 / 规范 / 体系 / 文化）

## 4 步成长路径

### Step 1：技术深度 → 技术广度（1-2 年）

**目标**：从「1 个技术方向」到「3-4 个技术方向都有深度」。

**做法**：
- 每季度学 1 个新技术方向（不是「会用」，而是「能用它落地 1-2 个项目」）
- 主动参与跨方向的技术评审 / ADR
- 主导 1-2 个跨方向项目（如「从离线到实时」跨数仓 / 实时 / OLAP 三个方向）

**证据**：
- 主导 1-2 个跨方向项目并成功交付
- 在公司内部分享过 3+ 个不同技术方向

### Step 2：项目负责人 → 平台 owner（1-2 年）

**目标**：从「项目交付」到「平台被多团队复用」。

**做法**：
- 主导 1 个内部平台（如指标平台 / 特征平台 / 湖仓平台）
- 推动 3+ 个团队 / BU 使用你的平台
- 投入 30% 时间做「平台易用性」（文档 / SDK / 监控 / SLA）

**证据**：
- 平台被 3+ 团队使用，月活 / 调用量稳步增长
- 有 1-2 个跨团队主动来对接 / 找你支持

### Step 3：技术输出 → 行业输出（1-2 年）

**目标**：从「公司内部」到「公司外部」—— 让你的方法论 / 工具影响行业。

**做法**：
- 在 Apache / CNCF / 公开技术大会分享
- 在 OSC / QCon / ArchSummit / KubeCon / ICDE 等会议演讲
- 写技术博客（公司博客 / Medium / 知乎 / InfoQ / 公众号）
- 申请专利 / 发表论文（SIGMOD / VLDB / OSDI / ICDE）
- 参与开源项目（提交 PR / 成为 Committer / Maintainer）

**证据**：
- 在公司外部有 1-2 个公开分享
- 内部 1-2 个项目被外部公司 / 同行引用

### Step 4：单团队 → 跨团队（持续）

**目标**：从「影响 1 个团队」到「影响 3-5 个团队 / 跨 BU」。

**做法**：
- 主动申请跨 BU 项目（如「全公司数据治理」「全公司 AI 平台」）
- 在跨 BU 技术委员会 / 架构委员会任职
- 推动跨 BU 共享规范（如数据分类分级 / SRE 规范 / 编码规范）

**证据**：
- 主导 1 个跨 BU 项目，被 3+ BU 使用
- 在跨 BU 委员会被认可为「架构权威」

## P7 → P8 失败的常见原因

- ❌ **继续死磕技术深度**：以为「再多学一点就能上 P8」
- ❌ **不愿意带人 / 带项目**：以为「我一个人也能做出 P8 的产出」
- ❌ **不愿意写文档 / 推动落地**：以为「好技术自然会有人用」
- ❌ **停留在公司内**：没有行业输出，错失「被外部认可」的机会
- ❌ **不主动争取跨团队项目**：永远只做本团队的事

## P7 → P8 成功的 3 个真实案例（国内大厂公开）

### 案例 1：阿里 P7 → P8 数据架构师
- 背景：某 BU 数据团队 P7
- 关键动作：主导「全 BU 数据中台 + 指标平台」项目，跨 5+ BU 使用
- 关键产出：被集团采纳作为参考架构；公开在阿里云栖大会分享
- 周期：2.5 年

### 案例 2：字节 2-2 → 3-1
- 背景：抖音数据团队资深工程师
- 关键动作：主导「实时数据通道」跨 BU 共享；3+ 业务线接入
- 关键产出：在公司内技术峰会分享；被外部公司 / 同行参考
- 周期：2-3 年

### 案例 3：美团 L8 → L9 资深架构师
- 背景：到店事业群数据团队负责人
- 关键动作：主导「全事业群数据治理 + 实时化」；培养 2-3 个 P7
- 关键产出：在 QCon / ArchSummit 公开分享；行业白皮书
- 周期：3 年

## 关键能力自评（每季度）

给自己打 4 项分（1-5）：

- [ ] **跨方向技术深度**：1-2 个新方向有项目落地
- [ ] **平台复用度**：被 3+ 团队使用
- [ ] **行业输出**：每年 1-2 次公开分享
- [ ] **跨团队影响**：主导 1 个跨 BU 项目

**4 项均 ≥ 4 → 准备好申请 P8 / 3-1**
