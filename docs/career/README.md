# 数据架构师成长路径

> 从 P7 到数据架构师的能力跃迁地图，以及如何规划你的 3-5 年成长路径。

## 为什么需要这个目录

> **技术能力有 S 型曲线，P7→P8 靠努力，P8→数据架构师靠"换跑道"**。

很多 P8 工程师努力 3-5 年仍然上不去数据架构师，核心原因不是技术不够深，而是**没有完成从"技术贡献者"到"团队领导者"的角色转换**。本目录帮助你：

1. 看清 P7→P8→数据架构师的**能力差**是什么
2. 规划你的**3-5 年成长路径**
3. 避开常见的**晋升陷阱**

## 数据架构师能力对照表

> 下表 P7 / P8 两列与 [01-competency-model.md](01-competency-model.md) 口径一致（团队规模一列同时与 [14-leadership/README.md](../14-leadership/README.md) 的画像表取齐），数据架构师列按 [03-p8-to-architect.md](03-p8-to-architect.md) 的目标口径。团队规模一列是**量级参考**，各家职级体系的带宽不同，不要拿它当硬门槛。

| 能力 | P7 | P8 | 数据架构师 |
| --- | --- | --- | --- |
| 技术深度 | 1 个技术域贯通 | 跨域 + 战略选型 | 跨领域 + 跨组织（推动技术演进） |
| 团队规模 | 独立贡献者 / 主导项目 | 带 3-10 人 / 团队带头人 | 带 20-50 人 / 跨团队协调 |
| 影响力半径 | 跨团队 | 跨 BU / 跨公司 | 跨组织 |
| 业务理解 | 参与业务讨论 | 推动业务决策 | 主导业务战略 |
| 决策半径 | 子系统 / 平台架构 | 企业级架构 | 战略决策 + 组织级规范 |
| 文化建设 | 主导实践 | 建立文化 | 主导跨团队 / 跨 BU 文化 |
| 业务沟通 | 与 PM 协商 | 与 VP 沟通 | 与 VP / CEO 沟通 |
| 风险管理 | 识别风险 | 缓解风险 | 主动管理风险 |
