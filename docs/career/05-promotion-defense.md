# 晋升答辩准备（Promotion Defense）

> **核心定位**：技术够硬不代表能晋升——答辩是**最被低估**的关卡。即使技术做得再好，答辩讲不好也会被刷下来。

## 4 个核心环节

1. **材料准备**（T-30 天）
2. **答辩稿写作**（T-14 天）
3. **内部预演**（T-7 天）
4. **现场答辩**（T-0）

## 通用 4 段答辩稿结构

### 1. 个人成长概览（2 分钟）

- 当前职级 + 入职时间
- 上一职级到现在的主要变化（业务域 / 技术深度 / 影响力）
- 本次晋升的核心论据（一句话）

### 2. 业务理解（5 分钟）

- 团队 / 业务定位
- 个人在团队的角色
- 业务的关键痛点（数字化举 1-2 个具体场景）

### 3. 核心贡献（15-20 分钟，按 2-3 个项目展开）

每个项目 5-7 分钟，按以下结构：
- **项目背景**（1 段）：业务为什么需要 / 挑战在哪
- **你的角色**（1 段）：架构师 / 负责人 / 骨干
- **关键决策**（2-3 段）：你做了什么具体决策，为什么
- **量化结果**（1 段）：数据 + 业务价值
- **沉淀与影响**（1 段）：是否被其他团队复用 / 行业引用

### 4. 软技能 + 成长（3-5 分钟）

- 跨团队推动 / 人才培养
- 行业发声（公开分享 / 专利 / 论文 / 开源）
- 未来 1-2 年规划

## 评委最常问的 10 类 Q&A

| # | 问题 | 应对策略 |
| --- | --- | --- |
| 1 | 「你做的工作里，**其他人不做**你能做的是什么？」 | 准备 1-2 个「只有你能 hold 住的」场景 |
| 2 | 「技术深度怎么体现？你做的和别人用开源有什么区别？」 | 准备 1 个**深度技术案例**（如自研 vs 开源对比） |
| 3 | 「你的贡献里，**最关键**的决策是什么？为什么？」 | 准备 1 个**关键决策点**（如选 A 不选 B 的依据） |
| 4 | 「如果让你**重做**一次，你怎么做？」 | 准备 1 个**真实反思**（不是客套） |
| 5 | 「你的工作对**业务**贡献是什么？」 | 准备 1-2 个**业务价值**数字（GMV / 时效 / 成本） |
| 6 | 「你**带人**了吗？带得怎么样？」 | 准备 1 个**真实带人案例**（招聘 / 培养 / 淘汰） |
| 7 | 「你**跨团队**的影响力？」 | 准备 1 个**跨团队项目**（被其他团队复用） |
| 8 | 「你**行业**上的发声？」 | 准备 1-2 个**公开输出**（blog / 演讲 / 专利 / 开源） |
| 9 | 「未来 1-2 年**规划**是什么？」 | 准备 1 个**业务-技术-团队**三维规划 |
| 10 | 「你的**短板**是什么？怎么改进？」 | 准备 1 个**真实短板**（不是套话） |

## 各职级答辩核心论据

### P5 → P6：高级工程师

- **核心论据**：独立完成 1-2 个完整模块 / 项目
- **必展示**：技术深度（能 hold 住一个技术方向）
- **量化**：项目交付 / 性能 / 代码量

### P6 → P7：技术专家

- **核心论据**：主导 1-2 个跨团队 / 跨 BU 项目
- **必展示**：技术决策能力 / 跨团队影响力
- **量化**：项目业务价值 / 团队产出 / 人才培养

### P7 → P8：高级技术专家 / 架构师

- **核心论据**：主导企业级平台 / 体系
- **必展示**：战略思维 / 行业视野 / 业务翻译
- **量化**：平台覆盖 / 行业引用 / 业务 GMV 贡献

### P8 → 数据架构师

- **核心论据**：主导业务战略 + 技术落地
- **必展示**：组织影响 / 行业发声 / 文化建设
- **量化**：跨 BU 覆盖 / 行业引用 / 团队规模

## 答辩的 7 大禁忌

- ❌ 念 PPT（评委立刻走神）
- ❌ 只讲技术不讲业务（评委大多是业务 / 管理者）
- ❌ 罗列项目不分主次（1 小时讲 10 个项目 vs 1 小时讲 2-3 个深度）
- ❌ 没有量化结果（全是形容词，没有数字）
- ❌ 把团队 / 同事的功劳归于自己
- ❌ 不承认短板（显得不诚实）
- ❌ 答辩时语速过快 / 念稿 / 紧张

## 推荐答辩准备流程

```
T-30 天  收集材料：3-5 个项目，每个项目的决策 / 量化 / 反思
T-14 天  写答辩稿（4 段结构 + Q&A 10 个问题）
T-7 天   内部预演 3 次（找同级别同事 / mentor 听）
T-3 天   修改答辩稿（基于预演反馈）
T-1 天   准备 1 份「答辩 Q&A 速查表」
T-0      现场答辩 30-60 分钟 + Q&A 15-30 分钟
```

## 评委心理：他们想听什么

- **听懂你做的事**：大多数评委的技术背景不如你
- **判断你的 level**：是不是达到了下一级的标准
- **判断你的潜力**：未来 1-2 年能做什么
- **看你的思维方式**：是否「像个 leader」

**最大禁忌**：让评委觉得「你讲得我都听不懂」或「你没做什么特别的事」

## 答辩的 5 个加分技巧

- **提前调研评委**：了解评委的职级 / 背景 / 关注点
- **第 1 句话抓眼球**：用「一句话总结」开场
- **故事化叙事**：用「故事」而不是「列表」
- **主动留互动点**：在每个项目结尾留 1-2 个「可追问的细节」
- **自信但不傲慢**：对自己的判断坚定，对未知诚实
