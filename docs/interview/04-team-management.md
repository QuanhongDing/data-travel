# 团队管理（Team Management）

> **核心定位**：怎么带 5-50 人的数据 / AI 团队 —— 招聘 / 培养 / 绩效 / 跨团队 —— P7+ 资深架构师与高级工程师的核心差异。

## 答题框架（场景 + 数字 + 反思）

1. **题目**：通常分两类
   - **场景题**：「你团队有人想离职怎么办？」「两个骨干冲突你怎么处理？」「如何给团队同学争取到更多 HC？」
   - **反思题**：「你做过的最难的团队决策」「你带过的最大团队」「你最骄傲的培养案例」
2. **考察点**：面试官在考「**真实场景 + 数字 + 反思**」三件套。
3. **参考答案框架**（**4 段结构**）：
   - **场景（1 段）**：简洁描述背景——团队规模 / 阶段 / 关键人物 / 关键挑战
   - **你做了什么（3-5 段）**：按时间线展开——先做什么后做什么，**给出 1-2 个关键决策点**
   - **数字（2 段）**：结果量化——人员留存率 / 项目交付率 / 团队产出 / 同学成长
   - **反思（1 段）**：如果再做一次你会怎么改——展现成长
4. **常见陷阱**：
   - ❌ 「以人为本」「信任团队」等正确但空话
   - ❌ 编造细节（面试官一追问就露馅）
   - ❌ 只讲成功不讲失败 / 反思
   - ❌ 把功劳归于自己，忽略团队
5. **追问预测**：
   - 「如果重做一次，你最大的改变是什么？」
   - 「你团队里最难管的人是什么样的？你怎么处理？」
   - 「你怎么判断一个人是 P6 还是 P7？」

## 关键数据：怎么谈「数字」

面试官最想听的**量化结果**：
- 团队规模：5 → 15 → 30 人的演变
- 关键人员成长：把 P5 同学 18 个月带成 P7
- 关键项目交付：3 个月内上线实时数仓，从 0 到 50 张表
- 团队稳定性：年留存率 90%+
- 团队产出：业务方 NPS / 项目交付率 / 跨团队评价

**避免**：「我做得很好」「大家都很努力」—— 这些是空话。

## 工业案例（推荐主动引用）

- **Netflix 自由与责任 + Keeper Test**—— P5 级别的面试官能力
- **Google Project Oxygen**—— 8 项行为面试 / 招聘画像
- **Amazon Bar Raiser**—— 跨团队面试官机制
- **阿里 P 序列 + 271 强制分布**—— 国内技术职级标准
- **字节职级体系 + 双月 OKR + 360**—— 国内最活跃的职级体系
- **美团 L6-L9**—— 大厂技术通道
- **Spotify Squad / Tribe / Chapter / Guild**—— 团队拓扑原型

## 进阶：怎么讲「失败」

**好回答**：「2023 年我做了一个错误的晋升推荐，把一个 P6 推到 P7，结果 6 个月后他明显撑不住。这次我学到：答辩辅导要看 6 个月后的表现，不是 PPT。」

**坏回答**：「我做得很好，没什么失败。」 —— 缺乏自我认知。
