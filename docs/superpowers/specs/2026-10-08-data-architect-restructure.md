## 1. 项目定位（重写）

- **名称**：`data-travel`
- **形态**：纯 Markdown 书籍型文章项目，无构建步骤，所有内容直接可读。
- **目标**：以「**AI 时代的数据架构师 / 智能体平台架构师**」为锚点，按画像能力展开——从数据科学、建模方法、数据基础设施，到 AI 智能体平台、多模型编排、AI 资产治理、数据智能产品的全景图。

## 2. 目标画像（核心约束）

以下画像从招聘截图（Agent 架构师（高级），扬州芯算智能科技，40-70K·15 薪）提炼，**作为每章必须对应回答的能力清单**：

### 核心职责（6 大模块）

1. **AI 智能体平台整体架构**：私有化部署、企业级 AI 基础设施 0→1、安全可控/可编排/自进化
2. **企业私有数据资产化与智能检索**：多源异构数据（文档/代码/报表/音视频）统一清洗、结构化、语义化编码；基于向量数据库构建高可用语义索引体系
3. **多模型编排与工具链调度**：多模型统一接入层、标准化工具调用框架、按需路由、灵活组合
4. **AI 资产沉淀与自进化系统**：全生命周期管理，使用-沉淀-复用-优化闭环
5. **行业情报智能体与精准分发**：7×24h 自动化情报采集/清洗/语义分类/AI 摘要/个性化推送
6. **AI 资产分级保密与防泄露体系**：黑盒化资产封装、细粒度权限管控、全链路操作审计、输出端防泄露

### 任职要求（8 大模块）

1. 本科以上、27-40 岁、**5 年以上**数据科学/算法/数据架构经验
2. 数据挖掘与机器学习（分类/聚类/回归/推荐），扎实特征工程、模型选型、效果评估能力，算法工程化落地经验
3. **精通数据建模**：数据仓库 + **知识图谱 + 本体建模 + 图数据推理**
4. **深刻理解数据全栈协同体系**：采集/集成、数据流转、样本库建设、评估、反馈
5. 数据智能类产品认知：智能标签、智能 BI、精细化运营、预测决策；能将模糊业务问题转化为量化指标
6. 极强的落地能力、创新精神、跨团队协同、结果导向
7. 可验证的过往业绩：大型数据算法类产品设计与落地
8. 国内外头部游戏/基金/数据智能产品/大型互联网企业工作经验

### 加分项（必备工具栈）

- 智能体框架：**LangChain、AutoGPT、OpenClaw** 二次开发、架构优化或核心贡献经验
- 行业 AI 智能体：企业级情报分析系统、**代码智能助手、自动化办公平台** 等
- 合规：国产化软硬件适配、**等保 2.0/3.0** 合规相关项目经验
- 工程能力：**Python/Go/Java + 微服务 + 分布式**、**TB 级大数据量**系统、高并发/高可用架构设计与性能优化
- 团队管理：**5 人以上**技术团队管理经验

## 5. 各章主题与重点

### 00 序章（`00-introduction/`）

- **核心问题**：AI 时代数据架构师的能力地图是什么？该如何按角色读这本书？
- **内容**：
  - 目标画像（6 大职责 + 8 大要求 + 加分项）
  - 4 能力域 + 4 横线的全景图
  - 难度梯度表（章级难度 + 推荐角色 + 前置章节）
  - 4 类读者阅读路径（智能体架构师 / 数据科学家 / 数据架构师 / 团队负责人）
  - 跨章术语表（Glossary，扩充 AI 相关术语）
- **特点**：总论 / 全景图，自身无技术子主题；为后续章节提供「能力地图」。

### Ch1 建模方法论（`01-modeling/`）

- **核心问题**：数据建模能力——从传统维度建模到知识图谱、本体建模、图数据推理
- **原理**：维度建模（Kimball）、Data Vault、Anchor Modeling、数仓分层（ODS/DWD/DWS/ADS）、OneData、OneID；**新增**：本体建模（Ontology）、知识图谱构建、图数据推理
- **架构决策**：ER vs 维度 vs Data Vault vs KG；OneData 落地路径；本体建模 vs 传统数据建模
- **实战**：用 Neo4j / NebulaGraph 搭本体建模；用 DataWorks / 阿里中台工具链建模
- **调优**：命名规范、版本管理、Owner 制度、模型评审；图谱质量与本体一致性
- **小结**：P7 会「建表」，P8 会「建模型」，**资深架构师会「建体系」**（数仓 + 本体 + 图谱 三合一）

### Ch2 数据科学与算法（`02-data-science/`）

- **核心问题**：算法能力——分类、聚类、回归、推荐四大类；特征工程、模型选型、效果评估
- **原理**：监督学习、无监督学习、强化学习；常见算法原理（LR / GBDT / XGBoost / DeepFM / DQN）
- **架构决策**：离线训练 vs 在线学习 vs 联邦学习；模型部署（在线服务 / 批处理 / 流式）
- **实战**：用 PyTorch / TensorFlow + MLflow 搭建推荐模型全流程；特征平台搭建
- **调优**：样本偏差、特征穿越、A/B 实验设计、效果评估指标（CTR / AUC / NDCG）
- **小结**：资深架构师要懂算法原理，但更要懂**算法工程化落地**与**业务问题抽象**

### Ch3 数据全栈基础设施（`03-data-stack/`）

- **核心问题**：数据全栈协同——采集/集成、数据流转、样本库建设、评估、反馈
- **原理**：CDC（Debezium / Flink CDC）、ETL（DataX / Airflow / DolphinScheduler）、数据湖（Iceberg / Hudi / Paimon）、数据流转（双向同步 / binlog）、样本库管理（Label Studio）、特征平台（Feast / Tecton）、反馈闭环（A/B 平台 / 实验平台）
- **架构决策**：离线 vs 实时 vs 流批一体；数仓分层 vs 数据湖 vs Lakehouse
- **实战**：用 Flink CDC + Iceberg + Airflow 搭建数据全链路；从采集到反馈的闭环
- **调优**：样本偏差、数据漂移、特征穿越、模型效果下降归因
- **小结**：数据架构师 不只让系统跑起来，还要让系统**「长期、可靠、可控」**地跑

### Ch4 企业级数据资产化与智能检索（`04-data-assetization/`）

- **核心问题**：把企业私有多源异构数据（文档/代码/报表/音视频）转化为可被 AI 检索的语义资产
- **原理**：数据清洗、结构化处理、语义化编码、向量化、向量索引、语义检索、混合检索（BM25 + 向量）、RAG 架构（检索-增强生成）
- **架构决策**：专有向量库（Milvus / Pinecone / Weaviate）vs AI 原生数据库（PostgreSQL + pgvector / DuckDB VSS）；RAG 架构（朴素 RAG / 高级 RAG / Agentic RAG）
- **实战**：用 Milvus + Embedding + RAG 搭建企业知识库；用 Pinecone + Claude 搭建语义检索
- **调优**：Embedding 选型（OpenAI text-embedding-3 / BGE / M3E）、Chunking 策略、Reranker、Recall@K
- **小结**：AI 时代数据架构师的核心能力——**让企业私有数据变成 AI 可消费的知识**

### Ch5 AI 智能体平台架构（`05-agent-platform/`）

- **核心问题**：企业级私有化 AI 智能体平台从 0 到 1 的整体架构
- **原理**：智能体架构（ReAct / Plan-Execute / Reflexion）、智能体框架（LangChain / AutoGPT / OpenClaw）、MCP 协议、智能体编排、工具调用（Function Calling / Tool Use）
- **架构决策**：单 Agent vs Multi-Agent；集中式编排 vs 去中心化协同；私有化部署 vs SaaS
- **实战**：用 LangChain + OpenAI 搭建企业级 Agent 平台；用 AutoGPT / OpenClaw 二次开发
- **调优**：Agent 可靠性、Prompt 工程、Token 成本、可观测性
- **小结**：资深架构师 要能把单 Agent 编排成可生产的企业级平台

### Ch6 多模型编排与工具调用（`06-multi-model/`）

- **核心问题**：统一接入多个大模型（OpenAI / Anthropic Claude / 国内大模型），实现按需路由与工具链调度
- **原理**：模型 API 抽象、模型能力评估、路由策略（成本 / 延迟 / 能力）；工具调用框架（Function Calling / JSON Schema / Tool Use）；Prompt 工程（系统提示、Few-shot、CoT）
- **架构决策**：自研 vs 接入 LangChain / LiteLLM；多模型路由策略；模型降级与限流
- **实战**：用 LiteLLM 统一接入 GPT-4 / Claude / 文心 / 通义；设计路由策略
- **调优**：Token 成本、API 限流、模型评估、Prompt 调优
- **小结**：资深架构师 要把「模型当成可调度资源」——像调度 Pod 一样调度 LLM

### Ch7 AI 资产沉淀与自进化（`07-agent-evolution/`）

- **核心问题**：AI 资产全生命周期管理——使用-沉淀-复用-优化闭环
- **原理**：会话资产沉淀、技能提取固化、组织级长期记忆、知识图谱自进化、A/B 实验平台、反馈学习（RLHF / RLAIF）
- **架构决策**：向量数据库 vs 图谱 vs KV 存储选型；沉淀策略（被动 vs 主动）；评估机制（人工 vs AI）
- **实战**：搭建会话资产平台；用 LlamaIndex 搭建企业级长期记忆系统
- **调优**：记忆压缩、上下文窗口管理、相关性评估
- **小结**：让 AI 越用越聪明——这是「自进化」的核心价值

### Ch8 AI 治理与安全（`08-ai-governance/`）

- **核心问题**：AI 资产分级保密、防泄露、合规
- **原理**：数据安全（脱敏 / 加密 / 分类分级）、权限管控（RBAC / ABAC）、审计日志、防泄露（DLP / 提示词注入防御）、合规（等保 2.0/3.0 / GDPR / 个保法）、国产化适配
- **架构决策**：自研 vs 采购合规组件；Prompt 注入防御方案；输出端脱敏
- **实战**：搭建 AI 资产分级保密系统；接入等保 2.0/3.0 合规流程
- **调优**：审计追溯、异常检测、应急处置
- **小结**：**资深架构师 必须守住底线**——AI 资产不能泄露

### Ch9 数据智能产品（`09-data-intelligence-product/`）

- **核心问题**：数据智能类产品的架构设计——智能标签、智能 BI、精细化运营、预测决策
- **原理**：智能标签（事实标签 / 模型标签 / 预测标签）、智能 BI（自然语言查询 NL2SQL / 自动洞察）、精细化运营（人群运营 / 触达策略）、预测决策（推荐 / 营销 / 风控）
- **架构决策**：标签系统（实时 vs 离线）；BI 系统（NL2SQL vs 传统）；决策系统（规则引擎 vs ML）
- **实战**：搭建智能标签平台；用 NL2SQL 搭建智能 BI
- **调优**：标签质量、查询优化、决策效果
- **小结**：让 AI 不只在后台——**变成业务可消费的产品**

### Ch10 行业智能体（`10-industry-agent/`）

- **核心问题**：垂直行业 AI 智能体的架构设计——行业情报智能体、代码智能助手、自动化办公平台
- **原理**：行业知识图谱、行业 Prompt 工程、行业评估体系、行业 Agent 协作（Multi-Agent）
- **架构决策**：通用 Agent vs 垂直 Agent；行业数据合规；行业效果评估
- **实战**：搭建行业情报智能体（金融/医疗/制造）；搭建代码智能助手（类似 Cursor / Copilot）；搭建自动化办公平台
- **调优**：行业准确性、效率、合规
- **小结**：把通用 AI 变成**懂行业的 AI**——这是行业智能体的价值

### Ch11 横切工程（`11-cross-cutting/`）

- **核心问题**：横切能力——数据质量、数据安全、成本、可观测、血缘
- **原理**：DQC（Data Quality Center）、数据脱敏、加密、审计、FinOps、可观测性（Metrics / Logs / Traces）、血缘采集
- **架构决策**：DQC 体系、SLA 体系、监控告警分级
- **实战**：搭建数据可观测性平台；GDPR / 个保法合规；成本优化 30-50%
- **调优**：数据漂移检测；质量告警；成本归因
- **小结**：**资深架构师 不只让系统跑起来，还要让系统「长期、可靠、可控」地跑**

### Ch12 架构与高可用（`12-architecture/`）

- **核心问题**：高并发、高可用、TB 级大数据量系统架构
- **原理**：微服务架构、分布式系统、CAP 理论、负载均衡、限流降级、熔断、单元化架构、CDC、双向同步、同城双活、两地三中心、RPO / RTO、混沌工程
- **架构决策**：单元化 vs 微服务；多活方案；压测方案
- **实战**：搭建 TB 级大数据量系统；混沌工程实战
- **调优**：性能工程、慢查询治理、灰度与回滚、容量规划
- **小结**：资深架构师 必须扛得住「老板最怕的事」——大促流量洪峰下的系统稳定性

### Ch13 决策与权衡（`13-decision/`）

- **核心问题**：在不确定的工程世界里，做出正确、可被全公司复用的架构决策
- **原理**：ADR（架构决策记录）、选型决策框架、FMEA、故障树分析、技术战略 3-5 年路线图
- **架构决策**：自研 vs 采购、伪自研陷阱、技术债管理
- **实战**：写 ADR、组织级技术决策流程
- **调优**：决策心理学（锚定效应、确认偏误、沉没成本、群体思维）
- **小结**：P8 能执行，资深架构师 能决策

### Ch14 团队管理与领导力（`14-leadership/`）

- **核心问题**：5 人以上技术团队管理、带人、做事、影响组织
- **原理**：人才画像（P5-P8 数据架构师）、结构化面试、绩效管理（KPI / OKR）、跨团队协作、向上管理、技术/管理双晋升通道
- **架构决策**：团队拓扑（Team Topologies）、远程团队管理
- **实战**：晋升答辩辅导；1:1、OJT、IDP；绩效面谈、末位淘汰、激励组合
- **调优**：团队文化建设、组织扩张节奏
- **小结**：资深架构师 不是「最会写代码的人」，而是「能让一群人写出好代码的人」

### Ch15 案例库（`15-case-studies/`）

- **核心问题**：从真实工业级 AI 智能体平台实践中学习
- **原理**：背景 / 挑战 / 架构演进 / 关键决策 / 踩坑 / 复用经验 的标准化案例结构
- **架构决策**：按行业组织案例——半导体 AI 智能体平台、高端制造 AI 智能体、企业服务 AI 智能体、金融/基金 AI 智能体、互联网/游戏 AI 智能体
- **实战**：阿里 AI 智能体平台、字节扣子、腾讯元宝、华为盘古、百度文心；以及国外 OpenAI / Anthropic / Databricks 的演进
- **调优**：失败案例（被废弃的 AI 项目、过度设计的智能体平台、失败的 RAG 项目）
- **小结**：资深架构师面试要的是「你研究过真实的工业级 AI 问题」

### 99 后记（`99-outro/`）

- **核心问题**：AI 智能体架构师正在向何处去？给准资深架构师的几句话
- **趋势**：MCP 协议标准化、Agent Marketplace、垂直行业 Agent、AI 安全合规、组织级 AI 转型
- **写给准资深架构师**：技术深度只是入场券；选对战场比埋头努力更重要；把每一次故障转化为组织能力；长期主义 vs 短期交付；写作是 资深架构师 的杠杆
