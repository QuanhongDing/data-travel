# 数据安全与合规落地（Data Security & Compliance）

> **一句话定位**：把"分级保护"从一句要求变成**可执行的机制**（脱敏 / 加密 / 权限 / 防泄露），再把机制变成**可举证的证据**（等保对照 / 国产化适配 / 合规评级）——前者决定 AI 系统能不能上线，后者决定它能不能**被审计通过**。

## 1. 概念与定位

### 1.1 是什么

**工业定义**：数据安全与合规落地，是**把"这一级数据该怎么保护"翻译成一组可执行的机制，并把机制的执行结果翻译成一组可举证的证据**的工作。它由两半构成，而这两半的**验收方式完全不同**：

- **机制半**（脱敏 / 加密 / 权限 / 防泄露）：验收方式是**技术验证**——用一次越权尝试、一次注入测试、一次连接审计来证明它生效（同 [Ch6 §03 §6.4](../../06-multi-model/03-model-gateway/03-model-gateway-section-6-sec6.md) 的"演练过拒绝比承诺不发送有力"）。
- **举证半**（等保对照 / 国产化清单 / 合规评级）：验收方式是**外部认可**——由测评机构、审计方或客户的安全团队判定。**它不看你做了什么，看你**能不能证明**你做了什么。

**工程定义**：在数据架构师手里，这一块是**四个动作的集合**：

1. **按级配机制**：分级（公开 / 内部 / 机密 / 绝密）产出之后，每一级要配什么脱敏、什么加密、什么权限粒度——**这一步是把"制度"变成"配置"**。
2. **把机制放在不可绕过的位置**：权限判定在召回之前、脱敏在出库之前、DLP 在输出之前——**位置错了，机制就等于没做**（§3.5 的反模式全部是位置问题）。
3. **把执行结果变成证据**：拒绝日志、脱敏前后对照、出网连接审计、演练记录——**没有留痕的机制无法被举证**。
4. **把合规要求映射到系统控制点**：等保的"一个中心、三重防护"、国产化清单、行业监管条款——**这一步是把"外部标准"翻译成"我的哪一行配置"**。

**「分级做完了」与「安全做完了」的差别**（这是本主题的判据表）：

| 维度 | 分级做完了 | 安全做完了 |
| --- | --- | --- |
| 产出物 | 一张表：哪些资产是哪一级 | 每个级都对应一组**已生效**的机制 |
| 验证方式 | 抽查表里的条目是否合理 | **演练**：越权尝试被拒、敏感字段被脱敏、出网被拦 |
| 出事时的回答 | "我们规定了机密级不许外发" | "这是拒绝日志，这是连接审计，这是上周的演练记录" |
| 失效信号 | 表里有条目，但没人看 | **机制可被绕过**（旁路、后置过滤、应用侧自觉） |

**一条判据**：**当你无法用一次演练证明某条安全要求生效时，你手上的是"制度"，不是"控制"。**

### 1.2 为什么需要

这一块不是"合规部门的附加要求"，而是**被四件事逼出来的**：

1. **AI 把数据的暴露面从"人读"扩大到"模型读"**：过去一份机密文档被读到，影响是"这个人知道了"；现在它进入模型上下文后，会影响输出、被写进日志、可能进入缓存——**暴露面的单位从"份"变成"次"**。
2. **RAG / Agent 让权限问题从"接口级"下沉到"行级"**：一个检索接口过去返回整表或整篇；现在用户问一句话，系统要从**他有权看的那部分**里召回——**"先召回再过滤"和"先裁剪再召回"在这里是安全差异，不是性能差异**（§3.2.6）。
3. **输出的不可控性引入了新的一类泄露**：模型会**复述**上下文里的内容。因此"入向管控"不够，必须同时管**出向**——这就是 DLP（§3.2.7）在 AI 场景里成为必需项的原因。
4. **受监管行业的准入门槛是"举证"而不是"能力"**：等保测评、信创验收、客户安全审查，问的都不是"你有没有这个能力"，而是"**你怎么证明**"。这决定了留痕与演练不是可选项。

**这四件事的共同点**：它们都不是"模型能力"问题，而是**机制位置与证据形态**问题——这正是本主题的职责范围。

### 1.4 演进历程

- **边界防护阶段（2010 年前）**：安全等于"把网络切干净、把人管住"——数据在边界内即可信，权限到库 / 表级。**AI 场景下这一阶段失效的直接原因**：模型调用会把数据带出边界（发往端点或从端点回来）。
- **数据级防护阶段（2010–2018）**：出现列级 / 行级权限、静态脱敏、透明加密（TDE）——**保护对象从"系统"变成"字段"**。同期等保 2.0 落地（GB/T 22239-2019），把"一个中心、三重防护"确立为国内合规的基本结构。
- **访问时防护阶段（2018–2023）**：动态脱敏、ABAC、DLP 从"邮件与终端"扩展到"数据平台"——**判定的时点从"入库"移到"访问"**，因为同一个字段对不同角色要呈现不同形态。
- **生成式防护阶段（2023 至今）**：检索期权限裁剪（召回之前就限定可见集）、输出端 DLP（复述、引用、缓存带来的二次泄露）、提示注入防御（[§01](../01-ai-data-governance/01-ai-data-governance.md) 已述）成为必需项。**这一阶段的新问题是**：**数据不仅被"读"，还会被"复述"**，因此管控必须覆盖生成链路。

> 演进的主线只有一句话：**保护对象的粒度在变小（系统 → 字段 → 行 → 片段），判定的时点在提前（入库后 → 访问时 → 召回前 → 输出前）。**

## 2. 核心原理

### 2.1 关键概念定义

- **分级（Classification）**：给每个数据资产打上一个**保护等级**（本书沿用公开 / 内部 / 机密 / 绝密四级，取值域与判定函数见 [§01 §2.1](../01-ai-data-governance/01-ai-data-governance.md)）。**分级是机制的输入，不是机制本身**。
- **静态脱敏（Static Masking）**：在数据**落库 / 出库时**把敏感字段替换或泛化，产生一份脱敏副本。特征：**脱敏结果持久化**，因此对**下游用途**是一次性决定（换了用途要重脱）。
- **动态脱敏（Dynamic Masking）**：在**查询 / 召回时**按调用者身份决定呈现形态，原始数据不变。特征：**同一份数据对不同角色呈现不同**，因此它是**权限机制的延伸**而非独立机制。
- **不可逆脱敏 vs 可逆脱敏**：替换为固定值 / 泛化为区间 → 不可逆；替换为**保序或加盐的哈希**、或用**格式保留加密** → 可逆（在持有映射表时）。**可逆性决定了脱敏副本还能不能参与关联分析**（§2.2 给出判据）。
- **差分隐私（Differential Privacy, DP）**：在**聚合统计**的结果上加入与隐私预算 `ε` 相关的噪声，使"某一条记录在不在数据集里"对输出的影响有上界。**它保护的是"个体能不能被推断出来"，而不是"字段能不能被看到"**——因此它不替代脱敏，它们解决不同问题。
- **同态加密（Homomorphic Encryption, HE）**：允许在密文上直接计算。**它的位置是"数据外包计算的最后一层"**（把计算也交出去时），不是日常查询的通用手段——代价是计算开销与功能受限（§3.2.4 给出边界）。
- **权限模型**：**RBAC**（角色 → 权限，主体是"角色"）、**ABAC**（属性 → 策略，主体是"主体 / 资源 / 环境属性的组合"）、**字段级权限**（同一行的不同列对不同角色可见性不同）、**行级权限**（同一张表的不同行对不同角色可见性不同）。**四者可叠加，不可互替**（§3.2.5）。
- **DLP（Data Loss Prevention）**：数据防泄露。在 AI 场景里它具体是三件事——**识别敏感实体**（身份证 / 银行卡 / 手机号 / 密钥）、**在输出前检测**、**必要时要求二次确认**（§3.2.7）。
- **等保「一个中心、三重防护」**：等保 2.0（GB/T 22239-2019）的结构性要求——**安全管理中心**（一个中心）+ **安全通信网络 / 安全区域边界 / 安全计算环境**（三重防护）。**落到 AI 系统上的关键动作是"逐条指认控制点"**（§3.2.8、§4.4）。
- **国产化适配**：把系统的依赖（芯片 / 操作系统 / 数据库 / 中间件 / 加密算法 / 模型权重）替换为符合信创要求的组分。**验收粒度是"关键算子级"而不是"能启动"**（§4.2（5））。
- **举证（Evidencing）**：把机制的执行结果整理成外部可验证的材料。**举证的对象不是"你做了什么"，而是"你能证明什么"**。
- **泄露面（Exposure Surface）**：一次数据流转中，数据**被实际读出**的所有位置（模型上下文、缓存、日志、遥测、导出物）。**判据**：机制要覆盖泄露面，而不只是"用户界面"。

### 2.2 数学 / 形式化基础

**权限判定是一个谓词，不是一个开关**。设主体 `s`、资源 `r`、动作 `a`、环境 `e`，则授权判定为

```
allow(s, r, a, e) = Policy(s.attrs, r.attrs, a, e.attrs)
```

- **RBAC** 是它的特例：`Policy` 只依赖 `s.roles`；
- **ABAC** 是全量形式：`Policy` 依赖主体 / 资源 / 环境的属性组合；
- **字段级 / 行级权限**是**给 `r` 加约束**：字段级是 `r.fields ⊆ visible(s, r)`，行级是 `r.rows ⊆ {row : Predicate(s, row, e)}`。

**这个式子的用途是"把权限前置到召回条件里"**：把 `visible(s, r)` 与 `Predicate(s, row, e)` 作为**检索的过滤条件**下推到索引 / 查询引擎，而不是取回后再筛——这正是 §3.2.6 的机制，也解释了为什么"后置过滤"在原理上不等价（它已经读出来了）。

**脱敏的可逆性判据**。设原始值域为 `D`、脱敏函数为 `m: D → D'`：

```
不可逆： |m(D)| < |D| 或 m 为单向压缩（泛化、固定替换）→ 无法还原，也无法跨表关联
可逆：   m 为单射且存在映射表 M（格式保留加密、加盐哈希 + 盐表）→ 可还原
        代价：M 本身成为最高密级的资产（它一泄漏，脱敏全部失效）
```

**这条判据直接决定选型**：脱敏副本若还要参与关联分析（例如"按用户 ID 聚合同一用户在多个系统的行为"），就必须用**保序 / 确定性的可逆脱敏**（同一输入总映射到同一输出）；若只是一次性对外提供，则用不可逆泛化更安全。**"可逆"不是更高级，而是把风险从"副本"转移到了"映射表"——因此选用可逆方案时必须同时给出映射表的保护方案。**

**差分隐私的隐私预算**。设相邻数据集 `D`、`D'` 只差一条记录，机制 `M` 满足 `ε`-差分隐私当且仅当对任意输出集合 `S`：

```
Pr[M(D) ∈ S] ≤ e^ε · Pr[M(D') ∈ S]
```

- `ε` 越小隐私越强、可用性越差；**`ε` 是可累加的**——对同一数据集做 `k` 次查询，总预算约 `Σεᵢ`。**因此"查询次数"本身是预算消耗**：一个允许无限次查询的 DP 接口，等价于没有隐私保护（差分隐私的组合定理）。
- **推论（实践中最常被忽略的一条）**：DP 保护的是**统计输出**，因此它要求**每个输出都有人在聚合层面消费**；如果系统把 DP 输出当作单条记录去查（"查一下张三的金额"），`ε` 再小也无意义——**那不是 DP 的失败，是用法错误。**

**脱敏的可用性代价（可算）**。设某字段脱敏后仍可用于下游任务的信息量为 `I`、脱敏前为 `I₀`，则

```
利用率 = I / I₀     —— 泛化越粗，利用率越低
误判成本 ≈ f(1 − 利用率)  —— 下游模型在粗粒度字段上的错误率上升
```

**因此脱敏的粒度选择是一个取舍，不是一个"越严越好"的排序**：把日期从"年月日"泛化到"年"，隐私提升有限（`年 + 地区 + 性别`仍然可识别），但下游的时间序列分析直接失效。**判据是"泛化到什么粒度之后，下游任务的指标开始不可接受"——这个拐点要用评测量出来，不能拍。**（这也是 §3.2.3 里"DP 与脱敏解决不同问题"的原因：DP 保的是个体不可推断，脱敏保的是字段不可见。）

**DLP 的漏出率与代价**。设输出量为 `N`、含敏感实体的比例为 `p`、检测的召回为 `r`、误报率为 `fp`：

```
漏出条数  = N × p × (1 − r)
误拦条数  = N × (1 − p) × fp
```

**这两个数必须一起看**：只优化 `r`（提高召回）会把 `fp` 抬上去，而误拦的业务代价（用户拿不到本该拿到的结果）与漏出的安全代价**方向相反**。因此 DLP 的阈值不是一个"安全参数"，而是一个**业务可讨论的取舍点**——它应当像 [Ch10 §04 办公自动化的字段级阈值](../../10-industry-agent/04-office-automation-agent/04-office-automation-agent-section-6-sec6.md) 那样，被画成一条**"拦得越严 → 漏得越少 → 误拦越多"的曲线**，由业务选点。

**等保映射的完备性（可核查的形式）**。设等保要求的控制项集合为 `C = {c₁…cₙ}`、系统已有的控制点为 `K = {k₁…kₘ}`，映射是一个函数

```
m: C → K ∪ {⊥}      —— ⊥ 表示"尚未指认控制点"
```

**验收判据是 `m` 的定义域覆盖整个 `C`**：即**每一条要求都能指到系统里的某一个具体控制点（文件 / 配置 / 代码位置），而不是指到"我们有安全团队"**。`m(c) = ⊥` 的那些项，就是测评时的失分项——**提前把它们列出来，是这一块唯一可自动化的动作**。

### 2.3 关键算法 / 方法

**① 敏感实体识别（DLP 的入口）**。两类方法分工：

- **确定性匹配**：正则 + 校验位（身份证的校验位、银行卡的 Luhn 校验）——**精确、可解释、零误报（在格式合法时）、但对变体无能**（带空格、全角、拆行）。
- **上下文判定**：模型或规则组合判定"这是不是真的手机号"（`13800138000` 与订单号形态相同）——**覆盖率更高、但引入误报**。

**工程判据**：**两类都要有，且顺序固定**——先做确定性匹配（拿掉最确定的、零误报的那部分），再用上下文判定处理剩余部分。**反过来做（先模型后规则）会让模型的正则无关紧要地重复一遍确定性能识别的东西，白白抬高误报。**

**② 脱敏的四种形态与选择顺序**：

```
① 泛化（Generalization）     ：日期截断、地区聚合、金额分桶     —— 保留分布，代价是精度
② 替换 / 掩码（Masking）     ：固定字符、部分保留（138****1234）—— 保留格式，代价是关联性
③ 保序 / 确定性假名（Pseudonymization）：加盐哈希、格式保留加密  —— 保留关联，代价是盐表本身要保护
④ 噪声注入（DP / 扰动）      ：统计扰动、合成数据                —— 保留统计性质，代价是可查询次数
```

**选择顺序是"从 ① 到 ④ 依次退让"**：能泛化就泛化（最安全、最便宜）；必须保留关联才用 ③；只有"统计输出"这一种需求才上 ④。**从 ④ 开始想的团队，通常是在用一个重武器解决一个轻问题。**

**③ 字段级权限的挂载点**。列级权限有两种挂法：**存储侧**（视图 / 列掩码，由引擎执行）与**语义层侧**（在语义层把"可见字段集"作为指标定义的一部分）。**判据是"同一份定义能不能同时服务两种消费者"**：如果人取数与 AI 取数走同一条链路，把权限挂在语义层上是唯一不会出现两套口径的做法（同 [Ch1 §10 指标体系](../../01-modeling/10-metric-system/10-metric-system.md) 的"指标口径唯一"）。

**④ 召回期权限裁剪**。检索请求先解析出**可见集**（`visible(s, r)` 与 `Predicate(s, row, e)`），把它**下推为过滤条件**，再召回。**可核查的标志**：召回结果里**不存在**任何无权文档的 id——注意这是**比"最终没返回给用户"更强的要求**，因为后者允许"读出来又删掉"（§3.2.6 的失效点）。

**⑤ 输出端 DLP 的三道闸**：`实体识别（是什么）→ 策略判定（该不该拦）→ 动作（拦 / 脱敏 / 要求确认 / 放行并留痕）`。**三道都要留痕**，否则事后无法回答"这条为什么被放行了"（而这正是审计必问的）。**二次确认只在"高风险实体 + 高置信"时启用**——把它当默认动作，会让每一次输出都变成一次人工介入（§3.2.7 的代价）。

**⑥ 等保控制点的指认方法**：对每条要求问三个问题——**我在哪个组件上做了这件事**（文件 / 配置）、**它的执行结果留在哪里**（日志 / 报表）、**我怎么证明它此刻生效**（演练动作）。三问答全，`m(c) ≠ ⊥`；缺任何一问，这条要求在测评时都是**不可举证**的。

**密钥与盐表的管理（跨全部机制的一条地基）**：脱敏的盐、加密的密钥、映射表，**都必须有轮换与吊销路径**，且**与数据分离存储**。**判据**：密钥与数据的访问控制是两套（能读数据的人不一定能读密钥）——**同一套权限管两样东西，等于把脱敏变成了一次编码。**

### 2.4 与相邻概念的关系

- **本主题 vs [§01 AI 数据治理](../01-ai-data-governance/01-ai-data-governance.md)**：§01 回答"**这是什么级、谁负责、怎么留痕**"（分级 / Owner / 审计表）；本主题回答"**这个级该配什么机制、机制怎么被验证**"。**关系是"输入与实现"**：分级是本主题的输入，本主题是分级的落地。两者不可互替——只有分级会停在制度，只有机制会没有依据。
- **本主题 vs [Ch11 §02 数据安全](../../11-cross-cutting/02-data-security/02-data-security.md)**：Ch11 讲通用做法（网络 / 主机 / 数据库 / 访问控制的横切规范），本主题讲 **AI 场景特有的那部分**——召回期权限、生成期复述、模型端点的出网判定。**通用做法先做，AI 特有部分叠加在它之上**。
- **本主题 vs [Ch11 §08 隐私计算](../../11-cross-cutting/08-privacy-computing/08-privacy-computing.md)**：隐私计算讲 DP / MPC / TEE / FL 的通用机制与数学；本主题只关心**它们各自的位置与代价**（什么时候该用、用它换来什么、付出什么），不重复推导。
- **本主题 vs [Ch4 §05 RAG 架构](../../04-data-assetization/05-rag-architecture/05-rag-architecture.md)**：RAG 决定"给模型什么上下文"；本主题决定"**上下文里能包含谁的数据**"。**接口是"可见集"**：RAG 侧的检索必须接受并下推它。
- **本主题 vs [Ch6 §03 模型网关](../../06-multi-model/03-model-gateway/03-model-gateway.md)**：网关的**出网白名单**是本主题"数据不出域"要求的执行点；**本主题提供"租户 → 可去端点"这张表，网关执行它**（§4.3 的接口表）。
- **本主题 vs [Ch12 架构](../../12-architecture/README.md)**：多活 / 单元化会**放大**策略一致性问题——同一份权限策略、同一批密钥要在多个单元保持一致；**不一致的单元边界就是一条越权路径**。

> 💡 **思考锚点**：把你手上最敏感的那一类数据（客户身份、财务、合同）拿出来，回答三个问题：① 它在**哪几个位置被读出来过**（用户界面之外，还有模型上下文、缓存、日志、遥测、导出物吗）？② 每个位置各有什么机制管着？③ 哪一条机制，你能用一次**十分钟内能做完的演练**证明它此刻生效？第三个问题答不上来的那条，就是你下一轮该补的第一条——你打算先补哪一处？
