## 4. 工程实现

### 4.1 落地步骤

安全机制有一个与其它主题不同的性质：**它的价值不来自"做了多少"，而来自"覆盖了哪些位置"**——因此落地顺序必须按"暴露面"排，而不是按"技术难度"排。

**Step 1：画暴露面位置清单（半天，先做这个）**
拿一条真实请求（一次问数 / 一次 RAG 问答 / 一次 Agent 调用），沿链路把"数据出现在哪"逐个位置标出来：用户界面、模型上下文、提示与响应缓存、应用日志、网关日志、遥测与 trace、导出物与报表、备份。**产出物是那张位置清单**——它是后面每一步的靶点。**为什么第一步是它**：没有清单时，"我们做了脱敏"这句话无法验证覆盖范围；有清单之后，每一步的完成都有明确判据。

**Step 2：把权限判定前置到召回条件里**
解析可见集（`visible(s, r)` + `Predicate(s, row, e)`）→ 下推为过滤条件 → 在可见集合内召回。**判据**：无权文档的 id 不出现在召回的中间结果里（用无权账号做一次请求并检查上下文构建日志 / 缓存）。**这一步不能往后放**：它是"数据读出来没有"的分界，晚做要改检索与索引侧的实现。

**Step 3：在数据侧补静态脱敏与四层权限**
出库副本走静态脱敏（与原件物理分离）；对内访问按 RBAC → ABAC → 行级 → 字段级依次收紧。**判据**：脱敏副本做一次重识别演练；抽查一个角色问"同角色两人的可见行列是否按业务应当不同"。

**Step 4：在输出路径装 DLP（双端 + 覆盖缓存与日志）**
识别（确定性匹配先行，上下文判定兜底）→ 策略判定 → 动作分级（拦 / 脱敏 / 二次确认 / 放行留痕）。**判据**：位置清单里"缓存写入"与"日志写入"也被纳入检测；误拦率与漏出率都有数。

**Step 5：把每个机制的执行点变成证据采集点**
拒绝日志（含租户 / 端点类别，不含内容）、脱敏前后对照、出网连接审计、演练记录。**判据**：每一条安全要求都能说出"证明它生效的动作是什么"。

**Step 6：补合规映射（等保控制点表 + 国产化五类清单）**
对每条要求指认控制点 / 结果存放处 / 生效证明动作；国产化按五类给三态。**判据**：映射表里没有 `⊥`；国产化清单说明外部组分的替代路径。

**Step 7：把策略变成有 Owner、有评审周期的资产**
每条策略一条记录：谁写的、为什么存在、上次评审时间、下次评审时间。**判据**：随机抽一条策略，能在记录里找到这三项。

**顺序的反面（最常见的错误）**：**先买 DLP 产品、后做暴露面清单**——产品会在它自己的检测点上工作（通常是某个流量入口），而真正的泄露路径（上下文、缓存、日志）不在它的视野里。**结果是"上了 DLP"与"泄露面被覆盖"两件事都没有发生。**

### 4.2 关键技术点

**（1）暴露面清单的画法（这一步决定后面全部工作的靶点）**

```
一次 RAG 问答的数据落点（逐格标注"有没有机制"）
  用户问题 ──▶ ① 应用日志（请求体）
              ▼
        ② 检索：可见集判定 ──▶ ③ 召回结果（内存）──▶ ④ 检索缓存
              ▼
        ⑤ 上下文拼装 ──▶ ⑥ 模型端点（出网判定在这里）──▶ ⑦ 提示缓存
              ▼
        ⑧ 生成输出 ──▶ ⑨ DLP 出向 ──▶ 用户
              ▼
        ⑩ 响应缓存  ⑪ trace / 遥测  ⑫ 会话留痕表  ⑬ 备份
  判据：①–⑬ 每一格都要能回答"管它的机制是什么"；
        答"没有"的格子就是泄露面——先补它，而不是先买工具
```

**（2）可见集下推的实现要点**

- **下推位置**：向量检索侧做成**过滤表达式**（多数向量库支持元数据过滤），关系侧做成**谓词下推**（把策略编译成 `WHERE`），文件 / 文档侧做成**索引期打标 + 检索期过滤**。
- **跨库边界**：定义"引用的可见性是否传染"——A 文档引用了 B 文档的定义，能看到 A 的人是否应看到 B？**判据**：把这条边界写进策略文档，并有测试用例；不写就会出现"能看 A 所以也能看 B 依赖"的越权路径。
- **可见集为空时**：必须**明确返回空并说明原因**（"你的权限下无匹配文档"），而不是回退到"不过滤"——**回退是这类实现里最危险的一条分支**。

**（3）身份传递链（判定输入的正确性）**

服务代调用时，判定必须用**人的身份**而不是服务身份：请求里带 `on_behalf_of`（或等价的委托凭证），策略判定以它为主语。**为什么这条是硬要求**：Agent / 服务账号通常权限很宽（它要能访问多个租户的数据），**以服务身份判定等于按最宽的那个身份放行**。**判据**：审计记录里能否回答"这条数据是**谁**（具体到人）触发的访问"——只能回答"哪个 Agent / 哪个服务"，说明身份链是断的。

**（4）DLP 的流式与滑窗**

流式输出的敏感实体可能被分片切开（`138` / `0013` / `8000`）。三种处理方式及其代价：

| 方式 | 做法 | 代价 |
| --- | --- | --- |
| 缓冲后再检 | 攒够一个窗口再输出 | 延迟上升（与"首字延迟"直接冲突） |
| 滑窗拼接 | 维护尾部 N 字符的重叠窗口 | 需要按实体长度定 N；误报略升 |
| 只检完整段 | 只对句末 / 段落边界检测 | 漏检概率上升 |

**判据**：写一条测试用例——把一个身份证号**跨分片**切开发送，看它是否被检出。**不做这个测试，等于不知道流式侧有没有生效。**

**（5）国产化适配的粒度（五类盘点 + 逐算子）**

| 类 | 盘点对象 | 验收粒度 |
| --- | --- | --- |
| 芯片 / 指令集 | CPU / NPU 型号、驱动、**关键算子**（向量检索内核、量化推理内核、压缩加密库、Python 扩展） | **逐算子**跑通 + 精度对照 |
| 操作系统 | 发行版、内核版本、依赖库 | 安装与运行 |
| 数据库 / 中间件 | 关系库、消息队列、缓存、向量库 | 功能 + 性能 |
| 加密与国密 | 算法库、证书链、是否满足国密要求 | 合规清单 + 互操作 |
| 模型与权重 | 自托管模型的推理栈、量化格式 | 结果一致性（与 x86 对照） |

**一条判据**：**整体跑通只能说明"能启动"**——客户真正关心的是"结果是否与 x86 一致"，那是逐算子的精度问题。**不接受这条的后果**：上线后出现"偶发的数值差异"，而这类问题在整体跑通的验收里测不出来。

**（6）策略的版本化与生效验证**

策略是**有版本、会漂移的资产**：每次修改要留痕（谁改的、为什么、影响哪些资源），并有**生效验证**——改完之后要能演示"新策略已生效、旧策略不再生效"。**判据**：用修改前的越权尝试重放一次，它现在应当被拒。

### 4.3 工具链与平台

| 能力 | 自建 / 开源 | 商业产品 | 选型要点 |
| --- | --- | --- | --- |
| 静态脱敏 | 引擎内置（视图 / 掩码）、自研 ETL 阶段转换 | 数据安全平台 | **看它能不能做准标识符组合的重识别评估** |
| 动态脱敏 | 查询重写 / 代理层 | 数据库安全网关 | 看**旁路能否被发现**（对账能力） |
| 权限 | 权限系统 + 策略引擎（ABAC）/ 行列级策略 | IAM / 策略中心 | 看**是否支持把判定下推**到召回条件 |
| DLP | 正则 + 校验位 + 模型分类 | DLP 产品 | 看**能否覆盖缓存与日志**、流式滑窗 |
| 加密 / 密钥 | KMS + 密钥轮换 | 云 KMS / HSM | 看**密钥与数据的权限是否分离** |
| DP / HE | 自研 / 研究原型 | 隐私计算平台 | 看**预算累计**与**运算集合**是否覆盖你的需求 |
| 合规材料 | 自建控制点映射表 | 合规咨询 | **这一项可自建，且自建往往更快**（它是文档工作） |

**一条选型原则**：**产品的检测点位置比它的功能列表重要**。同一个 DLP，装在流量入口与装在"输出 + 缓存 + 日志"三处，效果差一个量级；而**位置能不能扩展**，是选型时唯一值得压测的东西。

### 4.4 存量迁移

**（1）已存在的数据怎么办**

| 对象 | 处理 | 注意 |
| --- | --- | --- |
| 历史副本（未脱敏的导出物） | 盘点 → 分级 → 清理 / 重脱敏 / 加访问控制 | **先盘点**：多数团队的存量副本数量远超预期 |
| 已发的权限（历史授权） | 快照 → 逐条复核 → 收敛 | 不收敛则新策略与旧授权并存，**旧授权就是越权路径** |
| 正在跑的流程（硬编码了明文访问） | 列清单 → 逐条改走受控路径 | 判据：与底层库审计日志对账，差异收敛到 0 |
| 密钥 / 凭证（散落在配置） | 上收到密钥服务 → 轮换 | **轮换要一次做完**：留一半等于没换（旧密钥仍是有效入口） |

**（2）迁移的安全判据（三条）**

- **对账差异收敛**：受控路径的统计与被访问系统自身的审计日志，差异可解释（这是"没有旁路"的证据）。
- **重识别演练失败**：脱敏副本无法用非敏感字段组合还原个体。
- **越权尝试被拒**：用无权账号请求无权资源，被拒且拒绝原因可查。

### 4.5 模板 / 示例

**模板 1：暴露面位置清单（Markdown 表即可，但要逐格填）**

```text
| 位置 | 数据形态 | 管它的机制 | 证据（在哪查） | 生效证明动作 |
| --- | --- | --- | --- | --- |
| 应用日志 | 请求体（含原文） | 结构化字段白名单，正文不入日志 | 日志采样+字段清单 | 发一次含敏感实体的请求，查日志 |
| 检索缓存 | 召回片段 | 缓存键含租户+权限版本；撤权即失效 | 缓存键设计文档 | 撤权后重查同一问题 |
| 模型端点 | 上下文 | 出网白名单（按租户→端点类别） | 连接审计 | 让受监管租户请求外部端点 |
| 输出 | 生成内容 | DLP 出向（实体识别+策略+动作） | 判定日志 | 构造一条含身份号的输出 |
| trace / 遥测 | 调用元数据 | **只记元数据不记内容** | 字段清单 | 抽查一条 trace |
```

**模板 2：权限判定的下推（伪代码，示意"前置"这件事）**

```text
def retrieve(user, query):
    # ① 先解析可见集，并且它来自唯一权威源（企业权限系统），不是自建表
    visible = {
        "tenant": user.tenant,
        "fields": authz.visible_fields(user, resource),      # 字段级
        "row_pred": authz.row_predicate(user, resource),     # 行级
        "docs": authz.visible_docs(user, scope),             # 文档/片段级
    }
    # ② 把可见集下推为检索条件（不是取回后再筛）
    hits = index.search(query, filter=visible)
    if not hits:
        return []          # 明确返回空，不回退为"不过滤"
    # ③ 生成只用召回结果；上下文构建处再做一次入向 DLP
    ctx = build_context(hits)
    ctx = dlp.inbound(ctx)
    out = llm.generate(ctx)
    return dlp.outbound(out)   # ④ 出向 DLP
# 判据：把 index.search 的 filter 参数去掉，上述任何一条断言都会破——
#       也就是说"前置"这件事在设计里是可见的，不是隐含的
```

**模板 3：等保控制点映射表（每条要求一行，三问必答）**

```text
| 等保要求 | 控制点（文件/配置） | 执行结果存放处 | 生效证明动作 | 状态 |
| --- | --- | --- | --- | --- |
| 安全通信网络：通信传输保密 | gateway/egress-policy.yaml | 连接审计日志 | 让受监管租户请求外部端点→被拒 | 已指认 |
| 安全区域边界：访问控制 | tool-egress 出口鉴权配置 | 出口拒绝日志 | 用无权工具发起调用→被拒 | 已指认 |
| 安全管理中心：集中管控 | policy-service（策略唯一权威源） | 策略变更流 | 改一次策略，重放旧越权尝试→被拒 | 已指认 |
| （未指认项） | ⊥ | ⊥ | ⊥ | **待补** |
```

**一条使用说明**：模板 1 与模板 3 的**有效判据都是"没有空行 / 没有 `⊥`"**。它们看起来像文档工作，但**这一块有一半的价值就在这两张表里**——因为它们把"我们做了安全"变成了"这些位置、这些要求，逐条有主"。

### 4.6 成本：这套东西的账单

**硬件**：本主题**基本与硬件无关**——脱敏、权限、DLP 都是计算密集度很低的路径（一次字符串替换、一次谓词判定）。唯一与硬件相关的是**加密类工作**：同态加密（§3.2.4）的开销是数量级级的，**全密文计算的成本不能用常规口径估算**，必须按实际方案实测【经验：随方案与运算类型差异极大】。**国密算法替换**也会带来加解密开销的上升（通常在一到数倍区间【经验】），但相对模型推理成本仍属小项。

**人力（主项）**：本主题的成本集中在**三类人力**，且它们都不是一次性的：

1. **策略维护**：权限策略、DLP 规则、脱敏规则的增删与评审。成本随**资源数 × 策略维度**增长——**这是最容易被低估的一项**，因为它在立项时被算成"配置一次"。
2. **抽检与演练**：脱敏副本的重识别演练、越权尝试演练、DLP 的误拦 / 漏出抽检。按 [§3.2.7](02-data-security-and-compliance-section-3-sec3.md) 的口径，**每周 20 条 DLP 命中记录的抽检约 1.7 小时/周**【推算：20 × 5 分钟 ÷ 60】，加上演练与策略评审，**常备投入在 0.3–1 人年量级**【经验：随合规标准数与资源规模浮动】。
3. **合规材料**：控制点映射表维护、测评配合、客户安全审查应答。**它的成本随"合规标准数 × 系统变更频率"增长**——每接一套新标准、每做一次大改造，映射表都要复核。

**云账单（次项）**：KMS 调用、密钥轮换、审计日志存储（**留痕的存储成本随保存期线性增长**，且它往往是这套体系里最大的一笔云支出）、DLP 的计算资源。

**一条推论**：**本主题的成本函数是"人力为主、随资源数与标准数增长"，而不是"随数据量增长"**。这与 [Ch6 §03 模型网关](../../06-multi-model/03-model-gateway/03-model-gateway-section-7-sec7.md) 的线性成本曲线形成对照——**因此它的规模化压力来自"管的东西变多"，不是"跑的量变大"**。这条推论有一个直接的实践含义：**安全投入的性价比随系统数量上升而下降**，所以"先把一处的机制做透、再复制"通常优于"每处都上一套浅的"。

### 4.7 容灾与故障演练

**本主题的"灾"不是宕机，而是"机制静默失效"**——安全机制失效时，业务通常照常运转（这正是它危险的地方）。因此失效形态要按"机制"而不是按"组件"来定义：

| 失效形态 | 影响面 | 降级策略 | 演练动作 | 恢复目标 |
| --- | --- | --- | --- | --- |
| 权限系统不可用 | 全量检索（判定输入缺失） | **失败关闭**：拒绝访问而不是放行；给出明确错误 | 真关一次权限服务，看请求是否被拒而非放行 | RTO：分钟级；**RPO 不适用**（判定是实时的） |
| 密钥服务不可用 | 加密读写、脱敏还原 | 读路径可用缓存密钥，**写路径必须失败关闭** | 关闭 KMS，验证读可用、写被拒 | RTO：分钟级 |
| 策略服务不可用 | 新策略无法下发 | 用最后一次已生效策略继续服务，**不允许"无策略放行"** | 关策略服务，验证服务用旧策略而非全放行 | RTO：分钟级 |
| DLP 检测超时 | 输出路径 | **超时按"拦截"处理**（与"降功能不降可信"同一条理） | 注入一个检测超时的实体，看输出是否被拦 | 单请求级 |
| 审计日志写入失败 | 证据链 | 业务继续，**但立即告警**（证据断了要马上知道） | 关日志存储，验证告警触发 | 小时级 |
| 脱敏规则被误改 | 副本泄露面 | 版本回滚 + 重跑受影响副本 | 故意改错一条规则，验证能回滚并识别受影响范围 | 天级（重跑耗时） |

**这套演练的三条纪律**：

1. **凡是"判定类"的机制，不可用时必须失败关闭**——权限、出网、DLP 都属于判定类。**"降级为放行"是这类系统里最贵的一个设计决定**：它把一次可用性事故变成一次安全事件。
2. **凡是"证据类"的机制，不可用时业务可继续但要立刻告警**——审计日志属于这一类（让它阻断业务是把可用性绑在证据上，代价过高）。
3. **每次演练留"演练前 / 演练后"两组数字**——没有对照的演练只能证明"系统还活着"，不能证明"机制在起作用"。

**一条容易漏的演练**：**改一次策略，然后重放一次旧的越权尝试**。它同时验证了三件事——策略服务可用、策略已生效、旧权限已失效。**这三件事在日常运维里都不会自然暴露。**

### 4.8 演进路线：0 → 1 → 100

**0 → 1：把暴露面清单画出来，把权限前置**
- **这一步做什么**：画位置清单（§4.1 Step 1）；把权限判定下推到召回条件；在数据侧补静态脱敏与四层权限。
- **变贵的是什么**：**人力**——这是唯一需要"改动检索与索引侧实现"的阶段，人力投入集中且不可分片。
- **先坏的是什么**：**先坏的是"看得见的那一处"**——团队会把界面脱敏做完就认为安全做完了，而清单上的其他 12 格仍是空的。**这一阶段的判据不是"脱敏做完了"，而是"清单上没有空格"。**

**1 → 10：把机制变成有主、有证据的资产**
- **这一步做什么**：给每个机制装证据采集点（拒绝日志 / 对抗账 / 演练记录）；DLP 双端覆盖缓存与日志；策略加 Owner 与评审周期。
- **变贵的是什么**：**协调成本**——策略要跨团队评审、证据要在别人的组件上采集、演练要拉业务配合。**它变贵的不是技术，而是"让别人按你的节奏做事"**。
- **先坏的是什么**：**先坏的是 DLP 的误拦率**——机制覆盖变广之后，误拦会集中暴露（因为它第一次真的拦到了业务在用的东西）。此时正确的动作是**调动作层分级**（§3.2.7），而不是回退覆盖面。

**10 → 100：把合规变成可复制的产物**
- **这一步做什么**：控制点映射表成为常备资产（每套标准一份）；国产化五类清单做到逐算子；把"新系统上线要过哪几关"沉淀成一份可复用的检查单。
- **变贵的是什么**：**合规材料随标准数与系统数增长**——每接一套新标准、每上一个新系统，映射表都要复核。
- **先坏的是什么**：**先坏的是"证据的时效性"**——留痕有保存期，几年前的证据无法支撑当前的审查。因此这一阶段的重点是**证据的持续性**（定期演练并留痕），而不是把工作再做一遍。

**贯穿三阶段的一件事**：**每一阶段都要保留"用一次十分钟演练证明机制生效"的能力**。它是这套体系唯一的健康指标——**安全体系不会因为"很久没出事"而变好，只会因为"很久没演练"而变脆。**

### 4.10 小结

> 本节小结：安全机制的落地顺序**按暴露面排，不按技术难度排**——先画位置清单，再把权限判定前置到召回条件，然后补数据侧脱敏与四层权限，最后在输出路径装双端 DLP 并把每个执行点变成证据采集点，合规映射放在最后（它是纯文档工作，但投入产出比最高）。**变贵的是人力，而且它随"管的东西变多"增长，不随"跑的量变大"增长**——所以"先把一处做透再复制"优于"每处都上一套浅的"（§4.6）。**容灾有一条与其它主题不同的纪律**：判定类机制不可用必须**失败关闭**，证据类机制不可用可继续但必须告警（§4.7）。**三阶段的同一件事**：始终保留"用一次十分钟演练证明机制生效"的能力——**安全体系不会因为很久没出事而变好，只会因为很久没演练而变脆。**

> 💡 **思考锚点**：按 §4.1 的 Step 1 花半天画一次你自己的暴露面清单，然后数两个数：**十三个位置里有几格是空的**、**空格里有几格是你此前从没想过的**。第二个数字比第一个更有意义——它衡量的是"你这套体系离'看得见全部泄露面'还有多远"。画完之后再决定先补哪一格：是补那个**最容易出事**的，还是补那个**最便宜就能补上**的？
