## 5. 前沿演进（AI 时代）

### 5.1 先分清三类「前沿」

趋势清单的根本问题不是列错了，而是**没有时间维度**。「LLM 自动检测 ADR 中的认知偏误」与「Decision Graph 决策图谱平台化」被并列写在同一个列表里，但前者今天就能跑通，后者连「共识模式」都还没有定义。读者据此排路线图，会把一个演示当能力、把一个能力当路线图，最后在预算评审会上说不清交付了什么。

所以本节给每个方向标级别，判据必须可核验。三条判据沿用本项目通用口径：**已 GA 且有正式 release note**、**有第三方（非厂商）公开生产案例**、**接口稳定**——三条全中才算 **L1 生产可用**；只满足其中一部分，或只有厂商自有案例，算 **L2 可试点**；只有路线图、论文或演示，算 **L3 观望**。

本主题特殊在**绝大多数方向是过程类，不是产品类**，没有 release note 可查。因此对过程类方向用等价判据：**公开且可长期查证的流程文档**（ADR 模板、评审清单、决策日志规范）+ **独立于作者的组织在长期运行它** + **输入输出接口稳定**（谁能发起、以什么形态提交、多久得到答复、结果写在哪里）。可核验的范本不必在本书里找，公开的提案流程文档就是现成参照——Python 的 PEP 流程文档（PEP 1，2000）、Rust 的 RFC 仓库、Kubernetes Enhancement Proposal 都属此类，均可自行查阅。【公开，可自行核验】

把这条判据套到 AI 方向上是这样用的：判断「LLM 检查 ADR」是否够格，不看它答得多流畅，而看它有没有**稳定的输入输出契约**——给它同一份 ADR，输出结构是否每次都一样、是否可被下游解析、漏检时有没有明确的失败信号。答不上来的一律压在 L2 及以下。反过来，「把历史决策做成可语义检索的语料」这一项能过关，正是因为它有清楚得不能再清楚的契约：输入一段文字，输出若干段**你自己写过的原文**。

还要加第四条，这是本主题最重要的一条分界线：**它的正确性能不能被使用者自己核对**。检索返回的是原文，使用者能自己读、自己判断；模型返回的是判断，使用者只能选择信不信。这条不对称决定了级别差——组织**能承受**检索出错（你打开原文就知道不对，代价是几秒钟），**不能承受**判断出错（没有人能独立核对，代价是一次错误的架构决策）。本节唯一的 L1 落在检索一侧，所有「模型替你做判断」的方向都到不了 L1。

级别不同，读者的动作也不同，这条对应关系要说在前面：

- **L1** 可以排进路线图，并按正常工程标准要求它——包括可用性、降级路径与 Owner。
- **L2** 可以做 PoC，但**必须先写清退出条件**（什么指标不达标就撤），且不允许成为核心依赖——核心依赖意味着它挂了你就没有决策流程了。
- **L3** 只记录、不投入。特别要警惕的是「在架构里为它预留假设」：为了一个还不存在的组件去改接口、开权限、动数据模型，这些妥协会在它没来时一直留在系统里。

级别还会退化，这一点常被忽略：L2 试点失败退回 L3 是常态；L1 也可能因为依赖的接口被弃用或供应商变更而降级。所以路线图里除了级别，还应当写**下次复核时间**——不写复核时间的级别标注，三个月后就会变成一句没人负责的形容词。

下面这张表把演进方向逐条标级。归并规则先讲清楚：**同一方向内部若成熟度不一致（例如「检索可用但生成不可用」），按最弱的必需环节定级**——一条链的可用性由最弱环节决定，不是由最亮的那一节决定。这也是后面几节反复出现的判断方式。

本节不预测「AI 会不会让决策更理性」——这句话永远正确，因而没有信息量。可证伪的写法是标出**哪个环节的边际成本被改变了**，再看改变后组织的行为是否真的跟着变。

最后要认清既有方案卡在哪。§2 列的偏误里，最难对抗的不是「想不起来要用 Checklist」，而是偏误在**动机层面有收益**：确认偏误让人省去自我否定，承诺升级让人不必承认失败，权威偏误让人不必为判断承担责任。所以凡是「再提醒一次」的方案都无效——它没有碰到收益结构本身。判断一个 AI 方向的第一问因此不是「它准不准」，而是：**它是加了一次提醒，还是改变了一个成本或激励结构。**

本节与 §2 的分工也要说清：§2 讲偏误是什么、由什么机制产生；§3、§4 讲用什么流程去对抗；本节只回答一个新问题——**AI 让这些对抗手段里的哪一环变便宜了**。凡是答不出「哪一环」的方向，本节不给它排级别，因为它根本没有落在决策流程上。

| 演进方向 | 级别 | 判据 | 现在该做什么 |
| --- | :---: | --- | --- |
| Decision Journal + 向量库 / Decision + RAG（检索历史决策） | **L1** | 接口稳定、被大量相互独立的产品与开源项目消费；返回原文，正确性由使用者自核 | 现在就做：把 ADR 与决策日志变成可语义检索的语料 |
| Decision Journal AI（自动记录 + 提醒） | L2 | 无 release note 门槛，但「记什么」的 schema 未标准化，跨工具不可移植 | 可试点：先把字段定死，再谈自动化 |
| AI 辅助识别偏误（LLM 检查 ADR 文本） | L2 | 能力可用，但正确性不可自核；无第三方生产效果数据 | 可试点：只做作者自查，不进任何阻断环节 |
| 人机协同决策（Human-in-the-loop） | L2 | 流程形态早已生产可用，但「AI 出候选、人只批准」的实际把关强度无稳定评测口径 | 可试点：先测 AI 错误的可察觉性 |
| Decision Intelligence 平台（决策台账 / 看板） | L2 | 作为记录与呈现可用；「决策 → 结果」闭环所需的标签在多数组织不存在 | 可试点：先解决结果写回，再买平台 |
| Decision Intelligence 闭环优化 | L3 | 被分析机构列为趋势 ≠ 有第三方生产闭环案例 | 观望：不要在架构里预留假设 |
| AI 决策助手 / Decision Copilot（每个架构师一个常驻决策助手） | L3 | 能力与上文的 LLM 偏误检查器同源，只是从「提交前跑一次」变成「常驻在场」；常驻本身没有可核验的输入输出契约，也无第三方生产案例 | 观望：不要为「常驻」单独开接口、权限与预算 |
| Decision + KG / Decision Graph（决策图谱） | L3 | 「偏误类型」「共识模式」无统一定义；边（谁受影响）主观且会变化 | 观望：先有结构化决策台账，再谈图谱 |
| AI 决策可解释性（SHAP / LIME） | L2 | 方法有公开来源、工具成熟；但解释的是特征敏感性而非因果依据 | 可试点：用作排错，不用作举证 |
| Nudge 2.0（AI 个性化 Nudge） | L3 | 个性化干预的增量收益无同等强度证据，且难以随机化检验 | 观望：继续用通用默认值，那条证据更硬 |
| Behavioral AI（用行为经济学原理设计 AI 界面） | L2 | 选择架构方法本身成熟；「生成式界面实时改写表述」放大框架效应，可审计性下降 | 可试点：把默认值与选项数当发布评审项 |
| AI Constitutional（用「宪法」约束 AI 决策） | L3 | 它是训练方法，不是组织决策程序；「AI 治理宪法」无公开生产案例 | 观望；可借用它的一半：显式写下决策准则让模型自评 |
| 跨文化决策心理学 / AI 决策可解释性标准化（ISO / IEEE） | L3 | 前者受生态谬误质疑；后者目前只有通用的 AI 管理体系标准（ISO/IEC 42001:2023，见 5.4），没有针对「决策可解释性」的专门标准 | 观望：把两者都当研究议题，不进路线图 |

本主题下**唯一处在 L1 的是「对自有决策文档做检索与结构化」**——它的正确性可以被使用者当场核对（返回的是你自己写的原文），这也是它配得上 L1 的唯一理由。其余方向不够格的原因可以归成三类：**判断类**（LLM 偏误检查、可解释性工具）停在 L2，因为它们的正确性无法被使用者独立核对，也没有第三方生产效果数据（把同一个能力包装成「常驻助手」不但不升级，反而因为以「常驻」为承诺形态而够不到 L2 的可试点边界，落到 L3，理由见 5.2.1 末）；**闭环类**（Decision Intelligence 闭环、决策图谱）停在 L3，因为它们依赖的输入——决策结果的写回标签——在绝大多数组织里根本不存在，而这张标签没人愿意写；**规范类**（AI 宪法、可解释性标准）停在 L3，因为规范的对象还没定清楚：什么叫「共识模式」、什么叫「可解释」，都还没有能被判定的定义。

自我核对一遍：如果一个方向你指不出「判据」那一栏对应的**具体对象**（哪份流程文档、哪条 release note、哪个第三方案例），那说明你其实在凭感觉定级。凭感觉定级的结果不是报错，而是排进路线图后无人认领。

三类里最容易误判的是第二类。L2 常被当成 L1 排进路线图，理由通常是「我们已经跑通了」。跑通一次与生产可用之间的距离，可以用一句话概括：**跑通证明它能用，接口稳定证明它敢用，第三方案例证明它坏了有人修。** 三者缺一，就还在 L2——而缺的往往不是能力，是第三项。这也是本节反复引用「第三方、非厂商」这个限定语的原因：厂商自己的案例只能证明它存在，不能证明它在别人手里也能跑起来。

### 5.2 演进方向逐条拆解（核心节）

> 每组都按同一套六问展开：旧做法卡在哪、AI 改了哪个机制、由此得到什么、由此付出什么、证据在哪、成熟度几级。

#### 5.2.1 LLM 当作偏误检查器（对齐 12 种偏误清单）

- **旧做法与它的卡点**：ADR 模板挂一张「12 种偏误」清单，Reviewer Checklist 里写一句「是否检查了 12 种偏误」。卡点不是没人知道这张清单，而是**执行检查的人正是已经投入这个方案的人**，或者是不好意思当面说他的人。当面讲「你有确认偏误」有社交成本；而 Checklist 可以勾、可以不勾、勾了也不留痕。
- **AI 改变了什么机制**：把这一步从「有社交成本的人工动作」改成「零社交成本、可无上限重复的文本分析」。**改变的是成本函数，不是判断力**——模型的判断力并不比一个资深评审人更强，它只是不怕得罪人、也不会累。
- **由此得到的**：因为审查的边际成本从「一个资深评审人半小时加一次人际张力」降到「一次模型调用、没人旁观」，所以同一份决策可以在**无人旁观的条件下被反复挑刺**；作者可以先自己挨一遍批再提交，把「被发现偏误」从公开事件变成私下动作。这是 Checklist 结构上做不到的——Checklist 只能查「你有没有做某个动作」（比如是否列了 3 个候选），LLM 能查「你写下来的东西里有没有偏误痕迹」，两者互补，不能互相替代。§3.5 反模式里的「形式化 Review」，正好可以被这种互补治掉一半：Checklist 保证动作发生，检查器保证文字可被质疑。
- **由此付出的**：模型只能检查**已经被写进文本的**偏误痕迹。这是本节最需要记住的一条限制，它决定了这个方向的适用边界：

  | 偏误 | LLM 能否从 ADR 文本里抓到 | 为什么 |
  | --- | :---: | --- |
  | 锚定效应 | 能（常能） | 「因为 Twitter 用 Kafka」这类表述把锚写在了字面上 |
  | 过度自信 | 能 | 「100% 没问题」这类绝对化表述可被模式识别 |
  | 规划谬误 | 能 | 文本里给了工期或预算，可与同类项目对比 |
  | 确认偏误 | **不能** | 它是「搜索行为」——只找了支持自己的证据，这个行为不留在文档里 |
  | 群体思维 | **不能** | 它发生在会议现场，被压抑的异议恰恰没有被记录 |
  | 框架效应 | **不能** | 一份文档只有一种表述方式，比较对象不在上下文里 |

- **由此付出的（续）**：其次是**误报的惩罚**。一屏「疑似锚定效应」会训练评审人忽略这类提示，最终退化成又一种形式化 Review——而形式化 Review 比不检查更糟，因为它给出了「已经检查过」的错觉。第三是**责任稀释**：一旦检查器进了流程，作者很容易说「我跑过了、它没提示」，把本该属于人的判断责任转移给工具。工具越顺手，这条转移越容易发生，而且它没有技术解法——只能在流程里写死「检查器没有否决权，也没有免责功能」。
- **证据与来源**：Constitutional AI（Bai et al., arXiv, 2022）【公开】证明可以用自然语言准则引导模型自我批判；**没有公开可核验的第三方证据**说明 LLM 偏误检查能降低决策失误率。所以这里只能写判定方法，不能写结论——「它能识别偏误」是能力声称，「它让决策变好了」是效果声称，后者本节拿不出。
- **成熟度**：L2。判据：能力已可用（模型接口稳定），但正确性不可被使用者独立核对，且无第三方生产效果数据。
- **与既有对抗机制的分工**：Checklist 管「动作有没有做」、Devil's Advocate 管「有没有人反对」、Pre-Mortem 管「失败原因有没有被独立列举」、LLM 管「写下来的文字里有没有偏误痕迹」。四者的覆盖面不同，不能互相替代——尤其是最后一个，它替代不了前三者中的任何一个。
- **「Decision Journal AI（自动记录 + 提醒）」为什么也归进本组**：它的两条腿机制不同，要分开判。**自动记录**这一半与前一条同源——把「写下当时的判断」从靠意志力改成交给模型，记录成本被压到接近零；它同时是 5.2.2 检索层的前置（没有记录，检索层是空的）。**提醒**这一半则落在 5.1「凡是『再提醒一次』的方案都无效——它没有碰到收益结构本身」那一条上：它只是再提醒一次，不想记的人被提醒也不会写。所以它给 L2 的依据来自前一半（能力可用、记录成本下降），后一半不构成升级理由；再叠加「记什么」的 schema 未标准化、跨工具不可移植（见 5.1 表该行），落地顺序应是先按 5.2.2 的最小元数据表把字段定死，再谈自动记录与提醒。
- **「AI 决策助手（Decision Copilot）」为什么归进本组、却只给 L3**：它的能力与本节这一条完全同源，区别只在包装——从「提交前手动跑一次」变成「常驻在你身边」。机制没变，变的只是在场方式，所以它不会因为「常驻」而升级：一个 L2 的能力被包装成常驻，不等于它变成了 L1。它反而多出一项本节已经点过的风险——常驻意味着持续输出，而持续输出会加速责任稀释（「我问过它了」）。所以「每个架构师配一个 Decision Copilot」这句话在**能力**上成立、在**成熟度**上不成立：它缺少 L2 至少要求的可试点边界（谁发起、结果写到哪里、失败的后果归谁）。本节的处置是记录，不投入。

作者可自行执行的判定方法——检验它是真在读文本，还是在补故事：

```text
判定「LLM 偏误检查」是否在做实质分析（无需外部数据，自己就能跑）
  第 1 次：喂完整 ADR，记录它指出的偏误集合 S1
  第 2 次：喂同一份 ADR，但删掉「结论段」与「选项段」，只留证据与背景，记录 S2
  ────────────────────────────────────────────
  若 S1 与 S2 大幅不同 → 它匹配的是「表述形态」，不是决策结构
  若 S1 与 S2 高度一致 → 它至少抓住了结构性的东西
  ────────────────────────────────────────────
  关键：第二个输入里，「锚定效应」的证据已经被删掉了。
       它还能指出来，说明它在补故事；指不出来，才说明它在读文本。
```

还有一个更省事的对照：把同一份 ADR 的**结论反转版**（把「采用 A」改成「采用 B」，其余不动）也喂进去。如果它对两个版本给出数量与种类都差不多的偏误指控，那它是在按模板套话；如果指控随结论变化，它至少在做内容相关的判断。两个测试都不需要外部数据，一个人十分钟内可以做完。

#### 5.2.2 决策日志的检索化（Decision Journal + 向量库 / Decision + RAG）

- **旧做法与它的卡点**：Decision Journal 的典型命运是「写了没人看」。§4 的落地步骤把它排进季度复盘，而 §3 模式 5 给它的定位是「半年后回看」——价值完全依赖**有人恰好记得回去翻**。卡在检索成本：要找「我们上次做类似选型时怎么想的」，得先想起它存在，再想起它写在哪个文件里，最后还得记得当时的文件名。
- **AI 改变了什么机制**：改变了**访问接口**——从「按文件名和日期找」变成「按语义找」。嵌入检索让「我记不清关键词，但我记得那个决策是关于多活成本的」这类查询第一次变成可行。**接口形态变了，索引里的东西没变**：它仍然只是你写过的那些文字，所以它不会凭空多出一个你没做过的决策。
- **由此得到的**：因为历史决策从「只有记得的人能用」变成「任何参与者的当下问题都能查到」，所以决策日志第一次有了**被使用的理由**；日志被使用，才有可能积累成组织记忆，而不是变成一份每年归档一次的合规产物。这是本节唯一的 L1：它是检索，不是判断，命中结果是人自己读的原文。它与 §3 的 Decision Journal 模式是同一件事的两面——模式负责让人**写下来**，检索负责让人**用得上**；缺了前者，检索层是空的；缺了后者，日志是一堆没人翻的文本。
- **由此付出的**：检索质量高度依赖切块与元数据（决策日期、决策类型、当时的假设、最终结果是否写回），而这些标签**没人愿意补**，尤其是「最终结果」——它要求有人在半年后回来认领。更微妙的是：**检索出相似先例会引入新的锚定**。你查到的第一个历史决策会成为锚，而这正是 Considered Options 这个字段要对抗的东西（本章 §1.3 把它列为抗锚定的工具）。用 AI 降低检索成本，同时抬高了锚定风险，这是本节最真实的张力。
- **由此付出的（续）**：还有一条工程上的注意——**相似文本不等于相似情境**。检索出来的先例往往带着不同的前提条件（同一个「选 Flink」的决策，在团队没有流处理经验的前提下并不适用）。所以检索结果必须同时带出**当时的前提假设**，否则使用者会把一个不适用的先例当成依据。这也正是 5.2.3 里 `assumptions` 字段存在的理由：没有它，检索层只会更快地把错的先例送到你面前。
- **由此付出的（续）**：嵌入模型换代意味着**全量重嵌入**，不同模型产出的向量空间彼此不可比，这既是一个周期性的成本项，也是一种软锁定——换模型要重跑全部语料，而语料越大这笔账越贵。这类成本不会出现在 PoC 阶段，只会在几年后出现。
- **证据与来源**：检索接口之所以多年稳定，有两条具名的独立技术路线可核——图索引一侧是 HNSW（Malkov & Yashunin, *IEEE TPAMI*, 2020），库与索引格式一侧是 FAISS（Johnson et al., *IEEE Trans. Big Data*, 2019）【公开】。两条路线之上有多个相互竞争的实现与商业产品在消费同一批接口，这才是「不被单一供应商锁定」的依据。判断你手上的这一层是否真可替换，看它有没有独立的、不依赖单一厂商的索引格式与 API，而不是看厂商页面上的「毫秒级检索千亿向量」；那类声称只有在写明数据量、维度、召回率目标与硬件条件后才构成技术事实。【经验】在决策语料只有数十到数百条量级时，语义检索的排序稳定性明显不如按标签浏览——语料太小，相似度区分不出真正的相似；这一段是量级判断，不附精确数字。
- **成熟度**：L1。判据：接口稳定、不被单一供应商锁定，且返回原文——正确性可由使用者当场核对。
- **一个常被忽略的前置条件**：检索层不创造信息，它只是把已有的信息摊开。所以如果组织还没有「决策要写下来」的习惯，先补习惯再谈检索——顺序反了的结果是查不到东西，然后得出「AI 没用」的结论，而真正的原因是语料是空的。

最小落地顺序，四步做完再谈优化：

1. **先把语料收齐**：ADR 与决策日志落到同一个可检索目录，形态无所谓（Markdown 即可），但必须在一个地方。
2. **补最小元数据**：日期、决策类型、是否已复盘。少而必填，胜过全而无用。
3. **只做「按语义检索 + 返回原文」**：这一版**不要做摘要**——摘要会引入新的生成物，而这一步的价值恰恰在于返回原文。
4. **观察是否有人重复使用**：若三个月内没人第二次打开它，问题在语料质量，不在检索技术，此时换更强的模型不会有任何改善。

第 2 步的「最小元数据」值得展开，因为它是这一层唯一容易做错的地方——字段加多了没人填，加少了检索出来没法判断适用性：

| 元数据字段 | 必要性 | 谁维护 | 缺了会怎样 |
| --- | :---: | --- | --- |
| 决策日期 | 必填 | 提交者（提交时自动） | 无法按时间线看决策演化 |
| 决策类型（Type 1 / Type 2） | 必填 | 提交者 | 检索会把不可逆决策的先例套用到可逆场景 |
| 当时的前提假设 | 必填 | 提交者 | 先例被当成结论复用，而它的适用条件已经变了 |
| 最终结果 | 选填但**应追踪** | 复盘主持人 | 检索只会找到「当时的想法」，找不到「后来怎样了」 |
| 引用到的表 / 指标 | 选填 | 可从 ADR 正文抽取 | 复盘时说不清当时依据的是哪个指标、口径有没有被改过 |

#### 5.2.3 决策数据的闭环（Decision Intelligence / Decision + KG / Decision Graph）

- **旧做法与它的卡点**：决策做完就散了。决策文本在 ADR 里、执行数据在数仓里、结果好坏在某个人的印象里。三者不通，所以组织无法回答一个最朴素的问题：「我们这类决策的成功率是多少」。没有这个数，决策能力就无法被校准，只能靠换人——而换人恰恰是最贵、最慢、最不可复制的校准方式。
- **AI 改变了什么机制**：把「决策」变成数据栈里的一类**一等对象**——有 schema、有 Owner、有上下游引用，于是决策可以被 join、被统计、被回放。机制上改的是**接口边界**，不是模型能力；这里 LLM 甚至可以完全不参与。这一点很关键：这个方向被普遍归到「AI 演进」名下，但它真正的技术动作是把决策接进数据栈，模型只是让文本非结构化的部分（会议纪要、理由陈述）变得可抽取。
- **由此得到的**：因为决策成了可 join 的对象，所以「这个决策引用了哪些表与指标」「这类决策历史上结果如何」第一次可以计算。本主题的因果链在这里和 §6 的结论一致：**判断力能不能被校准，取决于决策与结果之间有没有一条可回放的路**，而不是取决于复盘会开得多诚恳。它也是 5.2.2 检索层的前提——`assumptions` 与 `rejected_reason` 如果不进 schema，检索出来的先例就永远缺一半上下文。
- **由此付出的**：**监督信号极稀疏**。决策的反馈周期通常是季度到年，而且同一时期有几十个决策同时作用，把结果归因到单个决策在统计上很难。没有结果标签，「DI 闭环」就只是一本决策台账；而台账的成本是实打实的：要有人持续写回、要维护 schema、要处理「预测的指标中途被改了口径」这类破事。更糟的是**半闭环比不闭环更危险**：一个只记了决策、没记结果的图谱，会让人以为组织已经在做决策校准。
- **由此付出的（续）**：把决策建成资产的代价还包括**写回压力反向扭曲行为**。一旦「预测是否命中」被记录并进入考核，人会倾向于把 `predicted` 写成模糊区间，让预测永远「不算错」。这是任何度量体系都会遇到的反身性问题，需要在设计时就承认，而不是等它发生——典型做法是区分「预测质量」与「结果好坏」：预测写了可观测指标并且被证伪，是**好**的复盘素材，不是过错。
- **证据与来源**：【公开】Gartner 的年度战略技术趋势清单（*Top Strategic Technology Trends*）中，Decision Intelligence 被单列于 2022 年那一期（本章 §1.4 演进历程同记 2022，两处口径一致）；引用时请回到 Gartner 原始新闻稿确认年份，不要转述本节或 §1.4 的年份。但**「被列为趋势」与「有第三方生产闭环案例」是两件不同的事**：前者是分析师判断，后者需要可核验的部署与效果；本节未找到满足后者的公开材料。
- **成熟度**：L3（闭环优化）；若只做决策台账与看板，可视为 L2 的可试点能力。判据：图谱与闭环的输入（结果标签）在多数组织里不存在，且无第三方生产案例。**采购前先问三个问题**：结果标签谁写？写回周期多长？`predicted` 字段是否强制？三个都答不上来，就先不要买平台——买了也是买一本台账。
- **三个常见失败形态**：① **只记决策不记结果**——平台上线了，台账越来越厚，但没人知道哪个决策对了；② **记了结果但不回填**——字段是有的，压力是没有的，半年后字段全是空的；③ **回填了但没人看**——复盘会照开，结论永远是「整体符合预期」。前两个是接口问题，第三个是激励问题；三者的解法不同，不要指望一个平台同时解决。
- **为什么这个方向常被误归到 AI 名下**：因为它手上的活（把文档变成字段）的确是语言模型擅长的，于是「抽取」这一步的能力被当成了「闭环」这个整体的能力。区分方法很简单：把 LLM 换成规则匹配，闭环还成不成立？成立，就说明核心不是 AI；不成立，才需要重新评估依赖关系。

```text
把「决策」当成数据栈里的一等对象（这才有 join 的可能）
  decision_id / decided_at / deciders(A) / type: Type1|Type2
  options:      [ {option, rejected_reason} ]      ← 抗锚定：备选必须留痕
  assumptions:  [ {claim, basis: 公开|推算|经验, owner} ]
  predicted:    {metric, expected_range, by_when}  ← 让复盘成立的唯一字段
  actual:       {metric, observed_range, at}       ← 这一行没人愿意写
  refs:         [dataset, metric, adr, rfc]        ← 这个决策依据了哪些数据与文档
  ────────────────────────────────────────────
  关键：predicted 与 actual 是闭环的两端。
       缺 predicted，复盘只能退化成「大家回忆一下当时怎么想的」；
       缺 actual，图谱只是更贵的台账。
```

#### 5.2.4 人机分工与解释（Human-in-the-loop / 可解释性 / Nudge 2.0 / Behavioral AI / AI Constitutional）

- **旧做法与它的卡点**：人的判断既不可复现（同一个人两次可能给出不同结论），也不可审计（说不出依据）；而团队又不敢把判断整个交出去，于是退回到「全都上会」——上会的成本高到大部分决策只能拍脑袋，两头都没占住。
- **AI 改变了什么机制**：改变**人机分工**——AI 穷举候选与风险清单，人保留批准权。§3 的 Reversibility Analysis（Type 1 不可逆 / Type 2 可逆）恰好给了这个分工一条边界：把 AI 放在可逆侧，把人的注意力留在不可逆侧。
- **由此得到的**：因为 AI 能在可逆、低成本的环节穷举候选，所以人的时间被释放到真正不可逆的判断上——「选项只有两个」常常不是因为世界上只有两个选项，而是因为没人愿意再想第三个，而 ADR 里那条 `Considered Options ≥ 3` 的硬要求，正是靠人工成本撑着才难以执行。
- **由此付出的**：**责任与能力分离**。人不会逐条审 AI 的全部输出，只会审「看起来可疑」的那些；所以 Human-in-the-loop 的实际把关强度取决于 **AI 错误的可察觉性**，而不是 loop 里有没有人。这是 §2 的权威偏误在 AI 场景中的变体：权威偏误原本指「资深架构师说 XX 不行，新人就信了」，现在权威换成了模型，而模型的「说得流畅」比资深架构师的资历更难反驳——资历可以质疑，流畅很难。
- **由此付出的（续）**：这条推论对可解释性工具同样致命。SHAP / LIME 解释的是「模型输出对输入特征的敏感性」，不是决策的因果依据；特征相关时贡献会被摊到多个相关特征上，读者拿到的是一个说得通但不忠实的故事——**可解释性幻觉带来的是更高的信任，不是更高的判断质量**。解释越好看，追问停止得越早，而追问停止才是真正的风险。
- **由此付出的（续）**：还有一个与 §2.1 直接冲突的代价——**决策疲劳**。AI 能让候选从 3 个变成 10 个，但待比较选项越多，比较负担越重，而人的比较能力不随选项数量线性增长。所以「让 AI 多列几个方案」如果不配「先粗筛并说明筛掉的理由」，净效果可能是更差的决策。把候选量交给 AI 扩增、把筛选理由要求成人必须写，是这一步的分工要点。
- **由此付出的（续）**：Nudge 2.0 的代价更直接。个性化干预需要个人行为数据（隐私与监控依赖），而平台优化的是「干预成功率」而不是「你的决策质量」，两个目标并不总是同向；同时异质干预更难做随机化对照，导致它的增量收益很难被证伪——**难以证伪的收益声称不构成选型依据**。行为科学里证据最硬的一条恰恰是最朴素的做法：改默认值。它有效是因为降低了「必须主动做一个动作」的成本，这个机制与「了解你这个人」无关（【公开】Madrian & Shea 对 401(k) 自动加入的研究，Quarterly Journal of Economics, 2001；具体数值以原文为准）。
- **Behavioral AI 的真实变化在哪**：把 Choice Architecture 用进 AI 产品界面，机制上换的是**表述的可变性**——传统界面里默认值与措辞是发布时定死的，生成式界面可以在每次会话里实时改写。于是框架效应（同一信息不同表述导致不同决策）的操控面变大，而用户之间不再可比、事后也无法复现「当时看到的到底是哪句话」。这是接口改良带来的**新治理问题**，不是架构变化；它的正确应对是把它当发布评审项（默认值是什么、选项有几个、用收益框架还是损失框架），而不是等出事后再追查。
- **关于 AI Constitutional**：Constitutional AI 是一套**训练方法**——用一组自然语言原则加模型自我批判来做对齐（【公开】Bai et al., arXiv, 2022）。它的目标是让模型的输出更无害，**不是**给组织提供决策程序。把它当治理规范用，是把方法论挪到了错误的对象上。真正可做、成本极低的是它的一半：**把组织的决策准则显式写下来，让模型按它给 ADR 自评**——这件事的价值不在于模型评得多准，而在于「写下来」这个动作本身逼着团队回答「我们的准则到底是什么」。
- **证据与来源**：LIME（Ribeiro et al., KDD 2016）【公开】、SHAP（Lundberg & Lee, NeurIPS 2017）【公开】、Constitutional AI（Bai et al., arXiv, 2022）【公开】、401(k) 自动加入（Madrian & Shea, QJE, 2001）【公开】。前三条说明方法本身有公开来源，**没有一条**说明它们能让组织的决策质量变好。「2024-2025：AI Agent 的『决策可解释性』成为研究热点」这条趋势，本节不为它单列方向、也不单列级别：研究对象从「一次模型输出」换成了「一条 Agent 的决策轨迹」，但可解释性的判定问题没有跟着变（这份解释忠实于模型了吗），所以研究热度不构成成熟度证据——热度是发表量，成熟度是接口与责任归属。
- **成熟度**：人机协同与可解释性工具 L2（可用，但正确性不可核）；Nudge 2.0 与「AI 决策宪法」L3（无公开生产案例，且各自的增量收益缺少可证伪的证据）。Behavioral AI 作为「选择架构用于 AI 界面」是 L2——它借用的方法早已生产可用，但生成式界面会实时改写选项与表述，使框架效应的影响面变大、可审计性变差，这条风险目前只有产品级观察、没有系统研究。
- **与 §7 的接口**：本章 §7 明确不提供「谁更好」的打分表（§7.1「为什么打分表会误导」）——它的对比对象是做法而不是工具，用的是 6 条判据而不是分数。按**能力 / 成熟度**看，AI 辅助这一类排得并不低；但换用**正确性可核对**这条标准重排，AI 辅助会低于 Red Team——不是因为它更笨，而是因为它的输出没有被独立核对的路径。评价标准换了，排序就会变，选型时请先明确自己在用哪套标准。

分工边界可以落成一张表，写清谁做、谁负责失败：

| 环节 | AI 做 | 人做 | 谁负责失败 |
| --- | --- | --- | --- |
| 列候选（Type 2 可逆） | 穷举并给出反方理由 | 判断有无遗漏 | 决策 Owner——「AI 没想到」不是免责理由 |
| 风险清单（Type 1 不可逆） | 可作为输入，但**不能替代** Pre-Mortem 的独立列举 | 各自独立写、再汇总 | 决策 Owner |
| 预测与假设 | 抽取成结构化字段 | 对 `basis`（公开 / 推算 / 经验）签字 | 假设的提出者 |
| 批准 | 不参与 | 批准并留名 | 批准人（RACI 的 A 只有一个，见 [§09 跨团队决策 §4.1](../09-cross-team-decision/09-cross-team-decision-section-4-sec4.md)） |
| 复盘 | 对齐 `predicted` 与 `actual` | 解释差异 | 复盘主持人 |

### 5.3 与本主题既有栈的接口在哪

不写「与 AI 结合」，写清接口边界：谁调用谁、数据以什么形态穿过边界、失败时谁负责。判断一个结合点值不值得做，就问一句——**这条边界上如果断了，谁会被叫起来修？** 答不上来的结合点，通常是没有 Owner 的结合点，它不会有人维护。

还有一条通用的形态要求：**数据以既有形态穿过边界**。ADR 是 Markdown，就别为了 AI 再造一份结构化副本；决策日志是文本，就让检索层去切块，而不是要求所有人改用一套新表单。原因很实在——再造副本等于多一份会过期的数据，而这次过期的不是血缘而是决策理由，过期之后没有任何自动校准能发现它。§4 的落地步骤里，唯一需要强制的字段是 `Considered Options ≥ 3` 与 `Pre-Mortem` 非空，其余都应当是可选，这条取舍同样适用于 AI 接入。

接口失效有三种形态，负责的对象各不相同，不要混为一谈：

1. **接口断（数据没到）**——例如 ADR 仓没同步到检查器，检查器报「无内容」。这是**工程失败**，由平台团队负责，监控能发现。
2. **契约漂移（数据到了但形状变了）**——例如 ADR 模板改了字段名，检查器仍按旧字段解析，输出为空却不报错。这是**工程失败**，但监控通常发现不了，只能在门禁里加「输出为空即失败」这类断言。
3. **语义错（数据对了但结论没用）**——例如检查器把「我们决定不采用 Kafka」判成锚定效应。这是**判断失败**，由评审人负责，且**只能靠人**——这一条没有自动化兜底，也不应有。

三条里只有前两条能靠工程手段兜底，第三条必须写进流程。由此得到一条通用原则：**门禁只拦形状，不拦语义。** 这也是为什么 §4 强制的必填字段里，唯一值得做成 CI 校验的是「字段是否填写」，而不是「内容是否合理」——后者一旦自动化，工具就会开始替人做判断，而本节整条主线都在说它不该做判断。

反过来，模型输出的形态越「像结论」，越容易诱发越界使用——一句「本 ADR 存在确认偏误风险」在作者眼里是提示，在评审记录里就可能被当成结论。所以接口设计上有一条要求：**输出的每条判断都必须带原文引用**。没有引用的判断，使用者无法核对，也就无法驳回；而无法驳回的判断会在几次使用后被默认接受，这正是「可解释性幻觉」在流程里的等价物。

| 结合点 | 接口形态 | 谁负责失败 | 现状 |
| --- | --- | --- | --- |
| ADR 仓 → LLM 检查器 | 输入 ADR Markdown 全文 + 12 种偏误清单；输出结构化 JSON（偏误项 / 原文引用 / 建议）。模型**不产出任何否决权** | 评审人。模型漏检或误报都不转移评审责任 | 可试点（作者自查环节） |
| Decision Journal → 向量索引 | 文档切块 + 嵌入 + 元数据（日期、决策类型、当时假设、结果）；查询返回原文片段 | 使用者。系统不承诺召回率 SLO，使用者必须自己判断这条先例适用不适用 | 生产可用 |
| 决策对象 → 被引用的数据集与指标 | 决策条目反向引用 dataset 与 metric；数据资产一侧怎么编目是别章的范围，本节只要求「引用了什么」可查 | **无人**。表改名由数据资产侧发布、决策文本由决策 Owner 维护，两边怎么对齐没有归属 | 少见，需自建 |
| 决策结果 → 复盘标签 | 人工写回 + 元数据 schema | **无人**。这是大多数组织里断掉的那一环，也是 L3 判定的依据 | 基本断裂 |
| ADR 模板 → CI 门禁 | 提交时校验 `Considered Options ≥ 3`、`Pre-Mortem` 字段非空 | 提交者。校验只查**字段有没有填**，不判断填得好不好——这个限制要写在门禁说明里 | 建议先做，成本最低 |
| Choice Architecture → AI 产品界面 | 默认值、选项数量、表述框架成为发布评审项 | 产品负责人。框架效应的责任从「用户自己不理性」转到「设计者做了选择」 | 可试点 |

### 5.4 公开进展与文献

分类口径先说清。规范要求分「论文 / 官方 release note / 第三方生产案例」三类列，而本主题几乎没有产品形态，没有 release note 可查——所以中类用它的等价物：**官方标准与规范文档**，判据与 5.1 对过程类方向用的判据一致（公开、可长期查证、有发布机构与年份）。第三类也要先把期望降一格：决策流程的第三方材料只能证明「有人长期这么跑」，不能证明「这么跑更好」，因为组织不会公开对照实验。三类的分工是：**论文给机制，官方文档给「规则定在哪一年」，第三方案例只给可行性。**

**一、论文 / 著作（给机制）**

- **偏误与前景理论**：Tversky & Kahneman, *Judgment under Uncertainty: Heuristics and Biases*, Science, 1974；Kahneman & Tversky, *Prospect Theory: An Analysis of Decision under Risk*, Econometrica, 1979。【公开】注意 §2.2 里的 λ ≈ 2.25、α ≈ 0.88 来自后续的累积前景理论，数值随估计样本与实验设计变化，属量级而非定值——不要把它们当作可直接代入业务模型的常数。
- **双过程理论**：Kahneman, *Thinking, Fast and Slow*, 2011。System 1 / System 2 的二分在学术界一直有争议，引用时宜作为通俗框架而非定论。【公开】
- **默认值的力量**：Madrian & Shea, *The Power of Suggestion: Inertia in 401(k) Participation and Savings Behavior*, Quarterly Journal of Economics, 2001。【公开，具体数值以原文为准】这是「改默认值比说服个人有效」最常被引用的证据，也是 Nudge 2.0 应当对标的基线。
- **事后解释方法**：Ribeiro et al., *「Why Should I Trust You?」: Explaining the Predictions of Any Classifier*, KDD 2016（LIME）；Lundberg & Lee, *A Unified Approach to Interpreting Model Predictions*, NeurIPS 2017（SHAP）。【公开】两篇都给方法，不给「决策因此变好」的证据。
- **模型的自我批判式对齐**：Bai et al., *Constitutional AI: Harmlessness from AI Feedback*, arXiv, 2022。【公开】请特别注意它的目标是**无害性对齐**，不是决策治理——这是本节最容易被张冠李戴的一条。
- **人物与时间点**：Daniel Kahneman 于 2024 年 3 月去世（【公开】多国主流媒体讣告，2024）。这一条解释了一种常见的引用错误：把 2024 年关于决策心理学的新闻当成研究进展，实际是讣告与纪念文章。

**二、官方文档 / 标准（给规则与时间点）**

- **AI 管理体系标准**：ISO/IEC 42001:2023, *Information technology — Artificial intelligence — Management system*, 2023 年 12 月发布。【公开】它可被第三方认证，但管的是「组织有没有一套 AI 治理体系」，不判定「某一次决策的解释是否忠实」——这正是 5.1 表末行「标准化」一项仍停在 L3 的原因：标准的对象还只到体系层，没到单次决策。
- **风险管理框架**：NIST AI Risk Management Framework 1.0（NIST AI 100-1），2023 年 1 月。【公开】它给的是一份「识别 — 度量 — 管理」的组织动作清单，不含决策质量的度量方法，也不给量化阈值；把它当成可打分的评估表会误用。
- **监管文本**：欧盟 AI Act（Regulation (EU) 2024/1689），2024 年生效。【公开】这是本节唯一带法律强制力的时间表：高风险系统的人类监督义务被写进条文，也是 5.6 那条「人保留批准」预测的外部依据；至于它怎么落成工程要求，取决于各成员国的执行细则。

**三、第三方生产案例（给可行性，不给效果）**

- **把「失败复盘」制度化**：Google 的 blameless postmortem 文化（*Site Reliability Engineering*, O'Reilly, 2016，其中一章专讲这套流程）【公开】。它证明「要求当事人写下失败原因而不追责」可以长期运行；但公开材料是实践描述、没有对照组，不能据此说它提升了决策质量——而且它记的是**失败原因**，不是决策前的**预测**，与 5.2.3 要的 `predicted`/`actual` 标签不是一回事。
- **把「写下来」变成强制流程**：Amazon 的六页叙述式备忘（Bezos 2017 年股东信，2018 年公开；另见 Bryar & Carr, *Working Backwards*, 2021）。【公开】它的机制正是本节主线：先付写作成本，换回一份可以被逐句质疑的文本；同样没有公开的对照数据，所以它证明的是可行，不是更优。

三类来源的可靠性不同，引用时别混：**论文**给的是机制与条件，通常有明确适用范围；**官方 release note 与标准文档**给的是「这个版本有什么 / 规则定在哪一年」，两者都不承诺效果；**第三方生产案例**给的是「有人真的跑起来了」，但往往缺对照组，所以只能证明可行、不能证明有效。本节对 L1 的要求是三类里至少要有一类**独立于作者**的证据，而不是只有厂商自己的说法。

本节刻意不列两样东西：**具体产品版本号**与**第三方案例里的效果数字**。前者半年就会过期，后者在本节无法核验；写上去只会让读者误以为它们比上面这些公开文献更硬。需要版本相关的判断时，请回到 5.1 的判定方法——自己去查所用组件的 release note，而不是相信一份会过期的清单。

上面这些条目都能按「作者或发布机构 + 出处 + 年份」三要素检索到原文，这是本节选它们的唯一标准：不是它们支持本节的观点，而是**读者可以自己去读、并得出不同结论**。凡达不到这三要素的，本节一律改写成判定方法或标注为 L3。三类的空置情况也要交代：**第一类不缺，第二类里没有一条是产品 release note**（本主题没有产品），**第三类里没有一条带效果数据**——这两个缺口是主题性质决定的，不是本节查漏，但读者据此就该明白：本节任何关于「效果」的判断都不会来自 5.4，只能来自 5.6 里写明的证伪信号。

### 5.5 被过度宣传的部分

**「AI 能识别决策中的认知偏误」** —— 实际是它只能识别**已经被写进文本的**偏误痕迹 → 因为模型只看得见上下文里的内容，「三个候选里有一个从来没被写进 ADR」「会上有人反对但没人记录」都不在上下文里，而这两件事恰恰是偏误最常出现的位置 → 它会成真的时点，是决策过程本身被完整记录之后：每个候选、每次异议、每次否决都留痕（也就是先有 §4 的 Decision Journal 与 ADR 强制字段），检查器才有材料可查。顺序反了就是空转：先买检查器、后补记录，检查器只会告诉你文书写得不够全。**怎么识别这类过度宣传**：看它把偏误当成「文本问题」还是「过程问题」——前者只需要一份文档，后者需要一份记录。

**「AI 可解释性（SHAP / LIME）能让 AI 决策可审计」** —— 实际是它解释的是模型输出对输入特征的敏感性，不是决策的因果依据 → 因为归因是对模型的局部近似，特征相关时贡献被摊薄，形成一个说得通但不忠实的故事；而「不忠实但好看」的解释比没有解释更危险，因为它终结了追问 → 它会成真的时点，是解释对象从「输入 → 输出」的函数关系换成「决策 → 结果」的因果链；后者靠对照实验与灰度发布得到，不靠解释工具。这也正是 Type 1 / Type 2 分层在 AI 时代仍然成立的原因。**怎么识别**：问「这张图能不能反过来推翻模型」——不能推翻的图是说明，不是证据。

**「个性化 Nudge（Nudge 2.0）比通用默认值更有效」** —— 实际是行为科学里证据最硬的那一条恰恰是「改默认值」这种最朴素的干预 → 因为默认值有效是因为它降低了「必须主动做一个动作」的成本，这个机制与是否了解这个人无关；个性化反而引入了个人行为数据的采集与监控依赖，并因干预异质而更难做随机化对照，导致增量收益难以证伪 → 它会成真的时点，是个性化干预能被随机化对照检验并公开出可复现的对比结果之后。在拿到那个结果之前，把预算放在默认值设计上的期望收益更高。**怎么识别**：看它给的是不是「更懂你所以更有效」这类机制描述——「更懂」不是机制，「降低了一次主动动作」才是。

三条被过度宣传的说法有一个共同结构：**它们都把「模型有能力做某件事」直接等同于「组织因此会变好」。** 中间缺的那一段，恰恰是本节花最多篇幅讲的东西——成本结构、激励结构、监督信号。识别这类说法的通用问法是：「如果这个方法真的有效，我们会先看到什么变好？」答不出前半句的，通常也答不出后半句。

### 5.6 未来 3–5 年：可证伪的预测

每条预测都配两个信号：**会成真的信号**是别人能替你观察到的事件，**会证伪的信号**是你自己也能承认「我错了」的证据。写不出这两个信号的，就不是预测，是态度。

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| 决策文档（ADR / 决策日志）会成为 AI 取数与 Agent 的上下文来源之一，但不会长成独立的产品品类 | 数据目录 / BI / Agent 平台出现「索引 ADR 仓」的正式功能（release note 级），而不是只有博客演示 | 三年后决策文档仍完全孤立于数据栈，没有任何平台把它当数据源 |
| LLM 偏误检查会进入 ADR 模板的**必填校验**，但不会进入有阻断权的门禁 | 主流 ADR 工具链出现针对 §4.1 那两个必填字段的「校验 / 缺项提示」插件 | 出现公开案例：LLM 的影响分析直接阻断合并，且被组织广泛接受并长期保留 |
| 组织治理的主要抓手会回到**结构性默认值**（模板必填项、CI 字段校验、发布清单），而不是个性化提醒 | 公开治理材料里，模板与门禁的改动明显多于提醒与推送的改动 | 出现大规模、可验证、可复现的个性化决策干预生产案例（含对照组） |
| AI Agent 不会拿到不可逆决策的批准权，「人保留批准」会被写进治理文档 | RACI / DACI 模板新增「AI 辅助环节」说明，而 A（Approver）仍然是人 | 出现监管文件或大型组织公开章程，把不可逆决策的批准权授予自动化系统 |

这四条预测有一个共同前提：**它们都在赌「人的责任不能被转移」这条约束不会变**。如果这条约束变了——比如监管明确允许某类不可逆决策由系统批准并配套责任机制——那四条会一起失效，届时本节关于 L2 / L3 的判断也要整体重估。这也是为什么 5.1 要求给每条级别标注写上「下次复核时间」，而不是把它当成一次性结论。

时间尺度也要说清：3–5 年里会变的是**工具层**（检索、抽取、表单、界面），不容易变的是**约束层**（责任归属、激励结构、监督信号）。把预测写在工具层的，多半会「对」但没用；写在约束层的，才是值得跟踪的那几条——本节四条都在约束层。

还有一个反向信号值得记下来：如果某一天「决策质量」可以被外部审计（例如以第三方评估组织决策流程为业的服务出现并被采购），那本节对 L3 的判断要上调——因为外部审计会强制产生结果标签，而结果标签正是当前所有闭环类方向的卡点。

### 5.7 给架构师的行动建议

先按可逆性给决策分层（§3 的 Type 1 / Type 2），再对号入座；同一个团队的两类决策，做法应当完全不同。

两条不要做的事写在前面：**不要在决策链上引入没有人的责任锚点**（RACI 的 A 必须只有一个，且必须是人，见 [§09 跨团队决策 §4.1](../09-cross-team-decision/09-cross-team-decision-section-4-sec4.md)）；**不要为了让工具好看而改决策的写法**——如果某个平台要求你把决策填进固定表单，先问这个表单能不能进版本库、能不能被 diff。不能，就不要把决策迁进去，否则你换来的可检索性，代价是决策记录失去版本历史。

```text
按可逆性与成熟度选动作（不是按技术热度）
  决策不可逆？
    ├─ 是（Type 1）→ Pre-Mortem + Red Team + Kill Criteria
    │                 AI 只允许出现在「列风险」的输入端，不允许出现在批准端
    └─ 否（Type 2）→ 轻量 ADR + Considered Options ≥ 3
                     AI 可列候选、可自查偏误，人拍板
  ────────────────────────────────────────────
  无论哪类，先做这三件（今天就能做，零依赖）：
    ① 决策写成 Markdown 进版本库 —— 否则后面全部无从谈起
    ② ADR 模板加两个必填字段：Considered Options ≥ 3、Pre-Mortem
    ③ predicted 写成可观测指标 + 时间点
  ────────────────────────────────────────────
  这三件都不需要任何 AI 组件，但它们是所有 AI 方向的前置条件。
```

| 你的处境 | 现在就该做 | 一年内观察 | 明确不要做 |
| --- | --- | --- | --- |
| 个人 / 小团队，还没有 ADR 流程 | ADR 模板先加 `Considered Options ≥ 3` 与 `Pre-Mortem` 两个字段；决策写成 Markdown 进版本库 | Decision Journal 的检索是否真的被人用过一次以上 | 不要买 Decision Intelligence 平台；不要先搭决策知识图谱 |
| 已有 ADR 与评审流程，想引入 AI | 把 LLM 放在**作者自查**位置（提交前跑一遍偏误检查），人保留否决权 | LLM 检查的误报率是否高到被评审人集体忽略 | 不要让 LLM 检查挂进 CI 阻断；不要用它替代 Reviewer 写的反对意见 |
| 正在做 Type 1（不可逆）决策 | Pre-Mortem + Red Team + 明确的 Kill Criteria；把 `predicted` 写成可观测指标与时间点 | 复盘时 `actual` 是否真的被写回，谁写的 | 不要用「AI 生成的风险清单」替代 Pre-Mortem 的独立列举——独立列举的价值就在于各自不知道别人写了什么 |
| 想用「AI 可解释性」做合规举证 | 用它做排错；举证改走实验设计与灰度对照 | 监管指南是否开始区分「解释」与「证据」 | 不要把 SHAP / LIME 的图当因果证据提交 |
| 在建决策数据资产 | 先定 schema：决策、候选、假设、预测、结果、引用六类字段 | 结果写回是否有具体的责任人与时限 | 不要在 `actual` 写不回来之前先建图谱——没有结果的图只是更贵的台账 |

「明确不要做」这一列值得单独说一句：这五条的共同点是**它们都能在看不到效果的情况下持续消耗预算与注意力**。一个平台买进来就有界面、有报表、有好看的图，唯独没有决策结果的标签；一套图谱搭起来就有节点、有连线，唯独连线的一端是空的。判断一件事现在做是不是浪费，标准只有一条——**它今天能不能产生一个会被使用的输出**。ADR 模板加两个必填字段，今天就会被使用；个性化 Nudge 引擎，半年后可能还没人说得清它改变了什么。

### 5.8 小结

> 本节小结：AI 在决策心理学上真正改变的是**唯一一条机制——决策记录的检索成本**：把「只有记得的人能用」变成「按语义查得到」，代价是检索出的第一条先例会成为新的锚。它**没有**改变的是判断本身：偏误产生于动机与处境（承认失败的代价、否决上级的代价），而这两样东西都不在模型的上下文里；它也没有解决监督信号稀疏——决策的结果要等到季度甚至更久才知道，且无法归因到单个决策。因此本节唯一的 L1 是检索，其余的成熟度由「结果标签是否存在」和「正确性能否被使用者核对」这两条判据决定，而不是由模型能力的进步速度决定。
>
> 一句话记住本节：**AI 让「找到过去的决策」变便宜了，但没有让「做出这次决策」变容易。**
>
> 本节所有判断都可以被证伪，且都写明了证伪信号——这是它区别于趋势清单的地方。若要把本节压缩成一条可执行的话：先把决策写下来，再把它们变成可检索的，最后才考虑让模型对自己说点什么。
>
> 💡 **思考锚点**：把你们的决策日志做成向量检索之后，检索出的第一条先例会成为这次决策的新锚点（§5.2.2 写明的代价）——你打算用什么信号区分「这条先例真的可比」还是「它只是语义最近」？再落一步：§5.2.3 的闭环要求结果（actual）能写回，若 actual 没人在时限内填，你检索到的只是候选与假设、不是结果——这一条在你司由谁负责？
