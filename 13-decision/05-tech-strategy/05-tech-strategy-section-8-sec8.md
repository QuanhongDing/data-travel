### 8.11 本章小结

本节收录 **55 道题**，覆盖 9 个原 PDF 子章节（§4.5 / §5.6 / §8.6 / §14.2 / §14.7 / §17.8 / §19.3 / §19.5 / §20.7）。虽然题源分布于"数仓建设""安全体系""统一数据服务""流处理""新一代架构""技术路线图""全球化数据平台"等不同章节，但**本文件只保留与「技术战略与路线图」这一子主题强相关的题目**——即那些考察"面向 3-5 年的技术决策、架构演进判断、路线图规划"的题。其余纯工程题（如单纯的小文件调参）已在本主题作答中按"战略视角"重新组织。

九个子章节可归为四条主线：

1. **大规模集群治理（§4.5）**：小文件、容量、安全、Metastore、成本治理、YARN 调度、生命周期——是"存量平台的稳态运营"，也是技术战略的**基本盘**。
2. **安全与合规（§5.6）**：Kerberos / Ranger / Sentry 三件套、云原生适配、隐私法规、细粒度授权、混合云管控、零信任——是技术战略的**约束边界**，AI 与数据出境的强监管让这条线越来越重。
3. **架构演进（§8.6 / §17.8 / §19.3）**：Lambda / Kappa / Lakehouse / 流批一体 / 存算分离——是技术战略的**主干方向**，answer 的核心永远是"何时从 A 演进到 B"。
4. **前沿与全球化（§14.2 / §14.7 / §19.5 / §20.7）**：流批一体的实时演进、Kappa 迁移工程、3-5 年路线图、AI for Data、跨国数据平台、Data Mesh——是技术战略的**未来储备（H3）**。

**答题心法（三条）：**

- **先定坐标系，再谈取舍。** 技术战略题的答案很少是"选 A"或"选 B"，而是"在约束 X 下选 A，在约束 Y 下选 B"。面试官真正想听的是**判断依据**——成本、时效、准确性、团队能力、合规五者的权衡，而不是某个技术的优缺点清单。任何一道题，先问"这道题的约束是什么"，答案自然浮现。
- **引用头部企业实践，落到具体人名 + 产品 + 时间。** 泛泛说"业界都用 Flink""大家都在上湖仓"是低分回答；说到"Netflix 是 Iceberg 最大生产用户""Uber 是 Hudi 主要贡献者""阿里用 Paimon 做流批一体""Databricks 提出并实现 Lakehouse"，才说明你真的读过一手材料。凡引用不确定的案例，宁可不引。
- **战略必须能翻译成业务价值 + 可度量的 KPI。** 无论是集群治理、安全合规还是架构演进，最终都要回答"这给业务带来什么"——成本降 X%、时效从 T+1 到分钟级、口径事故降为 0、合规风险归零。能把技术决策翻译成业务语言，是资深架构师与资深工程师的分水岭。
