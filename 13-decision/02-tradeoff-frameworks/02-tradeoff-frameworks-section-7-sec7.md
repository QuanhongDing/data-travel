## 7. 与其他方法对比

### 7.1 先立判据：为什么打分表会误导

若把「拍脑袋 / 加权打分 / AHP / TOPSIS / AI 辅助」五种做法按 6 个维度逐格打分（其中 5 个维度是 1–5 分，「适用规模」一档按规模分类取值），其中「AI 辅助」在共识构建、跨团队适用、AI 友好度三列同时拿到 5 分，于是它的排序最高。问题不在分数准不准，而在**这几列本身不可比**：「共识构建 5 分」在 AI 辅助那一格的含义是「LLM 输出一份结构完整、措辞笃定的对比文档，会议室里没人当场反驳」——这得到的是**显得有共识**，不是**真的有共识**（有人被说服 vs 有人放弃追问，打分表区分不了）。同一列在 AHP 那一格的 4 分却来自另一种机制：两两比较把判断拆小，参与者能在具体的一对比较上指出「我不认同这一次比较」。两种机制给出同一个数字，说明这个数字没有承载机制信息。第二个问题是**维度不可加**。「易用性」与「量化程度」不是可以互相折价的商品：一个方法即使量化程度满分，如果它的判据不显式、权重不可追溯，它输出的是**数字的形态**而不是**可核验的量化**；而「易用性 5 分」恰恰是判据不需要显式化的同义词——这两列在这个意义上互为因果而不是彼此独立。把两个强相关的维度分别打分再相加，等于把同一条信息计入两次，并且方向相反。

第三个问题是**候选不同质**。加权打分 / AHP / TOPSIS 是**聚合方法**（把多维压成一维）；CAP / PACELC 是**约束定理**（划出不可行域，不做排序）；TCO / CBA / NPV 是**货币化方法**（把维度换成同一种单位）；ADR / Tech Radar / Decision Graph 是**载体**（记录与复用结论）。它们作用于决策流程的**不同环节**——筛除 → 聚合 → 记录 → 复用——彼此不是替代关系，放进一张表逐格评分，等于把「筛子、秤、账本、档案柜」放在一起比谁更「好用」。

第四个问题是**阈值凭空来**。决策树写「单团队 + 低复杂度 → 加权打分（Excel）」「跨团队 + 中复杂度 → 加权打分 + Sensitivity + ADR」「战略级 + 高复杂度 → AHP + Scenario + TCO + AI 辅助」，但「低 / 中 / 高复杂度」没有度量：是判据数量？参与方数量？还是候选数量？三条对方法成本的压力完全不同——AHP 的成本随**判据数**二次增长，共识成本随**参与方数量**超线性增长，而填格子成本随**候选数 × 判据数**线性增长。一个没有度量的「复杂度」，等于把决策权还给直觉。本章的做法是：决策树的每个节点只问**可观测的事实**（这个决策选错后多久能改回来、格子里的数值能不能拿到、分歧在判据还是权重），阈值一律在树下给出推导链。

第五个问题是**分数不可复现**。同一个团队隔一个月重打一次那张表，五列里总有两三格会变——不是因为他们改变了看法，而是因为 1–5 的锚点没有任何外部参照。一个方法要可信，最起码要满足「不同人拿着同一份判据能打出接近的分」，而 1–5 的整数刻度做不到；相对比较类方法（Pugh Matrix 的 +/−/=）之所以放弃绝对刻度，正是为了绕开这一点。反过来说，如果一张打分表的每一格都能追溯到某个可核验的事实（报价单、压测报告、官方文档的限制条款），它的可复现性就不依赖刻度——**可追溯的格子才是分数，不可追溯的格子只是偏好**。

**本章采用的 6 条判据**：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| 不可协商项 | 有没有「无论如何不能违反」的约束（合规 / 许可 / 一致性硬指标 / 成本上限） | 有 → 判据必须先做筛除；任何加权模型都会把它折算成可扣的分 |
| 可逆成本 | 选错之后多久能改回来、要动谁 | 决定这个决策值不值得配重方法：可逆且便宜时，重方法是净亏 |
| 判据显式性 | 权重和判据是写下来的，还是只存在于某个人的判断里 | 决定结论能否被质疑与复用：不可质疑的结论只能靠人事变动推翻 |
| 数据可得性 | 每个格子的数值从哪来（文档 / 压测 / 报价 / 拿不到） | 决定方法是否可行：AHP 与 TOPSIS 需要数值，定性信息只能进相对比较类方法 |
| 参与方数量 | 结论需要几方同意、谁是最终决定者 | 决定共识成本项：参与方变多时，方法的作用从「算」变成「对齐」 |
| 结论载体 | 决策记不记、记在哪、给谁看 | 决定组织级复用：不落 ADR 的结论，下一年大概率被重新讨论一遍 |

### 7.2 候选方案全景

| 方案 | 定位 | 核心机制（一句话） | 典型使用者（【经验】） | 许可 / 商业模式 |
| --- | --- | --- | --- | --- |
| 拍脑袋（直觉 / 权威 / 类比） | 最小流程决策 | 不写判据，由最有话语权的人或最近一次经验给出结论 | 个人、初创、可逆成本低的决策 | 免费 |
| 加权打分（Weighted Scoring / Decision Matrix） | 多准则聚合 | Score = Σ w_j × s_ij，把判据与权重压成一个标量 | 最常见的选型模板 | 通用 |
| Sensitivity Analysis（敏感性分析） | 结论稳健性检验 | 扰动权重 w_j，看排名是否翻转 | 与加权打分配对 | 通用 |
| Pugh Matrix | 相对基准比较 | 每维只与基准选项比 +/−/=，不做绝对打分 | 设计 / 工程决策 | 通用 |
| AHP（层次分析法） | 权重推导 | 两两比较构造判断矩阵 → 特征向量求权重 → CR 一致性检验 | 战略级、跨部门选型 | 通用（教材与商业工具） |
| TOPSIS | 按距离排序 | 归一化决策矩阵，算到正负理想解的距离 | 工程评估、学术 | 通用 |
| ELECTRE | 按优序淘汰 | 用一致 / 不一致阈值构造「优于」关系，可设否决条件 | 学术；工程落地少见 | 通用 |
| Utility Function / Risk-adjusted Scoring | 把偏好写成函数 | 用效用曲线把风险偏好并入评分 | 已有量化风险偏好的组织 | 通用 |
| Trade-off Table | 显式化权衡 | 逐个选择写出「换来什么 / 付出什么」，不产生总分 | 与 ADR 配对使用 | 通用 |
| CAP / PACELC | 硬约束定理 | 分区期间 C 与 A 二选一；无分区时在延迟与一致性间选 | 分布式存储、消息选型 | 通用 |
| TCO / CBA / NPV（含 IRR） | 货币化 | 把所有成本收益折算成现金流并折现 | 自研 vs 采购（详见 §03） | 通用 |
| ADR（架构决策记录） | 决策载体 | 记录 Context / Considered Options / Outcome / Consequences | 工程组织 | 通用（【公开】Nygard, 2011） |
| Tech Radar / 参考架构 | 组织级前置结论 | 把已决策门类固化为「采用 / 试验 / 评估 / 暂缓」 | 大中型组织 | 通用（【公开】ThoughtWorks Radar, 2010 起） |
| Decision Graph + GraphRAG | 组织级经验复用 | 把历史 ADR 与决策关系建成图，用检索辅助新决策 | 大型组织、AI 辅助场景 | 通用 + AI 产品 |
| AI 辅助（LLM 生成候选 / 打分草案 / Review） | 跨族加速器 | 用 LLM 填决策矩阵的空白格子并给出理由 | 探索期团队 | 商业 LLM API |

这些候选其实分六**族**：**族 1 直觉型**（拍脑袋）；**族 2 聚合型**（加权打分 / Sensitivity Analysis / Pugh / Utility / Risk-adjusted）；**族 3 多准则矩阵型**（AHP / TOPSIS / ELECTRE）；**族 4 不折价型**（CAP / PACELC / Trade-off Table）；**族 5 货币化型**（TCO / CBA / NPV）；**族 6 载体与复用型**（ADR / Tech Radar / Decision Graph + GraphRAG）。同族内部可以逐项替换（加权打分换 Pugh 只改打分口径），跨族替换要动的是**流程环节**而不是工具。AI 辅助不属于任何一族——它改变的是「谁填格子」，不改变「格子里的判据从哪来」。**先分族再选，能省掉一半比较**。

### 7.3 机制差异：为什么它们表现不同

#### 7.3.1 聚合的可加性：把多维压成标量时丢掉了什么

**机制是什么**：聚合类方法隐含一个假设——维度之间**可以互相折价**（补偿性，compensability），即某一维的劣势能被另一维的优势抵消。加权和、Pugh 的 +/− 计数、效用函数都建立在这一点上；TOPSIS 只是把「加权和式的比较」换成「和理想解的距离」，补偿性并没有消失。

**实现差异**：

| 候选 | 维度间是否可折价 | 能否让一个候选出局 | 输出的形态 |
| --- | --- | --- | --- |
| 加权打分 | 完全可折价 | 不能（分低不等于出局） | 一个标量排序 |
| TOPSIS | 完全可折价（但按距离，对单维极端值更敏感） | 不能 | 一个标量排序 |
| Pugh Matrix | 完全可折价（相对基准） | 不能 | 相对基准的优劣 |
| ELECTRE | 部分不可折价（可设否决条件） | 能（弱否决关系） | 优序关系而非分数 |
| Trade-off Table | 不折价 | 不产生结论 | 逐项素材 |
| CAP / PACELC | 不可折价（存在性定理） | 能（直接排除整类候选） | 约束边界 |

**由此必然导出的性质**：因为加权打分是**完全补偿**模型，所以当某一维度是「不可协商项」时（合规不允许、许可不允许商用、写集必须线性一致），它会被其他维度的高分**折算掉**——总分照样能算出高分，否决项就此消失且不留痕迹。因为 CAP 是一个**存在性论证**（分区发生时不存在同时满足 C 与 A 的系统），所以它不能被书写成一个「可被性能拉平」的分数：把它写成 C=5 / A=3 / P=5 是对定理的误读，分区期间根本没有「三分」可选，只有取舍。因为 Trade-off Table 刻意不产生总分，所以它无法自动给出「选 A 还是选 B」，但它保留了「A 换来什么、付出什么」的完整信息——这是唯一能被下一个团队**复用**的形态，代价是必须有人真的做决定。

**公开证据【公开】**：Gilbert 与 Lynch 在 2002 年给出了 CAP 的形式化证明（*SIGACT News*, 2002）；Brewer 在 2012 年的回顾文章中把结论修正为「分区期间如何在 C 与 A 之间取舍」（*IEEE Computer*, 2012）——这条修正本身说明 CAP 的读法是取舍规则，而非三维评分表。判定方法：打开你的候选方案文档，找它**分区期间**的行为描述（不是「正常情况下多快」），找不到这一段的供应商通常没有把取舍写清楚。

**失效条件**：当所有维度确实能折算成同一单位时，聚合是成立的——TCO / CBA 就属于这种情形（全部货币化）。一旦有维度不可货币化（合规、团队技能、许可锁定），聚合就开始骗人，且骗得最狠的地方正是那些「一旦违反就无法补救」的维度。

#### 7.3.2 权重的来源：外生给定 vs 两两比较推导

**机制是什么**：权重是决策中最容易被隐藏的输入。所有聚合方法都要权重，差别在于权重从哪来：外生（层级、会议、默认模板）还是内生（由两两比较推导出来）。

**实现差异**：

| 候选 | 权重来源 | 权重可否被复算 | 一致性检验 | 成本随什么增长 |
| --- | --- | --- | --- | --- |
| 加权打分 | 外生给定（通常不可追溯） | 否 | 无 | 候选数 × 判据数（线性） |
| AHP | 内生于两两比较 | 可（特征向量可复算） | CR < 0.1 | 判据数的平方量级 n(n−1)/2 |
| TOPSIS / ELECTRE | 仍需外生给定 | 否 | 无 | 候选数 × 判据数 |
| Pugh Matrix | 不设显式权重 | 不适用 | 无 | 候选数 × 判据数 |
| Tech Radar | 组织级预先固化 | 不逐次复算 | 无 | 决策频率 |

**由此必然导出的性质**：因为 AHP 的权重来自**判断矩阵**，所以任何人对结果不服时可以指认「是哪一个两两比较导致了这个排名」——权重从「谁定的」变成「怎么算的」，这是它相对加权打分的唯一机制优势。但代价同样由机制导出：因为人对 n 个元素做两两比较时容易产生自相矛盾的判断（A 优于 B、B 优于 C、C 优于 A），所以 AHP 必须附一致性检验；而判断矩阵的元素个数按 n(n−1)/2 增长，所以 AHP 的成本随判据数**二次增长**。反过来，因为加权打分的权重是外生给定的，它的成本与判据数**线性相关**（每个判据只需填一遍格子）——判据少、参与方少时，加权打分比 AHP 便宜得多，这不是「更土的替代品」，而是成本结构上的正确选择。

**公开证据【公开】**：AHP 由 Saaty 于 1977 年提出、1980 年成书（Saaty, *The Analytic Hierarchy Process*, 1980），一致性比率 CR < 0.1 是该书给出的标准判据。判定方法：在你的 AHP 工具里看它是否输出 CR 值——只输出权重、不输出 CR 的工具，把一致性判断这一步省掉了，那它退化成了一张换了算法外壳的加权打分。

**失效条件**：当判据之间存在强相关（云上「性能」与「成本」在选型区间内高度耦合）时，两两比较会把同一条信息计入两次，权重被放大。更关键的是：CR 只检验「判断是否自相矛盾」，**不检验判断是否真诚**——如果参与者被要求在某一对比较上让步，两两比较只是把偏好拆成了更细的偏好，一致性照样能达标。所以 AHP 不会消解组织政治，它只会让政治留下更细的痕迹。

#### 7.3.3 判据的角色：约束、权重，还是记录

**机制是什么**：决策方法真正处理的对象不是候选，而是**判据**。同一条判据在流程里可以扮演三种角色——筛除用的硬约束、参与加权的可折价维度、供后人查证的记录——角色的选择决定了这条判据会不会失效。

**实现差异**：

| 候选 | 把判据当作什么 | 出错时的症状 |
| --- | --- | --- |
| 加权打分 | 全部可折价 | 否决项被高分拉平，总分掩盖「某维不可接受」 |
| AHP / TOPSIS | 权重的来源 | 权重被模板化，跨场景直接套用上一版权重 |
| Pugh Matrix | 相对优劣的观察项 | 基准选项一旦选错，全部比较随之偏移 |
| Trade-off Table | 解释材料 | 只有素材没有结论，流程停在半路 |
| CAP / PACELC | 定理约束 | 约束正确，但只管一致性一维，其余维度仍要另一套方法 |
| ADR | 决策档案 | 记录完备，但发生在决策之后，不参与决策 |

**由此必然导出的性质**：因为加权打分把所有判据放进同一个和式，所以它无法区分「扣分」与「出局」——一个不缺任何维度信息的模型，却不能让任何候选出局。因为 ADR 记录的是决策的**结果与理由**而不是决策过程，所以它不产生新信息，它降低的是「下次重新讨论同一件事」的概率——这是它唯一的、也是最重要的价值。因为硬约束的效果取决于**谁有权执行它**，所以在没有人能行使否决权的组织里，把判据写成硬约束只会让流程停在半路：约束需要一个能兑现它的角色，否则它只是一句备注。

**公开证据【公开】**：ADR 由 Michael Nygard 于 2011 年提出（其博客文章 *Documenting Architecture Decisions*, 2011，后被 ThoughtWorks 等组织推广）；AWS 的 Well-Architected 框架（2010 年代中期起发布、其后持续修订）把架构质量拆成**并列支柱**逐项作答、任何一项不能用另一项的优异抵消，而不是合成单一总分（AWS 公开材料 2015–2024，年份口径与本章 [§6 落地实践](02-tradeoff-frameworks-section-6-sec6.md) 的 AWS 案例一致）——「否决项独立于权重项」这一原则的公开实践形态，与 §6 那个案例里写明的「把『否决项』与『权重项』分开，而不是把所有维度合成一个分数」是同一件事。

**失效条件**：当判据本身不稳定（政策未落地、许可条款在谈）时，把它写成硬约束会让决策反复重启。此时正确做法是先把它写成 ADR 的 **Considered Options 里的假设**，标注「这一条一旦变化需要重开决策」——把不确定性显式化，而不是假装它已确定。

#### 7.3.4 载体与复用：一次性结论 vs 可被检索的决策

**机制是什么**：决策的价值 = 这一次的决定 + 下一次不必重做。载体（会议纪要、打分表、ADR、雷达、决策图）决定第二项能不能实现。

**实现差异**：

| 载体 | 保存了什么 | 丢失了什么 | 跨决策可查询性 |
| --- | --- | --- | --- |
| 会议纪要 | 结论 | 未选方案与理由 | 低（需人翻） |
| 加权打分表 | 分数 | 分数是怎么打出来的 | 低（格子里的数无出处） |
| ADR | 结论 + 备选 + 后果 | 数值推导过程 | 中（按决策归档） |
| Tech Radar | 门类的组织默认结论 | 个体场景的例外 | 高（按门类查询） |
| Decision Graph + GraphRAG | 决策之间的关系 | 单次决策的细节 | 高（按约束查询） |

**由此必然导出的性质**：因为 ADR 是**按决策归档**的（一次决策一份文档），所以它天然无法回答跨决策的规律性问题（「我们在延迟敏感场景一贯怎么选」）——这正是 Decision Graph 存在的理由：它把「文档集合」变成「可检索的关系」，代价是多一层需要维护的图数据。因为 Tech Radar 把个体决策的**上游结论**固化了，所以它把成本从「每次推导」移到「每次更新」；当同一门类的决策很少发生时，更新责任会大于它省掉的讨论时间。

**AI 在流程里的位置**：因为 AI 辅助改变的是「谁生成草案」而不是「判据从哪来」，所以它的正确用法是**填决策矩阵里空白的格子并写出理由**，权重与硬约束仍由人给；把 LLM 的排序直接当结论，等于把权重和判据一起放进黑箱。判定方法：把同一组候选换一个顺序再问一次，若排名翻转，说明输出含位置效应，只能作为草案候选池使用——这条检查不需要任何外部资料，你自己就能做。

**公开证据【公开】**：ThoughtWorks Technology Radar 自 2010 年起公开发布（ThoughtWorks 官网，2010 起）；Gartner 在其 2022 年顶级战略技术趋势中列出 Decision Intelligence（Gartner, 2022）。可自行核验的判据是：你的组织里是否存在一个**按门类可检索**的选型结论库，如果答案只有「在 wiki 里搜关键词」和「问老员工」，那说明载体这一层还停在族 6 的第一档。

**失效条件**：当团队规模小（决策半年内不会重做、同一门类决策不超过一两次）时，建决策图的收益低于维护成本——载体型投入只在「同一类决策会被反复做出」时才回本。

**四条机制维度的对照速查**（每行给出机制依据，而不是打分）：

| 候选 | 维度可折价吗 | 权重来源 | 判据的角色 | 载体 | 由机制导出的最短结论 |
| --- | --- | --- | --- | --- | --- |
| 拍脑袋 | 不适用（无显式判据） | 无 | 无 | 无（或口头） | 只适用于可逆成本 ≤ 一个人周 |
| 加权打分 | 完全可折价 | 外生 | 全部进和式 | 一张表 | 便宜、线性成本；不能否决也不能复现 |
| Pugh Matrix | 完全可折价（相对） | 无显式权重 | 相对观察项 | 一张表 | 缺数值时可用；基准选错则全盘偏移 |
| AHP | 完全可折价 | 内生（两两比较） | 权重来源 | 判断矩阵 + 权重 | 唯一能复算权重的选项；成本随判据数二次增长 |
| TOPSIS | 完全可折价（距离敏感） | 外生 | 权重来源 | 归一化矩阵 | 对单维极端劣势比加权和敏感；要求数值齐备 |
| ELECTRE | 部分不可折价 | 外生 | 约束 + 权重 | 优序关系 | 可设否决，但工程落地少、解释成本高 |
| Risk-adjusted Scoring | 完全可折价 | 外生 + 效用曲线 | 权重来源（含风险偏好） | 一张表 | 判据含风险偏好时的正解 |
| Trade-off Table | 不折价 | 不适用 | 解释材料 | 文档 | 不产生结论，保留完整信息供复用 |
| CAP / PACELC | 不可折价 | 不适用 | 定理约束 | 约束边界 | 直接排除整类候选；只管一致性一维 |
| TCO / CBA / NPV | 全部货币化 | 折现率隐含 | 可折价（同一单位） | 现金流模型 | 前提是所有维度能换成钱 |
| ADR | 不适用（不聚合） | 不适用 | 决策档案 | 按决策归档 | 降低「重复讨论同一件事」的概率 |
| Tech Radar | 不适用（不逐次聚合） | 组织级预置 | 组织默认 | 按门类检索 | 把成本从每次推导移到每次更新 |
| Decision Graph + GraphRAG | 不适用 | 不适用 | 可检索引用的历史判据 | 关系图 + 检索 | 回答跨决策的规律性问题 |
| AI 辅助 | 取决于它填的是哪一族的格子 | 由人给 | 草案填充 | 随宿主方法 | 只改「谁填格子」，不改判据从哪来 |

### 7.4 成本结构对比（不是价格表，是成本函数）

决策框架没有「单价」可比：同一张矩阵在跨部门评审和单团队自查下的成本差一个量级。可比较的是**成本函数的形式**——成本随哪个变量增长、增长得多快、哪一部分不随决策重要性增长却随组织规模增长。

```
总成本 ≈ 方法学习成本（固定，一次性）
        + f(候选数 × 判据数)          # 填格子的数据采集成本
        + g(判据数)                    # AHP 两两比较，约 n(n-1)/2 次
        + h(参与方数量, 争议程度)      # 共识成本（会议与对齐）
        + i(决策重复频率)              # 记录与检索成本：不记就每次重付
        + j(选错概率 × 迁移成本)       # 期望损失
```

**各族的成本主导项与隐性成本**：

- **族 1（拍脑袋）**：主导项是期望损失 j；隐性成本是「选错了没人知道为什么错」，下一次会以同样的方式再错一遍。
- **族 2（加权打分）**：主导项是 f（填格子）；隐性成本是格子填不满时用直觉补，而补的那一格不会被标注——打分表看起来比拍脑袋严谨，实际是「拍脑袋 + 不可见的补值」。
- **族 3（AHP / TOPSIS / ELECTRE）**：只有 AHP 的主导项是 g（判据数二次增长），TOPSIS / ELECTRE 的主导项是 f（候选数 × 判据数，线性，见 §7.3.2）；隐性成本是权重模板化，一份 2023 年做的权重被 2026 年的团队直接复用。
- **族 4（不折价型）**：CAP / PACELC 主导项近乎为 0（逐条核对清单），隐性成本是「只覆盖了它处理的那一维」、其余维度仍需另一套方法；Trade-off Table 主导项是逐个选择写出「换来什么 / 付出什么」，隐性成本是「只有素材没有结论」，仍需有人真的做决定。
- **族 5（货币化）**：主导项是把各维折算成现金流的估算成本；隐性成本是折算率与折现率的选择本身就是一个未记录的自由参数。
- **族 6（载体与复用）**：主导项是维护（写下、更新、下架）；隐性成本是过期的雷达条目会给出错误信心。
- **AI 辅助（跨族）**：主导项是草案的人工复核时间；隐性成本是把复核省略掉的那部分（见 §7.7 反模式）。

**【推算】填格子成本**：设 6 个候选、6 条判据，则矩阵有 36 个格子。若每格需要查文档、要报价或跑一次压测，按 0.5–2 人时/格（【经验】）计，得到 18–72 人时，按 8 人时 / 工作日折合 **2.25–9 人日**。推导链是「格子数 × 单格取证成本」；格子数由候选与判据的乘积决定，所以**把候选从 6 个收敛到 3 个，能把方法成本直接减半**——收敛候选是本方法里最便宜的一步，却常被跳过。

**【推算】AHP 的比较次数**：n 个元素的两两比较次数为 n(n−1)/2。n = 6 时为 15 次，n = 10 时为 45 次；每次比较按 1–3 分钟（【经验】）计，n = 6 约 15–45 分钟，n = 10 约 45–135 分钟。注意结论的形式：判据从 6 增到 10，成本约变 3 倍（45/15），而不是 1.67 倍（10/6）——线性直觉会系统性低估 AHP 的成本，这是它只适合判据适中场景的定量依据。

**【推算】共识成本**：设参与方 k 个，需要覆盖的对齐组合数与 k(k−1)/2 同阶。把参与方从 3 增到 8，组合数从 3 增到 28（约 9 倍）；若一次跨团队评审按 1–2 小时计（【经验】），那么「跨团队决策慢」有一个纯粹的算术解释，而不是会议纪律问题。这也解释了为什么族 6（载体）在跨团队场景里的性价比最高：它把「每次都要对齐」换成「查一次已有结论」。

**【经验】可逆成本低的场景**：日志库、序列化格式、SDK 版本这类日常选型，选错后的迁移成本通常在一个人日到一个人周量级（【经验】）。此时把决策成本控制在 30–90 分钟内才是理性的——用一张需要 2.25–9 人日才能填满的矩阵去决定它，是用确定的成本换不存在的收益。

### 7.5 决策树（每个分支都要有阈值依据）

```
第 0 问（先问，对全体方法生效）：这个决策选错后，多久能改回来？
├─ 一个人日到一个人周内可改回（可逆且便宜）
│    └─ 指定负责人直接定 + 记一行 ADR 即可；不要上矩阵（矩阵成本 > 期望损失）
└─ 不可逆，或迁移成本 ≥ 一个人月
     ↓
第 1 问（硬约束筛除，不进加权）：是否存在「不可协商项」？
│    （合规不允许、许可不允许商用、必须满足某项一致性 / 延迟硬指标）
├─ 有 → 先用清单把不满足的候选整体排除；把约束名单写进 ADR 的 Context 供下次复用
│        （此步禁止用分数，分数会让否决项被折算掉）
└─ 无 → 继续
     ↓
第 2 问：判据的数值能不能拿到？
├─ 多数格子拿不到数值（只能定性）
│    └─ Pugh Matrix（与基准逐维比 +/-）或 Trade-off Table（逐项摆开、不出总分）
└─ 大部分格子有数值
     ├─ 判据数 ≤ 4 且参与方 ≤ 3 → 加权打分 + Sensitivity Analysis
     ├─ 判据数 ≥ 5 且分歧在于「哪条判据更重要」 → AHP（必须附 CR 检验）
     ├─ 判据里含风险偏好（同一维度对不同团队含义不同）→ Risk-adjusted Scoring / 效用函数；若风险体现在「未来情景不确定」而不是「偏好不同」，改用 Scenario Analysis（按 2–3 个情景各算一遍，看结论是否随情景翻转）
     └─ 候选数 ≥ 5 且需要在多维度上同时接近最优 → TOPSIS / ELECTRE
          ↓
第 3 问：决策归属与载体
├─ 单团队拍板 → 一份 ADR（Context / Considered Options / Outcome / Consequences）
├─ 跨团队共识 → ADR + 显式写下判据与权重 + 逐项摆开的 Trade-off Table（防否决项被总分掩盖）
└─ 同一门类过去 12 个月被独立决策 ≥ 3 次 → 升进 Tech Radar，个体不再逐次推导
          ↓
第 4 问（并行，非替代）：要不要用 AI 辅助？
└─ 用它生成候选、填草案格子；权重与硬约束由人给；草案必须做「换序复问」稳定性检查
          ↓
第 5 问（回看，决定上面几问值不值得走）：过去 12 个月，你们做过几次「选项 ≥ 3 且不可逆」的决策？
├─ < 5 次 → 先补判据清单与 ADR，暂不上矩阵（方法的学习成本摊不平）
└─ ≥ 5 次 → 按第 0–4 问执行，固定成本可被重复决策摊薄
```

**阈值依据**：

- **「一个人日到一个人周 / 一个人月」**：可逆成本的分档，依据是决策容量而非重要性。一个团队一年能做的高质量决策数量有限，若每个决策消耗一周工程时间，这个数量被钉在几十个量级（【推算】按 50 个工作周、每周最多 1 个此类决策推算）。所以这里比较的是「决策成本 / 决策价值」的比值，而不是「这件事重不重要」。
- **「是否存在不可协商项」**：这不是数值阈值，依据是 §7.3.1 的补偿模型失效点——「否决项」与「加权项」的区别不在重要程度，而在它能不能被别的维度换回来；一旦进入和式就再也取不出来（§7.3.3）。判定方法：把候选逐条对照一份**写下来的**约束清单（合规、许可、一致性硬指标、成本上限），任何一条不满足的候选整体出局。「无」这一支的唯一含义是清单为空，而不是「我们还没想到」。
- **「判据的数值能不能拿到」**：依据 §7.3.1 与 §7.6——AHP / TOPSIS 要求归一化数值矩阵，缺值只能靠猜；而定性信息在 Pugh Matrix 的 +/− 里仍能保留，所以这条分流发生在选方法之前。判定方法：抽 5–10 个格子逐格问「这个数从哪来」，答案落在「查文档 / 跑一次压测 / 要一份报价」三者之一才算有数值，答案是「大家觉得」的格子计入拿不到的那一侧【经验】；拿不到的格子占多数就走定性分支。
- **「判据数 ≤ 4 → 加权打分」**：依据 §7.4 的成本函数。n = 4 时两两比较仅 6 次，与直接填 4 列格子的成本同阶，AHP 的额外一致性收益不足以覆盖其成本；n 增大后，相对比较比绝对赋权更省认知（人给绝对分数不稳定，做一对一的比较更稳），AHP 才开始回本。这条门槛全章只用一个口径：§7.6 里「直接定 + 一行 ADR」那一行同样以「判据 ≤ 4 条」为界，区别不在判据数，而在它同时命中了第 0 问的「可逆且便宜」——两处不是两条不同的门槛，是同一门槛叠加了不同的前置条件。
- **「参与方 ≤ 3」**：依据 §7.4 的共识成本函数。3 方需要覆盖的两两对齐组合是 3 组（k(k−1)/2），与填一张「候选数 × 4 条判据」的矩阵同阶；参与方增到 8 时组合数升到 28（约 9 倍），方法的作用就从「算」变成「对齐」。判定方法：若评审开到第三轮还在争「谁拍板」而不是「哪条判据排错了」，说明参与方已越过这条门槛——此时要么用 AHP 把权重变成可复算的中间结果，要么用载体把「每次都要对齐」换成「查一次已有结论」。
- **「分歧在于哪条判据更重要」**：这是选 AHP 的**唯一**机制理由——AHP 的价值是把权重变成可复算的中间结果（§7.3.2）。若分歧不在权重而在「某个候选根本不可接受」，那属于第 1 问的硬约束分支，用 AHP 是错的工具。
- **「CR < 0.1」**：【公开】档，Saaty 1980 给出的标准判据，不是经验值。CR 超阈值意味着判断矩阵自相矛盾，正确动作是重做比较，而不是继续用这份权重。
- **「判据含风险偏好 → Risk-adjusted Scoring / Scenario Analysis」**：这一支的分界不是数值而是**风险的存在形式**——「偏好不同」（同一维度对不同团队含义不同）用效用曲线把偏好写进评分；「未来情景不确定」用 Scenario Analysis 按情景各算一遍（【经验】取 2–3 个情景：只算 1 个就退化成普通打分，情景过多则管理成本超过它带来的信息）。判定方法：把同一张权重交给两个团队各打一次，分歧集中在某一维的取值上属于偏好问题，集中在「明年这条路还通不通」属于情景问题。
- **「候选数 ≥ 5 用 TOPSIS / ELECTRE」**：依据 §7.3.1 的补偿性问题——候选越多，任何单维上的极端劣势被总分抹平的概率越高。判定方法：把加权打分的排名与 TOPSIS 排名比对，看差异最大的那几个候选分别在哪一维上被拉平；若差异可忽略，说明候选集里没有单维持平的极端值，用加权打分就够。
- **「单团队拍板 → 一份 ADR」与「跨团队共识 → ADR + 判据与权重 + Trade-off Table」**：依据 §7.4 的共识成本函数与 §7.3.4 的载体机制。参与方增加时两两对齐组合数按 k(k−1)/2 增长，跨团队这一支多付的成本只能靠「把判据与权重写下来」抵消——写下来的判据才能被指出「是哪一条排错了」，否则争议会退回到「谁拍板」。判定方法：问一句「这个结论被质疑时，质疑者能翻到哪份文档」，答不出文档的，就是该补的那一层。
- **「同一门类 ≥ 3 次」**：组织约束而非数值阈值。只有当同一门类的决策在过去 12 个月被独立做出 3 次以上时，把结论固化成雷达条目才开始回本（【经验】）；低于这个频率，维护责任大于它省掉的讨论。
- **「要不要用 AI 辅助」**：依据 §7.3.4——AI 改的是「谁填格子」，不改「判据从哪来」，所以它是与第 0–3 问并行的加速节点，不产生新的方法分支，也不改变上面任何一层已做的选择。启用条件是可复核：有人能对每一格判断对错、且权重与硬约束由人给；无人能复核时不得启用（§7.7 第四条反模式）。
- **「过去 12 个月 < 5 次就暂不上矩阵」**：依据是「固定成本 ÷ 使用次数」这条摊薄算术，它与上一条的 3 次**不是同一个变量**：3 数的是**同一门类**的重复次数（决定要不要固化结论），5 数的是**全部选型决策**的年总量（决定要不要引入方法）。方法的引入（学方法、建模板、把判据标准化）是一次性固定成本，按 2–4 人日量级计（【经验】）：一年 5 次时单次摊销约 0.4–0.8 人日，仍在 §7.4 推算的 2.25–9 人日填格子成本之下，值得摊薄；降到 2–3 次时，摊销额与「补一份判据清单」的增量成本同量级，先把决策写下来更划算。所以 5 次是固定成本开始被摊薄的下界，不是精确最优点。两者也可以同时成立——一年做 10 次选型、但每个门类只碰一次，就是 5 达标而 3 不达标。这条问题的计数口径「选项 ≥ 3 且不可逆」也在同一条依据里：「选项 ≥ 3」是因为两个候选（其中一个是「维持现状」）几乎没有方法上的比较空间，不计入；「不可逆」沿用第 0 问的分档。

**这棵树不展开的分支**（以及为什么）：

- **「该不该引入多准则方法」本身**：这不是判据问题而是容量问题，所以它在树上只留一个频率节点（第 5 问），不展开成方法选择分支——团队一年只做两三次真正的选型时，任何方法的学习成本都摊不平，此时更该投入的是「把决策写下来」而不是「把决策算出来」。
- **「用算术加权和还是几何平均」这类聚合细节**：它对排序的影响通常小于「权重是从哪来的」和「有没有否决项」，先解决后两者再谈聚合函数。
- **「谁来当评委」**：这属于决策权归属的组织问题，不是方法问题。但有一条可判定的经验规则：**评委里必须包含未来要维护该选择的人**（【经验】），否则矩阵会在「运维复杂度」这一列系统性失分偏低——因为承担运维的人不在场。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因（机制层面） |
| --- | --- | --- | --- |
| 单团队、可逆成本低、判据 ≤ 4 条 | 直接定 + 一行 ADR | 加权打分 | 矩阵成本 2.25–9 人日，大于选错后的迁移成本 |
| 跨团队、判据 ≥ 5、分歧在权重 | AHP（附 CR） | 加权打分 + Sensitivity | 加权打分权重外生，回答不了「为什么这条权重是 3」 |
| 存在硬约束（合规 / 许可 / 一致性） | 清单筛除 + Trade-off Table | 加权打分（仅在筛除之后） | 完全补偿模型会把否决项折算掉且不留痕迹 |
| 分布式存储 / 消息中间件选型 | CAP / PACELC 定型 + 加权打分定品 | 纯加权打分 | 分区行为是存在性约束，不是可折价维度 |
| 自研 vs 采购 | TCO + CBA + NPV | 加权打分 | 非货币维度不折现，加权和会把锁定成本摊平 |
| 格子里的数值拿不到 | Pugh Matrix 或 Trade-off Table | TOPSIS | TOPSIS 需要归一化数值矩阵，缺值只能靠猜 |
| 判据含风险偏好 | Risk-adjusted Scoring / 效用函数（风险来自未来情景不确定时改用 Scenario Analysis） | 加权打分 | 同一「性能」对不同团队的风险含义不同，不调整则分数不可比 |
| 同一门类反复决策 | Tech Radar / 参考架构 | 每次重做一次 AHP | 重复推导同一结论＝把成本付第二遍 |
| 需要回答「我们以前在类似约束下怎么选的」 | Decision Graph + GraphRAG | 人工翻 ADR | 差距在「文档集合」与「关系图」之间 |
| 探索期、候选都还不清楚 | LLM 生成候选与草案 + 人定权重 | 无 | 直接采信 LLM 排序＝判据与权重一起进黑箱 |

**常见组合**（每条注明职责边界与维护代价）：

- **硬约束清单 + 加权打分**：清单负责「出局」，加权负责「排序」。边界是——凡进入加权的判据都必须是可折价的，否决项永远不进和式。维护代价是清单需要有人负责更新（合规与许可条款会变）。
- **AHP + Sensitivity Analysis**：AHP 产出可复算的权重，敏感性分析回答「权重扰动多少结论会翻转」。边界是敏感性只检验权重，不检验判据是否遗漏。维护代价很低（一次计算），收益是让「结论稳健吗」这个问题有答案。
- **加权打分 + ADR**：打分表是过程，ADR 是产物。边界是 ADR 里必须写出**未选方案与原因**，否则它只是结果公告。维护代价是一份文档，回报是「下一年不必重新讨论同一件事」。
- **Trade-off Table + Tech Radar**：Trade-off Table 服务个体解释，Tech Radar 服务组织默认。边界是雷达条目必须标注适用约束，否则会被过宽地套用。维护代价是按季度评审一次条目、并把过期条目下架。
- **AI 草案 + 人定权重 + ADR**：AI 负责生成候选与填草案格子，人负责权重、硬约束与最终结论。边界是 AI 输出永远带「草案」标记，且必须过换序复问检查。维护代价是复核时间——这一项不能省，省掉它整套组合就退化成「看起来有依据的拍脑袋」。
- **Sensitivity Analysis 单独使用**：不建议。它只回答「权重扰动后排名会不会翻转」，不回答判据是否遗漏、是否含硬约束。把它从加权打分配对里拆出来单独汇报，会给人「结论已经做过稳健性检验」的印象，而实际上检验的是**一个可能本身就不完整的模型**。
- **CAP / PACELC + TCO / CBA**：定理约束负责划掉不可行方案，货币化负责在可行方案里算钱。边界是这两者都可能漏掉「团队能力」这一维，所以仍需一条硬约束式的团队能力下限（例如「团队里至少两人具备该产品调优经验」）。

组合的原则只有一条：**每加一件，都要说清它负责哪个环节（筛除 / 聚合 / 记录 / 复用），以及它得出的东西谁能质疑**。

### 7.7 选错的代价与迁移成本

**反模式：用总分掩盖否决项** —— 症状：把合规、许可、一致性一并写进矩阵逐格打分 → 后果：一个在某维完全不合格的候选靠其他维度的高分排到第一，通过评审后在上线前被法务或运维打回，决策流程重启且时间已耗掉 → 正确的做法：先跑硬约束清单，把不满足的候选整体排除，判据里的硬约束项**不进入和式**。

**反模式：给可逆决策配重方法** —— 症状：为「选哪个日志库」「用哪个序列化格式」组织跨部门打分评审 → 后果：决策成本（2.25–9 人日，见 §7.4 推算）远超选错后的迁移成本（一个人日到一个人周【经验】），并且让团队学会「决策很慢」→ 正确的做法：按第 0 问分档，可逆且便宜的决策指定负责人直接定，用一行 ADR 留痕。

**反模式：权重不落地** —— 症状：会议上了结论，纪要只写「选用 A 方案」，判据与权重留在参会者的记忆里 → 后果：三个月后有人质疑时无法复现推理过程，讨论从「哪条判据排错了」退化为「当时是谁拍板的」→ 正确的做法：把判据、权重、以及**被排除的选项与排除理由**一起写进 ADR；判据被写下来才可能被质疑和修正。

**反模式：把 LLM 排序当结论** —— 症状：直接让模型给候选打分排序，取第一名提速 → 后果：权重与判据无从审查，模型的位置效应与措辞偏好会左右结论，且没有任何记录可供复核 → 正确的做法：只采信它填的草案格子与理由，权重与硬约束由人给，并做换序复问稳定性检查。

| 从 → 到 | 已有决策材料 | 判据与权重 | 流程与角色 | 团队再学习 | 工作量量级 |
| --- | --- | --- | --- | --- | --- |
| 拍脑袋 → 加权打分 | 需要补判据清单 | 首次显式赋权 | 需要一个主持打分的人 | 打分与敏感性概念 | 低（几天） |
| 加权打分 → AHP | 已有判据，可直接复用 | 权重从外生改为两两比较推导 | 需要一人操作判断矩阵与 CR | 一致性检验、判断矩阵 | 中（1–2 周） |
| 加权打分 → 硬约束筛除 + Trade-off Table | 需要补硬约束清单 | 权重不再是一切 | 需要明确谁有权否决 | 约束与折价的区别 | 低（几天，但组织阻力可能最大） |
| 结论无载体 → ADR + Tech Radar | 历史决策需要回填 | 权重可继续沿用 | 需要有季度评审角色 | ADR 模板、雷达门类划分 | 中（1–2 个月见效） |
| 逐次重做 → Decision Graph + GraphRAG | 需要历史决策的元数据 | 不适用 | 需要维护图与检索质量 | 检索结果的置信判断 | 高（数月，仅在决策高频时值得） |
| 人工评估 → AI 辅助 | 需要一份带理由的草案基线 | 权重仍由人给 | 需要复核流程与「草案」标记 | 换序复问等自检方法 | 低（数天，但复核成本长期存在） |

有一条容易被忽略的顺序约束：**判据显式化必须发生在引入更强方法之前**。先用 AHP 求解一组没人写下来的判据，得到的只是一份更精密的困惑；把判据写成清单和 ADR，往往不需要换工具就能解决大部分争议。

第二条顺序约束是**不要在一次决策里同时换方法与换结论来源**。如果这次既要引入 AHP，又要把「团队匹配度」从「谁用过」改成「谁能在三个月内独立运维」，那么结论一旦被质疑，你无法判断分歧来自方法还是来自判据定义——保险的做法是先用旧判据跑一遍新方法（对比方法差异），再用新判据跑一遍旧方法（对比判据差异），两次对比都做完再合并。

### 7.8 小结

| 你的处境 | 建议 | 关键理由（机制层面） |
| --- | --- | --- |
| 选错后一个人周内能改回 | 直接定 + 一行 ADR | 决策成本已是主导项，任何矩阵都是净亏 |
| 存在合规 / 许可 / 一致性硬指标 | 清单筛除先行，硬约束不进和式 | 完全补偿模型会把否决项折算掉 |
| 跨团队且分歧在「谁更重要」 | AHP 并附 CR 检验 | 只有它把权重变成可复算的中间结果 |
| 面对分布式存储 / 消息选型 | CAP / PACELC 定型，加权打分定品 | 分区取舍是存在性约束，不是可折价维度 |
| 自研 vs 采购 | TCO + CBA + NPV（详见 §03） | 前提是所有维度可货币化 |
| 格子里的数值拿不到 | Pugh Matrix / Trade-off Table | 缺值的聚合等于用直觉补格子 |
| 同一门类反复决策 | Tech Radar / Decision Graph | 复用型投入的回报来自重复次数 |
| 已经有一堆历史决策但没人查 | 先补 ADR，再谈决策图 | 没有结构化记录，图无从建起 |

回到本章的 6 条判据。这里不给它们排权重——按本章自己的立场，权重必须显式写下并且可追溯，凭印象说「这条更重要」正是 §7.3.2 批评的那种外生权重。本文只排**依赖顺序**：**不可协商项**决定了候选集合（先筛再比），**可逆成本**决定了该不该为这次决策付方法成本（便宜可逆的决策不配重方法）。这两条回答完，判据显式性、数据可得性、参与方数量、结论载体才有讨论价值——顺序反了，讨论就会永远停在「哪个工具更高级」的偏好层面。真到了必须给这 6 条排序的场合，动作也是先把权重写下来、写清它从哪来（外生给定还是两两比较推导，见 §7.3.2），而不是把顺序当成权重。

> 本节小结：这些方法之间唯一真正起决定作用的差异是**「判据里有没有不可折价的项，以及权重是否可复算可追溯」**——它同时决定结论能不能被质疑、会不会被复用、以及在下一次类似决策里要付多少成本。其余维度（易用性、量化程度、AI 友好度）都是这条差异的下游结果。
>
> 💡 **思考锚点**：拿你最近一次真正的选型，对一下 7.6 的两行——决策成本（矩阵 2.25–9 人日）与你选错后的迁移成本谁大；若选错的代价只是一个人日到一个人周，这次该不该用 AHP 或加权打分，还是直接定 + 一行 ADR，而你的判据里有没有一个不可折价的项被写进了和式？
