## 3. 设计模式与范式

### 3.1 主要模式

**模式 1：Core-Edge-Spot Framework（Gartner）**

| 类型 | 战略价值 | 推荐策略 |
| --- | --- | --- |
| **Core（核心）** | 业务差异化核心 | **自研**——掌控核心算法 / 数据 |
| **Edge（边缘）** | 必要但不差异化 | **采购 / SaaS**——如数据库、MQ |
| **Spot（机会）** | 暂时性机会 | **SaaS / 合作**——快速验证 |

**示例（智能体平台）**：
- Core：核心 Agent 编排逻辑、领域 RAG 策略 — **自研**。
- Edge：通用向量库、通用 LLM API — **采购 / SaaS**。
- Spot：临时 ChatOps 工具 — **SaaS**。

**模式 2：Make-or-Buy Decision Tree（McKinsey）**

```
需要的能力是什么？
        │
        ├── 是业务核心差异化？
        │       │
        │       ├── 是 + 团队有能力 + 长期投入？
        │       │       └── 是 → 自研
        │       │
        │       ├── 是 + 团队没能力？
        │       │       └── 是 → 采购 + 培养团队（双轨）
        │       │
        │       └── 否 → 进入下一层
        │
        ├── 上线时间紧迫？
        │       │
        │       ├── 是 → 采购 / SaaS（先上线再说）
        │       └── 否 → 进入下一层
        │
        ├── 采购方案成熟？
        │       │
        │       ├── 是 + 切换成本低 → 采购
        │       ├── 是 + 切换成本高 → 自研（BOT）
        │       └── 否 → 自研
        │
        └── 想平衡？
                └── 混合（核心自研 + 边缘采购）
```

**模式 3：Build-Operate-Transfer（BOT）**

| 阶段 | 时间 | 模式 |
| --- | --- | --- |
| Build（建设） | 0-6 个月 | 自研 + 第三方咨询 |
| Operate（运营） | 6-24 个月 | 团队独立运营 |
| Transfer（转让） | 24+ 个月 | 可移交到采购 / 混合 |

适用：核心能力初期自研，成熟后考虑采购。

**模式 4：Strategic Capability Mapping**

把能力按「战略重要性 × 团队能力」二维分类：

```
       战略重要性高
            │
  自研 + 投入 │ 培养 + 合作
            │
 ───────────┼─────────── 团队能力
            │
  采购 / 外包│ 渐进
            │
       战略重要性低
```

**模式 5：TCO 3 年 / 5 年 / 10 年对比**

| 时间维度 | 自研 | 采购 / SaaS |
| --- | --- | --- |
| 初始成本 | 高（人力 + 时间） | 低（订阅） |
| 运营成本 | 高（团队 + 维护） | 中（订阅升级） |
| 切换成本 | 高（迁移成本） | 中（迁移到其他供应商） |
| 长期 | 边际成本递减 | 边际成本恒定 |

→ 一般 3 年内采购 TCO 更低；5 年 + 自研 TCO 更优（视场景）。

**模式 6：Risk-adjusted Make-or-Buy**

考虑风险的决策：
- 自研失败概率 30% × 损失 50% = 风险调整 0.15。
- 采购失败概率 10% × 损失 20% = 风险调整 0.02。
- 即使自研 NPV 更高，风险调整后采购仍胜。

**模式 7：Pseudo-Self-Built（伪自研）检测**

伪自研特征（同时满足 ≥3 项即伪自研）：
- 80%+ 代码是开源复制。
- 仅做薄薄一层 UI / API 包装。
- 没有真正掌握核心算法。
- 团队无法独立维护（靠原社区）。
- 战略价值低（业务不依赖）。

**模式 8：Vendor Lock-in 评估**

| 维度 | 锁定风险 | 检测 |
| --- | --- | --- |
| 数据迁移 | 高 | 数据格式专属 |
| API 兼容 | 高 | 私有 API |
| 工具链 | 中 | 专有工具 |
| 培训 | 中 | 专有技能 |
| 社区 | 低 | 标准化 |

→ 锁定风险高 → 自研（BOT）。

**模式 9：Open Source as Middle Ground**

开源是「自研 + 采购」的中间态：

| 维度 | 开源 | 自研 | 采购 |
| --- | --- | --- | --- |
| 源码可见 | ✅ | ✅ | ❌ |
| 自主可控 | 中 | 高 | 低 |
| 运维成本 | 中 | 高 | 低 |
| 切换成本 | 中 | 高 | 低 |
| 战略价值 | 中 | 高 | 低 |

**模式 10：Make-Buy-Mix（混合模式）**

按组件分层决策：

| 组件 | 决策 | 理由 |
| --- | --- | --- |
| 核心 Agent 框架 | 自研 | 业务差异化 |
| 向量库 | 采购（Pinecone / Milvus 托管） | 通用能力 |
| LLM API | 采购（OpenAI / Anthropic） | 通用能力 |
| 领域微调 | 自研 | 业务差异化 |
| 监控 / 告警 | 采购（Datadog / Grafana Cloud） | 通用能力 |
| 编排调度 | 自研 | 业务差异化 |

### 3.2 适用场景决策表

| 场景 | 推荐策略 | 理由 |
| --- | --- | --- |
| 核心算法 / 业务差异化 | 自研 | 战略自主 |
| 通用 CRUD / ETL | 采购 / SaaS | 追平对手 |
| 上线时间紧迫 | 采购 / SaaS | 速度优先 |
| 团队没能力 + 核心 | 采购 + 培养 | 双轨 |
| 长期（5+ 年）核心能力 | 自研 | TCO + 战略 |
| 短期机会 / 验证 | SaaS | 试错 |
| 合规要求高 | 自研 / 私有化 | 数据可控 |
| 预算紧 | 采购 / 开源 | 成本优先 |

### 3.3 反模式与陷阱

1. **「伪自研」**：外壳套开源，无战略价值。**严格检测 5 项特征**。
2. **「盲目采购」**：所有都 SaaS，结果供应商锁定 + 数据合规失控。**核心能力必须自研**。
3. **「TCO 计算错误」**：只看初始成本。**3-5 年 TCO 必须**。
4. **「战略自主性误判」**：把非核心当核心，结果失焦。**用 Core-Edge-Spot 框架**。
5. **「采购周期长就自研」**：因为采购慢就自研。**评估自研周期是否更长**。
6. **「忽视维护成本」**：自研初期成本低，3 年后维护成本爆炸。**TCO 必须含人力**。
7. **「过度核心化」**：什么都自研。**通用能力坚决采购**。
8. **「不培养团队」**：采购后团队永远学不会。**采购 + 培养并行**。
