## 5. 前沿演进（AI 时代）

> 原 § 5 共 40 行、为方向清单，缺少机制与成熟度判断，重写为 ~300 行前沿评估。

### 5.1 先分清三类「前沿」

趋势清单的根本问题是**没有时间维度**。原清单把「AI 辅助 Make-or-Buy」与「Agent Marketplace」写在同一个层级里，但前者今天就能用（让模型把历史 ADR、合同条款、TCO 表翻出来做查漏），后者的**企业采购与治理路径尚未成型**。照同一个清单排路线图会同时犯两个错：把今天能做的事排到明年，把明年可能还不存在的东西写成今年的设计假设。

第二个问题是**没写清 AI 动的是哪一环**。本主题的决策对象是「自研 / 采购 SaaS / 开源自运维 / 托管 / 合作共建 / BOT / 混合」这几类候选（见 [§ 7 候选方案全景](03-build-vs-buy-section-7-sec7.md)），而 AI 之所以是变量，是因为它同时动三件事：**证据的获取成本**（历史决策可被检索）、**交付的边际成本**（写出第一版的成本下降）、**能力的采购单位**（从「一套系统」变成「一个模型或 Agent 能力」）。三件事的时间表并不相同——证据检索今天就能用；交付成本要等**维护**成本也跟着降才算数，而维护成本由「读懂既有代码 + 跟上上游变更 + 承担故障」决定；采购单位的变化卡在合同与审计口径上，这是最慢的一环。

第三，**级别不是永久标签**。一个方向可以从 L3 升到 L1——升级信号是「出现第三方（非厂商）生产案例」加上「接口冻结」；也可以从 L1 掉回 L2——比如某类服务开始频繁改接口或改计价单位。本节给的级别是 2026 年前后的快照，读到时请用同一套判据重判一次；**判据本身比结论耐用**。

所以本节不按「产品」分档，按**判据可核验的程度**分三档：**L1 生产可用**（有正式 release note 或官方文档，有第三方非厂商公开生产案例，接口稳定）、**L2 可试点**（已可用但接口或生态未稳，或只有厂商自有案例）、**L3 观望**（仅路线图、论文、厂商演示或预览特性）。判据不能是「感觉成熟」。

| 原清单条目 | 级别 | 判据 | 现在该做什么 |
| --- | :---: | --- | --- |
| AI 辅助 Make-or-Buy（LLM 推荐选项 + TCO 估算 + 风险评估） | **L1**（仅起草与查漏） | 三条判据逐条给口径：①工具已 GA，官方文档与 release note 可核验；②第三方（非厂商）公开实践能核验的是「用 AI 起草文书」这一类**产出**，**不能**核验「AI 改变过某次结论」——这条缺口写在 5.4；③接口稳定性只按产出物形态判定：一段带出处的初稿、错了可回退、不进入署名 | 用它检索历史证据与查漏；结论由人签 |

| Make-or-Buy + KG（决策知识图谱） | L3 | 组织级决策图谱只有趋势报告与厂商叙事，公开落地案例与效果度量缺位 | 记录；不要在架构里假设它存在 |

| Decision Intelligence Platform（组织级决策平台） | L2（作为留痕与报表）/ L3（作为推荐） | 汇总类能力有成熟 BI 实践；推荐类无公开效果度量 | 先做留痕与统计，不做推荐 |
| Agent Marketplace（采购入口） | L3 | 市场已上线，但企业采购的数据边界 / 可审计 / 退出路径未成型 | 个人生产力可用；进核心链路前先做边界评审 |
| AI Governance 自研（合规 / 安全 / 隐私回归自持） | L2 | 「责任不可外包」这条判据本身可核验（范围由监管属地决定）；自持程度因行业而异 | 先定数据与审计边界，再决定哪些自建 |
| 边缘 AI 自研（实时 / 离线 / 数据不出域） | L2 | 边缘推理框架 GA；是否「必须自持」取决于硬约束是否真实存在，而这条约束可自行核验 | 先确认硬约束，再谈自研 |

本主题下**唯一**够 L1 的是前两行——「把决策的文书与实现环节做快」这一族。它之所以唯一，是因为它**没有改变成本函数与责任归属**，只压低了已有环节的边际成本：错了可以退（初稿被否没有后果）、不用改合同、不用改组织。其余九行都在等两件事之一：等**维护成本**也跟着降（交付类方向），或等**合同与审计口径**成型（采购与治理类方向）——这两件事都不是模型能力问题，因此不会因为模型变强而自动发生。

表里最容易误判的是两处。一是「基础模型 API + 微调」常被当成一条：API 是**采购**（L1），而「微调出一个自己的模型」是**自持**（L2）——两者在 TCO 上落的位置完全不同，前者是运营支出，后者会带出一支必须长期存在的团队。二是「AI Governance 自研」常被写成趋势：它其实是**约束**，约束不会因为模型变强而消失，也不会因为模型变强而变强；它的范围由监管属地决定，属于「先确认再规划」的那一类。

最后一个提醒：**级别低不等于不重要**。L3 里有些方向一旦成真，会改变判据本身的形态（比如跨组件依赖推理，真能用时会改变「可逆性」怎么算）。这类东西现在不该进架构假设，但该进技术雷达（[§05 技术战略](../05-tech-strategy/05-tech-strategy.md)）。本节把它们列出来不是为了让你现在做，而是为了让你一年后重判时知道该看什么。

本节的写法本身是可复用的：**先问「AI 动了哪一项成本」，再问「这一项是不是决定结论的那一项」**。如果动的不是决定性的那一项（例如它降低的是首版成本，而这项能力要养三年），那么这条方向对你就是「工具级」而不是「决策级」——工具可以用，决策的算法不用改。

#### 5.2.1 把证据找齐：决策文书环节的边际成本趋零

- **旧做法与它的卡点**：TCO、NPV、Core-Edge-Spot 这些方法都要求先把「历史同类决策怎么做的、结果如何、合同怎么写的」摆上桌。这些材料通常散在 ADR、邮件、合同附件与少数人的记忆里，取齐一次的成本以人日计——于是小决策干脆不查（拍脑袋），大决策查一次管三年。卡点不是方法不好，是**取证成本高到让方法被跳过**。
- **AI 改变了什么机制**：改变的是证据检索的**边际成本函数**——从「按材料份数计的人时」变成「按查询计的一次调用」。它不改变证据的质量，也不改变谁对结论负责。
- **由此得到的**：因为取齐历史证据的边际成本趋零，所以「查一下以前怎么定的」从一次大作业变成一次对话，[§ 7.3.1 记账边界](03-build-vs-buy-section-7-sec7.md) 里那类因取证成本被跳过的判据（成本边界、可逆性）第一次有可能被**例行执行**，而不是只在「这次金额大」时才执行。
- **由此付出的**：
  - ①**不可核验的结论开始混入 ADR**——模型会把你的假设包装成一份带编号的论证，让未经讨论的假设获得文件级别的权威性；纠正成本高于节省的检索时间。
  - ②**新的锁定点**——把提示词、检索库、评测集放在某一家模型上，等于把「组织记忆的入口」外包；这一项通常不写进锁定评估表，因为它不在数据也不在接口里。
  - ③**过期证据**——检索到的旧决策可能已经失效（栈变了、监管变了、团队变了），而过期证据比没有证据更危险：它会以「上次就是这么定的」终止讨论。
- **证据与来源**：LLM 的检索与摘要能力已 GA，产出物形态（带出处的初稿）可直接核验【可自行核验：任意主流模型服务商的官方文档】。同目录 [§ 6 案例](03-build-vs-buy-section-6-sec6.md) 的四个决策（Netflix 的能力缺口 + 规模阈值、阿里 MaxCompute 产品化、Airbnb 控制面 / 存储面分界、Snowflake 的买方视角）都是**人**做出来的，没有一个的结论由 AI 改变——这就是本方向当前的证据边界。
- **成熟度**：**L1（起草与查漏环节）**。判据：工具已 GA、失败可回退（初稿被否不产生后果）、且它不进入结论署名。

这一条的最小可用形态（示意，不是任何产品的界面）：

```text
材料（ADR / 合同 / TCO 表 / 复评记录）
      │  检索：只回答"哪一条材料说了什么"，并给出处
      ▼
初稿（候选清单 + 风险清单 + 待核查项）
      │  人的动作：逐条判定"这条件对我成不成立"
      ▼
署名（谁写进 ADR 的"备选方案与理由"栏，谁承担）
      → 断点在最后一格：初稿没有署名权，这是本方向唯一的硬边界
```

| 这条能做 | 这条不能做 | 为什么 |
| --- | --- | --- |
| 检索历史决策、合同条款、TCO 参数 | 判定「这次该自研还是该买」 | 结论不可核验，且责任无法署名 |
| 列出待核查项与风险清单 | 用生成的失败概率填风险调整 NPV | P_failure 必须来自工程判断，不是模型给的（[§ 7.3.2](03-build-vs-buy-section-7-sec7.md)） |
| 把散落材料归一成结构化字段 | 替代与干系人的对齐 | 对齐是组织动作，不是检索动作 |

#### 5.2.2 把第一版写出来：交付成本降了，维护成本没降

- **旧做法与它的卡点**：自研的判据里有一条隐含前提——「我们要养得起它」。这条前提由 [§ 7.3.1 记账边界](03-build-vs-buy-section-7-sec7.md) 决定：TCO 表里记人力与基础设施，不记「三年后没人看得懂这段代码」。于是能力缺口真实存在、但养不起的团队只能买，哪怕买来的东西不贴合；而买来之后的绕过与补偿代码又变成新的技术债（[§06 技术债](../06-tech-debt/06-tech-debt.md)）。
- **AI 改变了什么机制**：改变的是**写第一版的边际成本**（Agent 框架、低代码、代码评审辅助），没有改变**维护的边际成本**——维护由「读懂既有代码 + 跟上上游变更 + 承担故障」决定，这三件事的工作量不由生成速度决定。
- **由此得到的**：因为首版成本下降而维护成本不变，所以**一次性、边界清晰、可弃**的自研（脚本、内部工具、实验性管道）重新变得划算，而**要养三年**的自研的相对成本几乎没变——这意味着 [§ 7.3.3 可逆性](03-build-vs-buy-section-7-sec7.md) 判据的适用区间被扩大了，判别性判据却没有。
- **由此付出的**：
  - ①**伪自研的 AI 变体**——外壳仍套着开源，只是外壳生成得更快，于是「看起来像自研」更难被识破，[§ 3.3 的伪自研特征](03-build-vs-buy-section-3-sec3.md) 需要补一条「这个外壳是谁写的、谁看得懂」。
  - ②**待维护面积扩大**——首版变便宜的直接后果是自研件数量上升，而维护人时是有限的，最终以「一堆没人敢改的小服务」形式表现出来。
  - ③**缺陷模式位移**——AI 生成的代码在评审中更容易被放行（它看起来规范、命名整齐），缺陷从「语法错误」转向「逻辑正确但语义错」，而后者更依赖领域判断才能发现。
- **证据与来源**：AI 辅助编码工具已 GA（厂商官方文档与 release note 可核验）。「维护成本不随生成速度下降」是机制推断，本节**不引用精确倍数**——任何「AI 让开发效率提升 N 倍」的数字，若无第三方对照实验，不应进入 TCO 表【可自行核验：查该数字背后有没有非厂商的对照实验与样本口径】。
- **成熟度**：**L1（作为工具）/ L2（作为自研决策依据）**。判据：工具本身生产可用；把它折进「自研更便宜」的论证，目前没有可核验的第三方生产数据，只能做 PoC 级结论。

拆开看这四类成本，AI 只动了第一行：

| 成本项 | 由什么决定 | AI 是否改变 | 可核验的判定方法 |
| --- | --- | --- | --- |
| 首版实现 | 生成与调试速度 | **改变** | 同一任务的人时前后对比（需固定任务口径） |
| 读懂既有代码 | 代码量与一致性 | 部分（能解释，但不能替代责任制） | 让没写这段代码的人改一个字段，计时 |
| 跟上上游变更 | 依赖面大小与变更频率 | 未改变 | 数一年内破坏性升级的次数 |
| 承担故障 | 责任归属与值班制度 | 未改变 | 出事时谁被叫醒 |

这张表给出一个可操作的判据：**只有当一项工作的成本主要压在「首版实现」这一行上时，AI 才真的降低了它的成本**。反过来，如果成本主要落在第二到第四行（读代码、跟上游、担故障），那么它要不要自研，与 AI 无关——这时候该问的是 [§ 7.5 决策树](03-build-vs-buy-section-7-sec7.md) 里的前提条件，而不是工具。

还有一层需要观测而不是预先断言：**维护成本本身也可能被 AI 改变，但方向不定**。读代码这件事 AI 确实帮得上（解释、定位、补测试），但它替代不了「有人对这段代码负责」；而有了 AI 之后，团队更可能选择「不读懂、直接改」——短期看起来更快，长期把维护成本从「读得慢」换成「改错得快」。这是本节唯一一处**建议在拿到真实数据后再下结论**的地方。

#### 5.2.3 把判据从文档搬进流水线

- **旧做法与它的卡点**：[§ 7.3.4 决策权与留痕](03-build-vs-buy-section-7-sec7.md) 已指出，决策质量取决于**结论挂在哪**——写在文档里的判据，在工期与预算压力下第一个被跳过。Make-or-Buy 的判据（差异化贡献、可逆性、合规归属）尤其如此：它们既不在代码里，也不在流程里，只在评审会的口头共识里，换一批人就换一套标准。
- **AI 改变了什么机制**：改变的是判据的**执行位置**，不是判据的内容——把「是否差异化 / 是否可逆 / 是否触及合规红线」写成可判定的校验规则，挂在采购请求、预算审批或架构评审门禁上自动跑。AI 在这里有两层作用，必须分开对待：一层是把自然语言写的采购与方案描述**归一化成结构化字段**（可枚举、可核验），另一层是**自动生成决策报告**（不可核验）。
- **由此得到的**：因为判据的执行从「在场者的记忆」挪到「每次请求必经的校验点」，所以「标准不一」与「结论没人看」这两个卡点第一次有了工程解；也让可逆性这类判据从一句理念变成一条真能拦下请求的规则——这正是 [§ 3.2 适用场景决策表](03-build-vs-buy-section-3-sec3.md) 从纸面走向流程的形态。
- **由此付出的**：
  - ①**策略维护成本**是新增的、常被低估的预算项；且过期策略比没有策略更危险——它让团队对一个已经失效的标准产生信任。
  - ②**假阳性阻断**会拖慢交付，累计后触发「绕过流程」。这是门禁类机制的典型失效模式，与 [§ 7.3.3](03-build-vs-buy-section-7-sec7.md) 里「过度阻断后被绕过」同源。
  - ③**把未经讨论的假设固化成规则**：规则一旦进了流水线，它就不再被质疑，而判据本身也会停止更新。
- **证据与来源**：相邻领域（预算 / 合规 / 基础设施校验）的「策略即代码」有公开生产实践，可查其官方文档与 release note【可自行核验，2024 年前后已普遍 GA】；**把 Make-or-Buy 判据本身写成流水线校验**的公开第三方生产案例未见——判定方法：查你所在组织或同行有没有「采购请求被自动阻断」的记录，没有就说明它还停在 L2。
- **成熟度**：**L2（校验规则）/ L3（自动生成决策报告）**。判据：相邻实践生产可用、目标场景案例缺位；报告生成不可核验，不得进入结论。

一条可写进流水线的硬判据大致长这样（示意，不是任何产品的语法）：

```text
rule "core_capability_must_not_be_outsourced":
  when  purchase_request.touches(service in core_services)
  require
    request.has("替代方案与理由")        # 被否方案必须写下来
    request.has("退出演练记录")            # 可逆性不是形容词，是演练
    request.has("数据出境与合规归属")      # 判据 5：责任归属，不参与成本比较
  else  block with_reason("缺硬约束，不予放行")
```

与 5.2.4 的分工：这一条解决「**判据放在哪**」，5.2.4 解决「**采购对象变成什么**」。前者的产出是一条能被触发的规则，后者的产出是一份采购条款与一次退出演练。两者共用同一个前提——**判据必须先被写成可判定的形式**，否则规则写不出、条款也写不实。这也是本节反复强调「把标准写下来」的原因：它同时是评审能否产品化（[§07 架构评审 § 7.3.2](../07-architecture-review/07-architecture-review-section-7-sec7.md)）与采购能否可逆的前置条件。

#### 5.2.4 采购单位变小，但责任不可外包

- **旧做法与它的卡点**：采购对象一直是一套**有边界的系统**（数据库、MQ、SaaS），边界清楚所以合同写得清、退出成本估得出，[§ 3.1 模式 8 的锁定评估表](03-build-vs-buy-section-3-sec3.md) 按「数据 / API / 工具链 / 培训 / 社区」五栏就能填。模型 API、Agent 市场、边缘推理把这些边界打散了：你采购的是「能力」，而能力的输入输出边界、责任边界、退出边界都不像一套系统那样清楚。
- **AI 改变了什么机制**：改变的是**采购的粒度与锁定点的位置**——从「一个系统」变成「一个可组合的能力」，锁定从「数据格式与接口」位移到「评测集与提示词资产」；同时在合规与边缘两类场景里，采购这条路被**结构性封死**（监管要求与物理约束）。
- **由此得到的**：因为采购单位变小，所以候选空间变大、组合自由度变高；因为约束场景不可采购，所以「核心能力自研」这条清单会随监管细化而变长——**AI 同时让可采购的东西更细、让不可采购的东西更多**，两个方向都指向同一个动作：把可逆性设计（BOT / 分阶段 / 退出演练）提前到决策当时，而不是等到第一次想换供应商时。
- **由此付出的**：
  - ①**责任边界模糊**——模型输出出错时，供应商只对可用性负责，不对你的业务后果负责；这条边界不写进合同就默认不存在。
  - ②**退出成本不可见**——锁定不再写在数据格式里，而写在评测集、提示词与团队经验里，迁移成本难以在采购前估出，于是 [§ 7.3.3 可逆性](03-build-vs-buy-section-7-sec7.md) 那套算法缺了输入。
  - ③**治理成本转移**——Agent 市场「安装方便」省下的是集成成本，增加的是安全与数据边界评审成本；省下的在明处，多出的在暗处。
- **证据与来源**：模型推理 API 与开源微调工具链均已 GA，第三方生产案例普遍【可自行核验：各厂商官方文档与 release note】；Agent 市场已上线（如 OpenAI 官方公告的 GPT Store，【公开，2024】）——但**企业级采购路径**（数据边界、可审计、退出）未见成型案例。判定方法：看它的条款里有没有数据处理与退出约定，而不是看安装量。
- **成熟度**：**L2（模型 API 与微调）/ L3（Agent 市场作为企业采购渠道）**。判据：API 已生产可用但接口与价格变动频繁；市场渠道目前只有消费级可用性，没有企业采购治理路径。

锁定点位移的对照：

| 锁定载体 | 传统采购（一套系统） | 能力级采购（一个模型 / Agent） | 判定方法 |
| --- | --- | --- | --- |
| 数据 | 数据格式与导出接口 | 数据边界写在条款里，实际边界取决于推理路径 | 问「输入会不会离开我的域」并要求书面回答 |
| 接口 | 私有 API | 提示词与调用协议 | 换一个模型，看有多少提示词要重写 |
| 技能 | 专有工具链 | 团队对某家模型行为的隐性经验 | 让一个没做过该项目的人接手一周 |
| 效果基准 | 功能对比表 | **评测集**——谁拥有它，谁定义「好」 | 评测集在谁手里？能不能带走？ |

这里有一个反直觉的组合：**采购单位变小与不可采购范围扩大是同一件事的两面**。因为能力可以被拆细，所以「哪一段必须自持」这个问题第一次能被问得足够小（不再是「整个推荐系统自研还是采购」，而是「特征平台自持、排序模型采购」）；而正因为被拆细，责任会散落到更细的接缝上，接缝越多，越需要有人对整体负责——这是 BOT 与分阶段设计在 AI 时代重新变重要的原因。

落到操作上，这一条给出的是**两件必做的文书**：一份写清数据边界与退出条件的采购条款，一份记录退出演练结果的复评材料。它们都不产生功能，只产生可核验的证据——也正因如此，它们在立项时最容易被砍，而砍掉的代价要等到第一次想换供应商时才浮现。

### 5.3 与本主题既有栈的接口在哪

「与 AI 结合」这种说法没有信息量。真正要写清的是**接口边界**：谁调用谁、数据以什么形态穿过边界、失败时谁负责。这三件事里最容易漏的是第三件——大多数「AI 辅助 X」的方案描述到「输出一份报告」就结束了，而报告之后的动作与责任，才是它能否留下来的分界线。

| 结合点 | 接口形态 | 谁负责失败 | 现状 |
| --- | --- | --- | --- |
| 文书辅助 → [§01 ADR](../01-adr/01-adr.md) | 模型输出作为 ADR「备选方案与理由」栏的草稿，人署名 | **签字人**——AI 不承担结论责任 | 可用；模板里需显式标注起草方式 |
| 决策记录 → 检索库 | 结构化字段（决议 / 被否方案 / 责任人 / 复评日期）→ 索引 | **记录人**——字段缺失则检索为空，责任在「谁来喂养」 | 可用；先结构化再上图 |
| 决策记录 → ADR 复评提醒 | 复评日期到期触发复评任务 | **ADR 所有者**——不复评则决策静默过期 | 可用（模板字段 + 日历） |
| 决策记录 → 复评看板 | 复评状态与闭环率汇总成管理视图 | **决策负责人**——不闭环由他解释 | 可用；先有字段，再有看板 |
| 判据规则 → 采购单与 [§07 架构评审](../07-architecture-review/07-architecture-review.md) 门禁 | 采购请求或变更单触发校验，返回放行 / 阻断 + 理由 | **规则所有者**——误报拖慢交付由他承担 | 规则可行；本主题公开案例缺位 |
| 能力级采购 → 合同与数据条款 | API 合同 + 数据处理条款 + 退出演练记录 | **采购方**——供应商只对可用性负责 | 模型 API 可行；Agent 市场未成型 |
| 微调 / 自研模型 → 评测集与提示词资产 | 评测集版本 + 模型版本 + 可替换性验证 | **自己**——模型供应商不为你的微调结果负责 | 可行；多数组织尚未自持评测集 |
| 供应商风险 → [§04 风险评估](../04-risk-assessment/04-risk-assessment.md) | 供应商风险项与 FMEA 条目合并，概率与影响由人填 | **评估人**——模型只能给清单，不能给概率 | 可用；注意别用生成值填 P_failure |

两处结构性失配要提前处理：其一，**AI 的输出形态**（一段带论证的文本）与**流程要求的形态**（结构化字段、可被门禁判定）不一致，所以「AI 写方案 + 人抄进表格」这种接法在第二次就会退化为不复用；正确做法是让 AI 直接产出字段。其二，**失败责任的默认归属**在 AI 介入后会漂移——谁都没错的时候，通常会落到「最后点通过的那个人」头上，因此需要在流程里显式写明签字人，而不是靠事后找人。

接口的**最小可用形态**不是「模型直接给答案」，而是「模型把材料变成字段」：

```text
决策记录的最小字段集（缺任何一项，检索与门禁都不可用）
  id / 决议（选了什么）
  / 理由（可核验的机制，不是生成文本）
  / 被否决的方案及其被否的理由
  / 责任人（具体到人，非团队） / 日期
  / 复评触发条件（日期或事件） / 复评结果
→ 字段化之后：检索、门禁、复评、审计四条路复用同一份数据
→ 不字段化：每加一个用途就要重做一次解析，第二次就不会再做
```

这也是判断一个「AI 决策平台」是否真的落地的最快方法：**看它的数据模型里有没有「被否决的方案」与「责任人」两个字段**。没有这两个字段，它存的是会议记录；有，它才可能成为判据的来源。

本节只把**能回查的条目**当文献列：给出文档名 + 年份。给不出文档名、只能给出**核验路径**的，单列进下面「判定方法」一段——它们的作用是告诉你「去哪读、按什么口径判」，不是替某个结论背书。两者混在同一张清单里，是这一节最容易读起来像有证据、实际无从核验的地方。

**论文与理论**

- 交易成本经济学的原始论证：Coase《The Nature of the Firm》【公开，Economica, 1937】与 Williamson 的展开《Markets and Hierarchies》【公开，1975】/《The Economic Institutions of Capitalism》【公开，1985】——「企业边界由交易成本决定」是本主题判据（差异化、可逆性）的理论根。

- Constitutional AI：Anthropic《Constitutional AI: Harmlessness from AI Feedback》【公开，arXiv, 2022】——它是**模型对齐**研究，不是组织决策方法；把它外推成「用宪法约束 Make-or-Buy」属 L3 类推，本节因此只作记录，不列为方向。
- 架构评审侧的公开方法论：SEI 的 ATAM（《ATAM: Method for Architecture Evaluation》，CMU/SEI-2000-TR-004，2000）与 ARID（Clements，《Active Reviews for Intermediate Designs》，CMU/SEI-2000-TN-009，2000）——本主题与评审的接口（5.3 表里的门禁与责任归属）以它们为判据来源，详见 [§07 架构评审](../07-architecture-review/07-architecture-review.md)。**年份与报告编号请以 SEI 官方站点为准**：此处给出编号是为了让你能回查原报告，而不是让这一段自成出处。

### 5.5 被过度宣传的部分

**「AI 让自研门槛消失」** —— 实际是「让写出第一版的门槛下降」。
→ 为什么会这样：自研的成本大头不在首版，在维护（读懂既有代码、跟上上游变更、承担故障），这三件事由「理解与责任」决定而不是由生成速度决定，而 AI 只压低了三个方向里的第一个（见 5.2.2 的表）。
→ 什么时候它才会成真：当 AI 生成的变更能被同等强度的评审门禁接受、且长期缺陷率不升。可核验的信号：同一团队在引入 AI 辅助后，单位变更的返工率与事故率持平或下降，并能拿出对照数据。

**「Decision Intelligence / 决策图谱让组织决策自动一致」** —— 实际是「把决策记录结构化地存下来」。
→ 为什么：图谱的价值来自**喂养质量**与**责任归属**，这两件都是组织问题不是技术问题；没有署名的历史决策入库后只是文本，检索出来的东西不能作为 ADR 理由（[§ 7.3.4](03-build-vs-buy-section-7-sec7.md)：理由必须是可核验的机制）。
→ 什么时候它才会成真：当「决策入库」变成流程的必填产物（像 ADR 一样有模板与门禁），而不是事后补录。判定方法：看图谱里有没有一条是「因为入库而被复用过」的。

**「模型 API 便宜 = 采购一定更划算」** —— 实际是成本函数换了形状，不是变便宜。
→ 为什么：API 把成本从「人头 + 基础设施」换成「按用量 + 按调用特征」，只要数据权属与合规边界不变，单位成本下降就不改变**退出成本**（[§ 7.3.3 可逆性](03-build-vs-buy-section-7-sec7.md)）；而 AI 场景下的锁定更多来自评测集与提示词资产，不来自数据格式，所以 [§ 3.1 模式 8](03-build-vs-buy-section-3-sec3.md) 那张五栏锁定表会给出偏乐观的结论。
→ 什么时候它才会成真：当供应商提供可携带的评测与微调资产出口（例如可导出微调成果或标准化评测迁移），或出现被广泛采用的模型替换中间层。

这三条有同一个形状：**它们都在拿「省下的在明处」换「多出的在暗处」**。判断一条宣传语是否值得采信，最快的办法是问一句「省下的那项写在哪张表上，多出的那项写在哪张表上」——如果多出的那项在任何表里都找不到位置，这一轮决策的账注定会记错。

它们能长期存在也是同一个原因：**收益记在当下的表里，代价记在未来的账上**。要在组织里顶住这类叙事，靠的不是怀疑，而是把「未结算项」提前写进决策记录——谁承担、什么时候复评、复评时看哪个数。

### 5.6 未来 3–5 年：可证伪的预测

每条预测都必须能说清「什么信号说明它对了、什么信号说明它错了」。写不出信号的预测不入表——「AI 原生决策」这类句子永远正确，因而没有信息量。

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| 「AI 生成初稿」成为 ADR 的默认输入，但**署名与责任仍在人** | 公开的组织级 ADR 模板出现「起草方式」字段或 AI 辅助声明要求 | 受监管行业的 ADR 模板明文禁止 AI 参与初稿，或要求人工重写并声明 |
| 锁定点从「数据与接口」位移到「评测集与提示词资产」，并写进合同 | 公开的采购条款模板出现评测集 / 提示词归属与导出约定 | 合同仍只约定数据导出，且模型替换被证实在数周内完成且不损失效果 |
| 决策留痕在大型组织里落地为「图谱 = 可检索记录」，提醒与推荐退居次要 | 落地图谱的 schema 里「责任人 / 签名 / 日期」是必填且不可空 | 出现被公开引用、由图谱推荐直接改变结论并度量了效果的案例 |
| 合规与边缘两类能力**持续不可采购**，且随监管细化而扩大范围 | 公开监管要求里出现「须能自证推理链路 / 数据不出域」的强制条款 | 跨境推理获得普遍合规通道且被监管明文认可 |

怎么用这张表：**每季度对一次信号，而不是对结论**。四条里前两条属于「会推着我们改流程」，后两条属于「会推着我们改清单」——如果年终发现第一条的成真信号已经出现，你的 ADR 模板就该先改；如果只有第四条出现，那说明不可采购的范围在扩大，该补的是「哪些能力必须自持」的清单，而不是采购工具。

还有一个经常被忽略的信号源：**招聘与团队组建**。当组织开始为「决策平台」设岗，说明它进了执行阶段；当这些岗位一年内又被合并掉，说明前一版假设没成立。招聘页面通常比路线图诚实。

这张表里**刻意没有**的东西，比有的东西更能说明本节的立场：没有「AI 会替人做 Make-or-Buy 决策」这一条。原因不是立场，而是它写不出证伪信号——「AI 参与决策」在什么情况下算错？答不上来，就不该进路线图。同理，本节也没写「几年内会到 L1」：时间点写不出信号，和预测写不出信号，性质是一样的。

### 5.7 给架构师的行动建议

| 你的处境 | 现在就该做 | 一年内观察 | 明确不要做 |
| --- | --- | --- | --- |
| 正准备做一次自研 vs 采购决策 | 用模型把历史 ADR、合同、TCO 表检索出来做**查漏**，结论自己签 | 同类决策的复评周期有没有缩短 | 不要让模型给出「该自研还是该买」的结论并写进 ADR 理由栏 |
| 组织里 ADR 已成型 | 把决策记录改成可检索（决议 / 被否方案 / 责任人 / 复评日期必填） | 检索是否真的改变过某次结论 | 不要先建图数据库或决策图谱平台 |
| 想上 Build-vs-Buy-as-Code | 先把 3–5 条硬判据（合规归属、预算上限、退出）写成可判定校验，挂在采购单或评审门禁 | 假阳性阻断率与绕行情况 | 不要让规则自动生成决策报告（属 L3），也不要先买平台 |
| 团队正在引入 AI 辅助编码 | 把省下的时间投到评审与测试，并把返工率纳入度量 | 待维护件数与维护人时的走向 | 不要把「AI 让自研更便宜」写进 TCO 论证当既定事实 |
| 强监管 / 边缘场景 | 先确认硬约束（数据不出域、延迟、离线）是否真实存在 | 监管条款与属地要求的变化 | 不要为了「自主可控」去自研可采购的通用件——这是伪自研的 AI 变体 |
| 已在用三方模型 API | 自持评测集与提示词，并做一次真实的退出演练 | 单位用量成本与替换周期 | 不要在没做过退出演练前，把核心链路锁死在单一模型上 |
| 团队人手紧、什么都想自研 | 用 [§ 3.3 反模式](03-build-vs-buy-section-3-sec3.md) 逐条自检，先砍掉通用件 | 自研件数量与维护人时之比 | 不要用「AI 能帮我们写」为任何一项边缘能力辩护 |
| 组织刚引入 AI 工具、没人管产出 | 先立一条规矩：AI 产出只能是「待核查项」，不能是结论 | 有没有出现「问过 AI 就直接执行」的记录 | 不要在没定署名规则前，把 AI 接进决策流程 |

「明确不要做」这一列才是本节的用处所在：上面八行里，**现在做就是浪费**的事有五件——让模型给结论、先建决策图谱、让规则自动生成决策报告、在没有退出演练的情况下锁死单一模型、在没定署名规则前把 AI 接进流程。它们的共同特征是**都能做出好看的产出物**（一份决策报告、一张图、一条规则、一次成功的调用演示），因此最容易在立项时拿到支持，也最容易在两年后变成没人维护的资产。

### 5.8 小结

> 本节小结：本主题下 AI 真正改变的**唯一一条机制**是**证据获取与首版实现的边际成本**——它让「查一下以前怎么定的」和「先写一版试试」变便宜，于是可逆性判据的适用区间被扩大。
>
> 它**没有改变**的是三件事：成本函数里维护那一项、结论的责任归属、能力级采购的退出成本。这三件决定了 AI 时代的 Make-or-Buy 判据仍然是**人签字的判据**——只是证据更全、首版更便宜、判据更容易被写进流水线。
>
> 因此本节的结论不是「AI 让自研更容易」，而是：**AI 把决策的证据门槛降低了，把可逆性的价值抬高了**。对一个具体的决策而言，先问「停得下来吗」，再问「AI 能不能帮我们做」，顺序不能反。
