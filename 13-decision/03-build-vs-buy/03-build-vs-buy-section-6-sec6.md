## 6. 落地实践

### 6.1 真实案例

**案例 1：阿里巴巴的数据中台自研**

阿里在 2015 年决定自研数据中台（OneData / OneID / OneService）：

- **战略价值**：核心差异化 → 自研。
- **团队能力**：阿里数据团队规模大 + 能力强 → 自研。
- **TCO 3 年**：自研 5 亿 vs 采购 3 亿 → 自研贵 67%，但战略价值更高 → 选自研。
- **结果**：数据中台成为阿里电商 / 金融 / 云的核心竞争力。

**案例 2：字节跳动的向量库选型**

字节跳动 2023 年向量库选型：

- **战略价值**：RAG 基础设施 → 中等。
- **TCO 3 年**：自研 1.5 亿 vs 采购 Pinecone 0.6 亿 → 自研贵 150%。
- **Vendor Lock-in**：Pinecone 高 → 自研（基于 Milvus 二次开发）。
- **决策**：混合——核心引擎自研 + 边缘 API 采购。

**案例 3：Netflix 的 Kafka 选型**

Netflix 选型 Kafka 时：

- **战略价值**：核心数据管道 → 高。
- **团队能力**：有 Kafka 专家 → 自研运营。
- **采购方案**：Confluent Cloud 托管 → 评估 TCO。
- **决策**：混合——核心自运维 + 边缘业务用 Confluent Cloud。

**案例 4：OpenAI 的自研 vs API（反面案例）**

OpenAI 自 GPT-3 起选择 API 优先：

- **优势**：快速上线 + 商业化快。
- **劣势**：被开源追赶 + 客户锁定 OpenAI。
- **后续**：2024 年推出 GPT Store + 微调，让客户「自建 + 采购」混合。

### 6.2 踩坑与经验

1. **「伪自研」**：外壳套开源，无战略价值。**严格检测 5 项特征**。
2. **「盲目采购」**：所有都 SaaS，结果锁定 + 合规失控。**核心必须自研**。
3. **「TCO 错误」**：只看初始成本。**3-5 年 TCO**。
4. **「战略自主性误判」**：把非核心当核心。**用 Core-Edge-Spot**。
5. **「采购慢就自研」**：因为采购慢就自研。**评估自研周期是否更长**。
6. **「忽视维护成本」**：自研初期便宜，3 年后爆炸。**TCO 含人力**。
7. **「过度核心化」**：什么都自研。**通用能力坚决采购**。
8. **「不培养团队」**：采购后团队永远学不会。**采购 + 培养并行**。

### 6.3 落地路径（0→1, 1→10, 10→100）

**0→1（10 人以下团队）**：

- Core-Edge-Spot 分类；
- 核心能力自研；
- 边缘能力采购 / SaaS；
- TCO 3 年计算。

**1→10（10-50 人）**：

- 引入 Risk-adjusted NPV；
- Sensitivity Analysis；
- Make-or-Buy Decision Tree；
- BOT 模式（核心能力分阶段）；
- ADR 强制。

**10→100（50+ 人）**：

- 组织级 Make-or-Buy 战略；
- AI 辅助决策；
- Decision Intelligence Platform；
- Build-vs-Buy-as-Code；
- 季度复盘。

### 6.4 ROI 评估

**直接收益**：

- 自研 vs 采购最优决策 → 节省 20-40% TCO；
- 战略自主性提升 → 长期竞争优势；
- 伪自研识别 → 节省维护成本 30-50%；
- 决策速度提升 → 30%。

**间接收益**：

- 组织战略对齐；
- 核心能力沉淀；
- 避免供应商锁定。

**成本**：

- 决策时间：每决策 +2-3 小时；
- TCO 计算：1-2 人天 / 决策；
- 培训成本：内部 Workshop。
