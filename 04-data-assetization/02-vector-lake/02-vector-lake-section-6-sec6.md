### 2.1 Databricks"**Lakehouse + Vector Search 4+ 年**"（2020-2024）

**背景（Why）**

- **LLM / RAG**——需要向量
- **多模态**——文本 + 图片 + 视频

**触发点（What）**

2020 年 Databricks 推出 **Lakehouse + Vector Search**（[Databricks 2020]），目标：
- **Lakehouse 上做向量**
- **RAG 直接用**
- **多模态**

**详细做法（How）**

Databricks Vector Search 的**5 大核心组件**：

1. **Delta Lake + Vector（核心创新）**

   - 关键能力：**湖仓一体**
   - 关键数字：**100% 兼容**

2. **多模态 embedding（核心）**
   - 关键设计：**Databricks 自研 embedding**
   - 关键能力：**文本 + 图片 + 视频**
   - 关键数字：**多模态**

3. **RAG 集成（核心）**
   - 关键设计：**LlamaIndex / LangChain 集成**
   - 关键能力：**RAG 直接用**

   - 关键设计：**自动 sharding**

> **本节小结**：
> - 4 个真实案例（Databricks / 字节 / 阿里 / Weaviate）印证：**向量湖不是「**向量库 + 湖**」，是「**Delta Lake + Vector + 多模态 + RAG + SaaS**」**5 件套**。

> - 选型第一原则：「**Milvus / pgvector 起步**」（**最简单**）——**1 个业务** → 「**多模态 + RAG**」（**必须**）→ 「**湖 + 向量 + SaaS**」（**生产**）→ 「**多业务 + PB 级**」（**AI 时代**）。
> - 99% 的失败来自「**湖与向量割裂 + RAG 集成难 + 性能不够**」——必须有 **Lakehouse + Vector + LangChain 集成 + 索引优化**。
> - 真正的 ROI 来自「**湖 + 向量统一 + 多模态 + 1000+ 客户**」——是**大厂核心向量湖基础设施的命脉**。
