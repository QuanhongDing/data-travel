### 3.1 某电商"**AI Function in SQL 4+ 年**"（2020-2024）

**背景（Why)**

该电商 2020 年面临**AI Function in SQL**：
- **AI 与数据割裂**——AI 在 Python，数据在 SQL
- **数据出仓**——AI 计算要先把数据导出
- **合规风险**——**数据出仓后无法管控**

**触发点（What）**

2020 年该电商启动**AI Function in SQL**（[案例 2020]），目标：
- **AI in SQL**
- **数据不出仓**
- **合规**

**详细做法（How）**

该电商 AI in SQL 的**5 大核心组件**：

1. **AI Function 注册（核心创新）**
   - 关键设计：**embedding / classify / llm 注册为 SQL UDF**
   - 关键能力：**SQL 直接调用 AI**
   - 关键数字：**100+ UDF**

2. **数据不出仓（核心）**
   - 关键设计：**AI 在数据仓库内执行**
   - 关键能力：**零数据出仓**
   - 关键数字：**0 出仓**

3. **SQL 集成（核心）**
   - 关键设计：**SELECT embedding(...) FROM ...**
   - 关键能力：**业务自助**
   - 关键数字：**100% SQL 化**

4. **合规可查（核心）**
   - 关键设计：**每条 AI 调用可追溯**
   - 关键能力：**合规**
   - 关键数字：**100% 可查**

5. **多模态 SQL（核心创新）**
   - 关键设计：**文本 + 图片 + 视频**
   - 关键能力：**多模态**
   - 关键数字：**多模态**

> **本节小结**：
> - 4 个真实案例（某电商 / Snowflake / Databricks / 阿里）印证：**AI 原生数据库不是「**AI + 数据库拼起来**」，是「**AI UDF + 数据不出仓 + 多模态 + PAI 集成 + SaaS**」**5 件套**。
> - 关键时间线：4+ 年 / 3+ 年 / 3+ 年 / 4+ 年 —— **AI 原生数据库是 3+ 年长期工程**。
> - 选型第一原则：「**AI UDF 注册起步**」（**最简单**）——**1 个业务** → 「**数据不出仓 + SQL 集成**」（**必须**）→ 「**多模态 + PAI 集成**」（**生产**）→ 「**10000+ 客户 + SaaS**」（**AI 时代**）。
> - 99% 的失败来自「**AI 与数据割裂 + 数据出仓 + 合规缺失**」——必须有 **AI in 仓 + 零出仓 + 每条可追溯**。
> - 真正的 ROI 来自「**AI in 仓 + 0 出仓 + 10000+ 客户**」——是**大厂核心 AI 原生数据库基础设施的命脉**。
