### 7.1 字节"**Bytemetric + 数据 API 网关 4+ 年**"（2020-2024）

---

> **本节小结**：
> - 4 个真实案例（字节 / 阿里 / 美团 / 某 SaaS）印证：**数据 API 网关不是「**业务方随便建 API**」，是「**API 网关 + 限流鉴权 + 标准化 + 业务自助 + 多业务**」**5 件套**。
> - 关键时间线：字节 4+ 年 / 阿里 8+ 年 / 美团 5+ 年 / 某 SaaS 4+ 年 —— **数据 API 网关是 4+ 年长期工程**。
> - 选型第一原则：「**API 网关起步**」（**最简单**）——**10+ API** → 「**GraphQL + 业务自助**」（**必须**）→ 「**多业务统一 + 集成**」（**生产**）→ 「**100 万+ API + SaaS**」（**AI 时代**）。
> - 99% 的失败来自「**API 割裂 + 限流缺失 + 复用率低**」——必须有 **API 网关 + Sentinel + 业务自助**。
> - 真正的 ROI 来自「**复用率 70~80%+ + 100 万+ API + 多业务**」——是**大厂核心数据 API 网关基础设施的命脉**。
