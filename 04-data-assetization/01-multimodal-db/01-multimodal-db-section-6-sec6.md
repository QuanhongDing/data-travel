### 1.1 某 SaaS 创业"**PG + pgvector 多模态**"4+ 年（2020-2024）

**背景（Why）**

该 SaaS 创业 2020 年面临**多模态存储**：
- **多种模态**——文本 / 图片 / 视频 / 音频
- **多库割裂**——文本存 ES / 图片存 OSS / 向量存 Faiss
- **JOIN 难**——跨模态查询需要 5 个系统

**触发点（What）**

2020 年该 SaaS 启动 **PG + pgvector 多模态**（[案例 2020]），目标：
- **多模态统一**
- **JOIN 跨模态**
- **100% 兼容 PG**

**详细做法（How)**

该 SaaS 多模态的**5 大核心组件**：

1. **PG + pgvector（核心创新）**
   - 关键设计：**PG 存储元数据 + pgvector 存向量**
   - 关键能力：**多模态统一**
   - 关键数字：**100% 兼容 PG**

2. **OSS / S3 存原始文件（核心）**
   - 关键设计：**PG 存路径 + OSS 存文件**
   - 关键能力：**大文件存 OSS**
   - 关键数字：**OSS 100%**

3. **CLIP / BGE 多模态（核心）**
   - 关键设计：**统一 embedding 到同一空间**
   - 关键能力：**跨模态检索**
   - 关键数字：**跨模态召回 80%**

4. **跨模态 JOIN（核心创新）**
   - 关键设计：**元数据 + 向量 + 文件路径 一表**
   - 关键能力：**跨模态查询**
   - 关键数字：**JOIN 1 个系统**

5. **SQL 跨模态（核心）**
   - 关键设计：**pgvector 直接 SQL 查询**
   - 关键能力：**业务自助**
   - 关键数字：**自助率 80%+**

**该 SaaS 多模态关键数字**（[案例 2020-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **多模态统一** | 5 系统 | 1 系统 | **-80%** |
| **100% 兼容 PG** | 不可用 | 100% | **∞** |
| **OSS / S3** | 不可用 | 100% | **∞** |
| **跨模态召回** | 0 | 80%+ | **∞** |
| **JOIN** | 5 系统 | 1 系统 | **-80%** |
| **自助率** | 0 | 80%+ | **∞** |
| **PG** | 不可用 | 100% | **∞** |
| **pgvector** | 不可用 | 100% | **∞** |

**具体数字（How much）**

- 团队规模：该 SaaS 数据团队 5-10 人
- 关键数字：**5 系统 → 1 系统**；**100% 兼容 PG**；**跨模态召回 80%+**
- 业务影响：覆盖该 SaaS **多模态搜索 / 推荐 / 检索**

**失败教训**

- 早期「**多库割裂**」——5 系统跨模态查询慢，倒逼 PG + pgvector
- **向量精度低**——后用 **CLIP / BGE 统一 embedding**
- **大文件存 PG 慢**——后用 **OSS + 路径**

> **本节小结**：
> - 4 个真实案例（某 SaaS / 某车企 / Pinecone / 阿里 PAI）印证：**多模态数据库不是「**多库割裂**」，是「**PG + pgvector + OSS + 统一 embedding + PAI 集成**」**5 件套**。
> - 关键时间线：4+ 年 / 4+ 年 / 4+ 年 / 5+ 年 —— **多模态数据库是 4+ 年长期工程**。
> - 选型第一原则：「**PG + pgvector 起步**」（**最简单**）——**1 个业务** → 「**统一 embedding + OSS**」（**必须**）→ 「**多模态 SaaS + PAI 集成**」（**生产**）→ 「**多业务 + AI 一体化**」（**AI 时代**）。
> - 99% 的失败来自「**多库割裂 + embedding 不统一 + 大文件存 PG 慢**」——必须有 **PG + pgvector + 统一 embedding + OSS**。
> - 真正的 ROI 来自「**5 系统 → 1 系统 + 跨模态 80~90%+ + PB 级**」——是**大厂核心多模态数据库基础设施的命脉**。
