### 7.2 决策树

```
你的业务是否有已知峰值事件？
├─ 是 → 你的峰值是日常的多少倍？
│      ├─ 3-10 倍 → 大促保障（限流 + 弹性扩容 + 全链路压测）
│      ├─ 10-50 倍 → 大促保障 + 单元化
│      └─ 50 倍以上 → 单元化 + 异地多活 + 大促保障
└─ 否 → 你的峰值是突发事件还是持续增长？
       ├─ 突发事件 → 容量规划 + 弹性扩容
       └─ 持续增长 → 容量规划 + 灰度发布
```

### 7.3 组合使用

大促保障通常不是单一手段，而是多种能力的组合：

- **大促保障 + 容量规划**：预测 → 评估 → 准备。
- **大促保障 + 单元化**：单元化是大促保障的高级形态。
- **大促保障 + 异地多活**：跨地域分摊峰值。
- **大促保障 + 混沌工程**：演练验证。
- **大促保障 + 灰度回滚**：快速止血。
- **大促保障 + AI 时代**：AI 推理服务保障 + 智能体链路保障。

**最佳实践组合**：

```
[容量规划] → 预测峰值
    ↓
[全链路压测] → 验证承载力
    ↓
[单元化 / 异地多活] → 架构形态
    ↓
[限流降级 + 熔断] → 流量管理
    ↓
[弹性扩容] → 资源调度
    ↓
[混沌工程 + 灰度回滚] → 应急手段
    ↓
[GameDay + 值班] → 组织能力
```
