### 6.1 阿里"**DR 三地五中心 + 单元化**"10+ 年（2013-2024）

**背景（Why）**

阿里 2013 年面临**双 11 DR**挑战：
- **单机房**——**「**故障就垮**」**
- **2013 杭州机房故障**——**30 分钟中断**——**千万级损失**

**触发点（What）**

2013 年**阿里启动 DR 三地五中心项目**（[阿里 2023 双 11 复盘]）——**目标**：「**5 个 9 + 月演练**」。

**详细做法（How）**

阿里 DR 的**5 大核心组件**：

1. **三地五中心（同城双活 + 异地灾备，核心）**
   - 关键设计：**杭州 2 + 上海 1 + 深圳 1 + 异地灾备 1**——**5 中心**
   - 关键能力：**异地灾备**——**RPO 秒级**——**RTO 分钟级**

2. **单元化（核心）**
   - 关键设计：**12 个 Cell**——**每 Cell 跨 5 中心**
   - 关键代码：
     ```java
     // 阿里 DR 单元化
     public class DRCellRouter {
         public int getDRCell(long userId) {
             int cell = (int) (Math.abs(userId) % 12);
             // 5 中心 + 12 Cell
             return cell;
         }
     }
     ```

3. **数据同步（精卫 CDC，核心）**
   - 关键设计：**精卫**——**CDC + 影子库**——**秒级同步**
   - 关键能力：**RPO < 10 秒**

4. **DR 演练（核心关键）**
   - 关键设计：**每月 1 次小演练**——**每年 1 次大促演练**
   - 关键能力：**「**真切换**」**——**「**5 分钟恢复**」**
   - 关键数字：**10+ 年 0 严重故障**

5. **「**异地多活 + 灾备**」**（核心架构）**
   - 关键设计：**多活 + 灾备**——**「**双保险**」**

**阿里 DR 关键数字**（[阿里 2023 双 11 复盘]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **RPO** | 1 小时 | < 10 秒 | **360 倍** |
| **RTO** | 30 分钟 | 2 分钟 | **15 倍** |
| **DR 演练** | 季度 1 次 | 月 1 次 | **12 倍** |
| **可用性** | 99.9% | 99.99%+ | **10 倍** |
| **0 严重故障** | 0 | 10+ 年 | **∞** |

**具体数字（How much）**

- 团队规模：阿里 DR 团队 100+ 人
- 关键数字（[2024 公开数据]）：
  - **RPO < 10 秒**
  - **RTO 2 分钟**
  - **月 1 次演练**
  - **10+ 年 0 故障**
- 业务影响：覆盖**阿里全集团**

**失败教训**

- 第 1 年**演练不足**——倒逼**「**月演练**」**
- **「**数据冲突**」**——倒逼**「**单元化**」**
- **「**切换慢**」**——倒逼**「**自动化**」**

### 6.2 AWS「**DR 多 Region + Pilot Light**」10+ 年（2014-2024）

**背景（Why）**

AWS 2014 年面临**云 DR**挑战：
- **「**云原生 DR**」**——**「**「**Backup & Restore**」**/**Pilot Light**」**/**Warm Standby**」**/**Multi-Site**」** 4 种策略
- **客户需求**——**「**「**简单**」** + **「**便宜**」** + **「**可靠**」

**触发点（What）**

2014 年**AWS 发布 DR 设计白皮书**（[AWS 2014 白皮书]）——**目标**：「**4 种 DR 策略**」。

**详细做法（How）**

AWS DR 的**4 大策略**（从最便宜到最可靠）：

1. **Backup & Restore（最便宜，RPO/RTO 小时级）**
   - 关键设计：**S3 备份**——**「**小时级恢复**」**
   - 关键代码：
     ```python
     # AWS Backup & Restore
     class BackupRestore:
         def backup(self, data):
             s3.put_object(Bucket='dr-backup', Key=data.id, Body=data)
         def restore(self, data_id):
             return s3.get_object(Bucket='dr-backup', Key=data_id)
         # RPO: 1 小时（每小时备份）
         # RTO: 1-12 小时
     ```

2. **Pilot Light（核心，RPO 分钟级 / RTO 小时级）**
   - 关键设计：**核心服务**——**「**最小运行**」**——**「**灾备**」**
   - 关键能力：**「**关键服务**」**——**「**永远在线**」**

3. **Warm Standby（核心，RPO 秒级 / RTO 分钟级）**
   - 关键设计：**「**完整环境**」**——**「**低流量运行**」**
   - 关键能力：**「**快速切换**」**

4. **Multi-Site（最可靠，RPO 秒级 / RTO 秒级）**
   - 关键设计：**多 Region**——**「**全流量**」**——**「**「**自动切换**」**
   - 关键能力：**「**实时**」**——**「**「**RPO=0**」**

**AWS DR 关键数字**（[AWS 2014 白皮书]）：

| 指标 | Backup & Restore | Pilot Light | Warm Standby | Multi-Site |
| --- | --- | --- | --- | --- |
| **RPO** | 小时 | 分钟 | 秒 | 秒 |
| **RTO** | 小时 | 小时 | 分钟 | 秒 |
| **成本** | $ | $$ | $$$ | $$$$ |
| **可用性** | 99% | 99.9% | 99.99% | 99.999% |
| **「**AWS 客户**」** | 100 万+ | 100 万+ | 10 万+ | 1 万+ |

**具体数字（How much）**

- 团队规模：AWS DR 团队 100+ 人
- 关键数字（[2024 公开数据]）：
  - **4 种 DR 策略**——**全行业标准**
  - **100 万+ AWS 客户**——**DR 实践**
- 业务影响：覆盖**全球 100+ 国家**

**失败教训**

- 早期**「**RPO 大**」**——倒逼**「**Pilot Light**」**
- **「**RTO 慢**」**——倒逼**「**Warm Standby**」**

### 6.5 真实落地路径（基于上述 4 个案例提炼）

---

> **本节小结**：
> - 4 个真实案例（阿里 / AWS / Netflix / Azure）印证：**DR 不是「**备份**」，是「**三地五中心 + 单元化 + 自动演练 + 混沌工程**」**组合。
> - 关键时间线：阿里 10+ 年 / AWS 10+ 年 / Netflix 10+ 年 / Azure 8+ 年 —— **DR 是 10+ 年长期工程**。
> - 选型第一原则：**Backup & Restore**（**最简单**）——**S3 备份** → **Pilot Light**（**核心服务**）→ **Warm Standby**（**完整环境**）→ **Multi-Site**（**多 Region**）。
> - 99% 的失败来自「**RPO/RTO 大 + 演练不足 + 手动**」——必须有**CDC + 月演练 + 自动切换**。
> - 真正的 ROI 来自「**360 倍 RPO + 12-30 倍 RTO + 12-365 倍演练**」——是**企业核心业务的命脉**。
