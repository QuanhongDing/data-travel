## 5. 前沿演进（AI 时代）

### 5.1 先分清四类「前沿」

本主题的清单里混着四种性质不同的东西：**既有方法与工具**（可解释性、因果推断、实时决策链路）、**把 LLM 接进决策链路的四种用法**（生成规则 / 生成解释 / 直接出决策 / 审计决策）、**Agent 编排框架**、以及**厂商平台与模型发布消息**。它们被并列成「演进方向」之后，最典型的一个误读是：把「某个库存在、某个模型在演示里跑通」当成「决策可以自动做对了」。

决策智能还有一条别的主题没有的判据约束：决策是**有问责后果**的动作。本章 [§3.1](02-decision-intelligence-section-3-sec3.md) 把这层约束写得很直白——**决定模式选择的第一条不是技术偏好，而是问责结构：这个决策做错了以后，代价由谁承担、能不能补救、事后能不能举证**。所以本节判一个方向能不能规划，问的不是「模型多强」，而是两件事：**它有没有改变问责结构**，以及**它的证据形态能不能被第三方复核**。

判一个方向能不能现在规划，本节用 L1 / L2 / L3 三级区分，判据是可核验的三条：

- **L1 生产可用**：**① 已 GA 且有正式 release note；② 有第三方（非厂商）公开生产案例；③ 接口稳定**。三条全中才算，可以排进路线图。
- **L2 可试点**：已可用但接口 / 生态未稳，或只有厂商自有案例，或只在小规模被验证。可做 PoC，不要做核心依赖。
- **L3 观望**：仅路线图 / 论文 / 厂商演示 / 预览特性。记录，不要在架构里预留假设。

**判据声明（只对表中标注「非 AI 能力」的行生效，本表与 §5.2 的逐项评估完全一致）**：本主题下第②条对 **AI 方向**是系统性不可得的——决策的运营细节（决策量、误判率、人工接管率、与监管沟通的口径）属于企业内部数据，公开材料通常只到「某公司在用某方法」，而这类材料绝大多数由产品或方法方自己发布，正是 L2 定义所指的「仅有厂商自有案例」。由此得到本节最重要的一句话：**没有任何一个 AI 方向达到 L1**。对标注「非 AI 能力」的行，本节把第②条替换为：**有多家彼此独立的组织分别实现或部署过该能力，且有可被第三方复核的机制性材料（论文 / 规范文本 / 公开仓库的发布记录）**；理由是这类能力的证据形态本就是「多方独立实现同一套方法」，而不是某一家的运营指标。这些行的①③仍按原样核（读者要能点到正式发布条目，并说清接口为什么是稳的）。

四件最容易混的事，先在这里分开：

- **方法名 vs 产品名**：SHAP、LIME、DML、CausalForest 都是**方法名**，各有原始论文；把它们当成某个平台的功能名会张冠李戴（本章 [§3.2.4](02-decision-intelligence-section-3-sec3.md) 已给出 DML、CausalForest、倾向得分匹配的论文出处）。各平台把这些方法实现成什么接口，互不相同。
- **论文里的原型 vs 产品里的能力**：判断某个能力能不能规划，只看一处——**该版本 release note 或官方文档里有没有对应条目**；产品博客、发布会视频、生态伙伴的转述都不算。
- **厂商自有案例 vs 第三方生产案例**：本章 [§6](02-decision-intelligence-section-6-sec6.md) 的四个案例（蚂蚁决策大脑、阿里多任务多目标、字节长序列建模、某银行三态风控）出处是「机构名 + 年份区间」的自述，属实践方自述，**不能充当第②条**。
- **接口改良 vs 架构变化**：把 LLM 接到决策链路上，多数情况下改的是**依据的获得方式**，不是决策的执行结构。判断方法只有一句：问「**能改状态的那个组件变了没有**」——没变，就是接口改良（本章 [§3.2.6](02-decision-intelligence-section-3-sec3.md) 的契约图把这条边界画在「LLM 只读、执行归确定性代码」上）。

本节有三件事不做，先说清楚：**不评模型能力**（「哪个模型推理更强」是别章的主题，这里只问它有没有改变依据的获得方式与问责结构）；**不评具体厂商产品的选型**（同一能力在不同产品里的成熟度不同，选型看各产品的官方文档与自家实测）；**不做「未来蓝图」式描述**（凡是写不出可观察信号的判断，都不写进 §5.6）。这三条边界决定了本节的结论会显得保守——**在后果不可逆的主题上，保守才是准确的**。

读下面这张表时，先看第三列，再看第二列：**判据是可核验的，级别只是它的结论**。如果你不同意某个级别，正确的反驳方式是拿出「某条判据其实满足」的证据（点得开的名字与年份），而不是争辩「这个方向很重要」——本节不按重要性排序，按可依赖性排序。

本节对每个方向都问同一句：**AI 到底改变了哪个机制**？本主题的答案只有一条：**决策依据的获得成本，从「必须先被人翻译成可枚举条件或特征」（一次性成本），挪到「每次决策都让模型读一遍文本」（边际成本）**。它改变的是**成本函数的位置与决策的频率门槛**，没有改变**问责结构**：谁最终裁决、出错了怎么举证、不可逆动作前有没有人——三件事一件没动（本章 [§3.1](02-decision-intelligence-section-3-sec3.md) 的六条约束表里，与这三条对应的是**第 2 行「可解释性与举证责任」与第 3 行「决策代价与可逆性」**——不是表首的「决策频率与延迟预算」）。这正是 L1 全在非 AI 侧的原因。

> 表里四条 L1 **全部是既有方法与既有工程能力**（可解释性工具、因果估计、实时链路、留痕与评估），没有一条是 AI 方向；AI 方向里最高只到 L2（LLM 起草规则与解释、LLM 直接出决策、检索侧的 RAG 与向量库、决策血缘与 ROI），检索侧的 KG 与 GraphRAG 路径推理更低，停在 L3。其余方向卡住的原因各不相同：Agent 决策卡在**失败模式组合化**（步数一多，成功率与成本都不可预测）；LLM 审计卡在**问责闭环**（审计者与被审计者同类）；KG 路径解释卡在**本体与图谱质量**。三条里没有一条是「模型不够强」。

**这三级排法直接决定路线图顺序**：

- **先做的四条就是上表前四行的「非 AI 能力」L1**：决策日志与留痕 → 分段延迟预算与降级 → 可解释性方法的落地（逐条可还原）→ 因果估计用于评估。它们排在所有 AI 方向之前，因为**后面每一个 AI 宣称都要靠这四件事才能被复核**：没有决策日志就没有「这次决策为什么」这句话，没有延迟预算就没有「LLM 能不能进在线链路」这句话，没有因果估计就没有「这个决策到底有没有用」这句话。
- **L2 做 PoC，并先测两个数**：LLM 在决策链路里的**单次成本 × 决策频率**（决定它该在离线侧还是在线侧），以及生成结果的**直接可用比例**（抽样复核后算）。这两个数拿不出来，L2 就停在原地。
- **L3 不排进排期**：Agent 决策、LLM 审计、KG 路径解释都属于「等信号」，它们的共同前提（步数与接管率可度量、问责闭环成立、本体有人维护）比选哪家框架重要得多。
- **回填机制**：每半年回填一次本行的级别；某个 L2 若一年内仍拿不到自己组织里的实测数字，降 L3 并停止投入。

### 5.2 演进方向逐条拆解（核心节）

下面四个方向按同一套结构写：**旧做法卡在哪 → AI 改变了什么机制 → 由此得到什么 → 由此付出什么 → 证据与来源 → 成熟度**。四个方向共用 §5.1 里的同一条机制（依据的获得成本从一次性翻译挪到边际推理），差别在**这条机制落在哪一层**——落在依据侧的（§5.2.1）、落在执行结构上的（§5.2.2）、落在举证交付物上的（§5.2.3），以及根本不落在 AI 上的（§5.2.4）。只写收益不写代价的方向，在评审时应被直接打回。

| 方向 | AI 改变了什么机制 | 这条机制落在哪一层 |
| --- | --- | --- |
| §5.2.1 LLM 增强决策 | 依据的获得成本从「一次性翻译」换成「每次决策重付一遍推理」 | **成本函数的位置**（一次性 → 边际） |
| §5.2.2 Agent 决策 | 执行从「单次调用」换成「多步状态循环」 | **执行结构**（错误沿调用链累积） |
| §5.2.3 可解释性与因果 | 合规压力的指向变了，**交付物没变** | **举证交付物**（逐条可还原，与模型无关） |
| §5.2.4 实时决策与决策可观测 | 与 AI 无因果关系 | **既有工程能力** |

读法建议：如果时间只够读一节，读 §5.2.1——它包含本主题今天最容易被算错的一笔账（把边际推理成本放到高频决策上）；§5.2.2 的护栏必须写在外部代码里，写在提示词里的护栏不算护栏；§5.2.3 的交付物（逐条可还原、可采信的解释）用不用模型都得做，但它恰好是 AI 方向能不能被信任的前提；§5.2.4 的两条收益都真实，但**没有一条来自模型**。

#### 5.2.1 LLM 增强决策：把依据的获得成本从「一次性翻译」挪到「边际推理」

- **旧做法与它的卡点**：决策依据大量存在于非结构化材料里——政策文本、合同条款、工单、对话记录。旧路只有两条：要么把它们**先翻译成可枚举条件**（规则或特征），要么放弃这部分依据。卡点在**成本结构**：翻译是一次性但按材料数量线性增长的人天投入，而材料一变，翻译成果就开始过期；本章 [§3.2.6](02-decision-intelligence-section-3-sec3.md) 把这层约束写成「先把它们翻译成规则的成本高于直接推理」。
- **AI 改变了什么机制**：**决策依据的获得成本从「一次性翻译」换成「每次决策重付一遍推理」**。这是本主题唯一一条真实的机制变化：它把成本从工程侧（写规则、做特征）挪到运行侧（按次调用），于是原来不划算的决策（依据难翻译、频次低）第一次变得划算，而原来很划算的决策（依据可枚举、频次高）反而变贵——**同一项技术对两类决策的方向是相反的**（本章 [§3.5](02-decision-intelligence-section-3-sec3.md) 的「盲目 LLM 决策」反模式说的就是只看前者、不看后者）。
- **由此得到的**：因为依据不必先被翻译，所以**「依据文本化、频率低、价值高」的那一类决策第一次可以被自动化到候选环节**——合同条款比对、政策适用性初判、复杂工单归类，这些过去卡在「规则追不上文本变化」的场景，现在可以先生成候选动作与理由，再由确定性代码裁决。这是本方向唯一真实的新增能力。

| 要做的判定 | 判定方法（不需要采购） |
| --- | --- |
| 该不该用 LLM | 决策依据能不能被人预先写成条件并逐条评审？能 → 用规则；不能 → 才轮到 LLM 出候选 |
| 该放在哪一侧 | 把在线调用按决策频率**分位**排序：**最高那一段（高频分位）贡献了多少推理账单**【经验：分几段、切在哪，按自家决策频率分布定，本节不设固定阈值】——占比高就说明该把 LLM 移到离线侧 |
| 单次成本怎么算 | 【推算】单次调用成本 ≈（输入 token 数 × 输入单价）+（输出 token 数 × 输出单价）；月度成本 ≈ 单次成本 × 月决策量 ×（1 + 重试与校验开销比例）。单价随模型与供应商变化，这一步必须用自己的账算 |
| 产出能不能用 | 抽 50 条生成结果人工核对，算两个比例：「直接可用」与「需要重写」。后者高说明省下的是打字时间 |

- **由此付出的**：**其一，成本从固定变成边际**，流量翻倍账单翻倍，而规则与模型的边际成本极低（本章 [§3.2.6](02-decision-intelligence-section-3-sec3.md) 把这一点写成失效点）；**其二，可复现性下降**——同一输入不保证同一输出，行为会随模型版本漂移，必须靠「提示词版本 + 模型版本 + 引用原文」一起留痕来补；**其三，多一层校验与兜底分支**，它不是加分项而是必需组件（输出过 schema 校验，不合法走保守动作）；**其四，解释的可信度需要额外工作**——LLM 写出的解释听起来通顺，但它可能引用了不存在的条款，而「通顺」会被误当成「正确」（本章 [§3.5](02-decision-intelligence-section-3-sec3.md) 的「LLM 幻觉决策」）。
- **证据与来源**：【公开】方法族有可核验出处：Chain-of-Thought（Wei et al., NeurIPS 2022）、Self-Consistency（Wang et al., ICLR 2023）、Tree-of-Thoughts（Yao et al., NeurIPS 2023）、ReAct（Yao et al., ICLR 2023）；本章 [§3.2.6](02-decision-intelligence-section-3-sec3.md) 已把这族用法分为「谁最终裁决」的四类。**判定方法**：要核某个平台是否真的支持某类用法，查它的官方文档里有没有对应条目与版本号，而不是看产品博客。【经验】产生「直接可用比例」这一口径的公开对照材料，本节给不出——这正是它停在 L2 的直接原因。
- **成熟度**：**L2**。判据：① 模型与框架有正式发布，但生成结果的验收标准无通行做法；② 只有厂商或方法方材料，无第三方机制级生产案例；③ 输出是自然语言，无稳定接口 → 做 PoC，不要作为核心依赖。
- **什么时候值得做**：依据文本化、决策频率低、单次错误可人工兜底、且你愿意为「生成 + 抽样复核」配人时。
- **什么时候不值得做**：决策频率高、依据本来就能写成条件、或者错误不可逆——此时 LLM 只应出现在离线一侧（生成规则草案、生成解释稿、离线审计），不进在线链路。
- **LLM-as-Decision-Auditor 为什么单独判 L3**：它面对的不是成本问题，是**问责闭环**问题——审计结论如果由与被审计者同类的模型给出，「谁为这个结论负责」答不出来（§5.1 表第 7 行）。要做的话，先由人把审计判据写成清单，再谈用谁执行。

#### 5.2.2 Agent 决策：把「单次调用」换成「多步状态循环」

- **旧做法与它的卡点**：一个决策要跨多个系统、多步执行（查库存 → 算运费 → 改订单 → 通知用户），旧路是**把流程写死**。卡点在**分支组合数**：每多一个可选系统、每多一个前置条件，流程的分支就乘一倍，而写死的流程只能覆盖被预想到的路径，剩下的靠人工补。本章 [§3.2.7](02-decision-intelligence-section-3-sec3.md) 把这条约束写成「单次调用或单条规则都无法覆盖」。
- **AI 改变了什么机制**：**执行从「单次调用」换成「多步状态循环」**——决策被表达成「状态 + 工具调用」的循环，于是它可以复用既有系统能力、在运行时选择路径。机制变化是真的，但**它置换的是可控性**：每一步的小偏差都会改变后续可选的状态与工具，而系统内没有全局约束能发现偏离。
- **由此得到的**：因为路径可以在运行时决定，所以**「跨多系统、分支不可穷举」的决策第一次不必先把流程穷举出来**——这正是它在客服工单、理赔初审、运维处置这类场景被尝试的原因。

```text
步数与端到端成功率：可靠性的代价随步数指数化
  设单步成功率 p、任务步数 n，且各步相互独立
  端到端成功率 ≈ p^n
  【推算】p = 0.99：
     n = 10 → 0.99^10 = 0.904
     n = 50 → 0.99^50 ≈ 0.605
  （0.99^50 由 50 × ln 0.99 = −0.5025 取指数得到，可自行复算）
  ────────────────────────────────────────────────
  读法：单步 99% 已经是很好的单步可靠性，
        但 50 步的任务约四成会在中途失败
  → 所以「限步数 + 中途截停 + 人工确认」不是保守，是必要条件
  → 步数分布的长尾，就是这个模式最直接的成本与风险指标
```

- **由此付出的**：**其一，失败模式是组合级的**，测试通过不代表路径穷尽，出事后难以逐步复盘（需全步留痕才可能复盘）；**其二，可靠性与成本随步数非线性增长**（上面的推算给出的是成功率一侧，成本一侧还要乘上每步的调用与工具开销）；**其三，护栏必须写在外部代码里**：工具白名单、步数上限、金额上限、不可逆动作前的人工确认点、紧急停止与回滚——本章 [§3.5](02-decision-intelligence-section-3-sec3.md) 明确指出「写在提示词里的护栏不算护栏」；**其四，预算单位从「每次调用」变成「每次任务」**，成本波动大。
- **证据与来源**：【公开】支撑这一模式的开源编排框架以 AutoGen、LangGraph、CrewAI、MetaGPT 为代表（四者均在 2023–2024 年间公开；发布年份、能力与许可以各项目官方仓库的当前记录为准，可按项目名检索核验）；本章 [§3.2.7](02-decision-intelligence-section-3-sec3.md) 已列出这一族的护栏清单与量化判据（步数分布、每步失败率、人工接管率、越界中止次数）。【经验】公开材料里**没有**给出「步数分布 + 每步失败率 + 人工接管率」这一组三件套的生产案例——这是它判 L3 的直接原因。
- **成熟度**：**L3**。判据：① 编排框架有正式发布，但「Agent 做决策」这一层没有独立 release note；② 只有厂商自有材料；③ 失败模式组合化，没有可复核的成功率口径 → 记录，不要在架构里预留假设。
- **判定方法**：让对方给出三个数——**平均步数与长尾步数、每步失败率、人工接管率**。三个数里缺任何一个，这个方案就还不能进入评审。
- **什么时候值得做**：流程分支确实不可穷举、且每个不可逆动作前都能插一个人工确认点时。
- **什么时候不值得做**：高频决策（每秒多次）——步数带来的成功率折损与成本波动在高频下不可接受。

#### 5.2.3 可解释性与因果：合规压力的指向变了，交付物没变

- **旧做法与它的卡点**：旧做法把「可解释」交付成**一张特征重要性图**（SHAP 值排序、注意力权重），把「有没有用」交付成**前后对比**（上线前后转化率变化）。两个卡点都在交付物本身：图说明的是模型的平均行为，回答不了「**这一次**为什么拒绝这个人」；前后对比无法排除同期其他变化，回答不了「**如果没做**会怎样」。本章 [§3.1](02-decision-intelligence-section-3-sec3.md) 约束表的第二条（可解释性与举证责任）与 [§3.2.4](02-decision-intelligence-section-3-sec3.md) 的因果约束，说的就是这两件事。
- **AI 改变了什么机制**：**没有改变交付物，改变的是压力与供给成本**。压力侧：自动化决策的可解释与公平要求是**法规**设定的事项，与用什么模型无关。供给侧：LLM 让「用自然语言写一段解释」的边际成本接近零。**这一条要老实说：LLM 解释是解释的供给方式变了，不是解释的可靠性变了**——生成一段通顺的理由，与这段理由能被逐条核验，是两件事。
- **由此得到的**：因为解释的供给成本下降，所以**「给每一次决策都配一段人能读懂的理由」第一次在成本上可行**（过去只有重要决策才人工写理由）；而因果估计回答的是另一个问题——**因为估的是干预分布下的差异而不是条件相关，所以「这个策略到底值不值」第一次可以被回答**（本章 [§3.2.4](02-decision-intelligence-section-3-sec3.md) 已给出 DAG 与估计量的写法）。

| 你要回答的问题 | 该用的交付物 | 不该用的替代品 |
| --- | --- | --- |
| 这一次为什么是这个结果 | 决策日志里的命中依据（规则 ID / 特征贡献 / 引用原文）+ 推理时刻快照 | 一张全局特征重要性图 |
| 这段解释能不能被采信 | 引用可定位到原文条款 + 输出过 schema 校验 | 通顺的自然语言（通顺不等于正确） |
| 这个策略值不值得继续 | 干预分布下的效应估计（实验或准实验） | 上线前后的指标对比 |
| 模型的判断有没有偏移 | 按群体分层的效果对照 + 漂移监控 | 整体均值 |

- **由此付出的**：**其一，LLM 解释引入一种新的失败形态**——解释听起来合理但与实际执行路径不符，读者会因为「说得通」而降低核查强度；**其二，因果估计依赖不可检验的假设**，「无未观测混杂」无法用数据检验，只能靠设计支持（本章 [§3.2.4](02-decision-intelligence-section-3-sec3.md) 的失效点）；**其三，没有可用干预来源时，因果方法会退化成用更复杂的方式估计同一个相关**；**其四，逐条解释是持续成本**，不是上线时的一次性投入——每一次规则或模型变更都要重走一遍验收。
- **证据与来源**：【公开】方法与法规两侧都可核验：SHAP（NeurIPS 2017）、LIME（KDD 2016）、反事实解释（Wachter et al., 2017）、倾向得分匹配（Rosenbaum & Rubin, 1983）、DML（Chernozhukov et al., 2018）、CausalForest（Wager & Athey, JASA 2018）；法规侧见 §5.4 的「官方文本」一栏（年份与条款适用时间以官方公报为准）。【经验】「LLM 写的解释被审计接受」这一情形，本节给不出可核验的机制级材料——它只是供给变便宜，不等于举证成立。
- **成熟度**：**方法与工具 L1（非 AI 能力）；把 LLM 解释当作举证材料 L2；KG 路径解释 L3**。判据：① 方法与法规有正式出处（法规的条款与适用时间以官方公报为准），LLM 解释只有产品文档条目，「图谱 → 路径 → 解释」这一层没有独立 release note；② 方法与法规有多方独立核验记录，LLM 解释与 KG 路径解释只有方法方材料；③ 方法接口稳定，LLM 输出与 KG 路径都没有稳定接口与验收口径 → 方法可进路线图，解释做 PoC，路径推理只观望（①③ 与 §5.1 表第 1、5、10 行逐条一致）。
- **判定方法**：抽 20 条线上决策，问三个问题——能不能还原出当时的输入快照与版本？解释里引用的条款能不能逐条点开？解释说的路径与日志里的实际路径一致吗？三问有一问答不上来，这份解释就还不能作为举证材料。
- **什么时候值得做**：有明确举证责任（受监管行业、大额不可逆决策）时；此时**先把决策日志与引用可定位做出来，再谈用谁写解释**。
- **什么时候不值得做**：把生成式解释当作解释质量的提升手段——它改变的是供给成本，不是正确率。

#### 5.2.4 与 AI 无因果关系的两条方向

这两条都被写进了「AI 时代的决策智能」，但机制与 AI 无关：

| 方向 | 旧做法与它的卡点 | AI 改变了什么机制 | 由此得到 | 由此付出 | 证据与来源 | 成熟度与判据 |
| --- | --- | --- | --- | --- | --- | --- |
| 实时决策 | 批量出清单，结果产出时场景已结束 | **没有改变机制**：改的是链路分段、超时与降级，是既有工程能力 | 决策能在用户还在等的窗口内返回，且每段有降级动作 | 常驻集群与在线存储的固定成本、不可重放的调试难度、影子链路与降级分支也要维护 | 判定入口：流处理与在线存储的发布页与官方文档条目（版本以发布页为准） | **L1（非 AI 能力）**（§5.1 表第 3 行）。判据：① 流处理与在线存储在各发布页有持续版本条目；② 多家彼此独立的组织有公开的流式生产材料（判定入口：引擎官方文档的采用者材料）；③ 窗口语义、超时与降级是既有工程约定 |
| 决策可观测与 ROI 量化 | 决策上线后说不清带来多少收益，回滚只能整体关掉 | **与 AI 无因果关系**，但被 AI 的一次性成本放大：边际成本越高，越需要按决策量算账 | 决策日志、延迟 / 转化 / 漂移监控、以及「决策成本 ÷ 决策收益」第一次成为必答项 | 监控与实验本身要养一套链路；ROI 的分母口径各家不同，跨团队不可比 | 判定入口：监控与实验类项目的发布页；血缘一侧的判定见本书《数据血缘与影响面》[§5.1](../../11-cross-cutting/05-lineage-and-impact/05-lineage-and-impact-section-5-ai.md) | **L1（指标与实验，§5.1 表第 4 行）/ L2（血缘与 ROI 口径，§5.1 表第 12 行）**。判据：指标与实验侧 ①②③ 齐（① 有版本化发布记录；② 多家彼此独立的组织分别部署；③ 指标口径未变）；血缘与 ROI 侧 ① 追溯机制有正式条目、② 无第三方机制级材料、③ ROI 的分母口径各家不同 → 指标与实验可排期，血缘与 ROI 先做 PoC |

**这两条的共同读法**：收益都真实存在，但**没有一条来自模型**——一条来自流处理与在线存储的工程能力，一条来自日志、监控与实验框架。把它们写成「AI 时代的决策智能演进」，会让真正要做的四件事（决策日志、延迟预算、逐条可还原、因果评估）一件都排不进排期。

再看一层：§5.2.3 与 §5.2.4 的收益**取决于你什么时候动手**（日志记不记、快照留不留、对照组设不设），而 §5.2.1 与 §5.2.2 的收益**取决于外部条件与护栏**（验收标准、成功率口径）。排期时应该优先做「取决于自己」的那些，把它们做成能力。

### 5.3 与本主题既有栈的接口在哪

决策智能与 AI 之间不是「结合」关系，而是**交接物**关系：谁把什么交给谁、失败时谁负责。这张表比「能不能用」更能决定它能不能落地。

| 结合点 | 接口形态 | 谁负责失败 | 现状 |
| --- | --- | --- | --- |
| 决策智能 ↔ 特征平台（[特征平台](../../02-data-science/01-feature-store/01-feature-store.md)） | 交接物 = **推理时刻的特征快照**（不是事后回查得到的当前值）；特征侧保证离线训练与在线推理同源，决策侧保证快照与决策一起留痕 | 特征侧：快照不可得时，任何解释与复盘都失去依据 | L1（快照与一致性机制）/ L2（跨团队的在线离线一致性口径） |
| 决策智能 ↔ 模型管理与 AI 计算平台（[AI 计算平台](../01-ai-compute/01-ai-compute.md)） | 交接物 = 模型版本 + 评测口径 + 上线条件（含延迟与可用性 SLA） | 平台侧：SLA 不写进上线条件时，取数与推理的抖动会直接打到决策 | L1（模型注册与评测机制）/ L2（决策侧验收标准） |
| 决策智能 ↔ 数据血缘与影响面（[数据血缘与影响面](../../11-cross-cutting/05-lineage-and-impact/05-lineage-and-impact.md)） | 交接物 = 「输入 → 决策 → 动作 → 结果」这条链上的边；**改口径前要能列出受影响的决策** | 血缘侧：边缺失时「这次口径变更影响了哪些决策」算不出来 | L1（采集机制）/ L2（决策链路的贯通率——机制可用、贯通率口径需自建；同类的口径判定见本书《数据血缘与影响面》[§5.1](../../11-cross-cutting/05-lineage-and-impact/05-lineage-and-impact-section-5-ai.md) 对「训练数据血缘追溯」的 L2） |
| 决策智能 ↔ 数据目录与指标平台（[数据目录](../../04-data-assetization/08-data-catalog/08-data-catalog.md)、[指标平台](../../04-data-assetization/10-metric-platform/10-metric-platform.md)） | 交接物 = 决策所依据字段的**机器可读口径**（含义、过滤条件、粒度、新鲜度） | 目录 / 指标侧：口径只对人可读时，LLM 与 Agent 拿到的是列名 | L1（口径定义）/ L2（决策所依据口径的机器可读化） |
| 决策智能 ↔ 审计与合规（[审计与合规](../../11-cross-cutting/07-audit-and-compliance/07-audit-and-compliance.md)） | 交接物 = 可逐条举证的决策记录（命中依据 + 输入快照 + 版本 + 引用） | 决策侧：举证材料不齐时，合规结论无法成立 | L1（日志机制）/ L2（逐条举证口径） |
| 决策智能 ↔ Agent 平台（[数据 Agent](../../05-agent-platform/01-data-agent/01-data-agent.md)） | 交接物 = 工具白名单、步数与金额上限、人工确认点、全步留痕 | 接入方：护栏写在提示词里时，越界调用在技术上仍可能发生 | L2 |
| 决策智能 ↔ 评估与实验（[模型评估](../../02-data-science/07-eval/07-eval.md)） | 交接物 = 对照组与判据；**没有对照组的变更视为未验证** | 评估侧：缺少实验框架时，任何决策变更都无法归因 | L1（实验机制）/ L2（不可实验场景的准实验设计） |
| 决策智能 ↔ 隐私计算（[隐私计算](../../11-cross-cutting/08-privacy-computing/08-privacy-computing.md)） | 交接物 = 参与方 / 协议 / 隐私参数 / 处理位置（跨域决策，见本章 [§3.2.8](02-decision-intelligence-section-3-sec3.md)） | 协作方共同：一方不遵守协议，全局保证不成立 | L1（原语）/ L2（跨域责任约定） |

一句话概括：**AI 没有给决策智能新增任何问责原语，只新增了一条获得依据的路径**。这张表里「现状」列的写法与前几节一致：**L1 指机制已稳、可以直接排期；L2 指机制可用但口径或责任还没统一**——决策场景下最常出问题的不是模型精度，而是「两边对同一个字段的理解不一样，谁也没错」。

由此得到三条约定。

**第一条约定：没有决策日志，就不叫「可解释的决策系统」。**日志里至少要能还原：推理时刻的特征快照、命中的依据、模型与提示词版本、最终动作。任何一项缺失，事后解释都只能靠推测。

**第二条约定：先把「生成」与「执行」分开，再谈用哪种模型。**只要有一个组件能直接改业务状态，就必须有独立于它的裁决与留痕（本章 [§3.4](02-decision-intelligence-section-3-sec3.md) 的组合模式 3 把这条写成职责边界）。

**第三条约定：不可逆的决策前必须留人或留确定性校验。**自动化率在可逆决策上是效率指标，在不可逆决策上是风险指标——这条与 AI 无关，但 AI 让「自动执行」变得更容易做到，所以更容易被忘记。

- **厂商决策平台**（Aera Technology、Diwo、Pecan AI，以及阿里云决策引擎 PAI-EAS、字节智能决策、蚂蚁决策大脑、平安智慧决策这几家国内平台的决策产品，以及通义决策助手 / 豆包决策助手 / Einstein GPT Decision 一类 LLM 决策助手）——本节**不转述其融资与客户数字**（这类数字无法被第三方按同一口径复核），只把它们当作检索入口。
- **实时决策与决策可观测工具**（流式规则侧 Flink CEP + Drools Fusion、在线学习侧 FTRL 与 Vowpal Wabbit、实时存储 Materialize / RisingWave / Pinot；可观测侧 Arize Phoenix / Langfuse / Helicone）——**判定入口，不是论据**：本节不断言任何一项的具体能力与版本，一律以各自官方文档与发布页为准。

**怎么用这份清单**：要核「能力存不存在」看官方文档与发布条目（最快）；要核「接口稳不稳」看规定的版本兼容说明（最稳）；要核「在我这里值不值得做」看 §5.2 每条给出的判定方法——**第三类问题没有任何公开材料能替你回答**。

**第三方生产案例**

- 说明：本节**未能给出**可核验的、含机制细节（决策量、误判率、人工接管率、单次成本）的第三方「决策智能 + AI」生产案例。本章 [§6](02-decision-intelligence-section-6-sec6.md) 的四个案例（蚂蚁决策大脑、阿里多任务多目标、字节长序列建模、某银行三态风控）出处标注为「机构名 + 年份区间」，划在自述一类——它们能支撑「规则分层 + 模型判别 + 策略映射」「多任务多目标」「长序列建模」「三态取舍」这一层的做法，**不能充当 AI 方向的第②条**。**这个空白本身是结论**：它正是本节把所有 AI 方向判在 L2 / L3 的直接原因。
- 要补第②类证据，最实际的办法是自己造：把决策量、误判率、人工接管率、长尾步数、单次推理成本留存成口径。这五组数在决策系统评审里的分量，超过任何厂商案例。
- 三类证据里**最容易造假的是「决策准确率提升」**：只报提升而不给评测集、口径与基线，无法复核。**判定方法：只接受同时给出「评测集来源 / 口径定义 / 基线（人工或旧方案）」三样的数字。**

**核验 §5.1 表里各条宣称的最小动作**（都不需要采购）：
1. **决策可还原**：随机抽 10 条线上决策，看能不能拉到当时的特征快照与版本号。
2. **生成可用性**：抽 50 条 LLM 生成结果，数「直接可用」与「需要重写」两条。
3. **成本账**：把在线调用按决策频率**分位**排序，算最高那一段（高频分位）贡献了多少推理账单。
4. **失败模式**：问 Agent 方案的平均步数与长尾步数、每步失败率、人工接管率。
5. **解释可采信**：抽 20 条解释，逐条点开它引用的原文。
6. **结论可归因**：问「最近一次决策变更的对照组是什么」。

### 5.5 被过度宣传的部分

**「LLM 让决策智能从规则 + 模型进化到规则 + 模型 + LLM」**——实际是：**换掉了依据的获得方式，没有换掉裁决结构**。本章 [§3.4](02-decision-intelligence-section-3-sec3.md) 的组合模式 3 把边界写成「LLM 只读不写、Agent 只执行不裁决、人只在不可逆节点介入」，映射前后这条边界都成立。**为什么会这样**：决策系统的可信性来自「谁裁决、怎么举证」，而这两件事由问责结构决定，不由生成能力决定。**它什么时候才会成真**：LLM 的输出被纳入与规则、模型同等的验收与留痕体系——即逐条可还原、引用可定位、版本可回滚时。**判定方法**：问「上一季度有多少条决策的解释被审计采信」，答不上来就说明它只是换了个理由生成器。

**「决策可解释性成为合规刚需，所以接一个 XAI 工具就够了」**——实际是：**合规要求的交付物是「这一次为什么」，不是「模型平均在看什么」**。SHAP 图回答的是后者（本章 [§3.1](02-decision-intelligence-section-3-sec3.md) 的约束表把「有 SHAP 就算可解释」列为最容易被推翻的直觉）。**为什么会这样**：把「方法存在」当成了「举证成立」，忽略了举证要有主体、有时点、有可定位的依据。**它什么时候才会成真**：解释与决策日志绑定成一条不可分割的记录——每条解释都能回到当次的输入快照与命中的具体依据。**判定方法**：抽一条真实决策，看能不能只凭这条记录回答「为什么」；不能，就说明解释还停在平均层面。

**「Agent 让决策从单点智能走向协同智能，全自动化」**——实际是：**多步执行把失败概率按步数指数化**（见 §5.2.2 的推算），而「全自动」这个目标与「不可逆动作前留人」这条约定直接冲突。**为什么会这样**：把「能跨系统把流程走完」当成了「能承担决策后果」，两者是不同的问题。**它什么时候才会成真**：公开材料开始给出**步数分布 + 每步失败率 + 人工接管率**这一组三件套，且长尾步数被压到可解释的范围内。**判定方法**：让对方把上一周的任务按步数画一张分布图——画不出来，说明这个模式还没有被度量过。

这三条的共性：**它们都把「某个环节变得更容易」当成了「整套机制已经成立」**——生成更容易、解释更容易、执行更容易。而本主题的判据始终只有一条：**你能不能指出这条宣称改变了问责结构里的哪一项，并且证明它真的变了。** 三项都没动的，就是成本函数或接口的改良。

### 5.6 未来 3–5 年：可证伪的预测

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| LLM 在决策链路里会先稳定在**离线一侧**（生成规则草案、生成解释、离线审计），而不是在线决策路径 | 公开架构材料里 LLM 出现在离线或异步侧；推理账单与在线决策量解耦 | 出现高频决策（每秒千次以上）由 LLM 主裁决的公开生产案例，并披露单次成本与 P99 延迟 |
| 「可解释」的交付物会从特征重要性图收敛到**逐条可还原的决策记录**（命中依据 + 输入快照 + 版本） | 监管或审计口径、以及模型管理产品的正式条目里出现「单次决策可还原」的字段要求 | 公开材料仍把全局特征重要性图当作合规举证的全部，且能通过审计 |
| Agent 决策会停在**低频 + 高价值 + 不可逆动作前有人**的场景，不会成为高频决策的默认形态 | 公开生产材料给出步数分布与人工接管率两个数，且长尾被压缩 | 出现高频决策由多步 Agent 执行、并披露端到端成功率与单次成本的生产案例 |
| 因果推断会以**评估与决策依据**两种身份留在生产里，而不会成为在线决策链路的组成部分 | 因果估计出现在实验平台与评估侧的正式条目里，而不是在线服务的延迟预算里 | 出现把因果效应估计放进在线决策路径、并给出 P99 延迟与调用频率的公开方案 |

写这四条时的共同约定：**信号必须是外部可观察的**（正式功能条目、发布说明、带口径的公开案例），而不是「我觉得会」。**被检验得最快的是第一条**——下一批公开架构材料里 LLM 挂在哪一侧，一两年内就能看到；**最慢的是第三条**——它是一种否定式预测，需要有人长期公开步数与接管率。

### 5.7 给架构师的行动建议

| 你的处境 | 现在就该做 | 一年内观察 | 明确不要做 |
| --- | --- | --- | --- |
| 有人提出「决策链路接入大模型」 | 先把决策按频率与依据形态分成两列，标出哪些依据能预先写成条件 | 观察在线推理账单与决策量是否解耦 | 不要在依据本来可枚举的高频决策上用 LLM 裁决 |
| 还没有决策日志 | 先建日志：输入快照 + 命中依据 + 模型 / 提示词版本 + 最终动作 | 观察能否用日志还原任意一条历史决策 | 不要先买解释工具——没有日志，解释无处附着 |
| 监管或审计要求解释 | 先把「逐条可还原」做成能力，再用 LLM 写解释稿 | 观察解释的引用能否逐条点开 | 不要把生成式解释当作解释质量的提升手段 |
| 想上 Agent 自动化跨系统流程 | 先给护栏：工具白名单、步数上限、金额上限、人工确认点、全步留痕 | 观察步数分布与人工接管率 | 不要把护栏写在提示词里——那不叫护栏 |
| 想用 LLM 审计决策 | 先把审计判据由人写成清单 | 观察生成式审计结论能否被复核 | 不要让同类模型互相审计并当作结论 |
| 要做策略效果评估 | 先建对照组或准实验设计 | 观察不可实验场景的替代设计是否成立 | 不要用上线前后的对比替代对照 |
| 业务要求「效果立刻可见」 | 先写清决策 ROI 的分子与分母口径 | 观察 ROI 是否可跨团队比较 | 不要在口径未定义时公布 ROI 数字 |
| 跨机构要联合决策 | 先做隐私求交与特征对齐（原语层，见《隐私计算》[§5](../../11-cross-cutting/08-privacy-computing/08-privacy-computing-section-5-ai.md)） | 观察参与方与协议是否稳定 | 不要先交换原始数据再「脱敏比对」 |
| 预算有限，只能做一件事 | 做**决策日志 + 输入快照**（它同时喂饱解释、审计、实验与因果评估） | 观察它是否被下游一个个接起来 | 不要把预算先花在接一个决策 Agent 上 |
| 要给管理层一份判断 | 写成三行：决策量 / 人工接管率 / 单次决策成本 | 观察这三行能否被第三方按口径复核 | 不要用「我们上了决策智能平台」代替数字 |

「明确不要做」这一列的共同逻辑：**这些动作的代价是确定的**（改链路、动权限、引入新的边际成本），**而收益依赖一个尚未成立的假设**（模型理解语义 / 生成即正确 / 多步执行仍可控）。等 §5.6 的信号出现再投入，损失的只是时间。

### 5.8 小结

> 本节小结：本主题下 AI 真正改变的**唯一那条机制**是**决策依据的获得成本从一次性翻译挪到边际推理**——于是「依据文本化、频率低、价值高」的决策第一次能被自动化到候选环节，也第一次需要按决策量算账。它**没有**改变的是本章 [§3.1](02-decision-intelligence-section-3-sec3.md) 的问责结构：**谁裁决、怎么举证、不可逆动作前有没有人，三条一条都没动**；也没有改变决策链路的成本曲线（实时链路的延迟由最慢的依赖决定，在线学习的上限由反馈速度决定）。
> 
> 判断本主题下任何新提法的快捷方式：**它改变的是「依据从哪里来」，还是「谁最终裁决」？** 前者立刻改变可用性与账单（本节判 L2 的那几条），后者才叫架构变化（到目前为止没有发生）。第二条同样快的判断：**这件事能不能在没有任何 AI 的前提下先做完**——能做完的（决策日志、逐条可还原、对照组、因果评估），今天就该排进路线图。
> 
> 如果只能带走一句话：**先把「这一次为什么」变成可还原的记录，再谈用哪种模型来生成理由**；顺序反过来，就是给一个没有留痕的系统配了一位很会讲话的解说员。
> 
> 💡 **思考锚点**：就按本节「只能做一件事」那一条动手：随机挑上周的一条决策，看你能不能凭日志还原出输入快照、命中依据、模型 / 提示词版本、最终动作这四项？缺哪一项，就会让你算不出这条链路的边际推理账单——你的缺口落在哪一项上？
>
