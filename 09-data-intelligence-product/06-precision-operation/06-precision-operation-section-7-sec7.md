## 7. 与其他方法对比

### 7.1 先立判据：为什么打分表会误导

给"自建运营系统 / 买营销云 / 用 CDP + 自研触达 / 用实验平台 + 自建编排 / 只做批量群发 / 用增长团队的外部工具"打分是常见做法，但它有三个结构性问题：

① **同一列在不同处境下方向相反**——"渠道覆盖广"对做**通知类**触达的团队是必需（账单、到期提醒要到达），对做**营销类**触达的团队是**风险**（渠道越多，退订遗漏点越多、频控越难统一）。
② **打分表隐含"这些选项互斥"**，而真实做法是组合（**标签平台 + 自建频控与归因 + 营销云发通道**是常见组合）。
③ **最关键的判据不是可打分的维度，而是门槛**——**"能不能算增量"**与**"频控能不能按用户统一裁决"**这两条是门槛：不满足就直接出局。**一个渠道覆盖极全、发送能力极强的营销云，如果频控按活动算、且不产出对照组标识，会在活动数增长时把你推向系统性过度触达。**

**本节采用的 6 条判据**：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| **能算增量** | 它能不能产出对照组标识，并支持同口径同窗口比较？ | **这是门槛不是权重**——不能算增量 → 效果不可测 → 预算无法分配 |
| **频控按用户** | 上限是按用户还是按活动？ | 按活动 → 总量随活动数线性上升（**而单活动视角看不见**） |
| **退订强一致** | 退订与同意状态是否集中管理、触达前强一致校验？ | 否 → 误发（**合规代价与延迟代价不对称**） |
| **成本可分解** | 触达成本能不能按渠道与激励分开核算？ | 不能 → "划算"可能只是"大部分量走了便宜渠道" |
| **污染可控** | 支不支持实验分层（同层互斥、跨层正交）？ | 不支持 → 跨活动干扰 → **有效活动被判无效（假阴性）** |
| **运维承接** | 谁看护长期 holdout、谁有权限暂停活动？ | 本主题的成本是人力为主，**没有护栏值守的体系会稳定滑向过度触达** |

**这 6 条里，前两条是门槛（不满足直接出局），后四条是权重的输入。**

### 7.2 候选方案全景

| 候选 | 定位 | 核心机制（一句话） | 典型使用者 | 主要代价 |
| --- | --- | --- | --- | --- |
| **只做批量群发** | 最简 | 规则拉名单 → 全量触达 | 通知类触达为主的业务 | **测不出效果**（只能算工作量） |
| **CDP + 自研触达** | 折中 | CDP 管人群，触达与实验自建 | 已有 CDP、要自主可控的团队 | CDP 通常不解决频控与增量口径 |
| **营销云（全流程）** | 最快见效 | 人群 + 编排 + 通道 + 报表一体交付 | 要快上线、活动规模中等的团队 | **频控常按活动算**；对照组标识未必产出 |
| **实验平台 + 自建编排** | 测量优先 | 实验平台管分流与显著性，编排自建 | 对效果口径要求高的团队 | 两块要自己集成（分流贯穿到触达与归因） |
| **全自研** | 控制力最强 | 分流 + 频控 + 编排 + 归因全自建 | 运营是核心竞争力、或规模极大 | 短期投入最大；**护栏值守是常备人力** |
| **增长团队外部工具** | 外部智囊 | 用咨询 / 代运营的方法与工具 | 缺经验、要快速搭体系 | **口径与数据留在外部**，长期不可控 |

**这六个候选其实分三族**：

- **测量族**（实验平台、CDP 的自带分析、营销云的报表）——**解决"效果能不能算"**，差别在**对照组标识的归属**。
- **执行族**（营销云、自研编排、CDP 的触达模块）——**解决"怎么发"**，差别在**频控口径与退订一致性**。
- **治理族**（自建频控 + 长期 holdout + 护栏）——**解决"发多少、什么时候必须停"**。

**族内可替换，跨族不可换**：执行族内部换（营销云 ↔ 自研）代价可控（**前提是对照组标识能带走**）；测量族之间换代价大（**历史实验数据往往不可迁移**）；而**治理族不能被前两族替代**——**没有任何产品会替你决定"你的用户一天最多收几条"。**

### 7.3 机制差异：为什么它们表现不同（核心节）

#### 7.3.1 对照组的归属：你的分流、产品的分流，还是没有分流

**机制是什么**：对照组标识只有三个位置——**你的分流系统产出的标识**（贯穿到曝光与归因）、**产品的分流被迫使用它的口径**、**不存在**（批量群发与只看转化率的形态）。

**它在各候选中的实现差异**：实验平台族的分流标识是**你的资产**（可导出、可贯穿）；营销云的分流**在产品内部**，能不能贯穿到归因取决于它是否暴露未触达组的行为数据；而批量群发**没有这个概念**。

**由此必然导出的性质**：因为**增量 = 处理组 − 对照组**，所以**没有对照组标识就没有增量**——这条不是"做得不够好"，而是**在缺这个字段时不可定义**。**这条性质解释了为什么"上了营销云却仍然算不出增量"**：产品能发、能统计触达后的转化，但**它不产出"谁没被触达"这个可比队列**。

**失效条件**：当业务问"这次活动值不值"而只能给出转化率时，说明对照组不在你手里——**此时要补的是分流标识的贯穿，而不是换一个更强的发送工具。**

#### 7.3.2 频控的口径：按用户，还是按活动

**机制是什么**：上限的作用对象是**用户**（跨活动）还是**活动**（各自）。

**它在各候选中的实现差异**：营销云的频控**通常配在活动或旅程上**（因为它的模型是"一个活动一次旅程"）；跨活动上限需要**打破产品的活动边界**，因此往往得自建或在产品外挂一层裁决。

**由此必然导出的性质**：因为**用户感受到的是总量的和**，所以**按活动限频在原理上管理不了用户感受**——活动数翻倍时，每条都"合规"而总量翻倍。**这条性质给出一个明确的归属判断**：**频控必须落在能看到全部活动的那一层**，而那一层通常不在营销云里。

**失效条件**：当出现"用户投诉收到太多"而**每个活动的复盘都显示"只发了 1 条"**时，说明频控口径错了。

#### 7.3.3 退订的一致性：集中校验，还是各渠道各一份

**机制是什么**：同意与退订状态是**一份权威名单**，还是**每个渠道各维护一份**。

**它在各候选中的实现差异**：自建族可以在**触达出口**做统一强一致校验；营销云**内部一致**（它管所有渠道时），但**一旦你还有自建的触达通道（App 推送、站内信），跨系统的退订就断了**；而多渠道各自接入第三方 SDK 时，**退订往往是各渠道各一份**。

**由此必然导出的性质**：因为**退订是用户的明确意愿**，所以**违反一次的代价（投诉）远高于延迟一次的代价**——**这个不对称决定了它必须是强一致，而不是最终一致**（§6.4）。**另一条性质**：**校验必须落在"全部触达的必经之处"**，否则新增一个渠道就多一个遗漏点。

**失效条件**：当出现"我在短信里退了，还在收推送"的投诉时，说明退订没有集中——**此时要补的是出口校验，而不是在每个渠道里再实现一遍。**

#### 7.3.4 成本的可分解性：按渠道与激励分开，还是混算

**机制是什么**：触达成本能否**按渠道与激励分开**核算。

**它在各候选中的实现差异**：营销云的报表通常**按渠道给出消耗**（它替你付了渠道费，因此知道单价）；**自建族要自己维护单价表**；而**激励成本（券、补贴）常常不在任何触达工具的账里**——它在交易系统里。

**由此必然导出的性质**：因为**激励成本常常是触达成本的数量级之上**（一条短信几分钱，一张券几元到几十元），所以**只算触达成本会严重低估活动的真实代价**。**这条性质决定了"ROI"这个数必须由能把两边合起来的人算**——通常不是触达工具，也不是交易系统，而是**指标平台**（[Ch4 §10](../../04-data-assetization/10-metric-platform/10-metric-platform.md)）。

**失效条件**：当"这个活动很划算"的结论只基于触达费用时，说明激励没被计入——**此时的 ROI 是半个 ROI。**

### 7.4 成本结构对比（不是价格表，是成本函数）

| 方案家族 | 主导项 | 隐性成本（上线时不计入、第二年计入） | 成本随什么增长 |
| --- | --- | --- | --- |
| **测量族** | 平台许可 + 实验设计人力 | 实验数据不可迁移；分流标识贯穿到归因的集成成本 | 随**活动数**增长 |
| **执行族** | 渠道费 + 编排维护 | 频控口径错的代价（用户疲劳）；退订遗漏的合规代价 | 随**触达量**增长（激励另计） |
| **治理族** | 人力（护栏值守 + holdout 观察） | 内部博弈的协调成本；暂停决策的组织成本 | 随**活动数与渠道数**增长 |

**成本函数的三条判据**：

① **测量族的曲线是"台阶 + 低斜率"**——平台许可是台阶，之后每次实验的边际成本很小；**它的规模化压力来自集成的复杂度**（分流标识要贯穿到曝光、归因、报表）。
② **执行族的曲线随触达量线性**，但**激励成本可能是数量级更大的那一项**——**因此"控制成本"的杠杆常常在激励设计，不在渠道选择**。
③ **治理族的曲线随"活动数 × 渠道数"增长**，且**它是最容易被砍的一族**——**因为它没有直接的营收关联**。

**把三条曲线写成式子（读者可代入自己的数）**：

```text
设：N = 活动数   V = 月触达量（万条）   c_ch = 渠道单价（元/条）
    i = 单次触达的期望激励成本（元）   H_gov = 治理族常备人力（人年）
    P = 平台许可（万元）

测量族：  Cost_meas(N) = P + N × 实验设计人力               ← 台阶 + 低斜率
执行族：  Cost_exec(N,V,i) = V × c_ch + V × 命中率 × i       ← 随 V 线性；i 常是数量级更大的一项
治理族：  Cost_gov(N)    = H_gov × 人均年成本                ← 与营收无直接关联，最易被砍

反直觉的一条【推算】：当 i / c_ch 的比值大于一到两个数量级时【经验】，
          控制成本的杠杆在激励设计（谁该拿券），不在渠道选择（走短信还是推送）；
          而"谁该拿券"正是 §2.2 的 τ > c/v 判据 —— 它要求先有对照组。
```

**这个式子的用法**：**先量 `i / c_ch` 这个比值**。它很大时（多数带券活动都是），**你的成本问题在"给谁券"，而给出这个答案的前提是增量口径**——**这解释了为什么"先做对照组"不是学术洁癖，而是成本优化的前置条件。**

### 7.5 决策树（每个分支都要有阈值依据）

1. **你的触达是"告知"还是"说服"？**
   - **告知**（账单 / 到期 / 物流）→ **批量群发够用**，只需做到达率与退订一致；**不需要分流**。
   - 说服（促销 / 激活 / 挽回）→ 进入第 2 问。
2. **业务能不能接受"有一部分人作为对照不发"？（这是社会成本，不是技术问题）**
   - 能 → 进入第 3 问。
   - 不能 → **先把这件事谈成**：没有对照组，**"这次值不值"永远答不出**；可以先用很小的比例（几 %，对大活动几乎无感）。
3. **是否已有实验平台或分流能力？**
   - 有 → 用它产出分流标识，并**贯穿到曝光与归因**（这一步常被漏）；进入第 4 问。
   - 没有 → 先自建稳定分流（一行哈希），**再谈工具选型**——因为**分流标识是你唯一不可替代的资产**。
4. **团队能不能长期维护频控与护栏（按 0.3–0.8 人年的常备投入量级估算【经验】）？**
   - 能 → **自建治理族**（频控按用户 + 长期 holdout + 护栏），执行族可买产品。
   - 不能 → 买营销云，但必须**先压测两条门槛**：频控能不能按用户、对照组标识能不能导出。

**阈值的诚实说明**：上表的"0.3–0.8 人年"与"几 %"都是【经验】档——它们用来区分"这一档"与"那一档"，请用你自己的排期与活动规模校准，**不要当门槛用**。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因 |
| --- | --- | --- | --- |
| 只有通知类触达 | 批量群发 | CDP + 自研 | 给通知类做分流是浪费（目标是告知） |
| 有说服类触达、要自主可控 | 自建分流 + 自建编排 | 实验平台 + 自研编排 | 全买产品则分流标识可能拿不到 |
| 活动规模中等、要快上线 | 实验平台 + 营销云（**核频控口径**） | 全自研 | 营销云的频控常按活动算 |
| 多渠道多活动并行 | 自建治理族（按用户频控） | 营销云（须验跨活动上限） | 按活动限频会让总量随活动数上升 |
| 带券 / 带补贴活动为主 | 指标平台算 ROI（**含激励**） | 营销云报表 | 只算触达费会严重低估成本 |
| 受监管行业 | 自建（**退订集中 + 强一致**） | 营销云（须验跨系统一致性） | 各渠道各一份退订名单必出投诉 |
| 团队只有 1–2 人 | 营销云 + 最小分流 | 批量群发 | 自建治理族的人力不会因为团队小就消失 |
| 已有 CDP | CDP + 自建频控与归因 | 全自研 | CDP 通常不解决增量口径与跨活动频控 |

**组合的两条次序原则**：① **先把分流标识与归因口径固定，再谈工具选型**——它是唯一不可替代的资产，且换工具时它最容易丢；② **先把频控与退订一致性做上，再扩大渠道**——渠道越多，遗漏点越多，而**投诉不会等你补齐渠道**。

**第三条原则（方向相反但同样重要）**：③ **先把"用户一天收到多少条"变成可查的数，再谈优化**——它是一行 SQL 的事，而它一旦可查，**很多后续决策会自动变得没有争议**。

### 7.7 选错的代价与迁移成本

| 选错的方向 | 症状 | 迁移动作 | 工作量量级 |
| --- | --- | --- | --- |
| 无对照 → 有对照 | "这次值不值"答不出 | 补稳定分流 + 口径卡 + 历史结论标注"未测" | 以周计（**代码量小，社会沟通是主要成本**） |
| 频控按活动 → 按用户 | 用户接收量随活动数上升 | 建跨活动裁决层 + 优先级表 + 被挡留痕 | **以月计**，且**需要有人获得"否决活动"的授权** |
| 退订各渠道 → 集中 | 退了还收、有投诉 | 合并名单 + 出口强一致校验 + 跨渠道演练 | 以月计（**往往是合规驱动的紧急改造**） |
| 营销云锁定 → 自建 | 换工具要重写全部活动与报表 | 逐活动迁移 + 重建分流标识与归因 | **以季度计**，且**历史实验数据不可迁移** |
| 只看触达成本 → 含激励 | ROI 是半个 ROI | 把激励成本并入指标平台口径 | 以周计（**数据在交易系统，接入是主要工作**） |
| 无长期 holdout → 有 | 不知道整体是否过量 | 划出几个百分点 + 按季度观察 | **以季度计**（观察期无法压缩） |
| 无护栏 → 有 | 触达量缓慢过度 | 负向指标硬阈值 + 指定暂停执行人 | 以周计建，**难在组织上敢于暂停** |
| 污染不检测 → 有 | 有效活动被判无效 | 建实验分层 + 污染检测进报告 | 以月计，**分层设计有复杂度** |

**一条硬结论**：八条里最贵的是**"营销云锁定之后的收回"**——不只是活动重写，而是**历史实验数据不可迁移**（对照组标识、曝光日志、归因结果都在产品里），因此**你会失去"过去一年的增量基线"**。**所以第 1 条门槛（能不能算增量、标识能不能导出）必须在第一版就判对。**

**第二条硬结论**：上表里有一项的代价**部分不可逆**——"无对照 → 有对照"里的历史部分：**没有对照组的历史活动，其增量永远不可补算**。**其余七项都是"要花时间"，这一项是"花时间也拿不回来"**；这决定优先级：**如果只能做一件事，先把分流标识加上**（成本极低），而不是先优化发送能力。

### 7.8 小结

> 本节小结：六个候选之间的差异，最终都能归到四问——**对照组归谁且能不能导出**、**频控按用户还是按活动**、**退订是集中强一致还是各渠道各一份**、**成本能不能按渠道与激励分开**。四问决定了它们的分族（测量族 / 执行族 / 治理族）与成本曲线（测量族台阶 + 低斜率、执行族随触达量线性**且激励常是数量级更大的一项**、**治理族随活动数与渠道数增长且最容易被砍**）。**选型顺序不可颠倒**：先用"触达是告知还是说服"筛掉不必要的复杂度，再用"能不能算增量"决定要不要分流，最后才用团队承接能力在剩下的里选——**把最后一问当权重而不是门槛，是第二年最常见的失效原因**。**本主题有一条与其它主题不同的推论**：**"先做对照组"不是学术洁癖，而是成本优化的前置条件**——因为成本杠杆在"给谁券"（`τ > c/v`），而给出这个答案的前提是先有对照组（§7.4）。

> 💡 **思考锚点**：拿 §7.1 的六条判据给你现在的方案做一次**门槛检查**（不是打分）：能算增量、频控按用户、退订强一致、成本可分解、污染可控、运维承接——**哪一条是"不满足"而不是"分数低"**？那一条就是你最可能被迫迁移的方向（§7.7）；而你今天的补救成本，是否还落在"以周计 / 以月计"的那几格里？**另一问更具体**：如果明天换掉现在的运营工具，**你的分流标识与历史实验数据能不能带走**？答不出，说明你的效果口径还没有真正掌握在自己手里。
