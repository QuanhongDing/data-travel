#### §8.1 你们的运营活动效果怎么算？为什么"转化率"不能说明活动有效？

**1. 考察点**
- 是否知道**增量（uplift）与转化率是两个不同的量**；
- 是否理解"本来就会转化的人"占多数时，转化率会系统性高估效果；
- 有没有可执行的验证动作（补对照组）。

**2. 参考答案框架**

**第一层：给出两个量的定义与差别。**

```
观测转化率  P(Y=1 | T=1)                     —— 只看收到触达的人里有多少转化
本次的增量  P(Y=1 | T=1) − P(Y=1 | T=0)     —— 因为触达而多转化了多少
```

**第二层：说明为什么转化率不能说明有效。** 当 `P(Y=1|T=0)` 很高时（成熟业务里大部分转化是自然发生的），观测转化率可以很高而**增量接近 0**——**"效果很好"与"没有效果"在只看转化率时无法区分**。而更隐蔽的是：**优化目标若定成"转化率高的人"，会把预算持续投给本来就会转化的人**，且**不可自查**。

**第三层：给出验证动作。** **补对照组**（哪怕几 %）：稳定分流（只依赖 `user_id` 与 `campaign_id` 的哈希）→ 同口径同窗口比较 → 得到增量。**判据**：效果报告里必须有"对照组"这一列。

**第四层：说出代价与边界。** ① **社会成本**（"为什么不发给他"）；② **小样本测不出小增量**（要检出 0.5 个百分点可能需要几十万每组），**此时正确结论是"未测出"而不是"无效"**；③ **污染**（对照组被其他活动触达 → 增量被稀释 → 有效活动被判无效）。

**3. 常见陷阱**
- 只谈转化率与 GMV，不提增量；
- 认为"转化率高就是活动好"；
- 说"我们有对照组"但拿不出稳定分流的实现；
- 把"未测出"记成"无效"（会系统性淘汰小活动）。

**4. 追问预测**
- "对照组留多少合适？"
- "怎么判断对照组被污染了？"
- "归因窗口定多长？定短了会怎样？"
- "如果业务不接受有人收不到，你怎么处理？"

**5. 参考资料**
- 本主题 §2.2（增量与样本量算式）、§3.2.1–§3.2.2、§4.2（1）（稳定分流实现）、§6.2（精准反而让效果报告失真）。

#### §8.2 一个人一天最多该收到多少条触达？这个数由谁定、写在哪？

**1. 考察点**
- 是否知道**注意力的稀缺性按用户计，不按活动计**；
- 是否理解"按活动限频"在原理上管理不了用户感受；
- 有没有意识到这需要**有人对总量负责**。

**2. 参考答案框架**

**第一层：直接给出上限口径。** 上限必须是 **`用户 × 时间窗`**（渠道可作为子维度，但不能替代用户维度）。**按活动限频**时，用户接收量与活动数近似成正比；**按用户限频**时总量恒定，**新增活动只能抢存量名额**。

**第二层：给出裁决逻辑。** 全部活动在**触达前**经过同一处裁决：按优先级排序 → 保留下限内的 → 其余按处置（丢弃 / 顺延 / **合并成汇总**）。**判据**：新增一个活动后，用户接收量分布不应右移。

**第三层：给出为什么它难做（组织而非技术）。** 它要求**某个团队获得"否决别人活动"的权力**——这是打破产品边界的改动。因此**优先级必须可解释**（按什么排序），否则会退化成"谁嗓门大谁优先"。

**第四层：给出两个配套。**
- **被挡条数上看板**，且**定义为正面指标**（系统在克制）——否则业务会把它当故障，持续要求放宽；
- **上限必须有 Owner**，否则临时提额变成常态。

**3. 常见陷阱**
- 只谈"我们有频控"，说不出**按什么维度**；
- 用渠道上限替代用户上限（多通道叠加会绕过）；
- 被挡条数不留痕（业务误以为漏发）；
- 没有 Owner（上限形同虚设）。

**4. 追问预测**
- "优先级怎么定才不会被质疑？"
- "被挡下的触达是丢弃还是顺延？"
- "大促期间上限要不要放宽？放宽的判据是什么？"
- "怎么证明频控真的在起作用？"

**5. 参考资料**
- 本主题 §2.2（统一频控的形式化）、§3.2.4、§4.2（5）（裁决逻辑）、§6.1（按活动限频的失败）。

#### §8.3 用户投诉"我在短信里退了订，怎么还在收推送"——你会怎么改？

**1. 考察点**
- 是否知道**退订是强一致要求**（代价不对称）；
- 是否理解校验要落在**全部触达的必经之处**；
- 有没有演练意识（合规审查会问）。

**2. 参考答案框架**

**第一层：先定性——这是强一致问题，不是最终一致问题。** 代价不对称：**退订后误发一次 = 一次投诉**；**延迟发几分钟 = 这条触达晚了几分钟**。因此选择"宁可延迟发，不可误发"。

**第二层：给出改造方向。**
- **退订与同意状态集中管理**（一份权威名单）；
- **触达前强一致校验**，校验失败即不发；
- **校验放在统一出口**（而不是各渠道 SDK 里各做一遍）——**各渠道各做一遍 = 新增一个渠道就多一个遗漏点**。

**第三层：给出证明动作。** **跨渠道演练**：在任一渠道退订 → 验证**其他所有渠道**在下一个触达周期内都停止——并**留演练记录**（合规审查必问）。

**第四层：给出规模感。** 退订同步若延迟到小时级，**一次批量触达就是数十万条误发**【推算：误发条数 ≈ 触达速率 × 同步延迟】；而集中校验的延迟通常在毫秒级——**两者代价相差几个数量级。**

**3. 常见陷阱**
- 答"我们在每个渠道都实现了退订"（那正是问题）；
- 用最终一致（"最多延迟一小时"）；
- 不演练（无法证明）；
- 把退订当成渠道功能，而不是用户与品牌之间的约定。

**4. 追问预测**
- "退订状态存在哪里？各渠道怎么读？"
- "如果校验服务挂了，是发还是不发？"
- "退订与'降低频次'要不要分开设计？"
- "用户退订后多久可以再触达（如果有冷却期的话）？"

**5. 参考资料**
- 本主题 §4.7（退订强一致）、§3.2.5（退订跨渠道）、§6.4（一次合规投诉带来的改造）、[Ch8 §02 §4.7](../../08-ai-governance/02-data-security-and-compliance/02-data-security-and-compliance-section-4-sec4.md)（判定类机制的失败关闭）。

#### §8.4 "每个活动的 A/B 都显示正增量，所以我们继续加密触达"——这句话哪里不对？

**1. 考察点**
- 是否理解**单活动实验把"反感与疲劳"外部化了**；
- 是否知道**长期 holdout** 是唯一能回答"整体是否过量"的形态；
- 有没有意识到"每个都有效"与"整体过量"可以同时成立。

**2. 参考答案框架**

**第一层：指出机制。** **单活动的增量是在"其他活动照常"的前提下测的**——它测的是"多加这一条"的边际效果；而**整体触达量是所有这些"多加一条"的累积**。**反感与疲劳是跨活动累积的，单活动实验把它外部化了**——因此"每个都有效"推不出"整体不过量"。

**第二层：给出正确的测量形态——长期 holdout。** 固定一小部分用户（几个百分点）**长期不接收某类触达**，比较**长期指标**（留存 / 活跃 / 退订）。**它与单次活动的对照不同**：它把"所有活动的总和"当作处理对象。

**第三层：给出结论的处置。** 若 holdout 组长期留存高于处理组 ⇒ **整体已过量**；此时**改的是总量上限（Cap 调低）**，而不是砍掉某个活动——因为问题不在单个活动，在总量，**改单活动会让结论无法解释**。

**第四层：说出代价。** ① holdout 用户的短期收益归零；② **观察期以季度计**（长期指标变化缓慢）；③ **它需要有人长期看着**（月度数据会覆盖它）。

**3. 常见陷阱**
- 只答"再多做实验"（单活动实验解决不了这个问题）；
- 认为 holdout 就是"对照组"（它是长期版，测量对象不同）；
- 结论落地时去砍单个活动（判据与动作不匹配）；
- 忽略观察期（按周看长期指标会得出噪声结论）。

**4. 追问预测**
- "holdout 留多少？太小会怎样？"
- "如果 holdout 组留存更低，说明什么？"
- "上线时怎么处理'我们不能不给这部分人发'的反对意见？"
- "总量上限调低之后，名额怎么在活动间分配？"

**5. 参考资料**
- 本主题 §3.2.8（长期 holdout 与护栏）、§6.3（单活动都有效、整体过度的案例）、§2.1（负向指标）。

#### §8.5 你们想做 Uplift 定向，先决条件是什么？为什么"预测谁会转化"不够？

**1. 考察点**
- 是否知道 Uplift 的**训练数据必须有对照组**；
- 是否理解"高转化概率的人常常不是高增量的人"；
- 有没有"即使现在不做也要保留数据"的意识。

**2. 参考答案框架**

**第一层：给出目标差异。**

```
转化概率模型：P(Y=1 | i)            —— 谁最可能转化
增益模型：    τ(i) = P(Y=1|T=1,i) − P(Y=1|T=0,i)   —— 谁最可能"因触达而"转化
决策规则：    仅当 τ(i) > c / v 时才值得触达
```

**第二层：说明为什么前者不够。** **高转化概率的人常常 `τ ≈ 0`**（他本来就会买）——按转化概率排序，**会把预算持续投给不需要补贴的人**。这解释了为什么"精准人群"在没对照组时看起来效果更好、净增量却不涨（§6.2）。

**第三层：给出先决条件。** ① **历史数据里必须有处理组与对照组的样本**（`T=0` 占比不足三成时，任何 Uplift 建模都不可靠）；② 足够的样本量（`τ` 是两个概率之差，方差大）；③ **按触达形式分场景**（换文案 / 换渠道 / 换激励，`τ` 分布会变）。

**第四层：给出现在就该做的一件事。** **即使暂时不做 Uplift，也要保留"哪些用户在哪次活动里是对照组"的日志**——**它是一次性的原料，不保留就永远补不回来**（§5.3.2）。

**3. 常见陷阱**
- 认为 Uplift 只是"换个模型"（它需要不同的数据）；
- 用没有对照的数据训练增益模型（会退化成转化概率预测）；
- 忽略 `τ` 的方差（结论过于自信）；
- 用一次活动的模型跨场景套用。

**4. 追问预测**
- "T-learner 与 S-learner 你选哪个？为什么？"
- "如果历史数据里对照组只占 5%，够不够？"
- "`c / v` 里的 `v` 怎么估？"
- "Uplift 跑出来之后，怎么验证它真的比按转化概率排序更好？"

**5. 参考资料**
- 本主题 §2.2（`τ > c/v` 判据）、§3.2.7（Uplift 的适用条件与失效点）、§4.2（4）（两条路线）、§5.3.2（保留对照组日志的推论）。

#### §8.6 一个带券活动的 ROI，你会怎么算？为什么"只算触达费用"会得出错误结论？

**1. 考察点**
- 是否知道**激励成本常常是渠道成本的数量级之上**；
- 是否理解**成本杠杆在"给谁券"而不是"走哪条渠道"**；
- 有没有"成本必须可分解"的意识。

**2. 参考答案框架**

**第一层：给出成本的完整式子。**

```
触达成本 = Σ_渠道 (条数 × 渠道单价) + 激励成本
ROI      = 净增量 × 单次转化价值 − 触达成本
注意：分子必须是"净增量"（处理组 − 对照组），不是"转化数"
```

**第二层：说明量级关系。** 一条短信是**几分钱**，一张券是**几元到几十元**——**激励常是数量级更大的一项**。因此**只算触达费用会严重低估活动代价**，让"不划算"的活动看起来"很划算"。

**第三层：给出成本杠杆的所在。** 当 `激励 / 渠道单价` 的比值很大时，**控制成本的杠杆在"给谁券"**（`τ > c/v` 的判据），而不是"走短信还是推送"——**而"给谁券"的答案要求先有对照组**。**这条推论把 ROI 与实验设计连了起来**：没有对照组，ROI 的分子是错的，成本优化的方向也是错的。

**第四层：给出归属判断。** ROI 必须由**能把两边合起来的人**算——**触达工具不知道激励成本，交易系统不知道触达成本**，因此应当在**指标平台**里定义这一个指标（[Ch4 §10](../../04-data-assetization/10-metric-platform/10-metric-platform.md)）。

**3. 常见陷阱**
- 只算触达费用；
- 分子用"转化数"而不是"净增量"；
- 把激励成本按"核销数 × 面额"算但与触达人群不匹配（分母错位）；
- 不按渠道分解（"划算"可能只是"大部分量走了便宜渠道"）。

**4. 追问预测**
- "券的核销里有自然核销（不给也会买）的，这部分算不算成本？"
- "长期价值（复购、口碑）要不要计入？怎么计？"
- "如果 ROI 小于 1 但战略上要做，怎么处理？"
- "负向指标（退订）的代价怎么进 ROI？"

**5. 参考资料**
- 本主题 §4.6（成本账单与量级）、§7.4（三条成本曲线与 `i / c_ch` 的推论）、§2.2（成本判据与增量）、§6.7（ROI 口径）。
