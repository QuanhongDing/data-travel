# 协议一：质量审核与深度重写（Anti-Laziness Protocol）
1. **技术原理四段式（强制）**：每个核心技术点必须按此结构重写：
   - [Why] 为什么需要它（业务痛点与数据规模瓶颈）
   - [What] 它解决了什么核心问题（架构层面的本质）
   - [How] 底层运行机制（必须包含核心算法、关键参数、公式或源码级逻辑）
   - [Trade-off] 性能瓶颈、资源消耗与架构权衡（不写废话，只写硬指标）
2. **反偷懒绝对指令**：严禁使用"如上所述"、"同理"、"代码省略"、"由于篇幅限制"等省略语。
   每一个小节必须完整输出，宁可分多次完成，绝不可省略一行核心代码或原理。
3. **架构师全局视角（★ 章级，不是节级）**：**每一章**必须补齐：
   - TCO 成本分析（硬件 / 人力 / 云账单）
   - 容灾与故障演练（SRE 视角）
   - 从 0 到 1 再到 100 的演进路线
   这三件事**在章内任何一处出现即可**，不要求每个分节文件都各写一份。
   （复核这一类"约定"时，先确认它是**章级**还是**节级**——按错的粒度查，会产出一张把章级要求
   硬塞进每个文件的大工单。）

# 协议二：证据获取与案例验证 SOP（★ 已改为离线环境下的实际做法）
1. **证据环境（先记住这条）**：本环境**无网络**——联网搜索不可用，WebSearch 返回空、WebFetch 被拦。
   因此证据只能来自三个方向，**按优先级**：
   - **(a) 本书自己点名的出处**：书里已有的具名文档、论文、发布说明、官方文档；
   - **(b) 当场推算**：给出完整推导链（写成 `【推算：<链>】`），读者可换参数重算；
   - **(c) 经验区间**：只给量级与区间，不写精确值（写成 `【经验】`）。
2. **禁用形态**：**裸精确数字**——没有三级标注的"降低 47%"、"成本 300 万"这类，
   读者无从判断它从哪来。**每个精确数字都必须带 【公开】/【推算】/【经验】 之一。**
3. **案例不足时的降级**：若某个案例在书内无具名出处、又无法当场推算，
   则写成符合物理规律的"高仿真推演案例"，并标注 `[推演案例]`。
   **不要**编造一个像模像样的具名来源。
4. **★ 裁决规则（本会话反复用到）**：两侧说法不一致时——
   **先数两边各有几处，再决定方向**：
   - 悬殊的比值（如 43:1、97:4、548:8）⇒ 少数那边是**落单者**，改它；
   - 一侧一比（1:1）⇒ 那只是**两个实例，不是一条判据**，不要动；
   - **"有具名出处的一侧优先"只在两侧指的是同一个对象时成立**——
     否则你解决的就不是冲突，而是悄悄删掉一个从没被否定的断言。
   - **规则是全书惯例还是我自己的推断？** 推断出来的规则，**语料多数永远压过它**。

# 协议三：单代理推进与任务切片（★ 全局并行度 = 2）
1. **任务切片**：将全书拆解为「章-节-主题」树状结构；分片以**文件为单位**，
   分片之间**必须文件不相交**（否则两个并发写者会互相覆盖）。
2. **默认单人串行**：一轮只碰一个切片，走完一个闭环再开下一个——
   读原文 → 记缺陷 → 跑门禁取证 → 最小改动 → 再跑门禁 → commit + push。
   上一轮没闭环（没 push、或只改了半程）时，**先补齐再开新切片**。
3. **全局并行度上限 2**：确有**互相独立、且不写同一文件**的活时，才外派子代理，
   且**同时在跑的代理合计不超过 2 个**（你 + 至多 1 个）。这是**全局总并发**
   （所有工作流与子代理加起来），**不是「每个工作流 2 个」**；多开工作流只是把
   这 2 个槽位分给它，不提高上限。外派的那一个**只做只读核查**（回原文找反例）
   ——**写文件的永远是你自己**，这样两个写者互相覆盖的风险根本不会发生。
4. **确有两个写者时**（例外情形），用**文件占用登记**（`/tmp/claims.py`）做互斥；
   **手工改文件前也要先查占用**（`/tmp/safe-edit.py --add <file>`，它同时保证只 stage
   指定路径、绝不 `git add -A`）——脚本有守卫而手没有，是出过事故的。
5. **反截断**：单个交付单元过大就拆开；**宁可分多轮，不可半途而废**——

6. **只改该改的**：每行改动都要能追溯到本轮目标；不顺手"改进"相邻内容。

# 协议七：验证纪律（★ 本节是执行中最贵的一课，逐条都是踩出来的）
1. **零必须被验过。** 任何检查报 0，先拿一个**已知实例**让它报出来；
   再从它的命中里**挑一条回原文亲眼看一遍**。两步都过，这个 0 才算数。
   - 一个报 0 的门禁，与一个**没喂到输入 / 正则没匹配上 / 被喂了陈旧快照**的门禁，
     输出长得一模一样。（本会话曾有一道门禁读了 11 小时前的旧快照，报了整整一轮的"0"。）
2. **判据的边界先于判据。** 检查失败几乎都败在**边界**，不在判据本身：
   词类多收了一个字符（把 `-` 放进拉丁词类，命中从 1 变成 333）；
   切分切错了层级（按 `###` 切 vs 按 `####` 切，误差 308 道题）；
   白名单漏了合法变体（Conventional Commits 的 `!`、单位词 `GB-月`、超长标题）。
   **写任何白名单 / 字符类 / 长度上限时，先问：它漏掉了哪些合法写法？**
3. **先看被处理对象长什么样，再决定按什么切。** 一条 `grep '^#\{2,4\} '` 常常省掉后面所有的猜。
4. **自述是线索，不是事实。** 外派核查子代理的结论、以及**你自己上一轮写下的结论**，
   都只是线索：说"改了 24 处"，实际 diff 可能是 5 行；说"某某在某某之后"，也可能说反。
   **核验一律回原文**——**不要拿自己的总结当原文**，那是单代理模式下最容易自欺的一步。
5. **改动越大，越要先设计一个能证明"只改了想改的那一类"的比对。**
   例：整篇标点归一后，把全角半角标点全部折叠掉再比对——**改前改后逐字一致**，
   "只动了标点"这句话才是证出来的。（证不出来，就不该合。）
6. **记录而不改。** 当"该不该改"的答案是"该，但改法不是机械的 / 会牵动另一处已自洽的东西"时，
   **记下来交给作者**，并附上量好的代价（几处、几处引用）。不要自己定一套新约定。

# 本书自己的证据与一致性规则（改稿时的判据来源）
1. **三级证据档**：【公开】指名文档 / 发布说明 + 年份；【推算】当场给推导链；【经验】只给区间。
   禁裸精确数字。**一个精确数字没有档，就是缺陷。**
2. **有具名出处的一侧优先**（同一对象之间比较）。若两侧都带档但一侧具名、一侧泛称
   （如"某公司公开材料 2023-2024"），按**具名程度**判，不是按"有 vs 无"。
3. **案例年份以该案例主文件 §1.1 年表为准**；量级是另一个轴，要独立给出处。
4. **四种缺陷形态**（找缺陷时按这四类去找，比随机读有效）：
   - **落单者**：同一事实有 N 种写法，N−1 种已经一致 —— 对齐到语料多数那一侧；
   - **未传播的修复**：一处改了，兄弟文件仍引旧值（同一文件里的另一处也算）；
   - **框架错**：值没错，但断言的结构错了（判据张冠李戴、量纲不通、单选式断言覆盖了多选事实）；
   - **编造专名**：以某系统名展开整节，而该名全仓零命中（核验法：`grep` 这个名字）。
5. **已知的、有意不统一的地方（不要"修"）**：
   - 全书 §6 案例叙述的规模量级普遍比该案例主文件的具名出处高一级（PB→EB），≥7 家公司 / 155+ 处。

   - `01-alibaba-data-middle-platform` 的 §5/§6/§7 与同级体例不同（是分析体例），属主题级差异。

     但文件名里编码了原题库的 §8.x 编号，改名会丢出处；**改名要新造一套命名，属作者决定**。
