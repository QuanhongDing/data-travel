## 3. 设计模式与范式

### 3.1 先看约束：模式不是选择题，是约束的产物

推荐系统的模式常被讲成「按业务特征挑一个模型」。但真正决定架构的是**候选集规模 × 请求延迟预算**这一对约束：Item 动辄千万级，而单次请求必须在用户划走之前返回——在线推荐 P99 通常被压在几十到几百毫秒量级【经验】。这条约束一立，任何「把所有候选送进一个强模型」的方案就被直接排除：不是因为它不准，而是因为它算不完。召回 → 粗排 → 精排 → 重排的分层漏斗，是被这条约束逼出来的第一个模式，其余模式（多任务、多模态、图、RL、LLM、生成式、冷启动、实时、联邦）都是在漏斗的某一层上补某一种缺失的信号。

第二条约束是**反馈闭环**。训练数据由推荐系统自己产生：只有被曝光的 Item 才有标签，没被曝光的 Item 永远没有反事实标签。这条约束把所有「监督学习式」的直觉都打上问号——评估、探索、冷启动、公平性这几类模式，本质上都在处理「标签来自策略自身」这一件事。

第三条是**目标多元**。平台要的是长期 GMV 与留存，而能即时测量到的只有点击。目标越多模型越难；只优化可测量的那个，不可测量的那个会掉。多任务与强化学习都是这条约束的产物，区别在于：多任务在一次请求内平衡多个目标，强化学习把平衡推到时间维度上。

所以下面先立约束，再拆模式。表中「最容易被它推翻的直觉」一列是本节反复使用的判别法：**当某个模式的选择理由与你团队当下的直觉冲突时，先看是哪条约束在起作用。**

| 约束 | 它决定了什么 | 本主题下最容易被它推翻的直觉 |
| --- | --- | --- |
| 候选集规模（万 / 千万 Item） | 用不用分层漏斗、召回用什么形态（向量检索 / 生成式 / 规则） | 「模型够强就行」——候选到千万级，强模型只在被召回的小集合上才有机会运行 |
| 请求延迟预算（几十～几百毫秒） | 每层能放多少算力，实时特征能算多复杂 | 「离线跑得好就能上线」——离线没有延迟预算，线上有 |
| 反馈闭环与样本分布 | 探索是否必需、离线评估是否可信 | 「离线 AUC 高就行」——离线样本是被旧策略筛过的，分布已被裁剪 |
| 目标数量与考核周期 | 多任务还是 RL、探索预算能否保住 | 「先只优化 CTR」——可测量目标会被优化到损害不可测量目标 |
| 行为稀疏度与冷启动比例 | ID 特征、内容特征、图特征三者的相对权重 | 「上更强的 ID 模型」——共现为零时 ID 表征拿不到梯度信号 |
| 更新时效与合规边界 | 要不要实时特征链路、要不要联邦 | 「数据集中起来训练最好」「天级更新够用」——合规不允许 / 热点以分钟计 |

### 3.2 模式逐个拆解（核心节）

#### 3.2.1 分层漏斗（召回 → 粗排 → 精排 → 重排）

- **被什么约束逼出来**：候选千万级 + 请求延迟百毫秒级【经验】，而精排单次推理成本随候选数线性增长。
- **结构**：
  ```text
  请求 ─► 召回   1000~10000 候选  （向量检索 / 倒排 / 规则；量级为经验值【经验】）
          └► 粗排   100~500 候选   （轻模型、少特征）【经验】
              └► 精排   10~50 候选 （重模型、全特征）【经验】
                  └► 重排  最终 N 条（多样性 / 频控 / 业务硬规则）

  成本模型：总开销 ≈ 召回 O(候选全集) + 精排 O(候选数 × 单条推理成本)
  若不分层：O(候选全集 × 单条推理成本) → 延迟与算力都不可接受
  ```
- **为什么这样设计有效**：因为召回大多是无参数或极轻的近邻检索，而精排是重模型，所以把「贵的推理」限制在一个小集合上，总开销远小于「精排全量」——这是分层而非「换个更快的模型」能换来的量级差。
- **代价**：级联不可逆——没进召回候选集的 Item，后面任何一层都救不回来，所以召回决定效果上限、精排只决定上限内的相对顺序。四层各有一套模型、一套特征、一套监控，版本必须对齐。
- **失效点**：当召回为可扩展性牺牲了「用户 × 候选」交叉能力时（典型是双塔把用户与 Item 编码成两个独立向量、只在向量空间做内积），精排再强也补不回召回丢掉的表达力——机制是内积空间无法表达特征交叉，交叉只能等到精排，而精排永远看不到没被召回的 Item。
- **真实使用**：YouTube 的候选生成 + 排序两阶段结构见 Covington et al., RecSys 2016【公开】；Google Play 的 Wide & Deep 见 Cheng et al., RecSys 2016【公开】；国内电商普遍采用「召回—粗排—精排—重排」四层，属工程惯例【经验】。

#### 3.2.2 多任务学习（MMoE / PLE / ESSM / AITM）

- **被什么约束逼出来**：要同时优化 CTR / CVR / GMV / 时长，而各目标的标签空间不同——CVR 只在点击样本上有标签，样本选择偏差（SSB）是内生的。
- **结构**：
  ```text
  共享底层（Shared-Bottom）              多门控（MMoE / PLE）
     x ─► shared ─┬─► tower_CTR            x ─► experts[E] ─► gate_CTR ─► tower_CTR
                  └─► tower_CVR                        └─► gate_CVR ─► tower_CVR
                                        （每个任务用独立门控决定取哪些专家）

  全空间多任务（ESSM）：
    曝光 ─► pCTR ─┐
                  ├─► pCTCVR = pCTR × pCVR  ← 监督信号在全曝光空间，CVR 塔隐式训练
    点击 ─► pCVR ─┘
  ```
- **为什么这样设计有效**：因为 CVR 的训练分布（点击样本）与推理分布（全曝光）不一致，直接训练 CVR 必然有偏；而 pCTCVR = pCTR × pCVR 在曝光全空间上有标签，所以 CVR 塔能从乘法结构里隐式拿到无偏梯度。
- **代价**：任务间梯度冲突要靠门控/专家隔离，参数量与训练成本上升；任务损失权重成为新的超参，改权重等于改各任务的实际优化强度；样本空间不一致时还要额外处理采样。
- **失效点**：当两个任务的用户行为几乎不相关时（例如「完播」与「下单」），门控会退化成各任务各用一组专家，共享信号近似为零——多任务相对单任务不再有增益，而参数量、训练时长、调参成本全部保留；机制是门控的收益来自专家被多任务共用，不共用时它只是一层路由。
- **真实使用**：MMoE 见 Ma et al., KDD 2018【公开】；PLE 见 Tang et al., RecSys 2020【公开】；ESSM 见 Ma et al., SIGIR 2018【公开】；AITM 见 Xi et al., 2021【公开】。

#### 3.2.3 多模态推荐

- **被什么约束逼出来**：新 Item 零交互，ID 特征拿不到梯度信号，但它的标题、封面、视频帧是现成的。
- **结构**：
  ```text
  文本 ─► 文本编码器（BERT 类）  ─┐
  图像 ─► 图像编码器（ViT / CLIP）┼─► 融合（拼接 / 注意力）─► 内容向量 c_i
  视频 ─► 视频编码器             ─┘                              │
                                                                 ▼
        ID 特征 e_i ──────────────────────────────────► 排序模型（精排）
  冷启动路径：协同信号缺失时，用 c_i 做近邻召回 / 初始化 e_i
  ```
- **为什么这样设计有效**：因为内容向量由在海量图文对上预训练的编码器给出，它对零交互的新 Item 仍是一个非退化的向量，所以「内容相似」可以立即转成「候选相似」，不必等交互积累。
- **代价**：每个 Item 多一份（多模态时是多份）向量存储与一次编码推理；编码器版本与排序模型版本解耦，编码器升级意味着整库向量重刷，且升级前后向量处于不同空间、不可混用。
- **失效点**：当内容语义与用户偏好弱相关时（标品、工具类、强价格导向的品类），多模态相似度会稳定指向「长得像但不该推」的 Item——机制是编码器优化的是语义相似，而推荐要的是行为共现，两者在弱相关内容上并不同向。
- **真实使用**：CLIP 提供图文对齐编码器，见 Radford et al., ICML 2021【公开】；VBPR 验证视觉信号对推荐有增益，见 He & McAuley, AAAI 2016【公开】；工业界把多模态向量用于冷启动物品召回与内容去重是通行做法【经验】。

#### 3.2.4 图神经网络推荐（GNN）

- **被什么约束逼出来**：协同过滤的本质信号是「用户—物品」二部图上的多跳传播，而矩阵分解只建模一跳。
- **结构**：
  ```text
        u1 ── i1 ── u2          二部图：用户 — 物品 — 属性
        │      │      │
        i2 ── u3 ── i3

  LightGCN 一层传播：e_u^(k+1) = Σ_{i∈N(u)} e_i^(k) / sqrt(|N(u)| · |N(i)|)
  说明：去掉非线性与特征变换，只剩邻域加权聚合；
        k 层 = 「朋友的朋友看过的物品」进入 u 的表示
  ```
- **为什么这样设计有效**：因为在同构二部图上，去掉特征变换后的逐层邻域聚合近似于对高阶邻域做低通平滑，所以 k 层传播就把多跳共现灌进用户表示——这正是 ItemCF 用手工相似度近似的东西，GNN 把它变成可学习的。
- **代价**：每层一次邻接聚合，邻居数随层数膨胀，必须采样子图；训练图与线上推理图必须是同一张快照，否则线上线下不一致；图规模大时「图更新」本身成为独立工程项。
- **失效点**：当交互更新频率远快于图重算周期（小时级新行为）时，图上传播出的高阶信号描述的是过期兴趣——机制是 GNN 的收益依赖图结构稳定，图越旧偏差越大，此时只用最新序列特征的轻模型反而更准。
- **真实使用**：NGCF 见 Wang et al., SIGIR 2019【公开】；LightGCN 见 He et al., SIGIR 2020【公开】；KGAT 见 Wang et al., KDD 2019【公开】。

#### 3.2.5 强化学习 / Bandit 推荐

- **被什么约束逼出来**：曝光由策略自身决定，未被曝光的 Item 没有反事实标签；只看即时点击会陷入局部最优。
- **结构**：
  ```text
  监督学习视角（有偏）              Bandit 视角（纠偏）
    日志里的曝光 → 有标签             臂 = 候选（或候选分组）
    日志里没有的 → 永远没标签         回报 = 点击 / 转化
                                      策略 = ε-greedy / Thompson / LinUCB
                                      目标 = 最小化累积遗憾（regret）

  RL 视角：状态 s（用户 + 上下文）─► 动作 a（推荐集合）─► 奖励 r ─► s'
           优化的是策略 π(a|s) 的长期回报，而不是单次点击概率
  ```
- **为什么这样设计有效**：因为探索让每个臂的回报估计逐步无偏，所以「热门越曝越热」的流行度偏置在机制上被削弱——这正是只拿日志做监督训练做不到的事。
- **代价**：探索必然牺牲短期指标，在线实验中表现为探索组点击率下滑；策略评估困难（需反事实估计，如 IPS / doubly robust，方差大）；奖励函数的设计本身就是业务问题，改奖励等于改目标。
- **失效点**：当考核周期短于探索回报周期时，探索带来的短期指标下滑会触发「关掉探索」的决定——机制是探索的成本即时发生、收益延后兑现，考核只看当期就会系统性地杀掉探索，长期价值目标随之落空。
- **真实使用**：Yahoo! 的上下文 Bandit 新闻推荐见 Li et al., WWW 2010【公开】；DQN / PPO 类深度 RL 推荐目前更多见于论文与实验环境【经验】。

#### 3.2.6 LLM 推荐

- **被什么约束逼出来**：零交互或跨域场景下纯 ID 模型学不到，而 LLM 的语义先验不依赖本站交互；同时 LLM 的推理成本与延迟高。
- **结构**（三种用法，对应三个不同的挂载点）：
  ```text
  ① 直接推荐：prompt(画像 + 历史文本) ─► LLM ─► Item 列表（必须约束输出空间）
  ② Embedding 推荐：Item 文本 ─► 编码器 ─► 向量库 ─► 检索 ─► 进漏斗
  ③ 理由生成：精排结果 ─► LLM ─► 一句话解释（展示层，不参与排序）

  分界：①② 的产物进漏斗当召回信号；③ 只在展示层
  ```
- **为什么这样设计有效**：因为 LLM 在预训练语料上学到的是「内容讲什么」，这与本站交互是否稀疏无关，所以它在共现为零时仍能给出语义级相似；也正因为它不理解本站实时反馈，它适合当召回/补充信号而不是主排序。
- **代价**：单次生成的 token 成本与端到端延迟比向量检索高出若干数量级【经验】；提示词、目录描述、模型版本都成为模型外的隐性依赖，换模型等于换了一整套「特征」。
- **失效点**：当 Item 空间有几十万以上而生成不施加约束时，LLM 会输出目录里不存在的 Item（幻觉 ID），此时它从「零样本可用」反转成「输出不可用」——机制是自由文本生成的概率分布覆盖整个词表，而合法 Item 只占其中极小一部分。
- **真实使用**：P5 见 Geng et al., RecSys 2022【公开】；GPT4Rec 见 Li et al., 2023【公开】；ChatRec 见 Gao et al., 2023【公开】。

#### 3.2.7 生成式推荐（TIGER / LC-Rec / CFGen）

- **被什么约束逼出来**：双塔把用户与物品压成两个独立向量、交互只能在内积空间发生；而生成模型可以让「检索」与「生成」共用同一个序列空间。
- **结构**：
  ```text
  Item ─► 内容向量 ─► 量化（RQ-VAE / 层次聚类）─► 语义 ID（分层码本）
       例：item_4711 → "AA23-BB45-CC67"（3 级码，每级取自一个码本；级数为实现选择【经验】）

  用户历史 ─► 语义 ID 序列 ─► 自回归生成 ─► 下一组语义 ID
  解码约束：beam search + 前缀树（trie），只在真实存在的 ID 前缀上扩展
  ```
- **为什么这样设计有效**：因为语义 ID 把每个 Item 变成一段短 token 序列，且前缀树把解码限制在合法 ID 集合内，所以生成空间被约束成真实目录的子集，「生成不存在的 Item」在解码层面就被排除；同时相似 Item 共享 ID 前缀，模型学的是有层次的语义而不是任意编号。
- **代价**：语义 ID 依赖一次量化训练，目录新增/下架要增量维护或重训；自回归推理逐 token 展开，延迟高于单次向量检索；ID 一旦重训，历史序列与旧 ID 不再可比。
- **失效点**：当目录高频变动时（每日大量上新），语义 ID 的重训周期跟不上目录变化，旧码本与新 Item 的语义空间错位——机制是「共享前缀」的前提是码本稳定，码本漂移后前缀不再代表语义，生成式召回最核心的语义邻近优势首先受损。
- **真实使用**：TIGER 见 Rajput et al., NeurIPS 2023【公开】；LC-Rec 与 CFGen 属同一方向的后续工作，引用前请按论文名（LC-Rec、CFGen）检索原文，确认作者、发表会议与年份后再补全出处【经验】。

#### 3.2.8 冷启动处理

- **被什么约束逼出来**：协同信号来自共现，而新用户/新 Item 的共现为零——不是「少」，是「没有」。
- **结构**（三路兜底 + 一条闭环）：
  ```text
  新 Item：内容向量 → 近邻召回（相似 Item 的受众）
  新用户：人口学 / 设备 / 地域 / 社交关系 → 人群先验（该人群的高频 Item）
  两者都有：探索配额（Bandit）→ 小额均匀曝光 → 回流的共现喂给 ID 模型

  闭环：曝光 → 交互 → 共现 → 下一轮才有协同信号可用
  强调：前两路只能回答「像谁」，只有第三路能产生新标签
  ```
- **为什么这样设计有效**：因为内容与群体先验是与共现无关的替代信号，所以在共现为零时仍能给出非随机候选；而探索配额负责把「候选」变成「标签」，填补 ID 模型的数据缺口。
- **代价**：内容侧依赖内容质量（标题、类目、封面），字段缺失或错标会直接误导；探索配额按定义要牺牲一部分曝光效率；冷启动链路需与主链路并网并单独监控，运维面变大。
- **失效点**：当内容特征与真实偏好正交时（老内容换新壳、小众垂类），内容相似度会稳定地把新 Item 推给错的人——机制是冷启动路径没有反馈纠正项：正反馈来自点击，而推错的人不会点，于是既拿不到正样本也拿不到有区分度的负样本，错误被持续放大。
- **真实使用**：用内容 Embedding 做冷启动召回在电商与内容平台是通行做法【经验】；用 Bandit 分配新 Item 探索曝光见 Li et al., WWW 2010 一类工作【公开】。

#### 3.2.9 实时推荐（Streaming）

- **被什么约束逼出来**：用户兴趣的衰减尺度是分钟级，离线训练与离线特征表是天级；热点事件的分布变化快于模型重训周期。
- **结构**：
  ```text
  批链路（T+1）：  行为日志 ─► 离线特征表 ─► 离线训练 ─► 模型
  流链路（分钟级）：行为日志 ─► 流计算（如 Flink）─► 实时特征（如近 5 分钟点击类目【经验】）
                            └─► 特征服务（在线拼接）
  在线：请求 ─► 模型读取【离线特征 + 实时特征】─► 排序
  可选的第三层：在线学习（用回流样本持续更新模型参数，而不只是重算特征）

  口径纪律：同名特征在批、流两侧必须是同一份定义，否则线上线下分布不一致
  ```
- **为什么这样设计有效**：因为实时特征在请求时点由最近的原始行为算出，携带了离线表尚未包含的信息，所以在「兴趣刚刚变化」的窗口内模型不再完全依赖昨天的画像——缩小训练与推理的时间差，等于缩小分布差。
- **代价**：批与流两套实现、两套测试，口径对齐是持续性成本；实时特征不可回填（无法重放当时状态），出问题只能堵不能补；流作业的延迟与背压直接叠加进推荐延迟。
- **失效点**：当两套链路的口径悄悄分叉（同名特征两套 SQL、流侧漏处理迟到数据）时，线上特征分布与训练时不同，模型静默退化——离线 AUC 不变、监控不报警，只有业务指标缓慢下滑；机制是特征错位不会被离线评估捕捉，因为离线评估用的正是训练时的那套特征。
- **真实使用**：Lambda 架构由 Nathan Marz 提出，代表性出处为 Marz & Warren《Big Data: Principles and Best Practices of Scalable Realtime Data Systems》（Manning, 2015）中对批层 + 速度层的论述【公开】；以流式特征 + 在线/近线更新支撑实时推荐，在内容与电商平台是通行做法【经验】。

#### 3.2.10 联邦推荐

- **被什么约束逼出来**：数据不出域（跨企业、跨机构），而协同信号分布在多方；中心侧无法收集原始行为。
- **结构**：
  ```text
  各方（数据不出域）：本地数据 ─► 本地模型 ─► 只上传【梯度 / 更新 / 加密摘要】
                                                  │
  中心：聚合（FedAvg 类）─► 全局参数 ─► 下发各方

  对齐前提：各方 Item 空间需有交集（隐私集合求交 PSI / 公共 ID 体系）
  可聚合对象：用户侧参数（各侧都有用户） > Item 侧参数（Item 不重叠则无意义）
  ```
- **为什么这样设计有效**：因为各方共享的是模型更新而非原始行为，所以在合规约束下用户表示仍能吸收多方的协同信号——前提是各方有重叠实体，否则聚合的是互不相干的目标。
- **代价**：多轮通信带来延迟与网络开销；ID 对齐需要 PSI 或公共 ID 体系，本身是一个工程项；上传的更新仍有被反演与成员推断的风险，需额外防御（安全聚合、差分隐私）。
- **失效点**：当各方 Item 重叠度很低时（跨行业营销、不同垂类），只有用户侧参数可共享、Item 侧参数无法共享，联邦增益接近于零而通信与对齐成本全在——机制是联邦聚合的收益来自「同一实体在不同方有不同的侧面」，实体不重叠时没有侧面可拼。
- **真实使用**：FedAvg 见 McMahan et al., AISTATS 2017【公开】；联邦推荐是学术界活跃方向，落地多见于跨机构联合建模场景【经验】。

### 3.3 模式选择决策表

| 约束组合 | 推荐模式 | 为什么不选另一个 | 关键判据 |
| --- | --- | --- | --- |
| Item 千万级 + 延迟 < 200ms【经验】 | 双塔召回 + 分层漏斗 | 单个强模型全量排序算不完 | 单次请求能承受多少次模型推理 |
| 新 Item 占比高 + 内容可用 | 内容/多模态向量召回 + 探索配额 | 纯 ID 双塔对零交互 Item 拿不到梯度 | 新 Item 首次曝光前有无可用内容向量 |
| 行为丰富 + 单目标 | ItemCF / FM / DeepFM 起步 | DIN / Transformer 在数据不足时过拟合 | 交互量级与特征维度 |
| 长尾分布明显 + 行为稀疏 | 双塔召回 + MMoE（多任务缓解稀疏） | 单塔的容量被头部 Item 占满，长尾 Item 的样本养不起独立参数 | 头部与长尾 Item 的样本量相差几个量级 |
| 长序列行为（数百条）+ 算力足 | DIN / DIEN / SIM | 只用统计特征会丢掉兴趣演化 | 序列长度与在线算力预算 |
| 强上下文（新闻 / 短视频） | SASRec / BERT4Rec 类序列模型 | 静态画像更新慢于上下文变化 | 兴趣半衰期【经验】 |
| 实时性要求高（兴趣衰减以分钟计）【经验】 | 流特征 + 在线学习 / 近线更新（Flink 类） | 纯离线特征表的新鲜度落后于兴趣漂移，模型描述的是昨天的人 | 特征更新周期能否短于兴趣漂移窗口 |
| 多目标（CTR + CVR + GMV） | MMoE / PLE / ESSM | 加权单目标权重不可解释且反复调 | 任务间标签空间是否一致 |
| 内容异构（文本 + 图像 + 视频） | 多模态编码 + 融合 | 只用 ID 特征则冷启动无解 | 内容模态覆盖率 |
| 知识密集（医疗 / 教育） | 知识图谱 + KGAT 类图模型 | 纯协同在共现稀疏时无信号 | 是否存在可用的实体关系图 |
| 需要可解释 / 对话式 | LLM 理由生成 / ChatRec | 把 LLM 当主排序成本与延迟过高 | 解释是展示层需求还是排序需求 |
| 范式对齐 + 目录相对稳定 | 生成式推荐（TIGER） | 目录高频变动时语义 ID 重建跟不上 | 目录变更频率 vs 码本重建周期 |
| 需要探索未知兴趣 | Bandit | 纯利用会被流行度偏置锁死 | 探索预算能否跨过考核周期 |
| 长期价值优化 | RL / 序列决策建模 | 贪心点击率会损害长期指标 | 反馈是否闭环、长期奖励是否可得 |
| 跨域 / 隐私约束 | 联邦推荐 | 集中训练不合规 | 各方实体重叠度 |
| 图文输入 + 模态对齐 | CLIP / CLIP4Rec 类编码器 + 向量检索 | 单模态会丢失一半信号 | 模态与用户偏好是否相关 |

本主题下**最常被误选的一对**是「单塔强模型」与「双塔召回 + 轻精排」。团队在行为数据只有十万级用户、万级 Item 时【经验】就上 DIN / Transformer，离线 AUC 往往确实更高，但在线延迟超预算后被迫把强模型只跑在 Top-N 候选上，等于自己手搓了一个退化版漏斗；而正确的起点通常是双塔 + FM/DeepFM，等交互量与算力同时到位再换重精排。误选的实际后果不是「不准」，而是**把延迟预算花在了最不该花的位置上**。

### 3.4 组合模式：真实系统不会只用一种

**组合 A：双塔召回 + 多任务精排（MMoE / PLE）+ 重排规则**（电商 / 内容主流）

- 职责边界：双塔只负责「别漏」，主动放弃交叉特征换可扩展；多任务负责在一次请求内平衡 CTR / CVR / GMV；重排负责多样性、频控与业务硬规则。
- 组合的运维代价：三套模型、三套特征、三套监控；召回与精排若用不同的负采样口径，会出现「召回排名与精排排名系统性错位」，需要定期做一致性校验。
- 适合规模：Item 千万级、日活千万级以上【经验】。

**组合 B：内容/多模态向量 + 探索配额 + 冷启动旁路**（新品或新用户占比高的平台）

- 职责边界：内容向量回答「像谁」，探索配额回答「标签从哪来」，冷启动旁路独立于主链路运行，避免冷启动样本污染主模型分布。
- 组合的运维代价：内容向量随编码器升级需整库重刷；探索配额需要算法、产品、运营三方协商预算，是组织成本而非技术成本。
- 适合规模：日新增 Item 千级以上、或新用户占比高【经验】。

**组合 C：实时流特征 + 近线更新 + 生成式召回**（内容 / 短视频）

- 职责边界：流链路负责分钟级兴趣，近线更新负责让模型跟上，生成式召回负责语义邻近与架构对齐。
- 组合的运维代价：批流两套口径 + 语义 ID 重建周期，三者叠加是本节运维面最大的组合，建议只在有专职推荐平台团队时采用。
- 适合规模：目录相对稳定、算力充足的中大型内容平台【经验】。

### 3.5 反模式与失效分析

| 反模式 | 症状（怎么发现它） | 后果（机制层面的后果） | 成因（为什么团队会写成这样） | 修法 |
| --- | --- | --- | --- | --- |
| 一开始就用深度学习 | 十万用户 / 万级 Item【经验】直接上 DIN / Transformer | 参数远多于有效样本，验证集波动大，线上不稳 | 论文与招聘市场都以深度模型为标杆 | 结构化数据双塔 + DeepFM 起步，按数据量升级 |
| 忽视冷启动 | 新 Item 曝光量长期接近零 | 协同信号永远攒不起来，长尾 Item 自我实现地失败 | 评估只看整体指标，头部 Item 掩盖了新 Item 的塌陷 | 内容 Embedding 召回 + 探索配额 + 新 Item 独立监控 |
| 单一目标优化 | 只看 CTR，GMV / 复购下滑 | 可测量目标被优化到损害不可测量目标，且滞后暴露 | 只有 CTR 有即时、稳定的在线信号 | 多任务（MMoE / PLE）+ 业务指标对齐 |
| 信息茧房 | 推荐类目熵持续下降 | 纯利用策略强化已有偏好，探索通道被指标压掉 | 多样性没有对应的考核指标 | 重排多样性约束 + 探索预算 + 类目熵监控 |
| 离线 AUC 高但在线效果差 | 离线涨、在线平或跌 | 离线样本由旧策略筛选，训练分布与线上暴露分布不一致 | 把离线指标当成效果的充分证明 | A/B 实验 + 反事实评估 + 训练/推理特征一致性校验 |
| 训练数据不更新 | 模型训练时间戳远早于当前 | 兴趣漂移后模型描述的是历史人群，效果断崖式下滑 | 重训链路未自动化、重训成本高 | 实时特征 + 定期重训 + 训练数据新鲜度监控 |
| 忽视公平性 | 少数群体曝光显著偏低 | 偏见在闭环里自我强化，因为被低估的群体拿不到样本 | 公平性指标不在需求文档里 | 分群指标监控 + 公平性约束 + 反事实评估 |
| LLM 推荐盲目信任 | LLM 输出无评估集、波动大 | 没有基线就无从判断增益，退化时也发现不了 | LLM 效果「看起来很好」，跳过了评估环节 | Golden Set + 持续监控 + 与传统召回并行对照 |
| 生成式推荐无约束 | 输出目录中不存在的 Item ID | 展示层拿不到实体，链路断裂且用户可感知 | 把自由文本生成直接当检索用 | 语义 ID + 前缀树受限解码 + 输出合法性校验 |
| 不做重排 | 首页前十高度同质 | 精排只优化单条相关性，不做集合级优化 | 重排被视为「规则层」，不算模型工作 | 重排必须做：多样性 / 频控 / 上下文规则显式化 |

最危险的三条，生产中通常这样暴露：

**「一开始就用深度学习」**——它的暴露方式是「指标看板全绿但业务没感觉」：验证集 AUC 在涨，上线后在线的增量被延迟与工程损耗吃掉。它的成因往往是组织性的：招聘要求写深度模型，团队就一定会先建深度模型，而没有人负责回答「这些参数有多少有效样本养得起」。

**「离线 AUC 高但在线效果差」**——暴露方式是每一次离线模型迭代都在线无收益，团队逐渐失去对离线指标的信任，进而放弃迭代。机制在 3.2.9：离线评估使用的特征分布与线上请求时点的分布不同，而这个问题不会让离线指标变差，只会让在线指标不动。

**「生成式推荐无约束」**——暴露方式是线上偶发白屏或占位缺失，日志里出现无法解析的 Item ID。机制在 3.2.7：生成模型的概率分布覆盖整个词表，合法 Item 只占极小一部分，缺少受限解码时「偶尔生成不存在的 Item」是必然而不是意外。

### 3.6 规模跃迁时模式何时该换

模式不是一劳永逸的。**当规模或访问模式跨过某个阈值，原来正确的模式会变成错的**——判据是「当前方案的复杂度函数与数据量的关系」，而不是「效果好不好」。

| 跃迁 | 原模式 | 为什么开始疼 | 换成 | 迁移的代价 |
| --- | --- | --- | --- | --- |
| 万级 → 十万级 Item | 相似度矩阵 / 内存态协同过滤 | 用户×Item 相似度矩阵的空间与更新成本随 Item 数平方级增长 | 双塔（用户塔 + 物品塔独立编码） | 放弃交叉特征，召回表达力下降，靠精排补偿 |
| 十万 → 千万级 Item | 全量精排 | 单次推理次数等于候选全集，延迟预算被击穿 | 分层漏斗（召回 → 粗排 → 精排 → 重排） | 新增三层模型与特征链路，需接受级联损失 |
| 单目标 → 多目标 | 单塔单目标 | 目标冲突时只能靠人工加权，权重随业务反复漂移 | MMoE / PLE / ESSM | 参数量与训练成本上升，损失权重成为新超参 |
| 天级 → 分钟级更新 | 纯离线特征表 | 兴趣漂移窗口短于特征新鲜度，模型描述的是昨天的人 | 流特征 + 在线/近线更新 | 批流两套口径的长期对齐成本，实时特征不可回填 |
| 单域 → 跨域 / 合规约束 | 集中式训练 | 数据无法汇聚，集中训练在合规上直接不成立 | 联邦推荐（FedAvg 类） | 通信轮次开销 + ID 对齐工程，且要求各方实体重叠 |

### 3.7 自检清单

- [ ] 精排的候选数是否被上游明确限制？若精排直接面对千万级全集，说明漏斗没有真正建起来。
- [ ] 召回层丢掉的能力是否被记录？能否回答「当前召回方式放弃了哪些交叉特征、由谁补偿」。
- [ ] 线上特征与离线训练特征是否同源同口径？同名特征能否追溯到唯一一份定义。
- [ ] 曝光日志是否记录了当时的策略版本？没有记录就无法做反事实评估，也无法审计探索。
- [ ] 每个优化目标是否都有对应的在线指标？只有离线指标的目标等于没有验收标准。
- [ ] 新 Item / 新用户的曝光量是否单独监控？只看整体指标会掩盖冷启动塌陷。
- [ ] 多任务模型的损失权重是否有版本记录？权重变更是否走评审。
- [ ] 探索预算是否写入排期与考核？若只存在于算法描述里，它会在第一次指标下滑时被砍掉。
- [ ] 生成式召回的输出是否受限于合法 ID 集合？是否存在输出合法性校验。
- [ ] 重排规则是否显式化并可审计？隐式规则在事故复盘时无法定位。
- [ ] 是否保留了传统召回与 LLM 召回的并行对照？单一信号源退化时需要有基线可比。
- [ ] 模型的训练数据时间戳是否可见？无法回答「模型学的是哪段时间的人」就是不达标。

### 3.8 小结

| 你的约束 | 建议模式 | 关键理由（机制层面） |
| --- | --- | --- |
| 候选千万级 + 延迟硬约束 | 分层漏斗 + 双塔召回 | 把重推理限制在小候选集，总开销不再随候选全集线性增长 |
| 零交互 Item 多 | 内容/多模态向量 + 探索配额 | 共现为零时 ID 特征无梯度，必须先有非共现信号再接标签 |
| 多目标且标签空间不同 | ESSM / MMoE / PLE | 在曝光全空间上监督，才能消除点击样本带来的选择偏差 |
| 兴趣以分钟计 | 流特征 + 批特征双链路 | 特征新鲜度决定模型描述的是哪一刻的用户 |
| 数据不能出域 | 联邦推荐 | 共享更新而非共享原始行为，且要求各方实体重叠 |

> 本节小结：本主题下决定模式选择的**唯一那条约束是「候选集规模 × 延迟预算」**——它逼出了分层漏斗，也决定了每个模式被挂在哪一层上；其余约束（反馈闭环、目标多元、稀疏度、时效、合规）只决定这一层里放什么，不决定要不要分层。
