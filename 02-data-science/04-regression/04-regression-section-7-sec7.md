## 7. 与其他方法对比

> 原 § 7 共 97 行、为 10 维度打分表 + 决策树 + 6 条组合，缺少机制解释与可溯源证据，重写为 300 行对比与选型工程。

### 7.1 先立判据：为什么打分表会误导

打分表把「**取决于用途的结论**」写成「**绝对结论**」。同一列在不同用途下权重会反过来：可解释性这一列，在受监管场景（评分卡、保险定价）是硬约束，因为「每个特征值多少钱」要能写进决策文件并逐条审阅；在只进报表的预测里它几乎不影响选型。更关键的是，「精度」这一列在本主题里特别容易误导——**离线精度只在误差沿步长和区间内累积得可控时才有意义**：多步外推、成本非对称、需要干预决策，这三种用途下同一个「精度 5 分」的模型可能是完全错误的选型。

第二类误导是**维度之间不独立**。「精度」与「训练速度 / 推理速度 / 工程门槛」在本主题里是同一个资源的不同侧面：容量决定了能拟合多复杂的函数，也同时决定了训练成本、推理延迟与复现难度。把它们拆成四列各打一个分，读者会以为可以在不牺牲任何一条的情况下提高容量。

第三类误导是**打分把代价的形状删掉了**。这里每种方法的强项都是拿代价换的：GBDT 的内插拟合是拿「区间外输出为常数」换的，深度学习的表征学习是拿「参数量与调参面」换的，因果回归的因果性是拿「识别假设不可检验」换的，时序模型的周期刻画是拿「每个序列一套参数」换的。表里只剩收益，读者就会按收益选。

第四类误导是**被并列的维度可能不在同一个量纲上**。「训练速度」「推理速度」「工程门槛」这三列，一行里比的是 CPU 小时、另一行里比的是「团队有没有人能调好深度网络」——前者可以压测，后者是一个组织事实。把它们压到 1–5 再相加，得到的排序反映的是编表人的权重直觉，而不是你的约束。量纲不同的东西可以并列描述，但不能相加比较。

所以本章不给分，给判据：先问「这个预测值会被用来做什么动作」，再问「它的失效方式在你的场景里是报错还是静默」，最后才问「用哪个模型」。

**本章采用的 6 条判据**：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| 决策用途（能力边界） | 输出会被用成什么动作：报表、订货点、干预名单，还是长期规划？ | 损失的最优解位置由用途决定——MSE 的最优解是条件均值，成本非对称时均值不是最优决策点 |
| 假设空间契合度 | 模型的假设空间（线性可加 / 分段常数 / 表征学习）匹配我的数据形态吗？ | 分段常数模型无法外推、线性模型无法表达未写入的交叉，这不是精度问题而是结构问题 |
| 成本结构 | 成本随样本数、特征数、序列数还是请求量增长？ | 增长方向决定规模上限：随序列数增长的方案，遇到千级 SKU 时维护面会先崩 |
| 运维复杂度 | 需要几个人维护特征管线、重训调度与在线特征服务？ | 回归的线上成本主要在特征管线与监控，不在训练代码 |
| 解释与合规锁定 | 结论要能逐条审阅吗？换模型后归因方式怎么变？ | 线性模型的解释力依赖特征被显式构造；换到树或网络后归因方式整体改变，历史结论不可比 |
| 失效可见性 | 外推失效、特征漂移、LLM 侧升级时，是报错还是静默？ | 本主题的多数失效是静默的：预测整体偏移而输入监控完全正常，只能靠预测分布监控发现 |

### 7.2 候选方案全景

| 方案 | 定位 | 核心机制（一句话） | 假设空间与区间外行为 | 典型使用者 | 许可 / 商业模式 | 实现形态 |
| --- | --- | --- | --- | --- | --- | --- |
| 线性家族（OLS / Ridge / Lasso / ElasticNet） | 可审阅的基线 | 预测是特征的线性组合，系数可逐条拆分 | 线性可加；区间外沿固定斜率无限外延 | 评分卡、保险定价、政策结论团队 | 宽松开源，无授权费；锁定在特征口径而非厂商 | scikit-learn / statsmodels，可按官方文档核验 |
| GBDT（XGBoost / LightGBM / CatBoost） | 表格数据的默认主力 | 加性树的序列，每棵树拟合上一轮的梯度 | 分段常数；区间外落到最后一个叶子，输出近似常数 | 销量、评分、时长预估的主流团队 | 宽松开源，可自托管，无供应商锁定 | 三个主流开源实现 |
| 深度学习特化（MLP / Wide & Deep / DeepFM） | 高维与强非线性 | 表征层从原始输入自学交叉与相似度 | 表征学习；区间外依赖训练分布，通常随远离训练域而退化 | 有 GPU 与调参能力的大厂推荐 / 广告团队 | 训练框架宽松开源；成本在算力与人力，不在许可 | 自研 + 训练框架 |
| 多任务结构（MMoE / PLE） | 多目标共享底层 | 共享底层 + 任务专属上层 | 表征学习；区间外行为与深度学习同源 | 推荐、广告、多目标增长团队 | 结构与论文公开，实现自研，无授权费 | 自研结构 |
| 时序专用（ARIMA / Prophet） | 显式建模时间分量 | 时间分量显式成型：自回归项（滞后值 + 滞后残差）或趋势 + 季节 + 节假日分量相加 | 时间被参数化；趋势项可外推，结构性断点后被拉回旧水平 | 业务基线预测、零售 / 供应链分析岗 | 宽松开源，无授权费；锁定在日历表等自建资产上 | 开源库 |
| 时序 Transformer / 基础模型（PatchTST / Chronos / TimeGPT / Lag-Llama） | 长序列与跨域零样本 | 在大规模多序列语料上预训练，再做零样本或微调 | 全局预训练；区间外泛化优于单序列模型，但仍受业务日历与促销规则限制 | 时序中台与平台型团队 | 开源权重与商业 API 并存，两者许可与计费模式不同 | 开源权重 / 商业 API |
| 贝叶斯回归（Bayesian Ridge / 高斯过程） | 输出分布而非点 | 参数有先验，预测区间由后验积分得到 | 输出分布；区间外随先验收缩，先验错时收缩方向也错 | 小样本、风险敏感场景（精算、临床、实验分析） | 宽松开源，无授权费 | PyMC / Stan / GPyTorch，可按官方文档核验 |
| 分位数回归 / Conformal Prediction | 输出尾部位置 | 改损失函数训练第 τ 分位，或做分布无关的区间覆盖 | 不改变假设空间，只换损失；区间外覆盖率由校准集决定 | 库存备货、风险预警团队 | 开源实现为主，无授权费 | LightGBM / XGBoost 的分位数目标 |
| 因果回归（Causal Forest / DML / T-Learner） | 估增量而非关联 | 把处理作为独立变量，对混淆结构显式建模 | 结论由识别假设决定，不由拟合优度决定；区间外不可评 | 营销、补贴、政策评估团队 | 开源因果库 + 自研；锁定在方法论能力而非许可 | 开源因果库 + 自研 |
| 物理信息回归（PINN） | 数据稀缺但有方程 | 微分方程残差作为损失的一部分 | 物理方程约束下的函数类；区间外受方程约束 | 工程仿真、科学计算团队 | 开源 + 自研，具体条款以官方仓库为准 | DeepXDE 等，可按官方文档核验 |
| LLM 增强 | 文本变数值特征 | LLM 离线批处理产出向量或分数，再喂给回归器 | 表征学习（外置）；区间外行为随 LLM 版本变化 | 评论、商品描述、工单类场景团队 | 商业 API 按量计费，或自托管开源权重；锁定在模型版本 | 两段管线 |

「许可 / 商业模式」一列要读的是**锁定形态**，不是价格：宽松开源的锁定在技能与运维（可以换实现，但换不走你已经写下的特征口径与调参经验），商业 API 的锁定在配额、计费与版本节奏（供应商升级一次，你的特征分布跟着变一次），「开源权重 + 商业 API 并存」的那几族则要逐项确认权重许可能否商用。具体条款请以各项目官方仓库的 LICENSE 与官方文档当前版本为准。

读这张表的方式是**从「假设空间与区间外行为」这一列往右看**：先确认这个方案的假设空间能不能表达你要的关系（这是结构问题，不是调参能救的），再看它的区间外行为是否可接受，然后看谁在用它、许可与锁定是什么形状，最后才看实现形态。反过来读（先看实现形态）会得到一份「哪些库我熟」的清单，却答不出「为什么它在我这个用途上是错的」。

这张表里的候选其实分**五族**：**结构化拟合族**（线性家族、GBDT）——差别只在假设空间是线性可加还是分段常数；**表征学习族**（深度学习、多任务结构、LLM 增强）——共同点是把「造特征」也交给模型，代价是参数量与版本耦合；**分布输出族**（贝叶斯、分位数 / Conformal）——共同点是输出不是一个点，代价是评估口径与模型数同时增加；**识别族**（因果回归、PINN）——共同点是结论不来自拟合优度，而来自一个外部的识别假设（干预设计或物理方程），代价是它无法用精度验收；**时序族**（时序专用、时序 Transformer / 基础模型）——共同点是「时间」在模型里被显式表达（自回归项、可加分量，或从大量序列上预训练出来的形状），而不是像通用回归那样把滞后列当成一列普通特征。

分族能省掉一半比较，但对**时序族**要打个折。本主题里「时间怎么进来」是一条独立的机制维度（见 7.3.4），而时序族的两个候选与结构化拟合族里的「通用回归 + 滞后特征」做的是同一件事，区别只在于时间结构放在模型外面还是里面——所以遇到时间结构时，正确的顺序不是「在线性 / GBDT / ARIMA / 基础模型里挑一个」，而是先按 7.3.4 定下时间结构的进法，再回到这张表选实现。7.5 的节点② 单列时间结构分支、7.6 把「强时序依赖 + 多步外推」与「长期规划」两行分开，都是按这个顺序排的；反过来先挑库再问时间结构，选出来的差异多半只是实现形态的差异，与你的用途无关。

### 7.3 机制差异：为什么它们表现不同（核心节）

四个机制维度之间是有顺序的：7.3.1 决定「模型能表达什么」，7.3.2 决定「什么叫做得对」，7.3.4 决定「时间怎么进来」，7.3.3 决定「结论能不能当因果用」。前两个维度决定模型在你的用途上是否**可能**正确，后两个决定它在你的数据形态上是否**可行**。顺序反过来（先挑模型再问用途）就是本章要避免的那类选型错误。

#### 7.3.1 假设空间：线性可加、分段常数、表征学习

**机制是什么**：模型能表达的函数集合。

```text
线性可加      ŷ = w₀ + Σⱼ wⱼ·xⱼ
              → 非线性与交互必须由人写进特征列；区间外是固定斜率的直线

分段常数      ŷ = Σₘ f_m(x) ,  f_m 是第 m 棵树的叶值
              → 阈值由训练数据学到；区间外全部落进同一个叶子，输出近似常数

表征学习      ŷ = head( enc(x) )
              → enc 从原始输入自学交叉与相似度；区间外行为依赖训练分布
────────────────────────────────────────────────
关键差别：三者对「训练数据之外会发生什么」给出的答案完全不同
```

| 假设空间 | 函数形态 | 输入侧要求 | 区间外行为 |
| --- | --- | --- | --- |
| 线性可加 | ŷ = w₀ + Σ wⱼ·xⱼ | 非线性与交互必须由人显式写进特征 | 沿固定斜率无限外延 |
| 分段常数（树 / GBDT） | ŷ = Σ 树的叶值 | 数值与低基数类别可直接喂入，缺失值自带默认方向 | 落到最后一个分裂点之外的叶子，输出近似常数 |
| 表征学习（深度学习） | 表征层 + 回归头 | 原始文本 / ID / 图像直接输入 | 依赖训练分布，通常随远离训练域而退化 |

**因果句**：因为 GBDT 的分裂阈值是从训练数据里学到的常数，所以它的输出在训练标签取值域之外就是常数——需要外推的场景下，它必然把预测钉在历史极值附近；**代价**是它对内插的强拟合能力换不来一点外推能力，而这个代价在「渠道迁移、价格结构性调整」这类换挡期才暴露。因为线性模型的预测是特征的线性组合，所以单样本归因可以按 Σ wⱼ·xⱼ 逐项拆分、系数方向直接对应业务动作；**代价**是所有交互与非线性都得由人预先构造，特征数量随假设组合数增长，且新增列会改变已有系数的含义。因为表征层直接从原始输入学习交叉与相似度，所以不需要人工穷举特征组合；**代价**是把「调参—训练—部署」的复杂度整体抬高一个量级，且参数量远超有效信息量时会优先拟合训练集里的偶然相关性。

**公开证据**：【公开】XGBoost（Chen & Guestrin，KDD 2016）、LightGBM（Microsoft，2017）、CatBoost（Yandex，2018）；【公开】Ridge（Hoerl & Kennard，1970）与 Lasso（Tibshirani，1996）的原始工作；【公开】Uber 用深度学习做到达时间预估（DeepETA，Uber Engineering Blog，2022）；【公开】MMoE（Ma 等，KDD 2018）与 PLE（Tang 等，RecSys 2020）。具体实现的当前能力以各自官方文档为准。

**失效条件**：假设空间的优势在「有效信息量 vs 模型容量」失衡时反转。线性模型在特征接近共线时（同时存在订单数、订单金额、客单价），系数方差随条件数放大，「可逐条解释」反转成「系数不可信」——预测可能仍然稳定，但归因与政策建议已经失效；树与网络则在样本量远小于容量时把拟合能力用来记噪声。

#### 7.3.2 损失函数与最优解的位置：均值、分位、后验

**机制是什么**：训练目标决定了模型收敛到哪个统计量。

```text
均方损失（MSE）      → 最优解是条件均值 E[y|x]
绝对损失（MAE）      → 最优解是条件中位数
分位损失 L_τ         → 最优解是条件第 τ 分位
   L_τ = Σ_{y≥ŷ} τ(y−ŷ) + Σ_{y<ŷ} (1−τ)(ŷ−y)      （主文件 §2.2）
贝叶斯后验           → 输出整个分布，区间由后验积分得到
Conformal            → 不假设分布，用留出集校准区间的覆盖率
────────────────────────────────────────────────
关键：损失函数决定了「最优」这个词的含义
```

目标分位不是「选一个保守的数字」，而是从成本比推出来的：设单位缺货成本为 $C_u$、单位积压成本为 $C_o$，报童模型意义下的最优分位 τ* = $C_u$ / ($C_u$ + $C_o$)【推算，链：分位数 τ 处的边际成本相等时库存期望成本最小】。缺货成本是积压成本的 4 倍时，τ* = 0.8 ——这才是「取 0.8 分位」的依据，而不是「80% 听起来比较稳」。

**因果句**：因为 MSE 的最优解是条件均值，所以它只在成本对称（高估与低估的代价相同）时才是最优决策点；**代价**是成本非对称时（缺货 ≠ 积压、坏账 ≠ 少赚利息），继续用均值模型不是「精度差一点」，而是系统性地把决策点锚在错误位置——最优订货点是某个高分位，不是均值。因为分位数由损失函数直接定义，所以它可以按业务成本比推出目标分位；**代价**是为每个目标分位训练一个模型（或改造成多目标），模型数与评估口径同时翻倍，且多个独立单分位模型之间没有单调性约束，会出现 90 分位低于 80 分位的分位交叉。因为贝叶斯路线把参数的不确定性一起建模，所以小样本下也能给出带先验的区间；**代价**是计算成本高一个量级（MCMC 采样或变分推断），且先验选错时小样本结论会带着看不见的偏。

**公开证据**：【公开】LightGBM 与 XGBoost 都提供分位数目标函数，可按其官方文档的 objective 可选值核验；【公开】PyMC、Stan、GPyTorch 是活跃的贝叶斯实现，可按官方文档核验当前能力。库存备货取高分位、风险预警取尾部是通用做法【经验】，具体分位取值应由缺货成本与积压成本的比值推出，而不是照搬。

**失效条件**：当不同分位由互相独立的单分位模型预测时，「尾部可控」会反转成「分位交叉」——下游按这些分位做库存或风险决策时，会得到互相矛盾的行动建议。失效的根源是各模型独立训练、彼此没有单调性约束，这个缺陷不会随样本量增大而消失。

#### 7.3.3 因果性的来源：拟合、干预与识别假设

**机制是什么**：结论的因果性从哪里来——从数据的拟合优度，还是从一个外部的识别设计。

| 路线 | 因果性的来源 | 能否用精度验收 | 前提 |
| --- | --- | --- | --- |
| 观测数据回归 | 无（估的是关联） | 能，但验收的是预测而非效应 | 无——所以不能当因果用 |
| 随机实验 | 随机分配本身 | 否，用效应量与置信区间验收 | 处理可随机分配 |
| Meta-Learner / 因果森林 | 可忽略性（无未观测混淆）+ 重叠 | 否，靠模拟数据与安慰剂检验 | 有处理变量与干预记录，倾向得分不接近 0/1 |
| DML | 残差正交化 + 可忽略性 | 否 | 同上，且要求两阶段估计的误差可控 |
| PINN | 物理方程（守恒律 / 微分算子） | 部分——残差可作为诊断量 | 方程可写、配点可采样 |

**因果句**：因为因果效应估计的识别来自设计与假设而不是拟合优度，所以因果模型无法用「精度」验收——精度高只说明预测像，不说明效应真；**代价**是验收标准从单一指标变成「论证 + 安慰剂检验 + 重叠检查」这一整套不可自动化的流程。因为 Meta-Learner 用倾向得分或残差正交化把混淆从处理效应里剥开，所以它能回答「对谁有效」这类增量问题；**代价**是数据要求高（要有干预记录）、方法复杂度高（自研因果代码）、结论不可从数据内部自证——假设不成立时，数据再多也不会暴露它。

**公开证据**：【公开】Causal Forest 与异质处理效应估计（Wager & Athey，JASA 2018）；【公开】Double Machine Learning（Chernozhukov 等，Econometrics Journal 2018）；【公开】PINN（Raissi、Perdikaris、Karniadakis，Journal of Computational Physics，2019），DeepXDE 提供实现，可按官方文档核验。增长与营销团队普遍用 T-Learner / X-Learner / Causal Forest 做增量建模【经验】，通常与随机实验并行：先做实验定因果方向，再用因果模型做人群细分。

因果结论没有单一指标可验收，实际的验收由三件事组成：**重叠检查**（倾向得分接近 0/1 的样本占总量的比例——比例越高，结论越依赖模型形式）、**安慰剂检验**（用一个不该有影响的伪处理跑一遍，看是否也"显著"）、**模拟数据校准**（在已知真效应的合成数据上验证估计器是否无偏）。这三件事都不产出「准确率」，但没有它们，因果结论与拟合优度之间就没有任何可检验的联系。

**失效条件**：当处理组与对照组的协变量分布几乎不重叠时（倾向得分接近 0 或 1 的样本没有可比的对照），「异质效应可估」会反转成「区间内插值、区间外外推」——τ̂(x) 在那部分人群上完全由模型形式决定，不由数据决定。另一条失效路径是把因果模型当预测模型用：它优化的是效应的估计精度，不是预测误差，两者对超参的选择往往相反。

#### 7.3.4 时间结构怎么进模型：滞后特征、显式分量、全局预训练

**机制是什么**：序列自身的历史以什么形式进入模型。

| 路线 | 历史进模型的方式 | 单序列的维护成本 | 多步外推能力 |
| --- | --- | --- | --- |
| 通用回归 + 滞后特征 | 手工构造滞后 / 滚动窗口列 | 低（一个全局模型） | 递归外推，误差沿步长累积 |
| 加法模型（Prophet 风格） | 趋势 + 季节 + 节假日分量显式相加 | 中（日历表要维护） | 趋势项可外推 |
| 自回归 / 状态空间（ARIMA 风格） | 滞后值 + 滞后残差 | 高（每序列一套阶数选择与平稳性检验） | 递归外推，结构性断点时被拉回旧水平 |
| 时序 Transformer / 基础模型 | 全局模型，在大量序列上预训练 | 低到中（多一个模型依赖） | 直接多步预测，长序列更好 |

```text
按时间前向切分（唯一正确的方式）：
  ├── 训练窗口 ──┤── 验证窗口 ──┤── 测试窗口 ──►  时间
  特征只能看见自己所在窗口及之前的数据

随机 K-Fold（错误但常见）：
  每个窗口的样本都可能出现在训练集里
  → 滚动均值、近 7 天计数这类特征的值由未来算出
  → 离线指标很好，上线后断崖下跌（不会报错）
```

**因果句**：因为加法模型把趋势与季节拆成可加的分量，所以分析师能逐项手调、也能对趋势项做外推；**代价**是节假日这类日历效应需要人工维护日历表，日历表过期即静默出错（预测仍然出数，只是系统性偏离）。因为自回归把上一期观测显式作为输入，所以趋势与周期被参数化而不是被当成噪声；**代价**是结构性断点时它会把最近的极端值当作未来会重复的信号，趋势项需要若干周期才能跟上。因为时序基础模型在大规模多序列语料上预训练，所以零样本就能给出可用基线；**代价**是它对你特有的促销节奏与断供事件没有先验，且引入第二套依赖（权重版本、推理服务），与你自建的节假日表之间还要决定以谁为准。

**公开证据**：【公开】Prophet（Taylor & Letham，The American Statistician，2018）；【公开】DeepAR 用自回归 RNN 做多序列预测（Salinas 等，International Journal of Forecasting，2020）；【公开】PatchTST（ICLR 2023）；【公开】Chronos（Amazon，2024）、TimeGPT（Nixtla，2024）与开源的 Lag-Llama（其预印本为 2023 年，2024 年前后有更新版本——具体年份以论文页面与官方仓库为准，这一条不写死）。零售与供应链场景通常先跑加法模型做基线，再判断是否值得上更复杂的模型【经验】。

**失效条件**：三条路径的失效点不同但都指向同一件事。通用回归 + 滞后特征在切分方式错误时失效得最隐蔽——随机 K-Fold 会把未来样本放进训练集，滚动均值之类的特征值于是由未来算出，离线指标很好看，上线才崩。自回归在结构性断点（政策变化、渠道迁移）时被拉回旧水平。基础模型在业务特有的日历与促销规则上不如一张维护良好的日历表。**共同点是：三者都不会报错**。

### 7.4 成本结构对比（不是价格表，是成本函数）

```
总成本 ≈ 训练成本（样本数 × 特征数 × 迭代轮数 × 单步成本）
       + 推理成本（QPS × 单请求成本 × 副本数）
       + 特征与数据管线（特征数 × 变更频率 × 人时）
       + 序列维护（需独立建模的序列数 × 单序列月度工时）   ← 时序专用路线的隐性主导项
       + 失效成本（外推偏离 / 分布漂移发生时的业务损失）
```

| 方案 | 主导项 | 隐性成本（最容易漏的一项） |
| --- | --- | --- |
| 线性家族 | 特征工程人时 | 共线时归因失效，需要额外的特征治理 |
| GBDT | 推理成本（随树数 × 深度增长） | 跨机器一致性：同一份模型文件 + 同一套特征计算代码，任一不符即静默改变预测 |
| 深度学习 | 训练 GPU + 调参人时 | 复现成本：换随机种子或数据顺序即可让效果落在业务可感知范围内【经验】 |
| 多任务结构（MMoE / PLE） | 结构设计与任务权重平衡的调参人时 | 任务间负迁移：共享底层让一个任务的标签分布变化传递到其余任务的预测，排障时无法把责任定位到单个任务 |
| 时序专用 | 序列维护人时 | 日历表 / 节假日表的过期，静默出错 |
| 时序 Transformer / 基础模型 | 长序列推理算力（不随需独立建模的序列数增长，与「时序专用」相反） | 第二套依赖：预训练权重的版本与推理服务要独立于现有链路维护，且它与自建日历表冲突时以谁为准要先定 |
| 贝叶斯 / 分位数 | 计算成本与模型数 | 评估口径增加（区间覆盖率、分位损失），且要防分位交叉 |
| 因果回归 | 数据准备与论证人时 | 结论无法用精度验收，需要一套独立的验证流程（安慰剂、重叠检查） |
| LLM 增强 | 离线批处理成本 | 两段管线的版本耦合：LLM 侧升级一次，特征分布整体漂移一次 |
| PINN | 训练成本（每个配点都要自动微分） | 数据项与物理项权重 λ 的调参，没有理论最优解 |

**推理成本的量级（含推导）**：【推算】GBDT 的单样本推理约等于「树数 × 平均深度」次分裂比较——1000 棵树、每样本平均 6 层，就是每样本约 6000 次比较；1 万 QPS 换算成每秒 6 × 10⁷ 次比较。这个量级能不能被单核扛住，取决于你机器上每样本的实际延迟，请用你自己的压测数据乘一下再定副本数——别人的数字在这里不可移植，因为它同时取决于树数、深度、特征数量与缓存局部性。

**多步外推误差的量级（含推导）**：【推算】在误差不衰减（随机游走式累积）的假设下，H 步递归外推的误差标准差 ≈ 单步误差 × √H（链：每步独立误差的方差相加 ⇒ 方差 ∝ H ⇒ 标准差 ∝ √H）。H = 30 时 √30 ≈ 5.5，即 30 天后的误差约为单步误差的 5.5 倍。注意这个推导的前提是「误差不衰减」——若模型是一阶自回归且系数明显小于 1，误差会被逐级衰减，此时 √H 不成立。这就是为什么多步评估必须给误差曲线，而不是一个数。

**序列维护成本的量级（含推导）**：【推算】若每个需要独立建模的序列，每月的建模、检验与监控合计约 0.5 人时（这个假设要用你团队的实际工时校准），1000 个序列就是 500 人时/月，按月 160 人时折算约合 3 个人力。这正是「时序专用」路线与「一个全局模型 + 滞后特征」路线的分水岭成本项：前者随序列数线性增长，后者基本不随序列数增长，代价是全局模型对每个序列的刻画更粗。

**哪一项是隐性成本**：本主题的成本表里，最容易被漏掉的是**「跨机器一致性」与「特征口径漂移」这两项**。它们的特点是既不在训练账单里，也不在推理账单里，而是以「预测悄悄变了」的形式出现：GBDT 的模型文件与特征计算代码只要有一侧不同步，同一份输入就会得到不同的输出；LLM 增强路线里文本侧升级一次，特征分布整体漂移一次，而输入监控（长度、非空率）完全正常。这两项的成本不在预算表上，而在事故账单上——所以防御方式是监控**预测分布本身**（均值、分位数、远超阈值的样本比例），而不是监控输入。

### 7.5 决策树（每个分支都要有阈值依据）

```
[回归任务]
   │
   ├─ ① 输出会被用来做什么动作？
   │     ├─ 只进报表 / 看趋势 ────────────────────────► ②
   │     ├─ 触发一个成本非对称的动作（订货 / 备货 / 授信额度）
   │     │        → 分位数回归或分布输出（决策点在分位，不在均值）
   │     ├─ 决定给谁干预（发券 / 触达 / 补贴）
   │     │        → 必须同时有处理变量与干预记录；
   │     │          没有 → 只能做预测，不能做增量决策，退回上一分支
   │     └─ 决定长期规划（多步外推）→ 时序专用结构或显式趋势项
   │
   ├─ ② 目标有没有时间结构（自相关 / 周期 / 节假日）？
   │     ├─ 有 → 按时间前向切分；加显式滞后特征或换时序专用结构
   │     └─ 无 → 横截面路径，继续
   │
   ├─ ③ 样本量 ÷ 特征数落在哪一档？
   │     ├─ 特征数 ≥ 样本量（p ≥ n）→ 必须正则化：Ridge / Lasso / ElasticNet
   │     ├─ 每特征样本数在 10 ~ 10³ 量级，特征是数值与低基数类别 → GBDT
   │     └─ 每特征样本数 ≥ 10³，且特征是文本 / 图像 / 高基数 ID → 深度学习特化
   │
   ├─ ④ 单请求响应预算（端到端 P99）落在哪一档？→ 决定模型侧还剩多少预算
   │     ├─ ≤ 0.1 s【公开】 → 模型侧只剩十毫秒级【推算】
   │     │        → 轻模型（线性 / FM / 双塔），或把重模型离线预计算好再取
   │     ├─ 0.1 s ~ 1 s【公开】 → 模型侧可占十毫秒 ~ 百毫秒
   │     │        → GBDT / 小型深度模型；放不放得下按 7.4 的换算自测
   │     └─ ≥ 1 s【公开】 → 可异步 / 近线 → 深度学习特化，或改为离线批量打分
   │
   ├─ ⑤ 结论要不要能逐条审阅（监管 / 定价 / 政策）？
   │     ├─ 要 → 分箱 + 线性 / 逻辑回归；GBDT 只能用 SHAP 类解释层做补充
   │     └─ 不要 → 按 ③ 选
   │
   └─ ⑥ 有没有可写成微分方程或守恒律的先验，且观测稀疏？
         ├─ 有 → PINN
         └─ 无 → 按上面分支选
```

**阈值依据**：

- **节点 ①（输出用途）**：依据是损失函数的最优解位置——MSE 的最优解是条件均值，分位损失的最优解是条件分位（见 7.3.2）。所以「用途」不是一个偏好问题，而是「最优决策点在哪」的问题；同时因果用途还额外要求干预数据存在，这一条判错会让整条链路的方向错掉。
- **节点 ②（时间结构）**：依据是「只要存在自相关，随机切分就会把未来信息泄进训练集」——这是可检验的判据：把切分方式换成按时间前向，若指标断崖式下跌，说明之前一直靠泄露撑着（§3.5 的「时序泄露」反模式）。
- **节点 ③（样本量 ÷ 特征数）**：其中 **p ≥ n ⇒ 必须正则化** 是数学边界，不是经验——特征数达到样本量时 (XᵗX) 不可逆，OLS 无唯一解，只能靠 L1 / L2 惩罚定解。而「10 ~ 10³」这一档是量级启发式【经验】：真正的判据是「有效信息量 vs 模型容量」，不是某个具体样本数；把它写成档位是为了让你有个起检点，而不是当定理用。
- **节点 ④（响应预算）**：三个阈值都取自公开的响应时间界标，它们划的是**调用形态**，不是模型型号——交互响应研究把 0.1 s / 1.0 s / 10 s 列为三档响应时间界标（【公开】Nielsen，*Usability Engineering*，1993），其中 0.1 s 是「感觉即时」的上界、1.0 s 是「思路不被打断」的上界。这三个数约束的是端到端响应，而树上问的是「模型侧还剩多少」，两者之间的换算是【推算】且必须由你自己做：在 ≤ 0.1 s 这一档，扣掉特征回捞、网络往返与业务逻辑（同一调用链里通常占大头）之后，留给模型的部分落在个位数到十毫秒量级，所以这一档只能放轻模型，或把重模型离线预计算好再取；在 0.1 s ~ 1 s 这一档，模型侧可以占到十毫秒到百毫秒，GBDT 与小型深度模型通常落在这里，放不放得下按 7.4 的成本函数自测——单样本成本 ≈ 树数 × 深度 次比较（1000 棵树、每样本平均 6 层 ≈ 6 × 10³ 次比较），乘上你单机每秒能完成的比较次数才是容量上限；超过 1 s 用户会明显感到等待，与其在同步链路里塞重模型，不如把预测挪到离线批量或近线预计算。三档之间没有空档，换档点是你的端到端预算减去调用链开销后的余量——别人机器上的「十毫秒」在你的调用链里没有意义。
- **节点 ⑤（是否需要逐条审阅）**：依据是「线性模型只在你显式写入特征时才有正确的解释」（§3.2.1 的失效点）——特征共线时系数方差随条件数放大，且这个方差不随样本量增大而消失，所以「用线性回归就等于可解释」是不成立的；反过来，树模型的分段常数结构给不出「每单位特征值多少钱」，只能用 SHAP 类归因做补充，而补充归因与原生系数的可审阅性不在一个等级。
- **节点 ⑥（物理先验）**：依据是「方程能否被写出来」——有可写出的微分算子或守恒律，就能把方程残差作为损失的一部分（见 7.3.3），此时泛化不再只依赖观测点密度；没有可写出的方程，PINN 就退化成普通网络加了一组无意义的正则项。

**顺序约束**：节点 ① 到 ⑥ 不是一张并列清单，而是一条有先后的判定链。用途定错时（节点 ①），后面选出的模型再精确也只是在一个错的决策点上精确；时间切分错了（节点 ②），离线指标越高越危险，因为它高出来的部分正是泄露。顺序反了，投入越多、错得越像真的——这与本主题常见的失败形态一致：**离线报告最漂亮的那一版，往往是最不可上线的那一版**。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因 |
| --- | --- | --- | --- |
| 低维 + 线性关系 + 要可审阅 | 线性家族（OLS / Ridge / Lasso） | GBDT + SHAP | 树的分段常数归因给不出「每单位特征值多少钱」 |
| 表格数据 + 中等规模 | GBDT | 线性 + 人工交叉特征 | 用 DL：无 GPU 依赖的同等精度拿不到，调参面反而更大 |
| 高维 + 大数据 + 强非线性 | 深度学习特化 | GBDT + Embedding | 用线性：人工交叉写不完 |
| 强时序依赖 + 多步外推 | 时序专用 / 时序基础模型 | 通用回归 + 滞后特征 | 用普通回归：样本假设里没有「时间」 |
| 按分位或区间决策 | 分位数回归 / 贝叶斯 / Conformal | 点估计 + 人工安全系数 | 用均值模型：最优决策点不在均值处 |
| 异质处理效应 / 增量决策 | 因果回归（Causal Forest / Meta-Learner / DML） | 实验 + 分组看指标 | 用普通回归：系数估的是关联，混淆会污染它 |
| 多任务联合 | MMoE / PLE | 每任务一套独立模型 | 任务间共享信号被浪费，维护面按任务数增长 |
| 长期规划（外部环境会换挡） | 显式趋势项 / 结构项 | GBDT | 树在训练区间外是常数，换挡期系统性偏离 |
| 文本是信息主源 | LLM 增强 + GBDT | 人工标注关键词特征 | 纯 GBDT：语义无法人工穷举成特征列 |
| 数据极少 | Ridge / 贝叶斯回归 | GBDT（强正则） | 容量远超有效信息量 |
| 物理约束场景 | PINN | 纯数据驱动 + 后处理约束 | 纯数据驱动会把物理规律当噪声去学 |
| 高基数类别特征多 | CatBoost | 独热编码 + 其他 GBDT | 独热后维度爆炸，训练时间与内存超预算 |
| 标签是「含 0 的金额」（大量未发生） | 两段式：先判是否发生，再预测金额 | 单模型直接回归 | 一个模型同时承担「是否」与「多少」，0 值样本会把两个问题搅在一起，MAPE 也会在 0 附近发散 |
| 自变量有强异方差 | WLS / GLS | OLS | 同方差假设不成立时标准误是错的，显著性判断不可用 |

这张矩阵与 §3.3 的模式选择决策表用的是同一组约束，但两表的分工不同：§3.3 按「约束组合 → 推荐模式」写，并把「为什么不选另一个」与「关键判据」各列一栏；本表把「首选」与「备选」拆成两列，用一列集中写「不选它的原因」，判据则由 7.1 与 7.5 承担，所以不再重复 §3.3 的判据列。**选型时最常见的错误不是选了一个差的方案，而是没有说清为什么不选另一个**，于是在评审时无法解释这个选择。

**6 种常见组合**（逐条给出职责边界与运维代价）：

1. **线性 + GBDT（残差学习）**：线性捕捉趋势与结构项，GBDT 拟合残差。职责边界是「能外推的部分归线性，其余归树」；运维代价是两个模型两套版本，排障时先判断误差出自哪一段——若把时间索引直接喂给树，两段会学同一个东西，外推时误差被叠加而不是被补偿。
2. **Prophet + LightGBM（趋势 + 残差）**：Prophet 分解趋势与季节，LightGBM 拟合残差。职责边界同上，只是结构项换成了可手调的加法分量；运维代价是日历表 / 节假日表要持续维护，过期即静默出错。
3. **因果 Forest + 业务决策**：Causal Forest 估计 CATE，按 CATE 分群做决策（营销、政策、风控）。职责边界是「因果模型决定对谁、预测模型决定何时」；运维代价是需同时维护干预数据链路与因果建模能力，且两者的人群口径必须对齐。
4. **贝叶斯 + GBDT（不确定性 + 精度）**：GBDT 预测均值，贝叶斯路线估计不确定性。职责边界是「均值给报表、区间给决策」；运维代价是两套评估口径（误差指标 + 区间覆盖率），且先验假设需要论证——先验选错时小样本结论会带着看不见的偏。
5. **LLM Embedding + LightGBM（语义 + 结构化）**：LLM 离线批处理产出 embedding，与结构化特征拼接后喂给 LightGBM。职责边界是「LLM 只负责把文本变成数，回归器负责把数变成预测」；运维代价是提示词与模型版本的版本耦合——LLM 侧升级一次，特征分布整体漂移一次，而输入监控（长度、非空率）完全正常。
6. **时序基础模型 + 微调**：Chronos / Lag-Llama 零样本给基线，再用业务数据微调。职责边界是「基础模型给通用形状、微调补业务日历」；运维代价是多了一套模型依赖（权重版本、推理服务），且它与自建日历表之间要先决定冲突时以谁为准。

### 7.7 选错的代价与迁移成本

下面三条反模式按「暴露得越晚、损失越大」排列：前两条在复盘阶段暴露，第三条要等到业务事故发生时才暴露。

**反模式：把外推当内插用。** 症状是只用内插验证集评估——验证集与训练集来自同一时间窗，从没测过区间外。后果是换挡期（渠道迁移、价格结构性调整）模型给出的预测落在历史区间里不动，而模型监控看的输入特征全部正常，没有任何告警。正确做法是给预测值加上下限截断并保留一条基线规则，让失效时表现为「预测保守」而不是「业务事故」；同时把区间外验证做成常规验证项。

**反模式：把观测数据回归的系数当因果效应用。** 症状是结论写着「投放越多销量越高」，而投放本身是按历史销量分配的（反向选择）。后果是按系数把预算加到「历史销量高」的人群，增量接近零，而报表上一切正常。正确做法是先问「这个结论有没有来自随机实验、断点或工具变量的证据」；只有观测数据时，结论只能用于描述，不能用于干预。

**反模式：分位数各自为政。** 症状是同时上线 0.5 / 0.8 / 0.9 三个独立训练的分位模型，出现 90 分位预测值低于 80 分位的情况。后果是下游按这些分位做备货或授信时收到互相矛盾的行动建议，而每个模型的误差指标都合格。正确做法是用同一个多目标模型训练（或加单调性约束），并把「分位交叉率」作为上线前的验收项。

| 迁移 | 要动的数据 / 链路 | 要改的口径 | 要重建的组件 | 团队要补的能力 | 量级 |
| --- | --- | --- | --- | --- | --- |
| 线性 → GBDT | 特征侧从「人工写交叉」改为「喂原始列 + 类别编码」 | 从系数归因改为 SHAP / 部分依赖 | 模型训练与版本管理、在线特征服务 | 调参与特征口径治理 | 中 |
| 单点 → 多步 / 时序 | 按时间切分并重建回测框架 | 单点误差 → 多步误差曲线 | 回测与监控链路 | 时序诊断（平稳性、季节性） | 中到大 |
| 点估计 → 分位 / 分布 | 训练目标与标签侧要保留分位口径 | MAE / RMSE → 区间覆盖率 + 分位损失 | 多目标或多模型训练 | 成本函数与分位的对齐 | 中 |
| 预测 → 因果 | 干预记录、对照单元池、倾向得分特征 | 从「预测准不准」改为「识别假设是否成立」 | 因果建模与检验流程（安慰剂、平行趋势、重叠检查） | 因果推断与实验设计 | 大（人时主导） |
| 加 LLM 增强 | 文本 → 向量的离线批处理链路 | 特征监控要加「分布漂移」项 | 提示词与模型版本管理 + 特征回填 | 两段管线的版本治理 | 中 |
| 加 PINN | 配点采样与微分算子实现 | 从单一误差改为「数据误差 + 物理残差」分量 | 训练成本预算与自动微分框架 | 数值方法与自动微分 | 大 |

表里「量级」的判据是**要动的组件数与人时，不是数据量**：凡是需要新增一套常驻流程（回测框架、因果检验流程、自动微分框架）的迁移都算大，因为它们要的是团队现在没有的方法论能力，而不只是工程工时。

迁移还有一条顺序上的建议：**先把口径与切分改对，再换模型**。多数「换了个更复杂的模型但效果没起来」的案例，根因在切分方式或特征口径，而不在模型容量——在错的验证框架下，更强的模型只会把泄露或口径错误放大得更明显。

### 7.8 小结

| 你的处境 | 建议 | 关键理由（机制层面） |
| --- | --- | --- |
| 结论要能逐条审阅，样本量有限 | 线性家族（含正则化） | 单样本归因可按线性项拆分；代价是特征必须人工构造 |
| 表格数据、要精度、不要 GPU | GBDT | 残差加性拟合任意关系；代价是区间外输出为常数 |
| 高维 ID / 文本、样本量足够 | 深度学习特化 | 表征层自学习交叉；代价是参数量与调参面同时上升 |
| 多步外推、有周期结构 | 时序专用 / 时序基础模型 | 时间分量被显式参数化；代价是序列数放大的维护面 |
| 决策按区间或分位 | 贝叶斯 / 分位数 / Conformal | 成本非对称时最优解不在均值处；代价是多模型与分位交叉风险 |
| 决策是干预而非预测 | 因果回归 / DML | 混淆被显式建模；代价是识别假设无法从数据内部自证 |
| 文本是信息主源 | LLM 增强 + GBDT | 语义被压缩成数值特征；代价是两段管线的版本耦合 |
| 信息少但方程已知 | PINN | 物理残差进入损失，泛化不再只依赖观测点密度；代价是无理论最优的权重与配点调参 |

这张表是 7.1 六条判据逐条落下来的结果：用途决定最优解的位置（判据一），假设空间决定能否外推（判据二），成本函数的增长方向决定能维护多少个序列或多少次请求（判据三），而剩下三条判据（运维、解释锁定、失效可见性）决定这套模型能不能安稳跑过一年——判据一选错的代价是「决策点锚错位置」，判据六选错的代价是「模型已经偏了而监控全绿」。

> 本节小结：本主题的对比中**唯一真正起决定作用的差异，是「预测值会被用来做什么动作」**——报表用于描述、分位用于订货、因果用于补贴、外推用于长期规划，这四种用途对同一份数据给出的正确模型完全不同，而离线精度只是这条约束下的一个验收项，不是选型的起点。
