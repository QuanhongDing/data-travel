### 8.2 §4.1 回归算法核心原理与选型

> 本主题考察「回归任务的基本功」：损失函数选择的业务含义、模型选型的工程权衡、时序预测的范式对决、信用评分中回归与概率的边界、不确定性估计的方法学，以及因果回归与相关回归的本质区分。面试官通常从损失函数问起，逐层下钻到业务场景里"用错方法的代价"。

---

#### §4.1.1 回归任务中 MSE、MAE、Huber Loss 是如何选择的？请结合业务场景说明各自适用性，并指出 MAPE 在实际项目中的常见陷阱。

**1. 考察点**

- 是否理解三类损失的**数学性质**与对应的**业务容错偏好**——MSE 二次罚导致对大误差敏感、MAE 一次罚对异常值鲁棒但在 0 点不可微、Huber 是两者的自适应混合。
- 能否从**业务目标反推损失**——例如"预测销量偏少会导致缺货（损失大）、偏多只会增加库存周转（损失小）"应当用非对称损失，而不是默认 MSE。
- 是否知道 MAPE 在 y 接近 0 时爆炸的真实工程陷阱，以及为什么 SMAPE、WMAPE 在销量预测中更可靠。
- 加分项：能给出 L1 / L2 / Huber 在工业场景的对照案例（如 Uber ETA 用 MAE+Huber 混合、风控 PD 评分用 Brier / Logistic Loss）。

**2. 参考答案框架**

**第一层：先区分三类损失的"梯度语义"。** MSE 的梯度正比于残差，残差越大、梯度越大，意味着模型会被少量大误差样本"拽过去"，适合**误差近似对称分布**且**大误差本身就是关键信号**的场景（典型如金融收益率、股票收益率——一个 5σ 事件必须被模型认真对待）。MAE 的梯度是常数，模型对所有残差赋予同等更新力度，不被异常值绑架，适合**长尾分布 + 异常值多为噪声**的业务（典型如销量预测中的爆品/冷门 SKU 混合）。Huber 在残差小于 δ 时用 MSE（光滑可微、便于收敛），大于 δ 时退化为 MAE（不放大异常值），是工业界最常用的"折中默认"。

**第二层：业务目标反推损失。** 损失函数是"业务容忍度"的数学翻译——

- **对称容忍**：预测偏高、偏低代价相同（如电价预测、股价预测）→ MSE 或 Huber。
- **非对称容忍**：预测偏低代价远大于偏高（如销量预测、库存备货、配送 ETA）→ 类 Pinball Loss 的分位数损失（α=0.7-0.9），主动让预测偏高以减少缺货。
- **相对误差优先**：业务关心"比例偏差"而非绝对偏差（如销量同比）→ WMAPE（加权 MAPE，把低销量 SKU 权重压低）、SMAPE（对称 MAPE，分子分母都带 y）。

**第三层：MAPE 的工程陷阱与替代。** MAPE = (1/N) Σ|y - ŷ|/|y|，y→0 时 MAPE→∞。**真实案例**：某零售平台按 SKU 粒度算 MAPE，冷门 SKU（y≈1）MAPE 动辄 500%，掩盖了爆品 SKU（y=10000）的真实偏差；模型优化方向被彻底带偏。**正解**：① 按销量分桶分别计算（爆品 SKU 单独算 MAPE）；② 用 WMAPE = Σ|err| / Σ|y|（分母带权重）；③ 用业务自定义指标如"备货满足率"（预测 ≥ 真实天数占比）。沃尔玛做需求预测时同时报 MAPE、SMAPE、Pinball Loss（取高位分位）、缺货率四组指标，正是为了让"业务损失"与"模型 loss"对齐（该实践本节无法给出可核验的出处，分位取值按【经验】档处理）。

**第四层：指标体系而非单一指标。** 工业界绝不只用单一指标评估回归：

- **绝对指标**：MAE、RMSE、R²（解释方差比，越接近 1 越好但 0~1 之外也有意义）。
- **相对指标**：SMAPE、WMAPE。
- **业务指标**：备货满足率、阈值命中率、配对准确率（序数一致性）。
- **分布指标**：分位数 loss 曲线（P10 / P50 / P90 分别报），揭示模型在不同分位的表现。
- **校准指标**：预测置信区间的覆盖率（90% 区间应覆盖 90% 真实值），对应 Conformal / Bayesian 回归。

阿里 GMV 预测、字节视频播放量预测、京东销量预测都报**至少三组指标**（MAE/MAPE + 业务指标 + 分位数 loss），这是工业标准而非个人偏好。

**第五层：Huber 的 δ 取值经验。** δ 通常设置为 y 残差标准差的 0.5~1.5 倍；可通过验证集网格搜索。Huber 在 Uber 的 DeepETA、米哈游充值预测、微众银行信用评分中都被作为默认起点。

**3. 常见陷阱**

- **默认 MSE 不解释。** 不少工程师写完模型用 MSE 训练，线上 MAE 也很低，但解释不出"为什么不是 MAE 训练"——这是背概念的表现。
- **MAPE 当万能指标。** 没意识到 y=0 附近的失效；没考虑加权；不看绝对值。
- **混淆 loss 与 metric。** 训练用 Huber、评估用 RMSE——这可以是正确选择，但要主动说出来；什么都不说的简历会显得分不清"我在优化什么"。
- **忽略业务非对称性。** 备货场景用 MSE 默认，模型给均值预测，业务缺货照样发生。
- **只报一个数字。** "RMSE=12.3" 不报分位数、不报业务指标、不报置信区间——这种答法在资深面试官面前立刻减分。

**4. 追问预测**

- **「业务关心"宁可多预测也别少预测"，损失函数怎么改？」** 答：用 Pinball Loss，α 设为 0.7~0.9（越偏向 1 越激进乐观）；或在 LightGBM / XGBoost 中设 `objective='quantile'`、alpha=0.9。阿里做双 11 备货预测时用到高位分位数，对应"宁可多备、容忍小概率补货"的口径（具体分位档位本书无法给出可核验出处，此处按【经验】档处理）。
- **「MAE 在 0 点不可微，训练时怎么办？」** 答：实际训练用 sub-gradient（残差>0 时梯度=+1，残差<0 时梯度=-1）；或者用 Huber 在 0 附近的光滑替代；或用 RMSProp / Adam 自适应学习率缓解。
- **「R² 为负值代表什么？是模型错了吗？」** 答：模型比"用均值预测"还差——通常出现在分布漂移、特征缺失、或数据极端不平衡时，需要检查输入分布而非模型本身。
- **「如果真实业务关心 ATE 而非预测误差，回归 loss 怎么设计？」** 答：需要在损失层做"反事实重加权"（IPW / DR 形式），让模型对处理组样本赋予正确权重——这是因果回归与普通回归损失层的本质差异。

**5. 参考资料**

- Huber P. J. (1964) "Robust Estimation of a Location Parameter"——Huber 损失函数的原始论文，是工业界折中 MSE/MAE 的理论起点。
- Royston P. & Altman D. G. "Regression using fractional polynomials of continuous covariates"——讨论连续型自变量的非整数幂多项式建模，是回归函数形式选择的一般参考（该文不涉及 WMAPE 等加权指标）。
- 阿里 PAI / 阿里妈妈公开技术博客——GMV / 销量预测中非对称损失（Pinball，α 取高位分位）的实战经验，对应"宁可多备不可少备"的备货目标（本节无法给出该博客的具体篇目与链接，α 的取值引用时请自行查证）。
- 沃尔玛技术博客与京东零售预测平台公开材料——需求预测中 MAPE / SMAPE / Pinball Loss / WMAPE 多指标并报的标准做法（本节无法给出该博客与材料的具体篇目、年份与链接，引用时请自行查证）。
- Uber Engineering 关于 DeepETA 的公开技术博客——Huber+MAE 混合作为 ETA 损失函数，理由是"ETA 偏短导致用户漏车、偏长导致司机空跑"的非对称偏好（本节无法给出该博客的具体篇目、年份与链接，引用时请自行查证）。
- **京东零售双 11 GMV 预测** —— 用高分位数回归给大促备货做"上限估计"，对应宁可过量备货也不缺货的业务目标（具体分位档位本节无法给出可核验出处，此处按【经验】档处理）。
- **美团配送时长预估** —— Huber Loss + 截断的双塔结构，对抗极端天气 / 突发路况导致的异常 ETA。
- **米哈游充值流水预测** —— 角色粒度 14 天充值金额预测用 Huber + Pinball 双损失，避免大 R 玩家充值异常把模型拽偏。
- **微众银行 PD 评分** —— 用 Brier Score / Logistic Loss 直接校准违约概率，而非用 MSE 拟合 0/1——这是把"回归"任务重新定义为"概率校准"的标准做法。
- **招行信用卡账单分期预测** —— 金额预测用 WMAPE + MAE 双指标，避免低账单金额客群遮蔽高金额客群的真实偏差。

#### §4.1.2 给定一个销量预测问题（10 万 SKU、日粒度、未来 30 天），如何在 OLS / Lasso / GBDT / 深度学习 / 时序 Transformer 之间做选型？请给出决策依据并说明不同数据规模下的最优解。

**1. 考察点**

- 是否理解**模型家族的归纳偏置（inductive bias）**——线性族假设线性、GBDT 擅长阶跃式非线性、深度学习擅长高维稀疏+连续交互、时序模型擅长时间依赖。
- 能否给出**基于数据规模与特征形态的决策表**，而不是直接说"用 GBDT 默认就行"。
- 是否知道**集成策略**——Prophet 拟合趋势 + LightGBM 拟合残差，比单模型精度高很多。
- 加分项：能说清"为什么深度学习在结构化数据上常常输给 GBDT"以及"什么时候例外"。

**2. 参考答案框架**

**第一层：先确定任务的归纳偏置需求。** 销量 = 趋势 × 季节性 × 节假日 × 促销 + 残差，这五项对模型有不同的依赖：

- **趋势**：线性 / 平滑线性，强可解释。Ridge / Lasso 即可。
- **季节性**：周/月/年周期。Prophet 的 Fourier 项 / 时序 Transformer 的位置编码更擅长。
- **节假日 + 营销活动**：离散触发。GBDT 的分裂天然擅长处理这类指示变量。
- **非线性交互**：年龄 × 品类 × 城市 → 销量。DeepFM、LightGBM 都能学到，但 GBDT 解释性更好。
- **多 SKU + 长尾分布**：需权衡——GBDT 可以独立建模每个 SKU，但 SKU 间共享信息需要深度学习或层级模型（hierarchical reconciliation）。

**第二层：四类模型的能力边界。**

- **OLS / Ridge / Lasso**：低维 + 线性 + 强可解释。优点是训练快、特征重要性清晰；缺点是无法捕捉非线性。**适用**：业务稳定、特征工程已做透、约束在 30 个以内。
- **GBDT（XGBoost / LightGBM / CatBoost）**：表格数据回归 SOTA。对缺失值 / 类别特征鲁棒，特征工程友好，能自动发现交互。**适用**：约 80% 的销量预测场景（经验判断，非统计口径）。阿里双 11 GMV、京东日清销量、字节视频 vv 预测都以 GBDT 为底座。
- **深度学习（MLP / DeepFM / TabNet / FT-Transformer）**：高维稀疏 + 强非线性 + 自动交叉学习。但表格数据上"调好后"往往只能追平 GBDT 而非显著超越。**适用**：① 特征空间 > 1 万维（如大量品类交叉）；② 时空特征 + 用户序列特征的混合；③ 多任务共享底层。
- **时序 Transformer（PatchTST / iTransformer / TimesNet / Chronos）**：长时间序列 + 跨 SKU 迁移学习。**适用**：数据量足以训练大规模 Transformer / 想用基础模型做零样本预测；销量预测中**通常作为"残差层"**叠加在 GBDT 之上，而非端到端。

**第三层：基于数据规模的选型梯度。**

| 数据规模 / 特征量 | 推荐 | 理由 |
| --- | --- | --- |
| < 1 万样本 / 10 维特征 | Ridge / Lasso | 简单优先，免过拟合 |
| 1 万 ~ 100 万样本 / 50 维特征 | LightGBM | 工业默认 |
| 100 万~ 1 亿样本 / 200 维特征 | GBDT + 时序特征 + 集成 | 时序 + 非时序双信号 |
| > 1 亿样本 / 高维稀疏 | 深度学习 + GBDT 集成 | 容量足够，捕捉深层模式 |
| 跨 SKU 迁移 / 零样本 | Chronos / TimeGPT | 大模型预训练红利 |
| 多任务（多区域多品类） | 多任务 GBDT / 层级模型 | 共享信息 |

**第四层：集成策略主导工业。** 真实销量预测几乎没有单模型：

- **Prophet + LightGBM（趋势 + 残差）**：Prophet 拟合趋势 + 季节性 + 节假日，LightGBM 拟合残差（用促销、价格、竞品等非时序特征）。这是阿里 / 美团 / 京东最常用的"分解 + 残差学习"范式。
- **GBDT + 时序 Transformer**：GBDT 拟合主体非线性，时序模型拟合长序列依赖（30 天 + 跨 SKU）。
- **多模型加权**：训练 Prophet / ARIMA / LightGBM / Chronos 四个模型，用验证集 MAE 反向加权（auto-ensemble）。

**第五层：可解释性 vs 精度的现实平衡。** 业务侧常问"为什么这个 SKU 预测跌了 30%"——必须能答。深度学习即使精度略高，也会被业务拒绝。**实际生产中 GBDT + SHAP 占主导**：可解释性与精度兼得。Uber ETA 用 GBDT + SHAP 解释"为什么这单时间这么长"，是同等逻辑。

**3. 常见陷阱**

- **"默认 GBDT" 不解释为什么。** 资深面试会反问"为什么不直接用深度学习"——必须能答出 GBDT 在表格数据上的归纳偏置优势 + SHAP 可解释性。
- **忽略时序依赖。** 把销量当普通回归做，丢掉 lag-1 / lag-7 / lag-30 / 滚动均值等时序特征，效果断崖。
- **忽视跨 SKU 共享信息。** 每个 SKU 独立建模 = 浪费信息。层级对账（hierarchical reconciliation）/ Time-series Foundation Model 是正解。
- **认为"深度学习一定更好"。** 这是学术圈常见误解。表格数据上 GBDT 仍占主导（参见 2022-2024 多篇 tabular DL benchmark 论文）。
- **不设 baseline。** 直接上 LightGBM 不跑 OLS，不知道"线性模型上能拿到多少分"。baseline 永远要设。

**4. 追问预测**

- **「10 万 SKU 都跑 LightGBM 太慢怎么办？」** 答：① 按品类聚类，建 50 个模型而非 10 万个；② 用 LightGBM 的 `categorical_feature` + 直方图加速；③ 上游做特征降维 / 特征选择；④ 用 Chronos / TimesFM 一次性对所有 SKU 做零样本基线，再对头部 SKU 微调。
- **「Prophet + LightGBM 集成，权重怎么定？」** 答：① 验证集网格搜索（0~1 步长 0.1）；② 多模型加权（auto-ensemble）；③ 简单版 0.5/0.5 起步，再扫权重。
- **「深度学习在销量预测里什么时候真的优于 GBDT？」** 答：① 训练数据极大（> 1 亿行）；② 特征含大量高维稀疏（如商品 ID embedding）；③ 时空 + 用户序列联合建模；④ 多任务共享 embedding（销量 + 价格 + 库存）。否则不显著。
- **「多 SKU 模型如何保证不互相拖后腿？」** 答：用层级时间序列（hierarchical time series）+ MinT / OLS 对账方法，保证 SKU 级别预测能向上汇总到品类级、品类级能向上汇总到全店级。

#### §4.1.3 Prophet、ARIMA 与时序 Transformer 在工业级销量预测中各自适合什么场景？为什么 ARIMA 在很多实际项目中被 Prophet 取代？

**1. 考察点**

- 是否理解**三类时序模型的归纳偏置差异**——ARIMA 假设线性平稳 + 短程依赖、Prophet 加法分解 + 趋势断点 + 节假日显式建模、Transformer 长程依赖 + 大规模预训练。
- 能否说出 ARIMA 在工业场景的**真实痛点**——p/q 难调、长季节性失效、多 SKU 自动化困难。
- 是否知道**时序基础模型**（Chronos / TimesFM / MOIRAI）正在重塑时序预测的范式。
- 加分项：能指出 Prophet 的局限（异常值敏感、滞后变量难融入）与时序 Transformer 的局限（小样本易过拟合）。

**2. 参考答案框架**

**第一层：三类模型的本质差异。**

- **ARIMA（AutoRegressive Integrated Moving Average）**：经典统计模型。假设**线性 + 平稳**——通过差分让序列平稳，再用 AR（自回归）+ MA（移动平均）刻画短期依赖。**优势**：理论基础扎实、参数少、可解释（系数即"过去 lag-k 对未来的影响"）。**劣势**：① p/d/q 必须人工选择或 Auto-ARIMA，对每个 SKU 都要单独调；② 难以处理非线性（如促销造成的非线性跳变）；③ 长季节性（如年周期 = 365）会因参数爆炸而失效；④ 难以融入外生变量（虽然 SARIMAX 可以但代价大）。
- **Prophet（Facebook 2017）**：加法分解模型，把 y(t) = trend(t) + seasonality(t) + holiday(t) + error(t)。**优势**：① 自动处理多个季节性（周 + 月 + 年）；② 节假日通过显式表格注入（中国春节、双 11 等业务日历）；③ 趋势断点（changepoint）自动检测；④ 对缺失值鲁棒。**劣势**：① 加法模型无法刻画乘性关系（如"周末是工作日的 1.2 倍"需要显式交互）；② 滞后变量难以融入；③ 对剧烈促销导致的双 11 风格尖峰仍可能拟合不足。
- **时序 Transformer（PatchTST / iTransformer / TimesNet / Chronos / TimesFM）**：用注意力机制捕捉长程依赖，并通过 Patch / 反转 / 卷积等改进降低时序特有噪声。**优势**：① 长序列建模（数百到数千长度）；② 多变量协同（covariate）；③ 可预训练做零样本 / 跨域迁移。**劣势**：① 小样本过拟合；② 训练成本高（GPU）；③ 对超长历史依赖的"记忆"机制仍在演进。

**第二层：工业场景的选型梯度。**

| 场景特征 | 推荐 | 理由 |
| --- | --- | --- |
| 单 SKU + 平稳 + 历史 < 2 年 | ARIMA / SARIMA | 经典、可解释、训练快 |
| 多 SKU + 强季节性 + 复杂节假日 | Prophet | 自动化程度高 |
| 多 SKU + 大量外生特征（促销/价格/天气） | LightGBM + 时序特征 | 特征工程主导 |
| 多 SKU + 长序列 + 跨域迁移 | 时序 Transformer / Chronos | 大模型预训练红利 |
| 实时 / 在线（每分钟预测） | 在线学习时序模型 / 简化 ARIMA | 推理延迟要求 |
| 业务可解释优先 | Prophet / ARIMA + 业务注解 | 业务侧接受度 |

**第三层：为什么 ARIMA 在很多项目中被取代。**

- **「每个 SKU 单独建模」的运维灾难**：10 万 SKU = 10 万个 ARIMA 参数选择。即便用 pmdarima 做 Auto-ARIMA，单点训练时间 5~30 秒，总成本随 SKU 数线性爆炸。
- **季节性失效**：零售 SKU 通常含"日 / 周 / 月 / 年"四层季节性 + 春节等不规则周期。SARIMA(p,d,q)(P,D,Q)s 中 s=365 会让参数空间爆炸，PMDARIMA 在 s=365 时已经不稳。
- **外生变量难融入**：促销、价格、天气这些关键业务信号在 ARIMA 里通过 SARIMAX 勉强接入，但要为每个 SKU 单独验证外生显著性，工程成本极高。
- **精度被 GBDT / Prophet 超越**：在多数工业场景中 Prophet + LightGBM 在 SKU 销量上优于纯 ARIMA（MAPE 维度；具体幅度随数据与 SKU 结构差异很大，本书无法给出可溯源的统一数字，此处按【经验】档处理），原因是 GBDT 能学到"促销 → 销量"的复杂非线性映射。

阿里双 11 GMV、京东销量、字节 vv、沃尔玛需求预测的工业实践都印证了这一点：**ARIMA 仍未退出历史，但通常只作为"业务解释性补充"或"科研对比基线"，而非主力预测**。LinkedIn 时序异常检测团队曾对比过 Prophet 与 ARIMA 变体——前者在大规模时序上的模型维护成本明显更低，精度持平或略优（具体倍数本书无法给出该对比的可核验出处，此处按【经验】档处理）。

**第四层：时序基础模型是 2024+ 的新方向。** Chronos（Amazon 2024）把时序 token 化为离散序列、用 Transformer 预训练成"时序 LLM"，支持零样本预测；TimesFM（Google 2024）类似；MOIRAI（Salesforce 2024）尝试做多任务统一时间序列基础模型。**优势**：用一个大模型替代数十万的 SKU 单模型；冷启动 SKU 无需历史数据即可预测；跨域迁移学习。**局限**：对极长历史（> 5 年）支持的稳定性仍在验证；对业务外生变量（促销、价格）注入仍需微调。

**第五层：混合是工业标准答案。**

- **Prophet + LightGBM**：Prophet 拟合趋势 + 季节性 + 节假日 → LightGBM 拟合残差（用促销 / 价格 / 竞品等结构化特征）。
- **ARIMA + GBDT**：ARIMA 捕捉短程自相关，GBDT 拟合结构性部分。
- **Chronos + 微调**：用 Chronos 做零样本基线，用业务数据轻量微调 head。

这是 2024 年工业级时序预测的"事实标准"，而非单模型。

**3. 常见陷阱**

- **"ARIMA 已被淘汰"。** 不准确——ARIMA 在金融、气象、计量经济中仍是主力；它"被取代"主要发生在互联网销量 / 流量预测场景。
- **"Prophet 一招鲜"。** 不提 Prophet 的局限（异常值敏感、加法结构、滞后难融入）会让回答显得肤浅。
- **"Transformer 一定更准"。** 小样本场景 Transformer 严重过拟合；必须说清数据规模前提。
- **忘记外生变量。** 销量预测中价格 / 促销 / 天气是核心信号，纯时间模型根本接不住。
- **"调包就行"。** 不提 Prophet 的 `changepoint_prior_scale`、节假日的 `holidays` 表、Fourier 阶数等关键超参，等于没说。
- **混用 train_test_split。** 时序数据随机切分 = 泄露未来信息。**必须强调 TimeSeriesSplit**。

**4. 追问预测**

- **「10 万 SKU 都跑 Prophet 仍然很慢，怎么办？」** 答：① 按 SKU 聚类（品类 + 销量分桶）→ 一类一个 Prophet；② 用 Prophet 的全数据并行训练；③ 升级到 DeepAR / NeuralForecast / Chronos 做单模型全局建模。
- **「双 11 那种脉冲式峰值，Prophet 拟合得不好怎么办？」** 答：① 在 `holidays` 表中加入双 11 的"事前 + 当日 + 后续 3 天"窗口；② 把"双 11 标记"作为外部回归因子（`add_regressor`）；③ 单独为大促建一个"大促回归模型"叠加到日常 Prophet 上；④ 改用 LightGBM + `is_double11` 类别特征。
- **「如何判断 Chronos 零样本预测够用，还是要微调？」** 答：用 MAPE / MAE 在测试集对照——零样本 MAPE 若 < 业务容忍线则无需微调；否则用 LoRA / head 微调少量参数。
- **「时序数据切分怎么做？」** 答：必须 TimeSeriesSplit——训练集 < 验证集 < 测试集，按时间顺序。可用 `sklearn.model_selection.TimeSeriesSplit(n_splits=5)` 或 `Darts` 的 backtesting 框架。**严格禁止随机 K-Fold**——会让测试集"看见"未来。
- **「如何防止模型对训练集最后一个周期过拟合？」** 答：用 `changepoint_prior_scale` 控制 Prophet 的趋势灵活度（默认 0.05，过大会过拟合突变）；用 LightGBM 的早停（`early_stopping(100)`）；按时序滑窗评估而不是单点评估。

#### §4.1.4 时序回归最常见的工程陷阱是什么？请说明「时间切分泄露未来信息」与「特征工程陷阱」在销量预测场景中的具体表现与解法。

**1. 考察点**

- 是否理解时序数据的**特殊性**——不能随机切分、不能用未来信息、必须时间向前。
- 能否列出**至少 4 类典型特征工程陷阱**（泄露 / 缺失值 / 数据漂移 / 外生变量滞后）。
- 是否知道**业务日历**（双 11、春节、618）在销量预测中的关键作用。
- 加分项：能给出具体的工业级防御手段（TimeSeriesSplit、特征时间戳审计、滑动窗口评估）。

**2. 参考答案框架**

**第一层：时序数据的根本特殊性。** 时序数据的核心约束是「**未来尚未发生**」——任何让模型"看见未来"的特征或切分都会让评估指标虚高、上线翻车。这条约束贯穿数据、特征、训练、评估全链路。

**第二层：五大典型陷阱与解法。**

- **陷阱 1：随机 K-Fold 切分泄露未来。**
  - **表现**：用 `train_test_split` 做 8:2 随机切分，模型在测试集上 MAE 极低；上线后效果断崖。
  - **根因**：测试样本的"前 N 个时间步"与训练样本的"后 N 个时间步"重叠，相当于模型已经"看见"了测试样本的最近历史。
  - **正解**：必须用 `sklearn.model_selection.TimeSeriesSplit(n_splits=5)` —— 训练集永远 < 验证集 < 测试集。
  - **进阶**：评估时用「滚动预测（rolling forecast）」—— 用 [t0, t1] 训练，预测 t2；再用 [t1, t2] 训练，预测 t3；……覆盖整个时间轴。这是 Uber DeepETA、美团配送时长预估都在用的评估方式。

- **陷阱 2：特征工程里不小心泄露未来。**
  - **表现**：用"今日销量"作为今日的特征 → 模型实质是"复制"目标值，训练 MAE → 0。
  - **典型泄露来源**：① 用当日的实际值作为特征（应去掉或用 lag-1 替代）；② 用 t+1 期的滚动均值（应改为只到 t-1）；③ 用未来活动的标签作为特征（如"是否已参加双 11"——上线时该活动尚未发生）；④ 用全量数据的归一化参数（应只基于训练集 fit）。
  - **正解**：**特征时间戳审计**——每个特征必须明确"它的可用时间点是什么"。Uber 内部称之为 "feature freshness contract"。

- **陷阱 3：不处理缺失值 / 异常值 / 业务日历变化。**
  - **表现**：促销数据漏报导致双 11 当日预测严重低估；春节日期每年不同（农历）使得"2 月 10 日"特征失效；店铺关停导致销量断崖却仍被当作活跃样本。
  - **正解**：① 业务日历表（农历 + 公历 + 自定义节假日 + 促销黑名单）；② 异常值检测（Isolation Forest / 三倍标准差）+ Winsorize；③ 关停 / 缺货 / 异常事件打标签并单独建模。

- **陷阱 4：忽略了分布漂移与概念漂移。**
  - **表现**：模型部署后 3-6 个月，效果下降。原因是用户行为 / 供应链 / 竞品在变。
  - **正解**：① 监控输入分布（Feature Drift）与预测分布（Prediction Drift）；② 监控真实销量 / 预测销量的残差分布；③ 定期重训（周 / 月）+ 在线学习。

- **陷阱 5：用整体 MAE 忽略 SKU 异质性。**
  - **表现**：整体 MAE 看似 5%，但爆品 SKU 偏差 15%、冷门 SKU 偏差 2%——MAE 被冷门 SKU 稀释。
  - **正解**：分销量档位报 MAE/MAPE（高 / 中 / 低三档分别算）；用 WMAPE / SMAPE；按业务重要性加权。

**第三层：销量预测的特征工程模板（正确版）。** 一个工业级时序回归的特征体系通常包含四类：

| 类别 | 举例 | 时效约束 |
| --- | --- | --- |
| 时序特征 | lag-1, lag-7, lag-30, lag-365；rolling mean/std；差分；STL 分解 | 严格 lag，全局归一化只用训练集 fit |
| 日历特征 | 星期、月、是否月初 / 末、是否春节 / 双 11、是否工作日 | 提前算好，农历春节每年动态 |
| 外生特征 | 促销、价格、天气、竞品、库存、品类大盘 | 时效性强，必须明确数据就绪时间 |
| 交互特征 | 价格 × 是否促销 × 是否周末；品类 × 是否节庆 | 易泄露，必须严格审计 |

**第四层：业务日历是销量预测的命门。** 工业级销量预测的第一杀手是"业务日历不准"：

- **阿里双 11**：从前 30 天、预热、爆发、返场分阶段建模，每个阶段用 `is_preheat / is_boom / is_after` 等标志位。
- **京东 618**：6 月 1 日 ~ 18 日，每日权重不同。
- **春节**：用农历，每年动态生成；初一到初七、初八到十五对零售 / 旅游 / 餐饮有完全不同的影响。
- **黑色星期五**：Shein 的圣诞季 + Cyber Monday 是欧美区域的强季节性。

**第五层：评估体系而非单一指标。** 工业级评估必须包含：

- **滚动窗口 MAE / MAPE**（5 个窗口取平均）。
- **分位数覆盖**：P10 / P50 / P90 报三个数。
- **业务指标**：缺货率、备货满足率、预测偏多 vs 偏少分布。
- **分 SKU 评估**：头部 20% SKU、中部 60%、长尾 20% 分别报。
- **线上 A/B 检验**：最终以业务指标为标准。

**3. 常见陷阱**

- **没意识到"数据切分"本身就是陷阱。** 用随机 K-Fold 把时序当 i.i.d. 处理——这是初学者最常犯的错。
- **没说具体的特征泄露例子。** 抽象讲"特征工程要小心"等于没说；要列具体场景。
- **忽略业务日历。** 不提春节、双 11 等业务日历，显得没做过真实业务。
- **只报单一指标。** 只说"MAE=10%"不说分位数 / 业务指标，回答深度不够。
- **没提漂移检测。** 模型上线完事就走人，不提监控与重训，是常见盲区。
- **错误使用 One-Hot 而非 Target Encoding 处理高基数特征。** 商品 ID、SKU ID 等高基数离散特征用 One-Hot 会爆维度，应改用 target encoding + 时间衰减或 embedding。

**4. 追问预测**

- **「某 SKU 只有 6 个月历史，能建模吗？」** 答：① 跨 SKU 全局模型 + 该 SKU 微调；② 用相似 SKU 迁移（cluster-based）；③ 用 Chronos / TimesFM 零样本预测；④ 实在不行，用季节性 naive + 业务均值兜底。
- **「lag-30 特征必须保留 30 天的 NaN 怎么办？」** 答：① LightGBM / XGBoost 原生支持 NaN，让模型自己学；② 线性模型用前向填充 + 标记缺失位；③ 直接剔除近期无数据 SKU 的 lag 特征。
- **「双 11 当天的预测是只看双 11 自身，还是看去年双 11？」** 答：必须同时看——去年双 11 当天的 lag-365 + 今年同比日的滚动窗口 + 业务日历（距双 11 的天数 + 当日活动强度）。阿里在大促场景一般用 4 个独立模型：日常 / 大促前 / 大促中 / 大促后。
- **「上线后效果衰减怎么办？」** 答：① 监控预测残差分布；② 检测 feature drift（输入分布变化）；③ 触发自动重训 pipeline；④ 用增量学习（增量 GBDT、SGD）；⑤ 必要时回滚到上一个稳定版本。
- **「天气数据有时会缺失，未来要预测怎么办？」** 答：① 用历史同期的均值/中位数填补；② 用 Prophet 的 `fill_missing` 选项；③ 训练时把天气作为可选特征（缺失时跳过分裂）。
- **「怎么识别数据漂移？」** 答：用 PSI（Population Stability Index）监控每个特征 + 输出的分布；PSI > 0.2 触发预警；监控真实值与预测值残差的时间序列是否破带。

#### §4.1.5 在信用评分卡场景中，PD（违约概率）/ LGD（违约损失率）/ EAD（违约暴露）三个模型分别用什么方法实现？为什么 PD 通常用 Logistic 回归而非 GBDT？模型校准（Calibration）为什么至关重要？

**1. 考察点**

- 是否理解**信用评分卡的 IRB 体系**——PD、LGD、EAD 三模型各自的输出含义与监管约束。
- 能否说出 PD 用 Logistic 回归 + WOE 分箱的**业务原因**（可解释性 + 监管合规 + 稳定性），而非"GBDT 精度更高就应该用它"。
- 是否理解**校准（Calibration）**的本质——模型输出的概率是否与真实频率一致——以及 Platt Scaling、Isotonic Regression 等方法。
- 加分项：能区分点估计（mean）与分位数预测（LGD 通常用分位数回归 / Beta 回归）、能说出 PSI / CSI 等稳定性监控指标。

**2. 参考答案框架**

**第一层：IRB 体系下的三模型定位。** 巴塞尔协议定义的"内部评级法（IRB）"把信用风险分解为三个独立子模型：

- **PD（Probability of Default，违约概率）**：未来 12 个月违约概率 ∈ [0, 1]，是分类问题（二分类 / 多分类）。**输出**：0-1 之间的概率，必须**校准**（必须等于真实违约频率）。
- **LGD（Loss Given Default，违约损失率）**：违约后损失占暴露的比例 ∈ [0, 1]，是回归问题（连续 0~1）。
- **EAD（Exposure at Default，违约暴露）**：违约时点的未结余额，是回归问题（可能超过当前余额，因利息与新借款）。

最终**风险加权资产 RWA 由 PD、LGD、EAD、期限调整与资产相关性共同决定**（Basel IRB 资本公式中 PD 经标准正态分位数等非线性项进入，并非简单相乘）——三者中任何一个不准确，整体资本计算就失真。

**第二层：PD 用 Logistic 回归 + WOE 的真实理由。** 多数 ML 工程师会认为"GBDT 精度更高，应该用 GBDT"，但在金融风控场景答案相反：

- **可解释性**（监管要求）：巴塞尔、IFRS9、银保监会要求模型可解释——每个预测的贡献度可追溯。Logistic 回归的系数直接对应"年龄 +1，违约 log-odds 变化 β"（等价于违约 odds 变为 e^β 倍），业务人员能看懂；GBDT 必须配合 SHAP 才能解释，且 SHAP 是"事后近似"，银行监管对此态度保守。
- **稳定性**（PSI 监控友好）：LR 的特征（WOE 分箱后）是离散化变量，**对输入分布漂移更鲁棒**——分箱边界不变，每月 PSI 都稳定在低位。GBDT 的分裂对训练集分布极敏感，2 个月不重训 PSI 就飙升。
- **推理可复现**：LR 在 CPU 上毫秒级、可单线程、可重放；GBDT 模型文件大、依赖版本（如 LightGBM 1.x 与 2.x 输出略有差异），监管验证困难。
- **业务规则融合**：WOE 分箱天然便于将"硬规则"（年龄必须 ≥ 18、禁止特定行业）作为分箱边界，便于人审。

**当然 GBDT 也有用武之地**：① 申请评分卡的二阶段建模——先用 GBDT 挖掘特征，再用 LR + WOE 复刻；② 反欺诈 / 行为评分——用 GBDT + SHAP。**招行信用卡、平安普惠、微众银行都采用"GBDT 探索 + LR 落标"的双阶段范式。**

**第三层：LGD 与 EAD 的回归实现。** 这两个模型有自己的特殊性，**不能简单用 MSE + LR**：

- **LGD**：输出 ∈ [0, 1]，是**有界回归**问题。
  - **Beta 回归**：假设目标变量服从 Beta 分布，配合 logit 链接函数，是学术界主流。
  - **分位数回归**：预测 LGD 的中位数 / 75 分位数而非均值，对极端损失更敏感。
  - **两阶段模型**：先用分类器预测"是否会全部损失（LGD=1）"，再用回归器在非全部损失子集中预测具体值。
  - 招行使用 Beta 回归 + 分位数回归双模型；微众使用两阶段分类+回归。

- **EAD**：可超过当前余额，**右截断回归（censored regression）**、Tobit 模型、LightGBM 回归均可。
  - 业内常用 LightGBM / XGBoost 训练 EAD，配合 SHAP 解释。

**第四层：校准（Calibration）为什么至关重要。** PD 模型的输出 0.013 含义不只是"谁违约概率高"，而是"100 个评分 0.013 的人中应有 1.3 个人真实违约"。**若模型未校准，下游所有决策（额度、价格、资本计提）都会系统性偏误**。

- **校准指标的"两个一致"**：模型概率 P(Y=1|X) 应等于 E[Y=1|X]。具体评估：
  - **Hosmer-Lemeshow 检验**：分组观察"预测违约率 vs 真实违约率"。
  - **Calibration Plot**：把样本按预测概率等分 10 组，画"预测值 vs 真实值"的散点。理想是 45 度线。
  - **Brier Score**：均方误差的"概率版"，越小越好。
  - **ECE（Expected Calibration Error）**：分桶后预测与真实之差的加权平均。

- **校准方法**：
  - **Platt Scaling**：用 Logistic 回归对原模型输出做二次校准（适合 GBDT 等不平衡分数）。
  - **Isotonic Regression**：单调分桶校准（适合样本量足够）。
  - **Beta Calibration**：三参数，比 Platt 更灵活。

- **校准必须随时间更新**：人口结构、经济周期会漂移 PD 分母。如 2020 年疫情期间整体违约率上升，原 PD=0.005 在新环境下应映射到 0.008，必须按 PSI 与 ECE 触发重校准。

**第五层：稳定性是金融模型的"第二条命"。** 监管要求模型**上线后保持稳定**——

- **PSI（Population Stability Index）**：比较验证集与上线后样本的特征分布。PSI > 0.1 关注、> 0.2 报警、> 0.25 必须重训。
- **CSI（Characteristic Stability Index）**：单个特征的 PSI，比 PSI 更细粒度。
- **Score Distribution Stability**：每月监控评分分布，漂移过大即触发重训。

招行信用卡评分卡、平安普惠小微企业评分、微众银行"微粒贷"评分都设有 PSI 日级监控仪表盘。

**3. 常见陷阱**

- **"GBDT 一招鲜"忽视可解释性。** 不懂金融监管对模型可解释性的强制要求。
- **混淆 PD 与 LGD 的输出含义。** 把 LGD 当普通回归用 MSE，没意识到 LGD 的 [0,1] 约束与右偏分布。
- **不校准就直接使用。** GBDT 输出的是"分数"不是概率，必须 Platt / Isotonic 校准。
- **忘记 PSI 监控。** 上线完就走，不设置稳定性监控。
- **混淆"模型 AUC 高"与"模型有用"。** AUC 0.75 的模型如果不校准、PSI 失控，业务上毫无意义。
- **忽略经济周期。** 用 2019 年数据训练，2023 年仍在上线——PD 分母漂移，校准失效。

**4. 追问预测**

- **「WOE 分箱是怎么做的？为什么用 WOE 而非 One-Hot？」** 答：WOE = ln((违约占比)/(未违约占比))，让分箱后每箱的"违约 odds"线性可加。优点：① 数值化便于 LR；② 自然表达"该箱的风险相对均值的高低"；③ 便于 PSI / CSI 监控。One-Hot 会让 LR 系数失去单调性。**CRISP-DM** 与 **SAS Credit Scoring** 都有标准 WOE 分箱流程。
- **「AUC 0.78 算高吗？KS 又怎么算？」** 答：信用评分场景 AUC 0.75-0.80 已算可用。KS = max(TPR - FPR)，常用评分卡目标 KS ≥ 0.3（0.45 为优秀）。KS 对排序能力敏感，AUC 对概率准确性敏感，两者互补。
- **「LGD 为何不直接用 LightGBM？」** 答：① LGD ∈ [0,1] 强约束，LightGBM 不天然支持；② LGD 分布严重右偏（大量 0-30% + 少量 70-100%），MSE 会被中位数拉偏；③ Beta 回归给出基于分布的参数估计，能直接生成"置信区间"用于资本计提。**招行用 Beta 回归做 LGD、微众用两阶段分类+回归，均按业务规则取舍。**
- **「PSI > 0.2 怎么办？直接重训？」** 答：不急着重训——先诊断是 feature drift（输入变了）还是 concept drift（目标变了）；前者要补数据采集，后者要重建模型。稳的做法是"先 PSI 监控 + 评分分布稳定 + ECE 监控"三件套。
- **「PD 模型怎么做到对经济周期鲁棒？」** 答：① 通过 long-term 平均 + 周期性回归（through-the-cycle, TTC）平滑；② 用 Basel 公式分层评级（pd_base × stress_factor）；③ 引入宏观因子（Merton 距离 / GDP 增长）做宏观校准。招行、平安普惠都做"跨周期 PD"。
- **「为什么 LightGBM 在反欺诈比 LR 更好？」** 答：反欺诈特征复杂（设备指纹 / 关联图谱 / 行为序列）+ 黑样本少。LR 的 WOE 难以刻画复杂交互，LightGBM + SHAP 反而更合适。但最终仍要做 SHAP 解释用于人工审核。

#### §4.1.6 回归任务中"点估计 + 置信区间"与"分位数预测"有什么区别？为什么金融风控、库存管理、广告出价越来越多地使用分位数回归？

**1. 考察点**

- 是否理解**点估计 vs 区间估计**的本质差异——前者是均值 / 中位数、后者是分布信息。
- 能否说出**分位数回归 Loss（Pinball Loss）**的数学公式与它在 LightGBM 中的调用方式。
- 是否知道**贝叶斯回归 / 高斯过程 / 贝叶斯神经网络（MC Dropout）/ Conformal Prediction / 分位数回归**五类不确定性估计方法的能力差异。
- 加分项：能在具体业务场景（备货、风控出价、广告 ROI）说出"为什么分位数比均值更值钱"。

**2. 参考答案框架**

**第一层：先定义"什么是回归的不确定性"。** 一个回归模型的输出 $\hat{y}$ 在工业场景往往不够——业务需要的是**整个分布**，或者至少是**置信区间**：

- **点估计**：$\hat{y} = E[Y|X]$（均值）或中位数。
- **区间估计**：[P10, P90]（80% 置信区间）。
- **分布估计**：完整 Y|X 的分布（贝叶斯后验 / 高斯过程）。

业务上"明天销量预测 1000 件"信息量远小于"明天销量 P50=1000、P90=1500、P10=600"——后者能直接支撑备货决策。

**第二层：五类不确定性估计方法的对比。**

| 方法 | 输出形式 | 假设 | 训练成本 | 推理成本 | 适用 |
| --- | --- | --- | --- | --- | --- |
| **贝叶斯线性回归** | 后验分布 | 高斯先验 + 高斯噪声 | 高（采样） | 高 | 小数据集 |
| **高斯过程（GP）** | 后验均值 + 方差 | 核函数 | 高（N³） | 高 | < 1 万样本 |
| **贝叶斯神经网络（MC Dropout）** | 输出分布 | 隐式 | 中 | 高（多次前向） | 中等规模 |
| **分位数回归** | P10/P50/P90 | 无分布假设 | 低 | 低（多个模型） | 所有场景 |
| **Conformal Prediction** | 经验校准区间 | 分布无关 | 极低 | 极低 | 后处理 |

**第三层：分位数回归的工程实现。** 用 LightGBM 训练 P50 / P90 双模型的工程代码仅几行——

```python
params = {'objective': 'quantile', 'alpha': 0.9, 'metric': 'quantile'}
model_p90 = lgb.train(params, ...)
y_p90 = model_p90.predict(X_test)
```

其本质是**Pinball Loss**：
$$\mathcal{L}_\tau(y, \hat{y}) = \max(\tau(y - \hat{y}), (1-\tau)(\hat{y} - y))$$

- τ=0.5 训练中位数模型（MAE 同解）。
- τ=0.9 训练 90 分位数模型——"90% 概率真实值 ≤ 预测值"，对应"宁愿多备不可少备"的备货场景。

工业实现要点：① 训练 P10、P50、P90 三个模型；② 也可以训 P5、P95 用于极端值预警；③ 三个模型并行训练 / 推理，成本可控。

**第四层：业务为什么偏爱分位数。**

- **库存管理 / 销量预测**：业务关心"明天销量会不会爆"而非"平均多少"。P90 预测直接给"90% 概率不超过"的上限，避免缺货。**阿里双 11 备货预测、京东大促库存**都用高位分位数回归定备货上限（具体分位档位本书无法给出可核验出处，此处按【经验】档处理）。
- **金融风控 / 信用评分**：PD 模型关注 95% VaR（Value at Risk），需要高位分位数。LGD 模型需要 75 分位损失率用于"压力测试"。**招行信用卡 LGD 用高位分位的 Beta 回归**（该实践本书无法给出可核验的出处，具体分位取值按【经验】档处理）。
- **广告出价 / ROI 预测**：每次广告展示预测 P50 / P80 出价上限，避免低 ROI 干扰。**Google Ads、Meta Ads、字节巨量引擎的出价模型**都用分位数控制下界。
- **配送 ETA / 时长预估**：P50 给用户看，P90 用于"如果超出 P90 则补偿用户"的 SLA 决策。**Uber DeepETA、米哈游游戏匹配时长、美团配送**等时长预估场景都同时给出 P50 与高位分位数两路输出（具体分位档位随场景与口径而异，本书无法给出可核验的公开文档，此处按【经验】档处理）。

**第五层：分位数回归的局限与替代。**

- **局限**：① P10/P50/P90 三个模型独立训，无法保证 P10 ≤ P50 ≤ P90（顺序违例需要后处理）；② 分位数是"点估计 + 经验分位"，不是"完整分布"——贝叶斯 / GP 给出整个后验。
- **替代**：
  - **贝叶斯回归 + MCMC**：能给出整个后验分布。PyMC 是 Python 工业标准。**微众银行用它做 PD 评分的置信区间**。
  - **高斯过程（GP）**：适合小样本 + 平滑核函数场景。Uber 曾用 GP 校准 ETA 不确定性。
  - **MC Dropout**：训练时开启 Dropout，推理时多次前向输出方差。简单实用，无需重新训练。
  - **Conformal Prediction**：把任何点估计模型的输出 + 一批校准样本转换成"经验保证"的置信区间。**MAPIE** 是 Python 库，部署友好。

**第六层：工业级集成范式——"均值 + 分位数 + Conformal"三件套。**

- **均值模型**：LightGBM 训练 E[Y|X]，作为主输出。
- **分位数模型**：P10 / P90 两个 LightGBM 模型，给区间下/上限。
- **Conformal 后处理**：用一个月回测数据，按 Conformal 方法校准区间宽度——保证 90% 区间覆盖真实值。

百度搜索结果质量评分、京东大促销量预测、Shein SKU 销量区间预测都遵循此范式。

**3. 常见陷阱**

- **"分位数回归 = 模型自带置信区间"。** 不准确——许多算法（线性回归 statsmodels）会输出置信区间，但默认是**正态假设下**的参数不确定性，不是预测不确定性。预测不确定性要靠分位数 / 贝叶斯 / Conformal。
- **不区分 q=0.5 vs q=0.9 的损失**。 错把 P50 用作风险评估——风险评估必须用高位分位数。
- **不解决 P10/P50/P90 顺序违例**。 直接拿来用——业务可能遇到"P10=200、P50=100、P90=300"的荒唐结果。
- **把分位数回归当成 SOTA 一切场景**。 忽略样本量、训练成本、推理延迟的差异。
- **把 VaR 与分位数对立**。 VaR 本身就是**损失分布的 α 分位**，分位数回归正是估计它的工具——两者口径一致、可以并用，只需说清是损失侧分位。

**4. 追问预测**

- **「P50 / P90 三个模型训练成本高，如何压缩？」** 答：① 共享底层 embedding（多任务学习）；② 用单模型 + 多次随机种子预测做集成近似分位数；③ 用 Conformal Prediction 后处理，避免训练三个模型。
- **「分位数预测的 P90 总是低估极端值，怎么办？」** 答：① 把 α 调到 0.95 甚至 0.99；② 用 Beta 回归 / GP 给出基于分布的估计；③ 加 EVT（极值理论）尾部建模；④ 用 Conformal / HCQR（Heteroscedastic Conformal QR）。
- **「为什么 Conformal Prediction 越来越流行？」** 答：① 分布无关——无需任何分布假设；② 经验保证——90% 区间保证覆盖 90% 真实值；③ 计算开销低——只需校准集。**MAPIE / Amazon Science Conformal 库** 工业友好。
- **「贝叶斯回归 vs 分位数 vs GP 怎么选？」** 答：① 数据量 < 1 万 → GP 或贝叶斯；② 数据量 1-100 万 + 需要分布 → 贝叶斯神经网络（MC Dropout）或分位数；③ 已有 GBDT 主力 + 只补不确定性 → Conformal 后处理；④ 实时高并发 → 分位数（推理最便宜）。
- **「分位数预测如何用于风控决策？」** 答：把 PD P95 作为"压力测试"输入；把 LGD P75 作为资本计提基准；把 EAD P90 作为授信上限。**招行、平安普惠、微众银行**的实际决策基于高位分位数。

#### §4.1.7 解释因果回归（Causal Forest / T-Learner / DML）与传统回归的本质差异。在营销决策、信贷风控、政策评估场景下，为什么必须用因果方法而非传统的销量预测回归？

**1. 考察点**

- 是否理解**相关 vs 因果**的根本差异——传统回归学的是"看见什么"，因果回归学的是"做了一件事会怎样"。
- 能否说出**CATE（条件平均处理效应）**与**ATE（平均处理效应）**的定义与差异。
- 能否列举至少 3 个因果推断工具（DoWhy、EconML、CausalML、T-Learner/X-Learner/Causal Forest）并简述其适用场景。
- 加分项：能区分**反事实推断（Counterfactual）与 Uplift 建模**——前者求个体 P(Y|X,do(T))，后者求 P(Y|T=1)-P(Y|T=0)|X。

**2. 参考答案框架**

**第一层：先定义"相关"与"因果"的鸿沟。** 传统回归学的是**条件期望 E[Y|X]**——回答"看见 X 时，Y 的期望是多少"。因果回归学的是**反事实 P(Y|do(T))**——回答"如果我做了一件事 T，Y 会怎么变"。

著名的反例：冰淇淋销量与溺水人数高度相关——但**吃冰淇淋不是溺水的原因**（共同原因是夏天）。传统回归会预测"卖更多冰淇淋 → 溺水增加"，但干预"禁止冰淇淋销售"无法减少溺水。**因果回归要识别并剥离"夏天"这个混淆变量**，才能正确回答干预效应。

**第二层：因果推断的三个层级。**

- **关联（Association）**：P(Y|X)——传统回归 / 分类。
- **干预（Intervention）**：P(Y|do(T))——回答"如果强制 T=1，Y 会怎样"。
- **反事实（Counterfactual）**：P(Y_x|u)——回答"对个体 u，若 Y 取 x 与个体已观察到的状态不一致，会发生什么"。

Pearl 的"因果阶梯（Ladder of Causation）"清楚地告诉我们要到达干预甚至反事实层级，**仅靠传统回归是不够的**。

**第三层：因果回归的核心方法。**

- **倾向得分匹配（PSM）**：用 Logistic 回归估计 P(T=1|X)，按概率匹配处理组与对照组，比较两组的 Y。**优势**：简单直观；**劣势**：匹配后样本量小、对极端倾向得分样本不友好。
- **T-Learner / S-Learner / X-Learner**（Meta-Learner 范式）：
  - **T-Learner**：分别对处理组、对照组训练两个模型，$\hat{\tau}(x) = \hat{\mu}_1(x) - \hat{\mu}_0(x)$。
  - **S-Learner**：用 T 当作普通特征训练一个模型，$\hat{\tau}(x) = \hat{\mu}(x, T=1) - \hat{\mu}(x, T=0)$。
  - **X-Learner**：T-Learner 的改进，结合倾向得分加权，解决"处理组样本少"的不平衡。
- **Causal Forest / Causal Tree**（Wager & Athey 2018）：用"诚实树（honest tree）"——部分样本建树、部分样本估叶——给出 CATE 估计 + 置信区间。
- **DML（Double Machine Learning）**（Chernozhukov 2018）：用 ML 残差化——第一阶段把 Y、T 都对 X 做残差化（用任意 ML 模型）；第二阶段在残差上做线性回归，得到无偏的因果效应估计。这是稳健性最好的方法。
- **Dragonnet**（2020）：用神经网络直接建模 P(Y|X,T) + P(T|X)，并在 loss 中加入"治疗倾向正则化"，实现端到端的 CATE 估计。

Uber 的 **CausalML** 是工业级 Uplift 建模的标准库，**Microsoft 的 EconML** 是 CATE 估计的标准库，**DoWhy**（Microsoft）提供因果图建模 + 端到端推断。

**第四层：典型业务场景为何必须用因果方法。**

- **场景 1：营销决策（Uplift 建模）**——某 SaaS 公司想发优惠券触达 100 万用户，但预算只够 30 万。**传统回归**：用历史用户"是否转化"训练，预测每个用户的"转化概率"，选概率最高的 30 万。但这只能识别"高转化率"用户，不能识别"对优惠券有增量响应"的用户。**因果回归**：Uplift 建模区分**自然转化**（不发券也会转）与**增量转化**（发券才转），选 Uplift 最高的 30 万——这是 marketing ROI 的真正优化目标。**LinkedIn、Uber Eats、抖音推荐、星巴克 Push** 全部用 Uplift 建模做精准营销。
- **场景 2：信贷风控（Treatment Effect on Lending）**——利率是 6% 还是 8% 会影响违约率吗？传统回归会学"利率高 → 违约高"的相关关系，但**这可能是逆向因果**——风险高的客户被收更高利率（confounding by risk）。**因果推断**：用 DML 残差化剥离"风险等级"的影响后，估计纯利率对违约的因果效应。**微众银行、Lending Club、招行信用卡** 都用此类方法做利率弹性研究。
- **场景 3：政策评估（A/B 实验的反事实）**——某地区上线了免息分期政策，GMV 提升 5%。但**对照地区**若没上线，自然也可能提升 3%（季节性）。**因果推断**：用 DML / Synthetic Control 方法估计"纯政策效应"为 2%，而非直接算 5%。
- **场景 4：产品改版效果**——某 APP 改版后用户留存提升 2pp。**因果推断**：用 Causal Forest 识别改版对哪类人群 positive、对哪类人群 negative，避免对 negative 人群继续强制 push。

**第五层：因果回归与传统回归的工程区别。**

| 维度 | 传统回归 | 因果回归 |
| --- | --- | --- |
| 训练目标 | E[Y\|X] 最小化 MSE | $\hat{\tau}(x)$ 最小化 CATE loss |
| 需要的输入 | (X, Y) | (X, T, Y) 三件套 |
| 评估指标 | MAE / RMSE | uplift curve / Qini coefficient |
| 关键假设 | 无（i.i.d.） | 可忽略性 / 重叠 / SUTVA |
| 工具 | scikit-learn / GBDT | EconML / CausalML / DoWhy |

**因果回归的灵魂是「反事实估计」——它本质上是在问「如果 T 取不同值，Y 会怎样」**。

**第六层：因果推断的常见陷阱。**

- **混淆变量未识别**：训练数据中"利率"和"违约"的相关关系，若不剥离"风险等级"这个混淆变量，得到的就是反向因果。
- **倾向得分重叠不满足**：处理组与对照组的协变量分布不重叠，T-Learner 会外推完全失败。需用 propensity clipping。
- **SUTVA（稳定单元处理价值假设）失效**：用户之间会相互影响（如 A 发券后买，挤占了 B 的库存），传统的单点 CATE 失效。需要显式建模单元间的干扰——例如在结构因果模型（SCM, Structural Causal Model）中引入网络结构，或用随机块模型（SBM, Stochastic Block Model）刻画群体间的溢出效应。
- **工具变量识别错误**：用 2SLS / GMM 时，工具变量必须满足"影响 T、不影响 Y（除通过 T）"——若违反，因果估计仍偏。

**3. 常见陷阱**

- **"相关性就是因果"。** 这是新手最常犯的错——传统回归只能学相关，不能学因果。
- **混淆 ATE 与 CATE**。 ATE 是总体平均效应，CATE 是条件效应，二者业务含义不同。
- **使用 T-Learner 但不处理样本不平衡**。 处理组 / 对照组样本量悬殊时，T-Learner 会过拟合处理组。X-Learner / DR-Learner 更稳健。
- **忽视可忽略性假设**。 "给定 X，T 与 Y 独立"是非常强的假设，实际业务中很难满足。需做敏感性分析。
- **用 AUC 评估 CATE 模型**。 AUC 是二分类指标，Uplift 模型的评估应使用 Qini / AUUC（Area Under Uplift Curve）。

**4. 追问预测**

- **「没有随机实验数据，怎么做因果推断？」** 答：① 准实验（difference-in-differences / regression discontinuity / synthetic control）；② 用工具变量（IV）；③ 用 Causal Forest + 倾向得分匹配；④ 用 RDD（断点回归）；⑤ 用 Bayesian Causal Inference 加先验约束。Uber、LinkedIn 的很多决策基于准实验而非严格 RCT。
- **「T-Learner、S-Learner、X-Learner 哪个最好？」** 答：没有普遍最优。X-Learner 在处理组样本少时表现最好；S-Learner 在 T 对预测影响小时表现好；T-Learner 在两组样本都充足时稳健。**实战建议**：用 EconML 的工具对比三者，选表现最好的 + 最稳健的。
- **「CATE 怎么用于营销决策？」** 答：① 全样本估计 $\hat{\tau}(x)$；② 按 $\hat{\tau}(x)$ 排序；③ 选 top-K 用户做干预；④ 监控处理组的"真实 uplift"是否与 $\hat{\tau}$ 一致。**LinkedIn 通知策略、Uber Eats 优惠券、抖音 Push 都用此流程。**
- **「DML 为什么比 PSM 更稳健？」** 答：PSM 依赖"匹配后样本独立"假设，对高维特征不友好；DML 用 ML 做残差化后做线性回归，对特征维度鲁棒，且对模型误设稳健。
- **「Causal Forest 比随机森林好在哪？」** 答：Causal Forest 用"honest tree"——50% 样本建树、50% 估叶，避免自训练自验证的过拟合；分裂准则不再是"减小 MSE"而是"增大 CATE 异质性"。这让 CATE 估计的置信区间更可靠。

### 8.3 本章小结

本节收录 7 道题，覆盖回归算法的核心原理、模型选型、时序预测、信用评分、不确定性估计、因果推断六大横切主题。七道题构成一条完整的下钻链路：**损失函数选型（基础）→ 模型选型决策表（工程权衡）→ 时序方法对决（业务方向）→ 时序工程陷阱（落地）→ 信用评分与校准（金融场景）→ 不确定性估计（风险视角）→ 因果回归（决策视角）**。

回归算法是数据科学与 AI 时代数据架构的"基础设施"——它把"预测多少"翻译成业务可执行的具体行动（备货、定价、调度、风控、营销）。**回归不是 ML 中"简单"的子任务，而是连接 BI（描述性分析）→ AI（预测性分析）→ Decision（决策性分析）的桥梁**。参考答题的通用心法：**先说清业务约束与目标，再说清模型方法的边界，最后说清工程取舍**——这三层回答到位，才能从 P7 走到 P8。
