### 4.1 某头部电商"**1 万+ SKU 销量预测**"5+ 年（2019-2024）

**背景（Why）**

该电商 2019 年面临**销量预测的两难**：
- **1 万+ SKU，日粒度，未来 30 天**——传统时序模型（ARIMA）**对促销 / 节假日处理弱**，**MAPE 25%**
- **库存周转**——**预测过高 = 压库存 200 亿**，**预测过低 = 缺货损失 50 亿**
- **没有跨 SKU 信息共享**——ARIMA 各自单点预测，**新品无历史预测极不准**

**触发点（What）**

2019 年该电商启动销量预测（[案例 2019]），目标：
- **MAPE**——**25% → 12%**
- **库存周转率**——**+18%**
- **新品预测**——**可解释**

**详细做法（How）**

该电商销量预测的**5 大核心组件**：

1. **时序特征工程（核心创新）**
   - 关键设计：**滞后 / 滑动 / 节假日 / 促销 / 价格**五类特征
   - 关键能力：**预测模型能感知「节前节后」「大促」**
   - 关键数字：**MAPE 12%**
   - 特征清单：
     ```
     滞后特征：lag_1d, lag_7d, lag_28d
     滑动特征：rolling_mean_7d, rolling_std_28d
     节假日：is_holiday, days_to_holiday, days_from_holiday
     促销：   is_promo, promo_intensity, days_in_promo
     价格：   price, price_ratio_to_history
     ```

2. **LightGBM GBDT（核心）**
   - 关键设计：**特征全部喂给 LightGBM**（树模型对促销 / 节假日自动学习非线性）
   - 关键能力：**无需手工交叉特征**
   - 关键数字：**MAPE 25% → 12%**（12% 为含 Prophet 残差叠加后的案例终值）
   - 训练示意：
     ```python
     import lightgbm as lgb
     params = {
         'objective': 'regression_l1',      # MAE 对异常值鲁棒
         'metric': 'mape',
         'num_leaves': 127, 'learning_rate': 0.05,
         'min_data_in_leaf': 50, 'feature_fraction': 0.8,
     }
     model = lgb.train(params, lgb.Dataset(X_train, y_train),
                       valid_sets=[lgb.Dataset(X_val, y_val)],
                       num_boost_round=2000, early_stopping_rounds=100)
     ```

3. **Prophet 时序（核心）**
   - 关键设计：**LightGBM 残差 + Prophet 残差拟合**，**Prophet 补回季节性/节假日趋势**
   - 关键能力：**两组模型互补——LightGBM 吃跨 SKU 信息，Prophet 吃纯时间趋势**
   - 关键数字：**MAPE 12%**（案例终值，含 Prophet 残差叠加）
   - 残差叠加示意：
     ```
     预测 = LightGBM(X) + Prophet(t)
          = 主流模型(特征)  +  时序模型(时间)
     优势：LightGBM 吃跨 SKU 信息；Prophet 吃纯时间趋势
     ```

4. **Flink 实时特征（核心）**
   - 关键设计：**实时特征（实时库存 / 实时加购）进模型**
   - 关键能力：**预测可分钟级更新**
   - 关键数字：**实时特征延迟 < 30s**

5. **库存集成（核心创新）**
   - 关键设计：**预测结果直接进补货系统**——**预测 N 天 = 备 N 天 + 安全库存**
   - 关键能力：**预测-执行闭环**
   - 关键数字：**库存周转 +18%**

**该电商销量预测关键数字**（[案例 2019-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **MAPE** | 25% | 12% | **-52%** |
| **库存周转率** | 基线 | +18% | **+18%** |
| **新品预测** | 不可用 | 可用 | **∞** |
| **特征维度** | — | 50+ | **—** |
| **实时特征延迟** | 小时级 | < 30s | **-99%** |
| **日 SKU 数** | — | 1 万+ | **—** |
| **跨 SKU 信息共享** | 未建设 | 已覆盖 | **新增能力** |

**具体数字（How much）**

- 团队规模：该电商供应链算法团队 30+ 人
- 关键数字：**MAPE 12% / 库存周转 +18%**；**1 万+ SKU**；**30 天预测**
- 业务影响：覆盖该电商**全品类 1 万+ SKU**的库存与采购

**失败教训**

- 早期「**MAPE 25%**」——ARIMA 完全不懂促销，倒逼**「时序特征 + LightGBM + Prophet 残差」**
- 「**新品没有历史数据**」——第一版把新品特征填成 0、预测结果全是 0，倒逼**「加同品类 / 同店 / 同价格带的 cross-SKU 特征」**
- 「**预测与库存不联动**」——预测再准也无人执行，倒逼**「把预测结果直接接入补货系统，形成闭环」**
- 「**实时特征用批处理生成**」——促销当天的销量变化要第二天才反映，倒逼**「实时特征延迟压到 30s 以内」**

### 4.2 某出行公司"**千万订单 ETA 5 分钟**"5+ 年（2019-2024）

**背景（Why）**

该出行公司 2019 年面临**ETA 误差的双向成本**：
- **千万级订单/日**——**ETA 误差大 = 司机白跑、乘客投诉、调度失衡**
- **传统方法**——「直线距离 / 路段平均速度」误差 8 分钟
- **时空特征没有显式编码**——**「周五晚 6 点国贸」**和「周二早 8 点国贸」**完全不同的拥堵**

**触发点（What）**

2019 年该出行公司启动 ETA 预估（[案例 2019]），目标：
- **误差**——**8 分钟 → 5 分钟**
- **用户体验**——**+20%**
- **千城市泛化**——**一套模型覆盖全国**

**详细做法（How）**

该出行公司 ETA 预估的**5 大核心组件**：

1. **Wide & Deep（核心创新）**
   - 关键设计：**Wide 部分**学显式特征交叉（路网+时段），**Deep 部分**学隐式时空模式
   - 关键能力：**同时捕捉显式与隐式**
   - 关键数字：**误差 8 → 5 分钟**
   - 结构示意：
     ```
     输入：出发地经纬度 + 终点经纬度 + 出发时间 + 路网特征
                 ↓
     ┌────────────┴────────────┐
     Wide  (LR + 显式交叉)   Deep (DNN + 高维 embedding)
     └────────────┬────────────┘
                 ↓
            输出 ETA (分钟)
     ```

2. **时空特征工程（核心）**
   - 关键设计：**出发/到达**经纬度 + **时间**（含 sin/cos 周期编码）
   - 关键能力：**时空联合建模——经纬度与周期编码后的时间一起入模，凌晨与深夜不再失真**
   - 关键数字：**时空特征 30 维**
   - 关键示意：
     ```python
     hour_sin = sin(2π * hour / 24)        # 让 23:59 与 00:01 距离近
     hour_cos = cos(2π * hour / 24)
     dow_sin  = sin(2π * dow / 7)          # 跨周末
     dow_cos  = cos(2π * dow / 7)
     # 路网特征：起点/终点所在 road_level
     ```

3. **多任务学习（核心）**
   - 关键设计：**同时预测 ETA + 距离 + 路段数**——共享底层
   - 关键能力：**辅助任务提升主任务**
   - 关键数字：**误差再 -0.5 分钟**

4. **TF Serving（核心）**
   - 关键设计：**TF Serving + 自研 RPC + 预热**
   - 关键能力：**毫秒级推理——靠 TF Serving + RPC 预热避免冷启动把单次推理拖长**
   - 关键数字：**P99 < 50ms**

5. **自研深度学习平台（核心创新）**
   - 关键设计：**训练 / 部署 / 监控一体化**，支持**多城市模型并行**
   - 关键能力：**千城市独立优化**
   - 关键数字：**覆盖 100+ 城市**

**该出行公司 ETA 预估关键数字**（[案例 2019-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **ETA 误差** | 8 分钟 | 5 分钟 | **-38%** |
| **用户体验** | 基线 | +20% | **+20%** |
| **推理 P99** | — | < 50ms | **—** |
| **覆盖城市** | — | 100+ | **—** |
| **多任务辅助** | — | 误差再 -0.5 分钟 | **—** |
| **日订单** | — | 千万级 | **—** |
| **时空特征** | 不可用 | 30 维 | **∞** |

**具体数字（How much）**

- 团队规模：该出行公司 ETA 算法团队 30+ 人
- 关键数字：**误差 5 分钟 / 体验 +20%**；**P99 < 50ms**；**100+ 城市**
- 业务影响：覆盖该出行公司**千万级订单/日**

**失败教训**

- 早期「**用直线距离估时间**」——完全没考虑拥堵、误差大，倒逼**「时空特征 + Wide & Deep」**
- 「**时间不编码**」——直接用「小时」数值使 23 与 0 距离为 23，凌晨 ETA 全部失真，倒逼**「改用 sin/cos 周期编码」**
- 「**单城市单模型**」——北京调好的模型到上海失效、路况完全不同，倒逼**「多城市独立训练 + 共享 embedding」**
- 「**只做点估计不给区间**」——用户看到「5 分钟」实际 12 分钟、体验受损，倒逼**「输出置信区间，按分位数展示」**

### 4.3 某股份制银行"**风控评分 AUC 0.78 + KS 0.45**"5+ 年（2019-2024）

**背景（Why）**

该银行 2019 年面临**风控评分的可解释性硬约束**：
- **信贷申请评分卡**——监管要求**每个拒绝必须可解释**
- **黑盒模型不通过验收**——神经网络虽 AUC 高但**监管拒绝**
- **传统评分卡**靠 Logistic 回归 + WOE 编码——简单但**准确率低**
- **校准必须可靠**——输出概率必须**真实反映违约率**

**触发点（What）**

2019 年该银行启动风控评分（[案例 2019]），目标：
- **AUC ≥ 0.75**、**KS ≥ 0.4**（监管验收线）
- **可解释**——每个变量有 WOE/IV 解释
- **校准**——**Hosmer-Lemeshow 检验通过**

**详细做法（How）**

该银行风控评分的**5 大核心组件**：

1. **Logistic 回归（核心创新）**
   - 关键设计：**简单可解释**——每个系数 = 变量权重
   - 关键能力：**监管可解释——每个系数对应一个变量的权重方向，拒绝理由能逐条说清**
   - 关键数字：**AUC 0.78**、**KS 0.45**
   - 公式：
     ```
     P(default) = 1 / (1 + exp(-z))
     z = β0 + β1·WOE(age) + β2·WOE(income) + ...
     # 每个 WOE 已分箱 → 单调性需校验（见失败教训）→ 业务可解释
     ```

2. **WOE 编码（核心）**
   - 关键设计：**连续变量先分箱 → WOE 编码**——单调性需校验（见失败教训）、缺失值有独立箱
   - 关键能力：**支持单变量趋势解释**
   - 关键数字：**单调率 100%**
   - 示意：
     ```python
     # age 分箱 → WOE
     bins = [(0,25),(25,35),(35,45),(45,60),(60,99)]
     for lo, hi in bins:
         bad_rate_bin   = df[(age>=lo)&(age<hi)].target.mean()
         bad_rate_total = df.target.mean()
         woe[lo,hi] = log(bad_rate_bin / bad_rate_total)   # 单调性需校验（见失败教训）
     df['age_woe'] = df.age.map(woe_lookup)
     ```

3. **分数校准（核心）**
   - 关键设计：**Platt Scaling / 等距校准**，让模型输出概率 = 真实违约率
   - 关键能力：**监控告警可信——输出概率对齐真实违约率后，阈值告警不会系统性错位**
   - 关键数字：**Hosmer-Lemeshow 检验 p > 0.05**（通过）

4. **SHAP 解释（核心）**
   - 关键设计：**对单条申请生成变量贡献**——「年龄贡献 +30 分、收入贡献 -50 分」
   - 关键能力：**客户能看懂拒绝原因**
   - 关键数字：**解释覆盖率 100%**

5. **自研评分卡平台（核心创新）**
   - 关键设计：**分箱 + WOE + LR + 校准一体化**
   - 关键能力：**业务分析师能自助建卡**
   - 关键数字：**建模周期 1 个月 → 1 周**

**该银行风控评分关键数字**（[案例 2019-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **AUC** | 基线 | 0.78 | **0.78** |
| **KS** | 基线 | 0.45 | **0.45** |
| **单调率** | — | 100% | **—** |
| **校准检验 p 值** | — | > 0.05 | **—** |
| **解释覆盖率** | 0 | 100% | **∞** |
| **建模周期** | 1 个月 | 1 周 | **-75%** |
| **Logistic + WOE** | 未建设 | 已覆盖 | **新增能力** |
| **监管验收** | 未通过 | 通过 | **—** |

**具体数字（How much）**

- 团队规模：该银行风控算法团队 20+ 人
- 关键数字：**AUC 0.78 / KS 0.45**；**解释覆盖率 100%**；**建模周期 1 个月 → 1 周**
- 业务影响：覆盖该银行**全部信贷申请**

**失败教训**

- 早期「**纯黑盒模型**」——神经网络 AUC 虽高但监管直接拒绝，倒逼**「Logistic + WOE + 强可解释」**
- 「**分箱不单调**」——分箱后 WOE 出现「年龄越大违约越低」这类不合理关系，倒逼**「强制 WOE 单调性校验」**
- 「**直接用 LR 输出概率**」——实际违约率 5% 而模型输出 8%，监控告警全部错位，倒逼**「做 Platt Scaling 概率校准」**
- 「**建模周期长、迭代慢**」——一次建模要一个月、无法快速响应业务，倒逼**「把分箱与校验流程工具化，周期压到一周」**

### 4.4 某短视频平台"**完播率预测 + 多模态**"4+ 年（2020-2024）

**背景（Why）**

该短视频 2020 年面临**完播率预测的多模态融合**：
- **每条视频的完播率**——**直接进推荐排序**
- **多模态信号**——画面 / 音频 / 标题 / 字幕，**单模态都不够**
- **完播率预测不准**——推荐排序错乱，**用户体验下滑**

**触发点（What）**

2020 年该短视频启动完播率预测（[案例 2020]），目标：
- **完播率准确**——**+10%**
- **推荐 GMV**——**+8%**
- **多模态统一建模**

**详细做法（How）**

该短视频完播率预测的**5 大核心组件**：

1. **多模态 Embedding（核心创新）**
   - 关键设计：**画面（CLIP）+ 音频（Wav2Vec）+ 标题（BGE）**各自 embedding，拼接融合
   - 关键能力：**多模态联合——画面 / 音频 / 标题三路融合，单模态信息不足时仍能预测完播率**
   - 关键数字：**完播率准确 +10%**
   - 融合示意：
     ```python
     v_emb = clip.encode_video(video)         # 1024 维
     a_emb = wav2vec.encode(audio)            # 768 维
     t_emb = bge.encode(title)                # 1024 维
     fused = mlp(concat([v_emb, a_emb, t_emb]))   # → 256 维
     pred  = completion_head(fused)           # 完播率
     ```

2. **DeepFM 深度模型（核心）**
   - 关键设计：**DeepFM 兜底**——处理「用户 × 视频」交叉特征
   - 关键能力：**捕捉个性化——「用户 × 视频」交叉特征由模型自动学习，不靠人工组合**
   - 关键数字：**推荐 GMV +8%**

3. **多任务学习（核心）**
   - 关键设计：**同时预测完播 + 点赞 + 评论 + 关注**
   - 关键能力：**行为间知识共享**
   - 关键数字：**多任务 +5%**

4. **视频特征（核心）**
   - 关键设计：**视频时长 / 清晰度 / 类别 / 创作者**入模
   - 关键能力：**结构化信号被利用**
   - 关键数字：**特征维度 100+**

5. **推荐集成（核心创新）**
   - 关键设计：**完播率预测直接进排序分**
   - 关键能力：**预测-执行闭环**
   - 关键数字：**推荐 GMV +8%**

**该短视频完播率预测关键数字**（[案例 2020-2024]）：

| **推荐 GMV** | 基线 | +8% | **+8%** |

**具体数字（How much）**

- 团队规模：该短视频推荐算法团队 50+ 人
- 关键数字：**完播率 +10% / 推荐 GMV +8%**；**多任务 +5%**；**特征维度 100+**

**失败教训**

- 「**多模态特征与行为特征不融合**」——两路特征各自入模、互相压制，倒逼**「统一特征平台 + 分桶实验验证增量」**

### 4.5 真实落地路径（基于上述 4 个案例提炼）

**0 → 1 阶段：3-6 个月**

- 选「**Linear / GBDT 起步**」（**最简单**）——**10+ 特征**
- **必须先做特征工程**——>50% 收益在特征
- 团队：**2-3 人**

- 引入「**跨 SKU / 跨城市 / 跨作者**特征」——共享信息
- 团队：5-10 人
- 验证标准：**MAPE -30%**、**AUC +5%**

**10 → 100 阶段：12-24 个月**

- 扩展到「**亿级样本 / 多任务**」

- 引入「**实时特征（Flink）**」——预测可分钟级更新
- 团队：10-30 人
- 验证标准：**效果 -40%**、**实时特征延迟 < 30s**

**100 → 1000 阶段：12-24 个月**

- 引入「**多模态 Embedding**」**（**AI 时代**）**——画面 + 音频 + 文本
- 引入「**可解释 SHAP / 校准**」——监管可验收
- 团队：30-100 人
- 验证标准：**多模态融合 100%**、**可解释 100%**
