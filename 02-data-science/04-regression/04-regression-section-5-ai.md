## 5. 前沿演进（AI 时代）

### 5.1 先分清三类「前沿」

趋势清单的第一个问题是没有时间维度。清单把「用一份预训练权重直接预测一条从没见过的序列」（2024 年前后才有正式发表物的方向）与「把 LLM 打出的情感分数拼进 GBDT 的特征表」（今天多数团队已在离线做）写成同一种句式，读者据此排路线图，多半会先去做那个最写不出验收标准的。

第二个问题是机制差异被抹平。本主题的「前沿」横跨三层，改动它们的东西完全不同：

1. **特征与标签从哪来**（输入侧）：结构化列 → 文本语义列 → 检索到的历史相似场景。
2. **预测的形式**（输出侧）：一个点估计 → 一个分位点或一条区间。
3. **识别假设**（因果侧）：关联 → 效应。

[§3 §3.1](04-regression-section-3-sec3.md) 已把约束写在前面：标签的可观测方式、预测值的用途、一致性与可解释性要求。**第 3 层一条都不是 AI 能改的**——识别假设写在做实验、留干预记录这些设计动作里，不写在模型里；没有处理变量时，估计器再强也只能估关联（[§3 §3.2.6](04-regression-section-3-sec3.md) 的「前提」一段）。AI 真正改变的是第 1 层：特征这一层第一次能从长文本里自动长出来（[§3 §3.2.9](04-regression-section-3-sec3.md)）；第 2 层被改变的不是模型能力，而是损失函数与验收口径（[§3 §3.2.5](04-regression-section-3-sec3.md)）。

第三个问题藏得更深：本主题的多数方向**不是「能不能采购到某个产品能力」，而是「要不要自己按公开方法实现一条通道」**——把一段序列当上下文喂进一份权重、把文本批处理成数值列、用 ML 估 nuisance 参数再对残差正交化，都是后一类。因此判据 ① 按对象分两类核。

三级划分如下，三条判据必须可核验：

- **L1 生产可用**：三条全中才算。① 已 GA 且有正式 release note；② 有**第三方（非厂商）公开的生产案例**；③ 接口稳定、可预期。
- **L2 可试点**：① 成立、② 不成立；或能力已可用而接口 / 生态未稳。**③ 未稳的行只要能力今天可直接取用（有可调用的公开 API 或可安装的实现），就落这一档、不落 L3**——③ 不成立只说明接口形态还在动或关键交接物没有定义，不说明能力取不到。可以做 PoC，不要做核心依赖。
- **L3 观望**：① 不成立——这条机制拿不出正式载体（只有预印本、厂商演示或路线图），或它赖以实现的关键环节在公开材料里没有定义。记录即可，不要在架构里为它预留假设。
- **对 L3 的一处显式修正**（全节只此一处，5.1 表与 5.2.2 的判据均按它核）：若一行的 ① 不成立**仅**因为「赖以实现的关键环节在公开材料里没有定义」、而该机制所依赖的产品能力今天可从公开 API 拿到，则不判 L3，改按 L2 的「能力已可用而接口 / 生态未稳」一档核——缺的是定义与登记动作，不是能力。本节只有「LLM 作为特征生成器」一行落在这条上。

**本主题对本书的 L1 判据 ① 做如下修正，理由是对象不同**：① 的原义是「已 GA 且有正式 release note」。本主题的多数方向对象是**建模机制**而不是可直接采购的产品能力——自己实现的一条时序预测通道、一条文本特征通道、一套效应估计流程，它们没有「GA 产品」这一形态，正式发布物就是论文与公开实现。因此 ① 按对象分两类核，全节统一适用：**产品能力类**（要落地就得先拿到某一项产品能力：LLM 的结构化数值输出、分位数目标函数、保形校准流程）要求该能力项有版本化文档或 release note；**建模机制类**（时序基础模型、LLM 特征通道、因果估计器、物理信息回归、表格基础模型、联邦聚合、自动化建模流水线）要求该机制有可核验的正式载体——同行评审的会议或期刊论文，或带版本化发布记录的公开实现。只有预印本、厂商演示或博客，或该方向赖以实现的关键环节（上下文与权重的适用边界、提示词与模型版本作为特征定义、倾向得分与处理记录的留存）在公开材料里没有定义的，① 判不满足。**② 与 ③ 按本书 L1 判据（§5.1）原文核，不做修正**——② 仍是本节全部方向的上限。

判据 ② 在本主题格外难过，原因值得先说清：**回归效果的公开材料天然是建设方自述**。误差类指标（RMSE / MAPE / WAPE）对切分方式、预测步长、是否做尺度归一极其敏感，这些口径都握在发布方手里；论文一侧则几乎全是公开数据集上的指标，与业务里的标签口径隔着一层。**② 只有「满足」与「降为 L2」两种命运**：它不能改写成「有公开效果数字」，也不能靠「本节只评估某一层」把适用范围缩小来绕过去。

还要说清 L2 在本节的含义：它标的是**证据缺口或接口未稳**，不是「不建议用」。当一行的 ① 成立而缺 ② 时，缺的是「别人用过、并且公开说了代价」这类材料，不是能力本身；③ 未稳的行则是接口与适用边界还在动，能力今天同样可取用。采不采用由读者按自己的风险偏好决定，判据本身不因这句说明而放宽。

③ 分三档，全节统一：接口多年不变为**满足**；形态趋于一致但仍有未定部分为**大体满足**；接口本身还在变动、或关键交接物没有定义为**不满足**。

**本节没有一行达到 L1。** 最接近的是五行——时序基础模型、因果估计器、物理信息回归、可解释回归、区间与不确定性输出：这五行的 ① 满足、③ 满足或大体满足（上下文与预测长度、X/T/y 与 CATE 的输入输出形态、归因接口、`objective` 与分位参数多年未变），差的只有 **②**：本节给不出「建设方之外的机构在生产里用过、并公开了代价」这类材料。判断某条方向是不是 L1，不要看它由多少厂商支持，看第 ② 条的材料是不是**发布方之外的机构**给出的。

拿到任何一条方向，按顺序问三句就能自己核一遍：① 它的正式载体能不能找到（产品能力类看 release note 或版本化文档，建模机制类看同行评审论文或带版本记录的公开实现）？找不到 → L3（唯一例外是「LLM 作为特征生成器」一行，它缺的是关键环节的定义而不是能力，按 L2 核，理由见上文对 L3 的修正）。② 建设方之外的证据能不能找到？找不到 → L2。③ 接口明年会不会变？会变 → 至多 L2。

### 5.2 演进方向逐条拆解（核心节）

下面四个小节都按同一套结构写：**旧做法卡在哪 → AI 改变了什么机制 → 由此得到什么 → 由此付出什么 → 证据与来源 → 成熟度**。只写收益不写代价的方向，评审时应直接打回——回归的每一次能力提升，都对应一项成本结构的变化。

#### 5.2.1 时序基础模型：把「一个序列一套参数」换成「一份权重 + 一段上下文」

- **旧做法与它的卡点**：时序预测的旧做法是「一个序列（或一组同源序列）一套参数」——ARIMA 选阶数与差分次数、Prophet 手配节假日与变点、DeepAR 为每个数据集训一份权重。卡点在三处叠加：每个序列都要自己的参数选择与平稳性检验流程，维护面按序列数放大（[§3 §3.2.4](04-regression-section-3-sec3.md) 的代价一段）；新序列上线时没有历史可拟合，冷启动只能等；跨序列共享的只是特征工程经验，不是参数。
- **AI 改变了什么机制**：把「为每个序列学一套参数」换成「**一份预训练权重 + 在上下文窗口内做条件预测**」。机制上换掉的是参数的复用单位——从序列级变成跨序列级；预测任务的数学形式没有变，它输出的仍然是数值（或数值的分位数）。
- **由此得到的**：因为模式被压缩在权重里、每个新序列只需作为上下文喂进去，**所以**一条没有历史的新序列能立刻拿到非平凡预测，冷启动从「等够历史」变成「有上下文即可」；**又因为**预测是前向推理而不是逐序列拟合，**所以**上线一条新序列的边际工程量从「一次建模」降到「一次推理」——这两条合起来是它对平台团队的价值，与单点精度谁高谁低无关。
- **由此付出的**：**其一，上下文与算力成为新的成本项**——预测代价从一次函数求值变成一次注意力前向，延迟与算力随上下文长度增长【经验】。**其二，权重是黑盒资产**——预训练语料的构成决定它在哪类序列上退化（强间歇、高频、结构性断点），而这一点读模型卡读不出来，只能用自己的数据测。**其三，评估口径不可比**——公开评测的胜负依赖回测切分、预测步长与尺度归一，换一个口径结论可能翻转，所以「某基础模型比你的专用模型好」这类断言在自有数据上必须重测。
- **证据与来源**：【公开】Chronos（Ansari 等，2024）、TimesFM（Das 等，ICML 2024）、MOIRAI（Woo 等，ICML 2024）是该方向有正式发表物的代表；Lag-Llama 与 Nixtla 的 TimeGPT 的公开载体以预印本与产品文档为主（篇名与发表状态以论文库与官方文档当前版本为准）。**② 不满足**：本节给不出建设方之外、含回测口径与算力成本的公开生产案例。
- **成熟度**：**L2**（与 5.1 表「时序基础模型」行一致）：① 满足、③ 大体满足、**② 不满足**。

```text
机制差别只在一处：参数归谁
  旧：序列 A → 拟合 → θ_A     序列 B → 拟合 → θ_B     序列 C →（无历史，无法拟合）
  新：权重 W（预训练一次）──┬─► 上下文 [A 的历史] ──► 预测 A 的后 30 步
                            ├─► 上下文 [B 的历史] ──► 预测 B 的后 30 步
                            └─► 上下文 [C 的少量点] ─► 预测 C（冷启动有解）
  ────────────────────────────────────────────────
  没有改变的东西：预测仍是「给一段数值、要一段数值」
  改变的东西：参数的复用单位，以及新增一条序列的边际成本
  新增的登记项：权重版本 + 预训练数据口径（换权重 = 换整条预测分布）
```

**怎么判断该不该把它接进来**（三项都不需要新采购）：把你的序列按「历史长度」分层，看冷启动那一层的占比——那是它唯一的确定性收益面；用你自己的回测口径（切分点、步长、尺度归一）把基础模型与现役模型跑一遍同表对照；量一次单批预测的算力与延迟，因为预测代价从函数求值变成了前向推理。

#### 5.2.2 LLM 作为特征生成器：把「人写规则」换成「一次离线批处理」

- **旧做法与它的卡点**：长文本（评论、工单、商品描述）要进回归模型，旧做法是人工定维度、抽样标注、训一个小模型，或干脆写词典规则。卡点是覆盖与成本同时不达标：人工定维度的速度跟不上文本形态变化，标注样本量级撑不起细分维度，词典一遇新表达就失效（主文件 §1.2 痛点 2「特征工程」）。
- **AI 改变了什么机制**：把「人写规则 / 人标样本」换成「**LLM 在离线批量里把一段文本映射成固定维度的数值列**」（有序分数或向量）。换掉的是特征这一层的产生方式，回归器本身没变——[§3 §3.2.9](04-regression-section-3-sec3.md) 的边界写得很清楚：LLM 只负责「把文本变成数」，回归器负责「把数变成预测」。
- **由此得到的**：因为语义被压成固定维度，**所以**回归器能用上人工写不出来的文本信息，而不必在线上承担模型调用延迟——文本侧成本被离线批处理摊薄；**又因为**输出是数值列，**所以**它可以与既有结构化特征表按列拼接，GBDT 或线性回归这一侧一行不改，改造范围被限制在特征管线内。
- **由此付出的**：**其一，失效面扩到两段管线**——换一次提示词或模型版本，特征分布就整体漂移一次，而回归器是在旧分布上训练的；监控指标（非空率、长度分布）全部正常，故障只能从预测分布本身发现（[§3 §3.2.9](04-regression-section-3-sec3.md) 的失效点）。**其二，特征不可复现**——提示词与模型版本若不进登记，「这批预测是谁算出来的」无法回答，跨期对比不成立。**其三，标签噪声会被当信号学走**——在无人工校准的情况下直接拿 LLM 打出的分数当回归标签，噪声会被回归器拟合（[§3 §3.2.9](04-regression-section-3-sec3.md) 的真实使用一段）。**其四，成本从训练转到推理**——离线批处理成本随时长与调用量线性增长，且改口径就要重跑历史以保持一致性。
- **证据与来源**：【公开】把 LLM 输出作为特征或标签再喂传统模型是公开文献与工程资料里的通行做法（可按 `LLM as feature extractor` / `LLM-augmented` 一类关键词自行检索核验）；结构化数值输出能力在主流 API 上有版本化文档（各厂商能力名与配置项不同，请以各自官方文档当前版本为准）。**① 不满足**：本条按 5.1 对 ① 的修正判为建模机制类，赖以实现的关键环节——提示词与模型版本作为特征定义——在公开材料里没有定义。**② 不满足**：本节给不出建设方之外、含成本与漂移处置的公开生产案例。
- **成熟度**：**L2**（与 5.1 表「LLM 作为特征生成器」行一致）：① 不满足、③ 不满足、**② 不满足**；级别不是 L3，依据是 5.1 对 L3 的显式修正——结构化数值输出今天就能从公开 API 拿到，缺的是特征定义与登记动作，不是能力。

```text
两段管线，边界在特征层（版本登记是这条边界能否成立的前提）
  [文本：评论 / 工单 / 商品描述]
        │  ① 离线批量：LLM 批处理（不是在线逐次调用）
        │     登记项：提示词版本 + 模型版本 + 输出字段定义
        ▼
  [定长数值列] ── 按列拼接 ──► [结构化特征表] ──► GBDT / 线性回归 ──► ŷ
  ────────────────────────────────────────────────
  在线只跑右侧：文本侧成本被离线摊薄
  失效路线：换提示词或换模型版本 → 左侧分布整体漂移
            右侧模型没有任何感知，只有预测分布会变
```

**最容易被忽略的一次性动作**：把「提示词版本 + 模型版本」当成特征定义写进特征仓库的元数据。这与 [§3 §3.2.9](04-regression-section-3-sec3.md) 的失效点对应——没有这两项，漂移无法归因，回滚也没有落点。

#### 5.2.3 因果估计器：AI 换的是估计器，不是识别假设

- **旧做法与它的卡点**：「给谁发券」这类决策，旧做法是 A/B 实验加分层看均值，或直接对结果跑一个带处理变量的回归。前者的卡点是细分人群一多，样本量按分组数摊薄，长尾人群永远测不出显著；后者的卡点更根本——观测数据里处理变量与结果共享混淆变量，回归系数估的是关联，不是干预的增量（[§3 §3.2.6](04-regression-section-3-sec3.md) 的「被什么约束逼出来」）。
- **AI 改变了什么机制**：把「用一个回归系数代表处理效应」换成「**用 ML 估计 nuisance 参数、对残差正交化后再估异质效应**」（双机器学习 / Meta-Learner / Causal Forest）。换掉的是估计器这一环；**识别假设没有被换掉**——数据里没有干预记录、或倾向得分接近 0 或 1 时，模型再强也估不出效应。
- **由此得到的**：因为处理效应被显式参数化成 x 的函数 τ(x)，**所以**「该给谁发券」从「平均涨了多少」变成「哪些人涨得最多」，实验没覆盖到的细分人群第一次能拿到模型内插的效应估计；**又因为** nuisance 参数用交叉拟合估出、把混淆结构显式建模，**所以**在识别假设成立时估出的是干预的增量而不是关联——这是它能直接支撑动作，而不只是解释历史的原因。
- **由此付出的**：**其一，结论无法用单一指标验收**——预测精度可以用 RMSE 验收，效应估计只能靠模拟数据、安慰剂检验与实验对照交叉验证（[§3 §3.2.6](04-regression-section-3-sec3.md) 的代价）。**其二，数据要求高且事后不可补**——倾向得分与处理记录必须埋点时就留下，很多团队的历史数据因此根本用不了。**其三，外推区间的估计完全由模型形式决定**——倾向得分接近 0 或 1 的那部分人群没有可比的对照，τ̂(x) 在那里不是数据说的（[§3 §3.2.6](04-regression-section-3-sec3.md) 的失效点）。**其四，要同时维护结果模型与处理模型两套口径**，任一侧变了，效应估计就静默偏移。
- **证据与来源**：【公开】Causal Forest（Wager & Athey，JASA 2018）、双机器学习（Chernozhukov 等，The Econometrics Journal 2018）是该方向的两篇奠基工作；EconML 与 CausalML 是带版本化发布的公开实现。**② 不满足**。
- **成熟度**：**L2**（与 5.1 表「因果估计器」行一致）：① 满足、③ 满足、**② 不满足**。

```text
估计器换来的是「异质性可估」，不是「因果可识别」
  数据侧必须已经存在：处理变量 T + 干预记录 + 协变量 X + 结果 y
        │
        ├─ 有 T、且倾向得分不贴 0/1 ──► DML / Causal Forest 可估 τ(x)
        └─ 无 T，或无重叠 ───────────► 任何估计器都只能给关联，或给模型形式的外推
  ────────────────────────────────────────────────
  这条链路上 AI 改的是估计量；
  识别假设与数据留存是设计动作，改不了也补不了。
```

#### 5.2.4 其余方向为什么停在这里

下面 8 条同样按六行结构写：它们停在低处不是因为看不到收益，而是因为判据过不去；把理由拆成六行，是为了让「停在这里」这个判断能被逐条复核。

- **回归 + RAG 检索相似场景 · 旧做法与它的卡点**：新场景没有可比的历史参照，分析师靠记忆与人工翻报告找相似案例，覆盖窄且不可复现。四类落点是股价预测（检索相似市场环境）、销量预测（检索相似营销活动）、政策效果评估与营销决策（检索相似场景的因果分析报告）——四者卡在同一处：相似与否没有口径。
- **回归 + RAG 检索相似场景 · AI 改变了什么机制**：把「人工找相似场景」换成检索——**换的是输入侧的信息来源，不是回归器**；相似度判据（口径、时段、渠道）仍要人先定义。
- **回归 + RAG 检索相似场景 · 由此得到的**：**如果**检索命中确与目标场景同分布，它能为预测提供一个可比参照，并让「为什么这么预测」有材料可依。
- **回归 + RAG 检索相似场景 · 由此付出的**：检索得准与预测得更准之间没有共同度量——召回率上升不等于误差下降；且一旦把检索内容交给生成模型写成解释，幻觉会被当作依据进入决策文件。
- **回归 + RAG 检索相似场景 · 证据与来源**：公开材料以论文与工程博客为主，没有可点名的正式发布物；**① 不满足**；**② 无**。
- **回归 + RAG 检索相似场景 · 成熟度**：**L3**（与 5.1 表一致）：① 不满足、② 无。

- **因果基础模型 · 旧做法与它的卡点**：因果推断一直依赖「为每个场景重做一次识别设计」，估计器与场景强绑定，跨场景复用不了。
- **因果基础模型 · AI 改变了什么机制**：把因果估计表述成可预训练的任务（大模型预训练 + 因果微调），并尝试用模型从文本里找出工具变量等识别要素——**换的是估计器的复用方式，识别假设仍在数据与设计里**。
- **因果基础模型 · 由此得到的**：**如果**跨场景复用成立，同一份权重可以省掉每个新场景的一次估计器选型与调参。
- **因果基础模型 · 由此付出的**：跨场景复用的验收判据本身就是空缺——「这个模型在新场景估出的效应是对的」需要该场景有实验对照，而有实验对照的场景本来就不需要它；且 LLM 找出的工具变量是相关性候选，不是识别论证，误用会把无效工具当有效工具。
- **因果基础模型 · 证据与来源**：公开载体以预印本与厂商演示为主，未见该机制的可核验正式载体；**① 不满足**；**② 无**。
- **因果基础模型 · 成熟度**：**L3**（与 5.1 表一致）：① 不满足、② 无。

- **物理信息回归（PINN）· 旧做法与它的卡点**：数据稀缺但物理规律已知（守恒、传热、结构方程）时，纯数据驱动会给出违反物理的预测，而数值仿真贵到不能逐次调用（[§3 §3.2.8](04-regression-section-3-sec3.md) 的「被什么约束逼出来」）；四类应用——天气预报、流体仿真、材料科学、医疗仿真——共同点正是「方程已知、观测稀缺」。
- **物理信息回归（PINN）· AI 改变了什么机制**：把物理方程作为**损失函数的一项**（方程残差在配点上计算），而不是后处理约束——换的是约束进入训练的位置。
- **物理信息回归（PINN）· 由此得到的**：因为方程残差进了损失，模型在无观测区域也被物理牵引，泛化不再只依赖观测点密度。
- **物理信息回归（PINN）· 由此付出的**：数据项与物理项的权重与配点采样策略没有理论最优解，权重失衡时会出现「处处满足方程却与观测有系统偏差」的解（[§3 §3.2.8](04-regression-section-3-sec3.md) 的失效点）；训练成本高，每个配点都要自动微分。
- **物理信息回归（PINN）· 证据与来源**：【公开】Raissi、Perdikaris、Karniadakis，Journal of Computational Physics 2019；DeepXDE 是带版本化文档的公开实现。**② 不满足**。
- **物理信息回归（PINN）· 成熟度**：**L2**（与 5.1 表一致）：① 满足、③ 大体满足（损失形式与配点策略没有统一接口）、**② 不满足**。

- **可解释回归 · 旧做法与它的卡点**：结论要能写进决策文件时，「这个特征每变化一个单位、输出变化多少」必须给得出；高容量模型的内部结构给不出这句话（[§3 §3.2.2](04-regression-section-3-sec3.md) 的「为什么有效（因果句）」一段）。
- **可解释回归 · AI 改变了什么机制**：**这一条不是 AI 改的**——SHAP 与 LIME 都早于生成式 AI，它们改的是「把黑盒输出分摊到输入特征上」这一步的算法。AI 时代真正变化的是**被解释对象**：特征表里多了 LLM 生成的数值列之后，解释要连带回答「这条解释属于哪个提示词与模型版本」。
- **可解释回归 · 由此得到的**：因为归因可以逐样本给出，高容量模型第一次能进入需要逐条审阅的流程（金融风控的信贷与保险定价、医疗、政策评估）。
- **可解释回归 · 由此付出的**：归因方法的结论互不一致——同一模型换一种归因算法会得到不同的特征排序，而这个分歧没有「谁对」的判据；且归因解释的是模型，不是数据里的因果（与 5.2.3 是两件事）。特征侧一旦来自 LLM，解释还会随提示词版本一起失效。
- **可解释回归 · 证据与来源**：【公开】SHAP（Lundberg & Lee，NeurIPS 2017）、LIME（Ribeiro 等，KDD 2016）；EBM 有带版本化发布的公开实现。**② 不满足**。
- **可解释回归 · 成熟度**：**L2**（与 5.1 表一致）：① 满足、③ 满足、**② 不满足**。

- **Agent 驱动的回归 · 旧做法与它的卡点**：回归从「发现该建什么模型」到「上线并重训」是一条人工流水线，每一步都要人判断（主文件 §1.2 痛点 7「评估与业务对齐」）。
- **Agent 驱动的回归 · AI 改变了什么机制**：把这条流水线的若干步表述成可调用的工具与可自动化的决策——**换的是流水线的组织方式，不是回归的数学**。
- **Agent 驱动的回归 · 由此得到的**：**如果**评估协议已经机械可执行（切分固定、指标固定、对照固定），那么「扫数据、提候选、跑对照」这几步可以自动跑，人的工作收缩到「定义目标与验收标准」。
- **Agent 驱动的回归 · 由此付出的**：回归的验收标准恰恰是最难机械化的那一项——标签口径、切分方式、业务对齐都是判断题，自动挑出来的「更好」只对指标成立；且自动重训会放大 5.2.2 与 5.2.3 的静默失效（特征分布漂移、口径偏移）而无人发现。
- **Agent 驱动的回归 · 证据与来源**：公开载体以预印本与产品演示为主，本节核不到同行评审的正式载体或带版本化发布记录的公开实现；产品能力类那一支同样不成立——没有把「自动发现并上线回归任务」作为能力项的正式发布；**① 不满足**（本条按建模机制类核，见 5.1 对 ① 的修正）；**② 无**。
- **Agent 驱动的回归 · 成熟度**：**L3**（与 5.1 表一致）：① 不满足、② 无。

- **区间与不确定性输出 · 旧做法与它的卡点**：下游决策用的常常不是均值，而是「最坏情况大概多少」；MSE 训练出的点估计回答不了这个问题（[§3 §3.2.5](04-regression-section-3-sec3.md) 开头写的就是这条约束：「两者被同一个约束逼出来：下游决策用的不是均值，而是一个区间或一个分位点」）。
- **区间与不确定性输出 · AI 改变了什么机制**：把损失函数从误差平方换成非对称分位损失，或在一个留出的校准集上把点预测转成区间频次保证。**这条方向改的是损失与验收口径，不是模型容量**——它不需要新模型。
- **区间与不确定性输出 · 由此得到的**：因为最优解从条件均值变成条件分位数，模型能回答「90% 的样本低于它」；因为校准流程只需一个留出的校准集，区间输出可以套在**任意**现役模型外面，改造范围比换模型小一个量级左右【经验：视分位点数与现役模型的训练成本，通常 5–20 倍】（只新增一段校准流程与一套覆盖率验收，不重训、不切换模型）。
- **区间与不确定性输出 · 由此付出的**：分位数由多个独立单分位模型分别预测时会出现分位交叉（90 分位低于 80 分位），下游会拿到互相矛盾的行动建议（[§3 §3.2.5](04-regression-section-3-sec3.md) 的失效点）；保形预测的覆盖率保证依赖校准集与线上同分布，分布一漂移，覆盖率就只剩名义值；贝叶斯路线的计算成本高出一到两个量级【经验：视特征维度与采样器，通常 10–100 倍】（后验靠 MCMC 采样或变分推断迭代得到，成本随参数维度上升）并要维护先验。
- **区间与不确定性输出 · 证据与来源**：【公开】分位数目标见 LightGBM 与 XGBoost 的版本化文档（可按 `objective` 的可选值核验）；保形预测有专著与公开导论（Vovk 等，2005；Angelopoulos & Bates，2021）。**② 不满足**。
- **区间与不确定性输出 · 成熟度**：**L2**（与 5.1 表一致）：① 满足、③ 满足、**② 不满足**。

- **表格基础模型（TabPFN 一类）· 旧做法与它的卡点**：小样本表格回归只能靠梯度提升加正则与交叉验证硬撑，样本量小到一定程度后，任何需要拟合的模型都是方差主导。
- **表格基础模型（TabPFN 一类）· AI 改变了什么机制**：把「在目标数据上拟合参数」换成「**在合成任务上预训练一次、推理时把训练集当上下文**」——与时序基础模型是同一个机制换位。
- **表格基础模型（TabPFN 一类）· 由此得到的**：因为参数不依赖目标数据，小样本任务上省掉了「调参—交叉验证」这一整套流程，几分钟内能拿到一个基线。
- **表格基础模型（TabPFN 一类）· 由此付出的**：适用边界随每个版本变化（样本量、特征数、类别基数各有上限），这些上限写在版本说明里而不是写在机制里，跨版本不可比；且它给的是基线不是终点，当终点用会跳过特征与口径这一层真正的工作。
- **表格基础模型（TabPFN 一类）· 证据与来源**：【公开】TabPFN（Hollmann 等，ICLR 2023）提出该机制，其后继版本的发表物请按作者与篇名在论文库核验。**② 不满足**。
- **表格基础模型（TabPFN 一类）· 成熟度**：**L2**（与 5.1 表一致）：① 满足、③ 不满足（适用边界与接口随版本变动，按 L2 的第二条通道核）、**② 不满足**。

- **联邦 / 隐私保护回归 · 旧做法与它的卡点**：跨机构联合建模默认要把数据搬到一处，合规与工程成本都过不去；而它成立的前提——各方特征口径可对齐——在多数跨机构场景本就不满足。
- **联邦 / 隐私保护回归 · AI 改变了什么机制**：把「搬数据」换成「搬更新」——各方在本地训练，只交换参数更新。
- **联邦 / 隐私保护回归 · 由此得到的**：**在特征口径可对齐时**，它能在不集中原始数据的前提下扩大可用样本量，这是它唯一的机制性增量。
- **联邦 / 隐私保护回归 · 由此付出的**：上传的更新仍有反演与成员推断风险，需要额外防御；更根本的是特征对齐——各方的同名特征往往不同口径，聚合出来的全局模型没有意义，而这一步没有任何自动化能替。
- **联邦 / 隐私保护回归 · 证据与来源**：【公开】聚合方法的经典出处是 McMahan 等，AISTATS 2017（FedAvg），主流联邦学习框架普遍内置这一算法；**① 满足**；**③ 不满足**——跨机构特征与 ID 对齐没有标准形态；**② 不满足**——本节核不到建设方之外的第三方生产案例。
- **联邦 / 隐私保护回归 · 成熟度**：**L2**（与 5.1 表一致）：① 满足、② 不满足、③ 不满足——聚合能力今天可取用，③ 未稳按 L2 的第二条通道（能力已可用而接口 / 生态未稳）核；缺的是跨方特征对齐，不是聚合能力本身。

把上面几条并排看，停在低处的理由只有两类：**一类是接口还不成立**（PINN 的损失权重与配点策略、表格基础模型的适用边界、联邦的特征对齐），**一类是前提条件不成立**（Agent 驱动的回归需要一个机械可执行的验收协议，而回归的验收恰恰是判断题；检索作上下文需要「相似」有可定义的口径）。判据 ① 与 ③ 讲的是前一类，判据 ② 讲的是后一类——**能拿出「别人在生产里用过」的材料，本身就是前提条件成立的证据**。

### 5.3 与本主题既有栈的接口在哪

回归不是独立系统：它的输入来自特征与标签两侧，输出交给决策与监控两侧。写清接口边界（谁调用谁、以什么形态穿过边界、失败时谁负责）比写「与 X 结合」有用。

| 结合点 | 接口形态 | 谁负责失败 | 现状 |
| --- | --- | --- | --- |
| 特征表 ↔ LLM 特征管线 | 交接物 = 定长数值列 + **提示词版本 + 模型版本** | 拥有提示词的那一侧（换版本等于换特征定义） | 需登记：多数团队不登记提示词版本 |
| 回归器 ↔ 特征仓库 | 以「同名特征唯一一份定义」为接口；训练与在线必须同源 | 特征侧（口径分叉不会被离线评估捕捉，只会静默掉线上指标） | 既有技术，口径对齐是持续成本 |
| 时序基础模型 ↔ 预测服务 | 以「权重版本 + 上下文长度 + 预测长度 + 输出分位」为接口 | 拥有权重登记的一侧（换权重 = 换整条预测分布） | 需登记：权重版本常不进变更记录 |
| 分位数模型 ↔ 库存 / 风控决策 | 以「决策分位点」为接口；分位点由缺货与积压成本的比值推出，不由模型默认值决定 | 训练侧（多模型独立训练会出现分位交叉） | 可做：需加覆盖率与单调性验收 |
| 因果模型 ↔ 实验平台 | 以「处理变量 + 倾向得分 + 实验对照」为接口 | 数据侧（埋点没留处理记录，效应事后不可估） | 需自建：多数平台不强制留存倾向得分 |
| 回归 ↔ 监控 | 以「预测分布 + 特征分布」为接口；静默失效只能从分布漂移发现 | 监控侧（点估计指标正常而预测分布已偏，是这类故障的常态） | 部分既有：多数监控只盯误差指标 |
| 检索层 ↔ 回归输入 | 以「检索命中的相似场景 + 相似度判据版本」为接口；检索不到合法场景即视为未命中 | 检索侧（召回率上升与误差下降之间没有共同度量） | 需自建：相似度判据常被当成默认值跳过 |
| 回归 ↔ Agent 平台 | 以「预测值 + 区间 + 模型版本」为接口；Agent 不得自行外推训练标签取值域 | Agent 平台侧（外推的后果由调用方承接） | 未定型 |
| 保形校准 ↔ 校准集 | 以「一个留出的校准集 + 一个分数函数」为接口；校准集与线上分布不一致即失效 | 校准数据拥有方（覆盖率保证依赖同分布前提） | 可做，分布漂移后覆盖率需重测 |

这张表里只有一行算既有能力（特征仓库的同名唯一定义），其余都要新建登记或新建链路。**失败归属必须在设计阶段写清**，否则会退化成扯皮：线上误差掉了，是提示词换了、权重换了、还是分位点被模型默认值顶掉了？三件事都能解释同一个现象，而它们分属三个团队。

**判定这张表有没有被用起来**：每个季度核对两个数【经验：核对频率随变更频率与团队规模变，变更多则缩到每月一次】——本季有多少条特征变更有提示词与模型版本记录，有多少条预测服务变更有权重版本记录。两个数都是零，说明表还停在文档层面。

**官方 release note / 版本化文档**

**本类给的是判定入口，不列证据条目——这是上面开头的门槛在本类上的显式例外，不是省略**：本类给可点名的项目 / 模型或文档页名，加上该页上的核验字段；**年份一律由被点名页面自己的版本记录提供**，本节不转抄。理由是这类页面随版本滚动发布，抄一个没有逐页核对过的年份，比留下核验动作更糟。核验动作只有两个：这一页上有没有一条带年份的正式条目；条目描述的是「已发布」还是「预览」。

- 梯度提升库的目标函数文档：LightGBM 与 XGBoost 的文档里，回归目标与分位数目标（含分位参数）都是带版本沿革的条目，可按 `objective` 的可选值核验这些能力分别从哪一版起提供（**各库的参数名不同，年份与版本以各自官方文档的版本记录为准**）。用途是核验 5.2.4「区间与不确定性输出」一行的 ①：接口是否多年未变。
- 时序基础模型的权重发布与集成文档：检索入口是 5.1 表点名的那几个模型名（Chronos / TimesFM / Lag-Llama / MOIRAI / TimeGPT / UniTime）——模型库上的模型卡与版本记录、预测框架把它列为可选模型时的文档，可用来核验「权重版本」是否存在可引用的发布记录；换权重是否要求重跑对照，也写在这些页面的变更记录里。
- 因果推断库（EconML、CausalML）与保形预测实现（如 `MAPIE` 一类）的版本化文档：核验接口形态（输入 X/T/y、输出 CATE 与区间）是否稳定；年份同样看各项目版本记录页上的发布条目。
- 通用机器学习库的线性模型与统计推断模块：**scikit-learn** 的 `linear_model` 与 **statsmodels** 的 `statsmodels.regression`（`OLS`）两处文档里，系数估计、标准误与置信区间是拟合结果的一等输出，可按 `coef_` / `summary` / `bse` 这类字段核验「一组可逐条审阅的系数 w_j」这一性质自哪一版起稳定提供（**版本沿革以各自官方文档当前版本为准**）。它核的是本节 **5.2.4**「可解释回归」一条与 [§3 §3.2.1](04-regression-section-3-sec3.md) 的「真实使用」一段所依据的同一性质——「这个特征每变化一个单位、输出变化多少」要能写进决策文件；但两个库的指针只在 §3.2.1 的「真实使用」一段，本节 5.2.4 该条点的是归因方法一侧（SHAP / LIME / EBM），不点这两个库；两个项目各有可引用的发表锚点——Pedregosa 等，JMLR 2011（scikit-learn）、Seabold & Perktold，SciPy 会议论文集 2010（statsmodels），篇名与卷期以论文库当前版本为准。

**第三方生产案例**

本节**未能给出**可核验的、含回测口径与代价的第三方回归生产案例。企业落地百分比（沃尔玛 +20% / 联合利华 +15% / 阿里 +15% / 美团 -10% 等）属建设方自述口径（样本、切分、步长、统计口径均在发布方手里），本节不转载。**这个空白本身是结论**：它直接决定了本主题下没有任何方向可以排成 L1。

**引用纪律**：本主题最容易被误引的三类数字是「误差下降百分比」「零样本预测的胜负」「效应估计的提升倍数」。可核验的做法是回到来源找四样东西——切分方式、预测步长、尺度归一、对照条件；缺一个就不要引用这个数。

**怎么用这份清单**：先看你要核的是「特征从哪来」还是「参数归谁」。前者的证据看 API 的版本化文档（更新快、可核验性高，但只证明能力存在）；后者的证据看会议论文与公开实现（更新慢，但一篇有实现的论文抵十篇解读）。两类材料都不能替代判据 ②——它们证明的是机制存在，不是有人在生产里用它并承担了代价。

### 5.5 被过度宣传的部分

**「LLM 能端到端把回归做掉」**——实际换的是特征层，不是预测层。原因：连续值的输出精度与可复现性依赖一个可达的数值残差对象，而生成式解码没有「残差」这个可优化的量；把文本变成数是它能做好的部分，把数变成稳定预测是回归器做好的部分（[§3 §3.2.9](04-regression-section-3-sec3.md) 划的就是这条边界）。**它什么时候才会成真**：公开材料给出同口径对照，证明 LLM 直接输出的数值在同一特征下稳定不劣于回归器，且可复现——注意这说的是「数值输出」，不是「会算数」。

**「时序基础模型将取代专用模型」**——实际是给基线清单增加了一个选项，而不是替换掉一整套流程。原因：零样本能力来自「上下文里能看出模式」，而业务序列最贵的失效模式（口径变更、结构性断点、强间歇）恰好是上下文里看不出来的；同时预测代价从函数求值变成前向推理，成本结构整体上移。**它什么时候才会成真**：公开材料里出现带回测切分、预测步长与算力成本的跨域对照，而不是单数据集跑分。

**「因果推断加上基础模型就不再需要实验」**——实际换的是估计器，识别假设一步没动。原因：识别假设写在实验设计、干预记录与重叠条件里，不写在模型权重里；观测数据里没有处理变量时，任何模型都只能估关联（5.2.3 的三行示意）。**它什么时候才会成真**：出现公开材料显示「用观测数据估出的效应与同期随机实验结论一致」，并且在多个场景重复出现——单个场景的一致可能是运气。

这三条有一个共同结构：**把「某一环的成本降了」说成「整条链路可以少一环」**。判断它们何时成真，看的是同一件事——新一代方案有没有自己的成本与口径，并且这个口径能与旧链路逐项对齐。

### 5.6 未来 3–5 年：可证伪的预测

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| 时序基础模型会先成为**基线**而不是**替代品** | 预测框架与云服务的默认流程里出现「基础模型基线 + 专用模型对照」这一固定搭配 | 公开材料在带步长与切分口径的对照中稳定显示基础模型胜过专用模型，并被默认采用 |
| 「LLM 特征」会先进入**离线特征仓库并带版本登记**，而不是进入在线推理链路 | 特征平台的元数据里出现「提示词版本 + 模型版本」字段 | 三年后主流特征平台仍不把生成式特征纳入血缘与版本管理 |
| 因果估计的瓶颈会从「算法」转到「埋点」 | 实验与增长平台的文档里出现「处理变量与倾向得分必须落库」这类强制项 | 公开讨论仍以估计器对比为主，数据侧留存要求不出现 |
| 区间预测会成为高风险决策场景的默认输出形态 | 库存、风控、授信的模型验收文档里出现覆盖率与单调性指标 | 主流工具链的验收仍以点估计指标（RMSE / MAPE）为唯一口径 |

四条都能被**公开文档与实际的验收/发布流程**证实或证伪，不需要内部数据：

- 第 1 条看预测框架的默认流程与文档示例，一到两年见分晓。
- 第 2 条看特征平台的必填字段，一到两年。
- 第 3 条看实验平台的埋点规范，两到三年。
- 第 4 条看验收文档里的指标清单，一到三年。

最值得先盯第 2 条：它是唯一一条**不依赖任何新产品发布**就能观察到的信号，而且它一旦做不到，其余三条的结论都失去可比性——提示词换了而没人知道，任何跨期对比都不成立。

提醒一句：这四条问的都不是「哪个模型会更强」，而是「**判断依据会不会出现在公开文档里**」。前者无法证伪，后者可以逐条核对。

### 5.7 给架构师的行动建议

| 你的处境 | 现在就该做 | 一年内观察 | 明确不要做 |
| --- | --- | --- | --- |
| 序列多、冷启动差 | 把现役专用模型当基线，接一条时序基础模型通道，用自有回测口径同表对照（5.2.1） | 冷启动层序列的预测误差与算力占比是否同时可接受 | 不要在全量替换前先做权重替换；不要用公开跑分当选型依据 |
| 文本多、特征写不完 | 走离线批处理生成数值列，先把「提示词版本 + 模型版本」登记成特征定义（5.2.2） | 特征平台是否支持生成式特征的版本字段 | 不要在线逐次调用 LLM 生成特征；不要用未校准的 LLM 打标当标签 |
| 要做增量决策（发券 / 定价） | 先查数据里有没有处理变量与倾向得分；没有就先补埋点（5.2.3） | 实验平台是否把倾向得分纳入强制留存 | 不要用观测数据估出的关联冒充效应；不要用归因结果当因果结论 |
| 下游按区间做决策 | 把决策分位点由缺货与积压成本的比值推出，加覆盖率与单调性验收（5.2.4） | 验收文档里的指标清单是否从点估计扩到区间 | 不要为每个分位各训一个模型却不管分位交叉 |
| 想上 Agent 驱动的建模 | 先把评估协议机械可执行（切分、指标、对照固定） | 是否出现可复用的自动建模验收规范 | 不要让 Agent 自动重训并自动上线；不要跳过人工验收 |
| 刚开始建回归能力 | 先把三样登记成资产：提示词与模型版本、权重版本、特征口径（本节 §5.3） | 有多少条特征与预测变更能追到版本记录 | 不要把建设方自述的百分比写进选型结论 |

「明确不要做」这一列的共用逻辑只有一句：**本节真正变了的只有「特征与参数从哪来」，识别假设与验收口径一寸没动**。所以预算应当投在版本登记、对照集与埋点这三件确定性工程上；这三样没定下来之前，任何「AI 原生回归」的采购都不会带来可度量的收益。

如果只能排一个顺序，按这条走：

1. **先建对照**：固定的切分与回测口径 + 一个留出的校准集。没有它，后面任何改动都无法判断变好还是变坏。
2. **再接一条通道**：LLM 特征通道或时序基础模型通道，作为**并列**能力接入，只对照、不替换。
3. **然后定版本**：提示词版本、模型版本、权重版本、特征口径进变更登记。这一步决定跨期对比有没有意义。
4. **最后才谈 Agent 与因果基础模型**：这两类都会改变流程的层数与责任归属，回滚成本高于前三步。

最后一条提醒：本节所有「现在就能做」的动作都不需要新模型——对照集、版本登记、并列通道、分位点验收，全是流程与工程。这也解释了本节为什么没有 L1：真正成熟的那部分（分位数目标、保形校准、因果估计器）不需要被宣传，而需要被宣传的那部分，还没有成熟到能被建设方之外的人核验。

### 5.8 小结

> 本节小结：AI 在本主题上**只改了一条机制**——特征这一层第一次能从长文本里自动长出来（5.2.2），并顺带把「一个序列一套参数」换成了「一份权重加一段上下文」（5.2.1）。它**没有改变**的是两件事：识别假设写在做实验与留干预记录这些设计动作里，不写在模型里（5.2.3）；验收口径仍然是切分、步长与成本比这些判断题，Agent 接管不了（5.2.4）。本节没有一行达到 L1，最接近的五行——时序基础模型、因果估计器、物理信息回归、可解释回归、区间与不确定性输出——差的只有「第三方（非厂商）公开生产案例」这一条；所以现在该投的是版本登记、对照集与埋点，而不是「端到端 LLM 回归」。
>
> 💡 **思考锚点**：把你线上现役的文本特征列一遍，逐条查它能不能在特征平台里追到"提示词版本 + 模型版本"——追不到的那几条，跨期对比误差变化时，你拿什么判断是提示词换了、权重换了，还是分位点被模型默认值顶掉了？
