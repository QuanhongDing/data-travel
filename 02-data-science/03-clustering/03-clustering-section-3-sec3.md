## 3. 设计模式与范式

### 3.1 先看约束：模式不是选择题，是约束的产物

聚类的模式选择常被讲成「按数据形态挑一个算法」。但第一条约束比它更靠前：**你假设一个簇长什么样**。K-Means 假设簇是围绕质心的球；DBSCAN 假设簇是密度连通的一块；层次聚类假设簇是树上的一棵子树；谱聚类假设簇是图上切一刀切出的连通块；GMM 假设簇是一个高斯分布。同一份数据上这五种假设给出的答案并不相同，而且**都不是错的**——错的是把某一种假设当成了事实。

第二条约束是**相似度从哪来**，这是聚类里唯一无法由算法补救的输入。距离度量（欧氏 / 余弦 / Jaccard / 汉明）与特征量纲一旦定错，任何算法都只能在错的空间里分组：文本用欧氏距离、类别特征 One-Hot 后算欧氏距离、年龄与收入不做标准化直接聚类，这三类错误不会让算法报错，只会让结果无意义。

第三条约束是**无监督评估证明不了正确性**。轮廓系数、CH、DBI 全都是几何一致性度量——它们能说明"簇内紧、簇间松"，不能说明"这几个群是业务上真实存在的"。这条约束的直接后果是：聚类必须配一个业务可解释性环节（人工 review、命名、用标签驱动一个实际动作），否则再漂亮的指标也无法验收。

第四条是**规模与复杂度的硬上限**。聚类算法的时间复杂度从 O(NKT) 到 O(N²) 到 O(N³) 跨了三个量级，N 一变，可选的算法集合就会整体换一批——这不是性能调优问题，是可行性问题。以上四条是聚类特有的约束，下表把它们与另外两条工程侧约束（是否必须预先指定 K、稳定性与可复现要求）一并列出；后两条不改变「正确的簇是什么」，只决定结果能不能以可接受的成本跑出来、能不能稳定地进下游。

| 约束 | 它决定了什么 | 本主题下最容易被它推翻的直觉 |
| --- | --- | --- |
| 簇的定义（质心 / 密度 / 连通 / 概率） | 决定算法族，也决定了它会以什么形状失效 | 「聚类有标准答案」——没有，数据的形状决定了正确的簇定义 |
| 相似度是否可信（度量 + 量纲 + 编码） | 决定欧氏 / 余弦 / Jaccard，决定必须先做什么预处理 | 「换个算法就行」——度量错了，任何算法都在错的空间里分组 |
| 无监督评估与业务可解释性（指标 → 人工 review → 标签字典） | 决定要不要 LLM 命名与人工 review、要不要落标签字典供下游读 | 「指标达标就算做完」——几何指标说明不了簇业务上真实存在，下游看不懂的簇进不了运营动作 |
| 规模 N 与复杂度上限 | 决定能不能构造距离矩阵、要不要两阶段、要不要抽样 | 「先跑一次看看」——层次聚类 N=10⁷ 需约 5×10¹³ 次距离计算【推算：N(N−1)/2，N=10⁷】 |
| 是否必须预先指定 K | 决定 K-Means / GMM 还是密度、层次、主题模型 | 「K 必须事先知道」——K 可来自密度结构，也可来自业务分层需要 |
| 稳定性与可复现要求 | 决定要不要多 seed / 多算法投票，标签能不能直接当特征 | 「聚类标签就是标签」——单次结果不稳定时它只是一次抽签 |

### 3.2 模式逐个拆解（核心节）

#### 3.2.1 K-Means / GMM 起步（含 K-Medoids）

- **被什么约束逼出来**：低维数值型数据、需要最快拿到第一版分群，且工程上要求结果可增量、可解释。
- **结构**：
  ```text
  K-Means：交替执行两步，直到质心不再移动
    分配：C_k = { x : ‖x − μ_k‖ ≤ ‖x − μ_j‖, ∀j }
    更新：μ_k = mean(C_k)      ← 最小化 WCSS = Σ_k Σ_{x∈C_k} ‖x − μ_k‖²
  复杂度 O(N·K·T)；K-Medoids 用实际样本做中心（抗离群点），代价升到 O(N²)
  GMM：软分配  p(x) = Σ_k π_k · N(x | μ_k, Σ_k)；EM 迭代（E 步求后验 γ_zk，M 步更新参数）
  输出：cluster_id / 质心 / 簇内距离，与特征表并排落库供下游关联
  ```
- **为什么这样设计有效**：因为目标函数是「点到所属质心的距离平方和」，每一步迭代都让它单调下降，所以算法必然收敛；每轮只需要一次全量距离计算，成本线性于样本数（O(N·K·T)），所以可以用小批近似把十亿级样本分批消化【推算：N=10⁹、K=10²、T=20 即约 2×10¹² 次距离计算，全量单批不可行；Mini-Batch 每轮只对抽样小批计算，单轮成本随批大小而不是 N 增长】。同等规模下，带空间索引的 DBSCAN、BIRCH 的 CF 摘要（见 3.2.7）与流式 K-Means 也各有可行实践，选哪条路取决于是否需要形状无关与噪声输出。
- **代价**：必须预先给 K；平方距离把离群点的影响放大，一个极端点就能把质心拖走；必须先做标准化，否则量纲大的特征独占距离；只输出一次划分，拿不到「从粗到细」的层次。
- **失效点**：当簇是非凸形状（同心环、月牙）或大小悬殊时，K-Means 会切出错误边界，而且轮廓系数可能依然不低——机制是它优化的是簇内方差而不是连通性，在环形数据上「切成两半」的方差确实比「还原环形」更小，所以指标不会替你报警。
- **真实使用**：K-Means 由 MacQueen 于 1967 年提出【公开】；scikit-learn 的 KMeans / MiniBatchKMeans 是最常用实现【公开】，Spark MLlib 另提供 KMeans 与流式 StreamingKMeans（可按 Spark 官方文档当前版本核验）【公开】；用户分群、商品分层从 K-Means 起步是通行做法【经验】。

#### 3.2.2 密度聚类（DBSCAN / HDBSCAN）

- **被什么约束逼出来**：簇的形状事先未知，且「噪声本身就是业务产出」（异常交易、离群设备），不能事后另建一个模型去找。
- **结构**：
  ```text
  DBSCAN 三个角色（ε = 邻域半径，MinPts = 核心点最少邻居数）
    核心点：ε 邻域内点数 ≥ MinPts
    边界点：落在某个核心点的 ε 邻域内，自己不是核心点
    噪声点：都不是 → 输出为噪声簇，这本身就是异常检测结果

  HDBSCAN：把 ε 消掉
    1) 互达距离 d_mreach(a,b) = max(core_k(a), core_k(b), d(a,b))
    2) 在该距离上建最小生成树 → 层次结构
    3) 按簇的稳定性（λ = 1/distance，簇存活的 λ 区间长度）选簇
  输出：无需指定 K；可同时给出每个样本的离群分数
  ```
- **为什么这样设计有效**：因为簇的定义是「密度可达的连通块」而不是「到中心的距离」，所以形状不影响判定，「不属于任何核心点邻域」的点被显式标为噪声——异常检测与聚类在一次计算里同时完成。
- **代价**：需要邻域查询，得靠空间索引（kd-tree / ball-tree）撑着；维度升高后索引退化、距离集中，速度与效果同时下降；结果对 MinPts / min_cluster_size 敏感，而参数搜索是在「被标为噪声的比例」与「簇数」之间做权衡，不存在唯一最优解。
- **失效点**：当簇的密度差异明显时（一个密簇 + 一个疏簇），单一 ε 只能适配其中一个：ε 小则疏簇整体变成噪声，ε 大则两簇并成一个——机制是密度聚类用同一个阈值定义「密」，于是「疏」被等同于「不存在」。HDBSCAN 用稳定性部分缓解，但仍要能解释 min_cluster_size 的业务含义。
- **真实使用**：DBSCAN 见 Ester et al., KDD 1996【公开】；HDBSCAN 见 Campello et al., 2013【公开】及其 Python 实现【公开】；用于异常检测与空间数据分组是通行做法【经验】。

#### 3.2.3 层次聚类（输出树状图）

- **被什么约束逼出来**：业务需要的不是一个 K，而是「粗 / 中 / 细三档分层」，并且想知道「哪两个群先并到一起」。
- **结构**：
  ```text
  自底向上（凝聚）：每个点一个簇 → 反复合并最近的两个簇 → 形成一棵树
  簇间距离的四种定义：单链接（最近点） / 完全链接（最远点） / 平均链接 / Ward（簇内方差增量最小）

  dendrogram（在任意高度切一刀 = 取任意 K）
    |              ┌──────────── C
    |      ┌───────┤
    |  ┌───┤       └──────────── B     ← 切在这里 → 3 个簇
    | ─┤   └──────────────────── A
    |  └──────────────────────── D     ← 切在更低处 → 4 个簇
  ```
- **为什么这样设计有效**：因为输出是整棵树而不是一次划分，所以 K 可以事后选，切在不同高度就是不同的粒度，「这个群是什么时候分裂出来的」本身可读——这正好匹配分层运营这类需要多档粒度的业务。
- **代价**：需要全量两两距离，复杂度和存储都是 O(N²)【推算：N 个点两两距离数量 N(N−1)/2，N=10⁵ 即约 5×10⁹，单机内存已难以承载稠密矩阵】；合并是贪心的、不可撤销，合错无法回退；新样本没有天然的增量入口，通常只能重跑。
- **失效点**：当 N 超过十万级【经验】时，「可在任意高度切割、无需预设 K」这个优点会反转成跑不动：它的全部信息都在距离矩阵里，而矩阵规模随 N 平方增长，所以你会先被迫放弃它、退回需要预设 K 的算法——自由的代价是把数据量锁在中小规模。
- **真实使用**：Ward 连接准则见 Ward, 1963【公开】；scipy 的 linkage / dendrogram 与 R 的 hclust 是常用实现【公开】；多用于样本量中小、需要可视化分裂过程的分析【经验】。

#### 3.2.4 谱聚类（处理非凸数据）

- **被什么约束逼出来**：数据本质是「点与点的关系」（图、相似度矩阵），而簇在原始坐标里是非凸的。
- **结构**：
  ```text
  输入：相似度矩阵 W（RBF 核 / k 近邻图）、度矩阵 D（D_ii = Σ_j W_ij）
    1) 拉普拉斯 L = D − W（或归一化形式）
    2) 取 L 的前 K 个最小特征值对应的特征向量（跳过平凡解）
    3) 把 N×K 的特征向量当新坐标，做 K-Means

  直觉：图上切掉权重最小的边 ≈ 最小化图割；特征分解把非凸的原空间
        摊平成「按连通性分组」的空间，再交给 K-Means 收口
  ```
- **为什么这样设计有效**：因为拉普拉斯矩阵的前若干个特征向量编码的是图的连通结构而不是欧氏距离，所以在原空间里不可分的问题（同心环）在这些特征向量里近似线性可分——K-Means 只是最后一步的收口器，真正的分离发生在前一步。
- **代价**：要构造并分解 N×N 矩阵，稠密分解是 O(N³)【推算：K-Means 成本正比于 N·K·T，谱聚类正比于 N³，N=10⁵ 时前者可跑、后者不可跑】；核宽度 σ 或 k 近邻数成为新的关键超参，且输出仍依赖最后那次 K-Means 的随机初值。
- **失效点**：当 N 大到无法显式构造 N×N 矩阵时（十万级【经验】就要转向稀疏近似 / Nyström 采样），「非凸友好」这一优点会被「图只能被近似」抵消——机制是谱聚类的前提是完整图，采样后拉普拉斯矩阵的特征结构已经改变，非凸问题的解不再精确。
- **真实使用**：谱聚类见 Ng, Jordan, Weiss, NeurIPS 2001【公开】；scikit-learn SpectralClustering 提供实现【公开】；更大规模的图社区发现转向模块度优化（Louvain 见 Blondel et al., 2008【公开】；Leiden 见 Traag et al., 2019【公开】）。

#### 3.2.5 深度聚类（DEC / DCN）

- **被什么约束逼出来**：原始特征本身不适合聚类（图像像素、原始文本），需要「边学表示边聚类」，而不是在固定表示上聚一次。
- **结构**：
  ```text
  DEC（Xie et al., 2016）两段式
    ① 预训练自编码器：x ─► z（低维嵌入）─► 重构 x'
    ② 在 z 上初始化 K 个簇中心 μ_k，软分配
       q_ik = (1 + ‖z_i − μ_k‖²)^(−1) / Σ_j (1 + ‖z_i − μ_j‖²)^(−1)
    ③ 构造目标分布 p（把 q 平方后按簇归一化，使其更尖），最小化 KL(p ‖ q)
       ← 自训练：用高置信样本当伪标签，表示与簇中心联合更新
    ④ 保留重构损失，防止表示塌陷成常数
  ```
- **为什么这样设计有效**：因为聚类损失可以反传回编码器，表示会朝「让簇更可分」的方向移动，而不是在固定表示上做一次性划分；平方后归一化的目标分布起锐化作用，让高置信样本拿到更大梯度权重（等价于自训练）。
- **代价**：需要预训练 + 联合微调两阶段，训练成本与调参面远超传统聚类；软分配使结果对初始簇中心敏感；可复现性差——同一份数据换 seed 可能给出不同的簇结构，必须固定种子并报告多次运行。
- **失效点**：当数据本身没有可分的簇结构时，这套自训练机制会把随机初始化的簇中心逐渐「确证」成真实结构——机制是 KL 自训练只有确认偏差、没有反证信号，而轮廓系数会跟着一起变好，无监督评估无法发现它。
- **真实使用**：DEC 见 Xie, Girshick, Farhadi, ICML 2016【公开】；DeepCluster 见 Caron et al., ECCV 2018【公开】；对比聚类（Contrastive Clustering，CC）见 Li et al., AAAI 2021【公开】。

#### 3.2.6 Embedding 聚类（LLM 时代主流）

- **被什么约束逼出来**：文本、图像无法定义可信距离，而预训练编码器能提供一个现成的语义空间；同时业务不想为每个聚类任务单独训一个模型。
- **结构**：
  ```text
  文档 / 图像 ─► 预训练编码器（Sentence-BERT / CLIP / 托管 Embedding）─► 向量
              ─► L2 归一化（余弦等价于点积）
              ─► 降维（UMAP / PCA 到 10~50 维【经验】；密度聚类前常必需）
              ─► 聚类（HDBSCAN 或 K-Means）
              ─► 簇描述（每簇 c-TF-IDF 关键词，或 LLM 命名）

  纪律：编码器版本 = 向量空间版本；换模型必须整库重算，不能新旧混用
  ```
- **为什么这样设计有效**：因为编码器已经把「语义相似」翻译成「余弦距离小」，聚类算法的工作从「理解内容」退化成「在可信度量空间里分组」；而编码器是零样本的，新领域不需要标注与训练就能拿到第一版分组。
- **代价**：全库编码的算力与向量存储（每个对象一份）；向量维度仍然不低（数百维【经验】），密度聚类前通常必须降维；语义相似是「平均语义」，对细粒度区分（同义不同意图）不敏感。
- **失效点**：当编码器的训练目标与你的聚类目标不一致时（用通用语义模型区分工单紧急程度），簇会按主题而不是按业务维度分开，而且轮廓系数可能并不低——机制是相似度由编码器定义，聚类只能放大这个定义、无法修正它。修法是先做内在评估（同义句相似度排序），再做下游任务评估（用簇标签去驱动一个真实动作，看它是否比随机分组更有用）。
- **真实使用**：Sentence-BERT 见 Reimers & Gurevych, EMNLP 2019【公开】；CLIP 见 Radford et al., ICML 2021【公开】；近邻检索库见 Faiss, Johnson et al., 2017【公开】；「Embedding + 密度聚类」是文本归类的通行做法【经验】。

#### 3.2.7 层次化聚类（粗聚类 + 细聚类）

- **被什么约束逼出来**：N 到亿级后单次聚类跑不动，而且 K 一次定不准，需要「先粗分、再细分」且中间结果可复用。
- **结构**：
  ```text
  阶段一（粗）：Canopy / BIRCH CF 树 / Mini-Batch K-Means
    BIRCH：CF = (N, LS, SS) 三元组压缩子簇（N = 点数、LS = 线性和、SS = 平方和）
           CF 树把 N 个点压成 M 个可配置的 CF 节点，新点沿树下降并按需分裂节点
  阶段二（细）：在 M 个簇摘要（而非原始点）上跑 K-Means / 层次聚类，再回填归属

  为什么可行：CF 满足可加性——两组点的 CF 相加仍是合法 CF，
              所以在摘要上聚类是「在全体点上聚类」的近似
  ```
- **为什么这样设计有效**：因为粗阶段把 N 个点压成 M 个摘要（N ≫ M），而摘要携带点数、线性和、平方和，所以第二阶段的计算量由 M 而不是 N 决定，同时可加性保证了这种近似的合理性——这是让亿级数据在有限时间与内存内跑完聚类的关键。
- **代价**：引入两层近似误差（形状近似 + 摘要近似），结果依赖树的分支因子与阶段二的 K；数据流式到达时摘要会漂移，需要周期性重建；出问题时要跨两个阶段定位，诊断成本高于单阶段算法。
- **失效点**：当 K 的选择问题被「顺手解决」而未被验证时（粗聚类给出初始中心、细聚类直接沿用），错误会被固化——机制是两阶段只降低了计算量，没有提供任何关于 K 正确性的证据；更糟的是当业务需要的是细粒度小簇时，粗阶段的合并会先把小簇吞掉，第二阶段再怎么分也恢复不了。
- **真实使用**：BIRCH 见 Zhang, Ramakrishnan, Livny, SIGMOD 1996【公开】；Canopy 见 McCallum, Nigam, Ungar, KDD 2000【公开】；Mini-Batch K-Means 见 Sculley, WWW 2010【公开】。

#### 3.2.8 联邦聚类

- **被什么约束逼出来**：数据分布在多方且不能出域，但各方需要一套口径一致的簇定义（否则各方的「高价值用户」不是同一件事）。
- **结构**：
  ```text
  各方本地：本地数据 ─► 本地簇 / 本地簇摘要（样本数、线性和、平方和、质心）
              ─► 只上传摘要或加密参数，不上传原始样本
  中心：按样本数加权聚合各方质心 ─► 全局质心 ─► 下发
  迭代：各方按全局质心重新分配 → 再上传 → 收敛

  前提：跨方需要有共享的特征空间（同名字段口径 / 同一 ID 体系）
  风险控制：安全聚合 + 差分隐私（加噪）+ 轮次上限（隐私预算随轮次消耗）
  ```
- **为什么这样设计有效**：因为质心更新只需要「各簇的和与计数」这类可加摘要，所以多方只共享摘要就能算出全局质心，原始样本不出域——这是 K-Means 的更新公式天然允许的，不需要为隐私额外牺牲表达力。
- **代价**：多轮通信与同步开销；跨方特征空间对齐（同名字段的含义、单位、编码）是主要工程成本；差分隐私的噪声随轮次累积、影响簇边界；上传的摘要仍存在反演风险，需要额外防御。
- **失效点**：当各方特征口径不一致时（同名同字段但含义不同），聚合出的全局质心落在任何一方都不描述的位置，各方按它重分配后质量下降——机制是联邦保留的是「数值可加」，不保留「语义一致」，而聚类完全依赖语义一致。
- **真实使用**：FedAvg 见 McMahan et al., AISTATS 2017【公开】；联邦 k-means 的公开研究可按 k-FED / federated clustering 自行检索核验【经验】。

#### 3.2.9 主题建模聚类（BERTopic / Top2Vec）

- **被什么约束逼出来**：文档聚类要的不只是簇，还要「这一簇在讲什么」的标签；而 LDA 这类方法要求预先指定主题数，与「主题事先未知」的发现需求冲突。
- **结构**：
  ```sql
  -- 主题产物落库：主题词 + 归属 + 版本，供检索与人工复核
  CREATE TABLE doc_topic (
    doc_id       BIGINT,
    topic_id     INT,          -- -1 表示噪声 / 离群文档
    probability  DOUBLE,
    model_ver    VARCHAR(32),  -- 编码器 + 聚类 + 主题词同属一个版本
    built_at     TIMESTAMP
  );
  -- topic_word：每簇关键词与权重（c-TF-IDF）
  --   c-TF-IDF(w,t) = tf_{w,t} × log(1 + A / f_w)
  --   tf_{w,t}：词 w 在簇 t 的「超长文档」中的频次；f_w：词 w 在全语料的频次；A：每簇平均词数（该簇全部文档拼成的「超长文档」的平均长度）
  ```
- **为什么这样设计有效**：因为 c-TF-IDF 把「一个簇的全部文档」当作一篇文档来算词频，词的重要性就由「本簇密集、全局稀少」决定，无需任何标注；而簇数由密度或层次结构从数据里得出，不必事先指定主题数——这正好补上了 LDA 最被诟病的那一点。
- **代价**：主题词依赖分词、停用词与语言，多语语料要分别处理；离群文档（噪声簇）是常态而非异常，业务上必须单独定义处置方式；簇数不受控——换一个 min_cluster_size 就换一批主题数，需要人工收敛到可用的粒度。
- **失效点**：当语料把长文与短文混在一起时，「主题可解释」会反转成「看起来像但不可用」——机制是 c-TF-IDF 描述的是词分布而不是语义，长文档因词数多而主导关键词，短文档簇的关键词则由噪声词构成，读起来像主题、实际不对应任何业务概念。
- **真实使用**：BERTopic 见 Grootendorst, 2022【公开】；Top2Vec 见 Angelov, 2020【公开】；LDA 见 Blei, Ng, Jordan, 2003【公开】。

#### 3.2.10 LLM-as-Clusterer

- **被什么约束逼出来**：聚类的消费方是人和业务流程，需要的是「这个群是谁」的自然语言答案，而算法侧只能给出数字标签；「这两簇该不该合并」这类判断也缺少客观指标。
- **结构**：
  ```text
  用法一：命名 / 描述（最常用）
    每簇取代表样本（离质心最近的前 n 个）─► LLM ─► 建议簇名 + 一句话描述
    ─► 人工 review / 修正 ─► 写入标签字典（下游读字典，不现场调 LLM）

  用法二：辅助合并 / 切分判断
    给出两簇的代表样本与关键词 ─► LLM 判断「是否同一个群」─► 作为人工决策的输入

  用法三：额外视角（把 LLM 输出当特征，不当作最终簇）
  边界：LLM 不参与「谁属于哪个簇」的判定，只参与「这个簇是什么」的表达
  ```
- **为什么这样设计有效**：因为 LLM 擅长把一组样本概括成自然语言，而自然语言描述正是运营、报表、标签体系需要的接口，所以用它补上「命名」这一环能显著降低聚类结果被真正使用的门槛；同时归属判定不受它影响，簇的稳定性仍由算法负责。
- **代价**：每次命名都有 token 成本且不可复现（同一簇两次描述可能不同），所以必须把结果落成字典并由人签字；LLM 可能给出与业务口径冲突的名字（把「高退货率用户」说成「活跃用户」），review 环节不可省。
- **失效点**：当簇本身不稳定、而名称先被采用时，命名会把一次随机划分固定成组织事实——机制是标签一旦进入报表与考核就有了惯性，而聚类的可复现性缺陷不会在报表里显示出来，错误因此不可见。
- **真实使用**：用大模型为聚类结果命名与写描述是当前通行做法【经验】；可按关键词 LLM clustering labeling / text clustering with LLM 自行检索核验。

### 3.3 模式选择决策表

| 约束组合 | 推荐模式 | 为什么不选另一个 | 关键判据 |
| --- | --- | --- | --- |
| 大数据 + 低维数值 + 凸形 + 已知 K | Mini-Batch K-Means | 层次 / 谱聚类的复杂度不允许 | N 与距离矩阵、特征分解是否可行 |
| 用户分群 + 行为特征（低维数值、需周期产出标签） | K-Means / Mini-Batch K-Means | 密度聚类给不出可解释的中心，谱聚类与层次聚类的成本不允许周期重跑 | 分群是否要落到运营动作、中心能否被业务读懂 |
| 数据量小 + 需要抗离群点 | K-Medoids | K-Means 的质心会被极端点拖走 | 离群点比例与对中心的敏感度 |
| 需要同时产出噪声 / 异常 | DBSCAN / HDBSCAN | K-Means 没有噪声类，只能事后按阈值切 | 噪声本身是不是业务产出 |
| 簇密度差异明显 + 不想指定 K | HDBSCAN | DBSCAN 单一 ε 无法同时适配密簇与疏簇 | 簇间密度比 |
| 需要多档粒度 / 树状结构 | 层次聚类（Ward 等准则） | K-Means 只给一次划分，看不到分裂过程 | 是否要「从粗到细」解释群的形成 |
| 小到中等规模 + 非凸 + 图 / 关系数据 | 谱聚类 | K-Means 在非凸形状上切错边界 | 是否有可信的相似度矩阵 |
| 大规模图社区 | Louvain / Leiden | 谱聚类的 N³ 分解跑不动 | 图的规模与稀疏度 |
| 大数据 + 仍要树结构 | BIRCH | 凝聚层次聚类的距离矩阵撑不住 | N 与内存上限 |
| 文本主题发现 | BERTopic / Top2Vec | LDA 需预设主题数、且是词袋假设 | 是否需要主题词与可解释标签 |
| 通用文本聚类 | Sentence-BERT + HDBSCAN | 原始词袋 + 欧氏距离在高维稀疏下失效 | 是否有可用编码器 |
| 图像 / 多模态聚类 | CLIP Embedding + K-Means（或自编码器） | 纯像素特征不承载语义 | 模态与语义是否一致 |
| 亿级 / 流式到达 | Canopy 或 BIRCH 粗聚类 + Mini-Batch 或 Streaming K-Means 细聚类 | 全量重跑一次的成本与时效都不允许 | 数据是批量回灌还是持续到达 |
| 高维稀疏文本 + 余弦 | Embedding 归一化 + 余弦距离 + K-Means | 未归一化时欧氏与余弦排序不一致 | 向量是否已 L2 归一化 |
| 隐私 / 跨组织 | 联邦聚类 | 集中式训练不满足合规 | 各方特征空间与 ID 体系是否对齐 |
| 无标签异常检测 | Isolation Forest / DBSCAN | K-Means 的距离阈值随簇大小变化，无法统一 | 异常能否定义为「远 / 孤」 |

本主题下**最常被误选的一对**是「K-Means」与「密度聚类（DBSCAN / HDBSCAN）」。误选的代价不在于分组难看，而在于**错误不会及时可见**：环形或月牙形数据上用 K-Means，它会沿最短的方差路径把结构切成两半，而轮廓系数可能仍然体面，于是团队会带着一个几何上错误的分群去做运营，直到某次归因分析解释不通才回头发现。判据很简单：**先画二维投影，看形状，再选算法**；投影看不见结构时，说明该先换相似度或先降维，而不是先换聚类算法。

### 3.4 组合模式：真实系统不会只用一种

**组合 A：预训练编码器 + 降维 + 密度聚类 + LLM 命名**（文本 / 多模态语义聚类主流）

- 职责边界：编码器定义相似度，降维让密度估计可用，密度聚类给出簇与噪声，LLM 只负责命名；四者各自只做一件事，任一环出问题都能单独替换与评估。
- 组合的运维代价：编码器版本、降维参数、聚类参数三者共同决定结果，必须一起版本化；换编码器要整库重算向量并重跑全链路，标签会因为向量空间变化而不可比。
- 适合规模：文档或 Item 数在十万到千万级、以语义归组为目的的场景【经验】。

**组合 B：粗聚类（BIRCH / Canopy）+ 细聚类（Mini-Batch K-Means）+ 稳定性投票**

- 职责边界：粗聚类负责把 N 压成摘要并给出初始中心，细聚类负责最终划分，稳定性投票负责回答「这个簇标签能不能进下游模型」。
- 组合的运维代价：两层近似叠加，误差归因变难；投票要跑多次聚类，训练成本成倍；摘要需周期性重建，否则描述的是历史分布。
- 适合规模：亿级样本、需要周期性产出分群标签的场景【经验】。

**组合 C：密度聚类 + 异常旁路 + 人工复核**

- 职责边界：密度聚类同时产出簇与噪声，异常旁路单独承接噪声样本（告警 / 转入人工），人工复核负责把簇名与处置动作绑定。
- 组合的运维代价：异常旁路需要独立的阈值与运营流程，噪声比例随参数漂移会导致告警量忽高忽低；人工复核是持续的运营成本，不是一次性交付。
- 适合规模：风控、内容安全等「噪声即价值」的场景，样本量中等以上【经验】。

### 3.5 反模式与失效分析

| 反模式 | 症状（怎么发现它） | 后果（机制层面的后果） | 成因（为什么团队会写成这样） | 修法 |
| --- | --- | --- | --- | --- |
| 先用 K-Means 不调 K | 用默认 K 直接出结果，业务说不出各群差异 | 簇数与真实结构无关，分群进不了运营动作 | 库的默认值被当成推荐值 | 肘部法则 + 轮廓系数 + 业务可解释性三重确定 K |
| 高维直接聚类 | 原始特征上百维【经验】还直接算距离 | 距离集中，最近邻与最远邻差别趋近于零 | 认为算法会自己处理维度 | 先降维（PCA / UMAP / t-SNE）或改用 Embedding |
| 聚类不评估 | 聚完直接用，没有指标也没有 review | 无法区分「结构存在」与「算法自证」，问题只能靠事故暴露 | 无监督没有权威指标，索性跳过 | 轮廓系数 / CH / DBI + 业务人工 review 双轨 |
| K-Means 处理非凸数据 | 环形、月牙数据分群结果明显不合直觉 | 沿方差路径切错边界，指标却不报警 | 默认把 K-Means 当成通用算法 | 先可视化看形状，再选密度 / 谱聚类 |
| 不处理特征量纲 | 收入（到百万级）与年龄（到百级）同权参与 | 量纲大的特征独占距离，其余特征形同不存在 | 忘记标准化这一步会被静默跳过 | 标准化 / 归一化，并把它写进流水线而非脚本 |
| 文本用欧氏距离 | 高维稀疏词向量直接算欧氏距离 | 向量长度差异主导距离，语义相似被淹没 | 把所有距离都当成同一回事 | 文本用余弦距离或先转 Embedding |
| 依赖一次聚类结果 | 只跑一次就定稿 | 局部最优被当成唯一结构，稳定性无从谈起 | 省时间，且没有要求多次运行 | 多随机种子 + 多算法对比 + 业务验证 |
| 聚类标签直接当特征 | 簇标签进模型，线下涨线上不稳 | 标签不稳定导致下游模型输入分布漂移 | 把聚类输出等同于确定性标签 | 稳定性评估 + 多次聚类投票后再用 |
| 不处理类别特征 | One-Hot 后直接算欧氏距离 | 类别间距离全部相同，聚类结果无意义 | 数值化被当成预处理终点 | 类别特征用 Jaccard / 汉明距离，或先做合理的数值编码 |
| LLM Embedding 盲目信任 | 用通用编码器聚类，效果差但归因不清 | 相似度定义与任务目标不一致，聚类只能放大偏差 | 把编码器当成通用基础设施 | 内在评估（相似度排序）+ 下游任务评估 |
| HDBSCAN 参数拍脑袋 | 默认参数出结果，噪声比例异常 | 簇被拆开或整片变成噪声，且无人知道哪个对 | 参数没有权威默认值可抄 | 在 min_cluster_size / min_samples 上做搜索，并解释噪声比例 |
| 聚类无业务可解释性 | 指标达标，但没人说得出这群人是谁 | 簇无法进入任何业务动作，等于没做 | 验收标准只有几何指标 | LLM 命名 + 业务人工 review + 标签字典 |

最危险的三条，生产中通常这样暴露：

**「不处理特征量纲」**——它是最容易被静默跳过的错误：标准化通常写在一段临时脚本里而不是流水线里，某次重跑忘了执行，聚类照常出结果、指标照常可看，只有分群内容悄悄变成了「按收入分层」。机制在 3.2.1：平方距离会放大数值大的特征，模型没有任何机制提醒你距离被谁主导。

**「聚类标签直接当特征」**——暴露方式是下游模型上线后指标回落：聚类标签看起来是稳定的类别，实际每次重跑都可能变化。机制与 3.2.5 / 3.2.7 相同——聚类结果是模型的输出而不是数据的事实，把它当特征等于把一次抽签灌进下游。

**「聚类无业务可解释性」**——暴露方式通常是「看板有图、无人使用」：指标齐全、簇数正确，但运营说不出该对哪一群人做什么。按 3.2.10，命名与 review 不是装饰环节，而是让聚类结果能被消费的必要接口。

### 3.6 规模跃迁时模式何时该换

聚类是「复杂度与规模强耦合」的少数算法领域之一：N 一变，可选算法集合整体换一批。

| 跃迁 | 原模式 | 为什么开始疼 | 换成 | 迁移的代价 |
| --- | --- | --- | --- | --- |
| N 从 10⁴ → 10⁶ 以上 | 层次聚类 / 谱聚类 | 距离矩阵与特征分解分别是 O(N²) 与 O(N³)【推算】 | Mini-Batch K-Means / BIRCH | 放弃「任意 K 切割」与「非凸友好」，K 需要另外定 |
| 低维数值 → 高维或文本 / 图像 | 原始特征直接聚类 | 距离集中，欧氏距离失去区分度 | 预训练编码器 + 降维 + 余弦距离 | 增加编码与向量存储成本，换编码器要整库重算 |
| 批量 → 持续到达 | 全量重跑一次聚类 | 每次重跑的成本与时延都跟不上数据到达速度 | 增量 / 微批（Mini-Batch）+ 周期性重建摘要 | 需要处理摘要漂移，并定义「新旧标签可比性」 |
| 单方 → 多方且数据不出域 | 集中式聚类 | 数据无法汇聚，集中式在合规上不成立 | 联邦聚类（摘要 / 梯度聚合） | 通信轮次 + 特征空间对齐工程，依赖语义一致 |
| 一次性分析 → 周期性标签生产 | 临时脚本 + 一次性结果 | 标签进入下游后需要版本、稳定性与可追溯 | 模型版本化的标签表（含稳定性评估与字典） | 需要建标签治理（版本、Owner、变更评审），是组织成本 |

### 3.7 自检清单

- [ ] 距离度量是否与数据类型匹配？文本是否用了余弦、类别特征是否避开了 One-Hot 欧氏。
- [ ] 特征是否经过标准化，且这一步是否在流水线里而不是临时脚本里？
- [ ] 选算法之前是否看过二维投影的形状？看不到形状时是否先换相似度或降维？
- [ ] K 是如何确定的？能否说出「肘部 / 轮廓系数 / 业务分层需要」三者中哪一条起了作用？
- [ ] 是否跑过多个随机种子并比较簇结构？标签进下游前是否做过稳定性评估？
- [ ] 是否有业务侧能说清每个簇「是谁」？第 N 群对应的运营动作是什么。
- [ ] 高维数据是否降过维？降维是否与聚类参数一起版本化？
- [ ] 噪声 / 离群样本是否有明确处置路径（告警、人工、丢弃），而不是静默混进某个簇？
- [ ] 编码器（如使用）的版本是否与向量库版本绑定？换编码器是否有整库重算的流程。
- [ ] 簇数或主题数变化时，下游报表与标签字典是否同步更新？是否出现过「同一名字指向不同群」。
- [ ] 聚类标签作为下游特征前，是否评估过它的稳定性以及对下游模型的影响？
- [ ] 结果是否可复现？给定数据、参数、种子能否重跑出一致的划分。

### 3.8 小结

| 你的约束 | 建议模式 | 关键理由（机制层面） |
| --- | --- | --- |
| 低维数值 + 规模大 + 要快 | Mini-Batch K-Means | 每轮只对抽样小批计算，单轮成本随批大小而不是 N 增长 |
| 形状未知 + 噪声即价值 | DBSCAN / HDBSCAN | 簇由密度连通定义，噪声在算法内部就被显式标出 |
| 需要多档粒度 | 层次聚类 / BIRCH | 输出是树而不是一次划分，K 可事后在不同高度切 |
| 非凸 + 有关系矩阵 | 谱聚类 / Louvain | 特征向量编码连通性，把不可分的形状摊平 |
| 文本 / 图像语义归组 | 编码器 + 降维 + 密度聚类 + LLM 命名 | 编码器把语义转成可信距离，密度聚类负责结构与噪声 |

> 本节小结：本主题下决定模式选择的**唯一那条约束是「簇的定义」**——你假设一个簇是围绕质心的球、密度连通的一块、图上的一个连通块，还是树上的一棵子树，这决定了用哪个算法，也决定了它会以什么形状失效；其余约束（K 是否已知、规模、稳定性、可解释性）只决定这个假设能否在当下被计算出来、以及结果能否被消费。

> 💡 **思考锚点**：把你这批数据的 N 与维度代进 §3.6 的两行——N 是否越过了 10⁴→10⁶、维度是否已到「上百维直接算距离」？若两条都中，你既要付 O(N²)/O(N³) 的旧算法成本、又要付降维成本，而 §3.8 那张表里「非凸友好」的选项恰在规模换档时最先被放弃——你保形状，还是保规模？
