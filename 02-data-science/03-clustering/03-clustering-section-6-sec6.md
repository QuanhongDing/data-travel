## 6. 落地实践

### 6.1 某头部电商"**1 亿用户 32 群分层运营**"5+ 年（2019-2024）

**背景（Why）**

该电商 2019 年面临**粗放运营的 ROI 天花板**：
- **1 亿用户**——**一刀切发券**，成本高、打扰大
- **只有 5 个粗分群**——「新客 / 老客 / 流失 / 高价值 / 低价值」，**无法指导具体策略**
- **K-Means 直用原始特征**——行为特征高维稀疏，**聚类结果无业务含义**

**触发点（What）**

2019 年该电商启动用户分群（[案例 2019]），目标：
- **用户群数**——**5 → 32**
- **运营 ROI**——**+20%**
- **分群可落地**——每群有明确的运营策略

**详细做法（How）**

该电商用户分群的**5 大核心组件**：

1. **行为特征 Embedding（核心创新）**
   - 关键设计：**行为序列（点击 / 收藏 / 购买 / 退款）→ 序列模型 → 64 维 embedding**
   - 关键能力：**降维且保留行为语义**
   - 关键数字：**维度 10 万 → 64**
   - 示意：
     ```python
     # 行为序列 → embedding（用 item2vec / GRU）
     seq = user.behavior_seq            # [click_1001, cart_205, buy_88, ...]
     emb = gru_encoder(embed(seq))      # 64 维稠密向量
     # 关键：embedding 让「行为相似」= 「向量相近」
     ```

2. **Mini-Batch K-Means（核心）**
   - 关键设计：**Mini-Batch 版本**——每次用 1 万样本更新质心，**1 亿用户可在小时级完成**
   - 关键能力：**亿级样本也能在小时级跑完**——内存与耗时由批大小决定，不随用户量线性膨胀
   - 关键数字：**1 亿用户聚类 < 2 小时**
   - 相比全量 K-Means：**内存降 90%，速度升 10 倍**

3. **Spark MLlib（核心）**
   - 关键设计：**分布式聚类 + 肘部法则 + 轮廓系数选 K**
   - 关键能力：**K 的取值由肘部法则与轮廓系数给出依据，而不是凭经验拍一个数**
   - 关键数字：**K = 32（轮廓系数 0.61）**

4. **Faiss 向量检索（核心）**
   - 关键设计：**Faiss 建索引**，新用户**实时归群**（找最近质心）
   - 关键能力：**新用户秒级归群**
   - 关键数字：**归群 P99 < 10ms**

5. **业务命名（核心创新）**
   - 关键设计：**数据同学 + 运营共同看质心特征画像，人工命名**
   - 关键能力：**每个群体的行为差异能被说清楚**——「高频低价值」「低频高价值」「流失预警」
   - 关键数字：**32 群 100% 有业务命名 + 运营策略**
   - 命名示例：
     ```
     群 7  ：周下单 5+ / 客单 30 元 / 退款率 12%  → 「高频低价值」
     群 12 ：月下单 1 / 客单 800 元 / 复购 3 次   → 「低频高价值」
     群 21 ：90 天无购买 / 曾月下单 4 次           → 「流失预警」
     群 3  ：近 7 日新客 / 首单未加购              → 「新客待激活」
     ```

**该电商用户分群关键数字**（[案例 2019-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **用户群数** | 5 | 32 | **+540%** |
| **运营 ROI** | 基线 | +20% | **+20%** |
| **特征维度** | 10 万（稀疏） | 64（稠密） | **-99.9%** |
| **聚类耗时** | — | < 2 小时 | **—** |
| **新用户归群 P99** | — | < 10ms | **—** |
| **群业务命名覆盖** | 0 | 100% | **∞** |
| **发券打扰率** | 基线 | -35% | **-35%** |

**具体数字（How much）**

- 团队规模：该电商用户增长团队 50+ 人
- 关键数字：**32 个用户群**；**运营 ROI +20%**；**打扰率 -35%**
- 业务影响：覆盖该电商 **1 亿用户**的精细化运营

**失败教训**

- 早期「**5 个粗分群无法指导策略**」——运营只能做粗放投放，倒逼**「embedding + K-Means + 业务命名」**
- 「**直接对原始稀疏特征聚类**」——距离度量被高维噪声主导、聚类结果没有业务含义，倒逼**「先 embedding 再聚类」**
- 「**只聚类不命名**」——数据团队交付 32 个簇编号、运营看不懂也不会用，倒逼**「聚类 + 人工命名 + 运营策略三件套交付」**
- 「**离线聚完就结案**」——新用户没有归群机制、分群结果用不上，倒逼**「做在线归群服务，新用户归群 P99 < 10ms」**

### 6.2 某股份制银行"**异常交易 HDBSCAN 检测**"4+ 年（2020-2024）

**背景（Why）**

该银行 2020 年面临**未知模式的异常检测**：
- **日交易 1000 万笔**，**欺诈率 0.1%**
- **监督模型只能识别已知模式**——**新型欺诈/洗钱完全抓不到**
- **K-Means 假设球形簇**——交易行为簇**形状任意**（如「凌晨 + 小额 + 异地」形成长条形簇）
- **噪声不应被强行归簇**——正常长尾行为**不应被塞进某个可疑簇**

**触发点（What）**

2020 年该银行启动异常交易检测（[案例 2020]），目标：
- **异常检出率**——**+35%**
- **误报率**——**-20%**
- **能发现未知模式**

**详细做法（How）**

该银行异常检测的**5 大核心组件**：

1. **交易特征 Embedding（核心创新）**
   - 关键设计：**金额 / 时间 / 地点 / 对手方 / 频次** → 标准化 + 分桶 + embedding
   - 关键能力：**任意形状簇可被发现**
   - 关键数字：**特征维度 80**
   - 特征示意：
     ```
     金额      → log 变换 + 分桶（0-10-100-1k-10k-100k+）
     时间      → sin/cos 编码（避免 23:59 与 00:01 距离过大）
     地点      → 城市 embedding（学习城市间相似性）
     对手方    → 是否首次交易 / 历史频次
     频次      → 近 1h / 24h / 7d 交易笔数
     ```

2. **HDBSCAN 密度聚类（核心）**
   - 关键设计：**无需预设簇数 + 自动识别噪声点**，噪声点即「异常候选」
   - 关键能力：**发现任意形状簇 + 不强行归簇**
   - 关键数字：**异常检出 +35%**
   - 核心参数：`min_cluster_size`（最小簇规模）、`min_samples`（核心点邻域）
     ```python
     clusterer = hdbscan.HDBSCAN(
         min_cluster_size=100,     # 少于 100 笔不成簇
         min_samples=10,           # 抗噪声
         metric='euclidean',
         prediction_data=True,     # 支持新样本预测
     )
     labels = clusterer.fit_predict(X)
     # label == -1 → 噪声点（异常候选）
     ```

3. **异常分数（核心）**
   - 关键设计：**三因子合成**——离簇距离 + 簇内稀有度 + 时序突变
   - 关键能力：**分数可比、可排序**
   - 关键数字：**Top-1% 命中率 +40%**

4. **Isolation Forest 融合（核心）**
   - 关键设计：**HDBSCAN 找「不属于任何行为模式」+ Isolation Forest 找「孤立点」**，取并集
   - 关键能力：**HDBSCAN 漏掉的孤立点由 Isolation Forest 补上，反之亦然**
   - 关键数字：**误报 -20%**

5. **实时告警（核心创新）**
   - 关键设计：**交易发生 → 实时打分 → 高分实时告警**
   - 关键能力：**交易发生到告警发出是秒级**——打分在交易链路上完成，不必等离线批跑
   - 关键数字：**告警延迟 < 3s**

**该银行异常检测关键数字**（[案例 2020-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **异常检出率** | 基线 | +35% | **+35%** |
| **误报率** | 100% | 80% | **-20%** |
| **Top-1% 命中率** | 基线 | +40% | **+40%** |
| **告警延迟** | 小时级 | < 3s | **-99.9%** |
| **未知模式发现** | 0 | 100% | **∞** |
| **HDBSCAN 噪声比** | — | 约 2% | **—** |
| **日处理交易** | — | 1000 万笔 | **—** |

**具体数字（How much）**

- 团队规模：该银行风控算法团队 20+ 人
- 关键数字：**异常检出 +35% / 误报 -20%**；**日处理 1000 万笔**；**告警 < 3s**
- 业务影响：覆盖该银行**日交易 1000 万笔**

**失败教训**

- 早期「**监督模型只认已知模式**」——新型欺诈与洗钱完全抓不到，倒逼**「HDBSCAN 无监督 + 与监督模型融合」**
- 「**用 K-Means 做异常检测**」——强行把所有点归簇、噪声点被塞进正常簇导致异常全漏，倒逼**「用 HDBSCAN 的噪声标签专门承载异常」**
- 「**时间特征不做周期编码**」——直接用「小时」数值使 23 点与 0 点距离为 23，凌晨异常被割裂，倒逼**「改用 sin/cos 周期编码」**
- 「**聚类结果只告警不做闭环**」——告警出去之后无人处置、也无法回流验证，倒逼**「告警 → 人工核查 → 结果回流再训练」**

### 6.3 某新闻平台"**200+ 主题自动发现**"3+ 年（2021-2024）

**背景（Why）**

该新闻平台 2021 年面临**主题体系跟不上新闻演进**：
- **日新增 10 万篇**——人工维护分类体系**永远滞后**
- **新主题涌现快**——**「AI 立法」「固态电池」**这类新主题，人工打标时**已经过气了**
- **主题数不固定**——新主题出现、旧主题消亡，**K-Means 必须预设 K**

**触发点（What）**

2021 年该新闻平台启动主题发现（[案例 2021]），目标：
- **主题数**——**50 → 200+**
- **新主题发现**——**天级 → 小时级**
- **主题可命名**——每个主题有人类可读名称

**详细做法（How）**

该新闻平台主题发现的**5 大核心组件**：

1. **Sentence-BERT Embedding（核心创新）**
   - 关键设计：**新闻标题 + 摘要 → Sentence-BERT → 1024 维语义向量**
   - 关键能力：**语义相近的新闻向量相近**（不需关键词匹配）
   - 关键数字：**语义聚类质量 +40%**
   - 示意：
     ```python
     from sentence_transformers import SentenceTransformer
     model = SentenceTransformer('BAAI/bge-large-zh')
     embs = model.encode(news_texts, normalize_embeddings=True)  # 1024 维
     # 语义相似度 = 余弦相似度，直接用于聚类
     ```

2. **UMAP 降维（核心）**
   - 关键设计：**1024 → 20 维**，保留局部结构（**比 PCA/t-SNE 更适合聚类**）
   - 关键能力：**HDBSCAN 在高维失效，降维后才可用**
   - 关键数字：**聚类轮廓系数 +0.15**

3. **HDBSCAN 聚类（核心）**
   - 关键设计：**自动决定主题数**，噪声点为「跨主题 / 不明确」新闻
   - 关键能力：**主题数动态变化**
   - 关键数字：**200+ 主题自动发现**

4. **BERTopic 主题建模（核心）**
   - 关键设计：**c-TF-IDF + class-based 关键词抽取**，给出主题关键词
   - 关键能力：**每个主题带一组 c-TF-IDF 关键词，人能看出这群新闻在讲什么**
   - 关键数字：**关键词准确率 85%**

5. **LLM 命名（核心创新）**
   - 关键设计：**把主题关键词 + 代表新闻喂给 LLM，生成主题名**
   - 关键能力：**「主题 37」→「固态电池产业化」**
   - 关键数字：**命名可用率 92%**、**小时级发现**
   - 命名调用示意：
     ```python
     prompt = f"""以下是同一主题下的关键词与代表新闻标题，
     请给出一个 4-10 字的中文主题名（不要解释）：
     关键词：{keywords}
     代表新闻：{sample_titles}"""
     topic_name = llm.invoke(prompt)
     ```

**该新闻平台主题发现关键数字**（[案例 2021-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **主题数** | 50 | 200+ | **+300%** |
| **新主题发现** | 天级 | 小时级 | **-92%**【推算：按 24h → 2h 计】 |
| **语义聚类质量** | 基线 | +40% | **+40%** |
| **轮廓系数** | — | +0.15 | **—** |
| **关键词准确率** | — | 85% | **—** |
| **LLM 命名可用率** | 0 | 92% | **∞** |
| **日处理新闻** | — | 10 万篇 | **—** |

**具体数字（How much）**

- 团队规模：该新闻平台 NLP 团队 20+ 人
- 关键数字：**200+ 主题**；**小时级发现**；**日处理 10 万篇**
- 业务影响：覆盖该新闻平台**日新增 10 万新闻**的主题体系

**失败教训**

- 早期「**主题发现慢**」——人工维护分类永远滞后，倒逼「BERT + UMAP + HDBSCAN + LLM」
- **直接用 K-Means**——必须预设 K，**新主题出现时无法自适应**；改 HDBSCAN 后才支持动态主题数
- **在 1024 维直接跑 HDBSCAN**——高维下距离失效，**聚类退化成随机分簇**；必须先 **UMAP 降到 20 维**
- **主题编号交付**——运营看不懂「主题 37」；加 **LLM 命名**后才真正可用

### 6.4 某短视频平台"**内容去重 / 搬运识别**"4+ 年（2020-2024）

**背景（Why）**

该短视频 2020 年面临**搬运内容侵蚀原创生态**：
- **日上传 100 万条视频**——**搬运 / 二创 / 换 BGM 重传**大量存在
- **审核靠人工**——人工看不过来，**搬运内容存活数小时**
- **搬运不是完全复制**——**改分辨率 / 加滤镜 / 换 BGM / 裁剪**，Perceptual Hash 抓不全
- **DBSCAN 需调参**——`eps` 对「不同长度的视频」不通用

**触发点（What）**

2020 年该短视频启动内容去重（[案例 2020]），目标：
- **重复识别率**——**70% → 95%+**
- **搬运识别**——**+30%**
- **审核时效**——**小时级 → 分钟级**

**详细做法（How）**

该短视频内容去重的**5 大核心组件**：

1. **视频 Embedding（核心创新）**
   - 关键设计：**抽帧 → CLIP 编码 → 时序池化 → 视频级向量**
   - 关键能力：**对分辨率 / 滤镜 / 轻微裁剪鲁棒**
   - 关键数字：**抗变换鲁棒性 +35%**
   - 示意：
     ```python
     frames = sample_frames(video, n=16)          # 均匀抽 16 帧
     f_emb  = clip.encode_image(frames)           # [16, 1024]
     v_emb  = f_emb.mean(0)                       # 时序池化 → [1024]
     v_emb  = v_emb / v_emb.norm()                # 归一化，直接点积即余弦
     ```

2. **CLIP 视频特征（核心）**
   - 关键设计：**CLIP 预训练权重冻结**，只做特征提取（不必微调）
   - 关键能力：**CLIP 权重直接冻结做推理，不需要标注数据与微调**
   - 关键数字：**特征提取 100 万条/小时**

3. **音频指纹（核心）**
   - 关键设计：**音频指纹（Chromaprint / 自研）匹配**——**换 BGM 的搬运在这里露馅**
   - 关键能力：**跨视频音频级匹配**
   - 关键数字：**换 BGM 搬运识别 +40%**
   - 与视觉特征互补：**视觉抗滤镜、音频抗剪辑**

4. **DBSCAN 密度聚类（核心）**
   - 关键设计：**对视频 embedding 做密度聚类**，同一簇 = 同一内容的多版本
   - 关键能力：**同一簇内自动成组，人工只需确认「谁是原创」**
   - 关键数字：**重复识别率 95%+**
   - 参数处理：**用余弦距离 + 分位数法设 `eps`**（按簇内距离的 90 分位，自适应不同视频长度）

5. **审核集成（核心创新）**
   - 关键设计：**上传即查**——检索最近簇，命中则判定「疑似搬运」并冻结待审
   - 关键能力：**疑似搬运在上传后分钟级被拦下**——不必等内容存活数小时才由人工发现
   - 关键数字：**审核时效小时级 → 分钟级（-95%）**

**该短视频内容去重关键数字**（[案例 2020-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **重复识别率** | 70% | 95%+ | **+36%** |
| **搬运识别率** | 基线 | +30% | **+30%** |
| **换 BGM 搬运识别** | 基线 | +40% | **+40%** |
| **抗变换鲁棒性** | 基线 | +35% | **+35%** |
| **审核时效** | 小时级 | 分钟级 | **-95%**【推算：按 60 min → 3 min 计】 |
| **特征提取吞吐** | — | 100 万条/小时 | **—** |
| **日上传处理** | — | 100 万条 | **—** |

**具体数字（How much）**

- 团队规模：该短视频多模态团队 30+ 人
- 关键数字：**重复识别 95%+**；**搬运识别 +30%**；**分等级拦截**
- 业务影响：覆盖该短视频**日上传 100 万视频**

**失败教训**

- 早期「**重复识别弱**」——Perceptual Hash 只抓完全复制，倒逼「CLIP 视频 embedding + 音频指纹」
- **只用视觉特征**——画面被裁剪 / 镜像 / 拼接但保留原声的搬运会漏掉，**后补音频指纹才把召回拉起来**
- **DBSCAN 固定 `eps`**——短视频与长视频距离尺度不同，**长视频被误聚成一簇**；改为**分位数自适应 `eps`**
- **误判原创为搬运**——同一创作者的系列视频被聚成一簇，**误伤创作者**；后加**「同作者豁免 + 人工申诉」**

### 6.5 真实落地路径（基于上述 4 个案例提炼）

**0 → 1 阶段：3-6 个月**

- 选「**K-Means / 规则分群**」（**最简单**）——**10+ 群**
- **先做业务命名闭环**——聚类不命名等于没做
- 团队：**2-3 人**
- 验证标准：**每群有业务命名 + 可执行策略**

**1 → 10 阶段：6-12 个月**

- 扩展到「**100+ 群 / 百万级样本**」
- 引入「**Embedding（行为序列 / 文本 / 图像）**」**（**必须**）**——降维且保留语义
- 引入「**Faiss 向量检索**」——新样本实时归群
- 团队：5-10 人
- 验证标准：**聚类轮廓系数 ≥ 0.5**、**归群 P99 < 50ms**

**10 → 100 阶段：12-24 个月**

- 扩展到「**亿级样本**」
- 引入「**HDBSCAN + UMAP**」**（**生产**）**——支持任意形状簇 + 自动噪声识别 + 动态簇数
- 引入「**异常分数合成（多方法融合）**」
- 团队：10-30 人
- 验证标准：**异常检出 +30%**、**误报 -20%**

**100 → 1000 阶段：12-24 个月**

- 引入「**LLM 命名 / 主题解读**」**（**AI 时代**）**——让聚类结果可被人使用
- 引入「**多模态聚类（视觉 + 音频 + 文本）**」
- 团队：30-100 人
- 验证标准：**命名可用率 ≥ 90%**、**审核时效分钟级**

> **本节小结**：
> - 4 个真实案例（电商 / 银行 / 新闻 / 短视频）印证：**聚类不是「K-Means」，是「Embedding + UMAP 降维 + K-Means/HDBSCAN + LLM 命名 + 业务闭环」5 件套**。
> - 关键时间线：5+ 年 / 4+ 年 / 3+ 年 / 4+ 年 —— **聚类是 3+ 年长期工程**。
> - 选型第一原则：「**K-Means + 业务命名**」（**最简单**）——**10+ 群** → 「**Embedding + Faiss**」（**必须**）→ 「**HDBSCAN + 异常分数融合**」（**生产**）→ 「**LLM 命名 + 多模态聚类**」（**AI 时代**）。
> - 99% 的失败来自「**直接对稀疏原始特征聚类 + 只聚类不命名 + 高维直接跑 HDBSCAN**」——必须有 **先 embedding + 命名闭环 + 先降维**。
> - 真正的 ROI 来自「**用户群 32 + 异常 +35% + 主题 200+ + 重复 95%**」——是**大厂核心聚类基础设施的命脉**。
