## 7. 与其他方法对比

> 原 § 7 共 101 行、为一张 7 列 × 9 维度的打分表 + 决策树 + 7 条组合，缺少机制解释与可溯源证据，重写为 ~300 行对比与选型工程。

### 7.1 先立判据：为什么打分表会误导

打分表在聚类上的失真比在多数主题上更严重，原因是**聚类连一个公认的「正确答案」都没有**：轮廓系数、CH、DBI 这类指标衡量的是「簇内紧、簇间松」，它们能证明几何一致性，不能证明「这几个群在业务上真实存在」。于是打分表里那些看起来客观的列（速度、可解释性、参数易调）其实都在描述**同一组假设之下的相对表现**——同一份数据，换一个簇的定义，这些分值的排序就会变。

聚类列与列之间的差异，根子上是**簇的定义不同**：K-Means 假设簇是围绕质心的球，DBSCAN / HDBSCAN 假设簇是密度连通的一块，层次聚类假设簇是树上的一棵子树，谱聚类假设簇是图上切一刀切出的连通块，GMM 假设簇是一个高斯分布（详见 [§ 3 设计模式与范式](03-clustering-section-3-sec3.md) 的约束总览）。同一份环形数据，五种假设给出五个不同答案，而且**都不是错的**——错的是把其中一种假设当成了事实。按「任意形状 5 分 / K-Means 1 分」这种打分去选，只是在用别人的假设替代自己的判断。

「速度」这一列尤其容易误导。聚类算法的时间复杂度从 O(N·K·T) 到 O(N²) 到 O(N³) 跨了三个量级，N 一变，可选算法的集合就整体换一批——这不是性能调优问题，是**可行性问题**。一个在 N=10⁴ 上得分很高的算法，到 N=10⁷ 时不是变慢，而是根本跑不起来；而打分表给的是同一个数。同理，「AI 时代适配」这一列把 Embedding 给高分，但如果你的相似度定义本身就是错的（类别特征 One-Hot 后算欧氏距离），换上 Embedding 只是把错误从一个空间搬到另一个空间。

再举一个「同一维度随规模反向」的例子：层次聚类的「无需指定 K、可在任意高度切割」在中小规模上是决定性优点——它把「K 定不准」这个困扰整个主题的问题直接消掉；但当 N 超过十万级【经验】时，这份自由会被它自己的代价吞掉：全部信息都在距离矩阵里，而矩阵规模随 N 平方增长，于是你会先被迫放弃它、退回需要预设 K 的算法。同一列「无需指定 K」在小样本上是最强项、在大样本上是最先被牺牲的那一项，而打分表给出的始终是同一个数。**因此本章不排序，只给判据**——下表 6 条判据的用法是逐条否决候选，而不是给候选累加分数。

**本章采用的 6 条判据**：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| 簇的定义假设 | 我假设一个簇长什么样（球 / 密度块 / 连通块 / 子树 / 高斯） | 它决定算法族，也决定这个算法会**以什么形状失效**——假设与数据形状不符时，结果不会报错，只会悄悄地错 |
| 相似度是否可信 | 度量、量纲、编码对不对 | 相似度是聚类唯一的输入，也是唯一无法由算法补救的部分；定义错了，任何算法都只是在错的空间里分组 |
| 复杂度与规模上限 | N 到多大、d 到多高 | 复杂度决定「能不能跑」，维度决定「距离还有没有区分度」——两条都是可行性门槛，不是性能档位 |
| 产出能否被消费 | 噪声怎么处置、簇数谁定、簇名谁说得出 | 簇进不了任何业务动作就等于没做；这是无监督任务特有的验收条件 |
| 稳定性与标签用途 | 结果要不要进下游模型或报表 | 聚类结果是模型的输出而不是数据的事实，标签用于下游前必须有稳定性证据 |
| 运维与重算成本 | 多久重跑一次、换编码器要付什么 | 周期性标签生产的成本由「重算 + 复核」而不是由首次运行决定 |

### 7.2 候选方案全景

| 方案 | 定位 | 核心机制（一句话） | 典型使用者 | 许可 / 商业模式 |
| --- | --- | --- | --- | --- |
| K-Means（含 Mini-Batch 变体） | 低维数值分群的默认起点 | 交替执行「分配到最近质心 / 用均值更新质心」，最小化簇内平方和 | 用户分群、商品分层 | 开源（scikit-learn / Spark MLlib / Faiss 等） |

| DBSCAN | 形状未知 + 噪声即产出 | 簇由密度可达定义，不属于任何核心点邻域的点被标为噪声 | 异常交易、离群设备 | 开源 |

| 层次聚类（凝聚 / Ward 等准则） | 需要多档粒度与树状结构 | 反复合并最近的簇，输出可在任意高度切割的树 | 中小规模分层分析 | 开源（scipy / R 等） |

| Louvain / Leiden | 大规模图社区发现 | 优化模块度（Louvain）或带连通性约束的模块度（Leiden） | 社交图、知识图谱 | 开源 |

| 主题建模聚类（BERTopic / Top2Vec，含 c-TF-IDF） | 文档聚类且要主题词 | 编码 + 降维 + 密度聚类 + 每簇关键词提取 | 新闻、评论、知识库 | 开源 |

| 联邦聚类（摘要 / 参数聚合） | 数据不能出域但口径要统一 | 各方只上传可加摘要（计数、线性和、平方和）或加密参数 | 跨机构风控、隐私合规场景 | 自研 + 方法公开 |
| 聚类 + 分类（半监督） | 少量标签 + 大量无标签 | 聚类产伪标签，训练分类器把簇变成可预测的标签 | 冷启动标签体系 | 开源 |

| 聚类 + 召回（Item Embedding 聚类 + 双塔） | 推荐召回候选生成 | 同簇 Item 互为候选，双塔负责精排 | 电商、短视频 | 自研 |

**先分族，再比较。** 上表 18 行里，13 行是算法本体，分**三个族加一支树结构**：**第一族按「到中心的距离」定义簇**（K-Means、K-Medoids、GMM——GMM 把硬距离换成概率距离，3 行），**第二族按「密度或连通性」定义簇**（DBSCAN、HDBSCAN、OPTICS、谱聚类、Louvain / Leiden，5 行），**第三族把「相似度从哪来」整体外包给编码器**（深度聚类、Embedding 聚类、主题建模聚类，3 行）；**另有一支按「树上的子树」定义簇**（层次聚类、BIRCH，2 行）——它既不按「到中心的距离」、也不按密度或连通性划界，而是先建一棵合并树、再在某个高度切一刀，因此既不能塞进前三族，也不能借用它们的族内判据（7.3.1 的表同样把它单列成一种假设）。余下 5 行（两阶段、联邦、聚类 + 分类、聚类 + 异常检测、聚类 + 召回）不是新的族，而是**在族内成员外面套一层工程结构**：13 + 5 = 18。先定族（簇的定义），再在族内挑实现：跨族的差异来自假设，族内的差异主要来自规模与实现。

**族内（以及树结构这一支内）怎么挑，看的是各自的实际判据**：

| 族 | 族内选择的实际判据 | 换实现时真正会变的东西 |
| --- | --- | --- |
| 第一族（距离） | 是否要软分配、是否要抗离群点、N 有多大 | 中心是均值还是真实样本、是否需要多 seed |
| 第二族（密度 / 连通） | 密度是否均匀、维度是否低到索引有效 | ε / min_samples 或 k 近邻数等阈值参数 |
| 第三族（编码器） | 模态、编码器与任务的匹配度、能否接受重算 | 向量空间的定义，以及由此决定的全部簇结构 |
| 树结构一支（层次聚类 / BIRCH） | 数据量能否装下距离矩阵（决定用层次聚类还是 BIRCH）、要几档粒度 | 切割高度与簇数的对应关系，以及摘要的重建周期 |

### 7.3 机制差异：为什么它们表现不同

#### 7.3.1 簇的定义假设：它决定了算法以什么形状失效

**机制是什么**：每个聚类算法先假定了「一个簇是什么」，再去找这种结构；假设与数据形状不符时，算法不会报错，只会给出一个自洽但错误的划分。

| 假设 | 代表算法 | 在什么数据上成立 | 假设不成立时的表现 |
| --- | --- | --- | --- |
| 簇是围绕质心的球 | K-Means、K-Medoids | 低维数值、簇大小相近、大致凸 | 沿最短方差路径把结构切开，指标可能仍然体面 |
| 簇是密度连通的一块 | DBSCAN、HDBSCAN、OPTICS | 密度相对均匀、维度不高 | 单阈值只能适配一个密度；疏的那一簇整体变成噪声 |
| 簇是图上切出的连通块 | 谱聚类、Louvain / Leiden | 有可信相似度矩阵或稀疏图 | 图只能被近似时（采样、稀疏化），非凸的解不再精确 |
| 簇是一个高斯分布 | GMM | 簇近似椭球、且能被有限个高斯近似 | 用高斯去拟合长尾形状，尾部样本被强行分配 |
| 簇是树上的一棵子树 | 层次聚类、BIRCH | 规模允许构造距离矩阵或 CF 摘要 | 合并是贪心且不可撤销，合错无法回退 |

**由此必然导出的性质**：

- 因为 K-Means 优化的是簇内方差而不是连通性，所以在环形数据上「沿最短方差路径切成两半」的目标函数值确实低于「还原成一个环」——**它会给出一个在它自己的目标下正确的结果，而这个结果与数据形状无关**；代价是这个错误不会被任何几何指标报警（[§ 3.2.1](03-clustering-section-3-sec3.md)）。
- 因为密度聚类用同一个阈值定义「密」，所以当簇的密度差异明显时，ε 小则疏簇整体变为噪声、ε 大则两簇并成一个——**「疏」被等同于「不存在」**；代价是这个等价关系是单向的，你无法从结果里判断某片噪声到底是「没有簇」还是「簇太疏」。HDBSCAN 用稳定性部分缓解，但仍需能解释 min_cluster_size 的业务含义。
- 因为层次聚类输出的是整棵树而不是一次划分，所以 K 可以事后在不同高度切——**同一份数据可以给出粗 / 中 / 细三档粒度**（这正是分层运营需要的）；代价是它把全部信息压在距离矩阵里，规模一上去就先撞内存墙（见 7.3.3）。
- 因为谱聚类用的是拉普拉斯矩阵的前若干个特征向量、编码的是连通结构而不是欧氏距离，所以在原空间里不可分的形状（同心环）在这些特征向量里近似线性可分；**代价是最后收口那一步仍是 K-Means**，随机初值的影响并没有消失。

**假设不唯一，所以「多算法一致性」是唯一可用的证据**：因为没有哪个假设能被证明是对的，所以可行的做法是让两三个不同族的算法在同一份数据上跑，**把「被不同假设都分到一起的点」当作高置信结构**，把只在一种假设下成簇的部分当作待验证的候选。代价是这个做法把计算与复核成本乘以算法数，且当不同族给出互不兼容的划分时，它不会替你裁决——**它只是把分歧显式化，裁决仍要靠业务侧的动作验证**（7.3.2 的下游任务评估）。反过来，只跑一种算法时你不会看到分歧，也就无法知道自己的结论有多依赖那一个假设。

**公开证据**：K-Means 由 MacQueen 于 1967 年提出（【公开】MacQueen, "Some Methods for Classification and Analysis of Multivariate Observations", 1967）；DBSCAN 见 Ester et al., KDD 1996（【公开】）；HDBSCAN 的原始工作见 Campello et al., 2013（【公开】），其 Python 实现为公开开源库；谱聚类见 Ng, Jordan, Weiss, NeurIPS 2001（【公开】）；Louvain 见 Blondel et al., 2008（【公开】）、Leiden 见 Traag et al., 2019（【公开】）；Ward 准则见 Ward, 1963（【公开】）。

**失效条件**：当「正确的簇」由业务定义而非几何定义时（例如分层运营要的是一组可执行的运营动作），上述几何假设的对错不再重要——**必须先看二维投影的形状再选算法**，投影看不见结构时说明该先换相似度或降维，而不是先换聚类算法（[§ 3.3](03-clustering-section-3-sec3.md) 的判据）。

#### 7.3.2 相似度由谁定义：算法不能补救的部分

**机制是什么**：聚类是「在给定的相似度空间里分组」，相似度由度量、量纲与编码方式共同决定；这三样一旦定错，后面的算法无论多强都只在错的空间里工作。

| 相似度的来源 | 适用输入 | 常见错误 | 错误的表现形式 |
| --- | --- | --- | --- |
| 欧氏距离 | 低维、量纲一致的数值 | 未标准化就让收入与年龄同权参与 | 量纲大的特征独占距离，其余特征形同不存在 |
| 余弦相似度 | 文本、已归一化的向量 | 未归一化时欧氏排序与余弦排序不一致 | 向量长度差异主导距离，语义相似被淹没 |
| Jaccard / 汉明 | 集合、类别特征 | 类别特征 One-Hot 后算欧氏距离 | 不同类别之间的距离全部相同，结果无意义 |
| 编码器输出的余弦距离 | 文本、图像、多模态 | 通用编码器与任务目标不一致 | 簇按主题而非按业务维度分开，指标却可能不低 |

**由此必然导出的性质**：因为距离是聚类的唯一输入、而标准化与编码都发生在算法之外，所以这些错误不会让算法失败，只会让结果无意义——**「不处理特征量纲」是最容易被静默跳过的错误**：标准化常写在一段临时脚本而不是流水线里，某次重跑忘了执行，聚类照常出结果、指标照常可看，只有分群内容悄悄变成了「按收入分层」；代价是没有任何机制会提醒你距离被谁主导（[§ 3.5](03-clustering-section-3-sec3.md)）。第三族把这件事整体外包给编码器，换来的是另一个性质：因为相似度由编码器的训练目标定义，聚类只能放大这个定义、无法修正它——**用通用语义模型去区分工单紧急程度时，簇会按主题而不是按紧急度分开，而轮廓系数可能并不低**。修法是先做内在评估（同义句相似度排序），再做下游任务评估（用簇标签驱动一个真实动作，看它是否比随机分组更有效）。

**公开证据**：把语义相似翻译成可信距离的编码器路线见 Sentence-BERT（【公开】Reimers & Gurevych, EMNLP 2019）与 CLIP（【公开】Radford et al., ICML 2021）；大规模近邻检索与向量聚类的工程支撑见 Faiss（【公开】Johnson et al., 2017）；「编码器 + 降维 + 密度聚类」是文本归类的通行做法【经验】。

**把相似度当资产来治理**：因为相似度是一次性定义、长期复用的，所以它应当像特征口径一样被版本化——记录「用了哪个度量、做了哪几步预处理、编码器是什么版本」，并让这份记录随标签一起发布。**代价是这份记录在项目早期看不出价值**：单次分析时它只是几条注释，等到第 N 次重跑、换人接手、或领到一批新数据时，缺了它就无法判断前后两版分群是否可比。一个可自行核验的检查：把预处理链写成可重放的步骤（标准化方式、缺失值处理、编码方式、归一化时机），交给一个没参与过本项目的人按它重跑一遍，看能否得到同一批簇——跑不出来，说明相似度还没有被真正定义清楚。

**失效条件**：当编码器的向量维度与语料规模不受控时，余弦距离的区分度会退化——此时正确动作是先降维（PCA / UMAP）再聚类，而不是继续调聚类参数（[§ 3.2.6](03-clustering-section-3-sec3.md)）。

#### 7.3.3 复杂度与规模的耦合：N 一变，可选集合整体换一批

**机制是什么**：聚类算法的时间复杂度从 O(N·K·T) 到 O(N²) 到 O(N³) 跨了三个量级；规模跨过某个门槛时，失效的不是「性能」而是「可行性」，且先撞上的通常是内存而不是算力。

| 方案族 | 复杂度形态 | 主导资源 | 规模门槛 |
| --- | --- | --- | --- |
| K-Means / Mini-Batch | O(N·K·T)（每轮一遍全量或小批） | I/O 与内存带宽（向量要反复读） | 可用分批把 N 摊开 |
| 层次聚类 / 谱聚类 | O(N²) 距离矩阵 / O(N³) 稠密分解 | 内存（矩阵）与分解时间 | 见 7.5 的阈值推演 |
| 密度聚类 | 依赖邻域查询（索引有效时近线性，退化后近 N²） | 空间索引与维数 | 维度升高后索引失效 |
| BIRCH / Canopy 两阶段 | 摘要规模 M 而非 N 决定第二阶段成本 | 摘要维护与重建 | 需要增量与周期性重建 |

**由此必然导出的性质**：

- 【推算】距离矩阵与特征分解的规模门槛可以直接算出来：N=10⁴ 时两两距离约 5×10⁷ 项【推算：N(N−1)/2 = 10⁴×9999/2 ≈ 5×10⁷】，按 8 字节双精度约为 0.4 GB【推算：5×10⁷ × 8 B = 4×10⁸ B】；N=10⁵ 时约 5×10⁹ 项、约 40 GB【推算：10⁵×99999/2 ≈ 5×10⁹，× 8 B = 4×10¹⁰ B】——**在十万级就超过单机内存**，所以在这一步之前必须先降规模，而不是先调参数。
- 【推算】K-Means 的账不能只看「算术次数」。N=10⁸、d=50 的单精度向量约占 20 GB【推算：10⁸ × 50 × 4 B = 2×10¹⁰ B】；每轮迭代要把全部向量读一遍，T=20 轮即约 400 GB 的读放大【推算：20 GB × 20】，主导项是 I/O 与 shuffle 而不是算术——**所以「换个更快的 BLAS」通常无效，能有效的是减小每轮的读取量（Mini-Batch）或先压成摘要（BIRCH / Canopy）**；代价是压缩引入近似误差，且摘要描述的是历史分布，需要周期性重建。
- 【推算】谱聚类的稠密分解是 O(N³)：N=10⁴ 时为 10¹² 量级【推算：N³ = (10⁴)³】，属于可跑但不再便宜的区间；到 N=10⁵ 时是 10¹⁵ 量级【推算：(10⁵)³】，先撞上的仍是那张 40 GB 的矩阵。因此规模一上来，非凸友好这个优点会被「图只能被近似」抵消。
- 因为密度聚类把成本从「K 次比较」换成「邻域查询」，而邻域查询依赖空间索引，所以维度升高后索引退化为全扫描、距离还同时失去区分度——**速度与效果在同一步上一起下降**，这对组合是聚类特有的：大多数算法只掉其中一个。

**公开证据**：BIRCH 用 CF 摘要压缩样本见 Zhang, Ramakrishnan, Livny, SIGMOD 1996（【公开】）；Canopy 粗聚类见 McCallum, Nigam, Ungar, KDD 2000（【公开】）；Mini-Batch K-Means 见 Sculley, WWW 2010（【公开】）；近似最近邻与向量聚类的工程实现见 Faiss（【公开】Johnson et al., 2017）。

**失效条件**：当数据是流式到达而非批量回灌时，「跑一次」这个前提不成立——必须换成增量或微批，并定义「新旧标签是否可比」（[§ 3.6](03-clustering-section-3-sec3.md) 的跃迁表）。

**为什么规模门槛必须写在选型表里**：因为聚类不像分类那样可以「先用小样本试跑、再按比例地把规模放大」——它的复杂度对 N 是阶数不同的（线性 / 平方 / 立方），所以小样本上的成功不能外推。**代价是这条约束会让选型看起来「不讲道理」**：同样的数据、同样的目标，只因为 N 差两个数量级，正确答案就完全不同。把门槛写在选型表里，是为了让评审时能直接问「你的 N 在哪个区间、一年后会不会跨过门槛」——如果会跨过，现在的选择就要预留迁移路径（例如先用 K-Means 跑通标签生产流程，等规模上来再换两阶段）。

#### 7.3.4 产出的可消费性：噪声、软分配、簇数与命名

**机制是什么**：聚类算法的输出不是标签，而是一次划分加上一组结构信息（哪些点是噪声、每个点属于各簇的程度、簇有多少个）；这些信息如何被消费，决定了结果能否进入业务流程。

| 产出维度 | 谁提供它 | 提供时的代价 | 不消费它的后果 |
| --- | --- | --- | --- |
| 噪声标记 | DBSCAN / HDBSCAN 内生产出 | 噪声比例随参数漂移，需独立的阈值与流程 | 噪声被静默混进某个簇，异常检测失去意义 |
| 软分配 | GMM（后验概率） | 需要高斯假设与 K 值 | 用硬标签做「属于度」的决策，边界样本被误判 |
| 簇数 | 密度 / 层次结构自动给出，或由业务分层需要指定 | 换一个 min_cluster_size 就换一批主题数 | 簇数不受控，报表口径随参数漂移 |
| 簇名与描述 | 人（业务专家）或 LLM 命名 | 每次命名有 token 成本且不可复现，必须落字典并由人签字 | 指标齐全但没人说得出「这群人是谁」，分群进不了运营动作 |

**由此必然导出的性质**：因为无监督评估只能证明几何一致性、证明不了业务真实性，所以聚类必须配一个业务可解释性环节——**命名与 review 不是装饰，而是让聚类结果能被消费的必要接口**；代价是这个环节是持续的运营成本，不是一次性交付（LLM 命名能降低成本，但把结果落成字典、由人签字这一步不能省，因为它同时是口径的冻结动作）。更危险的一条是：因为标签一旦进入报表与考核就有了惯性，所以在簇结构本身不稳定时先采用名称，会把一次随机划分固定成组织事实，而聚类的可复现性缺陷不会在报表里显示出来——**错误因此不可见**（[§ 3.2.10](03-clustering-section-3-sec3.md)）。

**公开证据**：把「簇里在讲什么」变成可读标签的做法是 c-TF-IDF（【公开】Grootendorst, "BERTopic", 2022；同族的 Top2Vec 见 Angelov, 2020）；经典词袋主题模型见 LDA（【公开】Blei, Ng, Jordan, 2003）；用大模型为簇命名与写描述是当前通行做法【经验】，可按关键词 LLM clustering labeling 自行检索核验。

**失效条件**：当语料把长文与短文混在一起时，关键词方法给出的「可解释」会反转成「看起来像但不可用」——因为 c-TF-IDF 描述的是词分布而不是语义，长文档因词数多而主导关键词、短文档簇的关键词由噪声词构成；此时应改用编码器语义或按长度分层处理（[§ 3.2.9](03-clustering-section-3-sec3.md)）。

**「簇数谁定」是一道必须先回答的问题**：三类答案对应三种代价——由算法定（密度 / 层次结构自动给出），代价是换一个 min_cluster_size 就换一批簇数，报表口径随参数漂移；由业务定（分层运营需要几档），代价是算法被约束成一个可能不符合数据形状的 K；由指标定（肘部法则 / 轮廓系数选 K），代价是这些指标只衡量几何一致性，选出的 K 未必对应任何业务分层。**因为在同一份数据上这三种答案可以给出不同的簇数，所以簇数必须在开工前写明「谁定、依据是什么」**，否则每次重跑都要重开一次这个争论，而争论本身会消耗掉比算法更多的工期。

### 7.4 成本结构对比（不是价格表，是成本函数）

```
总成本 ≈ 一次性全量计算的算力与 I/O
        + 编码与向量存储（第三族）
        + 重算频率 × 单次重算成本
        + 人工 review 与标签治理
```

| 方案族 | 成本随什么增长 | 主导项 | 隐性成本 |
| --- | --- | --- | --- |
| 第一族（距离） | N × K × 迭代轮数（每轮读一遍向量） | I/O 与内存带宽 | K 的反复试跑、多 seed 稳定性投票的重复计算 |
| 第二族（密度 / 连通） | 邻域查询次数（索引有效时近线性） | 空间索引与内存 | 参数搜索（ε / min_samples）与噪声比例的运营流程 |
| 第三族（编码器） | 全库对象数 × 维度（编码一次 + 存储一份） | 编码算力与向量存储 | 换编码器要整库重算；编码器版本与向量库版本必须绑定 |
| 两阶段 / 联邦 | 摘要规模 M、通信轮次 | 摘要维护与重建 / 通信 | 两层近似叠加导致误差归因变难 |

**几条【推算】的数量级**：

- 向量存储：10⁷ 个文档 × 768 维 float32 ≈ 30 GB【推算：10⁷ × 768 × 4 B = 3.07×10¹⁰ B】。这意味着第三族的第一次入场成本不是「算法跑得动跑不动」，而是**先要有一份全库向量**；换一次编码器就要重算 10⁷ 次编码并重写同样量级的向量。
- 全库重算频率与成本的关系：若每季度重跑一次、每次要重编码全库，则年度成本里最大的一项与**数据增长速度**挂钩，而不是与簇数挂钩——把簇数从 50 调到 200 通常几乎不改变账单，把重跑频率从季度改成月度会成倍增加。
- 人工 review：簇数 × 每簇 10–30 分钟【经验】。簇数 100 即约 17–50 人时（单次）【推算：100 × 10 分钟 = 1000 分钟 ≈ 17 h；100 × 30 分钟 = 3000 分钟 = 50 h】；它是**每次重跑都要重付**的成本，这也是「簇数不稳定」之所以昂贵的原因。
- 两阶段结构的账：粗阶段把 N 压成 M 个摘要后，第二阶段的计算量由 M 决定而不是 N【推算：BIRCH 的 CF 摘要满足可加性，M ≪ N】；代价是两层近似误差叠加，出问题要跨两个阶段定位。

**成本的主语是「这次重算要动多少数据」，不是「算法有多快」**：因为在周期性标签生产里，账单由重算频率与重算范围决定，所以把聚类算法换成更快的实现通常只改变单次成本的一小部分（算法只占整条链路的一段，前面还有编码、后面还有 review），而把重跑频率从季度改成月度会成比例地增加全部那些段。**代价是这个结论与直觉相反**，团队更愿意优化看得见的算法环节；判断方法仍是上面那句：先写清成本函数，再决定优化哪一项。

**一个可自行核验的检查**：把「重算成本 ÷ 业务能接受的标签新鲜度」写成一句话。如果这个比值超过「人工 review 成本」，那么你的瓶颈不是算法而是治理流程；反之则应优先优化重算路径（增量、摘要复用）。这个判断不需要任何外部数据，只要两个你自己的数。

**增量与全量是两种不同的成本曲线**：因为 K-Means 这类「距离族」的每次迭代都要读一遍全部向量，增量更新只有在「新数据占比很小」时才划算；而编码器族里换一次模型就必须整库重算，增量根本不存在。**代价是「支持增量」常常被当成通用优点写进选型表**，而它实际上只对第一族成立——对第三族，正确的说法是「重算周期」而不是「增量能力」。判断方法：问一句「上一次全量重算是什么时候、下次什么时候」，答得出来说明重算路径已经是一条被管理的流程，答不出来说明它还只是一次性脚本。

### 7.5 决策树（每个分支都要有阈值依据）

用法：树上的方括号是**判断节点**，末端是**算法选择**。按 7.2 的两步法，先用「簇的定义」定族（形状已知用第一族、形状未知且噪声即产出用第二族、需要多档粒度用树结构一支、原始特征不可直接度量用第三族），再用规模与维度在族内筛实现。

```
[聚类任务]
   │
   ├─[数据有标签吗？]
   │     └─ 有 → 转分类（见 02-classification）；少量标签 + 大量无标签 → 聚类产伪标签 + 分类器
   │
   ├─[N 有多大？]
   │     ├─ N < 10^4 → 任意族都可尝试；要树结构用层次聚类，非凸 + 有关系矩阵用谱聚类
   │     ├─ 10^4 ≤ N < 10^5 → K-Means / GMM / HDBSCAN / BIRCH；距离矩阵类算法进入灰区（装得下但重算贵）
   │     └─ N ≥ 10^5 → 距离矩阵类退出；N ≥ 10^6 起改用 Mini-Batch K-Means / BIRCH 或 Canopy 两阶段 / 流式版本
   │
   ├─[原始特征是数值，还是文本 / 图像 / 多模态？]
   │     ├─ 数值且维度 < 100 → 直接聚类（先做标准化）
   │     ├─ 数值但维度 ≥ 100 → 先降维（PCA / UMAP）再聚类
   │     └─ 文本 / 图像 / 多模态 → 第三族：编码器 + 降维 + 密度聚类（主题场景叠加 c-TF-IDF 或 LLM 命名）
   │
   ├─[簇的形状事先知道吗？]
   │     ├─ 大致是球 / 椭球、且 K 已知 → K-Means / GMM
   │     ├─ 未知、且噪声本身是业务产出 → DBSCAN / HDBSCAN
   │     └─ 未知但需要多档粒度 → 层次聚类 / BIRCH
   │
   ├─[需要软分配（每个样本属于各簇的概率）吗？]
   │     └─ 需要 → GMM；否则硬划分的算法都可
   │
   ├─[需要抗离群点吗？]
   │     └─ 需要且 N 不大 → K-Medoids
   │
   ├─[簇标签要进下游模型或报表吗？]
   │     └─ 要 → 先做多 seed / 多算法稳定性评估，再落带版本的标签表与字典
   │
   └─[数据能否汇聚到一处？]
         └─ 不能（跨机构、合规限制）→ 联邦聚类；且必须先确认各方特征空间与 ID 体系口径一致
```

**阈值依据**（与树上节点一一对应）：

- 「有标签 → 转分类」与「少量标签 → 半监督」：无数值阈值，是任务类型判断——聚类的前提是无标签；有标签时分类是更直接的工具，标签少时用聚类产伪标签，把无监督结构变成可预测、可增量的目标（[§ 3.2](03-clustering-section-3-sec3.md) 与 7.6 的半监督组合）。
- N < 10^4：来自 7.3.3 的距离矩阵推算——10⁴ 时矩阵约 0.4 GB【推算：5×10⁷ 项 × 8 B】，单机可装；这也是层次聚类与谱聚类的实际可用区间。
- N ≥ 10^5 退出距离矩阵类算法：同上推算，10⁵ 时矩阵约 40 GB【推算：5×10⁹ 项 × 8 B】，超过单机内存。**这里用 10^5 作为退出点、10^4 作为舒适点**，两者之间的 10⁴~10⁵ 属于「能装下但重算昂贵」的灰区，取决于重跑频率。
- N ≥ 10^6 用两阶段 / 微批：来自 K-Means 的读放大推算（10⁸ × 50 维约 20 GB 向量、T=20 轮约 400 GB【推算】），以及 BIRCH / Canopy 用摘要把第二阶段规模降到 M【推算：CF 可加性，M ≪ N】。
- 维度 < 100 / ≥ 100，以及「文本 / 图像 → 第三族」：维度这条是本主题的经验分界【经验】——高维下距离集中、空间索引失效，两条同时发生（7.3.3）；阈值随向量是否已归一化与数据的内在维度（intrinsic dimension）移动，所以先看二维投影比看名义维度更可靠。非结构化输入之所以整支走第三族，是因为原始像素或原始 token 上无法定义可信距离（7.3.2）。
- 「形状已知 → K-Means / GMM」与「形状未知且噪声即产出 → DBSCAN / HDBSCAN」：来自 7.3.1——前一族没有噪声类，只能事后按距离阈值切；后一族在算法内部就把噪声标出来。
- 「形状未知但需要多档粒度 → 层次聚类 / BIRCH」：同样来自 7.3.1 的那一种假设（簇是树上的一棵子树）——它的产出是整棵树而不是一次划分，所以「要几档粒度」可以在事后选切割高度，不必在开工前把 K 定死；代价是全部信息压在距离矩阵或 CF 摘要里，可用规模由上面 10^4 / 10^5 两条决定（层次聚类在十万级退出，BIRCH 靠摘要续命到亿级）。
- 软分配节点：无数值阈值，是输出形态判断——GMM 的后验概率提供「属于各簇的程度」，硬划分算法没有这个输出（7.3.4）。
- 抗离群点节点：无数值阈值，是算法性质的判断——K-Medoids 用真实样本做中心，代价是复杂度升到 O(N²)（[§ 3.2.1](03-clustering-section-3-sec3.md) 的 K-Medoids 条目），所以只在 N 不大时可用。
- 标签进下游节点：无数值阈值，是稳定性要求——聚类结果是模型的输出而不是数据的事实，必须有多 seed / 多算法的一致性证据（[§ 3.5](03-clustering-section-3-sec3.md) 的「聚类标签直接当特征」）。
- 联邦节点：无数值阈值，是合规判断——前提是各方特征空间与 ID 体系口径一致，因为联邦保留的是「数值可加」，不保留「语义一致」（[§ 3.2.8](03-clustering-section-3-sec3.md) 的失效点）。

树上有两条分支在真实任务里会同时成立（例如「文本 + 亿级」「非凸 + 大 N」），此时不要在同一层里选一个算法硬扛，而是走 7.6 的组合：把其中一个约束交给外层结构解决（规模交给两阶段，非凸交给谱聚类或图方法）。判据很简单——**如果某个约束让你想把两个算法的优点都塞进一个算法，那就是结构的活，不是算法的活**。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因 |
| --- | --- | --- | --- |
| 用户分群、要周期性产出标签 | Mini-Batch K-Means | K-Means（N 小）、BIRCH（N 更大） | 密度聚类给不出可被业务读懂的中心，层次 / 谱聚类的复杂度不允许周期重跑 |
| 异常检测（噪声即产出） | HDBSCAN | DBSCAN（密度均匀时）、聚类后接 Isolation Forest | K-Means 没有噪声类，只能事后按阈值切，而阈值随簇大小变化 |
| 文本 / 文档主题发现 | 编码器 + UMAP + HDBSCAN + c-TF-IDF（BERTopic 式） | Top2Vec、LDA（需预设主题数时） | 词袋假设在高维稀疏下失效；且主题数事先未知 |
| 图文 / 多模态统一归组 | CLIP 式编码器 + 归一化 + K-Means | 深度聚类（自编码器路线） | 纯像素特征不承载语义，欧氏距离在原始空间里没有意义 |
| 亿级样本 + K 事先定不准 | Canopy 或 BIRCH 粗 + Mini-Batch K-Means 细 | 流式 K-Means（数据持续到达） | 全量重跑一次的成本与时效都不允许 |
| 需要多档粒度（粗 / 中 / 细） | 层次聚类（Ward 等准则） | BIRCH（N 大时） | K-Means 只给一次划分，看不到「哪两个群先并到一起」 |
| 非凸 + 有关系矩阵 / 图 | 谱聚类 | Louvain / Leiden（图稀疏且大时） | K-Means 在非凸形状上切错边界；谱聚类的 N³ 分解在大图上跑不动 |
| 跨机构、数据不能出域 | 联邦聚类（摘要聚合） | 各方各自聚类后人工对齐口径 | 集中式聚类不满足合规；各方口径不一致时聚合同一空间也不成立 |
| 少量标签 + 大量无标签 | 聚类产伪标签 + 分类器（半监督） | 直接标注（标注预算足够时） | 纯聚类结果进不了需要预测的下游；纯监督在标签太少时学不出来 |

**常见组合**（每条说明职责边界与运维代价）：

1. **Embedding + HDBSCAN**：编码器定义相似度，HDBSCAN 给出簇与噪声。职责边界是「语义由编码器负责、结构与噪声由密度聚类负责」；运维代价是编码器版本与聚类参数必须一起版本化，换编码器要整库重算向量。
2. **BERTopic 式全流程（Embedding + UMAP + HDBSCAN + c-TF-IDF）**：编码器给向量，UMAP 让密度估计可用，HDBSCAN 定簇，c-TF-IDF 出每簇关键词。运维代价是四者参数共同决定结果，簇数不受控（换一个 min_cluster_size 就换一批主题数），需要人工收敛到可用粒度。
3. **Canopy / BIRCH 粗 + K-Means 细**：粗阶段把 N 压成摘要并给出初始中心，细阶段在摘要上收口。运维代价是两层近似误差叠加，误差归因要跨两个阶段；摘要需周期性重建，否则它描述的是历史分布。
4. **聚类 + 分类（半监督）**：聚类产生伪标签，分类模型把簇变成可预测、可增量的标签。运维代价是伪标签的错误会被分类器学成规律，需要人工抽检与迭代；且聚类不稳定时，伪标签口径也随重跑变化。
5. **聚类 + 异常检测（HDBSCAN 或聚类后接 Isolation Forest）**：密度聚类同时产出簇与噪声，孤立森林对噪声子集再打分排序。运维代价是噪声比例随参数漂移会导致告警量忽高忽低，且异常处置流程是持续的运营成本。
6. **聚类 + 推荐召回（Item Embedding 聚类 + 双塔）**：同簇 Item 互为候选，双塔负责精排。运维代价是簇一旦漂移，召回集合会整体变化，需要监控簇的稳定性而不是只看离线排序指标。
7. **聚类 + LLM 命名 + 业务标签**：算法给簇，LLM 给描述，业务专家审核后写入标签字典。运维代价是命名与审核每轮重跑都要重付；边界是 LLM 只参与「这个簇是什么」的表达，不参与「谁属于哪个簇」的判定。

**组合的选择顺序不能反**：先定结构（是否需要两阶段、是否需要异常旁路、标签要不要进下游），再在结构里定族，最后用 7.4 的成本函数复核——因为每一层都引入一次近似或一次复核（两阶段是一层近似，命名与审核是一层人工），层数越多，误差归因越难、重算越贵。

**组合的收益来自「各件只做一件事」**：编码器只定义相似度、降维只让密度估计可用、密度聚类只给结构与噪声、命名只把簇翻译成人话——任一环出问题都能单独替换与评估。反过来，任何一环越权（例如让聚类算法去承担语义判断、让 LLM 参与归属判定）都会让整条链路的结论不可归因，而这是聚类最贵的故障形态：你只能看到「分群不对」，无法定位是哪一环把它弄错的。

### 7.7 选错的代价与迁移成本

**反模式：用几何指标验收** —— 症状：轮廓系数 / CH / DBI 达标就上线，没有人工 review、没有簇名、没有对应的业务动作；后果：看板有图、无人使用，簇进不了任何运营动作等于没做——**因为无监督指标只能证明几何一致性，证明不了业务真实性**；正确的做法是双轨验收：几何指标（判断要不要换相似度或降维）+ 业务可解释性（每个簇能说出「这群人是谁、对应什么动作」），并把后者写进验收标准。

**反模式：把 K-Means 当通用默认** —— 症状：不看二维投影直接上 K-Means，环形、月牙形数据分群结果不合直觉但指标体面；后果：沿方差路径切错边界，团队带着错误的几何结构做运营，直到某次归因分析解释不通才回头；**代价是这个错误不会报警**，因为 K-Means 优化的是簇内方差而不是连通性，在环形数据上「切成两半」的目标值确实更低。正确的做法是选型前先画二维投影看形状（[§ 3.3](03-clustering-section-3-sec3.md) 的判据）。

**反模式：把聚类标签直接当特征** —— 症状：簇标签不经稳定性评估就进下游模型；后果：聚类结果是模型的输出而不是数据的事实，每次重跑都可能给出不同的划分，下游模型的输入分布随之漂移，线下涨线上不稳；正确的做法是**先做多 seed / 多算法一致性评估，再落带版本的标签表**，并定义「标签变更时下游如何同步」。

**反模式：换编码器不重算全库** —— 症状：为了省重算成本，新旧向量混用同一索引；后果：向量空间变了之后，跨版本的余弦相似度没有意义，最近邻关系是噪声——**因为第三族的相似度完全由编码器定义，换编码器等于换度量**（7.3.2）；正确的做法是把「编码器版本 = 向量空间版本」写成硬纪律，换模型即整库重算，并保留版本标记以便回溯。

**换成另一个要动什么**：

| 迁移方向 | 数据 / 特征 | 计算与存储 | 评估与治理 | 团队再学习 |
| --- | --- | --- | --- | --- |
| K-Means → 密度聚类 | 无需改特征，但要补噪声处置流程与二维投影检查 | 从线性扫描换成邻域查询，需要空间索引 | 验收从「簇数对不对」变成「噪声比例能不能解释」 | 中：需掌握 ε / min_samples 与稳定性的关系 |
| 距离族 → 编码器族 | 需要重建整条向量管道，原始特征可能不再直接使用 | 新增全库编码算力与约 30 GB 级向量存储（10⁷ × 768 维【推算】） | 评估从几何指标换成内在相似度 + 下游任务双评估 | 中到高：编码器选型与版本管理是新技能 |
| 单机 → 两阶段 / 分布式 | 数据需可分批或流式读取 | 新增摘要维护与周期性重建；需要一致性对账 | 误差归因跨两阶段，评估口径要能定位到哪一层 | 中 |
| 一次性分析 → 周期性标签生产 | 需要稳定输入口径（否则每轮不可比） | 需要调度、版本与回溯 | 需建标签治理（版本、Owner、变更评审）与人工 review 预算 | 中到高：是组织成本而不只是技术成本 |

**上表里最容易被低估的一行是最后一行**：把一次性脚本变成周期性标签生产，技术改动不大，真正新增的是治理——而这部分成本只在标签开始被别处引用之后才显现。

**迁移的验收标准不是「新算法指标更好」**，因为两个不同的簇定义之间没有共同的评分函数可比——正确的验收标准是**下游动作是否变得更有用**：同一批用户按新分群投放，响应率、召回覆盖率或人工处置量是否真的变了。这意味着每一次换族都要有一个可比较的下游实验，而不是一次算法侧的对照；**代价是这条要求会把换族的决策周期拉长到一个业务实验的尺度**，而它也正是防止「按指标反复换算法」的唯一一道闸门。

### 7.8 小结

下表把「约束 → 方案 → 机制理由」压成一张速查表。每一行的理由都是机制而不是形容词：它说明这个方案**为什么能**在它假设的簇结构下工作。

| 你的处境 | 建议 | 关键理由（机制层面） |
| --- | --- | --- |
| 低维数值、规模大、要周期产出标签 | Mini-Batch K-Means | 每轮成本线性于样本数与簇数，且质心可被业务读懂 |
| 形状未知 + 噪声即产出 | DBSCAN / HDBSCAN | 簇由密度连通定义，噪声在算法内部就被显式标出 |
| 需要多档粒度 | 层次聚类 / BIRCH | 输出是树而不是一次划分，K 可在不同高度事后切 |
| 非凸 + 有关系矩阵 | 谱聚类 / Louvain | 特征向量编码的是连通性，把不可分的形状摊平 |
| 文本 / 图像语义归组 | 编码器 + 降维 + 密度聚类 + LLM 命名 | 编码器把语义转成可信距离，密度聚类负责结构与噪声 |
| 亿级 + 流式到达 | 摘要粗聚 + 微批细聚 | 第二阶段规模由摘要数 M 而非样本数 N 决定 |
| 数据不能出域 | 联邦聚类 | 质心更新只需要可加摘要，样本不出域 |
| 少量标签 + 大量无标签 | 聚类产伪标签 + 分类器 | 簇标签把无监督结构变成可预测的目标 |

> 本节小结：聚类选型中**唯一真正起决定作用的差异，是你假设一个簇是什么**——球、密度连通的一块、图上的连通块、高斯，还是树上的一棵子树。它决定用哪个算法，也决定了这个算法会以什么形状失效；其余约束（K 是否已知、规模、维度、稳定性、可解释性）只决定这个假设能否在当下被算出来、以及结果能否被消费。因此聚类选型的第一步不是比较算法，而是**先确认相似度可信、再看形状**——相似度错了任何算法都无用，形状没看任何比较都没有意义。
