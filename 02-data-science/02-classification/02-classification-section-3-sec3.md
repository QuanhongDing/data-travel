## 3. 设计模式与范式

### 3.1 先看约束：模式不是选择题，是约束的产物

分类模式的差异，根子上是**「标签信息从哪里来」**的差异。线性模型把判决信息放进人写的特征与交叉里；GBDT 把判决信息放进数据自身的划分里；深度模型把判决信息放进结构先验里（卷积的局部性、注意力的全局依赖）；LLM 把判决信息放进预训练语料里。同一张表、同一个标签，这四种「信息载体」能成立的前提完全不同 —— 所以「按场景选一个」的决策表会把人带偏，它把模型当成可替换的插件，而真实的选型是被约束推着走的。

第二件事是**信息量与自由度的匹配**。分类器的泛化上限由标注信息量决定，模型容量只决定它能不能把这个上限用出来。每类可用样本数、标签是否带层次、标签之间是否共现、决策延迟预算、误判代价结构 —— 任一条不同，同一场景的正确模式就不同。这就是为什么「结构化数据先上 GBDT」和「小样本直接用 LLM」这两条看似矛盾的建议可以同时成立：约束不同。

本主题下最容易被推翻的直觉是「模型能力排行榜」。排行榜比的是同等标注量下的拟合能力，而工业现场最常见的两种情况恰好落在排行榜的盲区：标注量小到任何强模型都会过拟合（此时正则与先验比容量更重要），以及延迟预算低到离线最强模型不能上线（此时服务侧账本比离线指标更有否决权）。先立约束，再谈模式。

还有一条常被忽略的约束是**反馈闭环的速度**。分类系统的真实质量标准不是某一版离线指标，而是「偏差被发现的周期」与「修正一版上线的周期」。当这两个周期都是月级时，复杂度必须压低到团队能在一次迭代内定位问题；当它们压到日级时，才谈得上在线学习、无监督兜底与级联复核这些需要持续运营的结构。模式选择在这里的差别不是精度，而是团队是否具备把系统长期跑住的能力。

| 约束 | 它决定了什么 | 本主题下最容易被它推翻的直觉 |
| --- | --- | --- |
| 标签信息量（每类可用标注样本数） | 决定假设空间的上限与正则强度 | 「数据不够就用更强的模型」—— 强模型在样本不足时先过拟合 |
| 决策模式（在线点查 / 离线批量打分 / 人机复核） | 决定推理路径能否含大模型、能否含实时特征拼装 | 「精度优先」—— 延迟超预算的模型等价于不可上线 |
| 变更频率与分布漂移（重训周期、类目新增频率） | 决定能否依赖重训，以及是否需要免训练路径 | 「一次训练长期使用」—— 漂移会把离线指标按期折损 |
| 一致性 / 可解释 / 合规要求 | 决定模型族与解释方式（权重、树路径、事后归因） | 「先上最准的」—— 无法解释的拒绝在强合规场景不能用 |
| 规模与成本约束（QPS、延迟、单次推理成本） | 决定特征维度上限、模型体积上限与是否需要蒸馏 | 「离线最好即上线最好」—— 离线指标不含账单 |
| 团队技能与运维能力 | 决定复杂度上限（自研训练框架、特征平台、监控） | 「别人能上我也能上」—— 缺监控套件的模型会静默劣化 |

### 3.2 模式逐个拆解

下面按 8 个模式逐个拆解。每个模式都追问同一组问题：它被什么约束逼出来、结构长什么样、为什么有效、必然付出什么代价、在什么条件下优点会反转。下文所有【公开】引用都给出「作者 + 标题 + 发表处 + 年份」，可按标题在出版方页面或 arXiv 检索到原文并核对版本。

先给一张总览，把每个模式与它依赖的「标签信息载体」对应起来 —— 后文的失效点，几乎都是这个载体在某个条件下被抽走或失效：

| 模式 | 判决信息载体 | 首要约束 | 结构层面的一句话 |
| --- | --- | --- | --- |
| 线性分类器优先 | 人写的特征与交叉 | 特征维度与延迟 | 一次稀疏点积，参数在特征维度上 |
| GBDT 主导 | 数据自身的划分 | 表格样本量 | 多棵树的残差加和，分段常数 |
| 深度学习特化 | 数据中的不变性（位置 / 时序） | 非结构化输入 + 标注量 | 参数在位置上共享 |
| LLM 增强 | 预训练语料 | 样本极少、类目常变 | 判决变成提示词与枚举约束 |
| 混合架构 | 流量的长尾分布 | 成本与覆盖的双重要求 | 路由把请求分到两条成本不同的路径 |
| 层次分类 | 标签的父子结构 | 叶类目分布极不均衡 | 逐层在兄弟节点间归一化 |
| 多任务分类 | 任务之间的相关性 | 部分标签样本稀疏 | 共享底层 + 任务独立塔 |
| 级联分类 | 误判代价的不对称 | 复核容量有限 | 先高召回粗筛，再高精度精判 |

#### 3.2.1 线性分类器优先（Linear-First）

- **被什么约束逼出来**：特征量级到亿级稀疏、QPS 到十万级、且必须能把「为什么判这一档」落到具体特征上时，只有线性假设既装得下特征维度、又能在延迟预算内完成一次点积。
- **结构**：

```text
score = σ( Σ w_i · x_i + b )        ← 全部参数在特征维度上，不在样本之间
特征侧（规则或人工交叉生成）：
  user_id:u123 = 1        hour=20 = 1        price_bucket=0-50 = 1
  交叉特征：gender=male × category=手机 → "male_手机" = 1
服务侧：稀疏向量点积 → sigmoid → 概率 → 阈值判定
→ 参数量 = 特征维度（可到 10^8~10^10 量级【经验】），与训练样本量解耦
```

- **为什么这样设计有效**：因为决策函数是特征的加性组合，所以每个参数的影响可以被单独读出（权重 × 取值），「为什么拒」能直接落到特征上；因为一次推理只做一次稀疏点积，推理成本与特征维度近似成正比、与「模型深度」无关，十万级 QPS 才有可能。
- **代价**：加性假设表达不了特征交互，这份工作量必然外移到特征工程 —— 需要维护一套特征生成与交叉的独立系统，交叉组合数随原始特征数近似二次增长，特征资产本身成为需要专人负责的模块，而不是模型的一部分。
- **失效点**：当决定性信息存在于特征交互中（如「深夜 + 异地 + 大额」的组合）时，本模式赖以立足的**可解释性会反转成误导**，因为权重只刻画主效应，团队会顺着权重去增删主效应特征，而真正决定结果的交互项永远不出现在解释里，离线指标长期不动而特征表持续膨胀。
- **真实使用**：Facebook 广告点击预估公开过「GBDT 产交叉特征 + LR 在线拟合」的结构（【公开】He et al., "Practical Lessons from Predicting Clicks on Ads at Facebook", ADKDD 2014）；小样本高维文本分类的经典基线是线性 SVM（【公开】Cortes & Vapnik, "Support-Vector Networks", Machine Learning, 1995）。工具面上，批量训练可以直接用 Spark MLlib 的 LR（【公开】Meng et al., "MLlib: Machine Learning in Apache Spark", JMLR 2016），亿级稀疏特征的在线服务则普遍走参数服务器架构（Angel、XDL 这类）【经验】。

#### 3.2.2 GBDT 主导（GBDT-Dominant）

- **被什么约束逼出来**：表格型数据、每类 10^3~10^6 级标注样本【经验】、特征已表格化且含缺失值与类别列、不要求绝对低延迟，此时任何「更复杂」的模型都换不回相应的精度。
- **结构**：

```text
F(x) = Σ_{m=1..M} f_m(x)         f_m = 一棵 CART 回归树
每一轮：拟合上一轮的负梯度（残差）→ 加一棵树 → 学习率 η 收缩
分裂约束：max_depth / max_leaf_nodes / min_child_weight 限制叶子「可信度」
XGBoost：二阶导数 + 正则项 Ω(f)      LightGBM：直方图分桶 + leaf-wise 生长
CatBoost：有序目标编码处理类别特征
→ 模型 = M 棵树的分段常数加和，天然免归一化、免缺失值填充
```

- **为什么这样设计有效**：因为分裂是对单特征按取值排序后切分，所以任何单特征单调变换（归一化、log、分箱）都不改变模型，预处理成本被内生消掉；因为每棵树只拟合上一轮残差，所以整体误差以加性方式被逐步拆解，训练集与验证集之间的差距可以用树数、深度、学习率三者直接调节。
- **代价**：参数是树结构与分裂点，模型体积随树数与深度增长（工业常见在 MB~百 MB 量级【经验】）；推理是 M 次树遍历，延迟与树数近似线性，且难以像线性模型那样按维度裁剪；叶节点是分段常数，对训练期未见过的取值不做任何平滑。
- **失效点**：当特征里出现高基数类别标识（用户 id、商品 id、设备 id）时，本模式「对缺失值与类别特征鲁棒」的优点会反转成**记忆性过拟合**，因为树的表达能力是分段常数，它会把每个高频 id 切进孤立叶子，训练集分数上去而新 id 覆盖不到。
- **真实使用**：结构化数据竞赛的获奖方案普遍以 GBDT 族为基座【经验】；工业三件套与其原始论文为 XGBoost（【公开】Chen & Guestrin, "XGBoost: A Scalable Tree Boosting System", KDD 2016）、LightGBM（【公开】Ke et al., "LightGBM: A Highly Efficient Gradient Boosting Decision Tree", NeurIPS 2017）、CatBoost（【公开】Prokhorenkova et al., "CatBoost: Unbiased Boosting with Categorical Features", NeurIPS 2018）。

#### 3.2.3 深度学习特化（DL-Specialized）

- **被什么约束逼出来**：输入是非结构化或高维稠密（像素、token、波形），且数据本身存在可被结构利用的不变性（平移不变、序列依赖、长程依赖），标注量足以撑起参数量。
- **结构**：

```text
图像：  H×W×3 → [Conv + BN + ReLU] × L → 全局池化 → FC → softmax(K)
        或切成 patch → [ViT block] × L → [CLS] 头（把局部性先验换成全局注意力）
文本：  token ids → Embedding → [Transformer block: MHA + FFN] × L → [CLS] 头
语音：  波形 / 梅尔谱 → [Conv 下采样] → [Transformer / Conformer] × L → 池化头
        自监督预训练路线用 Wav2Vec 2.0，大规模弱监督路线用 Whisper
多模态：各模态各出一个向量 → 投影到同一空间 → 点积对齐（CLIP 式双塔）
        或冻结两个编码器 + 跨模态注意力融合（Flamingo / GPT-4V 式）
强时序：位置编码（可学习 / 正弦 / 相对位置）把「第几步」显式注入注意力
共同点：同一组参数在空间 / 时间位置上复用 → 参数量与输入尺寸解耦
```

- **为什么这样设计有效**：因为核参数在所有位置共享，所以同一个局部模式在图像任何位置出现都得到相同响应，模型不必为「每个位置的同一模式」分别准备样本 —— 这是「特征自动学习」能成立的结构前提，也是它比全连接更省样本的原因。
- **代价**：训练必须用加速器，单次全量训练的成本随参数量与数据量增长；推理延迟通常比树模型高 1~2 个数量级【经验】；误差归因需要额外手段（注意力可视化、扰动分析），模型本身不给原因。
- **失效点**：当标注量低于参数量能支撑的量级时，本模式「用结构先验换取表达力」的优点会反转成**对训练集的记忆**，因为先验只能约束函数形状、不能替代样本提供的约束；典型信号是训练集指标持续上升而验证集停滞或下降。
- **真实使用**：医学影像读片的公开基线与评测数据（【公开】Rajpurkar et al., "CheXNet: Radiologist-Level Pneumonia Detection on Chest X-Rays with Deep Learning", 2017）；通用视觉骨干（【公开】He et al., "Deep Residual Learning for Image Recognition"（ResNet）, CVPR 2016）与把局部性先验换成全局注意力的一支（【公开】Dosovitskiy et al., "An Image is Worth 16x16 Words"（ViT）, ICLR 2021）；文本预训练与微调范式（【公开】Devlin et al., "BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding", NAACL 2019）；语音的自监督与弱监督路线（【公开】Baevski et al., "wav2vec 2.0", NeurIPS 2020；【公开】Radford et al., "Robust Speech Recognition via Large-Scale Weak Supervision"（Whisper）, 2022）；跨模态融合（【公开】Alayrac et al., "Flamingo: a Visual Language Model for Few-Shot Learning", NeurIPS 2022；【公开】OpenAI, "GPT-4V(ision) System Card", 2023）；图像-文本对齐的零样本路线见 3.2.4。

#### 3.2.4 LLM 增强（LLM-Augmented）

- **被什么约束逼出来**：每类标注样本为个位数甚至为零（新类目、冷启动、长尾），或标签空间随业务按周变更、重训周期追不上变更速度；同时业务能接受更高的延迟与单位成本。
- **结构**：

```text
零样本：文本 x + 类别清单 {c1..cK} → Prompt 模板 → LLM → 结构化输出（枚举 / JSON）
少样本：Prompt 内放 k 个标注示例（k 常见 1~8【经验】）→ 同上
打标机：LLM 只离线产标签 → 训练小模型 → 小模型上线（把 LLM 成本挪到离线）
必需校验层：输出必须落在枚举内 + 附置信度 → 越界即拒答或转人工
```

- **为什么这样设计有效**：因为判决所需的信息（类别语义、常识、领域词的关系）已在预训练语料中，所以不必再用样本向模型注入一次同类信息；因为接口是自然语言，新增一个类只需改枚举值与提示词，不需要重新训练与发布。
- **代价**：单次调用延迟与成本都显著高于本地分类器【经验】；输出不是确定性的（同一输入不同调用可能给出不同标签），标签口径难以冻结，评测必须脱离「人工看一眼」而建立固定对照集。
- **失效点**：当类别定义依赖私有业务口径（只有本组织知道边界）时，本模式「不需要训练数据」的优点会反转成**按公开语义猜测**，因为预训练先验覆盖不到私有定义，零样本准确率退化到接近按类名字面分布猜；此时必须补少样本示例与固定评测集。
- **真实使用**：图像-文本对齐支撑零样本分类（【公开】Radford et al., "Learning Transferable Visual Models From Natural Language Supervision"（CLIP）, ICML 2021）；免提示词的少样本文本分类路线（【公开】Tunstall et al., "Efficient Few-Shot Learning Without Prompts"（SetFit）, 2022）。

#### 3.2.5 混合架构（Hybrid）

- **被什么约束逼出来**：同一业务里同时存在高频主流样本（成本与延迟敏感、标注充足）与长尾难样本（样本极少、需要世界知识），任何单一模型都会在某一端失分。
- **结构**：

```text
x → [路由器 router] ─┬─ 类目频次高 且 专用模型置信度 ≥ t → 专用分类器（LR / GBDT / 小模型）
                     └─ 低频类目 / 置信度 < t / 新类目        → LLM（few-shot）→ y'
                                   ↓
                     两路结果与置信度回流 → 样本库 → 专用模型增量重训
路由信号：类目历史频次、专用模型置信度、特征缺失率、是否命中新类目白名单
```

- **为什么这样设计有效**：因为路由按「类目频次 × 置信度」把请求分流，所以占比最高的主流流量留在低成本路径，只有长尾付出大模型单价 —— 混合架构的价值来自流量分布的长尾特性，而不是来自某个模型更强；同时 LLM 的调用日志天然成为长尾样本的采集渠道。
- **代价**：多一条需要监控的路由逻辑与两套评估口径；两套模型的标签定义必须完全一致，否则回流样本会污染专用模型；路由阈值本身是需要持续调的超参，且它的漂移不会自己暴露。
- **失效点**：当长尾流量占比上升（新类目批量出现、分布漂移）时，本模式「高频走便宜路径」的优点会反转成**成本与延迟同时上涨**，因为路由器仍按历史频次标注分流，而实际流量已经从头部分散到尾部，被判定为「长尾」的比例越走越高。
- **真实使用**：工业上的常见折中是「小模型处理绝大多数请求、大模型只处理困难子集」【经验】；内容审核中「仅对模型分歧样本调用大模型」是同一思路的实例，见 [§6 落地实践](02-classification-section-6-sec6.md)。

#### 3.2.6 层次分类（Hierarchical）

- **被什么约束逼出来**：标签本身带父子结构（商品类目、疾病编码体系），底层类目数量大且分布极不均衡，扁平多分类在底部类目上样本不足。
- **结构**：

```text
标签树：电子产品 → 手机 → 智能手机 / 功能机 …
结构选择 A（扁平）：K = 全部叶节点数 → 一次 softmax(K)
结构选择 B（逐层）：每层一个分类器，父层预测决定子层的候选子集
  P(电子产品) = 0.62  →  在子集内 softmax(手机, 电脑, 配件) = 0.71
  → 同一路径内逐层归一化，路径外节点的概率记 0
硬约束：父层概率 = 该父节点下所有子节点概率之和，否则线上会出现自相矛盾的输出
```

- **为什么这样设计有效**：因为每层的分类器只在同一父节点下的兄弟之间比较，所以每层要区分的类数远小于叶节点总数，每层内部的类分布更接近平衡；同时每层的错误只影响该路径，不会让整棵树的所有类同时受污染。
- **代价**：误差沿层累积，路径上任意一层判错则后续层必然在错误的候选子集内比较；训练与上线要维护 L 个模型（或一个多头模型）与 L 套评估；标签树的任何结构变更（新增、移动节点）都会改变各层候选集，触发重训。
- **失效点**：当父层比子层更难判（父类识别精度低于子类）时，本模式「每层只学一个层次」的优点会反转成**错误沿层放大**，因为后续层被硬限制在错误的候选子集内，无法纠正父层的错误；此时应改为全路径打分再在路径间做一致性约束。
- **真实使用**：疾病编码体系本身是公开的层次化分类任务（【公开】WHO《国际疾病分类》ICD 编码体系，现行主版本为 2019 年获世界卫生大会通过的 ICD-11）；电商类目是最常见的工业层次分类场景【经验】。

#### 3.2.7 多任务分类（Multi-task）

- **被什么约束逼出来**：多个相关标签（点击、转化、时长）共用同一批曝光样本，其中部分标签的监督信号天然稀疏（转化只在点击后的样本上才有），单独建模时该任务样本量不足。
- **结构**：

```text
共享底层（embedding / 底层网络）─┬─ [门控或专家组合] ─┬─ 任务 A 塔 → σ → p_A
                                 │                    └─ 任务 B 塔 → σ → p_B
                                 └─ 稀疏任务：只在有前置条件的样本上计算损失
总损失：L = Σ_t w_t · L_t        （w_t 需按各任务量级校准）
最终排序分由各任务头组合（如 p_A × p_B），而不是只用单个任务头
```

- **为什么这样设计有效**：因为共享底层的参数由所有任务的样本共同更新，所以样本量少的任务从样本量大的任务那里借到了表示能力 —— 这才是稀疏任务能收敛的原因，它不是「学会了另一个任务」，而是获得了更多数据支撑的共享表示。
- **代价**：多套标注与多套回流（样本采集、标注、回溯都要按任务分别做）；任务之间可能存在梯度冲突，强任务会长期压制弱任务；损失权重成为新一层需要调、且效果敏感的配置。
- **失效点**：当任务之间相关性低甚至负相关时，本模式「共享底层缓解稀疏」的优点会反转成**任务互相拖累**，因为共享参数被方向冲突的梯度占据，共享层越强、弱任务被压得越死；此时应改为多专家加门控的拆分结构或直接分模型。
- **真实使用**：MMoE（【公开】Ma et al., "Modeling Task Relationships in Multi-task Learning with Multi-gate Mixture-of-Experts", KDD 2018）、ESMM（【公开】Ma et al., "Entire Space Multi-Task Model: An Effective Approach for Estimating Post-Click Conversion Rate", SIGIR 2018）、PLE（【公开】Tang et al., "Progressive Layered Extraction (PLE): A Novel Multi-Task Learning (MTL) Model for Personalized Recommendations", RecSys 2020）。

#### 3.2.8 级联分类（Cascade）

- **被什么约束逼出来**：类别极不平衡且误判代价不对称（漏检代价远高于误报），而高精度复核的容量（人工席位、昂贵特征、大模型预算）有限，单模型单阈值无法同时满足召回与精确。
- **结构**：

```text
第一级（粗筛，高召回，特征便宜）：
    score₁ = cheap_model(x)
    score₁ < t₁  →  判负，放行（不再进入下一级）
    score₁ ≥ t₁  →  进入第二级
第二级（精判，高精度，特征昂贵 / 大模型 / 人工）：
    score₂ < t₂  →  判负
    score₂ ≥ t₂  →  拦截 / 送人工复核
阈值标定方向：t₁ 由「可接受漏检率」反推，t₂ 由「复核容量」反推
```

- **为什么这样设计有效**：因为第一级只回答「能否排除」（一个比原问题更简单的判别问题），所以绝大多数样本在便宜路径上被处理掉，昂贵容量只被少量可疑样本占用 —— 级联能否成立取决于第一级的过滤率与第二级在剩余样本上的精度是否同时达标。
- **代价**：两套模型、两个阈值、一条新链路都要监控；两级的误差会叠加，被第一级排除的样本在后续永远不会被重新评估；阈值标定需要业务给出漏检代价，而这个数字业务侧往往给不出。
- **失效点**：当为省成本把第一级阈值调激进时，本模式「便宜路径承担大多数样本」的优点会反转成**召回上限被第一级锁死**，因为被第一级放行的样本不会进入第二级；更危险的是这个损失在离线评估里常常看不见 —— 评估集用的是同一套规则，被排除的样本同样被排除，只有线上业务指标会暴露。
- **真实使用**：医学筛查是两阶段结构的典型场景（先高召回初筛、再高精度复核）；工业风控中的「规则前置硬拦 + 模型打分 + 人工复核」是同类结构【经验】。

### 3.3 模式选择决策表

| 约束组合 | 推荐模式 | 为什么不选另一个 | 关键判据 |
| --- | --- | --- | --- |
| 每类标注 < 1000 + 表格数据 | GBDT 主导（强正则、限制深度）、TabPFN / SVM，或 LLM 少样本 | 深度网络参数量远超样本支撑的自由度，先过拟合；TabPFN / SVM 的假设空间更贴合这个样本量 | 每类样本数与模型自由度之比 |
| 每类标注 10^3~10^6 + 表格数据 | GBDT 主导 | 线性模型欠拟合特征交互 | 关键信息是否在特征交互中 |
| 特征稀疏到 10^8 维 + QPS ≥ 10^5 | 线性分类器优先（FM / DeepFM 把二阶交叉内建进模型，或 GBDT / 深度产交叉特征再喂给 LR） | 树与深度模型无法在延迟预算内遍历亿级稀疏特征 | 单请求延迟预算与特征维度 |
| 输入为图像 / 文本 / 语音（波形）/ 图文对 + 标注 ≥ 10^3 | 深度学习特化：图像走 CNN 或 ViT、文本走 BERT 类预训练骨干、语音走 Wav2Vec 2.0 / Whisper、图文对齐走 CLIP 式双塔 | 表格式模型无法利用位置、局部性与跨模态对齐结构 | 数据是否存在可共享的空间 / 序列 / 跨模态结构 |
| 输入含两种以上模态（图文、音视频） | 跨模态对齐模型（CLIP 式双塔，零样本可用）或跨模态融合模型（Flamingo / GPT-4V 式） | 单模态模型看不到模态间的一致与矛盾；各自编码后再拼接，互补信息在拼接前已被压掉 | 跨模态对齐本身是否构成判别依据 |
| 顺序本身决定标签（事件序列、时间步、强时序） | Transformer + 时序位置编码（或 LSTM 类序列模型） | 池化 / 袋化模型把顺序当噪声平均掉，顺序信息进不了决策 | 打乱时间步后标签是否改变 |
| 类目按周新增 + 每类样本 < 100 | LLM 增强（或混合架构） | 任何依赖重训的模式都追不上类目变更速度 | 类目新增频率与重训周期 |
| 长尾与高频流量并存且量级都大 | 混合架构 | 单一路径必然在成本或覆盖上失分 | 流量分布的长尾占比 |
| 标签存在真实父子结构 | 层次分类 | 扁平 softmax 在底部类目上样本不足 | 是否存在稳定的层次约束 |
| 多相关标签且部分标签稀疏 | 多任务分类 | 分模型训练让稀疏任务样本不足 | 标签共现结构与稀疏度 |
| 极不平衡 + 复核容量有限 | 级联分类 + 代价敏感损失（Focal Loss 等）+ 按代价标定阈值 | 单模型单阈值无法同时满足召回与精确；等权损失把多数类的梯度当成主要信号 | 可接受漏检率与复核容量 |
| 需要逐条解释拒绝理由且强合规 | 线性分类器优先，或决策树 / EBM 这类本身可解释的加性模型（树 + SHAP 事后归因是次选，须接受归因只是近似） | 深度模型的归因不构成决策过程本身 | 监管是否接受事后归因 |
| 类目语义开放、边界由业务持续定义 | 混合架构（LLM 只做打标或兜底） | 纯 LLM 路径不产出可聚合的类目概率与层次一致性 | 类目口径是否必须冻结 |

本主题下最常被误选的一对是「GBDT 主导 ↔ 深度学习特化」在表格数据上的错位：团队看到深度模型在图像、文本上的优势，把它平移到表格任务，于是拿到一个训练集分数很高、验证集不如基线的模型，还要额外背上加速器与推理延迟的账。误选的实际后果不是「精度略低」，而是**上线时间被拖长、延迟预算被吃掉、可解释通道被打掉**三件事同时发生，而这三件事都属于上线门槛而非精度问题。

第二常被误选的一对是「LLM 增强 ↔ 层次分类 / 多任务」在类目治理上的错位。类目多且长尾时，第一反应是把整个分类任务交给 LLM，短期确实省事；但 LLM 不产生「类目之间的层次一致性」，也不产生可聚合的类目概率分布，于是长尾类目的口径会一天一个样，跨类目的统计报表无法发布。正确顺序是先确定标签树与共现结构（数据侧的事），再用 LLM 去补那些树上也覆盖不到的长尾；反过来做，等于把一个需要长期治理的类目体系交给一个不保证口径的组件。

表里「推荐模式」一列给的是模式族，族内还有按更细约束分出的候选：标注量在百级以下的表格任务，除强正则的 GBDT 外可以试免训练的小样本表格先验（【公开】Hollmann et al., "TabPFN: A Transformer That Solves Small Tabular Classification Problems in a Second", ICLR 2023）或 SVM；不平衡场景除重采样与改权重外，还有直接改损失形状的 Focal Loss（【公开】Lin et al., "Focal Loss for Dense Object Detection", ICCV 2017）；二阶交叉不想靠人工枚举时，FM 与 DeepFM 把交叉内建进模型（【公开】Rendle, "Factorization Machines", ICDM 2010；【公开】Guo et al., "DeepFM: A Factorization-Machine based Neural Network for CTR Prediction", IJCAI 2017）；要可解释又不愿被纯加性假设限制时，EBM / GA2M 这类本身可解释的加性模型是折中（【公开】Lou et al., "Accurate Intelligible Models with Pairwise Interactions", KDD 2013），SHAP 是事后归因侧的通用做法（【公开】Lundberg & Lee, "A Unified Approach to Interpreting Model Predictions", NeurIPS 2017）。这些候选各自只对应表中某一列的约束，谁都不是普适的更优选择 —— 把其中任意一个当成默认值，就回到了本节开头说的「按排行榜选型」。

用这张表时有一条纪律：**先选出「不可谈判」的那一列约束**。延迟预算、合规解释要求、类目变更频率这三条中的任意一条被满足时，它的优先级高于精度 —— 因为它们决定模型能不能上线，而精度只决定上线后好多少。把可上线的模式先定下来，再在它的实现细节里榨精度（阈值、特征、蒸馏、融合），这才是工程顺序；反过来先追精度再去找上线方案，通常会把整条链路重做一遍。

### 3.4 组合模式：真实系统不会只用一种

**组合一：规则引擎 / 线性基座 + GBDT 主判**。规则承担硬约束拦截（黑名单、金额上限、合规禁用项），线性基座承担可解释的评分通道，GBDT 承担主要判别。职责边界按「可解释性要求 × 延迟预算」划：合规必须解释的部分走线性与规则，其余走树。运维代价是两套阈值标定与一致性对账 —— 规则拦下的样本不再进入模型评估，会让模型的训练分布相对线上偏移，需要定期用「规则旁路」实验校准这份偏移。适合万级 QPS、强合规的金融与风控场景。

**组合二：GBDT / 深度模型产特征 + 线性模型在线服务**。树或深度模型离线学习特征交叉，把交叉结果作为稀疏特征喂给线上线性模型。职责边界是「离线负责发现交叉、线上负责低延迟打分」。运维代价是要保证离线产特征与线上实时特征在同一时间口径下对齐（同一份交叉特征若在两侧用了不同的时间窗口，离线与线上指标会长期分离且互不归因）；适合特征维度上亿、QPS 十万级且延迟预算紧张的场景。

**组合三：多任务共享底层 + 混合架构分流**。多任务头在共享表示上联合训练（缓解稀疏标签），输出的置信度再作为混合路由的判据（低置信样本转 LLM 或人工）。职责边界是「多任务负责主流样本的联合建模、混合路由负责长尾兜底」。运维代价最高：多套标注、两套评估、一条路由链路与一套回流样本治理，且回流样本的标签质量直接决定共享底层的质量，通常到千万级日请求量、且类目分布明显长尾时才值得投入。

三种组合的共同点是：每一层只做一件它最擅长的事，并且**上一层的输出必须是下一层能校验的**。规则输出的是确定命中，模型输出的是概率，LLM 输出的是枚举标签加置信度 —— 只有概率与枚举这两类输出，才谈得上阈值与路由；如果某一层输出的是一段自然语言，那么它下游的所有自动化环节都会失去判据。这也是判断「某次组合是否过度」的最快方法：看这条链路上有几处需要人读文本才能继续。

### 3.5 反模式与失效分析

| 反模式 | 症状（怎么发现它） | 后果（机制层面） | 成因（为什么团队会写成这样） | 修法 |
| --- | --- | --- | --- | --- |
| 「先上深度学习」 | 表格特征百级、每类样本千级，训练集损失很低而验证集不收敛 | 参数量远超样本支撑的自由度，模型记住训练集，同时失去可解释与低延迟 | 把「更强」当成能力印象，忽略了强度必须与标注量匹配 | 先跑 GBDT 基线，深度模型只在基线跑不动或精度不足时引入 |
| 「类别不平衡直接训练」 | 输出几乎全是同一个类，混淆矩阵只有一列有数 | 损失被多数类主导，少数类梯度贡献过低 | 默认损失对各类等权，而样本比例天然不等权 | 类权重 / 重采样 / 按业务代价改损失，并与多数类基线对照 |
| 「特征穿越」 | 离线指标异常高、上线掉一个档次；按时间打散后指标大跌 | 训练时用到了预测时刻尚不可得的特征 | 特征按「当前值」取，而不是按预测时刻取 | 用带时间戳的特征快照做 Point-in-Time 对齐 |
| 「标签泄漏」 | 验证指标接近 1.0，训练验证重复样本占比高 | 训练与验证共享信息，验证集不再是未见样本 | 切分在特征构造之后，或对时间相关数据做随机切分 | 先按时间 / 实体切分，再统计归一化参数 |
| 「一味追求 AUC」 | 离线 AUC 微涨而业务指标不动 | 排序指标与业务代价脱钩（AUC 与阈值无关） | 用通用指标替代业务目标 | 写清代价矩阵，改看 PR-AUC 与固定误报率下的召回 |
| 「类别权重拍脑袋」 | 少数类召回上去了但精确率崩，误报投诉上升 | 权重等价于给漏检定价，而定价没有被显式写出来 | 把不平衡当成「数据集问题」，它其实是「代价问题」 | 用代价矩阵定权重与阈值，画 PR 曲线选点 |
| 「用 accuracy 评估不平衡数据」 | 报告的准确率恰好等于多数类占比 | 该指标没有信息量（全预测多数类即得此值） | 沿用平衡数据集的评估习惯 | 换 F1 / PR-AUC / 召回@固定误报率 |
| 「多标签用 softmax」 | 真实共现的两个标签概率互相压制 | softmax 的互斥归一化与共现标签结构冲突 | 把多分类模板直接套到多标签任务 | 每标签独立 sigmoid + BCE，每类单独定阈值 |
| 「模型越大越好」 | 参数量涨一个量级，验证指标持平或下降 | 泛化上限由样本量决定，容量只增加拟合能力 | 用「更大即更强」替代容量匹配 | 先测容量-样本量曲线，再用蒸馏 / 剪枝换延迟 |
| 「忽视校准」 | 输出 0.9 的样本实际正例率明显偏低 | 排序可能正确但概率不可解释，阈值与期望收益失真 | 只评估排序指标，不评估概率本身 | 用独立校准集（或交叉拟合）拟合 Platt / Isotonic 单调映射，评估 Brier / LogLoss |
| 「忽视推理成本」 | 离线方案很好，成本测算在评审阶段被否 | 推理路径的延迟与成本由特征拼装与模型遍历决定 | 选型只看离线指标，不算服务侧账单 | 用 QPS × 延迟预算反推模型上限，必要时蒸馏或预计算 |
| 「LLM 分类无评估」 | 抽样结果时好时坏，没有口径一致的对照集 | 生成式输出没有稳定边界，错例无法定位与回归 | 把 LLM 当确定性分类器用 | 建 Golden Set + 结构化输出 + 越界拒答 + 回归评估 |

最危险的反模式在生产中的暴露方式各不相同，下面挑出几条展开（其中「用 accuracy 评估不平衡数据」与「类别权重拍脑袋」常是同一个团队的两个阶段，合在一段讲）：

**特征穿越**不会表现为报错，而是表现为「上线当天指标打折」。它的机制是训练分布里含有一个线上取不到的特征，模型把一部分判决权分给了它，线上该特征恒为默认值，等价于模型的一部分权重永远失效；排查手段是逐特征做「时间打散实验」—— 把训练集按时间重排后重训，指标大幅下跌的那一列就是泄漏列。

**忽视校准**的影响不在模型侧而在决策侧。阈值是把概率翻译成动作的唯一开关，而多数梯度提升实现的输出概率并不等于实际频率，于是「按 0.5 切」或「按 0.9 自动处置」这类规则会系统性偏移；表现是自动处置比例远高于预期、或人工复核队列忽长忽短。修法是用独立校准集拟合单调映射，并评估概率误差（Brier / LogLoss），而不是只看 AUC。

**LLM 分类无评估**的危险在于它不产生异常指标，只产生不可复现的标签。生成式输出没有枚举约束时，同一输入可能返回不同措辞、不同粒度甚至越界类别，错误无法被聚合统计、也无法回归验证；一旦这批标签进入训练集，脏标签会以「模型效果波动」的形式在下游出现。修法是先冻结标签口径、强制结构化输出并拒答越界，再让 LLM 只做离线打标而由可评估的小模型上线。

**「用 accuracy 评估不平衡数据」与「类别权重拍脑袋」通常是同一个团队的两个阶段**：先用 accuracy 得出「模型很好」的结论，上线后发现少数类几乎抓不到，于是直接给少数类加大权重。这两步都跳过了同一件工作 —— 把业务代价写成矩阵。缺少代价矩阵时，权重与阈值只能凭感觉调，而每一次调整都会在「误报投诉」与「漏检事故」之间来回摆动，团队最后会把问题归因为「数据不可用」，而实际缺的是一份可为阈值定标的代价定义。

阈值该定在哪里可以直接推出来：【推算】设正类占比为 p、在阈值 t 处的漏检率为 FNR(t)、误报率为 FPR(t)、单次漏检与单次误报的业务代价分别为 C_漏检与 C_误报，则期望代价 ≈ p·FNR(t)·C_漏检 + (1−p)·FPR(t)·C_误报；使该式最小的 t 由两项的边际变化相等处决定，只与 p 以及两种代价的比值有关。代入后即可看出：「默认 0.5」只在「两类各占一半且两种错误代价相等」时才最优 —— 欺诈这类 p 在千分之一量级【经验】、且漏检代价远高于误报的场景里，最优阈值必然远离 0.5。

**「模型越大越好」在评审阶段很难被拦住**，因为它的代价以账单和延迟的形式出现在别人的环节里。把「离线指标 + 参数量」作为选型材料的方案，通常缺少一条最简单的对照：在固定延迟预算下，把容量从小到大扫一遍，看验证指标在第几档转平。转平点之后的容量只增加成本，不增加泛化。

这 12 条反模式里，有 8 条的共同成因是**把「模型指标」当成「系统指标」**：特征穿越、一味追求 AUC、类别权重拍脑袋、用 accuracy 评估不平衡数据、忽视校准、忽视推理成本、模型越大越好、LLM 分类无评估，都是同一个错误的变体 —— 用离线数字代表上线效果，而离线数字里既不含时间方向（穿越）、也不含代价结构（阈值）、也不含服务侧账本（延迟与成本）、也不含口径稳定性（LLM）。剩下 4 条（先上深度学习、类别不平衡直接训练、标签泄漏、多标签用 softmax）属于另一类：结构模板套错任务，修法都在结构层而非调参层。

### 3.6 规模跃迁时模式何时该换

| 跃迁 | 原模式 | 为什么开始疼 | 换成 | 迁移的代价 |
| --- | --- | --- | --- | --- |
| 每类样本百级 → 十万级（表格） | LLM 少样本 / TabPFN | 每次预测都要调用外部模型，成本随请求量线性增长，标签口径也难冻结 | GBDT 主导的专用模型 | 需建立标注与回流管线，重做阈值与解释口径 |
| 每类样本千级 → 十万级（表格） | 线性 / 强正则的小模型 | 加性假设成为偏差项，特征工程的人力增速追不上精度增速 | GBDT 主导 | 重做特征重要性与解释口径，替换合规解释链路 |
| 特征百级 → 亿级稀疏（CTR 类） | GBDT 主导 | 亿级稀疏高基数特征让树退化为按 id 记忆 | 线性优先 + 交叉特征（或 GBDT / 深度产交叉） | 建稀疏特征管道与参数服务器，重做线上特征拼装 |
| QPS 百级 → 十万级 | 深度学习特化 | 单次推理延迟乘上 QPS 后硬件成本不可接受 | 蒸馏到小模型 / 双塔 / 线性 | 精度回落需要重新标定阈值与业务对齐 |
| 类目百级 → 万级长尾 | 扁平多分类 | 底部类目样本不足，头部类目主导损失 | 层次分类 + LLM 兜底 | 维护标签树与各层评估，历史标签需重新映射 |
| 单目标 → 多目标 | 单任务模型 | 单目标最优会牺牲其他目标（如只优化点击伤了转化） | 多任务分类（共享底层 + 任务塔） | 多套标注与回流建设，损失权重调参周期 |
| 漂移周期月级 → 日级 | 定期重训的静态模型 | 两次重训之间指标持续折损，黑产或新类目一周内适配 | 在线 / 增量更新 + 无监督兜底通道 | 需要特征时效性治理与漂移监控，评测口径改为滚动窗口 |
| 单标签 → 多标签共存 | 单标签 softmax 模型 | softmax 的互斥归一化与共现标签的结构冲突 | 每标签独立 sigmoid + 分类阈值标定 | 标注口径重定义，每类阈值需重新标定与业务对账 |
| 单模态 → 多模态共现（图文、音视频） | 单模态编码器 + 后期拼接 | 各模态的互补与矛盾信息在拼接前已被各自编码器压掉 | 跨模态对齐（CLIP 式双塔）或跨模态注意力融合 | 需成对 / 多模态标注与新的评测口径，历史单模态样本需重新配平 |
| 弱时序 → 顺序成为判别依据 | 池化 / 袋化模型 | 顺序信息被平均掉，模型只看到「有哪些」而看不到「先后」 | Transformer + 时序位置编码（或 LSTM 类序列模型） | 需重建样本构造与位置编码方式，评测改为按时间切分 |
| 训练数据从单机可容纳 → 超出单机 | 单机 GBDT / 单机训练脚本 | 直方图与特征统计需要全量数据驻留，训练时长跨过可用窗口 | 分布式 GBDT 或参数服务器 + 稀疏特征管道 | 需要重建特征管道并做两侧一致性对账 |

上表的每一行都不是「换个更好的模型」，而是**换一种让判决信息进入系统的方式**。这也是跃迁容易做错的原因：团队往往在同一模式内加大容量（更多树、更深网络、更多参数），而真正需要换的是信息载体 —— 从人写特征换成数据划分，从数据划分换成结构先验，从结构先验换成预训练语料。判断该不该换，看的不是当前指标掉了多少，而是「新增标注的边际收益」是否已经低于「新增容量的边际收益」：前者转平，说明当前载体已经把信息用尽，加容量只会过拟合；后者转平，说明载体还有余量，继续攒样本即可。

### 3.7 自检清单

- [ ] 是否先写了「每类可用标注样本数 × 延迟预算」这两个数字，再选模型族？（没有这两个数字的选型是印象选型）
- [ ] 是否有一个不依赖模型的评估基线（多数类 / 规则 / 上一版模型），并报告它与新模型的差值？
- [ ] 评估指标是否与业务代价对齐：不平衡场景是否给出 PR-AUC 或「固定误报率下的召回」，而不是只给 accuracy 与 AUC？
- [ ] 每一列特征是否标注了「预测时刻是否可得」？有没有做过按时间打散的重训实验来验证无穿越？
- [ ] 特征统计量（均值、方差、分箱边界）是否只从训练集计算，并在推理时按同一版本读取？
- [ ] 概率输出是否在独立校准集（或交叉拟合）上完成校准，并报告了 Brier / LogLoss？自动处置类规则是否用校准后的概率定阈值？
- [ ] 多标签任务的输出层是否为每标签独立 sigmoid，每类阈值是否分别标定？
- [ ] 层次分类的父层概率是否等于其子层概率之和（线上抽检即可验证）？
- [ ] 多任务的损失权重是否按任务量级校准，并做过「去掉某任务」的消融对照？
- [ ] 级联结构的第一级阈值是否由可接受漏检率反推，且做过「第一级放宽 / 收紧」的敏感性分析？
- [ ] 混合架构是否监控了两条路径的流量占比随时间的变化（长尾占比上升会同时推高成本与延迟）？
- [ ] LLM 相关路径是否有冻结的 Golden Set 与回归评估，且输出被约束在枚举内、越界会拒答？

### 3.8 小结

下表把「约束 → 模式 → 机制理由」压成一张速查表。注意每一行的理由都是机制而不是形容词：它说明的是这个模式**为什么能**把信息带进决策边界，而不是它「更好」。

| 你的约束 | 建议模式 | 关键理由（机制层面） |
| --- | --- | --- |
| 标注极少、类目还在变 | LLM 增强 | 判决信息来自预训练先验，不依赖自有标注样本 |
| 表格数据、样本千到百万级 | GBDT 主导 | 分段常数加和对单特征单调变换免疫，预处理成本低 |
| 亿级稀疏特征、十万级 QPS | 线性分类器优先 | 参数量随特征维度而非样本量增长，推理只有一次点积 |
| 非结构化输入且标注充足 | 深度学习特化 | 参数在位置上共享，同一局部模式不必逐位置重复学习 |
| 长尾与主流流量都大 | 混合架构 | 按频次 × 置信度分流，让成本跟着长尾占比走 |
| 部分标签天然稀疏 | 多任务分类 | 共享参数由全部任务样本更新，稀疏任务借到表示 |
| 漏检代价远高于误报 | 级联分类 | 把判别拆成「能否排除」与「是否命中」，复核容量才够用 |

> 本节小结：分类模式的选择最终只由一条约束决定 —— **每个类别的标签信息从哪里来、有多少**。信息在人写的特征里就选线性，在数据自身的划分里就选树，在结构先验里就选深度网络，在预训练语料里就选 LLM；其余约束（延迟、成本、可解释、漂移）只决定这条主线上的实现细节与兜底通道。忘记这一条，就会把「模型更强」误当成「系统更好」。
>
> 落地顺序上，一条经验路线是：先用规则与线性模型跑通「特征 → 训练 → 在线服务 → 反馈回流」全链路并确立评估口径；样本攒到千级到百万级且为表格数据时切到 GBDT；特征维度与 QPS 量级逼迫时再加交叉特征与多任务；只有当标注极稀缺或类目高频变化时，才引入 LLM 与混合路由。倒过来做（先上大模型再补评估口径）会把最难的那部分工作留到最后，而它恰恰是决定系统能否长期运行的部分。
>
> 💡 **思考锚点**：把你的错误代价写进本节那条期望代价式 p·FNR(t)·C_漏检 + (1−p)·FPR(t)·C_误报——若漏检代价远高于误报（即 C_漏检 远大于 C_误报）、正类占比 p 在千分之一量级，代入后使该式最小的阈值会落在哪一档，和你现在用的 0.5 差多远？你线上这个阈值是从这个式子推出来的，还是拍出来的？
