## 7. 与其他方法对比

### 7.1 先立判据：为什么打分表会误导

打分表最根本的问题不是「打得不准」，而是它把**取决于场景的结论**包装成**绝对结论**。分类领域的列与列之间，差异往往不是「同一能力的高低」，而是「判决信息被放在了不同的载体里」——线性模型把判决权放进人写的特征与交叉里，树把它放进数据自身的划分里，深度网络把它放进结构先验里，LLM 把它放进预训练语料里（详见 [§3 设计模式与范式](02-classification-section-3-sec3.md) 的载体总览）。同一份数据、同一个标签，这四种载体的相对优劣会随「每类可用标注样本数」与「延迟预算」这两个变量翻转，而打分表的每一格都只有一个数。

举一个同一维度指向相反答案的例子。若按直觉给「可解释性」打分，线性模型会拿到高分、GBDT 拿到中低分；但在两类真实场景里这个排序会反过来。低延迟、亿级稀疏特征的 CTR 场景里，线性模型的权重只刻画主效应，当决定性信息存在于交互项（深夜 × 异地 × 大额）中时，「可解释」会反转成误导——权重表读起来清楚，而真正决定结果的那一项永远不会出现在解释里，团队会顺着权重去增删主效应特征，离线指标长期不动而特征表持续膨胀。反过来在受监管的信贷拒贷场景，GBDT 配加性事后归因（SHAP 一类的做法）反而更容易通过解释性评审，因为它不假设主效应可加。同一个维度、同一个「5 分 vs 3 分」，在两个场景里指向相反的选型。

「精度」这一列同样经不起单独使用。它比的是**同等标注量下的拟合能力**，而工业现场最常见的两种处境恰好落在这一列的盲区：标注量小到任何强模型都会先过拟合（此时正则强度与先验比容量更重要），以及延迟预算低到离线最强模型不能上线（此时服务侧账本比离线指标更有否决权）。用一列「精度」来替代这两条，等价于把两个否决权藏起来，等到评审阶段才由账单或合规把它们翻出来。

再看一个「同一维度随规模反向」的例子：随机森林的「抗过拟合」在小样本表格上是决定性优点——Bagging 把方差平均掉，同等精度下更不容易崩；但样本涨到中大规模后，GBDT 的加性残差拟合在同样精度下模型更小、延迟更低，随机森林的这份优点就变成了「用更大模型换同样的效果」。同一列「抗过拟合」在两端的权重相反，而打分表给出的始终是同一个数。**因此本章不排序，只给判据**——下表 6 条判据的用法是逐条否决候选，而不是给候选累加分数。

**本章采用的 6 条判据**：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| 能力边界 | 它在什么输入上必然失效（而不是平均精度多高） | 树在高基数 id 上退化为记忆、线性表达不了交互、LLM 覆盖不到私有口径——失效点是形状而不是分数，它能整类否决一个方案 |
| 成本结构 | 成本随什么变量增长（请求量 / 特征维度 / 标注量 / token 数） | 线性与树的边际推理成本只有本地算力占用，LLM 的边际成本还要额外按 token 计费，这个量级差决定它能否进在线主路径 |
| 机制契合度 | 判决信息该放在哪个载体里 | 载体选错时，补标注与调参都不会有进展，只能换载体（§3.6 的跃迁表就是这张对照） |
| 运维复杂度 | 要几个常驻组件、什么技能、多少人力 | 一个树模型是一个文件加一张特征表；一条 LLM 路径要网关、限流、降级、Golden Set 与回归评估 |
| 生态与锁定 | 离开它要付出什么 | 自研交叉特征资产、托管 Embedding 与托管 API 的口径绑定、标注与打标工具体系，都是迁移时的真实成本 |
| 演进风险 | 版本变化会不会改动我的标签口径 | 生成式输出的口径随模型版本与采样参数漂移，而线性与树的判决边界是训练产物的冻结函数 |

### 7.2 候选方案全景

| 方案 | 定位 | 核心机制（一句话） | 典型使用者 | 许可 / 商业模式 |
| --- | --- | --- | --- | --- |
| 逻辑回归 LR（+ 人工交叉特征） | 稀疏高维、低延迟、可解释 | 一次稀疏点积，参数落在特征维度而非样本之间 | CTR / 风控在线主路径 | 开源实现（scikit-learn / Spark MLlib 等） |
| FM / DeepFM | 稀疏特征的二阶 / 高阶交叉 | 用隐向量内积表达交互，避免显式枚举交叉组合 | 广告与推荐 CTR | 方法公开 + 开源实现 |
| 双塔（dual encoder） | 大规模候选集高吞吐召回 | 两侧各出一个向量，在线只做一次内积 | 推荐召回与粗排 | 自研为主，框架开源 |
| 线性 SVM（可加核） | 小样本高维、间隔最大化 | 最大化间隔；核函数把非线性映射到隐空间 | 文本分类经典基线 | 开源（libsvm / scikit-learn 等） |
| 朴素贝叶斯 | 极轻量的文本基线 | 条件独立假设下的后验比较 | 垃圾邮件、快速基线 | 开源 |
| 随机森林 / 单棵决策树 | 抗过拟合的表格基线 / 可直读的 if-then 规则 | 单棵树是自顶向下的分裂；森林用 Bagging 把多棵树投票、方差被平均 | 中小规模表格任务、需要规则化解释 | 开源（scikit-learn 等） |
| GBDT 三件套（XGBoost / LightGBM / CatBoost） | 表格数据主力 | 残差加和的分段常数函数 | 风控 / 营销 / 竞赛 | 各自开源（Apache-2.0 等） |
| EBM（可解释提升机） | 必须呈现解释的表格任务 | 广义加性模型 + 单特征形状函数 | 受监管行业的拒贷 / 理赔 | 通过 InterpretML 开源 |
| TabPFN | 小样本表格免训练 | 预训练先验拟合网络，一次前向即出预测 | 每类样本百级 | 方法公开 + 开源实现 |
| 深度特化（CNN / ResNet / ViT / BERT / wav2vec / Whisper） | 非结构化输入 | 参数在位置与时间上共享，从数据中学不变性 | 图像 / 文本 / 语音 | 预训练权重多开放，训练与推理自建 |
| CLIP 式图文对齐 | 零样本多模态分类 | 图文对比学习对齐到同一向量空间 | 内容安全、检索式分类 | 权重开放 + 托管 API |
| VLM（GPT-4V / Claude Vision 一类） | 多模态复杂判断 | 视觉编码器 + 语言模型联合推理 | 长尾图文审核 | 托管 API（按量计费） |
| LLM 分类器（零样本 / 少样本 / 结构化输出） | 冷启动、长尾、类目高频变更 | 判决来自预训练语料 + 提示词中的类别枚举 | 意图识别、Tool 路由 | 托管 API 或自托管开源权重 |
| 多任务（MMoE / PLE / ESSM） | 多个相关标签共享同一批样本 | 共享底层 + 任务塔，稀疏任务借到表示 | 推荐 / 广告 | 方法公开 + 开源实现 |
| 排序学习（Learning to Rank） | 列表顺序而非绝对概率 | 直接优化列表级目标 | 搜索 / 推荐重排 | 开源（GBDT ranker 等） |
| 检索增强分类（RAG） | 开放域与长尾类目 | 先检索证据再判断，判决可追溯到证据 | 开放域分类、知识密集型判断 | 自建（向量库 + LLM） |
| 级联 / 混合路由 | 误判代价不对称、主流与长尾并存 | 先廉价粗筛再昂贵精判 | 风控、内容审核 | 自建 |

**先分族，再比较。** 上表 17 行其实只有三个族，族内差异小、跨族差异大：**第一族把判决信息放在人写的特征里**（LR、FM / DeepFM、双塔、线性 SVM、朴素贝叶斯，5 行），**第二族放在数据自身的划分里**（随机森林、GBDT 三件套、EBM，加上在小样本上换一种先验的 TabPFN，4 行），**第三族放在结构先验与预训练语料里**（深度特化、CLIP、VLM、LLM 分类器，4 行），三族合计 13 行。多任务、排序学习、检索增强与级联不是第四族，而是**决定判决函数之间怎么接**的结构（4 行）——13 + 4 = 17，正是上表的全部数据行。先定族（判决信息放哪里），再在族内挑实现，能省掉一半的比较工作——因为跨族的比较结论会随着样本量与延迟预算翻转，而族内的比较结论基本稳定。

**族内怎么挑，看的是各族的实际判据**：

| 族 | 族内选择的实际判据 | 换实现时真正会变的东西 |
| --- | --- | --- |
| 第一族（人写特征） | 需要几阶交叉、稀疏维度多大、能否实时拼装 | 交叉特征的生成方式（人工 / GBDT 产 / FM 隐向量） |
| 第二族（数据划分） | 类别列与缺失值多不多、是否要输出可读的形状函数 | 类别编码方式（目标编码 / 有序编码）与模型体积 |
| 第三族（先验与语料） | 模态、标注量、能否接受外部调用与口径漂移 | 预训练来源、是否蒸馏、输出是否被约束到枚举 |

注意上表里有两类条目经常被混为一谈：**「模型」与「结构」**。LR、GBDT、BERT、LLM 是模型（提供判决函数）；多任务、排序学习、检索增强、级联是结构（决定判决函数之间怎么接）。结构可以套在任意族的模型上——用 GBDT 也能做排序学习，用线性模型也能做多任务——所以选型必须分两步：先选结构（要几个判决环节、它们怎么串），再在结构里的每个环节上选族。把两步并成一步是选型表最常见的用法错误。

本章保留全部具名候选，只是把它们重新分族：LR、SVM、随机森林、GBDT、深度学习、LLM，以及决策树与组合里出现的 FM / DeepFM、BERT、CLIP、Wav2Vec、Whisper、GPT-4V / Claude Vision 一类 VLM、TabPFN、EBM、MMoE / PLE / ESSM、双塔、排序学习（Learning to Rank）与检索增强（RAG），都能在上表或 7.6 的组合里找到落点。分族不改变它们的存在，只改变你比较它们的顺序。

**这 6 条判据怎么用**：它们不是打分项，而是**否决项**。用法是按顺序过一遍——先问「能力边界」能否接受（不接受就整类排除，不必再看分数），再问「成本结构」在你当前的量级下是否可行，最后才在活下来的候选里比契合度与运维。这个顺序把最容易翻车的两条放在最前面，代价是它会淘汰掉一些「离线指标最好」的方案——而这正是打分表的做法做不到的事。

### 7.3 机制差异：为什么它们表现不同

#### 7.3.1 判决信息的载体：参数放在哪个自由度上

**机制是什么**：一个分类器能表达什么，由它的可调参数被放在哪个自由度上决定——是特征的权重、特征的划分点、位置上共享的核，还是提示词与枚举。

| 载体 | 参数的自由度 | 数据需要为它准备什么 | 必然的代价 |
| --- | --- | --- | --- |
| 人写特征（线性 / 核） | 特征维度 | 显式写出交叉与分箱 | 交互项永不进入解释 |
| 数据划分（树） | 单特征排序后的切分点 | 几乎不用预处理，免疫单调变换 | 叶节点是分段常数，未见取值不平滑 |
| 位置先验（卷积 / 注意力） | 位置间共享的核与注意力 | 结构与足量标注 | 标注不足时先验变成记忆 |
| 预训练语料（LLM） | 提示词与类别枚举 | 不需要自有训练样本 | 私有口径覆盖不到，且延迟与成本高 |

**由此必然导出的性质**：

- 因为线性模型的参数只落在特征维度上、每个参数的影响可被单独读出，所以「为什么拒」能直接落到具体特征上；**代价是特征交互这份表达力必须由外部特征工程补上**——当决定性信息就在交互里时，可解释性会反转成误导，权重表只刻画主效应，团队顺着权重增删主效应特征，而真正决定结果的那一项永远不出现（[§3.2.1](02-classification-section-3-sec3.md)）。
- 因为树的分裂是对单特征按取值排序后切分，所以任何单调变换（归一化、log、分箱）都不改变模型，预处理成本被内生消掉；**代价是叶节点是分段常数**，用户 id、设备 id 这类高基数特征会被切进孤立叶子，训练集分数上去而新 id 覆盖不到。
- 因为卷积与注意力的参数在所有位置 / 时间步上共享，所以同一局部模式出现在任何位置都得到相同响应，模型不必为每个位置的同一模式分别准备样本；**代价是这条先验只能约束函数形状、不能替代样本**，标注量低于参数量能支撑的量级时，它先变成对训练集的记忆。
- 因为 LLM 的判决信息来自预训练语料，所以新增一个类只需改枚举与提示词，不需要重训与发布；**代价是当类别边界依赖私有口径时它会按公开语义猜**，零样本精度退化到接近按类名字面分布猜（[§3.2.4](02-classification-section-3-sec3.md)）。

**公开证据**：Facebook 公开过「GBDT 产交叉特征 + LR 在线拟合」的结构（【公开】He et al., "Practical Lessons from Predicting Clicks on Ads at Facebook", ADKDD 2014）；把局部性先验换成全局注意力的一支见 ViT（【公开】Dosovitskiy et al., "An Image is Worth 16x16 Words", ICLR 2021）；文本预训练与微调范式见 BERT（【公开】Devlin et al., "BERT", NAACL 2019）；图像-文本对齐支撑零样本分类见 CLIP（【公开】Radford et al., ICML 2021）。

**换载体的代价不是连续的**：因为每个载体都携带一套自己的工程量（第一族要特征系统、第二族要标注与重训、第三族要编码器或提示词与评测），所以「从第一族换到第三族」不是加一个模块，而是把判决信息的来源整体搬走——旧载体的工程量大部分作废（第一族的交叉特征表在换到第三族后基本无用），新载体的工程量要从零建（提示词、枚举校验、Golden Set）。**代价是这种迁移无法渐进**，只能用一个并行期（两族同时在跑、用同一个业务指标对照）来过渡，而并行期本身就是双倍运维。判断值不值得迁移，看的是 [§3.6](02-classification-section-3-sec3.md) 里的那条判据：新增标注的边际收益是否已经低于新增容量的边际收益——前者转平说明当前载体已把信息用尽，迁移才有必要。

**失效条件**：当每类标注不足千级且数据是表格时，「免疫预处理」这条优点仍在，但容量与样本的匹配不成立，第二族里要换成强正则的树、线性 / SVM 或 TabPFN（判据见 7.3.2）。

#### 7.3.2 容量与样本量的匹配：精度不是能力，是用出来了多少

**机制是什么**：泛化上限由标注信息量决定，模型容量只决定能不能把这个上限用出来。

| 每类可用标注样本数 | 可行方案 | 为什么这一档是这个组合 |
| --- | --- | --- |
| 0（冷启动） | LLM 零样本、CLIP 式零样本 | 判决信息全部来自预训练语料，自有样本为零 |
| 十级到百级 | LLM 少样本、TabPFN、强正则线性 / SVM | 假设空间必须先被压小，否则容量直接拟合噪声 |
| 千级到百万级【经验】 | GBDT 三件套；必须解释时用 EBM | 表格上每加一份样本都有边际收益，树的分段常数假设不额外吃样本 |
| 百万级以上且非结构化 | 深度特化（含预训练 + 微调） | 参数量只有在样本量同量级时才不构成过拟合（这一档是「含预训练的完整深度特化」门槛；若只是「迁移学习 / 微调现成预训练骨干」，入门门槛更低，见 7.5 的 10^3，两者不要混用） |

**由此必然导出的性质**：因为泛化上限由标注信息量决定、容量只决定能否把上限用出来，所以样本不足时「换更大的模型」只是把方差换成偏差——训练集指标继续涨而验证集停滞；**代价是这条约束不产生任何报错信号**，只能靠一条容量-样本量曲线把它显出来：固定延迟预算，把容量从小到大扫一遍，看验证指标在第几档转平，转平点之后的容量只增加成本、不增加泛化。

**这一档用「每类」而不是「总量」**：因为决定泛化的是最稀有的那个类的样本量，而不是全体样本量，所以在 99:1 的不平衡场景里，百万级总样本可能只有万级正样本——此时按总量判断会得出「样本充足、可以上大模型」的结论，而按每类判断会先去做重采样或代价敏感损失。这也解释了为什么给不平衡数据加类权重、换损失（Focal Loss 一类）在工业上有效【经验】：它们改的是**有效样本的加权分布**，把稀有一类的信息在梯度里放大，而不是凭空补上样本。类权重与阈值都是**给漏检定价**的动作，定价的依据是业务成本而不是数据比例（[§3.5](02-classification-section-3-sec3.md) 的代价矩阵推导）。

**公开证据**：小样本表格分类的免训练路线见 TabPFN（【公开】Hollmann et al., "TabPFN", ICLR 2023；该系列后续在 Nature 发表的版本见 Hollmann et al., "Accurate predictions on small data with a tabular foundation model", Nature, 2025）；三件套的原始工作分别为 XGBoost（【公开】Chen & Guestrin, KDD 2016）、LightGBM（【公开】Ke et al., NeurIPS 2017）、CatBoost（【公开】Prokhorenkova et al., NeurIPS 2018）；免提示词的少样本文本分类见 SetFit（【公开】Tunstall et al., 2022）。

**失效条件**：样本量跨过百万级【经验】后加容量重新变得有效（表示学习开始起作用）；这条阈值随特征的信息量与标签噪声水平移动，噪声高时转平点会显著前移。

#### 7.3.3 推理路径的成本函数：延迟由谁决定

**机制是什么**：单次推理的成本由路径上必须做哪几件事决定——特征拼装、模型遍历、前向传播，还是外部调用。

| 方案族 | 单次推理的形式 | 延迟的主导项 | 可优化手段 |
| --- | --- | --- | --- |
| 线性 / FM | 稀疏点积 | 特征拼装与网络往返 | 预计算、特征缓存、模型侧裁剪 |
| 树集成 | 树数 × 深度的节点比较 | 模型体积（常驻内存）与批处理效率 | 量化、限制树数、批量打分 |
| 深度特化 | L 层矩阵乘 | 加速器与模型体积 | 蒸馏、量化、批推理 |
| LLM / VLM | 一次外部生成 | 网络往返 + 解码步数 | 缓存、离线打标、降级到小模型 |

**由此必然导出的性质**：

- 因为树推理的步数是「树数 × 到叶深度」，所以它并不天然比稀疏点积慢：500 棵树、深度上限 6【经验】的单次推理最多 3000 次节点比较【推算：每棵树从根到叶至多 depth = 6 次比较，500 × 6 = 3000】，而 10^4 个非零特征的稀疏点积是 10^4 次乘加【推算：非零特征数 × 1 次乘加】——**真正的差异在模型体积与批处理向量化能力，而不是步数**；代价是树模型的常驻内存随树数与深度线性增长，而线性模型的参数量随特征维度增长。
- 因为 LLM 路径的成本随 token 数线性增长、且必须经过一次外部往返，所以它进不了低延迟主路径；**代价是常用「离线打标 + 上线小模型」把成本挪到离线**，而这条路线又新增了一套样本采集与回流管线。
- 【推算】设每次调用合计约 1k token【经验】、每天 100 万次调用，则日耗 ≈ 10^9 token = 1000 个「百万 token」单位；按每百万 token 数十美元的价位折算，日成本落在数万美元量级（单价请以官方定价页当前版本为准）。同一请求量换成本地树模型：单次推理按亚毫秒量级取保守上界 1 ms【经验】（与 7.5 的「微秒到亚毫秒」同源），10^6 次 × 1 ms = 10^3 CPU 秒 ≈ 0.3 核时【推算：10^6 × 10^-3 s = 10^3 s，10^3 s ÷ 3600 s/h ≈ 0.28 h】；按常见云 vCPU 时价折算约 0.01–0.03 美元【推算：0.3 核时 × 约 $0.03–0.10/核时，单价请以各家定价页当前版本为准】，即不足一美元。两者相差三个量级以上——这个量级差，而不是离线指标，才是「LLM 能不能当分类器」的真正约束。

**公开证据**：XGBoost 的二阶近似与稀疏感知分裂（Chen & Guestrin, KDD 2016）、LightGBM 的直方图分桶与 leaf-wise 生长（Ke et al., NeurIPS 2017）、CatBoost 的有序目标编码（Prokhorenkova et al., NeurIPS 2018）都是把「树数 × 深度」这条成本曲线往下压的工程手段；蒸馏与量化是把深度模型压进延迟预算的通行做法【经验】。

**「批」与「实时」是两种不同的账**：因为离线批量打分的成本由吞吐决定、在线点查的成本由尾延迟决定，所以同一个模型在离线跑得动、在线未必上线得去——离线可以用大模型扫全量用户，在线只服务被召回命中的一小部分；反过来，一个在线低延迟的小模型几乎总能在离线复用。**代价是团队常常拿离线批量的账单去论证在线方案**，而在线那笔账要按「QPS × 尾延迟 × 机器数」单独算，两者相差的正是被忽略的那一乘数。判断方法很直接：把候选方案的推理路径按「每次请求要做哪几件事」列成清单，再乘上 QPS——清单里任何一项需要跨网络往返，延迟的主导权就不在模型手里。

**失效条件**：当延迟由实时特征拼装（跨多个在线服务取特征）主导时，上述模型侧的优化全部无效，换模型不会带来任何改善【经验】。

#### 7.3.4 标签口径的可冻结性：能不能回归评估

**机制是什么**：分类系统能否长期运行，取决于同一输入是否稳定地给出同一标签——判决函数是不是一个确定性的、可版本化的产物。

| 方案族 | 判决函数的形态 | 错例能否回归 | 口径维护方式 |
| --- | --- | --- | --- |
| 线性 / 树 | 训练产物的确定性函数 | 能，同输入同输出 | 冻结特征口径 + 固定评测集 |
| 深度特化 | 训练产物的确定性函数（解码可随机） | 能（固定推理配置后） | 模型版本 + 固定评测集 |
| LLM / VLM | 生成式输出，受采样与版本影响 | 需先约束输出空间 | 结构化输出 + 枚举校验 + Golden Set |

**由此必然导出的性质**：因为线性与树的判决边界是训练产物的确定性函数，所以它们的错例可以被固定下来做回归测试，标签口径能冻结；而生成式输出没有枚举约束时，同一输入可能返回不同措辞、不同粒度甚至越界类别，错误无法被聚合统计、也无法回归验证——**代价是 LLM 路径必须把「结构化输出 + 越界拒答 + 固定 Golden Set」当作上线前提而不是加分项**（[§3.5](02-classification-section-3-sec3.md) 的「LLM 分类无评估」）。更危险的是这批发散的标签一旦进入训练集，脏标签会以「下游模型效果波动」的形式出现，而源头不可见。

**公开证据**：把分类输出约束到枚举的两条工业接口是结构化输出与工具调用（可按 OpenAI Function Calling、Anthropic Tool Use 的官方文档当前版本核验）；用免提示词的少样本路线降低对提示词口径依赖的做法见 SetFit（【公开】Tunstall et al., 2022）。

**失效条件**：当业务接受「LLM 只做离线打标、上线仍是可评估的小模型」时，这条约束被绕过——这正是 [§3.2.4](02-classification-section-3-sec3.md) 里的「打标机」路线，也是本主题下最常见的折中。

**「口径能否冻结」还决定了方案能不能被替换**：因为可冻结的口径意味着「同一份输入 + 同一份评测集」可以复现出同一个指标，所以族与族之间的迁移才能用一条 A/B 对照来验收；而口径不可冻结时，换方案之后连「是不是变好了」都无法回答，只能靠业务指标缓慢反馈。**代价是这条约束在项目早期几乎不产生痛感**——冷启动阶段没有历史口径可失，等到报表、考核、下游模型都依赖这批标签时，改口径的成本才显现出来。因此判断标准不是「现在能不能跑通」，而是「三个月后我要改它时，需要通知谁」。可自行核验的检查：把当前标签口径写成一份可由第三方复现的说明（含枚举值、判定边界、冲突时取哪个类），写不出来就说明口径还没有被冻结。

### 7.4 成本结构对比（不是价格表，是成本函数）

```
总成本 ≈ 标注与训练的一次性投入
        + 请求量 × 单次推理成本
        + 特征 / 口径 / 监控的持续人力
        + 评估与解释合规的固定开销
```

| 方案族 | 成本随什么增长 | 主导项 | 隐性成本 |
| --- | --- | --- | --- |
| 线性 / FM | 请求量 × 非零特征数 | 特征拼装与特征资产维护 | 交叉特征表随原始特征数近似二次膨胀，需要专人与独立系统 |
| 树集成 | 请求量 × 树数（内存带宽） | 模型体积与批处理效率 | 重训周期、特征口径变更、阈值随分布漂移后的重新标定 |
| 深度特化 | 训练算力 + 推理 × 模型体积 | 训练加速器与蒸馏 / 量化工作 | 标注采集与误差归因工具（注意力可视化、扰动分析） |
| LLM / VLM | 请求量 × token 数 | token 计费与外部往返 | Golden Set 与口径维护、限流与降级链、越界样本的处置流程 |
| 级联 / 混合 | 两条路径各自用量 × 长尾占比 | 长尾占比的漂移 | 路由本身与两套评估口径：两套模型的标签定义必须完全一致，否则回流样本会污染专用模型 |

**哪一项是主导项，取决于你的流量形状，而不是模型本身。** 请求量低、特征维度高时，第一族的主导项是特征工程的人力（一次性且持续）；请求量高、模型体积大时，第二族与第三族的主导项是机器（随请求量线性）；标注稀缺、类目常变时，任一族的隐性成本都是**标签获取与口径维护**——它包括标注人力、打标工具、一致性校验与错例回收，这部分成本不随请求量变化，却常常是长期运行里最大的一块【经验】。把这三项分开记账，是判断「换族能不能省钱」的前提：若你的成本主导项是标注与口径，换一个推理更快的模型不会让总账变好。

**两条【推算】的数量级对照**（推导链同上文，均以「请求量不变」为前提）：

- 树的边际成本：500 棵树、深度 6 的单次推理约 3000 次节点比较【推算：500 × 6】。这个量级说明它可以用批处理把内存带宽摊薄，而不是说它一定比线性慢。
- LLM 的边际成本：每天 100 万次调用 × 每次约 1k token【经验】= 10^9 token/天 = 1000 个百万 token 单位【推算：10^9 ÷ 10^6】；乘上每百万 token 单价即得日成本，单价请以官方定价页当前版本为准。
- 两者相差三个量级以上；因此「把长尾交给 LLM、主流留在本地」这个混合结构是否划算，只取决于一个可测量的量：**长尾流量占比**。占比上升时，本结构「高频走便宜路径」的优点会反转成成本与延迟同时上涨，因为路由器仍按历史频次分流（[§3.2.5](02-classification-section-3-sec3.md)）。

**标注那笔账同样可以估**：【推算】若目标是每类千级标注、共有 100 个类，则需 10^5 条标注【推算：10^3 × 10^2】；按每条数十秒到两分钟的人工耗时【经验】折算，是 830 到 3300 人时【推算：10^5 × 30 s = 3×10^6 s ≈ 830 h；10^5 × 120 s = 1.2×10^7 s ≈ 3300 h】。这个量级说明两件事：第一，标注是**一次性但有下限**的投入，千级 × 百类已经是一个需要专职团队支撑的规模；第二，它与请求量无关，所以「先攒够标注再上第二族」这条路线的时间成本可以由这个数反推，而不是凭感觉等。若标注由 LLM 离线代劳，这笔人力会被换成打标质检的人力，量级下降但不会归零——质检不能省，因为脏标签会以「下游模型效果波动」的形式出现。

**一个可自行核验的检查**：把候选方案的成本函数写成一句话（「成本 ≈ ____ × ____」），填不出来的方案说明还没有真正比较过；再把这句话里的两个变量各自写上「我当前的量级」与「一年后的量级」，如果结论会翻转，那么这次选型需要的是一个**可迁移的中间态**（如先用混合路由、把两族都跑起来），而不是一次压上。这套检查不依赖任何外部数据，可对任何候选方案执行。

### 7.5 决策树（每个分支都要有阈值依据）

用法：树上的方括号是**判断节点**，箭头末端是**结构选择**（几个环节、怎么串），最内层的分支才是**族选择**。按 7.2 的两步法，先走到「输入形态」与「误判代价」这两类节点定结构，再走到「样本量」与「稀疏度」定族。树只给出默认路线，遇到两个分支都成立的情况（如既有长尾类目又要低延迟），走的是 7.6 的组合而不是单选。

```
[分类任务]
   │
   ├─[输入是结构化表格，还是非结构化 / 多模态？]
   │     ├─ 非结构化 / 多模态
   │     │     ├─ 每类标注 ≥ 10^3 且有加速器预算 → 深度特化（ResNet / ViT / BERT / wav2vec / Whisper）
   │     │     ├─ 标注 < 10^3 或类目按周变更 → LLM 零样本 / 少样本；图文配对场景用 CLIP 式对齐
   │     │     └─ 在线主路径 P99 < 10 ms → 不直接上大模型：离线打标 / 蒸馏后上线小模型
   │     └─ 结构化表格
   │           ├─ 每类标注 < 10^3 → 强正则 GBDT / 线性 / SVM / TabPFN；冷启动配 LLM 少样本
   │           ├─ 每类标注 10^3 ~ 10^6 → GBDT 三件套；必须解释时用 EBM
   │           └─ 特征到 10^8 级稀疏、以高基数 id 为主 → 线性优先 + 交叉特征（FM / DeepFM / 双塔）
   │
   ├─[误判代价严重不对称，且昂贵复核容量有限？]
   │     └─ 是 → 级联：第一级高召回粗筛，第二级高精度精判
   │
   ├─[多个相关标签共用同一批样本？]
   │     └─ 是 → 多任务（MMoE / PLE；转化类稀疏标签用 ESSM 的全空间建模）
   │
   ├─[一个样本可以同时属于多个类吗？]
   │     ├─ 可以共现 → 每标签独立 sigmoid + BCE，每类阈值分别标定
   │     └─ 互斥 → softmax + 单组阈值
   │
   ├─[类别是否严重不平衡？]
   │     └─ 是 → 类权重 / 重采样 / 代价敏感损失；阈值由代价矩阵反推，不用默认 0.5
   │
   ├─[输出要的是绝对概率，还是列表顺序？]
   │     └─ 列表顺序 → 排序学习，不要用分类概率替代排序目标
   │
   └─[类别定义依赖私有口径，或判断需要引用外部证据？]
         └─ 是 → 补少样本示例 + 固定评测集；证据跨文档时用检索增强（RAG）把证据放进上下文
```

**阈值依据**（与树上节点一一对应）：

- 非结构化 + 每类标注 ≥ 10^3：来自 [§3.2.3](02-classification-section-3-sec3.md) 的适用条件——「标注量足以撑起参数量」；千级是本主题下「迁移学习（微调现成预训练骨干 / 少样本）」的入门门槛【经验】，它与 7.3.2「百万级以上且非结构化」一档的「含预训练的完整深度特化」门槛不是一回事——后者要求样本量与参数量同量级，两者不要混用。
- 标注 < 10^3 走零样本 / 少样本：同上，且与 [§3.3](02-classification-section-3-sec3.md) 决策表「每类标注 < 1000 时深度网络先过拟合」一致。
- 在线主路径 P99 < 10 ms：来自 7.4 的成本函数形状。外部模型调用的单次延迟在数百毫秒量级【经验】，本地线性 / 树推理在微秒到亚毫秒量级【经验】，10 ms 这一档的作用是**把「整类外部调用」排除在外**，而不是精确卡某个模型。
- 特征到 10^8 级稀疏、以高基数 id 为主：来自 [§3.2.2](02-classification-section-3-sec3.md) 的失效点（树在高基数 id 上退化为按 id 记忆）与 [§3.6](02-classification-section-3-sec3.md) 跃迁表（特征百级 → 亿级稀疏时换线性优先）。
- 每类标注 10^3 ~ 10^6 走 GBDT：来自 [§3.2.2](02-classification-section-3-sec3.md) 声明的适用范围与 [§3.3](02-classification-section-3-sec3.md) 决策表。
- 级联的两个阈值：不由准确率反推，而由「可接受漏检率」定第一级、由「复核容量」定第二级（[§3.2.8](02-classification-section-3-sec3.md) 的阈值标定方向）；这是本树上唯一不需要从数据里估计、而需要业务给出的阈值。
- 多任务节点：无数值阈值，是结构性判断——依据是 [§3.2.7](02-classification-section-3-sec3.md)：多个相关标签共用同一批曝光样本、且其中部分标签的监督信号天然稀疏。
- 多标签节点：无数值阈值，是输出层的结构判断——softmax 的互斥归一化与共现标签冲突，所以共现场景要换成每标签独立 sigmoid（[§3.5](02-classification-section-3-sec3.md) 的「多标签用 softmax」）。
- 不平衡节点：无数值阈值，是损失与阈值的联合判断。阈值依据来自代价矩阵：设正类占比 p、阈值 t 处漏检率 FNR(t) 与误报率 FPR(t)、两种错误的业务代价分别为 C_漏检与 C_误报，则期望代价 ≈ p·FNR(t)·C_漏检 + (1−p)·FPR(t)·C_误报，最优 t 由两项的边际变化相等处决定【推算：对 t 求导并令两项边际相等】。这说明「默认 0.5」只在两类各半且错误代价相等时才最优；欺诈场景 p 在千分之一量级【经验】、漏检代价远高于误报，最优阈值必然远小于 0.5。
- 排序节点：无数值阈值，是输出形态判断——绝对概率与列表顺序是两个目标，替换会改变评估口径。
- 私有口径 / 需外部证据节点：无数值阈值，是可行性判断——把提示词当成规格说明，先确认「这个边界是否被公开语料覆盖」，覆盖不到就必须补少样本示例与固定评测集。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因 |
| --- | --- | --- | --- |
| 亿级稀疏特征 + 十万级 QPS | 线性优先 + 交叉特征（LR / FM / DeepFM） | 双塔（候选集极大时） | 树在高基数 id 上退化为按 id 记忆，且模型体积压不进延迟预算 |
| 表格数据 + 每类千到百万样本 | GBDT 三件套 | EBM（必须解释）、TabPFN（样本更少） | 深度网络在这个样本量上边际收益低，运维却更重 |
| 表格数据 + 每类样本百级 | 强正则线性 / SVM / TabPFN | LLM 少样本 | 中等容量模型在此样本量上先过拟合 |
| 内容安全 / 长尾类目 | 级联：小模型粗筛 + LLM 精判 | 多模态 VLM（图文混合） | 全量走 LLM 会让成本随请求量线性上升三个量级 |
| 类别极不平衡（欺诈一类） | 类权重 / 重采样 / 代价敏感损失（SMOTE、Focal Loss 是常见手段） | 级联（漏检代价远高于误报时） | 直接默认损失训练会让输出几乎全是多数类，用 accuracy 评估还会给出「很好」的假象 |
| 多个相关标签（点击 / 转化 / 时长） | 多任务（MMoE / PLE / ESSM） | 各任务独立建模（相关性低时） | 任务负相关时共享参数会被方向冲突的梯度占据，弱任务被压得更死 |
| 类目按周变更、新类频出 | LLM 零样本 / 少样本 | 混合路由（主流路径专用模型） | 重训周期追不上类目变更速度 |
| 私有口径、合规要求解释 | EBM / 线性（可加性归因） | GBDT + SHAP 类事后归因 | 无解释能力的模型在高合规场景不能用于拒绝类决策 |

**常见组合**（每条说明职责边界与运维代价）：

1. **GBDT + LR（Facebook 公开的经典结构）**：GBDT 负责产出交叉特征，LR 负责在线拟合与快速迭代。职责边界清楚——GBDT 离线、LR 在线；运维代价是两套模型要一起版本化，交叉特征的编码方式一变，LR 侧必须同步重训。
2. **预训练编码器 + 轻量分类头（BERT + LR / MLP）**：编码器定义表示，分类头承担判决。运维代价是小样本下「训练快、效果接近微调」，但编码器版本必须与分类头绑定，换编码器要重训全部头。
3. **专用分类器 + LLM（混合架构）**：专用分类器吃高频主流流量，LLM 吃长尾与低置信样本。运维代价是多一条路由逻辑、两套评估口径，且两套模型的标签定义必须完全一致，否则回流样本会污染专用模型。
4. **多任务（MMoE / PLE / ESSM）**：共享底层承担表示，任务塔承担各自输出；ESSM 用全空间建模解决「转化只在点击后可见」的样本稀疏。运维代价是多套标注与回流，以及损失权重这层新的、效果敏感的配置。
5. **分类 + 排序（推荐 / 搜索）**：分类输出点击概率，排序学习输出列表顺序。运维代价是评估口径从「概率是否准确」换成「列表指标」，且两套目标需要分别调优、避免相互抵消。
6. **分类 + 检索（RAG 增强）**：检索负责把证据放进上下文，LLM 负责最终判断。运维代价是检索质量成为精度上限（检索召回不到就等于模型看不到），且延迟与成本都随检索条数上升。
7. **规则 + 模型 + 人工复核（风控三件套）**：规则承担硬约束与可审计的边界（如监管红线），模型承担边界内的排序与打分，人工承担昂贵复核。运维代价是三层各自有阈值与口径，且规则层会长期漂移——被规则硬拦的样本永远不进入模型与人工，这个损失在离线评估里看不见。
8. **离线打标机（LLM 打标 + 小模型上线）**：LLM 只出现在离线管线里产出标签，上线的是可评估、可冻结口径的小模型。运维代价是打标质量成为上限，且需要一套「打标样本抽检 + 人工校准 + 回流」的持续流程；好处是把 LLM 的成本从「随请求量增长」变成「随数据量的一次性增长」。

这八条组合的共同点：每一条都在**用第二个环节补第一个环节的结构性缺陷**——GBDT 补线性的交互表达、LLM 补专用模型的冷启动、级联补单阈值的取舍、打分机补 LLM 的成本与口径。所以评估一个组合是否值得，只要问一句「第二个环节补的是哪个结构性缺陷、这个缺陷在我的场景里值多少」；答不上来的组合，往往只是把两套系统叠在一起，运维代价照付、收益却来自同一个来源。

**组合的选择顺序不能反**：先按 7.5 定结构（要不要级联、要不要混合路由、要不要多任务），再在结构的每个环节上按 7.2 定族，最后用 7.4 的成本函数把各环节加起来复核——因为结构的每一环都要单独满足延迟与成本预算，环节加得越多，留给单环的预算越少（一个 P99 50 ms 的服务拆成两级，每级就只有一半）。反过来先挑族再拼结构，通常会在最后一步发现两族的标签口径不一致或预算被吃光，只能返工。

### 7.7 选错的代价与迁移成本

**反模式：用榜单精度选型** —— 症状：选型材料只有「离线指标 + 参数量」，没有延迟预算与单次推理成本；后果：方案在评审阶段被服务侧账本否决，或勉强上线后要靠持续加机器维持，而离线指标的优势几周内被分布漂移抹平——本主题下离线指标里既不含时间方向（特征穿越），也不含代价结构（阈值），也不含服务侧账本；正确的做法是**先写死「QPS × 延迟预算 × 单次成本上限」这三个数，再在满足它们的候选里比精度**（[§3.5](02-classification-section-3-sec3.md) 的十二条反模式里有八条是同一成因）。

**反模式：把全部流量交给 LLM** —— 症状：为了省掉标注与训练，直接让 LLM 判所有请求；后果：按 7.4 的推算，成本与延迟都随请求量线性上升，而主流类目本可以用本地模型以三个量级以上的低成本处理；更隐蔽的是标签口径随模型版本漂移，错例无法回归；正确的做法是按**类目频次 × 置信度**做路由，让长尾付出大模型单价，并监控长尾占比的漂移。

**反模式：用 accuracy / AUC 跨族比较** —— 症状：把线性、树、LLM 放在同一测试集上比一个数，据此换模型；后果：三族的训练与评测口径不同（树的阈值后处理、LLM 的提示词版本、标签是否被裁剪），跨族指标差常常来自口径而不是能力，团队会按噪声反复换方案；正确的做法是**固定标签口径与切分方式，报告基线差值**（多数类 / 规则 / 上一版模型），不平衡场景改用 PR-AUC 或「固定误报率下的召回」。

**反模式：把模型指标当成系统指标** —— 症状：选型材料与验收标准都只写模型侧数字（AUC、F1、参数量），没有延迟、没有成本、没有漂移监控、没有解释链路；后果：这四种缺失会在四个不同环节各爆一次——延迟在评审阶段被否、成本在上线后由账单暴露、漂移在「重训周期跟不上」时暴露、解释在合规评审时暴露，而团队每次都会误以为是模型选错了，于是换模型、重来一轮；正确的做法是**把验收拆成模型指标 + 服务指标 + 漂移指标 + 合规指标四张表**，模型只是其中一张（[§3.5](02-classification-section-3-sec3.md) 中八条反模式的共同成因正是这一条）。

**迁移里最贵的一项，通常不是模型而是评测口径。** 因为模型替换可以在几周内完成，而「新模型与旧模型的指标是否可比」需要重做切分、重标阈值、重建基线，所以迁移的实际工期由这部分决定，而不是由训练决定——下表里「评估与运维」这一列的工作，往往比「在线服务」这一列更重。**代价是这部分工期在计划里最容易被低估**，因为它不出现在任何人的任务清单上（模型与接口都有明确的交付物，口径没有）。一个可执行的做法是：迁移立项时先把「新旧口径对照表」列为第一交付物，它写不出来，说明这次迁移还没有可验收的标准。

**换成另一个要动什么**：

| 迁移方向 | 数据 / 特征 | 在线服务 | 评估与运维 | 团队再学习 |
| --- | --- | --- | --- | --- |
| 线性 → GBDT | 特征可从交叉表改为原始列，部分交叉工程可下线 | 一个模型文件替换，前端接口不变 | 阈值与解释口径重做，需要校准 | 中：需掌握树模型正则与特征重要性解读 |
| GBDT → 深度特化 | 需补特征标准化与序列 / 图像管道 | 推理从内存遍历换成加速器服务 | 误差归因工具重建 | 高：训练、调参、部署整链更换 |
| 任意族 → LLM 路径 | 特征工程可大部分作废，改为主推提示词与枚举 | 新增网关、限流、降级、缓存 | Golden Set 与回归评估从零建 | 中到高：口径管理与评测方法要新建 |
| LLM 打标 → 本地小模型 | 需要建立打标样本库与回流管线 | 从外部调用回到本地推理，延迟与成本大幅下降 | 阈值需在独立校准集上重新标定 | 中：需补齐校准与漂移监控 |
| 单任务 → 多任务 | 多套标注与样本回流 | 输出头增加，服务链路基本不变 | 评估拆分到各任务，损失权重成为新配置 | 中：需掌握共享底层与门控结构 |
| 级联 / 混合 → 单模型 | 需重新验证单模型在原先被粗筛挡掉的样本上的表现 | 链路变短，尾延迟更可控 | 需补回被第一级排除样本的评估集（否则指标虚高） | 低到中：结构简化，但评估集重建是关键 |

**上表里最容易被低估的两格**是「数据 / 特征」与「评估与运维」：前者要重建管道，后者要重建可比性；而「在线服务」这一格看起来最重，实际常常只是换一个推理进程。立项时把工期按这四格分别估，比按一个总的「迁移周期」估要准得多。

### 7.8 小结

下表把「约束 → 方案 → 机制理由」压成一张速查表。每一行的理由都是机制而不是形容词：它说明这个方案**为什么能**把判决信息带进决策边界，而不是它「更好」。

| 你的处境 | 建议 | 关键理由（机制层面） |
| --- | --- | --- |
| 亿级稀疏特征、十万级 QPS | 线性优先 + 交叉特征 | 参数量随特征维度而非样本量增长，一次推理只有一次稀疏点积 |
| 表格数据、样本千到百万级 | GBDT 三件套 | 分段常数加和对单特征单调变换免疫，预处理成本被内生消掉 |
| 表格数据、样本百级 | 强正则 / SVM / TabPFN，或 LLM 少样本 | 假设空间必须先被压小，否则容量直接拟合噪声 |
| 非结构化输入且标注充足 | 深度特化（含预训练 + 微调） | 参数在位置上共享，同一局部模式不必逐位置重复学习 |
| 冷启动、类目按周变更 | LLM 零样本 / 少样本 | 判决信息来自预训练语料，新增一类只需改枚举 |
| 主流与长尾流量都大 | 混合路由 | 按类目频次 × 置信度分流，成本跟着长尾占比走 |
| 漏检代价远高于误报、复核容量有限 | 级联分类 | 把判别拆成「能否排除」与「是否命中」，昂贵容量只被少量可疑样本占用 |
| 私有口径 + 强合规解释 | 可加性归因（EBM / 线性），或 GBDT + 事后归因 | 解释方式必须与模型的可加性假设匹配，否则解释只刻画主效应 |

> 本节小结：分类选型中**唯一真正起决定作用的差异，是判决信息被放进哪个载体**——放进人写的特征就选线性，放进数据自身的划分就选树，放进结构先验就选深度网络，放进预训练语料就选 LLM；其余约束（延迟、成本、可解释、漂移）不改变这条主线，只决定实现细节与兜底通道。因此「换一个更强的模型」几乎从来不是正确的动作，正确的动作是判断**当前载体是否已经把可用信息用尽**：新增标注的边际收益转平，说明该换载体；新增容量的边际收益转平，说明继续攒样本即可。
>
> 💡 **思考锚点**：写下你自己那条链路的「QPS × 延迟预算 × 单次成本上限」三个数，再回看当前载体（人写特征 / 数据划分 / 结构先验 / 预训练语料）——你这条链路上，先转平的是新增标注的边际收益，还是新增容量的边际收益，它告诉你此刻该换载体还是继续攒样本？
