## 6. 落地实践

### 6.1 某头部电商"**CTR 预估 LR→FM→DeepFM→多任务**"6+ 年（2018-2024）

**背景（Why）**

该电商 2018 年面临**广告 CTR 预估的四重约束**：
- **亿级用户 / 千万级商品**——特征稀疏度 **99.99%**
- **QPS 10 万+**——**延迟必须 < 50ms**（含特征 + 推理）
- **LR 的极限**——单模型只能学线性关系，**交叉特征靠人工组合**，人力成本爆炸
- **多目标**——只优化 CTR 会**伤 GMV**（推低价高点击商品）

**触发点（What）**

2018 年该电商启动 CTR 预估模型演进（[案例 2018]），目标四条：
- **CTR**——**+5%**
- **CVR**——**+8%**
- **广告收入**——**年增 10 亿+**
- **延迟**——**< 50ms**（P99）

**详细做法（How）**

该电商 CTR 预估的**5 大核心组件**：

1. **LR 起步（核心创新）**
   - 关键设计：**人工交叉特征 + LR**，先跑通全链路（特征 → 训练 → 在线服务）
   - 关键能力：**可解释、可上线**，三天出第一版
   - 关键数字：**基线 AUC 0.72**
   - 特征示意：
     ```
     人工交叉特征：
       gender × category      →  "male_手机"
       hour × user_activity   →  "20_high"
       price_bucket × city_tier → "0-50_一线"
     问题：组合爆炸，100 个原始特征 → 人工交叉出 10 万维
     ```

2. **FM 因子分解机（核心）**
   - 关键设计：**二阶交叉自动学习**，用隐向量内积替代人工组合
   - 关键能力：**稀疏场景下交叉特征可学**
   - 关键数字：**AUC +1.5%**

3. **DeepFM 深度模型（核心）**
   - 关键设计：**FM（低阶）+ DNN（高阶）共享 embedding**
   - 关键能力：**同时捕捉低阶与高阶交叉**
   - 关键数字：**AUC 0.78（+8%）**、**CTR +5%**

4. **XDL 分布式训练（核心）**
   - 关键设计：**参数服务器 + 稀疏梯度优化**，支持 **千亿参数**
   - 关键能力：**日级全量 + 小时级增量**
   - 关键数字：**训练吞吐 10 亿样本/小时**

5. **多任务（CTR + CVR + GMV）（核心创新）**
   - 关键设计：**MMoE / ESMM**——共享底层、任务独立塔
   - 关键能力：**缓解「CTR 高但 CVR 低」的价格偏置**
   - 关键数字：**CVR +8%**、**GMV 年增 30%+**
   - 结构示意：
     ```
     共享 embedding → [Gate 网络] → ┬→ CTR 塔 → σ → pCTR
                                    ├→ CVR 塔 → σ → pCVR
                                    └→ GMV 塔 →    → pGMV
     排序分 = pCTR × pCVR × price  （ESMM 思路）
     ```

**该电商 CTR 预估关键数字**（[案例 2018-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **CTR** | 基线 | +5% | **+5%** |
| **CVR** | 基线 | +8% | **+8%** |
| **AUC** | 0.72 | 0.78 | **+8%** |
| **广告收入** | 基线 | 年增 10 亿+ | **10 亿+** |
| **GMV** | 基线 | 年增 30%+ | **+30%** |
| **QPS** | 不可用 | 10 万+ | **∞** |
| **延迟 P99** | 不可用 | < 50ms | **∞** |
| **训练吞吐** | 基线 | 10 亿样本/小时 | **∞** |

**具体数字（How much）**

- 团队规模：该电商广告算法团队 100+ 人
- 关键数字：**CTR +5% / CVR +8%**；**广告收入年增 10 亿+**；**AUC 0.78**
- 业务影响：覆盖该电商**全部广告位**

**失败教训**

- 早期「**LR + 人工交叉特征**」——特征组合爆炸、维护成本失控，倒逼**「FM → DeepFM 自动学习交叉」**
- 「**只优化 CTR 伤了 GMV**」——模型猛推低价高点击商品、广告主 ROI 下降导致预算流失，倒逼**「多任务 + ESMM 建模」**
- 「**训练与推理特征不一致**」——线下 AUC 0.78 而线上只有 0.70，倒逼**「接 Feature Store 做 Point-in-Time 对齐」**
- 「**只做离线评估就上线**」——线上分布与训练分布不同、效果打折，倒逼**「全量 A/B + 增量实验」**

### 6.2 某股份制银行"**反欺诈 XGBoost 主导**"5+ 年（2019-2024）

**背景（Why）**

该银行 2019 年面临**反欺诈的极端不平衡 + 强合规**：
- **日交易 1000 万笔**，**欺诈占比 0.1%**——正负样本 **1:1000**
- **毫秒级响应**——决策 **< 30ms**
- **监管要求可解释**——拒绝客户必须给出理由
- **黑产快速对抗**——模型上线一周就被绕过

**触发点（What）**

2019 年该银行启动反欺诈建模（[案例 2019]），目标：
- **欺诈召回率**——**+25%**
- **误报率**——**-40%**
- **年减损**——**5 亿+**

**详细做法（How）**

该银行反欺诈的**5 大核心组件**：

1. **XGBoost 主导（核心创新）**
   - 关键设计：**树模型为主**——天然处理缺失值、对不平衡相对鲁棒、**SHAP 可解释**
   - 关键能力：**监管可解释 + 毫秒推理**
   - 关键数字：**AUC 0.92**、**推理 < 5ms**
   - 样本权重示意：
     ```python
     # 类别不平衡：正样本加权
     scale_pos_weight = neg_cnt / pos_cnt   # ≈ 1000
     model = XGBoost(scale_pos_weight=scale_pos_weight,
                     max_depth=6, eta=0.05,
                     eval_metric='aucpr')     # PR 曲线比 ROC 更贴合稀疏场景
     ```

2. **规则引擎 fallback（核心）**
   - 关键设计：**硬规则前置**（黑名单 / 大额异地 / 深夜跨境），命中直接拦截
   - 关键能力：**零延迟 + 绝对可解释**
   - 关键数字：**拦截 30% 欺诈（零延迟）**

3. **Isolation Forest 兜底（核心）**
   - 关键设计：**无监督异常检测**，捕捉**未见过的欺诈模式**
   - 关键能力：**对抗黑产变异**
   - 关键数字：**新欺诈模式召回 +15%**

4. **LightGBM（核心）**
   - 关键设计：**与 XGBoost 做模型融合**（加权投票）
   - 关键能力：**降低单模型偏差**
   - 关键数字：**AUC +0.01**

5. **Flink 实时特征（核心创新）**
   - 关键设计：**近 1 分钟/5 分钟滑动窗口特征**（同设备账户数、转账频次）
   - 关键能力：**捕捉实时团伙信号**
   - 关键数字：**特征延迟 < 500ms**

**该银行反欺诈关键数字**（[案例 2019-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **欺诈召回率** | 基线 | +25% | **+25%** |
| **误报率** | 100% | 60% | **-40%** |
| **年减损** | 基线 | 5 亿+ | **5 亿+** |
| **AUC** | 基线 | 0.92 | **0.92** |
| **推理延迟** | 200ms | < 5ms | **-97%** |
| **新欺诈模式召回** | 基线 | +15% | **+15%** |
| **决策延迟** | 200ms | < 30ms | **-85%** |
| **决策可解释率** | 60% | 100% | **+67%** |

**具体数字（How much）**

- 团队规模：该银行风控算法团队 30+ 人
- 关键数字：**欺诈召回 +25% / 误报 -40%**；**年减损 5 亿+**；**AUC 0.92**
- 业务影响：覆盖该银行**日交易 1000 万笔**

**失败教训**

- 早期「**纯规则引擎**」——规则被黑产研究透、绕过成本极低，倒逼**「ML + 规则 + 异常检测三通道」**
- 「**用 AUC 评估稀疏场景**」——AUC 0.95 看着很好但欺诈召回只有 40%，倒逼**「改看 PR-AUC 与 Top-K 召回」**
- 「**模型上线即被绕过**」——黑产一周适配，倒逼**「加无监督异常检测 + 特征周更，把适配周期拉长到一个月」**
- 「**只给分数不给理由**」——监管要求解释时无法说明依据，倒逼**「用树模型 + SHAP，把决策可解释率做到 100%」**

### 6.3 某短视频平台"**多模态内容审核**"4+ 年（2020-2024）

**背景（Why）**

该短视频 2020 年面临**日上传 1 亿条的多模态审核**：
- **日上传 1 亿条**——纯人工审核**不可能**（需要 10 万人）
- **多模态内容**——封面图 / 标题 / 正文 / 音频 / 视频画面，**违规信号分散在各模态**
- **误判代价高**——误杀创作者内容会**引发舆论**，漏放违规会**招致监管**

**触发点（What）**

2020 年该短视频启动多模态审核（[案例 2020]），目标：
- **违规识别率**——**+15%**
- **误判率**——**-30%**
- **人力审核成本**——**-50%**

**详细做法（How）**

该短视频多模态审核的**5 大核心组件**：

1. **CLIP 图像分类（核心创新）**
   - 关键设计：**CLIP 零样本 + 微调分类头**，识别封面违规（暴露 / 暴力 / 违禁品）
   - 关键能力：**新类别无需重训**，改 prompt 即可
   - 关键数字：**封面违规识别 +18%**
   - 零样本示意：
     ```python
     # CLIP 零样本：改文本描述即可扩展类别，无需重训
     labels = ["正常内容", "暴露内容", "暴力内容", "违禁品"]
     text_emb = clip.encode_text(labels)          # 文本塔
     img_emb  = clip.encode_image(cover)          # 图像塔
     pred = (img_emb @ text_emb.T).softmax(-1)    # 相似度分类
     ```

2. **Chinese-BERT 文本分类（核心）**
   - 关键设计：**标题 + 正文 + OCR 字幕**多段拼接进 BERT
   - 关键能力：**中文语义敏感词泛化**（识别「变体词」「谐音」）
   - 关键数字：**文本违规识别 +12%**

3. **GPT-4V 多模态复核（核心）**
   - 关键设计：**只对「模型分歧样本」调用**（图说正常、文说违规）
   - 关键能力：**用大模型解决跨模态冲突**
   - 关键数字：**分歧样本准确率 +25%**、**调用量仅 3%**

4. **多模态融合（核心）**
   - 关键设计：**图 / 文 / 音 / 视频四路打分加权融合**
   - 关键能力：**单模态漏掉的综合违规被抓住**
   - 关键数字：**违规识别率 +15%**

5. **自研审核平台（核心创新）**
   - 关键设计：**分级处置**——高置信自动处置、中置信人工复核、低置信放行 + 抽检
   - 关键能力：**人力只处理 5% 样本**
   - 关键数字：**人力成本 -50%**

**该短视频多模态审核关键数字**（[案例 2020-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **违规识别率** | 基线 | +15% | **+15%** |
| **误判率** | 100% | 70% | **-30%** |
| **人力审核成本** | 100% | 50% | **-50%** |
| **封面违规识别** | 基线 | +18% | **+18%** |
| **文本违规识别** | 基线 | +12% | **+12%** |
| **分歧样本准确率** | 基线 | +25% | **+25%** |
| **大模型调用占比** | 100% | 3% | **-97%** |

**具体数字（How much）**

- 团队规模：该短视频审核算法团队 50+ 人
- 关键数字：**违规识别 +15% / 误判 -30%**；**人力成本 -50%**；**日审 1 亿条**
- 业务影响：覆盖该短视频**日上传 1 亿条**

**失败教训**

- 早期「**只审文本**」——图文不符的违规全部漏掉，倒逼**「多模态融合审核」**
- 「**全量样本都调大模型**」——成本爆炸且延迟不可接受，倒逼**「只对分歧样本调用（占比 3%）」**
- 「**误杀没有申诉通道**」——创作者被误判后无处申诉、引发舆论，倒逼**「分级处置 + 申诉复核」**
- 「**各模态各建一套审核**」——重复建设且判定标准不一致，倒逼**「统一多模态模型 + 分歧判定机制」**

### 6.4 某三甲医院"**影像辅助诊断**"4+ 年（2020-2024）

**背景（Why）**

该三甲医院 2020 年面临**影像科医生缺口**：
- **CT / MRI 日均 2000+ 例**——**医生人手不足，报告延迟 24-48 小时**
- **肺结节漏诊**——小结节（< 5mm）**人眼易漏，漏诊率约 20%**
- **标注样本稀缺**——**有资质的标注医生本身就是稀缺资源**

**触发点（What）**

2020 年该三甲医院启动影像辅助诊断（[案例 2020]），目标：
- **影像分类准确率**——**80% → 95%+**
- **肺结节检出率**——**+20%**
- **医生效率**——**+30%**

**详细做法（How）**

该三甲医院影像辅助诊断的**5 大核心组件**：

1. **CNN 影像分类（核心创新）**
   - 关键设计：**先分类（正常 / 异常）后分割（病灶定位）**两阶段
   - 关键能力：**高召回优先**——宁可多报不可漏报
   - 关键数字：**分类准确率 95%+**
   - 两阶段示意：
     ```
     阶段 1：分类（高召回）
       CT 序列 → CNN → P(异常)  ── P < 0.3 直接放行（快速通道）
     阶段 2：分割（高精度）
       P ≥ 0.3 → 3D U-Net → 病灶掩码 → 直径 / 体积 / 位置
     ```

2. **ResNet 骨干（核心）**
   - 关键设计：**ResNet-50 + ImageNet 预训练 + 医学影像微调**
   - 关键能力：**小样本下也能收敛**
   - 关键数字：**标注需求 -60%**

3. **3D U-Net 分割（核心）**
   - 关键设计：**3D 卷积处理 CT 序列**，输出病灶体素级掩码
   - 关键能力：**结节体积可量化**（用于随访对比）
   - 关键数字：**分割 Dice 0.88**

4. **多病种分类（核心）**
   - 关键设计：**多标签分类**——肺结节 / 肺炎 / 骨折 / 肿瘤各自独立头
   - 关键能力：**一模型多病种**
   - 关键数字：**多病种覆盖 8 类**

5. **医生工作流集成（核心创新）**
   - 关键设计：**结果嵌入 PACS 阅片界面**，作为「第二意见」而非替代
   - 关键能力：**医生接受度高**
   - 关键数字：**医生效率 +30%**、**报告时间 48h → 8h**

**该三甲医院影像辅助诊断关键数字**（[案例 2020-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **肺结节检出率** | 基线 | +20% | **+20%** |
| **影像分类准确率** | 80% | 95%+ | **+19%** |
| **医生效率** | 基线 | +30% | **+30%** |
| **报告时间** | 48 小时 | 8 小时 | **-83%** |
| **分割 Dice** | — | 0.88 | **—** |
| **标注需求** | 100% | 40% | **-60%** |
| **多病种覆盖** | 1 | 8 类 | **+700%** |
| **CNN / 3D U-Net** | 未建设 | 已覆盖 | **新增能力** |

**具体数字（How much）**

- 团队规模：该三甲医院 AI 团队 20+ 人 + 影像科医生共建
- 关键数字：**影像准确 95%+**；**检出 +20%**；**医生效率 +30%**
- 业务影响：覆盖该三甲医院**全部 CT / MRI**（日 2000+ 例）

**失败教训**

- 早期「**纯 CNN 端到端分类**」——小结节漏诊率高，倒逼**「改为分类 + 分割两阶段，检出率才上来」**
- 「**追求单模型通吃所有病种**」——每一类都不精，倒逼**「多标签独立头 + 分病种微调」**
- 「**第一版直接输出诊断结论**」——医生因责任问题拒绝使用，倒逼**「改为第二意见 + 医生签字担责」**
- 「**标注全靠人工**」——标注成本高、周期长、病种扩展慢，倒逼**「主动学习：只标低置信样本，标注需求降到 40%」**

### 6.5 真实落地路径（基于上述 4 个案例提炼）

**0 → 1 阶段：3-6 个月**

- 选「**LR / 规则基线上线**」（**最简单**）——**10+ 特征**
- 目标：**先跑通全链路**（特征 → 训练 → 在线服务 → 效果回收）
- 团队：**2-3 人**
- 验证标准：**线上延迟达标**、**效果可归因**

**1 → 10 阶段：6-12 个月**

- 扩展到「**100+ 特征 / 单模型**」
- 引入「**XGBoost / LightGBM**」**（**必须**）**——稀疏与不平衡场景的稳妥选择
- 引入「**模型融合 + 规则 fallback**」
- 团队：5-10 人
- 验证标准：**AUC / PR-AUC 达标**、**误报率可接受**

**10 → 100 阶段：12-24 个月**

- 扩展到「**亿级样本 / 深度模型**」
- 引入「**DeepFM / 多任务（MMoE / ESMM）**」**（**生产**）**——解决多目标冲突
- 引入「**Flink 实时特征**」
- 团队：10-30 人
- 验证标准：**CTR / 召回提升可归因到模型**

**100 → 1000 阶段：12-24 个月**

- 引入「**多模态融合 + 大模型复核（分歧样本）**」**（**AI 时代**）**
- 引入「**无监督兜底（Isolation Forest）**」对抗模式漂移
- 团队：30-100 人

> **本节小结**：
> - 4 个真实案例（电商 / 银行 / 短视频 / 医院）印证：**分类不是「LR + XGBoost」，是「基线起步 → GBDT → DeepFM 多任务 → 多模态/大模型复核」分阶段演进**。
> - 关键时间线：6+ 年 / 5+ 年 / 4+ 年 / 4+ 年 —— **分类是 4+ 年长期工程**。
> - 选型第一原则：「**LR / 规则基线上线**」（**最简单**）——**10+ 特征** → 「**XGBoost + 规则 fallback**」（**必须**）→ 「**DeepFM 多任务 + Flink 实时**」（**生产**）→ 「**多模态融合 + 大模型复核（分歧样本）**」（**AI 时代**）。
> - 99% 的失败来自「**用 AUC 评估稀疏场景 + 只优化单目标 + 训练推理特征不一致**」——必须有 **PR-AUC + 多任务 + Point-in-Time**。
> - 真正的 ROI 来自「**CTR +5% / 召回 +25% / 识别 +15% / 准确 95%**」——是**大厂核心分类基础设施的命脉**。

> 💡 **思考锚点**：把 4 个案例共同的演进阶梯（LR/规则基线 → XGBoost + 规则 fallback → DeepFM 多任务 → 多模态 + 大模型复核）套到你自己正在跑的分类系统上：你实际停在第几级？如果卡在基线，你手里是有证据说明「下一级在你这类样本上不划算」，还是从没量过换级的收益？
