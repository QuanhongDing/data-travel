## 7. 与其他方法对比

### 7.1 先立判据：为什么打分表会误导

打分表把一个**取决于场景的结论**伪装成**绝对结论**。同一维度在不同约束下权重会反过来：因果性这一列，在能随机分配处理的场景里，组间实验以极低的论证成本拿到它；在不能随机化的场景里它直接归零——此时需要的是「一个可被论证的识别假设」，而不是「更高的因果性分数」。分数在这里没有可比性，因为一边比的是能力，另一边比的是「换一种方式拿到同一能力的代价」。

第二类误导是**维度之间并不独立**。速度与真实性在本主题里是同一个资源的两面：离线评估快，是因为它不占流量；它也正因为不占流量，测不到只有在线才出现的反馈回路（位置偏差、用户自适应）。把这两件事并列打分，等于给同一枚硬币的两面各记一次分，读者会以为可以「两个都要」。

第三类误导是**打分把代价的形状删掉了**。这里所有方法的能力都是拿代价换的：配对比较的灵敏度是拿「换不出业务绝对量」换的，Bandit 的实时性是拿「置信区间解释力」换的，因果推断的因果性是拿「识别假设不可检验」换的，LLM 自动评审的覆盖度是拿「裁判与被评对象同源」换的。表里只剩收益，读者就会按收益选。

还有一类更隐蔽的毛病：**被并列的两个维度可能根本不在同一个量纲上**。比如「工程成本」这一列，把「一次批处理消耗的算力」和「写出并论证一个不可检验的识别假设所花的人时」放在同一个 1–5 的刻度上相加，得到的排序反映的是编表人的权重直觉，而不是你的约束。量纲不同的东西可以并列描述，但不能相加比较——这是打分表最根本的结构性问题。

所以本章不给分，给判据：先问「它能回答的最强结论是什么」，再问「它的代价在什么条件下会反噬」，最后才问「我该选哪个」。

**本章采用的 6 条判据**：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| 因果性上限（能力边界） | 它的最强结论是「谁和谁一起变化」，还是「我干预之后会怎样」？ | 结论强度是第一分水岭：不能随机化时，再高的灵敏度也换不来因果结论 |
| 成本结构 | 成本随流量、评估单元数，还是人时增长？ | 增长方向决定规模上限——随流量增长的方案，在流量稀缺的业务里最先失效 |
| 判定单位契合度 | 它的判定单位（一次暴露 / 一次生成 / 一条轨迹 / 一次排序）与我要判定的对象是同一个吗？ | 单位不一致时指标再准也是答错问题：把配对胜出率当业务量即属此类 |
| 运维复杂度 | 需要几个常驻组件、几个人、什么技能？ | 评估的隐性成本主要在分流校验、口径对齐与评测集维护，不在算法本身 |
| 口径与资产锁定 | 换方法时哪些历史结论作废、哪些资产（评测集 / 分流链路 / 归因口径）要重建？ | 结论可比性来自口径延续，口径一改历史结论全部不可比 |
| 失效可见性 | 它失效时报错还是静默？ | 静默失效（SRM、评测集腐烂、裁判漂移）只能靠高频校验发现，必须在选型时就设计 |

### 7.2 候选方案全景

| 方案 | 定位 | 核心机制（一句话） | 典型使用场景 | 实现形态 |
| --- | --- | --- | --- | --- |
| 离线评估 | 候选筛除 | 在固定的历史样本上按与业务对齐的指标排序 | 实验流程的第一步 | 自建脚本 / 指标平台 |
| 组间实验（A/B 测试） | 因果判定 | 处理由独立哈希分桶随机分配，组间差即效应 | 上线决策的默认判据 | 自建实验平台 / 商业平台 |
| 配对比较（Interleaving） | 排序类快速筛选 | 同一请求内两套候选混排，消掉单元间方差 | 搜索 / 推荐排序筛选 | 自研为主 |
| 多臂老虎机（含 Contextual Bandit） | 边决策边学习 | 分配比例是累计观测的函数，而非设计时的常数 | 推荐位、动态定价、内容分发 | 自研决策服务 |
| 因果推断（DID / 合成控制 / PSM / DML） | 不可随机化时的效应估计 | 用一个可论证的识别假设替换随机化 | 政策落地、渠道投放、全局改版 | 论文方法 + 自研 / 开源因果库 |
| 归因分析（Shapley / 数据驱动） | 多触点贡献分摊 | 按合作博弈的边际贡献分配转化 | 营销预算分配 | 自建 / 商业归因工具 |
| LLM 评估（自动评审 + 人类锚点 + 真实偏好） | 开放文本判定 | 三路信号分工：覆盖、校准、真实偏好 | 对话与生成任务的迭代 | 开源框架 / 自建评测集 |
| Agent 评估 | 多步任务判定 | 判定单位是一条轨迹，环境必须可复现 | 工具调用与代码任务 | 公开基准 / 自建任务集 |
| 方差缩减（CUPED） | 增强项（不是独立方法） | 用实验前协变量扣掉与效应无关的方差 | 流量有限、效应很小的场景 | 实验平台内建 |
| 多重比较校正（Bonferroni / FDR） | 增强项（不是独立方法） | 控制族错误率或错误发现率 | 一次看多个指标的实验 | 统计库内建 |

读这张表的方式是**从右往左**：先看「实现形态」判断它是不是你能立刻上手的东西，再看「核心机制」判断它是不是在解决你的问题，最后才看定位。反过来读（先看定位再看机制）会得到一个漂亮的分类，却答不出「为什么它在我的场景里会失效」。

这张表里的十个候选其实分**三族**：**分配类**（组间实验、多臂老虎机）——差别只在分配比例是设计时固定的常数还是累计观测的函数；**不可分配类**（因果推断、归因分析）——差别只在用什么替换随机化；**判定单位变更类**（配对比较、LLM 评估、Agent 评估）——共同点是判定单位不再是「一组用户的均值」。离线评估与两项增强项是配件，不是可替代的整车。先分族再选，能省掉一半比较：同族内换工具只是换实现，跨族才是换问题。

### 7.3 机制差异：为什么它们表现不同（核心节）

#### 7.3.1 分配机制：固定分流、自适应分配、不可分配

**机制是什么**：谁进处理组、谁进对照组，由什么决定。

| 方案 | 分配规则 | 分配比例是否随观测变化 |
| --- | --- | --- |
| 离线评估 | 无分配（用历史已发生的暴露） | — |
| 组间实验 | 独立哈希分桶（主文件 §2.1） | 否——设计时固定的常数 |
| 多臂老虎机 | 由累计观测驱动的选择规则 | 是 |
| 因果推断 | 无分配——用历史上真实发生、非随机的处理 | 否，但处理本身不是随机的 |

三个机制各自要先回答一个不同的问题：**组间实验**问「分流比例对不对」（SRM 是第一道门禁，必须先过，见 §3.1 的约束表与 §3.5 的「忽视 SRM」反模式）；**老虎机**问「奖励的延迟与平稳性支不支撑边学边用」；**因果推断**问「我靠什么变化来识别因果」——最后一个问题必须在选方法之前回答，而不是在跑完模型之后补论证。

**因果句**：因为组间实验的分配比例是设计时固定的常数、与结果无关，所以组间差的无偏性只依赖随机化本身，置信区间与多重比较都有干净的解释；**代价**是较差的那一臂在整个实验期内持续拿走固定比例的流量，这份机会成本随实验周期线性累积。因为老虎机的分配比例是累计观测的函数，所以探索只花在与不确定性成比例的那部分流量上、后悔被限制在有界范围内；**代价**是每个臂的样本量不再是设计变量，置信区间与显著性检验失去组间实验那样的含义，且短期最优臂会把样本从「长期才显现的效应」上抽走。因为因果推断的处理在历史上不是随机分配的，所以它必须靠一个可论证的识别假设（平行趋势 / 条件可忽略性 / 外生变动）替换随机化；**代价**是这些假设大多不可直接检验，样本量再大也不会让一个错的识别策略变对。

**公开证据**：【公开】组间分流的工程实现（Google 的 Overlapping Experiment Infrastructure，Tang 等，KDD 2010）；【公开】上下文老虎机的形式化（LinUCB，Li 等，WWW 2010）；【公开】合成控制（Abadie 等，JASA 2010）与 Double Machine Learning（Chernozhukov 等，Econometrics Journal 2018）；【公开】SRM 校验与实验治理的系统化讨论（Kohavi / Tang / Xu，《Trustworthy Online Controlled Experiments》，Cambridge University Press，2020）。具体商业平台的当前能力请以官方文档当前版本为准。

**失效条件**：分配机制的优势在「随机化单位 ≠ 观测单位」时最先失效——按请求分桶而按用户观测，同一用户会同时落进两组，组间差里混进了分流错误，此时任何提升灵敏度的手段都只是在放大一个错的结论。老虎机则在奖励分布非平稳时失效：分配由历史观测决定，衰减太快退化为贪婪、太慢则对新环境迟钝。

**真实使用**：有实验平台的组织把组间实验当作上线决策的默认判据（本书 §6 的电商与短视频两个案例都以实验平台为基础设施）【经验】；老虎机在内容分发与在线广告的实时决策里是常规做法【经验】；因果推断的工业化更多发生在无法开实验的场景【经验】——具体到某个平台支持哪些形式，请以该平台官方文档当前版本为准。

#### 7.3.2 比较结构：组间均值、同一单元内配对、单序列

**机制是什么**：差异是在哪一个层面上被消掉的。

| 结构 | 差异的来源 | 消掉了什么 |
| --- | --- | --- |
| 组间比较 | 两组用户的均值之差 | 什么都没消：差异 = 策略差 + 用户间差 |
| 配对比较 | 同一请求内两套候选的相对胜负 | 消掉用户间差与请求间差 |
| 单序列前向回测 | 同一序列历史窗口上的误差 | 消掉序列间差，但顺序不能随机化 |
| 轨迹判定（Agent） | 终态是否达标 | 忽略中间路径差异，只看终态 |

```text
组间比较（A/B）：
  用户 1..n → 策略 A ；用户 n+1..2n → 策略 B
  差异 = 策略差异 + 用户间差异            ← 后者通常更大

配对比较（Interleaving）：
  同一用户的同一次请求 → A、B 的候选按规则交替插入
  差异 = 策略差异（单元内差异被配对消掉）
  读数 = 胜出率 / 偏好比例                 ← 相对量，不是业务量

单序列前向回测：
  同一序列上滚动：窗口内训练、窗口外验证
  差异 = 策略差异 + 窗口内其它一切变化      ← 时间混杂消不掉
```

**因果句**：因为配对比较把比较放进同一个单元内部，所以单元间方差被消掉、同样流量下可检测的效应更小（推导见 7.3.4）；**代价**是读数变成胜出率这类相对偏好，换算不出 CTR / GMV 这类绝对量，必须另配一个组间实验来给业务量。因为单序列前向回测的顺序不可随机化，所以它消掉了序列间差异却消不掉时间上的混杂（大促、竞品动作与策略同向发生时不可区分）；**代价**是它给出的「策略更好」只在你愿意接受「窗口内其它变化可忽略」时才成立。因为 Agent 判定只看终态，所以「单步做对了」与「任务完成了」被区分开；**代价**是只看终态无法定位失败原因，必须另记过程指标做诊断。

**公开证据**：【公开】配对比较的方法与灵敏度分析（Radlinski 等，CIKM 2008，可按篇目检索核验）；【公开】长期对照与实验治理（Kohavi 等，2020，Cambridge University Press）；Agent 基准见 7.3.3。

**失效条件**：当两次呈现之间的差异不止来自被比较的对象（页面整体改版、召回集同时变化）时，配对的高灵敏度会反转成系统偏差——「同一单元内」只保证单元内可比，不保证差异只有一个来源。

#### 7.3.3 判定对象：终态标量、开放文本、多步轨迹

**机制是什么**：评估里的「一个样本」到底是什么。

| 判定对象 | 单个评估单元 | 判定方式 | 主要失效模式 |
| --- | --- | --- | --- |
| 传统 ML 指标 | 一次预测 | 与真实标签比 | 离线样本分布与线上不一致 |
| 开放文本 | 一次生成 | 自动评审 + 人类锚点 + 真实偏好 | 裁判与被评对象同源、位置偏差 |
| 多步任务 | 一条轨迹（状态 → 动作 → … → 终态） | 终态达标判定 + 过程指标做诊断 | 环境不可复现导致分数不可比 |

两条各自的分工（对应 §3.2.6 与 §3.2.7）：

- **开放文本的三路信号**：自动评审覆盖全部提交（快、便宜、有偏）；人类评审小样本、慢，作为校准锚点；真实用户偏好最贴近「人真的想要什么」，但不可控也不可复现。三路结论冲突时的裁决权必须在事前定好。
- **Agent 的三层判定**：任务级指标（终态是否达标）用于判定价值；过程级指标（单步动作是否有效）只用于诊断；环境复现（容器化 + 固定初始状态）是前两者可比的前提。

**因果句**：因为开放文本的「好」无法用单一标量穷尽，所以评估被拆成「覆盖」（自动评审）与「校准」（人类锚点）两件事；**代价**是评测集会腐烂——模型与任务每变一次，锚点的区分度就下降一次，必须把它当版本化资产管理，并做污染检查。因为 Agent 的评估单位是轨迹而不是一次生成，判定对象与用户实际获得的价值一致，所以任务成功率可以被直接度量；**代价**是每条轨迹要真实执行动作、恢复环境、清理副作用，单次评估成本比调用一次模型高若干量级。因为三类对象的可靠性来源不同（标签 / 锚点 / 可复现环境），所以它们不能用同一套质量指标管理——把「准确率」的验收方式套到 Agent 上，等来的是一张不可复现的排行。

**公开证据**：【公开】HELM（Liang 等，2022）；【公开】MT-Bench 与 Chatbot Arena 的 LLM-as-Judge 研究（Zheng 等，2023）；【公开】AlpacaEval（Stanford，2023）；【公开】WebArena（Zhou 等，2023，CMU）；【公开】SWE-bench（Jimenez 等，2023 预印本，ICLR 2024）；【公开】OpenAI Evals（2023 开源发布）。这些基准的分数随题目集与裁判版本变化，引用时须连版本一起给出。

**失效条件**：当裁判与被评对象同源、或评测集被反复用于优化时，「可扩展的自动评审」会反转成「被度量的其实是评估系统自己」——偏好成了裁判—对象配对的属性，评测集的区分度也随之消失，而这两件事都不会因为样本变多而缓解。

#### 7.3.4 方差来源与缩减路径

**机制是什么**：最小样本量由什么决定。主文件 §2.2 给出 n = (z_{α/2} + z_β)² · 2σ² / δ²。

```text
最小样本量： n = (z_{α/2} + z_β)² · 2σ² / δ²      （主文件 §2.2）
  δ 减半  ⇒  n 变 4 倍                              【推算】
  CUPED ： Ỹ_i = Y_i − θ(X_i − X̄) ,  θ = Cov(Y, X)/Var(X)
           Var(Ỹ) = (1 − ρ²)·Var(Y)  ⇒ 等效于把 n 按 (1−ρ²) 缩小
  配对   ： 方差项从 σ² 换成单元内部分 σ_内²
  ────────────────────────────────────────────────
  三条路径作用在不同的项上：缩 σ、换比较结构、换分配规则
  相同点：都不改变效应本身，只改变「多大流量才能看见它」
```

**推导链**：取 α = 0.05（双侧 z = 1.96）、功效 0.8（z_β = 0.84），(1.96 + 0.84)² = 7.84 ⇒ n_per_group ≈ 15.7 / (δ/σ)²【推算，链：n = 7.84 · 2σ²/δ² = 15.68 · (σ/δ)²】。据此：

| δ/σ（最小可检测效应 ÷ 指标标准差） | 每组所需样本量【推算】 |
| --- | --- |
| 0.1 | ≈ 1.6 千 |
| 0.05 | ≈ 6.3 千 |
| 0.02 | ≈ 3.9 万 |
| 0.01 | ≈ 15.7 万 |

三条缩减路径各自作用在不同的项上：**缩小 σ**（CUPED 用实验前协变量，Var(Ỹ) = (1−ρ²)·Var(Y)，主文件 §2.2）、**换比较结构**（配对把方差项换成单元内部分）、**换分配规则**（老虎机不再为已确定较差的臂付全量流量）。

**因果句**：因为所需样本量与 δ² 成反比，所以要把最小可检测效应减半，样本量就得翻两番——想在这条路上省钱只能从 σ 下手【推算，链：δ → δ/2 ⇒ n → 4n】。因为 CUPED 扣掉的是与处理无关的那部分方差，所以它不改变效应的期望、只降低方差；**代价**是协变量必须在实验前确定且与目标指标同口径，而 θ 是用实验前窗口估出的常数，一旦 X 与 Y 的关系在实验期内漂移，它就由「降方差」反转成「引入偏差」。

**配对结构的量级**：【推算】把指标方差拆成用户间与用户内两部分。设用户间部分占 80%（这个比例要用你自己的分流日志估），组间设计的方差项正比于 σ²，配对设计剩下的正比于用户内部分 0.2σ²，于是同一 δ 所需样本量降到约 1/5（链：配对与组间的方差项之比 = σ_内² / σ² = 0.2）。前提是同一请求内两套候选真的能混排——做不到就没有这份收益。

**公开证据**：【公开】CUPED 的原始论文（Deng 等，WSDM 2013；本章主文件 §2.3 记为「CUPED，2013，Microsoft」）；【公开】样本量计算与方差缩减的系统整理（Kohavi / Tang / Xu，2020，Cambridge University Press）。本章主文件 §2.2 给出的样本量公式与 CUPED 的方差缩减推导沿用同一形式。某个实验平台当前内建了哪几种缩减手段（CUPED、分层抽样、回归调整各有还是没有），请以该平台官方文档的当前版本为准。

**失效条件**：所有缩减手段的前提都是分流本身可信。分流比例不对时，缩减只会让一个错的结论显得更精确。**顺序必须是先验 SRM，再谈灵敏度**。

**四个机制维度合起来是一句话**：评估方法的差异只有两个来源——「结论从哪个变化里来」（7.3.1 与 7.3.2）和「判定的是什么对象」（7.3.3）；7.3.4 的方差只是在这两者确定之后，才轮到去优化的效率问题。顺序反过来（先优化方差、再定识别策略），就是给一件错的事做效率工程。

### 7.4 成本结构对比（不是价格表，是成本函数）

```
总成本 ≈ 平台固定成本（分流服务 + 指标链路 + 看板 + 校验）
       + c1 ·（流量占用比 × 实验周期）        ← 机会成本项：组间实验、老虎机的主导项
       + c2 ·（候选数 × 单次离线评估成本）     ← 离线评估的主导项
       + c3 ·（评估单元数 × 单单元判定成本）    ← LLM / Agent 评估的主导项
       + c4 ·（指标数 × 口径维护人时）         ← 多指标与因果场景的隐性成本
```

| 方案 | 主导项 | 隐性成本（最容易漏的一项） |
| --- | --- | --- |
| 离线评估 | 候选数 × 单次评估 | 「与线上口径对齐」的持续度量——没有它，离线筛的是错的东西 |
| 组间实验 | 流量占用 × 周期 | 分流校验与 SRM 治理；实验越多，假阳性与互相污染越贵 |
| 配对比较 | 单元数 × 判定成本 | 把胜出率换算成业务量所需的第二个实验 |
| 多臂老虎机 | 流量占用（有界） | 置信区间解释力的丧失；长期效应拿不到样本 |
| 因果推断 | 人时（识别策略的论证与检验） | 数据准备（干预记录、对照单元池）；结论无法用精度验收 |
| LLM 评估 | 单元数 × 单次裁判调用 | 评测集版本管理与污染检查、一致率的重复测量 |
| Agent 评估 | 轨迹数 ×（执行 + 环境恢复 + 判定） | 环境容器化与基准维护，是一份长期工程预算 |

**固定成本项为什么最容易被低估**：分流服务本身不难写，难的是它周边的三件事——实际分流比例的高频校验（SRM 检测）、指标口径的统一定义、实验之间互不污染的分层设计。这三件事没有一件能在起步阶段被证明「必须现在做」，于是总被推迟，直到第一批实验结论被推翻时才回头补。这就是 7.1 判据六（失效可见性）在成本表里的落点：**静默失效的代价不会因为你没预算它而不发生，只会从「提前设计」挪到「事后重跑」。**

**机会成本项的量级（含推导）**：【推算】若日活 100 万、实验期 14 天、对照组拿走一半流量、主指标人均 ¥10/天，而最终较差的那一版拿的正是这一半流量、且比对方低 1%，则实验期的差额成本 ≈ 100 万 × 50% × ¥10 × 1% × 14 ≈ ¥70 万（链：50 万人 × ¥10 = ¥500 万/天；× 1% = ¥5 万/天；× 14 天 = ¥70 万）。这一项随 |Δ| 与周期**线性增长**，不是固定成本——所以把它压缩的正确方式是缩短周期或提高灵敏度，而不是砍平台预算。

**判定成本项的量级（含推导）**：【推算】单次裁判调用的成本 =（题目 + 两个候选回答 + 评分模板的输入 token 数）× 输入单价 + 输出 token 数 × 输出单价。以 10 万个单元、单次输入 3 千 token、输出 0.3 千 token 计，一轮全量评审要过 **3 亿输入 token 与 3 千万输出 token**（链：10 万 × 3 千 = 3 亿；10 万 × 0.3 千 = 3 千万）——这一步与选哪家模型无关，先就能算出来。剩下只差一个参数：裁判模型的单价，而公开价目表上这个参数在不同档位之间横跨两个数量级（每百万 token 从数元级到上百元级，请以你所用服务商官方价目表的当前版本代入）【经验】。于是同一轮 10 万单元的评审，成本大致分三档：小模型 / 自托管档**百元级**（3 亿 ÷ 100 万 = 300 个百万 token，× 数元 ≈ 数百元，输出侧按输入单价的 3–4 倍计后同量级）、中端档**数千元至万元级**（300 × 数十元 ≈ 数千元，加输出侧后上万）、前沿档**数万元级**（300 × 上百元 ≈ 3 万元，加输出侧后更高）。真正的价格在**轮数**上：同一套 10 万单元的评测集每周重跑一轮（约 50 轮/年），中端档就从单轮的数千元放大到年化十万元量级（链：约 ¥4 千/轮 × 50 轮 ≈ ¥20 万）——这才是「评测集建设慢」的真实价格。

**Agent 评估的量级**：【经验】每条轨迹要真实执行若干步动作并恢复环境，单条成本比一次模型调用高若干量级；因此同样预算下，LLM 评估覆盖的是万级单元，Agent 评估通常只能覆盖千级轨迹。这条约束不是工程投入能轻易抹平的，它是「判定单位是轨迹」这个选择的直接后果。

**成本函数什么时候会突变**：成本函数的形态在两种情况下会换主导项。其一是**实验量从月级个位数涨到百级/日**时，流量占用项从「一次偶发支出」变成「持续被瓜分的预算」，此时平台固定成本反而不再是主要开销，跨实验的污染与假阳性治理成为主导项。其二是**评估对象从标量变成文本或轨迹**时，`c3`（单元判定成本）从接近零变成主导项——离线指标的判定成本可以忽略，而一次裁判调用、一条轨迹执行都不是零成本，规模一大就改写整个预算结构。判断自己处在哪一段，看的是这两项在本季度涨幅最大的那一项。

### 7.5 决策树（每个分支都要有阈值依据）

```
[评估任务]
   │
   ├─ ① 能不能把处理随机分配？
   │     ├─ 能 ─────────────────────────────► ②
   │     └─ 不能 → 准实验：DID / 合成控制 / PSM / DML
   │                （结论强度以识别假设为准，样本量不解决问题）
   │
   ├─ ② 评估单位是什么？
   │     ├─ 一次排序（同一请求内两套候选可混排）→ 配对比较做筛选
   │     │     └─ 绝对量仍由组间实验给（配对结果只用于筛候选）
   │     ├─ 一次生成（开放文本）→ 自动评审 + 人类锚点 + 真实偏好三路并行
   │     ├─ 一条轨迹（多步任务）→ 任务级基准 + 环境容器化
   │     └─ 一次暴露的结果（标量指标）→ ③
   │
   ├─ ③ δ/σ（最小可检测效应 ÷ 指标标准差）落在哪一档？
   │     ├─ ≥ 0.05（每组样本在千级）→ 直接按公式算样本量
   │     └─ < 0.05（样本量随 δ/σ 减半翻四倍：0.04 ⇒ 约 9.8 千/组、0.02 ⇒ 约 3.9 万/组、0.01 ⇒ 约 15.7 万/组）→ 先上方差缩减或换配对结构，再算样本量
   │
   ├─ ④ 按 ③ 算出的周期在我决策窗口内吗？
   │     ├─ 在 → 组间实验 + 主指标预先登记 + 多重比较校正
   │     └─ 不在 → 决策必须在流量发生时做 → 上下文老虎机
   │               （并接受置信区间解释力下降、长期效应样本变少）
   │
   ├─ ⑤ 同时在看几个指标？
   │     ├─ < 5 个（含只看 1 个主指标的情形）→ 单指标检验为主，主指标仍要预先登记
   │     └─ ≥ 5 个（或含护栏指标）→ 主指标登记 + Bonferroni / FDR 校正 + 分维度呈现
   │
   └─ ⑥ 我关心的效应窗口是实验期，还是实验期之后？
         ├─ 实验期 → 常规组间实验即可
         └─ 之后（新奇效应 / 学习效应）→ 另留 Holdout + 长期监控
```

**阈值依据**：

- **节点 ①（能否随机分配）**：依据是结论的因果性上限——能随机分配时组间差就是效应（RCT 是金标准，主文件 §2.1）；不能随机分配时，同一份数据能回答的只是「谁和谁一起变化」。它不是数值阈值，而是可行性判据；判错会让后面所有步骤白做。
- **节点 ②（评估单位）**：依据是判定单位必须与要判定的对象一致——排序可配对、开放文本看锚点、Agent 看轨迹（§3.2.6 / §3.2.7）。单位不一致时，指标再准也是在回答另一个问题。
- **节点 ③（δ/σ = 0.05）**：来自主文件 §2.2 的样本量公式，取 α = 0.05 双侧、功效 0.8（(1.96 + 0.84)² = 7.84）时 n_per_group ≈ 15.7/(δ/σ)²，逐档为：0.1 ⇒ 约 1.6 千/组，0.05 ⇒ 约 6.3 千/组，0.04 ⇒ 约 9.8 千/组，0.02 ⇒ 约 3.9 万/组，0.01 ⇒ 约 15.7 万/组【推算，链：n = 7.84 · 2σ²/δ² = 15.68 · (σ/δ)²】。分界取在 0.05，是因为它是「每组样本还停在千级」与「此后每减半一档 δ/σ、样本量就翻四倍」的分水岭：低于 0.05 后 0.04 已近万、0.02 到万级中段、0.01 到十万级，灵敏度在这里开始只能靠缩减方差或换比较结构拿，靠延长周期拿不动。**这个分界点本身并不标出「两周周期」**：按节点 ④ 的换算口径（周期 ≈ n_per_group ÷ 日进组人数，日活均分两组），δ/σ = 0.05 时日活万级（每组每天 5 千）约 1.3 天、日活十万级（每组每天 5 万）约 0.1 天；要到两周，日活万级需约 7 万/组，即 δ/σ ≲ 0.015；日活十万级需约 63 万/组，即 δ/σ ≲ 0.005【推算，链：15.68/0.015² ≈ 7.0 万，÷5 千 ≈ 14 天；15.68/0.005² ≈ 62.7 万，÷5 万 ≈ 13 天】。也就是说，「样本量进万级」（n ≥ 1 万 ⇒ δ/σ ≈ 0.04）与「周期越过两周」（日活万级 ⇒ δ/σ ≈ 0.015）不是同一条线，而且只有后者随流量移动：「样本量进万级」由 n 单独决定，与流量无关；「两周」在流量差 10 倍时只移动 √10 ≈ 3.2 倍（0.015 ÷ 0.005 = 3，与前后两档流量相差 10 倍吻合）【推算，链：n ∝ 1/(δ/σ)² ⇒ δ/σ ∝ 1/√n】。两条线的距离因此取决于流量档：日活万级时 0.04 ÷ 0.015 ≈ 2.7 倍，日活十万级时 0.04 ÷ 0.005 ≈ 8 倍——用「相差一个数量级」概括它们会误导，两者也不能合并成一条阈值，周期是否越窗必须用节点 ④ 逐案算。
- **节点 ④（周期 vs 决策窗口）**：周期 ≈ n_per_group ÷（日进组人数）。用节点 ③ 的数：日活 10 万、均分两组 ⇒ 每组每天 5 万，δ/σ = 0.02 时约需 3.9 万/组 ⇒ 不到 1 天；δ/σ = 0.002 时约需 390 万/组 ⇒ 约 78 天【推算，链：15.68/0.002² = 392 万；392 万 ÷ 5 万 = 78 天】。周期超出决策窗口时的正确动作是换方法（方差缩减 / 配对比较 / 老虎机），而不是「多跑几天」。
- **节点 ⑤（≥ 5 个指标）**：依据是族错误率 FWER = 1 − (1 − α)^k。α = 0.05 时 k = 1 ⇒ 5%，k = 5 ⇒ 约 23%，k = 20 ⇒ 约 64%【推算，链：1 − 0.95⁵ = 0.226；1 − 0.95²⁰ = 0.642】。到 5 个指标时，即使所有指标都完全无效，也已经有约五分之一的概率至少看到一个「显著」——所以把 5 设为「必须做校正」的分界。
- **节点 ⑥（效应窗口）**：依据是新奇效应与学习效应都发生在实验窗口之外，短窗读数不能代表长期（§3.2.10）。Holdout 比例取 5–10% 这一量级【经验】：下限来自长窗口内仍要能看出衰减所需的功效，上限来自长期占住流量的机会成本——按 7.4 的机会成本项，留出的比例越高、持续越久，成本按乘积增长。

**顺序约束**：节点 ① 到 ⑥ 不是一张并列清单，而是一条有先后的判定链。分流比例不对时（节点 ① 的产物），方差缩减、配对比较、分层这些提升灵敏度的手段都只会让一个错的结论显得更精确；评估单位定错时（节点 ②），样本量算得再准也只是在为一件错的事做功效计算。顺序反了，投入越多、错得越像真的。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 注意事项 / 最容易犯的错 |
| --- | --- | --- | --- |
| 传统 ML 模型上线决策 | 离线两阶段 + 组间实验 + 业务指标 | 因果推断（不能随机化时） | 只做离线：历史样本上的排序 ≠ 线上效应 |
| 搜索 / 推荐排序快速筛候选 | 配对比较（Interleaving） | 小流量组间实验 | 用配对胜出率替代业务量：换算不出 CTR / GMV |
| 决策必须在流量发生时做 | 上下文老虎机 | 高频滚动的组间实验 | 用它判定长期效应：样本被短期最优臂吸走 |
| 不能随机化（政策 / 全局改版） | DID / 合成控制 / PSM / DML | 前后对比 + 对照单元池 | 直接跑回归：把相关当因果 |
| 多触点营销预算分配 | Shapley / 数据驱动归因 | 规则归因（首触 / 末触） | 把归因结果当因果证据：它是记账，不是效应 |
| LLM 对话输出 | 自动评审 + 人类锚点 + 真实偏好 | 单一总分榜 | 只用单一总分：维度退化被平均值掩盖 |
| LLM 推理（数学 / 代码） | 过程奖励模型 / Pass@k（能力成熟度见 §5.1，判 L3 观望） | 只看终态正确率 | 只看终态：分不清推理错还是格式错 |
| Agent 多步任务 | 任务级基准 + 环境容器化 | 单步成功率 | 用单步指标代表任务成败 |
| 多团队并行实验 | 流量分层 | 各团队各自分流 | 共享同一份流量会互相污染结论 |
| 流量小 + 效应小 | 方差缩减 + 配对结构 | 硬拉长周期 | 指标多而又不校正：小效应场景下假阳性随指标数与实验数累积 |
| 关心长期效果 | Holdout + 长期监控 | 短窗 + 事后回看 | 把新奇效应当成永久效应 |
| 实验量涨到百级 / 日 | 流量分层 + 主指标登记 + 多重比较校正 | 集中分流平台 | 各团队各自分流：互相污染、假阳性随实验数累积 |
| 有一条必须举证的发布流程 | 评估挂进 CI + 红线维度门禁 | 一次性评估报告 | 没有挂载点的评估不会有人维护 |

第 4 列写的是**这一行最容易犯的错**，不是「备选为什么更差」：多数场景里出错的不是备选本身，而是把首选用在了它答不了的问题上。列出备选只表示「另一条可走的路」，不表示它在这一行里更优——两条路的取舍要看 7.5 的树上条件。

这张表里最常被误选的一对，是**把配对比较当成组间实验的替代品**。它快、灵敏、结果好看，于是被用来做上线决策。后果不是数字错，而是**答错了问题**：胜出率回答「用户更喜欢哪套排序」，它不回答「改完之后 CTR / GMV 是多少」。一旦拿它替代业务量估计，上线决策就建立在无法换算成收益的量上。

**7 种常见组合**（逐条给出职责边界与运维代价）：

1. **离线 + 组间实验 + 因果推断（标准上线链路）**：离线筛候选、组间实验判因果、因果推断处理不能随机化的部分。运维代价是三套口径必须对齐（同一指标定义、同一分流口径、同一埋点），口径漂移会让三者给出互相矛盾的结论。
2. **Interleaving + 组间实验（搜索 / 推荐）**：配对比较做快速筛选，组间实验确认业务量。运维代价是必须持续度量两者的结论一致率——只看胜出率会上线一个「用户更偏好但没有业务收益」的改动。
3. **CUPED + 老虎机（小流量）**：CUPED 缩小 σ 提高灵敏度，老虎机在流量发生时决定分配。运维代价是两件事的前提不同：CUPED 要求实验前协变量与实验期同口径，老虎机要求奖励可在线观测且延迟可接受；两者都不满足时这个组合不成立。
4. **LLM-as-Judge + Human Eval（LLM 评估）**：自动评审覆盖全部提交、人类评审守住关键场景与校准锚点。运维代价是评测集的版本管理与污染检查、不一致样本的裁决流程——这部分成本不随模型变强而下降。
5. **WebArena + SWE-bench（Agent 评估）**：按能力维度分工（Web 操作 / 代码修改），而不是两阶段流水线；两者判定单位都是轨迹。运维代价是两套环境都要能固定到同一初始状态，且上升的分数要能拆到成本与步数，否则排名不可用。
6. **DID + Causal Forest（政策 / 营销）**：DID 估平均效应、Causal Forest 估异质性。运维代价是 DID 的平行趋势假设需要逐次检验，而 Causal Forest 的结论依赖「有无可比对照」——两组协变量几乎不重叠时，异质效应只是模型外推。
7. **HELM + Arena（LLM 综合评估）**：HELM 给多维度能力画像，Arena 给真实用户偏好排名；同样不是流水线，而是两类证据并列。运维代价是两者口径不同（前者是固定题目集上的能力，后者是持续流入的真实偏好），把它们拼成一个总分之前，必须先说明冲突时以谁为准。

### 7.7 选错的代价与迁移成本

下面三条反模式按「暴露得越晚、损失越大」排列：前两条在复盘阶段暴露，第三条要等到事故发生时才暴露。

**反模式：拿配对比较替代业务量估计。** 症状是上线决策的证据只有「胜出率」，一旦被问「这次改动值多少钱」就答不出，只能反复强调「用户更偏好」。后果是决策建立在一个无法换算成收益的量上：复盘说不清价值，也无法与其它改动的收益排序，下一次预算分配只能靠嗓门。正确做法是配对比较只用于候选筛除，绝对量由组间实验给，并且把两者的结论一致率当作平台自身的指标持续度量。

**反模式：把相关当因果并据此分配预算。** 症状是结论写着「投放越多销量越高」，而投放本身是按历史销量分配的（反向选择）。后果是把预算加到本来就会买的人群上，增量接近零，而报表上一切正常。正确做法是先问一句「这个结论有没有来自随机实验、断点或工具变量的证据」——只有观测数据时，结论只能用于描述，不能用于干预。

**反模式：评估没有挂载点。** 症状是评估跑完只产出一份报告，红线维度退化的版本照样上线。后果是没人因为退化承担后果，评估的维护优先级持续下降，最终没人跑评估；而「没人跑评估」在监控上表现为实验结论变少，不表现为报警。正确做法是把评估挂到发布门禁或 CI 上，并配好豁免与申诉流程——严格与可用之间的调参是常态工作。

| 迁移 | 要动的数据 / 链路 | 要改的口径 | 要重建的组件 | 团队要补的能力 | 量级 |
| --- | --- | --- | --- | --- | --- |
| 离线 → 组间实验 | 分流、埋点、曝光日志 | 离线样本口径 → 在线暴露口径 | 分流服务、SRM 校验、指标看板 | 实验设计与功效计算 | 大（平台级） |
| 组间实验 → 配对比较 | 请求级的两套候选混排能力 | 胜出率与业务量之间的换算关系 | 配对实验组件 + 与组间实验的交叉验证 | 配对设计的失效条件 | 中 |
| 组间实验 → 老虎机 | 在线实时特征与决策链路 | 从「组间均值差」改为「累计收益 / 后悔」 | 在线决策服务 + 模型热更新 | 非平稳环境下的探索策略 | 大 |
| 加因果推断 | 干预记录、对照单元池、倾向得分特征 | 从「效果」改为「效应 + 识别假设」 | 因果建模与检验流程（平行趋势、安慰剂检验） | 识别策略的论证能力 | 大（人时主导） |
| 加 LLM / Agent 评估 | 评测集、裁判链路、Agent 运行环境 | 从「准确率」改为「一致率 + 任务成功率」 | 评测集版本管理、环境容器化、发布门禁 | 评测集建设与污染检查 | 中到大 |

表里「量级」的判据是**要动的组件数与人时，而不是数据量**：判别一个迁移是不是「大」，问一句「这件事能不能靠一个团队在季度内自闭环」——离线转组间实验、组间实验转老虎机、加因果推断都越过了这条线，因为它们要么需要新的常驻服务，要么需要团队现在没有的方法论能力。

### 7.8 小结

| 你的处境 | 建议 | 关键理由（机制层面） |
| --- | --- | --- |
| 能随机化、流量够、要上线 | 离线筛候选 + 组间实验 + Holdout | 因果判定只能来自随机对照；长期效应只能来自长窗口 |
| 排序类、要快速筛掉大部分候选 | 配对比较筛选 + 组间实验确认 | 配对消掉单元间方差换灵敏度；绝对量仍要组间对照 |
| 流量不足、要检测小效应 | 方差缩减（CUPED）/ 配对结构 | 扣掉与效应无关的方差，不改变期望只降低方差 |
| 不能随机化 | DID / 合成控制 / PSM / DML | 用可论证的识别假设替换随机化，并写明假设 |
| 决策必须在线发生 | 上下文老虎机 | 分配随观测动态调整，把探索成本限制在有界范围 |
| 开放文本 / 多步任务 | 三路评审 + 任务级评估 | 判定单位与真实价值对齐；单步指标只做诊断 |
| 同时看多个指标 | 主指标登记 + Bonferroni / FDR | 不校正时，假阳性随指标数单调上升 |

这张表是 7.1 六条判据逐条落下来的结果：能不能随机化决定结论上限（判据一），评估单位决定读数能否换算成业务动作（判据三），成本函数决定这套评估能跑到多大规模（判据二），而剩下三条判据（运维复杂度、口径锁定、失效可见性）决定它能不能活过三年——判据一选错的代价是「结论不可用」，判据六选错的代价是「结论不可信而你不知道」。

> 本节小结：本主题的对比中**唯一真正起决定作用的差异，是「处理能不能被随机分配」**——它决定结论的因果性上限，其余所有维度（灵敏度、成本、周期）都只在这个上限之内做优化。而在能随机化的那一支里，第二决定性的差异是「判定单位与要判定的对象是不是同一个」：它决定你的读数能不能换算成业务动作，也决定了配对比较、LLM 评估与 Agent 评估各自该被放在流程的哪一段。
>
> 💡 **思考锚点**：挑一个你手上正要做决策的改动，问它能不能随机分配——能，就按判据二估成本、按判据三选评估单位；不能，就落到 DID / 合成控制那一支。你这条改动落在哪一支，它所需的识别假设你写得出并检验得了吗？
