## 4. 工程实现

§3 回答的是「有哪几种评估做法、每种被什么约束逼出来、代价与失效点是什么」。本节回答的是另一件事：**在你已经选定做法之后，怎么把它装进一个真实的组织与已有的实验存量里**——哪一步先做、每一步的产物与判据是什么、哪些技术点在实施层会坏、工具按什么判据选、已经在跑的实验和已经归档的结论怎么处理。

两类读者的入口不同：**从零搭建**（还没有实验平台，或只有埋点）从 §4.1 顺着读；**存量改造**（已有实验平台、已有几十上百个历史结论、已有模型在线上）先读 §4.4，再回头补 §4.1 里缺的步骤。§4.2 与 §4.3 两类读者共用。模式本身的约束、机制与失效点不在这里重复，需要时指向 §3。

### 4.1 落地步骤

**Step 1：业务目标与指标对齐（1–3 周【经验：随业务方数量与指标口径数量变】）**

把业务目标（CTR / GMV / 时长 / 满意度）翻成一组可计算指标，并写清每个指标的口径：哪张表、哪个状态、哪个时间窗、如何聚合。

- **产物**：评估指标体系文档——每个指标一条，含业务含义、口径 SQL、数据源、主指标 / 护栏指标标记、以及它的**随机化单位与观测单位分别是什么**。
- **判据**：把文档交给另一个人（不口头补充），让他只按文档写出其中 2 个指标【经验：抽几个随指标总数变，抽到能覆盖「简单指标 + 需要多表关联的指标」两类为止】的 SQL 并跑数，两边数字必须一致；对不上的那一条说明口径还没写清。
- **为什么必须这一步 / 为什么在这个位置**：随机化单位由指标决定——承诺 GMV 却按请求分流，指标的单位和分流的单位不一致，Step 3 会照着一个错的单位设计分流，整批实验配置要重做。所以它必须排在 Step 3 之前，且不能与 Step 3 合并。

**Step 2：离线评估（1–2 周【经验：随候选数与特征回填成本变】）**

搭离线评估 pipeline（数据 + 模型 + 指标计算），多指标对比（LogLoss / AUC / NDCG / MAE），按场景分维度看错误。

- **产物**：离线评估报告 + **噪声基线**——同一个模型在两个互不重叠的历史窗口上的读数差异。
- **判据**：抽 3 个候选模型【经验：数量随候选池大小变，覆盖最好 / 中等 / 最差三档即可】，看它们的离线指标差异是否超过本步算出的噪声基线；没有基线的差异不许进 Step 3 的实验名单。
- **为什么必须这一步 / 为什么在这个位置**：没有噪声基线，Step 7 会把窗口波动当提升写进决策记录。离线只回答「配不配进实验」，不回答「能不能上线」（[§3.2.1](07-eval-section-3-sec3.md)），所以它必须在 Step 3 之前、且不能替代 Step 3。

**Step 3：A/B 测试设计（3–10 天【经验：随指标数与样本量计算工具化程度变】）**

按 MDE + α + β 算最小样本量与必备周期；设计流量分层（Layer / Domain）与实验分组（实验组 / 对照组与比例）；把主指标登记进实验平台的登记表。

- **产物**：实验设计单——假设 / H0 / 主指标 / MDE / α / power / 最小样本量 / 预期周期 / 分流单元 / 护栏指标 / 回滚条件，全部在开跑前锁定。
- **判据**：把 MDE 改小一半，设计单里的最小样本量是否变成约 4 倍【推算：n = (z_{α/2}+z_β)²·2σ²/δ²，见主文件 §2.2，δ 减半 ⇒ n 变 4 倍】；数字不跟着动，说明样本量是拍的而不是算的。
- **为什么必须这一步 / 为什么在这个位置**：样本量与周期是「这个实验做不做得起」的唯一依据。放到跑起来之后再算，常见结果是**实验跑到中途**才被排期会告知「要跑到下个月中」【经验：这个时点随实验周期与排期流程变，落在实验期中段】——此时实现成本已经投入，回不了头。

**Step 4：A/B 测试执行（占实验周期全程，无独立工期【经验：时长由 Step 3 算出的最小样本量与实际流量决定】）**

配置实验（分流、参数、流量），每天检查 SRM，监控核心指标 + 护栏指标。

- **产物**：实验配置 + 监控看板 + **SRM 日报**（每日一次的实际分流比例校验）。
- **判据**：开跑 24–48 小时内【经验：随实验量与告警通道变】做两件事——① 从分流日志里数实际进入各组的用户数并与设计比例做检验；② 比较两组的**实验前**基线指标，差异应不显著。第 ② 项不做，第 ① 项通过也可能是空欢喜。
- **为什么必须这一步 / 为什么在这个位置**：SRM 必须在读任何指标之前查——它是这条链路上唯一一道能在流量还没作废时把实验叫停的门禁。反过来做的代价是流程性的：等结论已经进了上线评审、改动已经合进主干才发现两组不可比，这时要回滚的是一个已发布的改动加上一批照它排的期，而不是一个实验；灵敏度手段能省下的流量与周期（顺序上的机制见 [§3.6](07-eval-section-3-sec3.md)）此时已经换不回来了。

**Step 5：因果推断（可选，1–4 周【经验：随识别策略与对照池规模变】）**

不能随机化的场景写清识别策略并做可检验部分的检验（DID 的平行趋势前置窗口）；做反事实分析与长期效果评估（Holdout）；需要异质效应时做 CATE。

- **产物**：因果推断报告 + **假设清单**——每条识别假设写一句话，并标注「可检验 / 不可检验」及检验结果。
- **判据**：把同一份数据交给第二个人，只给假设清单，他能复算出同一个效应估计；复算不出来的，说明字段或窗口没写全。
- **为什么必须这一步 / 为什么在这个位置**：它要消费 Step 4 的随机对照结论来校准自己（准实验估计与 RCT 校准结果对不上时，问题在识别策略而不是数据量），所以排在 Step 4 之后。

**Step 6：归因分析（1–3 周【经验：随触点数量与数据回补周期变】）**

按触点做转化归因（最后 / 首次 / 线性 / 时间衰减 / Shapley），算多触点贡献度，据此做 ROI 评估。

- **产物**：归因报告——每个触点的贡献度、口径版本、以及在实验结论可得时两者的对照。
- **判据**：拿一次**有随机对照**的渠道实验去校准归因模型（一次渠道投放的上线实验即可），看归因给出的贡献排序与实验结论是否同向；不同向时必须在报告里写明。
- **为什么必须这一步 / 为什么在这个位置**：归因是描述性的、实验是因果的（主文件 §2.4）。不先有 Step 4 的对照，归因报告就没有任何可校准的锚点，之后它被拿去分配预算时无法被质疑。

**Step 7：决策与上线（1–5 天【经验：随审批层级变】）**

综合离线 + A/B + 因果 + 归因结果做决策：全量 / 灰度 / 回滚。

- **产物**：上线决策报告——结论、置信区间、护栏指标是否破线、**回滚触发条件**、以及本次决策引用的实验编号。
- **判据**：报告里必须能回答「如果这个结论是错的，多久能被发现、由谁发现」（写不出说明 Step 8 还没设计）；从实验平台导出的冷数据重算一次主指标，与看板数字一致。
- **为什么必须这一步 / 为什么在这个位置**：决策记录是 Step 8 的输入——没有引用的实验编号，长期监控不知道该盯哪个改动，复盘时也无法把线上变化接回当初的结论。

**Step 8：长期监控（持续，30–90 天起步【经验：随业务周期长度变，周期越长窗口越长】）**

Holdout 长期监控，漂移检测（数据漂移 / 概念漂移），持续评估接入 CI/CD。

- **产物**：Holdout 清单 + 漂移告警 + 复评排期（每个上线改动挂一个下次复评时间）。
- **判据**：抽 100 个 Holdout 用户【经验：抽查量随保留组规模变】，在实验曝光表里逐个查，应**没有任何曝光记录**；有一次曝光，这个 Holdout 就已经被污染。
- **为什么必须这一步 / 为什么在这个位置**：新奇效应与学习效应都发生在实验窗口之外（[§3.2.10](07-eval-section-3-sec3.md)），只有窗口关掉之后仍存在的对照才能把它们与真实效应分开。

**最常被跳过的是 Step 3 的样本量事前计算与 Step 4 的 SRM 日报。** 两者被跳过的理由一样：它们不产出任何可见功能，看起来像流程负担。它们的症状出现在**组织的时间点**上而不是技术上——样本量的问题在实验排期会上暴露（「这个实验要跑到下个月中」，而实现成本已投入、收不回）；SRM 的问题在复盘会上暴露（「为什么实验组里 Android 用户占比偏高」），此时期间的所有判读都要作废。这两个时点都在「已经花了钱」之后，所以它们只能靠流程锁死，不能靠事后发现。

### 4.2 关键技术点

#### 4.2.1 分流正确性：哈希分桶 / SRM 检测 / 流量分层

- **做法**：分流键固定为用户 ID 哈希（主文件 §2.1），只在实验服务里算一次；分层配置也集中在该服务，业务代码不允许自己实现分流；SRM 用卡方检验对每日实际分组人数做校验。
- **机制**：因为分流键同时被埋点、过滤条件与客户端版本读取，所以只要有一处用了别的键（或对「活跃用户」做了二次过滤），组间构成就会静默偏移；把分流收敛到单一服务，是把「构成一致」从口头约定变成结构约束。
- **失效条件**：**当过滤链在实验期内发布（例如新增一条「仅登录用户」的过滤）时**，这条会坏成「比例校验通过、结论仍然无效」——校验看的是分母比例，而偏移发生在分子（谁被算进指标）。症状：分流比例正常，但两组的实验前基线出现差异。观测信号 = 每日的分组人数校验 + 两组 pre-period 指标差异检验。
- **档位**：校验频率每日一次【经验：随实验量与告警通道变，实验量到百级/日后应降到小时级】。

#### 4.2.2 样本量与多重比较：样本量计算 / Bonferroni / FDR（BH）/ 主指标预先登记

- **做法**：设计单里写 MDE、α、power、分流单元与由此算出的样本量；主指标在开跑前登记入库；其余指标按集合大小校正后呈现（指标少且每个都要单独决策用 Bonferroni，指标多且目标是「发现一组退化」用 BH / FDR）。
- **机制**：因为显著性判断是在一组检验上做的，「看哪个显著报哪个」会把选择本身变成不受控的自由度；预先登记把检验集合固定下来，校正再把集合大小折回阈值里。两者必须成对出现——只登记不校正，追加指标仍会把假阳性带进来。
- **失效条件**：**当指标清单在实验期内被业务追加时**，这条会坏成「登记了但没锁」：追加指标不进校正集合，结论按未校正阈值发出。症状：同一个实验在两个看板上结论不一致（一个按校正后、一个按原始）。
- **档位**：【推算】10 个互相独立的检验、每个 α=0.05 时，至少出现一个假阳性的概率约 40%（1 − 0.95¹⁰ = 0.401）；Bonferroni 把单次阈值降到 0.05/10 = 0.005。

#### 4.2.3 方差缩减：CUPED / Stratified Sampling / Regression Adjustment / Switchback

- **做法**：CUPED 按实验前窗口计算 θ = Cov(Y, X) / Var(X)（主文件 §2.2）；分层抽样按实验前就已知的变量（客户端版本、地域、新老用户）在分流时配平；回归调整把协变量放进回归式；Switchback 用于用户级不可分的场景，按时间片切换。
- **机制**：因为 X 在分流之前就确定，扣掉它解释的方差不会改变效应的期望；但这份收益挂在 X 的生成链路上——X 的物化作业回填晚于实验开跑时，θ 是用不完整窗口估出来的，调整就从降方差变成引入偏差。
- **失效条件**：**当协变量表的分区在实验前几天还没补全时**，这条会坏成「置信区间比真实更窄」——而且不会报警。症状：实验结束后用完整窗口重算 θ，结论翻转（先显著后不显著，或反之）。观测信号 = θ 的重算差异。
- **档位**：【公开】用实验前数据做方差缩减在微软实验平台上被系统化使用（Deng 等, "Improving the Sensitivity of Online Controlled Experiments by Utilizing Pre-Experiment Data", WSDM 2013，论文报告缩减幅度约 30–50%；可按论文标题自行检索核验）；实际能拿到多少取决于协变量与目标指标的相关系数 ρ，按 (1 − ρ²) 折算【推算：Var(Ỹ) = (1 − ρ²)·Var(Y)，δ 不变时所需样本量降为 (1 − ρ²) 倍】。Switchback 的时间片长度不给统一值【经验：随效应的衰减时间与流量变】。

#### 4.2.4 配对比较接入：Balanced / Team Draft / Probabilistic Interleaving（与组间实验组合使用）

- **做法**：三种混合规则择一，把两套候选在同一次请求内混合，读数为胜出率；混排层放在召回之后、业务埋点之前；需要业务量估计时另开一个组间实验与它交叉验证。
- **机制**：因为配对把单元间方差消掉，同样流量下可检测的差异更小——但这份灵敏度只在「两次呈现的唯一差异是排序规则」时成立。把混排层固定在一个位置上，是让「呈现差异可归因」这件事可控的唯一办法。
- **失效条件**：**当同一次改版同时改了召回集或样式时**，这条会坏掉且没有任何自动报警（它的灵敏度来源与适用条件见 [§3.2.2](07-eval-section-3-sec3.md)）。症状出现在发布排期与复盘会上：用胜出率排进排期、据此定了改版优先级的改动，随后的组间实验给不出对应增量，团队只能在改动已经铺开之后回头补做一轮组间实验。观测信号 = 两种实验结论的一致率（即本条「档位」里的结论一致性校验）。
- **档位**：结论一致性校验的频率【经验：每次大改版前至少做一次】。

#### 4.2.5 Bandit 接入：ε-greedy / UCB / Thompson Sampling / Contextual Bandit

- **做法**：把分配逻辑放进服务侧的决策接口，参数（ε、置信系数、先验及其衰减）随配置版本化；每次决策落一条「曝光 + 奖励」事件，供离线复算。
- **机制**：因为分配比例成了观测的函数，「事前配置 → 事后读数」这条链路不再描述系统。要让结论可复核，必须把决策日志补成事实表——评估动作从「读实验结果」变成「重放决策日志」。
- **失效条件**：**当奖励延迟超过决策间隔时**（电商场景里下单常发生在曝光后数小时【经验：延迟随品类决策周期与客单价变】），这条会坏成「用未成熟的奖励更新分布」，早期偶然胜出的臂被锁死。症状：分配比例在整段观测窗口内几乎不动，而离线重放的收益低于上线时的读数（观测窗口按奖励回填延迟的 2–3 倍取【经验：倍数随衰减速度与决策节奏变】）。观测信号 = 各臂分配比例曲线 + 奖励回填延迟分布。
- **档位**：ε、置信系数、先验衰减速度不给统一值【经验：随奖励延迟与非平稳程度变】。

#### 4.2.6 不能随机化时的识别：RCT（作为校准基准）/ PSM / IV 与 2SLS / DID / Synthetic Control / Causal Forest / DML / DR-Learner

- **做法**：先写「我靠什么变化识别因果」这一句（主文件 §2.2 的 ATE 框架），再选方法——有对照单元 + 处理前后用 DID；有可比对照池用合成控制；处理由可观测变量决定用 PSM；高维协变量 + 强预测模型用 DML / DR-Learner；有外生变动来源用 IV / 2SLS；要异质效应用 Causal Forest / DR-Learner。任何一处能埋小流量 RCT 的，先用它校准一次。
- **机制**：因为准实验把随机化换成了可论证的假设，接入点不是「跑一个库」，而是**把假设需要的字段补进数仓**——DID 要处理单元与时间的事实表，合成控制要候选对照池，DML 要高维协变量。缺一列，方法就跑不出可复算的结果。
- **失效条件**：**当「谁被处理」的口径在运行期被业务侧改写时**（投放把新渠道并进同一笔预算、试点按第二批地区扩围、对照池里被掺进已在别处接受过处理的单元），这条会坏成「估计稳定但方向错」——每次复算都很干净，永远不收敛到校准值。症状：RCT 校准结果与准实验估计相差超过两者各自的置信区间，且方向一致地偏；此时加大样本量只把置信区间收窄，不改变这个差值。观测信号 = 校准差值（应作为该识别策略的长期读数保留），以及变更记录里对处理口径的每一次改动。
- **档位**：【公开】合成控制的原始设定见 Abadie 等, "Synthetic Control Methods for Comparative Case Studies: Estimating the Effect of California's Tobacco Control Program", JASA 2010；DML 的系统化形式见 Chernozhukov 等, "Double/Debiased Machine Learning for Treatment and Structural Parameters", The Econometrics Journal 2018（两篇在 [§3.2.5](07-eval-section-3-sec3.md) 中用于说明识别假设；可按论文标题自行检索核验）。校准用 RCT 的流量配额【经验：够检出效应即可，不必全量】。

#### 4.2.7 长期效应：Holdout / 新奇效应处理 / 学习效应

- **做法**：上线时留一组不接触新版本的长期对照；把效应读数按天展开成曲线，而不是只报一个窗口均值；对能力型改动额外留出学习期，学习期内的数据不进结论。
- **机制**：因为两个效应都发生在窗口之外，只有让对照在实验结束后继续存在、并让读数成为时间序列，才能把它们与真实效应分开。这条的运维接口是「每天为保留组写一行指标」，而不是「实验结束后再补」——补不回来。
- **失效条件**：**当保留组成员在长窗口内被逐步污染时**（被拉进别的新实验，或客户端灰度把新版本推给了它），这条会坏成「对照其实也接受了处理」。症状：保留组指标在某个时点整体抬升，且与任何已发布改动都对不上。观测信号 = 保留组的每日曝光校验。
- **档位**：留存比例的量级及其上下限理由见 [§3.2.10](07-eval-section-3-sec3.md)；抽查量【经验：与保留组规模相称，抽到能覆盖主要端与版本分布为止】。

#### 4.2.8 LLM 评估工程化：Golden Set 建设 / AI-as-Judge 校准 / 多维度评估 / 持续评估（CI/CD）/ 一致性（Agreement）

- **做法**：评测集按「任务 + 场景 + 难度」分层，带版本号与污染记录；自动评审固定提示词模板与裁判版本；一致率每日计算（自动评审对人工抽查）；准确性、安全性、流畅性、有用性分开呈现，不合成单一总分；评估挂进 CI，红线维度退化即阻断（[§3.2.9](07-eval-section-3-sec3.md)）。
- **机制**：因为自动评审的分差里混着裁判自身的漂移，把「一致率」当成与模型指标同等重要的读数，才能把「模型变了」与「裁判变了」分开。运维接口是每次评测都留存裁判的原始打分，而不是只留通过的结论。
- **失效条件**：**当裁判换版本、或被评模型与裁判同源时**，这条会坏成「分数整体抬升、一致率同时下降」。症状：模型版本没动，评分均值跳变。观测信号 = 每日一致率曲线（模型看板上看不到这个）。
- **档位**：人工抽查比例与评测集规模不给统一值【经验：随提交频率与标注预算变】；硬要求是每次评测都记录裁判版本与一致率。

#### 4.2.9 Agent 评估工程化：真实环境任务（WebArena / SWE-bench 类）/ 过程评估 / Tool 使用效率 / 安全性

- **做法**：任务级指标（终态是否达标）与过程级指标（每步动作是否有效）分表落库；每条任务在容器化的固定初始状态下重复跑若干次取多数；工具使用效率按成功率与步数两个读数记录；安全性用「破坏性动作是否发生」这类布尔量单列，不进入平均分。
- **机制**：因为单步正确不代表终态达标（[§3.2.7](07-eval-section-3-sec3.md)），两层指标必须分别落表；合成一个分数，等于把可诊断的能力换成一个不可行动的读数。
- **失效条件**：**当评估环境共享外部接口或资源时**（真实站点、共享沙箱；条件与代价见 [§3.2.7](07-eval-section-3-sec3.md)），这条坏掉的形态是「同一策略的分数在时间轴上不再稳定」。运行期症状：重跑同一策略得到的分数，与上一次的差和两个版本之间的差同量级——评估结论因此在复评时反复翻转，而每次翻转总有一方手上拿着「我这边跑出来不是这样」的结果。观测信号 = 容器启动日志里出现的外部网络依赖、同一策略重复评估的分数方差曲线，以及环境清理失败产生的重跑工单（环境不稳时它先堆起来）。
- **档位**：重复次数【经验：3–5 次，随任务的随机性与评估预算变】。

#### 4.2.10 归因接入：最后 / 首次 / 线性 / 时间衰减 / Shapley / 数据驱动归因

- **做法**：归因口径与实验结论放在同一份报告里；Shapley 精度不足时改采样近似，并把近似误差写进报告。
- **机制**：因为归因描述、实验因果（主文件 §2.4），把两者接起来的接口只有一条——归因的贡献排序必须与能做实验的那些渠道的结论同向；这条接口让归因从记账变成可校准的量。
- **失效条件**：**当触点数量上升时**，「精确 Shapley」会坏成算不动，退化成近似后又坏成「近似误差大于要比较的差异」。症状：预算分配报告每天给出的贡献度排序都在变。观测信号 = 同一份数据两次近似得到的排序差异。
- **档位**：【推算】精确 Shapley 需枚举 2^k 个联盟，k=10 时约 1000 次评估，k=20 时约 105 万次（2²⁰ = 1,048,576）——触点上百时必须走采样近似；采样数与误差的关系请按你实际使用的估计器复核。

### 4.4 存量迁移

存量改造的组织面对的不是「建一套评估流程」，而是**已经有一批结论在流通、一批实验在跑、一批模型在线上**——历史结论被引用、正在跑的实验未必按分层和登记规范建的、线上模型没有 Holdout。这一节的顺序是按「先做可回退的、再处理不可回退的」排的。

**① 先做立刻见效且可回退的一件事：接上 SRM 自动校验与主指标登记，只观测不阻断。** 不动现有分流逻辑、不改实验配置，只把每日分组人数校验和主指标登记表建起来。回退方式是把告警关掉——因为它不改任何分流行为，回退无副作用。这一步之后，你会立刻拿到一份**正在跑的实验中分流可疑的清单**，它决定后面哪些历史结论可以被继续引用。

**② 历史资产分三类处理，不搞全部返工。**

- **(a) 正在跑的实验**：补登记（主指标、MDE、分流单元）与口径说明，**不重跑**。已经消耗的流量补不回来，重跑的成本高于它带来的信息。判据：这个实验的名义主指标能否从登记表里查到。
- **(b) 已归档的结论**：**打标挂账**，不重算。给每条历史结论标三项状态——「无随机化 / 无 SRM 校验 / 无 Holdout」。这是给未来的自己看的：再有人引用这条结论时，知道它缺哪一项证据。判据：随机抽 10 条历史结论【经验：条数随结论总量变，抽到能覆盖主要业务域为止】，每条能否在几分钟内【经验：随登记表的检索方式变】给出这三项的状态。
- **(c) 已上线的模型**：**离线可以回填、在线不能回填**。用历史数据补算离线指标是可行的；补做当初的在线对照是不可能的（不受处理的对照已经不存在了）。这类模型一律按「无在线证据」标记，并挂一个**前向验证**——从今天起留一组 Holdout，之后的新结论才带在线证据。

**③ 迁移期的双轨怎么维持、维持多久。** 双轨是「老的路径：改动直接上线 + 事后看报表」与「新的路径：改动先有实验编号再上线」。维持期的关键不是时长，而是**每一轨都有明确的边界**：新路径覆盖所有「有业务指标影响」的改动，老路径只允许覆盖纯技术性、无指标影响的改动（重构、扩容）。这个划分写不清，双轨就退化成「谁急谁走老路」。周期按决策节拍定【经验：通常 1–2 个季度，随改动频率与审批层级变】。

**④ 什么信号说明可以退出双轨。** 三个读数同时成立：连续若干个决策都能给出引用的实验编号（**新上线的、有指标影响的改动全部有编号**，这是覆盖率的目标值【经验：目标定为全覆盖，达成的节奏随改动频率变】）；SRM 校验连续无告警；口径对账清单为空（抽查时没有人发现同一指标在两处定义不同）。三者缺一，说明退出的是一件事的形态而不是一件事本身。

**存量改造特有的一个陷阱**：把「补文档」当成迁移的主体。历史结论的状态标注、口径说明这些工作，价值在于**限制引用**（告诉别人这条结论缺什么），而不在于让历史变得完整。花两三个月【经验：随历史结论总量与投入人数变，量越大拖得越久】把历史结论补成看起来完整的样子，得到的是不可信但无法分辨的记录——比挂账更糟。

### 4.5 模板 / 示例

**模板 1：实验设计单（开跑前锁定，只填不改）**

| 项 | 值 |
| --- | --- |
| 实验编号 | {EXP-YYYY-NNNN} |
| 假设 | {如果做 X，主指标会朝 Y 方向变化，因为 Z} |
| H0 | {主指标在两组间无差异} |
| 主指标 | {指标名 + 口径 SQL 版本} |
| 护栏指标 | {指标名 1} / {指标名 2} |
| MDE | {要检测的最小相对提升} |
| α / power | {0.05} / {0.8} |
| 最小样本量 / 预期周期 | {由 MDE 反算} / {由流量反算} |
| 随机化单位 / 观测单位 | {用户 / 会话 / 请求} / {哪一个} |
| 分流层 / 分流键 | {层名} / {哈希键字段} |
| 回滚条件 | {护栏破线的具体阈值} |
| 引用的离线候选 | {模型 / 配置版本} |

**怎么用**：填 MDE 之后**先算样本量与周期再填进去**，这两格是反算出来的不是写出来的；「随机化单位 / 观测单位」两格必须都填且必须一致，不一致意味着指标与分流的口径本身对不上，要在开跑前解决而不是在读数时解释。「回滚条件」用具体阈值，不要写「效果不好就回滚」。

**示例 1：样本量计算（比例类指标）**

```python
import numpy as np
from scipy import stats

def sample_size(baseline_rate, mde, alpha=0.05, power=0.8):
    z_a = stats.norm.ppf(1 - alpha / 2); z_b = stats.norm.ppf(power)
    p1 = baseline_rate; p2 = baseline_rate + mde
    p = (p1 + p2) / 2
    n = ((z_a * np.sqrt(2 * p * (1 - p)) + z_b * np.sqrt(p1*(1-p1) + p2*(1-p2))) ** 2) / mde ** 2
    return int(np.ceil(n))          # 每组样本量
```

**怎么用**：只需要换 baseline_rate 与 mde 两个入参；mde 是**绝对**提升，写相对提升（如 10%）时要先乘回基线。算出来的 n 要再乘 1 个余量覆盖流失【经验：余量随实验期流失率变】。

**示例 2：显著性检验（含置信区间）**

```python
import numpy as np
from scipy import stats

def ab_test(control, treatment, alpha=0.05):
    n_c, n_t = len(control), len(treatment)
    mean_c, mean_t = np.mean(control), np.mean(treatment)
    var_c, var_t = np.var(control, ddof=1), np.var(treatment, ddof=1)
    se = np.sqrt(var_c / n_c + var_t / n_t)      # 不合并方差的 Welch 标准误
    diff = mean_t - mean_c
    # Welch–Satterthwaite 自由度：与上面的 se 属于同一套假设
    df = (var_c / n_c + var_t / n_t) ** 2 / (
        (var_c / n_c) ** 2 / (n_c - 1) + (var_t / n_t) ** 2 / (n_t - 1))
    t_crit = stats.t.ppf(1 - alpha / 2, df)      # p 与区间用同一个 t 分位
    p = 2 * (1 - stats.t.cdf(abs(diff / se), df))
    return {"diff": diff, "p_value": p, "ci_95": (diff - t_crit * se, diff + t_crit * se)}
```

**怎么用**：报告结论时必须同时给 diff、p 与置信区间——只给 p 不给区间，无法判断效应在经济上是否值得上线。这段检验假设两组独立同分布，配对设计（Interleaving）不能用它。上面这段全程只用一个约定（Welch：不合并方差 + Welch–Satterthwaite 自由度 + t 分位）；把其中任意一处换成合并方差或 z 分位，都会让 p 与区间出自两套假设——样本量大时两者数字几乎相同，样本量小或两组方差差得多时会给出互相矛盾的结论，而模板被照抄到小样本实验里正是照抄者踩到它的场合。

**示例 3：CUPED 方差缩减**

```python
import numpy as np

def cuped(y, x):
    theta = np.cov(y, x)[0, 1] / np.var(x)
    return y - theta * (x - np.mean(x)), theta
# x 必须来自实验前窗口，且不含实验期数据
```

**怎么用**：`x` 只能取实验前窗口的同一指标；跑完实验后**用完整窗口重算一次 θ**，若结论翻转，说明当初的 θ 是用不完整分区估的。缩减比例由 ρ 决定，不要预设数值。

**示例 4：DID 双重差分**

```python
def did(df, g, t, y):
    m = df.groupby([g, t])[y].mean()
    return (m[1, 'post'] - m[1, 'pre']) - (m[0, 'post'] - m[0, 'pre'])
```

**怎么用**：跑这段之前先画处理组与对照组在**处理前**的平行趋势图（多个前置时间点）；趋势不平行时这个数字没有意义。

**示例 5：AI-as-Judge（结构化输出）**

```python
def llm_as_judge(prompt, response, reference=None):
    sys = "按 JSON 输出四个维度分（1-10）与理由：accuracy/relevance/safety/overall。"
    user = f"任务：{prompt}\n回答：{response}\n参考答案：{reference or '无'}"
    return call_json(model="judge-<版本固定>", temperature=0, system=sys, user=user)
```

**怎么用**：裁判模型版本必须固定在配置里（写进日志），否则跨批次分数不可比；四个维度分**分别报**，不要只报 overall。位置偏差与自我偏好要靠交换 A/B 顺序来消。

**示例 6：LLM-Judge 与人工的一致性**

```python
from scipy.stats import pearsonr, spearmanr

def agreement(human, llm):
    return {"pearson": pearsonr(human, llm)[0], "spearman": spearmanr(human, llm)[0],
            "n": len(human)}
```

**怎么用**：抽到的人工样本要覆盖**低分区间**（只抽高分样本会得到虚高的一致率）；换裁判版本、换提示词模板、换评测集之后重测，并把结果与日期一起存档。

**示例 7：Thompson Sampling（Bandit）**

```python
class ThompsonSampling:
    def __init__(self, n): self.a, self.b = [1.0]*n, [1.0]*n
    def select(self):
        import numpy as np
        return int(np.argmax([np.random.beta(self.a[i], self.b[i]) for i in range(len(self.a))]))
    def update(self, arm, reward):
        if reward: self.a[arm] += 1
        else:      self.b[arm] += 1
```

**怎么用**：`update` 必须由**回填后的奖励**驱动而不是曝光即时驱动，否则奖励延迟会被当成失败；每次 `select` 的输入、输出与当时的后验参数都要落日志，否则复算不了。

### 4.6 成本：这套东西的账单

评估的账单不在服务器上，在**流量、日历时间和标注工**这三样不容易按需扩容的东西上。

**实验容量（最主要的一项）。** 检出更小的 MDE，样本量按平方反比增长：n/组 = (z_{α/2}+z_β)²·2σ²/δ²（主文件 §2.2）。取 α=0.05、power=0.8，则 (1.96+0.84)²=7.84，n/组 ≈ 15.68·(σ/δ)²【推算】——要检出 δ=0.1σ 的效应约需 1,568/组，δ=0.05σ 则约 6,272/组，**MDE 减半、流量与周期翻两番**。这份成本的特殊之处是它占用真实用户与真实月份，无法像算力那样临时扩产；多实验并行只能靠分层复用同一批流量（主文件 §2.1 的 Layer），而分层本身有上限。

**人力。** 门槛不在统计计算，在 §4.1 的 Step 1 口径与 Step 3 设计单——这两处错了，整批实验的读数作废，而不是某一步重做。成熟平台上被检验的想法里多数不带来正提升（Kohavi 等《Trustworthy Online Controlled Experiments》，Cambridge University Press，2020【公开：该书报告多家大型平台的实验规模与成功率，可按书名核验】），所以摊到每个成功改动的实验成本是单次成本的数倍。

**评测算力与标注（LLM / Agent 评估阶段特有）。** 自动评审的成本 = 条目数 ×（输入 token + 输出 token）× 单条价格 × 重复次数，价格随所选裁判与版本变化，不给数值【推算：按上式用你自己的条目数与裁判单价代入】；Agent 评估更重——每条任务要在容器化环境重复跑 3–5 次（§4.2.9），且常是长尾。它贵在这里的原因是：**评估要买的是「可复现的对照」，对照的单价是真实流量、日历时间与人工标注**，不是可弹性伸缩的算力。

通用的云账单口径与单位成本核算见 11-cross-cutting/03-data-cost-finops。

### 4.7 容灾与故障演练

这个主题的「容灾」对象不是服务可用性，而是**结论的可复现性**——多数失效不报警，只在复盘或复算时暴露。

**失效模式与影响面。** ① 分流污染：过滤链在实验期发布，组间构成静默偏移，比例校验通过而结论无效（§4.2.1）。② 协变量回填不全：θ 用不完整窗口估计，置信区间偏窄、结论翻转（§4.2.3）。③ 裁判漂移：换裁判版本或与被评模型同源，分数整体跳变、一致率下降（§4.2.8）。④ Agent 评估环境不稳：共享外部站点让同一策略的分数在时间轴上不稳定（§4.2.9）。⑤ Bandit 奖励延迟：用未成熟奖励更新分布，早期胜出臂被锁死（§4.2.5）。影响面都不是「服务挂了」，而是「决策依据失真、现场已被覆盖」。

**降级策略。** 冻结该实验期的判读（不发结论）、保留原始曝光与分流日志、用完整窗口重算 θ、固定裁判版本与提示词重跑、Agent 评估隔离网络依赖（§4.2.9）。

**演练方案（本主题特有，不是杀进程）。** ① 随机抽一条已发布结论，从原始事件重放到决策点，看能否复现；② 把一个正在跑的实验按回滚流程真的关掉（自检清单已列）；③ 同一策略在固定环境重复评估，看分数方差是否与版本差同量级。通用的故障注入与演练编排见 12-architecture/06-chaos-engineering。

**恢复目标。** 这里没有「数据 RPO」，等价物是**可重建窗口**——分流与曝光日志的保留期必须覆盖「实验最长周期 + 复评窗口」【经验：数月到一年，随最长实验周期与复评节奏变】；RTO 即重建 θ / 重跑一致率所需时间【经验：小时级】。

**为什么不套跨地域容灾。** A/B 平台的分流与读数是单区域内的随机化统计过程，把它复制到另一个区域并不能重建同一批随机化单元；真正的容灾对象是「原始事件 + 分流配置 + 实验设计单」三样可重建物，而不是服务的多活。跨地域 RPO / RTO 与多活拓扑见 12-architecture/07-disaster-recovery。

### 4.8 演进路线：0 → 1 → 100

**0 → 1（最小可用）。** 一个主指标 + 每日 SRM 校验 + 主指标登记表 + 一个面上的 A/B。变贵的是 Step 1 的口径：第一份指标文档要业务与数据两方对齐表、状态、时间窗与聚合。先坏的是口径——口径没写清，Step 3 会照错的随机化单位设计分流，整批配置重做（§4.1）。

**1 → 100（规模化）。** 分层多实验并行、CUPED 方差缩减、Holdout 长期监控、用 RCT 校准准实验、LLM / Agent 评估挂进 CI。变贵的是**实验容量**：流量成为瓶颈，只能靠分层与方差缩减挤出灵敏度，而方差缩减的收益挂在协变量链路上（§4.2.3）。先坏的是**口径一致性**——多团队多口径会让同一实验在两个看板上给出两个数，这正是双轨期最贵的维护项（§4.4）。

**100 →（下一道坎）。** 决策自动化（常驻 Bandit）、用因果识别部分替代随机化、跨组织的口径与评测集联邦。变贵的是**组织协调**：主指标登记表会腐化，指标本身会被优化目标反噬。先坏的是**结论可信度**——实验越多，唯一口径与登记纪律越难守，读数的可复现性先于模型能力退化。

### 4.9 自检清单

下面每一条都必须**动了系统才有答案**；「不跑系统坐下来想想就能答」的那类检查（粒度对不对、模式选得对不对）在 [§3.7](07-eval-section-3-sec3.md)。清单里的抽查量（抽几个实验、抽多少用户、取几批记录）都是【经验】档参数，随你自己的实验数量、保留组规模与评测频率调整——它们的量级不影响检查的效力。

- [ ] 抽 3 个正在跑的实验，从分流日志里数实际进入各组的用户数，与看板上的 SRM 日报对一遍，两边一致吗？
- [ ] 抽 100 个 Holdout 用户，在实验曝光表里逐个查，有没有任何一条曝光记录？
- [ ] 从实验平台导出冷数据，重算最近一次决策所依据的主指标，看板上的数字能复现吗？
- [ ] 对最近一次用了 CUPED 的实验，用完整实验前窗口重算 θ，结论是否翻转？
- [ ] 取一个「显著提升」的指标，按未校正与校正阈值各判一次，两次结论一致吗（不一致说明校正没生效）？
- [ ] 让两个人独立按指标文档写同一个指标的 SQL，跑出来的两个数字一致吗？
- [ ] 从埋点原始事件重算一次本周主指标，与看板对账，差异在可解释范围内吗？
- [ ] 最近一次 Agent 评估，任务级与过程级指标是否分别落表？抽 3 条失败轨迹，能回答「是终态失败还是某一步失败」吗？
- [ ] 取最近 3 次 LLM 评测日志，裁判版本是否一致？每日一致率曲线在换版本那天有没有断层？
- [ ] 报一个渠道 ROI 时，能否给出校准它的那次实验编号与实际差值？
- [ ] 演练一次：把正在跑的实验按回滚流程真的关掉，分流在多长时间内回落、监控上有没有残留？
- [ ] 每个正在引用的历史结论，能否在几分钟内【经验：随登记表的检索方式变】给出它「有无随机化 / 有无 SRM 校验 / 有无 Holdout」三项状态？

### 4.10 小结

> 本节小结：整个落地过程里唯一决定成败的环节，是 **Step 3–4 之间那份被锁定的实验设计单**——分流键、随机化单位、主指标与 MDE 在开跑前固定，并在开跑后 24–48 小时内【经验：随实验量与告警通道变】被校验过一次。它值得比其余环节更多投入，因为后面每一步（方差缩减、配对比较、多重比较校正、因果识别、归因校准）都只是在它之上做精度或补救：契约对了，这些手段各自省时间；契约错了，它们的作用是把一个错的结论放大得更有说服力。
>
> 💡 **思考锚点**：翻出你最近一次用了 CUPED 的实验，按 §4.5 的示例用完整实验前窗口把 θ 重算一遍——结论翻转了吗？如果翻转了，说明你那份锁定的实验设计单里，方差缩减这层是在不完整分区上估的，那么这次「显著」里有多少确定性来自你自己的分流，而不是业务真的变了？
