## 3. 设计模式与范式

> 原 § 3 共 98 行、10 个模式条目与 12 条反模式，每条 2–4 行要点、无结构示意代码块，重写为 ~300 行模式手册。

### 3.1 先看约束：模式不是选择题，是约束的产物

模式表把评估讲成「按场景挑一个方法」，但真实的方法选择是被约束推着走的。同一句话「我们做个 A/B」下面，正确的做法可能完全不同：能不能把处理随机分配、分配的单元和观测的单元是否一致、要检测的效应有多小、评估对象给的是终态还是一个过程、流量与决策周期的量级、组织能不能支撑分流实现与实验治理——任一条不同，该做什么就不同。

六条约束里最硬的是**能否随机化**。它决定你的结论是因果的还是相关的：能随机分配时，组间差异就是效应（RCT 是金标准，见主文件 §2.1）；不能随机时，同一份数据能回答的只是「谁和谁一起变化」。第二硬的是**随机化单位与观测单位是否一致**——主文件 §2.1 的哈希分桶之所以是默认做法，就是为了保证「同一用户在实验期内落进同一个桶」，否则分流比例与设计不符（SRM），后面所有显著性判断都建立在错的样本上。

| 约束 | 它决定了什么 | 本主题下最容易被它推翻的直觉 |
| --- | --- | --- |
| 能否随机化 | 结论的因果性上限（能随机 → RCT；不能 → 准实验） | 「离线指标好 + A/B 显著，就等于业务价值高」——不能随机化时两者都不构成因果证据 |
| 随机化单位与观测单位是否一致 | 分流是否真的随机（SRM 是第一道门禁） | 「分了组就是随机实验」——按时间或按请求切桶，会让不同时段的用户构成本就不同 |
| 要检测的效应量（MDE） | 所需样本量与实验时长（n ∝ 1/δ²，主文件 §2.2） | 「样本量不够就多跑几天」——周期一旦超过决策窗口，多跑几天等于没有结论 |
| 评估对象的形态（终态 / 排序 / 过程） | 判定单位与可用的比较设计 | 「A/B 是在线评估的通用形式」——排序可配对、Agent 是轨迹，都不是组间均值比较 |
| 流量规模与决策周期 | 能不能用得起严格但昂贵的方法 | 「方法越严格越好」——严格方法要的样本量可能超出业务能等的周期 |
| 组织规模与实验治理能力 | 假阳性与实验间污染是否可控 | 「多个实验各跑各的、互不影响」——共享一份流量时实验之间会互相污染 |

判断顺序固定：先问「能不能随机化」，再问「评估单位是什么」，最后才问「用哪个工具」。顺序反了，就会出现「用一个灵敏但答错问题的方法，得出一个好看但不可用的结论」。

### 3.2 模式逐个拆解（核心节）

#### 3.2.1 离线 → 在线两阶段（Offline-Online Pipeline）

**被什么约束逼出来**：真实流量不可逆且稀缺，而候选模型与配置的数量远超过流量能承担的实验数。
**结构**：
```text
候选空间（几十 ~ 几百个模型/配置）
   │ ① 离线：在历史数据上按与业务对齐的指标筛（主文件 §2.3）
   ▼
候选集（剩 2 ~ 5 个）
   │ ② 在线：哈希分桶 A/B（主文件 §2.1）
   ▼
业务指标（CTR / GMV / 留存）
   │ ③ 决策：上线 / 回滚 / 继续实验 —— 反馈回流到训练与候选生成
判据：离线只回答"配不配进实验"，不回答"能不能上线"
```
**为什么这样设计有效**：因为离线评估的单位成本比线上低若干量级且可重复，所以用它做候选筛除，能把真实流量（唯一的不可逆资源）只花在少数候选上。
**代价**：必须维护两套口径并持续度量「离线指标与业务指标的相关性」；这份对齐工作没有终点，模型与业务一变就要重测。
**失效点**：当历史数据里存在只有在线才会出现的反馈机制（位置偏差、用户对新排序的自适应、样本分布已被旧模型改变）时，「低成本筛选」会反转成「系统性筛错」，因为离线评估优化的是固定历史样本上的排序，而线上评估改变的是未来样本的生成过程。
**真实使用**：这是有实验平台的组织的默认流程；本书 §6 的四个案例都以它为基础（某头部电商 2018 起、某短视频平台 2019 起、某 LLM 公司 2021 起、某 Agent 公司 2021 起）【经验】。

#### 3.2.2 Interleaving 加速（配对比较优先）

**被什么约束逼出来**：排序类目标的「效果」是相对偏好，而用户之间的差异通常大于两个策略之间的差异。
**结构**：
```text
组间比较（A/B）：用户 1..n → 策略 A ；用户 n+1..2n → 策略 B
                 差异 = 策略差异 + 用户间差异   ← 后者通常更大
配对比较：同一用户的同一次请求 → A、B 的候选按规则交替插入
                 差异 = 策略差异（用户自身差异被配对消掉）
                 读数是胜出率 / 偏好比例，而不是绝对的业务量
```
**为什么这样设计有效**：因为比较发生在同一个单元内部，单元间方差被消掉，所以同样流量下可检测的效应更小——样本量与需要检测的效应平方成反比（主文件 §2.2 的 n 公式），配对设计把方差项从组间方差换成了配对差异方差【推算，推导链见 §3.2.4】。
**代价**：只适用于可配对的目标（同一请求下两套候选能混排），且产出的相对偏好量无法直接给出 CTR / GMV 这类业务量的估计，必须另配一个组间实验。
**失效点**：当两次呈现之间的差异不止来自排序（页面整体改版、召回集变化、位置样式同步改变）时，配对带来的高灵敏度会反转成系统偏差，因为配对比较默认「呈现差异可归因到排序本身」，一旦还有别的差异，胜出率度量的就是混合效应。
**真实使用**：搜索排序的配对比较实验在工业界长期被采用（【公开】Radlinski 等, CIKM 2008 报告了该方向的对比实验与灵敏度优势）；本书 §6 的某短视频平台把它用于排序实验并与常规实验交叉验证【经验】。

#### 3.2.3 多臂老虎机（Bandit）

**被什么约束逼出来**：有些决策必须在流量发生的当下做出（推荐位、动态定价），错过即不可补偿——不能「先跑两周实验再决定」。
**结构**：
```text
ε-greedy / UCB / Thompson Sampling / Contextual Bandit（主文件 §2.3 第 14–17 条）
   观测到的奖励 ──► 更新各臂的估计 ──► 决定下一次流量分配
        ▲                                    │
        └────── 闭环在系统内部（人不在环上）──┘
判据：分配比例是"观测结果的函数"，而不是实验设计时固定的常数
```
**为什么这样设计有效**：因为流量分配由累计观测驱动，探索只花在与不确定性成比例的那部分流量上，所以在「边决策边学习」的场景里它把探索成本压在有界范围内，而不像固定分流的组间实验那样把一半流量长期花在较差的臂上。
**代价**：每个臂拿到的样本数不再由设计决定，置信区间与多重比较失去组间实验那样干净的解释；同时它天然偏向当前最优臂，留给「长期才显现的效应」的样本很少。
**失效点**：当奖励分布非平稳（用户兴趣漂移、物料池换季）时，「边学边用」会反转成「锁死在早期偶然胜出的臂上」，因为分配比例由历史观测决定，而历史观测对新环境的权重取决于衰减速度——衰减太快退化为贪婪、太慢则对新环境反应迟钝，两头都不再是无偏估计。
**真实使用**：内容分发与在线广告的实时决策普遍采用（【公开】LinUCB 的上下文老虎机形式化见 Li 等, WWW 2010）；具体产品的当前实现请以其官方文档为准。

#### 3.2.4 方差缩减（CUPED）

**被什么约束逼出来**：流量的量级改不了，而要检测的效应越来越小，样本量与效应大小成平方反比。
**结构**：
```text
最小样本量： n = (z_{α/2} + z_β)² · 2σ² / δ²        （主文件 §2.2）
  → δ 减半 ⇒ n 变为 4 倍【推算】
CUPED：用实验前的同一指标 X 做协变量
  Ỹ_i = Y_i − θ(X_i − X̄) ,  θ = Cov(Y, X) / Var(X)
  Var(Ỹ) = (1 − ρ²) · Var(Y)                       （主文件 §2.2）
  前提：X 在实验前已确定、且与 Y 强相关
```
**为什么这样设计有效**：因为 Y 的方差里有一部分能被实验前的 X 解释，扣掉这部分不改变效应的期望、只降低方差，所以同样流量下能检测的 δ 更小（等价于把样本量需求按 (1−ρ²) 缩小）【推算，链条：δ ∝ σ，σ 降为 √(1−ρ²) 倍 ⇒ 同一 δ 所需 n 降为 (1−ρ²) 倍】。
**代价**：要为每个指标维护实验前的历史值并保证与实验期口径一致；协变量选取本身是个单独的方法问题，选得不好会放大方差而不是缩小。
**失效点**：当协变量与目标指标的关系在实验期内漂移（大促、季节性、用户结构变化）时，方差缩减会反转成偏差，因为 θ 是用实验前窗口估出的常数，而调整后估计的一致性依赖「X 与 Y 的关系在实验期内不变」这一前提。
**真实使用**：微软在实验平台中系统化使用了实验前数据做方差缩减（【公开】Deng 等, WSDM 2013，论文报告的方差缩减幅度约 30–50%）；缩减幅度与协变量相关性 ρ 的关系按 Var(Ỹ) = (1−ρ²)Var(Y) 推导【推算】，实际能拿到多少取决于你的协变量有多强。

#### 3.2.5 因果推断（不能随机化时）

**被什么约束逼出来**：处理无法随机分配——政策按地区落地、投放按渠道买量、干预按人群发放，随机化在伦理、成本或业务上都不可行。
**结构**：
```text
目标：ATE = E[Y(1) − Y(0)]（主文件 §2.2），而 Y(0) 对处理组永远不可观测
  ├─ 有对照单元 + 处理前后     → DID（差分掉共同趋势）
  ├─ 有大量可比对照单元       → 合成控制（加权构造"反事实对照"）
  ├─ 处理由可观测变量决定     → PSM（按倾向得分匹配）
  ├─ 高维协变量 + 强预测模型   → DML（残差化后回归，主文件 §2.2）
  └─ 有外生变动来源           → IV / 2SLS
判据：先答"我靠什么变化来识别因果"，再选方法
```
**为什么这样设计有效**：因为每种方法都用一个可被论证的假设替换掉随机化——DID 靠平行趋势、合成控制靠对照池的凸组合、PSM / DML 靠可观测变量充分性——所以不可实验的场景也能给出效应估计，而不是只给出相关系数。
**代价**：识别假设大多不可直接检验（平行趋势可在处理前验证，条件可忽略性不能）；结论的可信度依赖论证质量而不是样本量，样本再大也不会让一个错的识别策略变对。
**失效点**：当不可观测的混淆变量同时影响「谁被处理」与「结果如何变化」时，估计会反转成「只在假设成立时才成立的数字」，因为 PSM 只平衡可观测协变量、DID 只差分掉共同趋势，两者的偏移不会随样本量增大而消失。
**真实使用**：政策评估用 DID 与合成控制（【公开】合成控制的原始设定见 Abadie 等, 2010, JASA）；营销与广告归因用 PSM 与 DML（【公开】DML 的系统化形式见 Chernozhukov 等, 2018）。企业侧的具体归属请按论文与官方材料自行核验。

#### 3.2.6 LLM 评估（LLM-as-Judge + Human Eval）

**被什么约束逼出来**：输出是开放文本，没有唯一正确答案；人工评审质量够但吞吐量跟不上迭代频率。
**结构**：
```text
三路信号并列，各自负责不同的事
  ① 自动评审（AI-as-Judge）：覆盖全部提交，快、便宜、有偏
  ② 人类评审（Golden Set / 关键场景）：小样本、慢、作为校准锚点
  ③ 真实用户偏好（Arena 类两两比较）：最贴近"人真的想要什么"
判据：自动评审给的不是"分数"，而是"与人类判断的一致率"的函数
```
**为什么这样设计有效**：因为开放文本的「好」无法用单一标量穷尽，而自动评审的可扩展性与人类评审的校准能力互补，所以把「打分」拆成「覆盖」与「校准」两件事，既把成本压到可承受，又保留了一个可度量的可信度指标。
**代价**：评测集是会腐烂的资产——模型与任务变一次、Golden Set 的区分度就下降一次，需要持续补充与去污染；三路信号结论不一致时的裁决权也必须事先定好。
**失效点**：当裁判与被评对象同源、或裁判对呈现顺序敏感时，自动评审的「可扩展」会反转成「系统性偏向」，因为此时偏好不是被评对象的属性，而是「裁判—对象配对」的属性（自我偏好与位置偏差都属这一类），这类偏差不会因为样本变多而消失。
**真实使用**：HELM（【公开】Liang 等, 2022）、AlpacaEval（【公开】Stanford, 2023）与 MT-Bench / Chatbot Arena（【公开】Zheng 等, 2023）是公开可复现的对照来源；本书 §6 的某 LLM 公司案例用「多维度画像 + 自动评审 + 关键场景人工」，并把一致率作为评估系统自身的指标【经验】。

#### 3.2.7 Agent 评估（任务级基准）

**被什么约束逼出来**：Agent 的价值是「完成一件多步的事」，而每一步都对、最后仍可能失败；同时环境一变，分数就不可比。
**结构**：
```text
LLM 评估：  输入 → 输出                    （评估单位 = 一次生成）
Agent 评估：输入 → 状态₀ → 动作₁ → … → 终态（评估单位 = 一条轨迹）
  ① 任务级指标：任务成功率（终态是否达标）—— 用于判定价值
  ② 过程级指标：单步动作是否有效 —— 只用于诊断，不用于判定成败
  ③ 环境复现：容器化 + 固定初始状态（否则分数里混了环境差异）
判据：单步指标只能定位问题，不能判定价值
```
**为什么这样设计有效**：因为把评估单位从「一次生成」改成「一条轨迹」，判定对象就与用户实际获得的价值一致，所以「最终状态是否达标」可以直接被度量，单步指标则降级为诊断工具。
**代价**：每条轨迹要真实执行动作、恢复环境、清理副作用，单次评估成本比调用一次模型高若干量级；基准自身（任务、环境、评分器）的维护是一份长期工程。
**失效点**：当评估环境的状态不可复现（外部接口实时变化、共享资源被前序任务污染）时，「贴近真实价值」会反转成「不可比」，因为分数差异里混进了环境差异——同一策略在不同时间跑出的成功率差异，已无法区分是策略差异还是环境差异。
**真实使用**：WebArena（【公开】Zhou 等, 2023, CMU）与 SWE-bench（【公开】Jimenez 等, 2023, arXiv；后发表于 ICLR 2024）是公开的 Agent 基准；本书 §6 的某 Agent 公司案例用「任务级评估 + 环境容器化」，单步指标只用于诊断【经验】。

#### 3.2.8 流量分层（Layered Experimentation）

**被什么约束逼出来**：一份流量在同一时刻只能支撑一次干净的对照比较，而多个团队要同时做实验。
**结构**：
```text
100% 流量
 ├── 层 1（界面）  A1 / A2 / A3     层内互斥
 ├── 层 2（推荐）  B1 / B2          层内互斥
 └── 层 3（营销）  C1               层内互斥
同一用户在各层独立哈希分桶（主文件 §2.1）
判据：分层的依据是"层与层的效应近似可加"，不是"我们想让它们并行"
```
**为什么这样设计有效**：因为各层用独立的哈希分桶，同一用户在不同层可以落进不同实验，所以并行实验的结论互不污染，流量从一份被争抢的共享资源变成若干独立资源池。
**代价**：每层内部的可用流量被层数切薄（同层实验越多，单个实验分到的流量越少）；层划分与维护是持续工作，还需要独立机制来验证「层之间是否真的正交」。
**失效点**：当层与层之间的效应强交互（例如界面改动改变了推荐位的可见性）时，「层间正交」会反转成「每个实验的估计都被别的层污染」，因为正交只保证分流独立、不保证效应可加——组间实验的无偏性依赖「处理效应不随其它处理变化」，这个前提在强交互下不成立。
**真实使用**：Google 以论文公开了 Layer 的工程实现（【公开】Tang 等, 2010, "Overlapping Experiment Infrastructure: More, Better, Faster Experimentation", KDD；可按论文标题自行检索核验）；字节 ABT 与阿里 POE 是公开提到的同类平台，属于本节 §3.2.8 所讲的分层模式，其当前能力以各自官方文档为准；本书 §6 的某头部电商案例把分层作为核心组件之一【经验】。

#### 3.2.9 自动评估（Auto-Evaluation）

**被什么约束逼出来**：提交频率高于人工评审的周期，而评估太慢的结果就是没人跑评估。
**结构**：
```text
提交 / 训练完成
   └─► CI 流水线触发评估
        ├─ 离线指标（主文件 §2.3）
        ├─ 自动评审（LLM-as-Judge，§3.2.6）
        └─ 门禁判定：红线维度退化 → 阻断；其余 → 记录并放行
判据：评估必须挂在某个环节上（门禁 / 发布），否则它只是一份报告
```
**为什么这样设计有效**：因为评估被放进 CI，每次提交都必须正面回答「有没有退化」，所以退化在进入生产前被发现，而不是等线上指标变化之后回溯【经验，见本书 §6 的 LLM 与 Agent 两个案例】。
**代价**：门禁需要维护「红线维度」清单与豁免流程；误判会阻塞交付，而误判率高的门禁最终会被绕过——严格与可用之间要持续调。
**失效点**：当被优化的指标与真实目标不一致时，「每次提交都能评估」会反转成「被度量物被过拟合」，因为门禁把评估分数变成了提交方的目标函数，而评测集被反复用于优化后，其区分度也会随之下降。
**真实使用**：把 LLM 评估放进 CI 是公开框架的共同方向（【公开】OpenAI Evals, 2023 开源发布）；门槛与阈值的具体取值请以你所用框架的官方文档当前版本为准。

#### 3.2.10 Holdout + 长期监控

**被什么约束逼出来**：实验窗口（天 ~ 周）短于效应稳定所需的时间——新奇效应与学习效应都发生在窗口之外。
**结构**：
```text
实验期              上线
───┼────────────────┼──────────────────────► 时间
   │ 实验组 vs 对照组（短窗）→ 只证明"当下有效"
   └─ 长期保留一组不接触新版本的对照（Holdout）
      判据：短期效应随时间衰减还是放大 —— 只有长窗口能回答
```
**为什么这样设计有效**：因为 Holdout 提供了一个在实验结束之后仍然存在的对照，所以「新奇效应（初期虚高）」与「学习效应（后期上升）」能被区分开，而不是把窗口内的一次读数当成长期结论。
**代价**：保留流量有机会成本（这部分用户长期拿不到改进）；长期监控还要求指标链路、埋点与归因口径在数月内保持一致，口径一改前后就不可比。
**失效点**：当外部环境在长窗口内发生结构性变化（季节、渠道结构、同期其它变更）时，「长期对照」会反转成「被污染的对照」，因为 Holdout 只控制了「是否被处理」，没有控制两组共同经历的外部变化——窗口越长，外部变化累积越多，衰减或放大就越难归因到本处理。
**真实使用**：留出固定比例的长期对照是公开教材与工业实践中的常规做法（【公开】Kohavi 等, 2020《Trustworthy Online Controlled Experiments》, Cambridge）；留存比例取 5–10% 这一量级【经验】——下限来自「长窗口内仍要能看出衰减」，上限来自「机会成本不能长期占住过多流量」，具体取值应结合自己的流量与效应量复核。

### 3.3 模式选择决策表

| 约束组合 | 推荐模式 | 为什么不选另一个 | 关键判据 |
| --- | --- | --- | --- |
| 能随机化 + 流量充足 + 标准模型上线 | 离线两阶段 + 组间实验 + 业务指标 | 只做离线无法回答因果，业务不会认 | 离线指标与业务指标的相关性被测量过 |
| 搜索排序（想快速筛掉大部分候选） | 配对比较（Interleaving）做筛选 + NDCG 类离线排序指标做确认 | 只用配对比较拿不到业务量的绝对估计 | 配对结果与组间实验结论的一致率被持续度量 |
| 推荐排序（要看业务增量有多大） | 组间实验 + 业务量指标（CTR / GMV）+ GAUC 类排序质量指标 | 只看 GAUC 这类离线排序质量会漏掉线上增量，只做配对比较又给不出绝对量 | GAUC 与在线业务指标的相关性被测量过 |
| 想检测小效应 + 流量有限 | 方差缩减（CUPED）+ 组间实验 | 硬加样本量会让周期超出决策窗口 | 存在实验前协变量且与指标强相关 |
| 决策必须在流量发生时做（实时推荐 / 定价） | Contextual Bandit | 组间实验的结论来得太晚，错过即不可补偿 | 奖励可在线观测且延迟可接受 |
| 不能随机化（政策落地 / 全局投放） | DID / 合成控制 / PSM / DML | 直接跑回归会把相关当因果 | 识别假设被写明并做了检验 |
| 多触点营销归因 | Shapley 值 / 数据驱动归因 + 对照实验校准 | 纯规则归因（首触 / 末触）把预算分配变成记账 | 归因口径与实验结论不冲突 |
| LLM 对话输出 | AI-as-Judge + Arena 类人类偏好 + 人类评审校准 | 只用单一总分，维度退化会被平均值掩盖 | 自动评审与人类的**一致率**被度量 |
| LLM 推理（数学 / 代码） | 过程奖励模型（PRM）/ Pass@k | 只看最终答案，分不清是推理错还是格式错 | 过程指标与终态指标分开呈现 |
| Agent 多步任务 | 任务级基准（WebArena / SWE-bench 类）+ 环境容器化 | 单步指标无法代表任务成败 | 评估环境可复现、初始状态固定 |
| 多团队并行实验 | 流量分层（Layered） | 各团队各自开实验会互相污染结论 | 层间效应的可加性被验证过 |
| 同时看多个指标 | Bonferroni / FDR 校正 + 主指标预先登记 | 不校正时「跑得越多、发现的假效果越多」 | 结论中区分了校正前后的显著性 |
| 关心长期效果 | Holdout + 长期监控 | 只跑短窗会把新奇效应当结论 | 留存口径与分流口径一致 |
| 关心公平性 / 合规 | 反事实公平性评估 + 分组指标 | 只看总体指标会掩盖子群退化 | 子群指标被单独列出且不被平均抵消 |

这张表里最常被误选的一对，是**把配对比较当成组间实验的替代品**：它快、灵敏、结果好看，于是团队用它替代 A/B 来做上线决策。后果不是数字错，而是**答错了问题**——胜出率回答「用户更喜欢哪套排序」，它不回答「改完之后 CTR / GMV 是多少」；一旦拿它替代业务量估计，上线决策就建立在一个无法换算成收益的量上，复盘时也说不清这次改动的价值。

### 3.4 组合模式：真实系统不会只用一种

**组合 1：离线两阶段 + 组间实验 + Holdout（标准上线链路）**
- 构成与职责边界：离线负责候选筛除（决定「谁进实验」），组间实验负责因果判定（决定「能不能上线」），Holdout 负责长期效应（决定「要不要留下」）。
- 运维代价：三套口径必须对齐——同一指标定义、同一分流口径、同一埋点；口径漂移会让三者给出互相矛盾的结论。
- 适合规模：有稳定分流基础设施、实验量在周级、业务有明确的决策节拍。

**组合 2：流量分层 + 方差缩减 + 多重比较校正（多团队并行）**
- 构成与职责边界：分层解决实验之间的正交，方差缩减解决灵敏度，校正解决假阳性——三者各自修一个不同的失效模式，缺一个都会漏。
- 运维代价：层的划分要持续验证可加性假设；校正会让「显著」的结论变少，组织必须提前接受「更少但更可信」。
- 适合规模：并行实验到百级/日以上，且有独立的实验平台团队。

**组合 3：自动评审 + 关键场景人工 + 真实用户偏好 + 发布门禁（AI 场景）**
- 构成与职责边界：自动评审覆盖全部提交，人工守住关键场景与一致性校准，真实偏好防止评测集被过拟合，门禁把结论变成动作。
- 运维代价：评测集的版本管理与污染检查、一致率的持续监控、红线维度与豁免流程的维护——这部分成本不会随模型变强而下降。
- 适合规模：迭代频率高于每周一次、且有一条需要举证的发布流程。

### 3.5 反模式与失效分析

下表覆盖全部 12 条反模式（原 § 3.3 的 12 条编号条目全部保留，其中「无 Golden Set」与由它导致的评测集腐烂是同一机制的两面，写在同一行），并为每条补齐「症状 → 后果 → 成因 → 修法」四段。

| 反模式 | 症状（怎么发现它） | 后果（机制层面的后果） | 成因（为什么团队会写成这样） | 修法 |
| --- | --- | --- | --- | --- |
| 只看离线 AUC | 离线提升但业务指标不动，且没人答得出两者的相关性 | 历史样本上的排序 ≠ 未来反馈下的效应，判定面从一开始就选错了 | 离线便宜、可重复、给反馈快 | 离线只做候选筛，上线决策由能随机化的在线对照给出（§3.2.1） |
| 实验时间太短 | 3 天就出结论，从未跑满过一个完整业务周期 | 新奇效应与学习效应都在窗口之外，未稳定的读数被当成结论 | 决策周期压着实验周期 | 窗口覆盖 1–2 个完整业务周期【经验】+ Holdout 分离长期效应（§3.2.10） |
| 忽视 SRM | 实际分流比例与设计不符，往往实验结束才发现 | 两组用户构成不同，所有显著性判断建立在错的样本上（静默失效） | 分流逻辑散落在埋点、过滤、缓存、客户端版本里 | 高频自动校验实际分流比例，超阈值即告警并暂停（§3.2.8、本书 §6 案例） |
| 多重比较不管 | 同时测 10 个指标，其中一个 p≈0.04 被当作发现 | 检验越多，纯随机产生「显著」的概率越高，平台越活跃假阳性越多 | 指标清单由业务临时追加，缺少预先登记 | 主指标预先登记 + Bonferroni / FDR 校正 + 区分呈现（主文件 §2.2） |
| 样本量不够硬上 | 日流量千级仍要检测个位数的百分比提升 | 功效不足时「不显著」既可能是没效应、也可能是没流量，结论无法判读 | 「先跑起来再说」 | 先按 n ∝ 1/δ² 算最小样本量，算不出可行周期就换方法（§3.2.2、§3.2.4） |
| 把 Interleaving 当 A/B | 用配对比较的胜出率替代业务量来做上线决策 | 配对比较给相对偏好，换算不出 CTR / GMV 这类绝对量 | 灵敏度高、跑得快、结果好看 | 配对比较用于筛选，业务量估计仍由组间实验给出（§3.2.2） |
| 新奇效应误判 | 上线首周效果好，之后回落 | 初期由好奇驱动，随后回到基线；被当成永久效应就是误判需求 | 长窗口观测的成本高、反馈慢 | Holdout + 长期监控，看效应随时间的走向（§3.2.10） |
| 把相关当因果 | 「投放多时销量好」被当成加投的理由 | 混淆变量同时驱动投放与销量，回归系数不是效应 | 观测数据唾手可得、因果设计昂贵 | 能随机化就随机化；不能就写明识别假设并做检验（§3.2.5） |
| LLM-as-Judge 不校准 | 换一天跑分数明显变化，或裁判与被评模型同源 | 偏好成了「裁判—对象配对」的属性，不是对象本身的属性 | 自动评审便宜、能覆盖全部提交 | 人类评审锚定 + 一致率持续度量；两两比较时交换呈现顺序（§3.2.6） |
| Agent 评估只看最终结果 | 只报任务成功率，失败原因不可解释 | 单步错误与终态失败不是一回事，只看终态无法定位也无法改进 | 终态容易判定，过程需要额外记录 | 任务级指标判定价值、过程级指标只做诊断、环境容器化（§3.2.7） |
| 无 Holdout | 100% 流量都在做实验，任何时刻都没有未处理对照 | 长期效应无法与外部变化分离，结论都相对于「当时的其它处理」 | 流量永远不够，留出对照看起来像浪费 | 留出固定比例的长期对照，且留存口径与分流口径统一（§3.2.10） |
| LLM 评估无 Golden Set / 评测集腐烂 | 同一模型两次评估分数不可比，或被反复使用的评测集区分度下降 | 没有固定锚点就没有可比性；评测集被反复用于优化后就不再是独立的测试集 | 评测集建设慢、标注贵 | 维护带版本与更新机制的评测集，做污染检查与一致率监控（§3.2.6、§3.2.9） |

**忽视 SRM 是最典型的静默失效。** 它不会报错：实验照常跑、看板照常出数、显著性照常计算，只有两组用户的构成不同。暴露方式通常是实验结束、结论已经交付之后，有人发现某组的客户端版本分布不对；此时期间的所有判读都要作废。它的危险在于「看起来和分流无关」的来源太多——埋点位置、过滤条件、缓存穿透、版本分布——所以它只能靠高频自动校验来防，而且必须排在所有指标显著性检查之前。

**把 Interleaving 当 A/B 用的是边界误用，不是计算错误。** 这类误用往往不会在实验期暴露：灵敏度更高、周期更短，看起来处处更优。它暴露在复盘阶段——当有人问「这次改动值多少钱」时，团队拿不出一个能换算成业务量的数字，只能回答「用户更偏好」。更隐蔽的版本是：把配对比较的结论直接当作组间实验的替代证据存档，于是下一次复盘无法解释为什么线下偏好提升没有变成线上收益。

**LLM-as-Judge 不校准是 AI 场景里最容易复发的一条。** 它的暴露方式是评估结果与人工抽查结论不一致，且不一致的方向随批次变化（自我偏好、位置偏差、长度偏好各占一部分）。因为裁判模型也在迭代，校准不是一次性的：每次换裁判版本、换提示模板、换评测集，一致率都要重新测，否则评估系统本身就成了不确定性的来源。

### 3.6 规模跃迁时模式何时该换

模式不是一劳永逸的：实验量、效应量、指标个数或评估对象的形态跨过某个阈值时，原来正确的模式会开始失效。

| 跃迁 | 原模式 | 为什么开始疼 | 换成 | 迁移的代价 |
| --- | --- | --- | --- | --- |
| 实验量从月级个位数到百级/日 | 各团队各自开实验、各自写分流 | 共享流量被争抢，实验互相污染；假阳性随实验数累积 | 集中分流 + 流量分层 + 多重比较校正（§3.2.8） | 历史结论与新口径不可比，需要一次重跑；要养一个平台团队 |
| 要检测的效应从大变小 | 靠加大样本量、拉长周期 | 周期超出决策窗口，「跑得动的结论」变成「等不到的结论」 | 方差缩减 / 配对比较（§3.2.2、§3.2.4） | 需要实验前数据链路与协变量治理；配对设计适用范围受限 |
| 指标从单个变成一组 + 护栏指标 | 每个指标各自检验，谁显著看谁 | 假阳性随指标数上升，平台越活跃结论越不可信 | 主指标登记 + 校正 + 分维度呈现 + 红线维度（§3.2.9） | 组织要接受「显著」变少；需要处理红线与总分的取舍规则 |
| 从能随机化到不能随机化 | 组间实验 | 处理无法分配，实验根本开不起来 | DID / 合成控制 / PSM / DML（§3.2.5） | 结论强度下降；必须写出并论证不可检验的识别假设 |
| 评估对象从结果型模型到过程型系统 | 单一准确率 / 单一总分 | 维度退化被平均掩盖；单步正确不代表任务完成 | 多维度画像 + 任务级评估 + 混合评审（§3.2.6、§3.2.7） | 评测集与评估环境的建设成本变成长期预算项 |
| 评估结论从参考变成决策依据 | 评估只出报告 | 不承担后果的评估没人修，假阳性与退化版本照样上线 | 绑定发布门禁 + 豁免机制（§3.2.9） | 门禁误判会阻塞交付，需要申诉通道与阈值调优 |

跃迁的共同特征是：**触发条件都是可观测的**——实验数、所需 MDE、指标个数、评估单位——所以「该不该换模式」不该靠争论，而该靠这几个数之一是否已经越界来判断。

还有一条顺序上的约束：**先确认分流可信，再谈灵敏度**。分流比例不对时，方差缩减、配对比较、分层这些提高灵敏度的手段都只会让一个错误的结论显得更精确——顺序反了，投入越多、错得越像真的。

### 3.7 自检清单

- [ ] 每个正在跑的实验，都能说出它的随机化单位与观测单位分别是什么、两者是否一致？
- [ ] 实际分流比例有高频自动校验，偏差超阈值会告警并暂停实验吗（而不是实验结束才发现）？
- [ ] 上线决策的依据，是一个能随机化的在线对照，还是只有离线指标？
- [ ] 这个实验要检测的最小效应（MDE）是多少，按主文件 §2.2 的公式算出的最小样本量与可知的实验周期对得上吗？
- [ ] 同时在看的所有指标里，主指标被预先登记了吗？其他指标的显著性做了校正吗？
- [ ] 实验窗口覆盖了几个完整业务周期？如果只有一个，靠什么排除新奇效应？
- [ ] 长期对照（Holdout）存在吗？它的留存口径与实验分流口径一致吗？
- [ ] 排序类改动用的是配对比较还是组间实验？如果把配对结果当业务量，谁负责换算？
- [ ] LLM 评估里，自动评审与人工判断的一致率最近一次是什么时候测的？换过裁判版本之后重测了吗？
- [ ] Agent 评估里，任务级指标与过程级指标是分开呈现的吗？评估环境能被固定到同一初始状态吗？

### 3.8 小结

| 你的约束 | 建议模式 | 关键理由（机制层面） |
| --- | --- | --- |
| 能随机化、流量够、要上线 | 离线两阶段 + 组间实验 + Holdout | 因果判定只能来自随机对照，长期效应只能来自长窗口 |
| 排序类、要快速筛选 | 配对比较 + 组间实验确认 | 配对消掉单元间方差换灵敏度；绝对量仍要组间对照 |
| 流量不足、要检测小效应 | 方差缩减（CUPED） | 扣掉可由实验前协变量解释的方差，不改变期望只降方差 |
| 不能随机化 | DID / 合成控制 / PSM / DML | 用可论证的识别假设替换随机化，并明确写出假设 |
| 决策必须在线发生 | Contextual Bandit | 分配随观测动态调整，把探索成本限制在有界范围 |
| 开放文本 / 多步任务 | 三路评审 + 任务级评估 | 判定单位与真实价值对齐；单步指标只做诊断 |
| 组织级并行实验 | 分层 + 校正 + 主指标登记 | 正交解决污染，校正解决假阳性——两个不同的失效模式 |

> 本节小结：本主题下决定模式选择的**唯一那条约束是「处理能不能被随机分配到可比的单元上」**——能随机化时，所有方法都在回答「怎样用更少的流量更精确地测出效应」；不能随机化时，所有方法都在回答「用哪个假设替换掉随机化，以及这个假设有多可信」。第二条约束是**评估单位**（终态 / 排序 / 轨迹），它决定你的判定对象与用户实际获得的价值是否是同一个东西。
