## 5. 前沿演进（AI 时代）

> 原 § 5 共 174 行，把 8 个方向、与 RAG 的结合、学术与工业条目、8 条趋势写成同一张清单，缺少机制与成熟度判断，重写为约 310 行的前沿评估。

### 5.1 先分清三类「前沿」

[§3 §3.1](06-rl-section-3-sec3.md) 已指出：RL 的模式选择几乎被一条约束单独决定了一半答案——**样本从哪来，以及你能不能在那个环境里试错**。趋势清单把这条约束抹平了：它把「用一份可自动判定的奖励训练一个模型」（今天多个实验室在大规模做）与「让智能体在自我对弈里学会长期策略」（前提是完全可仿真的零和博弈）写成同一种句式，读者据此排路线图，多半会先去做那个前提根本不成立的。

第二个问题是机制差异被抹平。本主题的「前沿」改动三样东西，改动它们的东西完全不同：

1. **奖励从哪来**：人工设计 → 成对偏好 → 规则可判定的结果。
2. **状态与动作是什么**：数值向量与离散动作 → 模型生成的文本序列 → 一次工具调用。
3. **环境从哪来**：真实系统或手写仿真 → 可自动验证、可回滚的任务环境。

AI 真正改变的是第 1 层与第 3 层：它把「奖励」和「环境」这两样过去靠人工供给的东西，变成了可以批量生产的。**它没有改变第 2 层的代价**——动作空间从离散动作变成「一段文本」并不减少采样开销，一条轨迹几十步、每步都要模型生成，成本随步数叠加（[§3 §3.2.10](06-rl-section-3-sec3.md) 的代价一段）。它**也没有改变 §3.1 的第一条约束**：数据必须由当前策略产生，这笔 on-policy 的账，偏好与可验证奖励都绕不开（[§3 §3.2.3](06-rl-section-3-sec3.md) 的失效点讲的就是它）。

第三个问题藏得更深：本主题的多数方向**不是「能不能采购到某个产品能力」，而是「要不要自己搭一条训练回路」**——离线数据集、可回滚的环境、可判定的奖励函数，三样都得自己造。因此判据 ① 按对象分两类核。

三级划分如下，三条判据必须可核验：

- **L1 生产可用**：三条全中才算。① 已 GA 且有正式 release note；② 有**第三方（非厂商）公开的生产案例**；③ 接口稳定、可预期。
- **L2 可试点**：①③ 成立，② 不成立；或能力已可用而接口 / 生态未稳。可以做 PoC，不要做核心依赖。
- **L3 观望**：① 或 ③ 不成立——正式载体拿不出，或接口形态本身还在变动。记录即可，不要在架构里为它预留假设。

**本主题对 §2.1 的 L1 判据 ① 做如下修正，理由是对象不同**：① 的原义是「已 GA 且有正式 release note」。本主题的多数方向对象是**建模机制**而不是可直接采购的产品能力——离线策略的保守估计、从演示反推奖励、多智能体的集中训练分散执行、想象空间里的 rollout、分层的时间抽象，它们没有「GA 产品」这一形态，正式发布物就是论文与公开实现。因此 ① 按对象分两类核，全节统一适用：**产品能力类**（要落地就得先拿到某一项能力：带版本记录的偏好优化训练器、可回滚的 Agent 训练环境、带版本记录的多智能体训练框架）要求该能力项有版本化文档或 release note；**建模机制类**（偏好对齐目标、组内相对优势、保守 Q 学习、奖励反推、值分解、世界模型、时间抽象）要求该机制有可核验的正式载体——同行评审的会议或期刊论文，或带版本化发布记录的公开实现。**① 与 ③ 一样分三档，全节统一**：正式载体明确、且带版本化发布记录或同行评审出处的为**满足**；有正式发表物、但接口与版本由各实现自行定义的为**大体满足**；只有预印本、厂商演示或博客，或该方向赖以实现的关键环节（可自动判定且不泄漏评测集的环境、日志里事后不可补的倾向得分、可迁移的想象 rollout 精度）在公开材料里没有定义的，判**不满足**。**② 按 §2.1 原文核，不做修正**；③ 同样分三档，分档口径在表前一段给出——**② 仍是本节全部方向的上限，也是本节没有任何方向达到 L1 的唯一原因**。

判据 ② 在本主题格外难过，原因值得先说清：**RL 的效果数字与「奖励函数是什么、环境是什么」不可分割，而这两样通常不公开**。公开的「效果提升」基本都是建设方自述，样本量、对照条件与奖励口径都握在发布方手里；基准成绩（任务成功率一类）又与业务任务之间隔着一层，且「训练环境是否与评测集重叠」这件事在多数公开材料里不被交代。**② 只有「满足」与「降为 L2」两种命运**：它不能改写成「有公开效果数字」，也不能靠「本节只评估某一层」把适用范围缩小来绕过去。

还要说清 L2 在本节的含义：它标的是**证据缺口**，不是「不建议用」。当一行的 ①③ 成立而只缺 ② 时，缺的是「别人用过、并且公开说了代价」这类材料，不是能力本身；采不采用由读者按自己的风险偏好决定，判据本身不因这句说明而放宽。

③ 分三档，全节统一（与①同形，分档口径已在判据修正一段给出）：接口多年不变为**满足**；形态趋于一致但仍有未定部分为**大体满足**；接口本身还在变动、或关键交接物没有定义为**不满足**。

拿到任何一条方向，按顺序问三句就能自己核一遍：① 它的正式载体能不能找到（产品能力类看 release note 或版本化文档，建模机制类看同行评审论文或带版本记录的公开实现）？找不到 → L3。② 建设方之外的证据能不能找到？找不到 → L2。③ 接口明年会不会变？会变 → 至多 L2。

第 3 句在本主题特有的失手方式，是把「奖励函数」当成常量：策略会沿着奖励里**可被优化的那一部分**走，奖励不变而策略变强，行为照样会漂。判定方法是看变更记录里有没有「奖励函数版本 + 偏好或环境版本」这一项，而不是看训练曲线。

### 5.2 演进方向逐条拆解（核心节）

下面三个小节都按同一套结构写：**旧做法卡在哪 → AI 改变了什么机制 → 由此得到什么 → 由此付出什么 → 证据与来源 → 成熟度**。只写收益不写代价的方向，评审时应直接打回——本主题的每一次能力提升，都对应一项成本结构的变化。

#### 5.2.1 偏好对齐：把奖励从「人工设计」换成「成对比较」

- **旧做法与它的卡点**：想优化「回答好不好」这类目标，旧做法是把目标写成奖励函数（长度、格式、关键词命中），再对策略做策略梯度。卡点在奖励本身：这些指标都只是「好回答」的代理，策略会沿着可被优化的那一部分走，把长度堆上去、把关键词塞满，而真实质量没有提升（[§3 §3.1](06-rl-section-3-sec3.md) 把「奖励是这套系统的规格说明，不是超参」列为本主题四条反模式的共同根因）。而「好回答」根本写不成监督标签——写得出就直接做监督微调了。
- **AI 改变了什么机制**：把「人写奖励函数」换成「**人只给出成对比较，偏好本身成为训练信号**」。这一步在**信号来源**上是真变化：奖励不再是一个能被写下来的函数，而是从比较里学出来（RLHF）或被比较直接吸收进损失（直接偏好优化）。换的不是优化器，是奖励的产生方式。
- **由此得到的**：因为「哪个更好」比「好的标准是什么」容易回答得多，**所以**标注成本从「写规格」降到「做选择」，且能覆盖写不出规格的维度；**又因为**直接偏好优化省掉了「先训奖励模型再用 RL 优化」的两段式，**所以**训练链路少一个可被刷分的环节，稳定性与工程复杂度同时下降——这是它在对话模型对齐上成为默认路线的机制原因。
- **由此付出的**：**其一，省掉在线采样也就失去了训练中持续用新数据检验的能力**——直接偏好优化对偏好数据的分布更敏感，偏好集里没出现过的情况得不到纠正（[§3 §3.2.9](06-rl-section-3-sec3.md) 的代价一段）。**其二，代理目标会被优化到失效**：偏好胜率上升而真实任务成功率下降，两者都不报错，这是本主题最难发现的一类故障（[§3 §3.2.9](06-rl-section-3-sec3.md) 的失效点）。**其三，KL 约束要常驻一份冻结的参考权重**——对齐训练不是微调，实际显存成本就来自这里。**其四，偏好数据不可复现**：标注口径、采样来源、参考权重版本三者不进登记，跨期结论不可比。
- **证据与来源**：【公开】偏好学习用于策略训练的原始框架（Christiano 等，NeurIPS 2017）、直接偏好优化（Rafailov 等，NeurIPS 2023）；带版本记录的公开实现是 HuggingFace TRL 与 OpenRLHF 这两个开源训练库，它们把偏好优化做成了并列的训练器条目（`DPOTrainer` / `PPOTrainer` 一类），DPO 训练器在 2024 年前后进入各自的文档【公开】（按各库文档与发布记录核验；**类名、参数名与引入版本请以其官方文档当前版本为准**）。**② 不满足**：本节给不出建设方之外、含奖励口径与对照条件的公开生产案例。
- **成熟度**：**L2**（与 5.1 表「偏好对齐」行一致）：① 满足、③ 满足、**② 不满足**。

```text
奖励从哪来，决定了失效面在哪
  旧：人写奖励 r(x) ──► 策略沿 r 里可优化的部分走 ──► 现象：长度、格式、关键词被堆高
  新：人只给成对比较 ──► 偏好成为信号
        ├─ 路线 A：比较 → 学一个奖励模型 → 再优化策略（多一个可被刷分的环节）
        └─ 路线 B：比较 → 直接写进对比损失（少一个环节，但失去在线检验）
  ────────────────────────────────────────────────
  没有改变的东西：策略仍会沿着代理目标里可优化的那一部分走
  改变的东西：代理目标的来源，以及「谁有权定义什么叫好」
  新增的登记项：偏好数据口径 + 参考权重版本 + 奖励函数版本
```

**怎么判断该不该做**（三项都不需要新采购）：先看偏好数据是从哪采的——线上采样与离线收集的分布不同，结论不可互换；再看有没有一条与偏好指标**不同源**的业务指标在做双轨监控，只有偏好胜率一项，异常发现不了；最后量一次冻结参考权重带来的显存与吞吐开销，它决定这套流程能不能与现有训练任务共存。

#### 5.2.2 可验证奖励：把奖励从「比较」换成「规则判定」

- **旧做法与它的卡点**：偏好对齐解决的是「说不清的标准怎么学」，但它有一个结构性上限——**比较只能给出强度，不能给出对错**。在数学、代码、可执行任务这类「答案能被自动判定」的场景里，用偏好去逼近一个本来就存在判定器的东西，等于把可得的确定信号换成了有噪声的近似信号，而且偏好标注的规模永远赶不上自动判定的规模（[§3 §3.2.10](06-rl-section-3-sec3.md) 把「奖励可被规则自动验证」列为 2024 年以后 Agent 训练能规模化的关键）。
- **AI 改变了什么机制**：把奖励从「比较出来的偏好」换成「**由环境判定的成败**」（测试是否通过、答案是否匹配、约束是否满足），并把优势估计从「需要与策略同规模的价值网络」换成**组内相对得分**。换掉的是优势的估计方式与奖励的生产方式；策略优化本身仍是策略梯度那一套（主文件 §2.3 的 LLM RL 系列）。
- **由此得到的**：因为奖励可以自动产出，**所以**训练信号不再受标注产能限制，规模问题从「标多少」变成「造多少可判定的任务」；**又因为**组内相对得分替代了 Critic，**所以**优势估计不再需要一个与策略同规模的价值网络，显存与训练复杂度同时下降——[§3 §3.2.9](06-rl-section-3-sec3.md) 给过这条显存账：去掉一份与策略同规模的权重与它的优化器状态。
- **由此付出的**：**其一，奖励只在能被判定的地方存在**——把可验证奖励的做法搬到判定不了的场景（写作、咨询、开放对话），等于凭空造一个判定器，回到「代理目标被优化到失效」这条老路上。**其二，组内比较把成本转到采样**：同一道题要采多个回答才能算相对优势，推理开销从训练挪到了采样。**其三，奖励形态与超参没有共识**：这是本方向 ③ 只算大体满足的原因——奖励塑形、长度惩罚、组大小、KL 系数每家的选择都不同，换一个配置结论就可能翻转。**其四，参考权重仍要常驻**，KL 约束这一项成本一分没少。
- **证据与来源**：【公开】组内相对优势的做法出自 DeepSeek 的 GRPO 公开报告（DeepSeekMath，2024），把可验证奖励用于长链推理的代表是 DeepSeek-R1 的公开报告（2025）；带版本记录的公开实现是 HuggingFace TRL 的 GRPO 训练器（`GRPOTrainer`，2025 年前后进入该库文档）与 OpenRLHF 的同类训练器【公开】（按各库文档与发布记录核验；**正式发表状态、年份与类名请以其官方文档当前版本为准**）。**② 不满足**。
- **成熟度**：**L2**（与 5.1 表「可验证奖励训练」行一致）：① 满足、③ 大体满足、**② 不满足**。

```text
判定器存在与否，是这条方向能不能用的分界线
  判定器存在（测试 / 参考答案 / 约束检查）
        └─► 奖励可自动产出 ──► 训练信号随任务数扩展，不受标注产能限制
  判定器不存在（写作 / 咨询 / 开放对话）
        └─► 只能自己造一个代理判定器 ──► 回到偏好路线，
             或承受「代理目标被优化到失效」的风险
  ────────────────────────────────────────────────
  这不是模型能力问题：换更强的模型，判定器仍然不存在。
  判据很硬：能不能写出一个会在训练中不断被判错的函数。
```

**怎么判断该不该做**：先写出那个判定函数，再看两件事——它被判错时会不会连带正确的行为一起罚（奖励塑形是否过粗），以及它能不能在训练过程中持续产出新任务（任务池耗尽后，收益会退化成对同一批任务的过拟合）。

#### 5.2.3 Agent RL：把「环境」也变成可自动生产的

- **旧做法与它的卡点**：想让智能体学会多步操作（点页面、调工具、改代码），旧做法是人工写动作规则或拉一条演示数据做模仿。卡点有两处：规则覆盖不住长尾路径，演示数据只覆盖专家到过的状态；而真正的瓶颈是**奖励只在任务终局出现**，几十步的动作要分摊一个二值信号（[§3 §3.2.10](06-rl-section-3-sec3.md) 的「被什么约束逼出来」与失效点）。
- **AI 改变了什么机制**：把「环境靠人工搭建」换成「**环境由可自动验证的任务构成**」——任务来自真实网站与真实代码仓库，成败由单元测试或状态检查自动判定。换掉的是试错场所的生产方式；动作空间是模型生成的文本这一点没变（[§3 §3.2.10](06-rl-section-3-sec3.md) 的结构一段）。
- **由此得到的**：因为成败可以自动判定、任务可以批量产出，**所以**训练信号第一次不必依赖人工标注或专家演示，长链任务的训练从「采不起」变成「造得出」；**又因为**轨迹是可回放的（同样的环境、同样的动作可以重跑），**所以**信用分配可以借助中间检查点被切细——这两条合起来是它从演示时代进入训练时代的分界。
- **由此付出的**：**其一，最有价值的环境正好是最贵的那部分，而且它与评测集天然冲突**——能自动判定成败的任务集合是稀缺资源，实验室会把它同时用作训练集与评测集，一旦重叠，公开的成功率数字就不再说明泛化（本节 §5.3 表里「训练环境 ↔ 评测基准」是本节最容易失守的一行）。**其二，环境必须可回滚、可沙盒**，否则训练会污染真实系统；这一步的工程量大于算法本身。**其三，成本随步数叠加**——一条轨迹几十步、每步一次生成，采样成本线性甚至超线性上升。**其四，奖励密度不变时长链会退化**：终局奖励分到更多步上，回报方差随步数增长，同样训练步数提供的有效信息下降（[§3 §3.2.10](06-rl-section-3-sec3.md) 的失效点）。
- **证据与来源**：【公开】两个以真实网站与真实仓库为任务来源、成败可自动判定的公开评测环境：WebArena（Zhou 等，ICLR 2024）与 SWE-bench（Jimenez 等，ICLR 2024），篇名与页码以论文库当前版本为准；用大规模 RL 训练长链推理是模型厂商在公开材料里描述的方向——OpenAI 在 o1 / o3 的公开系统卡与发布材料（2024–2025）里描述过这条路线，DeepSeek 在 R1 的公开报告（2025）里给出了同类描述【公开】（建设方自述口径，用来核验机制存在，不能充当判据 ②）。**② 不满足**。
- **成熟度**：**L2**（与 5.1 表「Agent RL」行一致）：① 大体满足、③ 大体满足、**② 不满足**。

```text
训练环境与评测基准必须分离（否则数字没有意义，而且不会报错）
  任务来源：真实网站 / 真实代码仓库
        ├─► 训练集：环境可回滚、奖励可自动判定、允许反复重跑
        └─► 评测集：与训练集零重叠，且不参与任何梯度更新
  ────────────────────────────────────────────────
  失守的方式很安静：把评测集并入训练任务池，
  指标继续上升，泛化能力下降，两种变化都不触发告警。
  判定方法：训练日志里能不能逐条列出「本批任务不在评测集内」。
```

**怎么判断该不该做**：先算三个数——可自动判定的任务有多少条、其中有多少能回滚重跑、训练任务池与任何公开评测集的重叠比例。第三个数为零之前，训练出来的数字无法与外部对照。

#### 5.2.4 其余方向为什么停在这里

下面 7 条同样按六行结构写：它们停在低处不是因为看不到收益，而是因为判据过不去；把理由拆成六行，是为了让「停在这里」这个判断能被逐条复核。

- **Self-Play RL · 旧做法与它的卡点**：没有人类数据能达到目标水平（棋类、对战游戏），而模仿人类会把上限锁在人类水平（[§3 §3.2.8](06-rl-section-3-sec3.md) 的「被什么约束逼出来」）。
- **Self-Play RL · AI 改变了什么机制**：把对手的训练数据来源换成「策略的历史版本与联盟成员」——课程难度随自己提高而自动生成。
- **Self-Play RL · 由此得到的**：因为对手水平随自己提高，**所以**不需要人类数据就能持续获得「难度恰好」的训练信号；且评估标准是胜率而不是「模仿得像不像」，优化的是实际胜负。
- **Self-Play RL · 由此付出的**：训练要维护多个历史版本与多种角色并做海量仿真对战，成本高；单一自我对抗会双方共同收敛到一个狭窄的局部最优，必须引入种群结构（[§3 §3.2.8](06-rl-section-3-sec3.md) 的失效点）；且前提是环境完全可仿真且为零和博弈，这个前提在多数业务场景不成立。
- **Self-Play RL · 证据与来源**：【公开】自我博弈训练在棋类上的成果（Nature 2017 / Science 2018）与联盟式训练在实时策略游戏上的成果（Nature 2019）【公开】。**② 不满足**。
- **Self-Play RL · 成熟度**：**L2**（与 5.1 表一致）：① 满足、③ 满足、**② 不满足**；且前提在多数业务里不成立。

- **Offline RL · 旧做法与它的卡点**：不能在真实环境里试错（医疗、自动驾驶、部分推荐场景），但历史交互日志很丰富——有数据、没有试错权（[§3 §3.2.5](06-rl-section-3-sec3.md) 的「被什么约束逼出来」）。
- **Offline RL · AI 改变了什么机制**：把「在环境里试错」搬到「在数据与仿真里学」，并显式压低分布外动作的价值估计（保守项），使策略不跑到没有数据支撑的区域。
- **Offline RL · 由此得到的**：因为决策的在线代价被压到零，**所以**没有试错权的场景第一次能走策略优化而不是只能做监督学习。
- **Offline RL · 由此付出的**：**日志里没有反事实奖励**，所有「如果当时选了别的会怎样」都靠假设与修正项；**倾向得分与行为策略版本必须在埋点时就记录，事后无法补**，很多团队的历史日志因此根本用不了；且失败形态是「离线评估漂亮、上线即跌」，触发条件是策略与日志策略的分布距离，不是训练轮数（[§3 §3.2.5](06-rl-section-3-sec3.md) 的失效点）。
- **Offline RL · 证据与来源**：【公开】保守 Q 学习、隐式 Q 学习、TD3+BC 与离线评测基准都是公开论文与公开实现（2020–2021）【公开】。**② 不满足**。
- **Offline RL · 成熟度**：**L2**（与 5.1 表一致）：① 满足、③ 大体满足、**② 不满足**。

- **逆强化学习 / 模仿学习 · 旧做法与它的卡点**：能说清「做得好」很难，但能拿到专家演示——奖励未知、示范已知（[§3 §3.2.6](06-rl-section-3-sec3.md) 的「被什么约束逼出来」）。
- **逆强化学习 / 模仿学习 · AI 改变了什么机制**：把奖励从「人写」换成「**从专家会怎么做里反推**」，或绕开显式奖励、用判别器直接给策略打分。
- **逆强化学习 / 模仿学习 · 由此得到的**：因为奖励不再由人设计，它绕开了奖励设计这一关；且相对于纯行为克隆，它通过与环境交互修正分布偏移，缓解误差随轨迹长度累积的问题。
- **逆强化学习 / 模仿学习 · 由此付出的**：**学到的奖励不唯一**——同一行为可被多个奖励解释，因此它不能当业务口径用；演示数据的采集昂贵且覆盖窄（只覆盖专家到过的状态），部署环境一偏移，策略会去优化演示里偶然与专家行为相关的特征（[§3 §3.2.6](06-rl-section-3-sec3.md) 的失效点）。工程上更实际的顺序是先跑行为克隆，它本身是纯监督学习，不需要 RL。
- **逆强化学习 / 模仿学习 · 证据与来源**：【公开】生成对抗模仿学习（Ho & Ermon，2016）与对抗式逆强化学习（Fu 等，2017）是该方向的公开代表【公开】。**① 满足**；**③ 不满足**——学到的奖励无唯一解、无验收口径；**② 无**。
- **逆强化学习 / 模仿学习 · 成熟度**：**L3**（与 5.1 表一致）：① 满足、③ 不满足、② 无。

- **多智能体 RL · 旧做法与它的卡点**：决策主体多于一个，每个主体的回报都依赖其他人的动作，环境对每个个体都是非平稳的（[§3 §3.2.7](06-rl-section-3-sec3.md) 的「被什么约束逼出来」）。
- **多智能体 RL · AI 改变了什么机制**：把「各自独立学」换成「**训练期汇总全局信息、执行期只用本地观测**」（集中训练分散执行），并用值分解把团队回报拆到个体。
- **多智能体 RL · 由此得到的**：因为训练期能拿到全局信息，**所以**每个智能体的价值估计能「看见」别人造成的非平稳性，训练从这里获得稳定；因为执行期不需要中心信息，策略可以真的部署到去中心环境里。
- **多智能体 RL · 由此付出的**：中心 Critic 的输入是全体观测与动作的联合，维度随智能体数呈指数增长，可扩展性差；值分解要引入可分解的结构假设，假设不成立时个体价值失去解释力；智能体数量升到几十上百时，联合空间爆炸使训练直接不可行，奖励曲线长期震荡不上行（[§3 §3.2.7](06-rl-section-3-sec3.md) 的失效点）。
- **多智能体 RL · 证据与来源**：【公开】MADDPG（Lowe 等，2017）、QMIX（Rashid 等，2018）、MAPPO（Yu 等，2022）是公开代表算法与实现【公开】。**② 不满足**。
- **多智能体 RL · 成熟度**：**L2**（与 5.1 表一致）：① 满足、③ 大体满足（分工多年未变，但规模上限由联合空间决定）、**② 不满足**。

- **分层 RL · 旧做法与它的卡点**：奖励稀疏而任务时间长，单个动作对最终奖励的影响被稀释到无法学习（[§3 §3.2.11](06-rl-section-3-sec3.md) 的「被什么约束逼出来」）。
- **分层 RL · AI 改变了什么机制**：把「扁平策略直接选动作」换成「**高层在慢时间尺度上选子目标、低层在快尺度上执行**」——做的是时间抽象，不是网络结构。
- **分层 RL · 由此得到的**：因为高层看到的「一步」跨越了很多原始步，**所以**稀疏奖励在高层被压缩成「选哪个子目标」这个更密的决策问题，信用分配距离因此变短。
- **分层 RL · 由此付出的**：子目标空间与时间尺度都是先验，选错则低层不可达或高层失去意义；两层联合训练会互相掩盖问题（高层失败可能是低层没做到），调试成本高于单层；子目标一旦与最终目标不相关，两层都在优化一个无关的中间量（[§3 §3.2.11](06-rl-section-3-sec3.md) 的失效点）。工程上更常见也更可控的是手工分阶段与课程学习。
- **分层 RL · 证据与来源**：【公开】时间抽象框架（Sutton、Precup、Singh，1999）与可学习分层的公开实现（FeUdal Networks，2017）【公开】。**① 满足**；**③ 不满足**——子目标空间与时间尺度没有标准做法；**② 无**。
- **分层 RL · 成熟度**：**L3**（与 5.1 表一致）：① 满足、③ 不满足、② 无。

- **世界模型 · 旧做法与它的卡点**：真实交互代价高到不可承受，而每一份真实数据换来的策略改进太少（[§3 §3.2.4](06-rl-section-3-sec3.md) 的「被什么约束逼出来」）。
- **世界模型 · AI 改变了什么机制**：把「在真实环境里试错」换成「**先学一个环境模型，在它的隐空间里做 rollout 训练策略**」——MCTS 式规划与隐空间想象是同一件事的两种实现。
- **世界模型 · 由此得到的**：因为想象 rollout 也参与策略更新，**所以**同样次数的真实交互能产生更多梯度，样本效率的差距主要来自这里。
- **世界模型 · 由此付出的**：多了一个模型误差来源，而规划恰恰主动去访问模型没见过的区域——在错误的模型里规划得越深，偏离真实世界越远，误差随规划视野累积（[§3 §3.2.4](06-rl-section-3-sec3.md) 的失效点）；且观测编码与想象 rollout 的接口在实现之间差异很大，「想象训练能否迁移到真实环境」目前没有统一验收口径。
- **世界模型 · 证据与来源**：【公开】Dreamer 系列与 Transformer 世界模型一类的公开代表工作（2021–2023，正式发表状态与年份以论文库当前记录为准）【公开】。**① 满足**；**③ 不满足**——接口与迁移验收口径均未定；**② 无**。
- **世界模型 · 成熟度**：**L3**（与 5.1 表一致）：① 满足、③ 不满足、② 无。

- **用 RL 优化检索通路 · 旧做法与它的卡点**：检索策略靠人工规则与离线指标调（检索几个文档、按什么顺序、怎么融合），调完就对线上分布固定住了。
- **用 RL 优化检索通路 · AI 改变了什么机制**：把「人工定检索策略」换成「**把路由与检索决策当成动作、用奖励去优化**」——换的是策略的优化方式，检索本身仍是既有的那套。
- **用 RL 优化检索通路 · 由此得到的**：**如果**奖励能定义得比启发式指标更贴近任务成败，它可以把「检索哪些、按什么顺序」与最终结果直接挂钩。
- **用 RL 优化检索通路 · 由此付出的**：检索动作的回放极不稳定（同一问句在不同时间检索到的结果不同），**没有可回放的环境就没有可靠的信用分配**；而且奖励一旦只用最终答案正确性，检索策略会退化成「多检索总没错」，把成本转嫁给延迟。
- **用 RL 优化检索通路 · 证据与来源**：公开材料以论文与工程博客为主，没有把「用 RL 优化检索策略」作为能力项或机制的正式发布；**① 不满足**；**③ 不满足**——检索动作不可回放，「可回放的检索结果 + 奖励定义」这一交接物未定义；**② 无**。
- **用 RL 优化检索通路 · 成熟度**：**L3**（与 5.1 表一致）：① 不满足、③ 不满足、② 无。

把上面七条并排看，停在低处的理由只有两类：**一类是接口还不成立**（想象 rollout 的迁移验收、子目标空间与时间尺度、学到的奖励无唯一解、检索动作不可回放），**一类是前提条件不成立**（Self-Play 需要可仿真的零和博弈、离线 RL 需要日志里已有倾向得分、多智能体 RL 需要可仿真的多主体环境）。判据 ① 与 ③ 讲的是前一类，判据 ② 讲的是后一类——**能拿出「别人在生产里用过」的材料，本身就是前提条件成立的证据**。

### 5.3 与本主题既有栈的接口在哪

RL 不是独立系统：它的输入来自奖励与环境两侧，输出交给决策与监控两侧。写清接口边界（谁调用谁、以什么形态穿过边界、失败时谁负责）比写「与 X 结合」有用。

| 结合点 | 接口形态 | 谁负责失败 | 现状 |
| --- | --- | --- | --- |
| 偏好数据管线 ↔ 对齐训练 | 交接物 = 偏好对 + **标注口径 + 采样来源版本** | 数据侧（采样分布与线上分布不一致，偏好分数就只对偏好集成立） | 需登记 |
| 奖励函数 / 判定器 ↔ 策略更新 | 以「标量奖励 + 奖励函数版本」为接口；奖励是被优化的规格，不是超参 | 拥有奖励函数的一侧（奖励被优化到失效是规格问题，不是训练问题） | 可做，须版本化 |
| 冻结参考模型 ↔ 策略 | 以「参考权重版本」为接口；换参考权重 = 换一整套 KL 基准 | 训练侧（参考权重不进登记，训练不可复现） | 常被忽略 |
| 训练环境 ↔ 评测基准 | **必须分离**：训练任务池与任何评测集零重叠，且逐批可举证 | 环境侧（重叠 = 评测失效，且不报错） | 需自建，本节最容易失守的一行 |
| 离线数据集 ↔ 策略 | 以「行为策略版本 + 倾向得分」为接口；缺任一项事后不可补 | 埋点 / 数据侧（缺倾向得分，离线训练根本不该启动） | 需自建 |
| 仿真器 ↔ 策略（仿真到现实） | 以「仿真与真实的差距」为接口；用域随机化替代精确建模 | 仿真侧（差距无法自查，只能靠真实环境的小流量对照） | 既有技术 |
| 检索层 ↔ 策略（检索策略优化） | 以「可回放的检索结果 + 奖励定义」为接口；不可回放即视为无法训练 | 检索侧（同一问句不同时间结果不同，信用分配失效） | 未定型 |
| RL 策略 ↔ 业务决策引擎 | 以「动作 + 置信度 + 策略版本 + 回滚开关」为接口 | 上线一侧（故障形态是整段策略持续走偏，不是单次决策错） | 未定型 |
| 策略 ↔ 监控 | 以「奖励代理指标 + 业务指标」双轨为接口；代理升而业务降即奖励被优化到失效 | 监控侧（只盯代理指标是默认做法，异常发现不了） | 需自建 |

这张表里只有一行算既有能力（仿真到现实的技术栈），其余都要新建登记或新建链路。**失败归属必须在设计阶段写清**，否则会退化成扯皮：业务指标掉了，是偏好数据换了来源、奖励函数被改了、环境与评测集重叠了、还是策略走到日志没覆盖的区域了？四件事都能解释同一个现象，而它们分属四个团队。

**判定这张表有没有被用起来**：每个季度核对三个数——有多少条训练任务能列出「本批任务不在评测集内」的举证，有多少条策略变更有奖励函数版本与参考权重版本记录，有多少条离线数据集记了倾向得分。三个数都是零，说明表还停在文档层面。

**第三方生产案例**

本节**未能给出**可核验的、含奖励口径与对照条件的第三方 RL 生产案例。原 §5.3 列出的企业落地百分比（eCPM、长期 GMV、调度效率、毛利、订单、风险损失各项提升）属建设方自述口径（样本、对照、奖励定义均在发布方手里），本节不转载。**这个空白本身是结论**：它直接决定了本主题下没有任何方向可以排成 L1。

**引用纪律**：本主题最容易被误引的三类数字是「任务成功率提升」「离线回报涨幅」「样本效率倍数」。可核验的做法是回到来源找四样东西——奖励函数是什么、环境是什么、评测集与训练任务是否重叠、对照条件是什么；缺一个就不要引用这个数。

**怎么用这份清单**：先看你要核的是「奖励从哪来」还是「环境从哪来」。前者的证据看训练框架文档与偏好/奖励相关论文（更新快、可核验性高）；后者的证据看评测环境的仓库与判定方式（更新慢，但一个能自动判定成败的环境抵十篇解读）。两类材料都不能替代判据 ②——它们证明的是机制存在，不是有人在生产里用它并承担了代价。

### 5.5 被过度宣传的部分

**「RL 已经取代监督微调」**——实际是位置变了，不是被取代。原因：偏好与可验证奖励优化的是**相对排序**，不是「从零教出格式与知识」——「好回答」写不成监督标签，写得出就直接做监督微调了，RL 拿到的是比较信号（[§3 §3.2.9](06-rl-section-3-sec3.md) 的「被什么约束逼出来」）；而策略要在一个巨大的动作空间里被采到有效回答，靠随机探索几乎命中不了，起点仍然是一个已经会说话的模型——这与 [§3 §3.2.9](06-rl-section-3-sec3.md) 的「真实使用」列出的 InstructGPT 公开报告一致：其公布的 RLHF 流水线以监督微调后的检查点为起点，而不是从随机初始化开始。**它什么时候才会成真**：出现不经过监督微调、从基座直接做 RL 的有效配方，并在多个任务上被独立复现——注意是复现，不是一次报告。

**「智能体任务成功率的提升可以直接外推到业务」**——实际是数字与「训练环境是什么」不可分割。原因：能自动判定成败的任务集合是稀缺资源，而评测集与训练任务池一旦重叠，指标会继续上升而泛化能力下降，两种变化都不触发告警（5.2.3 的示意块）。**它什么时候才会成真**：公开材料同时给出三样东西——训练任务池的构成、一个从未参与训练的留出集结果、每一步的成本；缺任一样，这个数字就不能拿来排路线图。

**「世界模型让 RL 不再需要真实交互」**——实际是减少真实交互，同时新增一个误差来源。原因：规划与想象 rollout 会主动访问模型没见过的区域，而在错误的模型里规划得越深，偏离真实世界越远（[§3 §3.2.4](06-rl-section-3-sec3.md) 的失效点）。**它什么时候才会成真**：公开材料给出「想象 rollout 深度与真实收益」的关系曲线，并显示这条曲线在业务所需的视野长度内仍在上升——只给一个点成绩说明不了这件事。

这三条有一个共同结构：**把「某一环的成本降了」说成「整条链路可以少一环」**。判断它们何时成真，看的是同一件事——新一代方案有没有自己的成本与口径，并且这个口径能与旧链路逐项对齐。

### 5.6 未来 3–5 年：可证伪的预测

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| RL 的主流形态会向「可自动判定的奖励」集中，但**只在能写出判定函数的任务上** | 公开技术报告里，RL 阶段的奖励来源描述从「偏好模型」转向「规则判定 / 执行结果」的比例上升 | 三年后主流技术报告仍以偏好模型为唯一奖励来源，判定型奖励没有成为通用做法 |
| 监督微调不会被取消，但它在配方里的**位置**会从终点变成起点 | 公开技术报告里出现「监督数据规模下降、RL 阶段变长」的配方描述 | 出现不经过监督微调的成功配方并在多个任务上被独立复现 |
| Agent 训练的瓶颈会从算法转到**环境的可验证性与可回滚性** | 公开材料里出现专门讨论「如何构造可回滚、与评测集分离的训练环境」的工作，而不只是算法对比 | 公开材料仍以成功率成绩为主，环境构造方法不被讨论 |
| 离线 RL 会先在有仿真或可回测闭环的场景稳定下来，而不是在无试错权的开放业务里 | 公开工程材料里出现「离线训练 + 影子评估 + 小流量接入」这一固定流程 | 公开材料仍只有离线训练的做法，影子评估环节不出现 |

四条都能被**公开文档与公开材料里的必备字段**证实或证伪，不需要内部数据：

- 第 1 条看技术报告里 RL 阶段的奖励来源描述，一到三年见分晓。
- 第 2 条看监督数据规模与 RL 阶段长度的相对变化，一到三年。
- 第 3 条看公开讨论的题目是算法还是环境，一到两年。
- 第 4 条看工程材料里有没有影子评估这一步，两到三年。

最值得先盯第 3 条：它是唯一一条**不依赖任何新算法**就能观察到的信号，而且它一旦做不到，其余三条给出的数字都没有可比性——训练任务与评测集重叠，任何跨期对比都不成立。

提醒一句：这四条问的都不是「哪个算法会更强」，而是「**判断依据会不会出现在公开材料里**」。前者无法证伪，后者可以逐条核对。

### 5.7 给架构师的行动建议

| 你的处境 | 现在就该做 | 一年内观察 | 明确不要做 |
| --- | --- | --- | --- |
| 想用偏好数据对齐一个模型 | 先把偏好数据的采样来源、参考权重版本、奖励函数版本登记齐（5.2.1） | 训练框架是否把这三项做成必填 | 不要只盯偏好胜率；不要用一套偏好集同时做训练与验收 |
| 任务能被规则判定（代码、数学、可执行检查） | 只在这类子任务上做可验证奖励的 PoC，并持续投入新任务而非重复刷旧任务（5.2.2） | 任务池的产出速度是否跟得上训练消耗 | 不要为判定不了的任务硬造代理判定器；不要在小任务池上长时间训练 |
| 想做 Agent 的任务成功率优化 | 先造一个与任何公开评测集零重叠、可回滚的训练环境，并保留逐批举证（5.2.3） | 是否有可复用的环境构造与举证规范 | 不要把评测集并入训练任务池；不要在不可回滚的环境上训练 |
| 不能在线试错（医疗 / 风控 / 定价） | 先查日志里有没有行为策略版本与倾向得分；没有就先补埋点，训练不要启动（5.2.4） | 埋点规范是否把倾向得分列为必填 | 不要用 on-policy 算法吃历史日志；不要在缺倾向得分时做离线训练 |
| 有可仿真环境（棋类 / 对战 / 调度仿真） | 先确认环境是否为零和或可分解，再决定 Self-Play 还是多智能体路线（5.2.4） | 仿真到真实的差距是否有量化方法 | 不要用仿真里的胜率当作业务指标；不要在智能体数到几十后再回头改架构 |
| 刚开始建 RL 能力 | 先把四样登记成资产：奖励函数版本、参考权重版本、行为策略版本、倾向得分（本节 §5.3） | 有多少条策略变更能追到奖励与环境版本 | 不要把建设方自述的百分比写进选型结论；不要跳过影子评估直接全量上线 |

「明确不要做」这一列的共用逻辑只有一句：**本节真正变了的只有「奖励从哪来」与「环境从哪来」，而数据必须由当前策略产生这笔账一寸没动**。所以预算应当投在奖励函数与环境的版本化、日志埋点、影子评估与回滚开关这四件确定性工程上；这四样没定下来之前，任何「RL 驱动的决策」上线都会把故障形态从「一次决策错」放大成「整段策略持续走偏」。

如果只能排一个顺序，按这条走：

1. **先立奖励与环境**：把奖励函数写成可版本化的规格，把环境做成可回滚、与评测集分离的形态。没有它，后面所有指标都不可比。
2. **再补日志**：行为策略版本与倾向得分进埋点。这一步决定你将来能不能用离线方法，而且**事后补不了**。
3. **然后上影子评估**：离线或仿真训练的策略先跑影子，比对预估与实际，差距随分布距离扩大就是信号。
4. **最后才谈全量接入与 Agent**：这两类都会改变链路的责任归属，回滚成本高于前三步。

最后一条提醒：本节所有「现在就能做」的动作都不需要新算法——奖励版本化、环境可回滚、倾向得分埋点、影子评估，全是流程与工程。这也解释了本节为什么没有 L1：真正成熟的那部分（偏好优化、PPO、离线算法族）不需要被宣传，而需要被宣传的那部分，还没有成熟到能被建设方之外的人核验。

### 5.8 小结

> 本节小结：AI 在本主题上**只改了一条机制**——奖励与环境这两样过去靠人工供给的东西变成了可以批量生产的：偏好把「写不出规格的目标」变成可学习的信号（5.2.1），规则判定器把奖励变成可自动产出的量（5.2.2），可验证的任务环境把试错场所变成可自动搭建的东西（5.2.3）。它**没有改变**的是两件事：数据必须由当前策略产生这笔 on-policy 的账（所以不能在线试错的场景仍只能用日志或仿真），以及代理目标会被优化到失效这条结构性风险（所以双轨监控与影子评估仍然是必需品）。本节没有一行达到 L1，最接近的六行——偏好对齐、可验证奖励训练、Agent RL、Self-Play、Offline RL、多智能体 RL——差的只有「第三方（非厂商）公开生产案例」这一条；所以现在该投的是奖励与环境版本化、倾向得分埋点、影子评估与回滚开关，而不是「Agent 自主决策」。
