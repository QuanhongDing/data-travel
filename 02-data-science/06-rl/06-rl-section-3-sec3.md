## 3. 设计模式与范式

### 3.1 先看约束：模式不是选择题，是约束的产物

一张「业务特征 → 推荐算法」表读起来像"按场景挑一个"。但 RL 的模式选择其实被一条约束推着走，而且这条约束几乎单独决定了一半答案：**样本从哪来，以及你能不能在那个环境里试错**。能在真实流量上试错的，才谈得上 on-policy 与在线探索；不能试错的，无论算法多先进，都只能用历史日志或仿真。模式 1–11 里，第 5（离线）、6（演示）、8（自博弈）、9（偏好对齐）四条的分野直接来自这一条；第 7（多智能体）来自另一条——决策主体的数量。

第二条约束是**决策是不是单步的**。单步（Bandit）与序列（MDP）不是"简单版"与"复杂版"的关系，而是两个不同的问题：Bandit 里今天的选择不改变明天的状态分布，所以它不需要 Q(s,a)，也不需要 Replay Buffer；一旦这个假设不成立（推荐、定价里其实常常不成立，见 3.2.1 的代价），就必须换成序列模型。

第三条是**奖励的形态**：稠密反馈、稀疏终局反馈、还是只有成对偏好。它决定了要不要做奖励塑形、要不要世界模型、以及是走 RLHF 还是 DPO 这条路线。奖励形态不是实现细节——12 条反模式里有四条（奖励拍脑袋、稀疏奖励直接训练、奖励黑客、奖励与业务目标不对齐）说的是同一件事：**奖励是这套系统的规格说明，不是超参**。

| 约束 | 它决定了什么 | 本主题下最容易被它推翻的直觉 |
| --- | --- | --- |
| 决策步数（单步 / 序列） | Bandit 还是完整 RL | 「先上 PPO」——单步问题里状态转移与价值网络是白付的复杂度 |
| 能否在线试错（试错代价） | 在线 RL / Offline RL / 模仿学习 | 「有历史日志就能训 RL」——日志的分布由旧策略决定，修正不到位就学偏 |
| 动作空间（离散 / 连续 / 文本） | DQN 类 / Actor-Critic / 序列生成 | 「连续动作离散化就行」——维度一高网格按维数指数增长 |
| 奖励形态（稠密 / 稀疏 / 只有偏好） | 奖励塑形 / 世界模型 / RLHF-DPO | 「没有奖励就设计一个」——设计出来的奖励会被优化到失效 |
| 环境能否仿真 | Model-Based 规划能不能用 | 「不学模型也能做」——样本效率的差距几乎全部来自这里 |
| 算力与样本预算 | on-policy 还是 off-policy；PPO 还是 GRPO | 「堆 GPU 就行」——on-policy 的数据需求随更新次数线性累积，不是并行度问题 |

### 3.2 模式逐个拆解（核心节）

以下 11 个小节覆盖全部模式 1–11。每个模式严格按「被什么约束逼出来 → 结构 → 为什么有效 → 代价 → 失效点 → 真实使用」写。

#### 3.2.1 模式 1：Bandit 起步（Bandit-First）

- **被什么约束逼出来**：决策是单步的——这次展示/出价不改变未来的状态分布，且可以在真实流量上小步试错。场景：单步决策、A/B 测试、推荐与广告粗排、动态定价。
- **结构**：

```sql
-- Bandit 只维护"每个 arm 的统计量"，不维护状态价值
CREATE TABLE bandit_arm_stat (
  arm_id STRING,   -- 广告计划 / 优惠券面额 / 定价档位
  n BIGINT, reward_sum DOUBLE, reward_sq_sum DOUBLE,   -- 次数、累计奖励、后验/方差
  updated_at TIMESTAMP
);
-- UCB：选 mean + c·sqrt(ln(N)/n) 最大者；Thompson：按后验采样
-- 没有 s→s'，所以不需要 Q(s,a)、Replay Buffer 与网络
```

- **为什么这样设计有效**：因为探索被写进了选择公式本身（置信上界或后验采样），探索成本变成可定价的一项，而不是靠 epsilon 随手拍；因为只需要统计量，它可以在线增量更新、无需训练循环与回放缓冲区，工程面上几乎没有"训练不稳定"这一类问题。
- **代价**：它假设本次选择不影响未来状态分布，这个假设在推荐与定价里并不总成立；它无法优化长期价值，要长期价值就得换成能做 off-policy 修正的序列模型；contextual bandit 的特征工程与一个监督模型同级，不是"轻量方案"。
- **失效点**：当 arm 数多、每个 arm 的流量小且它们之间的真实差距小时，「探索成本线性可算」会反转成「探索预算被长尾吃光」——因为区分两个 arm 所需样本量与差距平方成反比。【推算：要把 CTR 1.0% 与 1.2% 两个 arm 区分开，按两比例检验 n ≈ 2·(z_{α/2}+z_β)²·p̄(1−p̄)/Δ²，取 α=0.05、power=0.8（(1.96+0.84)²≈7.85）、p̄≈0.011、Δ=0.002 → n ≈ 2×7.85×0.011×0.989/0.000004 ≈ 4.3×10⁴，即每个 arm 约需 4 万次曝光；1000 个候选就是 4×10⁷ 量级曝光花在探索上】
- **真实使用**：UCB1 出自 Auer 等 2002 年的公开论文，Thompson Sampling 最早由 Thompson 在 1933 年提出、后被重新发现并成为常用基线【公开，1933/2002，可按题名核验】；本节 §3.3 决策表（旧编号 §3.2）把"单步决策 + 探索有限"列为 Bandit 的适用场景。

#### 3.2.2 模式 2：DQN / Value-Based

- **被什么约束逼出来**：动作离散且可枚举，决策是序列的（今天的动作改变明天的状态），而每一次环境交互都昂贵，因此必须让同一批交互被反复利用。约束是"动作数有限 + 采样昂贵"。
- **结构**：

```sql
-- Replay Buffer：把"经验"当成可反复读的表（off-policy 的前提）
CREATE TABLE rl_transition (
  run_id STRING, episode_id STRING, step_no INT,
  state ARRAY<DOUBLE>, action INT, reward DOUBLE, next_state ARRAY<DOUBLE>,
  done BOOLEAN, ts TIMESTAMP,
  behavior_policy_version STRING    -- 哪个策略产生的（off-policy 修正要用）
);
-- 循环：采样 batch → TD 目标 r + γ·max_a' Q_target(s',a') → 更新在线网络；每 C 步把在线网络同步给 target 网络，否则自举目标自己在动
```

- **为什么这样设计有效**：因为 TD 目标用 target 网络计算、训练样本从缓冲区随机采样，所以同一条经验可以被反复用于梯度更新（样本复用），而学习目标在一段时间内保持稳定——这两条正是把 Q-Learning 与深度网络接起来的前提。
- **代价**：Q 值通过 max 自举会系统性高估（Double / Dueling 等改进针对的就是它）；缓冲区内存随容量 × 状态维度增长，状态特征本身还要一套特征管道；它只能处理离散动作，连续动作要么离散化要么换算法。
- **失效点**：当动作空间变成连续或高维（出价金额、关节力矩）时，「离散动作下样本复用率高」会反转成「量化误差 + 网格爆炸」——因为离散网格的数量随动作维数指数增长，而每个格子都需要被访问到才可能学好；此时最优动作往往落在两个格子的中间，量化误差直接变成策略的性能上限。
- **真实使用**：DQN 出自 Mnih 等《Human-level control through deep reinforcement learning》，Nature 2015；论文披露训练规模约 5×10⁷ 帧，原文表述相当于约 38 天的游戏体验【公开，2015】。这与人类玩家数小时的练习形成对比，也正是"样本效率"成为 RL 工程第一约束的来源。

#### 3.2.3 模式 3：Policy Gradient / Actor-Critic

- **被什么约束逼出来**：动作连续、且随机性本身就是策略的一部分（探索来自策略分布而非额外扰动）。场景：机器人控制、自动驾驶、连续动作的推荐与定价。
- **结构**：

```text
on-policy 的一批数据用几次就作废：
  采一批 rollout → 算 GAE 优势 → 用 clip 限制的比例更新策略 → 数据丢弃 → 再采
  ┌───────────────┐         ┌──────────────────────────┐
  │ Actor πθ(a|s) │ ◄── 优势 ┤ Critic Vφ(s)（学出来的基线）│
  └───────────────┘         └──────────────────────────┘
  PPO 把新旧策略概率比 clip 在 [1-ε, 1+ε]：让"一次更新走多远"有上界
  → 同一批数据才敢反复用几个 epoch，这是它取代 TRPO 的工程原因
```

- **为什么这样设计有效**：因为梯度直接对策略参数求（主文件 §2.2 策略梯度定理），连续动作不需要 max over actions，也不需要离散化；因为 clip 限制了单次更新的步长，同一批 rollout 可以安全地复用 3–10 个 epoch【经验】，把 on-policy 的样本效率往上拉了一截——但只是一截。
- **代价**：数据用完即弃，样本效率是结构性成本，调参消不掉；要同时维护 Actor 与 Critic 两套网络、两套学习率与两套归一化；Critic 的估计误差会直接污染优势估计，进而污染梯度方向，所以"训练不稳"往往出在 Critic 而不是策略网络。
- **失效点**：当环境交互极其昂贵（真实用户、真实机器人）时，「稳定、通用、连续动作友好」会反转成「样本成本随更新次数线性累积」——因为每次更新都要新采一批数据，这批数据不能跨策略复用；这正是把 PPO 换成 off-policy（SAC）或离线方法的触发条件，判据是"一次更新用掉的数据量 vs 你能新采到的数据量"。
- **真实使用**：PPO 出自 Schulman 等 2017 年公开论文，此后成为工业界事实标准【公开，2017】；SAC 出自 Haarnoja 等 2018 年论文，把最大熵目标与 off-policy 学习结合【公开，2018】；OpenAI 用域随机化取代精确建模的机械手解魔方工作（2019）以大规模并行仿真为训练环境【公开，2019，可按标题核验】。

#### 3.2.4 模式 4：Model-Based RL

- **被什么约束逼出来**：真实交互的代价高到不可承受，而环境可以被仿真或可以被学出来（围棋规则完全已知，机器人可以在物理仿真里跑）。约束是"想让每一份真实数据换来更多决策改进"。
- **结构**：

```text
AlphaZero 式（规则已知）：把试错搬进搜索里
   自我博弈 ──► (s, π, z) ──► 策略/价值网络
        │                          │
        └──► MCTS：用网络的先验 π 与价值 v 作为搜索起点，
             模拟若干次后返回改进的 π（每步决策多花算力换棋力）
MuZero 式（规则未知）：不重建真实状态，只学预测网络（reward/value/policy），在隐空间里做 MCTS；真实交互只用来校准模型
```

- **为什么这样设计有效**：因为规划在每一步决策时额外消耗算力，同样的经验量能换来更好的策略——棋力提升里相当一部分来自搜索而不是网络拟合；因为模型生成的"想象数据"也被用于更新策略（Dyna 式循环），同样次数的真实交互可以产生更多梯度。
- **代价**：多了一个模型误差来源，而规划恰恰会主动去访问模型没见过的区域；规划本身消耗算力（每步搜索次数是推理成本的主要部分），因此不能直接用于毫秒级在线决策；需要可仿真的环境，这个前提在多数业务场景（用户行为）里并不成立。
- **失效点**：当环境无法仿真、且在线延迟预算在毫秒级时，「样本效率高」会反转成「模型误差被规划放大」——因为在错误的模型里规划得越深，偏离真实世界越远，误差随规划视野累积。判定方法：把模型预测的下一状态与真实下一状态逐层对比，误差随 rollout 步数单调上升的那一段长度，就是可规划的视野上限。
- **真实使用**：AlphaGo 的成果发表于 Nature 2016、AlphaZero 发表于 Science 2018、MuZero 发表于 Nature 2020【公开，2016/2018/2020】；DreamerV3（2023）是"世界模型 + 隐空间想象训练"方向的公开代表【公开，2023，可按标题核验】。

#### 3.2.5 模式 5：Offline RL

- **被什么约束逼出来**：不能在真实环境里试错（医疗、自动驾驶、部分推荐场景），但历史交互日志很丰富。约束是"有数据、没有试错权"。
- **结构**：

```sql
-- 离线数据集：能训出什么，取决于日志里记了什么
CREATE TABLE rl_offline_dataset (
  request_id STRING, ts TIMESTAMP, context ARRAY<DOUBLE>,
  action STRING, propensity DOUBLE,   -- 实际发生的动作；该动作在旧策略下的概率 ← 缺它就做不了修正
  reward DOUBLE,                      -- 隐式反馈要靠延迟归因
  behavior_policy_version STRING, logging_ok BOOLEAN
);
-- 反事实动作的奖励永远是 NULL：离线 RL 的根本约束，不是数据质量问题
```

- **为什么这样设计有效**：因为它把"试错"从真实环境搬到数据与仿真里，决策的在线代价被压到零；因为目标被设定为"在数据分布内找到更好的策略"，CQL 一类方法显式压低分布外动作的 Q 值（保守项），策略就不会跑到没有数据支撑的区域去。
- **代价**：分布漂移——策略一旦偏离产生日志的策略，Q 值就要在无数据区域外推，误差被自举放大（外推误差）；日志里没有反事实奖励，所有"如果当时选了别的会怎样"都靠假设与修正项；`propensity` 与行为策略版本必须在埋点时就记录，**事后无法补**，很多团队的历史日志因此根本不能用于离线 RL。
- **失效点**：当学到的策略与日志策略的分布距离变大时，「无需在线试错」会反转成「离线评估漂亮、上线即跌」——因为离线评估用的也是同一份数据，它看不见策略已经走进无数据支撑的区域；这个反转的触发条件不是训练轮数，而是**分布距离**。判定方法：上线前先跑影子评估，比较预估回报与实际回报，差距随分布距离扩大就是信号。
- **真实使用**：CQL（2020）、IQL（2021）、TD3+BC（2021）是公开的代表算法，离线 RL 的评测基准 D4RL 同样来自公开论文【公开，2020–2021，可按标题核验】。工业上公开可核验的成熟做法集中在有仿真或可离线回测的场景（推荐、广告、仿真控制）【经验】。

#### 3.2.6 模式 6：Inverse RL / Imitation Learning

- **被什么约束逼出来**：能说清"做得好"很难，但能拿到专家演示（人类驾驶数据、机器人遥操作演示）。约束是"奖励未知、示范已知"。
- **结构**：

```text
专家演示只有 (s, a)，没有 r：
  IRL ：求奖励 R 使专家轨迹回报高于其他轨迹 → 再用 R 跑 RL
  GAIL：跳过显式求 R，用判别器分辨"策略轨迹 vs 专家轨迹"，策略的奖励 = −log(1 − D(s,a)) ← 判别器就是学出来的奖励
  π(a|s) ──► 轨迹 ──► 判别器 D ──► 奖励 −log(1−D(s,a))   ◄── 专家演示（无奖励）
  BC（行为克隆）：直接监督学习 s→a，不做逆推——工程上先跑它，再决定要不要上 IRL
```

- **为什么这样设计有效**：因为奖励不再由人设计、而是从"专家会怎么做"里反推出来，绕开了奖励设计的难题；BC 的误差会随轨迹长度累积，而 IRL / GAIL 通过与环境交互修正分布偏移，缓解这条累积。
- **代价**：需要大量高质量演示，而演示数据的采集昂贵、覆盖窄（只覆盖专家到过的状态）；GAIL 引入对抗训练，继承判别器过强则策略无梯度、过弱则奖励无区分度的整套不稳定；学到的奖励不是唯一的——同一行为可被多个奖励解释，因此它不能当业务口径用。
- **失效点**：当部署环境与演示环境存在差异时，「无需设计奖励」会反转成「策略学到了演示里并不重要的细节」——因为 IRL 的奖励只在演示分布内可辨识；状态分布一偏移，策略就会去优化那些在演示数据里偶然与专家行为相关的特征（虚假相关），而这些特征在新环境里与"做得好"无关。
- **真实使用**：GAIL 出自 Ho & Ermon 2016 年论文，AIRL 出自 Fu 等 2017 年论文【公开，2016/2017，可按标题核验】；自动驾驶与机器人领域公开资料里常见"先行为克隆、再用 IRL / RL 微调"的路线【经验】。

#### 3.2.7 模式 7：Multi-Agent RL（MARL）

- **被什么约束逼出来**：决策主体多于一个，且每个主体的回报都依赖其他人的动作——环境对每个个体都是非平稳的。场景：游戏、交通调度、机器人协作。
- **结构**：

```text
集中训练、分散执行（CTDE）：
  训练期：汇总所有智能体的观测，学一个联合 Critic Q_tot(o1..on, a1..an)，
          并把它分解成个体价值 Q_tot = f(Q1(o1,a1), …, Qn(on,an))  ← QMIX 用单调混合
  执行期：agent i 只用本地观测，π_i(a_i | o_i)，没有中心协调
  核心难题：信用分配——团队奖励怎么分到每个个体；值分解就是它的答案
```

- **为什么这样设计有效**：因为训练期能拿到全局信息，每个智能体的价值估计能"看见"别人造成的非平稳性，训练从这里获得稳定；因为执行期不需要中心信息，策略可以真的部署到去中心的环境里——训练与执行的这种分工是 CTDE 的全部要点。
- **代价**：中心 Critic 的输入维度随智能体数增长（联合观测/动作空间按指数增长），可扩展性差；值分解要引入可分解的结构假设（如单调性），假设不成立时分解出的个体 Q 失去解释力；通信、信用分配、对手建模都是额外的设计面。
- **失效点**：当智能体数量从个位数升到几十上百时，「集中训练带来稳定」会反转成「联合空间爆炸使训练不可行」——因为中心 Critic 的输入是全体观测与动作的联合；同时每个智能体面对的环境因他人策略更新而持续变化，收敛保证随之消失，表现为奖励曲线长期震荡不上行。
- **真实使用**：MADDPG（Lowe 等 2017）、QMIX（Rashid 等 2018）、MAPPO（Yu 等 2022）是公开代表算法【公开，2017/2018/2022，可按标题核验】；公开可核验的工业形态集中在对抗游戏与交通/物流仿真【经验】。

#### 3.2.8 模式 8：Self-Play RL

- **被什么约束逼出来**：没有人类数据能达到目标水平（围棋、Dota、星际），而对手可以自己造出来。约束是"训练数据的上限由人类水平决定"。
- **结构**：

```text
单智能体自博弈：π vs π 的历史版本——简单，但容易互相适应一套怪招
种群 / 联盟结构（AlphaStar 式）：
  main agents（只与联盟内的对手交手）
  + main exploiters（专门找 main 的弱点）与 league exploiters（找全联盟的弱点）
  每个人只与联盟的一部分交手 → 策略空间被持续推开，
  不会收敛到一个"互相自适应"的局部最优
```

- **为什么这样设计有效**：因为对手水平随自己提高，课程是自动生成的，不需要人类数据就能持续获得"难度恰好"的训练信号；因为评估标准是"与联盟对抗的胜率"而不是"模仿人类动作的准确率"，它优化的是实际胜负而不是模仿得像不像。
- **代价**：训练成本高——要维护多个历史版本与多种角色，还要做联盟匹配与海量仿真对战；训练目标（胜率）与业务目标未必一致，迁移时要重新定义评估；不收敛是常态，能力必须用"对全联盟的胜率"来评估，单点胜率会误导。
- **失效点**：当只有单一自我对抗、没有种群时，「无需人类数据」会反转成「双方共同收敛到一个狭窄的局部最优」——因为两边都在适应彼此的固定套路，一旦遇到分布外对手（人类玩家的常规打法）就失效；这正是"局部最优（需要 population）"，判据是"对最新版本胜率上升、对历史版本集合胜率停滞"。
- **真实使用**：AlphaGo Zero 与 AlphaZero 的自我博弈训练在 Nature 2017 / Science 2018 公开【公开，2017/2018】；OpenAI Five 在 Dota 2 上用大规模自我博弈达到公开比赛水平（2018–2019 公开材料）【公开，2018/2019，可按标题核验】；AlphaStar 用联盟式训练在《星际争霸 II》达到宗师段位，成果发表于 Nature 2019【公开，2019】。

#### 3.2.9 模式 9：RL for LLM（RLHF / DPO / GRPO）

- **被什么约束逼出来**：想让模型对齐人类偏好，但"好回答"写不成监督标签（写得出就直接监督微调了），只能拿到成对偏好；同时这条链路的显存是硬约束。场景：对话模型与人类偏好对齐。
- **结构**：

```text
PPO（RLHF）：policy（可训）+ reference（冻结，算 KL）+ reward model（冻结，打分）+ critic（可训，估 V(s)）——四个模型同时驻留
DPO：去掉 reward model 与 critic，policy + reference 直接在偏好对上做对比损失
GRPO：去掉 critic，用"同一 prompt 采一组回答"的组内相对得分当优势
  显存账（【推算】）：7B 模型 bf16 权重约 14 GB（7×10^9 × 2 B = 1.4×10^10 B）；
  PPO 四份权重 ≈ 56 GB，其中两份可训练模型还要各存 Adam 的一阶/二阶动量
  （fp32 约 8 B/参数 → 7B 约 56 GB/模型）→ 单机常常放不下；GRPO 去掉 critic，直接省掉一份 14 GB 权重与一份优化器状态
```

- **为什么这样设计有效**：因为偏好只给出"哪个更好"，DPO 把它直接写成一个可微的对比损失，省掉了"先训奖励模型再用 RL 优化"的两段式流程，也移除了奖励模型被刷分这一环；因为 GRPO 用组内相对得分替代 Critic，优势估计不再需要一个与策略同规模的价值网络，显存与训练复杂度同时下降。
- **代价**：DPO 省掉了在线采样，也就失去了"训练中持续用新数据检验"的能力，对偏好数据的分布更敏感；GRPO 的组内比较要求同一 prompt 采多个回答，推理开销转嫁到采样上；无论哪条路线，KL 约束都要常驻一份 reference 权重——"对齐训练不是微调"的实际成本就在这里。
- **失效点**：当偏好数据与线上真实分布不一致时，「对齐人类偏好」会反转成「优化出一套只在偏好集上讨喜、在真实任务上更差的行为」——因为偏好分数是代理目标，模型会向其中"可被优化的那部分"集中（奖励黑客的一种）；表现为偏好胜率上升而真实任务成功率下降，且两者都不报错。
- **真实使用**：RLHF 出自 Christiano 等 2017 年论文；InstructGPT 的公开报告（2022）给出 RLHF 用于对齐的完整流程与人工评估【公开，2017/2022】；DPO 出自 Rafailov 等 2023 年论文；GRPO 出自 DeepSeek 的公开工作（DeepSeekMath，2024；推理模型 DeepSeek-R1 的公开报告，2025）【公开，2023–2025，可按题名核验】。ChatGPT、Claude、Gemini 等对话模型是本模式的适用对象；各家公布的对齐流水线与其中使用的具体算法并不相同，需要对号入座时请以各家的官方技术报告为准。

#### 3.2.10 模式 10：Agent RL（Tool Use / Multi-Step Reasoning）

- **被什么约束逼出来**：任务是长链条的，每一步的动作是"调用工具"（离散、开放集、由模型生成），而奖励只在任务终局给出。约束是"奖励稀疏 + 动作是生成出来的文本"。
- **结构**：

```sql
-- 训练的原子单位是一条"状态-动作-观测"序列，不是一次问答
CREATE TABLE agent_trajectory (
  task_id STRING, step_no INT,
  obs STRING,          -- 页面结构摘要 / 报错信息 / 命令输出
  action_type STRING, action_arg STRING, tool_result STRING,  -- click / type / shell / read_file / finish
  terminal BOOLEAN, success BOOLEAN,   -- 终局标记；稀疏奖励只在 terminal 为真时有值
  token_cost INT       -- 每步动作本身是一次生成，成本随步数叠加
);
```

- **为什么这样设计有效**：因为动作空间是"生成一段文本"，它天然适合策略梯度类的序列生成方法（与主文件 §2.3 的 LLM RL 系列是同一套工具）；因为奖励可以被规则自动验证（测试是否通过、答案是否匹配），训练信号可以大规模自动产出，不必依赖人工标注——这是 2024 年以后 Agent RL 能规模化的关键。
- **代价**：一条轨迹可能几十步、每步都要模型生成，采样成本随步数线性甚至超线性上升；终局二值奖励要分摊到几十个中间动作上，信用分配距离长；工具环境必须可回滚、可沙盒，否则训练会污染真实系统。
- **失效点**：当任务步数变长而奖励密度不变时，「可自动验证带来规模化」会反转成「梯度信号被方差淹没」——因为终局奖励要分到更多步上，回报方差随步数增长，同样训练步数提供的有效信息随之下降；这也是把奖励做细（过程奖励、中间检查点）或改用分步可验证奖励的触发条件。
- **真实使用**：WebArena（2023）与 SWE-bench（2023）是公开的多步 Agent 评测环境，任务来自真实网站与真实 GitHub 仓库，并提供可自动判定的成败信号【公开，2023，可按标题核验】；用大规模 RL 训练长链推理是 OpenAI 在 o1/o3 公开材料里描述的方向【公开，2024】。

#### 3.2.11 模式 11：Hierarchical RL

- **被什么约束逼出来**：奖励稀疏而任务时间长，单个动作对最终奖励的影响被稀释到无法学习。场景：长期任务、稀疏奖励。
- **结构**：

```text
分层策略：高层在慢时间尺度上选子目标，低层在快尺度上执行
  高层 π_high(z | s)     每 k 步决策一次 → 输出子目标 z（区域 / 中间态 / 子任务）
      │
  低层 π_low(a | s, z)   每步决策 → 目标是把 z 达成或维持
  options 框架：一个 option = (子策略, 终止条件)，可当作"宏动作"接进标准 RL——做的是时间抽象，不是网络结构
  工程上常见的简化：手工分阶段（课程学习），往往比学出来的两层策略更可控
```

- **为什么这样设计有效**：因为决策被分层，高层看到的"一步"跨越了很多原始步，稀疏奖励在高层被压缩成"选哪个子目标"这个更密的决策问题；低层只在短暂、目标明确的分段内学习，信用分配的距离因此变短。
- **代价**：子目标空间与时间尺度 k 都是先验，选错则低层不可达或高层失去意义；两层联合训练会互相掩盖问题（高层失败可能是低层没做到，反之亦然），调试成本高于单层；终止条件学不好会出现子目标被无限维持。
- **失效点**：当子目标无法被有意义地定义时（"提升用户满意度"这类不可直接测量的中间量），「分而治之」会反转成「两层都在优化一个与最终目标无关的中间量」——因为高层优化的 z 与真实目标之间的相关性从未被保证，低层越是把 z 完成得漂亮，偏差越大；此时退化成手工分阶段反而更可靠。
- **真实使用**：时间抽象（options）框架出自 Sutton、Precup 与 Singh 1999 年论文，FeUdal Networks（2017）给出可学习分层的公开实现【公开，1999/2017，可按标题核验】；工业上更常见的是课程学习 + 分阶段奖励这类"手工分层"【经验】。

### 3.3 模式选择决策表

| 约束组合 | 推荐模式 | 为什么不选另一个 | 关键判据 |
| --- | --- | --- | --- |
| 单步决策、探索有限 | Multi-Armed Bandit / UCB / Thompson Sampling | 不用序列 RL：单步问题里状态转移与价值网络是白付的复杂度 | 选择是否改变未来状态分布 |
| 单步 + 有上下文特征 | Contextual Bandit / Neural Bandit | 不用完整 MDP：上下文只影响本次回报 | 是否有可用的场景/用户特征 |
| 离散动作 + 序列决策 + 可在线试错 | DQN / Rainbow DQN | 不用策略梯度：小离散动作空间下 value-based 的样本复用更高 | 动作数是否在千级以内【经验】 |
| 连续 / 高维动作 | DDPG / TD3 / SAC | 不用 DQN：离散化带来量化误差且网格按维数指数增长 | 动作维度是否超过 3【经验】 |
| 通用、要稳、能采数据 | PPO / A3C（+ 域随机化） | 不用 SAC：off-policy 对重放数据质量与冷启动更敏感 | 能否在可控流量/仿真上采样 |
| 围棋 / 棋牌 / 规则可仿真 | AlphaZero / MuZero | 不用纯 PPO：规则可仿真时规划能白拿一部分棋力 | 环境能否被仿真或学出模型 |
| 安全敏感 + 只有历史日志 | CQL / IQL / TD3+BC | 不用 PPO：on-policy 的数据必须由当前策略产生 | 日志里是否记了 propensity |
| 有人类演示数据 | GAIL / AIRL / IRL（先跑 BC） | 不用从零 RL：演示给了先验，从零探索代价高 | 是否拿得到专家轨迹 |
| 多智能体协同 / 竞争 | MADDPG / MAPPO / QMIX | 不用独立单智能体：每个个体的环境都非平稳 | 智能体数量是否在 10 以内【经验】 |
| LLM 偏好对齐 | PPO(RLHF) / DPO / GRPO | 不用监督微调：只有成对偏好，没有标准答案 | 奖励是偏好对还是可验证信号 |
| Agent 多步决策 | PPO / REINFORCE + WebArena / SWE-bench 式可验证奖励 | 不用 DPO：偏好数据覆盖不了长链条的中间步骤 | 成败能否被规则自动判定 |
| 稀疏奖励 + 长任务 | Hierarchical RL / Curiosity-Driven | 不用扁平策略：信用分配距离过长，信号被方差淹没 | 任务能否分解出子目标 |
| 仿真到现实的迁移 | PPO / SAC + Domain Randomization | 不用精确建模：建模误差是主要误差来源 | 是否有可大规模并行的仿真器 |
| 推荐 / 广告（长期价值） | Deep RL + Off-Policy Correction | 不用 Bandit：它无法优化长期价值 | 延迟反馈是否有观测窗口 |
| 动态定价 | Contextual Bandit / PPO | 不用静态定价模型：定价本质是反事实决策 | 价格改动能否做小流量试验 |

表里最常被误选的一对是**模式 3 与模式 5**：在"不能在线试错"的场景里，团队仍拿 PPO / DQN 去吃历史日志。后果按 3.2.5 的机制就是外推误差——Q 值在日志没覆盖的动作上被自举放大，离线评估指标随训练上升、上线后指标下跌。判断只差一句话：**这批数据是由当前策略采出来的吗**？不是，就不该用 on-policy 算法。

### 3.4 组合模式：真实系统不会只用一种

**组合一：Bandit 冷启动 + Offline RL 预热 + 受限在线微调（推荐 / 广告）**

- 组合构成：Bandit 负责长尾 arm 的探索与数据采集，Offline RL 在有 propensity 的日志上学一版初始策略，在线阶段只放开小流量做微调与影子评估。
- 职责边界：Bandit 管"哪些动作还没被探索过"，Offline RL 管"在已有分布内把策略改好"，在线阶段只负责验证与小幅修正，不负责学习一个全新策略。
- 运维代价：三条链路各有一套评估口径；日志必须记录行为策略版本与 propensity，否则离线这一段直接不成立；在线阶段的流量分配本身就是一次持续的实验设计。
- 适合规模：候选动作数百到数万、日请求量足够支撑分层试验的线上系统【经验】。

**组合二：行为克隆（BC / SFT）→ Offline RL（CQL / IQL）→ 受限在线 RL（机器人 / 自动驾驶）**

- 组合构成：BC 先把策略拉进有效动作区域，Offline RL 在演示 + 日志上做保守改进，最后只在受控条件下放开在线微调。
- 职责边界：BC 解决"策略能不能动起来"，离线 RL 解决"在数据分布内能不能更好"，在线阶段解决"分布漂移带来的最后一段差距"。
- 运维代价：三阶段都要有各自的验收标准与回滚点；仿真到现实的迁移需要域随机化与真机安全限制（限速、保护区）；任何一段跳过都会以"上线后不可解释的失效"形式暴露。
- 适合规模：试错代价高、但可以大规模并行的仿真环境 + 少量真机/真车验证通道【经验】。

**组合三：Self-Play 生成数据 + Model-Based 规划 + 可验证奖励（规则明确的任务）**

- 组合构成：自我博弈或种群对抗持续产生"难度递增"的训练数据，世界模型/MCTS 在决策时额外花算力，奖励由规则验证器给出（胜负、测试是否通过）。
- 职责边界：自博弈负责数据供给，规划负责单步决策质量，验证器负责奖励的客观性——三者中奖励最难做假，所以它必须是可自动判定的。
- 运维代价：需要大量并行仿真与一套联盟/对手池管理；规划的推理延迟限制了能上线的场景；验证器本身要被审计，否则会出现"优化验证器而不是优化任务"。
- 适合规模：任务规则明确、成败可自动判定、且能承受高推理延迟的场景（棋类、代码修复、工具调用）【经验】。

### 3.5 反模式与失效分析

| 反模式 | 症状（怎么发现它） | 后果（机制层面的后果） | 成因 | 修法 |
| --- | --- | --- | --- | --- |
| **1 奖励函数拍脑袋** | 奖励栏写着"点击 +1 / 跳出 −1"，没有与业务量的映射说明 | 策略向奖励里可优化的那部分集中，出现点击诱饵；奖励与业务量之间从未被验证过 | 奖励看起来只是加一项，而把业务目标翻译成奖励需要业务方参与 | 奖励工程按规格说明对待：先写清业务量、再写奖励、上线前做敏感性分析 |
| **2 稀疏奖励直接训练** | 训练曲线长期贴地，成功率与随机策略无差别 | 终局二值奖励分摊到整条轨迹，方差淹没有效梯度 | 任务天然只有成败，团队以为"多训就好" | 奖励塑形（课程学习 / HER / Curiosity）或分层（3.2.11） |
| **3 On-Policy 用历史数据** | 训练代码在 PPO 里挂了 Replay Buffer 装几天前的日志 | 数据分布与当前策略不匹配，优势估计系统性偏；训练不稳定且不收敛 | "数据越多越好"的直觉，加上已有日志现成可用 | on-policy 只用当前策略采样；要用历史数据就换 off-policy 或离线算法 |
| **4 忽略探索** | ε 被调成 0 或策略熵快速塌到接近确定 | 策略锁死在早期偶然找到的局部最优，且此后再也拿不到改出它的数据 | 线上指标压力下把探索当成本砍掉 | 保底探索率 / 熵正则 / Thompson 采样；把探索写进流量预算 |
| **5 离线 RL 用 on-policy 算法** | 用 PPO 直接吃离线数据集，训练集回报上升但评估集不动 | 外推误差被自举放大，策略走到无数据区域，离线评估看不见 | 混淆了"能读出数据"与"数据可用"两件事 | 离线场景用 CQL / IQL / TD3+BC，或先做 Off-Policy Correction |
| **6 奖励黑客** | 出现卡死不动、无意义长回答、只做最便宜的达成动作等"高奖励低价值"行为 | 策略找到了奖励函数的结构漏洞，代理指标与真实目标分离且差距扩大 | 奖励是有限写的，而优化是无限的——漏洞一定会被找到 | 多目标约束 + 对手式测试（专门找漏洞）+ 人工抽检异常高分轨迹 |
| **7 训练不稳定** | 换随机种子结果差异巨大，同配置两次跑不出同一个数 | 无法归因，超参搜索变成赌博；上线决策缺少可信依据 | RL 的方差来自采样、自举与探索三层叠加，单次实验没有统计效力 | 多随机种子 + 报告均值与方差；固定评估环境与评估集；学习率与优势归一化 |
| **8 直接上线不验证** | 只有离线指标，没有影子模式与灰度，直接切全量流量 | 第一次真实反馈就是事故，且探索期的损失直接由真实用户承担 | 离线指标好看就以为可上线，而离线评估看不见分布外的错误 | 影子模式 → 小流量灰度 → 分阶段放量，每阶段设止损线 |
| **9 样本效率低盲目上 GPU** | 交互次数已经是百万量级仍不收敛，投入的是更多机器而不是换算法 | on-policy 的数据需求随更新次数增长，加并行度只加快"采集同样的数据"，不改变所需数据总量 | 把样本效率问题当成了算力问题 | 换 Model-Based / Offline / 模仿学习；或先做行为克隆拿到可用基线 |
| **10 奖励与业务目标不对齐** | 优化的是点击，业务要的是 GMV；两套指标方向相反 | 代理目标被优化到极致，业务指标反而下降，且归因困难 | 业务目标难以拆成逐步奖励，于是用了最近的可测量替代 | 奖励必须与业务 KPI 有可验证的映射；上线后用真实业务量做回归 |
| **11 LLM RLHF 用 PPO 训练 LLM 不稳定** | 训练中 KL 与奖励忽然发散，语言质量塌陷 | 四模型链路的显存与方差同时压顶，一次发散就浪费一轮训练 | PPO 是通用 RL 默认解，直接迁移到 LLM 场景 | 用 DPO / GRPO 等更稳的路线；保留 reference 与 KL 约束、分阶段放大规模 |
| **12 多智能体 = 简单堆叠** | 把 n 个单智能体策略并起来跑，各自还用自己的奖励 | 环境非平稳且奖励互相抵消，训练震荡、信用无法分配 | 以为"多智能体"只是数量问题 | 用 CTDE + 值分解（MAPPO / QMIX / MADDPG），显式处理信用分配 |

最危险的三条是 **6、5、8**，它们的共同点是**离线指标看不出问题**。

**6 奖励黑客**在生产中的典型暴露方式是"指标涨了但业务方不认":报表全线向上，客服与退款却在增加。它的机制决定了不能靠调参修复——只要奖励函数有漏洞，优化过程一定会找到它，因此修法是加对手式测试与人工抽检，而不是把奖励权重再调一调。

**5 离线 RL 用 on-policy 算法**的暴露方式是一次"训练集回报漂亮、上线首日就跌"的切换。定位方法不是看算法，而是看日志里有没有 `propensity` 与行为策略版本——没有这两个字段，任何离线训练都缺了修正所需的信息。

**8 直接上线不验证**的暴露方式最直接：第一次探索的代价由真实用户付。它的危险在于"离线评估 + 一个小流量试验"的成本极低，而省掉它的收益看起来也很小，于是最容易被跳过——直到一次事故把两者的成本差摆出来。

### 3.6 规模跃迁时模式何时该换

| 跃迁 | 原模式 | 为什么开始疼 | 换成 | 迁移的代价 |
| --- | --- | --- | --- | --- |
| 从单步决策到序列决策 | Bandit（模式 1） | 选择开始影响未来状态分布，单步回报不再等于长期回报 | PPO / SAC / DQN（模式 2、3） | 需要状态特征、重放或 rollout 管道；评估口径从单次回报变成累积回报 |
| 动作从离散到连续/高维 | DQN（模式 2） | 离散网格按维数指数增长，量化误差成为性能上限 | DDPG / TD3 / SAC（模式 3） | Critic 与策略两套网络；训练不稳定的调试成本 |
| 从可在线试错到不能试错 | 在线 RL（模式 3） | 一次错误的真实动作不可回滚；探索预算等于业务损失 | Offline RL（模式 5）+ 影子评估 | 日志必须补 propensity 与行为策略版本（事后无法补）；评估方法要重做 |
| 从单智能体到多智能体 | 单智能体 PPO | 每个个体的环境因他人策略更新而持续变化 | CTDE：MAPPO / QMIX / MADDPG（模式 7） | 中心 Critic 的联合空间随人数膨胀；信用分配机制要新建 |
| 人类数据达到上限 | 模仿学习 / 人类数据（模式 6） | 数据质量的上限就是人类水平，无法再涨 | Self-Play + population（模式 8） | 要维护历史版本与联盟、评估改为对全联盟胜率 |
| 任务从单轮偏好对齐到多步工具调用 | DPO / PPO(RLHF)（模式 9） | 偏好数据覆盖不了长链条中间步骤，信用分配距离过长 | Agent RL + 可验证奖励（模式 10） | 需要可沙盒、可回滚的工具环境；采样成本随步数上升 |
| 显存成为硬约束 | PPO + Critic（模式 9） | 四个模型同时驻留，单机放不下，只能拆得很碎 | GRPO 等去 Critic 的路线（模式 9） | 优势估计改为组内相对得分；采样成本转嫁到同一 prompt 的多次生成 |

这张表里最容易被低估的是**第三行**：从在线切到离线看起来只是"换个算法"，实际代价是**数据本身要重建**——`propensity` 与行为策略版本没在埋点时就记录，历史日志是不可逆地不可用的。判断时机不是等出事故，而是第一次出现"这次试验不能做"的需求时。

### 3.7 自检清单

- [ ] 奖励函数的每一项都能对应到某个业务量吗？对应不上的项，上线后一定会被优化出副作用。
- [ ] 奖励里是否存在"永远不为负"或"不做动作也不亏"的构造？那是奖励黑客的入口。
- [ ] 训练数据是由当前策略采的吗？不是，就不该用 on-policy 算法。
- [ ] 日志里是否记录了 `propensity` 与行为策略版本？没有，离线路线现在就不能启动。
- [ ] 探索率 / 熵是否被监控？塌到接近 0 而没有人为决策，说明探索被指标压力悄悄砍掉了。
- [ ] 离线评估集与训练集是否分离，且评估集是否覆盖了历史策略的分布？
- [ ] 是否有至少 3 个随机种子的结果？单次实验在 RL 里没有统计效力。
- [ ] 上线路径是否包含影子模式与小流量灰度，且每阶段有止损线？
- [ ] 若用 DPO / GRPO，是否有与 reference 模型的 KL 约束，且 reference 的显存是否算进预算？
- [ ] 若环境可仿真，是否实测过"模型误差随规划步数上升"的曲线？上升越快，可规划的视野越短。
- [ ] 若是多智能体：信用分配机制是什么？回答不出，就还是简单堆叠。
- [ ] 若是自博弈：能力评估用的是"对全联盟胜率"还是"对最新版本胜率"？后者会掩盖局部最优。

### 3.8 小结

| 你的约束 | 建议模式 | 关键理由（机制层面） |
| --- | --- | --- |
| 单步决策、可在真实流量试错 | Bandit（UCB / Thompson） | 无需状态转移与价值网络，探索成本可显式计算 |
| 离散动作、序列决策、可在线采样 | DQN / Rainbow | 缓冲区让同一批经验反复产生梯度，样本复用率高 |
| 连续动作、通用稳定 | PPO / SAC | 直接对策略求梯度，连续动作无需离散化 |
| 环境可仿真、要样本效率 | Model-Based + MCTS | 每步决策额外花算力，同量经验换更好策略 |
| 不能在线试错 | Offline RL（CQL / IQL） | 保守项压制分布外高估，策略不跑到无数据区域 |
| 有专家演示 | BC → GAIL / IRL | 先克隆进有效区域，再学奖励修正分布偏移 |
| 多主体、回报互相依赖 | CTDE + 值分解 | 训练期用全局信息，执行期只用本地观测 |
| 人类数据到顶 | Self-Play + population | 课程自动生成，避免双方共同收敛到局部最优 |
| 显存与偏好数据约束 | DPO / GRPO | 去掉奖励模型或 Critic，减少常驻模型数与方差来源 |

> 本节小结：本主题下决定模式选择的唯一那条约束，是**"样本从哪来、能不能在出错的地方试错"**。能在线试错，才谈得上探索与 on-policy；不能试错，就只能用历史日志（要求日志带有 propensity）或仿真（要求环境可仿真）；而奖励的形态决定了这条链路是走奖励塑形、世界模型还是偏好对齐。先回答这一个问题，11 个模式里有一半会自动排除掉。
