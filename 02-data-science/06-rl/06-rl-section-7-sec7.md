## 7. 与其他方法对比

### 7.1 先立判据：为什么打分表会误导

把 Bandit / DQN / PPO / SAC / Offline RL / Inverse RL 放进同一张 1–5 分表，用「简单性 / 离散动作 / 连续动作 / 样本效率 / 安全性 / 可解释性 / 工业成熟度 / LLM 训练适配 / 多智能体」九个维度打分。这个做法有三个结构性错误。

**错误一：这六列不是同一层的选项。** Bandit 与 DQN 是**算法族**（策略用什么表示），PPO 与 SAC 是**策略更新与数据使用方式**（on-policy 还是 off-policy），Offline RL 是**数据来源约束**（不能在线试错），Inverse RL 是**奖励从哪里来**（从演示反推）。给一个算法族、一条数据来源约束、一条奖励来源各打一张分表，等价于比较「汽车 / 限速规则 / 油价补贴」谁更好——它们在真实系统里是**同时成立**的约束，不是**二选一**的选项。

**错误二：「样本效率」这一维在 RL 里没有绝对刻度。** Offline RL 的样本效率打分高，不是因为它的算法更聪明，而是因为**它根本不需要采**——它是「有历史日志、没有试错权」这条约束的产物。同理 DQN 的样本效率打分低，来自它必须与环境交互产生数据；一旦允许离线复用，同一族的价值类方法样本效率立刻上一个台阶。**把「约束不同」记成「能力不同」，是打分表最典型的失真。**

**错误三：「安全性 5 分」的符号取决于场景。** 给 Offline RL 打 5 分、给 PPO 打 2 分，隐含判据是「不试错更安全」。在日志已经覆盖了你要的动作区域的场景里，这是对的；但在**必须发现日志里没有的新动作**的场景里（新市场的定价档位、新工具链的 Agent 调用），那 5 分恰好意味着**学不到任何日志外的策略**，它是一张减分项。同一个数值在不同场景里符号相反——这正是打分表的症状：它把「取决于场景的结论」伪装成「绝对结论」。

打分表输出的是**名次**；选型要回答的是「**在我掌握的试错权、动作空间与奖励形态的约束下，下一步该用哪一族方法，以及它在什么条件下失效**」。

**本章采用的 6 条判据**（已针对 RL 主题具体化）：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| 试错权 | 这次决策做错，代价由谁付、能不能回滚 | 它给全部候选划出「在线 / 离线 / 仿真」三条分界线，并直接决定探索预算的上限（见 7.3.1） |
| 决策步数 | 本次选择是否改变未来的状态分布 | 单步与序列是两类问题：单步不需要 $Q(s,a)$、缓冲区与价值网络，多出来的都是白付的复杂度 |
| 动作空间形态 | 离散可枚举 / 连续高维 / 自由文本 | 决定策略怎么表达：对离散动作取 max、对连续动作求梯度、对文本逐 token 生成（见 7.3.2） |
| 奖励形态 | 每步可测 / 只在终局 / 只有成对偏好 / 可被规则判定 | 决定要不要奖励模型、Critic 或验证器，也决定信用分配的距离（见 7.3.3） |
| 推理延迟预算 | 单步决策允许花多少时间 | 决定能不能在决策时刻额外搜索——即能否用推理算力换样本（见 7.3.4） |
| 样本与算力预算 | 你能采多少次交互、能同时养几个模型 | on-policy 的数据需求随更新次数累积，常驻模型数决定显存，两者都是成本函数的主项（见 7.4） |

九个维度一个未丢，只是位置变了：**简单性** → 判据 2 与判据 3（单步、离散各去掉一半复杂度）；**离散动作 / 连续动作** → 判据 3；**样本效率** → 判据 1；**安全性** → 判据 1（离线族的「安全」就是「不试错」，代价是不会发现新动作）；**可解释性** → 判据 4（奖励从哪来决定了结论能被复核到什么粒度，见 7.3.3）；**工业成熟度 / LLM 训练适配** → 7.2 的族划分与 7.6 的选型矩阵；**多智能体** → 7.2 里一个独立的族。

### 7.2 候选方案全景

| 族 | 代表方法 | 定位 | 核心机制（一句话） | 典型使用者 | 依赖 / 许可 |
| --- | --- | --- | --- | --- | --- |
| Bandit 族 | Multi-Armed Bandit、UCB、Thompson Sampling、Contextual / Linear / Neural Bandit | 单步决策 | 只维护每个动作的统计量，探索写进选择公式 | 广告粗排、券面额、定价档位 | 无需训练框架；统计量存储即可 |
| Value-Based 族 | Q-Learning、SARSA、DQN、Double / Dueling DQN、Rainbow DQN | 离散动作的序列决策 | 学 $Q(s,a)$ 后取 max，靠 Replay Buffer 复用经验 | 离散动作的游戏、调度 | PyTorch 一类框架 + 缓冲区 |
| Actor-Critic 族 | REINFORCE、TRPO、A3C、**PPO**、DDPG、TD3、**SAC** | 连续/高维动作、通用 | 直接对策略求梯度，用 Critic 当基线；PPO 用 clip 限制单次更新幅度 | 机器人、自动驾驶、连续定价 | 需同时维护 Actor 与 Critic |
| 离线族（Offline RL） | BC、CQL、IQL、TD3+BC、ReBRAC | 有日志、无试错权 | 对分布外动作做保守压制，策略不跑到无数据区域 | 医疗、推荐、政策评估 | 日志须带 propensity 与行为策略版本 |
| 模仿与逆 RL 族（Inverse RL） | BC、GAIL、AIRL | 有专家演示、奖励写不出 | 先克隆进有效动作区，再学一个奖励把分布偏移纠正回来 | 机器人示教、NPC 行为 | 需要专家轨迹 |
| 偏好对齐族 | RLHF（PPO + 奖励模型）、RLAIF、DPO、IPO、KTO、GRPO、PRM | LLM 与人类偏好对齐 | 把「哪个输出更好」变成可优化目标；GRPO 用组内相对得分替代 Critic | LLM 后训练 | 偏好数据 + reference 模型 |
| 多智能体族（MARL） | MADDPG、QMIX、MAPPO、MAVEN | 多主体协同/竞争 | 训练期用全局信息，执行期只用本地观测（CTDE） | 交通调度、对抗策略、Agent 协同 | 需要联合模拟环境 |
| 规划与世界模型族 | Dyna-Q、MCTS、AlphaZero、MuZero、DreamerV3 | 环境可仿真或可学 | 决策时多做几次模拟，用推理算力换样本 | 棋类、博弈、机器人控制 | 需要仿真器或可学模型 |
| 自博弈族 | Self-Play、Population-Based Training、PSRO、AlphaStar、OpenAI Five | 对手即环境 | 让对手持续变强，自动生成难度递增的数据 | 棋牌、RTS、对抗策略 | 大规模并行仿真 |
| 可验证奖励 / Agent RL | 在线 RL + 规则验证器（WebArena / SWE-bench 式任务） | 多步工具调用 | 奖励由规则判定，不依赖人工偏好 | 代码修复、工具调用、网页任务 | 可沙盒、可回滚的执行环境 |

这十族其实是被三刀判据切出来的。第一刀按**试错权**切：能在线试错的（Bandit、Value-Based、Actor-Critic、偏好对齐、多智能体、自博弈、可验证奖励 / Agent RL）、不能试错但可仿真的（规划与世界模型）、不能试错也没仿真的（离线、模仿与逆 RL）；第二刀按**奖励形态**切：奖励可测的、只有偏好的、可被规则判定的；第三刀按**动作空间**切：离散可枚举的、连续高维的、自由文本的。**先切前两刀再选，能省掉一半比较**——这些候选跨在这三刀的不同侧，所以它们的关系是「不同条件下各自成立」，而不是「同一条件下的优劣排序」。

**上表只列机制，不断言「某方法在某个版本里是否支持某特性」**：RL 实现迭代很快，写死会产生过期断言。凡涉及具体能力，用下面三种判定方法自查：

- **某个算法在你的场景里是否可用**：先量「这批数据是由当前策略采出来的吗」。不是，就不该用 on-policy 算法——这与算法多新无关。
- **某个离线算法在你会不会跑偏**：看训练集回报与留出的时间切分评估集是否同向。只有训练集涨而评估集不动，就是分布外高估，与超参无关。
- **某个规划式方法的可规划视野有多长**：把模型预测的下一状态与真实下一状态逐层对比，误差随 rollout 步数单调上升的那一段长度，就是视野上限。

### 7.3 机制差异：为什么它们表现不同（核心节）

十族候选的全部差异可以归因到四个机制维度。选这四个，是因为它们分别回答选型时必然要问的四件事：**数据从哪来、能复用几次（7.3.1）· 策略怎么表达动作（7.3.2）· 奖励长什么样（7.3.3）· 决策时花不花额外算力（7.3.4）**。

#### 7.3.1 数据来源与修正能力：同一条经验能被用几次

**机制是什么**：训练数据由谁产生、能否跨策略复用、复用需要什么修正项。这是 RL 与监督学习在工程上最本质的差别——监督学习的数据是给定的，RL 的数据是策略自己产生的，因此**数据分布与策略耦合**。

**主要族的实现差异**：

| 族 | 数据由谁产生 | 能否用历史数据 | 复用的前提 |
| --- | --- | --- | --- |
| Bandit 族 | 真实流量上的选择 | 可用（就是全部数据） | 上下文特征稳定 |
| Value-Based 族 | 行为策略 + 缓冲区 | 可用（off-policy） | 记录行为策略版本；TD 目标用 target 网络稳定 |
| Actor-Critic 族 | 当前策略的 rollout | 不可跨策略复用（on-policy） | PPO 的 clip 允许同一批数据复用 3–10 个 epoch【经验】 |
| 离线族 | 历史日志（行为策略） | 只能用历史（这就是它的定义） | **日志必须带 propensity 与行为策略版本**，缺了不可逆 |
| 偏好对齐族 | 当前策略多次生成 + 偏好标注 | 可用（DPO 用固定偏好集） | 需要 reference 模型锚住分布 |
| 规划与世界模型族 | 仿真器 / 自我博弈 | 可用（生成式数据） | 仿真与真实的差距可控 |

**由此必然导出的性质**：**因为** on-policy 的梯度是对**当前策略分布**取的期望，**所以**一批数据用过几个 epoch 就得丢弃，样本需求随更新次数线性累积，加机器只能加快采集、改变不了所需数据总量。**而因为** off-policy 用行为策略的数据去估计目标策略，**所以**同一条经验能被反复产生梯度，样本效率上去了——**代价是必须做分布修正**（重要性权重 / propensity / 保守项）；修正不到位的后果不是报错，而是 Q 值在日志没覆盖的动作上被自举放大，表现成「离线评估一路上涨、上线首日下跌」。**这条因果链是整个选型里最贵的一条**：它决定了日志在埋点阶段就必须记录什么，而埋点漏了 propensity 之后，历史日志是**不可逆地不可用**的（机制见 [§ 3 模式 5](06-rl-section-3-sec3.md)）。

**公开证据**：DQN 出自 Mnih 等《Human-level control through deep reinforcement learning》，Nature 2015，论文披露训练规模约 5×10⁷ 帧、原文表述相当于约 38 天的游戏体验【公开，2015，可按论文标题核验】——这是「样本效率是 RL 工程第一约束」这句话的来源，也是把「能离线复用」当成一等能力的理由。PPO 把新旧策略概率比 clip 在 $[1-\epsilon, 1+\epsilon]$，使同一批 rollout 可安全复用几个 epoch，这是它取代 TRPO 的工程原因【公开，Schulman 等 2017，可按论文标题核验】。可自行核验的判据：**看训练代码里有没有一个跨越策略版本的缓冲区**——有，它就不是纯 on-policy。

**失效条件**：当行为策略与目标策略差距过大时，重要性权重会出现极端值，样本复用越多、偏差越大，此时唯一的出路是**把策略限制在日志覆盖区域内**（离线族的做法），或者用仿真补数据。第二种失效更隐蔽：**日志里的动作不是随机试出来的**（旧策略只会推荐它认为好的），所以「日志里没有的动作」永远无法从中评估——这正是「有历史日志就能训 RL」这个直觉不成立的原因。

#### 7.3.2 策略的表达方式：动作空间决定「怎么选」

**机制是什么**：策略被表示成「给每个动作打分再取最大」（value-based），还是「直接输出动作分布」（policy gradient），还是「逐 token 生成」（序列生成）。这三者的差别不在实现细节，而在**策略这个函数能不能对连续变量求梯度**。

**主要族的实现差异**：

| 族 | 策略的数学对象 | 支持的动作空间 | 对动作数量的假设 |
| --- | --- | --- | --- |
| Bandit 族 | 每个 arm 的统计量 | 离散、可枚举 | arm 数有限且每个都拿得到流量 |
| Value-Based 族 | $Q(s,a)$ + argmax | 离散 | 动作数在千级以内【经验，与 §3.3 同口径】 |
| Actor-Critic 族 | $\pi_\theta(a\mid s)$ 直接参数化 | 连续、高维 | 不假设动作可枚举 |
| 偏好对齐族 | 语言模型自身的 token 分布 | 自由文本 | 不假设动作可枚举，但假设**动作是一条序列** |
| 离线族 | 同属上三族，但加保守约束 | 同上 | 同上 |

**由此必然导出的性质**：**因为** value-based 的更新要在每个状态下对**全部动作**取 max，**所以**它只适用于离散且可枚举的动作空间，**代价**是连续动作必须离散化，而网格数量随动作维数指数增长、最优动作常常落在两个格子中间，量化误差直接成为策略的性能上限。**而因为** policy gradient 直接对策略参数求梯度、不需要 max over actions，**所以**它天然支持连续动作，**代价**是必须额外估一个基线（Critic）来降方差，而 Critic 的误差会直接污染优势估计，进而污染梯度方向——**「训练不稳定」在多数工程事故里出在 Critic 而不是策略网络**。这两条性质合起来解释了一个常见现象：连续控制场景下团队换了三代算法（DDPG → TD3 → SAC），框架一直在变，但瓶颈始终是 Critic 的估计质量。

**公开证据**：PPO 出自 Schulman 等 2017 年论文、SAC 出自 Haarnoja 等 2018 年论文，各自是两族的公开代表【公开，2017 / 2018，可按论文标题核验】；Double DQN 解耦动作选择与价值估计、Dueling DQN 把 $Q$ 分解为 $V+A$、Rainbow 集成多项改进，是针对「Q 值过估计」与「学习效率」的三项公开改进（题名与年份见主文件 §2.3 的算法清单）。GRPO 用组内相对得分替代 Critic（主文件 §2.2 给出的 $\hat A_i = (R_i - \mathrm{mean}(R_{\text{group}}))/\mathrm{std}(R_{\text{group}})$），去掉一个常驻网络——这是「用族内实现差异削掉 Critic 这一项」的直接证据【公开，DeepSeek 2024，可按论文或模型卡核验】。

**失效条件**：当动作空间是**自由文本**时（LLM 的输出选择），前两族都不直接适用——动作既不可枚举，也不是低维连续向量，只能退化成「序列生成 + 偏好或可验证奖励」。此时「离散化」这条补救路径完全无效，因为文本空间的枚举没有意义。

#### 7.3.3 奖励形态：信用分配的距离与结论能否被复核

**机制是什么**：奖励是每步可测（稠密）、只在终局给（稀疏）、只有成对偏好，还是能被规则自动判定。奖励的形态决定了**一个标量要摊回到多少个决策步上**，以及**结论能被复核到什么粒度**（这正是「可解释性」那一维的真正来源）。

**主要族的实现差异**：

| 族 | 奖励从哪来 | 信用分配方式 | 结论可复核到什么粒度 |
| --- | --- | --- | --- |
| Bandit 族 | 本次动作的即时回报 | 无（单步，不需要摊回） | 每个 arm 的统计量与置信区间可逐条看 |
| Value-Based / Actor-Critic | 每步奖励或终局奖励 | 价值函数自举 + GAE 一类平滑 | 到「某个状态-动作的价值高」这个粒度 |
| 离线族 | 日志里的回报 | 保守项压制分布外高估 | 同上，但可对照日志里真实发生过的动作 |
| 模仿与逆 RL | 由演示反推出的奖励 | 对抗式判别 + 策略梯度 | 到「专家在这个情形下会怎么做」 |
| 偏好对齐族 | 成对偏好（人类或 AI 打分） | 奖励模型给出分数，再由 PPO/GRPO 优化 | 到「这组输出里哪条更好」，**不到中间步骤** |
| 可验证奖励 / Agent RL | 规则验证器（测试是否通过、任务是否完成） | 终局可判定，逐 step 归因靠**可回滚的执行环境** | **到「这一步之后能否继续推进」**，可逐条复现 |

**由此必然导出的性质**：**因为**稀疏终局奖励要把一个标量摊回整条轨迹，**所以**有效梯度被方差淹没、训练曲线长期贴地，**代价**是必须补塑形奖励（课程学习 / HER 一类）、世界模型或分层——三者都是在**人为缩短信用分配距离**，而不是在改进优化器。**而因为**成对偏好只需要「哪个更好」而不需要「好多少」，**所以** DPO 一类路线能跳过奖励模型与在线采样，把一整条链路压成一个监督式损失，**代价**是偏好数据**覆盖不了长链条的中间步骤**：在单轮问答上它足够，一旦任务变成多步工具调用，最后一步的偏好标签无法告诉模型第 3 步错在哪。这条代价正是「单轮偏好对齐 → Agent RL」这一次跃迁的机制来源。

**公开证据**：RLHF 用人类偏好训练 RL 策略的路线出自 2017 年的公开工作，InstructGPT 与 ChatGPT 在 2022 年把它推到主流（主文件 §1.4 演进历程）；DPO 于 2023 年公开，去掉了奖励模型与在线 RL 两步【公开，Rafailov 等 2023，可按论文标题核验】。可自行核验的判据：**把你的训练数据分成「有标准答案」和「只有偏好对」两部分**——有标准答案的那部分应当走验证器路线，不要为了统一而全部走偏好模型，因为**偏好模型是奖励的代理，而任何代理都会被优化出漏洞**（主文件 §1.2 把这一现象列为「奖励黑客」）。

**失效条件**：当奖励可以被规则自动判定时（代码测试通过、棋局分出胜负、工具调用返回成功），**继续用偏好模型是净损失**——它既引入一个常驻模型与一份标注成本，又把「可判定的客观信号」降级成「主观代理」。此时正确的动作是把验证器当奖励源，把偏好模型留给无法判定的那部分（表达质量、礼貌程度）。

#### 7.3.4 决策时花不花额外算力：用延迟换样本

**机制是什么**：决策时刻是「一次前向出动作」（model-free），还是「做若干次模拟再出动作」（planning），还是「在隐空间里想象若干步再出动作」（世界模型）。这条机制的实质是**把训练期的样本需求挪到推理期去付**。

**主要族的实现差异**：

| 族 | 决策时的算力 | 样本效率来自哪 | 推理延迟 |
| --- | --- | --- | --- |
| Bandit / Value-Based / Actor-Critic | 一次前向（或一次查表） | 来自数据量与复用 | 单次前向 |
| 离线族 | 一次前向 | 来自日志的量与质量 | 与在线同族相同 |
| 规划族（MCTS / AlphaZero / MuZero） | 每步若干次模拟 | 搜索 + 模型生成的数据 | 单步乘上模拟次数 |
| 世界模型族（DreamerV3） | 隐空间想象 + 出策略 | 想象产生的 rollout | 与想象步数相关 |

**由此必然导出的性质**：**因为**规划把一部分「试错」从真实环境搬到了决策时刻的搜索里，**所以**同样次数的真实交互能换来更好的策略——棋力提升里相当一部分来自搜索而不是网络拟合，**代价**是单步推理成本乘上模拟次数，毫秒级在线决策场景（出价、推荐重排、风控评分）用不了这条路。**另一条性质来自误差方向**：**因为**规划会主动去访问模型没见过的状态区域，**所以**模型误差会随规划深度累积——**规划得越深，偏离真实世界越远**，这与「想得越多越准」的直觉相反。工程上唯一可用的判定是那条误差随 rollout 步数上升的曲线，它的有效长度就是可规划视野。

**公开证据**：AlphaGo 的成果发表于 Nature 2016、AlphaZero 发表于 Science 2018、MuZero 发表于 Nature 2020，三者都建立在「决策时做搜索」之上；DreamerV3（2023）是「世界模型 + 隐空间想象训练」方向的公开代表【公开，2016 / 2018 / 2020 / 2023，可按论文题名核验】。Dyna-Q 作为「真实经验 + 想象经验混合更新」的早期公开框架，其思路与今天的世界模型路线同源（主文件 §2.3）【公开，1990，可按题名核验】。

**失效条件**：当环境无法仿真、且观测不足以学出一个可用模型时，这一族整体不成立——**模型误差是它唯一的误差来源，也是它唯一的成本来源**。此时的兜底是回到采样式方法，或者先做行为克隆拿一个能跑起来的基线。

### 7.4 成本结构对比（不是价格表，是成本函数）

按**成本形状**把「成本随什么增长」相同的族归并起来。下表列出差异最大的五类（表内五行共覆盖 6 族）——**这不是十族的全部**：另有 4 族在这张表里没有落点，单列在表后，免得读者按「十族」去找落点时找不到：

```
年成本 ≈ 交互成本（真实流量上的探索损失 + 仿真算力）
       + 训练算力（rollout 生成 + 梯度更新 + 常驻模型数 × 单模型显存）
       + 推理成本（单步决策算力 × 请求量；含规划时的搜索乘数）
       + 人力（奖励函数定义与维护 + 评估集与上线门禁 + 灰度运维）
```

**主导项与隐性成本**：

| 族 | 主导项 | 隐性成本 |
| --- | --- | --- |
| Bandit 族 | 探索预算（次脏动作的损失 × 曝光量） | 候选 arm 数增长时探索预算按差距平方反比上涨（见下） |
| Value-Based / Actor-Critic | 采样量 + 常驻模型显存 | 训练不稳定导致的重复实验；评估口径要做两套（离线 + 线上） |
| 离线族 | 数据准备（日志字段是否齐全） | 埋点漏了 propensity 就是永久性缺口，事后补不回来 |
| 偏好对齐族 | 常驻模型数 × 显存 + 标注或 AI 打分成本 | 偏好数据覆盖不到中间步骤，多步场景仍要另建一套 |
| 规划与世界模型族 | 单步推理算力（搜索乘数）+ 仿真器建设 | 仿真与真实的差距是一个长期维护项，且误差随规划深度累积 |

**表外四族的成本落点**（与前五类不同形，单列，不与上表混并）：

- **模仿与逆 RL 族**：形状接近离线族——主导项同样是**数据可得性**，只是对象从「日志字段」换成**专家轨迹的采集与标注**；隐性成本是演示覆盖不到的状态区里策略没有先验，要靠 GAIL / AIRL 额外训一个判别器把分布偏移纠回来，这个判别器本身又是一份常驻训练开销。
- **自博弈族 / 多智能体族 / 可验证奖励（Agent RL）族**：这三族的成本形状可归为一类——主导项都是**环境基建与并行仿真算力**（自博弈按种群规模并行对局、多智能体要联合模拟环境、Agent RL 要「可沙盒、可回滚」的执行环境），而它们**判定的对错都来自环境本身**（胜负 / 联合收益 / 验证器）；隐性成本是**这套环境是一条长期运行面**而非一次性建设——仿真要随被测系统版本持续维护，联合环境随智能体数量膨胀，沙盒要跟着任务集一起演进。**因此这三族的成本与请求量无关，与「场景数 × 环境复杂度」成正比**——这与本节数量级示例里的「人力项」是同一个形状（与请求量无关的固定项）。

**数量级示例**（每条自带档位：**【推算】**条目把推导链写全，便于换参数重算；**【经验】**条目给条件与量级）：

- **Bandit 的探索预算**【推算】：要把两个真实 CTR 为 1.0% 与 1.2% 的 arm 区分开，按两比例检验 $n \approx 2(z_{\alpha/2}+z_\beta)^2 \bar p(1-\bar p)/\Delta^2$，取 $\alpha=0.05$、power 0.8（$(1.96+0.84)^2 \approx 7.85$）、$\bar p \approx 0.011$、$\Delta = 0.002$，得 $n \approx 2 \times 7.85 \times 0.011 \times 0.989 / 0.000004 \approx 4.3\times 10^4$，即**每个 arm 需要约 4 万次曝光**；候选数为 1000 时，仅探索就要 $1000 \times 4.3\times10^4 \approx 4.3\times10^7$ 次曝光。再注意 $n \propto 1/\Delta^2$：把要分辨的差距从 0.2 个百分点减半到 0.1 个百分点，所需样本量约乘 4（推导链：$(0.002/0.001)^2 = 4$）。**这就是「长尾 arm 吃光探索预算」的算术依据，也是 7.5 里「候选数是否在百级以内」这条判据的来源**。
- **on-policy 的数据需求随更新次数累积**【推算】：设一次 rollout 采 $N=10^5$ 条 transition、计划做 $U=200$ 次策略更新，则交互量约为 $N \times U = 2\times10^7$ 条；若同一批数据能跨策略复用 $R$ 次，达到同等更新次数只需 $2\times10^7 / 5 = 4\times10^6$ 条（取 $R=5$，与 [§ 3 模式 3](06-rl-section-3-sec3.md) 给出的 3–10 epoch【经验】同量级）。**加并行度改变的是单位时间能采多少，改变不了等号右边的总量**——这是 7.7 第一条反模式的算术依据。
- **常驻模型数与显存**【推算】：PPO 路线做 LLM 偏好对齐时要同时驻留策略、参考、奖励、Critic 四个模型；若四者同规模，常驻参数量记为 $4M$ 量级，换成去 Critic 的 GRPO 后为 $3M$，常驻参数量减少 25%（推导链：$4 \to 3$，$(4-3)/4 = 25\%$）。**代价转换而不是消失**：优势估计改由组内相对得分给出，需要同一 prompt 多次生成，采样成本从 Critic 转到了生成侧（主文件 §2.2 的 GRPO 优势公式）。
- **人力项**【经验】：奖励函数的定义与维护、评估集与上线门禁是**与请求量无关、与场景数成正比**的固定项。常见观察是：多目标加权里被系统性牺牲的那一项，往往在半年后才被发现，而这时它已经被写进多个场景的奖励函数——**所以奖励函数要由业务方共同定义并留下变更记录，这不是流程洁癖，是唯一的追溯手段**。

**主导项随场景切换，所以「先省哪一项」不是固定的**：

| 你的场景 | 成本公式里的主导项 | 因此第一优先 |
| --- | --- | --- |
| 候选动作多、单次回报低（券面额、素材选择） | 探索预算（次脏动作 × 曝光量） | 先压候选数或做分层，再谈更聪明的算法 |
| 真实交互昂贵、不能试错 | 数据准备（日志字段是否齐全） | 先补 propensity 与行为策略版本，再谈算法 |
| 交互便宜、有仿真器 | 采样量 + 常驻模型显存 | 先上并行仿真与规整的评估集 |
| 毫秒级在线决策 | 推理成本 | 规划族直接排除，不做延迟预算上的赌博 |
| 多场景、多目标 | 人力（奖励维护 + 门禁） | 先统一平台与奖励评审，再扩张场景数 |

### 7.5 决策树（每个分支都要有阈值依据）

```
先量下面几项：试错权 / 奖励形态 / 决策步数 / 动作空间形态 / 单步推理延迟预算 / 决策主体数
│
├─ ① 本次选择不改变未来的状态分布（单步）
│    → Bandit 族（UCB / Thompson / Contextual / Neural Bandit）
│      前置判据：候选 arm 数是否在百级以内
│
├─ ② 序列决策 + 动作离散可枚举
│    → Value-Based 族（DQN / Double / Dueling / Rainbow）
│      前置判据：动作数是否在千级以内
│
├─ ③ 序列决策 + 动作连续或高维
│    → Actor-Critic 族（DDPG / TD3 / SAC；通用要稳选 PPO）
│
├─ ④ 不能在真实环境试错，且日志里记了 propensity 与行为策略版本
│    → 离线族（CQL / IQL / TD3+BC）
│      前置判据：这批数据是由当前策略采出来的吗
│
├─ ⑤ 不能在真实环境试错，但拿得到专家演示
│    → 先 BC 拿基线，再 GAIL / AIRL（模仿与逆 RL 族）
│
├─ ⑥ 只有成对偏好、没有可自动判定的奖励
│    → 偏好对齐族：先 DPO 起步，再按需上 PPO(RLHF) / GRPO
│      前置判据：任务是否单轮（多轮则由 ⑦ 接管）
│
├─ ⑦ 奖励可被规则自动判定（测试通过 / 胜负 / 工具调用成功）
│    → 在线 RL + 可验证奖励（自博弈族与 Agent RL 走这条）
│
├─ ⑧ 环境规则已知且可大规模仿真，且单步延迟可放宽
│    → 规划族（MCTS / AlphaZero / MuZero）
│
├─ ⑨ 环境不可仿真、但观测充足到能学出一个模型，且样本预算极紧
│    → 世界模型族（DreamerV3 一类）
│
└─ ⑩ 决策主体多于一个，且各自的最优动作互相影响
     → 多智能体族（MAPPO / QMIX / MADDPG / MAVEN），训练期用全局信息
```

**阈值依据**（与树上每个判断节点一一对应）：

- **①「单步」**：这是**结构判据**而非数值阈值——判据是「本次选择是否改变未来的状态分布」。由 7.3.2 导出：单步问题里不需要 $Q(s,a)$、Replay Buffer 与价值网络，多出来的都是白付的复杂度。判定方法：把「这次选择」与「下一次请求的输入分布」做一次因果检查，若不相干，就还是 Bandit。
- **①「候选 arm 数是否在百级以内」**：由 7.4 的探索预算推算导出。该推算表明 $n \propto 1/\Delta^2$，而总探索量还乘上 arm 数，因此候选数上千、单个 arm 流量又小的时候，探索预算会被长尾吃光。**这不是「上千就不能用 Bandit」，而是「上千时先分层或先聚簇」**——把 1000 个候选归成 20 组做组间探索，是这一步的标准动作。
- **②「动作数是否在千级以内」**：由 7.3.2 的「value-based 要对全部动作取 max」导出，与数据量无关。超过这条线应当换族（连续/高维走 ③），而不是把网络加大——加宽网络改变不了「每个动作格子都要被访问到才可能学好」这件事。阈值取千级是**工程经验量级**【经验，与 §3.3 同口径】。
- **③「连续或高维动作」**：判据是**动作维度**而不是动作个数：维度超过 3 之后离散化带来的网格数按维数指数增长，量化误差成为性能上限【经验，与 §3.3 同口径】。这条线上要额外注意的是：换了族不等于解决了问题，Critic 的估计质量成为新的主导约束（7.3.2）。
- **④「这批数据是由当前策略采出来的吗」**：由 7.3.1 导出，是**唯一一条非数值、却最硬的门槛**。判定方法不是看算法而是看日志字段：有没有 `propensity`、有没有行为策略版本。**没有这两个字段，离线路线现在就不能启动**——它们无法事后补采。
- **⑤「拿得到专家演示」**：这也是约束判据——演示存在与否是数据可用性问题，不是算法问题。由 7.3.3 导出：演示给的是「在这个情形下专家怎么做」，它能提供先验、缩短探索，但它提供不了奖励函数，所以 GAIL / AIRL 要额外学一个判别器。
- **⑥「任务是否单轮」**：由 7.3.3 的「偏好数据覆盖不了长链条中间步骤」导出。单轮问答的偏好标签能落到整条输出上，多步任务的偏好标签落不到第 3 步——所以这条判据的实质是**信用分配距离是否超过一个决策步**。超过，就要由 ⑦ 接管（可验证奖励能逐步归因）。
- **⑦「奖励是否可被规则自动判定」**：这是**约束判据**：可自动判定意味着奖励源是客观的，此时用偏好模型是净损失（7.3.3 的失效条件）。判定方法：写下任务的成功标准，如果它可以用一段代码判定，就走这条；不能判定的那部分（表达质量）才留给偏好模型。
- **⑧「单步延迟可放宽」**：由 7.3.4 导出——规划族的单步推理成本是单次前向乘上模拟次数。**毫秒级在线场景直接排除**：不是规划不好，而是它在延迟预算上就装不进去。判定方法：把当前单步延迟预算与一次前向的实测耗时相除，得到的商就是你能负担的模拟次数上限。
- **⑨「观测充足到能学出一个模型」**：由 7.3.4 的误差方向导出——模型误差随规划/想象深度累积。判定方法：把预测的下一状态与真实下一状态逐层对比，误差单调上升的那一段长度即可规划视野；视野短于任务所需步数时，这一族不成立。
- **⑩「决策主体多于一个」**：这是**结构判据**：多主体的环境因他人策略更新而持续变化，非平稳性不是超参能解决的。由 §3.6 的迁移表导出：解法是 CTDE（训练期用全局信息、执行期只用本地观测），而它的代价是中心 Critic 的联合空间随人数膨胀——所以智能体数量在 10 以内时这套机制还划算【经验，与 §3.3 同口径】。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因 |
| --- | --- | --- | --- |
| 单步决策、候选百级以内、要求即时回本 | Bandit 族（UCB / Thompson） | 人工规则 + A/B | 人工规则 + A/B：规则写死后不随反馈自适应，A/B 一次只比两个版本，候选上百时比较轮数成倍累积 |
| 离散动作、序列决策、可在真实流量试错 | Value-Based 族（DQN / Rainbow） | Actor-Critic 族 | 直接上策略梯度：小离散动作空间里 value-based 的样本复用更高 |
| 连续或高维动作、通用要稳 | Actor-Critic 族（PPO / SAC / TD3） | 离散化 + DQN | 离散化：网格按维数指数增长，量化误差成为上限 |
| 安全敏感、只有历史日志 | 离线族（CQL / IQL / TD3+BC） | 影子模式下的受限在线 RL | 影子模式：动作不上线就拿不到它自己造成的回报，训练只能继续吃旧策略的日志；放开让它真动作，这行「安全敏感」的前提就不再成立 |
| 有专家演示、奖励写不出 | 模仿与逆 RL 族（BC → GAIL / AIRL） | 手工奖励 + 在线 RL | 从零探索：演示给了先验，从零开始的交互代价高得多 |
| 单轮偏好对齐 | 偏好对齐族（DPO 起步） | PPO(RLHF) | 直接上 PPO：多一整套奖励模型与 Critic 的方差来源 |
| 多步工具调用、成败可自动判定 | 在线 RL + 可验证奖励 | 偏好对齐族 + 人工抽检 | 只靠偏好：覆盖不到中间步骤，信用分配距离过长 |
| 规则已知、可大规模仿真 | 规划族（AlphaZero / MuZero） | 世界模型族 | 世界模型族：规则已知时仿真器已经在手上，再学一个模型等于把精确的转移函数换成有误差的近似，误差还随规划深度累积（7.3.4） |
| 多主体协同/竞争 | 多智能体族（MAPPO / QMIX / MADDPG） | 独立单智能体 + 规则仲裁 | 各自独立训练：环境非平稳，训练震荡且信用无法分配 |

1. **Bandit + RL（粗排 + 精排）**：Bandit 负责粗排与探索（哪些候选还没被充分试过），RL 负责精排与长期价值优化。边界是**探索归 Bandit、长期价值归 RL**。运维代价：两段各有一套评估口径，且探索期的数据必须完整回流给 RL 侧，否则精排模型只在 Bandit 已经偏好的分布上学习。
2. **SFT + RLHF（LLM 训练）**：SFT 打基础能力，RLHF / DPO / GRPO 做偏好对齐。边界是**能力归 SFT、对齐归 RL 侧**。运维代价：要同时维护 reference 模型与对齐数据的版本；对齐阶段一旦发散，语言质量的塌陷会掩盖能力层面的回归。
3. **Imitation Learning + RL（Offline → Online）**：IL 从专家演示学初始策略，在线 RL 在受控条件下微调。边界是**冷启动归 IL、分布漂移的最后一段归在线 RL**。运维代价：两阶段各有验收标准与回滚点；真机/真车场景还要有安全限制（限速、保护区），否则「微调」会直接变成事故来源。
4. **Multi-Agent + LLM（Agent 协同）**：多个 LLM Agent 通过多智能体机制协同（MAPPO / MADDPG 一类训练协同策略，或规则化的角色分工）。边界是**协调机制归 MARL、语言理解与生成归 LLM**。运维代价：中心 Critic 的联合空间随 Agent 数膨胀，信用分配机制要单独建；一旦 Agent 数量上去，「谁做错了」会比「整体差」更难定位。
5. **World Model + RL（Model-Based）**：学环境模型，在模型里做规划与想象训练。边界是**数据供给归模型、决策质量归规划**。运维代价：仿真与真实的差距是长期维护项；模型误差随规划深度累积，所以这套组合必须配一条「误差随 rollout 步数上升」的监控曲线。
6. **LLM + Bandit（推荐 + 对话）**：LLM 生成候选，Bandit 在候选间做探索与选择。边界是**候选生成归 LLM、临门一脚的选择归 Bandit**。运维代价：LLM 的输出分布会随版本更新变化，Bandit 的统计量在换模型那一刻全部失效——所以这套组合必须把「LLM 版本」当成 Bandit 上下文的一部分记录下来。

**组合的共同原则**：每个组合都要能回答「哪一件负责产生数据、哪一件负责决策、哪一件负责判定对错」。**因为**奖励的形态决定了链路里有没有一个客观判定者（7.3.3），**所以**组合里必须有一个**明确的奖励来源**——它可以是真实业务回报、可以是规则验证器、可以是偏好模型，但**不能是「几个都算一点」而没有主次**；主次不清时，被牺牲的那个目标会在半年后才被发现，而那时它已经写进了所有场景的奖励函数。

### 7.7 选错的代价与迁移成本

**反模式：把样本效率问题当成算力问题** —— 交互次数已经是千万量级仍不收敛，投入的是更多机器与更多卡 → **因为** on-policy 的梯度对当前策略分布取期望，一批数据用过几个 epoch 就作废，**所以**数据需求随更新次数线性累积，加并行度只能加快「采集同样的数据」，改变不了所需数据总量（7.4 的推算已给算术依据）→ **正确做法**：先量「一次更新用掉的数据量 vs 你能新采到的数据量」，比值决定该不该换族；要换就换到能跨策略复用的路线（off-policy / 离线）或能生成数据的路线（仿真 / 世界模型 / 自博弈），而不是加机器。

**反模式：在不能试错的场景里用 on-policy 算法** —— 团队拿 PPO 或 DQN 直接吃历史日志，训练集回报一路上涨，上线首日指标下跌 → **因为** 日志的分布由**旧策略**决定，on-policy 的目标却是对**当前策略**分布取期望，**所以**训练时优化的对象与评估的对象不是同一个分布，优势估计系统性偏，且偏差随训练推进扩大；更隐蔽的是，**因为** 日志里没有的动作永远无法被评估，**所以**这个偏差在离线阶段**看不见**（训练集回报照样涨）→ **正确做法**：离线场景换 CQL / IQL / TD3+BC 一类带保守约束的算法，或先做 off-policy 修正；同时回到埋点检查 `propensity` 与行为策略版本是否已记录——**没记录就是永久性缺口**，此时唯一的路是用仿真补数据，而不是继续调超参。

**反模式：奖励函数一次性写成、之后只看模型指标** —— 奖励里写着「点击 +1、跳出 −1」，没有任何一项能对应到业务量，上线后点击涨、退款涨 → **因为** 优化过程会找到奖励函数里所有可优化的结构，而奖励是有限写的，**所以**任何漏洞都会被找到并放大；**又因为** 奖励函数一旦写进多个场景就很难收窄（收窄会让所有历史实验不可比），**所以**错误的奖励会被长期沿用，危害随模型能力增强而放大（主文件 §1.2 的「奖励黑客」）→ **正确做法**：把奖励当规格说明而不是超参——先写清业务量、再写奖励，上线前做敏感性分析（把每一项权重扰动一下，看策略行为是否剧变），并留一份「奖励函数变更记录」作为唯一的追溯手段。

**换成另一族要动什么**：

| 迁移方向 | 数据迁移 | 算法 / 代码改写 | 运维重建 | 团队再学习 | 工作量量级 |
| --- | --- | --- | --- | --- | --- |
| Bandit → 序列 RL（同业务） | 中：要补状态特征与延迟回报的回流 | 大：从统计量更新换成 rollout + 训练循环 | 中：新增训练与评估管道 | 状态表示、GAE、缓冲区 | 3–6 人月 |
| Value-Based → Actor-Critic | 小：回放数据可复用 | 中：多一套策略网络与学习率 | 中：训练稳定性监控 | Critic 调参与方差排查 | 1–3 人月 |
| 在线 RL → 离线 RL | 大：**数据本身要重建**（propensity 与行为策略版本） | 中：换算法与保守项 | 中：离线评估集与方法重做 | 分布外评估、保守约束 | 3–9 人月 |
| 在线 RL → 偏好对齐（LLM） | 大：要建成对偏好数据集 | 中：DPO 压成监督损失；PPO 路线要加奖励模型 | 中：reference 模型与 KL 约束要进预算 | 偏好数据构造与标注一致性 | 2–6 人月 |
| 偏好对齐 → 可验证奖励（Agent RL） | 大：要建可沙盒、可回滚的执行环境 | 大：奖励源换成验证器，评测集换成任务集 | 大：执行环境本身是一个长期运行面 | 环境工程、逐步归因 | 6–12 人月 |
| 单智能体 → 多智能体 | 中：要能重放其他智能体的动作 | 大：换 CTDE，新增信用分配 | 大：联合模拟环境与联盟管理 | 非平稳性、值分解 | 6–12 人月 |

> 量级按「一个熟悉本系统的 3–5 人小组」估算【经验】。按上表区间中值排序，最贵的两条是「偏好对齐 → 可验证奖励」与「单智能体 → 多智能体」（中值均为 9.0 人月）：它们的共同点是**都要新建一个长期运行的环境或联盟**，而不是改算法。而真正**在埋点那一刻就锁死、事后无法补救**的只有一条：「在线 RL → 离线 RL」的数据迁移——`propensity` 与行为策略版本没记，历史日志就永久不可用。这也解释了为什么「先把日志字段设计对」比「先选一个算法」更值钱。

### 7.8 小结

| 你的处境 | 建议 | 关键理由（机制层面） |
| --- | --- | --- |
| 单步决策、候选百级、要即时回本 | Bandit 族 | 不需要状态转移与价值网络，探索成本可用置信区间显式计算 |
| 动作离散可枚举、可在线采样 | Value-Based 族 | 缓冲区让同一批经验反复产生梯度，样本复用率高 |
| 动作连续或高维、通用要稳 | Actor-Critic 族 | 直接对策略求梯度，不需要对动作取 max，因此不必离散化 |
| 不能试错、日志齐全 | 离线族 | 保守项压制分布外高估，策略不跑到无数据区域 |
| 不能试错、有专家演示 | 模仿 + 逆 RL | 演示给了先验，缩短了信用分配与探索的距离 |
| 只有成对偏好、任务单轮 | 偏好对齐族（DPO 起步） | 偏好只需「哪个更好」，因此可以跳过奖励模型与在线采样 |
| 多步任务、成败可自动判定 | 可验证奖励 + 在线 RL | 奖励可逐条复现，信用能落到具体步骤而不是整条输出 |
| 规则可仿真、延迟可放宽 | 规划族 | 决策时多做几次模拟，同等交互换更好策略 |
| 多主体、回报互相依赖 | 多智能体族（CTDE） | 训练期用全局信息、执行期只用本地观测，正视非平稳性 |
| 训练不收敛、想加机器 | 先量「每次更新用掉的数据量 vs 能新采到的量」 | on-policy 的数据需求随更新次数线性累积，并行度改变不了总量 |
| 离线指标涨、上线跌 | 先查日志里有没有 `propensity` | 数据分布由旧策略决定，缺修正项的离线训练看不见分布外错误 |
| 指标涨了但业务方不认 | 先查奖励函数每一项对应哪个业务量 | 奖励是规格说明，有限写的奖励一定会被优化出漏洞 |

> 本节小结：本节所比的十族候选之间**唯一真正起决定作用的差异**是——**试错权：谁为一次错误动作付费**。它是给全部候选划第一条线的判据（能在线试错 / 只能在仿真里试错 / 完全不能试错），并顺带决定了探索预算的上限与日志在埋点阶段必须记录什么。第二位的是**奖励形态**，它决定链路里有没有一个客观判定者，从而决定单轮对齐够不够、要不要建可验证环境。其余所有维度都是这两条的**表现形式**：所谓「样本效率」就是「数据能不能跨策略复用」，所谓「安全性」在必须发现新动作的场景里恰好是一张减分项，所谓「可解释性」则取决于奖励是从哪来的。选型的正确顺序是：**先量试错权（切族）→ 再量奖励形态（定判定者）→ 最后才量动作空间与延迟预算（族内挑方法）**。
