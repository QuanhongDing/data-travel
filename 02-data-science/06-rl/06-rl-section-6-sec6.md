## 6. 落地实践

### 6.1 某头部电商"**广告出价：从静态公式到 Contextual Bandit + PPO**"（2019-2024）

**背景（Why）**

该电商 2019 年面临**"出价策略的探索-利用难题"**：
- **日均十亿次展示**——**每次展示都要在几十毫秒内给出价格，出价策略的改动直接影响收入**
- **静态出价无法表达上下文**——**同一个用户在不同时段、不同位置的价值差异极大，用一组固定系数无法表达**
- **新广告主没有数据**——**历史数据驱动的方法对新广告主直接失效，导致新广告主起量困难**
- **业务目标多元**——**平台收入、广告主 ROI、用户体验需要同时优化，任何单一指标最优都会伤害其余两个**

**触发点（What）**

2019 年起该电商把广告出价从静态公式迁移到 **Contextual Bandit + 深度 RL**（[案例公开材料 2019-2024]），目标：
- **eCPM 提升**——单位流量的价值提升
- **广告主 ROI 不降**——出价策略不能只对平台有利
- **新广告主可起量**——冷启动不能靠等数据

**详细做法（How）**

该电商广告出价 RL 的**5 大核心组件**：

1. **以"上下文 → 出价"为单位做探索-利用（核心创新）**
   - 关键设计：**把每次出价视为一次 Bandit 决策**——上下文是（用户特征、时段、位置、广告特征），动作是出价档位，奖励是后续的转化价值；用探索-利用算法在不确定中逐步逼近最优
   - 关键能力：**不确定的地方也能被试探**——这是 RL 相对监督学习的核心差别：监督学习只能学到"已经发生过的"，Bandit 能主动去试探"没发生过但可能更好的"
   - 关键数字：**eCPM +15%**
   - 关键示意：
     ```text
     探索与利用的取舍（决定上线初期会不会"崩"）
       利用：选当前估计收益最高的动作 → 稳，但永远发现不了更好的
       探索：选不确定的动作去试       → 可能更好，也可能更差
       ────────────────────────────────────────────────
       常见错误：一上线就全量探索
         → 大量流量被用于"试错"
         → 短期收入明显下滑，业务方直接叫停
       ✓ 保守开局 + 逐步加码
         阶段 1：探索比例极低（只在小流量上试）
         阶段 2：确认策略稳定后，逐步提高探索比例
         阶段 3：探索比例收敛到与"不确定性"匹配的水平
       ────────────────────────────────────────────────
     判据：探索的强度应当与"我们对这个动作有多不确定"成正比，
           而不是与"我们有多想进步"成正比
     ```

2. **深度 RL 处理连续动作与长期价值（核心）**
   - 关键设计：**策略网络直接输出出价，价值网络评估长期回报**；用 PPO 类算法在策略更新幅度上做约束，避免一次更新把策略推离太远
   - 关键能力：**出价不再是离散档位，长期回报可被纳入**——广告的价值往往不在一两次展示上，而在于对同一用户的持续触达
   - 关键性质：**策略更新受约束，训练稳定**

3. **奖励函数对齐业务真实目标（核心创新）**
   - 关键设计：**奖励不能只看点击**，而是采用与广告主长期价值挂钩的指标（如一段时间窗口内的 ROI）
   - 关键能力：**优化方向与业务方向一致**——奖励函数一旦选错，模型会精确地优化一个错误的目标，而且效果越好危害越大
   - 关键性质：**奖励对齐长周期 ROI**

4. **实时决策引擎满足延迟约束（核心）**
   - 关键设计：**请求到达 → 实时推理 → 出价**，模型与特征服务共同保证尾延迟
   - 关键能力：**RL 策略可用**——再好的策略如果超出延迟预算就等于不可用
   - 关键数字：**P99 < 50ms、QPS 10 万+**

5. **探索策略专门服务冷启动（核心）**
   - 关键设计：**对新广告主加大探索**（用 Thompson Sampling 类方法给出乐观估计），并在奖励中体现探索带来的信息价值
   - 关键能力：**新广告主不必等数据积累**——这直接决定了平台对新广告主的吸引力，也决定了广告主生态的健康度
   - 关键数字：**新广告主起量时间 -50%**

**该电商广告出价关键数字**（[案例公开材料 2019-2024]）：

| 指标 | 改前（静态出价） | 改后 | 提升 |
| --- | --- | --- | --- |
| **eCPM** | 基线 | +15% | **+15%** |
| **广告收入** | 基线 | 年增数亿量级 | **显著** |
| **奖励函数** | 只看点击 | 对齐广告主长周期 ROI | **方向正确** |
| **探索策略** | 无 | 保守开局 → 逐步加码 | **不伤短期收入** |
| **新广告主起量** | 靠等待数据 | 主动探索 | **-50%** |
| **决策延迟 P99** | 100ms | < 50ms | **-50%** |
| **吞吐** | — | QPS 10 万+ | **可支撑** |
| **策略更新** | — | 受约束（PPO 类） | **训练稳定** |

**具体数字（How much）**

- 团队规模：该电商广告 RL 相关团队 50+ 人
- 关键数字：**eCPM +15%**；**P99 < 50ms**；**QPS 10 万+**；**新广告主起量 -50%**
- 业务影响：覆盖该电商日均十亿量级的广告展示，并改善广告主生态的冷启动体验

**失败教训**

- 早期「**用静态系数出价**」——无法表达上下文差异、新广告主直接失效，倒逼**「以（上下文 → 出价）为单位做探索-利用」**
- 「**一上线就全量探索**」——短期收入明显下滑、业务方要求回滚，倒逼**「保守开局、探索比例逐步加码」**
- 「**奖励只看点击**」——广告主长期 ROI 下滑、生态受损，倒逼**「奖励改为对齐长周期 ROI」**
- 「**策略更新步长太大**」——训练过程中策略剧烈震荡，倒逼**「用 PPO 类方法约束每次更新的幅度」**
- 「**模型与特征服务各自定时延**」——尾延迟超出预算，倒逼**「把延迟预算作为硬约束统一分配」**

### 6.2 某短视频平台"**推荐重排：在监督学习的饱和区之外找增量**"（2019-2024）

**背景（Why）**

该短视频平台 2019 年面临**"短期指标已经饱和，而长期价值没人优化"**：
- **亿级用户、短期 CTR 已接近上限**——**继续在"点不点"上优化，提升空间已经很小**
- **真正重要的是更长周期的价值**——**用户是否会第二天再来、是否会持续消费，比单次点击重要得多**
- **监督学习看不见长期**——**监督信号是"这一次点没点"，它不包含"多刷几分钟"或"下周还会不会来"**
- **在线上直接试错代价大**——**推荐策略面向亿级用户，一次错误策略的影响面极大**

**触发点（What）**

2019 年起该短视频平台在重排阶段引入 **RL**（[案例公开材料 2019-2024]），目标：
- **长期价值提升**——而不是短期点击
- **风险可控**——策略上线前能被评估
- **与现有链路稳定共存**——不破坏已经跑通的监督模型

**详细做法（How）**

该平台重排 RL 的**5 大核心组件**：

1. **只动重排、不动粗排（核心创新）**
   - 关键设计：**短期点击预测仍由监督模型承担**（保持稳定基线），**RL 只在重排阶段生效**——即候选集已定，RL 决定最终呈现顺序
   - 关键能力：**风险被限定在可控范围**——RL 最大的问题是不可预测，把它限制在链路的最后一步，即使策略出问题，影响面也有上限
   - 关键数字：**长期 GMV +8%**
   - 关键示意：
     ```text
     一次用户会话 = 一条轨迹（在 RL 里就是天然的 MDP）
       s0 ──a0──► s1 ──a1──► s2 ──a2──► … ──► 会话结束
       状态 = 用户当前上下文与已消费内容
       动作 = 下一条呈现什么
       奖励 = 该次呈现带来的长期价值（可延迟）
       ────────────────────────────────────────────────
     接入方式的选择（决定风险大小）
       ✗ 全链路 RL：召回 / 粗排 / 精排 / 重排都交给 RL
         → 出问题时影响面覆盖整条链路，不可回滚
       ✓ 只动重排：粗排保持监督模型不变
         → 候选集稳定，RL 只在这批候选里排序
         → 有问题时影响有限，且可单独回滚
       ────────────────────────────────────────────────
     奖励设计的关键：
         reward = 长期价值项 − 短期点击项
         必须有"短期负项"，否则模型必然退化成标题党
         （标题党能最大化点击，但伤害长期消费）
     ```

2. **奖励中显式放入"短期负项"（核心创新）**
   - 关键设计：**奖励由长期价值项（留存、完播、消费深度）与短期点击项共同构成，且短期点击带负权重**，用于抑制标题党
   - 关键能力：**模型不会退化成"只骗点击"**——只要奖励里没有对"骗点击"的惩罚，模型必然朝那个方向演化，而且优化得越好越糟
   - 关键数字：**多目标奖励 +6%**

3. **离线模拟器作为上线前置门禁（核心）**
   - 关键设计：**策略先过用户行为模拟器评估，达标后才能进入线上实验**；模拟器对"策略决策与线上实际表现"的吻合度被持续度量
   - 关键能力：**上线前的风险被提前暴露**——在亿级用户上直接试错，代价远高于在模拟器里试
   - 关键数字：**模拟器与线上吻合率 92%**

4. **多目标加权使业务目标可调（核心）**
   - 关键设计：**点击 / 完播 / 点赞 / 关注等各自权重**，权重由业务目标决定而不写死在模型里
   - 关键能力：**业务目标变化时不必重训**——推荐系统的目标在不同阶段会变（拉新期与留存期不同），权重可调让机制具备延续性
   - 关键性质：**多目标可调**

5. **训练到部署的流水线化（核心）**
   - 关键设计：**监督 → 离线 RL → 在线 RL 三阶段流水线**，每阶段的产物都有明确的准入门槛
   - 关键能力：**迭代速度可控**——RL 的迭代成本高，如果每轮都靠人工拼流程，实验数量上不去
   - 关键数字：**训练 → 部署 < 1 天**

**该短视频重排 RL 关键数字**（[案例公开材料 2019-2024]）：

| 指标 | 改前（纯监督 CTR） | 改后 | 提升 |
| --- | --- | --- | --- |
| **优化目标** | 单次点击 | 长期价值（留存 / 完播 / 消费深度） | **方向变化** |
| **长期 GMV** | 基线 | +8% | **+8%** |
| **用户活跃** | 基线 | +5% | **+5%** |
| **短期负项** | 无 | 奖励中显式抑制标题党 | **不退化成标题党** |
| **RL 生效范围** | — | 仅重排，粗排不动 | **风险受限** |
| **上线前置门禁** | 直接上实验 | 离线模拟器过关才上线 | **风险提前暴露** |
| **模拟器吻合率** | — | 92% | **可作门禁** |
| **训练到部署** | 手工流程 | < 1 天 | **迭代加快** |

**具体数字（How much）**

- 团队规模：该短视频重排 RL 相关团队 50+ 人
- 关键数字：**长期 GMV +8%**；**活跃 +5%**；**多目标 +6%**；**模拟器吻合 92%**
- 业务影响：在短期指标饱和之后，从长期价值上找到新的增量空间

**失败教训**

- 早期「**只优化短期点击**」——长期留存下滑，倒逼**「把优化目标换成长期价值 + 短期负项」**
- 「**奖励里只有正向项**」——模型迅速退化成标题党，倒逼**「奖励中显式加入短期点击的负权重」**
- 「**没有离线模拟器就直接上实验**」——出现过明显的时长下滑，倒逼**「模拟器过关作为上线硬门禁」**
- 「**全链路都换 RL**」——风险不可控且无法单独回滚，倒逼**「只动重排，粗排保持监督模型」**
- 「**按固定单目标训练**」——业务目标一变就要重训，倒逼**「多目标加权，权重可调」**

### 6.3 某出行公司"**动态定价：三个目标互相冲突时怎么加权**"（2020-2024）

**背景（Why）**

该出行公司 2020 年面临**"供需实时变化，而定价策略无法实时适应"**：
- **供需在秒级变化**——**早晚高峰、天气突变、大型活动都会让供需在短时间内剧烈偏移，固定定价无法跟上**
- **三个目标互相冲突**——**平台收入、用户体验、司机收入三者不可能同时最优，固定权重必然会牺牲某一方**
- **环境非平稳**——**不同城市、不同时段、不同天气下的最优策略差异极大，一套参数无法覆盖**
- **新城市冷启动难**——**新城市没有任何历史数据，纯数据驱动的方法直接失效**

**触发点（What）**

2020 年起该出行公司把定价迁移到 **Contextual Bandit + 多目标 RL**（[案例公开材料 2020-2024]），目标：
- **订单匹配率提升**——供给与需求更有效匹配
- **用户与司机满意度不降**——不能靠单方面压价或抬价达成匹配
- **新城市快速起效**——不依赖本地历史数据

**详细做法（How）**

该出行公司动态定价 RL 的**5 大核心组件**：

1. **以（城市，时段，天气，供需）为上下文的定价决策（核心创新）**
   - 关键设计：**把定价倍数视为 Bandit 的动作，上下文包含城市、时段、天气、实时供需比、是否有大型活动**；模型在高维上下文下选择定价倍数
   - 关键能力：**同一套机制适配不同环境**——而不是为每个城市单独调参；这让"覆盖上百个城市"成为可能
   - 关键数字：**订单匹配率 +10%**
   - 关键示意：
     ```text
     三个目标互相冲突时，加权是唯一的选择（但权重必须显式）
       ✗ 只优化收入
         提高定价 → 短期收入上升
         → 司机不接单（或接了但体验差）、用户流失
         → 长期收入反而下降
       ✗ 只优化用户
         压低定价 → 用户满意
         → 司机供给退出 → 无车可打 → 用户更不满意
       ✓ 多目标加权（权重显式、按阶段可调）
         Reward = w1·平台收入 + w2·用户体验 + w3·司机收入
         关键点：
           ① 权重是业务决策，不是模型超参
           ② 不同阶段（拉新期 / 成熟期）权重不同
           ③ 任一目标的"底线"应当作为约束，而不是只进加权
       ────────────────────────────────────────────────
     为什么必须有底线约束：
         加权是可交换的 —— 只要权重不是无穷大，
         模型可以用"严重伤害某一方"去换取另一方的巨大提升
         → 对不可牺牲的目标（如安全、合规、司机基本收入）
           应当做成硬约束而非加权项
     ```

2. **多目标加权可调（核心）**
   - 关键设计：**平台收入 / 用户体验 / 司机收入三目标加权**，权重由业务方设定并可按阶段调整
   - 关键能力：**业务目标变化时机制可延续**——出行市场在不同阶段的核心矛盾不同（早期拉供给、成熟期平衡体验）
   - 关键数字：**满意度 +5%**

3. **在线学习满足低延迟（核心）**
   - 关键设计：**用支持在线学习的 Bandit 实现（如 VW）**，模型更新不依赖离线重训流程，单次决策延迟极低
   - 关键能力：**策略能跟得上环境变化**——供需模式是每天重复的，昨天的数据今天就用
   - 关键数字：**延迟 < 10ms**

4. **冷启动靠跨城市迁移（核心）**
   - 关键设计：**新城市借助其他相似城市的数据与城市 embedding 冷启动**，而不是从零开始
   - 关键能力：**新城市不必等数据积累**——纯本地数据驱动会让新城市在最初的几周表现很差，直接影响开城效果
   - 关键数字：**新城市冷启动 < 1 周**

5. **统一平台承载多城市独立策略（核心创新）**
   - 关键设计：**训练 / 部署 / 实验 / 监控一体化**，各城市策略可独立迭代但共用平台
   - 关键能力：**上百城市的策略可被管理**——如果每个城市都是一套独立流程，运维成本会指数上升
   - 关键数字：**覆盖 100+ 城市**

**该出行公司动态定价关键数字**（[案例公开材料 2020-2024]）：

| 指标 | 改前（固定定价） | 改后 | 提升 |
| --- | --- | --- | --- |
| **订单匹配率** | 基线 | +10% | **+10%** |
| **用户 / 司机满意度** | 基线 | +5% | **+5%** |
| **目标处理方式** | 隐式偏向收入 | 显式三目标加权 + 硬约束 | **不牺牲任一方** |
| **决策延迟** | — | < 10ms | **可满足实时** |
| **环境适配** | 一套参数 | 高维上下文自适应 | **多城市适用** |
| **新城市冷启动** | 依赖本地数据积累 | 跨城市迁移 + 城市 embedding | **< 1 周** |
| **策略管理** | 城市各自为政 | 统一平台承载 | **100+ 城市可行** |
| **权重调整** | 改代码 | 业务可调 | **可随阶段变化** |

**具体数字（How much）**

- 团队规模：该出行公司定价 RL 相关团队 30+ 人
- 关键数字：**匹配 +10%**；**满意度 +5%**；**延迟 < 10ms**；**覆盖 100+ 城市**
- 业务影响：在高维上下文下实时定价，同时不让任一参与方被系统性牺牲

**失败教训**

- 早期「**固定定价**」——无法适应秒级供需变化，倒逼**「以（城市/时段/天气/供需）为上下文的 Bandit 定价」**
- 「**只优化平台收入**」——司机不接单、用户流失，长期收入反而下降，倒逼**「三目标加权并把权重交给业务方」**
- 「**把不可牺牲的目标也放进加权**」——模型用极端手段换取另一目标的高提升，倒逼**「对底线目标改为硬约束」**
- 「**新城市从零开始训练**」——开城初期体验很差，倒逼**「跨城市迁移 + 城市 embedding」**
- 「**每个城市维护独立流程**」——运维成本随城市数上升，倒逼**「统一平台承载，策略独立但流程共用」**

### 6.4 某银行"**反欺诈：奖励函数里的非对称代价**"（2020-2024）

**背景（Why）**

该银行 2020 年面临**"对手会主动适配，而模型上线即开始过期"**：
- **黑产快速适配**——**监督模型上线后，对手会在一周左右摸清模式并绕过**
- **静态规则被摸清即失效**——**规则越明确，被绕过的成本越低**
- **被动等样本来不及**——**等新欺诈模式积累出足够样本再训练，损失已经发生**
- **误报的代价被低估**——**把正常交易拦下来会直接伤害客户体验，而这类成本往往不计入模型指标**

**触发点（What）**

2020 年起该银行把反欺诈决策迁移到 **Contextual Bandit + 在线学习**（[案例公开材料 2020-2024]），目标：
- **欺诈召回提升**——不漏掉该拦的
- **误报不上升**——不能靠多拦截刷召回
- **对手适配周期拉长**——从周级到月级

**详细做法（How）**

该银行反欺诈 RL 的**5 大核心组件**：

1. **非对称奖励：把"放行错了"和"拦截错了"的成本显式区分（核心创新）**
   - 关键设计：**奖励函数对不同类型的错误给出不同量级的惩罚**——放行一笔真实欺诈的代价，远大于误拦一笔正常交易；"转人工审"作为中间动作，用人力成本换取确定性
   - 关键能力：**模型不会靠"多拦"刷指标**——如果两类错误的惩罚对称，模型必然倾向于多拦截（因为拦截能保证"不漏"），代价全部转嫁给正常用户
   - 关键数字：**欺诈召回 +20%、误报 -30%**
   - 关键示意：
     ```text
     为什么反欺诈的奖励必须非对称（否则模型必然跑偏）
       设：放行 × 正常 → +1
       若两类错误惩罚对称：
         放行 × 欺诈 → −1
         拦截 × 正常 → −1
         → 模型的最优解是"不拦也不放那笔最不确定的"，
           而当必须二选一时，偏向"拦截"（因为拦截确定"不漏"）
         → 结果：召回看起来很高，但误报率同步爆炸
       ✓ 非对称奖励（成本按业务损失标定）
         放行 × 正常  → +1
         放行 × 欺诈  → −C_fraud   （C_fraud 远大于 1）
         拦截 × 正常  → −C_fp      （真实存在、不可忽略）
         转人工审     → 中间成本   （用人力换确定性）
       ────────────────────────────────────────────────
     关键：C_fraud 与 C_fp 的比值是业务决策，不是超参
           它应当由"一笔欺诈的损失"与"一次误拦的损失"标定
     ```

2. **三动作设计：放行 / 转人工审 / 拦截（核心）**
   - 关键设计：**动作空间包含"转人工审"**，而不是只有"过 / 不过"二选一
   - 关键能力：**不确定性有出口**——对模型不确定的交易，用人力成本换取确定性，比强行二选一好
   - 关键性质：**人工审的量可控且集中在高不确定样本**

3. **离线模拟器作为上线前置门禁（核心）**
   - 关键设计：**用历史交易回放模拟不同策略的结果**，达标才允许上线上实验
   - 关键能力：**避免大规模误拦**——反欺诈策略出错的代价是"大量正常客户被拦"，影响面大且恢复慢
   - 关键数字：**模拟器与线上吻合 90%+**

4. **在线学习让策略跟上对手（核心）**
   - 关键设计：**交易 → 实时特征 → 决策 → 真实结果回流 → 秒级更新**，黑产改手法后策略在小时级重新适配
   - 关键能力：**对抗周期被拉长**——从"一被绕过就失效"变成"需要更长时间才能摸清"
   - 关键数字：**对抗周期从周级拉长到月级**

5. **多目标平衡召回与体验（核心）**
   - 关键设计：**召回 / 误报 / 用户体验三目标同时进入目标函数**，且硬性限制误报上限
   - 关键能力：**不让"提升召回"以牺牲客户体验为代价**——这在被监管的行业里是底线要求
   - 关键性质：**多目标综合提升**

**该银行反欺诈 RL 关键数字**（[案例公开材料 2020-2024]）：

| 指标 | 改前（监督模型） | 改后 | 提升 |
| --- | --- | --- | --- |
| **欺诈召回** | 基线 | +20% | **+20%** |
| **误报率** | 基线 | -30% | **-30%** |
| **奖励函数** | 两类错误对称 | 按业务损失非对称标定 | **不靠多拦刷分** |
| **动作空间** | 过 / 不过 | 放行 / 转人工审 / 拦截 | **不确定性有出口** |
| **对手适配周期** | 约一周 | 约一个月 | **拉长** |
| **策略更新** | 离线重训 | 在线秒级更新 | **跟得上对手** |
| **上线前置** | 直接上实验 | 离线模拟器门禁 | **避免大规模误拦** |
| **损失规模** | 基线 | 年减损数亿量级 | **显著** |

**具体数字（How much）**

- 团队规模：该银行反欺诈 RL 相关团队 20+ 人
- 关键数字：**欺诈召回 +20%**；**误报 -30%**；**对抗周期月级**；**模拟器吻合 90%+**
- 业务影响：在对手主动适配的对抗环境中保持召回，同时不以误拦为代价

**失败教训**

- 早期「**用监督模型 + 静态规则**」——被对手摸清后一周即失效，倒逼**「改为持续探索的 RL 策略」**
- 「**两类错误的惩罚对称**」——模型靠多拦截刷召回，客户体验明显下降，倒逼**「按业务损失标定非对称奖励」**
- 「**动作空间只有过 / 不过**」——不确定的样本被迫二选一，倒逼**「加入"转人工审"作为中间动作」**
- 「**没有模拟器就直接上实验**」——出现过一次较大规模的误拦，倒逼**「模拟器过关 + 灰度 + 人工审核兜底」**
- 「**把误报当作次要指标**」——短期召回上去了，长期客户流失，倒逼**「把误报上限做成硬约束」**

### 6.5 真实落地路径（基于上述 4 个案例提炼）

**0 → 1 阶段：3-6 个月**

- 选「**Contextual Bandit + 明确的奖励函数**」（**最简单**）——**1 个业务场景**
- 产出：**奖励函数定义（含各项目标的成本 / 收益标定）+ 保守开局的探索方案 + 延迟预算**
- 团队：**2-3 人**
- 验证标准：**奖励函数能对齐 1 个明确的业务指标**、**探索比例从低起步**、**单次决策延迟满足业务约束**、**两类错误的代价被显式区分**

**1 → 10 阶段：6-12 个月**

- 扩展到「**10+ 场景 / 连续动作**」
- 引入「**深度 RL（PPO 类）**」——连续动作空间 + 长期价值
- 引入「**在线学习（低延迟）**」——让策略跟得上环境变化
- 团队：5-10 人
- 验证标准：**业务指标有可归因的提升**、**策略更新不引起剧烈震荡**、**在线更新延迟进入毫秒级**

**10 → 100 阶段：12-24 个月**

- 扩展到「**100+ 场景 / 多目标**」
- 引入「**多目标加权（权重可调）**」+「**对底线目标改为硬约束**」
- 引入「**离线模拟器作为上线硬门禁**」——这是避免大规模事故的关键
- 团队：10-30 人
- 验证标准：**模拟器与线上吻合 ≥ 90%**、**任一目标都不被系统性牺牲**、**冷启动场景有明确方案**

**100 → 1000 阶段：12-24 个月**

- 引入「**统一训练 / 部署 / 实验 / 监控平台**」——让大量场景的策略可被管理
- 引入「**在线学习 + 实时对抗**」——在对抗型场景中把适配周期拉长
- 引入「**全链路风险分层**」——把 RL 限制在链路末端可控位置
- 团队：30-100 人
- 验证标准：**训练到部署进入天级**、**对抗周期从周级拉长到月级**、**策略问题可单独回滚**

> - 4 个真实案例（电商广告 / 短视频重排 / 出行定价 / 银行反欺诈）印证：**RL 不是「跑个 DQN」，是「Contextual Bandit 起步 + 奖励函数对齐业务 + 多目标与硬约束 + 离线模拟器门禁 + 保守探索与在线学习」5 件套**。
> - 关键时间线：5+ 年 / 5+ 年 / 4+ 年 / 4+ 年 —— **RL 是长期工程**，且**它最关键的一步是"奖励函数怎么定"**——奖励定错，模型越强危害越大。
> - 选型第一原则：「**Contextual Bandit + 明确奖励函数**」（**最简单**）→ 「**深度 RL + 在线学习**」（**必须**）→ 「**多目标加权 + 硬约束 + 离线模拟器门禁**」（**生产**）→ 「**统一平台 + 实时对抗 + 链路末端分层**」（**AI 时代**）。
> - 99% 的失败来自「**探索过激 + 奖励单一/错误 + 没有模拟器 + 全链路替换**」——必须有 **保守探索 + 多目标与约束 + 模拟器门禁 + 只动末端可回滚**。
> - 真正的 ROI 来自「**eCPM +15% / GMV +8% / 匹配 +10% / 召回 +20% 且误报 -30%**」——是**"短期指标饱和之后还能找到增量"的分水岭**。
