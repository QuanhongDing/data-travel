> **本节小结**：
> - 4 个真实案例（字节 / Uber / Netflix / 美团）印证：**查询引擎不是「**默认配置**」，是「**Trino + Iceberg + Doris / Pinot + 30+ connector + 多业务**」**5 件套**。
> - 关键时间线：字节 6+ 年 / Uber 4+ 年 / Netflix 5+ 年 / 美团 4+ 年 —— **查询引擎是 4+ 年长期工程**。
> - 选型第一原则：「**Trino 起步**」（**最简单**）——**1 个业务** → 「**Iceberg 数据湖 + Doris / Pinot**」（**必须**）→ 「**5+ 业务统一 + 4 Region**」（**生产**）→ 「**2 亿+ 用户 + 全球**」（**AI 时代**）。
> - 99% 的失败来自「**Presto 慢 + 跨源弱 + EB 级撑不住 + 多业务不一致**」——必须有 **Trino + 30+ connector + Iceberg + 4-5 业务统一**。
> - 真正的 ROI 来自「**千亿级 + P99 < 3s + 2 亿+ 用户**」——是**大厂核心查询引擎基础设施的命脉**。
