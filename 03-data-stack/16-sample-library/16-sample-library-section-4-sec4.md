## 4. 工程实现

### 4.1 落地步骤

这一块有一条与其它主题不同的性质：**它的第一个交付物是"一份样本的元数据字段表"，而不是一个平台**——因为**没有这五个字段（时点 / 来源 / 快照 / 切分 / 血缘），后面的机制都无处挂**。

**Step 1：定样本的元数据字段（先做这个）**
把 `event_time` / `label_source` / `snapshot_id` / `split` / `lineage` 五个字段写进样本表结构。**判据**：抽一条样本，能否回答"它当时看到了什么、谁标的、属于哪一版、在哪个切分里"。**为什么第一步是它**：它是一张表的改动，而**它是后面所有机制（回填、切分、污染检查）的挂载点**；晚做则存量样本要批量补元数据，而有些元数据**当时没记就永远补不回来**（谁标的、当时的口径版本）。

**Step 2：把特征回填做成唯一入口的脚本**
回填脚本读 `(entity, event_time)`，按 `feature_ts <= event_time` 取截至那一刻的值。**判据**：全库搜索还有没有别的地方在 JOIN 特征表做样本组装（有 = 穿越的入口存在）。

**Step 3：跑三种泄漏检测**
实体交集、时间边界、跨集近重复。**判据**：三种各返回 0。**若第一版就发现泄漏**（很常见），先修切分再谈模型。

**Step 4：定切分规则 + 快照 + 种子**
三种切分按业务选一种写死；评测集**随机抽样**（与训练集来源分开）；快照 id 与种子一同记录。**判据**：同一次评测能用同一个快照复现。

**Step 5：把标注口径做成任务配置**
输入展示 + 判定问题 + 取值域 + **3–5 个边界案例** + 审核规则。**判据**：新标注者不看别人的口头说明，能独立开工。

**Step 6：算一次一致性（κ 与分歧分布）**
抽样重复标注。**判据**：分歧**集中在少数几类**上——集中则补边界案例，均匀则缩小任务范围。

**Step 7：能规则化的先规则化**
写标注函数（**带弃权**）+ 留出集估权重；剩下的才给人工。**判据**：标注预算里"其实规则能判"的比例接近零。

**Step 8：污染检查 + 数据来源台账**
跨集近重复比对、来源语料比对、**逐个来源登记"它可能包含什么"**。**判据**：能回答"某个公开语料里有没有我们的评测题"。

**顺序的反面（最常见的错误）**：**先扩样本量、后建元数据**——扩量之后存量样本缺元数据，而**"谁标的、当时口径是什么版本"这类字段是事后补不回来的**（只能标成"未知"，而"未知"在评测时不能被信任）。**第二条反面**：**先做主动学习、后做切分与污染检查**——主动学习会产出**分布偏移的训练集**，若评测集也偏移（用了主动学习样本），结论会同时受两个偏差影响，且**无法分离**。

### 4.2 关键技术点

**（1）样本表的最小字段集**

```yaml
sample:
  sample_id: s_9f31…
  entity: {type: user, id: u_1024}          # 依赖 OneID，否则同一人样本会分裂
  event_time: "2024-06-01T10:23:11+08:00"   # 特征只能看这一刻之前 —— 全表的锚
  features_ref: {store: "offline", version: "ds=2024-06-01"}   # 引用，不是值本身
  label: {value: 1, confidence: 0.9}        # 弱监督给概率，人工给 1.0
  label_source: weak_multi                  # human | rule | weak_multi | model_review | online_feedback
  label_meta: {annotators: [a1, a2], kappa: 0.78, guideline_version: g3, reviewed_by: r7}
  snapshot_id: snap_2024w23                 # 切分与评测都绑它
  split: train                              # train | valid | test | online_eval
  lineage: {upstream: [...], feature_versions: {...}, exposure_policy: null}
判据：一条样本能否只靠这些字段被复现 —— 不能，说明还缺字段
```

**（2）一致性度量与分歧定位**

```python
# 抽样重复标注 → κ + 分歧分布（本主题最便宜的一次诊断）
import pandas as pd
from sklearn.metrics import cohen_kappa_score

def diagnose(dup: pd.DataFrame) -> dict:
    """dup: (sample_id, annotator, label, label_class)"""
    piv = dup.pivot_table(index="sample_id", columns="annotator",
                          values="label", aggfunc="first")
    pairs = piv.dropna()
    # ① 整体一致性：κ（而不是原始一致率 —— 后者含随机一致的部分）
    kappa = cohen_kappa_score(pairs.iloc[:, 0], pairs.iloc[:, 1])
    # ② 分歧分布：按"哪一类"聚合 —— 这一项比 κ 的数值更有用
    dis = pairs[pairs.iloc[:, 0] != pairs.iloc[:, 1]]
    by_class = (dup[dup.sample_id.isin(dis.index)]
                .groupby("label_class").sample_id.nunique()
                .sort_values(ascending=False))
    # 读法：分歧集中在少数几类 ⇒ 补边界案例；均匀 ⇒ 任务定义有问题
    return {"kappa": round(kappa, 3), "disagreement_by_class": by_class.to_dict()}
```

**（3）点时回填的两种实现与它们的边界**

```text
实现 A：从特征历史表按 ts 取（灵活，适用跨度长）
  代价是历史保留期必须 ≥ 样本跨度 —— 保留期不够时老样本永远回填不出当时的值
实现 B：从特征快照表按 ds 取（快，适用跨度短、且特征已按天快照）
  代价是快照粒度决定时点精度（按天快照时，同一天内的时点差异被抹平）
判据：写清用哪一种、以及它在你样本跨度上的失效边界；
      两种混用时，同一条样本可能回填出两个值（而没人知道为什么）
```

**（4）三种泄漏检测脚本（各返回 0 才算通过）**

```sql
-- ① 实体泄漏：同一实体的样本跨集出现
SELECT entity_id FROM samples GROUP BY entity_id
HAVING COUNT(DISTINCT split) > 1;         -- 期望 0 行（若业务允许多样本/实体的随机切分例外）

-- ② 时间泄漏：训练集的时间范围与测试集交错
SELECT MAX(event_time) AS max_train FROM samples WHERE split='train';   -- 应 ≤
SELECT MIN(event_time) AS min_test  FROM samples WHERE split='test';    -- 这一行

-- ③ 近重复泄漏：跨集相似度超阈值（用向量近似 + 抽样）
--    SELECT a.sample_id, b.sample_id, sim(a.embedding, b.embedding) AS s
--    FROM samples a JOIN samples b ON a.split='train' AND b.split='test'
--    WHERE s > 0.95;                     -- 期望 0 行
判据：三个脚本都在 CI 里跑，且失败即阻断 —— 泄漏不是"注意一下"，是"不许发布"
```

**（5）污染检查的三件与它们各自的盲区**

| 检查 | 能发现 | 发现不了 |
| --- | --- | --- |
| 跨集近重复比对 | 训练集里**直接出现**的评测样本 | 经过改写的版本；间接混入 |
| 来源语料比对 | 评测集的**来源文档**出现在训练数据里 | 来源语料是黑箱下载时的内部内容 |
| **数据来源台账** | 上面两件都发现不了的**间接污染** | 台账没登记的来源 |

**判据**：**三件都要有**——前两件是机械检查（便宜、可自动），第三件是流程约束（靠人登记，而它是唯一能挡间接污染的一件）。

**（6）合成数据与评测集的分区隔离**

```text
合成数据（模型生成、增广、改写）与评测集必须来自不同的数据分区
  原因：用含评测题的语料做合成 ⇒ 合成样本带着评测题进入训练集
        而它**不是近重复**（经过改写），因此比对检查发现不了
  做法：① 合成流程的输入语料与评测集的来源语料**物理分开**（不同目录 / 不同快照）
        ② 合成产出登记进"数据来源台账"，标注"由哪些语料生成"
判据：合成流程能不能读到评测集的来源分区 —— 能读到，就存在自证风险
```

### 4.3 工具链与平台

| 能力 | 自建 / 开源 | 产品化 | 选型要点 |
| --- | --- | --- | --- |
| 标注平台 | Label Studio / Argilla / Doccano | 商业标注平台 | 看**任务配置是否支持边界案例**与**一致性计算** |
| 弱监督 | Snorkel 一类 | 标注服务平台 | 看**函数能否弃权**与聚合权重是否可估 |
| 样本存储与血缘 | 自建（数仓表 + 血缘采集） | 数据目录 / ML 平台 | 看**能不能导出**样本元数据（锁死则迁移代价高） |
| 特征回填 | 自建（小时点连接 SQL） | 特征平台自带 | 看**历史保留期**与**时点精度**（这是硬约束） |
| 切分与快照 | 自建（脚本 + 快照表） | ML 平台 | 看**三种泄漏检测是否内置**，只做一种的不够 |
| 污染检查 | 自建（向量近似 + 抽样） | 评测平台 | 看**是否含来源台账**（多数只做近重复比对） |
| 漂移监控 | 复用质量平台（[Ch11 §01](../../11-cross-cutting/01-data-quality/01-data-quality.md)） | 监控产品 | 看是否**同时覆盖特征侧 / 标签侧 / 关系侧** |

**一条选型原则**：**回填与切分的归属比标注工具的易用性重要**。标注工具不好用只影响效率，而**回填与切分做错了会让全部结论失效**——而这两件通常是自建的（它们要接你自己的特征平台与数仓）。**因此选型时的第一问是"回填与切分我能不能自己掌控"，而不是"标注界面好不好用"。**

### 4.4 存量迁移

**（1）存量样本集怎么办**

| 对象 | 处理 | 注意 |
| --- | --- | --- |
| 散在各人手里的 CSV / 表格 | 收进样本库 → **补元数据（能补的补，不能补的标"未知"）** | **不要假装补全**：`event_time` 可以从数据里推，**"谁标的、当时口径版本"推不出来** |
| 已经用于训练的样本 | 按新规则重新切分 → **重跑泄漏检测** | 重新切分会让历史结果不可比（**先留一份旧切分的快照**） |
| 评测集 | **优先做污染检查**（它最容易有问题） | 评测集一旦被污染，**此前所有结论都要打折** |
| 特征回填的历史脚本 | 收进唯一入口脚本 | 差异处（有的人用最新值）逐个核对 |
| 标注口径（若还找得到） | 写成版本化文档 + 边界案例 | 找不到的口径 ⇒ 那批样本标为"口径未知" |

**（2）迁移的三条验收判据**

- **三种泄漏检测各返回 0**。
- **回填只有唯一入口**（全库搜索无第二处 JOIN）。
- **评测集有随机抽样记录与污染检查结果**。

```text
| Owner | growth-algo@ |

| 来源构成 | 弱监督 62%（7 个标注函数）· 人工 28% · 回流 10%（绑曝光策略 v12） |
| 特征回填 | 唯一入口 backfill.py；连接条件 feature_ts <= event_time |
| 切分 | 按时间：train ≤ 2024-05-31；test ≥ 2024-06-01（种子 42） |
| 泄漏检测 | 实体 0 · 时间 0 · 近重复 0（最近一次 2024-06-03） |
| 污染检查 | 跨集近重复 0 · 来源语料 0 · 台账已登记 4 个来源（最近一次 2024-06-03） |
| 已知边界 | 新用户（注册 < 7 天）样本极少，模型在该子群上未评估 |
判据：这张卡能回答"它能用在哪、不能用在哪、结论可信到什么程度"
```

**模板 2：一次投产前的检查清单（可勾选）**

```text
[ ] 五种元数据字段齐全（event_time / label_source / snapshot_id / split / lineage）
[ ] 特征回填走唯一入口，连接条件含 ts <= event_time
[ ] 三种泄漏检测各返回 0（附运行记录）
[ ] 评测集为随机抽样，且与训练集来源分开
[ ] 污染检查三件跑过（含来源台账登记）
[ ] 合成数据与评测集分区隔离
[ ] 标注口径有版本与边界案例；κ 与分歧分布有记录
[ ] 漂移监控覆盖特征侧 / 标签侧 / 关系侧
[ ] 快照 id 与随机种子写入实验记录
判据：任一项未勾选 ⇒ 本次结论标注"带保留发布"，而不是"已通过"
```

**模板 3：漂移监控的三个轴（分桶看命中率）**

```text
| 轴 | 指标 | 阈值动作 |
| --- | --- | --- |
| 特征侧 P(X) | 关键特征 PSI | 超阈值 ⇒ 查上游数据变更，考虑重训 |
| 标签侧 P(Y) | 正例率 | 超阈值 ⇒ 查业务季节性 or 口径漂移，**先分清这两者** |
| 关系侧 P(Y|X) | 按特征分桶的命中率 | 某桶命中率显著下降 ⇒ **最有价值的信号**（X 没变而关系变了） |
判据：只看前两轴会漏掉"关系变了" —— 而它恰恰是"模型悄悄失效"的主因
```

### 4.6 成本：这套东西的账单

**硬件**：样本库本身几乎无专属硬件成本（元数据是行级存储，量级远小于明细数据）。三处与算力相关：① **特征回填**（按历史时点取值的查询比读最新值重，长跨度样本尤其）；② **跨集近重复比对**（向量近似 + 抽样，可弹性）；③ **主动学习的重训迭代**（每轮一次训练）。

**标注人力是本主题的成本主项**，且它是**唯一无法自动化的一项**：

```
标注成本 ≈ 样本数 × 单条标注时长 × 标注人数 / 复用率
  其中"单条标注时长"由任务复杂度决定（判断类 vs 确认类差数倍）
  而"复用率"由主动学习 / 弱监督提升

判据：先量"单条时长"与"能规则化的比例"这两个数 ——
      它们比"要标多少条"更能决定预算，而两者都可以在第一天测出来
```

**样本的第二个成本是它在时间上的衰减**：

```
样本的有效期 ≈ min(业务口径稳定期, 分布稳定期)
判据：样本不是"标完就一直能用" —— 一年前的样本在今天的分布上可能已失效，
      而失效是静默的（不报错，只是效果慢慢差）。
      因此"重标 / 增补"应当被算进常态预算，而不是当成一次性项目。
```

**人力（三项）**：① **标注**（可被弱监督 / 主动学习削减，但**边界样本永远要人**）；② **口径维护**（写边界案例、裁分歧、更新版本，**成本随任务数增长**）；③ **治理**（回填脚本、切分与快照、泄漏与污染检查的维护）。

**一条推论**：**本主题的成本是"标注人力 + 口径维护"，且样本本身在衰减**——因此**"标得准"比"标得多"更值钱**，而**主动学习与弱监督的价值是把"多"换成"准 + 省"**。这也解释了为什么 §4.1 的 Step 1 是元数据而不是标注：**元数据没有标注成本，而它决定后面所有的可信度。**

### 4.7 容灾与故障演练

**本主题的"灾"分两类**：① **样本库不可用**（训练与评测停摆——影响可见，可等待）；② **样本静默失效**（分布漂了、口径漂了、污染进来了——**训练照常、评测照常，只是结论不再可信**）。

| 失效形态 | 影响面 | 降级策略 | 演练动作 | 恢复目标 |
| --- | --- | --- | --- | --- |
| 样本库不可用 | 训练 / 评测中断 | **用最近快照只读**；不允许"用临时拼的数据凑一次训练" | 关库，验证是否退到只读快照 | 小时级 |
| 特征历史保留期不足 | 老样本无法回填 | **显式报错**（不静默用最新值）；标注受影响样本区间 | 对超出保留期的样本发起回填，看是报错还是静默穿越 | 天级（需上游调保留期） |
| 标注平台不可用 | 新样本停止产出 | 已有快照继续可用；**不影响训练与评测** | 关平台，验证不影响既有快照 | 小时级 |
| **回填脚本被绕过** | 部分样本穿越 | 检测脚本查"连接条件"；受影响样本重灌 | 手工加一处直连特征的组装，看检测能否发现 | 天级 |
| 口径被误改 | 新样本标签含义变化 | 口径版本回滚 + 受影响样本重标 / 标注 | 故意改一处边界案例，验证能回滚并识别受影响范围 | 天级 |
| 评测集被污染 | 结论系统性乐观 | **即刻冻结该项结论**；重建评测集 | 人为把一条评测样本放进训练集，看污染检查是否报警 | 天级 |
| 来源台账缺失 | 间接污染无法判定 | 对未登记来源的数据**先隔离**再使用 | 引入一份未登记的公开语料，看流程是否阻断 | 天级 |
| 样本漂移 | 效果缓慢下降 | 监控告警 + 增补样本 + 重训 | 人为偏移一批特征分布，看漂移监控是否报警 | 天级 |

**这套演练的三条纪律**：

1. **凡是"对齐类"机制（回填 / 切分）被绕过，必须阻断发布**——它们不是"注意一下"的问题，而是**结论是否成立**的问题。
2. **老样本回填不出来时宁可报错，不许静默用最新值**——静默穿越会把"数据不可得"变成"指标虚高"，而后者更难发现。
3. **每次演练留"演练前 / 演练后"两组数字**——特别是三种泄漏检测的结果与样本分布的三轴指标。

### 4.8 演进路线：0 → 1 → 100

**0 → 1：元数据 + 唯一回填入口 + 三种泄漏检测**
- **这一步做什么**：五个元数据字段；回填脚本唯一入口（连接条件含时点约束）；三种泄漏检测各返回 0。
- **变贵的是什么**：**改动特征组装链路**——回填从"各人自己 JOIN"收成唯一入口，短期会拖慢既有流程。
- **先坏的是什么**：**先坏的是离线指标**——历史上用最新值回填时，把连接条件改对之后**指标会下降**。**这一阶段的判据不是"指标变好"，而是"指标变得可信"**（下降的那部分本来就是借来的）。

**1 → 10：口径、一致性、来源**
- **这一步做什么**：标注任务配置化（含边界案例）；κ 与分歧定位；弱监督 + 主动学习；污染检查三件；快照与切分规则写死。
- **变贵的是什么**：**口径维护与标注人力**（边界样本永远要人标）；以及**回填的历史保留期**要求（要推动上游延长）。
- **先坏的是什么**：**先坏的是"标注预算不够"**——一旦开始认真做一致性，你会发现难点样本的数量远超预期。因此这一阶段的重点是**先规则化能规则化的部分**（弱监督），把人力留给边界。

**10 → 100：治理与自服务**
- **这一步做什么**：样本集资产卡（模板 1）成为常态；来源台账随每个新数据源更新；漂移监控三轴；合成数据分区隔离；样本集作为资产在目录中登记。
- **变贵的是什么**：**治理的边际成本**——每加一个数据源、每加一个标注任务都要登记与复核。
- **先坏的是什么**：**先坏的是样本的时效性**——样本在衰减，而**重标/增补没有进入常态预算**时，团队会用一批一年前的样本反复训模型，并把效果下降归因为"业务变难了"。因此这一阶段的重点是**把"样本增补"算进常态预算**。

**贯穿三阶段的一件事**：**保留"三种泄漏检测 + 污染检查"的机械可执行**。它们是这一块唯一的健康基础——**样本库的腐化不会报错，只会让结论越来越乐观、而模型上线越来越差。**

### 4.9 自检清单

- [ ] 五个元数据字段（时点 / 来源 / 快照 / 切分 / 血缘）齐全吗？
- [ ] 特征回填走唯一入口吗？连接条件含 `feature_ts <= event_time` 吗？
- [ ] 全库还有别的地方在 JOIN 特征表做样本组装吗？
- [ ] 特征历史保留期 ≥ 样本跨度吗？超出时是报错还是静默用最新值？
- [ ] 三种泄漏检测（实体 / 时间 / 近重复）各返回 0 吗？在 CI 里阻断吗？
- [ ] 切分规则 + 快照 id + 随机种子三者一同记录吗？
- [ ] 评测集是随机抽样吗？与训练集来源物理分开吗？
- [ ] 污染检查三件都跑了吗？**来源台账**存在吗？
- [ ] 合成数据与评测集分区隔离了吗？合成流程能读到评测来源吗？
- [ ] 标注任务有 3–5 个边界案例吗？它们是真正分歧的地方吗？
- [ ] κ 与**分歧分布**都有记录吗？分歧集中在哪几类？
- [ ] 标注口径有版本、Owner 与最近一次更新记录吗？
- [ ] 弱监督函数有弃权档吗？聚合权重在留出集上估过吗？
- [ ] 主动学习是"边标边重训"吗？
- [ ] 预标注的修正比例与未修正批的抽检准确率都看了吗？
- [ ] 回流样本绑曝光策略版本了吗？
- [ ] 漂移监控覆盖三个轴（特征 / 标签 / 关系）吗？
- [ ] "样本增补"在常态预算里吗？

### 4.10 小结

> 本节小结：样本库的落地顺序**以"五个元数据字段"为先**——它没有标注成本，却决定后面所有的可信度；然后回填做成唯一入口（连接条件含时点约束）、跑三种泄漏检测、定切分与快照、把口径做成任务配置、算一致性并定位分歧、能规则化的先规则化、最后做污染检查与来源台账。**变贵的是标注人力与口径维护，而样本本身还在衰减**（§4.6）——因此**"标得准"比"标得多"更值钱**，且**样本增补应当算进常态预算**而不是一次性项目。**容灾有一条本主题特有的纪律**：**对齐类机制（回填 / 切分）被绕过必须阻断发布**；**老样本回填不出来时宁可报错，不许静默用最新值**（静默穿越会把"数据不可得"变成"指标虚高"，§4.7）。**三阶段的同一件事**：保留"泄漏与污染检测"的机械可执行——**这一块的腐化不会报错，只会让结论越来越乐观、而模型上线越来越差。**

> 💡 **思考锚点**：做一件今天就能验证的事——**把你的特征回填连接条件改成"只允许 `feature_ts <= event_time`"，然后重跑一次离线评测**。**如果指标明显下降，说明此前一直在穿越**（借用了未来信息），而那个下降的幅度就是你真实的水平。这个动作成本是改一个条件、跑一次评测；**它给出的数，比任何一次调参都重要**。
