#### §8.1 你们模型的离线指标比线上好一截，怎么排查？为什么"调模型"不是第一步？

**1. 考察点**
- 是否知道**特征穿越会让离线指标更好看**——因此它不会被任何指标暴露，反而会被当成"模型好"；
- 有没有**机械检查**的意识：把连接条件改成只允许 `feature_ts <= event_time` 重跑一次，看指标是否明显下降；
- 是否理解四类成因的**排除顺序**由"隐蔽性 × 影响面"决定，而不是由"哪个最容易查"决定；
- 知不知道处置前的**定性动作**：先分清是 bug 还是还账，再决定处置强度（记录 / 更正 / 重训）；
- 加分项：能说出穿越的**分布特征**（差异集中在"时点之后仍会变化的特征"上），并知道这条特征本身就是诊断依据。

**2. 参考答案框架**

**第一层：先给成因清单，再给排除顺序。** 四类成因：① **特征穿越**（回填用了 `event_time` 之后才产生的信息）；② **切分泄漏**（实体 / 时间 / 近重复，§2.2）；③ **训练与线上的一致性**（同一条特征在两条链路上的计算实现不同）；④ **评测集不代表线上分布**（非随机抽样，或用了主动学习样本）。**顺序是先查 ①，再查 ②③④**——依据不是"①最容易犯"，而是**①最不可观察**：②③④都会在某处留下可查的不一致（实体交集不为空、两侧实现对不上、抽样方式可查），而①的后果是"指标更好看"，系统里没有任何一处会为此报警。**这一层的失效条件**：当链路根本没有"当时值"可取（特征历史保留期短于样本跨度）时，①无法用"改对连接条件重跑"来验，只能退回"报错 + 标出受影响区间"（§4.7 的纪律：老样本回填不出来时宁可报错，不许静默用最新值）。

**第二层：穿越的机械检查。** 动作只有一个——**把回填的连接条件改成只允许 `feature_ts <= event_time`，重跑一次评测**；**指标明显下降 ⇒ 此前一直有穿越**。成本是改一处条件 + 跑一次评测，§4.2（3）的两种实现（按历史表取 ts、按快照表取 ds）都支持这个动作。两个附带动作让这条检查从"一次性"变"常态"：① **全库搜索还有没有第二处直接 JOIN 特征表做样本组装**——命中数应当只剩唯一入口脚本，这是穿越复发的根因（§6.3 的教训是"根因不是某个人写错，而是回填不是唯一入口"）；② **确认超出保留期的样本是报错还是静默取最新值**。**这一层的失效条件**：回填不是唯一入口时，改对一处并不解决问题——只要存在第二条组装路径，它就会在下一次赶工期里用最新值。

**第三层：为什么它最难发现（这是性质，不是现象）。** **穿越的性质是"让离线指标更好看"**——所以它不会被任何指标暴露，反而会被当成"模型好"，于是团队继续在这个虚高的基准上做选型、调参、扩量（§3.2.6）。**唯一能发现它的方式是检查连接条件本身，而不是看指标。**这一点决定了它与②③④的处置差别：②③④属于"发现后要修"，①属于"不检查就永远不知道"——**后者没有任何自然的发现时机**。

**第四层：诊断的分布特征。** 差异**集中在"时点之后仍会变化的特征"上**：窗口类特征（如"最近 7 天消费额"，在 `event_time` 之后仍在变化）差异最大，快照类特征（如注册渠道）几乎不受影响（§6.3，【经验：穿越幅度随特征的变化频率上升】）。**这条分布本身就是"是 bug 还是还账"的定性依据**——如果是 bug，差异会集中在少数特征上且分布异常；如果是穿越，差异与"特征的变化频率"正相关。**这一步必须在改代码之前做完**，否则会先花时间在"回滚改造"上。**这一层的失效条件**：样本里几乎全是快照类特征时，穿越幅度会小到测不出来——那不是"没有穿越"，而是这条链路本来就不借未来信息。

**第五层：处置与解释（处置强度按"影响的是选择依据还是模型能力"分）。** ① **受影响的历史结论做标注，不必全部重训**——穿越影响的是"当时的选择依据"，不是"模型现在的能力"；② **但对外承诺过的指标要更正**；③ **把"当时值"与"现在值"两条读路径显式分开**（训练侧按 `event_time` 取历史版本、线上打分取当前最新值），否则同一条样本会回填出两个值而没人知道为什么（§6.3 第⑤步）。**向业务解释的成本往往高于改造本身**——同一份指标，改造前叫"我们的模型很好"，改造后叫"我们此前的好是借来的"；把这句话提前到立项时说清，才是这一层的真正难点。**这一层的失效条件**：若这块模型从未对外发布过指标，处置可退化成"内部记录一条"，成本大幅下降。

**3. 常见陷阱**
- **直接开始调模型 / 扩样本**：这看起来对，因为"效果不好"的默认解释就是"模型不够好"；但更多样本只会把虚高基准变得更稳定——**更多样本让错误结论更"显著"**（§5.7 第 5 条）。
- **只答"做交叉验证"**：交叉验证查的是泛化，而穿越是**信息集**问题——它在任何切分方式下都存在，交叉验证在原理上发现不了。
- **把"离线好"当成模型好的证据**：这正是穿越能存活三年的原因（§6.3 的失败教训）——**它恰好是穿越的症状，不是反证**。
- **不知道要检查连接条件**：把排查当成"找一个更好的指标"，而这条错误的可发现性不在指标侧，在**代码与配置**侧。
- **看到指标下降就回滚改造**：把"还账"读成"改造引入 bug"，于是把唯一一次改正的机会退回去（§6.3 第①步：先定性、再决定处置）。

**4. 追问预测**
- "怎么量穿越的幅度？"（答：同一批样本在两种口径下的指标差；**按特征族拆开给分布**，而不只给一个总差——总差只给幅度，"哪一类结论受影响最大"才是对外沟通的输入）
- "穿越幅度已知后，此前的模型结论怎么办？"（答：受影响结论做标注、不必全部重训，但对外承诺过的指标要更正；先列一张"受影响的历史结论清单"，并标出其中哪些对外发布过）
- "特征历史保留期不够，老样本回填不出来怎么办？"（答：显式报错而不是静默取最新值；把"保留期 ≥ 样本跨度"当作上游硬约束去谈，并在样本集资产卡上标出受影响区间，§4.7 的演练动作就是"对超出保留期的样本发起回填，看是报错还是静默穿越"）
- "训练与线上的特征计算实现在两侧不同，怎么发现？"（答：这是第③类成因——比对两侧对同一 `(entity, event_time)` 的输出，而不是比对指标；它不会表现为固定方向的"离线好线上差"，方向取决于哪一侧算错）
- "怎么防止它复发？"（答：唯一入口 + CI 里三条检查——全库 JOIN 命中数为 1、连接条件含时点约束、每条样本都有 `event_time` 与特征版本引用）

**5. 参考资料**

#### §8.2 训练集与测试集怎么切？有哪几种泄漏、各怎么检测？

**1. 考察点**
- 是否知道**三种泄漏**（实体 / 时间 / 近重复），而不是只知道"随机切分"；
- 有没有"三种检测各跑一次、各返回 0，且进 CI 失败即阻断"的实践；
- 知不知道按主体重复时随机切分必然产生实体泄漏，而**这是切分方式的第一分水岭**；
- 有没有意识到**评测集的抽样方式**（随机 vs 主动学习）本身就是切分问题的一部分；
- 加分项：能说清"可复现"要求的三件套（切分规则 + 随机种子 + 快照 id），并知道重切之后旧快照必须保留。

**2. 参考答案框架**

**第一层：先问"一个主体会不会贡献多条样本"。** 会 → **必须按实体切分**（同一实体的样本全在同一侧）；不会 → 随机切分合法。判据不是样本量大小，而是**"一个实体在样本里出现几次"的分布**：全为一，随机切分合法；出现多次，随机切分必然泄漏。**这条判据有一个前置**：实体标识必须可靠——OneID 不统一时按实体切分会切错（同一个人被当成两个，于是"实体不同侧"的检查返回 0，却并不代表安全）。**这一层的失效条件**：主体确实重复而实体标识不可靠时，正确动作是先修实体标识，而不是先改切分脚本。

**第二层：给出三种泄漏与各自的检测。**

```text
① 实体泄漏：同一实体跨集出现 —— 按 entity 求交集，期望空集
② 时间泄漏：训练集与测试集时间交错 —— 期望 max(train.event_time) ≤ min(test.event_time)
③ 近重复泄漏：同一内容以不同形式跨集 —— 跨集相似度超阈值，期望零对
判据：三种都要有检测脚本，且都在 CI 里阻断（失败即阻断，不是"注意一下"）
```

**三者的性质不同**：①与②可以用一条 SQL 判死（集合与边界），③必须用向量近似 + 抽样——精确比对的计算量随"两组样本数的乘积"增长，规模一上来就不可行（§7.4 的第二条量级推导）。**这一层的失效条件**：③的阈值是相似度阈值，**改写程度高的重复落在阈值之下**——所以"近重复返回 0"不等于"没有重复内容"，它只保证没有**近**重复；这条盲区在污染检查里同样存在（§8.5）。

**第三层："按时间切分"的取舍，以及为什么评测集必须另抽。** 按时间切分最贴近线上（测试集是"未来"），且**天然防时间泄漏**；代价是测试集只能是最近一段、样本量可能不足，而样本少会让指标的置信区间变宽，容易把噪声读成提升。**另一件容易被混进切分问题的事是评测集的抽样方式**：训练集可以来自主动学习样本，**评测集必须随机抽样且与训练集来源分开**——用主动学习样本做评测，等于"用边界样本评一个为边界优化的模型"（§8.6）。**这一层的失效条件**：当线上分布本身在快速漂移时，按时间切分的测试集反而更贴线上，"随机切分 = 同分布"这个前提不再成立。

**第四层：可复现要求（三件套）。** **切分规则 + 随机种子 + 快照 id 三者一起记录**——否则同一次评测不可复现，而"结论不可复现"等于"结论不可比"。**重新切分时要先留一份旧切分快照**（§4.4）：重切会让历史结果不可比，而"当时那一版切分长什么样"只有在旧快照里还找得到。**这一层的失效条件**：若团队只看单次指标、从不比较历史数字，快照的收益会变小——但只要有一次对外结论需要回溯，它就是唯一依据。

**第五层：第四件东西——把检测写进 CI。** 三种检测的价值不在"跑过"，而在**失败即阻断**（§4.2（4））：它们属于对齐类机制，**被绕过必须阻断发布**（§4.7 的纪律①）。工程上还有一步常被漏掉——**检测脚本自身要随表结构一同维护**：表结构改了而脚本没跟着改，会出现"检测在跑、但查的是一个不再被写入的字段"的假安慰。**判据**：抽一次运行记录，看最近几次的返回行数是不是都为 0，以及那几次跑的是不是当前的表结构。

**3. 常见陷阱**
- **只答"随机切分"**：在主体不重复时它是正确的，因此听起来没问题；但主体重复的业务里它**必然**产出实体泄漏，而结果会更好看——于是没人怀疑。
- **只做实体检测**：实体交集为 0 会给人一种"切分已经做对了"的确认感，而时间交错与近重复仍在漏——这是最常见的半成品。
- **切分不留种子与快照**：看起来只是"少记两个字段"，代价是换一版样本集之后，此前结论与现在结论不可比。
- **不区分"实体可重复"与"不可重复"的业务**：按实体切分在主体不重复的业务上是多余约束（会无谓损失样本量），照抄别人的切分脚本就会犯这个错。
- **把"近重复返回 0"当成"没有重复"**：阈值以下还有改写形态的重复，而它恰恰是污染检查里最难发现的那一类（§8.5）。

**4. 追问预测**
- "按时间切分导致测试集样本太少怎么办？"（答：先看能不能扩大时间窗口，而不是改用随机切分——随机切分会引入时间泄漏；若样本量确实不够，就把置信区间明确写出来，不要拿小测试集的点估计当结论）
- "近重复的阈值怎么定？"（答：用一批已知重复对做校准，看阈值取在哪一档时误判与漏判都可接受；**并且要承认阈值越高漏得越多**，所以这条检查必须与来源台账配套）
- "重新切分之后，历史结果怎么处理？"（答：留旧快照、历史结果标注"含旧切分泄漏"，不追溯改写——同 §6.4 的处理纪律：不追溯改写，但必须知道哪些结论要打折）
- "OneID 不统一时，按实体切分会怎样？"（答：会切错——两个标识下的人其实是同一个人，"实体不同侧"的检查返回 0 而实际仍在泄漏；先修实体标识再谈切分）
- "评测集的抽样方式要不要单独检查？"（答：要——评测集必须是随机抽样，且与训练集来源分开登记；这一条不在三种泄漏检测里，但失效后果与泄漏相同：结论不代表线上）

**5. 参考资料**
- 本主题 §2.2（三种泄漏的形式化与检测）、§3.2.7（切分与快照的机制、代价、失效点与判定方法）、§4.2（4）（三条可执行 SQL 与"失败即阻断"）、§4.4（存量重切先留旧快照）、§4.5 模板 1（切分规则 / 种子 / 快照 id 三格）、§6.5（把三种泄漏检测排在模型工作之前）。

#### §8.3 你们打算用 LLM 预标注来扩大样本量，怎么保证质量不下降？

**1. 考察点**
- 是否知道**修正比例低有两种相反解释**（模型好 / 人在点"同意"）；
- 知不知道要**从未被修正的那批里**抽样本独立重标——而不是抽被修正的那批；
- 有没有意识到**模型的系统性偏差会进入标签、并被下一代模型学走**（"模型 ↔ 标注互相加强"的循环，它不表现为标注质量差）；
- 有没有把**预标注的输入语料与评测来源分区**当作前置条件，而不是上线后的优化项；
- 加分项：知道这个方向的成熟度只到 L2，卡点恰是"预标注引入的偏差有多大"这个数（§5.2）。

**2. 参考答案框架**

**第一层：先说清机制变化（不是"更快的标注"，而是成本结构与误差来源都换了）。** 标注从"判断"变成"确认与修正"——认知负荷下降，同样人力能标更多（判断类与确认类的单条时长相差数倍，【经验】，§4.6）；但**标签的分布开始带上模型偏好**：人倾向于确认看起来合理的候选，于是模型的系统性偏差被固化进标签，再被下一代模型学走。**这条循环最危险的形态是它不表现为"标注质量差"**，而表现为"模型与标注互相加强"（§5.3.2）。**这一层的失效条件**：在"人必须从零判断"的任务上（没有可接受的候选，或任务本身要求的是发现而非确认），成本结构不变，本方向的收益就不存在。

**第二层：验证动作（本题关键）。** **从"未被修正"的样本里随机抽一小批独立重标**，比较它与"被修正"批的准确率：**未修正批明显更低 ⇒ 人在盲从**（【经验：条数取几十条量级，以你能分辨出两批差异为准】，§5.3.2）。**为什么必须抽未修正批**：修正比例本身只给一个数，而它同时受"模型质量"与"人是否盲从"两件事影响；只有把两批分开比，才能把这两个解释拆开。**这一步的失效条件**：若团队从不保留"是否被修正"这个标记，动作就做不了——所以**它必须在写入路径上落成一个字段**（§4.2（1）的 `label_source` 取值里含 `model_review`），而不是靠事后回忆。

**第三层：两条护栏。**
- **周期性的人工独立标注作为锚**：这批标注**不参考模型候选**，用来测偏差是否在累积（§5.3.2 的代价②）。**它的量级特点是"小但不可省"**——不随样本量增长，却是唯一能测出偏差趋势的东西。
- **把修正比例当监控项而不是质量指标**：它同时受模型质量与人是否盲从影响，只适合看趋势与突变，不适合当验收门槛；**"修正比例低"不能作为发布依据**。
**这一层的失效条件**：当独立锚也由同一批人做、且他们知道候选来自模型时，锚会被污染——**锚的关键不是"谁标"，而是"标的时候看不看得到候选"。**

**第四层：分区的必要性（前置条件，不是优化项）。** 预标注的输入语料**不能包含评测集的来源**：否则它会以改写形式把评测题带进训练集，而**那不是近重复，跨集比对发现不了**（§3.2.8；§6.4 的案例就是这一形态）。隔离要靠**读取白名单**表达而不是靠约定——预标注 / 合成 / 增广流程的输入只能来自训练分区（§4.2（6）、§6.4 第⑤步）。**判据**：能不能列出"预标注流程当前能读到的分区清单"——需要临时翻代码或问人才答得出，就说明隔离还没落在配置上。**这一层的失效条件**：若预标注用的语料与评测集来源在物理上不可能重叠（例如评测集全部由内部人工编写），这一层的紧迫性下降；但读取白名单的成本很低，仍值得先立。

**第五层：为什么"生成更多样本"不等于"更可信"。** 这个方向的稀缺性转移是"从数量到可信度"（§5.1）：当模型已能判得不错时，扩大预标注量会把**样本分布推向模型已经能判的区域**（人更愿意快速确认看着顺的候选）——**长尾与边界反而更少**，而它们才是模型最需要的（§5.3.2 的代价③）。因此顺序应当是**先把未修正批抽检与独立锚建起来，再扩预标注的量**；反过来做，等于在一个未经校准的标签来源上加速。**这一层的失效条件**：当团队已在做"边界样本单独管理（难例库）+ 提高边界样本优先级"时，分布收缩的风险被抵消一部分（§7.4 的推论：`N_e` 压不动，正确动作是把它单独管起来）。

**3. 常见陷阱**
- **只答"抽检"但抽的是"被修正"的那批**：这样能测出"被修正的样本确实被改对了"，但测不出"没被修正的样本是不是本来就标对了"——而盲从恰恰发生在后者身上。
- **把修正比例低当成模型好的证据**：它看起来是最省事的解释，而"人在点同意"这条路只有在主动抽检时才会暴露（与 §8.1 同一种推理错误：指标好看 ≠ 结论可信）。
- **不设独立锚**：偏差不会报警，只会随时间累积，最后表现为"模型在某些子群上效果差"，而排查要花的时间远超那批锚定样本的标注时间。
- **预标注流程能读到评测来源**：这在当期看不出问题（指标正常、标注量上去了），而**污染没有事后检测手段**——只有分区隔离能在读取的那一刻挡住它。
- **把预标注与合成数据混用**：两者都属生成类方向、都带自证风险，混用时两个偏差**无法分离**（§5.3.3）。

**4. 追问预测**
- "独立锚的规模要多大？多久做一次？"（答：规模以"能分辨出两批差异"为准【经验】，不随样本量增长；频次按模型与语料的更新节奏定——每次换模型或换语料来源之后都应当有一个锚）
- "如果未修正批准确率确实低，你怎么办？"（答：先停扩量、恢复抽检比例，再查两处——候选的呈现方式是否在引导确认、以及标注者的培训；必要时退回"从零判断"一段时间做校准）
- "模型候选的置信度能不能用来分层审核？"（答：可以，但要意识到**分层本身会改变标签分布**——低置信进人工会被修得干净、高置信保留模型偏差；因此分层阈值必须与独立抽检配合使用）
- "预标注与合成数据混用时会怎样？"（答：两个偏差叠加且无法分离——预标注带模型偏好、合成带分布偏差与自证风险；分区隔离与来源标记要同时做）
- "这一方向现在能做到什么程度？"（答：L2——有正式条目，但"预标注引入的偏差有多大"这个数只有做过抽检的团队才有，§5.2 的②判据在这一行写的是"核不到"）

#### §8.4 标注口径怎么写？为什么"边界案例"比"判定问题"更重要？

**1. 考察点**
- 是否知道**分歧集中在口径未覆盖的边界上**，因此"补边界案例"是可执行的修法，而"加强培训"不是；
- 知不知道 κ 是**口径的诊断量**，不是**标注者的考核**；
- 有没有"任务配置五部分"的概念，并知道**边界案例与审核规则要分开检查**（前者决定分歧从哪来，后者决定分歧怎么收口）；
- 知不知道**裁定结论必须回写进配置**——不回写，同一类分歧会反复出现，且每次裁定可能不同；
- 加分项：知道 κ 低时第一个动作是改口径（不是换人），以及"边界案例超过十条"通常意味着判定问题没写清楚。

**2. 参考答案框架**

**第一层：给出任务配置的五个部分。** 输入展示 / 判定问题 / 取值域 / **边界案例（3–5 个，【经验：随任务主观性浮动】）** / 审核规则（§4.1 Step 5、§6.1）。**边界案例是口径的主要载体**——**判定问题决定任务看起来在做什么，边界案例决定它实际怎么做**。这一层还要给出每部分各自的失效形态：输入展示少了上下文会逼人猜（而"猜"的分歧无法通过改口径消除）；取值域不写死（把自由文本约束到"其他 + 说明"里）会让分歧逃出统计；审核规则缺失会让积压转成"裁定者拍板"。

**第二层：为什么"边界案例"比"判定问题"更重要。** 因为**分歧出现在"判定问题没说清"的地方**，而没说清的地方**只能靠案例来固定**（"问一下会员权益有哪些"算不算资金类——这句话本身说不清，给一个例子就清楚了）。这条性质直接推出一条可验收的判据：**让一个新人只看任务配置、不看口头说明开工**，数他被卡住并要问人的处数——每一处就是边界案例没覆盖到的一类分歧。**这一层的失效条件**：当任务是"发现型"的（要标注者找出未预料的类别）时，把边界案例写死反而会限制覆盖面——此时该固定的是"什么算有效发现"，而不是"每一类的答案"。

**第三层：一致性的用法（κ 加分歧分布，而不是一个分数）。** 抽样批次做重复标注，算 κ 并**看分歧分布**：**分歧集中在少数几类 ⇒ 补边界案例；分歧弥散在各处 ⇒ 判定问题本身没定义清楚，该改的是判定问题（或缩小任务范围）**。**κ 衡量的是口径的清晰程度，不是标注者的水平**——拿它考核会让人彼此对齐（人为抬高），从而掩盖口径的真实问题；所以 κ 只进口径版本的变更说明，不进任何人的绩效（§6.1）。**为什么"分歧分布"比"κ 这一个数"更重要**：κ 只给一个总分，无法区分"全表都模糊"与"少数几类特别模糊"，而后者才是靠补三到五个边界案例就能修掉的那一类。**这一层的失效条件**：当标注者通过私下沟通达成一致时，κ 会上升而口径并未变清晰——所以 κ 必须配合"分歧分布"与"新人独立开工"两条一起读。

**第四层：审核与裁定——把积压当设计对象，把裁定回写成配置。** 审核环节会积压，这与所有人审闸门是同一个问题（§3.2.1 的代价③）：**积压不报错，只表现为"标注完成了但入库很慢"**，于是团队的第一反应是增加标注者，而**增加标注者会让口径维护面变大，反向加重积压**。同时有一条纪律：**裁定结论若超出当前边界案例，必须写进下一版配置**——不回写，同一类分歧会反复出现，而每次的裁定可能不同。**判据**：审核队列的等待时长有没有数；裁定结论有没有回写成边界案例。**这一层的失效条件**：若任务只有一个人标、且从不做抽样重复，裁定环节不存在——但那时一致性也没有任何度量，形态退回到"口径在人的脑子里"。

**第五层：口径是一份会演进的资产——谁维护它。** §3.1 的约束 5 问的就是这件事：**有没有人负责写边界案例、裁分歧、维护版本**。没有这个人，样本集在头两个月质量很好，之后**一致性缓慢下降而没人察觉**——因为下降是渐进的，且**看指标看不出来**（模型效果下降会被归因为"业务变难了"）。**判据**：口径文档有版本、有 Owner、有最近一次边界案例更新记录。**这一层的失效条件**：当业务判定规则极少变化（口径长期不动）时，Owner 的负担很轻，可以并入别的角色；但"有版本、有记录"这一条仍要保留——**它是口径变更时唯一能界定影响范围的依据**。

**3. 常见陷阱**
- **口径写在一份共享文档里**：这是零成本的默认动作（写文档只要把已经想到的说出来，写配置要先想清判定问题与取值域），因此几乎总被先选上；代价是文档与任务的对应靠人维护，而分歧恰好落在文档没覆盖的情形上（§6.1 的失败教训："口径的主要载体是边界案例，不是判定问题"）。
- **只写判定问题与取值域**：这样任务看起来完整、也能开工，但"实际怎么做"没有载体。
- **拿 κ 考核标注者**：κ 会上升（人彼此对齐），而口径的真实问题被掩盖——**看起来是质量提升，其实把信号消掉了**。
- **边界案例选的不是真正分歧的地方**：挑了几个"标准答案很明确"的例子，于是它们不产生任何约束力，标注者仍会各自发挥。
- **裁定结论不回写配置**：同一条分歧下一批照旧出现，而每次裁定的结果可能不同——**分歧被"解决"了很多次，口径却一次都没变。**

**4. 追问预测**
- "边界案例选几个？谁来选？"（答：覆盖一个任务的常见分歧，通常三到五个就够【经验】；**由裁定者从真实分歧里选**，而不是由写口径的人凭想象选；超过十条通常意味着判定问题没写清楚，该改的是判定问题）
- "κ 低的时候你第一步做什么？"（答：改口径——先看分歧集中在哪几类，补边界案例；κ 低而分歧弥散时才回头改判定问题；换人是最后一步，而且要承认换人会掩盖问题）
- "新任务的口径怎么从零建立（没有历史分歧数据）？"（答：先做一小批试标——几名标注者独立标同一批，用分歧分布起草边界案例，再放量；**试标的产出是边界案例，不是标签**）
- "主观性强的任务（如'有没有风险'）怎么处理一致性？"（答：把主观判断拆成可判定的子问题——哪些要素构成风险、什么情况下必须升级；把不可拆的部分限定在"其他 + 说明"里；同时接受这类任务的 κ 天然低于客观任务，判据是**分歧是否收敛**而不是 κ 的绝对值）
- "口径改了，历史标注怎么办？"（答：口径版本落在样本上（`label_meta.guideline_version`），历史标注标为"版本之前的"，**不追溯重标**——重标是新口径下的新标注，不是旧的）

#### §8.5 你们的评测集怎么保证没被污染？为什么"训练集和测试集不重叠"不够？

**1. 考察点**
- 是否知道**污染有直接与间接两种**，且两者的处置动作不同（前者可以"先检测再决定"，后者只能"先隔离再使用"）；
- 有没有**来源台账**的意识，并知道它登记的是"可能包含什么"而不是"来源地址"；
- 知不知道**合成 / 增广会带来自证风险**，且它与污染是同一条通道上的两个后果；
- 有没有把**排查顺序**排对（先列来源清单 → 逐源问 → 最后才比对）；
- 加分项：知道"评测集与训练集不重叠"只覆盖了直接污染里最容易被发现的那一部分。

**2. 参考答案框架**

**第一层：区分两类污染，并说清为什么"不重叠"不够。** 直接污染——评测样本（或它的近重复）出现在训练数据里，**可以用跨集比对发现**；间接污染——经由公开语料、合成数据、改写入训练数据，**比对发现不了**（它不是近重复）。**"训练集和测试集不重叠"检验的是两份集合的表面交集**：它既不覆盖"同一内容以不同形式出现在两侧"（改写、翻译、摘要），也不覆盖"两侧内容各自与一份第三方语料重叠"——而后者正是间接污染的入口（§6.4 的案例：评测集是自家挑的历史工单、训练数据是自家整理的，两者来源上确实不同，**而中间隔着一份公开语料**）。**这一层的失效条件**：若训练数据全部由内部产生、且从不引入外部语料与生成流程，间接污染的入口会大幅缩小；但只要有一条外部语料或一条生成通道，结论就不再成立。

**第二层：三件检查，以及各自的盲区。** 三件（跨集近重复比对 / 来源语料比对 / 数据来源台账）的机制、能发现什么与发现不了什么、以及"三件都要有"的判据，见 §4.2（5）——**这里不再重排那张表，只排它们在本题里的失效条件**。

**这一层的失效条件**：台账只覆盖"你登记过的来源"——未登记的新来源是它唯一的盲区，而补登记的对象恰好是"最近引入的全部外部数据源"（这一步的产出就是台账的补录清单）。

**第三层："来源台账"为什么不可替代。** 因为**"这份公开语料里有没有我的评测题"这个问题，在下载时就已经无法回答**（语料是黑箱）——**只有"每个来源登记它可能包含什么"这条陈述能在当时把它记下来**。它是本主题里**预防成本最低、缺失代价最高**的一项：记录数与来源数同阶，而不是与样本量同阶——**它在样本量增长时不增长**，所以没有"等规模大了再做"的理由（§6.4）。一条台账记录要能回答四件事：来源是什么、什么时候引入、**它可能包含什么**、授权状态；再加一格"与评测来源是否隔离"（§6.4 第③步给了可照抄的一行）。**判据**：能不能在不查历史记录、不重新跑比对的前提下，直接答出"某个来源里可能有什么"。**这一层的失效条件**：当所有来源都是"可控的内部产生"时，台账的边际价值下降；但授权状态那一格仍要留——它服务的是举证，不是污染。

**第四层：合成 / 增广的自证风险，以及它的唯一手段。** **用含评测题的语料生成样本 ⇒ 合成样本带着评测题进入训练集，而它是改写的、不是近重复**；**唯一手段是分区隔离**（合成流程的输入语料与评测集来源物理分开）+ 把合成产出的来源登记进台账。隔离要落在**读取白名单**上而不是约定上：训练流程与合成流程可读训练分区、评测分区仅评测流程可读、合成产物必须带"合成"标记（§4.2（6）、§6.4 第⑤步）。**为什么必须物理分隔而不是"注意一下"**：这条通道上的污染经过改写，**没有事后检测手段，只能在读取的那一刻挡住**。**这一层的失效条件**：当合成只在"与评测集来源完全不重叠的语料"上做时，隔离的紧迫性下降——但白名单的成本很低，仍应先立。

**第五层：排查顺序与处置纪律。** 顺序是**先列训练数据来源清单（时间倒序）→ 再逐源问"它可能包含什么" → 最后才做比对**。**顺序不能反**：比对只能发现直接污染，**用它去排除间接污染，等于用一个原理上发现不了它的工具去排除它**——跑完一遍返回 0，会得到一个错误的"干净"结论（§6.4 第④步）。处置纪律与 §6.3 同一条：**受污染期间的结论做标注（"该期间的结论含污染"）、不追溯改写**，同时**重建一份与所有已用训练来源隔离的评测集**；重建之后历史结论不可比，这一点要在重建时就说清。**这一层的失效条件**：若受污染的是唯一一份评测集且没有任何快照，重建会让所有历史指标失去可比性——此时先冻结"依赖这份评测集的对外结论"，再重建。

**3. 常见陷阱**
- **只答"我们做过去重"**：去重确实有效，因此听起来是个完整答案；但它只覆盖直接污染，而间接污染**恰好是比对在原理上发现不了的那一类**。
- **不做来源台账**：不做台账当期没有任何损失（样本量照涨、指标照好），代价全部推到"以后有人问起"的时候——**它是收益完全滞后的动作，因此总被排到最后**（§6.4 的失败教训）。
- **把合成数据当成"干净的扩量手段"**：生成能扩量是真的，而**用生成的数据评模型必然乐观**——那是自证，不是验证。
- **合成流程能读到评测来源**：这在当期看不出问题，而这条通道**没有检测手段**。
- **发现污染后第一反应是"全部作废重来"**：这会连带推翻未受影响的结论，代价远大于收益；正确动作是标注 + 隔离 + 重建（§6.4 第②、③步）。

**4. 追问预测**
- "近重复的阈值怎么定？改写程度多大会漏？"（答：阈值越高漏得越多，改写程度越高越漏——所以它必须与台账配套，而不能单独作为"未污染"的证据；阈值本身用一批已知重复对校准，同 §8.2 的那一问）
- "台账每个来源要登记什么字段？"（答：来源 id / 来源描述 / 引入时间 / **可能包含什么** / 授权状态 / 与评测来源是否隔离；**关键判据是这一行能不能回答"它可能包含什么"**——答不出，就只是登记了来源、没登记内容）
- "如果发现污染，此前的结论怎么办？"（答：受污染期间的结论做标注、不追溯改写；对外发布过的要更正；同时重建一份与所有已用训练来源隔离的评测集——重建之后历史指标不可比，这一点要提前说明）
- "对外评测（第三方榜单）的污染怎么处理？"（答：思路相同但变量更多——你控制不了榜单的构成，能做的是在提交前确认"训练数据里有没有含榜单语料"，并把这条确认记进台账；**若榜单来源是黑箱，就按"可能有"处理**）
- "怎么证明我们没被污染？"（答：证明不了，只能出示证据链——三件检查的运行记录 + 台账 + 分区白名单；**这三件给出的是"可回答性"，不是"保证"**）

#### §8.6 主动学习能省多少标注？为什么它不能用来做评测集？

**1. 考察点**
- 是否理解主动学习**改变训练集分布**，因此它是一种"分配策略"而不是"更多样本"；
- 知不知道**评测集必须随机抽样**（它的全部意义是代表线上）；
- 有没有"边标边重训"的意识，并知道少了它收益会随轮次衰减；
- 说不说得出**退出条件**（能规则化的比例、评测集能否保持随机抽样）；
- 加分项：知道回流样本是"最贴线上但自带偏置"的那一类，必须绑曝光策略版本。

**2. 参考答案框架**

**第一层：它省的是什么（不是"样本"，而是"无效标注"）。** 它把预算从"均匀覆盖"改成"投在决策边界上"——**而模型的提升恰恰来自边界样本**（大量已能正确判的样本标了也不改变模型）。**因此省下的那部分是"没有信息量的标注"，不是"标注本身"。** 由此推出一个量的口径：**省下的比例取决于候选池里"对模型没有新信息"的比例**，而这个比例与"能规则化的比例"是两件事——前者决定主动学习的回报，后者决定弱监督的回报（§6.2 的判据是"先估它，再决定投入是否划算"）。**这一层的失效条件**：当候选池本身已经很小、或模型已经很准时，边界样本的绝对数量少，主动学习省下的绝对量也随之变小——**它省的是比例，不是固定额度**。

**第二层：它的硬前提——边标边重训。** 判据是**"边标边重训"**（§2.2、§3.2.3）：一次性选完再标，等价于只用最初那个模型的不确定度去挑，**收益随轮次迅速衰减**，而**每批标注看起来都"选得很准"**（这是它不报错的原因）。可查的动作只有一个：**翻最近三次标注批次的记录，看每批之后有没有一次重训与重新打分**——三次都没有，说明它已退化成"一次选完再标"。**这一层的失效条件**：当任务是一次性交付（样本只标一轮就冻结）时，"边标边重训"不适用，主动学习退化成"一次性采样"，它的价值也随之从"持续省"退化成"这一轮选得更值"。

**第三层：为什么不能用来做评测集（本题关键）。** **评测集的全部意义是"代表线上分布"**，而**主动学习样本恰恰不代表线上分布**（它偏向模型的不确定区域）。**用它做评测，等于"用边界样本评一个为边界优化的模型"**——指标会高，且**不能外推到线上**；这条错误的形状是"越训越好看、线上没变化"（§5.5 第 5 条）。判据很省事：**评测集的抽样方式是不是随机的、且与训练集来源分开登记。** **这一层的失效条件**：当业务只关心"模型在边界样本上的表现"（例如自动审核里的高风险子集）时，用偏向边界的集合评测是**有意为之的另一种评测**——但那时它不叫评测集，而是"子群评测"，必须与代表线上的总评测集同时存在。

**第四层：正确的组合——三类来源各司其职。** 主动学习样本**喂训练**；**随机抽样做评测**；线上回流**贴近线上**，但要**绑曝光策略版本**处理偏置。三者混用会使偏差叠加且**无法分离**（§3.4 的来源组合）。回流这一支另有一条硬约束：**回流样本必须标出来源与偏置**（§2.4 的接口），登记形态如"回流占一成、绑曝光策略 v12"【经验：占比随业务浮动；§4.5 模板 1 给的是登记格式】——**不绑曝光版本，偏置就永远无法事后分析**。**这一层的失效条件**：当回流只有被曝光的那部分才有反馈时（几乎所有推荐 / 排序场景），回流样本反映的是"当前策略下的表现"而不是"用户的偏好"——**只用它训练会让策略越来越窄**。

**第五层：退出条件与冷启动。** 两个退出条件：① **能规则化的比例低于一成时不投弱监督**（§7.5 的第四问：低于这条线，标注函数的设计与维护成本会超过它省下的人力）；② **评测集无法保持随机抽样时不投主动学习**（§5.7 第 2 条）。冷启动另有一处必须承认的现实：**模型太差时不确定度估计不可靠**，第一批样本的选取质量不高——处理方式不是硬选，而是**先用一批随机抽样把模型做到可用，再切到主动学习**。**这一层的失效条件**：当团队没有"每轮重训"的工程能力（训练链路不能按天跑）时，主动学习会自然退化成一次采样；此时诚实的做法是先按随机抽样标注，而不是挂一个名义上的主动学习流程。

**3. 常见陷阱**
- **把主动学习样本也当评测集**：省了一次随机抽样，代价是**评测集不再代表线上**——而指标越高，误导越强。
- **不做"边标边重训"（一次选完）**：每批看起来都选得很准，因此没人发现问题；收益衰减是静默的。
- **忽略冷启动时不确定度不可靠**：模型太差时它挑出的"最不确定"样本与随机抽样差别不大，而团队会以为已经在按信息量分配预算。
- **把回流样本当无偏样本用**：它零标注成本、看起来最干净，而**它是唯一自带偏置的样本来源**——评估用的是同一批曝光样本时，会得到"线上指标好而全量评估差"的结果。
- **只比"标了多少条"，不比"模型是否变好"**：主动学习的价值必须用**独立评测集上的指标**来读；用训练集上的指标读它，等于自己评自己。

**4. 追问预测**
- "不确定度怎么定义（熵、投票分歧、预期模型变化）？"（答：三者在不同场景下各有优势；选型判据不是"哪个更准"，而是**能不能与重训轮次配合**——预期模型变化的计算量最大，但它直接对齐"这条样本能带来多大改变"）
- "冷启动时怎么选第一批？"（答：先用一批随机抽样把模型做到可用，再切主动学习；直接上主动学习时，不确定度来自一个尚不可用的模型）
- "主动学习选出来的样本分布偏差，对线上评估有什么影响？"（答：不进评测集时无影响；一旦混进评测集，评测就会系统性偏高——**所以评测集的来源要单独登记**）
- "回流样本的曝光偏置怎么处理？"（答：绑曝光策略版本 + 抽样核查"它属于哪一版曝光"；偏置不是靠算法消除的，而是靠**记录**让它可以被事后分析）
- "如果只有一份标注预算，先做主动学习还是先做随机抽样？"（答：先随机抽样——它同时产出"可用的模型"与"可用的评测集"；主动学习的收益建立在准确的基线之上）
