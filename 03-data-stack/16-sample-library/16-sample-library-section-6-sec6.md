## 6. 落地实践

> **本节的材料纪律（先说清楚）**：样本库的公开材料以**开源工具与工具文档**为主，而**标注一致性、穿越幅度、污染排查结果这类真正有用的数据几乎无人公开**——它们直接暴露"此前的离线指标里有多少是借来的、有多少结论要打折"。因此本节 4 例的构成是：
>
> - **§6.1–§6.2** 是**开源项目文档层面的机制复述**（任务怎么被配置化、标注函数怎么被审计与聚合），**不是对任何一家公司内部实现的转述**；方括号内是**来源类型 + 年份**，属**建设方自述**，不构成本书 §5 判据里要求的「第三方（非厂商）公开生产案例」。
> - **§6.3–§6.4** 是**匿名案例**（不给可指名的来源），只作机制示例、不作举证。
> - 文中数字一律标注档位：有具名出处的标【公开】，有推导链的标【推算】，只有量级与条件的标【经验】。本节没有给出可核验出处的精确数值，请以你自己的实测口径为准。

### 6.1 Label Studio"**把口径写进任务流：标注从个人劳动变成可配置的流水线 3+ 年**"（2021-2024）

**背景（Why）**

标注最初是"每个人拉一批数据、自己标完给自己用"：

- **口径在人的脑子里**——新人接手要口头交接，而交接必然失真；
- **没有一致性度量**——两个人对同一输入判得不一样时，**没人知道**；
- **样本散在各人的导出文件里**——"上一版训练用的是哪批"无法回答。

**触发点（What）**

Label Studio 一类开源标注工具把**标注任务做成可配置的对象**（[Label Studio 公开材料 2021-2024]，核验入口是其官方文档 / 仓库，**按当前版本核**）：输入展示、判定问题、取值域、审核流都在配置里，**而配置可版本化**。它给出的判断是**"口径要写进任务流，而不是写在交接文档里"**：

- **配置即口径**（改口径 = 改配置，有版本可回滚）；
- **多人独立标注 + 一致性计算**让分歧第一次可见；
- **任务与样本分离**（样本进库，任务只是它的一次标注过程）。

**详细做法（How）**

**① 任务配置的五个组成部分**

```text
① 输入展示：给标注者看什么 —— 少了上下文会逼人猜，而"猜"的分歧无法通过改口径消除
② 判定问题：一个可判定的问题（不是"这条好不好"）
③ 取值域：枚举写死（自由文本只允许出现在"其他 + 说明"里）
④ 边界案例：3–5 个已知难例及其正确判定 —— 口径的主要载体
⑤ 审核规则：谁审、怎么抽、分歧怎么裁
判据：④ 是不是"真正会分歧的地方"—— 不是的话，标注者仍会各自发挥
```

**② 一致性作为口径的诊断工具（而不是标注者的考核）**

- **关键设计**：抽样批次做重复标注，算 κ 并**看分歧分布**。
- **关键性质**：**κ 低时第一个动作是改口径，不是换人**——因为 κ 衡量的是口径的清晰程度，而不是标注者的水平。**把它当考核指标会让标注者彼此对齐（人为抬高），于是口径的真实问题被掩盖。**

**具体数字（档位标注）**

- 重复标注的人力代价：**同一批样本至少两人标** ⇒ 被抽中的批次人力翻倍【推算：口径为"抽出比例 × 1"的额外人力】——因此通常只对**抽样批次**做重复（抽多少取决于口径的稳定程度）。
- 边界案例的数量：**3–5 个**通常够覆盖一个任务的常见分歧【经验：随任务主观性浮动】。
- **自测动作**：让一个新人**不看口头说明**、只看任务配置开工，看他是否会被卡住——**被卡住的地方就是配置缺的部分。**

**失败教训**

**第一版把口径写在一份共享文档里**——任务配置里只有"判定问题"与"取值域"。结果是标注者遇到文档没覆盖的情形时各自发挥，而**分歧恰好集中在这些情形上**（也就是模型最需要正确的样本上）。教训：**口径的主要载体是"边界案例"，不是"判定问题"**——判定问题决定任务看起来在做什么，**边界案例决定它实际怎么做。**

### 6.2 Snorkel"**用标注函数替换一部分人工标注：把标注变成可审计的规则投票 5+ 年**"（2019-2024）

**背景（Why）**

标注需求里有一大块是**可以写成规则的**：

- **金额超限、字段缺失、状态异常**——这些不需要人看；
- **但没人愿意把它们做成规则**——因为"规则会腐化"，而腐化后没人知道；
- **于是这些样本也在耗人力**，而人力是最贵的。

**触发点（What）**

Snorkel 一类弱监督方法把**标注变成多个标注函数的投票**（[Snorkel 公开材料 2019-2024]，核验入口是其论文与开源仓库，**按当前版本核**）：

- **每个函数可以不准**（只要比随机好），靠**聚合**得到概率标签；
- **每个函数可审计**（用规则表达，不是黑盒）——**这一点是它相对"训个模型来打标"的根本优势**；
- **允许弃权**：函数对不适用的样本投 `abstain`，而不是硬投一个值。

**详细做法（How）**

**① 标注函数的三条设计要求**

```text
① 可审计：用规则表达（"金额 > X 且 状态 = 待审"），而不是模型 ——
   出问题时你能指出是哪条规则错，而不是"模型就是这么认为的"
② 有弃权：不适用的样本投 abstain ——
   硬投会把噪声均匀洒进数据，而弃权把它集中暴露出来
③ 要留置信度：聚合后给概率标签 ——
   二值化会丢掉"这条有多确定"这个信息，而下游常常需要它
判据：函数签名里有没有"不适用"这一档 —— 没有就是硬投
```

**② 聚合权重必须在留出集上估**

- **关键设计**：用一小批人工标注作为"锚"，估各函数的准确性，再加权投票。
- **为什么**：**没有锚时，聚合权重只能凭感觉**——而权重错了会让一个不准的函数主导标签，且**它表现为"模型在某些子群上效果差"，很难追到标注层**。

**③ 规则腐化要有监控**

- **关键设计**：监控各标注函数的命中量随时间的变化。**命中量突变（激增或归零）通常意味着上游业务变了。**
- **判据**：某个函数连续一段时间命中为 0，说明它的条件已经不可能被满足（业务变了而规则没改）。

**具体数字（档位标注）**

- 人工量的下降幅度：取决于"能规则化的比例"，而**这个比例可以在第一天估出来**【经验：随业务规则化程度浮动，请用你自己的数据估】——**先估它，再决定投入弱监督是否划算**。
- 锚定样本量的量级：聚合权重的估计只需要**一小批人工标注**（相对全量很小），但**它必须与训练集分开**（同 §3.2.7 的切分纪律）。
- **自测动作**：数一下你的标注需求里，**写成规则就能判的比例**是多少——这个数决定弱监督的投入回报。

**失败教训**

**第一版让所有函数对所有样本硬投**——于是"不适用"的样本被硬投成噪声，而它的表现是"模型在少数子群上效果差"。排查花了两周，最后发现根因在标注层。教训：**"弃权"不是可选设计，它是让噪声可定位的唯一手段**——硬投把噪声均匀洒开，弃权把它集中成"这一批函数都没投"的可观测信号。

### 6.3 某电商"**特征回填改对之后，离线指标下降了：借来的那部分被还回去 3+ 年**"（2021-2024）

> **来源声明**：本例为**匿名案例**——不给可指名的来源，只作机制示例、不作举证（同 [Ch4 §05 RAG 架构](../../04-data-assetization/05-rag-architecture/05-rag-architecture-section-6-sec6.md) 对匿名案例的处理口径）。

**背景（Why）**

转化率模型的离线 AUC 一直很好，而**上线后表现明显差一截**。团队反复调特征、调模型、扩样本，效果都不稳定。

**触发点（What）**

**一次特征平台的改造**：改造后，样本组装从"读特征表最新分区"改成"按样本 `event_time` 读历史版本"。改造上线后，**离线 AUC 明显下降**，团队第一反应是"改造引入 bug"。

**详细做法（How）**

**① 先把"下降"定性：是 bug 还是还账**

- **关键设计**：对同一批样本，分别用两种回填口径算特征值，**逐条比对差异样本的特征分布**。
- **关键性质**：**如果是 bug，差异会集中在少数特征上且分布异常；如果是穿越，差异会集中在"时点后发生变化的特征"上**（例如"最近 7 天消费额"这类窗口特征）。**本例的差异集中在窗口特征上 ⇒ 是穿越。**

**② 把"穿越幅度"量出来**

- **关键设计**：量化同一批样本在两种口径下的指标差（AUC 差、以及正例上的差异）。
- **为什么**：**这个数是"此前有多少结论建立在借来的信息上"**——它同时决定"要不要重做历史模型"与"怎么向业务解释指标下降"。

**③ 把回填收成唯一入口（防止再被绕过）**

- **关键设计**：回填脚本成为唯一入口；**CI 里加一条检查**：全库搜索还有没有别处直接 JOIN 特征表做样本组装。
- **为什么**：**穿越的根因不是"某个人写错了"，而是"回填不是唯一入口"**——只要存在第二条组装路径，它就会在某次赶工期时用最新值。

**具体数字（档位标注）**

- 穿越幅度的量级：本例中窗口类特征的穿越幅度最大（**"最近 7 天消费额"在 `event_time` 之后仍在变化**），而**快照类特征（注册渠道）几乎不受影响**【经验：穿越幅度随特征的"变化频率"上升】——**这条分布特征本身就是诊断依据**。
- 重做的成本：受影响的历史模型结论要做标注（"此前的离线指标含穿越，幅度见记录"），**而不必全部重训**——但**对外承诺过的指标要更正**【经验：随对外程度上浮】。
- **自测动作**：把回填连接条件改成含时点约束，重跑一次评测——**下降的幅度就是你的穿越幅度**。

**失败教训**

**把"离线好"当成"模型好"**——三年里所有选型与调参都基于一个含穿越的离线指标。教训：**特征穿越的性质是"它让离线指标更好看"**，因此**没有任何指标能发现它**；唯一的发现方式是**机械地检查连接条件**——而这件事必须做成脚本（CI 检查），不能靠人记得。

### 6.4 某银行"**评测集污染排查：一份公开语料里混着自家评测题 2+ 年**"（2022-2024）

> **来源声明**：本例为**匿名案例**——不给可指名的来源，只作机制示例、不作举证。

**背景（Why）**

风控文本模型的评测集是从历史工单里挑的 3,000 条。模型迭代一直"稳定提升"，团队据此决定扩大使用范围。

**触发点（What）**

**一次内部评审**：有人问"我们的训练数据里有没有用到公开语料"。追查发现——**半年前为了扩充训练数据，引入了一批行业内公开的语料包，而那批语料包里包含该行的部分历史工单**（工单曾被脱敏后用于行业交流）。**于是 3,000 条评测里有约两成以改写形式出现在训练数据里**，而**它们不是近重复**（经过改写），跨集比对检查发现不了。

**详细做法（How）**

**① 区分"直接污染"与"间接污染"，并承认后者只能靠台账**

- **关键设计**：直接污染可用比对发现（跨集近重复）；**间接污染（经语料 / 合成 / 改写）无法靠比对**——**只能靠"数据来源台账"**（每个来源登记"它可能包含什么"）。
- **为什么**：**没有台账时，"这份语料里有没有我的评测题"这个问题在那个时点已经无法回答**——语料是黑箱下载下来的，你无从得知它的构成。

**② 重建评测集并标注历史结论**

- **关键设计**：重建一份**与所有已用训练数据来源隔离**的评测集；对受污染期间的结论**做标注**（不追溯改写，但要说明"该期间的结论含污染"）。
- **判据**：**"不追溯改写结论，但必须知道哪些结论要打折"**——这是与 §6.3 同一条处理纪律。

**③ 建台账 + 分区隔离**

- **关键设计**：每个新数据源登记一条（来源描述 + 可能包含什么 + 授权状态）；**合成 / 增广流程的输入语料与评测集来源物理分开**。
- **为什么**：**分区隔离是防"自证"的唯一手段**——用它自己的来源生成数据、再用它评测，结论必然乐观，而**这条路径没有任何指标能发现**。

**具体数字（档位标注）**

- 污染的规模：本例中约两成评测样本受间接污染【经验：随语料来源与评测集来源的重叠度浮动】——**这个比例决定了此前结论的可信度**。
- 台账的维护成本：**每个数据源一条记录**【推算：随引入数据源的频率线性增长】——**这是本主题里预防成本最低、而缺失代价最高的一项**。
- **自测动作**：问一句"我上个月引入的那份公开语料，里面可能有我们的评测题吗"——**答不出来就是台账缺失**。

**失败教训**

**把"评测集是自己挑的、训练数据是自己整理"当成"两者隔离"**——它们来源上确实不同，而**中间隔着一份公开语料**。教训：**污染不只是"直接混入"，还有"经由第三方语料间接混入"**；而**第二类只能靠"来源台账"防**——它要求把"我用的数据从哪来"变成一条需要被登记的陈述，**而不是一个事后可以回忆的记忆**。

### 6.5 真实落地路径（基于上述 4 个案例提炼）

四个案例拼起来是一条顺序固定的路径，与 §4.1 的八步对应：

1. **先定五个元数据字段**（§6.3 的改造前提）——没有它们，回填、切分与污染检查都无处挂。
2. **再把回填收成唯一入口，并做 CI 检查**（§6.3）——**穿越的唯一发现方式是机械检查，不是看指标**。
3. **然后跑三种泄漏检测 + 污染检查**（§6.4 的排查前提）——**这一步常常会发现问题，而它必须在模型工作之前做**。
4. **接着把口径写进任务流**（§6.1）——任务配置的五个部分，核心是**边界案例**。
5. **最后把能规则化的部分规则化**（§6.2）——**先估"能规则化的比例"，再决定投入。**

**顺序的反面**：**先扩样本量、后建元数据与检查**（§4.1 的反面）——扩量之后存量样本缺元数据（**"谁标的、当时口径是什么版本"补不回来**），且**污染与泄漏的概率随规模放大**。**第二条反面**：**先用预标注 / 合成数据扩量、后做分区隔离**（§6.4）——**生成类方法会把评测题带进训练集，而它不是近重复，比对发现不了**。

### 6.6 踩坑与经验（4 个案例提炼）

| 坑 | 症状 | 机制层面的后果 | 修法 |
| --- | --- | --- | --- |
| 口径只在共享文档里 | 标注者遇到未覆盖情形各自发挥 | 分歧集中在模型最需要的样本上 | 边界案例写进任务配置（§6.1） |
| 拿 κ 考核标注者 | 一致性人为抬高 | 口径的真实问题被掩盖 | κ 作口径诊断（§6.1） |
| 弱监督函数硬投 | 少数子群效果差、追溯到不标注层 | 噪声均匀分布 | 函数加**弃权**档（§6.2） |
| 聚合权重凭感觉 | 不准的函数主导标签 | 同上 | 留出集估权重 |
| 规则腐化无监控 | 命中量长期为 0 | 静默产出错标签 | 监控各函数命中量（§6.2） |
| 回填用最新值 | 离线好线上差 | 特征穿越，**且离线指标更支持这个错误** | 连接条件含 `ts <= event_time`（§6.3） |
| 回填不是唯一入口 | 赶工期时又用最新值 | 穿越复发 | CI 检查"有无第二处组装"（§6.3） |
| 只做实体切分 | 实体交集 0 而结果仍乐观 | 时间与近重复泄漏 | 三种检测各跑（§3.2.7） |
| 用主动学习样本做评测 | 评测高而全量低 | 评测集不代表线上 | 评测集随机抽样（§3.2.3） |
| 只做跨集比对、无台账 | 无法回答语料里有无评测题 | 间接污染不可发现 | 建来源台账（§6.4） |
| 合成流程能读到评测来源 | 自证风险 | 结论必然乐观且无指标可查 | 分区隔离 + 来源登记（§6.4） |
| 预标注无独立抽检 | 修正比例极低被当成模型好 | 人在盲从、偏差固化 | 抽未修正批独立重标（§3.2.4） |

### 6.7 ROI 评估（4 个案例的量级账，**非实测**）

> **声明**：下表是**量级口径的估算框架**，用于说明"收益落在哪一块"，**不是任何一家组织的实测数据**；每项都给出可自测的动作，请用你自己的基线替换。本节不给"某公司实测提升 N%"这类数字——样本库的收益形态是"结论可信、人力省下、返工避免"，前两者可量，第三者只能用"有没有发生"来判。

| 收益项 | 计量口径 | 量级（【经验】） | 自测动作 |
| --- | --- | --- | --- |
| 结论可信度 | 三种泄漏检测 + 污染检查的结果 | 从**未做过**到**各返回 0** | 各跑一次并留记录 |
| 穿越幅度 | 改对回填后离线指标的变化 | **下降的幅度就是此前借用的未来信息量**（本例集中在窗口特征上） | 改连接条件重跑一次 |
| 标注人力 | 单条标注时长 × 条数 × 人数 / 复用率 | 弱监督 + 主动学习可显著下降；**边界样本永远要人** | 量"单条时长"与"能规则化的比例" |
| 标注一致性 | κ 与分歧分布 | 补边界案例后通常可显著提升（幅度取决于原口径的模糊程度） | 抽样重复标注算一次 |
| 返工避免 | 因穿越 / 泄漏 / 污染导致的结论作废次数 | 从**偶发**到"由检查从机制上排除" | 数最近一年此类返工 |
| 排障时间 | 从"效果异常"到"定位到样本层"的时长 | 版本标识齐全时可从**天级**降到**小时级** | 取最近一次复盘实际耗时 |
| 代价 | 标注 + 口径维护 + 治理（回填/切分/检查） | **人力为主，且样本本身在衰减** | 按月核算，并把"样本增补"算进常态预算 |

**读法**：前两项是**可信度收益**（检查通过、穿越还账），第三、四项是**成本与质量收益**（人力、一致性），第五项是**返工避免**，第六项是**排障效率**，最后一项是**代价**。**本主题最容易出现的错位是只算"标注省了多少人力"，不算"结论是否可信"**——前者是一次性节省，后者决定**每一次实验结果是否作数**。**另一条读法**：最后一项里"样本增补"常被当成一次性项目，而**样本在衰减**——把它漏出预算的后果是"用一年前的样本反复训模型，并把效果下降归因为业务变难"。

> 本节小结：四个案例的先后顺序不是偏好而是依赖——**元数据先行**（回填、切分、污染检查都挂在它上面），**回填收成唯一入口并做 CI 检查**（穿越只能机械发现），**泄漏与污染检查在模型工作之前做**（它们常常会发现问题），**口径写进任务流**（核心是边界案例），**最后把能规则化的规则化**（先估比例再投入）。四次失败教训指向同一件事：**样本层的失败几乎都不是"标得不准"，而是"看起来干净而实际不干净"**——回填用了未来信息（离线更好看）、切分留了泄漏（结论更乐观）、语料带来污染（无指标可查）。**而这三种"不干净"有一个共同点：它们都让指标更好看，因此都不会引起怀疑。**

> 💡 **思考锚点**：从 §6.1–§6.4 里挑一个与你处境最像的案例，只做一件最小的事——按它的"判据"跑一次自测（让新人只看配置开工 / 数能规则化的比例 / 改回填连接条件重跑一次 / 问语料里有没有评测题）。哪一件**今天就能做**就先做它：**这一块的腐化不会报错，只会让结论越来越乐观、而模型上线越来越差。**
