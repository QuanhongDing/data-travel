# 样本库（Sample Library / Training Data Management）

> **一句话定位**：把"训练与评测用的样本"做成**有血缘、有时点、有版本、可回填的资产**——样本是算法侧**最贵且衰减最快**的资产，而它的两个致命问题（**特征穿越**与**评测集污染**）都只在"样本当时看到了什么"被记录下来时才能被发现。

> 本文是 data-travel 项目 [Ch3 · 数据全栈基础设施](../../README.md) 的子章节（**16 样本库**）。覆盖 **R4 数据全栈协同** 能力中"样本库建设"相关的标注工程、样本血缘、特征回填与版本管理实践（这也是招聘要求第 4 条「采集 / 集成、数据流转、**样本库**、评估、反馈闭环」里点名的一环）。本主题**不**重复讲特征平台本身的存储与在线服务（那是 [Ch2 §01 特征平台](../../02-data-science/01-feature-store/01-feature-store.md) 的内容），只讲**"样本"这一层的资产化**——它从哪来、当时看到了什么、怎么切分、怎么防污染。

## 1. 概念与定位

### 1.1 是什么

**工业定义**：样本库是**面向模型训练与评测的样本资产管理**——它把"一条样本"从"一行带标签的数据"升级为**一个带来源、时点、标注过程与版本的资产**。它的最小充分定义：

```
Sample = (entity, event_time, features_ref, label, label_source, label_meta,
          snapshot_id, split, lineage)

  entity        样本主体（用户 / 商品 / 会话 / 设备）
  event_time    这条样本在业务上发生/被观察的时刻  ← 特征只能看这一刻之前的
  features_ref  特征取值的引用（指向特征平台某一版），不是值本身
  label         标签
  label_source  标注方式（人工 / 规则 / 弱监督 / 模型预标注 + 人审 / 线上反馈）
  label_meta    标注元数据（谁标的、何时、一致性如何、原始依据）
  snapshot_id   样本快照版本（切分与评测都绑定它）
  split         训练 / 验证 / 测试 / 线上评测
  lineage       上游数据与特征版本（可复现的依据）
```

**工程定义**：在数据架构师手里，样本库是**四件事**：

- **生产**：标注（人工 / 规则 / 弱监督 / 预标注+人审）与线上反馈回流；
- **对齐**：**特征回填**——按 `event_time` 取那一刻的特征值（点时正确，同一个 `(实体, 时点)` 取到同一份特征）；
- **切分**：训练 / 验证 / 测试 / 线上评测的划分规则与**防泄漏**；
- **治理**：血缘、版本、标注质量度量、漂移监控。

**「样本库」与「特征平台」的分工**（这是本主题的判据表）：

| 维度 | 特征平台（Ch2 §01） | 样本库（本主题） |
| --- | --- | --- |
| 管理对象 | **特征**（定义、存储、在线服务） | **样本**（一条带标签的观测） |
| 回答的问题 | "这个特征现在是多少" | "**这条样本当时看到了什么**" |
| 时间语义 | 点时正确（Point-in-Time） | **时点 + 快照 + 切分**三者同时固定 |
| 主要风险 | 训练线上不一致 | **特征穿越**与**评测集污染** |
| 最贵的成本 | 在线存储与回填算力 | **标注人力**（唯一无法自动化的一项） |

**一条判据**：**当"这条样本当时看到了什么"答不出来时，你手上的是数据集，不是样本库**——而这两个问题的差别，恰好是"模型效果不可复现"与"评测结论不可信"的根源。

### 1.2 为什么需要

样本库不是"存数据的目录"，而是**被四件事逼出来的**：

1. **样本是唯一无法自动化的投入**：数据可以采、特征可以算、模型可以训，而**标注只能靠人**（或靠规则 / 弱监督去近似人的判断）。因此它**最贵**，也最值得被管理。
2. **样本衰减最快**：业务变了、用户行为变了、标注口径变了——**一年前的样本集可能在今天的分布上完全失效**。而"失效"是静默的：**它不报错，只是模型效果慢慢变差**。
3. **两个致命缺陷只在样本层可发现**：**特征穿越**（用了 `event_time` 之后才知道的信息，导致离线虚高、线上崩）与**评测集污染**（评测样本混进训练集，导致结论乐观）。**它们的共同点是：不记"当时看到什么"就永远查不出来。**
4. **标注质量直接决定模型上限**：标注不一致（两个人对同一输入判得不一样）时，模型学到的是**标注者的分歧**，而不是业务规律——**此时再强的模型也只能逼近那个分歧的中位数。**

**这四件事的共同点**：它们都不是"模型好不好"的问题，而是**样本这一层的资产化程度**问题——这正是样本库的职责范围。


### 1.4 演进历程

- **人工整理阶段（2010–2016）**：样本以 CSV / 表格形式存在于各算法工程师手里。**问题**：无血缘、无版本、不可复现，同一样本集在不同人手上不同。
- **标注平台阶段（2016–2020）**：出现标注工具（可配置任务、多人标注、审核流），标注从"个人劳动"变成"流水线"。**收益**：标注有了过程记录与一致性度量。
- **样本库 + 特征回填阶段（2019–2023）**：样本与时点绑定，特征按 `event_time` 回填（点时正确）；样本血缘与版本进入治理。**关键变化**：**离线与线上的一致性第一次有了机制保证**（同 [Ch2 §01 特征平台](../../02-data-science/01-feature-store/01-feature-store.md) 的同一思路）。
- **弱监督与主动学习（2020 至今）**：用标注函数 / 规则生成标签、用模型挑"最该标的样本"，把人工标注量降下来。**关键变化**：**标注成本从"随样本数线性"变成"随难点数增长"。**
- **LLM 预标注与合成数据（2023 至今）**：用模型生成候选标签与候选样本，人来审核。**新问题**：**合成数据会带来分布偏差与"自证"风险**——用模型生成的样本去评模型，评测结论会系统性乐观（§5.2）。

> 演进的主线只有一句话：**样本从"人手里的表格"变成"带时点与快照的资产"，而每一阶段的收益都来自"把某个以前靠人记着的约束搬到系统里"。**

## 2. 核心原理

### 2.1 关键概念定义

- **样本（Sample）**：一条带标签的观测（§1.1 的最小充分定义）。**它必须能回答"当时看到了什么"**。
- **标注口径（Labeling Guideline）**：什么算正例、什么算负例的**可判定描述 + 边界案例**。**判据**：它是可判定的句子与示例，而不是"大家凭经验"。
- **标注一致性（Inter-Annotator Agreement）**：多个标注者对同一输入的一致性（如 Cohen's / Fleiss' Kappa）。**它衡量的是标注口径的清稀程度，不是标注者的水平**——一致性低时，第一反应应当是**改口径**，而不是换人。
- **弱监督（Weak Supervision）**：用多个**标注函数**（规则、启发式、外部知识库）产生带噪声的标签，再聚合。**它的价值在于把"人工标注"换成"标注函数的维护"**，且每个函数可审计（[Snorkel 一类](16-sample-library-section-6-sec6.md)）。
- **主动学习（Active Learning）**：用当前模型挑出"最不确定 / 最可能改变决策"的样本给人标。**它改变的是标注的分配策略**——把人力投到信息量大的样本上。
- **预标注 + 人审（Pre-annotation + Human Review）**：模型先给候选标签，人只做确认与修正。**判据**：修正比例要监控——**修正比例接近零时，要么模型已经很好，要么人在点"同意"**。
- **特征回填（Feature Backfill）**：按样本的 `event_time` 取那一刻的特征值。**它是防穿越的唯一工程手段**（§3.2.6）。
- **特征穿越（Feature Leakage / Time Travel）**：样本的特征里包含了 `event_time` 之后才知道的信息。**症状**：离线指标虚高、线上崩。**成因**：回填用了"最新值"而不是"当时值"。
- **样本快照（Snapshot）**：样本集的一次不可变版本。**切分与评测都绑定快照**——判据：同一次评测能用同一个快照复现。
- **切分泄漏（Split Leakage）**：训练集与测试集存在信息泄漏（同一实体跨集、时间上交错、近重复）。**三种形态**：实体泄漏、时间泄漏、近重复泄漏（§3.2.7）。
- **评测集污染（Benchmark Contamination）**：评测样本以某种形式进入了训练数据（直接混入、或经由合成数据 / 公开语料）。**它是"结论乐观"的最常见成因**，且**只在做污染检查时才发现**（§3.2.8）。
- **样本漂移（Sample Drift）**：样本分布随时间变化（特征分布、标签分布、两者关系）。**判据**：漂移监控要同时看**特征侧**（PSI 一类）与**标签侧**（正例率变化）。

### 2.2 数学 / 形式化基础

**标注一致性的度量**。设 `P_o` 为观测一致率、`P_e` 为随机一致的期望，则 Cohen's Kappa：

```
κ = (P_o − P_e) / (1 − P_e)
判据：κ 的意义要按任务读 ——
  分类边界清晰的抽取任务，κ 低于 0.6【经验】通常说明口径没写清；
  而"这条内容有没有风险"这类主观任务，κ 天然偏低，此时更该看"分歧集中在哪几类"
```

**这条式子的实用读法**：**不要只看 κ 的数值，要看分歧的分布**——分歧集中在少数几类上时，**把这几类的口径写清**就能显著提升一致性；而分歧均匀分布时，说明**任务定义本身有问题**（此时应当缩小任务范围，而不是继续标）。

**特征穿越的形式化**。设样本 `i` 的 `event_time` 为 `t_i`、特征 `f` 的特征值为 `f(i)`，则**点时正确**要求：

```
∀ i, f :  f(i) 只依赖 { 数据 d : timestamp(d) ≤ t_i }

工程上等价于：f(i) = f_as_of(t_i)   —— 取"截至 t_i 的最新值"
反例（穿越）：f(i) = f_latest      —— 取"现在的最新值"
```

**为什么这条约束在本主题里特别重要**：**它无法靠观察发现**——穿越的样本在离线评测上表现更好（因为特征里含了未来信息），因此**"效果虚高"会被当成"模型好"**。**判据**：抽一条样本，问"这个特征值在 `event_time` 那天算得出来吗"——答不出来就是穿越。

**切分的三种泄漏（都可测量）**：

```
① 实体泄漏：同一条样本主体同时出现在训练集与测试集
   检测：按 entity 求交集 —— 交集应当为空（若业务允许多样本/实体，则按"实体分组切分"）
② 时间泄漏：训练集的时间范围与测试集交错
   检测：max(train.event_time) ≤ min(test.event_time) 吗
③ 近重复泄漏：同一条内容以不同形式同时出现在两侧
   检测：对跨集的样本对做相似度检测（阈值按业务定）
判据：三种都要有检测脚本；只做 ① 是最常见的半成品
```

**评测集污染的两种形态与检测**：

```
① 直接混入：评测样本（或其近似）出现在训练数据里
   检测：训练集 × 评测集 做近重复比对；另查"评测集的来源语料是否被用于训练"
② 间接混入：通过合成数据 / 公开语料 / 模型自生成数据带进来
   检测：无法靠比对——只能靠"数据来源台账"（每个训练数据来源登记它可能包含什么）
判据：② 是"看起来干净但实际不干净"的那一类，只有台账能防
```

**样本量的分配（标注预算怎么分）**：

```
设总标注预算 B、主动学习每标一条的期望信息增益 g(x)、随机抽样为 g_rand
则同一预算下的期望收益 ∝ Σ g(x_i)
判据：g 的估计依赖当前模型（不确定度），因此主动学习必须"边标边重训" ——
      一次选完再标，等价于只用最初那个模型的不确定度去挑，收益会衰减
```

**样本漂移的两个轴（必须分开看）**：

```
特征侧：P(X) 变了（例如用户结构变化）—— 用 PSI 一类指标监控
标签侧：P(Y) 变了（例如正例率上升）—— 直接统计
关系侧：P(Y|X) 变了（同样的特征，正例概率变了）—— 最难发现，需要按特征分桶看命中率
判据：只看特征侧会漏掉"关系变了"（X 没变而 Y|X 变了）；只看标签侧会把"业务季节性"误报成漂移
```

### 2.3 关键算法 / 方法

**① 标注任务的配置化（把口径做成可执行的任务）**：

```
一条好的标注任务定义包含
  ① 输入展示：给标注者看什么（原文 / 上下文 / 相关字段）—— 少了上下文会逼人猜
  ② 判定问题：一个可判定的问题（不是"这条好不好"）
  ③ 取值域：枚举写死（不允许自由文本，除非有"其他 + 说明"）
  ④ 边界案例：3–5 个已知难例及其正确判定（口径的主要载体）
  ⑤ 审核规则：谁审、怎么抽、分歧怎么裁
判据：④ 的边界案例是不是这个任务里真正会分歧的地方 ——
      不是的话，标注者仍会各自发挥
```

**② 标注一致性的计算与使用**：

```
流程：同一批样本由 ≥2 人独立标 → 算 κ → 看分歧分布 → 决定动作
  κ 低且分歧集中 ⇒ 补口径（把分歧的那几类写进边界案例）
  κ 低且分歧均匀 ⇒ 缩小任务范围 / 改判定问题
  κ 高 ⇒ 可减少重复标注人数（省人力），但保留抽样复核
判据：κ 是"口径的诊断结果"，不是"标注者的考核指标" ——
      拿它考核个人会导致标注者彼此对齐（人为抬高一致性）
```

**③ 弱监督的标注函数设计**：

```
弱监督的分工：
  标注函数（LF）：每个函数是一个"有倾向性的投票"（准确率不必高，只要比随机好）
  聚合：按各 LF 在留出集上的准确性加权投票，得到概率标签
判据：① 每个 LF 要可审计（用规则表达，而不是黑盒）；
      ② 要有"弃权"（LF 对不适用的情况投 abstain，而不是硬投）；
      ③ 聚合后的标签要留置信度，低置信的进人工复核
```

**④ 特征回填的实现（点时连接）**：

```sql
-- 正确的回填：按样本的 event_time 取"截至那一刻的最新特征值"
SELECT s.sample_id, s.entity_id, s.event_time, f.feature_value
FROM   samples s
LEFT JOIN feature_history f
  ON   f.entity_id = s.entity_id
 AND   f.feature_ts <= s.event_time            -- ← 这一行是防穿越的全部
QUALIFY ROW_NUMBER() OVER (
    PARTITION BY s.sample_id ORDER BY f.feature_ts DESC) = 1;

-- 错误形态（且它在离线指标上更好看）：JOIN "当前最新值"
--   ON f.entity_id = s.entity_id AND f.dt = current_date()
-- 判据：把回填改成"只允许 f.feature_ts <= event_time"，
--      离线指标如果明显下降，说明此前一直有穿越
```

**⑤ 切分与快照的绑定**：

```
切分规则（三种按业务选，且要写死）
  随机切分：只在"实体可重复出现但样本独立"时合法
  按实体切分：同一实体的样本全在同一侧（多样本/实体时必需）
  按时间切分：测试集的时间晚于训练集（最贴近线上，且天然防时间泄漏）
判据：切分规则 + 随机种子 + 快照 id 三者一起记录，否则同一次评测不可复现
```

**⑥ 污染检查脚本（三件）**：**跨集近重复**（训练 × 评测）、**来源语料比对**（评测集的来源是否被用于训练）、**数据来源台账**（每个来源登记"它可能包含什么"，防间接污染）。

### 2.4 与相邻概念的关系

- **样本库 vs [Ch2 §01 特征平台](../../02-data-science/01-feature-store/01-feature-store.md)**：特征平台管**特征**（定义、存储、在线服务、点时正确）；样本库管**样本**（带标签的观测、时点、快照、切分）。**接口是"按 `event_time` 的回填请求"**——样本库给时点，特征平台给那一刻的值。**两者缺一**：只有特征平台时，样本散在各人手里；只有样本库时，特征值可能与样本时点错配（穿越）。
- **样本库 vs [Ch2 §07 效果评估](../../02-data-science/07-eval/07-eval.md)**：评估侧管**指标与检验**（用什么指标、样本量多少、显著性如何）；样本库管**评测集本身**（它从哪来、有没有被污染、切分是否干净）。**接口是"评测集快照"**——评测结论必须绑定快照 id，否则换一版样本集结论就不可比。
- **样本库 vs [Ch4 §08 数据目录](../../04-data-assetization/08-data-catalog/08-data-catalog.md)**：目录管"有哪些资产、谁负责"；样本库是其中**一类特殊资产**（它的价值随时间衰减、且含个人信息）。**接口是"样本集的登记项"**（Owner、快照 id、标注口径版本）。
- **样本库 vs [Ch7 §02 反馈闭环](../../07-agent-evolution/02-feedback-loop/02-feedback-loop.md)**：线上反馈（采纳 / 纠错 / 显式评价）是**样本的重要来源**，但它有偏（只有被曝光的才有反馈，同 [Ch2 §05 推荐](../../02-data-science/05-recommendation/05-recommendation.md) 的"反馈闭环"约束）。**接口是"回流样本的来源标记"**——来自线上反馈的样本必须标出来源与偏置。
- **样本库 vs 标注平台**：标注平台是**生产工具**（任务配置、多人标注、审核流），样本库是**资产层**（血缘、快照、切分、污染检查）。**关系是"工具与资产"**：只有平台时，标注完的样本仍散在导出文件里。

> 💡 **思考锚点**：挑一条你们在用的训练样本，回答四个问题：① 它的 `event_time` 是什么、特征值是**按那一刻**取的吗（还是当前最新值）？② 它属于哪个快照、在哪个切分里（训练还是测试）？③ 它的标签是**谁标的**、当时的口径是什么版本？④ 你们做过**评测集污染检查**吗（近重复比对 + 来源台账）？四问里最先答不出的那一个，就是你下一轮该补的地方——**而第 ① 问答不出时，你的离线指标里就有一部分是借来的（未来信息）。**
