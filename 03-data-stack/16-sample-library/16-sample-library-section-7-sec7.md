## 7. 与其他方法对比

### 7.1 先立判据：为什么打分表会误导

给"自建样本库 / 开源标注工具 + 自建资产层 / 商业标注平台 / 标注外包服务 / 纯人工整理"打分是常见做法，但它有三个结构性问题：

① **同一列在不同处境下方向相反**——"标注界面好用"对**非工程角色参与标注**的团队是必需，对**标注量小、口径稳定**的团队是**风险**（越容易标，越容易在没有口径的情况下标）。
② **打分表隐含"这些选项互斥"**，而真实做法是组合（**开源标注工具 + 自建回填与切分 + 外包做批量**是常见组合）。
③ **最关键的判据不是可打分的维度，而是门槛**——**"回填能不能按时点"**与**"切分能不能防三种泄漏"**这两条是门槛。**一个标注体验极好、但回填用最新值的平台，会让你的全部离线结论建立在一个虚高的基准上。**

**本节采用的 6 条判据**：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| **回填可否做到点时** | 它能不能按 `event_time` 取历史特征值、且历史保留期够？ | **这是门槛不是权重**——不能则全链路离线结论虚高 |
| **切分可否防三种泄漏** | 实体 / 时间 / 近重复检测是内置还是可插？ | 不防 → 结论乐观且**无法察觉** |
| **样本元数据可否导出** | 五个字段能不能导出成不依赖产品的材料？ | 不能 → 换平台要重建样本资产 |
| **污染检查与台账** | 有没有跨集比对与**来源登记**能力？ | 无台账 → 间接污染不可发现 |
| **口径的载体** | 边界案例能不能写进任务配置（而不是文档）？ | 不能 → 一致性靠口头交接，规模无法扩大 |
| **运维承接** | 谁维护口径、谁做检查、谁负责样本增补？ | 本主题人力是主项，**没有承接人的方案会在样本衰减后失效** |

**这 6 条里，前两条是门槛（不满足直接出局），后四条是权重的输入。**

### 7.2 候选方案全景

| 候选 | 定位 | 核心机制（一句话） | 典型使用者 | 主要代价 |
| --- | --- | --- | --- | --- |
| **纯人工整理（表格）** | 最简 | 样本以表格形式在各人手里 | 样本量极小、一次性 | **无血缘、无版本、不可复现** |
| **开源标注工具 + 自建资产层** | 现实默认 | 工具管标注，回填 / 切分 / 检查自建 | 多数团队 | 资产层要自己建（**而它才是门槛所在**） |
| **商业标注平台（含资产层）** | 成品能力 | 标注 + 样本库 + 版本 + 检查一体 | 要快上线、非工程角色要参与 | **回填与切分的口径由产品定**，需压测 |
| **标注外包服务** | 人力补充 | 把标注执行外包（口径由你定） | 批量标注、内部人力不足 | 口径仍需你维护；**质量靠抽检** |
| **弱监督 / 主动学习框架** | 成本优化 | 规则投票 + 按信息量分配人力 | 标注预算受限的团队 | 需留出集估权重；**会改变训练集分布** |
| **ML 平台的样本模块** | 复用既有 | 复用 ML 平台的样本与实验管理 | 已有 ML 平台的团队 | **回填与切分未必可控**（它常按平台自己的约定） |

**这六个候选其实分三族**：

- **生产族**（开源工具、商业平台、外包服务）——**解决"标得出来"**，差别在**口径的载体与人力弹性**。
- **资产族**（自建资产层、ML 平台的样本模块）——**解决"样本是什么、什么时候看到的"**，差别在**回填与切分的可控性**。
- **优化族**（弱监督 / 主动学习）——**解决"省人力"**，差别在**是否改变训练集分布**。

**族内可替换，跨族不可换**：生产族内部换代价可控（**前提是样本元数据能导出**）；从生产族换到资产族**不是替换而是补齐**；而**优化族建在资产族之上**——**回填与切分没做对时，省下的标注人力会被虚高的指标吃掉**（更多样本让错误结论更"显著"）。

### 7.3 机制差异：为什么它们表现不同（核心节）

#### 7.3.1 回填的归属：你的脚本、产品的约定，还是没有回填

**机制是什么**：特征值的取得方式只有三种——**你的回填脚本**（连接条件含时点约束）、**产品按自己的约定取**（通常是"当前最新值"）、**没有回填概念**（样本自带特征副本，且不知道是什么时点的值）。

**它在各候选中的实现差异**：自建资产族**可以完全控制连接条件**（也能把唯一入口做成 CI 检查）；商业平台**按它的约定取**（能不能配时点语义取决于产品，**而这是压测时最该问的一句**）；纯人工整理的样本**特征值往往是"当时导出的那一份"**——它的时点不明，且**从样本本身看不出来**。

**由此必然导出的性质**：因为**穿越会让离线指标更好看**，所以**回填错了不会引起任何怀疑**——它表现为"模型效果好"，而团队会继续在此基础上做一切决策（选型、调参、扩量）。**这条性质决定了回填的归属是本节最硬的一条门槛**：**它不可观察、只能机械检查，因此必须在自己手里。**

**失效条件**：当"离线好、线上差"的差距持续存在且无法归因时，先查回填——**而不是继续调模型。**

#### 7.3.2 切分的归属：三种检查，还是只做一种

**机制是什么**：切分是**按规则脚本切**（可跑三种泄漏检测），还是**按产品的默认切**（随机切，不管实体与时间）。

**它在各候选中的实现差异**：自建族**三种检测都能跑**；平台族**通常只做随机切分**（对"同一实体多样本"的场景会产生实体泄漏）；ML 平台的样本模块**可能支持按实体或时间切**，但**检测是否内置要核**。

**由此必然导出的性质**：因为**三种泄漏各自有确定的检测方法**（§2.2），所以**"防泄漏"不是能力问题而是配置问题**——**而它的收益（结论可信）与成本（几行检查代码）严重不对称**。**这条性质说明：任何"只能做随机切分"的方案，在"一个主体贡献多条样本"的业务上都不合格。**

**失效条件**：当"评测指标明显高于线上表现"而鼓捣不出原因时，先跑三种检测。

#### 7.3.3 口径的载体：任务配置、共享文档，还是个人记忆

**机制是什么**：口径写在哪——**任务配置（含边界案例）**、**共享文档**、还是**在人的脑子里**。

**它在各候选中的实现差异**：开源工具与平台族**都能把边界案例写进任务**（区别是操作是否方便）；外包服务**要求你把口径交出去**（因此载体必须能被外部读懂）；而纯人工整理**根本没有载体**（口径随人走）。

**由此必然导出的性质**：因为**分歧集中在"口径未覆盖的边界"上**（§3.2.1），所以**口径的载体决定了一致性**——**载体是任务配置时，补一个边界案例就能立刻改善一致性；载体是文档时，改动与任务的对应关系靠人维护；载体是记忆时，规模无法扩大。** 这条性质给出一条排序：**先写边界案例，再谈多人标注**。

**失效条件**：当新人标注需要"跟着老人标两周"时，说明口径的载体不合格。

#### 7.3.4 样本衰减的归属：谁负责增补

**机制是什么**：样本会随时间失效（§4.6），**而"谁来增补"决定了样本集是活的还是死的**。

**它在各候选中的实现差异**：外包服务**能按需增补**（只要你愿意继续付费），但**它不负责判断"该重标哪些"**（那是口径与漂移的问题）；自建族**可以按漂移监控触发增补**（三轴指标 → 触发重标 / 增补）；平台族**通常只提供存储与版本，不提供触发机制**。

**由此必然导出的性质**：因为**样本失效是静默的**（不报错、只是效果慢慢差），所以**"增补"必须有触发信号**——**没有漂移监控时，增补只能靠"感觉效果变差了"，而彼时团队通常已经怀疑过模型、怀疑过业务，最后才会怀疑样本。** 这条性质决定了"漂移监控三轴"（§4.5 模板 3）不是可选项。

**失效条件**：当团队用一批一年前的样本反复训模型、并把效果下降归因为"业务变难了"时，说明增补没有触发机制。

### 7.4 成本结构对比（不是价格表，是成本函数）

| 方案家族 | 主导项 | 隐性成本（上线时不计入、第二年计入） | 成本随什么增长 |
| --- | --- | --- | --- |
| **生产族** | 标注人力（或外包费用） | 口径维护、一致性诊断、外包质量的抽检 | 随**样本数 × 任务数**增长 |
| **资产族** | 人力（回填 / 切分 / 检查的维护） | 特征历史保留期的存储成本、检查脚本的持续运行 | 随**样本跨度与样本量**增长 |
| **优化族** | 框架集成 + 迭代重训 | **分布偏移带来的评测重建**（评测集须保持随机抽样） | 随**迭代轮次**增长 |

**成本函数的三条判据**：

① **生产族的成本随时间线性**，且**边界样本永远要人标**（无论弱监督多强）——**因此它的下界不是零**。
② **资产族是"台阶 + 低斜率"**——建回填与检查是台阶，之后维护便宜；**但"特征历史保留期"是一笔随跨度增长的存储成本**（要提前与上游谈）。
③ **优化族的成本藏在"分布偏移"里**——它省下的标注人力，可能被"评测集要重建"吃掉；**表面上省得多，实际要看评测重建的频率**。

**把三条曲线写成式子（读者可代入自己的数）**：

```text
设：N = 样本数   n_label = 需人工标注的比例   t = 单条标注时长   c_h = 人力单价
    N_e = 边界样本数（永远要人标）   S = 样本跨度（月）   c_keep = 单位跨度的历史保留成本
    K = 主动学习迭代轮次

生产族：  Cost_prod(N, n_label) = N × n_label × t × c_h + N_e × t × c_h
                                    ↑ 弱监督与主动学习压的是前者；后者压不动
资产族：  Cost_asset(S)         = 回填与检查的维护人力 + S × c_keep
                                    ↑ 随跨度线性 —— 这是"要提前与上游谈"的那一笔
优化族：  Cost_opt(K)           = 迭代重训 + K × 评测重建成本

反直觉的一条【推算】：当 N_e × t × c_h 在预算里占比很大（边界样本多）时，
   继续投入弱监督的回报会迅速下降 —— 因为边界样本恰恰是规则判不了的那些。
   此时正确的动作是：把边界样本单独管理（难例库），并提高它们的标注优先级。
```

**这个式子的用法**：**先量 `n_label` 与 `N_e`**——前者决定弱监督值不值得投，**后者决定你的人力下界在哪**。**边界样本是弱监督的边界**：它们规则判不了，因此**无论怎么优化，这部分人力都在**。

### 7.5 决策树（每个分支都要有阈值依据）

1. **一个主体会不会贡献多条样本？**
   - **会** → 切分**必须按实体**，且三种泄漏检测都要跑；进入第 2 问。
   - 不会 → 随机切分可接受，但**时间与近重复检测仍要做**。
2. **样本跨度多长（样本最早到现在的时长）？**
   - **超过特征历史保留期** → **先与上游谈保留期**，否则老样本永远回填不出当时的值；进入第 3 问。
   - 在保留期内 → 进入第 3 问。
3. **能不能把回填做成唯一入口并加 CI 检查（按 0.3–0.6 人年的常备投入量级估算【经验】）？**
   - 能 → **自建资产层**（回填、切分、检查都在自己手里）；生产工具可外购。
   - 不能 → 买平台，但**必须压测两条门槛**：回填能否按时点、切分能否按实体与时间。
4. **标注需求里"规则能判"的比例大概多少？**
   - **一成以上** → 值得投入弱监督（先估这个比例再投入）。
   - 一成以下 → 直接用人工标注 + 主动学习分配人力。
5. **要不要对外举证（交付 / 审计 / 对外评测）？**
   - 要 → **来源台账必须自建**（没有任何产品会替你登记"你的数据从哪来"）。

**阈值的诚实说明**：上表的"一成""0.3–0.6 人年"都是【经验】档——它们用来区分"这一档"与"那一档"，请用你自己的比例与排期校准，**不要当门槛用**。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因 |
| --- | --- | --- | --- |
| 样本量极小、一次性 | 表格 + 元数据字段 | 开源工具 | 上平台是治理过剩；**但元数据字段仍要写** |
| 样本量大、要多人参与 | 开源工具 + 自建资产层 | 商业平台 | 平台的回填与切分口径要压测 |
| 非工程角色参与标注 | 商业平台（**核边界案例可写性**） | 开源工具 + 培训 | 载体不合格则一致性靠口头交接 |
| 内部人力不足、要扩量 | 外包（**口径自持 + 抽检**） | 弱监督 + 人工 | 外包不负责判断"该重标哪些" |
| 预算受限、样本池大 | 弱监督 + 主动学习 | 纯人工 | **须先估"能规则化的比例"** |
| 已有 ML 平台 | ML 平台的样本模块 + **自建回填与检查** | 全自研 | 平台的回填约定未必按时点 |
| 要对外交付 / 过审计 | 自建（**台账 + 授权链 + 快照**） | 平台（核台账能力） | 无台账则间接污染无解 |
| 样本跨度长（跨年） | 自建 + **先谈历史保留期** | —— | 保留期不足时，任何工具都回填不出当时值 |

**组合的两条次序原则**：① **先把回填与切分收成唯一入口，再谈标注效率**——顺序反了会让"省下的人力"被"虚高的指标"吃掉（§7.2 的族间关系）；② **先把口径的载体做对（边界案例进配置），再扩标注规模**——载体不合格时，加人只会让分歧多样化。

**第三条原则（方向相反但同样重要）**：③ **先把漂移监控建起来，再谈样本增补**——**没有触发信号时，增补只能靠"感觉效果变差了"**（§7.3.4）。

### 7.7 选错的代价与迁移成本

| 选错的方向 | 症状 | 迁移动作 | 工作量量级 |
| --- | --- | --- | --- |
| 无回填 → 点时回填 | 离线好线上差 | 建回填脚本唯一入口 + CI 检查 + 重跑评测 | **以月计**，且**离线指标会下降**（还账） |
| 随机切分 → 按实体 / 时间 | 评测乐观但说不清为什么 | 重切 + 三种检测 + 快照管理 | 以周计（**历史结果不可比，要留旧切分快照**） |
| 无元数据 → 有 | 无法回答"当时看到什么" | 补字段 + 存量样本批量标注（**部分字段补不回来**） | 以月计，且**"谁标的 / 当时的口径版本"永久未知** |
| 平台锁定 → 自建 | 换平台要重建样本资产 | 导出元数据 + 重建回填与检查 | **以季度计**，且**历史检查结果不可迁移** |
| 纯人工 → 弱监督 + 人工 | 标注预算不够用 | 写标注函数 + 留出集估权重 | 以月计（**先估"能规则化的比例"再决定**） |
| 无台账 → 有 | 无法回答语料里有无评测题 | 逐个来源补登记 | **以周计建台账，但存量来源的补登最难** |
| 评测集非随机 → 随机 | 评测高而全量低 | 重抽评测集 + 重建基线 | 以周计，**且此前的评测结论不可比** |
| 预标注无抽检 → 有 | 修正比例低而被当成模型好 | 补未修正批的独立重标 | 以周计 |

**一条硬结论**：八条里最贵的是**"平台锁定之后的收回"**——不只是元数据重建，而是**历史检查结果（泄漏 / 污染 / 一致性）不可迁移**，因此**你会失去"过去这些结论是否可信"的依据**。**所以门槛（回填能否按时点、切分能否防三种泄漏）必须在第一版就判对。**

**第二条硬结论**：上表里有两项的代价**部分不可逆**——"无元数据 → 有"里的"谁标的 / 当时口径版本"（**事后补不回来**）与"评测集非随机 → 随机"里的历史结论（**不可比**）。**其余六项都是"要花时间"**；这决定优先级：**如果只能做一件事，先把五个元数据字段写上**（成本极低），而不是先优化标注效率。

### 7.8 小结

> 本节小结：六个候选之间的差异，最终都能归到四问——**回填归谁且能不能按时点**、**切分能不能防三种泄漏**、**口径的载体是任务配置还是人的记性**、**样本衰减由谁触发增补**。四问决定了它们的分族（生产族 / 资产族 / 优化族）与成本曲线（生产族随时间线性但有下界、资产族台阶 + 随跨度增长的保留成本、**优化族的成本藏在评测重建里**）。**选型顺序不可颠倒**：先用"主体是否重复"与"跨度是否超过保留期"筛掉不可行，再用"能不能把回填与切分收成唯一入口"决定自建还是外购，最后才用标注比例与举证需求在剩下的里选——**把门槛当权重，是第二年最常见的失效原因**。**本主题有一条与其它主题不同的推论**：**优化族的回报有一个硬下界——边界样本永远要人标**（`N_e × t × c_h`，§7.4），因此**弱监督投到一定程度后，正确的动作是把边界样本单独管理并提高优先级**，而不是继续加函数。

> 💡 **思考锚点**：拿 §7.1 的六条判据给你现在的方案做一次**门槛检查**（不是打分）：回填可否按时点、切分可否防三种泄漏、元数据可否导出、污染台账、口径载体、运维承接——**哪一条是"不满足"而不是"分数低"**？那一条就是你最可能被迫迁移的方向（§7.7）；而你今天的补救成本，是否还落在"以周计 / 以月计"的那几格里？**另一问更具体**：如果明天换掉现在的样本平台，**你的元数据、检查结果与评测集快照能不能带走**？答不出，说明样本资产还没有真正掌握在自己手里。
