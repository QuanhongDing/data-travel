## 3. 设计模式与范式

### 3.1 先看约束：模式不是选择题，是约束的产物

样本库的形态由**五条约束**决定，顺序不能颠倒：

1. **标签能不能被规则化**：判定是"可写成规则的"（金额超限、字段缺失），还是"只有人看得准"？**能被规则化的部分不必耗人力**——这一条决定人工标注的**范围**，而范围决定成本。
2. **样本主体会不会重复出现**：一个用户会不会贡献多条样本？**会，则切分必须按实体分组**，否则出现实体泄漏（约束 5 的前置）。
3. **样本的时间跨度有多长**：样本从"近期快照"（几周）到"跨年历史"？**跨度越长，特征回填的时点正确性越关键**——长跨度下"用最新值回填"的穿越幅度最大。
4. **要不要对外举证**：数据集要交付给客户 / 过审计 / 参与对外评测吗？**要，则血缘、来源台账、授权链都要能出示**。
5. **谁维护标注口径**：口径是一份会演进的资产（业务变了它就要改），**有没有人负责写边界案例、裁分歧、维护版本**？**没有这个人，一致性会在三个月内退化**（因为新样本落在口径未覆盖的边界上）。

> **判据的用法**：先用 1 圈定人工标注的范围（把能规则化的剔出去）；用 2 决定切分方式；用 3 决定回填策略的严格度；用 4 决定血缘字段的完整度；用 5 决定要不要把口径当资产管。**跳过第 5 条最常见的后果**：样本集在头两个月质量很好，之后**一致性缓慢下降而没人察觉**——因为下降是渐进的，且**看指标看不出来**（模型效果下降会被归因为"业务变难了"）。

**每条约束的"过关"是可核查的**：

| 约束 | 过关的可核查标志（不是"我们考虑了"，而是"我们量过"） |
| --- | --- |
| 1 能否规则化 | 标注预算里"其实规则能判"的比例（应为零，否则在浪费人力） |
| 2 主体是否重复 | 一条实体在训练与测试两侧同时出现的条数（应为 0） |
| 3 时间跨度 | 回填用的连接条件里有没有 `feature_ts <= event_time`（做成脚本可查） |
| 4 是否对外举证 | 每个样本都有 `label_source` 与 `lineage` 吗；来源台账存在吗 |
| 5 口径维护人 | 口径文档有版本、有 Owner、有最近一次边界案例更新记录 |

### 3.2 模式逐个拆解（核心节）

#### 3.2.1 人工标注平台（配置化任务 + 多人 + 审核）

**被什么约束逼出来**：判定只有人看得准（约束 1 的另一侧），且样本量超出"一个人能管"的规模。

**结构**：任务配置（输入展示 + 判定问题 + 取值域 + 边界案例）→ 多人独立标注 → 一致性计算 → 审核与裁定 → 入库（带 `label_meta`）。

**为什么这样设计有效**：因为**它把"口径"从一个人的脑子里搬到任务配置里**——边界案例写进任务后，**新标注者不需要口头交接**，而一致性也第一次可以被测量（§2.2 的 κ）。**它的有效性来自"口径的可传递性"**：口径不可传递时，标注规模无法扩大（每加一个人就要重新校准一遍）。

**代价**：① **口径的维护成本随任务数增长**（每个任务一套边界案例）；② **一致性测量需要重复标注**（同一批样本至少两人标，人力翻倍——因此通常只对**抽样批次**做重复）；③ **审核环节会积压**（同所有人审闸门的积压问题，需要超时与转交规则）。

**失效点**：**任务定义里没有边界案例**——此时标注者遇到难例只能各自发挥，**而分歧会集中在这些难例上**（也就是模型最需要正确的那些样本上）。**判据**：κ 的分歧分布是否集中在少数几类上——集中，说明补边界案例就能解决。

#### 3.2.2 规则 / 弱监督标注（标注函数）

**被什么约束逼出来**：判定里有一部分**可以写成规则**（约束 1），而全用人工标是浪费。

**结构**：把"能判的"写成多个**标注函数**（每个有倾向性、可审计）→ 聚合（按各函数在留出集上的准确性加权）→ 得到**概率标签** → 低置信进人工复核。

**为什么这样设计有效**：因为**它把"标注"从一次性人力投入，变成"标注函数的维护"**——而规则是**可审计、可解释、可版本化**的（这是它比"再训一个模型来打标"优越的地方：**你知道它为什么这么判**）。**第二条有效性来自"弃权"**：允许函数对不适用的样本投 `abstain`，比强迫它硬投一个值要好——**硬投会把噪声均匀洒进数据，而弃权把它集中暴露出来。**

**代价**：① **聚合权重要在留出集上估计**（因此仍需要一部分人工标注作为"锚"）；② **规则会腐化**（业务变了规则不变，会静默产出错标签）；③ **标签是概率的**（下游要能接受软标签，或按阈值切）。

**失效点**：**没有弃权机制**——所有函数对所有样本都投一个值，于是**"不适用的样本"被硬投成噪声**，而它表现为"模型在某些子群上效果差"，**很难追到标注层**。**判据**：标注函数签名里有没有"不适用"这一档。

#### 3.2.3 主动学习（把人力投到信息量大的样本上）

**被什么约束逼出来**：标注预算有限，而**随机抽样的样本里大部分对模型没有新信息**。

**结构**：用当前模型对候选池打分（不确定度 / 预期模型变化）→ 选 top-k 交人标 → **标完重训 → 再选**。

**为什么这样设计有效**：因为**它把预算从"均匀覆盖"改成"投在决策边界上"**——而模型的提升**恰恰来自边界样本**（大量已能正确判的样本标了也不改变模型）。**这条机制有一个硬前提：边标边重训**（§2.2 的判据）——一次性选完再标，等价于只用最初那个模型的不确定度去挑，**收益会随轮次迅速衰减**。

**代价**：① **它会让样本分布偏离线上分布**（过度集中在边界上）——因此**训练用主动学习样本、评测**必须另用**随机抽样**（否则评测集也是边界偏向的，结论不能代表线上）；② 迭代成本（每轮重训）；③ 冷启动时模型太差，不确定度估计不可靠。

**失效点**：**用主动学习选的样本去做评测集**——这是一条不显眼的错误：**评测集代表线上分布是它的全部意义**，而主动学习样本恰恰**不代表线上分布**。**判据**：评测集的抽样方式是不是随机的（与训练集来源分开记录）。

#### 3.2.4 模型预标注 + 人审

**被什么约束逼出来**：模型已经能判得不错，全人工浪费；但模型的判断不能直接当标签（约束：标签质量下限）。

**结构**：模型给候选标签（带置信度）→ 人**确认或修正**（不是从零判断）→ 入库并记录"是否被修正"。

**为什么这样设计有效**：因为**人的成本从"判断"降到"确认"**——若是判断类任务，确认的认知负荷显著低于从零判断（同 [Ch10 §04 §6.3](../../10-industry-agent/04-office-automation-agent/04-office-automation-agent-section-6-sec6.md) 的"改比写快"）。**而它的有效性依赖一个可观测的指标：修正比例。**

**代价**：① **修正比例会给出两个相反的信号**——接近零可能是模型很好，**也可能是人在点"同意"**（同人审闸门的"橡皮图章"）；② **模型偏差会被固化**（人倾向于接受看起来合理的候选，于是模型的系统性偏差进入标签）；③ **抽样复核仍不可省**（预标注的产出必须按比例抽检）。

**失效点**：**把"修正比例低"当成"模型好"**——判据是**抽检**：从"未被修正"的样本里随机抽一批独立重标，看准确率是否与"被修正"的那批相当。**如果未修正批的抽检准确率明显低于被修正批**，说明人在盲从。

#### 3.2.5 线上反馈回流（有偏采样）

**被什么约束逼出来**：线上行为/反馈是**免费且真实**的标签来源（采纳、纠错、显式评价）。

**结构**：线上事件 → 转成样本（带来源标记与曝光上下文）→ **按偏置加权或分层** → 入库。

**为什么这样设计有效**：因为它**零标注成本**，且**分布就是线上分布**（这是它比主动学习样本更贴线上的一点）。**它的有效性取决于是否处理了"只有被曝光的才有反馈"**——没有处理时，模型学到的是"当前策略的偏好"，而不是"用户的偏好"（同 [Ch2 §05 推荐](../../02-data-science/05-recommendation/05-recommendation.md) 的反馈闭环约束）。

**代价**：① **偏置必须显式**（曝光策略决定样本分布）；② **反馈稀疏且滞后**（显式评价极少、转化要等）；③ **它奖励的是"当前策略下的表现"**——因此**只用它训练会让策略越来越窄**。

**失效点**：**把回流样本当无偏样本用**——症状是"线上指标好而全量评估差"（因为评估用的是同一批曝光样本）。**判据**：回流样本的来源是否与"曝光策略版本"绑定记录——不绑就永远无法分析偏置。

#### 3.2.6 特征回填（点时连接）

**被什么约束逼出来**：样本的 `event_time` 与特征的可用时点必须对齐（约束 3）。

**结构**：按 `(entity, event_time)` 取"截至那一刻的最新特征值"（§2.3 的 SQL）；**回填脚本是唯一入口**，不允许各人自行 JOIN。

**为什么这样设计有效**：因为它把**防穿越**从"靠人记得用对时点"变成**一条写在连接条件里的约束**（`feature_ts <= event_time`）。**这条约束的性质与其它模式不同：它无法靠观察发现是否被违反**——穿越的样本在离线评测上**表现更好**，因此"效果虚高"会被当成"模型好"。

**代价**：① **回填要读历史特征版本**（存储与查询成本高于读最新值）；② **长跨度样本的回填很重**（跨年的历史特征要能查到）；③ **特征平台的历史保留期**成为硬约束——**保留期短于样本跨度时，老样本永远回填不出当时的值**。

**失效点**：**用"当前最新值"回填**（§2.3 的错误形态）——它更简单、更快，且**离线指标更好看**。**判据**：把连接条件改成 `feature_ts <= event_time` 重跑一次，**离线指标若明显下降，说明此前一直在穿越**。

#### 3.2.7 切分与快照（防三种泄漏）

**被什么约束逼出来**：样本主体会重复出现（约束 2），且评测结论要求可复现。

**结构**：三种切分规则按业务选（随机 / 按实体 / 按时间）＋ **快照 id** ＋ 随机种子；**切分脚本是唯一入口**。

**为什么这样设计有效**：因为**三种泄漏（实体 / 时间 / 近重复）各自有确定的检测方法**（§2.2），而**它们都能被脚本一次性堵住**——这是本主题里"投入产出比最高"的一处：**几行检查代码，换来评测结论的可信。** 与回填不同的是，**泄漏是可以被检测的**（实体交集、时间边界、跨集相似度），因此它属于"可机械化"的一类。

**代价**：① **按时间切分会牺牲样本量**（测试集只能是最近一段，而最近一段通常样本少）；② **按实体切分要求实体标识可靠**（OneID 不统一时会切错）；③ **快照要长期保留**（评测结论的可复现依赖它）。

**失效点**：**只做实体切分、不做时间与近重复检查**——这是最常见的半成品：实体泄漏堵住了，而**时间交错与近重复仍在**。**判据**：三种检测脚本各跑一次，各返回 0。

#### 3.2.8 污染检查与数据来源台账

**被什么约束逼出来**：评测结论要被信任（约束 4），而**污染会让结论系统性乐观**。

**结构**：**三件**——① 跨集近重复比对（训练 × 评测）；② 评测集的**来源语料**是否被用于训练；③ **数据来源台账**（每个训练数据来源登记"它可能包含什么"）。

**为什么这样设计有效**：因为**直接污染可以被比对发现，而间接污染（经由合成数据 / 公开语料 / 模型自生成）不能**——**只有台账能防**。**台账的机制价值在于它把"我用的数据从哪来"变成一条需要被登记的陈述**：**没有台账时，"这份公开语料里有没有我的评测题"这个问题在那个时点已经无法回答**（因为语料是黑箱下载下来的）。

**代价**：① **台账要人工维护**（每个来源一条记录，含来源描述与可能内容）；② **近重复比对有算力成本**（跨集全对比较重，通常用向量近似 + 抽样）；③ **它挡不住"你自己生成的合成数据里包含评测题"**（如果合成过程用了评测集）——这一条只能靠**流程隔离**（合成与评测用不同的数据分区）。

**失效点**：**只做比对、不做台账**——比对能发现"训练集里出现过的评测样本"，但发现不了"训练用的公开语料里有评测题"（因为它不是近重复，可能经过改写）。**判据**：能不能回答"上个月加进来的那个公开数据集里，有没有我们的评测题"——答不出，说明台账缺失。

### 3.3 模式选择决策表

| 约束组合 | 推荐模式 | 必须同时上的部件 | 不选它的原因（反面） | 关键判据（可核查） |
| --- | --- | --- | --- | --- |
| 判定只有人看得准、量不大 | 3.2.1 人工标注平台 | 任务配置（含边界案例）、一致性测量、审核流 | 上弱监督是重武器 | κ 与分歧分布 |
| 判定里有一部分可写成规则 | 3.2.2 弱监督 | **标注函数含弃权**、聚合权重、留出集 | 全人工会浪费人力 | 函数签名里有没有"不适用" |
| 预算有限、候选池大 | 3.2.3 主动学习 | **边标边重训**、评测集另用随机抽样 | 用主动学习样本做评测 ⇒ 结论不代表线上 | 评测集抽样方式是否随机 |
| 模型已能判得不错 | 3.2.4 预标注 + 人审 | **修正比例监控 + 抽检** | 修正比例低可能是盲从 | 未修正批的抽检准确率 |
| 线上行为/反馈可用 | 3.2.5 反馈回流 | **来源与曝光策略版本绑定**、偏置处理 | 当无偏样本用 ⇒ 策略越训越窄 | 来源是否绑定曝光版本 |
| 样本跨度长、要防穿越 | 3.2.6 点时连接 | **回填脚本唯一入口**、特征历史保留期 ≥ 样本跨度 | 用最新值回填 ⇒ 离线虚高 | 连接条件有没有 `ts <= event_time` |
| 主体重复出现、结论要复现 | 3.2.7 切分 + 快照 | **三种泄漏检测各跑一次**、快照与种子记录 | 只做实体切分 ⇒ 时间与近重复仍在漏 | 三种检测是否各返回 0 |
| 结论要被信任 / 对外举证 | 3.2.8 污染检查 + 台账 | 跨集比对、来源语料比对、**来源台账** | 只比对 ⇒ 间接污染发现不了 | 能否回答"某个公开语料里有没有评测题" |

### 3.4 组合模式：真实系统不会只用一种

1. **生产组合**：3.2.2（弱监督，覆盖能规则化的部分）+ 3.2.1 或 3.2.4（人工处理剩余与边界）——**先剔除能规则化的，再花人力**；顺序反了会把预算花在机器能判的样本上。
2. **对齐组合**：3.2.6（点时回填）+ 3.2.7（切分与快照）——**这两件是"结论可信"的地基**：一个防穿越、一个防泄漏；**两者都必须是唯一入口的脚本**，否则会被绕过。
3. **来源组合**：3.2.3（主动学习，训练集）+ **随机抽样（评测集）** + 3.2.5（回流，线上分布）——**三类来源的用途不同**：主动学习喂训练、随机抽样做评测、回流贴近线上；**混用它们的角色会得出错误结论**。
4. **信任组合**：3.2.8（污染检查 + 台账）+ 3.2.7（快照）——**结论要能复现且未被污染**。

**常见误配**（每条对应一个可观测的后果）：

| 误配 | 后果（可观测） |
| --- | --- |
| 用最新值回填特征 | 离线指标虚高、线上崩 |
| 只做实体切分 | 时间交错与近重复仍在泄漏 |
| 用主动学习样本做评测 | 评测结论不代表线上分布 |
| 回流样本不绑曝光版本 | 无法分析偏置，策略越训越窄 |
| 预标注无抽检 | 人在盲从，模型偏差被固化 |
| 弱监督函数无弃权 | 噪声均匀洒进数据，难点上效果差 |
| 无来源台账 | 间接污染（公开语料 / 合成数据）无法发现 |
| 口径无 Owner | 一致性缓慢下降且无人察觉 |
| 回填允许各人自行 JOIN | 穿越无法机械检测 |
| 评测不绑快照 | 换一版样本集结论就不可比 |

### 3.5 反模式与失效分析

| 反模式 | 症状（怎么发现它） | 机制层面的后果 | 成因（为什么会写成这样） |
| --- | --- | --- | --- |
| **用最新值回填** | 离线好、线上差 | 特征穿越，且**离线指标更支持这个错误** | 读最新值更快更省 |
| **只做实体切分** | 实体交集为 0 而结果仍乐观 | 时间与近重复泄漏 | 三种检测只做了一种 |
| **主动学习样本当评测集** | 评测指标高而全量评估低 | 评测集不代表线上分布 | 省了一次随机抽样 |
| **回流样本当无偏** | 线上指标好、全量差 | 策略越训越窄 | 曝光偏置未记录 |
| **预标注无抽检** | 修正比例极低 | 人在盲从、偏差固化 | 修正比例被当成质量指标 |
| **弱监督无弃权** | 某些子群效果差，追不到原因 | 噪声均匀分布 | 函数签名设计时省了一档 |
| **无来源台账** | 无法回答"语料里有没有评测题" | 间接污染不可发现 | 台账要人工维护 |
| **口径只在一人脑子里** | 新人标注需口头交接 | 规模无法扩大、一致性退化 | 边界案例没写进任务 |
| **样本散在各人手里** | 同一样本集两人手上不同 | 结论不可复现 | 没有唯一入口 |
| **拿 κ 考核标注者** | 一致性人为抬高 | 口径的真实问题被掩盖 | κ 被当成绩效指标 |
| **把"样本量大"当质量** | 标注量大而边界覆盖差 | 模型在难点上仍差 | 量比构成更容易汇报 |
| **评测集与训练集同源而无隔离** | 合成数据自证 | 结论系统性乐观 | 合成与评测共用数据分区 |

### 3.6 规模跃迁时模式何时该换

| 跃迁 | 开始疼的信号 | 换成 | 迁移的代价 |
| --- | --- | --- | --- |
| 人工整理 → 标注平台 | 新人交接靠口头、样本散在各处 | 3.2.1 | 任务配置与边界案例补写；存量样本补元数据 |
| 全人工 → 弱监督 + 人工 | 标注预算里"规则能判"的比例高 | 3.2.2 | 标注函数设计 + 留出集 + 聚合权重 |
| 随机抽样标注 → 主动学习 | 预算不变而模型提升变慢 | 3.2.3 | **边标边重训的迭代流程**；评测集须保持随机抽样 |
| 无回填 → 点时回填 | 离线指标明显高于线上【经验：出现"离线好线上差"即触发】 | 3.2.6 | 历史特征保留期要够；回填脚本统一入口 |
| 单一切分 → 三种泄漏检测 | 结果乐观但说不清为什么 | 3.2.7 | 检测脚本 + 快照管理 |
| 无台账 → 有 | 出现"评测题在训练语料里" | 3.2.8 | 逐个来源补登记（**存量来源的补登最难**） |
| 口径无 Owner → 有 | 新样本落边界上时各自发挥 | 3.2.1 的边界案例 + 版本 | 每个任务一套边界案例的维护成本 |

**一条通用判据**：**跃迁的触发点不是"样本变多"，而是"某个失效形态第一次出现"**——第一次出现"离线好线上差"就该查回填；第一次出现"结果好得不真实"就该查切分与污染；第一次出现"标注预算不够用"就该考虑弱监督与主动学习。**按样本量预设跃迁点，几乎一定过早或过晚。**

### 3.8 小结

> 本节小结：样本库的形态由五条约束按序决定——**标签能否规则化 → 主体是否重复 → 时间跨度 → 是否对外举证 → 谁维护口径**；八种模式里，**点时回填与切分快照（3.2.6 / 3.2.7）是"结论可信"的地基**（一个防穿越、一个防泄漏，且两者都必须是唯一入口的脚本），**弱监督 + 人工（3.2.1 / 3.2.2）决定成本**，**主动学习与预标注（3.2.3 / 3.2.4）改变人力的分配方式**，而**污染检查与来源台账（3.2.8）决定结论能不能被信任**。判断这一套有没有建成，只看两条：**抽一条样本，能不能说出它当时看到了什么**；**三种泄漏检测与污染检查，能不能各返回 0**。**本主题最反直觉的一条**：**特征穿越会让离线指标更好看**——因此"效果虚高"不会引起怀疑，反而会被当成模型好；**唯一的发现方式是机械地检查连接条件，而不是看指标。**

> 💡 **思考锚点**：从 §3.2 里挑一条你系统已有的做法，问三个问题：它**防的是哪一类失效**（穿越 / 泄漏 / 污染 / 盲从 / 偏置）？它的**失效形态是什么**？**有没有一个可执行的检查**能证明它此刻生效？第三个问题往往最有价值——**"回填生效"的证明是"把连接条件改成时点约束后指标明显下降"，"切分生效"的证明是"三种检测各返回 0"，"台账生效"的证明是"能回答某个语料里有没有评测题"**。你打算先补哪一条？
