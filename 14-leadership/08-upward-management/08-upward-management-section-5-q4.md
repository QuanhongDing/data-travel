## 10. Q4 计划

季度计划会是少数几个「钱还没花、话还能改」的场合：编制、预算、跨团队配合都要在这里或这里之前定下。多数人把它开成了**表态会**——把计划讲成「我会努力做好」，因为表态当场不会被追问，说出来舒服；代价是它换不到任何资源，也拦不住任何风险。

它难在哪：**认知链与分配链是两条链**。对方听懂你的计划属于认知链；人和钱怎么落地属于分配链，而分配链按**窗口**运作——预算与编制的口子常常在计划会之前就定了。于是同一场会上，你把计划讲得再清楚，只要它没有被换成一个当场动作（拍板 / 指派 / 被写进对方的材料），下一次排序时它就会被排到别人后面。

第二层难处在你自己身上：**计划会的现场会奖励模糊**。说得越具体，被追问的面就越大；说得越像表态，当场越安全。这份脚本的全部设计都对抗这个默认倾向——每一段都带一个**要对方做的动作**，而不是一个要对方听懂的结论。

### 10.1 什么场合用

**触发条件**（满足两条即该用）：
- 你需要在下一个季度内新增 HC、预算、算力或工具，且它们不在你当前的授权额度内【经验：额度随组织授权层级与你的岗位级别而变】。
- 你有一条**关键路径**是单点（只有一个人能改、只有一条链路能跑），而本季交付压在这条路径上。
- 你手上已有至少一个**必须提前说**的坏消息（延期、合规缺口、依赖方掉链子）——同一件事，今天说与晚一个季度说，账单不同。

**谁在场**：你的 +1（决策者与转述者）、能给资源的预算人（可能是 +1 的上游）、以及要配合你的跨团队 Owner。

三类听众关心的东西并不一样，同一份材料必须能按听众换第一屏：

| 听众 | 他首先看什么 | 你的第一屏该放 |
| --- | --- | --- |
| 预算人 | 钱与周期（什么时候释放、什么时候见效） | 成本与收益的等式、释放节奏 |
| 技术上级（你的 +1） | 风险与可行性（谁做、单点在哪） | 关键路径与单点、依赖方 |
| 非预算上级（+2 / 跨 BU） | 战略与影响面（与他的目标什么关系） | 一句话定位 + 影响面 |

**不适用**：纯内部的排期草稿；以及「资源窗口已关、只做进度同步」的会上首次提资源需求。

后一条值得单独说清它为什么贵：需求被记过一次顺延之后，你下一次要论证的就不只是需求本身，还要论证「上次是我判断失误，还是资源环境真的变了」——后一个问题几乎无法自证。所以窗口（见 §3.2.8）不是流程细节，它是这份材料唯一的有效期。

### 10.2 脚本骨架（可套用）

```text
第一段｜目的：用上一季的结果开场，先让对方拿到「你的数字可信」这个前提
    「Q{上一季}我这边三件事：{结果 1，带口径}、{结果 2，带口径}、
      以及一件没做到的事：{X}，原因是 {Y}，我已经 {已做的动作}。」
    → 结构是结论先行 + SCQA（情境 → 冲突 → 问题 → 答案），半分钟内讲完
      【经验：讲完时长随听众层级与是否要交代背景而变】

第二段｜目的：报 Q4 目标，每条自带一个可核验判据，并说明不做的代价
    「Q4 我承诺三条：① {目标}，验收方式是 {哪个数、什么时候、谁来看}；
      ② {目标}，验收方式 {…}；③ {目标}，验收方式 {…}。
      其中 ② 不做的话，代价是 {代价，同口径}。」
    → 目标用「示例形态」占位，数字必须换成你自己的监控与合规基线，本脚本不提供业绩目标：
      「RAG 系统优化到 P95 < {你的目标值}」「数据治理覆盖 {你的业务线范围}」
      「完成等保认证（现行为等保 2.0 系列标准、按级别计，请以主管部门与测评机构当前要求为准）」

第三段｜目的：要资源——四类全部挂在「不投入的代价」上，不挂在愿望上
    ① HC（招聘名额）：「当前 {关键路径} 上只有 {N} 人可改，业务增长 {口径}，
        需要 {Z} 个 HC 才能并行。」
    ② 预算（算力 / 工具 / 培训）：「投入 {X}，预计收益 {Y}，ROI = {Y/X}，口径来自 {来源}。」
    ③ 技术投入（新平台 / 新工具）：「预期节省 {Z} 人天 / 提升 {W}% 效率，口径 {…}。」
    ④ 跨团队资源（Sponsor / 跨 BU 支持）：「影响的是 {全公司口径的业务}，
        需要 {具体的人或团队} 在 {具体场合} 站台。」

第四段｜目的：把风险写成计划的一部分，而不是出事之后的通报
    ① 立即汇报：发现即说，不等根因完全清楚
    ② 事实 + 影响：先讲事实与影响面（哪些下游、哪条承诺），再讲判断
    ③ 解决方案：每个风险带 2–3 个各自写清代价的选项
    ④ 主动担责：自己的部分先认，再讲外部原因
    ⑤ 后续跟进：约定下次同步的时点与内容
    → 这五个动作要以固定顺序说，完整流程（5 步法）见 §8 面试真题集 §14.8.2；
      §4 工程实现的模板 6 给的是另一套更格式化的五步上报清单（事实 / 影响 /
      已做 / 需要你 / 下次同步），与上面五步不是同一套，不要混着套。它们
      服务于同一个三段式（① 事实 ② 我的判断 ③ 选项，见 §3.2.9）——「缺任一段
      都会退化成单纯的坏消息」说的是那个三段式，不是这五个动作

第五段｜目的：把决定变成选择题——这一段最常被跳过
    「所以请你今天定一个：A 不给 → 我把 {范围} 砍掉；
      B 给一半 → {哪一条}延一个季度；C 给足 → 三条全保。」
    → 让对方做选择，而不是做审批；每个选项必须自带代价

第六段｜目的：复述你听到的决定，并挂上下次复查的时点
    「我听到的是 {决定}。我按 {口径} 在 {MBR / QBR 时点} 复查是否兑现。」
    → 复查节奏用 30 / 60 / 90 天三个检查点
      【经验：检查点间距随交付周期与组织的评审节奏而变】
```

开场那一句「一句话定位」按听众换说法，三选一：

```text
给 +1：      「{领域} 这一季的一句话是 {结论}，它决定 {哪条承诺} 能不能保。」
给预算人：    「{领域} 这一季需要 {资源量}，换取 {交付提前量 / 影响面收敛}。」
给 +2 / 跨 BU：「{领域} 这一季的一句话是 {结论}，与您 {哪条目标} 直接相关。」
```

整份骨架通常讲 20–40 分钟【经验：时长随会场类型、在场人数与是否留讨论时间而变】。时长被压到只剩开场与结论时，保留**第一、三、五**三段，其余整段砍掉、材料放进附录，等有人问再给——被压缩掉的如果是第五段，这次会就不必开了。

最常被跳过的是**第五段**。跳过之后，整场会从选择题退化成审批题，对方只需要回一句「再想想」——你拿到的是零，而不是一个被修正过的目标。第三段也没好到哪去：把资源挂在「我们很努力」「行业都在投」上，等于请对方替你想理由。

**该带什么材料进来**：① 上一季的数字，每个都带口径与来源；② 四类资源的清单，每类写清周期与释放时点；③ 坏消息清单，逐条带影响面与选项；④ 跨团队资源的**具体人名或团队名**——写「某业务方」等于没写。缺 ①，对方一定会绕开你的论点去追口径；缺 ④，跨团队资源那一类会被当场改写成「你去协调一下」。

材料本身还有三条纪律（展开见 [§9 预期 ROI](08-upward-management-section-4-roi.md)）：每一层都要写清分母；折算系数必须署名来源，或用区间加推导链；核不实的量一律给区间不给单点。

同一份材料要准备三个版本，按在场的人递哪一版【经验：版本数随在场角色数而变】：给预算人的版本第一屏是钱与周期，给技术上级的版本第一屏是风险与单点，给非预算上级的版本第一屏是一句话定位与影响面。用错版本的代价不是难看，而是对方在第一屏找不到他要的东西，于是他的结论是「我再看一下」。

季度结果那一段的完整结构（情境 → 冲突 → 问题 → 答案 + 结论先行 + Storytelling）与面向老板的季度业务汇报同源：它要回答的不只是「我做了什么」，还包括业务结果、团队成长，以及风险与需求三项【经验：三项权重随组织与汇报层级而变】。其中「叙述优先于幻灯片」这一条的依据不在本节：亚马逊以叙述性六页备忘录替代幻灯片、并要求开会前集体静读，其公开描述与核验方式见 [§4 工程实现](08-upward-management-section-4-sec4.md) 的模板 4；Bridgewater 的「极端透明（Radical Transparency）」属常被引用的说法，引用前请按其官方材料与原书核验。

会前材料可以提速的四件事（只记方向，能力边界与风险见 [§5 前沿演进（AI 时代）](08-upward-management-section-5-ai.md)）：LLM 生成 PPT 草稿、LLM 辅助数据可视化（Gamma、Tome）、AI 辅助 Storytelling、LLM 模拟老板提问与预演；异步场合可换用 Loom 类录屏汇报。一条纪律：**只让它碰结构与措辞，数字与结论不外包**——生成出来的数字没有口径链，一次追问会击穿整份材料。

### 10.3 判据：说完之后怎么知道成了

| 判据 | 可观察的反应（对方做了什么 / 说了什么） | 为什么它说明成了 |
| --- | --- | --- |
| 目标被当成数字用 | 对方开始追问某条目标的**分母**（「这个覆盖率的分母是哪些业务线」） | 追问口径说明他准备把它拿去用，而不是听完就放 |
| 议题从「要不要」转到「怎么给」 | 对方问「什么时候要人」「人从哪来」「预算走哪条线」 | 必要性已经过关，讨论进入落地路径 |
| 对方开始替你排序 | 对方说「你应该先做 X 再做 Y」这类反建议 | 反建议的投入远高于正建议；他在把你的计划放进他的优先级里 |
| 对方问「你需要我做什么」 | 提问对象从「解释」变成「配合」 | 决策者问这句话时，心里已经批了这件事，只差一个动作 |
| 资源落到具体名字上 | 对方当场点名某个下游团队或某个人，让你去对接 | 跨团队资源只有被指名才存在；会后的「你去协调一下」不算 |
| 风险被当作信息而非态度 | 你讲坏消息时对方没打断，而是问「还有别的选项吗」 | 他在比较选项，说明坏消息被接收为可决策的输入 |
| 目标进入对方的材料 | 你后来在对方的季度材料或会议纪要里看到你这条目标 | 可转述性成立——你的目标成了他的目标，排序时才有人替你说话 |
| 下一次被约 | 对方当场或会后给了一个更早的时点（「下个月双周会上讲一下」） | 他愿意在自己的会上给你一个位置，说明这件事进了他的视野 |
| **没成的信号** | 会后 48 小时内没有任何人被指派任何事，也没人约下一次【经验：这个观察窗随组织的会议与排期粒度而变】 | 会上没有产生决定，计划退化成表态；下次排序里你排在别人后面 |

表里最难判定的是「对方开始替你排序」——它听起来像被批评，实际是好消息：一个不打算给你资源的人，不会花力气重排你的计划。

判据只读一条也够用：**会后有没有一个人被指派了一件带日期的事**。没有，就是没成；其余几行都只是它更早的征兆。写完这一列请自查一遍：如果某一行的「可观察的反应」里出现「对方认可」「达成共识」这类词，它就不是判据，而是结论——回去看对方到底做了什么。

### 10.4 常见失败

| 失败形态 | 症状（怎么发现它） | 机制（为什么这么说会反噬） | 改法 |
| --- | --- | --- | --- |
| 目标用形容词 | 通篇「显著提升」「进一步优化」「加强治理」 | 不可判定的目标无法被授权：对方没法把它写进自己的材料，于是在排序里被自动放到最后 | 每条目标后跟「什么时候、看哪个数、谁来验」 |
| 资源需求首次出现在会上 | 对方说「下次预算窗口再说」 | 分配链按窗口运作，会上首次出现的需求当季进不了流程，只留下一条被顺延的记录 | 窗口前用 1:1 递一页纸，会上只做确认（§3.2.8） |
| 坏消息夹在成绩中间 | 对方反复追问第一条成绩 | 对方读材料是先找结论再校验；夹带会让他把整份材料的可信度一并降权 | 用三段式单独成段，且放在资源请求之前（§3.2.9） |
| 只报问题不报选项 | 对方问「那你打算怎么办」 | 你把决策成本转了出去，对方必须先救援才能谈计划，资源议题被挤掉 | 每个风险带 2–3 个各自写清代价的选项 |
| 只报进度不报判断 | 通篇「已完成 X、进行中 Y」，没有一句「我认为」 | 进度是任何人都能报的信息，独家的只有判断；只报进度，你在对方眼里就是一个可替换的信息通道 | 每条进展后跟一句「我的判断是…」 |
| 不写「不投入的代价」 | 会上没人问，会后没下文 | 没有对照项，你的申请与别的团队的申请无法比较，默认规则退化为「谁先提谁先得」 | 把代价写成与收益同口径的一行 |
| 计划讲成技术方案 | 对方在你还没讲到业务影响时就打断 | 资源按业务口径排序，技术细节在他那里不是论据而是成本；你越细，他越快下「再想想」 | 结论先行，技术细节进附录 |
| 计划里没有别人的位置 | 跨团队 Owner 是从你嘴里第一次听到他要配合 | 他没准备，当场只能给原则性同意；等到排期落地时归零 | 定稿前与每个跨团队 Owner 各过一次 |
| 承诺绝对目标 | 写上「覆盖 100%」「零事故」 | 绝对目标一旦进了对方的材料，你此后每期汇报都在解释偏差，信任账户只减不增 | 写成区间 + 触发条件（多久内达到多少）【经验：区间随你的历史基线与业务线数量而变】 |
| AI 生成的数字直接上会 | 被问「这个数哪来的」 | 无口径链的数字会击穿整份材料，并让你其余判断一并降权 | AI 只碰结构与措辞，数字与结论自己签字（§5 前沿演进） |

表里出现频率最高的组合是「目标用形容词 + 不写不投入的代价」。这两条单独看都只是不够专业，合在一起会变成一次**无法被决策的汇报**：对方既没有可判定的目标，也没有可比较的代价，于是他能给出的唯一结论是「再想想」——而你把它读成了「他没听懂」。

### 10.5 接口

本节只给台词与判据，材料在别处：一页纸、三档方案与资源申请模板见 [§4 工程实现](08-upward-management-section-4-sec4.md) 的模板 5；ROI 的收益 / 成本 / 门槛与敏感性见 [§9 预期 ROI](08-upward-management-section-4-roi.md)；资源论证模式与坏消息三段式见 [§3 设计模式与范式](08-upward-management-section-3-sec3.md) 的 §3.2.8 与 §3.2.9；AI 辅助汇报的能力边界与「数字不外包」见 [§5 前沿演进（AI 时代）](08-upward-management-section-5-ai.md)；本章四个案例给出的口径（风险前置 < 24h、资源争取 75%+ 等）见 [§6 落地实践](08-upward-management-section-6-sec6.md) §6.5【经验：案例口径】。资源当场被砍价之后的谈判边界与退让顺序，见 [§8 面试真题集](08-upward-management-section-8-sec8.md) 的 §14.8.3。

同一章里，导师制（§07）管的是职业成长、绩效管理（§03）管的是激励口径、跨团队协作（§04）管的是资源在团队之间怎么流转、团队拓扑（§11）决定你的汇报路径有几跳、团队节奏（§10）决定这份计划该在哪个会上讲、技术布道（§05）决定你在没有汇报关系的人那里有多少可信度——这六者都会改变本脚本的参数（谁在场、在哪讲、要不要借外部可见度），但都不改变骨架。

### 10.6 小结

这套脚本的成败取决于一个动作：**有没有把计划换成一个当场决定**——被拍板的档位、被指派的人、被写进对方材料的目标。计划讲得漂亮只改认知链；只有挂到一个当场动作上，它才会进入分配链。

> 💡 **思考锚点**：翻出你上一次季度计划会，把第六段承诺的 30/60/90 天复查点逐个对照判据「有没有一个人被指派了一件带日期的事」；如果第一个复查点（30 天）就查不到人名，那么当场你递给对方的是第五段那三档 A/B/C 选择题，还是被一句「再想想」退回了审批题？
