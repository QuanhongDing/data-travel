## 5. 前沿演进（AI 时代）

> 原 § 5 共 87 行、为方向清单（4 个方向簇 + 与 RAG / GraphRAG 的结合 + 6 条趋势），缺少机制与成熟度判断，重写为 ~300 行前沿评估。

### 5.1 先分清三类「前沿」

**第一个问题：趋势清单没有时间维度。**

同一张清单里，「已经在生产里跑」和「厂商演示里跑过一次」被并列在一起，读者据此排路线图就会踩空——把 L3 的东西写进季度计划，代价是一个季度的返工；把 L1 的东西当成「未来再说」，代价是白白多花一年的人工。

本节用三级划分，判据必须可核验，而不是「感觉成熟」：

- **L1 生产可用**：
  - ① 已 GA 且有正式 release note；
  - ② 有第三方（非厂商）公开生产案例；
  - ③ 接口稳定。
  - 三条全中才算，没有「准 L1」「边界案例」这类说法——②核不到就是 L2。
- **L2 可试点**：已可用但接口 / 生态未稳，或仅有厂商自有案例，或只在小规模被验证。可以做 PoC，不要做核心依赖。
- **L3 观望**：仅路线图 / 论文 / 厂商演示 / 预览特性。记录，不要在架构里预留假设。

下表各行以 ① / ② / ③ 引用上面的三条判据，并在 5.2 / 5.5 / 5.6 中展开。

**一处判据声明（只作用于规则型方向）。** 本主题下有两类方向：**工具型**（由某款产品交付，如简历解析、转写）与**规则型**（由监管与流程定义，如反偏见审计、合规审计）。对规则型方向，本节对上面三条判据中的 ① 做如下修正：**① 的「正式 release note」在这些行上读作「监管文本的正式发布」**（含法规编号与生效日期），理由是这类方向的交付物是流程与审计制度，不以某个产品的发布说明为凭据；**② 仍是「非厂商、非建设方的公开记录」，监管文本本身只计入 ①，不折算成 ②**；**③ 不变**。修正只改 ① 的口径，其余各行仍按上面的原文判。

**第二个问题：本主题的判据比别处更难满足。**

招聘工具的生产证据有一个结构性缺陷：公开材料要么来自工具厂商（产品页、客户案例页），要么来自使用方自己（招聘团队的技术分享、内部分享 PPT 流出的截图），而判据②要的恰恰是「既非供应商、也非建设方自述」的第三方记录。

更麻烦的是反馈延迟——一个人招得对不对，要等到他入职后的产出被评估才知道，而「产出」本身又是绩效体系给的分。

- **因为选人工具的效度反馈以年计、且被评估量本身带有管理者的主观评分成分，所以招聘 AI 很难像元数据 / 血缘那类系统一样在一年内积累出可核验的生产证据**：血缘准不准，跑一次就知道；招人准不准，要等三年。
- 这也是本节结论相对保守的原因：不是这些技术做不到，而是**没人能在公开材料里证明它做到了**，而架构决策需要的恰恰是可核验的证明。

**第三个问题：不要给既有做法改名字。**

「结构化面试 + 行为锚定（BAR）+ 多面试官盲评」在 §2 与 §4 里已经是一套完整机制（六维胜任力模型、STAR 行为事件、独立打分再合议、每季度打分校准会）。本节评估的每个 AI 方向都要回答同一个问题：它相对这套骨架**改变了什么**？

- 改变了机制（成本函数、接口形态、人机分工）的，值得单独讨论；
- 只换了前端的（把同样的判断换了个界面、换了个人来点按钮），本节会明说「这是接口改良，不是架构变化」。

**本主题下没有任何方向达到 L1。**

上表里判据站得最稳的是规则型的两行——「AI 反偏见」与「招聘 AI 的合规审计」：它们的①（监管文本的正式发布）与②（非厂商的公开记录，见 5.4）都成立，卡住的是③，偏见审计的工具链与流程标准还没定型，所以它们同样停在 L2。另一类是「反 AI 作弊：现场化与过程可复核」：做法普遍，但**②③都缺**——既没有统一的流程标准，也没有非厂商的公开生产记录，缺两条的它比上面两行更远。

按本节的判据，①成立而②或③缺一条的，停在 L2；①本身不成立的（该方向只出现在路线图、论文或厂商演示里），按 L3 处理——表里按后一条判的是 Onboarding Agent、雇主品牌 Agent 与面试评估 GraphRAG 化这三行。降级不是贬低，是准确：它决定了你现在能不能把它排成路线图上的核心依赖。**读者若要在自己的场景里把某一格判成 L1，先看那一格缺的是哪一条**：多数行缺的是②，那就得找到一份非厂商、非建设方的公开生产记录，写清楚它是哪个组织在哪个规模下、跑在哪个环节上；规则型的两行缺的是③，那就得等到审计方法与流程标准稳定到不会一次换版本就被推翻。

**读者怎么自己核验一格是 L2 还是 L1。**

- 先找**正式 release note**（①）：看的是「发布日期 + 能力条目」，不是博客宣传稿、不是发布会 PPT；找不到正式条目就不成立。规则型方向（反偏见、合规审计）的①换读为**监管文本的正式发布与生效日期**，见上面的判据声明。
- 再找一份**既不是供应商写的、也不是你所在组织写的**外部记录（②）：第三方采购方的技术分享、监管或审计机构对某次具体部署的检查与处罚报告、通讯社报道、论文里描述的生产部署，都算；供应商的客户案例页不算，使用方自己的内部分享也不算，**法规条文本身也不算**——它证明义务存在，不证明有人真的在做。
- 最后看**接口有没有跨版本破坏性变更**（③）：换一次版本会不会推翻你的 schema、阈值或流程——会，就是③不成立。
- ①成立、而三条里缺②或③的，就在路线图上按 L2 处理；①本身不成立（只出现在路线图、论文或发布会页面里）的，按 L3 处理。这套动作比任何厂商的成熟度自评都可靠，因为它核的是证据，不是表态。
- 本节的每一格都按这套动作过了一遍；读者在自己的场景里若得到不同结论，差异通常出在②与③上——②取决于你所在的行业里有没有人公开讲过，③取决于你要接的接口有没有跨版本标准。

**如果本主题真要写一个可以依赖的东西进路线图，那不是任何一个 AI 方向，而是 §4.2 已经落地的那套骨架**：结构化面试 + BAR 锚点 + 多面试官独立打分再合议 + 每季度打分校准会。

- 它的效度有公开的方法学依据（见 5.4），不依赖任何供应商，也不会因为模型换代而失效；
- AI 在本章的正当位置，是**在这套骨架的两端做事**——前端把投递变成可比对的字段，后端把过程记录留成可复核的证据——而不是替掉中间那一步判断。

### 5.2 演进方向逐条拆解（核心节）

下面四条是本主题下的四个方向簇。每条都按同一结构展开：旧做法卡在哪 → AI 改变了什么机制 → 由此得到什么 → 由此付出什么 → 证据与来源 → 成熟度。

- 前两条（**智能体驱动的招聘漏斗、技能图谱**）是「信息形态」的改变：一条改的是文本被读取的方式，一条改的是岗位被查找的方式。
- 后两条（**反偏见与合规、反 AI 作弊**）是「责任与证据」的改变：一条把偏见治理从个案搬到分布，一条把评估对象从产物搬到过程。
- 这个分组不是为了好看，而是因为**两组的前沿性来源不同**：前两组靠模型能力推进，后两组靠监管与争议处理推进——所以它们的成熟节奏也不一样，前两组等的是效果证据，后两组等的是规则落地。

#### 5.2.1 智能体驱动的招聘漏斗：把「不可比对的文本」变成「可排序的字段」

- **旧做法与它的卡点**：漏斗前端（简历初筛）的人力是线性成本，而且不可比。
  - **量的卡点**：年招 100 个岗位、每岗阅读 80–120 份简历【经验】，年阅读量在 8,000–12,000 份【经验：100 岗 × 80~120 份/岗】；按每份 3 分钟计【经验】，是 400–600 小时的纯阅读。
  - **质的卡点**：不同 HR 的读法不同，§2.3 漏斗五杠杆里的「简历通过率」这一节因此既不可比、也无法归因——你不知道通过率的变化是因为候选人池变了，还是因为换了个筛选的人。
- **AI 改变了什么机制**：把初筛的输入从「人来读的自由文本」改成「受 schema 约束的结构化记录」。
  - 抽取（技能 / 年限 / 项目产出 / 角色）由机器做，判断（要不要进下一轮）仍由人做；
  - 但**判断的输入形态与单位成本同时变了**——这是接口形态与成本函数双变，不是「换了个更好用的界面」；
  - 落在哪个代理变量上（过去做过什么 vs 未来能不能产出）没有变，这是本节判断它「只是改良了一半」的依据。
- **由此得到的**：
  - 因为单份简历的处理成本从「人分钟」降到「一次调用」，所以漏斗前端可以「宽进」——先扩触达再筛，而不是靠 JD 关键词把投递量卡在人力能处理的上限；
  - 因为抽取用的是同一套 schema，所以不同来源的候选人第一次能在同一组字段上比较，这正是 §2.2 里 Talent Persona 形式化（SkillSet / Experience / Seniority / …）的前提；
  - 因为初筛变成了可复算的操作，所以「漏斗哪一节漏了」第一次可以被定位，而不是笼统地归因到「HR 不给力」。
- **由此付出的**：
  - **错误形态变了**：人工筛选的错误是「看漏了谁」，可复盘、可追责；排序模型带来的错误是「谁从来没被排到前面」，几乎不可观测，也没有申诉入口。
  - **新的锚定故障模式**：如果评估草稿在面试官独立落笔之前出现，它会把分数往草稿上拉——§4.2 的「多面试官盲评」与「延迟评价」两条防偏见机制会被绕过，而且是静默绕过。
  - **供应商锁定**：抽取 schema 与打分层写进了 ATS，换供应商等于重建人才画像与题库（§4.1 Step 1–2 的产出）。
  - **合规成本**：一旦输出被用于筛掉人，它就落进「自动化就业决策」的监管范围（见 5.2.3）。
- **证据与来源**：
  - 【公开】模型侧的结构化抽取有正式发布说明——OpenAI 于 2024 年发布 Structured Outputs，使「按 JSON Schema 约束的输出」成为稳定接口（可按 "OpenAI Structured Outputs 2024" 检索核验）。
  - 招聘侧的②（非厂商公开生产记录）本节未给出，这是它停在 L2 的直接原因；厂商功能页只能证明「这个能力被做成了产品」，不能充当②。
- **成熟度**：L2（①③满足、②缺）。

```text
自由文本简历                       受 schema 约束的结构化记录
"做过推荐系统，QPS 大概几千"   →   { 技能: 推荐系统, 规模: "QPS 千级", 证据: 自述 }
"带过 3 人的排期小组"          →   { 角色: tech_lead, 团队规模: 3, 证据: 自述 }
"把召回率从 0.6 提到 0.8"      →   { 指标: 召回率, 变化: +0.2, 证据: 待核验 }
────────────────────────────────────────────────────────
关键：能被排序的不是「能力」，是「可抽取的声明」。
      声明能不能被核验，取决于你有没有独立的验证入口
      （作品、开源提交、可追问的项目细节）——
      没有入口时，模型只是把「自述」搬运到一张更好看的表里。
```

**同簇但机制不同的两条。** 它们经常被和前一条写在同一个清单里，但改变的东西完全不同：

- **Onboarding Agent**（入职首周推送文档、答疑、安排 1:1）：改的是入职期的信息分发方式，不改变任何筛选或评估环节，本质是一份会自动推送的 checklist——L3（①不成立：公开材料只有厂商演示；②③缺）。
- **雇主品牌 Agent / LLM 内容优化**（生成技术博客草稿、分析雇主评价平台评论）：改的是内容产出成本，而它对招聘漏斗的影响要经过「内容 → 关注 → 投递」这条长链，这条链的因果从未被建立——L3（①不成立：公开材料是厂商演示与既有内容工具的拼装；②③缺）。
- 可以用它们省写作时间，但不要把它们写成漏斗指标的分子，否则你会得到一个漂亮但不可归因的漏斗。

**表里还有一行落在本簇：面试评估 Agent（转写 + 摘要 + 评估草稿）。** 转写与摘要侧的①③成立（转写工具已 GA、接口稳定），评估草稿侧卡在②（没有非厂商的独立案例），因此同判 **L2**（①③满足、②缺）——它的问题不在成熟度，而在时序：草稿只能出现在面试官独立落笔之后，否则 §4.2 的盲评会被静默绕过（见 5.3 表第二行）。

#### 5.2.2 技能图谱替代 JD：把岗位从「一段文本」改成「一张图」

- **旧做法与它的卡点**：JD 是静态文本，是「筛掉」的工具而不是「匹配」的工具。
  - **对外的卡点**：JD 用关键词设门，非典型背景（自学、开源、跨职能）会在第一道门就被挡下，而这些人恰恰是最难通过关键词描述的那一类。
  - **对内的卡点**：它对内部转岗几乎无用——一个人的能力只写在他的简历里，不写进 HR 系统，所以内部候选人不可检索，「先看内部」在绝大多数团队里是一句口号而不是一个动作。
  - **结构上的卡点**：§2.1 的胜任力模型（技术深度 / 系统设计 / 工程素养 / 业务理解 / 协作 / 领导力）是**评估者的语言**，配 BAR 锚点用；它不是**查找结构**，天生不适合回答「谁离这个岗位最近」。
- **AI 改变了什么机制**：把「岗位 = 一段文本」改成「岗位 / 人 = 技能节点 + 熟练度 + 节点间关系」的可推理结构。
  - 它改变的是**查找结构**（从文本检索变成图上的近邻 / 路径）与**证据来源**（从自述变成产出与协作记录）；
  - 它不改变「这个岗位需要什么」这件事本身——那是业务判断，图谱只是把它写成了机器可读的形式。
- **由此得到的**：
  - 因为匹配从「关键词命中」变成「图上的距离」，所以跨领域与非典型背景第一次可以被找回，而不是被 JD 关键词挡在门外；
  - 因为人与岗位用同一套节点表示，所以内部候选池可以先于外部招聘被检索——**图谱真正的杠杆是它改了候选人来源，不是它把筛选做得更快**；一个只在筛选环节提速、却不改变来源结构的系统，收益上限很低。
- **由此付出的**：
  - **模糊被搬走了，没有被消除**：JD 的口径模糊变成技能节点的粒度模糊，谁定义「熟练」，谁就定义了谁能被搜到。
  - **治理负担**：节点与熟练度要有人维护，而「元数据与技能数据大约三个月后就开始失真」这条规律【经验】在技能数据上同样成立，还需要 Owner 具体到人，否则图谱会退化成一份过期的技能字典。
  - **偏见换了入口**：如果熟练度用历史晋升与绩效数据推断，历史的不均衡就被固化成可检索的排序，而且看起来比 JD 客观得多。
  - **数据出域**：把员工技能数据交给第三方 HR SaaS，是新的合规面（保留期、删除权、跨境）。
  - **激励扭曲**：一旦节点被用来分配机会，它就会被优化——刷标签、堆砌无意义认证，这是把评估指标当目标之后的必然结果。
- **证据与来源**：
  - 【公开】欧盟委员会的 ESCO 分类（技能 / 能力 / 职业，持续版本更新）是一套公开、可核验的技能本体——它是本节唯一能给出「非厂商」参照的图谱类资产，可以用它检验某个平台宣称的技能节点是否可复核。
  - Eightfold / Gloat / Beamery 一类平台的材料只能证明「这个能力被做成了产品」，不能充当②。
- **成熟度**：L2（②缺，③亦不稳：节点定义与熟练度分档没有跨平台标准）。

**原清单给技能图谱列了三条优势，本节只留下其中一条。** 原清单写的是「可推荐内部候选人转岗、可量化技能差距、可预测未来技能需求」——第一条是本方向真正的杠杆（见上「由此得到的」）；后两条不作为收益写入，因为它们过不了本节的判据：

- **「可量化技能差距」**要求熟练度可比较，而熟练度分档没有跨平台标准（这正是本方向③不成立的原因）——同一个人的「熟练」在两个平台上不是同一个数，两者相减得到的差值也不可复核。
- **「可预测未来技能需求」**是把图谱的输出再接一段更远的预测，而预测目标（三年后需要什么技能）在招聘周期里没有可回测的历史记录——没有回测就无法证伪，详见 5.5。
- 两条都不是「做不到」，而是**现在核不到**：它们需要的对照物（统一的熟练度标尺、可回测的技能需求历史）尚不存在。

**同一张图的另一种用法（属 L3）。** 把候选人的项目、产出、协作抽成实体关系图，用图推理回答「他在 A 项目里解决了 X，因此具备 Y」——这是 §2.1 冰山模型想穿透的那部分（动机、学习力、可塑性）。

- 它的吸引力在于「从经历到能力」的推理看起来比一个匹配分更可解释；
- 但它有一个硬缺陷：**推理链没有 ground truth**。检索型图谱的错可以被人一眼看出来（搜出来的技能对不上），推理型图谱的错看起来和一段流畅的分析没有区别；
- 所以在有公开的效度研究之前，它只能记录，不能进生产。

#### 5.2.3 AI 反偏见与合规审计：把偏见治理从「个案申诉」搬到「分布审计」

- **旧做法与它的卡点**：§2.3 列出的四类个体偏见（光环效应、首因效应、相似性偏见、对比效应）都是**个体层面**的偏差，§4.2 的防偏见机制（结构化打分卡、延迟评价、多面试官盲评、校准会）能压住它们。
  - 但它们压不住**样本层面**的系统性差异：同一份能力在不同群体上的通过率差，从任何单个面试官的视角里都看不见，也不在合议会的议程上。
  - 个案申诉这条兜底路径本身就有前提——候选人得先知道结果、再判断自己被区别对待、再愿意申诉。三个「再」之后，剩下的样本已经很小了。
- **AI 改变了什么机制**：把偏见的发现位置从「候选人申诉与事后复盘」搬到「上线前的分布检验」，同时把担责主体从「某个面试官」改成「使用该工具的雇主」。
  - demographic parity、equal opportunity 这类指标本质是**分布**指标，它们不评价某一次判断，只评价一组判断的分布；
  - 因此改变的是**发现时机与担责主体，不是模型本身**——同一个模型，在被审计与不被审计的两套流程里，风险完全不同。
- **由此得到的**：
  - 因为偏见第一次被写成可以度量、可以写进合同与法规的验收条件，所以它从「价值观问题」变成「采购与合规条款」——这正是监管介入的位置（见 5.4）；
  - 因为落点从人换成了流程，一线面试官的个人努力不再是唯一的防线；反过来，流程一旦没有审计，偏见会以「一致性好」的形式被固化下来——一致性高不等于没有偏差，这是最容易骗过自己的一个假信号。
- **由此付出的**：
  - **指标可以被优化而不解决原因**：只把各群体通过率拉平，可能掩盖代理变量（邮编、社团、开源社区关系）继续起作用，甚至把相关性更强的信号一起削掉。
  - **去字段不是免费的**：去掉姓名 / 学校 / 年龄 / 性别会同时削掉一部分有效信号，短期内筛选的一致性与准确率都会下降——这个代价必须被承认，否则「去字段」会被当成零成本的道德加分。
  - **多模型投票换个方式不透明**：把「单一模型的偏见」换成「投票规则的不透明」，可解释性反而下降（§4.2 的防偏见机制之所以有效，前提是打分可被逐条追问）。
  - **监管地图碎片化**：市、州、国家层级的要求不同，跨区运营要做多套留痕与披露流程，而留痕本身有保留期约束。
  - **审计成本落在使用方**：执法对象是雇主，不是工具供应商——所以「工具供应商通过认证」不等于「你的流程合规」。
- **证据与来源**：
  - 【公开】Regulation (EU) 2024/1689（AI Act，2024 年在欧盟官方公报发布）把「就业、人员管理与自雇机会获取」相关的 AI 系统列入高风险附件，高风险义务按官方时间表分阶段适用（具体适用日期以官方文本当前版本为准）。
  - 【公开】纽约市 Local Law 144（2021 年通过，2023 年 7 月 5 日起执行）要求自动化就业决策工具做年度独立偏见审计并向候选人披露。
  - 【公开】路透社 2018 年报道亚马逊弃用其内部简历筛选引擎，原因是该引擎对女性候选人给出系统性不利排序。
  - 这三条的共同点：材料都来自**非工具厂商**——法规文本充当①（正式发布的义务与生效日期），通讯社对那次生产失效的报道充当②。②在本主题里最难满足，却恰好在这条线上满足。
- **成熟度**：L2（①②满足，③不成立：偏见审计的工具链与流程标准未稳）。

#### 5.2.4 反 AI 作弊与评估有效性：从「看产出物」转向「看生成过程」

- **旧做法与它的卡点**：Take-Home 与在线笔试的效度建立在一个前提上——「这份代码是候选人独立完成的」。
  - 生成式代码助手把这个前提打破了，于是同一份作业的分数不再可比；
  - 这不是难度问题，是**测量对象失效**：题目没变，被测量的东西变了。继续用同一套题目与同一套评分，得到的是一组无法解释的分数。
- **AI 改变了什么机制**：把观测对象从 artifact（产出物）改成 trajectory（过程与决策）。
  - 现场编码、实时屏幕共享只是手段，真正的判别信号是**设计决策的解释**——为什么这样拆、放弃过哪些方案、哪一段是让助手生成的、边界条件是怎么想到的；
  - 判据从「产物像不像人写的」换成「人能不能解释这个产物」——这是评估对象的改变，而且它把评估成本从「事后看作业」推回到「面试官在场」。
- **由此得到的**：
  - 因为判据落在「能不能解释」上，所以评估重新变得可复核——人可以追问、可以当面对质，检测器不能；而「讲不清设计决策」这条信号在 AI 代写之前并不好用，现在重新变得可用；
  - 这与 §2.1 里冰山模型「穿透不可见部分」的目标方向一致：生成过程恰好是可见能力与不可见能力同时暴露的窗口。
- **由此付出的**：
  - **可得性代价**：现场评估消耗面试官时间，并对时区、设备、网络提出要求，会系统性排斥一部分候选人——这是可得性代价，不是能力代价，必须单独记账，否则会被误读成「这些人能力不行」。
  - **外推距离**：现场编码测的是「有人在看时怎么解题」，与长期演进、多人在场的协作式工程工作仍有距离。
  - **不要用检测器**：自动检测生成式文本的误报无法被候选人申诉，误判一次就等于把一个诚实候选人判为作弊；因此正确做法是让过程可复核，而不是让内容可判别（可按 "AI text detector false positive"、"生成文本检测 误报" 自行检索核验这类工具的主要弱点）。
  - **行为分析要单独评估**：鼠标轨迹、停留时长、复制粘贴这类信令看起来客观，但它们与能力的关系没有被验证过，而监控强度本身有合规边界（录屏与行为采集都属于个人数据采集）。用它们做风险提示可以，做淘汰依据不行。
  - **留痕带来新的数据责任**：录屏、录音、转写文本、行为日志的保留期与删除权在部分辖区有硬性要求（见 5.4）。
- **证据与来源**：
  - 【公开】伊利诺伊州 AI Video Interview Act（2019 年通过、2020 年生效）要求在使用 AI 分析面试视频前告知候选人并取得同意——它是「过程留痕必须有合规边界」的直接证据，也说明这条线上监管关注的是**披露与同意**，不是准确率。
  - ②（非厂商公开生产记录）本节未给出：做法在各家公司的流程说明里都能看到，但这些说明是使用方自述。
- **成熟度**：L2（①满足、②③缺；做法普遍，但无统一流程标准，③不成立）。其中「生成式作答自动检测」在 5.1 表里单列一行，级别同为 L2（①满足、②缺、③不成立）——它缺的是②与③两条：检测器本身有正式产品与官方文档（①），但没有非厂商记录证明它在生产里判得准（②缺），且误报不可申诉、判定与申诉接口未稳（③不成立）。

**原清单点名的三个工具，对应这条线上的三类东西。** 原清单写「用 GPT-4 写 Take-Home、用 Devin 完成 Coding 实操」，反作弊手段里点名了「现场 Coding（CoderPad）」：

- **生成式助手（GPT-4 一类）**与**自主编码代理（Devin 一类）**是「作业代表候选人独立产出」这个前提的破坏者，但破坏程度不同：助手做的是补全，代理做的是端到端交付，后者让限时作业这种形式的效度下降得更快。名字在这里的作用是**标出问题类别**，不是给某款产品背书。
- **现场编码环境（CoderPad 一类）**是观测手段，不是判据：它能让你看到轨迹（过程），但「看得见」不等于「判得准」，判据仍然要落在设计决策的解释上（见上）。把工具名写进采购清单可以，写进效度论证不行——一款工具已 GA、有正式发布说明，只说明它可用（①），不说明它测得准（②）。
- 这也是这条方向停在 L2 的一个具体例子：工具层面的成熟度与「它是否真的预测了产出」是两件事。

### 5.3 与本主题既有栈的接口在哪

不要写「与 AI 结合」这种空话。下面写清**接口边界**：谁调用谁、数据以什么形态穿过边界、失败时谁负责。这张表的作用是防止一个新工具悄悄绕过 §4.2 已经成立的机制。

| 结合点 | 接口形态 | 谁负责失败 | 现状 |
| --- | --- | --- | --- |
| AI 初筛 ↔ 招聘漏斗看板（§4.1 Step 4） | 候选人结构化记录 + 匹配分写回 ATS；阈值是人设的 | 阈值设错由招聘负责人负责，不由模型负责 | L2，可试点 |
| AI 评估草稿 ↔ 结构化面试打分卡（§4.2） | 草稿只能落在「证据摘录」字段，不得落在分数上；分数由面试官独立落笔后再合议 | 面试官（签字的是人，不是模型） | L2，须先改流程再上工具 |
| 技能图谱 ↔ 人才画像（§2.1）与内部转岗 | 技能节点 / 熟练度 ↔ 六维胜任力的映射表，双向可查 | 图谱维护方（Owner 具体到人） | L2，先内部 |
| 转写 / 录屏 ↔ 面试记录与合规留存 | 音频、视频、转写文本的保存期与删除权 | 数据控制方（雇主），不是工具厂商 | L2，多地运营按最严辖区设计 |
| 自动化决策 ↔ 合规审计 | 「用了哪些工具、决策到哪一步」的登记表 + 年度审计所需的分布数据导出 | 雇主（执法对象是雇主） | L2，先登记后审计 |
| 雇主品牌内容 ↔ 招聘漏斗前端 | 内容 → 关注 → 投递的长链，不做归因就不进指标 | 内容团队 | L3，只当写作工具 |

这张表里最要紧的是前两行：**分数只能由一个地方产生（面试官的独立打分），草稿永远在分数之外**。§4.2 的「独立打分 + 延迟评价 + 盲评 + 校准会」是一组相互咬合的机制，任何一个新工具只要提前把结论暴露出来，整组机制就退化成「给草稿补个签名」。

第二要紧的是倒数第二行「自动化决策 ↔ 合规审计」：自动化决策的担责方是雇主，采购合同里要写清审计配合条款与数据导出格式，否则到了审计时你拿不到可用的分布数据——而拿不到数据本身，在部分地区就等于不满足审计义务。

接口设计上最常见的两种失败，正好是这张表的两端：

- **第一种是「工具直接改分数」**：新工具为了方便，把自己算出的匹配分直接写进打分卡，面试官只做确认。流程还在，机制已经没了——这是本节最需要防范的一种。
- **第二种是「责任没人接」**：转写、录屏、图谱数据都上了，但没人说得清保留期是多久、候选人要求删除时谁执行、审计要数据时从哪导出。这类问题不会在出事之前暴露，一旦暴露就已经是合规问题。

- 【公开】纽约市 Local Law 144（2021 年通过，2023 年 7 月 5 日起执行）：自动化就业决策工具的年度独立偏见审计与候选人披露义务。
- 【公开】伊利诺伊州 AI Video Interview Act（2019 年通过，2020 年生效）：AI 分析面试视频的告知与同意义务。
- 三者的共同特征：它们约束的是**披露、审计与同意**，而不是准确率。这决定了合规落点在流程与留痕，不在算法。

**方法学依据（既有骨架为什么可信）**

- 【公开】Schmidt & Hunter 关于人员选拔方法效度的元分析（Psychological Bulletin，1998）把「结构化面试」「工作样本」「经验」「学历」等方法放进同一个可比较的效度框架。
- 这是本节敢说「结构化面试 + BAR 是可靠的」、而不是「大家都这么做」的依据；后续同领域的更新综述可按「selection method validity meta-analysis」自行检索核验。

**外部对照资产（复核技能节点的定义用，本身不构成②）**

- 【公开】欧盟委员会的 ESCO 技能 / 能力 / 职业分类（首个完整版 v1.0 于 2017 年发布，其后按 v1.x 版本迭代；各版本的发布年份可按 "ESCO version history" 自行核验）：一套公开、可核验的技能本体，用来检验商业「技能图谱」的节点定义是否可复核。

**案例报道（②侧证据）**

- 【公开】路透社 2018 年报道亚马逊弃用其简历筛选引擎，原因是该引擎对女性候选人给出系统性不利排序——这是本主题里少见的、由非厂商揭示的生产问题。

**厂商侧产品形态（对照①用，不计入上面的文献条目）**

- 招聘平台侧陆续推出简历匹配与候选人寻源助手（LinkedIn、Greenhouse 一类产品线），协作工具侧把 AI 用于流程自动化（Notion、Linear 一类）。这一块不给具名版本与年份——产品迭代快，写死的版本号很快失效；要核验某款产品的能力边界，看它官方文档里的版本说明与变更记录那一节。
- 这些材料的正确用法是：看**产品是否已进入正式发布说明、接口是否稳定、能力边界写在文档的哪一段**；不要用它们判断效果。产品发布节奏能告诉你这个能力是不是「已经被做成了商品」，不能告诉你它在你这里有没有用。

**四类仍在进行的研究方向（不给编号，给检索关键词）**

- {面试公平性审计}、{技能图谱的标准化评估}、{LLM 做简历匹配}、{用机器学习预测入职后绩效}。
- 这四类在 FAccT / FAT* 与人资管理期刊两套检索体系里都有公开工作，但分工不同：前两类问「工具是否公平」，后两类问「工具是否有效」。请按关键词自行检索核验，本节不引用具体论文编号。
- **预测入职后绩效这一类的最大问题在标签本身**：绩效评分是有偏的代理变量（主管印象、项目分配、曝光度都在里面），用它当监督信号训练出来的模型，学到的可能正是要反对的那个东西。

**怎么用这几类文献。** 法规类文献用来看**义务边界**（要披露什么、要审计什么、留痕多久），不要用它判断工具好不好用；方法学文献用来判断**骨架是否可信**（结构化面试的效度有几十年研究垫底，这是它不依赖供应商的原因）；案例报道用来看**失效形态**（一个真实的生产事故，比十个成功案例更有信息量）；研究方向用来排**观察队列**——把关键词记进技术雷达，等有可复核的效度研究再动，不要用一篇论文的摘要决定明年的招聘流程。

### 5.5 被过度宣传的部分

- **「AI 面试官可以替代面试官」**——实际是：模型能在结构化维度上给出一致性更高的初评，但不能承担「录用决策」这一需要担责的判断。为什么会这样：模型被优化的目标通常是「与人类评分的相关性」，而真正要预测的是「入职后的产出」，中间隔着一个未验证的假设，且反馈以年计，无法快速证伪。什么时候它才会成真：出现独立、公开、可复核的效度研究——不是相关性研究——在多个岗位类别上复现，且监管允许自动化录用决策。在那之前，「AI 面试官」在流程里的正确位置是**取证**，不是**定罪**。
- **「技能图谱能消除 JD 的模糊，还能量化技能差距、预测未来技能需求」**——实际是：模糊被搬家了，从「岗位描述」搬到「技能节点的定义与熟练度分档」，而后者更难被外部复核（JD 至少有行业惯例可比）；后两条优势还要更远一层——量化技能差距要求熟练度可以跨主体相减，预测未来技能需求要求存在可回测的岗位需求历史，这两个前提目前都不存在，所以它们是**图谱的输出被当成了图谱的能力**（见 5.2.2）。为什么会这样：任何匹配结构都必须先定义「什么算一个技能、什么算熟练」，这一定义权落在建设方手里，越用它做排序，定义权的杠杆越大；而定义权没有被外部对照物约束时，「差距」和「预测」都只是同一个定义的另一面。什么时候它才会成真：节点定义有行业公认的对照本体（如 ESCO 这类公开分类）、技能需求有可回测的历史序列，并且图谱被用于**可复核的决策**（转岗、培养计划）而不只是检索与排序。
- **「去掉姓名 / 学校就能去掉偏见」**——实际是：去字段会同时削掉有效信号，而代理变量会把偏见绕回来（邮编、社团、开源社区关系、语言习惯）。为什么会这样：偏见不是住在某个字段里，是住在「用什么变量预测产出」这个选择里；只要代理变量存在，删字段只是把偏见推后一步。什么时候它才会成真：审计发生在**结果分布**而不是**输入字段**上（纽约市 LL 144 的年度偏见审计正是把审计位置从输入搬到结果），并且审计结果公开到能被第三方复核。

### 5.6 未来 3–5 年：可证伪的预测

趋势清单里的句子大多不可证伪（「AI 将主导招聘」永远正确）。下面把本节可证伪的判断写出来。

原清单里的另外两类说法，本节的看法是：**「雇主品牌 = AI 时代的人才入口」**是渠道问题，不构成架构判断（见 5.1 表第 4 行）；**「结构化面试 + AI 增强」成为全球标准**描述的是已经发生的事实——结构化面试在 §2 / §4 里本来就是标准做法，不需要预测，只需要执行。

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| 漏斗前端的自动化比例继续上升，但「终面由人做」的比例不降——因为担责结构没变 | ATS 把「自动化环节」标注到漏斗的具体步骤，并把终面默认留给人类；雇主公开流程里出现固定的「自动化决策 + 人工复核」表述 | 出现多份公开的、全流程无人工决策的大规模招聘生产记录，并且通过合规审计 |
| JD 不会被淘汰，会被拆解：技能图谱先在内部分配（转岗、培养）落地，对外招聘仍以职责描述为主 | 内部转岗决策先于对外招聘使用图谱；对外招聘文案同时出现职责描述与技能标签 | 图谱成为对外筛选的强制入口，并成为招聘公告的主要形式 |
| 远程 + 异步 + 结构化评估会成为高级岗标准，但驱动力是「评估可复核」（争议处理与合规），不是效率 | 争议处理流程里出现「面试记录留存与复核」的硬性要求；评估材料可一键导出 | 高级岗位评估仍以面对面非结构化为主流，且无留痕要求 |
| 合规审计的要求会从「披露使用了自动化工具」升级到「提交结果分布的量化审计」，成本落在使用方 | 雇佣方公开的审计摘要里出现数据化的通过率 / 影响比；采购合同里出现审计配合与数据导出条款 | 监管要求停留在披露层面，不要求结果分布的量化审计 |

### 5.7 给架构师的行动建议

| 你的处境 | 现在就该做 | 一年内观察 | 明确不要做 |
| --- | --- | --- | --- |
| 年招 < 20 人、没有专职招聘 | 把人才画像与 BAR 锚点写出来（§4.1 Step 1–2）；面试记录归档 | 免费额度内的简历解析能力是否够用 | 不要买技能图谱；不要做 Onboarding Agent；不要自己训模型 |
| 年招 50–200 人、有 HRBP | 结构化面试 + 多面试官盲评落地；漏斗按 §2.3 五个杠杆逐节归因 | 初筛工具在你们自己历史数据上复现出的通过率分布 | 不要把初筛分数当录用门槛；不要让评估草稿出现在独立打分之前 |
| 平台型团队（年招数百以上） | 建「自动化决策登记表」：用了哪些工具、决策到哪一步；问清留痕与删除权 | 审计要求是否从「披露」升级到「结果分布审计」 | 不要用语音 / 视频情感分析；不要自己给自己出审计报告 |
| 多地运营的合规敏感团队 | 按最严辖区的留痕标准设计一次，别按地区做多套 | 高风险义务的官方适用时间表更新 | 不要假设工具供应商的合规认证能覆盖你的担责 |
| 多个 BU 各自招人的集团 | 统一人才画像与 BAR 锚点，评估标准跨 BU 对齐；题库存版本 | 是否出现跨 BU 的内部人才检索需求（这才是图谱的入口） | 不要在标准还没统一时先上图谱——那只是把各 BU 的差异写成了节点 |

「明确不要做」这一列的判据很简单：**凡是把不可逆的事（录用、淘汰、买断）交给自动化，或把可复核的判据换成不可复核的分数，现在做都是浪费**——省下的时间会在争议处理、审计和重建流程时还回去。

### 5.8 小结

> 本节小结：AI 在本主题下真正改变的**唯一一条机制**，是把候选人信息从「不可比对的自由文本」变成「可排序的结构化记录」——它压低了筛选的单位成本，也让不同来源的人第一次能被放在同一组字段上比较。它**没有**改变的是判断的落点：用「过去做过什么」预测「未来能不能产出」这个代理变量没变，反馈延迟以年计这件事也没变，因此担责的那一步仍然必须留给人。
>
> 因此本章的前沿判断是「两端可动、中间不动」：前端（触达、初筛）与后端（记录、复核、审计）都可以用 AI 换效率，中间那一步判断必须有人签字，而且要有人能被追责。
