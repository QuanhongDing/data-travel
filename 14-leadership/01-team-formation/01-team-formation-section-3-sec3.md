## 3. 设计模式与范式

### 3.1 先看约束：模式不是选择题，是约束的产物

五种画像模式（**能力驱动 / 产出驱动 / 潜力驱动 / 文化匹配 / AI 增强**）都是真实存在的做法。但把它们并列成一张「按场景选一个」的清单，读者读完仍然不知道**为什么这个场景就该用这个**——而模式的正确性恰恰来自这一层。

第一个论断：**这五种模式真正的差别不是「看能力还是看潜力」，而是「在做出录用决定之前，你拿得到、并核验得了哪一类证据」。** 拆开看，五者用的是五种不同的**代理变量**：能力维度评分是**对潜变量的编码**（能力不可直接观测，评分只是人为判断的编码，见 [§ 7.3.1](01-team-formation-section-7-sec7.md)）；产出是**可查证的历史事实**；潜力是**预测**；价值观只能从**行为史**里观察；模型输出是**文本语义匹配分**。**它们的精度不同，可得性更不同**——拿不到的那类证据，写得再重要也无法在面试里被评估。这就是为什么校招不能抄关键岗的画像：不是因为应届生「不够好」，而是因为那一维证据在他们身上不存在。

第二个论断：**同一维度在不同批量下权重相反。** 「一致性」在单人单岗招聘里几乎不需要（你怎么打分都不会有人和你比），在一年招几十人的批量里权重最高（不可比的分数等于没有分数）；「单点精度」在关键岗上权重最高（一次判断错误决定一整条方向的投入），在校招里无法实现（没有可比历史，精度无从谈起）。所以先立约束、再谈模式——同一个岗位，约束不同，正确的画像就不同。

把「优点 / 缺点」写成形容词（可复用 / 容易僵化）是不够的，这里要补的正是形容词背后的机制：**每一个「优点」都是某个结构在某个规模下的产物，而每一个「缺点」都对应一个具体的失效条件**——过了那个条件，优点会反转，而且反转时通常不报错。

| 约束 | 它决定了什么 | 本主题下最容易被它推翻的直觉 |
| --- | --- | --- |
| 证据可得性（有没有可比的过往产出） | 画像锚在哪一维：产出 / 能力 / 潜力 | 「谁强就要谁」——没有可比产出时，产出驱动直接失效，只能锚在潜力或行为史 |
| 招聘批量与一致性要求（一次招几人） | 要不要把画像拆成维度 + 行为锚点 | 「逐个人深入看更全面」——批量下不可比的分数等于没有分数 |
| 岗位产出的可定义程度（6 个月内的交付物写不写得出来） | 用产出反推，还是用潜力兜底 | 「先把人要来再说」——产出写不出来的岗位，能力清单也写不准 |
| 团队文化的强度与容错空间 | 价值观是否进入硬性维度、要不要独立打分 | 「价值观可以入职后再对齐」——共事方式不匹配时，能力越强破坏越大 |
| 候选人数量与评审带宽（材料量 / 阅读工时） | 是否引入模型做召回 | 「上 AI 就能提效」——它压缩的是读材料的工时，不是评估质量 |
| 面试官池与培养能力（有几个人能评、能不能校准） | 结构化能落到多深 | 「发了打分卡就等于结构化了」——无人认证与校准的锚点会各自漂移 |

**读法**：第一行是本节的主线（它决定画像锚在哪一维），第三行决定「产出还是潜力」，第五、六行决定「规模手段能不能上」。**后两行常被当成执行细节，其实它们是前置条件**——面试官池不够时，多面试官机制会退化成「同一个人打两次分」。

**为什么反模式要按「到期日」重排**：把反模式写成「表现 → 危害 → 对策」是对的；但**「危害」只写成后果、而不写它多久之后显形时，读者容易得出一个错误结论——「这些事看起来都不急」**。反模式的共同特征恰恰是账单的到期日离决策日期很远，所以它们在每个季度都无害，只在跨年度的数据里现形；**把「代价落在哪一项、离决策有多远」单独列成一张表（见 3.5 末尾），「现在该先修哪一条」这个问题才有答案**。

### 3.2 模式逐个拆解（核心节）

下面五个模式按同一结构写：**被什么约束逼出来 → 结构 → 为什么这样设计有效 → 代价 → 失效点 → 真实使用**。「失效点」是最不可省的一段——它回答的不是「有什么缺点」，而是「在什么条件下优点会反转成缺点，以及为什么（机制）」。

**关于数字**：本节出现的量级一律标档位，**不引用任何未标注来源的统计数字**。结构示意里的示例（如「支持 1000 QPS 的 RAG 服务」）属**示例量级**【经验】，**不是行业基准**；凡涉及某个做法「有多少公司采用」「效果提升多少」这类量，本节一律不给数——它们是本书无法在本处核验的统计量，写成数字会让整句话失去可信度。

#### 3.2.1 能力驱动画像模式（Competency-Driven Persona）

- **被什么约束逼出来**：同一岗位要在同一招聘季评估数十人，而评估人与候选人每次都不相同。要让不同面试官对同一候选人的结论**可比较**、跨批次**可比对**，只能先把「够不够格」拆成固定维度与固定锚点。
- **结构**：

```sql
-- 一个岗位的画像 = 固定的维度集 + 权重 + 每档可观察的行为锚点
CREATE TABLE role_persona (
  role_code  TEXT,      -- 如 data_architect
  dimension  TEXT,      -- 技术深度 / 系统设计 / 工程素养 / 软素质 / 文化匹配
  weight     NUMERIC,   -- 权重之和 = 1
  min_score  INT,       -- 该维度不得低于此分：总分再高也不通过
  anchor_1   TEXT,      -- BAR：1 分对应一条可观察行为（不是形容词）
  anchor_3   TEXT,
  anchor_5   TEXT,
  PRIMARY KEY (role_code, dimension)
);
-- 结论 = Σ(weight × score)，且每个核心维度 ≥ min_score
-- 冻结规则：维度集与权重一旦确定，冻结到本批次结束
-- 面试中途改权重 → 本批次分数不可比，等于前面面的人白面
```

- **为什么这样设计有效**：**因为维度集、权重与锚点在批次开始前就被冻结，所以两个面试官在同一维度上的分数落在同一把尺子上**——横向可比是批量的前提，而不是锦上添花；**因为 min_score 与加权总分同时存在，所以「总分够高但某一维不及格」能被挡住**；否则最弱的那一维会被其他维度的高分买通，而岗位恰恰可能死在那一维上。
- **代价**：冻结换来可比性的同时损失了适应性——画像只覆盖**已经被写进维度**的能力；新出现的能力（近两年的 Agent 工程一类）在写进画像之前无法被评分，只能活在个别面试官的自定义追问里，不入账、不可比、也无法被回溯。此外，写锚点与季度校准消耗的是资深面试官的时间，这笔开销不会体现在任何业务指标上。
- **失效点**：**当岗位要求的变化快于画像的迭代周期时，本模式「可比较」的优点会反转成「所有人都在同一把过时的尺子上被量」**——**因为流程里唯一的纠错信号来自比较结果，而尺子本身错了不会产生任何异常：分数照样呈正态分布，面试官照样对得上**。修法是给画像设一个「过期告警」（例如连续两批录用者与画像的匹配度都无差异），而不是等人来发现。
- **真实使用**：**结构化面试的预测效度高于非结构化面试，这一结论来自 Schmidt & Hunter 1998 年发表于 *Psychological Bulletin* 的元分析**（【公开：Schmidt & Hunter, 1998】，与 [§ 7.3.1](01-team-formation-section-7-sec7.md) 同一出处）；胜任力取向的源头是 McClelland 1973 年 *Testing for Competence Rather Than for Intelligence*（【公开】）；行为锚定评分的方法学由 Smith & Kendall 1963 年提出（【公开】）。**注意这三条各自能证明什么：它们证明「结构化优于非结构化」这条方向成立，不证明任何一种取材料的绝对精度**。字节把面试官认证与晋升挂钩、要求打高分必须给出行为证据，见本章 [§6](01-team-formation-section-6-sec6.md)（【经验】）。
- **与相邻模式的边界**：能力驱动画像与「结构化面试」的分工是**前者回答「考哪几维、权重多少」，后者回答「怎么问、按什么顺序判」**。两者常被当成一件事，于是出现最常见的半成品：打分卡上有五个维度、每维 1–5 分，但没有一条锚点——**分数可比了，可比的是各自的直觉。**
- **自验方法**：让两名面试官独立给同一段作答打分。差值超过 2 档，说明锚点里还留着形容词。

#### 3.2.2 产出驱动画像模式（Outcome-Driven Persona）

- **被什么约束逼出来**：0→1 阶段的新团队与关键岗位，**岗位职责本身还在变**——写得出的是「前 6 个月要交付什么」，写不出「需要何种能力清单」；此时从能力正推，得到的清单往往是从上一个阶段抄来的。
- **结构**（从产出反推，而不是从能力清单正推）：

```text
产出驱动画像：先写交付物，再反推能力与证据形态
  ① 6 个月关键产出（可验收）：
       搭建支持 1000 QPS 的 RAG 服务【经验：示例量级，非统计】
  ② 拆交付物 → 组件与关键决策：
       向量库选型 / 召回与重排 / 性能调优 / 缓存与降级
  ③ 每件反向写成证据形态（问过去做过什么，不问会什么）：
       向量库选型 ← 有过一次选型对比并留下取舍记录（不是「熟悉向量数据库」）
       性能调优   ← 有过一次把 P99 压下来的经历，并能说出瓶颈在哪
  ④ 6 个月后：同一份 ① 直接用作试用期验收标准
  反规则：产出写成「负责 XX 系统」→ 不可验收，反推链不成立
```

- **为什么这样设计有效**：**因为画像是从交付物反推出来的，所以面试里的每一维都能追溯到一项交付**——评估结论与岗位要求之间存在一条可指认的因果链，而不是两套互不相干的清单；**因为同一份产出清单在 6 个月后就是验收标准，所以评完之后的验证成本接近零**：画像与试用期标准是同一份文件，人岗匹配度在入职前就已经被定义。**它最大的收益不是「评得准」，而是「评完能被验证」**——这条环闭不上，前面所有打分都只是一次性判断。
- **代价**：它要求「6 个月产出」必须写得出来，**因此只对有可比历史的人有效**（校招、转岗、跨行业的候选人直接失效）；产出清单依赖业务计划的稳定性，业务一变则画像与验收标准同时作废，此前的招聘投入沉没；它还天然偏向「能复现已有产出」的人，对「能定义新方向」的人不友好——后者恰恰没有可比历史。
- **失效点**：**当业务在 6 个月内变化超过一次时，本模式「画像即验收标准」的优点会反转成「标准在入职前就已经过期」**——**因为候选人按旧产出被评估、入职后要交付的是新产出，评估结论与岗位要求之间那条因果链断了，而系统里没有任何信号提示标准已作废：JD 还在，产出清单还在，只有它与现实的关系没了**。此时应当把标准的时间窗缩到「一个可验收的里程碑」，而不是继续沿用季度级的产出表述。
- **真实使用**：关键岗（独立方向负责人）走产出驱动 + 多轮深度面 + 背调，是本卷 [§ 7.6](01-team-formation-section-7-sec7.md) 的结论；「JD 里有没有可验收的交付物」是任何人都能自行核验的判定方法（【经验】：多数 0→1 团队的岗位描述以「前 6 个月要交付什么」开头，本书不给出比例数字）。
- **与相邻模式的边界**：产出驱动与能力驱动的分工是**方向相反**——产出驱动问「要交付什么，所以需要什么能力」，能力驱动问「这一类人应当满足哪些维度」。同一个岗位在两年跨度里通常两者都用：先用产出反推出一份清单，再把这份清单固化成维度与权重供批量使用（[§ 7.6](01-team-formation-section-7-sec7.md) 的组合 1 说的就是这条路径）。
- **自验方法**：拿你自己的 JD 读一遍，直接回答「6 个月后拿什么验收这个人」。答不出来的句子，删掉它比留着更好。

#### 3.2.3 潜力驱动模式（Potential-Driven Persona）

- **被什么约束逼出来**：校招与跨领域招聘（如 Java 转 AI 平台）时，**可比的过往产出不存在，或者不可迁移**。这不是「产出不重要」，而是这类候选人的产出证据在结构上为零——此时若仍按能力清单筛，筛出来的只是「简历写法更接近清单」的人。
- **结构**（潜力不是分数，是可被追问到细节的行为史）：

```text
潜力的可观测代理（每一项都必须在面试里被追问到细节，否则退回形容词）
  可塑性：换过领域 / 技术栈的真实经历
          追问：用什么方式补、花了多久、交付了什么
  学习力：有过一次「别人解决不了的问题被我定位到根因」的记录
          追问：当时的判断依据是什么、走了哪些弯路
  迁移力：已有经验里能折算到新领域的部分
          追问：哪一段能直接复用、哪一段必须重建
  价值观：在冲突里怎么选（结构见 3.2.4）
  反规则：「学习能力强」是评价不是证据，写进评语等于零信息
```

- **为什么这样设计有效**：**因为潜力是预测而不是事实，所以它只能由行为史支撑**——一句「学习能力强」无法被核验，而「三周内自己补完某个技术栈并交付了一项可演示的东西」可以被追问、被交叉验证；**又因为校招与转岗候选人的行为史样本天然很小，个体判断的误差必然偏大**，所以这类评估的正确用法是**批量下注**：单个判断不准，但一批人在同一套培养与项目机会下，平均产出可以被拉起来（「长周期 ROI 高」，说的正是这件事）。
- **代价**：短期产出不稳定，前几个月是投资期；如果培养体系（导师、项目机会、阶段性验收）不到位，潜力的收益不会兑现，而成本已经付出；它还**把风险后移到了试用期**——这就要求组织先有可用的试用期退出机制与阶段性验收，否则「批量下注」会变成「批量沉没」。
- **失效点**：**当岗位的容错窗口短于培养周期时（要到岗即产出），本模式「人才池大」的优点会反转成「用人成本被推迟到在职期内暴露」**——**因为潜力型候选人的产出缺口只在入职后才出现，而录用决策已经不可撤回；试用期退出本身也是一次沉没成本，只是它落在另一个预算项里，所以账面看不出来**。
- **真实使用**：校招与转岗按潜力筛是行业通例（【经验】）；本卷 [§ 7.6](01-team-formation-section-7-sec7.md) 对校招的结论是「潜力驱动 + 工作样本 + 结构化」——**加工作样本这一步，正是为了让潜力评估至少有一段现场证据，而不是全凭讲述**。
- **与相邻模式的边界**：潜力驱动与「降低标准」的分界是**有没有保留验证节点**——潜力驱动的完整定义里必须包含「验证放到试用期 + 阶段性验收」；只把门槛降下来、不设验证节点，那是降低标准，与潜力无关，也与本节讲的模式无关。
- **自验方法**：抽三位你判为「高潜力」的候选人，看他们的评语能不能还原成一条可追问的行为史。还原不了，你给的其实是印象分。

#### 3.2.4 文化匹配模式（Culture-Fit Persona）

- **被什么约束逼出来**：技能可以在岗位上补，共事方式不能。在强自主、高坦诚的团队里（Netflix 的「人才密度 × 坦诚文化」，见主文件 § 2.1），日常协作没有主管逐条监督，个体的行为标准只能靠价值观自持——**于是价值观必须在入口处被评估，否则它的成本由整个团队分摊**。
- **结构**（把「文化匹配」操作化为「共事方式是否兼容」，而不是「像不像我们」）：

```text
文化匹配 = 价值观条目 × 行为锚点（必须是过去发生过的事）
  价值观条目        行为锚点（问过去）                          伪答案特征
  坦诚              有过一次当面指出上级方案错误的经历          「我比较直」
  自主              有过一次无人指派下自己立项并交付            「我不喜欢被管」
  以数据说话        有过一次用数据推翻自己原有判断的经历        「我很理性」
  反规则 ①：问「你认同我们的价值观吗」→ 必然答「认同」，零信息量
  反规则 ②：价值观当一票否决用、却没有行为锚点
            → 等于把面试官的个人偏好制度化（§ 7.6 已记这条）
```

- **为什么这样设计有效**：**因为价值观只能从「他在冲突里怎么选」来观察，所以问题必须是过去的行为事件，而不是态度声明**——态度声明人人都会给出正确答案，行为史无法伪造细节；**因为匹配被定义为「协作方式兼容」而不是「同类人」，所以它筛掉的是不兼容的协作方式，而不是差异本身**——这条区分就是它会不会退化成同质化的分水岭。
- **代价**：这是全部维度里最难校准的一维——它最依赖面试官自身经验，也最容易被相似性偏见（偏好「像我这样的人」）污染，而这两件事在打分表上看不出来；结构化程度低时，它还会成为唯一一个「可以凭感觉给分」的维度。
- **失效点**：**当组织自身的做法需要被改变时（转型、进入陌生领域），本模式「凝聚力强」的优点会反转成「系统性地放大既有偏见」**——**因为筛选标准来自当前团队的共识，而当这份共识需要被挑战时，这套标准会优先筛掉提出不同做法的人；更麻烦的是它不留下任何异常：被筛掉的人从一开始就进不了面试记录，复盘时看不到自己漏掉了什么**。
- **真实使用**：Netflix 的 Keeper Test 与「人才密度」取向由 2009 年公开的《Culture Deck》阐述（【公开：Netflix Culture Deck, 2009】，与 [§ 7.3.3](01-team-formation-section-7-sec7.md) 同一出处）；Reed Hastings 与 Erin Meyer 在《No Rules Rules》（2020）中进一步记述了这套取向（【公开】）。「亚马逊 2024 年因多元化相关争议调整此类实践」属案例记录，**本节不据此断言具体事件与年份**（【经验】；读者可按公司名与年份自行检索核验）。
- **与相邻模式的边界**：文化匹配与相似性偏见的分界是**锚点问的是行为还是偏好**——问「他过去在冲突里怎么选」是评估，问「他像不像我们」是偏见。前者能被第三方复核（有原话、有事例），后者不能，且后者在记录上看起来与前者一模一样。
- **自验方法**：调出最近 10 份面试评价，看有没有一条写明了候选人「在冲突里怎么选」。全都是「沟通好、气场合适」，说明这一维实际上没有被评估。

#### 3.2.5 AI 增强模式（AI-Augmented Persona，2024+）

- **被什么约束逼出来**：候选人数量与每人材料量超过了面试官团队的阅读带宽；同时核心技能的失效周期已压到 1–2 年（见 [§ 02 人才梯队 § 3.2.8](../02-talent-ladder/02-talent-ladder-section-3-sec3.md)），静态 JD 的校准节奏跟不上。**要解决的是「量」，不是「判断」。**
- **结构**（模型出草稿，人做判定；边界就划在「草稿」这一侧）：

```text
AI 增强画像的数据流
  候选人材料 ──► LLM 按既定 schema 抽取：技能节点 / 经历 / 项目产出
                        │
                  与技能图谱对齐（岗位需要哪些节点、各自达到哪一档）
                        │
                  输出：差异清单 + 建议追问的问题（草稿）
                        │
   ──► 人核验并追问 ──► 人对着证据做录用判定（AI 不进入判定环节）
  ─────────────────────────────────────────────
  留痕：抽取结果 + 模型版本 + 人工复核样本
        （这是偏见审计与候选人披露要求的前置条件，不是可选项）
```

- **为什么这样设计有效**：**因为模型的输出是「按 schema 抽取的字段」而不是判断，所以它能把形态各异的材料统一成可比较的结构**，把筛选的边际成本压到接近零——这正是「候选人量超过阅读带宽」这个约束的直接解法；**但也正因为它是从历史材料上训练出来的统计模型，它的输出与「这个人能不能干」之间没有因果链**，所以它能替代的只有「读材料的工时」，不能替代「对着证据做判断」这一步。**把边界划在草稿一侧，是为了让效率收益进来、让判定责任留在人身上。**
- **代价**：偏见会被规模化——历史筛选偏好被复制一遍，并套上一个看起来客观的外壳；候选人侧的对抗成本极低，材料由 AI 生成后更难分辨，于是必须增加现场实操（工作样本、现场编码、屏幕共享）来取得可信证据，**面试总时长反而上升**；此外还有合规成本：纽约市 Local Law 144（2023 年 7 月生效，要求对自动化就业决策工具做偏见审计并向候选人披露）与欧盟 AI Act（2024 年生效，就业场景归入高风险）是两条公开参照线（【公开】，与 [§ 7.2](01-team-formation-section-7-sec7.md) 同一出处）。
- **失效点**：**当评估材料本身由 AI 生成时，本模式「量化、可校准」的优点会反转成「输入信号被污染」**——**因为模型抽取的是表述而不是事实，材料越容易写得「看起来匹配」，抽取结果的可核验性就越低；而系统里没有任何信号会提示这一点，模型抽取能力越强，这个缺口越大**。此时要补的不是更强的模型，而是不可伪造的现场证据。
- **真实使用**：AI 简历解析与 AI 面试分析工具在 2024–2025 年被广泛使用（【经验】，本书不给出采用率数字）；判定一个工具是否属于「自动化就业决策工具」，看它是否**实质上参与了筛选或录用判断**（哪怕是排序或推荐），而不是看它是否「由 AI 驱动」（判定方法见 [§ 7.2](01-team-formation-section-7-sec7.md)）。
- **与相邻模式的边界**：AI 增强与传统关键词筛选的区别不在「用了模型」，而在**输出形态**——关键词筛出的是「通过 / 不通过」，AI 增强筛出的是「差异清单 + 建议追问的问题」。**前者的错误不会被下游发现**（被筛掉的简历不会再被看一眼），后者的错误会在人核验追问时暴露；这也是边界必须划在「草稿」一侧的另一个理由。
- **自验方法**：对同一份简历做无关变量扰动（姓名、性别相关措辞、院校），比较模型输出是否变化。**这是任何人都能在自己环境里跑一遍的检验**。

### 3.3 模式选择决策表

这张表不回答「哪种画像更先进」，只回答**「你现在的约束把你放在哪一行」**。七行覆盖全部适用场景——**注意它们不是七种模式，而是七组约束**：同样的「能力驱动」在校招与在批量社招里都是基础，区别只在于它上面还要叠哪一层。

**读这张表时最容易犯的一个错，是把「推荐模式」那一列当成可以自由组合的菜单。** 组合是有前提的：潜力驱动必须配工作样本（否则潜力无从验证）、能力驱动必须配锚点（否则分数不可比）、文化匹配必须配行为锚点（否则退化成相似性偏见）、AI 召回必须配人工判定（否则偏见规模化）。**没有配套件的模式不是「弱化版」，而是会反向伤害的那一版。**

| 约束组合 | 推荐模式 | 为什么不选另一个 | 关键判据 |
| --- | --- | --- | --- |
| 校招（无可比产出） | 潜力驱动 + 结构化能力维度 + 工作样本 | 不选产出驱动：应届生没有可比产出，这一维证据在结构上为零 | 候选人身上有没有 6 个月可验收的历史交付 |
| 0→1 团队组建（职责仍在变） | 产出驱动 + 文化匹配 | 不选纯能力驱动：能力清单此时只能从上一阶段抄来 | 「6 个月关键产出」写得出来吗 |
| 1→10 规模化（年招数十人以上） | 能力驱动 + 结构化 + AI 做召回 | 不选潜力驱动：批量下看的是可比性与到岗速度，不是长周期下注 | 面试官池够不够组成多面试官，且能被认证 |
| 10→100 跨 BU（跨领域适配） | 潜力驱动 + 文化匹配 | 不选单一能力清单：同一职级在不同 BU 的含义不同，清单无法跨域比 | 候选人的经验里有多大比例可折算到新域 |
| 高端社招 / 独立方向负责人 | 产出驱动 + 深度追问 + 背调 | 不选潜力驱动：单次判断错误的损失落在一整条方向上，不能用预测下注 | 这个决定错了，损失落在一个人还是一条方向 |
| 跨领域招聘（如后端转 AI 平台） | 潜力驱动 | 不选产出驱动：过往产出与目标岗位不可比，只能看迁移力与学习力 | 他的产出能否被追问出「与目标岗位同构」的部分 |
| 远程岗位（面试官与被评估者异时异地） | 能力驱动 + 工作样本 + AI 辅助记录 | 不选只靠文化匹配：异步下最易失真的正是判断「气场」的维度 | 评估证据能不能被异步复算（录音、作答、代码） |

表里最常被误配的一对是 **产出驱动与潜力驱动**，而且错法通常是**反向的两次**：关键岗上用了潜力驱动（理由往往是「这个人成长性极好」），校招上用了产出驱动（理由是「希望来的人能立刻上手」）。**前者的后果是「一个方向押在预测上」**——预测错误的纠偏时间常数以季度计；**后者的后果是「用一把量不到东西的尺子筛人」**——应届生那一栏是空的，于是筛出来的实际是「简历写法更接近清单」的人。两个方向的判据只有一句：**这个人身上，有 6 个月可验收的历史交付吗？**有，用产出驱动；没有，用潜力驱动 + 工作样本，并把验证放到试用期。

第二常被误配的一对是 **能力驱动与文化匹配**：把「价值观」当成能力清单里顺带的一行，用同一个 1–5 分的模糊尺度一起打。后果是这一维永远得 3 分——因为它没有行为锚点时是唯一无法被复核的维度。正确做法是给它独立的锚点与独立的记录（见 3.2.4），**并且把「一票否决」这类用法先降级成「打分 + 记录 + 合议时单独讨论」**：无锚点的一票否决，等于把面试官的个人偏好制度化。

第三对是 **AI 增强与「所有岗位都上 AI」**：把工具当成模式的全部。**AI 增强解决的是评审带宽，不解决证据类型**——在还没有确定画像锚在哪一维时引入模型，得到的只是「用模型把一份错的清单筛得更快」，而且历史筛选偏好会被同时放大、并套上客观外壳。判断顺序应当是**先定证据类型（3.2.1–3.2.4 选一个），再决定要不要上模型做召回**。

把这三对合起来，就是这张表的用法：**先定位你被哪条约束支配（证据类型 / 批量与一致性 / 文化强度 / 评审带宽 / 面试官池），再检查那一行的前提是否具备，最后才决定用哪种组合。** 跨行使用不是不行，但**跨行不会省掉任何一项成本，只会把下一行的成本提前预支。**

### 3.4 组合模式：真实系统不会只用一种

下面三个组合不是「推荐的三种搭法」，而是这类招聘体系里反复出现的三种结构。每一个都要说清三件事：**构成是什么、各自的职责边界在哪、以及它把代价放在了哪里**——第三个问题最常被跳过，而它恰恰决定这个组合会不会变成一种长期负担。

1. **能力驱动 + 结构化面试 + BAR 锚点**——**构成**：画像定义「考哪几维、各占多少权重」，结构化面试定义「怎么问、谁先落笔」，BAR 定义「1 分和 5 分差在哪里」。**职责边界**：画像负责**考什么**，流程负责**谁来判、按什么顺序判**，锚点负责**判得能不能被复核**——三者引用同一套维度命名，改一处必须同时改三处。**运维代价**：季度校准 + 面试官认证（影子 → 副 → 独立 → 校准四阶段）+ 极端分必须附候选人原话作为证据；这笔开销落在资深工程师身上，不会体现在业务指标里。**适合规模**：年招数十人以上（固定投入是题库与锚点，摊到人头上才划算，【经验】）。
2. **产出驱动 + 潜力驱动（同一团队跑两条轨道）**——**构成**：关键岗与有可比历史的人走产出反推，校招与转岗走潜力 + 工作样本。**职责边界**：产出轨道负责「已在别处证明过同类交付的人」，潜力轨道负责「还没有可比历史、但行为史支持可塑性的人」；两条轨道**必须共用同一套维度命名**，否则两条轨道的分数无法在同一个职级体系里被比较。**运维代价**：两套题库、两类面试官、两种验收周期（前者 6 个月，后者要跨更长时间），管理成本接近翻倍【经验】。**适合规模**：从 0→1 走向 1→10 的过渡团队——既需要能立刻交付的人，也需要能被培养起来的人。
3. **AI 做召回 + 人工判定 + 现场工作样本**——**构成**：AI 从数百份材料里挑出值得细看的那几十份并给出追问建议（示例量级，【经验】）；现场实操用来取得不可伪造的证据；人对着证据做判定。**职责边界**：AI 管**注意力分配**，现场样本管**证据真实性**，人管**判定**——三者的边界一旦挪动（例如让模型直接给排序结论并据此淘汰），合规与偏见风险同时上台阶（Local Law 144，2023；欧盟 AI Act，2024，【公开】）。**运维代价**：校准集与抽检、留痕与审计材料、现场环节占用的面试官时间，以及「AI 生成材料」带来的反制作业投入。**适合规模**：候选人量已经大到人工初筛成为瓶颈时。

三个组合共有一个前提，值得单独说：**它们都要求「证据能落到具体的人名与具体的行为上」**。维度、锚点、产出、行为史、现场样本——五者形式不同，作用相同：**把人从「印象」里移出来，放进可以被第三方复核的记录里**。做不到这一点，组合再多也只是流程装饰。

把三个组合放在一起，可以看出它们各自把「变化」关在哪一层：

| 组合 | 谁承担稳定 | 谁承担变化 | 组合的失效方式 |
| --- | --- | --- | --- |
| 能力驱动 + 结构化 + BAR | 维度命名与锚点 | 题目、追问、面试官 | 锚点无人校准 → 分数看似可比，实际各打各的；题库不换 → 题目被候选人背下来 |
| 产出驱动 + 潜力驱动 | 维度命名（两条轨道共用） | 产出清单、培养路径与验收节点 | 两条轨道各自演化 → 分数无法在职级体系里合并；验收标准不更新 → 产出清单变成摆设 |
| AI 召回 + 人工判定 + 现场样本 | 判定权归属（人） | 模型、材料形态、反制手段 | 边界被挪动（模型进入淘汰判断）→ 偏见规模化并触合规；只加模型不加现场样本 → 材料越写越漂亮、证据越来越少 |

这张表要传达的只有一句：**组合的前提是「变化被限制在某一层」，一旦变化同时发生在两层——例如既换材料形态又挪动判定权——组合就退化成耦合，而耦合的典型症状是「出了问题找不到该修哪一层」。**

### 3.5 反模式与失效分析

下表覆盖全部反模式（8 条，一条不删），每条写成「症状 → 后果 → 成因 → 修法」四段。**其中「后果」一列一律写机制层面的后果，不写留存率一类的阈值数字**——留存率随岗位、城市与团队而异，把某个百分比写成通用结论，会让判据变成猜谜；**机制是否成立才是可复用的部分**（例如「考核周期短于反馈周期时，短周期指标必然胜出」），阈值应当由你自己的数据给出。

| 反模式 | 症状（怎么发现它） | 后果（机制层面的后果） | 成因（为什么团队会写成这样） | 修法 |
| --- | --- | --- | --- | --- |
| **拍脑袋招人** | 面试记录只有结论没有证据；同一候选人不同面试官结论相反且无法仲裁 | 结论不可复算 → 偏见直接进入录用，且事后无法复盘「当初为什么这么判」 | 结构化是缓慢、可选的准备工作，而面试是当期必须完成的任务 | 结构化面试 + BAR 锚点 + 多面试官先独立落笔再合议 + 校准会 |
| **唯学历论 / 唯大厂论** | JD 里写着院校或公司标签的硬门槛；初筛只按标签分层 | 筛的是与真实产出相关性最弱的代理 → 把「有可核验产出但不满足标签」的人整批排除，池子变窄且同质 | 标签是唯一能在几秒内做完的判断，而读证据要花时间 | 标签只作加分项；初筛只问一条：有没有可核验的产出证据 |
| **JD 模糊** | JD 里是「数据架构师 / 高级工程师 / 资深开发」这类头衔，没有维度，也没有可验收产出 | 候选人与评估者各自脑补一份画像 → 漏斗每一级的转化率都无法解释：说不清筛掉的是「不合格」还是「期待不匹配」 | 复用 JD 模板比写画像快，且模板看起来更专业 | 每个岗位配三件套：画像 + BAR + 漏斗指标 |
| **面试官不培训** | 新面试官没旁听过就上场；同一维度在不同面试官之间差 2 档以上 | 面试官的个体尺度成为主要噪声源 → 评分不可比较，结构化退化成「多了几张表的凭感觉」 | 「自己能做」被当成「能评估别人」；面试在多数组织里被当作义务劳动 | 四阶段培养（影子 → 副 → 独立 → 校准）+ 认证 + 准度回看（[§ 7.3.3](01-team-formation-section-7-sec7.md)） |
| **招聘漏斗只看 Offer 数** | 看板上只有 Offer 数、到岗天数、招聘周期 | 「招对人」的反馈以年计而考核以季度计 → 短周期指标必然胜出，用降低标准购买速度，一两年后以留存率体现 | 被看见的东西才会被优化；滞后指标不进看板 | 把试用期通过率、1 年留存、面试分与实际表现的关联并排展示 |
| **Offer 拖延症** | 终面到发 Offer 超过两周；候选人在等待期继续面试别家 | 决策窗口与他人的流程错位 → 候选人在别处先到 Offer 即离场，同时这段体验会反馈到雇主品牌 | 内部审批链长，而内部流程的延迟不计入任何人的指标 | 流程固化到固定天数并公布；薪资带宽预授权，48 小时内给结果（【经验】为常见目标） |
| **忽略文化匹配** | 面试评价里没有任何关于共事方式的记录；冲突型新人入职后团队协作成本上升 | 共事方式不匹配的破坏力随能力增强而放大 → 但团队会把它归因为「这个人性格问题」，看不到是入口没评估 | 这一维没有行为锚点时最难打分，于是被整体跳过 | 独立维度 + 行为锚点独立打分；合议时单独讨论（见 3.2.4、[§ 7.6](01-team-formation-section-7-sec7.md)） |
| **面试官「面霸」症** | 面试表现很好的人入职后平庸；面试里只有讲述，没有实操 | 评估的变成表达与准备能力，而它与岗位产出相关性弱 → 试用期淘汰率上升，且淘汰成本落在试用期而不是评审期 | 聊项目比设计工作样本省事，对候选人也更「友好」 | 增加工作样本 / 现场编码；极端分必须附候选人原话作为证据 |

**最危险的一个是「拍脑袋招人」**，但它的危险不在单次错判，而在**它让整套体系失去纠错能力**：没有证据链，面试分与后续表现之间的关联就无法被计算，于是画像永远得不到校准（[§ 7.5](01-team-formation-section-7-sec7.md) 的第 12 个月那一步会直接落空）。它的典型暴露方式是评审争议——讨论最后落到「感觉」上，而这通常被归因为「评委水平不行」，实际原因是记录里没有可被讨论的对象。

**第二个是「招聘漏斗只看 Offer 数」**，因为它是**结构性问题而不是个人失误**：考核周期短于「招对人」的反馈周期，短周期指标必然胜出，团队会把「降低标准」当成完成 KPI 的理性手段。它的典型暴露方式是两年后的密度下滑——**此时追责到某个人是不公平的，因为换任何人来都会做同样的选择**。

**第三个是「面试官『面霸』症」**，它的机制特点是**把举证责任留给了表达**：面试只有讲述时，评分实际由「谁讲得更清楚」决定；这不是偏见，而是**证据缺位时的必然结果**。修法只能是补证据（工作样本、现场编码），而不是提醒面试官「别被表达带偏」。

**这八条共享同一个成因**：写结构（维度、锚点、记录格式、验收标准）是**缓慢、可选、且不产生当期产出**的工作，而面试、发 Offer、推进流程都是当期可见的动作。因此结构被系统性地跳过，直到某次错判或某次离职潮把成本显性化——**而此时补结构的成本，已经包含了一次已经发生的事故**。一个共通的识别信号是：**如果连续两次评审的争议都发生在「这个人到底行不行」上，而不是「哪一维证据不足」上，那么问题几乎一定在结构侧。**

**这些反模式的代价落在哪一项**（沿用 [§ 7.4](01-team-formation-section-7-sec7.md) 的成本函数估，不引入外部系数）：

| 反模式 | 代价落在哪一项 | 机制（为什么它一定会出现在那一项） |
| --- | --- | --- |
| 拍脑袋招人 | 误招的期望成本 | 没有证据链 → 面试分与后续表现的关联无法计算，画像永远得不到校准 |
| 唯学历 / 唯大厂论 | 候选人池（供给侧） | 用相关性最弱的代理筛人，池子变窄且同质，缺口最后只能靠放宽标准补 |
| JD 模糊 | 面试工时（返工） | 候选人与评估者各自脑补画像，面试双方谈的其实不是同一个岗位 |
| 面试官不培训 | 面试工时（信息量接近零） | 个体尺度成为主要噪声源；工时照付，但结论不可比、无法合并 |
| 只看 Offer 数 | 误招的期望成本（被后移） | 用降低标准购买速度，一两年后才以留存率的形式体现 |
| Offer 拖延症 | 候选人池 + 雇主品牌 | 决策窗口与候选人的其他流程错位，先到别家即离场 |
| 忽略文化匹配 | 团队协作成本（长期） | 共事方式不匹配的破坏力随能力增强而放大，且不体现为可量化的绩效差 |
| 面试官「面霸」症 | 误招 + 试用期退出成本 | 评估的是表达与准备能力，淘汰只能发生在试用期这个更贵的环节 |

**读这张表的重点是「到期日」**：这八条的共同特征不是「贵」，而是**账单的到期日离决策日期很远**——所以它们在每个季度看起来都无害，只在跨年度的数据里显形。这也是为什么修法几乎都指向同一件事：**把证据留在决策现场**（记录、原话、锚点、工作样本）。**有了证据，账单就与决策同时到期。**

### 3.6 规模跃迁时模式何时该换

| 跃迁 | 原模式 | 为什么开始疼 | 换成 | 迁移的代价 |
| --- | --- | --- | --- | --- |
| 年招个位数 → 年招数十人 | 深度面 + 逐人判断 | 面试官池不够，且同一天面多人时结论不可比 | 能力驱动 + 结构化 + BAR 锚点 | 题库与锚点的一次性投入 + 面试官认证，约数人周量级【经验】 |
| 0→1 → 1→10 | 产出驱动为主 | 编制扩张速度快于「每个岗位的 6 个月产出」被定义的速度 | 增加能力驱动轨道与校招 / 潜力轨道 | 两条轨道意味着两套题库、两类面试官；且都必须共用同一套维度命名 |
| 单团队 → 跨 BU | 各 BU 各自的画像 | 同一职级在不同 BU 含义不同，内部转岗要重新面一遍 | 统一维度命名 + 跨级评委池 | 统一标准必须有唯一 Owner，否则会出现培训材料与标准不一致 |
| 校招为主 → 社招为主 | 潜力驱动 | 潜力评估的验证周期（数月）长于业务等待窗口 | 产出驱动 + 深度追问 + 背调 | 流程变长（多轮 + 背调），需要业务侧接受「宁可慢、不可错」 |
| 技能清单 1–2 年一换 | 静态 JD / 一次性画像 | 画像里的核心要求已有一半不在项目中实际使用 | 能力图谱 + 指定维护人 | 图的维护是永久成本；无人维护时它会主动给出过时的学习与评估方向（[§ 02 § 3.2.8](../02-talent-ladder/02-talent-ladder-section-3-sec3.md)） |
| 候选人量超过评审带宽 | 人工初筛 | 初筛成为瓶颈，且材料由 AI 生成的比例上升 | AI 做召回 + 人工判定 + 现场工作样本 | 校准集、留痕与合规审计；现场环节拉长面试时长（见 3.2.5） |

**跃迁的判据不是人数，而是「约束是否已经变了」**——人数只是约束变化的代理指标。真正触发切换的是三条可观测信号：**① 同一候选人被不同面试官判成不一致结论的比例在上升；② 面试官的准度无法被度量（说明没人记录、也没人回看）；③ 候选人池里「材料很匹配但拿不出可核验证据」的比例在上升**。三条中任意一条为真，就说明当前模式已到界。

**迁移里有两项近乎不可逆，要在切换前想清楚**：一是**画像权重一旦被录用数据绑定过**（用「面试分 ↔ 实际表现」回填过），再改权重就需要重新积累一年的数据才能重新校准——**改动本身不贵，重新获得可信度很贵**；二是**流程一旦标准化，回退会被读成「降低标准」**，即使回退的理由是业务阶段变了。因此迁移方向应当是**先收紧标准、再加轨道**，反过来做会把两件事的难度叠加。

**还有一条纪律与「什么时候不换」有关**：同样是「招不到合适的人」，可能是证据类型变了（该换画像模式）、可能是供给池太薄（该做雇主品牌与内推，属供给族，见 [§ 7.6](01-team-formation-section-7-sec7.md)）、也可能只是流程太慢（该改决策速度）。**换错模式的代价通常大于晚换**：晚换只是继续疼，换错则是把疼换成了「旧模式还在用、新模式还要维护」——而两套画像并行时，面试官会各自挑自己顺手的那套去用。

### 3.7 自检清单

下面 12 条按「证据 → 判断 → 激励 → 规模」的顺序排列，对应 3.2 五个模式的失效点与 3.5 的八条反模式。

- [ ] 这个岗位的画像，锚在哪一类证据上（产出 / 能力 / 潜力 / 行为史）？这一类证据在这批候选人身上拿得到吗？
- [ ] 画出画像的那一维，能不能同时写出一条「1 分长什么样」和一条「5 分长什么样」？写不出，这一维不可复核。
- [ ] 面试记录里有没有候选人原话？只有结论没有原话，说明结论无法被第三方复核。
- [ ] 同一段作答交给两名面试官独立打分，差值会不会超过 2 档？
- [ ] 这个岗位的「6 个月关键产出」写得出来吗？写不出来，说明它该走潜力 + 工作样本，而不是产出驱动。
- [ ] 画像上有多少个维度是「新出现、但还没写进去」的能力？它们现在靠谁的临场追问在兜？
- [ ] 文化匹配这一维，最近 10 份评价里有没有一条写明了「他在冲突里怎么选」？
- [ ] 招聘看板上有没有一个以年计的指标（试用期通过率 / 1 年留存 / 面试分与实际表现的关联）？一个都没有，看板必然驱动「快速填坑」。
- [ ] 面试官有没有认证，有没有人回看过他的准度？没有，面试在机制上就是过场。
- [ ] 从终面到发 Offer 要几天？超过两周，候选人就在别家的流程里。
- [ ] 如果用了自动化筛选工具：它有没有参与淘汰判断？有没有做过偏见审计与披露？
- [ ] 抽一份简历做无关变量扰动（姓名 / 措辞 / 院校），模型输出会变吗？会变，说明召回本身就带着偏见。

### 3.8 小结

| 你的约束 | 建议模式 | 关键理由（机制层面） |
| --- | --- | --- |
| 有 6 个月可验收的历史交付 | 产出驱动 + 深度追问 + 背调 | 可查证的历史事实是精度最高的代理变量，且同一份产出清单直接成为验收标准 |
| 没有可比历史（校招 / 转岗） | 潜力驱动 + 工作样本 | 潜力是预测，只能由行为史支撑；补一段现场证据，避免全凭讲述 |
| 一次招数十人、面试官多人 | 能力驱动 + BAR + 多面试官独立落笔 | 能力不可观测，批量下一致性优先于精度；不可比的分数等于没有分数 |
| 强自主 / 高坦诚的团队文化 | 文化匹配 + 行为锚点独立打分 | 共事方式不兼容的破坏力随能力增强而放大；无锚点的文化匹配会退化成相似性偏见 |
| 候选人量超过评审带宽 | AI 做召回、人做判定 + 现场实操 | 模型输出是表述而不是事实，只能压缩读材料的工时，不能承担判定 |
| 岗位要求一年一变 | 能力图谱 + 指定维护人 | 冻结的画像在失效后不会报错，只会让所有人被同一把过时的尺子量 |
| 只追求到岗速度 | 先把滞后指标并上同一块看板 | 考核周期短于反馈周期时，短周期指标必然胜出，这是结构问题不是态度问题 |
| 面试结论经常互相矛盾 | 补锚点与记录格式（先统一尺子） | 争议发生在「人行不行」而不是「哪一维证据不足」时，问题在结构侧 |

> 本节小结：决定画像模式的**唯一那条约束，是「在做出录用决定之前，你能拿到并核验哪一类证据」**——它决定画像锚在产出、能力、潜力还是行为史上，其余差异（权重、锚点、AI 手段、文化维度）都是在这条确定之后的优化项。五个模式在这套结构里的位置是**同一约束的五种取值**：产出对应「证据已有且可比」，能力对应「证据没有、只能编码」，潜力对应「连编码的原料都很少」，文化匹配对应「证据只存在于冲突情境里」，AI 增强对应「证据量超过了人工阅读带宽」。**换模式的前提，永远是先确认证据类型变了，而不是先确认人数变了。**

把本节压成三句可执行的话：**第一，先数证据，再选画像**——「这批候选人身上，有 6 个月可验收的历史交付吗」这个问题的答案，比任何画像模板都更能决定你该用哪一个模式。**第二，任何一维都要能写出 1 分和 5 分长什么样**——写不出锚点的维度一定会在评审时退化成印象分，而文化匹配这类高价值维度，恰恰最容易退化成这一种。**第三，把证据留在决策现场**——记录、原话、工作样本、留痕；**证据在哪里到期，账单就在哪里到期**。

最后一条需要读者自行判断可迁移性：本节的五个模式是**按证据类型分家的，不是按公司分家的**。任何一家公司的招聘体系里通常同时跑着其中两三条轨道（关键岗走产出、校招走潜力、批量岗走能力维度 + 结构化），**它们的差别不在于谁更先进，而在于各自服务的那一批候选人的证据形态不同**——把某一条轨道上的成功做法整批搬到另一条轨道上，失败往往不是因为方法错，而是因为那一维证据在新的人群里根本不存在。
