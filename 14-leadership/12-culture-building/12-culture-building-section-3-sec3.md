## 3. 设计模式与范式

文化建设的「模式」不是价值观清单，而是**把「什么行为会被奖励、什么行为会被淘汰」固定下来的装置**。主文件 §1.2 列的五个痛点——「贴在墙上的口号」「说一套做一套」「心理安全缺失」「Ownership 缺失」「Customer Focus 缺失」——没有一个能靠宣讲解决：宣讲改变的是宣称（Espoused Values），而员工读的是底层假设。本节沿用 [§ 7 与其他方法对比](12-culture-building-section-7-sec7.md) 的六条判据（激励耦合度、信息流方向、决策权默认归属、可观测性、被游戏的空间、约束兼容性，见 §7.1 的判据表，逐字未改）。但需要说明的是：**下面这四族是本节自己的分法**，按「这个装置作用于哪一层」划分，与 §7.2 的「激励驱动族 / 状态度量族 / 约束外延族」不是同一套分类——后者比的是候选文化方案，前者比的是单个机制装置，两处不可互相套用。四族为：管**信息流**的（3.2.1–3.2.2，加上 3.2.4——客户反馈闭环的作用是让组织外的信号能进来，因此在 3.4 的组合 A 里与 3.2.1、3.2.2 同族）、管**宣称与行为对齐**的（3.2.3 价值观行为化）、管**激励与问责**的（3.2.5、3.2.8）、管**决策权与度量**的（3.2.6–3.2.7）。后两族分开写是有意的：3.2.6 管的是决策权分级，3.2.7 管的是度量的可观测性与被游戏空间，而 3.2.7 的第一条纪律恰恰是**不进个人考核**（3.4 的组合 B 与 3.7 都把「文化指标进考核」列为失格），把它和管激励的 3.2.5、3.2.8 归成一族，会与本节自己的表述冲突。

### 3.1 先看约束：模式不是选择题，是约束的产物

文化模式最容易被讲成「选一套价值观」：想做创新就学 Netflix，想做客户导向就学 Amazon。但真实的约束比这硬——§7 已经证明：**文化是激励结构的因变量，不是自变量**。抽走薪酬与淘汰机制只抄「自由」，剩下的不是文化，是没有约束的混乱。所以先立约束，再谈模式。

还有一层约束在所有模式之上：**文化准则必须能被写成可观察的行为，否则它只能被反复宣讲**。这决定了后面所有模式的形态——用文本写不清的准则，用度量也测不准，用结构更锁不住。所以六条约束不是一张并列的清单，而是有先后的：**可观测性决定一条准则能不能被写成行为，信息流方向决定写错了能不能被修正**——这两条不成立时，剩下四条调得再准也是空转。约束之间还会互相顶：人才密度不够时，监管强度再低也不能给自由；管理者示范不可观测时，制度写得再细也会被一次例外作废。

| 约束 | 它决定了什么 | 本主题下最容易被它推翻的直觉 |
| --- | --- | --- |
| 行为的可观测性 | 用文本、用度量，还是用结构来固定行为 | 写了就会做 → 不可观测的准则只能反复宣讲，无法改进 |
| 激励耦合位置（挂在招聘 / 评价 / 晋升 / 淘汰） | 行为改变的速度与表演程度 | 宣讲到位就能改变 → 不进激励的行为回报为零 |
| 信息流方向（坏消息能否上行） | 组织是否有纠错开关 | 文化好不好看满意度分 → 分数治不了不敢说话 |
| 组织规模与人才密度 | 「给自由」是否是可选项 | 头部公司这么做所以我也能 → 低人才密度下自由必然翻车 |
| 监管与合规强度 | 自由裁量的边界被预先裁掉多少 | 照搬无审批式自由是激进 → 在可举证的硬约束面前它是违规 |
| 管理者示范的可观测性 | 规则是「被宣布的」还是「被执行过的」 | 用制度替代示范 → 制度执行者自己破例一次，规则可信度归零 |

**六条里权重最高的是第二条（激励耦合位置）**：它决定文化改得多快、被表演得多厉害；而第三条（信息流方向）是前置开关——坏消息上不来，任何文化机制都无法被修正。

### 3.2 模式逐个拆解（核心节）

> 结构示意里的具体数值一律是**示意值**（用来说明结构长什么样，不指向任何真实系统）；本节凡涉及真实口径、时限与比例的地方，都单独标了【公开】/【推算】/【经验】档位。

#### 3.2.1 心理安全模式（Psychological Safety）

**被什么约束逼出来**：说真话的成本由组织的反应决定，不由个人勇气决定。

**结构**：

```text
心理安全必须与高标准成对（Edmondson 的二维框架）
┌────────────────┬──────────────────┬──────────────────┐
│                │ 低标准           │ 高标准           │
├────────────────┼──────────────────┼──────────────────┤
│ 高心理安全     │ 舒适区（敢说，没人觉得必须改）│ 学习区 ← 目标 │
│ 低心理安全     │ 冷漠区（不说，也不做）        │ 焦虑区（做但不敢报）│
└────────────────┴──────────────────┴──────────────────┘
→ 关键：心理安全只降低「说」的成本，不降低「做错」的成本
```

**为什么这样设计有效**：因为它降低的是「上报」的边际成本、而不是「犯错」的边际成本，所以必须与高标准成对给出；只给心理安全不给标准，得到的是舒适区——问题敢提，但没人觉得必须解决。主文件 §2.3 的「心理安全建设 5 步法」（高管先承认错误、无指责复盘、直接反馈、允许试错、多元声音被听见）正是把这四象限往右上角推的动作序列。

**代价**：管理者要让渡一部分即时处置权（事故当下不能当场对提问题的人发火），这在压力最大的一刻是反直觉的；示范错误同样要花掉管理者的面子，而且这笔支出必须重复支付才有用。

**失效点**：当心理安全被等同于「没有后果」时，标准会跟着一起降下来，组织进入舒适区——问题被提出、被记录、被搁置，因为可观测的只有「有没有人说话」，不是「说完之后发生了什么」。判断方法很直接：看最近一次有人公开提反对意见之后，相关的事情有没有真的改变。

**真实使用**：Google 的 Project Aristotle（2015）把心理安全与团队效能关联【公开：年份见主文件 §1.4】；Edmondson 的框架见主文件 §2.1 所记《The Fearless Organization》（2018）。需要提醒的是，心理安全的主流测量是自陈量表，会被社会赞许性偏差污染——§7 已把这一条列为「被游戏的空间」判据的依据，所以它适合看趋势，不适合下断言。

#### 3.2.2 无指责复盘模式（Blameless Postmortem / Just Culture）

**被什么约束逼出来**：追责会立刻抑制信息上报，而上报是复盘唯一的原料。

**结构**：

```text
复盘产出结构（事实优先于责任）+ 免责边界
① 时间线：只写事实，包含「当时我看到什么、以为是什么」
② 系统条件：为什么这个错误在当时是「合理的」
             （信息缺口 / 权限边界 / 时间压力 / 工具误导）
③ 动作：改条件，不改人；每条动作有 Owner 与截止时间
──────────────────────────────────────────────
免责边界（Just Culture，三类必须分开）：
  无意错误     → 不追责，改条件
  风险行为     → 看是否「已知风险下的合理判断」
  鲁莽 / 故意  → 必须处理，否则 blameless 整体失效
```

**为什么这样设计有效**：因为把「人」从复盘对象中移出后，上报的边际成本下降，故障的原始事实才可能被完整写下来；而完整的事实是唯一能改进系统的输入。

**代价**：组织主动放弃「快速处理一个人」的便利——这在事故当下的观感是效率损失；同时复盘要写系统条件，比写「谁的责任」费力得多，需要有人愿意花两小时还原一条时间线。

**失效点**：当 blameless 被当成「永不追责」时，真正违规的行为也被免责，同事会据此判断「说了也没用」，复盘退化为表演；因为免责边界一旦模糊，规则的可信度比规则的严厉程度更重要。识别信号：复盘会后一周，动作清单上有几条真的关闭了。

**真实使用**：主文件 §2.1 把 Blameless Postmortem 与 Just Culture 列为概念并注明详见 §06【公开：见主文件 §2.1 与 §2.3 心理安全建设 5 步法第 2 步】；免责边界的具体画法各组织差异很大，属【经验】范围，本节不对某家公司的制度作断言。

#### 3.2.3 价值观行为化模式（Schein 三层对齐）

**被什么约束逼出来**：员工读的不是墙上的文本，而是「谁被奖励、谁被淘汰」。

**结构**：

```text
Schein 三层对齐（不一致时，底层获胜）
Layer 1 Artifacts    可见的：口号、模板、会议室、招聘 JD、晋升材料格式
Layer 2 Espoused     宣称的：价值观条目、文化手册、新人培训
Layer 3 Assumptions  真实的：谁被晋升、谁被淘汰、什么会被容忍
──────────────────────────────────────────────
逐层检查（三层两两都要对得上）：
  L2 → L3：宣称的这一条，最近一次晋升答辩里出现过吗？
  L1 → L2：可见的形式（模板 / 流程 / 会议）在奖励什么行为？
  L2 → L1：墙上这一条，有没有对应的一条可观察行为？
```

**为什么这样设计有效**：因为人从「谁被奖励」反推真实规则的速度远快于从手册里学习，所以当 L2 与 L3 断裂时，新成员会在很短时间内学会底层假设，并把那套假设当成组织的真实价值观——此时手册越漂亮，断裂被察觉时越有讽刺意味。

**代价**：把价值观逐条写成可观察行为是昂贵的手工活，写不出来就说明这条价值观还没想清楚；而一旦写成可观察行为，它就有了被拿去做考核的可能，从而产生表演（§7 的「被游戏的空间」）。

**失效点**：当「价值观进考核」跳过了行为化这一步时，考核的其实是印象分而不是行为——因为可观测的变成「别人怎么评价你」，不是「你做了什么」，此时价值观条目反而成为政治筹码。

**真实使用**：Netflix 公开的 Culture Deck（2009）把「自由」与「责任」写成成对的标准，是 L2 与 L3 对齐的公开样本【公开：Netflix 文化公开材料，2009，见 §7 候选表】；阿里把价值观（六脉神剑）放进考核排序【公开：见 §6 阿里案例与 §7 候选表】；字节的「Context, not Control」是另一条路线：它同样有成文的价值观条目（ByteStyle「字节范儿」，见 §8），但落地的主要杠杆不是逐条行为化，而是改变信息分布——用信息透明替代审批，让判断下沉到一线【公开：见 §6 字节案例（字节公开材料 2019–2024）与 §8 的 ByteStyle 条目】。

#### 3.2.4 客户反馈闭环模式

**被什么约束逼出来**：客户反馈的衰减极快，且客户通常不会重复提同一个问题——他们直接流失。

**结构**：

```text
闭环流水（§ 3 的三条做法在这里各占一环）
① 受理：反馈入口 → 去重 → 定 Owner → 24 小时内给「已收到 + 预期时点」【经验】
② 追踪看板：状态机，而不是计数板
     新 / 已确认 / 处理中 / 已交付 / 已回访 / 已拒绝（写明拒绝理由）
③ 输出：客户 NPS 报告（推荐者% − 贬损者%，客户口径）
──────────────────────────────────────────────
关键：响应 ≠ 解决。24 小时承诺的是「响应」，不是「修复」。
```

**为什么这样设计有效**：因为闭环的定义不是「我们处理了」，而是「提反馈的人知道你做了什么」，所以看板必须有「已回访」这一列、拒绝也要写理由——只有到这一步，客户 NPS 报告才有解释力；NPS 是滞后指标，单独看它无法区分「没人提反馈」和「提了没人处理」。

**代价**：24 小时响应承诺会持续产生「快速敷衍」的诱惑（先回一句「已收到」把时限做掉）；看板是要给人看的展示面，渠道每多一个就多一份维护；NPS 需要样本量与回收率支撑，小样本的波动不可解读。

**失效点**：当 24 小时响应被当成绩效指标时，可观测的变成响应时长而不是问题是否解决，于是响应质量下降、周期长但重要的反馈被跳过。判断方法：抽查被标记「已响应」的条目里，最终进入路线图的占比是多少。

**真实使用**：【经验】多数团队的做法是「单一入口 + 响应时限 + 每期回访」三件套，难点从来不在建看板，而在把「已回访」这一列真正走完；把客户 NPS 与工单状态配对分析，通常在客户成功职能独立建制之后才有条件做。本节不对具体公司的公开制度作断言——判断自家是否已在闭环上，看的是那条抽查比例。

#### 3.2.5 Ownership 与 Keeper Test 模式

**被什么约束逼出来**：一件事被交给「团队」而不是「个人」时，责任会在机制上被稀释到零。

**结构**：

```text
Owner 表 + Keeper Test
┌──────────┬────────┬────────────────┬────────────────────┐
│ 事项     │ Owner  │ 授权边界       │ 放权前提            │
├──────────┼────────┼────────────────┼────────────────────┤
│ 实时链路 │ 个人   │ 可自行改配置   │ 拿得到完整上下文    │
│ 治理口径 │ 个人   │ 需会签         │ 前提未满足 → 先补   │
└──────────┴────────┴────────────────┴────────────────────┘
Keeper Test（管理者定期自问）：
  "如果这位成员今天提出离职，我会全力挽留吗？"
  否 → 坦诚处理，而不是「再观察观察」
```

**为什么这样设计有效**：因为「共同负责」在机制上等于无人负责，所以每件事需要一个唯一责任人；而 Keeper Test 的作用是把「什么样算不合格」变成一个可以自问的问题——它同时让「坦诚分手」正当化，避免长期容纳不合适的人稀释所有人对标准的判断。§6 的 Netflix 案例把放权前提写成三问：当事人拿得到上下文吗、清楚「公司最有利」意味着什么吗、我的动作是在提供控制还是提供信任。

**代价**：Keeper Test 必然带来人员流动及其成本（招聘、交接，以及与 §7 所记「高薪酬 + 慷慨离职金」绑定的支出）；而授权本身降低了管理者的直接控制力，这在事故复盘时会被重新质疑一次。

**失效点**：当人才密度不足时，Keeper Test 的答案永远是「留」，它退化为绩效拖延，标准被持续稀释——因为「自由 + 责任」这套结构的前提是高人才密度，前提不成立时，结构只会放大偏差。

**真实使用**：Netflix 通过 Culture Deck（2009）与《No Rules Rules》（Hastings & Meyer，2020）公开了这套机制【公开：年份见 §7 候选表】；同源的还有 Patty McCord《Powerful》（2022）——她从 Netflix 人才官的视角把「坦诚、真实、追求卓越」写成可执行的做法，是这套机制在中文读者里最常见的一手入口之一【公开：见主文件 §1.1 与 §8】；§6 的 Netflix 案例记其核心为「自由与责任必须成对给出」——取消一项管控，同时给出与之对价的责任标准【公开：见 §6】。

#### 3.2.6 Bias for Action 与决策分级模式

**被什么约束逼出来**：绝大多数决策是可逆的，但审批流程对可逆与不可逆一视同仁。

**结构**：

```text
先分类，再决定要不要审批
Type 2 可逆（错了能改回来）  → 授权，快做，错了再改
Type 1 不可逆（改不回来）    → 交给有决策权的人，慢做
──────────────────────────────────────────────
判据三问：
  ① 决策错了，能在一周内改回来吗？
  ② 改回来的代价是工时，还是数据 / 声誉 / 合规？
  ③ 谁承担「误判可逆性」的责任？（必须写出名字）
```

**为什么这样设计有效**：因为可逆决策的成本随延迟近似线性上升，而不可逆决策的成本随延迟上升得更陡，所以把两类决策放进同一个审批队列，会同时造成两种损失——可逆决策白白变慢，不可逆决策在被追问时草率通过。

**代价**：分级本身要求判断，而误判的责任落在分类的人身上；把不可逆误判为可逆是最贵的一类错误，它会让人本能地想「全都上升审批」，从而退回到原状态。

**失效点**：当组织默认「一切都可逆」时，架构级决策会被草率拍板——因为可观测的是「速度」，不是「有多少决策被拦下来」。识别信号：过去半年如果没有出现过一个被拦下的不可逆决策，说明分级事实上已经不存在。

**真实使用**：Amazon 的 14 条领导力准则含 Bias for Action（主文件 §2.1 已列）【公开：见主文件 §2.1】；可逆 / 不可逆的分级（Type 1 / Type 2，单向门 / 双向门）出自 Amazon 致股东信，与领导力准则同为公开文本——年份与措辞口径见同章 [§ 7 与其他方法对比](12-culture-building-section-7-sec7.md) 的 7.2 候选表（准则与致股东信公开：2004 / 2015 / 2016）与 7.3.3（该处记为 Amazon 2015 年致股东信）【公开：可自行核验 Amazon 投资者关系页上的历年致股东信原文，本处不另作年份断言】。

#### 3.2.7 文化衡量模式（文化指标 / Engagement）

**被什么约束逼出来**：文化不可直接观测，只能度量代理指标；而一旦用于考核，代理指标就会被管理。

**结构**：

```text
文化指标（诊断用，成组出现）
┌──────────────┬───────────────────────────────┬──────────────────┐
│ 指标         │ 口径                          │ 用途             │
├──────────────┼───────────────────────────────┼──────────────────┤
│ eNPS（员工） │ 推荐者% − 贬损者%（0–10 分）   │ 同组织纵向比趋势 │
│ 回收率       │ 应答人数 / 团队总人数          │ 低于阈值即弃用   │
│ 行为指标     │ 反馈频次 / 跨团队协作次数       │ 诊断             │
│ 业务指标     │ 留存 / 交付 / 决策周期          │ 诊断             │
└──────────────┴───────────────────────────────┴──────────────────┘
注意：eNPS（员工口径）与客户 NPS（3.2.4）是两个不同的东西，不可混用
```

**为什么这样设计有效**：因为自陈量表受社会赞许性偏差影响，且分数一旦与管理者利益挂钩，何时发、发给谁就会被管理（只发给愿意答的人、把调研推迟到风波之后），所以必须成组读——eNPS 配回收率、行为指标配业务指标；单个分数不构成信息。

**代价**：调研成本，以及「问了就要有动作」的义务；一次没有后续的调研会让下一次回收率下降，这笔信任支出与 3.2.4 的客户反馈是同一条机制——问而不动，下次就没人答。

**失效点**：当文化指标进入个人考核时，它从测量工具变成政治工具，数值可被管理而信息量为零，因为可观测的是「谁答了、什么时候答的」，不是「人怎么想」；§7 把这条单列为判据「被游戏的空间」。

**真实使用**：主文件 §2.3 已给出四类文化指标（敬业度 / 满意度 / 行为 / 业务），其第 7 条（AI 辅助文化评估，2024+）列的方向是「LLM 分析 Slack / 邮件 / 会议记录」「AI 评估心理安全、Trust、Ownership」「AI 识别文化风险」【公开：见主文件 §2.3】；[§ 5 前沿演进](12-culture-building-section-5-ai.md) 的 5.1 把「AI 辅助文化评估」（LLM 分析聊天 / 会议 / 调研文本；含敬业度调研平台）评为 L2，并注明「用 LLM 评估心理安全」未核到公开评测与第三方生产案例（见 §5.1 的演进方向表）。这是**方向判断，不是已验证的工具清单**；至于具体的敬业度调研 SaaS（Culture Amp、Glint、Officevibe 一类），本节不对厂商归属、并购年份与产品现状作断言——商用工具的更名与并购变动快，读者应直接核验厂商官网，不要以本节或任何二手清单为准【经验】。

#### 3.2.8 AI 治理文化模式（2024+）

**被什么约束逼出来**：AI 让决策被批量自动化，而合规要求「可举证」。

**结构**：

```text
AI 治理的三层（每一层都要挂在机制上，缺一层就退化成文档）
① 可解释：每个自动化决策能说清用了哪些输入与哪条规则
② 可追责：每个模型 / 规则有 Owner 与变更记录（ADR 式留痕）
③ 可申诉：被决策影响到的人有一条人力通道，且申诉会被回访
──────────────────────────────────────────────
检验：把「谁会因为这条要求被叫去解释」写出名字；
      写不出名字，说明它还没成为文化。
```

**为什么这样设计有效**：因为文化只能通过后果传导，所以 AI 治理若不挂在审计与问责上，它就只是一份文档；只有当「被叫去解释」真实发生过一次，团队才会在建模阶段就考虑合规，而不是在上线前补一份说明。

**代价**：留痕与审计增加流程成本，试新模型与快速迭代的速度下降——这是确定的当期成本，收益要等到第一次监管检查或客户审计时才兑现，因此它在资源紧张时最先被砍。

**失效点**：当治理被做成一次性合规检查（上线前过一遍、之后不复核）时，模型一迭代治理即失效——因为可观测的是「有没有做过检查」，不是「当前版本是否仍然可解释」。

**真实使用**：主文件 §1.2 的「AI 时代的新诉求」把 AI 治理列为文化核心，§2.1 给出的措辞是「AI 治理文化：合规、伦理、隐私」【公开：见主文件 §1.2、§2.1】；[§ 5 前沿演进](12-culture-building-section-5-ai.md) 的 5.1 则把这一方向记为「可解释 / 可追责 / 可申诉；含 Bias 防范与 Transparency」（见 §5.1 的演进方向表）；各公司的治理组织形态差异很大，本节只给出可自行核验的三层结构，属【经验】表述，不对具体公司作断言。

### 3.3 模式选择决策表

| 约束组合 | 推荐模式 | 为什么不选另一个 | 关键判据 |
| --- | --- | --- | --- |
| 坏消息上不来、会上没人反对 | 心理安全 + 无指责复盘 | 不先上度量：分数治不了不敢说话 | 最近一次反对意见之后，事情是否真的变了 |
| 价值观只写在手册与培训里 | 行为化（L2 → L3 对齐） | 不先上考核：行为没写清就考核，等于评印象分 | 最近一次晋升答辩里出现过哪条价值观 |
| 客户反馈散落在多个渠道 | 反馈闭环（单入口 + 状态机看板） | 不先做客户 NPS：没有闭环时它无法解释 | 「已响应」条目中进路线图的比例 |
| 有人长期不达标但没人处理 | Owner 表 + Keeper Test | 不做全员满意度调研：它不解决个体标准问题 | 最近一次坦诚分手发生在什么时候 |
| 决策慢、审批多但事故不多 | Bias for Action 分级 | 不一刀切取消审批：不可逆决策需要拦 | 近半年被拦下的不可逆决策数 |
| 文化要往上汇报或对外展示 | 指标成组（eNPS + 回收率 + 行为） | 不用单点分数：单指标一定会被管理 | 指标是否已进入个人考核 |
| 强监管 / 有对外举证责任 | AI 治理三层 + 审计留痕 | 不照搬「无审批式自由」：合规是硬约束 | 能否说出「谁会被叫去解释」 |
| 快速扩张、新人占比高 | 招聘门槛 + 行为化准则 | 不加流程：流程挡不住价值观稀释 | 新人三个月内学到的是哪套规则 |

表中最常被误选的一对是「用文化调研解决行为问题」与「先行为化、再谈度量」。误选的后果不是白花钱，而是**方法论被证伪**：分数出来了，但没人知道要改什么——因为分数指向的是感受而不是行为；下一期分数继续波动，团队得出「调研没用」的结论，此后连真正的诊断需求也无法被满足。修法很便宜——先把「最近一次晋升或淘汰中出现过的价值观条目」当作先行指标，行为化做完再上度量。

### 3.4 组合模式：真实系统不会只用一种

**组合 A：信息流组合——心理安全 + 无指责复盘 + 客户反馈闭环**（10–50 人【经验】、故障或客诉高频）

- 构成与职责边界：心理安全管「敢说」，无指责复盘管「说了之后的处置」，客户反馈闭环管「组织外的信号能不能进来」。三者都作用于信息流，不作用于激励。
- 运维代价：复盘要有人花时间还原时间线；反馈闭环要有人维护看板状态；两项都属长期固定投入，不能停。
- 适合规模：事故或客诉已经能直接影响客户时。

**组合 B：激励耦合组合——行为化准则 + 招聘与晋升门槛 + 文化衡量**（50 人以上【经验】、扩张期）

- 构成与职责边界：行为化准则定义「什么叫做到了」，招聘与晋升门槛决定「谁留下」，文化衡量只做诊断、不进个人考核。
- 运维代价：准则的行为化是一次性大手工作，之后每季度要在晋升案例里复用；文化调研有回收率与「问了要有动作」两笔持续成本。
- 适合规模：新人带来的旧习惯开始明显冲淡原准则时。

**组合 C：速度与约束组合——Bias for Action 分级 + AI 治理三层**（AI 产品团队、强监管场景）

- 构成与职责边界：决策分级负责把可逆决策放开，治理三层负责把不可逆、需举证的部分收紧；两者边界必须写清，否则团队两头都慢。
- 运维代价：分级需要有人承担误判责任；治理需要留痕与审计，迭代速度下降是确定成本。
- 适合规模：模型迭代频繁、且对外有合规举证责任时。

### 3.5 反模式与失效分析

| 反模式 | 症状（怎么发现它） | 后果（机制层面） | 成因（为什么团队会写成这样） | 修法 |
| --- | --- | --- | --- | --- |
| 贴在墙上的口号 | 手册很漂亮，但没人引用它做决定 | L2 与 L3 断裂，新人很快学会「真实规则」 | 写文本比改激励便宜得多 | 逐条写成可观察行为，并让它在晋升里出现 |
| 说一套做一套（高管不示范） | 规则对下不对上，管理层例外 | 一次例外被观测到，全部规则的可信度归零 | 管理者的时间稀缺、示范的成本即时 | 让管理层先在自己的复盘里做示范 |
| 心理安全缺失 | 会上无人反对，会后私下意见一堆 | 坏消息上行受阻，纠错开关关闭 | 提反对的即时成本高、收益延迟 | 先建立「提了之后有动作」的记录 |
| Ownership 缺失（推诿甩锅） | 每件事都是「我们共同负责」 | 责任真空，事故无人闭环 | 共同负责在协作语境下显得安全 | 每件事写出唯一的责任人 |
| Customer Focus 缺失 | 路线图由技术驱动，客户问题排在后面 | 投入与客户价值脱钩，反馈闭环空转 | 技术收益看得见，客户收益要等 | 把反馈闭环接进路线图决策，而不是接进报表 |
| Blameless 变成不追责 | 复盘有输出、动作从不关闭，违规者仍在其位 | 复盘变表演，信息上报再次关闭 | 把免责边界误当成全部免责 | 明确区分无意错误 / 风险行为 / 鲁莽 |
| 把文化当模块移植 | 抄来「自由」，没抄激励与人才密度前提 | 得到无约束的混乱，结论被错误总结为「给自由不行」 | 文本可复制，激励结构不可复制 | 先检查三前提：人才密度、薪酬水平、离职成本 |
| 文化分进考核 | 分数按季度变好看，问题却在积累 | 指标被管理，测量失效 | 考核需要一个可比的数 | 文化指标只做诊断，不进个人考核 |
| 客户反馈 24 小时响应变成绩效指标 | 响应时长漂亮，问题积压变多 | 可观测的变成时长不是解决，长周期问题被跳过 | 时限是最容易度量的那一项 | 抽查「已响应」条目进入路线图的比例 |
| 政治化文化 | 反馈被读成「站队」，会上没人说真话、会后拉小群 | 说真话的成本重新上升，纠错开关被关掉 | 评价缺少可观察的行为口径，只能比人际与资历 | 把评价锚到可观察行为与结果上，并公开评价口径 |
| 文化僵化 | 价值观多年不动，新业务因「不符合价值观」被砍 | 文化从约束变成筛选器，组织失去适应性 | 成文条目带来「终于定下来了」的确定感 | 每 2–3 年 Review 一次价值观：保留核心、调整细节【经验：区间见 §8】 |
| 文化与业务脱节 | 文化单独立项，与经营目标各说各话 | 文化投入不落到分配链上，资源一紧就最先被砍 | 文化工作由 HR 独立立项，不与业务节奏挂钩 | 让每条文化条目对应本期的业务约束与一个分配动作 |

**「贴在墙上的口号」在生产里长什么样**：它通常不表现为管理层不信，而表现为所有决定都在别处做。开会时没人提价值观，晋升讨论时说「他业务做得好」——价值观条目一次都没出现。真正的伤害发生在新人身上：三个月后他会总结出这套组织实际奖励什么，而那套总结与手册无关。

**「Blameless 变成不追责」在生产里长什么样**：复盘会开得很好，时间线也还原了，但动作清单半年后仍然开着；某个反复造成事故的人没有任何变化。此时团队学到的是「复盘是仪式」，下一次事故的第一反应是先在群里解释一下自己不在场——信息流从此反向。

**「把文化当模块移植」在生产里长什么样**：最常见的形态是先取消审批（报销、休假、上线），再补标准；补不上标准时，问题会被总结成「我们的人不行」，于是又加回审批。此时唯一的补救是回到机制：先确认三条前提是否成立——人才密度、是否有与之匹配的薪酬、离职成本是否足以支撑坦诚分手；任一不成立，自由就是错的选择。

### 3.6 规模跃迁时模式何时该换

| 跃迁 | 原模式 | 为什么开始疼 | 换成 | 迁移的代价 |
| --- | --- | --- | --- | --- |
| 约 10 人以内 → 20–50 人【经验】 | 靠创始人示范 | 示范的带宽是有限的，创始人不再能被每个人观测到 | 行为化准则（把示范写成条文） | 条文会损失示范的即时说服力 |
| 20–50 人 → 50–200 人【经验】 | 口头共识 | 新人的稀释速度超过口头传递速度 | 招聘门槛 + Keeper Test | 招聘周期变长、淘汰率上升 |
| 50–200 人 → 200 人以上【经验】 | 全员宣讲 | 宣讲覆盖不到日常决策现场 | 文化衡量 + 管理者逐层示范 | 调研与培训的持续成本 |
| 单一产品 → 多 BU | 统一文化 | 各 BU 的激励结构与毛利不同 | 共同底线 + 子文化 | 需要重新定义「哪些条目不允许本地化」 |
| 人工把关 → AI 治理（2024+） | 靠人评估与签字 | 决策被批量自动化，人已无法逐条复核 | 可解释 + 可追责 + 可申诉三层 | 迭代速度下降，需长期留痕 |

上表的人数跨度是【经验】档位的粗粒度代理，不是刻度——真正触发切换的是**约束是否已变**（示范还能不能被观测到、口头传递是否还跟得上新人进入速度、宣讲能否到达决策现场），人数只是这三条约束变化的代理指标。50 人与 200 人两个节点的推导见 [§ 7 与其他方法对比](12-culture-building-section-7-sec7.md) 的 7.5：前者按每周可投入 3–5 场面试与评价、年增长 30%–50% 估算创始人的覆盖上限，后者按管理跨度 8–10 人、组织深度 2–3 层估算示范的到达率衰减点【推算 + 经验，推导见 §7.5】。

### 3.7 自检清单

- [ ] 最近一次有人公开提出反对意见之后，相关的事情真的改变了吗？
- [ ] 最近一次复盘的动作清单里，有几条已经关闭？有没有超过一个季度仍开着的？
- [ ] 最近一次晋升讨论中，价值观条目出现过几次？一次都没出现，说明 L2 与 L3 已断裂。
- [ ] 组织里有没有「共同负责」的事项？有，就说明它现在无人负责。
- [ ] 客户反馈看板里是否有「已回访」这一列？没有，就还不是闭环。
- [ ] 被标记「已响应」的客户反馈中，进入路线图的比例是多少？
- [ ] 最近一次尴尬的人员决定（坦诚分手）发生在什么时候？如果答不出来，Keeper Test 可能已经停用。
- [ ] 过去半年有没有一个不可逆决策被明确拦下来过？
- [ ] eNPS 与客户 NPS 是否被混用在同一个汇报口径里？
- [ ] 文化指标是否进入了任何人的个人考核？（进入即失去诊断价值）
- [ ] 如果有人问「AI 治理要求违规时谁会来解释」，你能说出名字吗？
- [ ] 你正在推行的准则里，有哪一条是「不可观测、只能宣称」的？把它改成一条可观察行为。

### 3.8 小结

| 你的约束 | 建议模式 | 关键理由（机制层面） |
| --- | --- | --- |
| 坏消息上不来 | 心理安全 + 无指责复盘 | 纠错速度上限由坏消息上行速度决定 |
| 价值观停在手册里 | 行为化（L2 → L3） | 员工从「谁被奖励」反推规则，不从文本学习 |
| 客户反馈散落 | 反馈闭环（单入口 + 状态机） | 闭环的定义是「提交者知道发生了什么」，不是「我们处理了」 |
| 责任被稀释 | Owner 表 + Keeper Test | 共同负责在机制上等于无人负责 |
| 决策慢、审批多 | Bias for Action 分级 | 可逆与不可逆的成本函数不同，不能共用一个队列 |
| 文化要被汇报 | 指标成组、远离考核 | 进了考核的指标会被管理，数值不再携带信息 |
| 强监管 / 要举证 | AI 治理三层 + 留痕 | 不挂在问责上的治理只是文档 |

> 本节小结：文化建设的八个模式，**决定选哪一个的唯一约束是「你打算把价值观挂在激励的哪一环」**——挂招聘与淘汰（Netflix 式）、挂评价与排序（阿里、Amazon 式）、还是只度量不挂（Google 式），决定了改得多快、被表演得多厉害。而在此之前的那个开关是信息流：**坏消息上不来时，模式选得再对也无法被修正**——3.2.1 与 3.2.2 之所以排在模式清单最前面，不是它们更高级，而是其余六个模式全都建立在「第一手事实能被说出来」之上。
>
> 💡 **思考锚点**：先按 3.6 判断你落在哪个跃迁节点上：示范覆盖上限（每周 3-5 场面试、年增长 30%-50%）与示范到达率的衰减点（管理跨度 8-10 人、组织深度 2-3 层）分别对应约 50 人、约 200 人——你的模式是还没到就该换，还是已经过了却还靠口头共识？再翻一遍你的准则，找出那条「不可观测、只能宣称」的，它就是信息流这道开关还没打开的证据（3.8）。
