## 4. 工程实现

§3 回答的是「有哪几种机制、各自被什么约束逼出来、代价与失效点是什么」。本节不再选型，只回答另一件事：**你已经知道要选哪一个之后，怎么把它装进一个正在运行的组织**——先做哪一步、每一步手上该多出什么、怎么在自己家里验证这一步做对了、既有的人与流程怎么办。

绩效体系几乎没有「从零搭建」的场景：所有组织都已经有一版在跑的评估，员工也已经围绕它形成了行为习惯。所以本文件默认面向**存量改造**：Step 0—5 是按顺序改造一条既有体系的路径，§4.4 单列双轨与历史资产处理。若你确实在一个还没有任何绩效流程的组织里从零开始，顺序不变，可以跳过 Step 0（没有存量耦合关系要拆）。

### 4.1 落地步骤

**Step 0：钉住「评级与回报的耦合关系」（1–2 周【经验】；随组织规模与层级数变——到主管能直接观察到全部下属的组织取下限，多一层中间管理就多一轮口径解释）**

- 逐个团队收集现行目标清单，对每一项标注「换 / 不换」回报；把处于模糊地带的（「作为参考」「影响晋升但不决定」）单独列出来——**模糊地带是后面所有争议的来源**。
- 写下三个动作各自的用途：校准会输出的是「尺子」还是「人数」；360 的输出进「发展」还是进「评级」；盘点结论进「投入决策」还是进「档位」。
- 结论由高管与 HRBP 双签（沿用组织既有的签署方），并对全员公开这份表。

- **产物**：一页《耦合关系表》——目标类别 → 换不换回报 → 由谁判定 → 模糊地带如何处理。
- **判据**：随机抽 3 个团队的负责人，问同一个问题「你们这条 KR 完成 0.7 会不会影响你的评级」，三人的回答必须与表一致；只要出现第二种说法，这一步就没做完。
- **为什么必须这一步、且必须排在最前**：因为耦合强度决定同一条机制是改进工具还是博弈对象（机制分析见 §3.1）。先改机制、后改耦合，等于要求员工在旧激励结构下执行新流程——他们会用新流程去服务旧目标，返工的不是流程，是整套目标文书。

**Step 1：选择绩效模式（1–2 周【经验】；随候选模式数与是否有专职 HRBP 变——没有专职 HRBP 的组织，约束盘点本身要占掉大半工期）**

- 用 [§3.3 模式选择决策表](03-performance-management-section-3-sec3.md) 按**约束组合**选，而不是按行业惯例选（团队规模 / 业务性质 / 文化成熟度这三项常被当成选型依据，但它们是约束的**代理变量**：同规模、同行业的两个团队，可以因为「管理者可用工时」不同而选相反的模式——真正要对得上的是 §3.1 约束表里的那几行）；每一个选择都写出「为什么不选另一个」。
- 选定后立即写下一句话判据（例：「评优比例是否已明显超出预设档位」「反馈周期是否短于业务显著变化间隔」），作为此后每个季度的复查项。
- 高管 + HRBP 就选型达成一致，留书面记录。

- **产物**：《模式选择记录》——约束 → 选中的模式 → 被否决的备选 → 否决理由 → 复查判据。
- **判据**：抽其中任意一条约束向 HRBP 复述，获得的答案与记录一致；记录里若出现「我们两者都要」而没有写清分工，视为未完成。
- **为什么必须在 Step 0 之后**：模式选择依赖耦合关系。耦合未定就选模式，最典型的产物是「与评级挂钩的 OKR」这种自相矛盾的组合；等年底发现 OKR 等于考核时，重选模式的代价是两个完整评估周期。

**Step 2：设计目标体系（2–4 周【经验】；随团队数与跨团队依赖数变——依赖清单长起来之后，对齐会是按依赖簇而不是按团队逐个开的）**

- 准备三层模板：公司级、团队级、个人级；KPI 与 OKR 分成两张清单，各自独立纠偏（KPI 走口径审计，OKR 走向上对齐）。
- 组织一次跨团队对齐会，产出**依赖清单**：谁的 KR 依赖谁的产出，避免两个团队重复造同一个轮子。
- 定下季度 Review 机制与检查点（例：双月检查点 + 季度总结），并把「目标与结果是否公开」作为一个显式选项写进制度。

- **产物**：目标清单（每项带复算口径）+ 跨团队依赖清单 + Review 日历。
- **判据**：抽 3 条 KR，交给不参与该项目的同事，请他们在同一数据源上独立复算一遍，结果一致才算可复算；另查团队目标里是否至少有一项**能力跃迁项**，且它不是「参加某培训」这类不可验证的表述。
- **为什么必须这一步**：评估体系需要「依据」才能评。没有可复算的 KR，校准会与 360 评的都是印象，而印象无法被举证，也就无法被申诉。

**Step 3：建立评估体系（2–4 周【经验】；随参评人数与是否已有工具承载变——没有承载工具时，盘点表收集与合并本身就是工期大头）**

- 360 度评估：自评 + 上级 + 平级 + 下级 + 跨部门；用途**写死**为「发展」或「评级」之一。
- 9 宫格：绩效（过去 6–12 个月【经验，随业务节奏变】的可复核证据）× 潜力（到更高层级的成长空间），两维分开评、不允许加权合并。
- 跨级评委 / 校准会：同层级管理者同时到场，先独立初评，再横向对比，最后形成组织一致的分布与标准。

- **产物**：证据标准文档（可复核 / 可指认 / 带边界）+ 校准会议程 + 9 宫格盘点表。
- **判据**：调出上一轮盘点记录，抽 3 个人的潜力评分，看它后面是否附有可复核的行为证据——只有结论没有证据，说明这一维在校准之外；再翻校准会纪要，出现「这组必须有 N 个 A」即为配额分配。
- **为什么必须在目标体系之后、反馈机制之前**：证据标准由目标定义，没有目标就无从谈起评什么；它又必须早于面谈，否则面谈只能输出「感觉」，员工无法从结论走到改进。

**Step 4：建立反馈机制（持续）**

- 季度 1-on-1（按管理者带宽可设为双周或月度）+ Real-Time Feedback（Slack / Teams 等日常渠道）。
- 绩效面谈：每年 1–2 次正式面谈【经验，随评估周期数与管理者带宽变】 + 持续对话，面谈走「准备 → 开场 → 自评 → 反馈 → 共建改进」五步。
- 把上一次对话的结论写进同一条记录，作为下一次的起点，并把结论接进 IDP。

- **产物**：每位下属一条可回溯的对话记录（含结论、证据与下一步）。
- **判据**：抽 3 名员工问「你能说出为什么是这个结果吗」，答不出即反馈未到达；再看面谈覆盖率，以及每次面谈是否带行为 + 数据 + 例子。
- **为什么必须在激励兑现之前**：面谈结论是兑现的说明来源。先兑现、后沟通，员工会把结果解释成「分配不公」，而不是「一次被解释过的判断」——**同一笔钱，说的顺序不同，留下的东西不同**。

**Step 5：设计激励组合（2–4 周【经验】；随承诺类型数与所在法域的合规成本变——涉及期权与跨境团队的组合，法务核验会显著拉长）**

- 物质层：Base / Bonus / RSU 与福利；精神层：Title / 晋升 / 认可 / Conference 演讲机会；内在层：自主、专精、目的。
- 末位处置：PIP + 转岗 + 淘汰；PIP 的判据、周期（30–90 天，口径见主文件 §2.3【经验】）、资源与申诉路径在开始前写死。
- 建一本**兑现台账**：每条承诺 → 承诺人 → 到期日 → 状态（已兑现 / 已书面说明），按季度对账。

- **产物**：员工可读的激励组合说明 + 兑现台账 + PIP 模板与申诉路径。
- **判据**：抽上一周期 3 条承诺的激励，逐条查台账状态；只要有一条既不兑现也没有书面说明，这一层的兑现信用已经在折价。再抽 2 份 PIP，看判据是否在开始前就已写明。
- **为什么放在最后**：兑现是前四步的信用结算。承诺在前、体系在后，会把激励变成无依据的分配；而兑现信用一旦破裂，方向不可逆（§3.2.7）。

最常被跳过的是 **Step 0 与 Step 4**。跳过 Step 0 的症状不会立刻出现：第一年通常只是「目标写得更务实」，直到第一次调薪包分完、员工发现 OKR 完成度没进公式（或意外进了公式），此后一整年没人再定需要踮脚的目标——**滞后一个完整评估周期才暴露**。跳过 Step 4 的症状出现在第一次给出低评的那一天：员工是第一次听到这个结论，于是争议从能力问题转成人身问题，而返工只能从下一次面谈才开始。

### 4.2 关键技术点

**耦合关系表（把隐性规则写成可检查的对象）**

- **做法**：对每一类目标标注是否换回报，对校准会 / 360 / 盘点三类动作标注用途，模糊地带单列并指定裁定人。
- **机制**：因为被直接考核的目标必然被定到「必然能达成」的水平，所以「哪些目标换钱」决定了目标是拉升工具还是避险工具；写在纸上，这个激励结构才成为可检查的对象。
- **失效条件**：**当组织大到主管无法直接观察全部下属（【经验】直接下属超过十余人）时，这张表会退化成口号**，因为中间层会各自解释「参考」的含义。症状：同一批 KR 在不同团队里的评级权重不同，且没人说得清差别从哪来。
- **档位**：结构性判断，无数字。

**可复算的 KR**

- **做法**：每条 KR 写明数据源、口径与时间窗；验收前由不参与该项目的人独立复算一遍。
- **机制**：因为复算不需要理解项目上下文，所以它是唯一一种「不必管理者在场也能判定」的验收方式，把一部分判定成本从管理者工时里挪走。
- **失效条件**：**当 KR 退化成「访谈 N 个用户」「输出 M 篇文档」这类计数表达时，复算仍然可行，但指标已被换成最容易留痕的那一维**。症状：KR 全部达标而业务目标未达成，且没人能指出错在哪一条。
- **档位**：结构性判断，无数字。

**校准会（输出尺子，不输出人数）**

- **做法**：同层级管理者同时到场，先独立初评再横向对比，偏离整体分布者举证；纪要只输出尺度与依据。
- **机制**：因为两个团队的「4 分」本来含义不同，跨团队可比只能靠先对齐尺子；**对齐的是尺子，不是把人拉到某个比例**。
- **失效条件**：**当校准结论被写成「这组必须有 2 个 A」时，它反转成配额分配**。症状：校准后各经理的名单分布高度雷同，而真实产出差异仍在。它的成本随「同层级管理者数 × 参评人数」增长且不可并行——参会者要同时到场，会议长度由**参评人数**决定，出席工时则由**管理者数 × 轮次**决定，两个因子各进一处。【推算：参评人数 = 20 名同层级管理者 × 每名管理者名下 8 人 = 160 人；按每名被评人约 1 分钟的上会口径【经验】 → 每轮会议约 160 分钟 ≈ 2.7 小时，取 3 小时；20 名管理者同时到场 × 3 小时 × 每年 2 轮 = 120 人时；按每年约 1700 人时折算 ≈ 0.07 人年；"20 名""8 人/管理者""1 分钟/人""3 小时""2 轮""1700 人时"六项输入均按【经验】取值，只用于量级判断】。
- **档位**：【推算】（见推导链）+【经验】（工期与规模阈值）。

**9 宫格（两维分开，禁止加权）**

- **做法**：绩效维用过去 6–12 个月【经验，随业务节奏变】的可复核证据；潜力维写明证据要求（学习速度、复杂度承载力、带人效果）；两维独立评、独立记录。
- **机制**：因为盘点表与校准议程里，绩效与潜力是**两个独立字段、两轮独立采集**（先各自书面填，再上会），所以议程上根本不存在「合并成一个总分」这一步。阻断这个推理的是流程节点而不是原则——会议材料里没有那个可相加的空格，就没有人能临场加出来。
- **失效条件**：**当潜力列被下游流程直接消费（进入保留名单、继任序列或调薪包的输入）时，这一维就从「盘点表的一栏」溢出成一个决策字段**，此后它被填写的完整度取决于下游要什么，而不是证据有多少。症状：连续两轮盘点的潜力名单几乎不变，有人说不出「去年被列为高潜的人做成了什么」。第一个暴露点是**下一轮盘点的会前材料**——潜力栏的档位已经填好、证据栏还空着，而这个空栏在会前就看得见，不必等结果出来。
- **档位**：结构性判断，无数字。

**持续反馈与面谈的成本上限**

- **做法**：把一次大评估拆成多次小对话，把单次成本压到管理者可接受的水平；用同一条记录串起上下文；面谈结论接 IDP。
- **机制**：因为一次 1:1 的成本拆开是「准备 + 对话 + 写进同一条记录」，而**只有对话本身随频率线性增长，准备应当被上一次的结论覆盖**，所以「记录是否可回溯」直接决定第二次对话的边际成本。把第二次的准备工作压到读上一次的记录，高频才在工时上成立。
- **失效条件**：**当一名管理者的直接下属数或协作面数使其单周可用于面谈的工时为负时（【经验】直接下属超过十余人、或同时带两个以上跨时区团队），高频反馈反转成走过场**，且比低频深度对话更差。症状按暴露顺序出现：先是 1:1 被临时取消且不补，再是同一条记录里连续三个周期出现同一批话题，最后是面谈变成「先说结论、员工点头」。**三个症状都在 1:1 记录里先看得见**，评估结果只是滞后确认。
- **档位**：【经验】（频率与工时）。

**激励兑现台账**

- **做法**：每条承诺登记承诺人、到期日与状态；到期未兑现时当面说明为什么变，并把说明也记进台账。
- **机制**：因为台账把每条承诺压成「承诺人 + 到期日 + 状态」三个字段，所以一条承诺在**到期日之前**就能被系统发现，不必等员工提出异议；兑现的关键不是给得多，而是「说到做到」这件事有了一个可对账的对象。
- **失效条件**：**当同一考核周期内跨部门的承诺条目多到一个人记不住（【经验】十余条以上），且台账没有自动到期提醒时，漏兑现先落在「不在主管日常视野里」的那一类承诺上**（转岗、Conference 机会、跨部门资源），而不是落在加薪这类天天被提起的承诺上。症状：员工对晋升与调薪的预期与台账长期不一致，却没人提出异议——他们只是不再为评估投入注意力。第一个暴露点是**季度对账**：表上「待补说明」一栏空着，而员工访谈里冒出台账上不存在的承诺。
- **档位**：结构性判断，无数字。

**AI 辅助绩效（三个角色必须彼此独立）**

- **做法**：把流程切成三段——写证据（可自动化：LLM 汇总代码、工单、文档，形成时间线与事实缺口清单）、定级（不可自动化）、受理申诉（不可自动化，且由不参与初评的角色处理）；产出只进「证据」，不进「档位」。
- **机制**：因为三个角色被切成三个**流程位**（写证据的自动化管道、定级的责任人、受理申诉的独立角色），所以自动化只能落在第一段：它把「把散落的记录拼成时间线」这段成本压下来。定级与申诉这两段的成本挂在责任上，不随模型能力下降——这就是「三个角色必须彼此独立」在实现层的含义：独立性是可检查的岗位与权限设置。
- **失效条件**：**当证据管道先于校准机制与证据标准上线时，它反转成把已有噪声规模化并贴上「客观」标签**——被放大的不是准确度，是可记录性。症状：每条评分看起来都有数据支撑，而不留痕的贡献（避免了一次事故、替同事补位）仍被系统性低估。第一个暴露点是**校准会记录**：管理者举证时引用的是 AI 生成的时间线而不是自己观察到的行为；一旦两条时间线冲突，会上的裁定依据会变成「谁的材料更完整」。当自动化输出会影响雇佣决策时，它还落入偏见审计、日志留存与人工监督等要求——适用范围请以当地监管文本的当前版本为准。
- **档位**：结构性判断，无数字。

### 4.3 工具链与平台

绩效工具链有个反直觉之处：**成本的大头不在软件上，在管理者工时上**。所以选型的第一判据不是功能清单，而是「这个工具把哪一段工时搬走了」。

| 类别 | 候选 | 选型判据（在什么约束下选哪个） | 不选它的代价 |
| --- | --- | --- | --- |
| **目标与 OKR 载体** | 文档 / 表格；协作平台（Slack / Teams / 飞书 / Notion / Confluence 一类）；专用 OKR 工具 | 目标是「公开」还是「层级对齐」决定选型：只求公开，协作平台足够；要层级对齐与进度汇总，才值得上专用工具 | 专用工具前一两年通常只增加填表动作【经验，随组织层级数与目标条数变】；用文档代替则汇总靠人工，目标飘移不可见 |
| **持续反馈与 1:1 记录** | 日常沟通渠道（Slack / Teams）；文档型 1:1 记录；HR 系统内的反馈模块 | 判据是「记录是否可回溯」，不是「是否即时」 | 不留记录的后果不是丢信息，是每次面谈都在重复同一批话题 |
| **证据来源系统** | 代码仓库（Git 平台）、工单系统、文档 / Wiki | 判据是有没有「按人 / 按项目」聚合的能力；没有就只能人工汇总 | 人工汇总永远滞后，覆盖度取决于谁记得提交 |
| **校准与盘点** | 9 宫格表格；HR 系统内的人才盘点模块 | 判据是「能否保留历史轮次数据」：只看当轮，潜力的准确率永远无法验证 | 潜力的误差不会被发现，只会被继承 |
| **兑现与激励台账** | 薪酬 / 期权管理系统；自建台账（表格） | 判据是「到期提醒是否自动」：承诺量大且跨部门时，靠人记一定会漏 | 漏兑现一次，后续所有激励的折扣率上升，且不可逆 |
| **AI 辅助绩效** | 具备「汇总工作记录、生成评语草稿」能力的工具 | 判据只有一条：输出是否只进「证据」不进「档位」，三个角色是否彼此独立 | 把定级交给模型，等于把个人偏见换成不可解释的系统性偏差，并触发合规要求 |
| **调研与申诉通道** | 员工调研平台；HR 系统内的申诉流程 | 判据是「申诉是否由不参与初评的人受理」 | 由初评人受理，等于没有通道，且会加速信任流失 |

这一类里最容易被误选的是**专用 OKR 工具**。团队通常在「想让目标透明」的动机下采购它，但它真正解决的是「层级对齐与进度汇总」，而透明靠公示一张表就能做到。误选的后果不止是每年多出几轮填表：**当 OKR 与评级悄然接上之后，工具会把这种耦合自动算成一个完成度数字，使耦合变得更难被察觉**。先有决策机制，再选承载工具；反过来做，返工成本落在员工的行为习惯上，而习惯比流程更难改。

### 4.4 存量迁移

改造一套已经在跑的绩效体系，与新建的差别在于：**存量里已经有人围绕旧规则做了决定，而这些决定不能撤回**。所以迁移的第一原则是——**只改规则，不追溯结论**。

**① 立刻见效、且能立刻回退的动作**

- 把 OKR 完成度从评级公式里摘出去（或反过来，明确写进公式）。可回退性来自它是**一处公式**，改回去的成本接近零。
- 把「面谈覆盖率」纳入管理者自身的评估项。
- 给每一个低评附加举证要求：没有具体事例的低评不予通过。
- 收回面向个人的例外通道（临时豁免评审、临时跳过校准这类），把豁免权收到一个明确的主体。

这四条共用同一个判据：**改的是流程参数，不是人的历史结论**。因此它们可以在一个季度内上线，也可以在发现问题时一周量级内撤回【经验，随组织规模与是否需改制度文本变】。

**② 历史资产怎么分类处理**

| 历史资产 | 处理方式 | 为什么这样处理 |
| --- | --- | --- |
| 已发出的评级与已分完的奖金 | **打标挂账，不追溯重算** | 追溯会把「规则变了」变成「你去年被高估了」，代价是团队内部的互信 |
| 已承诺但未到期的激励 | 全部登记进兑现台账，到期必兑现或当面说明 | 兑现信用是唯一一项「一次破裂不可逆」的资产 |
| 正在进行的 PIP | 按新判据重签一份，周期从重签日起算 | 判据在过程中被追加，会让整个 PIP 失去正当性 |
| 历史盘点中的潜力评分 | 标记为「无证据」，下一次盘点重新采集证据 | 潜力维的误差不会自己暴露，只能靠重新取证 |
| 仍在沿用的旧目标文书 | 保留到本周期结束，之后不再新建 | 中途换文书，会让员工已经做出的承诺失去对象 |

分类原则只有一句：**能用新规则的用它，不能用的打标挂账——但不要把它悄悄删掉**。挂账项必须在下一轮盘点时被显式处理，否则它会变成没人认领的历史。

**③ 双轨怎么维持、维持多久**

新旧并行是常态，脆弱的不是「并行」本身，而是**并行期的身份不清**：谁适用哪一套、什么时候切换。

- 维护一张名单：每个团队标注「当前适用新规 / 旧规」，切换日期写死。
- 并行期禁止交叉引用：新 OKR 不进旧评级公式，旧目标不进新的 9 宫格盘点。
- 维持期以完整评估周期计，通常 1–2 个周期【经验】。长度取决于组织的评估频率：季度评估的组织约半年，半年评估的组织可能到一年。**上限是「第二个完整周期结束」**——超过这个长度，双轨自己就变成了新的存量。

**④ 什么信号说明可以退出双轨**

三个信号同时满足才退出，缺一个就再等一个周期：

1. **分布信号**：评优比例回到预设区间且不再上漂。
2. **时效信号**：抽样问员工「你在下一次评估之前是否已经知道自己的短板」，多数回答是。
3. **带宽信号**：管理者一个周期内在目标对齐、填表、校准、面谈、合规五项上的实际工时被算出来过，且未超过可用工时。

退出时最容易漏掉的一件事：**把旧规则正式宣布作废，并说明历史结论不再被引用为惯例**。不宣布就不算退出——员工会默认两套都还有效，并按对自己有利的那套解释。

### 4.5 模板 / 示例

**模板一：耦合关系表（Step 0 的产物）**

```markdown
# 耦合关系表 - {组织/团队} - {版本日期}

| 目标类别 | 是否换算回报 | 换算方式 | 判定人 | 模糊地带如何处理 |
| --- | --- | --- | --- | --- |
| 线上责任类（可用性 / 质量 / 成本） | 是 | {直接进评级公式} | {直线主管} | — |
| 探索类（新架构 / 能力跃迁） | 否 | 不计入评级 | {跨级评委} | 完成度不作评级依据，但影响投入决策 |
| 团队建设类 | 部分 | {写明是哪一部分} | {跨级评委} | 需在下一次校准会上说明 |
| 个人发展类（培训 / 认证） | 否 | — | {主管} | 只作发展证据，不进入档位 |

三个用途的标注（必填，二选一）：
- 校准会输出：尺子 / 人数
- 360 的用途：发展 / 评级
- 盘点结论去向：投入决策 / 档位
```

**怎么用**：填「是否换算回报」与「判定人」两列；「模糊地带」一列必须给出裁定人，而不是给一段解释。三个用途的二选一不是修辞，是制度开关——同一份 360 同时用于发展和评级，互评结盟会立刻出现。这张表是给员工看的，不是给 HR 存档的。

**模板二：OKR 模板（三层目标中的团队级）**

```markdown
# {季度} OKR - {团队名}

## Objective（目标）
{一句话方向，不只是指标名}

## Key Results（关键结果）
- KR1：{可复算的量化结果} ｜数据源：{库/表} ｜口径：{怎么算} ｜时间窗：{起止}
- KR2：{上线 / 接入类结果} ｜验收方式：{谁在什么数据源上复算}
- KR3：{能力跃迁项} ｜可验证产出：{主导 1 个 POC / 参数基线 / 复盘文档}

## 检查点
- {双月日期}：只看事实与阻塞，不改目标口径
- {季度末}：自评完成度 0–1.0（0.7 起进入卓越区，口径见主文件 §2.2）

## 完成度（季度末填写；是否进入评级公式由耦合关系表决定）
- KR1：{0.0–1.0}　KR2：{0.0–1.0}　KR3：{0.0–1.0}
```

**怎么用**：每条 KR 后面那三个格子（数据源 / 口径 / 时间窗）不要照抄，必须填真实值——三格填不出来说明这条 KR 不可复算，应改写或删除。末行括号里的说明按你的耦合关系表改：若组织确实把 OKR 接进评级，就把名字改成 KPI，不要保留 OKR 这个名字来做 KPI 的事。

**模板三：9 宫格盘点表**

```markdown
# {周期} 9 宫格盘点 - {团队/组织}

| {员工} | 绩效档位 | 绩效证据（可复核） | 潜力档位 | 潜力证据（行为） | 处置动作（建议） |
| --- | --- | --- | --- | --- | --- |
| {员工 A} | 高 | {项目 + 结果 + 数据源} | 高 | {在何种复杂度下独立承重} | 保留：独立目标 + 承重角色 |
| {员工 B} | 高 | {同上} | 低 | {证据指向专业性而非扩张性} | 资深专家：给 Title 与挑战 |
| {员工 C} | 中 | {同上} | 高 | {学习速度证据} | 培养：给导师 + 重点项目 |
| {员工 D} | 低 | {同上} | 中 | {同上} | 改进：PIP（判据事前写死） |
| {员工 E} | 低 | {同上} | 高 | {同上} | 转岗 + 再评（可能岗位错配） |

潜力维只允许写三类证据，写不出就留空：学习速度 / 复杂度承载力 / 带人效果
```

**怎么用**：两列证据必须填具体行为，不许写「表现良好」；潜力栏留空是合法结果，编一个分数才是问题。处置动作一列是**建议**，未经校准会不得作为最终结论。

**模板四：绩效面谈模板**

```markdown
# 绩效面谈 - {员工姓名} - {周期}

## 1. 绩效数据（基于 OKR / KPI）
- 综合完成度：{0.0–1.0}
- 关键结果：{逐条列事实，不写评价}

## 2. 优势（具体 + 行为）
- {在什么场景下做了什么，产生了什么可复核的结果}

## 3. 改进点（具体 + 行为 + 例子）
- {行为 + 当时的资源与时间约束 + 可指认的后果}

## 4. 改进计划（IDP）
- 目标 / 资源 / 检查点 / 判定方式

## 5. 激励兑现
- {本期兑现内容} / {未兑现项的说明}

## 6. 员工自评与异议
- {员工本人的说法；有异议时记入申诉通道}
```

**怎么用**：按 1→6 的顺序填写，顺序本身就是设计——先事实、后优势、再改进，避免开场定调。第 3 节必须带例子与当时的资源约束（证据三要件：可复核、可指认、带边界），只写「沟通能力需要加强」在制度上视为未完成面谈。第 5 节与兑现台账逐条对齐。

### 4.6 自检清单

- [ ] 抽 3 个团队问「这条 KR 完成会不会影响你的评级」，回答是否与耦合关系表完全一致？
- [ ] 随机抽 3 条 KR，交给不参与项目的同事独立复算，结果是否一致？
- [ ] 团队目标里是否至少有一项能力跃迁项，且它不是「参加培训」这类不可验证的表述？
- [ ] 校准会纪要里是否出现过「这组必须有 N 个 A」？出现即视为配额分配。
- [ ] 抽查上一轮 3 份盘点记录，潜力评分后面是否附有可复核的行为证据？
- [ ] 360 的用途是否被写死为「发展」或「评级」之一？两个都在用的组织必然出现互评通胀。
- [ ] 抽样问 3 名员工「你能说出为什么是这个结果吗」，答不出即反馈未到达。
- [ ] 管理者上一周期在目标对齐、填表、校准、面谈、合规五项上的实际工时是否被算出来过？
- [ ] 抽上一周期 3 条承诺的激励，逐条查台账：是否到期兑现或有书面说明？
- [ ] 每个 PIP 的判据、周期、资源与申诉路径是否在开始前就已写明？
- [ ] AI 产出是否只进「证据」不进「档位」？写证据 / 定级 / 受理申诉三个角色是否彼此独立？
- [ ] 双轨期是否有一张名单写明「谁适用哪一套」以及每个团队的切换日期？

### 4.7 小结

> 本节小结：整个落地过程里唯一决定成败的环节是 **Step 0——把「哪些目标换回报、哪些不换」写成一张所有管理者回答一致的纸**。它比其余环节更值得投入，不是因为它更重要，而是因为**它不可补救**：其余每一步做错都能在下一个周期调整，而耦合关系一旦在员工心里定了型（「目标定保守一点更安全」），恢复要花的不只是一个周期，还有一批人重新愿意踮脚。
