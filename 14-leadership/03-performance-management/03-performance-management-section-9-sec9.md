## 9. 改进计划（IDP）

面谈走到最后一步「共建改进」时，手上要留下的不是一句「下季度加油」，而是一份双方各持一份、到期能被第三方复核的书面计划。这份文件同时被当成两件方向相反的东西用：**它是培养工具**（要员工愿意说出自己的短板，前提是这次谈话安全），**它又是证据链**（到期要能举证「改没改」，前提是留痕）。安全与留痕的要求互相拉扯，所以这套脚本的成败不取决于目标写得多漂亮，而取决于开场那句话有没有把用途钉死——员工在知道「这份东西会不会进评级」之前，听不进后面任何一条目标。

### 9.1 什么场合用

**触发条件**（三条同时成立才用这套脚本）：

- 面谈前四步（准备 → 开场 → 自评 → 反馈）已经走完，结论已经说清，现在只差「下一步做什么」（五步法见 [§4 工程实现](03-performance-management-section-4-sec4.md) Step 4）
- 存在**可指认的维度差**，且能写成两档之间（如技术深度 3 → 4），而不是「整体感觉还不够」
- 这个差距在下一周期内**有真实项目可承载**——手上没有可挂载的项目时，缺的不是计划而是机会，此时发计划只会产出课程名

**谁在场**：主管与员工 1:1。HR 只出现在 PIP 场景与申诉通道里，不旁听 IDP。

**第二条怎么判定**：「可指认」不是形容词，它有可检验的写法——你能不能写出**当时的情境、他做了什么、产生了什么后果**这三件事。三件都写得出，这一维就可谈；只能写「感觉还差点」的维度，先去补一条证据，再回来谈。

**不适用**（两种，各自走别的路径）：

- 明确不达标或落入低评档——那是 PIP：单独触发、单独文档，期限 30–90 天【经验，随法域合规要求与岗位可改进性变】，未达成的后果是转岗或退出流程；而 IDP 未达成只是顺延并改计划
- 本次谈话只是季度例行沟通、没有任何具体差距——那就只谈事实与反馈，不发文档

两者必须分开：混在一起的直接后果是员工无法判断这次谈话是「培养」还是「警告」，同一个词在两种语境里含义相反，会同时毁掉培养的信任与处置的正当性。

| | IDP（个人发展计划） | PIP（绩效改进计划） |
| --- | --- | --- |
| 触发 | 每次面谈都可以有 | 明确不达标或落入低评档 |
| 目标 | 补维度差、争取下一级 | 回到合格线 |
| 期限 | 6-12 个月【经验，随职级体系的晋升周期与维度差数量变】 | 30-90 天限期【经验，口径同主文件 §2.3 的末位淘汰五步】 |
| 资源 | 导师、项目机会、课程预算 | 导师 + 培训 + 每周检查点 |
| 未达成 | 目标顺延，改的是计划本身 | 转岗或进入退出流程 |
| 常见错用 | 变成人人都要交的作业，没人 Review | 变成「合法解雇的倒计时」 |

### 9.2 脚本骨架（可套用）

```text
第零段｜目的：开场先说清这次谈话的边界（多长、记录谁看得见、有没有第三人在场）
    「这场我们谈 {x} 分钟，记录你我各一份；你不同意的部分我按原话记进去。」
第一段｜目的：把这份文档的用途钉死，排在所有内容之前
    「这份是 IDP，不是 PIP：它的用途是 {补哪一维 / 争取哪一级}，不会直接进本期评级，
      我会在 {日期} 跟你对一次进度。」
第二段｜目的：把差距落成两档，而不是形容词
    「{维度} 这一项，我看到的你是 {现状锚点}，这个角色在这一维需要的是 {目标锚点}。
      差别具体出现在 {情境} + {他做了什么} + {产生了什么后果}。」
第三段｜目的：先让对方说差距，不同意的当场记下
    「这两档之间，你自己觉得差的是什么？哪一条观察你不认同？」
第四段｜目的：把行动项挂到真实项目上
    「下个季度你手上会有的机会是 {项目/任务}。我想把 {维度差} 挂在这上面：{可验证的产出}。」
第五段｜目的：把资源写成具体的人和钱，不写「团队支持你」
    「我负责给你 {导师：谁、多久一次}、{项目机会}、{预算或时间}。哪一项到不了位，你直接找我。」
第六段｜目的：判据与复核日期当场写死，双方各留一份
    「到期看的是 {评审记录 / 上线结果 / 带出的第二个人}，这条现在就定，之后不改。
      下一次复核是 {review_due}。」
```

最常被跳过的是**第一段与第六段**。跳过第一段，员工会后会去问同事「这是不是要动我了」，此后你的每句目标都被当成文书；跳过第六段，约一个季度后这份文件就只剩培训记录【经验，随项目交付周期与团队复盘节奏变】，判据留到期末才讨论——那时争的不是「改没改」，是「谁印象更强」。

**六段的顺序本身是设计**：第三段（先让对方说差距）必须排在第四段（给行动项）之前。先给方案再问意见，对方会接受一个不是自己选的方案——他会在会上同意，执行时把它排在真实工作的最后。反过来，他自己说出来的差距，才可能被他当成本季度要做的事。

**中止条件**：如果第三段对方提出的分歧落在事实上（「那次延期是因为上游数据没到」），当场不要定判据，把材料补齐后再谈一次。在事实未对齐时写下的判据，等于把争议封进了计划里，到期必然爆开。

**该带什么材料进来**（缺哪一样，对方一定会绕开你的论点）：

- 一份双方共用的**维度锚点表**（每个维度各档分别是什么样子；档数随职级体系而定【经验】）——不共用锚点，员工会拿「别人也没做到」当论据
- 上一轮面谈记录里的**证据时间线**（可复核、可指认、带边界）
- 下季度的**项目与任务分配表**——证明机会是真的，不是安慰
- **资源清单**里每一项的提供人（不点名到人的资源，第一个月就会卡住）
- 计划本身，按五元组写：

```text
改进计划的五元组（缺一项即不可跟踪）
  维度    差距要落在某一维上（技术深度 / 系统设计 / 工程素养 / 业务理解 / 协作 / 领导力）
  现状 → 目标  必须写成可对照的两档（例：技术深度 3 → 4；档位口径随职级体系变【经验】），
              不写「需要大幅提升」
  行动项  必须挂到一个真实项目或任务上（只写「上课」= 买了资源，没有产生证据）
  资源    导师 / 项目机会 / 预算 / 时间；写清每一项由谁提供
  判据    到期用什么证据判定「做到了」（评审记录 / 上线结果 / 带出的第二个人）
  review_due   下一次复核日期；没有日期 = 只有清单，没有计划
────────────────────────────────────────
一条硬规则：判据必须在计划开始时写死，不临场定标准
```

写每条行动项时问三个问题，三个都答得上才算可执行：

1. **挂在哪个项目上**——缺口是「没做过」，行动项却写成「上一门课」，两者机制不同：课程给的是输入，评审与上线结果才是证据
2. **到期看什么**——只能靠主管印象判定的行动项，不是判据，是印象的另一种写法
3. **谁在什么时候看**——Review 日是计划的一部分，把 Review 写进日历，比把目标写得更漂亮有用

**数量**：一份计划里 2-3 条行动项比 6-8 条更容易真的做完【经验，随维度差数量与可用项目数变】；条目越多，越像愿望清单。

### 9.3 判据：说完之后怎么知道成了

| 判据 | 可观察的反应（对方做了什么 / 说了什么） | 为什么它说明成了 |
| --- | --- | --- |
| 锚点被共享 | 员工用自己的话复述「我现在是 X，要到 Y」，并能指出其中哪一条他不认同 | 能复述说明两档在他脑子里是同一个东西；能当场提异议，说明这段不是单方面输出 |
| 行动项被改写 | 员工把某条行动项改写成带项目名的句子，或追问「这个项目我什么时候能排期」 | 行动项从输入变成了产出，到期才有证据可查 |
| 资源被当成消耗品 | 员工追问「导师是每周一次还是两周一次」「预算能用在哪些地方」 | 他开始算怎么用，说明他打算真的用；没人算过的资源从未被使用 |
| 日期进了日历 | 员工当场打开日历记下 `review_due`，或会后就发起日程邀请 | 日期被一个双方之外的系统固定住，不再依赖任何一方记得 |
| 异议进了记录 | 员工要求把「我不认同 X 这一条」写进记录，或问申诉路径 | 异议有了出口，比会上沉默、会后再向同事散播便宜得多 |
| 计划进入了他的工作 | 之后某次 1:1 里他主动提起计划里的项目进度，或要求调整行动项 | 计划被当成工作的一部分而不是抽屉里的文件；敢要求调整说明他正在用它 |

```text
判据的写法（左边这种到期必然吵架）
   ✗「到期时整体表现有明显提升」         → 不可复核
   ✗「到期时跨团队反馈变好了」           → 不可指认（谁的反馈、哪一次）
   ✗「到期时能独当一面」                 → 无边界（什么规模、什么资源条件下）
   ✓「由他主导的 POC 通过评审并有记录」   → 可复核 + 可指认 + 带边界
   ✓「带出的第二个人能独立值班」         → 可复核 + 可指认
────────────────────────────────────────
自查一句话：把这条判据交给一个不认识他的人，他能不能独立判定做到没做到
```

反向自查一遍：**会后点头说「理解」不算判据**——那是礼貌，不是复述能力；**主管觉得谈得挺好也不算**，那是自我评价。判据只认对方做了什么。

**交付前自检 7 问**（发给对方之前逐条过）：

1. 差距是否落在具体维度与两档之间（3 → 4），而不是一句形容词？
2. 每条行动项后面有没有项目名或任务名？
3. 到期判据是否写在计划里，且双方手上各有一份？
4. `review_due` 是否在过去一个季度内，过期未复核的条目有几条？
5. 手上这份是 IDP 还是 PIP，两者的判据与后果有没有混进同一份文档？
6. 有没有把「发了 IDP」当作「已改进」的证据？
7. AI 起草的那几条行动项，最后真的立了几项？

### 9.4 常见失败

| 失败形态 | 症状（怎么发现它） | 机制（为什么这么说会反噬） | 改法 |
| --- | --- | --- | --- |
| 只发不跟 | `review_due` 已过期、无 Review 记录 | 缺口仍在，账面却显示「已规划」——员工据此判定「计划发下来就结束了」，下一轮他不会再为计划投入注意力 | 季度校准，把行动项与真实项目分配挂钩 |
| 行动项与项目脱钩 | 行动项全是课程名与书名 | 输入增加而证据为零，下一轮仍在同一维上失分；他还会读成「要我自己想办法」，抵触从这一句开始 | 每条行动项写项目名；写不出就说明当前没有机会，先解决机会问题 |
| 把 IDP 当惩罚 | 只对低评档的人发 IDP | 员工把「有 IDP」读作「被盯上了」，从此没人主动暴露短板，而暴露短板恰是这套机制唯一的输入 | IDP 面向全员，PIP 单独触发、单独文档 |
| 判据临场定 | 到期前才讨论「算不算达标」 | 结论不可复核，争议回到「谁印象更强」；期末追加要求会让整份计划失去正当性 | 判据在开始前写死，双方各留一份 |
| 差距写成形容词 | 计划上写的是「需要大幅提升沟通」「要更有架构思维」 | 形容词不可指认即不可改进，到期只能靠印象判定，员工也会判定为主观——争议回到「谁印象更强」 | 每条差距写成两档 + 情境 + 行为 + 后果 |
| 资源栏没有义务人 | 写的是「团队会支持」「有问题找我」 | 没点名到人的资源等于没有资源，行动项在第一个月就卡住，而卡住的责任落不到任何人头上 | 每项资源写提供人与到位时间 |
| IDP 不进入下一轮 1:1 | 上一次的行动项在后续 1:1 里从未被提起 | 计划与日常对话脱钩后，唯一的推进力只剩到期那次 Review，而一次性 Review 的产出通常是一句「有些进步」 | 把行动项放进 1:1 固定议程，每次几分钟看进度即可 |
| 让 AI 直接定评级 | 模型输出评级与百分比 | 把不可复核的判断伪装成了数据，且一旦接进雇佣决策就落入监管 | 用 LLM 汇总维度差、列候选行动项、起草初稿（它压缩的是整理工时，不是判断责任）；评级与取舍由人定 |

最危险的一条是**只发不跟**：它不会报错，反而会让流程看起来更规范——计划齐备、双方签字、归档完整。真正的代价在下一个周期显形：员工发现上一份计划从未被读过，于是这一份他也只会在会上点头。此后你要花的不只是一个季度，而是先证明「这次真的会跟」，才谈得上改进。

### 9.5 接口

这套脚本自己只负责「谈」和「写」：材料里的证据时间线来自 [§4 工程实现](03-performance-management-section-4-sec4.md) Step 4 的面谈记录与 [§4.5 模板 / 示例](03-performance-management-section-4-sec4.md) 的模板四（第 4 节即 IDP）；资源的真实性与范围来自 Step 5 的激励组合与兑现台账；PIP 的 30–90 天期限沿用主文件 [§2.3](03-performance-management.md) 末位淘汰五步里的口径，IDP 的 6–12 个月则是按晋升周期定的经验区间【经验，随职级体系与维度差数量变】；而「判据事后不得追加」这一条，与 [§3 设计模式与范式](03-performance-management-section-3-sec3.md) 处置链是同一件事：那里把预警写成「无预警 = 程序瑕疵」，把再评估写成「按事先写好的判据评价，不临场定标准」。AI 在这条链上只出现在两个位置——起草初稿与汇总证据；定级、沟通、受理申诉不可自动化，三个角色（写证据 / 定级 / 受理申诉）必须彼此独立，见 [§5 前沿演进](03-performance-management-section-5-ai.md)。这套脚本在整章里的位置见 [§6 落地实践](03-performance-management-section-6-sec6.md) 与 [§7 与其他方法对比](03-performance-management-section-7-sec7.md)。合规上有一件事要先核：欧盟《人工智能法案》（Regulation (EU) 2024/1689，2024 年通过）把用于就业与员工管理的 AI 归入高风险类别【公开】，落地前按当地要求核验员工是否被告知、是否留痕、是否保留人工复核与申诉通道，具体以官方文本当前版本为准。

### 9.6 小结

这份计划能不能用，取决于两个动作而不是两条目标：**开场先把用途钉死**（漏了它，后面每句话都被读成警告），**结尾把复核日期写进日历**（漏了它，这份文件约一个季度后就是一张培训记录【经验，随项目交付周期与复核频率变】）。差距写 3 → 4 还是 4 → 5，那是准确性问题；而用途与日期是结构性问题——结构错了，再准的目标也不会被跟踪。

> 💡 **思考锚点**：翻出团队里现在还挂着的 IDP 数两个数——`review_due` 已过期却没有任何复核记录的条目有几条，行动项里写的又是项目名还是课程／书名？前者不为零，你是不是已经落入「只发不跟」；后者若全是课程名，这份计划到期时你手上还剩什么可复核的证据，还是只能回到「谁印象更强」？
