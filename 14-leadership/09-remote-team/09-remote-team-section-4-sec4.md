## 4. 工程实现

本节只回答一个问题：**§3 的模式选定之后，怎么把它装进一个已经有人在上班的组织——第一步动什么、怎么知道动对了、多久见效、什么时候算装完。** 术语沿用 §3：空间层讲「默认在哪办公」，协议层讲「默认怎么传信息」，默认介质讲「信息附着在人身上还是文档上」。§4 不复述这些机制，只给顺序、产物、判据与迁移路径。

本文件同时服务两类读者，**第一步不同**。**从零搭建**（新团队、或第一次正式出台远程政策）从 4.1 的 Step 1 顺序走，Step 1–5 全是你的。**存量改造**（已在同地办公要引入远程，或已宣布远程但默认值没动）先做 4.4 的第 ① 步，再回到 4.1 的 Step 2——因为 Step 1 的结论在存量组织里通常已被场地租约与招聘历史替你决定，真正缺的是协议层。

### 4.1 落地步骤

**Step 1：选择远程模式（1–2 周）【经验，取决于法务与 HR 是否已有跨地域用工模板】**

1. 先量六条约束，再谈偏好：业务性质（工作能否被切分、协作是否依赖实时交换）、团队规模、合规边界（税务 / 用工 / 数据驻留）、招聘地域、团队时区跨度、存量场地租约到期时间。
2. 用 §3.1 的约束表与 §3.3 的决策表把候选收到两三个：**先用可行性筛掉不可行的空间形态，再用重叠窗口决定协议层能不能是同步，最后才用成本与习惯做减法。**
3. 高管 + HR（必要时加法务）共同签字，把「哪些地区能雇、数据能放哪」写成边界，而不是留在会议纪要里。
4. 空间默认值与协议默认值一起定——只定空间不做协议，等于只发了远程名额（§3.3 的误选形态一）。

- **产物**：一页纸的**模式决策记录**——选定模式、被判掉的两个候选及判掉理由、地区与数据边界、签字人。
- **判据**：抽三个在招或在岗岗位，看岗位描述里是否还限定城市；再抽一个跨地域岗位，问 HR「这个地区的人签哪种合同、数据能不能落在他自己的机器上」——答不上来，说明 Step 1 没做完。
- **为什么必须这一步 / 为什么在这个位置**：合规边界与招聘地域是**不可折价**的约束（§3.1），且先一步决定人才池。先宣布远程、再发现某地区不能雇人，此时已有成员需要调整，沟通成本远高于事前划边界；存量组织里这条更贵，因为已经有人按旧边界入职了。

**Step 2：建立 Async-First 文化——把协议层写成规则（首批规则 4–8 周定稿）【经验，取决于团队规模与文档存量】**

1. **文档优先**：决策默认落文档，口头定下的事被要求补录到可检索位置。
2. **异步沟通默认**：先写下来再讨论，讨论在线程里收敛并留下结论。
3. **响应预期写成规则**：什么级别的事多久内回，覆盖到「谁在什么时候必须回」。
4. **会议最小化**：给会议一条判据（这件事是否必须实时交换才能推进），可选会议一律异步。

- **产物**：一页**协作协议**（文档默认 / 响应预期分级 / 会议必要性判据）+ 一个可检索的决策记录位置（ADR 或同类的决策日志）。
- **判据**：抽最近 5 个决策，看能否在 5 分钟内从文档里找到「谁定的、依据什么、什么时候生效」；抽一条最近的非事故类讨论，数它从提出到收敛花了几轮往返——**往返轮次是异步协议的实际单位**，超过两轮且没人能说出谁必须何时回，协议等于没写。
- **为什么必须这一步 / 为什么在这个位置**：协议层决定同步的例外怎么开（§3.2.2）。它必须排在 Step 3 之前：Onboarding 与 1:1 都要往一个「信息落在文档里」的环境里放人，环境没建好，新人学到的是「问旁边的老同事」——这恰好是在场者优先的默认值。先装人再改协议，等于让第一批新人替团队付迁移成本。

**Step 3：建立远程 Onboarding（持续，第一批新人入职前 1 周启动，4 周计划本身随岗位与文档完整度伸缩）【经验】**

1. 定 4 周 Onboarding 计划（模板见 4.5），第 1 周只做环境、人与文档三件事。
2. 指定 Buddy（具体到人，进计划而不是口头约定），并明确 Buddy 的产出被算进他的绩效口径。
3. 给一个「先查再问」的入口（文档检索 + 问答频道），把重复问答从人身上挪到可检索的位置。
4. 第 2 周与第 4 周各留一次反馈，反馈对象是计划本身，不是新人。

- **产物**：一份填好的 4 周计划（含 Buddy 姓名）、一个提问入口的链接、两次反馈记录。
- **判据**：问新人「入职第 3 天，你上一次问问题是在哪里问的、多久得到回复」；再问 Buddy「这两周你为新人花了多少小时」——**Buddy 的时间没有被显式记账，就是没被分配**。
- **为什么必须这一步 / 为什么在这个位置**：同地 Onboarding 靠「旁边有人」自然发生，远程没有这个副产品通道（§3.5 反模式四），所以必须显式指定责任人。它排在 Step 2 之后：没有可检索的文档，「先查再问」这个入口是空的，新人只能继续问人。

**Step 4：建立远程 1:1 与会议节奏（持续，节奏规则 2–4 周内固定下来）【经验】**

1. 每周 1:1（30–60 分钟），议程见 4.2 与 4.5，上一次的 Action Items 是固定第一项。
2. 异步 Standup（每日，文档或 Bot）+ 同步 Weekly（每周一次，覆盖跨团队事项）。
3. 月度 / 季度 Review 与个人目标回顾，各自有固定入口而不是临时约。
4. 把所有周期性会议按时区排一遍，确认没有人长期落在非工作时间。

- **产物**：一张**会议与 1:1 日历**（频率、时长、参加者、时区落点），以及每次 1:1 的 Action Items 记录。
- **判据**：把过去一个月的周期性会议按参加者时区排一遍，看是否有人长期落在 22:00–06:00 区间【经验口径：该区间按团队所在地的法定休息时段校准】；再抽一次 1:1 记录，看有没有「我承诺了什么 / 他承诺了什么」两列——只有「聊了什么」的记录，1:1 已经退化成进度汇报。
- **为什么必须这一步 / 为什么在这个位置**：1:1 是远程团队唯一稳定的关系与上下文采样点（见 4.2）。它排在 Step 3 之后、Step 5 之前：新人先有节奏可循，信任建设才有承载物；反过来先做聚会（Step 5）而节奏混乱，一次线下聚会补起来的关系仍会回到原状（§3.4 的组合边界）——回落的时间尺度在数周量级【经验，随非正式通道是否定期发生、日常协作里还有多少非任务性交流而变化】。

**Step 5：建立信任建设机制（持续，首次 Offsite 建议在政策生效后 3–6 个月内）【经验】**

1. Virtual Coffee：非正式通道定期发生，而不是「想聊就聊」。
2. Quarterly Offsite（年度可加 Annual Retreat）：把「必须当面」的环节集中安排，会上不做日常汇报。
3. 个人化关心：记住个人关心、家庭、爱好，写进 1:1 记录而不是靠记性。
4. 可见度建设：进展与决策定期公开在可检索处，而不是只发给主管。

- **产物**：非正式通道的日程（Virtual Coffee 频次与主持轮值）、Offsite 预算与议程、可公开查阅的进展记录。
- **判据**：抽一次回顾会记录，看反对意见是否只来自同地成员；另找一位远程成员问「最近一次与工作无关的交流是什么时候」——记不起来，说明非正式通道被当成了福利而不是机制。
- **为什么必须这一步 / 为什么在这个位置**：关系通道在远程下没有副产品，只有被设计出来的通道（§3.5 反模式六）。放在最后不是因为它次要，而是因为它最贵（差旅按人 × 次计，§7.4），且只有在前面四步都成立时它才产生净增益。

**五步里最常被跳过的是 Step 2 的第 3 项——把响应预期写成规则。** 团队通常把沟通工具装好、宣布「我们异步优先」，就认为协议层已经建成。跳过的第一个症状出现在第 2–4 周【经验】：同一件事在文档或线程里来回超过两轮仍未收敛，且没有人能说出「谁在什么时候必须回」；随后管理者会把它误判为「响应不及时」并去要求更快回复，让等待继续被放大（§3.5 的时区地狱条目是同一机制更晚的形态）。第二个被跳过的是 Step 1 的合规边界，它的代价不在第一个月出现，而在第一次跨地区招聘时才出现。

### 4.2 关键技术点

**Overlap 窗口管理（时区）**

- **做法**：先把成员时区分布与各自的法定工作时段列成一张表，再定一条核心重叠带（每日必须共同可达的时间），把「必须实时交换」的议题压进这条带里，其余一律异步；重叠确实不足时用轮班会议 + 录屏补齐。
- **机制**：同步要求同时在场，异步把信息从时间轴解耦（§7.3.1）——所以重叠窗口的大小不决定协作能力，只决定**哪些议题可以走同步**。窗口越窄，越要把同步留给不可逆事项（分歧收敛、事故处置）。
- **失效条件**：**当团队跨 3 个以上时区、且核心重叠低于 2 小时【经验，主文件 §2.2：≥ 4 小时可维持每日一次同步，≥ 2 小时只够紧急事项】时**，这条会以「少数人的作息补贴协作」的形式坏掉。症状：把周期性会议按时区排一遍，有人长期落在 22:00–06:00；第二个信号是同一件事的往返轮次——跨时区下一轮往返即一天，超过两轮说明实际决策周期已是天级。
- **档位**：重叠阈值为【经验】，来自主文件 §2.2 与本章 §3.1，不是实验结论。

**响应预期协议（异步的完成信号）**

- **做法**：按事项级别写明时限（例如需决策的事项、需确认的事项、需知晓的事项各一档），写进协作协议；超时未回按默认路径推进，并在记录里写明「按默认推进」。
- **机制**：异步没有天然的完成信号——不问就不知道对方看没看到，所以每一次未定义的等待都会追加一次确认往返，实际吞吐低于同步（§3.2.2 失效点）。响应预期把等待变成有上限的量，这是「时间轴解耦」能成立的前提。
- **失效条件**：**当响应预期没有写下来、而并行线程数继续增长时**，协议会退化成「谁新发消息谁优先」。症状：同一个人同时盯 5 个以上未收敛线程，重要但不紧急的决策长期停在「已读未回」；判别动作是让每个人列出自己手上「等别人回」的事项，数量最多的那个人就是协议失效的代价承担者。
- **档位**：【经验】。关键是「有明确时限」，而不是那个具体数字。

**决策默认落文档（文档优先的执行形态）**

- **做法**：每类决策固定一个记录位置（ADR / 决策日志），规定写入时限；口头或私聊定下的事，由发起人补齐到该位置；文档需带「谁定的 / 依据什么 / 何时生效 / 影响谁」四格。
- **机制**：默认介质换成文档后，信息附着在可检索位置而不是「当时在场的人」，于是协作不再要求同时在场，决策也天然可追溯（§7.3.1）。这也是 Step 3–5 的前提。
- **失效条件**：**当文档量跨过检索能力上限时**，「写下来」会变成「写完就沉」——找不到等于没写。症状：同一个问题在三个不同频道被重复提问，或新人入职第一周问的问题在文档里其实已有答案。此时要补的不是写，而是归档规则与检索入口（谁负责归档、按什么关键词）。
- **档位**：【经验】。指标口径建议自定，例如「抽 5 个决策能否在 5 分钟内定位」。

**远程 1:1 议程结构**

- **做法**：固定五段——生活近况（5 分钟）→ 上次 Action Items 回顾（5 分钟）→ 当前进展与风险（10 分钟）→ IDP / 成长（5 分钟）→ 个人关心（5 分钟）；模板见 4.5。主持人每次结尾写下双方的 Action Items。
- **机制**：同地团队对成员状态有一整套低成本的副产品信号（走廊、表情、随口一问），远程没有，1:1 是唯一稳定的采样点。前 5 分钟的生活部分不是礼节——它补的是同地团队免费获得的那部分信息带宽。
- **失效条件**：**当 1:1 被填满工作汇报、或被以「没什么可聊的」为由取消时**，关系与风险信息同时断供。症状：离职、倦怠、跨团队摩擦在发生时没有前兆记录——1:1 记录里最近三次只有任务清单。判别动作：翻上三次 1:1 记录，看有没有一条信息不是从工单或文档里能得到的。
- **档位**：【经验】。频率与时长按团队节奏与经验档（每周 30–60 分钟）自定，关键是它是否稳定发生。

**远程 Onboarding 的 4 周节奏与 Buddy 制度**

- **做法**：第 1 周环境与文档，第 2 周第一个低风险任务，第 3 周主导一个小项目并做跨团队介绍，第 4 周完全投入并安排 90 天回顾；Buddy 具体到人，其时间进绩效口径；给「先查再问」入口。
- **机制**：远程入职缺的不是信息量，而是**获取路径的责任人**——同地时路径由物理邻近自动提供。指定 Buddy 相当于把这条路径显式化，并把它从「老同事的善意」变成「被记账的产出」。
- **失效条件**：**当 Buddy 同时带 2 个以上新人、或入职时点撞上季度末冲刺时**，这条会以「新人自己摸索」的形式坏掉。症状：新人前两周的提问全部集中在一人身上，Buddy 自己的交付在下滑，新人 90 天内流失；判别动作是问 Buddy「上周为新人花了多少小时」，答不出量级即为失效。
- **档位**：【经验】。4 周是节奏框架，实际长度随岗位与文档完整度变化。

**会议必要性判据与会议执行规格**

- **做法**：会前发议程并写明决策点；单次时长控制（主文件 §2.3 给 ≤ 45 分钟）、留间歇不背靠背；会后 24 小时内发出纪要（结论 + Action Items + 负责人 + 截止日期）【经验口径，时限按团队节奏定，关键是「有明确时限」】；可选会议一律异步。
- **机制**：同步会议占用的是**所有人的公共时间窗口**，成本超线性（§7.3.2）——每多一人、每多一分钟，边际成本上升，而异步只占用各自的时间。所以会议必须由一条判据来发放，而不是由发起人的习惯决定。
- **失效条件**：**当「不开会」的判据缺失、且远程下开会比写文档更省事时**，会议会回填日历。症状：日历被会议填满、连续无间歇、摄像头被要求常开——这类会议疲劳的公开研究记录见 §7.3.2 所列来源【公开，Bailenson 2021 / Fauville 等 2021 / Microsoft WorkLab 2021】。判别动作：随机抽一周，统计有多少会议的议程里写明了决策点。
- **档位**：会议时长与纪要时限均为【经验】。

### 4.3 工具链与平台

选型的第一判据不是功能多少，而是**它让信息落在哪、能不能被检索回来**。下表按类别给判据与不选的代价；产品能力更新频繁，请以各自官方文档当前版本为准。

| 类别 | 候选 | 选型判据（在什么约束下选哪个） | 不选它的代价 |
| --- | --- | --- | --- |
| 即时沟通 | Slack / 飞书 | 看信息是否需要长期可检索、是否需要跨组织通道（Slack Connect 跨组织协作；飞书与国内团队作息一致） | 用 IM 承载决策不留痕，决策载体退回「在场者的记忆」 |
| 视频会议 | Zoom / 腾讯会议 | 看录制与转录能否导出、参会者所在区域网络是否可达 | 纪要只能靠人写，异步回看成本转移到记录者身上 |
| 文档 / Wiki | Notion / Confluence / Coda | 看全文检索与权限分级是否够用；需要「文档 + 表格/数据库」混排（如指标台账）选 Coda 一类 | 文档找不到等于没写，Step 2 的协议层直接空转 |
| 录屏 | Loom / Vidyard | 工程评审、异步说明用 Loom 一类短录屏；需要观看行为追踪（销售 / 客户场景）用 Vidyard 一类 | 口头解释无法留痕，重复解释成本随人数增长 |
| 项目管理 | Linear / Jira / 飞书项目 | 小团队快迭代选 Linear；已有合规与审批流程、需与既有流程对接选 Jira；国内协作选飞书项目 | 工单与文档两套系统并存，上下文在工具之间断链（§6.3 字节案例的机制） |
| Async Standup | Notion / Coda / Geekbot / Standuply | 需要自动汇总与提醒用 Bot 类（Geekbot / Standuply）；只要记录、不要打扰用文档类 | 站会变成长文，没人读，等于没有节奏 |
| AI 会议纪要与摘要 | Otter.ai / Granola / Slack AI / Notion AI / Loom AI | 先看输入是否已有记录、转录能否导出并逐句回溯、语料是否允许出境；不满足就不上线 | 不可回溯的摘要会以「看起来像原文」的形式新增事实 |
| AI 翻译与转录 | DeepL / Google Translate / Whisper + GPT | 需要逐句对照的书面协作用翻译类；会议音频实时转录用转录 + 摘要链路，前提是录音与上传合规 | 语言成为隐藏的同步成本，非母语者在会议里被系统性边缘化（§3.6 跃迁） |

这一类里**最容易被误选的是文档工具**：团队先买 Notion（或任一 Wiki），再讨论「什么必须落文档、谁负责归档」。误选的典型后果是半年后文档区变成归档区——写了没人读，检索不到，于是团队回到「问人」这个默认通道，而这次连迁移预算都已经花掉了。正确顺序是**先定协议与归档责任，再选工具**；工具只决定介质长什么样，不决定信息会不会被写下来。

### 4.4 存量迁移

**① 先做可回退、且立刻见效的一件事。** 从一个小团队开始，只改**下一次决策**：任何一个已经排进日程的决策会，会前把材料与备选方案写进文档，会上只收敛分歧，会后 24 小时内补齐记录。它可回退（不影响其它团队，最多回到旧做法）、立刻见效（下一个决策周期就能看到留痕），并且不花钱。第二件事是把一个团队的周期性会议按时区重排一遍，把非工作时间那一档移进重叠带——同样是可回退的动作。

**② 历史资产分类处理，不要全部返工。** 三类，逐类给判据：

- **全部返工**（只对仍有依赖的资产）：仍被跨团队引用的决策文档与常青流程页，补「谁定的 / 依据什么 / 何时生效 / 影响谁」四格与检索关键词。判据是**近 3 个月是否被引用过**（看链接与评论），没被引用过的进第 3 类。
- **只改动的部分**：1:1 记录、会议纪要、工单模板——从下一份开始用新格式，不回补历史。理由是这些记录的价值在增量上，回补不产生信息，只产生工作量。
- **打标挂账**：历史文档不做格式返工，只打一个「未复核」标记并列出清单，把复核排进后面的容量窗口——这是「挂账」，不是「不管」：清单本身要可检索，且要有复核优先级（按引用频率排）。

**③ 双轨怎么维持、维持多久。** 新决策走文档 + 异步，旧决策留在原处；同一件事不要求两边都记。双轨期按 1–2 个季度设【经验，随团队规模与决策频率变化】，期间允许「这次特殊，先口头定」，但要求口头定的事**当天补录**——补录这一条是双轨期唯一不能松的纪律，它保证双轨不会变成永久的两套习惯。同时给双轨期一个显式的结束条件（见 ④），否则它会以「一直这样」的形式长期存在。

**④ 什么信号说明可以退出双轨。** 三个可核验的信号，全部满足再退：一是随机抽一位不在任何办公室所在城市的成员，问「最近一个对他有影响的决定，你是怎么知道的」——答「某个文档 / 频道」就算过（§3.2.1 的验证动作）；二是把周期性会议按时区再排一遍，没有人长期落在非工作时间；三是抽一条最近的决策，看它从提出到收敛是否在两轮往返以内。三个信号里任何一个不过，退出双轨只是把文档纪律又变成口头默认。

### 4.5 模板 / 示例

**模板 1：远程 1:1 议程**

```markdown
# 远程 1:1 - {员工姓名} - {日期}

**1. Life Check（5 分钟）**
- 最近有什么新鲜事？
- 工作生活平衡如何？

**2. 上次 Action Items Review（5 分钟）**
- [ ] {上次我承诺的} - Due: {日期}
- [ ] {上次他承诺的} - Due: {日期}

**3. 当前进展（10 分钟）**
- 关键成果 / 关键风险 / 需要什么支持

**4. IDP / 成长（5 分钟）**
- 本季度 IDP 进展、下一级晋升的准备项

**5. 个人关心（5 分钟）**
- 远程工作感受、团队融入、工作生活平衡

## Action Items
1. [我] ______ - Due: ______
2. [员工] ______ - Due: ______
```

**怎么用**：每格都填，但**第 3 格不要写成任务清单**——任务清单在工单系统里，写进来的是「哪件事卡住了、卡在谁那里」。第 1 格与第 5 格不要因为「没什么可聊」而删，它们补的是同地团队免费拿到的信息带宽。

**模板 2：Async Daily Standup**

```markdown
# Daily Standup - {日期} - {姓名}

## 昨天做了什么？
- ______

## 今天计划做什么？
- ______

## 有什么 Block？
- ______

## 需要谁的支持？
- ______
```

**怎么用**：只填四格，**不写「正常/没事」**——没有 Block 也要写「无」。第 4 格是这份模板的真正用处：它把等待关系写下来，让响应预期有对象；如果连续两周第 4 格全是空，说明异步站会已经变成打卡。

**模板 3：远程会议（含议程与纪要）**

```markdown
# 远程会议 - {标题} - {日期}

## 时间
{YYYY-MM-DD HH:MM-HH:MM} {时区}

## 参与者
{姓名（时区）}

## 议程
1. 上周进展（10 分钟）
2. 关键问题讨论（20 分钟）
3. 跨团队决策（10 分钟）—— 本次的决策点：{写清楚}
4. Action Items Review（5 分钟）

## 决策机制
- 现场可决策：{列出}
- 需要会后异步补充的：{列出}

## 纪要（会后 24 小时内补）
- 讨论议题 / 决策结论 / Action Items（负责人 + 截止日期）
```

**怎么用**：**「决策点」那一格空着的会不要开**。时间格必须带时区，否则跨时区团队会把本地时间直接当成共识；「需要会后补充」那一栏不要用来藏未决事项，它是「本次会议不收敛」的显式声明。

**模板 4：远程 Onboarding 4 周计划**

```markdown
# Remote Onboarding 计划 - {新人姓名} - {入职日期} - Buddy: {姓名}

**Week 1：环境搭建**
- 设备到位、账号开通；Buddy 介绍（Slack / Zoom）
- 阅读团队 Wiki；1:1 with Manager

**Week 2：第一个任务**
- 第一个小任务（PR / 文档）；Buddy 1:1；Manager 1:1；加入 Slack 频道

**Week 3：跨团队融入**
- 主导 1 个小项目；跨团队介绍会；Onboarding 反馈 Review；Virtual Coffee

**Week 4：完全投入**
- 完全投入项目；Onboarding 总结；季度 Offsite（如适用）；90 天 Review 计划
```

**怎么用**：**Buddy 必须写姓名**，写「团队」等于没指定；第 2 周的任务要小到能在一周内合并一次，它的作用是让新人第一次走完「写 → 评审 → 合并 → 上线」全链路。第 3 周的反馈对象是计划本身，不是新人的表现。

**模板 5：Async Decision 记录（ADR）**

```markdown
# ADR-{YYYY-MM-DD}: {决策标题}

## 状态
{Proposed / Accepted / Superseded by ADR-xxx}

## 背景
{要解决什么问题，谁受影响}

## 决策
{选了什么，包含关键参数与生效时间}

## 选项
**选项 A：{候选，例：Milvus}**
- 优点 / 缺点：{}
**选项 B：{候选，例：Pinecone}**
- 优点 / 缺点：{}
**选项 C：{候选，例：Qdrant}**
- 优点 / 缺点：{}

## 决策依据
- 约束：{合规 / 规模 / 团队技能}
- 参考：{内部 benchmark 链接、讨论线程链接}

## 后果
- {需要投入的人力与周期}
- {未来什么条件下需要重审这个决定}
```

**怎么用**：**「被否掉的选项」不要省**——只留结论的 ADR 半年后无法复审，因为没人知道当时排除了什么。选项里的具体名字（Milvus / Pinecone / Qdrant）只是示例，换成你的候选，但**每个候选都要有一行缺点**，没有缺点的候选表等于没有比较。四格必须齐：谁定的、依据什么、何时生效、影响谁；「后果」里的人力与周期要写量级（例如自建一类方案的运维投入可用「1 人 6 个月」这种量级描述【经验】），最后那条「什么条件下重审」是这份记录最有价值的一行。

**模板 6：AI 异步会议摘要 Prompt**

```python
ASYNC_MEETING_SUMMARY_PROMPT = """
你是资深远程协作专家。请基于以下讨论记录，生成本次异步会议摘要。

要求：
1. 关键讨论议题（3-5 条）
2. 决策结论（逐条给出原文出处）
3. Action Items（负责人 + 截止日期）
4. 未解决议题
5. 下次会议建议议题

约束：只做压缩，不做决策；无法从记录中找到出处的结论标注「无法回溯」。

讨论记录：
{slack_thread}
"""
```

**怎么用**：输出必须**逐句能回溯到原始记录**，回溯不出来的句子就是新增的事实，要删掉。别让摘要替你写「结论」——结论由人写下并署名，摘要只负责把长线程压成一页。

### 4.6 自检清单

- [ ] 抽三个在招岗位，看岗位描述里是否还限定城市？限定的团队实际仍是 Office-First 或 Hybrid，无论它怎么自称。
- [ ] 问 HR「某个跨地区岗位签哪种合同、数据能放哪」，能否当场答出？答不出说明合规边界没写成规则。
- [ ] 决策是否默认落文档？口头定下的事，有没有被要求当天补录到可检索位置？
- [ ] 是否写明了响应预期（什么级别的事多久内回）？只有「尽快」等于没有协议。
- [ ] 抽一条最近的非事故类讨论，数它几轮往返收敛？超过两轮且没人能说出谁必须何时回，即为失效。
- [ ] 把所有周期性会议按时区排一遍，有没有人长期落在 22:00–06:00 区间【经验口径，按团队所在地法定休息时段校准】？
- [ ] 随机抽一位不在办公室所在城市的成员，问「最近一个影响你的决定你怎么知道的」？答「别人告诉我的」说明默认介质仍是口头。
- [ ] 抽最近三次 1:1 记录，有没有一条信息是工单与文档里拿不到的？没有说明 1:1 已退化成进度汇报。
- [ ] 新人有写明的 Buddy 姓名与「先查再问」入口吗？问 Buddy 上周为新人花了多少小时，他能否给出量级？
- [ ] 回顾会上的反对意见是否只来自同地成员？是则说明文化通道缺失，而不是成员没有意见。
- [ ] 若接入 AI 摘要或答疑：摘要能否逐句回溯到原始记录？有没有越过「只压缩、不决策」这条线？
- [ ] 存量改造中，历史文档清单是否有「未复核」标记与复核优先级，而不是宣称「已全部整理」？

### 4.7 小结

> 本节小结：整个落地过程里唯一决定成败的环节是 **Step 2 的第 3 项——把响应预期写成规则**。它比选模式、买工具、办聚会都更值得投入，因为它决定默认介质能不能真的从口头换成文档：没有响应预期，异步只是在等待里打转，于是团队会退回同步，而同步又要求同时在场——跨时区与远程成员在这一步被重新排除在外（§3.2.2 的失效点即此）。其余四步都在为这件事创造条件：Step 1 划出可行的边界，Step 3–5 让信息与关系有承载物。
