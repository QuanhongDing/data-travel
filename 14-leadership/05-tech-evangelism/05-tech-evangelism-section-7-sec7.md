## 7. 与其他方法对比

### 7.1 先立判据：为什么打分表会误导

原文件给「制作成本」行打了 `开源 = 1 / AI 辅助 = 5`，又在「长期价值」行打了 `开源 = 5 / Newsletter = 3`，五行打完分让读者自己权衡。这套打分表有四个结构性问题。

第一，**它把不同层的对象放进了同一张表**。「开源」是一种资产（可被 clone、可被提 issue、可被采用），「Conference」是一个事件（只存在于那 40 分钟里），「AI 辅助」是一种产能放大器（不改变分发路径、不产生一手证据）。三者在同一行里比「制作成本」，等于拿「买一台机床」和「开一次发布会」比单价。§2 定义的**金字塔模型（Content Pyramid）**其实已经给出了正确的组织方式——底层沉淀、中层演讲、顶层开源——金字塔是**编排**，不是候选。把编排和候选并列，会诱导出「要不要用开源替代博客」这种没有答案的问题。

第二，**它把场景相关的结论伪装成绝对结论**。「触达范围」给 Conference 打 5 分，只在「你能拿到席位且现场有 200 人」时成立；同一个候选，讲给 20 人且无录播，触达可能不如一篇被检索三年的博客。**同一维度在不同规模下权重相反**：受众少时看互动质量，受众大时看分发机制，而打分表只允许一个数字。

第三，**它没有时间维度**。内容类工作的收益分布不只有大小，还有形状：博客 / 开源 / 视频是**累计分布**（今天写的东西三年后仍在被检索），Conference / 直播 / 内部分享是**脉冲**（散场即归零，除非有录播与再分发）。只比「触达范围」的打分表，会把脉冲型渠道的瞬时峰值与沉淀型渠道的累计面积比成同一个数字。

第四，**它没有成本纪律**。原表只比「哪个效果更好」，不比「你付得起哪一个」。布道最真实的约束几乎总是**边际产能**：一篇 2000–3000 字的深度技术文，从选题、取数与复现实验、写作到配图校对合计 7–14 人时（【推算】，分项推导见 §7.4）；一次 25 分钟的演讲合计 28–48 人时（【推算】，§7.4）。按两者区间中位估算相差约 3–4 倍（中位 10.5 人时 vs 38 人时，【推算】），足以让一个每季度只有几十人时余量的团队重排优先级——而打分表把它们抹平了。

**本章采用的 6 条判据**：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| 分发机制 | 内容靠被检索、被推送，还是被邀请（现场） | 检索型是复利、推送型看订阅基数、现场型是脉冲——三种收益曲线不可比 |
| 证据密度 | 能否承载可复现的证据（代码、数据、迁移步骤） | 采纳要赌上对方的时间与项目，没有证据的观点不改变采纳动作 |
| 单位产能 | 生产一个「可用单位」要几小时 | 布道的瓶颈是产能不是创意；先算清每周产量，再谈组合 |
| 反馈带宽 | 一次性、单向，还是可追问、可验证 | 决定建立哪种信任（判断信任 / 人格信任 / 能力信任），三者不可互换 |
| 时间衰减 | 内容多久失效 | 决定它该做成一次性消耗品，还是可被引用、可被再分发的资产 |
| 复用性 | 同一次准备能被几条渠道再分发 | 决定高成本渠道（Conference / 视频）能否被摊薄 |

### 7.2 候选方案全景

原 § 7 的七个候选（博客 / Conference / 开源 / Podcast / 视频 / Newsletter / AI 辅助）与决策树中出现过的做法（内部分享 + 读书会 / 金字塔 / 业务翻译 / 个人品牌 / 个人 IP / 团队品牌）在本表中**全部保留**；并按 §2 的术语补上「技术直播」与「Storytelling」，把「个人 IP / 团队品牌 / 公司品牌」按 §2 的定义（§2 把它们定义为**影响力**）标注为目标而非渠道。决策树里出现过的「多模式组合」同样没有被删掉——它不是一种独立方法，本表没有也不需要有对应行，它由 §7.6 的「常见组合」按原名承接。

| 方法 | 渠道类型 | 核心机制（一句话） | 典型角色 | 成本结构 |
| --- | --- | --- | --- | --- |
| 内部分享（Internal Tech Talk） | 现场型 | 同处一个组织：讲者能引用听众的代码与报表，说服成本最低 | 平台采纳、跨团队对齐 | 准备 4–8 人时 / 次（【经验】） |
| 读书会（Book Club） | 现场型（低频） | 把外部知识变成共同词汇，降低后续所有沟通成本 | 团队知识基线 | 人均 1–2 小时 / 次（【经验】） |
| 技术博客（Tech Blog） | 沉淀型 | 稳定 URL + 可被检索：一次生产进入累计收益 | 个人 IP、团队品牌、招聘 | 一次性 7–14 人时（【推算】§7.4） |
| 技术大会演讲（Conference） | 现场型 | 主办方背书 + 现场高带宽 + 会后转述 | 行业影响力、团队品牌 | 28–48 人时 / 次（【推算】§7.4） |
| 开源项目（Open Source） | 沉淀型（可验证） | 代码是可执行证据：能被 clone、被 issue、被采用 | 团队品牌、能力证明、生态 | 固定投入 + 长期运维（§7.4） |
| 技术 Podcast | 订阅型 | 分发交给订阅关系；陪伴场景适合「人物与判断」类内容 | 行业影响力、同行关系 | 每期 2–4 人时（【经验】） |
| 技术视频（YouTube / Bilibili） | 订阅型（可检索） | 演示过程与画面不可替代；平台推荐带来冷启动 | 上手教学、产品布道 | 每分钟成片 1–2 小时（【经验】） |
| 技术 Newsletter | 订阅型 | 直接触达名单，不依赖平台算法，但增长慢 | 稳定触达、候选人池 | 每期 3–6 人时（【经验】） |
| 技术直播（LinkedIn Live / Twitter Space） | 现场型（无剪辑） | 双向、零剪辑：真实感换精度 | 社区运营、答疑 | 时长即成本（【经验】） |
| 业务翻译（Business Translation） | 编排动作（非渠道） | 把技术价值改写成业务指标口径 | 内部采纳的前置条件 | 一次对齐 1–2 小时（【经验】） |
| Storytelling | 表达层（非渠道） | 提升记忆与转述意愿，牺牲精度 | 演讲、晋升陈述、布道 | 素材获取成本 |
| 金字塔模型（Content Pyramid） | 编排层（非候选） | 底层沉淀一次，上层再分发 N 次 | 所有渠道的组合方式 | 无独立成本 |
| 个人 IP / 团队品牌 / 公司品牌 | **目标**（非渠道） | 影响力的三种归属层级 | 招聘、跨团队协作 | 由上面各渠道共同产出 |
| AI 辅助布道 | **放大器**（非独立渠道） | 降低内容生产的边际成本 | 放大上述任意渠道 | 近乎零现金成本，风险在事实错误 |

这十四条里十三条是渠道或编排动作，分四**族**：**族 1 沉淀型**（博客 / 开源）——决定你有没有可以被检索、被引用的资产；**族 2 现场型**（内部分享 / 读书会 / Conference / 直播）——决定信任的转化速度；**族 3 订阅型**（Newsletter / Podcast / 视频）——决定能否把触达从「人来找」变成「内容去找人」；**族 4 编排与放大器**（金字塔 / Storytelling / 业务翻译 / AI）——不产生新受众，只改变前 3 族的效率；余下的一条「个人 IP / 团队品牌 / 公司品牌」是目标而不是渠道，不入族。

**先分族再选**能省掉一半比较：族 4 不产生新受众，所以「只有族 4、没有族 1–3」的布道必然表现为**材料越做越漂亮、但没人来**；族 1 是复利但冷启动极慢，所以「只有族 1、没有族 2」的团队常见于技术很强但没人知道的团队——他们的文章写得好，却从没被人当面追问过，因此内容里的判断从未被压力测试过。

族之间还存在一条搬运关系，理解它能让组合决策变得简单：**同一份素材可以在族之间搬运，但只能从族 1 往族 2 / 族 3 搬，不能反向搬**。原因是搬运的成本不对称——把已有长文压缩成一份 25 分钟的提纲是 3–5 人时（【推算】，§7.4 的「选题与提纲」项），而把一次演讲补成一篇有证据的长文，需要补做取数与复现、并补齐图表（演讲通常不带完整参数与基线），边际成本是 6–12 人时（【推算】，§7.4；参数若还留在手边可降到 3–6 人时）。因此「先写后讲」几乎总是对的；「先讲后写」只在你讲的时候已经把完整参数与基线留了痕时才划算。

### 7.3 机制差异：为什么它们的表现不同

本节讨论的「机制」不是技术机制，而是**受众获取与信任建立机制**：内容怎么到人眼前、靠什么被相信、被什么放大。

#### 7.3.1 分发机制：检索、推送、邀请是三条不同的收益曲线

**机制是什么**：内容要抵达人，只有三条路径——人来找（检索）、系统推（推荐 / 订阅）、主办方请（邀请）。三条路径决定了收益曲线的形状，而形状比峰值更重要。

**实现差异**：

| 渠道 | 发现路径 | 收益曲线 | 峰值时点 | 尾部 |
| --- | --- | --- | --- | --- |
| 技术博客 | 检索 + 转发 | 累计分布 | 发布后数周 | 长（可被反复检索） |
| 开源项目 | 检索 + 被依赖 | 累计，且带网络效应 | 不稳定 | 长（可被采用与再分发） |
| 视频 | 推荐算法 + 检索 | 早期由推荐决定，后期转检索 | 发布后数天 | 中到长（可被搜索） |
| Podcast / Newsletter | 订阅推送 | 随名单线性 | 发布当天 | 短（无订阅则归零） |
| Conference | 主办方邀请 | 脉冲 | 现场那一刻 | 无（除非录播） |
| 内部分享 / 读书会 | 组织安排 | 脉冲 | 现场那一刻 | 无 |
| 直播 | 平台 + 通知 | 脉冲 | 开播那一刻 | 无（除非回放） |

**由此必然导出的性质**：因为博客有稳定 URL，且被搜索引擎与新一代检索式问答索引，所以它的收益是累计分布——同一篇文章在三年后仍可能被检索到，**投入的边际回报随时间上升**；因为 Conference 的听众是主办方聚起来的，所以它的收益在散场那一刻到达峰值然后衰减到接近零，**同样的准备成本只兑换一次**。这两条合起来推出一条可操作结论：**做现场型渠道时，必须同步产出沉淀型资产**（录播、逐字稿、配套长文），否则 28–48 人时的投入只换来一次脉冲；反过来，做沉淀型渠道时不必强求当期反馈，因为它的收益本来就不在当期。

**公开证据【公开】**：Rogers 在《Diffusion of Innovations》中给出的采用者分布（创新者约 2.5%、早期采用者约 13.5%、早期大众约 34%、晚期大众约 34%、落后者约 16%）说明受众被切成两类人：早期采用者接受「愿景」，早期大众要求「参考与同伴案例」（Rogers, 1962）。这解释了为什么技术布道必须两层并行——愿景内容（Conference / 视频）负责第一层，文档与开源（博客 / 仓库）负责第二层。跨越这两类人之间的断层是另一套论述（Moore, 1991）。行业侧的渠道结构变化也有公开痕迹：O'Reilly 于 2019 年停办 OSCON（O'Reilly 官方公告, 2019，可由其官网存档核验），说明单一现场型渠道的行业集中度在下降；而同期检索与订阅型渠道在扩张，该趋势可由任一技术内容的来源分析自行验证。

**内部渠道是一条被低估的分支**：组织内部的内容**不走公开检索**，走的是组织记忆。这导出一个反直觉的结论——因为组织记忆的载体是文档与录播，而不是「会上讲过」，所以**只做没留痕的内部分享，等于没做**：三个月后新入职的同事、转岗的同事、以及当时没被邀请的团队，都拿不到这份信息，于是同一个技术选型会在半年后被重新讨论一次。这就是为什么内部分享的正确产出不是「讲完了」，而是「留下了一份能被别人自己读完的材料」。

**失效条件**：当你的目标受众**只在一个封闭渠道里**（例如某公司的内部 IM、某个 200 人的 Discord），检索型渠道的价值大幅下降——他们不会去搜，只会在这个渠道里看到。判定方法：问一句「他们平时在哪看到技术内容」，答案指向哪一族，就先用哪一族。

#### 7.3.2 证据密度：布道的货币不是观点，而是可复现的证据

**机制是什么**：布道的目的不是「被看到」，而是让**对方愿意承担采纳风险**。采纳风险是他要花自己的时间、团队的排期、甚至线上的稳定性去试你的东西。能降低这个风险的只有证据。

**实现差异**：

| 渠道 | 能承载的证据形态 | 对方的验证成本 | 能改变什么 |
| --- | --- | --- | --- |
| 开源项目 | 可运行代码 + issue 历史 | 数十分钟（clone 后跑通） | 敢于在生产上试 |
| 技术博客 | 数据、参数、步骤、副作用记录 | 数小时（需复现） | 敢于在方案里写进去 |
| 技术视频 | 操作过程与画面 | 数十分钟（跟着做一遍） | 敢于自己上手 |
| Conference | 结论 + 少量图表 | 数天（要自己补实验） | 改变印象与优先级 |
| Podcast / 直播 | 判断与经验 | 无法验证 | 改变对该人的评价 |
| 内部分享 | 内部系统的真实数据 | 可直接印证 | 改变组织内的共识 |

**由此必然导出的性质**：因为观点不可复现，所以观点类内容最多改变「印象」，不能改变「决策」；而一个能 clone 下来跑通的仓库、一份带完整参数与基线的实验记录、一份「从 A 换到 B 的完整步骤与副作用」清单，把对方的试错成本从「数天」压到「数十分钟」——**采纳就发生在这个成本被压下来的那一刻，而不是在你讲得最好的那一刻**。这也解释了传声性：能被二手转述的，往往不是你的结论，而是你的证据（「他们那边用了同样的量级数据，成本从 X 档降到 Y 档，方法在这个链接里」）。因此**写方法不写版本号**：方法可以被别人拿去用，版本号三个月后就是错的（阈值推导见 §7.5）。

**公开证据【公开】**：Karpathy 的 zero-to-hero 系列（YouTube，2022 年起）被反复引用的原因不是观点，而是每一集都从零写下可运行的代码，观众可以自己跑出同样结果（Karpathy, YouTube, 2022）；这类内容的传播不依赖演讲席位，只依赖可复现性，可由播放与引用情况自行核验。反面的可核验信号同样公开：一个仓库的首次 issue 响应时间与 PR 合并时间完全可观测（任选仓库，用 issue 创建时间与首次回复时间之差即可算出），它是「是否真的可被依赖」的代理指标。

**失效条件**：当受众是**决策层**（不会亲手跑你的代码）时，证据密度的边际收益下降，此时「业务翻译」的权重上升——把证据折算成时间、成本与风险口径。判定依据只有一个：**对方会不会亲手执行**。会，就给证据；不会，就给口径。

#### 7.3.3 反馈带宽与信任类型：三种信任不可互换

**机制是什么**：不同渠道的反馈带宽差了几个数量级，而反馈带宽决定了你建立的是哪一种信任。

**实现差异**：

| 渠道 | 反馈带宽 | 建立的信任 | 典型转化 |
| --- | --- | --- | --- |
| 内部分享 | 高（可追问，同组织可验证） | 判断信任 | 平台上多一个业务方 |
| Conference | 中（现场提问、会后交流） | 人格信任 | 多一个愿意合作的人 |
| 开源 | 高但异步（issue / PR） | 能力信任 | 多一个生产采用者 |
| 博客 | 低（评论、转发稀疏） | 观点可见性 | 多一个读者 / 候选人 |
| Newsletter / Podcast | 极低（打开率是唯一信号） | 弱关系 | 多一个名单成员 |

**由此必然导出的性质**：因为现场渠道能实时追问，所以它检验并建立的是**判断与人格**（「这个人遇到反例时怎么反应」）；因为开源的反馈是「代码跑不跑得通」，所以它建立的是**能力信任**（「做出来的东西是否可靠」）；因为博客是异步且低反馈的，它建立的是**观点可见性**（「这个团队在想什么」）。三者的不可互换性有直接后果：**一场精彩的演讲不会让人敢在生产环境用你的库；一个 star 很多的库也不会让人相信你对行业趋势的判断**。因此在设计布道体系时，先问「我需要哪一种信任」，而不是「哪个渠道效果最好」。

**公开证据【公开】**：Guy Kawasaki 在 1980 年代担任苹果的「软件布道师」（software evangelist），其工作形态是现场演示与开发者面对面，而非发文档（Kawasaki,《Selling the Dream》, 1991），这体现了「人格信任靠现场」的早期形态。需要说明的是，「布道师」作为岗位在 Apple 的组织序列中出现于 1980 年代，通常归于当时 Apple 管理层的组织安排；Kawasaki 是这个角色最有名的实践者，也是把它推向公众视野的人，把「创设该岗位」直接归于他个人并非通行说法。反过来，开源侧的信任由可核验的工程信号构成——CNCF 对项目成熟度的判定包含「独立最终用户与跨组织贡献者数量」这类无法靠宣传获得的条件（CNCF 官方项目成熟度标准，可由其官网项目申请要求核验）。

**失效条件**：当受众已经决定要用你的东西、只缺文档时，反馈带宽不重要，沉淀型渠道就够——此时再去追求现场曝光是浪费。判定方法：如果最近三次对接的问题都是「怎么用」而不是「为什么要用」，说明你已经越过信任门槛。

#### 7.3.4 AI 只降低生成成本，不降低分发成本，也不产生证据

**机制是什么**：LLM 降低的是「把已有信息组织成文本 / 图像 / 语音」的边际成本。它不改变内容抵达人的路径，也不创造一手信息。

**实现差异**：

| 环节 | AI 能压缩吗 | 压缩幅度 | 备注 |
| --- | --- | --- | --- |
| 选题与判断 | 部分（可列候选，不能替你选） | 低 | 选题决定内容上限 |
| 取数 / 复现实验 | 几乎不能 | 近零 | 这是证据的唯一来源 |
| 写作与结构 | 能 | 高 | 真正的省钱位置 |
| 配图 / 排版 / 翻译 | 能 | 高 | 多语言布道的价值最大 |
| 分发与曝光 | 不能 | 零 | 渠道机制不因 AI 改变 |
| 被信任 | 不能 | 负（若出现无出处数字） | 一次追问即失分 |

**由此必然导出的性质**：因为生成成本在 2023–2024 年间出现了一个数量级以上的下降（【推算】：当代旗舰档与次代轻量档的公开定价相差约 50–67 倍，即约 1.7–1.8 个数量级，见下方公开定价），所以「结构完整但不含一手经验」的内容供给量急剧膨胀，其单位注意力价值随之趋零；而**供给无法被 AI 增加的部分（一手数据、真实踩坑、可运行代码）的相对价值上升**。这不是审美判断，是供需关系。它推出一条判据：**「要不要用 AI 写博客」是错误的问题，正确的问题是「我的哪一段内容 AI 造不出来」**——把产能花在那一段上，其余交给 AI。

**公开证据【公开】**：OpenAI 在 2023 年 11 月 DevDay 公布的 GPT-4 Turbo 定价为 $10 / 百万输入 token、$30 / 百万输出 token（OpenAI DevDay, 2023）；2024 年 7 月发布的 GPT-4o mini 为 $0.15 / 百万输入 token、$0.60 / 百万输出 token（OpenAI, 2024）。【推算】按这两个公开价格直接相除：输入 $10 → $0.15 是 66.7 倍，输出 $30 → $0.60 是 50 倍，即在约 8 个月内下降约 50–67 倍、约 1.7–1.8 个数量级——接近但不足两个数量级，这正是「观点变便宜」的量化来源。口径要说清：这是**跨档位**比较（当代旗舰 GPT-4 Turbo → 次代轻量档 GPT-4o mini），两者能力不同档，不能读成「同一能力的模型降价 50 倍」；同能力档位的降幅小于此。国内侧同一时期多家厂商把主力模型 API 压到每百万 token 一元级（DeepSeek 2024 年 5 月定价公告，可由各厂商官网历史定价核验）。

**AI 不承担署名责任**：内容一旦发布，署名的人要为它的每个数字负责。AI 没有可被追责的主体地位，因此它无法替你把「我确认过」这句话说出口。这看似是道德问题，实际是机制问题——读者判断内容可信度用的是**可追责性**（谁说的、错了会怎样），而不是文笔。所以 AI 参与度越高，你的校验成本越高，而校验恰恰是唯一不能被外包的环节。这与 [§ 7.3.2](#732-证据密度布道的货币不是观点而是可复现的证据) 的证据密度机制是同一件事的两面：AI 让生成变便宜，于是「谁确认过」成了唯一的稀缺信号。

**失效条件**：当内容的核心价值就是「结构」时（把散落的中文会议记录整理成可读纪要、把一份材料翻译成多语言受众可读的版本），AI 的收益巨大且真实。判定方法一句话：**把 AI 拿掉之后，这段内容是否仍然成立**——只是变难读，AI 是放大器；根本不成立（没有素材），AI 无关。

**四条机制维度的对照速查**（每行给机制依据与由它导出的最短结论，不给分数）：

| 方法 | 分发机制 | 载体证据 | 反馈带宽 | 复用性 | 由机制导出的最短结论 |
| --- | --- | --- | --- | --- | --- |
| 内部分享 | 组织安排（脉冲） | 内部真实数据 | 高（可追问） | 中 | 必须留痕，否则等于没讲 |
| 读书会 | 组织安排（脉冲） | 外部材料 | 高 | 低 | 目的是统一词汇，不是传播结论 |
| 技术博客 | 检索 + 转发（累计） | 数据与步骤 | 低 | 高 | 冷启动慢，但收益随时间上升 |
| Conference | 主办方邀请（脉冲） | 结论 + 少量图表 | 中 | 低 | 必须配沉淀物，否则只换一次曝光 |
| 开源 | 检索 + 被依赖（累计） | 可运行代码 | 高但异步 | 高 | 成本在长期运维，不在第一版代码 |
| Podcast | 订阅推送 | 判断与经验 | 极低 | 低 | 适合人物与判断，不适合教程 |
| 视频 | 推荐 + 检索 | 操作过程 | 低 | 中 | 平台算法决定受众，上手教学最优 |
| Newsletter | 订阅推送 | 观点 + 链接 | 极低 | 中 | 燃料是已有内容，先有内容再开渠道 |
| 直播 | 平台通知（脉冲） | 无剪辑的真实感 | 高 | 无 | 换真实感，代价是不可修订 |
| 业务翻译 | 一对一 / 一对多（定向） | 业务口径 | 高 | 中 | 面向决策层时优先于技术长文 |
| Storytelling | 依附于其他渠道 | 案例与冲突 | 依附 | 中 | 提升记忆与转述，牺牲精度 |
| 金字塔模型 | 编排层 | — | — | 高 | 决定上层渠道的边际成本 |
| AI 辅助 | 不改变分发 | 不产生证据 | 不改变 | 极高 | 只压缩写作与翻译，不压缩取数 |

### 7.4 成本结构对比（不是价格表，是成本函数）

```
布道总成本 ≈ Σ(渠道生产成本 ÷ 复用次数)
           + 持续运营成本 × 月数
           + 渠道门槛成本（演讲席位、差旅、录制设备、域名）
           + 事实错误的期望损失（可信度是不可逆资产）
```

**各渠道的主导项与隐性成本**：

- **内部分享 / 读书会**：主导项是准备时间与占用同事的会议时间；隐性成本是「没有议题的分享」会消耗听众的耐心，第三次之后就没人来了。
- **技术博客**：主导项是一次性生产；隐性成本是「为发而发」——为了节奏写没有新证据的文章，长期拉低整站的可信度。
- **Conference**：主导项是准备 + 差旅（真正的成本在差旅，不在 PPT）；隐性成本是**没有沉淀物**，回报只有一次脉冲。
- **开源**：主导项是固定投入（抽象、文档、CI、许可证、脱敏）；隐性成本是长期运维承诺——issue 不回比不开源更伤品牌。
- **视频**：主导项是后期与剪辑（每分钟成片约 1–2 小时，【经验】）；隐性成本是「平台算法决定你的受众」，你无法把观众带到别处。
- **Newsletter / Podcast**：主导项是持续性（断更等于归零）；隐性成本是增长慢，且名单不等于注意力。
- **直播**：主导项就是时长本身；隐性成本是无剪辑，说错的话被永久记录。
- **AI 辅助**：主导项近乎零现金成本；隐性成本是多一道事实校验，跳过这道校验就等于用可信度换速度。

**【推算】一篇深度技术博客的产能**：选题与资料 1–2 人时 + 取数 / 复现 3–6 人时 + 写作 2–4 人时 + 图表与校对 1–2 人时 = **7–14 人时**（【推算】；假设内容不直接来自正在做的工作，若来自已有工作，可减掉取数与复现项）。若同一份素材被 3 条渠道复用（博客 + 内部分享 + 演讲素材），摊薄后约 2.3–4.7 人时 / 次（【推算】）。

**【推算】一次 25 分钟 Conference 演讲的产能**：选题与提纲 3–5 + 素材与实验 8–16 + 制版 4–6 + 彩排 3 次 × 约 1.5 = 约 4.5 + 差旅与当天 8–16，合计 **28–48 人时**（【推算】，假设需要新做实验、且为跨城出差）。素材现成且同城时降到约 **15–20 人时**（【推算】：素材与实验由 8–16 降为整理已有素材的 1–2，差旅与当天由跨城的 8–16 降为同城的 2–3，即 3–5 + 1–2 + 4–6 + 4.5 + 2–3 ≈ 15–20）。**由此得出一条硬规则：先有沉淀物，再把它改成演讲**——方向上，长文改演讲的边际成本只有 3–5 人时（压缩与取舍，不必再取证）；反过来，一场没有留下参数与基线的演讲要补成有证据的长文，边际成本是 6–12 人时（取数与复现 3–6 + 写作 2–4 + 图表与校对 1–2，正好是首次生产的 7–14 人时里省不掉的项）；若演讲内容就是你手头正在做的事、参数随时可取，这一项回落到写作与配图的 3–6 人时（【推算】）——这是内部分享转长文比 Conference 转长文便宜的机制原因。

**【推算】开源的固定成本**：把一件业务代码抽象成可开源项目，需要脱敏、README / Quick Start、示例、CI、许可证、发布流程，按 1 人 × 2–3 个月、每月约 160 人时投入推算，约 **300–500 人时**起步（【推算】）。这解释了为什么「把开源当布道手段」对个人和小团队通常不划算——**除非你要开源的东西本来就存在于日常工作里**（内部工具的自然抽象），否则这 300–500 人时是从零支出的沉没成本。

**【推算】AI 辅助的省钱位置**：一篇文章 7–14 人时里，写作与校对占 3–6 人时。AI 把其中约一半压缩（【经验】），节省约 1.5–3 人时，**占总量的一到两成**，不是「数倍提效」。省下来的时间应当投到取数与复现上——那部分是 AI 帮不了的，也正是证据的来源。

**一项不写进公式的隐性成本：可信度折旧**。布道的所有成本项里，只有这一项是**不可逆**的——加班可以补，稿子可以重写，但一个被引用过的错误数字会长期留在别人已经转发的内容里。它的期望损失 = 错误概率 × 传播范围 × 修复难度，而三项里只有第一项你能控制（靠校验清单）。因此成本函数的形式给出一条纪律：**在证据类内容上，宁可少发一篇，也不要发一篇数字没出处的**——因为前者损失的是频率，后者损失的是可核验性，而可核验性正是 §7.3.2 里唯一能推动采纳的东西。

### 7.5 决策树（每个分支都要有阈值依据）

```
你手里有什么？
├─ 有正在做的工作（代码 / 数据 / 踩坑记录）
│    ├─ 只想沉淀认知 → 技术博客（写成「我们怎么做 + 数据 + 副作用」）
│    ├─ 想让别人能用 → 开源（先把内部工具抽象出来）+ 一篇配套长文
│    └─ 要拿去讲 → 先写成文再改提纲（长文改演讲的边际成本 3–5 人时，反向补成长文 6–12 人时，见阈值依据「先沉淀后现场」）
├─ 只有观点与方法论
│    ├─ 受众在内部 → 内部分享 / 读书会（能追问，成本最低）
│    └─ 受众在外部 → 先补一次实验或一次取数，再考虑对外发布
└─ 什么都没有、只有时间
     └─ 先做族 1：写 3–5 篇有你署名的一手技术分析。没有沉淀层，上层渠道全是空转

你的目标在哪一层？
├─ 内部采纳（业务方用你的平台）→ 业务翻译 + 内部分享 + 文档（主渠道是文档）
├─ 团队品牌（招人、跨团队影响力）→ 博客（团队署名）+ 开源 + 少量 Conference
├─ 个人 IP → 博客或视频（选一个主渠道）+ 稳定输出 + 少量 Conference
└─ 行业影响力 → 开源 + Conference + Newsletter（三者互为正反馈）

你的稳定产能是多少？（按 §7.4 的人时估值换算）
├─ 每周 < 4 人时 → 只做复用型内容（把已有工作写成文），不开新实验
├─ 每周 4–10 人时 → 一个沉淀型主渠道 + 每月一次内部分享
└─ 每周 > 10 人时 → 可加一个订阅型渠道，但前提是主渠道已稳定 6 个月

你的内容会因版本迭代而过期吗？
├─ 会（涉及具体版本号、API、模型名）→ 以速查表 / 教程形式发布，接受短半衰期
└─ 不会（方法、判据、踩坑模式）→ 做成可被长期引用的资产，投入更多打磨
```

**阈值依据**：

- **「每周 4 人时」**：来自 §7.4 的产能推算。月更一篇按 4.3 周计，需要每周 1.6–3.3 人时；「4 人时」是「月更能长期维持 + 有余量应对一次深度实验」的下限（【推算】，假设月更一篇；若改为双周更，阈值翻倍）。
- **「稳定 6 个月」**：来自沉淀型渠道的冷启动结构——收益是累计分布，前几个月接近零，多数人在看不到反馈时放弃。6 个月是「能看到第一批检索来源与订阅增长信号」的经验区间（【经验】），可由自己博客的搜索来源数据核验，不是平台规定。
- **「内容半衰期」**：依据可核验的发布节奏——Kubernetes 近年约每年 3 个 minor 版本（Kubernetes 官方发布记录）；Python 自 PEP 602 起改为年度发布（3.9 起，2020）；模型侧更快，OpenAI 已公告旧模型于 2024-01-04 关停（OpenAI, 2023）。因此**涉及版本号的内容半衰期以季度计，涉及方法与判据的内容以年计**——写方法，版本号放附录。
- **「先沉淀后现场」**：来自 §7.4 的搬运成本不对称——长文压缩成提纲的边际成本 3–5 人时，而演讲补成有证据的长文是 6–12 人时（两者都是【推算】，分项见 §7.4）。树上对应的节点是「你手里有什么 / 要拿去讲」这一支。
- **「开源前先抽象」**：来自门槛成本推算（300–500 人时）。只有当它本来就在你的日常工作里时，这笔投入才被摊薄。
- **「每周 > 10 人时」**：经验值，含义是「主渠道之外还有余量」。判定方法不是数小时，而是**主渠道是否连续 6 个月未断更**——断更状态下加渠道等于两个都做不成（【经验】）。
- **「3–5 篇」**：这是「能被检索与推荐识别为一个持续来源」的最低样本量——单篇是孤例，站点的来源数据要积累到几篇才会出现可辨认的模式；按 §7.4 的 7–14 人时 / 篇，3–5 篇约 21–70 人时，在月更节奏下对应 3–5 个月，与「稳定 6 个月」同量级（【经验】）。判定方法不是数篇数，而是看自己站点的来源分析：第几篇开始出现稳定的外部检索来源，那个序号就是你的下限。

**这棵树刻意不覆盖的分支**：

- **「要不要做个人 IP」**：这是目标不是手段。判定方法是看结果而非意图——过去 12 个月里，有多少人是因为看过你的内容主动来找你；答案是零，就说明问题在族 1 缺位，而不在「是否经营 IP」。
- **「要不要买流量 / 投广告」**：付费分发改变的是触达数量，不改变证据密度。判定方法：把付费去掉后，内容是否仍被转发；不转发说明它本身不可转述，买来的曝光不会二次传播。
- **「用哪个具体工具（Notion / Substack / 某视频平台）」**：工具只改变生产的便利度，不改变分发机制与信任类型。判定方法同上：换工具后，内容的来源构成是否变化。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因（机制层面） |
| --- | --- | --- | --- |
| 平台要业务方接入 | 内部分享 + 文档 + 业务翻译 | Workshop / 认证培训 | 只发对外博客＝内部受众不在检索路径上 |
| 招人（团队品牌） | 团队署名博客 + 开源 | Conference 演讲 | 只靠演讲＝脉冲，候选人搜不到你 |
| 个人 IP 起步 | 一个沉淀型主渠道（博客或视频） | 直接做 Newsletter | 名单从零开始，没有内容可喂 |
| 想推进一个技术标准 | 开源 + 参考实现 + 长文 | Podcast / 直播 | 只有观点＝对方不敢在生产上用 |
| 拿到一手大案例（如降本、迁移） | 长文 + 内部分享 + 一次演讲 | 视频教程 | 只做视频＝把可引用性换成了观看量 |
| 已有成熟内部工具 | 抽象后开源 + 配套长文 | 只写博客介绍 | 只写博客＝对方要自己重写，采纳成本没降 |
| 面向决策层 | 业务翻译 + 一页数字 | 技术长文 | 决策层不看细节，看口径与风险 |
| 面向工程师同行 | 可运行代码 + 实验数据 | 纯架构图讲解 | 无复现路径＝无法验证 |
| 时间极少（每周 < 4 人时） | 复用已有工作写文 | 内部分享 | 开新实验＝必然烂尾 |
| 多语言受众 | AI 翻译 + 人工校对 | 只做中文 | 只做中文＝放弃可被检索的另一半受众 |
| 内容含大量事实数字 | AI 出结构、人出数字 | 全文 AI 生成 | 无出处数字＝一次追问即失分 |
| 举办内部大会 | 内部分享 + 录播沉淀 | 只做现场 | 无录播＝一次投入换一次脉冲 |

**常见组合**（原决策树里那条「资源足 → 多模式组合」的「多模式组合」，指的就是本节这几条组合的统称；每条注明职责边界与运维代价）：

- **博客（沉淀）+ Conference（放大）**：博客负责可被检索与引用，Conference 负责把判断与人格快速传达给一批人；两者的素材应当同源——CFP 的提纲由已有长文改写而来。边界是**在场讲的东西必须有对应的书面版本**，否则现场听众无法回头核验。代价：需要维护「同一内容两种形态」的同步。
- **开源（证据）+ 视频（上手）**：仓库负责可验证，视频负责把上手时间压到最短。边界是 README 必须能在 5 分钟内跑通——视频不能代替 Quick Start。代价：两套材料的版本必须一起更新，否则视频会教你用已被改掉的 API。
- **内部分享 + 业务翻译**：内部分享解决「知不知道」，业务翻译解决「值不值得」。边界是翻译要用对方的指标口径，不是你的技术口径。代价：需要提前拿到对方的业务数据，准备期更长。
- **Newsletter / Podcast（订阅）+ 博客（沉淀）**：订阅负责触达与提醒，博客负责被引用。边界是订阅渠道提供的是**入口**而不是**内容**——把订阅当作内容容器，会让你的内容被困在平台里。代价：需要长期维持节奏，断更两次后打开率不会再回来（【经验】）。
- **AI 辅助 + 人工证据**：AI 负责结构、措辞、翻译、配图，人负责数字、判断、一手经历。边界是「每一个进入正式内容的数字都有出处」。代价：多一道校验；跳过它就等于用可信度换速度。
- **内部分享 + 录播 + 文档（内部闭环）**：现场负责对齐与追问，录播与文档负责跨时间、跨批次传播。边界是**回放必须可被单独读懂**（不依赖现场气氛与口播补充）。代价：多一道录制与整理；不做的代价更高——同事会在半年后重新讨论同一个问题。

组合只有一条原则：**每一件都要说清它覆盖哪一段，以及它失效时谁来兜底**。以下几组组合的兜底必须提前想清楚，而不是出事时再找。「博客 + Conference」里 Conference 失效（拿不到席位）时，兜底是博客继续积累；「开源 + 视频」里视频失效（没时间剪）时，兜底是 Quick Start 与示例仓库；「AI + 人工」里 AI 失效（生成的内容事实错误）时，兜底是校验清单——而这条兜底如果本身也靠 AI，就等于没有兜底。

### 7.7 选错的代价与迁移成本

**反模式：把「没时间」当成不做沉淀的理由，只做现场** —— 症状：一年讲了 10 场分享，博客三年没更新，团队网站还是空的 → 后果：每一场都从零准备（28–48 人时 / 场），收益全是脉冲，外部搜不到任何可引用的东西，招人时拿不出作品集 → 正确的做法：把每场分享按 §7.4 的边际成本改写成文章（【推算】）——参数还在手边时为 3–6 人时，没留痕就要补到 6–12 人时，让每次现场投入同时生产一份沉淀资产。

**反模式：用 AI 生成「技术观点」而不含一手证据** —— 症状：产量很高，每周三篇，内容是综述式的行业趋势 → 后果：在同质化供给里没有区分度（因为生成成本对所有人都下降了），一旦被追问细节就暴露，且内容无法被别人引用（引用需要可验证的事实） → 正确的做法：AI 只压缩写作与结构，产能余量全部投给取数与复现——**供给无法被 AI 增加的部分才是差异化的唯一来源**。

**反模式：把开源当作「做一次就完事」的布道动作** —— 症状：把一段内部代码匆忙开源，README 只写了两行，issue 无人回复 → 后果：300–500 人时的固定投入变成沉没成本，且「不回 issue」的负面信号比不开源更强（外部能看到响应时间，见 §7.3.2） → 正确的做法：开源前先确认有长期运维人时（或明确标注为「不接受 PR 的示例仓库」），把承诺边界写进 README。

| 从 → 到 | 内容迁移 | 渠道重建 | 组织流程改动 | 团队再学习 | 工作量量级 |
| --- | --- | --- | --- | --- | --- |
| 只有现场 → 增加沉淀层 | 需把历史分享改写成文 | 建博客 / 仓库 | 低（发布流程） | 中（写作规范） | 中（数周到数月） |
| 只有沉淀 → 增加现场 | 需从既有内容提炼提纲 | 需 CFP / 内部排期 | 中（评审与预算） | 中（演讲训练） | 中（每场 28–48 人时） |
| 只做博客 → 增加开源 | 需业务代码抽象与脱敏 | 建仓库与 CI | 中（法务与许可） | 高（开源协作方式） | 高（300–500 人时起步） |
| 无 AI → 有 AI 辅助 | 无（产能内部转移） | 无 | 低（校验清单） | 低 | 低 |
| 有 AI → 建立证据纪律 | 需回溯已有内容的数字出处 | 无 | 中（发布前校验） | 中 | 中 |
| 个人布道 → 岗位化布道（背采纳率） | 需把内容变成采纳材料 | 需采纳率看板 | 高（岗位与指标） | 高 | 高（见本书 §6） |

迁移有一条常被忽略的约束：**沉淀型资产的迁移速度由内容生产速度决定，不由渠道决定**。建一个博客站是一个下午的事，但让它在检索里产生稳定来源需要持续数月的产出——所以「我要开始写博客」的正确版本是「我先把手上这三件事各写一篇」。

可操作的迁移顺序是「**先沉淀，再分发，最后放大**」：第一段把已有工作写成 3–5 篇有一手证据的长文（成本低、可复用、是后面一切的地基）；第二段把一个主渠道做成稳定节奏，并把内容用现场渠道（内部分享 / Conference）放大（成本中等，收益可复用）；第三段才上订阅型渠道与开源（成本最高，且前两段没做时基本无效）。顺序颠倒的典型症状是「开了播客 / Newsletter，三个月后停更」——因为它的燃料（可说的内容）来自第一段，而第一段从未被建立。

这个顺序有一个边界要说清：**它描述的是普遍情形，不是绝对规则**。存在两类例外，且各有前提。第一类是「先现场后沉淀」——当你的工作本身就是高频对外交付（售前、咨询、客户支持），现场素材每天都在产生，把它们录音转写再整理成文，比专门写文章便宜，此时顺序可以反转，前提是**每次现场都留了数据与录音**。第二类是「先开源后写文」——当你要布道的对象本来就是一件工具（内部平台、SDK），README 与 Quick Start 本身就是主要内容形态，长文只是它的补充，此时不必先写文。判断例外是否成立的统一标准仍只有一条：**你手里是否已经有可搬运的素材**——有，任何顺序都能省成本；没有，任何顺序都要先做取数。

### 7.8 小结

| 你的处境 | 建议 | 关键理由（机制层面） |
| --- | --- | --- |
| 手里有一手工作成果 | 写成博客（数据 + 步骤 + 副作用） | 证据密度是唯一能降低对方采纳成本的东西 |
| 想让别人直接用 | 开源 + Quick Start + 长文 | 代码是可执行证据，验证成本压到数十分钟 |
| 受众在内部、要推动采纳 | 内部分享 + 业务翻译 + 文档 | 现场可追问（人格信任）+ 口径对齐（改变决策） |
| 受众在外部、要建影响力 | 沉淀型主渠道 + 少量 Conference | 检索型是复利，现场型是脉冲，前者保底后者放大 |
| 每周产能 < 4 人时 | 只做复用型内容，不开新实验 | 一篇深度文 7–14 人时，开新实验必然烂尾 |
| 内容含大量数字与事实 | AI 出结构，人出数字 | 事实错误是不可逆的可信度损耗 |
| 想招人 / 建团队品牌 | 团队署名博客 + 开源 + 招聘页互链 | 候选人先搜到的是可检索的资产，不是你的演讲 |
| 想推动行业标准 | 参考实现 + 规范文档（开源）+ 会议 | 只有观点无法被采用，规范与实现可以 |
| 想做多语言受众 | AI 翻译 + 人工校对 + 同源发布 | 翻译成本被 AI 压到近零，是 AI 最真实的省钱位置 |
| 想做 Newsletter 但没有素材 | 先积累 20–30 篇长文再开（【推算】：周更按每年 52 期、每期由一篇长文同源改写计，20–30 篇约支撑 5–7 个月） | 订阅渠道的燃料是内容，先开渠道必然断更 |
| 分享做得多、沉淀做得少 | 分享当天就留参数，会后按 3–6 人时（【推算】§7.4）补成文 | 现场收益是脉冲，改写把同一份准备变成资产 |
| 打算开源内部工具 | 先确认长期运维人时与承诺边界 | 固定投入 300–500 人时，且不回 issue 比不开源更伤 |

回到本章 6 条判据里权重最高的两条：**证据密度**决定你能否改变别人的采纳决策（观点免费之后，一手证据是唯一稀缺品），**分发机制**决定这份证据的收益是复利还是脉冲（检索型累计、现场型归零）。其余判据——单位产能、反馈带宽、时间衰减、复用性——都服务于这两条。

本章与原文件最大的方法论差别是：原文件给的是**结论**（一张评分表和一棵决策树），本章给的是**推导**——为什么现场型渠道必须搭配沉淀型资产、为什么 AI 只压缩写作而压缩不了取数、为什么开源的成本不在代码而在长期承诺。结论会随工具与平台变化，推导不会：任何新渠道（无论叫短视频、AI 播客还是一年后的新形态）都可以用同一套判据重新评估——**它改变分发机制了吗？它承载证据吗？它把我的产能花在哪一段？**

> 本节小结：这些方法之间唯一真正起决定作用的差异是**「它能不能承载一手证据」**——同样 20 人时的投入，能承载证据的渠道（博客 / 开源 / 教程视频）会转化为采纳，不能承载证据的渠道（纯演讲 / 纯 Podcast / 纯观点）只转化为印象；而印象是否兑现，取决于对方是否刚好在找你。其余差异（做不做视频、上不上 Newsletter、用不用 AI）都是这条主轴的下游选择。
