## 5. 前沿演进（AI 时代）

### 5.1 先分清三类「前沿」

1. **机制变了**：链路里某个环节换了工作原理（摘要从"抽取式"变成"生成式 + 引用回指"；分类从"关键词规则"变成"语义分类 + 标签体系"；去重从"指纹"变成"向量相似 + 事件簇"）。**这类变化影响架构决策。**
2. **接口与规范变了**：信源侧的开放接口、内容的标识与元数据规范（例如 AI 生成内容的标识要求）在演进【公开：以该项规范的官方文本当前版本为准】。**这类变化影响合规与分发。**
3. **只多了产品**：同一套能力换包装。**只在选型表里体现。**

判别方法仍是那一句：**"换一家厂商，这条结论还成立吗？"**

### 5.2 判据与分级

沿用三条 L1 判据：**① 已 GA 且有正式文档 / 发布条目**；**② 有第三方（非厂商）公开的生产案例**；**③ 接口稳定、可预期**。

| 演进方向 | 级别 | 机制变了什么 | 判据落点（可否自行核验） |
| --- | --- | --- | --- |
| 端到端情报流水线（采集 → 分发闭环） | **L2** | 从"抓取 + 关键词推送"变成"分级信源 + 事件簇 + 带出处的摘要 + 频控" | ① 成立（商业情报产品与内部平台的文档条目可核）；② **核不到**（生产细节与质量数据几乎都是建设方自述）；③ 成立 |
| 生成式摘要 + 引用回指 | **L2** | 摘要从"抽原文句子"变成"生成 + 事实点指回片段" | ① 成立（检索增强生成类能力的文档条目可核）；② **核不到**（摘要正确性的公开数据几乎都来自建设方）；③ 成立 |
| 语义分类 + 标签体系 | **L2** | 分类从关键词规则变成"规则硬信号 + 模型语义"的混合 | ① 成立；② 核不到；③ 成立 |
| 向量去重与事件簇 | **L2** | 去重从"文本指纹"变成"相似度 + 时间窗 + 主体动作" | ① 成立（向量检索与相似度判定是成熟条目）；② 核不到（阈值与窗口的经验值无公开可比值）；③ 成立 |
| 事件与实体抽取的 Schema 化 | **L2** | 抽取从"自由文本摘要"变成带 Schema 的结构化结果（含片段位置） | ① 成立（结构化输出是正式能力条目）；② 核不到；③ 成立 |
| 多模态情报（音视频 / 图文 / 图像情报） | **L2** | 情报的输入从文本扩到多模态，编码能力是前提 | ① 成立（多模态模型能力条目可核，见 [§01](../01-multimodal-ai/01-multimodal-ai.md)）；② 核不到；③ 部分成立（跨模态的检索与对齐仍有差异） |
| Agent 自主采编（模型自己决定抓什么、写什么） | **L3** | 从"人定信源与口径"变成"模型自己选择与组织" | ① 只有演示与自研；② 核不到；③ 不成立（**责任无法归属**：错误的采编决策由谁负责无通行做法） |

**本节没有一行达到 L1**——卡点同样在 ②：**情报链路的公开材料几乎都是建设方自述**（来源清单、误报率、摘要正确性这类数据极少公开）。因此这一层的成熟度应按"**机制可验证、效果不可验证**"理解：接口与机制你可以核验，**质量必须用你自己的抽检与样本集去量**。

### 5.3 演进方向逐条拆解（核心节）

下面六个方向（§5.3.1–§5.3.6）按**同一套结构**写：**旧做法与它的卡点 → AI 改变了什么机制 → 由此得到的 → 由此付出的 → 证据与来源 → 成熟度**（判定方法与适用条件另列）。它们各自的级别见 §5.2 的那张表——**表给结论，本节给机制**；只写收益不写代价的方向，在评审时应被直接打回。§5.2 表首行的「端到端情报流水线」是总括行，它对应的是本节小结（§5.8）而不是某一个部件，因此不单列单元。§5.3.7 把同一套结构反过来用：遇到本节没列到的新名词，用那三步自己判。

#### 5.3.1 摘要：从"抽取式"到"生成 + 回指"

- **旧做法与它的卡点**：抽取式摘要拼接原文句子，不会编，但读起来割裂、限定词与上下文被丢。真正的卡点是**"好读"与"可信"被当成了同一件事**——于是团队去优化流畅度，而流畅的改写恰好会抹掉"据称 / 尚未确认"这类可信度载体（§6.2 的背景段把它列成第一条）。

- **AI 改变了什么机制**：生成式摘要不再拼接句子，而是**生成表达并给每个事实点挂上出处片段**。机制性的变化不是"模型更强"，而是**摘要从"一段文本"变成一个"带位置的结构"**——因此流水线要传片段位置、存储要能按片段回溯、回查要能访问原文（§4.2（6）的摘要模板与 §4.5 模板 1）。这三项是"换生成式摘要"的真实前置条件，比换模型重要得多。

- **由此得到的**：信任的验证成本从"读者去读原文"降到"点开一个位置"；数值 / 日期 / 主体可以做机械化回查，**回查不通过就不写进摘要**（§3.2.6、§4.5 模板 1 的 `value_appears_in_span`）。可点开验证因此成为本主题唯一能把摘要送进决策流程的准入条件——§6.7 把"可验证率"单列为**准入性收益项**，说的就是这件事。

- **由此付出的**：必须保留片段映射（存储与处理成本上升）；回查规则要按领域维护单位换算与口径改写（亿元 → 万元、同比 → 环比、指代替换），不做规范化就只能做"原文里有没有这个字符串"的弱回查（§3.2.6 的代价段）；**降级路径也被这条约束住了**——模型端点故障时只能降成"抽取结果 + 原文链接"，不能降成"无出处的自由生成"（§4.7 容灾演练表的"降功能不降可信"）。**另有一条硬规则不能省**：生成式摘要**必然**引入幻觉，因此"回查不通过的数字不写进摘要"不是优化项——**省略它，等于把链路可信度交给模型**。

- **证据与来源**：【公开】生成式摘要所依赖的检索增强生成类能力有版本化文档可核；摘要的事实性度量在全书他处有具名框架——`04-data-assetization/05-rag-architecture` 的 §1.4 记 RAGAS 于 2023.10 发布，同章 §4.3 与 §5 的分级表把 2025 年的评估体系写成 RAGAS / TruLens / ARES / DeepEval，指标含 `faithfulness` / `groundedness`，并明确"忠实性在各框架里的定义不同、跨框架分数不可比"。【经验】"每周抽 20 条摘要逐条核对数值 / 日期 / 主体"这个抽检量与单条约 5 分钟、合计约 1.7 小时/周，是本主题 §6.2 给出的档位（【推算：20 × 5 分钟 ÷ 60】）。

- **成熟度**：**L2**。判据 ①（已 GA 且有正式文档 / 发布条目）成立——生成能力与评估框架都有版本化文档；判据 ②（第三方非厂商公开生产案例）**不成立**，摘要正确性的公开数据几乎都来自建设方、且无统一评测集（§5.2 表第二行、§5.5 第 2 条）；判据 ③（接口稳定、可预期）成立。动作：排进试点但不进架构约束，退出条件写"抽检可验证率连续两个周期不升即停"（§5.3.7 的三步法）。

- **判定方法**：抽 20 条摘要，逐条把每个数值 / 日期 / 主体点回片段——**能点开、且片段确实支持该事实点的比例**就是这个方向是否真落地了的证据（与 §3.2.6 的判定方法同一动作）。

- **什么时候值得做**：摘要已经（或将要）被拿去做判断时——不可验证的摘要在决策场景里是负资产，它比"没有摘要"更危险（§6.2 的失败教训）。

- **什么时候不值得做**："每周抽检 20 条"这个人力还没排进期时——先排抽检，再谈生成式摘要；否则你只是把幻觉的正文换成了更流畅的幻觉摘要。

#### 5.3.2 分类：从关键词到"规则 + 语义"

- **旧做法与它的卡点**：关键词规则对"同义不同词"与"同词不同义"都无解——**同义漏报与同词误报同时存在**，且误报会随规则变宽而累积（主文件 §1.4 的 2010s 阶段与 §3.2.5 的约束段写的就是这一对）。

- **AI 改变了什么机制**：判别从"一个判别器"拆成两层——**规则层负责必须命中的硬信号**（文号、代码、主体白名单，保证可解释与必命中），**模型层负责在标签体系内做语义归类**。机制变化的关键不是模型精度，而是两件连带的事：**标签体系成为必须先立的对象**（没有它就无法量误报，因为不知道"应该有哪些类别"，调阈值也无从下手），以及**误报第一次可以归因**（落到"哪条规则过宽"或"哪个标签阈值过低"）。

- **由此得到的**：硬信号判断可复述，语义判断可带置信度——**两类判断各用它自己需要的可解释性标准**（§3.2.5 的机制段）；误报从"只能忍受的常数"变成"可以一轮一轮改下来的量"（§7.3.4）。落成配置就是 §4.2（5）的 `priority: hard|soft`、按标签分设的 `model.threshold`，外加 `attribution` 三个字段。

- **由此付出的**：两套逻辑要维护；标签体系必须有 Owner 与增删流程，否则标签膨胀到无法归因——**可测信号是"新增标签的速度持续高于归档标签的速度"**（§3.2.5 的代价段）。还有一条边界不能越：**规则层不会被模型替代**（同名不同公司这类误报模型也难判，必须有主体白名单），两者是分工而不是替换。

- **证据与来源**：【公开】规则 + 模型 + 人工复核的分工在全书他处有具名形态——`01-modeling/09-one-id` 的 §7.2 把托管实体解析服务写成"服务商提供候选生成、匹配规则 / 模型与人工复核工作台，客户只做字段映射"；`11-cross-cutting/01-data-quality` 的 §4.3 工具链表把「AI 辅助能力（非独立品类）」单列一行（Mona AI Quality Copilot / Anomalo Autonomous / Monte Carlo + LLM 一类），用法是生成规则草稿与异常归因，并写明"生成的规则必须经复核才能进 P0"。【经验】"标签增速高于归档速度"这条可测信号与阈值按标签分设的做法，出自本主题 §3.2.5 与 §4.2（5），无公开数值可比。

- **成熟度**：**L2**。① 成立（分类与结构化输出有正式能力条目与版本化文档）；② **不成立**（§5.2 表第三行：核不到第三方非厂商生产案例）；③ 成立。**这里的 L2 只标证据缺口**——语义分类今天就能用，降级不改变这一点。

- **判定方法**：抽 20 条被判为误报的情报，逐条填"命中了哪条规则"或"哪个标签的多少分"——答不出来的那部分就是还没有归因字段（同 §3.2.5 的判定方法）。

#### 5.3.3 去重：从指纹到事件簇

- **旧做法与它的卡点**：指纹去重只能抓"完全相同的正文"，抓不住跨源转载与改写；而**分发单位仍是素材**，于是重复只能靠"每次再判一次"去拦——判一次错就重复一次（§6.1 的两种单位对照图把这两种世界画在一起）。

- **AI 改变了什么机制**：去重的单位从"素材"变成"事件簇"（相似度 + 时间窗 + 主体动作日期三元组，§4.2（3））。这里要看清两层：**跨源语义相似是靠向量能力才做得成的**（这是 AI 那一半），但**真正消除缺陷的是结构的那一半**——这是本主题里少见的"**用结构而不是用判断消除一类缺陷**"：判断型去重每次都要重新决定，结构型去重只要归簇正确，重复在机制上不可能发生（§3.2.4 的机制段）。

- **由此得到的**：分发键改成簇标识之后，"同一件事推几遍"这个问题在结构上消失；同簇多来源可以保留为可信度信号（"这件事被几家独立确认"），而对簇只需摘要一次、分类一次——§4.6 算例里摘要量降到素材量的百分之十几到三成，正是这条的直接账目。

- **由此付出的**：阈值与时间窗必须按事件类型分别标定（并购类可到数天、行情类分钟级），这需要按类型积累标注样本，成本随类型数增长（§3.6 跃迁表末行）；**误合并的代价是不对称的**——重复只是"用户烦"，误合并是漏报，因此阈值要偏向"宁可不合"，并同时评估同簇准确率与拆分准确率（§3.2.4、§4.2（3））；簇**会生长**，还要额外定义"补充推送 / 只更新不重推"的规则（§5.3.3 原有的这条边界，落到 §6.4 的簇生长规则）；**另一条边界是向量去重的能力上限**——它对"同一事件的不同角度报道"效果有限，**不要把"不同角度"当成"不同事件"**（合并它们同样是漏报）。

- **证据与来源**：【公开】向量检索与相似度判定是成熟条目（§5.2 表第四行 ① 成立）；同一族问题在全书他处以实体解析产品化——`01-modeling/09-one-id` 的 §7.2 把「托管实体解析服务」写成一行，列出 AWS Entity Resolution、Salesforce Data Cloud、Palantir Foundry、阿里云实体解析，§4 的产品表把 Palantir Foundry Entity Resolution 记为"图原生 + Ontology"。**但那讲的是主数据身份，不是外部事件归簇，引用时不可互相替代**。【经验】θ 与窗口按事件类型标定的取值方向（并购数天 / 行情分钟级）与"拆分准确率比同簇准确率更该盯"这条判断，出自本主题 §4.2（3）与 §3.2.4，无公开可比值（§5.2 表第四行 ② 核不到）。

- **成熟度**：**L2**。① 成立；② **不成立**（阈值与窗口的经验值无公开可比值）；③ 成立。补一条 L2 在本主题的特殊含义：这里缺的是"别人在生产里用过并公开说了代价"的材料，**不是能力**。

- **判定方法**：抽样 100 组被判为同簇的素材，同时算同簇准确率与拆分准确率——只报前者会系统性高估质量（同 §3.2.4 的判定方法）。

#### 5.3.4 抽取 Schema 化：把"摘要"变成"带位置的结构"

- **旧做法与它的卡点**：抽取结果停在自由文本里，于是"按主体查历史事件""统计某类事件频次"只能靠全文检索加人工翻；更要紧的是，**摘要一旦是纯文本，回指与数值回查就无处挂载**（§3.2.6 的机制段讲的就是这条依赖）。

- **AI 改变了什么机制**：实体与事件以 Schema 约束输出（主体、动作枚举、金额、时间、片段位置，§4.2（4））。机制变化不是"抽得更准"，而是**抽取产物从"文本"变成"可查询对象 + 可回指坐标"**——`source_span` 与 `span_start, span_end` 这一类字段，是它同时服务摘要回指与数值回查的那个接口。

- **由此得到的**：事件表 / 关系表成为普通查询的对象，"按主体查历史"不再需要重新跑一遍模型；这也是情报与 [Ch1 §06 知识图谱](../../01-modeling/06-knowledge-graph/06-knowledge-graph.md) 对接的接口（见 §5.4 的接口表第 3 行）；对簇抽取一次即可，**成本随归簇收敛而不随转载数放大**。

- **由此付出的**：**Schema 越细，抽取越脆**——新事件类型会被塞进错误的槽位；因此判据是"Schema 变更有版本与兼容策略"，而不是"字段越多越好"（§5.3.4 原有的边界）。另有一条常被低估的实现代价：**动作枚举的每一次增项都要同时过抽取与分类两侧**，它不是纯配置改动。

- **证据与来源**：【公开】结构化输出是正式能力条目、有版本化文档（§5.2 表第五行 ① 成立）；Schema 化的下游出口在全书他处是知识图谱——`01-modeling/06-knowledge-graph` 的 §4 把"批量抽取由 Airflow / DolphinScheduler 调度"写成常态，同章 §8 记"每日 / 每周批量补全历史数据"。【经验】"Schema 越细越脆、动作枚举增项要过两侧"这一判断出自本主题 §5.3.4 与 §4.2（4），无公开数值。

- **成熟度**：**L2**。① 成立；② **不成立**（§5.2 表第五行）；③ 成立**但附带条件**——版本化与兼容策略到位才算成立，否则 Schema 变更本身就是一次静默的召回退化。

- **判定方法**：从结构化库里挑一条事件，问三个问题——"它的动作落在哪个枚举值、它的片段位置在哪、它按哪一版 Schema 抽的"；**答不出 Schema 版本，就说明变更还没有版本与兼容策略**，此时"字段越多"只会让召回退得更静默。

- **什么时候值得做**：要把情报接进"按主体查历史"这类查询，或要接知识图谱时——这是那两件事的接口，没有它就只能重新跑模型。

- **什么时候不值得做**：还没有稳定的事件类型清单时——先把 §3.2.5 的标签体系立起来，Schema 的形状是从标签与动作枚举里长出来的，反着做会频繁改 Schema。

#### 5.3.5 多模态情报：输入侧的扩充，不是链路的重写

- **旧做法与它的卡点**：情报输入只有文本（公告、研报、新闻），会议录音、监管直播、图片公告这类信息只能靠人听人看——**覆盖窄且不可扩展**（主文件 §1.4 的人工简报阶段就是这么运行的，而它的断点是"人一休假就断"）。

- **AI 改变了什么机制**：编码能力把非文本输入变成可处理的素材——但**多模态只是输入侧**：采集侧要能处理媒体文件、处理侧要能转写与编码，链路的其余部分（去重、分类、回指、频控）逻辑不变。**把多模态当成整条链路的替代，是范围挪用**（这也是本书审计时对原章节的主要意见，与 §2.4 的边界及 Ch10 §01 的口径一致）。

- **由此得到的**：覆盖面的扩充恰好落在采集与处理两段，而这两段正是 §2.2 时效预算里可独立测的两项——因此扩容的成本与延迟可以被分开计量，不会污染分发与频控的口径。

- **由此付出的**：**回指更难**——音视频的"片段位置"是时间戳与帧，多模态情报的引用回指要额外定义（时间戳 + 转写片段），否则本主题第一约束（判断风险）在这一类输入上直接失守（§5.3.5 原有的边界）；此外跨模态的检索与对齐仍有差异（§5.2 表第六行 ③ 判"部分成立"），因此多模态素材的归簇阈值不能照搬文本侧。

- **证据与来源**：【公开】多模态模型能力条目可核——Ch10 §01 的 §5.1 分级表把"多模态模型直接消费原始模态"判 **L2**（①③ 满足、② 不满足），并写明"**② 只有『满足』与『降为 L2』两种命运**：它不能改写成『有公开演示』，也不能靠『本节只评估某一层』把适用范围缩小来绕过去"——**这条口径在本单元必须原样沿用**，不能因为"本节只评估输入侧"就把 ② 判成满足。同一处还给出多模态生成商用前要额外核的两件事：生成内容的知识产权与训练数据来源规则、平台与当地法规对生成内容标识的要求。【经验】"先在会议 / 直播 / 监管发布这类场景落地、而不是全域铺开"是本主题 §5.6 的可证伪预测之一，明标【经验】档。

- **成熟度**：**L2**（与 Ch10 §01 的 §5.1 分级表、以及本主题 §5.2 表第六行一致）。① 成立（多模态能力条目可核）；② **不成立**（判据 ② 在多模态侧更难——发布方与使用方常是同一家）；③ **部分成立**，跨模态检索与对齐仍有差异。**这里的 L2 只标证据缺口**，不代表不能用。

- **判定方法**：取一条来自音视频素材的摘要，看它的引用能不能指到"**时间戳 + 转写片段**"；只能指到"某个录音 / 某个视频"就等于没有回指——**这时先别扩大这类输入的覆盖面**，因为扩得越大，不可验证的条目越多。

- **什么时候值得做**：会议、监管直播、图片公告这类"只有非文本形态、且判断价值高"的场景——这时它扩的是覆盖面而不是链路。

- **什么时候不值得做**：回指方案（时间戳 + 转写片段）还没定义时——先定义回指，再放素材进来，否则你换来的是"更不可验证"而不是"更全"。

#### 5.3.6 Agent 自主采编：为什么停在 L3

- **旧做法与它的卡点**：采编权在人手里——人定信源、人定口径、人决定报什么；卡点是**这条链路不可扩展**，人一休假就断（主文件 §1.4 与 §3.1 约束 5）。

- **AI 改变了什么机制**：**机制其实没有变成"可以交出去"。** 本方向想替换的是"人定信源与口径"这个**动作的落点**，但三件事在机制上不成立：① 采编决策错误的**责任无法归属**（漏报一个监管处罚，谁负责）；② 信源选择涉及**授权边界**，而模型无法判断授权；③ 缺少可比较的"采编质量"口径。按 §5.3.7 第一步"写不出它替换的是谁就没有机制内容"——这里替换的动作落点写得出来，**但替换之后的责任结构写不出来**。

- **由此得到的**：可做的只有把"自主"限定在**候选生成**——模型给候选信源与候选选题，人定清单与口径；这样链路仍然拿到人的判断力，同时把人的时间从"每天翻信源"压到"每天审候选"（§5.7 第 3 条把它列进"先别投"，指的就是不要交出采编权）。

- **由此付出的**：这条限制把本方向的收益上限压住了——它不会带来覆盖面的数量级变化，只带来人工比例的下降；而在责任归属有通行做法之前，任何"把采编权交出去"的形态都会在第一次漏报时把整条链路的信用一次性花掉。

- **证据与来源**：【经验】**本方向给不出【公开】档证据**——§5.2 表末行写的是"① 只有演示与自研；② 核不到；③ 不成立（责任无法归属）"。与之相对，可核验的成熟形态在全书他处都站在"人定口径"那一侧：`01-modeling/09-one-id` 的 §7.2 把"匹配规则 / 模型 + 人工复核工作台"写成产品形态，客户只做字段映射与阈值确认；`11-cross-cutting/01-data-quality` 的 §4.3 也把自动生成的规则挡在 P0 之外（"生成的规则必须经复核才能进 P0"）。这两条支持的是"机器给候选、人定口径"，**不是"自主采编"**。

- **成熟度**：**L3**。① **不成立**（只有演示与自研，无正式发布条目）；② 核不到；③ **不成立**（责任无法归属，无通行做法）。动作：只做最小版本（生成候选、人决定发布），不做技术选型（§5.3.7 的分级动作表）。

- **判定方法**：对任何号称"自主采编"的方案问一句——**"它漏报了，谁签字？"** 答不出来就还停在 L3，无论演示多完整。

#### 5.3.7 一条可复用的操作：怎么判断某条演进方向该不该跟

上面的分级是结论，下面把它变成三步操作——**以后遇到本节没列到的新名词，用这三步自己判**：

**第一步：定位它替换掉了哪个部件。** 写不出"它替换的是谁"，就说明它没有机制内容。**情报链路上合法的三种答案**：替换了一个**部件的实现**（如去重从指纹换成事件簇归并）、替换了一个**字段的归属**（如摘要从"一段文本"变成"带位置的结构"）、替换了一个**动作的落点**（如人审从"分发后反馈"前移到"分发前闸门"）。判不出来 → 归第 3 类，只改选型表。

**第二步：查三条判据的落点，尤其是②。** ① 与 ③ 通常容易满足（有文档、接口稳），**真正的分水岭是 ②——第三方非厂商的生产案例**。本主题的卡点比接入层更硬：**情报系统的关键指标（漏报率、摘要正确性、误报归因）几乎不可能从外部核验**——它们依赖各组织自己的标注样本与信源集合，跨组织不可比。**因此情报链路上"有文档"离"已验证"更远**。

**第三步：按级别决定动作，且动作要带退出条件。**

| 级别 | 动作 | 必须同时写下的东西 |
| --- | --- | --- |
| L1 | 可以直接进架构约束 | ——（本主题暂无） |
| L2 | 排进试点，**但不进架构约束** | **退出条件**（什么观测结果出现就停）；对情报场景还要加一条：**它会不会降低可验证性** |
| L3 | 只做最小版本，不做技术选型 | 最小版本是什么（如自主采编只做"生成候选、人决定发布"） |

**情报场景有一条本主题特有的准入条件**：任何提升"自动化程度"的方向，都要先回答**"它会不会让摘要变得更不可验证"**——因为本主题的第一约束是判断风险（§3.1 约束 3），而**"更流畅但更少出处"的进步在本主题里是退步**。这条条件把若干看起来诱人的方向直接筛掉（例如"端到端直接生成成品简报而不保留事实点映射"）。

### 5.5 被过度宣传的部分

1. **"Agent 自动盯全网"**：授权边界、反爬合规、以及"漏报责任"都还无通行做法；可核验的形态是**分级信源 + 抽检**，不是"全网自主"。**它什么时候才会成真**：这三件事都从"无通行做法"变成"有外部可核的做法"时——信源侧把采集授权登记成可查条目、抓取范围有共同的边界约定、漏报责任在合同或监管文本里能指到归属方；在那之前，"自主"最多只能到"生成候选、人定清单"这一步（§5.3.6）。
2. **"摘要准确率 95%+"**：摘要正确性的公开数据几乎都来自建设方，且**没有统一的评测集**——请用自己的抽检（每周 20 条）去量。**它什么时候才会成真**：出现**第三方（非建设方）**公开的摘要质量报告，且它**同时**给出评测集、口径定义与失败样本；只给一个百分比、不给这三样的，都还不能与你的数相比（§5.2 表第二行的判据 ② 卡点就在这里），这个更高的准确率也就无法进入验收。
3. **"个性化推荐提升打开率"**：打开率上升与**漏报**是两个方向；只优化打开率会让系统退化成"推用户爱看的"，与情报的目标相反。**它什么时候才会成真**：采购或验收文件把**漏报 / 误报 / 时效**与打开率、条数并列成同一组指标，并各自给出分母与统计口径——即 §5.6 第 3 条那一行的"会成真的信号"在采购侧留下的外部痕迹；在此之前，打开率上升只说明推荐在工作，不说明情报在工作。

### 5.6 未来 3–5 年：可证伪的预测

预测必须写成「预测 + 会成真的信号 + 会证伪的信号」，**写不出信号的预测不要写**。两列信号都只写**外部可观察的事实**（某个能力出现在文档的哪一类条目里、哪类材料开始公开），不写"体验会变好"这类无法观察的判断——**只留证伪方向时，"还没发生"与"已经开始错了"在读者眼里是同一件事**，预测就只能等到窗口末端才可判读。本节尤其要守这一条：本主题的卡点正是 §5.2 那句"情报链路的公开材料几乎都是建设方自述"，所以信号只能取**接口定义、采购与验收文件、公开材料形态**这三类外部留痕——质量数字（漏报率、摘要正确性）恰恰属于拿不到的那一类。

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| "引用回指"会成为情报类产品的默认功能（不是卖点） | 检索增强生成类工具的接口定义把"片段位置"写成**默认输出的一部分**（而不是可选参数），商业情报产品的条目里出现可点开的原文位置——即 §5.4 接口表第 2 行那个"片段映射"从自家字段变成别人家接口的默认字段 | 两年后主流工具仍只给摘要、不指片段 |
| 事件簇会成为分发的基本单位 | 产品族的默认推送单位从"文章 / 条目"改成"事件 / 簇"——**外部可核**的痕迹是**推送计数按事件而不按条**、同一件事不再按转载篇数各推一次；与之对应的内部痕迹是三处标识同时按簇走（分发键、频控维度、留痕主键，即 §7.3.2 表"改成簇时要动几处"那一列的答案），这三处采购方从文档与接收端都看不到 | 主流产品仍按文章条数推送、不做跨源归并 |
| 情报质量口径会从"打开率"转向"漏报 / 误报 / 时效"三组 | 采购与验收文件把漏报、误报、时效与打开率、条数**并列成同一组**，并各自给出分母与统计口径（本节外同一口径的具名落点：§3.6 跃迁表的"无质量口径 → 有口径"一行写的正是**漏报 / 误报 / 时效三组指标**，§3.5 反模式表把它记成"只看打开率不看漏报"，主文件 §1.4 的原话是**漏报率 / 误报率 / 时效达标率**） | 采购与验收仍只看打开率与条数 |
| 多模态情报会先在"会议 / 直播 / 监管发布"这类场景落地，而不是全域铺开 | 该类场景的公开材料从演示转为**带验收指标的形态**——引用能指到"时间戳 + 转写片段"、并给出失败样本（与 [Ch10 §01](../01-multimodal-ai/01-multimodal-ai.md) 的 §5.6 表里那一行的正列同形） | 两年内仍无该类场景的公开可用形态 |

**这四条全部是【经验】档**：它们是对机制与采购行为的判断，无具名出处、无推导链——**请按"可被证伪"使用，而不是当结论**。

四条都能被**公开文档与发布物**核对，不需要内部数据——**这不是矛盾**：预测本身是判断（【经验】档，依据不可引），而判读它的痕迹是外部事实（可查）。**本节标题的 3–5 年是窗口上限，不是判读点**：各条的可判读点都早于窗口末端，窗口末端用来确认它是一个趋势而不是一次性现象。以下分条年限与窗口上限均属【经验】档，随各环节的采纳周期变，采纳慢的方向可放宽：

- 第 1 条看两处：工具与产品的接口定义里"片段位置"是不是默认项，以及商业情报产品的条目里有没有出现可点开的原文位置——一到两年即可首次判读（到时仍只给摘要、不指片段，即落到证伪那一侧）。
- 第 2 条看默认推送单位是文章还是事件——一到两年即可首次判读。
- 第 3 条看采购与验收文件里出现的是哪几组指标——两到三年（采购与验收周期比产品发布慢一档）。
- 第 4 条看该类场景的公开材料是演示还是带验收指标的形态——两到三年是它转成"带验收指标"的读数点；**两年内仍无该类场景的公开可用形态即证伪**（与本条证伪栏的"两年内"同一时点）。

**最值得先盯第 2 条**：四条里只有它**不用翻任何文档或第三方报告**——你被推送的单位本身就是答案（其余三条都要去读接口定义、采购文件或公开发布物）；而且它一旦不成立，§5.8 的两条机制性变化里「去重从"素材指纹"变成"事件簇"」那一条会整体失去前提（分发键、频控维度、留痕主键三处都按簇走这一组动作也随之失去依据，§7.3.2 的"三处外部引用"）。

### 5.7 给架构师的行动建议

1. **今年就该做**：信源清单（含授权边界与断供判据）+ 四段时效预算 + 事件簇去重。三件事不依赖任何前沿判断。
2. **可以试点**：生成式摘要 + 引用回指 + 数值回查（先在**非高风险**标签上开，每周抽检 20 条）；语义分类（先立标签体系再开）。
3. **先别投**：Agent 自主采编（责任无归属）、全域多模态情报（先选一个场景）。
4. **无论哪条**：把**"摘要条数 ÷ 素材条数"**与**"被频控挡下的条数"**作为两条日常指标——前者说明筛选层在起作用，后者说明系统没有变成骚扰源。

### 5.8 小结

> 本节小结：AI 时代对情报链路的改变**有两条是机制性的**——**摘要从"抽原文"变成"生成 + 引用回指"**（于是片段映射成为必需），**去重从"素材指纹"变成"事件簇"**（于是分发单位改变）；其余方向（语义分类、Schema 化抽取、多模态输入）都是在这两条之上的输入扩充与结构加固。情报链路没有一行达到 L1，卡点全在"第三方非厂商生产案例"；因此请按"**机制可验证、效果不可验证**"理解它——**质量必须靠你自己的抽检与漏报样本集去量**。**给读者的动作**：先把不依赖前沿判断的三件事（信源清单、时效预算、事件簇）做完，再谈生成式摘要与多模态。

> 💡 **思考锚点**：在你现在的链路里挑一条最近发出的摘要，做一次"回指测试"：它的每个数字 / 日期 / 主体，能否在原文里点到具体片段？然后把这条链路的关键词换成"如果模型端点在发布高峰期故障，我会降级成什么"——如果你的答案是"降级成没有出处的自由生成"，那就说明 §4.7 那条纪律（**降功能不降可信**）还没落地。你打算先补回指，还是先写降级策略？
