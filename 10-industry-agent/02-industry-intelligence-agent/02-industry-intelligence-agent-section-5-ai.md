## 5. 前沿演进（AI 时代）

### 5.1 先分清三类「前沿」

1. **机制变了**：链路里某个环节换了工作原理（摘要从"抽取式"变成"生成式 + 引用回指"；分类从"关键词规则"变成"语义分类 + 标签体系"；去重从"指纹"变成"向量相似 + 事件簇"）。**这类变化影响架构决策。**
2. **接口与规范变了**：信源侧的开放接口、内容的标识与元数据规范（例如 AI 生成内容的标识要求）在演进【公开：以该项规范的官方文本当前版本为准】。**这类变化影响合规与分发。**
3. **只多了产品**：同一套能力换包装。**只在选型表里体现。**

判别方法仍是那一句：**"换一家厂商，这条结论还成立吗？"**

### 5.2 判据与分级

沿用三条 L1 判据：**① 已 GA 且有正式文档 / 发布条目**；**② 有第三方（非厂商）公开的生产案例**；**③ 接口稳定、可预期**。

| 演进方向 | 级别 | 机制变了什么 | 判据落点（可否自行核验） |
| --- | --- | --- | --- |
| 端到端情报流水线（采集 → 分发闭环） | **L2** | 从"抓取 + 关键词推送"变成"分级信源 + 事件簇 + 带出处的摘要 + 频控" | ① 成立（商业情报产品与内部平台的文档条目可核）；② **核不到**（生产细节与质量数据几乎都是建设方自述）；③ 成立 |
| 生成式摘要 + 引用回指 | **L2** | 摘要从"抽原文句子"变成"生成 + 事实点指回片段" | ① 成立（检索增强生成类能力的文档条目可核）；② **核不到**（摘要正确性的公开数据几乎都来自建设方）；③ 成立 |
| 语义分类 + 标签体系 | **L2** | 分类从关键词规则变成"规则硬信号 + 模型语义"的混合 | ① 成立；② 核不到；③ 成立 |
| 向量去重与事件簇 | **L2** | 去重从"文本指纹"变成"相似度 + 时间窗 + 主体动作" | ① 成立（向量检索与相似度判定是成熟条目）；② 核不到（阈值与窗口的经验值无公开可比值）；③ 成立 |
| 事件与实体抽取的 Schema 化 | **L2** | 抽取从"自由文本摘要"变成带 Schema 的结构化结果（含片段位置） | ① 成立（结构化输出是正式能力条目）；② 核不到；③ 成立 |
| 多模态情报（音视频 / 图文 / 图像情报） | **L2** | 情报的输入从文本扩到多模态，编码能力是前提 | ① 成立（多模态模型能力条目可核，见 [§01](../01-multimodal-ai/01-multimodal-ai.md)）；② 核不到；③ 部分成立（跨模态的检索与对齐仍有差异） |
| Agent 自主采编（模型自己决定抓什么、写什么） | **L3** | 从"人定信源与口径"变成"模型自己选择与组织" | ① 只有演示与自研；② 核不到；③ 不成立（**责任无法归属**：错误的采编决策由谁负责无通行做法） |

**本节没有一行达到 L1**——卡点同样在 ②：**情报链路的公开材料几乎都是建设方自述**（来源清单、误报率、摘要正确性这类数据极少公开）。因此这一层的成熟度应按"**机制可验证、效果不可验证**"理解：接口与机制你可以核验，**质量必须用你自己的抽检与样本集去量**。

### 5.3 演进方向逐条拆解（核心节）

#### 5.3.1 摘要：从"抽取式"到"生成 + 回指"

**机制**：摘要不再拼接原文句子，而是**生成表达并给每个事实点挂上出处片段**。

**对架构决策的影响**：摘要环节从"文本处理"变成"**必须保留片段映射**的处理"——存储要能按片段回溯，流水线要传片段位置，回查要能访问原文。**这三项是"换生成式摘要"的真实前置条件**，比换模型重要得多。

**边界**：生成式摘要**必然**引入幻觉，因此"回查不通过的数字不写进摘要"这条硬规则**不能省**；省略它，等于把链路可信度交给模型。

#### 5.3.2 分类：从关键词到"规则 + 语义"

**机制**：硬信号（文号、代码、名单）由规则保证可解释与必命中；语义归类由模型在**标签体系内**完成。

**对架构决策的影响**：**标签体系成为必须先立的对象**——没有它，模型的"语义分类"无法量误报（因为不知道"应该有哪些类别"），调阈值也无从下手。

**边界**：规则**不会**被模型替代（同名不同公司这类误报，模型也难判断，必须有主体白名单）；两者是分工，不是替换。

#### 5.3.3 去重：从指纹到事件簇

**机制**：去重的单位从"素材"变成"事件簇"（相似度 + 时间窗 + 主体动作 + 日期）。

**对架构决策的影响**：**分发单位改变**——推送的是簇（含多来源），不是素材。这带来两个必须处理的细节：① 簇**会生长**（后续来源持续加入），要有"补充推送"的规则（否则用户只看过第一版）；② 阈值与窗口要**按事件类型分别标定**。

**边界**：向量去重对"同一事件的不同角度报道"效果有限——**不要把"不同角度"当成"不同事件"**（那会造成漏报）。

#### 5.3.4 抽取 Schema 化：把"摘要"变成"带位置的结构"

**机制**：实体与事件以 Schema 约束输出（主体、动作、金额、时间、片段位置）。

**对架构决策的影响**：抽取结果**可以进结构化库**（事件表 / 关系表），于是"按主体查历史事件""统计某类事件频次"变成普通查询——这也是情报与 [Ch1 §06 知识图谱](../../01-modeling/06-knowledge-graph/06-knowledge-graph.md) 对接的接口。

**边界**：Schema 越细，抽取越脆（新事件类型被塞进错误的槽位）；**判据**是"Schema 变更有版本与兼容策略"，而不是"字段越多越好"。

#### 5.3.5 多模态情报：输入侧的扩充，不是链路的重写

**机制**：情报输入从文本扩到音视频 / 图文（会议录音、监管直播、图片公告）。

**对架构决策的影响**：多模态**只是输入侧**——采集侧要能处理媒体文件、处理侧要能转写与编码，但**链路的其余部分（去重、分类、回指、频控）逻辑不变**。**把多模态当成整条链路的替代，是范围挪用**（这也是本书审计时对原章节的主要意见）。

**边界**：多模态内容的**回指更难**（音视频的"片段位置"是时间戳与帧），因此多模态情报的引用回指要额外定义（时间戳 + 转写片段）。

#### 5.3.6 Agent 自主采编：为什么停在 L3

**机制**：让模型自己决定"盯哪些信源、报什么、怎么写"。**卡点**：① 采编决策错误的**责任无法归属**（漏报一个监管处罚，谁负责）；② 信源选择涉及**授权边界**（模型无法判断授权）；③ 缺少可比较的"采编质量"口径。**给读者的动作**：把"自主"限定在**候选生成**（模型给候选，人定信源与口径），而不是把采编权交出去。

#### 5.3.7 一条可复用的操作：怎么判断某条演进方向该不该跟

上面的分级是结论，下面把它变成三步操作——**以后遇到本节没列到的新名词，用这三步自己判**：

**第一步：定位它替换掉了哪个部件。** 写不出"它替换的是谁"，就说明它没有机制内容。**情报链路上合法的三种答案**：替换了一个**部件的实现**（如去重从指纹换成事件簇归并）、替换了一个**字段的归属**（如摘要从"一段文本"变成"带位置的结构"）、替换了一个**动作的落点**（如人审从"分发后反馈"前移到"分发前闸门"）。判不出来 → 归第 3 类，只改选型表。

**第二步：查三条判据的落点，尤其是②。** ① 与 ③ 通常容易满足（有文档、接口稳），**真正的分水岭是 ②——第三方非厂商的生产案例**。本主题的卡点比接入层更硬：**情报系统的关键指标（漏报率、摘要正确性、误报归因）几乎不可能从外部核验**——它们依赖各组织自己的标注样本与信源集合，跨组织不可比。**因此情报链路上"有文档"离"已验证"更远**。

**第三步：按级别决定动作，且动作要带退出条件。**

| 级别 | 动作 | 必须同时写下的东西 |
| --- | --- | --- |
| L1 | 可以直接进架构约束 | ——（本主题暂无） |
| L2 | 排进试点，**但不进架构约束** | **退出条件**（什么观测结果出现就停）；对情报场景还要加一条：**它会不会降低可验证性** |
| L3 | 只做最小版本，不做技术选型 | 最小版本是什么（如自主采编只做"生成候选、人决定发布"） |

**情报场景有一条本主题特有的准入条件**：任何提升"自动化程度"的方向，都要先回答**"它会不会让摘要变得更不可验证"**——因为本主题的第一约束是判断风险（§3.1 约束 3），而**"更流畅但更少出处"的进步在本主题里是退步**。这条条件把若干看起来诱人的方向直接筛掉（例如"端到端直接生成成品简报而不保留事实点映射"）。

### 5.5 被过度宣传的部分

1. **"Agent 自动盯全网"**：授权边界、反爬合规、以及"漏报责任"都还无通行做法；可核验的形态是**分级信源 + 抽检**，不是"全网自主"。
2. **"摘要准确率 95%+"**：摘要正确性的公开数据几乎都来自建设方，且**没有统一的评测集**——请用自己的抽检（每周 20 条）去量。
3. **"个性化推荐提升打开率"**：打开率上升与**漏报**是两个方向；只优化打开率会让系统退化成"推用户爱看的"，与情报的目标相反。

### 5.6 未来 3–5 年：可证伪的预测

| 预测 | 被证伪的信号 |
| --- | --- |
| "引用回指"会成为情报类产品的默认功能（不是卖点） | 两年后主流工具仍只给摘要、不指片段 |
| 事件簇会成为分发的基本单位 | 主流产品仍按文章条数推送、不做跨源归并 |
| 情报质量口径会从"打开率"转向"漏报 / 误报 / 时效"三组 | 采购与验收仍只看打开率与条数 |
| 多模态情报会先在"会议 / 直播 / 监管发布"这类场景落地，而不是全域铺开 | 两年内仍无该类场景的公开可用形态 |

**这四条全部是【经验】档**：它们是对机制与采购行为的判断，无具名出处、无推导链——**请按"可被证伪"使用，而不是当结论**。

### 5.7 给架构师的行动建议

1. **今年就该做**：信源清单（含授权边界与断供判据）+ 四段时效预算 + 事件簇去重。三件事不依赖任何前沿判断。
2. **可以试点**：生成式摘要 + 引用回指 + 数值回查（先在**非高风险**标签上开，每周抽检 20 条）；语义分类（先立标签体系再开）。
3. **先别投**：Agent 自主采编（责任无归属）、全域多模态情报（先选一个场景）。
4. **无论哪条**：把**"摘要条数 ÷ 素材条数"**与**"被频控挡下的条数"**作为两条日常指标——前者说明筛选层在起作用，后者说明系统没有变成骚扰源。

### 5.8 小结

> 本节小结：AI 时代对情报链路的改变**有两条是机制性的**——**摘要从"抽原文"变成"生成 + 引用回指"**（于是片段映射成为必需），**去重从"素材指纹"变成"事件簇"**（于是分发单位改变）；其余方向（语义分类、Schema 化抽取、多模态输入）都是在这两条之上的输入扩充与结构加固。情报链路没有一行达到 L1，卡点全在"第三方非厂商生产案例"；因此请按"**机制可验证、效果不可验证**"理解它——**质量必须靠你自己的抽检与漏报样本集去量**。**给读者的动作**：先把不依赖前沿判断的三件事（信源清单、时效预算、事件簇）做完，再谈生成式摘要与多模态。

> 💡 **思考锚点**：在你现在的链路里挑一条最近发出的摘要，做一次"回指测试"：它的每个数字 / 日期 / 主体，能否在原文里点到具体片段？然后把这条链路的关键词换成"如果模型端点在发布高峰期故障，我会降级成什么"——如果你的答案是"降级成没有出处的自由生成"，那就说明 §4.7 那条纪律（**降功能不降可信**）还没落地。你打算先补回指，还是先写降级策略？
