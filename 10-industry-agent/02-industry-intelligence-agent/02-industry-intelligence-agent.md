# 行业情报智能体（Industry Intelligence Agent）

> **一句话定位**：把"人每天手工看十几个信源、写一份简报"变成**一条可运营的流水线**：信源接入与调度 → 清洗与语义分类 → 带引用的摘要 → 个性化分发 → 反馈回流。它交付的不是"更聪明的模型"，而是**一条从不间断的链路**。

> 本文是 data-travel 项目 [Ch10 · 行业智能体](../../README.md) 的子章节（**02 行业情报智能体**）。覆盖 **核心职责⑤ 行业情报智能体与精准分发** 中"7×24h 自动化情报采集 / 清洗 / 语义分类 / AI 摘要 / 个性化推送"的工程实践。本主题**不**讲多模态模型的工程实现（那是 [§01 多模态 AI](../01-multimodal-ai/01-multimodal-ai.md) 的范围），只讲"情报链路"本身。

## 1. 概念与定位

### 1.1 是什么

**学术 / 工业定义**：行业情报智能体是一套**面向"外部世界的持续变化"的信息系统**——它的输入是**不断新增的外部信源**（公告、研报、新闻、社交、招投标、专利、监管文件），输出是**按人 / 按角色分发的、带来源的、可追溯的判断**。它做五件事：**采集 → 清洗与分类 → 摘要 → 分发 → 反馈**。

**工程定义**：在数据架构师手里，情报智能体是**一条被当成数据管道来运营的链路**——有延迟预算、有质量口径、有成本账、有断供告警：

- **采集（Ingest）**：信源清单、抓取配额、增量游标、失败退避。
- **清洗与分类（Enrich）**：正文抽取、去重、实体与事件抽取、标签分类。
- **摘要（Summarize）**：带**引用回指**的摘要，事实性可校验。
- **分发（Distribute）**：订阅规则、频控、渠道编排。
- **反馈（Feedback）**：打开 / 采纳 / 纠错回流，用于调整信源权重与分类阈值。

**「情报智能体」与「RAG 问答」的差别**（这是最常被混的一对）：

| 维度 | RAG 问答 | 情报智能体 |
| --- | --- | --- |
| 触发 | **人问** | **信源变了**（无人触发也要跑） |
| 时效 | 检索当下的库 | 有**从发布到可见的延迟预算** |
| 正确性口径 | 答案能否被引用支撑 | 还有：**是否漏了应该报的**（召回）与**是否报了不该报的**（误报） |
| 输出 | 一次回答 | 持续的分发流（且要**去重与频控**） |
| 失败形态 | 答错 | 断供（静默）、重复推送、误报风暴 |
| 成本结构 | 按提问量 | **按信源数 × 抓取频次 + 摘要量 + 推送量** |

**一句话判断**：**「只在人问的时候才动」的是问答，不是情报——情报的判据是"没有人问，它也在跑，并且断了你第一个知道"。**

### 1.2 为什么需要

情报链路是被**五件事**逼出来的：

1. **信源会变**：外部站点的结构、频率、反爬策略、授权条款都在变——**没有信源清单与断供检测，"静默失效"会成为常态**（你以为在跑，其实三天没抓到）。
2. **同一事件有多个来源**：同一件事在三家媒体、五个公告里各说一遍；不去重就是**重复推送**，重复推送会直接消耗用户的信任。
3. **摘要会编**：LLM 摘要的幻觉在情报场景**代价极高**（"某公司被收购"的假情报会进入决策），因此摘要必须有引用回指与事实性校验。
4. **推送会变骚扰**：没有频控与优先级，个性化会退化成"什么都推"——用户很快学会忽略。
5. **效果无法闭环**：没有反馈回流，信源权重与分类阈值只能靠感觉调，**且无法证明系统在变好**。

### 1.3 在 AI 时代数据架构中的位置

```
   [外部信源：公告 / 研报 / 新闻 / 社交 / 招投标 / 专利 / 监管]
                    ↓ 采集（配额 + 退避 + 增量游标）
   [原始素材区]  →  [清洗与分类]  →  [事件库 / 标签]
                        ↓                ↓
                   [摘要与引用回指]   [实体与关系]（可与 Ch1 图谱对接）
                        ↓
   [分发与频控] → [用户 / 角色 / 群组] → [反馈回流]
```

- **上游**：Ch11 数据质量（信源质量与断供检测同源）、Ch4 数据资产化（素材与向量的存储与检索）、Ch1 建模（实体与关系的建模口径）。
- **下游**：Ch9 数据智能产品（情报作为一种产品形态）、Ch10 §01 多模态 AI（音视频 / 图文情报的编码与理解）。
- **横向**：Ch5 §02 Agent 平台（情报 Agent 是平台上的一个租户级应用）、Ch8 治理（信源合规、输出合规）、Ch11 §03 成本、Ch12 高可用（断供与雪崩）。

### 1.4 演进历程

- **人工简报阶段（长期存在）**：分析师每天手工看十几个信源，写一份简报。**优点是判断质量高，缺点是覆盖窄、不可扩展、且人一休假就断。**
- **抓取 + 规则阶段（2010s）**：爬虫 / RSS 聚合 + 关键词规则，做"命中即推送"。**解决了覆盖，没解决重复与误报**——关键词规则对"同义不同词"与"同词不同义"都无解。
- **LLM 摘要阶段（2023–2024）**：用模型做分类与摘要，质量明显提升；**但引入了幻觉与不可追溯**，于是"引用回指 + 事实性校验"成为必需项。
- **端到端流水线阶段（2024–2025）**：采集、去重、抽取、摘要、分发、反馈被当作一条**有延迟预算与质量口径的管道**来运营；评价标准从"摘要好不好看"转向**"漏报率 / 误报率 / 时效达标率"**。

> 主线：**从"抓到了就推"，变成"该报的必须报、不该报的不能报、报了要能追溯到原文"。**

## 2. 核心原理

### 2.1 关键概念定义

- **信源（Source）**：一个可稳定获取的信息出口（API / RSS / 页面 / 文件），**必须有：归属方、获取方式、授权边界、抓取配额、Owner、断供判据**。
- **授权边界（Entitlement）**：该信源允许你做什么——只读展示？可摘要？可对外分发？**"能抓到"不等于"能分发"**，这是情报合规最常出事的地方。
- **增量游标（Cursor）**：记录"上次处理到哪"的指针（时间戳 / ID / 页码），决定**能否只处理新增**。游标设计错会导致漏报（跳过了条目）或重复处理。
- **去重指纹（Dedup Fingerprint）**：把一条素材映射成可比较的标识——**同一事件的不同来源**要能归到同一个"事件簇"（常用形态：正文指纹 + 向量相似 + 时间窗口）。
- **事件簇（Event Cluster）**：一组描述同一件事的素材；**分发单位是簇，不是素材**（这是"不重复推送"的机制基础）。
- **标签体系（Taxonomy）**：分类的**口径集合**——谁定义、几级、如何新增、如何废弃。**没有标签体系的"语义分类"是无法量误报的**。
- **引用回指（Citation Back-reference）**：摘要中的每个事实点都能指回原文片段（句子级 / 段落级），使"能不能信"变成可点开验证的动作。
- **事实性校验（Factuality Check）**：对摘要里的**数值、日期、主体**做机械化回查（是否出现在原文、是否被改写），是引用回指之后的第二道闸门。
- **频控（Frequency Cap）**：对**人 / 群组 / 事件簇**三个维度的推送上限（例如"同一事件簇 24 小时内只推一次""每人每天不超过 N 条"）。
- **反馈回流（Feedback Loop）**：打开 / 采纳 / 纠错 / 屏蔽等信号回流，用于调整**信源权重、分类阈值、推送优先级**。
- **时效预算（Freshness Budget）**：`采集延迟 + 处理延迟 + 分发延迟 ≤ SLA`——**三项要分开测**，否则无法定位"为什么晚了"。

### 2.2 数学 / 形式化基础

**时效预算的分解**（情报 SLA 的核心式）：

```
T_total = T_ingest + T_enrich + T_summarize + T_distribute ≤ SLA

T_ingest      = 抓取间隔/2（平均等待） + 抓取耗时 + 排队
T_enrich      = 去重 + 抽取 + 分类（可并行，取关键路径）
T_summarize   = 摘要调用（含重试）
T_distribute  = 频控检查 + 渠道投递
```

**判据**：**SLA 的每一项都要有独立的分位指标**（P95 而非均值）。只给总时长，事故时无法回答"哪一段慢了"。

**分类的质量口径**（漏报与误报要分开算）：

```
precision = 报对了 / 报了的总数        （误报的反面：报了不该报的）
recall    = 报对了 / 应该报的总数      （漏报的反面：该报的没报）

情报场景的取舍：漏报的代价通常高于误报 —— 所以阈值要偏召回，
但必须用「误报上限」把它框住（例如：误报率 ≤ X%，X 由受众承受度决定）
```

**这条取舍必须显式写下来**：只写"要准"等于没有判据；**写下"误报上限 + 漏报目标"两个数**，阈值才有依据。**这两个数的具体取值取决于行业与受众**（监管情报与市场情报的容忍度差一个量级）【经验】。

**去重的形式化**：对素材 `d` 计算指纹 `fp(d)` 与向量 `v(d)`，则

```
同一事件簇 ⇔ sim(v(d1), v(d2)) ≥ θ_sim 且 |t(d1) − t(d2)| ≤ W
```

- `θ_sim` 与窗口 `W` 必须**按事件类型分别标定**（并购类事件窗口可以长到数天；行情类只有分钟级）；
- **判据**：抽样 100 组"被判为同簇"的素材人工核对，同簇准确率低于目标就调 `θ_sim`（这是可执行的标定动作，不是调参玄学）。

**摘要的事实性抽检**：

```
抽检率 r = 抽检条数 / 生成条数
目标：对「高风险摘要」（涉及数值、主体、时间）取更高的 r
可执行动作：每周抽 20 条命中记录，逐条核对「数值 / 日期 / 主体」是否与原文一致
```

**一条判据**：**抽检命中错误后必须能定位到"哪一类提示 / 哪一类信源"**——否则抽检只是发现了问题，不能改进系统。

### 2.3 关键算法 / 方法

1. **调度与配额**：按信源的**价值 × 时效要求**分级调度（高价值高频、长尾低频）；每信源有抓取配额与**退避**（失败退避、封禁退避）；**判据**：任意信源的抓取频次是否能从配置里读出来（而不是"代码里写死"）。
2. **增量与漏报防护**：游标必须**可回拨重放**（发现漏抓时能把一段窗口重跑），且**去重指纹要能容忍重放**（重放不产生重复推送）。
3. **去重**：三级——① 完全相同的指纹（同源重复）；② 高相似同簇（跨源转载）；③ 人工确认的"相关事件"（关联而非重复）。**分发单位是簇**。
4. **抽取与分类**：实体与事件抽取用**Schema 约束**（公司、动作、金额、日期），分类用**规则 + 模型混合**——规则负责"必须命中"的硬信号（例如监管文号），模型负责语义归类；**判据**：每条被推送的情报，其分类结果能否追溯到"命中了哪条规则 / 哪个模型的哪一档置信度"。
5. **摘要与事实性**：摘要模板约束为"事实点 + 出处"；**数值与日期做机械化回查**（在原文中能否找到同一个数）；**不能回查的数字不写进摘要**——这是可执行的硬规则。
6. **分发与频控**：按"事件簇 × 人 × 时间窗"三维限流；渠道编排（即时渠道只推高优先级的，摘要汇总走日报渠道）；**判据**：一个人一天最多收到多少条，这个数写在哪。
7. **反馈回流**：打开率、采纳率、纠错率按**信源 × 标签 × 渠道**分组统计——用于调信源权重、分类阈值与推送优先级。**判据**：最近一次阈值调整，依据的是哪一组数据。

### 2.4 与相邻概念的关系

- **行业情报智能体 vs RAG 问答（[Ch4](../../04-data-assetization/05-rag-architecture/05-rag-architecture.md)）**：RAG 由人触发、答当次问题；情报由**信源变化**触发、要持续分发。**RAG 的评估（能不能被引用支撑）只是情报评估的一半**，另一半是漏报与误报。
- **行业情报智能体 vs 推荐系统（[Ch2 §05](../../02-data-science/05-recommendation/05-recommendation.md)）**：推荐系统在**已有内容池**里排序，目标是点击与留存；情报要在**外部持续新增**的流里做"该不该报"的判断，目标是**不漏关键信号**。**把情报做成推荐（只优化点击）会让系统退化成"推用户爱看的"**。
- **行业情报智能体 vs 数据质量（[Ch11 §01](../../11-cross-cutting/01-data-quality/01-data-quality.md)）**：数据质量管内部数据的"完整 / 准确 / 及时"；情报把同一套思路用在**外部信源**上——**断供检测就是"及时性"的外部版本**。
- **行业情报智能体 vs 多模态 AI（[§01](../01-multimodal-ai/01-multimodal-ai.md)）**：多模态解决音视频 / 图文的编码与理解，是**情报的输入侧能力**；**用多模态顶替整条情报链路是范围挪用**。
- **行业情报智能体 vs Agent 平台（[Ch5 §02](../../05-agent-platform/02-agent-platform-architecture/02-agent-platform-architecture.md)）**：平台提供会话、工具出口、配额与审计；情报链路是平台上的**一个常驻作业**（它多数时候无人触发，这决定了它更像"数据管道 + Agent"而不是纯对话应用）。

> 💡 **思考锚点**：把你现在（或你想做的）情报链路按 §2.2 的时效预算写四项：采集、清洗、摘要、分发各占多少分钟。再写下两个数：**允许的最大误报率**与**不能漏掉的事件类型**。这四个时间与两个数都在纸上之后，你才会发现"AI 摘要"往往不是瓶颈——**采集间隔与去重窗口才是**；你的瓶颈落在哪一项？
