## 3. 设计模式与范式

> 原 § 3 共 93 行：7 个模式各 3 项「优点 / 缺点 / 适用」、1 张 7 行场景决策表、10 条反模式各 1 行「反模式 → 必须……」，全节没有一处结构示意。本文件重写为模式手册，原 7 个模式名与 10 条反模式名全部保留。

### 3.1 先看约束：模式不是选择题，是约束的产物

模式表把 7 个模式列成「按业务特征挑一个」。但多模态的模式分野不是「用 CLIP 还是用 VLM」，而是**跨模态的桥建在哪一层**。主文件 §2.2 给出的对齐目标是 `-1/N Σ log(exp(sim(I_i,T_i)/τ) / Σ_j exp(sim(I_i,T_j)/τ))`——这个式子只要求「匹配的图文对距离近」，它产出的是一座**只有距离、没有语言的桥**。要在桥上说话，就得把视觉信号翻译成 token 送进自回归模型（VLM）；要让桥连上语气与韵律，就得让所有模态在同一条序列里联合训练（原生多模态）；要让桥能指向库里的存量内容，就得把它落到索引上（多模态 Embedding）；要让它接上动作与时间，就得继续往后加两层（Agent / 世界模型）。**桥建得越靠前，越便宜、越可组合、越能换件；建得越靠后，能力越强、越贵、越难验证。** 所有多模态选型都是在这条轴上找位置。

第二个约束是**输入形态本身**。视觉与视频不是「更长的文本」：图像在进入模型前必须先被切成 token，切法（分辨率、切块数、采样帧率）直接决定 token 数量、成本与细粒度信息是否被保留。主文件 §2.2 只给了融合的数学形式，工程上真正的分岔发生在「切多少」这一步。

第三个约束是**验证成本**。文本任务的错是「读到就知道错」，多模态任务的错是「读起来完全通顺」——一个数字识别错误、一个位置描述错误，输出形态与正确答案没有区别。所以多模态模式的成败往往不取决于模型能力，取决于**有没有一个外部判据能判断输出对不对**（原文位置、业务回查、单号对账）。这条约束解释了为什么「专用模型 + 确定性输出」在关键字段上仍然胜过通用大模型。

第四个约束是**数据边界**。多模态输入往往比文本更敏感（证件、人脸、监控、医疗影像），而能力最强的模型通常是托管 API。模型选型因此不只是效果问题，也是「这份数据能不能离开这个边界」的问题。

| 约束 | 它决定了什么 | 本主题下最容易被它推翻的直觉 |
| --- | --- | --- |
| 桥建在哪一层 | 选双塔对齐 / 桥接式 VLM / 原生多模态 / 索引 / 专用 / Agent / 世界模型 | 「上最强的那个多模态模型就够了」——强的是桥的后端，前端切法与判据仍要自己建 |
| 输入切法（分辨率、帧率、切块数） | token 数、成本、细粒度细节是否被保留 | 「输入越完整越准」——分辨率与帧数直接换成 token，超出预算的部分会被静默丢或截断 |
| 验证判据是否存在 | 用生成式模型还是确定性专用模型 | 「效果好就能上生产」——没有外部判据时，错误与正确答案无法区分 |
| 数据边界（能否离域） | 托管 API 还是本地 / 私有化部署 | 「先验证，之后再把模型换回本地」——换回本地意味着重新评测与重新调优 |
| 延迟预算 | 云端大模型、蒸馏小模型还是级联流水线 | 「加个缓存就行」——首帧 / 首次调用仍要走完整推理 |
| 任务结构（版面 / 时序 / 空间） | 是否值得引入专用模型 | 「通用模型会自己学会结构」——二维版面与时空邻接不写进表示就不存在 |

### 3.2 模式逐个拆解（核心节）

这 7 个模式按「桥建在哪一层」从浅到深排列：表征层（CLIP）→ 投影层（VLM）→ 单序列（原生多模态）→ 索引层（多模态 Embedding）→ 任务归纳偏置（专用模型）→ 动作空间（多模态 Agent）→ 时间 / 动力学（世界模型）。读的时候盯住同一个问题：**这座桥上，能被传递的到底是什么？**

#### 3.2.1 CLIP 风格（视觉-语言对齐）

**被什么约束逼出来**：要为每个业务类别都标一批图，标注成本随类别数线性增长；而「零样本」要成立，对齐就必须建立在某种无需人工标注的监督信号上——互联网上天然存在的图文对。

**结构**（双塔 + 对比学习，桥建在表征层）：

```text
  图像 ──► 图像编码器 (ViT) ──► I ∈ R^d ┐
                                        ├─► 同一个向量空间：匹配对近、不匹配对远
  文本 ──► 文本编码器 (Transformer) ─► T ∈ R^d ┘
  训练目标：主文件 §2.2 已给（InfoNCE，把匹配图文对拉近、批内其他对推远）

  推理时的两种用法，都不需要专门的分类头：
    检索（以文搜图）：库侧全部 I 离线建索引，查询侧算 T，取近邻
    零样本分类：把每个类别名写成 prompt 的 T，取相似度最大者
  关键：换任务只换文本侧，图像侧不动
```

**为什么这样设计有效**：因为「类别」由文本定义而不是由标注定义，所以新增一个类别不需要训练，只需要写一句描述——这是零样本能力强于任何监督分类器的机制根源；因为两个塔彼此独立，图像侧可以离线批量编码并建索引，检索延迟由索引决定而不是由模型决定。

**代价**：共享空间只暴露「相似度」这一个接口，它不产出语言、不产出结构，也不支持多步推理；训练目标是判别式的，学到的是整体语义对应，细粒度差异会被压平（本章 §8 记有这条：「红色的猫」与「红色气球」在向量空间里被拉得很近，必须用 Reranker 兜底）；因此下游一旦要「说得清」，就得再挂一个生成模型，系统的组件数随之增加。

**失效点**：当任务需要计数、空间关系或组合推理时（「图里有几只猫」「谁在谁的左边」），本模式的「零样本泛化」会反转成「零样本答错」，因为**共享向量空间编码的是整体语义相似度，不是结构化的场景表示**——位置与组合既没被编码，也没有输出语言的通道，所以它错得和它对得一样流畅。

**真实使用**：【公开】CLIP 由 OpenAI 于 2021 年提出（论文《Learning Transferable Visual Models From Natural Language Supervision》，Radford 等，ICML 2021）；Google 的 ALIGN 同年用噪声图文对把路线扩到更大规模（《Scaling Up Visual and Vision-Language Representation Learning With Noisy Text Supervision》，Jia 等，ICML 2021）；Google SigLIP 于 2023 年改用 Sigmoid Loss 改善小 batch 下的表现（本章 §8 已列）。判断某系统是否属于本模式：看它能否在不重训的情况下加一个新类别——不能，就说明它只是某个监督分类器的包装。

#### 3.2.2 VLM（视觉-语言模型）风格

**被什么约束逼出来**：检索只能回答「像不像」，回答不了「发生了什么」；而从零训一个原生多模态大模型的门槛高到绝大多数团队不可及——只能在两个已经成熟的部件之间架一座桥。

**结构**（视觉编码器 + 投影层 + LLM，桥建在投影层）：

```text
  图像 ──► 视觉编码器 (ViT / CLIP，常冻结) ──► 视觉特征
                │
                ├─ 投影层（MLP 或 Q-Former）──► 视觉 token 序列
                │        ↑ 桥在这里：训练主要更新的就是这一层
                ▼
  文本 prompt ──► 与视觉 token 拼成同一条序列 ──► LLM 自回归生成
  关键：LLM 的推理与指令跟随能力被完整保留；
        代价是视觉 token 要占上下文预算，帧数与分辨率都受它约束
```

**为什么这样设计有效**：因为视觉 token 与文本 token 进入同一个自回归序列，所以模型可以直接用语言推理、对话、调工具，不必为每个视觉任务单独设计输出头；因为训练主要发生在投影层，所以用远小于预训练的算力就能把已有视觉编码器与 LLM 接起来——本章 §8 记为「LLaVA（2023）首次把这种桥接式架构跑通」，这也是开源 VLM 生态能迅速铺开的机制原因。

**代价**：视觉 token 挤占上下文，图越多、分辨率越高，留给推理的空间越少；投影层是有损压缩通道，小字号、表格线、密集文本这类低层细节在投影时被压掉，文档类任务通常要靠高分辨率切块与动态分辨率补偿；两端是可替换件，但也意味着耦合——换视觉编码器要重训投影层，换 LLM 要重新对齐，组件升级不是免费的。

**失效点**：当任务要的是「像素级正确」而不是「语义级合理」时（读发票上的一串数字、核对表格的每一行），本模式的「能力全面」会反转成「错得很自然」，因为**投影层压掉的恰恰是低层细节**，而 LLM 会在细节缺失处用语言先验补出一个看起来合理的值；输出形态不携带「我在猜」的信号，业务侧无法用肉眼区分。

**真实使用**：【公开】LLaVA 确立了「视觉编码器 + 投影层 + LLM」这一主流开源形态（论文《Visual Instruction Tuning》，NeurIPS 2023）；BLIP-2 的 Q-Former 是另一种投影实现（Salesforce，ICML 2023）；Qwen-VL（阿里）与 InternVL（上海 AI Lab）是该形态的中文 / 双语代表，本章 §6 的 1.1 节（Qwen-VL）与 1.2 节（InternVL）记其实践（属实践方自述，本书不按【公开】档引用）。判断某个「多模态」产品属于本模式还是原生多模态：看它能否单独替换视觉编码器——能替换的是桥接式，不能的是原生。

#### 3.2.3 原生多模态（Native Multimodal）

**被什么约束逼出来**：桥接式把模态之间的对齐交给一个投影层，而语气、韵律、画面与音效的对应这些「跨模态细粒度同步」在投影层里被压掉了；要学到它们，模型必须在预训练阶段就见到所有模态并联合优化。

**结构**（同一条 token 序列，没有外接模块）：

```text
  文本 token ┐
  图像 token ├─► 单一 Transformer（共享参数）──► 自回归输出
  音频 token │       ↑ 各模态 token 在同一序列内 interleave
  视频 token ┘       ↑ 模态间对齐由联合预训练产生，不由投影层产生

  关键差别：桥是「训练出来的表示」，不是「外接的适配器」
    → 因此能表达无法用文本 token 转述的属性（语气、打断、音效对应）
    → 代价是任何一部分都换不掉：融合发生在参数里
```

**为什么这样设计有效**：因为所有模态共享同一套参数与同一个训练目标，模态之间的关系可以在表示层直接形成，不必先被翻译成文本再对齐——这是「音频进、音频出」能不经过 ASR / TTS 级联的原因（本章 §5.1 把低延迟、强融合列为原生多模态的优点）；因为只有一个模型，端到端链路省掉了多次排队与传输。

**代价**：训练与推理的算力、数据与工程复杂度全部集中在一家或少数几家手里，使用者拿不到任何可替换的中间件；模型是整体黑盒，出错时无法定位「视觉端错了还是语言端错了」；参数规模使本地部署成本高，多数团队只能走托管 API，于是把数据边界问题一并接受下来。

**失效点**：当场景要求把能力放进自己的边界内（私有化、离线、按模块替换、成本可控）时，本模式的「能力强」会反转成「不可用」，因为**它的能力与它的不可拆分是同一件事的两面**——融合发生在参数里，所以无法只搬走视觉部分；团队只能退回桥接式，接受能力上的折让。

**真实使用**：【公开】GPT-4o 由 OpenAI 于 2024 年发布，定位为文本 / 图像 / 音频同一模型的原生多模态；Gemini 1.5 与 Gemini 2.0 由 Google 分别于 2024-02 与 2024-12 发布，主文件 §1.1 与本章 §5.1、§5.3 已列其原生多模态与长上下文定位。判断某个模型属于哪一类：看它能否「音频进、音频出」而不经过外部 ASR / TTS 级联——需要级联的就是桥接式，无论它宣传什么。

#### 3.2.4 多模态 Embedding 检索（Multimodal Embedding + RAG）

**被什么约束逼出来**：生成模型的上下文装不下整个多模态语料，而每次问答都在全库现找也不可能——只能把语料预先压成可快速比对的形式，把「找」和「答」拆开。

**结构**（桥建在索引层，检索不进入上下文预算）：

```text
  入库（离线）：图像 / 视频帧 / 音频 ──► 编码器 ──► 向量 + 元数据 ──► ANN 索引
  查询（在线）：文本或图像 ──► 编码器 ──► 向量 ──► 近邻检索 ──► TopK
                  ──►（可选）Reranker 精排 ──► VLM 生成答案

  结构上的关键选择：统一空间 还是 多空间并行
    统一空间（CLIP / ImageBind）：一次检索跨模态召回；简单，粒度粗
    多空间并行：各模态各自编码后候选层融合；精度高，
                但「各模态 TopK 怎么合并、权重怎么定」必须自己设计
  本章 §8 记录的工业形态：统一 Embedding 粗排 + 专用编码器 / 重排精排
```

**为什么这样设计有效**：因为检索代价与「索引规模」相关、与「生成模型上下文」无关，所以库可以长到亿级而单次问答成本基本不变——这是它相对「把更多内容塞进模型上下文」的根本优势；因为编码与建索引是离线批量动作，索引成本是一次性且可计划的，而不是每次问答都要付的钱。

**代价**：向量存储是常驻成本，按「维度 × 实体数」放大（【推算】一幅 1080p 图像先缩放到 224×224（ViT-L/14 的固定输入）才得到 (224/14)² = 16×16 = 256 个 patch token 与 768 维向量——256 这个数由「224 输入 / 14 像素 patch」决定，与原始分辨率无关，更高分辨率走切片、patch 数按切片数成倍上升；同样一段文本通常只有数十到数百 token，所以同一份内容的向量存储量级是文本的数十倍——本章 §8 记为 50–100 倍，压缩到 int8 可显著降低）；索引是另一套必须与源数据同步的系统，源数据更新而索引滞后时，系统会以很高置信度回答过期内容；换编码器意味着全库重编码，这是选型时最容易被忽略的一次性大成本。

**失效点**：当查询依赖精确匹配而非语义相近时（订单号、零件编号、法规原文、人名），本模式的「语义检索效果好」会反转成「永远召不回正确答案」，因为**向量空间保留语义相似度、主动丢弃字面标识符的区分度**——一串数字在向量空间里与其它数字串几乎无法区分；此时要补的是字面检索（倒排 / 关键词）与结构化过滤，调编码器解决不了。

**真实使用**：【公开】CLIP 与 Meta 的 ImageBind 分别代表二模态与多模态统一空间方案（《ImageBind: One Embedding Space To Bind Them All》，CVPR 2023；本章 §8 已列）；中文侧的候选是 BAAI 的 BGE-VL（《BGE-VL Technical Report》，2024；能力、许可与版本以官方仓库当前版本为准）；生产级多模态 Embedding 的工程实现可参照 Jina CLIP 技术报告（2024，本章 §8 已列）。判断一个多模态 RAG 是否真的多模态：看检索单元是什么——只有文本 chunk 的属于「文本 RAG 加了图片描述」，检索单元包含图像 / 帧向量的才是本模式。

#### 3.2.5 专用多模态模型

**被什么约束逼出来**：通用模型的训练目标是「什么都会一点」，而某类任务的判别依据藏在结构里——文档的二维版面、视频的时间顺序、语音的帧级对齐、3D 的空间几何；这些结构如果不写进输入表示，模型只能靠数据量去逼近。

**结构**（以文档理解为例，桥建在任务归纳偏置上）：

```text
  通用 VLM 的输入：像素 ──► patch ──► 一维 token 序列（版面结构被丢掉）
  专用文档模型的输入：
    ┌───────────────────────────────────────────┐
    │ 文本 token  +  (x0, y0, x1, y1) 二维版面框  │ ← 每个 token 带坐标
    │ 图像 patch 特征                            │
    └───────────────────────────────────────────┘
    同一次预训练里联合建模：文本 / 版面 / 图像
  → 表单里「同一行的两列」在结构上相邻，模型不需要靠猜

  其它模态同理：
    视频 → 时序位置编码 + 帧采样策略
    语音 → 帧级声学特征（非自回归结构可一次并行出全部 token）
    3D   → 点云的置换不变性与局部邻域注意力
```

**为什么这样设计有效**：因为任务的结构先验被写进了输入表示与注意力结构，所以小几个数量级的模型也能在该任务上超过通用大模型——这是「专用」能成立的全部理由；因为输出形态固定（框、类别、转写文本），阈值与评测都是确定的，不涉及生成式幻觉。

**代价**：一个模型只覆盖一个或少数几个任务，换任务就要换模型、换数据、重训；标注成本按任务分别支付；多任务并存时，服务层要维护多个模型版本、多套评测集与多条推理链路，工程复杂度从「一个模型」变成「一个模型矩阵」。这条代价在垂直行业里尤其突出（医疗影像、工业质检、自动驾驶的模型清单往往有几十个）。

**失效点**：当需求从「一个固定任务」变成「一批长尾任务」时，本模式的「领域内精度高」会反转成「覆盖成本失控」，因为**每个新任务的边际成本是「一份标注 + 一次训练 + 一套评测」三件事，而长尾任务的数量是按天增长的**；常见错误应对是给每个长尾任务都上一个专用模型，维护面比收益增长得更快。

**真实使用**：文档理解侧的公开代表是 LayoutLMv3 与 DocFormer【公开】（LayoutLMv3 论文发表于 ACM MM 2022），原清单中的 Qwen-VL-Doc 属 Qwen-VL 系列的文档理解方向（确切名称、能力与许可以官方文档当前版本为准）；视频理解侧有 VideoLLaMA、Google 的 VideoPrism【公开】（VideoPrism 于 2024 年发布，CVPR 2024）与 Gemini 1.5 的视频理解（主文件 §2.3 已把它列为视频理解代表）；语音侧 Whisper 由 OpenAI 于 2022 年开源、Paraformer 是阿里的非自回归 ASR 方案（主文件 §2.3 已列），FunASR 见主文件 §2.1 的语音识别条目；3D 侧的代表是 Point Transformer（ICCV 2021）、NeRF（ECCV 2020）与 3D Gaussian Splatting（SIGGRAPH 2023）。判断该不该上专用模型：先看通用模型错在哪——错在语义理解，还是要读的结构信息根本没被编码进去；只有后者才值得上专用。

#### 3.2.6 多模态 Agent

**被什么约束逼出来**：感知得再准也不改变任何东西。要让多模态能力产生效果，模型的输出必须能改变外部状态——而一旦输出是动作，错误就会作用在真实系统上，可靠性要求随之变化。

**结构**（桥建在动作空间，形成闭环）：

```text
  ┌──────────────────────────────────────────────────────┐
  │ ① 感知：截图 / 文档图像 / 语音 / 传感器 ──► 结构化观察  │
  │ ② 决策：VLM 推理 + 工具选择（读哪个库、调哪个 API）     │
  │ ③ 动作：点击 / 输入 / 调 API / 写文件 / 驱动物理设备    │
  │ ④ 观察：执行结果（含报错）回灌为下一轮输入             │
  └──────────────────────────────────────────────────────┘
        ↑ 每一轮都要重新感知环境，不是一次推理就结束
  关键：动作接口必须幂等或有补偿——模型的输出是概率性的，
        执行层不能假设「它这次是对的」
```

**为什么这样设计有效**：因为每一轮都把执行结果（含报错）重新作为观察送回模型，错误可以在下一步被纠正，所以「不可靠的感知 + 不可靠的推理」仍能闭环完成任务；因为动作空间是被显式声明的工具集合，能力边界与审计粒度都由这份声明决定，而不是由模型的自觉决定。

**代价**：误差会累积——第 2 步的小偏差会被第 5 步的动作放大，而 Agent 通常不区分「环境拒绝」与「自己错了」，会把拒绝当成需要重试：模型不像人会自己换一种调用方式，接口契约一旦模糊（字段缺失、错误码一律返回空集），它只会反复重试并编出看似合理的参数，把一处分歧放大成一批无效调用；成本按轮数增长，一轮演示里可能有几十次模型调用；权限必须授予到远超单次任务所需（否则点不动界面），因此独立身份与可归因的调用记录是准入条件，不是加分项。

**失效点**：当任务的成功判据是「绝对正确」而不只是「看起来做完了」时，本模式的「自主闭环」会反转成「把错误更高效地执行完」，因为**循环的终止条件是「模型认为任务完成了」，而不是「外部校验通过」**——而真正能判断对错的那个判据，模型看不到。修法是给关键步骤加可验证的中间结果（对账数字、单号回查、单据编号复核），而不是调大推理步数。

**真实使用**：【公开】GPT-4o 与 Claude 的 Computer Use 形态（2024）把「看屏幕 + 操作界面」做成通用能力（主文件 §2.1、本章 §5.1、§5.3 已列）；工具协议侧可参照 MCP【公开】（Anthropic 于 2024 年公开，本章 §5.3 已述；本节不给版本号，支持程度以官方文档为准）。判断一个 Agent 是否可上线：看它的写操作有没有幂等键与回滚路径——没有就还只是演示。

#### 3.2.7 多模态世界模型（World Model）

**被什么约束逼出来**：要规划就必须能预演，而在真实环境里试错太慢、太贵、太危险（自动驾驶、机器人）；唯一的出路是让模型学会「下一步会看到什么」，把试错搬进模型内部。

**结构**（桥建在时间上，预测的是下一时刻的观测）：

```text
  历史观测序列 ──► 学习环境动力学
    ├─ 训练目标：给定过去观测 + 动作，预测未来观测 / 下一帧
    └─ 三种用途：
         ① 生成：按条件生成一段连贯视频（主文件 §2.3 已给 DiT 的定位）
         ② 仿真：给策略模型一个可交互环境，替代真机试错
         ③ 规划：在模型内部推演多个动作序列，选回报最高者
  关键结构：视频 ──► 时空 token ──► 在 token 空间上做扩散去噪
```

**为什么这样设计有效**：因为模型学的是「观测随动作如何变化」这一转移关系，所以它能在没有真实环境的情况下生成反事实轨迹，规划得以在内部完成；因为视频生成与策略仿真共享同一个「预测下一观测」的目标，同一份能力可以同时服务内容生成与机器人训练两类场景，这也是它被当作 AGI 方向的原因（本章 §5.4）。

**代价**：数据与算力在另一个量级——它要学的不是一个任务的判别边界，而是视觉世界的动力学，训练数据是海量视频、算力是预训练级别；一致性没有保证，生成的下一秒画面在物理上可以完全不合理，而模型不会提示；评测困难，「像不像真实世界」没有单一指标，只能靠下游迁移成功率间接衡量。

**失效点**：当把世界模型当作可信仿真环境去训练策略时，它的「通用性」会反转成「系统性偏差」，因为**模型只学到训练分布里出现过的动力学，而规划恰恰要求它在没见过的状态下仍然正确**；策略会学会利用模型的偏差（在仿真里得分很高、上真机就失败），而这类失败无法通过增加算力以外的办法在仿真内发现。

**真实使用**：【公开】OpenAI 于 2024 年公布 Sora，其技术报告《Video generation models as world simulators》（2024）把视频生成模型表述为「世界模拟器」（可按该标题自行检索核验）；Google Veo 系列与 DeepMind Genie / Genie 2 属同一方向（主文件 §1.4、§2.1、本章 §5.1、§5.3 已列）。判断某个系统只是「视频生成」还是世界模型：看它对动作条件是否敏感——给定同一观测、不同动作能生成一致且不同的后续状态，才谈得上动力学。

### 3.3 模式选择决策表

| 约束组合 | 推荐模式 | 为什么不选另一个 | 关键判据 |
| --- | --- | --- | --- |
| 图像检索 / 以文搜图 / 零样本分类 | CLIP 风格 | 上 VLM 会把「检索」变成逐条生成，成本与延迟都高一个量级 | 是否需要在不重训的情况下加新类别 |
| 通用多模态理解（VQA / 文档 / 描述） | VLM 风格 | 双塔只能给相似度，给不出自然语言答案 | 输出必须是语言，且需要多步推理 |
| 实时交互 / 音频进音频出 | 原生多模态 | 桥接式级联（ASR → LLM → TTS）会丢韵律、按段累加延迟 | 能否接受把数据交给托管 API |
| 多模态检索增强 / 库内内容问答 | 多模态 Embedding + RAG | 把全库塞进上下文不可行，成本与窗口都不允许 | 库规模是否远超单次上下文 |
| 垂直行业（医疗影像 / 工业质检 / 文档版面） | 专用多模态模型 | 通用模型不编码任务结构，长尾关键样本最不可靠 | 通用模型错在语义，还是结构没进表示 |
| 跨系统自主执行（点界面 / 调系统 / 驱动机器人） | 多模态 Agent | 只输出文本不改变任何状态 | 写操作是否有幂等键与回滚 |
| 自动驾驶 / 机器人 / 需预演决策 | 多模态世界模型 | 直接真机试错的代价不可承受 | 是否需要「预演未来观测」做规划 |

最常被误选的一对是 **CLIP 风格** 与 **多模态 Embedding 检索**：它们都用编码器 + 向量，团队常以为「都接了 CLIP，检索这一块就算做完了」。误选的实际后果不是报错，而是**精度长期上不去且找不到原因**——把短文检索的语料直接搬成图像向量库后，语义粒度不匹配的问题会表现为「召回的内容总是差一点」，而每一次调参都像是在与玄学搏斗。正确的分界是：CLIP 解决「像不像」，检索系统要解决的是「召回什么、怎么排序、怎么与元数据过滤组合」，后者需要粗排 + 精排 + 元数据三件套，编码器只是其中一件。

### 3.4 组合模式：真实系统不会只用一种

**组合一：统一 Embedding 粗排 + VLM 精排与生成（多模态 RAG 的标准两层）**

- 组合构成：编码器与索引负责从海量库中召回候选，VLM 负责对少量候选做精细理解并生成答案。
- 职责边界：检索层保证「相关内容不会漏」，理解层保证「答案说得清」；两者的成本量级相差几个数量级，所以候选数必须严格控制。
- 运维代价：两条链路各自的评测与阈值独立；换编码器要全库重编码，换 VLM 要重新验证端到端效果，而两者会互相掩盖问题——召回变差与生成变差在业务指标上表现相同。
- 适合规模：库规模进入百万级以上、且需要自然语言答案的场景（商品搜索、内容理解、企业文档问答）。

**组合二：专用模型预处理 + VLM 理解（多模态输入流水线）**

- 组合构成：廉价的确定性模型先做结构化工件（OCR 转写、ASR 转写、关键帧抽取、版面检测），VLM 在工件之上做理解与推理。
- 职责边界：专用模型保证「字与位置不出错」，VLM 负责「意思是什么」；关键字段的最终取值应来自专用模型而不是 VLM 的复述。
- 运维代价：流水线多了一层，端到端延迟与失败面同时增加（任何一环超时都会拖慢整条链路）；两层的输出要能对齐，否则会出现「转写里有这个数字，但模型引用的位置对不上」。
- 适合规模：文档与视频类输入占主导、且关键字段有明确取值要求的场景。

**组合三：VLM + 多模态 Agent + 工具（可执行的感知链路）**

- 组合构成：VLM 做理解与决策，Agent 框架负责工具选择与循环，执行层提供幂等动作与回滚。
- 职责边界：VLM 不直接改系统状态，它只产出候选动作；动作的合法性、幂等性与权限由执行层负责。
- 运维代价：需要独立身份、配额、全量审计与回滚路径——执行层的每一次调用都要能归因到具体任务与调用方，否则失败无法追溯；模型的重试行为会把一次错误放大成一批调用，因此执行层必须有去重与熔断。
- 适合规模：任务可分解、关键步骤有外部校验、且失败可回滚的场景；不满足这三条时应停在「生成建议 → 人确认」这一步。

### 3.5 反模式与失效分析

| 反模式 | 症状（怎么发现它） | 后果（机制层面的后果） | 成因（为什么团队会写成这样） | 修法 |
| --- | --- | --- | --- | --- |
| **「盲目追求 SOTA」** | 所有场景都调同一个最强模型；账单与延迟随调用量同比例上升 | 单位任务成本由「最强模型的价格」决定，而任务难度分布是长尾的——多数调用只需要一次分类或一次 OCR | 排行榜只比能力不比单位成本，「最强 = 最稳」的直觉被默认接受 | 按任务难度分层：简单 OCR 用 PaddleOCR 这类轻量专用模型，复杂文档再上 Qwen-VL 这类 VLM；用同一评测集验证分层前后 |
| **「忽视延迟」** | 交互场景端到端等待进入秒级；用户开始重复点击 | 延迟预算里模型推理只是一部分，上传、网络往返、排队都在同一笔账上；一次长推理会阻塞整个会话 | 离线评测只看效果不看耗时 | 把延迟拆项测量（预处理 / 上传 / 排队 / 推理 / 后处理）；交互场景选本地或蒸馏方案、用流式输出 |
| **「忽视成本」** | 长视频 / 高分辨率输入把上下文打满；单次请求费用不可预测 | 【推算】30 分钟视频按 1 帧/秒 = 1800 帧；单帧视觉 token 下限按 224×224 输入、14×14 patch 计为 16×16 = 256 token（CLIP ViT-L/14 的标准配置）；1800 × 256 ≈ 46 万 token/次请求，已超多数模型单次上下文 | 输入形态没有工程约束，源上给什么就传什么 | 预处理先行：帧采样 + 切片 + 转写摘要，把「整段直传」改成「先廉价抽取再理解」 |
| **「忽视幻觉」** | 描述流畅但细节错（数字、否定、位置） | 正确与错误内容以同等置信度输出，下游无法用形态区分 | 生成式输出不携带「我在猜」的信号 | RAG + 知识库 / 知识图谱兜底 + 关键字段人工或规则复核；关键取值改由确定性模型给出 |
| **「忽视多语言」** | 中文文档的错误率明显高于英文，专有名词被音译 | 语言上限由编码器与预训练语料决定，改提示词改不了 | 选型时只用英文样例做对比 | 用自己的语料建小评测集再选型；中文场景评估 Qwen-VL / InternVL / 文心一言这类国产模型；必要时补领域词表 |
| **「数据隐私」** | 敏感图像离域上传；日志里留存原始图像 | 数据出境与留存合规风险由使用方承担，且难以回溯 | 先用托管 API 快速验证，之后再没回头 | 数据分级（可外发 / 不可外发）+ 本地化部署 + 脱敏 + 关闭图像留存 |
| **「忽视版权」** | 用 Midjourney 这类工具生成的内容直接用于对外物料 | 生成模型训练数据来源与输出权属在不同司法辖区规则不同，商用链条可能不完整 | 把生成工具的使用条款当成授权条款 | 商用前核对产品条款与当地法规、留存来源与授权记录；对高曝光物料走法务审查 |
| **「过度依赖单一模型」** | 全部任务走同一模型；一次版本更新后全线效果波动 | 能力上限与故障域同时被一个供应商绑定，迁移要重新评测全部场景 | 一次接入最省事，多模型组合看起来是过度设计 | 按能力分层组合（专用模型预处理 + 向量检索粗排 + VLM 理解生成），把调用按能力抽象 |
| **「忽视评测」** | 上线后只有业务方的主观反馈 | 没有基线就没有「这次改动是变好还是变坏」的判断，模型升级无法评估 | 多模态标注贵，评测集被排到最后 | 建小规模但固定的评测集 + 关键字段准确率 + 定期人工抽检 |
| **「忽视可解释」** | 出错时无法定位是视觉端还是语言端 | 归因只能靠重试，同类问题无法收敛 | 生成式模型天然不给解释，也被当成「没法给」 | 保留中间产物（检测框、注意力区域、OCR 原文）作为证据链；关键结论要求引用原文位置 |

三个最危险的反模式值得单独展开。

**「忽视成本」**之所以高发，是因为它的触发条件与「效果很好」同时出现：输入越完整、分辨率越高，模型答得越准——直到某天有人把一段长视频直接丢进来。上面那条推算说明问题不在单价，而在**输入形态与上下文的乘积**：一帧就是几百个 token，帧数与分辨率各自相乘，成本是输入规模的线性函数，而提问次数还会再乘一次。可行的最小工程约束是三步：先转写与抽关键帧（廉价且确定性），再对片段做摘要（一次调用换多次复用），最后才让 VLM 看到原始帧。

**「忽视幻觉」**的危险在于它在多模态下比纯文本更严重：文本幻觉至少与源文可比对，图像幻觉要与像素比对，而人的复核习惯通常停在「读起来通顺」。机制上的应对不是「更仔细地读」，而是**把关键取值从生成路径搬到确定性路径**：数字、编号、日期、金额由 OCR / 版面模型直接给出，VLM 只负责组织与解释；生成的部分必须能引用到原文位置，引用不到就当作未确认。

**「盲目追求 SOTA」**的代价不在单次调用，而在**它掩盖了真正的工作**：分层、预处理、评测集、缓存这些工程动作在「反正最强模型大概能过」的心态下会被一直推迟，等到成本或延迟成为硬约束时，团队手里没有评测集、没有分层路由、也没有预处理流水线，只能整体重构。判据很简单：**如果把你正在用的最强模型换成便宜一个量级的模型，系统还有多少能力保留？** 答不出来，说明工程层几乎不存在。

### 3.6 规模跃迁时模式何时该换

模式不是一劳永逸的。下面这些阈值的共同点是：**触发它们的不是数据量，而是输入形态、验证要求或延迟预算的变化**。

| 跃迁 | 原模式 | 为什么开始疼 | 换成 | 迁移的代价 |
| --- | --- | --- | --- | --- |
| 单图问答 → 长视频理解 | 逐帧 / 切片直传 VLM | token 随帧数线性增长，单次请求的成本与延迟不可定价 | 预处理层（关键帧 + 转写 + 分段摘要）之后再做理解 | 要建预处理与缓存；摘要本身也是模型调用，且会引入自己的误差 |
| 通用场景 → 垂直行业 | 通用 VLM | 领域长尾落在通用训练分布之外，错在最关键的少数样本上 | 专用模型（任务归纳偏置）或领域微调 | 标注 + 训练 + 评测三份成本；模型矩阵开始出现，版本管理变成常态 |
| 离线批处理 → 实时交互 | 托管大模型 API | 上传、网络往返、排队与生成时长都进入延迟预算 | 本地小模型 / 蒸馏 / 流式输出 | 效果折让 + 部署与运维成本；数据边界问题反而顺带解决 |
| 检索 → 需要跨步推理 | 多模态 Embedding + RAG | 向量只给相似度，给不了计数、空间关系与组合推理 | VLM 做理解，需要动作时再上 Agent | 上下文与成本上升；需要按问题类型做分级路由 |
| 级联流水线 → 语音 / 视频原生交互 | ASR → LLM → TTS 级联 | 级联丢掉韵律与打断，延迟按段累加 | 原生多模态（音频进、音频出） | 只能走托管 API，数据边界与可替换性一起交出 |
| 感知 → 执行 | VLM 只输出文本 | 需要能改变外部状态的接口，而错误会作用在真实系统上 | 多模态 Agent（幂等工具 + 回滚 + 独立身份） | 权限、审计、配额、回滚路径都要新建 |
| 内容生成 → 用于决策 / 训练 | 生成模型直接产出 | 生成质量的判据是「像」，决策要的是「对」 | 世界模型 + 外部校验（仿真训练、真机验收） | 仿真偏差无法自查，必须建真机增量数据闭环 |

最容易误判的是「级联流水线 → 原生交互」这一行。它被低估的原因是**级联方案在离线评测里的分数通常不差**——转写准确率、答案正确率都能看，真正丢掉的是延迟的叠加与韵律、打断这类交互质量，而这两项在离线评测里根本不进指标。所以这个跃迁要盯的不是准确率，而是**首个响应字节的时间与「用户打断后系统的反应」**。

### 3.7 自检清单

- [ ] 这座桥建在哪一层？能否用一句话说清「系统传过来的是相似度、是 token、还是动作」？
- [ ] 输入切法（分辨率、帧率、切块数）是否被显式约束？超预算的输入是报错、降采样还是静默截断？记录在哪？
- [ ] 关键取值（数字、编号、金额、日期）来自生成路径还是确定性路径？生成的部分能否引用到原文位置？
- [ ] 是否有一个外部判据能判断输出对不对？没有的话，为什么还敢让它自动执行？
- [ ] 检索单元的向量化是统一空间还是多空间并行？多空间融合时的 TopK 合并与权重规则写在哪？
- [ ] 源数据更新后索引多久同步一次？有没有「索引滞后但系统仍高置信回答」的窗口？
- [ ] 编码器换版本时，全库重编码需要多久、成本多少？这个数字是否被评估过？
- [ ] 关键字段上是否对比过「专用模型」与「通用大模型」——错在哪一侧，是语义还是结构？
- [ ] 交互场景的延迟是否按项拆开测过（预处理 / 上传 / 排队 / 推理 / 后处理）？
- [ ] 敏感数据的分级与部署边界是否明确？有多少类输入是不允许离开本地的？
- [ ] 生成类内容商用前，来源与授权链条是否可查、条款是否已核对（以产品当前条款与当地法规为准）？
- [ ] 是否有一个固定评测集，能回答「把最强模型换成便宜一个量级的模型，能力还剩多少」？

### 3.8 小结

| 你的约束 | 建议模式 | 关键理由（机制层面） |
| --- | --- | --- |
| 只要能检索、不要求说出理由 | CLIP 风格 | 桥建在表征层，零样本与离线索引都成立；但没有语言输出通道 |
| 需要语言答案与多步推理 | VLM 风格 | 视觉 token 进入 LLM 序列；代价是投影层的有损压缩 |
| 需要原生交互、能接受托管边界 | 原生多模态 | 对齐发生在参数里，语气与打断才保得住；代价是不可拆分 |
| 库远超上下文、要回答库内问题 | 多模态 Embedding + RAG | 检索代价与索引规模相关，与上下文无关 |
| 垂直任务、关键字段要精确 | 专用多模态模型 | 结构先验写进表示；代价是每个任务一份标注与评测 |
| 要改变外部状态 | 多模态 Agent | 闭环能自我纠错；前提是幂等动作与外部校验 |
| 要先预演再决策 | 多模态世界模型 | 学的是观测转移，可内部推演；代价是偏差不可自查 |

> 本节小结：本主题下决定模式选择的**唯一那条约束是「桥建在哪一层」**——建在表征层只得到距离，建在投影层得到语言，建在参数里得到原生融合，建在索引上得到规模，建在归纳偏置上得到精度，建在动作上得到执行力，建在时间上得到预演能力。每一层的代价是下一层能力的准入费：越往后，能表达的东西越多，能验证的东西越少、能替换的部件越少。所以正确的问法不是「哪个模型最强」，而是「我需要的传递物是什么，以及我准备用什么外部判据来验证它」。
