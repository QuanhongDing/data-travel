## 7. 与其他方法对比

> 原 § 7 共 79 行、为「10 维度 1–5 打分表 + 场景决策树 + 6 个组合条目」，缺少机制解释与可溯源证据，重写为 ~300 行的对比与选型工程。

### 7.1 先立判据：为什么打分表会误导

把一个候选方案压成 1–5 分，丢掉的恰恰是选型最需要的那部分信息：**这个分数在什么条件下成立**。

同一张表里，传统 CV 在「工程成熟度」上高于多模态 AI，这个差值不是模型能力强弱的差，而是两者**输出空间不同**：

- 判别模型的输出是从固定标签集里选一个，可以拿一组固定回归样本断言「这次改动没让它变差」；
- 多模态模型输出自由文本，同一输入两次调用之间就未必一致。

取决于你的场景要的是「可写进 CI 的确定性」还是「覆盖没被预先定义过的长尾问题」，这两个分值的权重会反向——**分数没有错，错的是它被当成与场景无关的结论**。

打分表的第二个问题是**维度之间不可通约**。把「算力成本」与「推理能力」并排打分再心算加权，等价于假设 1 分的算力等于 1 分的推理能力；但在你自己的账单上，这两项的换算比例由调用量决定，不由表格决定。10 万页文档一次性批处理与每天几十次问答，同一个模型的性价比结论可以完全相反。

第三个问题是**把「能力出现了」当成「整条链路可以少一层」**。模型 API 能吃图像，改的是输入形态，不是索引结构：从大规模语料里「找哪几条」这件事仍然只能靠索引完成（[§5 §5.2.1](01-multimodal-ai-section-5-ai.md)）。打分表把这两件事混在一格，于是读者会把「接口可用」读成「架构可以简化」——这是本节要反复拆开的那一类混淆。

第四个问题是**打分表不写代价**。任何一项能力提升都对应一项成本结构的变化：开放输出换来长尾覆盖、付出可复现性；自托管换来数据边界可控、付出可选模型范围的收窄。只列收益的对比表，会选择完成之后才让人发现代价。

**本章的做法**：先问「它做不到什么」，再问「成本随什么增长」，再问「它的核心机制是否匹配我的数据形态与访问模式」，最后才看生态与演进。**打分表可以作为排序线索，不能作为结论。**

**本章采用的 6 条判据**：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| 输出空间 | 输出是封闭标签集还是自由生成 | 封闭输出可以写死回归断言；开放输出只能抽检——它决定这个候选能不能进无人值守链路 |
| 成本结构 | 成本随什么变量增长（批次数 / 调用次数×输入体量 / 步数） | 三类曲线有交叉点，交叉点才是「谁的性价比更高」的答案 |
| 机制契合度 | 我的语料是按「编码一次、查询多次」消费，还是每次重新理解 | 索引路径与直读路径的规模上限差若干个数量级 |
| 验收判据 | 我能不能判断输出对不对（「像」还是「对」） | 判据不存在时，能力再强也只能进「辅助 + 人确认」流程 |
| 锁定面 | 换掉它要重做什么（重编码 / 重评测 / 重写提示词） | 桥接式可以只换一层，原生与 Agent 只能整换，代价差一个量级 |
| 演进风险 | 它换代时我的资产会不会作废 | 向量索引绑定编码器版本、提示词与评测绑定模型版本，换代成本必须提前写进选型文档 |

这 6 条判据的用法是**逐条淘汰，不是逐条打分**：

1. 先用「能力边界」（输出空间 + 验收判据）淘汰做不到的——例如要求可写死回归的场景，直接淘汰开放输出；
2. 再用「成本结构」比较剩下的——看谁的成本随你的主导变量增长，并把交叉点算出来；
3. 最后用「锁定面」与「演进风险」判断代价你付不付得起——这一步淘汰的往往是看上去最优的那个候选。

### 7.2 候选方案全景

| 候选 | 定位 | 核心机制（一句话） | 典型使用者 | 许可 / 商业模式 |
| --- | --- | --- | --- | --- |
| 传统 CV（YOLO / ViT） | 图像单模态判别 | 单次前向输出类别或框，输出空间固定 | 质检、安防、自动驾驶感知 | 开源权重为主，各仓库许可不同，以仓库当前许可为准 |
| 传统 NLP（微调小模型 / 规则 + 模型混合） | 文本单模态判别 | 编码器 + 分类头，输出空间固定 | 分类、抽取、风控规则 | 开源权重 + 自建 |
| OCR 引擎（Tesseract / PaddleOCR 一类） | 图像 → 文本的专用转换 | 检测 + 识别两步，输出可比对 | 票据、证照、扫描件 | 开源为主，以仓库当前许可为准 |
| 单模态 LLM | 文本理解与生成 | 自回归生成文本 token | 文本问答、代码、摘要 | 闭源 API 与开源权重并存 |
| 多模态 Embedding（CLIP / ImageBind 一类） | 跨模态向量化 | 把多模态数据映射到同一向量空间，供检索用 | 以文搜图、去重、聚类 | 开源权重 + 闭源 API |
| 多模态 AI（桥接式 VLM：LLaVA 系 / Qwen-VL / InternVL） | 视觉 + 语言理解 | 视觉编码器 + 投影层 + LLM，对齐发生在投影层 | 文档理解、图像问答 | 闭源 API + 可自托管开源权重 |
| 原生多模态模型（GPT-4o / Gemini 1.5–2.0 一类） | 多模态理解 + 生成一体 | 各模态 token 在同一条序列联合训练，对齐发生在参数里 | 语音助手、实时交互 | 闭源 API 为主 |
| 多模态生成模型（Stable Diffusion / DALL·E / Midjourney / Sora / Veo / 可灵） | 条件生成媒体 | 扩散去噪 / DiT 生成 | 内容生产、素材生成 | 闭源 + 开源权重并存 |
| 语音模型（Whisper / VALL-E 系） | 语音 ↔ 文本 | 编码器 + 自回归解码 | 会议转写、语音交互 | 开源权重 + 闭源 API |
| 视频理解（VideoLLaMA / Video-LLaVA / Gemini Video） | 时序理解与视频问答 | 抽帧 + 时间位置编码 + LLM | 视频审核、长视频摘要 | 开源 + 闭源 |
| 3D 视觉（Point Transformer / NeRF / 3D Gaussian Splatting） | 几何与空间理解 | 点云或辐射场表示 | 自动驾驶、机器人、数字孪生 | 算法与库开源 |
| 世界模型（Sora / Veo / Genie 2 / GAIA-1 一类） | 观测预测与生成 | 学观测分布而非可控的状态转移 | 仿真、预演（研究阶段） | 闭源为主 |
| 多模态 Agent（Claude Computer Use / OpenAI Operator · CUA） | 感知接到动作 | 模型按当前状态生成动作序列并执行 | GUI 自动化、跨系统任务 | 闭源 API + 自建执行层 |
| 多模态 RAG（CLIP 类 Embedding + 向量库 + VLM） | 检索编排 | 索引路径筛候选、直读路径做精读 | 企业知识问答、多模态检索 | 组件开源，评测自建 |
| 知识图谱 / GraphRAG | 关系显式化的另一套索引 | 实体与关系显式存储、可遍历 | 行业知识库、风控 | 图数据库开源 / 商业 |

**表后第一件事：先分族再选。** 上表这 15 个候选按机制只分成八族，同族内部差异小、跨族差异大（语音模型一个候选横跨两族：转写侧入判别族，合成侧并入生成族的「音频生成」）：

| 族 | 成员 | 族内真正要比的 | 跨族真正要比的 |
| --- | --- | --- | --- |
| 判别族 | 传统 CV、传统 NLP 微调、OCR 引擎、语音模型（转写侧） | 标签体系（语音侧为词表与口音覆盖）、部署方式、单样本成本 | 输出空间封闭 vs 开放 |
| 向量化族 | 多模态 Embedding | 向量维度、跨模态可比性、编码器换代成本 | 只做检索 vs 还要做理解与生成 |
| 单模态生成族 | 单模态 LLM | 上下文长度、成本、可自托管性 | 单模态 vs 多模态输入 |
| 多模态理解族 | 桥接式 VLM、原生多模态、视频理解 | 对齐发生在投影层还是参数里、帧采样与时间位置编码 | 理解 vs 生成 |
| 生成族 | 图像 / 视频 / 音频生成（含语音合成）、世界模型 | 输出可控性、验收判据 | 判据是「像」还是「对」 |
| 空间感知族 | 3D 视觉（点云 / 辐射场） | 表示形式（点云 / 体素 / 辐射场）、标注形态 | 几何先验要不要写进输入表示 |
| 行动族 | 多模态 Agent | 环境可重置性、动作幂等性 | 动作由脚本写死 vs 模型生成 |
| 编排族 | 多模态 RAG、知识图谱 | 索引结构（向量 / 关系图） | 编排层 vs 能力层 |

三条常在选型会上被忽略的硬边界：

- **能力边界不在「支持几种模态」上**：支持图像与视频的模型多，能给出可复现输出的少——后者才是稀缺项。
- **候选之间常常不是替代关系，而是接力关系**：编排族（RAG / 知识图谱）本来就要与某个理解族或向量化族成员一起用，把它们排进同一张比较表会得出伪结论。
- **同族内部的差异可以靠配置消化，跨族差异只能靠架构消化**：前者改提示词与阈值，后者改数据流与责任划分。

多数跨族差异不是「谁更强」，是**代价落在哪一层**：落在接口层（调用费、数据边界）、落在参数层（不可拆分）、落在执行层（沙箱与幂等）。先确定族与代价层级，再在族内比，能省掉一半比较。

### 7.3 机制差异：为什么它们表现不同（核心节）

#### 7.3.1 输出空间：封闭标签集 vs 自由生成

- **机制是什么**：判别模型从固定标签集里选一个并给出置信度；生成模型输出自由文本或像素，输出空间无界。这一条决定「验收能不能自动化」，不是「谁更聪明」。
- **它在各候选中的实现差异**：

| 候选 | 输出 | 由此得到的 | 由此付出的 |
| --- | --- | --- | --- |
| 传统 CV / 传统 NLP | 标签 + 置信度 | 可用固定回归集断言「没变差」 | 只能回答训练时定义过的问题 |
| OCR 引擎 | 文本串 | 字段级可比对 | 版式复杂时错误率上升，且错误不可逆 |
| 单模态 LLM / VLM | 自由文本 | 覆盖未预先定义的长尾问题 | 两次调用未必一致，验收靠抽检 |
| VLM 输出结构化字段 | 自由文本 + 提示词约束 | 形式上接近判别 | 约束由提示词提供，不是输出空间被限死 |

- **由此必然导出的性质**：因为输出空间封闭，**所以**可以用一组固定回归样本加关键字段准确率断言「这次改动有没有让它变差」，**代价是**业务每加一类就要重新标注与训练；反过来，因为 VLM 的输出是自由生成，**所以**它能覆盖长尾问题，**代价是**同一输入两次输出可能不同，「看起来对」与「对」之间没有自动判据——门禁与回归都无处可挂。
- **公开证据**：【公开】判别式一侧的代表作有 YOLO（Redmon 等，CVPR 2016）与 ViT（Dosovitskiy 等，ICLR 2021）；【公开】「视觉编码器 + 投影层 + LLM」这一开放输出形态的代表作是 LLaVA（Liu 等，NeurIPS 2023，Visual Instruction Tuning）。
- **失效条件**：当分类体系本身在持续扩张（新增品类、新增单据类型）时，判别模型的优势消失——每次扩张都要重走标注与训练，而开放输出模型只要改提示词；反过来，当判据要求逐条可复现（对账、计费）时，开放输出的优势消失。
- **判定方法**：写出你这个任务的验收断言。如果它只能是「人工看看对不对」，说明你落在开放输出一侧，选型时要把抽检人力与评测集算进预算，而不是只算 API 费用。

#### 7.3.2 对齐发生在哪里：投影层（外接适配器）vs 参数里（联合训练）

- **机制是什么**：桥接式把模态之间的对齐交给一个外接的投影层或查询式适配器；原生多模态把对齐放进同一条序列的联合训练里，模态关系在参数中形成。这是**架构选择**，不是接口能力。
- **它在各候选中的实现差异**：

| 候选 | 对齐位置 | 可替换性 | 跨模态细粒度同步 |
| --- | --- | --- | --- |
| 桥接式 VLM（LLaVA / Qwen-VL / InternVL） | 投影层（外接） | 视觉编码器与 LLM 可分别替换 | 被投影层压掉 |
| 原生多模态（GPT-4o / Gemini 一类） | 参数里（联合训练） | 只能整换 | 保留（语气、韵律、音画对应） |
| 级联（ASR → LLM → TTS） | 各段之间用文本交接 | 各段可替换 | 丢在环节之间，且延迟按段累加 |
| 多模态 Embedding | 对比学习得到的共享向量空间 | 编码器可换，但要全库重编码 | 不涉及（只做相似度，不生成） |

- **由此必然导出的性质**：因为对齐发生在参数里，**所以**「音频进、音频出」不必经过转写与合成的级联，低延迟与跨模态细粒度同步这两项才成立，**代价是**任何一部分都换不掉——换视觉编码器等于换模型，出错时也无法定位是感知端还是语言端错了（[§5 §5.2.2](01-multimodal-ai-section-5-ai.md) 的失效点）；反过来，**因为**桥接式把对齐放在一个可替换的适配器里，**所以**它能自托管、能只升级其中一层，**代价是**那些无法用文本 token 转述的属性（语气、韵律、音画对应）会在投影层被压掉。
- **公开证据**：【公开】桥接式一侧有论文可核（BLIP-2 的 Q-Former，Li 等，ICML 2023）；【公开】原生多模态侧有具名材料可核——GPT-4o 的官方发布与系统卡（OpenAI，2024）、Gemini 1.5 技术报告（Gemini Team，"Gemini 1.5: Unlocking multimodal understanding across millions of tokens of context"，2024），**文档名与年份可检索，具体版本与条目以官方发布说明当前版本为准**。
- **失效条件**：任务不需要跨模态细粒度同步时（多数文档理解与图像问答属于此类），原生架构的这两项收益接近于零，而你仍要付它不可拆分的代价。
- **判定方法**：能否举出一个只有原生架构能做、桥接式做不到的任务？指不出，说明你在为不需要的能力付代价；若答得出，则要接受「换不掉」这一条写进选型文档。

#### 7.3.3 验收判据：「像」还是「对」——决定它能否进自动链路

- **机制是什么**：任务能被写成「输出与外部事实是否一致」（对），还是只能写成「输出看起来是否合理」（像）。这一条与模型强弱无关，只与任务形态有关。
- **它在各候选中的实现差异**：

| 任务形态 | 判据 | 能否自动回归 | 上生产的前提 |
| --- | --- | --- | --- |
| OCR / 结构化抽取 | 对（字段可比对） | 能（固定评测集 + 关键字段准确率） | 评测集不过期 |
| 检测 / 分类 | 对（标签可比对） | 能 | 标签体系稳定 |
| 语音识别（通用语料） | 接近「对」 | 能 | 自有口音 / 噪声分布要单独抽样 |
| 语音识别（方言、强噪声） | 退化为「像」 | 不能 | 人工抽检 + 关键字段复核 |
| 图像 / 视频 / 音频生成、开放问答 | 像 | 不能 | 人确认环节不可省 |

- **由此必然导出的性质**：因为生成类任务的判据是「像」，**所以**它无法自动断言「没变差」，回归测试与责任归属都必须靠人，**代价是**它只能进「辅助创作 + 人确认」的流程，无法进无人值守链路；反过来，**因为**抽取类任务有外部可判定的字段，**所以**它可以被写进 CI（对固定评测集跑关键字段准确率），**代价是**评测集本身要持续维护——一份过期的评测集，会让你在不成立的前提上做出已经发生的决策。
- **公开证据**：【公开】语音侧有公开模型与评测方式可核（Whisper，Radford 等，2022）；【经验】生成侧与多模态 RAG 侧目前没有可跨厂商复用的验收协议，属「需自建评测集与验收判据」的状态（[§5 §5.3](01-multimodal-ai-section-5-ai.md) 的交接物表「多模态 ↔ 评测集与验收判据」一行已把它列为「需自建，这是本节所有 L2 的共同门槛」）。
- **失效条件**：判据存在但样本不覆盖你的分布时，公开榜单分数不代表你的可用性。
- **判定方法**：拿自有样本跑一次对照（方言 / 版式 / 噪声各抽一批），而不是看榜；把「典型 / 边界 / 长尾」三批样本存成可复测的基线，换模型时用同一批重跑。

#### 7.3.4 动作闭环：动作由脚本写死，还是由模型按当前状态生成

- **机制是什么**：旧做法由人先把界面抽象成坐标与选择器脚本；Agent 从像素与可访问性树推断下一步动作。改变的只是动作的来源（预定义 vs 即时生成），执行层的责任划分没有变。
- **它在各候选中的实现差异**：

| 形态 | 动作来源 | 天然性质 | 主要缺口 |
| --- | --- | --- | --- |
| 脚本 / RPA | 人预先写死 | 幂等、可回归 | 界面一变即失效，长尾写不出来 |
| 多模态 Agent | 模型按当前状态生成 | 覆盖长尾、界面变化不必然失效 | 环境要可重置、动作要幂等、方差大 |
| 模型生成 + 人确认后执行 | 模型生成、人复核 | 可回滚 | 复核人看不懂动作依据时变成橡皮图章 |

- **由此必然导出的性质**：因为动作由模型按当前状态生成，**所以**界面变化不再必然让流程失效、长尾路径第一次能被覆盖，**代价是**环境必须可重置、动作必须幂等，否则模型的重试会把一次错误放大成一批调用；又因为一次执行是一条 n 步轨迹，**所以**任务整体成功率随步数按单步可靠性的 n 次方衰减，而不是等于单步准确率——**这是步数比模型能力更早决定能不能上生产的原因**。
- **公开证据**：【公开】Computer Use 类能力自 2024 年起有正式文档与调用方式（Claude 侧以 beta 形式发布；OpenAI 侧以 Operator / CUA 名义发布），**具体条目与可用范围以官方文档当前版本为准**；【公开】Agent 评测基准有具名论文与公开榜单可核——"AgentBench: Evaluating LLMs as Agents"（2023）、"WebArena: A Realistic Web Environment for Building Autonomous Agents"（2023）、"OSWorld: Benchmarking Multimodal Agents for Open-Ended Tasks in Real Computer Environments"（2024），三者的任务集、评测环境与提交格式都写在论文与榜单页里，可按论文标题检索核验。
- **失效条件**：环境不可重置（依赖外部服务状态）时，两次运行结果不可比，这条路线退化为不能做回归的演示；基准里的工具权限是固定的，与生产中的权限、超时、长尾接口不是一回事。
- **判定方法**：把同一任务在同一环境快照上连跑数次，记录步数分布与失败分类【经验】。只看「成没成」的评估，回答不了「上生产还差什么」。

**四个机制维度合起来看**，它们各自锁死一件事：

- 7.3.1 决定**验收能不能自动化**；
- 7.3.2 决定**未来能不能局部替换**；
- 7.3.3 决定**能不能进无人值守链路**；
- 7.3.4 决定**长流程能不能上生产**。

某一个维度不满足时，用另一个维度的高分去补偿通常是无效的：验收自动化不了，再便宜也不能进自动链路；不可拆分，再准确也换不掉。**这正是打分表最容易骗人的地方——它鼓励你把这些维度加总。**

### 7.4 成本结构对比（不是价格表，是成本函数）

先写清每个候选的成本**随什么变量增长**，再谈贵不贵：

```text
判别模型（传统 CV / 传统 NLP）   成本 ≈ 一次性训练与标注成本 + 单样本成本(近似固定) × 批次数
向量化（多模态 Embedding）        成本 ≈ 全量编码一次（可视作索引路径的固定项）
多模态理解（VLM 直读）          成本 ≈ 调用次数 × 输入体量(视觉 token 数) × 单价
多模态 RAG（索引 + 精读）       成本 ≈ 全量编码一次 + 查询次数 × Top-K × 单件直读成本
生成模型（图 / 视频 / 音频）     成本 ≈ 生成时长或分辨率 × 次数（且输出不可复现，重跑即重付）
多模态 Agent                    成本 ≈ 步数 × 单步成本 × (1 + 重试放大因子)
编排层（向量库 / 图库 / 目录）   成本 ≈ 固定集群成本 + f(向量或实体数) + g(查询并发)
```

**主导项与隐性成本**：

| 候选 | 主导项（成本随什么增长） | 隐性成本（账单上看不到） |
| --- | --- | --- |
| 判别模型 | 标注工作量（每扩一类重来一次） | 误判造成的业务返工 |
| 向量化 / 索引 | 向量条数与查询并发 | 编码器换代时的全库重编码 |
| VLM 直读 | 输入体量（分辨率、帧数、时长） | 模型换代后全部评估与提示词重跑 |
| 多模态 RAG | 查询次数 × Top-K | 评测集维护、重排分数口径的校准 |
| 生成模型 | 生成时长或分辨率 × 次数 | 不可复现导致的重跑与人工筛选 |
| 多模态 Agent | 步数 × 重试 | 沙箱、幂等、审计等执行层建设 |
| 编排层 | 向量或实体数、查询并发 | 与上游元数据的一致性维护 |

**【推算】索引路径与直读路径差多少**：设语料 N 件、每次查询精读 K 件、共 Q 次查询、单件单次消费成本为 c，取 N = 10 万、K = 20、Q = 1000：

- 索引路径总成本 ≈ N·c + Q·K·c = 10 万·c + 1000×20·c = 12 万·c
- 直读全量总成本 ≈ Q·N·c = 1000 × 10 万·c = 1 亿·c
- 两者之比 ≈ 0.0012，即**索引路径约为全量直读的千分之一量级**

推导里没有引用任何外部单价：把你自己账单上的单价乘进去即可，会变的只是绝对值。这里有两个比值要分清：**单次查询里「读全量」与「只精读 K 件」的成本比等于 N / K**（本例 10 万 / 20 = 5000），它只由「语料件数」与「你要精读几件」决定，与用哪家的模型无关；上面那条 0.0012（即直读全量约为索引路径的 833 倍）则是**把一次性编码成本摊进 Q 次查询之后、两条路径的总成本之比**，它随 Q 变化——Q 越大越向 N / K 逼近，Q = 1 时两者相等（见下一个算例）。

**【推算】反向确认交叉点**：同一个算例取 Q = 1（语料只被检索一次）：

- 索引路径 ≈ N·c + 1·K·c = 10 万·c + 20·c ≈ 10 万·c
- 直读全量 ≈ 1 × 10 万·c = 10 万·c
- 两者几乎相等——这正是 7.5 节点 ⑥ 的阈值来源：**一次性批处理不值得为它建索引，从第二次检索开始才值得。**

**【经验】Agent 的失败放大**：若单步可靠性为 98%，走 20 步的任务整体成功率约为 0.98²⁰ ≈ 2/3；同样 98% 只走 5 步则约为 0.90。**步数是可设计的变量**——把长流程拆成几个短流程、给每步加幂等与熔断，比换一个更强的模型更能提高任务成功率。

**最容易被漏算的一项：换代成本。** 向量索引绑定编码器版本（换版本等于全库重编码），提示词与评测绑定模型版本（换版本等于全部重跑）。它不在任何月度账单上，但通常是这类系统里最大的一笔一次性支出——[§5 §5.3](01-multimodal-ai-section-5-ai.md) 的交接物表已经把「编码器版本 + 模型版本」列为必登记字段，登记的目的就是让这笔成本可预算。

### 7.5 决策树（每个分支都要有阈值依据）

```text
[① 产出是「判断」还是「内容」？]
   ├── 内容（图 / 视频 / 音频）
   │      └── [② 验收判据是「对」还是「像」？]
   │             ├── 「对」（有外部可判定的正确性） → 生成模型 + 规则/人工验收
   │             └── 只有「像」 → 只能进「辅助创作 + 人确认」，不进自动链路
   └── 判断
          └── [③ 输入是单模态还是多模态联合？]
                 ├── 单模态文本 → 单模态 LLM（开放问题）/ 传统 NLP 微调（标签封闭）
                 ├── 单模态图像 → [④ 标签集是否封闭可枚举？]
                 │        ├── 封闭 → 传统 CV（YOLO / ViT）
                 │        └── 开放（要自由描述或推理） → 桥接式 VLM
                 ├── 单模态音频 → [转写还是合成？]
                 │        ├── 转写 → 语音模型（Whisper 系）：判据接近「对」，按口音 / 噪声另抽样
                 │        └── 合成 → 生成族（VALL-E 系）：产出是「内容」，归 ①→② 那一支
                 └── 多模态联合 → [⑤ 是否需要跨模态细粒度同步？]
                          ├── 需要（语音韵律 / 音画对应） → 原生多模态模型（接受不可拆分）
                          └── 不需要 → 桥接式 VLM（可自托管），并继续问：
                                   [⑥ 同一份语料会不会被反复检索（Q 大于 1）？]
                                      ├── 不会（一次性批处理） → 直读路径即可
                                      └── 会 → 多模态 RAG（索引路径 + 精读 Top-K）
   [⑦ 需要改变外部系统的状态吗？]
      ├── 不需要 → 交付「判断」或「内容」，到此为止
      └── 需要 → 多模态 Agent：先在可重置沙箱里做回归，再考虑生产写入
```

**阈值依据**（与树上 ①–⑦ 一一对应）：

- **①**：依据是输出空间的形态（7.3.1）——「内容」类任务的判据天然是相似性，「判断」类任务可能可以写成字段比对；这一步不含数字，它只决定后面走哪条链。
- **②**：依据是判据的**存在性**而非数值——有外部可判定的正确性才允许进自动链路；判据只有「像」时必须保留人确认环节（7.3.3 的失效条件）。
- **③**：依据是成本函数里的输入体量项（7.4）——多模态联合输入的视觉 token 数随分辨率与帧数上升，单模态任务若走多模态链路，等于为一个不参与判断的模态付输入体量的钱。音频同理：只有音频这一路输入时，用专用语音模型转写即可，不必引入多模态链路。音频内部再按判据分（7.3.3）——转写的输出可与原文逐段比对，落在「接近『对』」一侧，因此归判别族（方言与强噪声下退化为「像」，是这一族的失效条件）；合成的产出是「内容」而不是「判断」，判据只有「像」，由 ① 的「内容」支接走、归生成族。
- **④**：依据是「封闭输出可写死验收」（7.3.1）：标签集封闭且稳定时，判别模型的单样本成本比生成式模型低一个量级以上【经验】；标签集会持续扩张时此阈值失效，改走开放输出。
- **⑤**：依据是「对齐发生在参数里」这一机制（7.3.2）——只有需要跨模态细粒度同步时，原生的收益才不为零；判据是能否举出一个只有原生能做、桥接式做不到的任务。
- **⑥**：依据是成本交叉点的推导（7.4）：令索引路径总成本 N·c + Q·K·c 等于直读全量总成本 Q·N·c，解得 Q = N / (N − K) ≈ 1（本例 N = 10 万、K = 20）。**交叉点不在「查询很多次」，而在「多于一次」**——同一份语料只要会被第二次检索，索引路径在总成本上就占优；反过来说，一次性批处理场景不必为它建索引。
- **⑦**：依据是轨迹可靠性的衰减（7.3.4）：n 步任务整体成功率约为单步可靠性的 n 次方，20 步、单步 98% 时约为 2/3——步数越大越必须拆步、加幂等与熔断，而不是直接接生产；沙箱这一条不是成本项，是能不能做回归的前置条件。

**这棵树的读法**：先走 ①–② 判断产出类型，再走 ③–⑥ 判断能力落点与消费模式，最后用 ⑦ 判断要不要接执行层。**每一步只用一条判据**，不要把后面的问题提前搬进来——「先用 Agent 做个原型看看效果」这类顺序颠倒，常见的后果是先付了执行层的建设成本，再发现根因在检索召回。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因（机制层面） |
| --- | --- | --- | --- |
| 封闭标签集的工业质检 | 传统 CV 判别模型 | VLM 做低置信复核 | 主线用 VLM：单样本成本高一个量级【经验】，输出不可复现，写不出固定回归 |
| 票据 / 表单结构化抽取 | 桥接式 VLM + 关键字段抽检 | OCR + 模板规则 | 纯 VLM 且无人抽检：字段级错误会不可逆地污染下游 |
| 跨模态检索（以文搜图） | 多模态 Embedding + 向量库 | 关键词 + 元数据 | 纯关键词：向量空间保留语义相似度、主动丢弃字面标识符的区分度（[§3 §3.2.4](01-multimodal-ai-section-3-sec3.md)） |
| 企业文档问答 | 多模态 RAG | 全量直读 | 全量直读：查询多于一次即丧失成本优势【推算】——同一份语料只要被第二次检索，索引路径总成本就更低（7.5 节点 ⑥）；查询量到上千次时差距拉到近千倍（7.4 算例 Q = 1000 时约 833 倍），继续增加查询会向 N / K = 5000 逼近 |
| 内容生产（图 / 视频 / 音频） | 生成模型 + 人确认 | 素材库检索 | 进自动链路：判据只有「像」，回归与责任归属都靠人 |
| 视频审核 / 长视频摘要 | 视频理解 + 抽帧策略（先抽样再精读） | 全量逐帧理解 | 全量逐帧：输入体量随帧数线性上升，而信息密度通常集中在少数片段 |
| GUI 自动化 | 沙箱内 Agent 回归 | 脚本 / RPA | 直接生产写入：重试会放大，且环境不可重置时无法回归 |
| 自动驾驶 / 机器人感知 | 3D 视觉 + 封闭场景验收 | 世界模型做预演 | 通用世界模型：判据是「能否指导决策」，目前无公开材料支撑 |
| 通用 AI 助手 | 多模态 Agent + 原生多模态 | 桥接式 VLM | 桥接式：需要语音与音画同步时，细粒度对应被投影层压掉 |

**常见组合**（每条说明职责边界与运维代价）：

- **多模态 AI + RAG**：RAG 负责「从大规模语料里筛出候选」，多模态 AI 负责「精读候选」。边界是**候选数量上限**——直读只能作用于已筛出的少量候选，上量前必须按调用次数重算成本。运维代价：多一套索引与重排组件，且编码器换代要全库重编码。
- **多模态 AI + Agent**：Agent 负责决策与行动，多模态 AI 负责感知。边界是**执行层不归 Agent 管**——独立身份、配额、审计、回滚必须另建。运维代价：可重置沙箱、依赖冻结、失败分类统计，缺一项就退化成演示。
- **多模态 AI + 知识图谱**：图谱负责关系与约束，多模态 AI 负责实体与关系的抽取。边界是**两套索引之间的一致性没有自动保证**（[§5 §5.3](01-multimodal-ai-section-5-ai.md)）。运维代价：抽取质量抽检 + 图侧治理，人工量随实体类型数增长。
- **多模态 AI + 数据智能产品**：多模态 AI 提供能力，产品提供可用形态（智能 BI / 智能运营）。边界是**验收判据在产品侧**——同一能力在「辅助决策」与「自动执行」两种形态里标准不同。运维代价：产品侧要建一套业务口径的抽检机制。
- **多模态 AI + 行业智能体**：多模态能力 + 行业知识 + 流程 + 编排。边界是**行业关键字段的判据要自己定**（行业评测协议未定型）。运维代价：每个行业一套评测集与抽检样本，无法跨行业复用。
- **多模态 AI + 世界模型**：今天成立的只有「把生成模型当工具用」这一半；「用它预演并指导决策」这一半缺公开判据。运维代价：若按预演系统的标准建设，回报取决于判据何时出现，属于高风险投入。

**矩阵的用法**：先用「场景」列定位到一行，再重点看「不选它的原因」列——那一列才是选型文档里真正要写下来的部分：你放弃了什么、为什么可以放弃。评审时最难被接受的往往不是「选了 A」，而是「没写清为什么没选 B」。

### 7.7 选错的代价与迁移成本

- **反模式：用开放输出替代封闭输出** —— 症状：质检、计费、对账这类有明确正确答案的任务改由 VLM 承担；后果：单样本成本高一个量级、输出不可复现，回归测试写不出来，验收退化成人工抽检，而抽检比例会随上量变得不可维持；正确的做法：先测判别模型在你自有样本上的关键字段准确率，够用就不换；要换时用「VLM 复核判别模型的低置信样本」这种混合形态，而不是整条链路替换。
- **反模式：把「先文本化」当默认且没有对照** —— 症状：图像与音频一律先 OCR / 转写，只把文本送进模型；后果：版面与韵律信息在链路最上游被丢掉，误差不可逆——一个数字读错，后面检索、生成、引用全建立在错的文本上；正确的做法：让原件与文本同时进入上下文做对照，把不可逆点移到可对照的位置（[§5 §5.2.1](01-multimodal-ai-section-5-ai.md)）。
- **反模式：让 Agent 直接改生产状态** —— 症状：跳过沙箱，直接在生产系统上跑动作序列；后果：一次错误被重试放大成一批调用，且环境不可重置导致无法复现与回归；正确的做法：先建可重置沙箱与幂等动作，加独立身份、配额、熔断与全量审计，再谈生产写入。
- **反模式：用公开榜单代替自有样本对照** —— 症状：按榜单名次选模型，不抽自有分布样本；后果：榜单分布在你的方言 / 版式 / 噪声上不成立，关键字段准确率不够要等到上线后才暴露，而此时链路已经建成；正确的做法：选型阶段就抽三批样本（典型 / 边界 / 长尾）跑对照，结论与榜单并排存档，后续换模型用同一批复测。

**换成另一个要动什么**（工作量量级为【经验】，取决于差异落在哪一层）：

| 迁移方向 | 数据迁移 | 查询改写 | 运维重建 | 团队再学习 |
| --- | --- | --- | --- | --- |
| 判别模型 → 桥接式 VLM | 无（同一批原件） | 判据从标签比对改为字段抽检 + 人工比例 | 小（新增配额与版本登记） | 中（提示词、评测集） |
| 单模态 LLM → 多模态理解 | 无（原件本来就在存） | 增加原件引用与模态组装 | 中（新增版本登记与数据边界审批） | 中 |
| 桥接式 VLM → 原生多模态 | 无 | 提示词与上下文组装要重写 | 中（多数只能走托管，数据边界要重审） | 中 |
| 直读路径 → 多模态 RAG | 需全量编码一次 | 引入 Top-K 与重排分数口径 | 大（索引、重排、编码器版本管理） | 中到高 |
| 传统 CV → 多模态理解 | 需补标注与版式样本 | 输出结构从框 / 类改为字段 | 中到高（新增评测与抽检） | 高 |
| 脚本 → 多模态 Agent | 无（动作在外部系统里） | 由脚本改为动作生成 | 大（沙箱、幂等、审计、失败分类） | 高 |
| 桥接式 → 叠加知识图谱 | 需抽实体与关系入库 | 增加图遍历路径 | 中（图库 + 一致性校验） | 中到高 |

### 7.8 小结

| 你的处境 | 建议 | 关键理由（机制层面） |
| --- | --- | --- |
| 判据能写成字段比对、分类体系稳定 | 传统 CV / 传统 NLP 判别模型，VLM 只做低置信复核 | 封闭输出可写死回归；生成式输出的成本与不可复现性是白付 |
| 判据能写成字段比对、但问题是开放长尾 | 桥接式 VLM + 关键字段抽检 | 开放输出覆盖长尾，但必须自建抽检与评测集 |
| 单模态任务，只是缺一个更强的文本模型 | 单模态 LLM | 多模态链路会带来输入体量成本与模态版本管理，收益为零 |
| 语料大规模、且会被反复检索 | 多模态 RAG（索引路径 + 精读 Top-K） | 单次查询「读全量」与「读 K 件」的成本比为 N / K；查询多于一次时索引路径总成本即占优 |
| 语料只处理一次、没有重复查询 | 直读路径，不建索引 | 交叉点 Q = N / (N − K) ≈ 1，一次消费不值得建索引 |
| 需要语音或音画细粒度同步 | 原生多模态模型 | 只有对齐在参数里时这类属性才不被投影层压掉，代价是不可拆分 |
| 想自托管、受数据边界约束 | 桥接式 VLM + 开源权重 | 可只替换一层、可本地部署，代价是跨模态细粒度能力受限 |
| 要改外部系统状态 | 先在可重置沙箱里做 Agent 回归 | n 步任务成功率按单步可靠性的 n 次方衰减，步数与幂等比模型能力更早决定成败 |
| 产出是内容而非判断 | 生成模型 + 人确认，不进自动链路 | 判据是「像」，没有自动判据就没有自动回归 |

> 本节小结：这一主题下**唯一真正起决定作用的差异是「能力落在哪一层」**——接口层（能不能直读原件）、参数层（对齐在投影层还是参数里）、执行层（动作由脚本还是模型生成）。落在接口层的差异可以用调用费与数据边界结账，落在参数层的差异是不可拆分的锁定，落在执行层的差异是一整套要自建的沙箱、幂等与审计。选型时先确定差异落在哪一层，再谈「谁更强」；顺序反了，结论会随场景翻转。
