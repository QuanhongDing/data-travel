## 5. 前沿演进（AI 时代）

### 5.1 先分清三类「前沿」

趋势清单在这门主题上比别的章节更容易误导，因为**这一节的关键词全是「原生」「通用」「工业化」**：一个 2024 年的托管 API、一条论文里的研究目标、一段演示视频，可以用同一套措辞写成并列的三行。原清单把「原生多模态成为事实标准」「世界模型成为 AGI 核心」「具身智能产业化」并列，读者据此排路线图，会以为它们在同一个时间尺度上。

第二个问题是机制差异被抹平。本主题的「演进」实际横跨三层，改动它们的东西完全不同：

1. **感知**（能不能读原件）：输入形态从「先转成文本」变成「模型直接吃图像 / 音频 / 视频」。
2. **表示**（桥建在哪一层）：跨模态的桥建在表征层（对齐）、投影层（桥接式 VLM）、参数里（原生）、索引上（检索），还是动作上（Agent）。[§3 §3.1](01-multimodal-ai-section-3-sec3.md) 已把这条轴写成本主题的模式分野。
3. **行动**（能不能改变外部状态）：从「输出一段文本」到「调用工具、操作界面、驱动机械」。

**第 1 层已经变了，第 3 层还没有定型**。第 1 层的变化是接口边界上移：主流模型 API 从 2024 年起把图像与音频输入列为正式能力（GPT-4o 与 Gemini 1.5 / 2.0 是这一批原生多模态与长上下文的代表，具体条目请以各厂商官方文档当前版本为准），于是「预处理」从架构上的必经环节变成可选的优化环节。第 3 层的问题是**验证成本**与**环境可复现性**：[§3 §3.1](01-multimodal-ai-section-3-sec3.md) 的第三条约束说得很清楚——多模态任务的错「读起来完全通顺」，所以能不能上生产往往不取决于模型能力，而取决于有没有一个外部判据能判断输出对不对；而 Agent 要改变外部状态，就必须先有可重置的环境、幂等的动作与回滚路径。

命名与版本纪律在本节尤其要紧，三条：

- **区分产品名与能力名**：`Computer Use` 是能力名（看屏幕、点控件）而不是某个产品的专名；`MCP` 是协议名不是产品名；「多模态」在两家文档里可能指完全不同的输入集合。判定方法是去官方文档里找那个具体字段，而不是找那个词。
- **区分已发布与路线图**：演示与技术报告里的目标不等于已交付的版本。判定方法是看官方发布说明里有没有它，而不是看有没有它的演示。
- **区分论文原型与产品实现**：六模态统一向量空间（ImageBind 一类）是研究原型（CVPR 2023），产品里真正在生产的是「图文对齐 + 各模态各自编码 + 元数据关联」，两者不是同一件事。

本节用三级划分，三条判据必须可核验：

- **L1 生产可用**：三条全中才算。① 已 GA 且有正式 release note；② 有**第三方（非厂商）公开的生产案例**；③ 接口稳定、可预期。
- **L2 可试点**：①③ 大体满足、② 不满足；或能力可用而判定标准尚未形成共识。可以做 PoC，不要做核心依赖。
- **L3 观望**：仅路线图、论文、厂商演示或预览特性。记录即可，不要在架构里为它预留假设。

判据 ② 在本主题有两重难度。其一是**材料的形态**：多模态的生产实践大多嵌在产品内部（一次质检、一次单据结构化、一次客服会话），公开出来的往往是效果视频与宣传口径，样本量、输入分布与对照条件都不在材料里。其二是**发布方与使用方常常是同一家**：能跑通原生多模态训练的机构，通常也自己发布模型与案例。所以本节的方向大多停在 L2 或 L3。**② 只有「满足」与「降为 L2」两种命运**：它不能改写成「有公开演示」，也不能改写成「被非厂商文档列为支持的输入类型」（那是文档，不是生产案例），更不能靠「本节只评估某一层」把适用范围缩小来绕过去。

还要说清 L2 在本节的含义：它标的是**证据缺口**，不是「不建议用」。表里第一行的 L2 尤其要这样读——「模型能直接读原件」这件事今天就能用，判 L2 只是因为本节给不出可核验的第 ② 条；缺的是「别人在生产里用过、并且公开说了代价」这一类材料，不是能力。采不采用由读者按自己的风险偏好决定，判据本身不因这句说明而放宽。

另有一条评级规则，全节通用：**合并方向取最弱子项**。本节把「多模态生成工业化」与「世界模型」拆成两行，而不是合成「生成式 AI 走向物理世界」一行，理由是它们的可规划性差一个量级：前者今天就能用在素材与草稿环节，后者要先有一个可验证的预测判据。

**本节没有一行达到 L1。** 最接近 L1 的有四行——多模态模型直读原件、原生多模态、多模态 RAG、语音识别与合成——它们卡在同一条上：**②（第三方非厂商公开生产案例）拿不出**。四行的差别只在 ③ 的稳定程度：直读原件一行的接口（消息内的内容块）跨版本稳定；原生多模态一行的接口也稳定，但它稳定在「不可拆分」上——你依赖的是一个整体，换不了其中任何一部分；多模态 RAG 一行居中，分路建索引的接口稳定，但跨模态分数的可比性没有公开协议（[§3 §3.2.4](01-multimodal-ai-section-3-sec3.md) 的失效点）；语音一行最接近「随手可用」，接口形态（音频文件进、文本出）多年未变，缺口只在评测侧。判断某条方向是不是 L1，不要看它由多少厂商支持，看第 ② 条的材料是不是**发布方之外的机构**给出的。

给读者的核验动作——拿到任何一条方向，按顺序问三句：

1. 它的正式 release note / 论文 / 版本化文档能不能找到？找不到 → L3。
2. 发布方之外的证据能不能找到？找不到 → L2。
3. 接口明年会不会变？会变 → 至多 L2。

第 3 句在本主题特有的失手方式，是把「模型版本」当成常量：同一个提示在不同模型版本上对同一张图的回答会变，因此「这件原件被哪个模型版本读过」必须落进元数据，否则模型换代之后无法重跑（5.3）。判定方法是看你的记录里有没有这个字段，而不是看模型换了几次。

三个常见误判，排路线图时最容易踩：

- **把「能力强」误当成「可拆分」**：原生多模态的能力与它的不可拆分是同一件事的两面（[§3 §3.2.3](01-multimodal-ai-section-3-sec3.md)），能接受的场景与桥接式完全不同。
- **把「演示能跑」误当成「环境可复现」**：一次成功的界面操作演示，回答不了「同样的初始状态再跑五次，成功率是多少」。
- **把「代理指标的分数」误当成「任务达标」**：相似度一类指标衡量的是「像不像」，可被优化，适合做回归门禁，不适合做验收标准。

本节与主文件 §1.4 的关系值得说一句：§1.4 沿时间线记录「发生了什么」（CLIP、多模态大模型、原生多模态），本节回答的是「现在能不能用」。同一条时间线在两种写法下结论可能相反——§1.4 把 2023 年的开源 VLM 涌现列为里程碑（研究意义），本节判的是工程可用性：桥接式与原生都落在 L2，理由却不同（前者是投影层的有损压缩，后者是不可拆分）。**里程碑讲的是研究意义，成熟度讲的是工程可用性**。

核验「支持多模态」这句话时，可用的动作只有三类，建议照做：

- **查发布说明**：在对应产品 / 版本的官方发布说明里搜关键词，看条目写的是「实验性 / 预览」还是正式能力。
- **查模型仓库**：型号名与输入模态以官方模型卡与仓库为准，不要按二手材料里的型号认定。
- **自己测一次**：拿自己的方言样本、自己的版面样本、自己的长视频跑一次，并把这个数字留在评测集里。

本节不预测「多模态会不会成为默认」——这类判断永远正确，因而没有信息量。本节只回答两件事：**某个具体动作今天能不能做，以及做它要付出什么代价。**

### 5.2 演进方向逐条拆解（核心节）

下面 5.2.1–5.2.3 三个小节都按同一套六行结构写：**旧做法卡在哪 → AI 改变了什么机制 → 由此得到什么 → 由此付出什么 → 证据与来源 → 成熟度**。5.2.4 收的是其余八个方向，逐条仍然给出这六项信息——每条以方向名起首，段内依次写明旧做法卡点、机制改变、由此得到、由此付出、证据与来源与成熟度——只是不另起六行：理由是这八个方向停在低处的理由只有两类（验证判据不存在 / 前提条件不成立），逐行展开会把同一段论证重复八遍。只写收益不写代价的方向，评审时应直接打回——多模态的每一次能力提升，都对应一项成本结构的变化。

#### 5.2.1 模型直接消费原始模态：接口边界上移，索引结构没动

- **旧做法与它的卡点**：主文件 §1.2 的痛点 1 与痛点 4 说的就是这条要解的题——单模态 LLM 处理不了图像与视频，于是过去的绕法是在预处理阶段把一切**文本化**（OCR、语音转写），而文本化把版面与声音信息丢在链路最上游，**误差不可逆**：一个数字读错，后面检索、生成、引用全都建立在错的文本上。
- **AI 改变了什么机制**：**接口边界上移**——模型 API 直接接受图像 / 音频 / 视频，于是「预处理」从架构上的必经环节变成可选的优化环节。注意这条机制的适用范围：它改的是**输入形态**，不是索引结构。
- **由此得到的**：因为模型能直接吃原件，**所以**「先文本化、再理解」这个不可逆点被移到了可对照的位置（原件与文本可以同时进入上下文，让模型自查矛盾），并且**原件从「归档物」升级为「可再次消费的资产」**——对数据层的直接推论是元数据里必须记「这件原件被哪个模型版本消费过」；**又因为**编码一次、查询多次的索引路径没有变化，**所以**「从大规模语料里找」这件事仍然只能靠索引完成，模型直读只能作用于已经筛出来的少量候选（[§3 §3.2.4](01-multimodal-ai-section-3-sec3.md) 的成本对比）。

```text
同一种模态的两条消费路径（不要混用，也不要用一条替代另一条）
  路径 A（索引路径 / 回答「从大规模语料里找哪几条」）
     原件 → 各自的编码器 → 向量索引 → Top-K
     特点：编码一次、查询多次，边际成本随查询次数被摊薄
  路径 B（直读路径 / 回答「理解了再说」）
     候选原件（来自路径 A 或人工指定）→ 多模态模型 → 答案 / 结构化结果
     特点：每次调用都付费，输入体量线性影响成本与延迟
  ────────────────────────────────────────────────
  被改动的是路径 B 的输入形态（不再要求先变成文本）；
  路径 A 的结构、以及两条路径之间的候选数量上限，都没有被改动
```

- **由此付出的**：**其一，成本与延迟随输入体量上升**——长视频与高分辨率图像尤其明显，所以直读只能作用于已筛出的少量候选，上量前必须按调用次数重算（[§3 §3.5](01-multimodal-ai-section-3-sec3.md) 的「忽视成本」给出了推算方法）。**其二，可复现性下降**——模型版本迭代会改变对同一原件的理解，同一个问题在不同版本上答案不同，因此「用哪个版本消费过这件原件」必须落进元数据，否则模型换代后无法重跑。**其三，锁定面从存储格式转到模态接口**——换模型等于重跑评估与重写提示词，而这一步的成本通常低估。**其四，数据边界**（[§3 §3.1](01-multimodal-ai-section-3-sec3.md) 的第四条约束）：能力最强的模型通常托管，把原件送进模型就等于出域，而这一步通常没有走过数据审批。
- **证据与来源**：模型 API 的模态输入是否为正式条目可自行核验（判定方法：查该 API 文档中图像 / 音频 / 视频输入是标注为 GA 还是 preview）；图文对比对齐的基础工作有公开论文（Radford 等，ICML 2021），六模态对齐的代表工作是公开论文（Girdhar 等，CVPR 2023），后者是**研究原型**，不等于产品里的「任意模态互搜」已经可用。**② 不满足**：本节给不出发布方之外的机构公开的生产案例。
- **成熟度**：**L2**（与 5.1 表「多模态模型直接消费原始模态」行一致），判据：①③ 满足、② 不满足。**这里的 L2 只标证据缺口**：接口能力今天就能用，降级不改变「现在就能用」这个结论。

上量之前必须先测出三个数，它们共同决定「直读」这条路在你这里成不成立：

- **单次问答的原件直送成本**：按真实输入体量（分辨率、帧数、时长）算，不是按文本 token 估。
- **首字节 / 首次响应延迟**：交互式应用里这是硬约束，且它不随模型升级自动消失。
- **关键字段准确率**：用你自己的样本集测，并与「确定性路径给出的值」逐条对照——两者不一致的比例，就是这条链路要求的人工复核量。

#### 5.2.2 原生多模态：融合发生在参数里

- **旧做法与它的卡点**：桥接式把模态之间的对齐交给一个投影层，而语气、韵律、画面与音效的对应这些**跨模态细粒度同步**在投影层里被压掉了；级联方案（转写 → 语言模型 → 合成）则把延迟按段累加，并把韵律与打断丢在环节之间（[§3 §3.6](01-multimodal-ai-section-3-sec3.md) 的跃迁表）。
- **AI 改变了什么机制**：**把桥从「外接的适配器」改成「训练出来的表示」**——各模态 token 在同一条序列里联合训练，模态间的关系在参数里形成，不由投影层产生。
- **由此得到的**：因为对齐发生在参数里，**所以**「音频进、音频出」可以不经过转写与合成级联，低延迟与强融合这两项优势才成立（[§3 §3.2.3](01-multimodal-ai-section-3-sec3.md)）；**又因为**只有一个模型，**所以**端到端链路省掉了多次排队与传输。反过来说：如果你的场景不需要跨模态细粒度同步，这三项收益对你接近于零，而你仍要付它的代价。
- **由此付出的**：**其一，任何一部分都换不掉**——融合发生在参数里，所以无法只搬走视觉部分；模型是整体黑盒，出错时无法定位是感知端还是语言端错了（[§3 §3.2.3](01-multimodal-ai-section-3-sec3.md) 的失效点）。**其二，部署边界被动接受**——参数规模使本地部署成本高，多数团队只能走托管 API，于是数据边界问题一并接受；而「先验证、之后再把模型换回本地」这条常见计划，意味着重新评测与重新调优。**其三，能力与不可拆分是同一件事的两面**，所以「更强的原生模型」不会让你的架构更可替换，只会让它更难替换。
- **证据与来源**：【公开】原生多模态一侧有具名材料可核验：GPT-4o 的官方发布与系统卡（OpenAI，2024）与 Gemini 1.5 技术报告（Gemini Team，"Gemini 1.5: Unlocking multimodal understanding across millions of tokens of context"，2024）——文档名与年份可检索，具体版本与条目以官方发布说明当前版本为准；【公开】桥接式一侧有公开论文可核验（"Visual Instruction Tuning"，NeurIPS 2023；BLIP-2 的 Q-Former，ICML 2023）。**② 不满足**。
- **成熟度**：**L2**（与 5.1 表「原生多模态」行一致），判据：① 满足、③ 满足但不可拆分、② 不满足。注意这条与 5.2.1 的差别：**5.2.1 是接口能力，5.2.2 是架构选择**——前者可以只当输入形态用，后者会改变你整套系统的可替换性。

#### 5.2.3 多模态 Agent：把感知接到动作上

- **旧做法与它的卡点**：GUI 自动化的旧做法是写死坐标与选择器，界面一改就失效；而复杂任务（跨多个内部系统、需要读屏判断）写不出确定性脚本。卡点有两个：**动作的幂等性**与**环境的可重置性**——前者决定失败能不能重试，后者决定结论能不能复现。
- **AI 改变了什么机制**：**把「看到的样子」直接作为动作的输入**——模型从像素与可访问性树推断下一步动作，取代了「人先把界面抽象成脚本」这一步。机制上改变的是接口形态（从「调用预先写好的 API」变成「生成并执行动作序列」），不是执行层的责任划分。
- **由此得到的**：因为动作由模型按当前状态生成，**所以**界面变化不再必然让流程失效，长尾路径第一次可以被覆盖；**又因为**一次执行是一条轨迹（思考 → 调工具 → 读结果 → 再调），**所以**它可以按步数、成本与失败分类来度量，而不只是回答「成没成」——后三项比成功率更直接地决定它能不能上生产。
- **由此付出的**：**其一，环境维护成本前置**——沙箱要能重置、依赖要冻结、外部服务要可控；这是从演示走向回归工具的真正门槛，也是多数团队做不下去的原因。**其二，方差极大**——同一模型同一任务跑两次，中间的工具调用次数与环境状态就可能不同，成功率本身是随机变量；样本量不足时最容易给出过早结论。**其三，执行层责任新建**——独立身份、配额、全量审计与回滚路径，一样都不能少；模型的重试行为会把一次错误放大成一批调用，所以执行层必须有去重与熔断（[§3 §3.4](01-multimodal-ai-section-3-sec3.md) 组合三）。**其四，基准分数与生产可用之间没有必然联系**——基准里的工具权限是固定的，而生产事故多来自权限、超时与长尾接口。
- **证据与来源**：【公开】看屏幕操作这一能力有正式文档与调用方式（2024 年起，原文件点名的 OpenAI Operator 与各家 Computer Use 都属这一类；具体条目以官方文档当前版本为准）；【公开】开源侧的编排实现（原文件点名的 LangGraph + 多模态、AutoGen + 多模态一类）提供的是工具调用与多模态输入的接线方式，本节不逐个评估它们对多模态的支持——核验方式是查其官方文档里「多模态输入 / 工具调用」是不是正式条目；【公开】Agent 评估基准有具名论文与公开榜单可核验——"AgentBench: Evaluating LLMs as Agents"（2023）、"WebArena: A Realistic Web Environment for Building Autonomous Agents"（2023）、"OSWorld: Benchmarking Multimodal Agents for Open-Ended Tasks in Real Computer Environments"（2024），三者的任务集、评测环境与提交格式都写在论文与榜单页里，可按论文标题检索核验。**② 不满足**：能充当第三方生产案例的公开材料，本节给不出来源与统计口径。
- **成熟度**：**L2**（与 5.1 表「多模态 Agent」行一致），判据：① 满足、③ 不稳（工具契约与环境快照未标准化）、② 不满足。

报数时必须带上两样东西，否则这个数字没有意义：

- **采样次数与区间**：同一模型、同一任务、同一环境快照，连跑五次以上【经验】；结果不稳时只报区间。
- **成本与步数**：单次任务的模型调用次数与费用，以及失败样本的失败分类——它们比成功率更早暴露上生产的障碍。

| 用法 | 什么时候可以 | 什么时候不行 |
| --- | --- | --- |
| 生成建议、由人确认后执行 | 动作可由人复核，且失败可回滚 | 复核人看不懂模型的动作依据时，确认会退化成橡皮图章 |
| 在可重置的沙箱里跑回归 | 环境快照与工具契约都固定 | 依赖外部服务状态、无法重置时，两次跑的结果不可比 |
| 直接改生产系统状态 | 有独立身份、配额、全量审计与幂等动作 | 缺任意一项都会让一次错误被重试放大成一批调用 |
| 用它替代人工的既有流程 | 有外部判据能判断每一步对不对 | 判据只有「看起来完成了」时，错误会被流程放大 |

#### 5.2.4 其余方向为什么停在这里

- **多模态 RAG** —— **旧做法与它的卡点**：文本索引对图像与音频无从下手，只能先转写再检索，而转写把版面与声音信息丢在链路最上游；**AI 改变了什么机制**：改的是**编码侧的模态覆盖**——各模态各自编码到同一个可比空间、同一查询跨模态召回，检索与重排的骨架没有变（[§3 §3.2.4](01-multimodal-ai-section-3-sec3.md) 的失效点已经指出向量空间保留语义相似度、主动丢弃字面标识符的区分度）。
  **由此得到的**：「以文搜图 / 搜视频 / 搜音频」成为一件可做之事，原文件点名的代表项目（LangChain / LlamaIndex 的多模态检索模板、VideoRAG 一类）已把这条链路接起来；**由此付出的**：跨编码器的分数不可比——相似度在 CLIP 系与 SigLIP 系之间不能直接比大小，跨模态重排因此没有公开协议；评测集与指标也没有公开标准，只能自建（含引用正确性）。
  **证据与来源**：编码、向量检索、重排三层都有版本化文档可核；**② 不满足**。**成熟度**：L2，判据 ①③ 大体满足、② 不满足（与 §5.1 表「多模态 RAG」行一致）；缺的是评测协议，不是能力——可做的事是分路建索引 + 元数据关联，先自建评测集再改链路。
- **多模态 GraphRAG 与多模态知识图谱** —— **旧做法与它的卡点**：只靠向量相似度回答不了跨模态的多跳问题（「这只手属于哪台机器、那台机器停在哪条线」），而人工建图谱的成本按条数增长；**AI 改变了什么机制**：把桥从「向量相似」移到「显式关系」上——实体、关系与多模态属性成为另一套索引，改的是索引的类型，不是检索的骨架。
  **由此得到的**：跨模态的多跳检索在概念上成立，原文件点名的代表项目（MMKG、MMKGRAG、亚马逊 Product Graph 一类）都落在这一层；**由此付出的**：多一套索引、多一套一致性维护，而图与向量两套索引的一致性没有自动保证（§5.3「多模态 ↔ 图 / GraphRAG」一行的现状列）。
  **证据与来源**：这些材料是论文与概念材料，本节给不出可核验的公开生产案例。**成熟度**：L3，判据 ① 不满足、② 无（与 §5.1 表「多模态 GraphRAG 与多模态知识图谱」行一致）；可做的事是先用元数据关联顶上，不要为跨模态图谱检索预留接口。
- **多模态生成工业化（图像 / 视频 / 音频 / 3D）** —— **旧做法与它的卡点**：素材靠人力或专用工具生产，产能被工序时长锁住，改一版就要重走一遍流程；**AI 改变了什么机制**：把「做出一件素材」从工序变成一次采样，改的是单件成本，不是验收标准。
  **由此得到的**：草稿与素材环节的产能上升，原文件点名的 Midjourney、Sora / Veo 2、Suno、Meshy 一类都已进入正式服务形态；**由此付出的**：输出不可复现（同一输入两次结果不同），回归测试与责任归属都变难，且生成质量的判据是「像」，业务要的可能是「对」。
  **证据与来源**：① 满足——有正式服务与版本化文档；**② 不满足**。**成熟度**：L2，判据 ① 满足、③ 输出不可复现、② 不满足（与 §5.1 表「多模态生成工业化」行一致）；商用还要额外核两件事：生成内容的知识产权与训练数据来源规则、以及平台与当地法规对生成内容标识的要求（以产品当前条款与当地法规为准）。
- **语音识别与合成** —— **旧做法与它的卡点**：转写要按场景单独调，麦克风、方言与噪声一变就得重配，专用模型的词表也换不了；**AI 改变了什么机制**：把声学条件吸收进大规模弱监督训练里，改的是「换一个场景还要不要重训」。
  **由此得到的**：接口形态（音频文件进、文本出）多年未变，是最接近「随手可用」的一类多模态能力，原文件点名的 VALL-E 2、CosyVoice、ElevenLabs Voice Design、Cartesia Sonic 一类都在这个接口之内；**由此付出的**：通用榜上的词错率不能代表你的方言、口音与噪声分布，合成语音还多一层身份与授权问题。
  **证据与来源**：有公开模型与正式服务可核；**② 不满足**。**成熟度**：L2，判据 ①③ 满足、② 不满足（与 §5.1 表「语音识别与合成」行一致）；判定方法是拿自己的样本跑一次词错率对照，而不是看榜。
- **具身智能 / 机器人基础模型** —— **旧做法与它的卡点**：机器人的动作由逐任务编程或专用策略给出，换一个物体、换一间屋子就要重做一遍示教；**AI 改变了什么机制**：把动作策略改由大规模数据训练出的基础模型给出，改的是「策略能不能跨任务迁移」。
  **由此得到的**：跨任务泛化第一次有了可走的技术路线，原文件点名的 Figure 02、Tesla Optimus Gen 2、Unitree G1、智元机器人 GO-1、Galbot 一类都是这条路线上的型号；**由此付出的**：**仿真偏差无法自查**——学到的策略在真机上的失败模式，仿真环境里看不出来，因此必须有真机增量数据闭环（[§3 §3.6](01-multimodal-ai-section-3-sec3.md)）。
  **证据与来源**：公开材料以演示、论文与融资声明为主，没有把「通用操作」做成 GA 能力。**成熟度**：L3，判据 ① 不满足、② 无（与 §5.1 表「具身智能」行一致）；能在封闭场景里按自己的验收判据成立，不等于通用能力成立。
- **世界模型（视频生成一脉）** —— **旧做法与它的卡点**：仿真环境要人工建模，成本高，而且它与真实世界的差距说不清是建模问题还是参数问题；**AI 改变了什么机制**：用生成模型从观测数据里学一个可采样的动力系统，改的是建模的输入——从人工规则改成数据分布。
  **由此得到的**：拿生成模型做预演在概念上成为可能，原文件点名的 Sora、Veo 2、Genie 2、可灵 1.5、Vidu 一类都是这条路线上的公开名字，但它们目前是生成工具，不是可验收的预测器；**由此付出的**：它学的是观测分布，不是可控的观测转移，生成的判据是「像」，而决策要的是「对」。
  **证据与来源**：定位在技术报告里是研究目标，没有公开的、以真机验收通过的证据链。**成熟度**：L3，判据 ① 不满足、② 无（与 §5.1 表「世界模型」行一致）；把它当生成工具用是今天成立的部分，自动驾驶与机器人的仿真用法另算。
- **行业多模态标准化（医疗 / 工业 / 金融 / 政务）** —— **旧做法与它的卡点**：每个行业的关键字段判据都靠项目自定，换一家客户就要重谈一遍验收口径；**AI 改变了什么机制**：模型把「读一份影像 / 一份单据」的能力通用化，于是行业之间的差别从「能不能读」变成「按什么口径算读对」。
  **由此得到的**：通用能力的复用面变大，行业侧真正要建的只剩评测集与字段口径；**由此付出的**：口径没有行业共识，任何跨组织的横向对比都不成立，而「等标准」的代价是把交付周期押在别人的时间表上。
  **证据与来源**：无公开可核验的行业评测协议或标准草案。**成熟度**：L3，判据 ① 不满足、② 无（与 §5.1 表「行业多模态标准化」行一致）；可做的是按自己的业务口径定义关键字段判据与验收集——这比等行业标准更快，也不会因为标准变化而返工。
- **多模态治理与合规** —— **旧做法与它的卡点**：内容合规过去按「文本里能不能搜到关键词」处理，图像、音频与视频里的内容天然躲过文本审查；**AI 改变了什么机制**：生成与理解都变成模型的批量动作，于是合规要处理的对象从「一份发布的文档」变成「每一次生成」。
  **由此得到的**：来源登记与生成标识第一次成为可落地的工程字段；**由此付出的**：义务性文本证明的是「要求存在」，不证明「工程方法存在且可核验」，先承诺「合规达标」就会在后面发现没有判据可依。
  **证据与来源**：可核验的落地方法本节给不出来源。**成熟度**：L3，判据 ① 不满足、② 无（与 §5.1 表「多模态治理与合规」行一致）；可做的是来源登记与生成内容标识字段，不是「合规达标」的结论。

把上面几条并排看，它们停在低处的理由只有两类：**一类是验证判据还不存在**（多模态 RAG 的评测协议、跨模态图谱的抽取质量口径、生成内容的验收链条、行业关键字段标准），**一类是前提条件还不成立**（具身智能需要真机闭环、世界模型需要先定义「可用于预演」的判据）。判据 ①③ 讲的是第一类，判据 ② 讲的是第二类——**能拿出「别人在生产里用过」的材料，本身就是前提条件成立的证据**。

### 5.3 与本主题既有栈的接口在哪

多模态系统与上下游不是「结合」关系，而是**交接物**关系：一次感知或生成的结果以什么形态交给下一跳、失败时谁负责，比「支持哪些模态」更能决定系统能不能用。下表按「谁把什么交给谁」来写。

| 结合点 | 接口形态 | 谁负责失败 | 现状 |
| --- | --- | --- | --- |
| 模型 API ↔ 应用（直读路径） | 交接物 = 原件引用或字节 + **模型版本**；预处理从必经降为可选 | 应用侧（谁引入模型谁负责重跑与重评） | 接口能力可用；版本登记需自建 |
| 编码器 ↔ 向量索引 | 以「编码器版本 + 向量维度」为接口；换版本等于全库重编码 | 索引侧（索引可重建）；原件侧负责不丢 | 既有技术，版本管理是缺口 |
| 检索结果 → 生成（多模态 RAG） | 交接物 = Top-K + 元数据 + 原件引用（不是原件字节） | 检索侧；**返回空优于返回越权或过期结果** | 既有技术，评测需自建 |
| Agent ↔ 执行层 | 交接物 = 幂等动作 + 独立身份 + 配额；执行层负责合法性 | 执行层（权限、审计、回滚不在 Agent 侧） | 未定型，需自建 |
| 生成模型 ↔ 数据边界与版权 | 以「可用条款 + 标识要求 + 来源记录」为接口 | 使用方（条款与法规的核对责任在使用方） | 需自建登记，不能默认可用 |
| 多模态数据 ↔ 数据目录与元数据 | 资产登记补三项：**模态、权限范围、被哪个模型版本消费过** | 数据侧（缺项则拒绝发布） | 需新建字段 |
| 多模态 ↔ 评测集与验收判据 | 以「固定评测集 + 关键字段准确率 + 人工抽检比例」为接口 | 业务侧（没有基线就没有变好变坏的判断） | 需自建，这是本节所有 L2 的共同门槛 |
| 多模态 ↔ 图 / GraphRAG | 多模态实体与关系作为另一套索引 | 图侧；与向量索引的一致性无自动保证 | 概念与自建阶段 |
| 多模态 ↔ 可观测 | 新增指标穿过边界：命中率、原件取回失败率、单次直读成本与延迟 | 平台侧提供通道，业务方定义「什么算异常」 | 需新建，不是既有指标的复用 |

这张表九行里只有两行属于既有技术（「编码器 ↔ 向量索引」与「检索结果 → 生成」），其余七行都要新建登记或新建链路——语音接口不在本表内，它在 5.1 表与 5.2.4 里单列：接口形态多年未变，但本节同样给不出它的判据 ②。**失败归属必须在设计阶段写清**，否则会退化成扯皮：一次问答答错了，是原件取错、检索没召回、模型版本换了，还是上下文被截断？四件事都能解释同一个现象，而它们分属四个团队。唯一能让争论停下的是把「原件引用 + 编码器版本 + 模型版本 + 评测集版本」登记成资产——这也是 5.7 里那条最不性感、却最省事的要求。

还有一件容易漏的事：这张表的失败**多数最终会落到业务侧而不是平台侧**。原件版本对不上，损失由上线后的用户承担；评测集过时，结论不成立而决策已经做出；生成内容权属不清，损失由商用链条承担。把这三条写进接口表的用途不是分工好看，而是让争论在事故发生前就有归属。

**论文**

- Radford 等，"Learning Transferable Visual Models From Natural Language Supervision"，ICML 2021——图文对比对齐的奠基工作，也是理解「统一向量空间能做到什么、不能做到什么」的基础。
- Jia 等，"Scaling Up Visual and Vision-Language Representation Learning With Noisy Text Supervision"，ICML 2021（ALIGN）——同年把这条路线扩到更大规模。
- Li 等，"BLIP-2: Bootstrapping Language-Image Pre-training with Frozen Image Encoders and Large Language Models"，ICML 2023——Q-Former 这种投影实现的代表。
- Liu 等，"Visual Instruction Tuning"，NeurIPS 2023（LLaVA）——确立「视觉编码器 + 投影层 + LLM」这一主流开源形态。
- Girdhar 等，"ImageBind: One Embedding Space To Bind Them All"，CVPR 2023——六模态对齐的代表工作；本节把它当作「该研究方向存在」的证据，**不是**「产品里可用」的证据。
- Zhai 等，"Sigmoid Loss for Language Image Pre-Training"，ICCV 2023（SigLIP）——说明这条路线仍在快速迭代（也即：接口稳定不等于模型稳定，换编码器意味着重建索引）。
- Radford 等，"Robust Speech Recognition via Large-Scale Weak Supervision"，2022（Whisper）——语音侧公开模型与评测方式的主要来源。

**官方发布说明 / 版本化文档（判定入口）**

- OpenAI、Google（Gemini API）与 Anthropic 三家 API 文档中的多模态输入章节（OpenAI 的 "Images and vision" 指南、Gemini API 的 "Image understanding" / "Video understanding" / "Audio understanding" 文档页、Anthropic 的 "Vision" 文档页；图像输入自 2024 年起列为正式能力）——用途是核验 5.2.1 的 ①：输入是 GA 还是 preview。**章节名、版本号与生效时间请以各厂商文档站当前版本为准**，本节不转写具体型号的规格。
- 开源多模态模型的模型卡与仓库（Qwen-VL / Qwen2-VL 系列、InternVL 系列等，2023–2024）——用途是核验输入模态、上下文长度与许可，这些是自托管路线的三个必查项。
- 模型上下文协议（MCP）的公开规范（2024-11 起，版本化）——用途是核验 Agent 侧的工具接入形态；**它是协议名，不是产品名**。

**第三方生产案例**

本节**未能给出**可核验的、含输入分布与对照条件的第三方多模态生产案例。原 §5.3 所列的版本与日期、以及原文件提到的融资数字，本节不转载（前者以官方发布说明为准，后者属公司公开声明与媒体报道口径且时点敏感）。**这个空白本身是结论**：它直接决定了本主题下没有方向可以排成 L1。

**怎么用这份清单**：先看你要核的是「感知」还是「行动」。感知侧的证据看模型文档与技术报告（更新快、可核验性高）；行动侧的证据要看基准发布物里有没有成本、步数与失败分类（只有成功率与名次的榜单回答不了上生产的问题）。两类材料都不能替代判据 ②——它们证明的是机制存在，不是有人在生产里用它并承担了代价。

### 5.5 被过度宣传的部分

**「原生多模态 = 更强的多模态」**——实际是优势集中在跨模态细粒度同步（语气、韵律、画面与音效的对应）与端到端延迟，不在「文本 + 图像问答更准」。原因：对齐发生在参数里，所以它擅长的是无法用文本 token 转述的属性，而这些属性在多数图文问答任务里根本不参与评分。**它什么时候才会成真**：你能指出一个只有原生架构能做、桥接式做不到的任务，并且它进了你的验收标准——指不出，说明你在为不需要的能力付不可拆分的代价。

**「视频生成模型就是世界模型」**——实际是它在学观测分布，不是可控的观测转移。原因：生成的判据是「像」，决策要的是「对」；而仿真偏差无法自查，真机验收又需要增量数据闭环，所以这两件事之间隔着一个完整的验证体系。**它什么时候才会成真**：出现公开的、在自动驾驶或机器人上以真机验收通过的证据链（含任务、指标与失败样本），而不是以画面质量取胜的对比视频。

**「多模态 Agent 能替代 GUI 操作」**——实际是「能看屏、能点击」这一能力已经可用，而可复现性、权限、回滚与成本还没解。原因：能力由模型提供，可靠性由环境与执行层提供，而后者是每个团队要自己建的那部分（5.2.3）。**它什么时候才会成真**：基准与内部评估的发布物里同时给出成本、步数与失败分类，且沙箱能重置到同一初始状态——那时「能不能上生产」才有可比的答案。

这三条有一个共同结构：**把「某一层的成本降了」或「能力出现了」说成「整条链路可以少几层」**。判断它们何时成真，看的是同一件事——**有没有一个外部判据能判断输出对不对**（[§3 §3.1](01-multimodal-ai-section-3-sec3.md) 的第三条约束）。

### 5.6 未来 3–5 年：可证伪的预测

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| 多模态的默认架构会是「便宜预处理 + 索引检索 + 模型精读」的分层，而不是一个原生大模型端到端扛下所有输入 | 产品与开源框架文档里出现分层的正式条目（预筛、抽样、摘要、精读各自可配置）；对外口径开始按两条路径分开给成本 | 端到端单模型在同等任务上的单位成本与延迟低于分层链路，并被多个团队公开采用 |
| 模型与编码器的换代会成为常态运维项，而不是一次性迁移 | 变更记录与依赖清单里出现模型版本与编码器版本字段；文档给出编码器升级的迁移指引（重编码范围与顺序） | 编码器升级仍然「免费」——不重编码、旧向量与新向量混用也没有后果 |
| 具身智能仍不会在通用场景落地，而会在「有明确验收判据的封闭场景」先落地 | 公开材料从演示视频转为带验收指标的作业报告（任务、成功率、失败样本、人工介入率） | 出现通用家务或通用工厂场景的、第三方发布的长期运行报告 |
| 多模态治理的落地形态会是「来源与生成标识」而不是「模型能力认证」 | 平台与产品文档出现来源登记、生成标识字段与留存要求，并可被外部核验 | 治理要求长期停在原则性文本，平台侧始终不出现可核验的字段 |

四条都能被**公开文档与发布物**证实或证伪，不需要内部数据：

- 第 1 条看产品与框架文档里有没有分层配置项，一到两年见分晓。
- 第 2 条看变更记录里的字段，一到两年。
- 第 3 条看公开材料的形态（演示还是作业报告），两到三年。
- 第 4 条看平台侧的字段与留存要求，两到三年。

最值得先盯第 2 条：它是唯一一条**不依赖任何新产品发布**就能观察到的信号，而且它一旦做不到，其余三条的结论都失去可比性——模型换了而没人知道，任何跨期对比都不成立。

提醒一句：这四条问的都不是「哪个模型会更强」，而是「**判断依据会不会出现在公开文档里**」。前者无法证伪，后者可以逐条核对。

### 5.7 给架构师的行动建议

下表按「你的处境」分行：同一项技术在不同处境下的正确动作不同——文档密集的团队该先建关键字段判据，而只有文本资产的团队最该做的是先别引入多模态。

| 你的处境 | 现在就该做 | 一年内观察 | 明确不要做 |
| --- | --- | --- | --- |
| 只有文本资产，业务提「能不能看图」 | 先做「文本链路 + 图像链路各自独立 + 元数据关联」，不要先合并存储 | 图文混排文档在实际语料里的占比——它决定要不要上多模态索引 | 不要为「任意模态互搜 / 统一向量空间」预留 schema；不要一上来就换数据库 |
| 文档密集（合同 / 报表 / 发票） | 关键字段（数字、编号、金额、日期）走确定性路径，VLM 只做组织与解释；生成部分必须能引用到原文位置 | 原件是否被作为可再次消费的资产登记（模态、权限、被哪个模型版本读过） | 不要在没有对照评测的情况下宣布「免 OCR 上线」；不要把关键取值交给生成路径 |
| 要上多模态 Agent | 先解决环境可重置，再谈成功率；先用「生成建议 → 人确认」跑通责任链 | 基准与评估的发布物里是否出现成本、步数与失败分类 | 不要在权限、审计与回滚路径建好之前让 Agent 直接改系统状态 |
| 要自托管中文 VLM | 逐个模型核验权重许可、上下文长度与支持的输入模态，并用自有语料跑一次对照 | 推理集群与批处理调优的真实成本（按 GPU 小时算，不按 token 算） | 不要按「开源即可任意用」假设许可；不要用单次榜单排名做选型结论 |
| 要生成内容并商用 | 先核产品条款与当地法规对生成标识与权属的要求，留存来源与授权记录 | 平台侧是否出现生成标识与来源登记的强制字段 | 不要把生成工具的使用条款当成授权条款；不要把生成结果直接用于对外高曝光物料 |
| 行业垂直（医疗 / 工业 / 金融 / 政务） | 自建固定评测集 + 关键字段准确率 + 定期人工抽检，先把验收判据写死 | 是否出现可核验的行业评测协议（大概率不变） | 不要等行业标准再动手；不要用通用榜的分数当行业验收依据 |

「明确不要做」这一列的共用逻辑：**这些动作的代价是确定的（改 schema、全库重编码、责任落在自己身上），而收益依赖一个尚未成立的假设**（统一向量空间已可用 / 编码器升级免费 / 生成内容权属已清）。等 5.6 的信号出现再投入，损失的只是时间。

如果只能做一件事：**把「峰值能力」与「底线能力」分开测**。多模态项目最常见的失败不是模型不够好，而是没有人能回答「换成便宜一个量级的模型，系统还剩多少能力」（[§3 §3.5](01-multimodal-ai-section-3-sec3.md) 的判据）。具体三步，今天就能落地：

1. **把关键取值从生成路径搬到确定性路径**——数字、编号、日期、金额由专用模型给出，VLM 只负责组织与解释。
2. **建一个固定评测集**，含关键字段准确率与失败分类；它同时是选型依据与回归门禁。
3. **把三样登记成资产**：编码器版本、模型版本、原件是否被消费过及被哪个版本消费过。

如果只能排一个顺序，按这条走：

1. **先定关键字段的取值来源**：哪些走确定性路径、哪些允许生成并引用原文——这一步决定错误可不可控。
2. **再建固定评测集**：含关键字段准确率与失败分类，并用它做选型与回归门禁。
3. **然后接模型**：把直读接在候选集之上（路径 B），不改变索引那条路径。
4. **最后才谈 Agent 与自托管**：这两类都会改变数据边界与责任归属，回滚成本高于前三步。

### 5.8 小结

> 本节小结：本主题下 AI 真正改变的**唯一那条机制**是**接口边界上移**——模型可以直接消费原始模态，于是「预处理」从架构必经环节变成可选优化环节，原件从归档物升级为可再次消费的资产；原生多模态把这条机制推到参数层（桥是训练出来的表示，不再是外接的适配器）。它**没有改变**的是三件事：验证成本（生成式输出不携带「我在猜」的信号，关键取值仍要有确定性路径）、环境可复现性（Agent 的结论要环境可重置才成立）、以及索引的基本职责（「从大规模语料里找」仍然只能靠编码 + 索引完成）。本节没有一行达到 L1，最接近的四行——模型直读原件、原生多模态、多模态 RAG、语音识别与合成——都卡在「第三方（非厂商）公开生产案例」这一条上；所以现在该投的是确定性路径、固定评测集与三样版本登记，而不是等待一个更强的模型。
>
> 判断本主题下任何新提法的快捷方式：**它改变的是「感知」「表示」还是「行动」？** 改变感知的（直读原件）今天就能用；改变表示的（原生融合、统一向量空间）要按「可替换性」算账；改变行动的（Agent、具身）要先有外部判据与可重置的环境。
