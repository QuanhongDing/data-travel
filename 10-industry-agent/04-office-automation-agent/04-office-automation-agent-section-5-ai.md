## 5. 前沿演进（AI 时代）

### 5.1 先分清三类「前沿」

1. **机制变了**：抽取从"模板 / 序列标注"变成**生成式抽取 + 原文回指 + 字段级置信度**；起草从"套模板"变成"生成 + 人审"；执行从"单个 RPA 脚本"变成"状态机 + 可补偿动作"。**这类变化影响架构决策。**
2. **接口与规范变了**：电子发票与电子凭证的格式规范、办公套件的扩展接口、身份与单点登录协议在演进【公开：以各自规范与文档当前版本为准】。**这类变化影响集成与合规。**
3. **只多了产品**：同一套能力换包装。**只在选型表里体现。**

判别方法仍是那一句：**"换一家厂商，这条结论还成立吗？"**

### 5.2 判据与分级

沿用三条 L1 判据：**① 已 GA 且有正式文档 / 发布条目**；**② 有第三方（非厂商）公开的生产案例**；**③ 接口稳定、可预期**。

| 演进方向 | 级别 | 机制变了什么 | 判据落点（可否自行核验） |
| --- | --- | --- | --- |
| 生成式文档抽取（带原文回指） | **L2** | 从模板 / 标注模型变成"生成 + 位置回指 + 置信度" | ① 成立（文档理解类能力条目可核）；② **核不到**（准确率数据几乎都来自建设方）；③ 部分成立（Schema 表达各家不同） |
| 字段级置信度与低置信转人工 | **L2** | 阈值从"整篇"细化到"字段"，人工只核对不确定的部分 | ① 成立；② 核不到；③ 成立 |
| 流程状态机 + 可补偿动作 | **L2** | 从"脚本串行执行"变成"显式状态与补偿" | ① 成立（持久化工作流引擎的文档条目）；② 核不到（补偿动作表是业务特有的，无通行清单）；③ 成立 |
| 短期凭证与按实例授权 | **L2** | 凭证从"长期服务账号"变成"按流程实例、短期、最小权限" | ① 成立（身份与令牌相关文档条目）；② 核不到；③ 成立 |
| RPA 与模型分工（理解 / 执行分离） | **L2** | 从"模型直接操作界面"变成"模型给判断、RPA 做执行" | ① 成立；② 核不到；③ 部分成立（RPA 工具接口差异大） |
| 受限端到端办公 Agent | **L3** | 从"多步人工点击"到"一句话办完" | ① 只有演示与自研；② 核不到；③ 不成立（**责任无法归属**） |
| 全自主审批决策 | **L3** | 由模型决定"批不批" | ① 只有演示；② 核不到；③ 不成立（**合规与责任均无通行做法**） |

**本节没有一行达到 L1**——卡点同样在 ②：**办公自动化的效果数据（字段准确率、介入率、返工率）几乎都来自建设方**，且**强依赖于各家自己的单据形态与流程**，跨组织不可比。因此这一支应按"**机制可验证、效果必须自测**"理解。

### 5.3 演进方向逐条拆解（核心节）

#### 5.3.1 生成式抽取：把"模板维护"换成"回指与阈值"

**机制**：抽取不再依赖为每种版式写模板，而是生成式抽取并给出**字段级置信度 + 原文位置**。

**对架构决策的影响**：模板维护成本下降，但**新增两项职责**——① **原文位置的存储与呈现**（供人工核对）；② **阈值曲线的维护**（阈值成为质量与成本的调节旋钮）。这两项是"换生成式抽取"的真实代价，比换模型重要。

**边界**：生成式抽取**必然**有误差，因此"低置信转人工"与"高代价字段用更严阈值"**不能省**；省掉它们，等于把错误直接写进业务系统。

#### 5.3.2 状态机与补偿：从"能跑"到"错了能退"

**机制**：把流程显式建模为状态与转移，并为每个可写动作定义逆向动作（或将其列入"不可逆、必须前置审批"清单）。

**对架构决策的影响**：**"可补偿性"成为设计期约束**（不是运行期补丁）；这直接改变了动作顺序——**不可逆动作不能放在链路中间**（与 [Ch12 §09 灰度与回滚](../../12-architecture/09-gray-and-rollback/09-gray-and-rollback.md) 同源）。

**边界**：补偿不是"撤销"——财务上常常是"冲销"（产生一笔反向记录），因此**补偿本身也要留痕**（`inverse_of`），否则事后无法证明已退回。

#### 5.3.3 短期凭证与按实例授权：把爆炸半径压到一张单据

**机制**：不再用长期服务账号，而是为**每个流程实例**发放短期、最小权限凭证。

**对架构决策的影响**：安全模型从"服务可信"变成"实例可信"——**一次凭证泄漏的影响面从"所有单据"缩到"一张单据的窗口期"**；代价是要内部身份体系支持细粒度签发。

**边界**：凭证的 scope 必须与流程步骤对齐（写 ERP 的凭证不该能读人事）；**判据**是"越权调用会被拒并留痕"。

#### 5.3.4 RPA 与模型分工：把脆弱性收敛到一处

**机制**：模型负责读与判断，RPA / 脚本负责确定性的点击与写入；界面变化时由模型给出**变更建议**。

**对架构决策的影响**：**两类错误的可观测性成为必需**（"理解错"与"执行错"要分开计数），否则混合链路无法调试；这也让"界面变化"从"突然全断"变成"有信号可跟进"。

**边界**：不要让模型直接操作系统界面（脆弱且难归因）；界面的**最终修法仍由人确认**。

#### 5.3.5 受限端到端与全自主审批：为什么停在 L3

两者卡点不同：**受限端到端**卡在"动作集的边界与责任"（可做，但边界必须由系统强制、回放必须完整）；**全自主审批**卡在"合规与责任归属"——**批与不批是责任行为，不是技术行为**。**给读者的动作**：把"自主"限定在**理解 + 起草 + 建议**，签字权保留给人。

#### 5.3.6 一条可复用的操作：怎么判断某条演进方向该不该跟

上面的分级是结论，下面把它变成三步操作——**以后遇到本节没列到的新名词，用这三步自己判**：

**第一步：定位它替换掉了哪个部件。** 写不出"它替换的是谁"，就说明它没有机制内容。**本主题合法的三种答案**：替换了一个**部件的实现**（如抽取从"模板匹配"换成"生成 + 回指 + 阈值"）、替换了一个**字段的归属**（如审批记录从"结果"变成"输入快照 + 依据"）、替换了一个**动作的落点**（如凭证从"按服务发放"变成"按流程实例发放"）。判不出来 → 归第 3 类，只改选型表。

**第二步：查三条判据的落点，尤其是②。** ① 与 ③ 通常容易满足，**真正的分水岭是 ②——第三方非厂商的生产案例**。本主题的卡点有一条特殊的形状：**办公自动化的效果数据（介入率、返工率、错单率）几乎全部由建设方自述，而且它们高度依赖各自的组织流程与单据分布**——同一个模型在 A 公司的报销单上很好，在 B 公司的合同条款上可能毫无优势。**因此本主题里，"别人的数字"最不可移植。**

**第三步：按级别决定动作，且动作要带退出条件。**

| 级别 | 动作 | 必须同时写下的东西 |
| --- | --- | --- |
| L1 | 可以直接进架构约束 | ——（本主题暂无） |
| L2 | 排进试点，**但不进架构约束** | **退出条件**（什么观测结果出现就停）；本主题还要加一条：**它是否让"退回能力"变差** |
| L3 | 只做最小版本，不做技术选型 | 最小版本是什么（如全自主审批只做"生成建议 + 人确认 + 留痕"） |

**本主题特有的准入条件有两条**：① **任何提升自动化程度的方向，先回答"它把哪个动作变成了可写"**——**每多一个可写动作，就多一格需要写"失败怎么退"的位置**（§6.4 的红线检查）；② **任何减少人工环节的方向，先回答"少掉的那个人原本在拦什么"**——办公场景里的人工环节常常是**偶然形成但真实存在的闸门**，把它去掉之前要先确认那个风险已经被系统承担。

### 5.5 被过度宣传的部分

1. **"全自动办公"**：宣称"单据自己流转、审批自己完成"。**可核验的形态**是"理解 + 起草 + 建议自动化，签字保留给人"；全自主审批在合规与责任上无通行做法。
2. **"抽取准确率 99%"**：这个数字通常来自**自家单据分布**，换一个供应商版式就会变；可核验的形态是**你自己的字段级曲线**。
3. **"RPA 已死，全用 Agent"**：确定性操作交给概率模型，**是提高而非降低维护成本**——分工才是正解（§3.2.7）。

### 5.6 未来 3–5 年：可证伪的预测

| 预测 | 被证伪的信号 |
| --- | --- |
| "字段级置信度 + 低置信转人工"会成为单据类抽取的默认形态 | 两年后主流实现仍用整篇阈值且无转人工规则 |
| "补偿动作表"会成为流程自动化的标准交付物 | 两年后实现仍普遍把不可逆动作放在链路中间 |
| 短期凭证（按流程实例）会成为跨系统写入的默认做法 | 主流实现仍用长期服务账号写入业务系统 |
| 端到端验收指标会从"准确率"转向"介入率 + 返工率" | 采购与验收仍只看抽取准确率 |

**这四条全部是【经验】档**：它们是对机制与采购行为的判断，无具名出处、无推导链——**请按"可被证伪"使用，而不是当结论**。

### 5.7 给架构师的行动建议

1. **今年就该做**：流程与红线清单 + 字段级阈值 + 幂等与补偿动作表。三件事不依赖任何前沿判断。
2. **可以试点**：生成式抽取（先选一类单据，带原文回指与更严阈值）；审批工单的输入快照；短期凭证。
3. **先别投**：全自主审批与"一句话办完且无需确认"的端到端——责任与合规无通行做法。
4. **无论哪条**：把**介入率与返工率**作为两条日常指标——前者说明自动化程度，后者说明自动化质量。

### 5.8 小结

> 本节小结：AI 时代对办公自动化的改变**有两条是机制性的**——**抽取从模板变成"生成 + 回指 + 字段级置信度"**（于是阈值曲线与原文位置成为基础设施）、**流程从脚本变成"状态机 + 可补偿动作"**（于是可补偿性成为设计期约束）；其余方向（短期凭证、RPA 与模型分工）都是在这两条之上的安全与工程加固。这一支没有一行达到 L1，卡点全在"第三方非厂商生产案例"；因此请按"**机制可验证、效果必须自测**"理解它——**效果只能靠你自己的字段曲线与端到端两个指标去量**。

> 💡 **思考锚点**：如果你的抽取模型明天换一代（更强），你的**阈值表**需要重画吗？如果需要，说明你的"质量—成本旋钮"依赖模型；如果不需要，说明阈值是按字段代价定的（正确做法）。再问一个：你现在的**补偿动作表**有几条？答"零条"意味着不可逆动作在链路里没有任何退路——你打算先补哪一张表？
