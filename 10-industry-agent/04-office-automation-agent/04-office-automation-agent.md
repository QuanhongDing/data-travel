# 办公自动化智能体（Office Automation Agent）

> **一句话定位**：办公自动化的对象是**文档、流程与既有系统**三件事——智能体的价值不在"会聊天"，而在**把一张单据从头走到尾，并且走错了能退回**。

## 1. 概念与定位

### 1.1 是什么

**学术 / 工业定义**：办公自动化智能体是**以"文档 + 流程 + 既有系统"为操作对象**的智能体家族，典型能力有四类：**文档理解与结构抽取**（把 PDF / 扫描件 / 邮件 / 表单变成结构化字段）、**流程编排**（按状态机推进多步，含审批节点）、**跨系统执行**（把结果写进 ERP / CRM / 工单 / 数据库）、**起草与润色**（在人的确认下生成文本）。

**工程定义**：在数据架构师手里，办公自动化智能体是**一件"确定性骨架 + 概率性填充 + 人审闸门"的组合**：

- **确定性骨架**：流程、权限、幂等、补偿、留痕——这些**必须零概率**，由代码与系统保证。
- **概率性填充**：文档抽取、意图理解、草稿生成——这些**必然有误差**，所以必须带**字段级置信度**与**转人工规则**。
- **人审闸门**：写操作与不可逆动作前的人工确认（带超时与留痕）。

**「办公自动化智能体」与「RPA」「工作流引擎」的差别**：

| 维度 | RPA（机器人流程自动化） | 工作流引擎 | 办公自动化智能体 |
| --- | --- | --- | --- |
| 输入 | 界面元素 / 坐标 / 固定字段 | 结构化表单与事件 | **非结构化文档 + 半结构化表单 + 事件** |
| 变化耐受 | 界面一改就断 | 流程外的情况处理不了 | **对输入形态变化有容忍**（靠模型理解） |
| 确定性 | 高（但不健壮） | 高 | **混合**：骨架确定，判断部分概率 |
| 失败形态 | 点错按钮 / 找不到控件 | 卡在某个节点 | **抽取错误被静默写进系统**（最危险） |
| 留痕 | 操作日志 | 流程日志 | 需要**输入 + 判断 + 动作**三段留痕 |

**一句话判断**：**"它能不能在没人盯着的时候把一张单据走完，并且走错时能被发现和退回"**——这才是办公自动化的判据，而不是"能对话"。

### 1.2 为什么需要

这一支是被**五件事**逼出来的：

1. **文档是非结构化的**：发票、合同、邮件、报表的格式千差万别，**模板匹配撑不住**（新供应商换一个版式就断）；语言模型提供了"理解"的能力，但**必须配置信度与兜底**。
2. **流程跨系统**：一张单据要走 ERP、CRM、工单、财务多个系统，**每一步的失败模式不同**（超时、部分成功、权限不足）。
3. **审批必须可举证**：谁在什么时候批准了什么、依据什么材料——**留痕不足会导致责任无法认定**。
4. **错误代价不对称**：抽取错一个金额并写进财务系统，**修复成本远高于人工复核成本**；所以"低置信度转人工"不是保守，而是经济性最优。
5. **权限最敏感**：办公自动化天然要触碰**人事、财务、合同**这类高敏数据，权限域与最小凭证是前提而不是优化项。

### 1.3 在 AI 时代数据架构中的位置

```
   [邮件 / 扫描件 / 表单 / IM]  ← 输入
            ↓
   [办公自动化智能体 · 本文]
     ├ 文档解析与结构抽取（带字段级置信度）
     ├ 流程编排 + 审批闸门（人审、超时、留痕）
     ├ 跨系统执行（凭证托管 + 幂等 + 补偿）
     └ 评测（字段级准确率 + 人工返工率）
            ↓ 依赖
   [模型网关](../../06-multi-model/03-model-gateway/03-model-gateway.md)（生成能力）
   [Agent 平台](../../05-agent-platform/02-agent-platform-architecture/02-agent-platform-architecture.md)（配额 / 审计 / 沙箱）
   [治理](../../08-ai-governance/01-ai-data-governance/01-ai-data-governance.md)（分级保密与权限）
```

- **上游**：Ch8 治理（分级保密与出网）、Ch1 建模（主数据与实体口径，决定"抽出来的字段往哪落"）。
- **下游**：Ch9 数据智能产品（办公自动化是产品形态之一）、Ch15 案例（流程与组织的真实约束）。
- **横向**：Ch11 §01 数据质量（抽取质量的度量同源）、Ch11 §07 审计（留痕与合规）、Ch12 §09 灰度与回滚（写操作的可逆性）。

### 1.4 演进历程

- **RPA 阶段（2015–2020）**：以界面操作为主，**确定性高但脆弱**——界面一改就断，维护成本随流程数线性上升。
- **OCR + 模板阶段（2018–2022）**：把扫描件转文本，用模板 / 规则抽字段；**对版式变化敏感**，模板数随供应商数增长。
- **抽取模型阶段（2022–2024）**：用序列标注 / 文档理解模型抽字段，**格式容忍度提升**，但引入"置信度如何用"的新问题。
- **LLM 抽取 + 起草阶段（2023–2025）**：抽取与起草合并到生成式链路；**"引用回指 + 字段级置信度 + 低置信度转人工"成为标配**，因为幻觉在财务 / 合同场景的代价不可接受。
- **编排与人审阶段（2024–2025）**：智能体不再只做单点动作，而是**在流程编排里承担"理解 + 起草"环节**，执行与审批仍由确定性系统与人完成。评价标准从"抽取准确率"转向**"端到端人工返工率"**。

> 主线：**确定性骨架不变，概率性部分逐步上移——从"替代点击"到"替代理解与起草"，人保留在判断与签字位。**

## 2. 核心原理

### 2.1 关键概念定义

- **文档结构抽取（Document Extraction）**：把非结构化文档映射为**Schema 约束的结构化字段**（含类型、单位、日期归一），每个字段带**置信度**与**原文位置**。
- **字段级置信度（Field Confidence）**：单个字段的可信程度；**判据是"按字段设阈值 + 低置信度转人工"**，而不是给整篇文档一个总分。
- **流程状态机（Process State Machine）**：把流程显式建模为状态与转移（含人工节点与超时）；**确定性骨架就长在这里**。
- **审批闸门（Approval Gate）**：不可逆动作前的人工批准，**必须带超时**（超时默认不执行），并留下"谁、何时、依据什么、批准了什么"的记录。
- **不可否认（Non-repudiation）**：留痕足以在事后还原"当时是谁基于什么做的决定"——这要求记录**输入、判断、动作**三段，而不是只记结果。
- **幂等键（Idempotency Key）**：抽取结果的**业务键哈希**（例如"单据号 + 供应商 + 金额 + 日期"），保证重试与重跑不会重复入账。
- **补偿动作（Compensating Action）**：当后续步骤失败时，用于抵消已执行动作的**显式操作**（冲销、回滚、生成红字单）；**没有补偿动作的步骤不能放在链路中间**。
- **人工介入率（Human Touch Rate）**：需要人工处理的单据占比；**它是"自动化程度"的诚实指标**（比"处理量"更能说明系统是否真在替人干活）。
- **返工率（Rework Rate）**：自动化处理后被人工纠正的比例——**端到端质量的核心指标**。
- **边界（RPA 与 Agent 的分工）**：**确定性操作交给 RPA / API**（点击、调用、写库），**理解与起草交给模型**；把确定性操作交给模型是这一支最常见的架构错误。

### 2.2 数学 / 形式化基础

**抽取质量的字段级口径**（不能用整篇准确率）：

```
对字段 f：precision_f = 抽对且写对的次数 / 写入次数
          recall_f    = 抽对且写对的次数 / 应抽取的总数（含漏抽）

判据：按字段分别设定阈值与转人工规则 ——
      金额 / 日期 / 主体 这类字段的错误代价高（财务场景），阈值应更严；
      备注 / 分类 这类字段可容忍更高错误率
```

**为什么必须字段级**：整篇准确率会被"大字段"稀释——一张发票有 20 个字段，其中"金额"错了但其余 19 个对，整篇准确率看起来仍有 95%，而错误的代价集中在那一项。

**置信度阈值与人工成本的关系**：

```
人工介入率 λ(θ) 随阈值 θ 上升而上升（低置信度都转人工）
错误漏出率 ε(θ) 随阈值 θ 上升而下降
目标：在 ε(θ) ≤ 可接受错误率 的前提下，最小化 λ(θ)

可执行动作：用历史数据画出「阈值 → 介入率 / 漏出率」曲线，取交点作为初始阈值
```

**判据**：**"可接受的错误漏出率"必须由业务写下来**（财务入账与内部纪要的容忍度差很多）【经验：具体数值随业务与审计要求浮动】，否则阈值没有依据。

**端到端指标（两个数一起看）**：

```
人工介入率 = 需人处理的单据数 / 总单据数
返工率     = 被人工纠正的单据数 / 已自动处理的单据数
判据：只降介入率而不看返工率，等于把风险从"人工处理"搬到"事后纠正"
```

**流程的可逆性判据**：

```
步骤 s 若不可逆（已发款 / 已对外发送 / 已入库不可撤），则：
  必须在 s 之前完成全部校验与审批，且 s 不得位于可回滚链路的中间
  （与 [Ch12 §09] 的"不可逆动作前置条件"同一条理）
```

### 2.3 关键算法 / 方法

1. **文档解析**：版面分析（区分正文 / 表格 / 印章）+ 表格结构还原 + 文本抽取；**判据**：抽出的表格能还原出"行 × 列"的语义（而不是把整页当段落）。
2. **Schema 抽取**：按单据类型定义 Schema（字段、类型、必填、单位、归一规则）；抽取结果**必须带原文位置**（用于回指与人工核对）。
3. **低置信度转人工**：按字段阈值分流——**低置信度的字段转人工核对**（不是整篇转人工，否则介入率会高得无法接受）。
4. **流程编排**：状态机 + 超时 + 重试分类（可重试 / 不可重试）+ **补偿动作表**；**判据**：每个可写步骤都能回答"失败了怎么退"。
5. **跨系统执行**：凭证托管（最小权限、按流程实例发放短期凭证）+ **幂等键** + 超时与熔断；**判据**：同一单据重复执行不产生重复入账。
6. **审批与不可否认**：审批记录含"输入快照 + 判断依据 + 动作 + 时间 + 人"；**判据**：事后能还原当时的材料（而不是只有"已批准"三个字）。
7. **端到端评测**：字段级准确率（离线）+ 人工介入率 / 返工率（线上）+ 流程成功率（线上）；**三者缺一不可**（这就是 [Ch2 §07 效果评估](../../02-data-science/07-eval/07-eval.md) 的三层结构在办公场景的形态）。

### 2.4 与相邻概念的关系

- **办公自动化智能体 vs RPA**：RPA 是**确定性界面操作**，健壮性差但可预测；智能体是**概率性理解**，容忍输入变化但会出错。**正确分工**：确定性操作（点击 / 调用 / 写库）交给 RPA 或 API，理解与起草交给模型——把点击交给模型是常见且昂贵的错误。
- **办公自动化智能体 vs 工作流引擎**：工作流引擎擅长**已知流程的确定性推进**（状态、超时、重试、补偿），智能体擅长**流程外的异常与模糊输入**。**正确组合**：引擎做骨架（谁批准、什么时候超时），模型做填充（读文档、起草、分类）。
- **办公自动化智能体 vs 文档管理系统（DMS）**：DMS 解决"存与找"，智能体解决"读与办"；抽取结果最终要落进 DMS / 业务系统，**元数据模型要对齐**（否则会出现两套字段口径）。
- **办公自动化智能体 vs 数据质量（[Ch11 §01](../../11-cross-cutting/01-data-quality/01-data-quality.md)）**：数据质量的"准确性 / 完整性"用在**抽取结果**上：字段级准确率、必填缺失率、单位一致性——**同一套断言思路**。
- **办公自动化智能体 vs Agent 平台（[Ch5 §02](../../05-agent-platform/02-agent-platform-architecture/02-agent-platform-architecture.md)）**：平台提供配额、审计、工具出口与沙箱；办公智能体是平台上的**一个高敏感租户**（它的工具出口直接连生产业务系统）。

> 💡 **思考锚点**：挑一张你现在（或同事）手工处理的单据，回答三个问题：它有几个字段？其中哪几个字段错了代价最大？这几个字段的置信度低于多少时你愿意让人看一眼？第三个问题的答案就是你的初始阈值——**先写下来，再去看历史数据能不能支撑它**；这三个问题里哪一个你答不上来？
