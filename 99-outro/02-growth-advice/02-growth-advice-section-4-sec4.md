## 4. 读书 / 写文章 / 做开源——三件复利的事

[§ 3 思维模型的落地：刻意练习](02-growth-advice-section-3-sec3.md) 已把「写文章 / 开源」作为刻意练习的其中一种形态讲过约束、代价与失效点（见 3.2.4），读书不在其列；本节不再重复那些判断，只回答执行问题：**三件事的先后顺序是什么、每一件做到什么算做完、它留下什么可被检索的东西、承载它的平台怎么选、你手上已经有的存量怎么办**。影响力的另一面（这三件事作为杠杆怎么放大影响半径）在 [§ 5 影响力的复利](02-growth-advice-section-5-sec5.md)。

本文件面向**已经在做、但产出还没有出去的人**——典型画像是做了几年事、读过一些书、手上有一堆内部文档和私有代码，但没有一件东西能被不认识他的人检索到。三件事的顺序是按「**除了你，还有谁能用上这个产出**」排的：读书只改变你自己，写文章让读者能用，做开源让使用者能用。谁在前面谁在后面，由这条决定，而不是由难易决定。

### 4.1 落地步骤

**Step 1：读书——先把配比写下来，再选书（第 1 个月，每月 8–20 小时【经验】）**

- 定下三个层次的阅读配比并写在纸面上：**专业书 30%**（工具 / 框架 / 方法）、**通识书 40%**（思维 / 认知 / 心智）、**闲书 30%**（想象 / 审美 / 人性）。比例是自设口径【经验】，作用不是精确，而是拦住「全部时间都被专业书吃掉」这个默认结果。
- 每读完一本，写**一行**「它改变了我原来的哪个判断」——不是摘抄，不是目录，是判断的前后对比。
- 给每一本认知框架类的书配一个可验证的落地动作：一次选型、一段代码、一份决策记录。配不上的书，标记成「暂不读」。

- **产物**：一份写明配比的书单（含三个层次各要读什么）；一份一行一条的「判断改动」索引；对每本书一个落地动作或一个「暂不读」标记。
- **判据**：抽一本你三个月前读完的书，不翻书说出它与你原来的判断差在哪一点——说不出来，说明只是读完了，没读进去。再检查你的书单：三个层次的实际占比写在纸面上吗（不写下来的话，实际占比会明显偏向有当期工作需求推动的那一类，通常是专业书【经验】）。
- **为什么必须这一步 / 为什么在第一位**：因为后两步的素材全部来自输入与一手实践，而输入是唯一一件**在时间上无法后补**的事——写作可以补写，开源可以补发布，但一本没读过的书不可能在需要它的那个下午被临时读完。代价是这一步的反馈最慢：读书本身不给任何纠错信号，所以判据必须由你自己外挂上去（见 4.2 第一条）。
- **谁负责 / 多久见效**：只有你自己，没有任何外部依赖；也正因如此它最容易被挤掉。见效时间以**月到年**计，第一次能感到回报通常是在某次讨论里你提出了别人没提出的那个角度。

**Step 2：写文章——先建「一手问题」清单，再排产（第 1–3 个月，每周 2–4 小时【经验】）**

三种类型各有出口，不能互相替代：

- **技术博客**：把「经验」变成「可分享的知识」，出口是公开渠道。
- **ADR / 设计文档**：把「决策」变成「可复用的资产」，出口是团队可检索的位置。
- **复盘 / 总结**：把「过程」变成「组织的学习」，出口是一次复盘会或一份可追踪的行动项清单。

具体动作：

- 建一个「问题—代价」清单：每踩到一个坑就写一行（当时想做什么、被什么挡住、最后付了什么代价）。写作的选题只能从这里出。
- 排产到每月 1 篇公开文章，每篇 1500 字以上【经验】（这是本书的一手主张，不是行业基准，按你的时间形态可降到每两月 1 篇，但不要降到「有空再写」）。
- 写完必须发出去——发到公司、社区、公众号、行业大会，任一；只存草稿等于没写。

- **产物**：一份持续更新的「问题—代价」清单；每月 1 篇公开发表的文章；每篇文章末尾由读者追问留下的问题清单。
- **判据**：打开最近一篇文章，里面有没有一句「我当时是这么取舍的」——没有，它是资料整理，不是一手产出；再看后台，有没有**不认识你的人**留下过具体问题（不是点赞、不是同事的鼓励）。
- **为什么必须这一步 / 为什么在第二位**：因为写作是唯一一个「把你的约束与代价变成可被引用文本」的动作，而它是开源的前置——没有可被引用的文字，别人读不懂你的仓库在解决什么问题。换序的代价很直接：先开源后写作的人，项目 issue 里最多的提问是「这东西到底解决什么问题」。
- **谁负责 / 多久见效**：你自己负责写，但**读者负责让它活下来**；公开渠道的第一次外部反馈通常在数周到数月内出现【经验】。若你要写的是涉密内容，先过 4.2 的「发布前的三道判定」。
- **三条反模式**（各自对应一种失败）：**不要「为了写而写」**——写是为了留下可被复用的资产，不是完成产量任务；**不要「追热点」**——选题只能从一手约束里出，追热点的文章寿命以月计【经验】；**不要「只写不说」**——写完必须发出去，只存草稿等于没写。

**Step 3：做开源——先当使用者，再当贡献者，最后才当主导者（第 3–12 个月【经验】，随你手上项目的真实使用规模与社区响应速度而变）**

三种参与方式是有顺序的，跳级通常不成功：

1. **使用者**：通过使用一个真实项目提升自己（这是基础）。
2. **贡献者**：通过 PR / Issue 参与社区（这是进阶）。
3. **主导者**：维护一个自己的项目（这是顶级）。

具体动作：

- 从你**每天在用**的那个模块里抽出可以独立的部分，不从「造一个轮子」开始。
- 开源前写下维护承诺：多久回一次 issue、同时支持几个版本、什么条件下归档。
- 前三个月只做贡献者：补文档、补测试、修 bug，不改别人的设计。
- 在公共代码托管平台发布，并写一节「本项目不解决什么问题」。

- **产物**：至少 1 个被合并的 PR；一份写明维护承诺的 README（或一份「我为什么不开源这个模块」的判断记录）；一个带 issue 响应记录的仓库。
- **判据**：最近 10 个 issue 里超过 30 天未回的有几个——超过 3 个，说明你在同时欠着几笔维护债（见 4.2 第五条）；再看你的 PR 是在补文档 / 补测试 / 修 bug，还是在改别人的设计——前者被合并的概率高得多【经验】。
- **为什么必须这一步 / 为什么在最后**：因为开源是**长期承诺**而不是一次性动作，它的成本曲线在发布之后才开始上升；把它排在最后，是为了让你先用写作确认「这个东西确实有人关心」，再付这份承诺。跳过的代价是把自己锁进一个没人用的仓库——issue 没人来，README 也没人读。
- **谁负责 / 多久见效**：你自己负责，但项目一旦有外部使用者，维护就变成持续义务（不能靠热情续期）。见效时间以**年**计，且量的是「被采用」而不是「被点赞」。
- **三条反模式**（各自对应一种失败）：**不要「为了开源而开源」**——先解决自己的问题，再考虑开源；**不要「重造轮子」**——先看社区里有没有类似的，能贡献就不要自己造；**不要「光做不管」**——开源是长期承诺，不是一次性 PR。

三步里最常被跳过的是 **Step 2 的「发出去」**：写完了放在草稿箱、笔记软件或公司内网，看起来迟早会发。跳过之后第一个出问题的时点是**一次需要现场解释的场合**——技术分享的提问区、晋升答辩、面试追问，症状是同一句话：能讲清「我做了什么」，讲不清「为什么这么做、代价是什么」。这句话之所以出现，是因为没有经过读者追问的文本从来没有被检验过。

### 4.2 关键技术点

**输入必须配一个输出**

- **做法**：每读完一本认知框架类的书（或一份长文档），在两周内产出一个可被检验的东西：一次选型判断、一段代码、一份决策记录、一篇 1500 字的文章。
- **机制**：因为输入是反馈周期最长的动作——读的时候没有任何判据检验你理解得对不对，所以只有把它挂到一个会在外部产生结果的动作上，误差信号才会回来。代价是阅读速度看起来会更慢：你不可能一年读完二十本，因为每本都要配一个产出。
- **失效条件**：**当你的岗位本身每周都有上线与复盘时**（反馈已经足够密），额外为阅读外挂判据的边际收益下降，此时应把时间从「读 + 产出」转向「做事 + 记录」；反之在一年只做一两个大决策的岗位上，不加输出的阅读风险最高。症状：你的书单在增长，但判断的版本号没有变过。
- **档位**：【经验】（本主张属本书一手经验）。与之相关的一般性公开讨论，常见源头是 Ericsson 与其合作者 1993 年的研究【公开】（Ericsson, Krampe & Tesch-Römer，Psychological Review，1993，可按关键词 deliberate practice 检索原文；该研究讨论的是技能习得的一般条件，不是「读书无效」的结论）。

**配比先写下来**

- **做法**：把三个层次（专业书 / 通识书 / 闲书）的配比写在书单表头上，每季度回看一次实际占比。
- **机制**：因为**取用最方便的书会挤掉取用最不方便的书**——专业书有明确的工作需求推动，闲书与通识书没有，于是默认结果就是把后两者挤没。把它写成一条占比，等于给「暂时用不上」的书留出预算。代价是你必须接受一部分阅读时间当期不产生任何工作产出。
- **失效条件**：**当你处在明确的技能冲刺期（转岗、面试、接手一个陌生技术栈）时**，强行维持 30/40/30 会让当期最需要的那部分不够用。此时的判据不是比例，而是「这次冲刺有没有明确的截止日期」；有截止日期就允许暂时倾斜，没有就说明只是习惯性逃避。
- **档位**：配比是自设口径【经验】，不是行业基准。

**选题只能从一手约束里出**

- **做法**：选题从「问题—代价」清单里挑，写的是「我当时被什么挡住、付了什么代价、什么条件下会重来」；公开资料里已经写清楚的部分，最多用两段带过。
- **机制**：因为读者能自己搜到的事实你写得再全也不加分，而你的一手约束与代价别人拿不到，所以可被引用的价值集中在这一段。代价是**产量被你的经历封顶**：换岗、纯维护期、休假期，产量必然下降。
- **失效条件**：**当选题开始从热点与资料整理里出时**，这条会以「阅读量还行、但没人引用」的形式坏掉。症状：文章里没有一句「我当时是这么取舍的」，评论区只有「写得清楚」这类评价。此时正确的动作是停一期，回到清单上找真实的坑，而不是把频率提上去。
- **档位**：【经验】。追热点的文章寿命通常只有几个月，写长期约束与代价的文章可能被引用数年——这是方向判断，不是承诺；具体数值在不同领域差几个量级，请以你自己后台数据核验。

**产量由你做事的速度封顶**

- **做法**：把「每月 1 篇」当作上限而不是下限【经验】；排产前先看这个月有几个真实的一手问题入库，不足就从存量里补，不硬凑。
- **机制**：因为一手素材的数量等于你参与真实决策的数量，所以写作频率的上限由你真实做事的节奏决定；硬凑出来的产量会把内容拖向资料整理，反而稀释可引用部分。代价是产出曲线随工作节奏波动，看起来不稳定。
- **失效条件**：**当你被要求按固定频率产出时**（专栏合约束、团队博客轮值），这条会让位给排期。此时的处理办法是提前把曾经写成 ADR 的决策改写成对外的版本，而不是现编选题——前者成本低且有存量，后者必然注水。
- **档位**：【经验】。

**开源的三档参与与维护承诺**

- **做法**：使用者 → 贡献者 → 主导者逐级走；升到主导者时，在 README 里写明维护承诺（响应周期、支持版本数、归档条件），并把它当作对外条款。
- **机制**：因为发布是一次性动作，而「别人还在用」是持续的，所以开源的成本曲线在发布后上升而不是下降；写下承诺的作用是把这份负债显性化，让使用者据此决定要不要依赖你。代价是你失去「随时不管了」的自由。
- **失效条件**：**当你同时维护的项目数超过你能稳定响应 issue 的数量时**，这条会以信用损耗的形式坏掉：逾期 issue 与过期结论都在扣同一份信用。症状：最近 10 个 issue 里超过 30 天未回的有 3 个以上，或你已经在用「最近很忙」回复。此时正确动作是归档并写清「本项目不再维护」，而不是继续挂名。
- **档位**：【经验】。开源贡献的复利方向常见描述是「主导一个项目若干年 → 个人品牌 + 行业影响力 + 招聘磁石 + 商业机会」「持续贡献一个主流项目若干年 → 行业声誉 + 同行人脉 + 跳槽筹码」，这是方向而不是承诺，兑现速度取决于项目是否被真实采用。

**发布前的三道判定**

- **做法**：任何要出组织边界的内容，发布前依次过三道：有没有引用内部数据（数据）、有没有暴露内部结构与路线（信息）、组织政策与保密规定允不允许（政策）。三道都过再动手写终稿。
- **机制**：因为公开内容不可撤回（会被转载、镜像、缓存），所以判定必须发生在发布之前；撤回原文不等于撤回副本。代价是涉及内部数据时产出周期显著拉长【经验】，从「一周写完」变成「写完再等审」。
- **失效条件**：**当没有人明确负责合规口径时**，这条会以两种相反的方式坏掉：什么都发不出去（自我审查过度），或发出去才发现越界（审查缺失）。判据是「先写完再问能不能发」这个顺序有没有出现过——出现过一次，说明三道判定还没被当成步骤。
- **档位**：【经验】。能发到什么粒度以你所在组织的当期规定为准，不要以「别人发过」为依据。

**判断索引：一行一条，长期维护**

- **做法**：维护一份「书 / 文章 / 决策 → 改变了哪个判断」的索引，每行三条：被改的判断（写成前后对比）、改动来源、改动日期。用纯文本存，放在你能一次性全量导出的地方。
- **机制**：因为复利只在产出被检索到时发生，而人对自己判断变化的记忆衰减最快，所以必须把「我读过什么」转成「我的判断改过哪几次」；索引的检索单位是判断，不是书名。代价是它必须长期维护——中断一次之后，中间那段时间的判断变化就再补不回来了。
- **失效条件**：**当索引条目开始退化成书籍摘要或目录复述时**，这条就坏掉了：它从判断的版本历史变成了读书笔记，检索价值归零。症状：某一行你读不出「之前是怎么想的」，只有「这本书讲了什么」。修法是只保留能写成前后对比的行，其余删掉。
- **档位**：【经验】。

### 4.3 工具链与平台

这一节不给「推荐组合」，因为三件事的成本结构完全不同：读书的成本在时间，写作的成本在渠道的维护，开源的成本在响应。下表按类别给选型判据与不选它的代价。

| 类别 | 候选 | 选型判据（在什么约束下选哪个） | 不选它的代价 |
| --- | --- | --- | --- |
| 阅读与笔记 | 纸质书 + 电子阅读器 / 笔记软件 / 版本化的纯文本仓库 | 按「五年后你还找得到吗」选：要长期检索、要被引用的判断索引，用纯文本 + 版本控制；只是读书时标记，用阅读器自带的标注即可 | 把判断索引放在会换供应商、不能导出的笔记软件里，换工具时索引断档，「我读过的书改变了我什么」这件事重新变成零 |
| 写作与发布渠道 | 自建域名的站点 / 技术社区专栏 / 公众号 / 内部知识平台 | 第一判据是**换渠道时读者能不能跟你走**（订阅、邮件、域名可迁移；平台推荐流不可迁移）；第二判据是组织允不允许公开 | 把不可迁移的渠道当唯一出口，换公司或换平台时影响力归零；把可迁移渠道当唯一出口，则在渠道本就没有推荐流的情况下，最初的几十到一两百个读者要自己一个个找来【经验】，第一次外部反馈来得更慢 |
| 开源托管 | 公共代码托管平台 / 自建 Git 服务 | 按「你希望谁来参与」选：要外部贡献者与可核验的公开记录，用公共平台；模块含内部依赖或只能内网使用，选自建并同时决定「是否真的对外开源」 | 在自建服务上做「开源」，项目被锁在没有外部读者的房间里——外部贡献者与 issue 的数量级会明显更低【经验】 |
| 检索与备份 | 全文检索工具 / 导出能力 / 纯文本优先的存放 | 按「能不能一次性全部导出」选；写之前先确认导出格式是开放的 | 内容积累三五年后无法迁移，等于把复利资产存进了一个会到期的保险箱 |
| 读者的来源 | 技术社区 / 邮件订阅 / Meetup 与会议 | 按「反馈有多硬」选：不认识你的人提出的具体问题最硬，同事的鼓励最软；社区适合冷启动，订阅适合长期，线下场合适合建立连接 | 只在熟人圈里发布，得到的反馈会被关系软化——你无法知道自己在陌生标准下是什么水位 |

表里最容易被误选的是**阅读与笔记**：多数人的第一步是「先把笔记系统搭好」，把工具当成前提。后果不是没笔记，而是**笔记永远在整理、判断从未落盘**——三年后你有一个整齐的知识库，却答不出「我读过的东西改变了我哪个判断」。正确的顺序是反的：先写下第一行判断，再决定用什么工具承载它。

第二个高频误选是**渠道**：用「粉丝数增长」当渠道好坏的判据，会系统性偏向推荐流平台，而这类增长在你停更几个月后回落得最快【经验】。渠道的第一判据始终是「换平台时读者能不能跟你走」。

### 4.4 存量迁移

这一节面向**已经有存量的人**：你已经读过一些书、写过多份内部文档、维护着若干私有代码。三件事在存量上落地，难的不是从零开始，而是**不把历史全部推翻**。

**① 先做什么：立刻见效且可回退**

从「把最近一次真实工作产出改写成对外版本」开始：选一个你已经做完、结论已经验证、且不涉及内部数据的决策，写成一篇 1500 字左右的文章或一份 ADR，**不改动任何历史文档**。同时给你手上正在维护的那个模块补一节 README（解决什么问题、不解决什么问题、怎么回退）。两件事都可在几个小时内完成，写错删掉即可，也不会触发任何流程。

**② 历史资产怎么分类处理**

| 存量类型 | 处理方式 | 判据 |
| --- | --- | --- |
| 过去读过的书 | **打标挂账**：不重读，只在某本书真的被用上的那一刻，回填一行「它把我原来的哪个判断改了」 | 这本书最近 12 个月有没有被引用过一次 |
| 已经写好的内部文档 / 复盘 | **只公开一部分**：脱敏成本低、结论已被验证的那批先公开；其余挂账，不为了公开而返工 | 去掉内部数据后，结论是否依然成立 |
| 维护中的私有代码 / 内部工具 | **只抽一部分**：抽最近三个月还在改动、且不依赖内部系统的模块；其余不动 | 这个模块有没有第三方依赖内部服务 |
| 已经读过的公开项目源码 | **打标挂账**：标记「我读过」，不算贡献；下一次给它提一个 PR 时才升级为贡献 | 有没有一条被合并的 PR |

判断顺序是：先看结论是否已稳定（决定能不能公开），再看脱敏成本（决定现在就做还是挂账）。**唯一值得立刻全部返工的是判断索引**——它的成本是一行文字，不是重读一遍书。

**③ 双轨怎么维持、维持多久**

公开发布之后，你一定会有两个版本并行：内部版（有上下文、可引用内部数据、结论更具体）与公开版（脱敏、以约束与代价为主）。双轨的维持成本主要落在**两版结论不一致时谁更新谁**这件事上。可用的规则有三条：

- 公开版只写**已经稳定、且不会再被内部数据推翻**的结论，内部版的细节更新不回灌到公开版；
- 两版共用同一份「判断索引」，判断改了先在索引里改，再决定要不要同步到文章；
- 公开版一旦被人引用，修正要发在原位（补一段说明），不要删旧文重发。

维持时长按【经验】设为**到公开版能独立回答 3 个追问为止**；能不能缩短，看的不是时间，而是**你有没有在不查内部资料的情况下答上过追问**。

**④ 什么信号说明可以退出双轨**

- 公开渠道出现**自然增长**：有人不是通过你的转发找到它的。
- 有不认识你的人引用你的结论，并**指出其中一处错误**（这比表扬更能说明它进了信息流）。
- 你能不查内部资料答上一次追问，且答案与公开版一致。
- 内部文档与公开文章出现结论冲突时，你能立刻说出**哪一版更新、为什么**。

四条里满足三条就可以停止「内部版先写、公开版后改」的流程，改为一次成稿。**只满足第一条就退出，是最常见的翻车方式**——自然增长可能只来自一次平台推荐，而正文里还留着没被追问检验过的判断。

**迁移分几波、每波要谁的许可**

三件事的存量迁移都不需要立项，但需要越过三道不同的门槛，按顺序推比按时间排更有效：

- **第一波（只靠自己，几小时内可完成）**：写第一行判断索引、把最近一次完成的决策改写成对外版本、给正在维护的模块补一节 README。
- **第二波（需要组织允许的）**：把内部文档里的通用部分脱敏后公开、在公开渠道建立发布位置。这一波的关键是**先拿到一次明确的「可以发」**，而不是默认没人管——一旦越界，代价是一次不可撤销的发布。
- **第三波（需要外部反馈的）**：把仓库放到公共平台、给别人的项目提第一个 PR、把文章投给一个会审稿的渠道。这一波必须有真实读者或审查者才有可能发生；没有的话不要提前做第三波，你只会得到一个没人看的仓库。

顺序不可换：第一波没做完就去做第三波，最常见的结局是「有仓库没内容」或「有渠道没素材」——发布位置上挂着三篇资料整理，然后这个渠道再也不更新了。

### 4.5 模板 / 示例

**模板一：三层次书单配比表（把原书单填进去即可用）**

| 层次 | 配比【经验】 | 候选书（示例，可替换） |
| --- | --- | --- |
| 专业书 | 30% | 《Designing Data-Intensive Applications》、《数据中台 / 数据治理实战》、《AI Engineering》、《Knowledge Graphs》、《Spark / Flink 权威指南》 |
| 通识书 | 40% | 《原则》、《奈飞文化手册》、《团队协作的五大障碍》、《系统之美》、《第五项修炼》、《Thinking, Fast and Slow》、《影响力》、《非暴力沟通》 |
| 闲书 | 30% | 《人类简史》《未来简史》《今日简史》、《三体》《基地》《银河帝国》、《苏东坡传》《杜甫传》《曾国藩家书》、《百年孤独》《霍乱时期的爱情》 |

**怎么用**：这一栏填的是「层次 + 已读判断」，不是书名清单本身；每读一本，在它后面补一行判断（见模板五）。书目的作者与版本以你手上的版权页为准——同名书较多。比例是起点：处在技能冲刺期时允许暂时倾斜，但要写下期限。

**模板二：写作的复利账（自己算一遍，不引用任何人的数字）**

```text
推算链（替换成你自己的实测值）：
  频率        1 篇 / 月                         ← 自设节奏【经验】
  年产量      1 × 12 = 12 篇 / 年               【推算】
  五年产量    12 × 5 = 60 篇                    【推算】
  阅读量      每篇按 5,000 次计 → 60 × 5,000 = 300,000 次浏览
              其中 5,000 是你的自设口径【经验】，不是行业基准；
              不同领域差几个量级，请换成你后台的实测中位数后再算

  这个数字的意义不是曝光量，而是：五年后你手上有一份
  可被检索的、能被别人引用的判断清单。
```

**怎么用**：把三行里的频率与阅读量换成你自己的实测值再算；不要照抄 5,000——它是一个占位符，写它的目的是提醒你「这个乘数必须来自你自己的后台」。如果算出来的数量让你觉得太少，答案通常是内容类型不对（资料整理型），而不是频率不够。

**模板三：每篇文章的选题卡（四格，写完就能判断该不该写）**

```text
[1] 一手问题：我在哪件事上真的踩过坑（时间 / 场景）
[2] 当时的约束：哪些条件是不可改的（时间 / 人力 / 数据 / 合规）
[3] 被否决的选项与代价：我还考虑过什么，为什么没选
[4] 可被引用的结论：读者能在自己那里复用的那一句
```

**怎么用**：四格里 `[3]` 最容易被跳过，而它恰恰是文章唯一不可被搜到的部分。如果 `[3]` 写不出来或写不出代价，说明这次经历还没有形成判断，改去写「问题—代价」清单里的另一行。

**模板四：开源 README 的维护承诺节（发布前必须写完）**

```text
## 维护承诺
- 响应周期：issue < {N} 天，PR < {M} 天（写你确定做得到的）
- 支持版本：{主版本数}
- 不解决：{明确写出不打算支持的使用场景}
- 归档条件：{什么条件下本项目会停止维护，例如连续 3 个月无维护者}
```

**怎么用**：填 `响应周期` 时按你**最忙的那个月**的能力写，不要按最好的月份写；`不解决` 这一节是减少未来 issue 成本的最有效手段，宁可写得不客气，也不要写「欢迎各种需求」。

**模板五：一行判断索引（纯文本，一行一条）**

```text
# 判断索引（按改动日期倒序，只写能写成前后对比的行）
2026-{月}-{日} | {来源：书名 / 文章 / 决策名} | 原来：{我原来的做法或信念} → 现在：{改成什么} | 触发场景：{在哪里被这个改动打脸}
```

**怎么用**：`原来` 与 `现在` 两栏必须都能写出来，写不出「原来」的条目直接删掉——那说明你本来就没有这个判断，只是记住了书上的结论。`触发场景` 一栏用来说明这次改动的可信度：写在真实项目里被推翻的判断，比写在读后感里的判断更值得被引用。

### 4.6 自检清单

1. 抽一本你三个月前读完的书，不翻书说出它改变了你哪个判断——说不出，这本书对你没有留下判断。
2. 你的书单里三个层次的实际占比写在哪里？凭感觉配比的人，实际占比会明显偏向有当期工作需求推动的那一类，通常是专业书【经验】。
3. 打开最近一篇文章，里面有没有一句「我当时是这么取舍的」？没有，它是资料整理。
4. 你的公开渠道后台里，有没有一个**不认识你**的人问过一个具体问题？
5. 你最近读过的东西，能不能指向一个具体动作（一次选型 / 一段代码 / 一份决策记录）？
6. 你手上正在维护的开源项目有几个？最近 10 个 issue 里超过 30 天未回的有几个？超过 3 个说明欠债。
7. 你提过的 PR 属于哪一类：补文档、补测试、修 bug，还是改别人的设计？
8. 上一次发布前，你有没有先过「数据 / 信息 / 政策」三道判定，还是写完才问能不能发？
9. 你公开发过的内容里，有没有一篇的第二版修正了第一版的结论？一次都没有，说明还没被认真追问过。
10. 内部文档与公开文章出现结论冲突时，你能立刻说出哪一版更新吗？
11. 最近一次被人当场问住是什么时候？想不起来，说明输出可能一直停在复述层面。
12. 你的判断索引（一行一条那种）现在存在哪里，五年后你还找得到、导得出吗？

### 4.7 小结

> 本节小结：三件事里真正决定成败的环节只有一个——**把读到的与做过的变成一段别人能引用的文字（Step 2 的「发出去」）**。读书只改变你自己，开源只在有人使用时才算数，中间的这一步是唯一把「你的判断」变成「可被检索的资产」的动作；没有它，前一步的输入无法被检验，后一步的项目也无法被理解。它的成本最低（一篇 1500 字即可开始）、可回退（删掉重写即可）、且立刻可用（下一次分享、答辩、面试就能引用），所以在三件事里它最值得优先投入。开源可以晚，书可以慢读，这一步不能跳。
>
> 💡 **思考锚点**：按 Step 2 的判据翻你自己的产出——最近一篇文章里有没有一句「我当时是这么取舍的」，后台有没有「不认识你的人」留下的**具体问题**；如果你的「判断索引」里最新一行的日期停在半年前，那么卡住你的是 Step 1 的输入，还是 Step 2 的那次「发出去」？
