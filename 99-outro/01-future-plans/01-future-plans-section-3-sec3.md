## 3. 实战建议

### 3.1 给正在转型的资深架构师

#### 三个"必须"做的转型动作

| 优先级 | 动作 | 时间窗 | 验收标准 |
| --- | --- | --- | --- |
| P0 | 主导一个 RAG / 智能体项目 0→1 | 6 个月内 | 跑通业务闭环、能 demo、能讲清指标 |
| P0 | 写一篇公开的技术博客 / ADR | 3 个月内 | 500+ 阅读 / 内部被引用 5+ 次 |
| P1 | 完成 AI 治理 / 数据合规培训 | 6 个月内 | 拿到信通院 / DAMA / CDA 证书 |
| P1 | 建立一个 5 人跨职能小组 | 12 个月内 | 跑通"数据 + 算法 + 业务"三方协同 |

#### 三个"不要"

- **不要**只做"翻译"工作（业务说一句话，你翻译成技术方案）。要做"反向翻译"：把技术趋势翻译成业务机会。
- **不要**把所有时间都投入"工具学习"。要把 30% 时间投入"组织建设"——你不带人，就永远是工具人。
- **不要**追求"全知"。要追求"在最关键的两个领域做到顶尖 + 跨领域有判断力"。

### 3.2 给正在求职的资深架构师

#### 选 Offer 的 Checklist（30 分钟决策版）

**业务层（40 分）**：
- [ ] 业务有真实的复杂数据问题（不是"为了 AI 而 AI"）
- [ ] 业务规模足够大（日活百万 + / GMV 千万 + / 数据 TB 级）
- [ ] 业务有清晰的护城河（数据资产 / 用户资产 / 网络效应）

**团队层（30 分）**：
- [ ] Leader 愿意培养你（不是"只榨取不培养"）
- [ ] 团队有 5 人以上（含你），且至少有一个 P9 / 总监级 mentor
- [ ] 团队过去 12 个月内有人晋升（不是"死海"）

**成长层（30 分）**：
- [ ] 有 0→1 的项目空间（不是"只维护"）
- [ ] 有跨部门影响力（不是"孤岛"）
- [ ] 有公开表达 / 行业发声的机会（不是"闷头干活"）

**总分 ≥ 70 才值得去**。低于 70 的 offer，再高的 package 也要慎重。

#### 谈薪的三个原则

1. **base + 期权 = 总包，而不是只看 base**。AI 时代的股权 / 期权可能比 base 更重要。
2. **签字费 / 安置费 / 搬家费** 都是可以谈的，不要不好意思开口。
3. **试用期条款**一定要看：试用期内被裁有没有补偿？有没有转正答辩？

#### 面试准备清单

- 准备 3 个深度技术故事（每个能讲 30 分钟）
- 准备 3 个领导力故事（带人 / 跨团队 / 失败复盘）
- 准备 3 个业务故事（业务理解 / 决策贡献 / 业务结果）
- 准备 1 份"作品集"（GitHub / 技术博客 / ADR 文档）

### 3.3 给正在带团队的技术 Leader

#### "5 人团队 → 20 人团队"的管理升级路径

```
单人贡献者（IC）→ Tech Lead（带 3-5 人）
                ↓
Tech Lead      → 架构师（带 5-10 人，跨 2-3 个小组）
                ↓
架构师          → 准资深（带 10-20 人，跨 3-5 个小组，对一个域负责）
                ↓
准资深          → 资深（带 20-50 人，跨 5-10 个小组，对一个 BU 负责）
```

#### 三个"必须"建立的管理体系

| 体系 | 目的 | 关键动作 |
| --- | --- | --- |
| OKR 体系 | 让目标对齐 | 季度 OKR review，月度 check-in |
| 1:1 机制 | 让个体成长 | 每周 30 分钟，听对方说 80% |
| 故障复盘机制 | 让组织学习 | 24 小时内出复盘，5 个 Why，3 个 Action Item |

#### 三个"不要"犯的管理错误

- **不要**把所有决策都自己拍板。要把决策分层：技术细节让 IC 拍，架构决策让架构组拍，业务建议由 Leader 拍。
- **不要**用"加班时长"评估贡献。要用"决策质量 + 业务结果 + 团队成长"评估。
- **不要**把自己当"救火队长"。要把 80% 时间花在"防止着火"（流程、机制、工具、文档）。
