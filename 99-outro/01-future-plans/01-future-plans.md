## 1. 现状与坐标

### 1.1 我们站在哪里

写下这份计划的此刻（2026 年），整个数据栈正处在一次「主轴切换」的临界点上：

- **从"BI 时代"切到"AI 时代"**——过去 15 年我们为"看数据"修路，未来 5-10 年我们要为"AI 用数据"修路。
- **从"集中式数据中台"到"联邦式数据网格"**——中台的边际收益递减，业务域自治成为新的增长曲线。
- **从"SQL Boy"到"Agent Architect"**——LLM 把 80% 的写 SQL、写 ETL、写报表工作自动化，剩下 20% 的"判断与决策"反而更贵。
- **从"经验主义"到"决策智能"**——指标体系从"事后度量"演化为"事前 / 事中决策"，因果推断、强化学习、知识图谱成为新一代基座。

这四条主线相互交织，决定了「未来 3-5 年」不是"做一点增量优化"，而是一次「**角色的整体迁移**」。架构师如果不主动迁移，就会被时代迁移。

### 1.2 三个最大的变化

#### 变化 1：数据架构师的"产品化"义务

过去数据架构师是"修路的"，给业务铺管道；未来数据架构师是"造车的"，要把数据资产封装成**可以被 Agent / 业务 / 合作伙伴直接调用**的产品。

- 指标平台（dbt Semantic Layer / Cube / AloudData）从内部工具升级为 **Agent 可调用的 API**
- 标签体系从"运营分层工具"演化为 **对外可租用的资产**
- 知识图谱从"研究项目"演化为 **客服、风控、销售 Agent 的核心依赖**
- 模型仓库从"算法团队的私产"演化为 **全公司的共享平台**

#### 变化 2：AI 治理成为第一类约束

AI 应用上线不再只是"算法准不准"，而是"**用得对不对、放得稳不稳、出了问题谁来兜底**"。

- 监管侧：欧盟 AI Act、中国《生成式 AI 服务管理办法》、等保 2.0/3.0、信通院 AI 治理框架
- 业务侧：幻觉、偏见、版权、隐私、未成年人保护、跨境数据合规
- 工程侧：模型路由、限流降级、AB 测试、效果回滚、Human-in-the-loop

数据架构师必须把"AI 治理"和"数据治理"放到同等高度，否则会出系统性风险。

#### 变化 3：从"工具选型者"升级为"系统设计者"

过去架构师的价值是「选型 + 集成」，未来架构师的价值是「**设计一个让 AI 与人协同运转的系统**」。

- 这要求你懂业务、懂数据、懂模型、懂组织、懂合规、懂商业
- 这意味着你不再是"最会写代码的人"，而是"最会定义问题的人"
- 这意味着你的影响力来源从"技术深度"扩展到"组织信任 + 业务洞察 + 决策质量"

## 2. 核心洞察

### 2.1 洞察 1：未来 5 年的"主战场"是"AI 原生数据栈"

#### 为什么是 AI 原生数据栈？

传统数据栈是「人用 BI 看数据」，AI 原生数据栈是「**Agent 用 API 调用数据**」。

两者的本质差异：

| 维度 | 传统数据栈 | AI 原生数据栈 |
| --- | --- | --- |
| 使用者 | 人（看报表） | Agent / 人（调 API） |
| 查询方式 | SQL + BI 工具 | 自然语言 + 语义层 |
| 数据形态 | 结构化为主 | 结构化 + 向量 + 文本 + 图 |
| 一致性要求 | "看起来差不多" | "必须严格一致"（幻觉放大一切不一致） |
| 治理重点 | 报表口径 | 语义图谱 + 权限 + 审计 |
| 监控重点 | 查询性能 | 调用成本 + 业务效果 + 合规 |

#### 这意味着什么？

- 你需要掌握 **RAG / 向量检索 / 语义层 / 知识图谱** 这四个新基座
- 你需要把 **数据可调用性（data API-ability）** 当作新的 SLO
- 你需要为 **Agent 友好的元数据 / 文档 / 语义描述** 投入工程资源

### 2.2 洞察 2：架构师的"路径图"从"技术 T 型"升级为"决策 π 型"

#### 过去的 T 型架构师

```
       技术深度（X）
            |
            |
   ----+----+----
        业务广度（Y）
```

#### 未来的 π 型架构师

```
        技术深度（X）
            |
            |
   --+--/--+--\--+--
    业务  |  组织  |
    广度  |  广度  |
   (Y1)   |   (Y2)  |
```

- **X 轴**：技术深度（仍然要保持，AI 让基线能力贬值，所以深度要更稀缺）
- **Y1 轴**：业务广度（理解行业、用户、痛点、价值链）
- **Y2 轴**：组织广度（带人、做事、影响跨团队、推动变革）

三个轴都要够硬，否则架构师会被"业务架构师"或"组织架构师"或"AI 工程师"挤掉生态位。

### 2.3 洞察 3：成长不再靠"经验年限"，而靠"决策密度"

过去经验是"做了多少项目"，未来经验是"**做过多少次高质量决策**"。

- 一次重大选型（流计算 vs 批流一体）
- 一次重大重构（Lambda -> Kappa）
- 一次重大治理（指标口径统一 / ID-Mapping 收敛）
- 一次重大决策（自研 vs 采购 / 集中 vs 联邦）

如果一个 P8 五年只做了"小修小补"，他的五年经验可能只值 P6 的两年经验。

#### 提升决策密度的三个方法

1. **主动承担新领域**：每 18 个月主动跳一次"不熟的方向"
2. **写 ADR / 复盘文档**：把每一次决策显性化，让组织复用
3. **跨团队项目治理委员会**：让自己进入"决策会议室"，而不是"执行工位"
