## 5. 风险与陷阱

「下一步该押哪个方向」上的大多数错误，不是判断失误，而是**判断被跳过了**：提案里写着"用了 LLM""上了 XX 神器"，没有一句能被证伪的话，讨论照样通过。本节把三类陷阱——**过度炒作（Hype Cycle 陷阱）/ 工具崇拜（Tool Worship 陷阱）/ 角色错位（Role Misalignment 陷阱）**——压成一套**当场能问出口的脚本**，加一张**每半年自检一次的表**。

它难在哪一个人性约束上：**批准与拒绝的记账时间是不对称的**。拒绝一个当下最热的方向，成本当月兑现——"你错过了风口"这句话立刻能听到；批准它，成本要等结果出来才清算，而且届时更容易被归因为"技术还不成熟"，而不是"我们当时没算过"。因为两端的反馈周期不同，**默认动作永远是"先上了再说"**，代价不是一次亏钱，而是**判断力被替换成了下注次数**：下注的人不需要判断，只需要运气。脚本唯一的用处，是把那笔被推迟的账提前摆到桌面上。

### 5.1 什么场合用

**触发条件**（三条都能判定真假）：
- 一份提案里全是技术名词，而**"改前多少、改后多少、口径谁定"这三样一样都找不到**。
- 你要在**一个季度内**【经验，随预算周期与评审节奏变】批准一笔不可逆投入：招聘名额、采购合同、数据迁移、对外公开承诺，任意一项。
- 你在给自己做年度复盘，而"要不要继续"的理由只剩"我已经投了一年了"。

三类陷阱是同一台机器的三个出口，认出它长什么样，比记住它的名字有用：

| 陷阱（英文名） | 它长什么样（都是把 A 等同于 B） | 对应脚本 |
| --- | --- | --- |
| 过度炒作（Hype Cycle 陷阱） | 把"用了 LLM"等同于"AI 原生"（其实只是套壳）；把"Demo 能跑"等同于"业务能用"（中间隔着大量工程细节【经验】，随系统所处的合规与数据条件变）；把"开源项目热度"等同于"生产可用" | 第一至第四段 |
| 工具崇拜（Tool Worship 陷阱） | 把"用了 XX 神器"等同于"做出了好架构"；把"工具列表长"等同于"能力强"；把"押注新工具"当作"前瞻性" | 第五至第七段 |
| 角色错位（Role Misalignment 陷阱） | 资深 IC 假装 Leader（技术很强但不愿带人）；Tech Lead 假装架构师（管了几个人但没有跨团队影响力）；架构师假装业务负责人（懂技术不懂业务）；业务负责人假装技术专家（懂业务但假装懂技术） | 第八至第九段 |

前两类的共同点是**把"手段"偷换成"结论"**，所以它们可以用证据检验：问口径、问失败定义、问三年后谁维护，答案会露出破绽。第三类不同——它的每一次具体决策看起来都合理，错位只在时间尺度上显形（哪一类人被组织反复请去解决什么问题），所以它只能靠自己定期比对，无法在单次会议里问出来。

**谁在场**：提案人、能说清业务口径的人、能指出不可改约束（时间 / 人力 / 合规 / 成本）的人——三者缺一，问出来的多半是表态而不是事实。**不适用**：纯探索性调研（无投入、可随时放弃、结论只对内）。对它也上重脚本，代价是没人再愿意提新想法——而你正需要有人在早期提出它。

**用多勤**【经验，随组织的项目节奏与投入规模变】：随立项走的问答每有提案就用一次（不要积到季度末集中评审，那时提案已经各自长了两个月，改小它的成本变高）；第八、九段的自查半年一次，快了这个区间没有足够的信息变化，慢了你的时间分配已经固化到改不动。判断频率是否合适的标志很直接：如果两次自查写下的答案完全一样，说明它该拉长；如果每次都不一样，说明前面那次没有真正落到时间分配上。

三句话判断"这个场合要不要开脚本"：

```text
① 有没有一笔改不回来的投入？（没有 → 不必开）
② 提案人能不能说出改前值？     （不能 → 先补材料，再开会）
③ 输的人会承担什么后果？      （没人承担 → 这不是决策场合，是宣讲场合）
```

三条里只要有一条答"否"，改去 §3 的成长模式里找一个可试错的小动作，比在这里过一遍问句更有效。

### 5.2 脚本骨架（可套用）

```text
〈一次 20–30 分钟的立项或复盘对话【经验，随议题与在场人数变】，逐段推进。每问完一段，先给出你自己那一份答案再等对方〉

第一段｜目的：把技术名词翻译成业务问题（治"用了 LLM = AI 原生"）
    「这个方案要让哪个指标从 {改前值} 变到 {改后值}？改前值取自哪张表、谁的口径？
     这两样说不出来，今天我们就不批——不是不看好，是没法判断。」

第二段｜目的：把投入与回收写在同一行（治"Demo 能跑 = 业务能用"）
    「这笔投入是 {人月 / 采购额}，回收方式写在哪一栏？
     如果 {X 个月} 内没有出现 {某个可观察信号}，我们按什么停止？」

第三段｜目的：逼出可量化的失败指标——三问法的第三问
    「请写下这个项目失败时你会看到什么。不是"效果不好"，而是一个数：
     {指标名 + 阈值 + 从哪里查得到}。写不出来，说明它还没有失败的定义。」

第四段｜目的：小步快跑——切路径、给每一步留出口（治"一口气上生产"）
    「{3 个月} Demo + {3 个月} 试点 + {6 个月} 规模化的节奏合不合适？
     更重要的是：每一段的出口条件分别是什么？{节奏随不可逆程度调整【经验】}」

── 工具崇拜：把"选了什么工具"和"解决了什么问题"拆开 ──

第五段｜目的：问题驱动
    「如果这个工具明天消失，我们手上哪个问题会受影响？
     反过来说：现在哪个问题非它不可、别的组合做不到？」

第六段｜目的：长周期视角
    「{3 年} 后我们还要维护它吗，谁来维护？3 年后还活着的工具，和 1 年后被淘汰的工具，
     是完全不同的两个选择——后者不是便宜，是把迁移成本挪到了未来。{年限随技术迭代速度变【经验】}」

第七段｜目的：回归本质
    「工具换掉之后，业务价值改前多少、改后多少？两个数一样，
     那这是一次技术升级，不是一次架构决策，别按决策的规格给它要资源。」

── 角色错位：这一段只对自己说，用在年度自查里 ──

第八段｜目的：认清自己的生态位，并认出自己正站在哪一格
    「我最近一次被别人请教，是因为 {哪件事}？
     我最近一次否决一个需求，是因为 {什么可被验证的理由}？
     {资深 IC 假装 Leader / Tech Lead 假装架构师 / 架构师假装业务负责人 /
      业务负责人假装技术专家}——我现在站的是其中哪一格？」

第九段｜目的：找到合适的战场 + 持续校准
    「我现在做的事，是在放大我的下一步，还是在贬损我的下一步？
     这个问题每 {6 个月} 问一次，并把当时的答案写到纸上【经验】。」
```

**只有五分钟时**，砍掉其余，只留三句——它们三个分别守住"这是不是一个业务问题""这笔账怎么算""它什么情况下算失败"：

```text
5 分钟版【经验，随你手上已有多少材料变】（三句，顺序不可换）
  1. 「改前 {X}、改后 {Y}，口径谁定？」        ← 答不出就到此为止
  2. 「投 {人月 / 金额}，{X 个月}内看到什么就继续？」 ← 把回收写成可观察信号
  3. 「失败时我查哪个数、阈值是多少？」        ← 没有这一句，前两句会一起失效
```

**顺序不能颠倒**：必须先问口径（第一段）再谈投入（第二段）。先谈钱会把话题变成预算谈判，对方为了拿到预算会把口径做得好看，后面所有的数都失去检验价值；而先确认"改前值取自哪张表、谁认定"，等于先把裁判定下来，之后的每一个数都要落在同一条尺子上。同理，第五至第七段只能用在工具已经进提案之后——在问题还没被描述清楚时问"如果这个工具消失会怎样"，得到的答案一定是"那我们就没有方案了"。

**最常被跳过的是第三段。** 原因不是忘了问，而是**写下停止条件等于提前给自己判负**，而会议现场所有人都在为"立项"出力，没人愿意当那个写下退出条件的人。跳过的后果会顺延到第四段：没有失败定义的路径，只能靠"再给一点时间"延续，预算以沉没成本的形式被锁定——这正是四段路径本该防住的事。

**该带什么材料进来**：① **改前值**及其口径来源（缺了它，对方一句"这是战略性投入，不能只看短期"就能把话题带走）；② 这笔投入的**人月或金额**（缺了它，讨论停在"要不要做"，永远到不了"在什么约束下做"）；③ 一个**先例**——本组织过去同类项目在第几个月出现过什么信号，可以是历史项目，标【经验】；④ 你自己那份答案（每一问都轮到你答）。①和④缺一个，这场对话就会退化成质询。

**第八、九段为什么必须写下来**：不写下来的自查最后会变成"我想过这件事"，而想过的结论会随情绪被重写——你今天认定该押组织影响力，三个月后同一句话会被读成"所以我该多做点内部分享"，两者对时间分配的要求完全不同。写到纸上（哪怕只是一行带日期的记录）之后，下一年你手上才有可比对的对象；要比的不是答案对不对，而是你有没有按当时写下的答案分配时间。

### 5.3 判据：说完之后怎么知道成了

| 判据 | 可观察的反应（对方做了什么 / 说了什么） | 为什么它说明成了 |
| --- | --- | --- |
| 失败被定义出来 | 纪要里出现带日期或数值的"若…则停"句，且提案人把它写进自己的材料 | 退出被当成了提案人的责任，而不是等组织来砍 |
| 比较真的发生过 | 纪要里出现第二条被否决的方案，以及它具体的代价 | 只有一条方案的评审不是评审，是通报 |
| 名词被翻译成口径 | 会上有人把"用了 LLM"改口成"要让 {指标} 从 A 到 B" | 判断有了可证伪的落点，后续才能复盘 |
| 口径来源被追认 | 会后提案人补来"改前值从哪张表、谁认定"的一行字 | 说明这不是为了过关临时编的数 |
| 有人当场反对并留在记录里 | 反对意见被写进纪要，而不是被劝服或"会后单聊" | 会议允许分歧存在，判据才不会被一致同意掩盖 |
| 对自己那一格给出答案 | 年度自查的本子上写着"{我要选的战场}、{我放弃的战场及代价}" | 角色错位只能自己认，写下来才有下一次比对 |
| 三个月后有人回看停止条件 | 有人（含你自己）拿当初那句"若…则停"来对现状 | 脚本进入了运行期，而不是停在会议当天 |
| 提案被改小或被推迟 | 会上有人提出"先做 {更小范围}，到 {时间点} 再看"，并写进了纪要 | 说明判据真的筛掉过东西；一个只会放行的过滤器等于没有过滤器 |
| 否决留下了记录 | 被否的方案连同它的代价进了决策记录，半年后你还检索得到 | 否决是唯一能证明你在做判断、而不是在当通道的动作 |

这张表要在**说完之后当天**用一次，不要留到季度复盘。理由是可观察行为会随时间失去可分辨性：隔一个月再回想"当时他到底是答应了还是在拖"，你只能得到自己的印象，而印象恰恰是这套脚本要防的东西。当天记三行就够：谁写下了停止条件、有没有第二条方案、反对意见有没有进纪要——三行都在，这次对话的产出就成立；缺哪一行，对应的那一段等于没问。

### 5.4 常见失败

| 失败形态 | 症状（怎么发现它） | 机制（为什么这么说会反噬） | 改法 |
| --- | --- | --- | --- |
| 连珠炮式三问 | 对方开始解释，而不是给数；回答越来越短 | 连续追问在三句之内把对话变成答辩，被问的人从"共同判断"切到"防守"模式，只会提供能过关的最小信息 | 一问一停，每问完先说出你自己那份答案，把对称性先建立起来 |
| "战略性投入"挡箭牌 | 你一提回收，对方就说"这是长期布局，不能拿季度口径衡量" | 一旦"战略"成立，任何量化要求都会被重新描述成格局不够，争论从数据转向身份，你必输 | 不争论它是不是战略，只要求"战略的观测信号是什么、在哪个时间点能看见" |
| 提案与自我绑定后无法退出 | 同一个方向连续两个季度被追加资源，理由从"效果"变成"已经投了这么多" | 退出等于承认判断错误，继续投入才是保住面子的动作，于是投入曲线只增不减 | 立项文件里由提案人自己写下停止条件；预先让退出与个人判断脱钩 |
| 只审技术方案，不审角色 | 同类技术提案被否过三次，而你自己的时间分配三年没变过 | 前两类陷阱有外部证据可以检验，角色错位没有：它的代价以"被年轻人超越"这类延迟事件出现，当期没有任何症状 | 把第八、九段变成每年固定一次的自问，并把答案留痕，供下一年比对 |
| 三问法沦为仪式 | 纪要里三问都有答案，但半年内没有任何项目被否、被改小或被延期 | 一个只通过的过滤器不是过滤器，它教给组织的是"形式正确即可"，之后连形式都会被省掉 | 数一次过去两个季度的评审：被否 / 被改小 / 被延期各占多少。一条都没有，判定它没在工作 |
| 拿"别人都上了"当证据 | 论据全是行业趋势与竞对动作，没有一条本组织自己的数 | 这把"同行怎么选"塞进了"不可改约束"那一栏，而它其实只是偏好；讨论随后无法收敛到自己的条件上，只能比谁引用的案例更新 | 把"别人上了"记为一条信息，然后回到第一段，问自己的改前值取自哪张表 |
| 把脚本用来评人 | 有人开始拿三问法问同事或下属，被问的人提前准备答案 | 一旦问句变成考核工具，回答就会优化成能被接受的形态，脚本随即失去信息价值——它衡量的不再是被问的事，而是被问的人 | 把它限定在 5.1 的两个场合：有投入要批、自己在复盘 |

这张表的使用方式与 §3.5 的反模式表一致：先找症状，再看机制，最后才看改法。只看改法的人，会把这张表读成七条注意事项——而它们各自对应的是不同的失败结构，其中"只审技术方案、不审角色"那条，靠任何一次会议都改不掉。

### 5.5 接口

这套脚本吃的是 §3 的判断：3.2 的六个成长模式决定你手上有多少可比较的先例，3.5 的失效分析给出"症状 → 机制 → 修法"的读法（同一张表的写法也建议照它），3.6 的跃迁表则告诉你模式什么时候该换——三问法本身也会过期：当"问出失败定义"这件事不再能筛掉任何提案时，它就该从"审别人的方案"换成"审自己的时间分配"。产出物落在 §4：模板四（大型技术决策记录）的"决定它成立的前提"一栏，就是停止条件在文档里的位置；模板一（年度 OKR）的 KR 是这套问答的验收面；4.6 自检清单里问"你的口径分母写在哪里、由谁认定"，正是第一段那句话的检查方式。再往上一层，§6 的终极思考处理的是这套脚本管不到的部分——那些今天算不出回报、但方向本身成立的事。

### 5.6 小结

这套脚本的成败只取决于一个动作：**在立项文件里由提案人自己写下停止条件**。三类陷阱的结构是同一个——拒绝的成本立刻可见、批准的成本延迟清算——而停止条件是唯一能把两笔账拉回同一时间尺度、并且不需要任何人当场认错的东西。写不出它，三问法就只是把会议拉长了二十分钟。

> 💡 **思考锚点**：翻开你上一次立项或复盘的纪要，按 §5.3 那三行查一遍——谁写下了停止条件、有没有出现第二条被否决的方案、反对意见有没有进纪要？缺的那一行对应 §5.2 里哪一段没问？如果三行都缺，按 §5.1 的第三条自检，那场会其实只是「宣讲场合」，这套脚本根本没开——你下次准备先补哪一行？
