### 1.1 阿里电商"**实时数据质量平台 5+ 年**"（2018-2024）

**背景（Why）**

阿里 2018 年面临**电商数据质量的硬约束**：
- **订单 / 支付 / 库存**——错一个数，**就是赔付级事故**
- **业务自助率提升**——**没人帮业务写数据校验**
- **实时发现**——离线发现太晚，**事故已扩大**

**触发点（What）**

2018 年阿里电商启动**实时数据质量平台**（[阿里 2018]），目标：
- **质量事故 0**
- **业务自助**
- **实时发现**

**详细做法（How）**

阿里电商实时数据质量的**5 大核心组件**：

1. **5 类规则（核心创新）**
   - 关键设计：**完整性 / 一致性 / 准确性 / 时效性 / 唯一性**
   - 关键能力：**全维度质量检查**
   - 关键数字：**5 类规则 100% 覆盖**

2. **实时监控（核心）**
   - 关键设计：**Flink 实时监控 + 告警**
   - 关键能力：**秒级发现**
   - 关键数字：**延迟 < 1 分钟**

3. **业务自助（核心）**
   - 关键设计：**业务方自助配置规则**
   - 关键能力：**数据团队不排队**
   - 关键数字：**自助率 70%+**

4. **质量分（核心）**
   - 关键设计：**每张表 / 字段质量分**
   - 关键能力：**业务可信度**
   - 关键数字：**质量分 0-100**

5. **告警分级（核心创新）**
   - 关键设计：**P0 / P1 / P2 / P3**
   - 关键能力：**告警不疲劳**
   - 关键数字：**P0 自动告警 + 自愈**

**阿里电商实时数据质量关键数字**（[阿里 2018-2024]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **质量事故** | 不可用 | 0 | **∞** |
| **延迟** | 小时级 | < 1 分钟 | **-99.9%** |
| **自助率** | 不可用 | 70%+ | **∞** |
| **5 类规则** | 不可用 | 100% | **∞** |
| **告警疲劳** | 不可用 | 0 | **∞** |
| **质量分** | 不可用 | 100% | **∞** |
| **实时监控** | 不可用 | 100% | **∞** |
| **业务可信** | 不可用 | 100% | **∞** |

**具体数字（How much）**

- 团队规模：阿里电商数据质量团队 100+ 人
- 关键数字：**5 类规则**；**延迟 < 1 分钟**；**质量事故 0**
- 业务影响：覆盖**阿里电商全集团**

**失败教训**

- 早期「**质量事故频发**」——倒逼实时质量平台
- **规则过严**——误报太多，**业务方不信**；后调阈值
- **告警疲劳**——告警太多无人看，**后加告警分级**
