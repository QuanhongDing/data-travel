## 5. 前沿演进（AI 时代）

### 5.1 先分清三类「前沿」

本节要解的第一个问题不是「隐私计算能不能用在 AI 上」，而是**保护对象换了没有**。把"样本对齐后只交换加密中间量"（本章 [§3.1](08-privacy-computing-section-3-sec3.md) 的纵向联邦模式，金融联合风控已经跑了很多年）与"联邦训练一个大模型"（本节核到的是项目方材料与研究论文）并列写成"演进方向"，读者会误以为后者只是前者的规模放大。它们不是同一件事：前者的成本随**参与方数量与样本量**增长，后者的成本随**参数量 × 通信轮次**增长，量级截然不同。本章 [§1.3](08-privacy-computing.md) 已经把 AI 时代的五个协同点写清楚了（跨域 AI 训练、机密 LLM 推理、RAG 隐私保护、Agent 跨域协作、差分隐私训练），本节要做的是给这五个点加时间刻度与代价。

判断一个方向能不能落地，本节用 L1 / L2 / L3 三级区分，判据必须是可核验的三条：**① 已 GA 且有正式 release note；② 有第三方（非厂商）公开生产案例；③ 接口稳定**。**三条全中才算 L1**，可以排进路线图；只满足一部分、或只有厂商 / 项目方自有案例的算 **L2**，可做 PoC、不要作为核心依赖；只有路线图 / 论文 / 演示的算 **L3**，记录即可、不要在架构里预留假设。

**判据声明（本主题对三条 L1 判据做的修正，5.1 与 5.2 两处完全一致）**：第②条在本主题上是**系统性不可得**的——隐私计算的落地细节天然涉及参与方身份与数据边界，公开材料通常只到"某机构做了某场景"，不会给出可复核的口径与规模（见 §5.4）。对**非 AI 的既有能力与原语**这一类行（即下表里标注"非 AI 能力"的那三行：跨机构协作原语、差分隐私训练原语、处理位置前移），本节把第②条替换为：**有多家彼此独立的组织分别实现或部署过该能力，且有可被第三方复核的机制性材料（协议规范 / 安全性分析 / 公开论文）**；这三行的①③仍按原样核（读者要能点到正式发布条目，并说清接口为什么是稳的）。理由是隐私计算的有效证据形态是**机制性证据**（协议的安全性、预算记账的正确性、证明的可验证性），而不是运行指标。修正**只对"非 AI 能力"这一类行生效，不覆盖任何 AI 能力方向**；凡 AI 能力方向一律按原三条判据，**因此下表里没有任何一条 AI 能力方向到 L1**——这是本节最重要的一句话。

写这一节时最容易混的四件事，先在这里分开：

- **产品名 vs 能力名**："机密 LLM 推理""RAG + TEE""FedLLM"都是**能力名**；对应的产品（各家云厂商的机密计算产品、各开源项目的 LLM 模块）命名各不相同。凡看到"某平台支持机密推理"，先问它保护的是**输入**、**权重**、还是两者。
- **已发布版本 vs 路线图**：判断某个隐私计算能力是否真的可用，只看一处——**该版本的 release note 或官方文档里有没有对应条目**；项目官网的路线图、生态伙伴的转述、演示视频都不算（§5.4 给了本主题具体例子）。
- **论文里的原型 vs 产品里的实现**：DP-Prompt、密文近似检索（ANN）、联邦大模型训练在本主题里都有论文原型；能否在生产里开箱使用是另一回事。判定方法：看官方文档里该能力有没有**配额、计费、SLA** 三项。
- **隐私保护 vs 合规通过**：隐私计算改变的是"谁能在什么条件下看到明文"这一环，**不自动回答**目的限定、留存期限与可举证；把技术隔离当成合规结论，是本主题最常见的一处越位。

本节对每个方向都问同一句：**AI 到底改变了哪个机制**——改变了成本结构、改变了接口边界、把人工判断换成统计判断，还是只换了个前端？本主题的答案分两层，**这两层在 §5.1 与 §5.2 里写法完全一致**。**第一层：AI 真正改变的机制只有一条——保护对象的边界**：敏感物从"数据集"扩展到 prompt 与权重、梯度与训练过程、检索结果（§5.2.1、§5.2.2、§5.2.3 依次对应这三类）；联邦训练与差分隐私的**数学没有变**（(ε, δ) 的定义与 DP-SGD 的算法在 AI 之前就定型），变的是它被套在什么对象上。**第二层：同一条边界落在哪一层，四个方向各不相同**——§5.2.1 落在**信任假设**上（可远程验证的硬件声明替代了"我们不会看"这句承诺）、§5.2.2 落在**被保护对象本身**（从统计发布扩到训练过程）、§5.2.3 落在**接口边界**上（出现只能查询、不能打包控制的出口）、§5.2.4 落在**架构层**（处理位置从服务端前移到设备本地，是既有架构属性的复用，**不是 AI 新造的机制**）。这两层分法不是文字游戏：**它决定了一个方向能不能靠"加一层库"落地**——把这条边界落到架构层（处理位置）与接口层（出口审计）的，接入后立刻改变风险；只把旧机制套到新对象上、落点仍在服务端的，先要付的是效用与成本。

| 演进方向 | 级别 | 判据（可核验） | 现在该做什么 |
| --- | :---: | --- | --- |
| 跨机构协作原语层（PSI 隐私求交 / 秘密分享 / 纵向联邦协议） | **L1**（非 AI 能力） | 按 §5.1 判据声明：是密码学原语而非产品特性，多家彼此独立的组织分别实现（FATE / SecretFlow 等），协议规范与安全性分析可复核（§5.4）；①③：两个项目的官方 Releases 页给出正式版本条目（FATE 的条目可回溯到 2019 年的 1.0，见本章 [§1.4](08-privacy-computing.md)），原语的接口面由协议规范固定，没有需要长期兼容的产品接口（对应判据①与③） | 排进路线图；先做样本对齐，再谈建模 |
| 差分隐私训练原语（DP-SGD + 隐私预算记账） | **L1**（非 AI 能力） | 同上：有正式论文（CCS 2016）与多个彼此独立的实现库，机制与记账方式可复核（§5.4）；①③：实现库（Opacus / TensorFlow Privacy）各有正式发布页与版本化的文档，隐私预算记账的接口由库版本固定（对应判据①与③） | 先把 ε 口径立起来；没有口径的"差分隐私"不算保证 |
| 处理位置前移（端侧先处理 + 本地差分隐私） | **L1**（非 AI 能力） | 按 §5.1 判据声明：本地差分隐私有**多家彼此独立的组织**的公开部署与机制材料——Apple "Learning with Privacy at Scale"（Apple Machine Learning Journal, 2017）、Google "RAPPOR"（CCS 2014）、Microsoft "Collecting Telemetry Data Privately"（NeurIPS 2017）；端侧先处理是架构决定而非 API，没有需要长期兼容的接口面（对应判据①与③）。**出处见 §5.4 第三方生产案例** | 先判上收必要性，再谈加噪档位 |
| 机密 LLM 推理（TEE + 远程证明） | **L2** | 底层隔离（机密 VM / 机密容器 / 远程证明）有正式发布条目；但端到端机密推理的算子覆盖、证明粒度无通行做法，②核不到 | 可做 PoC；**不要把它当合规结论** |
| 联邦 LLM 训练（FedLLM / FATE-LLM / SecretFlow-LLM） | **L3** | 只有项目方材料与研究论文；"参与方数量 × 模型规模 × 通信量"的组合无公开对照材料 | 记录；先算出通信量再谈可行性 |
| 差分隐私 LLM 微调与提示（DP-Fine-Tuning / DP-Prompt） | **L3** | 论文为主；公开材料里缺少"ε 与效果损失"的成对口径 | 记录；若要试，先定 ε 与效果损失的度量方式 |
| RAG + 隐私计算（TEE / FL / MPC / DP） | **L2**（TEE 内的检索与推理）/ **L3**（密文检索、检索结果加噪、联邦索引） | TEE 侧有产品化条目（同 §5.2.1）；密文 ANN 检索与检索结果加噪仍以论文为主，接口不稳 | 先做**出口审计与查询预算**，再谈密文检索 |
| GraphRAG + 隐私计算（TEE / FL / DP） | **L3** | 双重未知：图检索本身仍在演进，叠加隐私层后无任何可核验落地材料 | 记录；不要在架构里预留 |
| 同态加密实用化 | **L3**（作为通用方向） | 通用 FHE 的开销条件无公开生产对照材料；其中"加法同态 / 秘密分享"这类密文计算不是新方向，属本表第 1 行的原语层 | 只在特定函数上用；先看参数与计算深度条件 |
| 数据要素流通技术成熟、隐私计算 + 区块链 | **L3**（"成熟"这一断言） | 两者都是**制度与存证问题**，判定入口是试点规则与交易所的公开规则，不是技术发布条目；**与 AI 无因果关系** | 先划参与方与责任；不要先上链 |

> 表里出现的 L1 全部是既有能力或既有原语：第 1、2、3 行分别是样本对齐（PSI）、差分隐私预算记账与处理位置前移（第 9 行提到的"加法同态 / 秘密分享"这类密文计算属于第 1 行的原语层，不是独立的新 L1）。**没有一条 L1 是 AI 能力方向**——**AI 能力方向里最高只到 L2**（机密 LLM 推理、RAG 的 TEE 侧）。其余方向卡住的原因各不相同：联邦 LLM 训练卡在成本结构（参数量 × 轮次）；DP-LLM 卡在"效用与 ε 的公开兑换率"；GraphRAG 的隐私层卡在双重未知；数据要素与区块链卡在**它们根本不是技术能力问题**。

**这三级的排法直接决定路线图的顺序**：

- **先做的三条（就是上表前三个非 AI 的 L1）**：样本对齐（PSI）→ 隐私预算口径（ε / δ 与记账）→ 处理位置前移（能端侧闭环就不上收）。它们排在所有 AI 方向之前，因为**后面每一个 AI 方向的宣称都要靠这三件事才能被复核**：没有样本对齐就没有"不泄露交集"的说法，没有 ε 口径就没有"差分隐私"的说法，没有处理位置就没有"数据不出设备"的说法。
- **L2 做 PoC，并先测两个数**：机密推理的**开销比**（同一负载在 enclave 内外的耗时与吞吐之比）；RAG 出口的**访问画像**（谁在什么时候查了多少、被拒多少）。这两个数拿不出来，L2 就停在原地。
- **L3 不排进排期**：联邦 LLM 训练、DP-LLM 微调、密文检索、GraphRAG 的隐私层都属于"等信号"。它们的共同前提（通信量可接受、效用损失可量化、检索接口可约束）比选哪家框架重要得多。
- **回填机制**：每次协作项目复盘时回填一次级别；某个 L2 若一年内仍拿不到自己组织里的实测数字，降 L3 并停止投入。

### 5.2 演进方向逐条拆解（核心节）

下面四个方向按同一套结构写：**旧做法卡在哪 → AI 改变了什么机制 → 由此得到什么 → 由此付出什么 → 证据与来源 → 成熟度**。四个方向共用 §5.1 里的**同一条机制（保护对象的边界）**，差别在**它落在哪一层**——下表第三列就是各自的分层（§5.1 表里那条标"非 AI 能力"的处理位置行，就是落在架构层的那一个方向）。只写收益不写代价的方向，在评审时应被直接打回——本主题里每一次"隐私变强"，都对应一处新的成本、新的信任假设或新的效用损失。

| 方向 | AI 改变了什么机制 | 这条边界落在哪一层 |
| --- | --- | --- |
| §5.2.1 机密 LLM 推理 | 信任锚从"信任运营方"换成"可远程验证的硬件声明" | **信任假设**（可验证替代了承诺；新增的被保护对象是 prompt 与权重） |
| §5.2.2 联邦 / 差分隐私 LLM 训练 | 被保护对象从"统计发布"扩展到"训练过程" | **被保护对象本身**（数学保证没变，变的是它被套在什么对象上） |
| §5.2.3 RAG / GraphRAG 的隐私保护 | 泄漏面从"数据集被拷贝"变成"检索接口被反复询问" | **接口边界**（出现了只能查询、不能打包控制的出口） |
| §5.2.4 端侧先处理与同组方向 | 处理位置从服务端前移到设备本地 | **架构层**（不是模型能力，也不是 AI 新造的机制——既有架构属性的复用） |

读法建议：如果时间只够读一节，读 §5.2.3——"检索接口是数据出口"这件事在 AI 之前不被当作隐私问题，而它恰恰是本节里唯一一条**新增的、且今天就存在于你系统里**的风险；§5.2.1 的收益要等你愿意把信任假设写进合规材料时才兑现；§5.2.2 与 §5.2.4 里真正能落地的部分，一个是原语（DP 预算），一个是位置（端侧）。

#### 5.2.1 机密 LLM 推理：把信任锚从"运营方"换成"可验证的硬件声明"

- **旧做法与它的卡点**：要让模型推理不泄露用户输入，旧路只有两条——不出来（私有部署，自己承担全部运维与算力）、或签合同（把信任交给服务方）。卡点是**信任不可验证**：你能得到的只有"我们不会看"这句承诺，而合规要回答的是"谁在什么条件下能看到明文"（本章 [§1.2](08-privacy-computing.md) 把这一点写成"合规阻碍业务"与"机密泄露担忧"）。
- **AI 改变了什么机制**：**信任锚的落点变了**——从"信任组织"换成"信任硬件 + 可远程验证的声明"。这是真正的机制变化：过去只能靠合同约束的东西，第一次有了可被第三方复核的技术凭据（远程证明给出可校验的度量）。它也解释了为什么这条方向与"更聪明的模型"无关：**模型再强也不会让运营方变得可信**，能改变这点的只有证明。
- **由此得到的**：**因为存在可远程验证的执行环境声明，所以"数据出域但计算过程隔离"第一次可以写进合规与采购材料**——不是"我们保证不看"，而是"设备签名的证明说这台机器跑的是这个镜像"。同一机制还能保护权重：模型方不必把权重交给调用方，调用方也不必把明文交给模型方（两侧同时受约束，这是本章 [§1.3](08-privacy-computing.md) 里"机密 LLM 推理"这一协同点的新意所在）。

| 要保护什么 | 掩护手段 | 掩护不了的 |
| --- | --- | --- |
| 用户输入（prompt / 上下文） | 推理在 enclave 内 + 不落盘不记日志 | 输入本身被模型记住并复述（这是模型行为问题，不是隔离问题） |
| 模型权重 | 权重只在 enclave 内解密 | 权重被推理过程间接推断（输出可用于蒸馏） |
| 推理过程与中间态 | 显存加密 + 证明度量覆盖运行时 | 侧信道与微架构类攻击（见"由此付出的"第一条） |

- **由此付出的**：**其一，信任只是转移，不是消失**——威胁模型从"服务方违规"换成"厂商固件与微架构的漏洞、以及密钥管理"，而这一类攻击是被持续公开的（2018 年前后起，针对 SGX 的瞬态执行类攻击如 Foreshadow 被陆续公开）。所以"用 TEE 就不用信人"是错的说法，正确的是"从信运营方变成信硬件厂商 + 证明流程"。**其二，性能与可移植性有代价**：enclave 内的算子覆盖、显存加密带来的带宽影响、I/O 路径长短都会改变吞吐，**具体幅度必须以你自己负载的基准为准**——本节不给数字，因为公开的性能声称几乎都缺条件限定（数据量、序列长度、批次、硬件）。**其三，合规口径并未自动认可**：技术隔离回答的是"谁能看到明文"，回答不了目的限定、留存期限与可举证；把证明当成合规结论，是本主题最容易踩的一处越位。
- **证据与来源**：【公开】各云厂商的机密虚拟机 / 机密容器 / 远程证明是正式产品条目并有公开文档（判定入口：看官方文档里该能力是 GA 还是预览，以及**证明里测量的是镜像还是整机**）；【本节未能核到】"因为用了机密推理，某机构的合规结论因此改变"的第三方可核验材料。**"某年某月某厂商 GA"的精确时点，本节无法核验，一律改为判定入口**（§5.4）。
- **成熟度**：**L2**。判据：①③ 在底层隔离层成立（正式条目、接口稳定），但端到端机密推理（算子覆盖、证明粒度、编排方式）无通行做法，②核不到 → 做 PoC，不要作为核心依赖，也不要拿它当合规结论。
- **判定方法**：用厂商的证明工具跑一次，看证明里能不能读出"镜像哈希 / 启动配置 / 是否 debug 模式"；读不出来，说明隔离边界比你想象的小。再测一次开销比（enclave 内外同负载的耗时与吞吐之比），这个数决定它能不能进你的在线链路。
- **什么时候值得做**：你确实需要把受监管数据交给外部模型、或需要把模型交给外部调用方，且能接受"专用实例 + 专用密钥 + 单租户"的形态时。
- **什么时候不值得做**：如果你的数据本来就允许出域、只需要约定不留存，那么先做**合同与访问审计**更划算；先上 TEE 会把运维复杂度提上去，而合规问题一个也没解决。

#### 5.2.2 联邦 LLM 训练与差分隐私 LLM：保护对象换了，成本结构没换

- **旧做法与它的卡点**：跨机构要联合建模，联邦学习（本章 [§3.1](08-privacy-computing-section-3-sec3.md) 的模式 1 / 模式 2）在中小模型上是可行的：各方本地训练、只交换加密中间量（梯度、拆分份额、聚合统计），纵向联邦的树模型（如 SecureBoost 一类）在联合风控里已经跑了很多年。搬到大模型上，卡点不在密码学，而在**成本结构**：通信量随"参与方数量 × 参数量 × 训练轮次"增长，而后者在 LLM 上是十亿到千亿级参数——**收益（数据不出域）没变，代价变了一个量级**。
- **AI 改变了什么机制**：**换了被保护对象，没有换隐私机制**。差分隐私的形式化定义（ε, δ）在 2006 年就已定型，DP-SGD（2016）做的事是把它接进训练循环：逐样本梯度裁剪 + 加噪 + 预算记账。LLM 改变的是**被保护对象的位置**——过去保护的是"发布出去的统计结果"，现在要保护的是"训练过程本身"，因为有研究证明**梯度与更新量本身就是泄漏面**（Deep Leakage from Gradients, NeurIPS 2019；成员推断攻击更早，见 IEEE S&P 2017）。这就是为什么本章 [§3.3](08-privacy-computing-section-3-sec3.md) 的反模式清单里，"FL 模型效果等同明文"与"忽视差分隐私"要分开写：**FL 解决的是数据放置，不提供隐私度量**。
- **由此得到的**：**因为保护对象第一次包含训练过程，所以跨域训练第一次有了可陈述的隐私参数**（ε），而不是"我们只交换梯度"这种定性说法。这条收益是硬的：ε 可以被写进合同与合规材料、可以被审计、也可以在两次训练之间比较——这是联邦训练从"技术方案"走向"可评估方案"的分界。
- **由此付出的**：**其一，效用与 ε 的兑换率是硬的**——ε 收紧，效果下降；而要对大模型做 DP-SGD，逐样本梯度裁剪 + 加噪还会显著抬高单步成本，于是"隐私代价"与"训练成本"叠在一起。**其二，联邦的收益与通信成本同时放大**——参与方越多、模型越大，同步瓶颈越重；参数高效微调（只交换适配器更新）能把可行性拉回来一点，但它同时把"联邦训练"缩成了"联邦适配"，这个问题必须在方案里讲清楚，否则验收时会打架。**其三，预算记账必须可信**——ε 是一个累计量，记账实现错了，等于宣称的保证不成立；不同库的记账方式存在差异，验收时要看的是**记账实现在你这条链路上是否被独立复核过**，而不是文档里的建议值。

| 路线 | 成本随什么增长 | 在 LLM 规模上的后果 |
| --- | --- | --- |
| 纵向联邦（PSI + 树模型，本章 [§3.1](08-privacy-computing-section-3-sec3.md) 模式 2） | 样本量、特征数、参与方数 | 与参数量无关，因此在 LLM 时代**仍然是可用的那一条**（它换的是特征，不是大模型） |
| 横向联邦 + 全参数训练 | 参数量 × 通信轮次 × 参与方数 | 通信量按参数量放大，量级跃迁；同构数据也未必存在 |
| 横向联邦 + 参数高效微调 | 适配器参数量 × 轮次 × 参与方数 | 可行得多，但接受"只适配"的定位，别按"训练大模型"立项 |
| DP-SGD（任意规模） | 训练步数 × 批大小（逐样本裁剪 + 噪声 + 记账） | 单步成本显著上升，且 ε 与效果损失的兑换率必须自己测 |

这张表的读法是**看成本量纲**，不是看技术先进性：**只有第一行与参数量无关**，所以"跨机构 + 大模型"这个组合在今天的可行解，通常落在第一行或第三行，而不是第二行。
- **证据与来源**：【公开】DP-SGD 有正式论文与多个彼此独立的实现库（判定入口：查论文页与各库的隐私预算记账文档）；【公开】联邦框架 FATE 与 SecretFlow 是两家彼此独立的组织的开源项目（判定入口：各项目的官方仓库与发布说明；**本章 [§6](08-privacy-computing-section-6-sec6.md) 的案例标到"机构名 + 年份区间"，没有可检索的文档名，因此只作对照、不作本行证据**）。**【本节未能核到】"联邦或 DP 训练的大模型在公开口径下的规模、通信量与效果损失"的对照材料**——FedLLM / FATE-LLM / SecretFlow-LLM 的具体形态与版本，以各项目官方文档为准。
- **成熟度**：**L1（DP 训练原语，非 AI 方向）**——按 §5.1 判据声明判定；**L3（联邦 LLM 训练、DP-LLM 微调与 DP-Prompt）**——只有项目方材料与论文，且缺"ε ↔ 效果"的成对口径。
- **判定方法**：先把通信量算出来（参数量 × 轮次 × 参与方数 × 每参数字节），再问这个数在你网络条件下需要多久；同时把 ε 与目标效果损失写成一对可验收的数。**两个数里任何一个算不出来，这个方向就还停在 L3。**
- **什么时候值得做**：参与方少（个位数）、模型可以做到参数高效、且监管要求必须给出可陈述的隐私参数（ε）时。这三个条件同时满足的场景真实存在，但比宣传里的少得多。
- **什么时候不值得做**：参与方多、模型要全参数训练、或你的真实约束只是"数据不能出域"（那就该回到 PSI + 纵向联邦，而不是上联邦大模型）。

#### 5.2.3 RAG / GraphRAG 的隐私保护：检索接口本身就是一个数据出口

- **旧做法与它的卡点**：把语料放进检索库，靠"只让有权限的人查"来控制。卡点是**出口的性质变了**：top-k 检索是被反复调用的预言机——多查几次、换着措辞问，可以把不该看的内容一片片拼出来；而检索结果一旦进了外部模型的上下文，数据就已经出域了。传统系统的权限控制假设"数据以文件或表为单位被访问"，而检索是**以片段为单位、按查询节奏**被访问的。
- **AI 改变了什么机制**：**泄漏面的形状变了**——从"数据集被拷贝"变成"检索接口被反复询问"。这不是"多了一个组件"，而是**出现了一个只能查询、不能打包控制的出口**：你可以对一张表授权，但很难对"第 3 次查询返回的第 5 个片段"授权。GraphRAG 把出口从文本块扩展到实体与关系，泄漏面的维度更多（实体之间的关系本身就是敏感信息）。
- **由此得到的**：**因为出口是"查询"而不是"文件"，所以访问控制第一次必须是"预算 + 审计"型的**——限次、限范围、逐次留痕，而不是一次授权长期有效。这条结论今天就能落，而且不依赖任何隐私计算技术：先把出口的访问画像建起来，才谈得上后面选 TEE 还是密文检索。

```text
        同一份语料，两种被拿走的方式（差别在出口的粒度）
        ────────────────────────────────────────────────
        ✗ 以文件 / 表为单位的控制（传统权限模型）
          能授权的对象：这张表 / 这个目录 / 这个文档
          实际发生的访问：片段级、按查询节奏
          → 每次查询都"合法"，拼起来越界
        ✓ 以出口为对象的控制（检索出口审计）
          查询预算：谁 / 每天多少次 / 能返回多少条
          范围约束：密级过滤放在「召回前」，不是「返回前」
          逐次留痕：查询串 + 返回的片段 id（可回溯"谁看过什么"）
          成员推断评测：用自己的语料跑一次"能否从返回里认回个体"
        ────────────────────────────────────────────────
        判定方法：数两周内"同一条内容被不同查询拼出来"的次数
        ——这个数不为零，说明出口还没有被当成一个出口来管
```

| 出口 | 保护手段 | 代价 | 现状 |
| --- | --- | --- | --- |
| 检索服务本身 | 放在 TEE 里，索引与查询都不过运营方 | 运维复杂、算子覆盖受限、需要证明流程 | L2 |
| 检索内容（ANN） | 密文检索（MPC）| 近似检索的密文实现在开销上远重于明文；接口不支持通用 ANN | L3 |
| 检索结果 | 加噪（DP）或只返回聚合 | 召回质量下降；下降会以"模型答错"的形式出现，归因难 | L3 |
| 多机构索引 | 联邦索引（FL，FedRAG 类） | 索引的更新频率与一致性问题；多一层的对齐成本 | L3 |
| 知识图谱 | 图放在 TEE / 联邦图谱 / 输出加噪 | 同上，且图检索本身仍在演进 | L3 |

- **由此付出的**：**其一，检索进上下文之后就收不回来**——一旦 top-k 进了外部模型，后续只能靠合同与"不留存"承诺，技术手段到此为止；所以真正要防的是"不该出的片段被检索出来"，而不是"检索出来之后再保护"。**其二，加隐私层会让检索质量下降**，而质量下降会以"模型答错、且答得很自信"的形式出现——这比传统系统里"查不到"更难归因。**其三，权限过滤放在召回前还是召回后，是一个显式设计决定**：放在召回后意味着敏感片段已经进了内存与日志，等于只做了展示层的控制。
- **证据与来源**：【公开】TEE 内的检索与推理有产品化条目（同 §5.2.1 的判定入口）；**【本节未能核到】"密文 ANN 检索在生产规模下的吞吐与召回"的第三方材料**，也未能核到"检索出口审计（查询预算 / 访问画像）被产品化为正式条目"的公开材料。
- **成熟度**：**L2（把检索与推理放在 TEE 里）/ L3（密文检索、检索结果加噪、联邦索引、GraphRAG 的隐私层）**。判据：TEE 侧第①③条在底层成立；密文检索与加噪侧三者都不成立。
- **判定方法**：数两周的检索日志——**同一条内容被不同查询"拼"出来的次数**，以及被权限拒绝的次数。前一个数不为零，说明你的出口审计还没建立。
- **什么时候值得做**：你的检索库里混着不同密级的内容、且有外部模型参与时。**先做出口审计与查询预算**，这两件事的成本远低于任何隐私计算方案。
- **什么时候不值得做**：在检索粒度的权限控制（行 / 列 / 文档级）都还没做之前谈密文检索——那等于给一个还在漏的桶换更好的盖子。

#### 5.2.4 端侧先处理，以及被 AI 带起来的四条方向

**端侧先处理（可落地部分）**

- **旧做法与它的卡点**：服务端收集原始数据、再脱敏。卡点是**不可逆**：原始数据已经在服务方存在过，脱敏只改变了后续的使用方式，改不了"曾经存在"这个事实（这是本章 [§1.2](08-privacy-computing.md) 的合规与用户认知双重压力）。
- **AI 改变了什么机制**：**落点在架构层——改的是处理位置，不是模型能力**（对照 §5.1 的两层写法：机制仍是"保护对象的边界"，这里变的是它落在哪一层）：原始数据在设备本地完成特征提取或加噪后才上传，隐私保证与"服务端是否可信"解耦。同时端侧学习（模型下发、更新量上传）让"不上收数据"与"模型可迭代"第一次同时成立，这是 AI 带来了新工作负载之后才出现的组合——**但"端侧处理 + 本地加噪"这套机制在 AI 之前就存在，这正是它判 L1（非 AI 能力）、不计入 AI 能力方向的原因**。
- **由此得到的**：**因为保证不再依赖服务端可信，所以"服务端被攻破"的后果被大幅削弱**——这一条不靠密码学、不靠硬件，靠的是"数据根本没上去"，成本最低、争议最小。
- **由此付出的**：**其一，端侧算力与版本碎片**——设备能力参差、端侧逻辑发不出去就改不动；**其二，加噪的效用代价必须按用途分档**——一刀切收紧会让数据几乎不可用（本书 [§6](08-privacy-computing-section-6-sec6.md) 的这一类案例里，"预算按用途分档 + 效果回归"是两个必备动作）；**其三，上收必要性要有人判**——"能收就收"的习惯会在压力下回来，所以必要性判定要写进流程而不是靠自觉。
- **证据与来源**：【公开】本地差分隐私与端侧先处理在操作系统级遥测里有**多家彼此独立**的公开部署与机制材料——Apple "Learning with Privacy at Scale"（Apple Machine Learning Journal, 2017）、Google "RAPPOR"（CCS 2014）、Microsoft "Collecting Telemetry Data Privately"（NeurIPS 2017），三家都公开了端侧加噪的机制与预算（ε）的设定方式（§5.4 第三方生产案例）；**本章 [§6](08-privacy-computing-section-6-sec6.md) 的端侧案例是同一套做法的一份自述材料，标注到机构名 + 年份区间、无可检索文档名，故只作对照、不作证据**。【经验】具体的 ε 档位必须在自有数据上做效果回归确定，**没有通用值**，本节不给数字。
- **成熟度**：**L1（既有生产能力，非 AI 方向）**。判据（按 §5.1 判据声明）：①端侧加噪与端侧先处理是已 GA 的既有能力；②有多家彼此独立的组织分别部署过，且有公开的机制材料（Apple 2017 / Google RAPPOR 2014 / Microsoft NeurIPS 2017，出处见 §5.4）；③它是架构决定而不是要调的 API，没有需要长期兼容的接口面，因此可以直接排进路线图。

同组还有四条方向（连同上面的端侧先处理，这个组合共五条），它们都被写进了"AI 时代的隐私计算"，但机制与 AI 无关：

| 方向 | 旧做法与卡点 | AI 改变了什么机制 | 由此得到 | 由此付出 | 证据 / 成熟度 |
| --- | --- | --- | --- | --- | --- |
| 同态加密实用化 | 密文上算不了复杂函数，得先解密 | **没有改变机制**：FHE 的开销来自密文膨胀与自举，与模型无关；AI 只是在概念上让"密文下的简单函数"有了新用法 | （若成熟）统计与部分推理可在密文上完成 | 参数与计算深度决定一切，"能算"与"可用"之间隔着数量级；**要写清多项式深度与吞吐条件** | 判定入口：看公开材料给的是参数组合还是场景口号 → **L3（通用方向）**，特定函数的密文计算属原语层 |
| 数据要素流通 | 数据不能跨机构流通，只能靠合同与个案谈判 | **与 AI 无因果关系**：它改的是制度与责任划分 | 若规则稳定，跨机构协作的**责任与收益分配**第一次有依据 | 规则本身在演进；合规解释成本落在法务与安全，不在技术 | 判定入口：试点与交易所的公开规则 → **L3（"成熟"这一断言）** |
| 隐私计算 + 区块链 | 协作过程难以自证"谁在什么时候做了什么" | **机制正交**：区块链给的是存证与不可篡改，隐私计算给的是"看不到明文" | 协作过程的存证可被第三方核对 | 上链不产生新的隐私保证，只增加一条运营与运维面（密钥、节点、治理） | 无公开可核验落地材料 → **L3** |
| 隐私计算 + AI 治理融合 | 隐私与合规分开管，材料各写一套 | **与 AI 无因果关系**，但被 AI 的合规压力加速 | 一套材料同时回答"数据怎么用"与"看不到什么" | "AI 治理 = 合规 + 隐私"是简化：治理还要问数据来源、标注、模型行为，隐私计算一条都答不了 | 【公开】合规要求真实存在（本章 [§1.2](08-privacy-computing.md)）→ **L2（要求）/ L3（等式）** |

**这五条方向（上面的端侧先处理 + 上表四条）的共同读法**：收益都真实存在，但**没有一条的收益来自模型**——两条来自架构（处理位置、存证），一条来自密码学的参数条件（HE），两条来自制度（数据要素、AI 治理）。把它们写成"AI 时代的隐私计算演进"，会让真正要做的三件事（判上收必要性、划参与方责任、算清参数条件）一件都排不进排期。

### 5.3 与本主题既有栈的接口在哪

隐私计算与 AI 之间不是"结合"关系，而是**交接物**关系：谁把什么交给谁、失败时谁负责。这张表比"能不能用"更能决定它能不能落地。

| 结合点 | 接口形态 | 谁负责失败 | 现状 |
| --- | --- | --- | --- |
| 隐私计算 ↔ 数据安全（[../02-data-security](../02-data-security/02-data-security.md)） | 交接物 = 分类分级结果与脱敏策略；**先分级，才能定哪类数据必须走不出域路线** | 安全侧定级、隐私计算侧实现；定级错了，后面所有技术选择都白做 | L1（机制）/ L2（跨机构的分级口径一致性） |
| 隐私计算 ↔ 目录与血缘（[../../04-data-assetization/08](../../04-data-assetization/08-data-catalog/08-data-catalog.md)、[../05-lineage-and-impact](../05-lineage-and-impact/05-lineage-and-impact.md)） | 交接物 = 字段级敏感标注与访问策略；参与方要知道哪些字段必须留在本地 | 目录侧（标注缺失时，隐私计算方案按什么字段出域？） | L1（机制）/ L2（跨机构标注口径） |
| 隐私计算 ↔ 调度与编排（[../../03-data-stack/12](../../03-data-stack/12-scheduler/12-scheduler-section-3-sec3.md)） | 交接物 = 协作任务的编排与参与方身份（PKI）；**失败时不能单方面重跑** | 平台侧；一方重跑而另一方没重跑，是协作链路上最常见的静默错误 | L2（跨机构重放语义无通行做法） |
| 隐私计算 ↔ 审计与合规（[../07-audit-and-compliance](../07-audit-and-compliance/07-audit-and-compliance.md)） | 交接物 = 可陈述的隐私参数（ε / 参与方 / 协议 / 证明摘要） | 合规与安全联合；**参数不可陈述时，技术隔离无法被写进材料** | L1（材料形态）/ L2（跨机构互认） |
| 隐私计算 ↔ 可观测（[../04-observability](../04-observability/04-observability.md)） | 交接物 = 协作链路指标（参与方等待时长、通信量、enclave 内耗时）；**不看这些就看不出瓶颈在哪一方** | 平台侧；只看业务结果不看链路指标，会把"某一方慢"误判成"方案不可行" | L2 |
| 隐私计算 ↔ 模型服务（[../../04-data-assetization/05-rag-architecture](../../04-data-assetization/05-rag-architecture/05-rag-architecture.md)） | 交接物 = 模型制品 + 证明摘要（谁签的、跑的哪个镜像、上下文里放了什么） | 部署方；**检索出口的访问控制在这里断掉**，模型方不承担你的出口责任 | L2 |
| 隐私计算 ↔ 数据湖与表格式（[../../03-data-stack/03](../../03-data-stack/03-lakehouse/03-lakehouse.md)） | 交接物 = 出域前的物化视图（哪些列、哪个分区、什么粒度） | 数据平台侧；物化粒度太细时，"不出域"只剩字面意思 | L1（机制）/ L2（粒度约定的落地） |

一句话概括：**AI 没有给隐私计算新增任何信任锚，只新增了一个受保护对象（计算过程）和一个泄漏面（检索出口）**。它带来的第一个新问题就是可陈述性：**过去"隐私保护得好不好"是技术判断，现在它必须能被写成参数与材料，否则在合规与采购那里一文不值。**由此得到三条约定。

**第一条约定：没有参数就不叫隐私保证。**ε（差分隐私）、参与方数量与协议（MPC / FL）、证明摘要（TEE）至少要写出其中一类；写不出来的方案，只能描述成"数据处理流程"，不要用"隐私计算"命名。

**第二条约定：先定处理位置，再选技术。**顺序是：能不下发就不下发 → 能端侧闭环就端侧闭环 → 必须出域才走求交 / 加密 / 隔离环境。**顺序反了，最常见的后果是用最重的密码学方案做一个本可以在端侧解决的问题**（本章 [§3.3](08-privacy-computing-section-3-sec3.md) 的第一条反模式）。

**第三条约定：跨机构协作的失败处理要事先约定。**谁重跑、谁负责重放、身份与密钥怎么轮换、某一方退出后已算出的中间结果怎么销毁——这四件事在合同与技术方案里都要有答案，因为**协作链路上的故障不能靠一方单方面修复**。

### 5.4 公开进展与文献

分三类列：论文与第三方案例只列能给出标题 / 出处 + 年份的条目；文档一类给的是**可点名的页面或发布说明 + 年份区间**（属判定入口，进页面即可核验，具体版本与日期一律以页面上的条目为准）；**宁少勿假**。

**论文（可核验）**

- Yao, "Protocols for Secure Computations", FOCS 1982——百万富翁问题与安全两方计算的起点，是本章 [§1.1](08-privacy-computing.md) 记的 MPC 源头。
- Shamir, "How to Share a Secret", CACM 1979——门限秘密分享，MPC 与协作计算的基础构件（本章 [§2.2](08-privacy-computing.md) 给出其形式化表述；**注意本章 [§1.4](08-privacy-computing.md) 把这条记为 1986 年，而可核验的出处是 1979 年的 CACM 论文，判定入口是论文本身**）。
- Dwork, McSherry, Nissim, Smith, "Calibrating Noise to Sensitivity in Private Data Analysis", TCC 2006——差分隐私 (ε, δ) 的形式化定义，是本节"ε 可陈述"这条约定唯一的理论依据。
- Gentry, "Fully Homomorphic Encryption Using Ideal Lattices", STOC 2009——全同态加密的可行性证明；注意它证明的是**可行性**，不是**可用性**（§5.5 第三条）。
- Abadi et al., "Deep Learning with Differential Privacy", CCS 2016——DP-SGD 与隐私预算记账，是"DP 训练原语"这一 L1 判断的机制依据。
- Shokri et al., "Membership Inference Attacks Against Machine Learning Models", IEEE S&P 2017——模型本身是泄漏面的早期证据。
- Zhu, Liu, Han, "Deep Leakage from Gradients", NeurIPS 2019——**为什么"只交换梯度"不等于隐私**：这是联邦学习不能替代差分隐私的关键反证。
- **三条学术条目本节无法核验**：「2024 NeurIPS 联邦 LLM 训练」「2024 CCS 机密 LLM 推理安全分析」「2025 S&P AI 时代隐私计算」——它们给的是主题名而非可检索的标题与作者。处理办法：**保留它们所指的方向**（联邦 LLM 训练、TEE 的攻击面、AI 时代的威胁模型），但不把它们当证据。

**官方 release note / 文档（判定入口）**

- **FATE 的官方 Releases 页（GitHub 仓库 FederatedAI/FATE）与 SecretFlow 的官方发布说明（GitHub 仓库 secretflow/secretflow）**——核验"隐私求交、纵向联邦算法、LLM 相关模块"是否都是正式条目（年份区间：FATE 的正式版本条目可回溯到 2019 年的 1.0，SecretFlow 自 2021 年开源起，两处均与本章 [§1.4](08-privacy-computing.md) 的演进历程一致；具体版本号与发布日期以页面上的条目为准）；**判定方法：看发布说明里有没有独立条目，而不是看项目官网的功能介绍页**（"某年某月 GA"这类时点，均以这里的发布说明为准）。
- **Opacus 文档的 "Privacy Engine" 页与隐私预算记账（accountant / RDP）相关页面；TensorFlow Privacy 的差分隐私与 privacy accounting 文档**（年份区间：两个库自 2019–2020 年起持续发布正式版本，具体版本号与日期以各自发布页为准）——核验"隐私预算记账"的实现方式与假设；**这是"DP-SGD 是 L1 原语"这一判断的可核验依据**。
- **各云厂商的机密计算产品文档**——可点名的两个入口是 **Azure Confidential Computing 文档的 "Confidential VM" 与 "Attestation" 章节**、**Google Cloud 的 "Confidential VM" 文档**（年份区间：这两条产品线的机密 VM 与远程证明文档在 2020–2021 年前后成形，此后随版本持续更新；具体 GA 日期以页面上的标注为准）。核验三件事：机密 VM / 机密容器是否 GA、远程证明报告里测量的是什么（镜像 / 启动配置 / 整机）、是否支持在证明里写到你的密钥。**判定方法：看能力条目旁标的是 GA 还是 Preview，而不是看概览页的场景口号**。**各厂商产品，其能力与版本一律以各自的官方文档为准，本节不给版本号，也不断言某项特性存在。**
- **NVIDIA 的 Confidential Computing 文档（H100 一类 GPU）**（年份：本章 [§1.4](08-privacy-computing.md) 把 H100 CC 的商用记为 2024 年；文档按版本更新，能力以页面上的清单为准）——核验"哪些算子与库支持在机密模式下运行、哪些会因此不可用"；**判定方法：看文档里有没有明确的算子 / 库支持清单，而不是看"支持机密推理"这句概述**。
- **工业界的机密推理 / 联邦产品一例**（判定入口 = 各自的官方发布说明）：机密 LLM 推理方向的 **Azure Confidential AI**、**Google Confidential Gemini**、**阿里通义机密版**、**蚂蚁摩斯**，联邦方向的 **SecretFlow 2.0**。**"某年某月 GA / 大规模商用"这类时点本节无法核验，能力与版本一律以各厂商官方发布说明为准。**
- 本章 [§4.3](08-privacy-computing-section-4-sec4.md) 的工具链表（本书章节而非外部文献，故不标年份）——核验各框架的定位（FATE / SecretFlow / PySyft / FedML 等）；工具名与定位以各项目官方文档为准。

**第三方生产案例**

- 说明：本节**未能给出**可核验的、含参数与规模口径的第三方"AI + 隐私计算"生产案例。公开材料里能核到的是协作模式与工程做法的自述（本章 [§6](08-privacy-computing-section-6-sec6.md) 已整理四个案例，其出处标注为"机构名 + 年份区间"，无可检索文档名，故划在自述一类），以及各家对机密计算能力的正式发布条目；**缺的是"因此在 ε / 参与方数 / 精度损失 / 开销比上是什么值"这类带口径的第三方材料**。**这个空白本身是结论**——它正是本节把所有 AI 能力方向判为 L2 / L3 的直接原因。
- 本节能核到的第三方生产部署只有一类，且**它不在 AI 方向上**：操作系统级遥测里的**本地差分隐私（端侧加噪后再上报）**——Apple, "Learning with Privacy at Scale"（Apple Machine Learning Journal, 2017）；Google, "RAPPOR: Randomized Aggregatable Privacy-Preserving Ordinal Response"（CCS 2014）；Microsoft, "Collecting Telemetry Data Privately"（NeurIPS 2017）。三家彼此独立、都有公开的机制材料，因此 §5.1 表第 3 行（处理位置前移）的②条成立。**但它不能外推**：这三者保护的都是统计上报量，不涉及模型训练与检索出口，所以 §5.1 表里那些 AI 能力方向的②条仍然核不到。
- 对要做技术评审的人：**本主题第②类证据最实际的补法是自己造**——把你们的参与方数量、协议、ε 与记账方式、开销比、精度损失（对照明文基线）算出来并留存口径。这五组数在隐私计算评审里的分量，超过任何厂商案例。
- 三类证据里**最容易造假的是"开销比"**：只报"接近明文"或"可接受"而不给条件的性能声称无法复核。**判定方法**：只接受同时给出"数据量 / 参与方数 / 硬件 / 网络条件"的开销数字。

**怎么用这份清单**：要核"能力存不存在"看官方文档与 release note（最快）；要核"保证成不成立"看论文与协议规范（最慢但最稳）；要核"在我这里值不值得做"看 §5.2 每条给出的判定方法——**第三类问题没有任何公开材料能替你回答**。

**核验 §5.1 表里各条宣称的最小动作**（都不需要采购）：

1. **样本对齐**：问一次"交集计算有没有可能泄露我方的独有名单"，看对方能否给出所用 PSI 协议的出处。
2. **差分隐私**：要一个 ε 值及其记账方式；拿不到具体 ε，"差分隐私"就还只是一句形容词。
3. **处理位置**：数一次"本可以端侧闭环却仍然上收"的数据项有几个。
4. **机密推理**：跑一次远程证明，看证明里能否读出镜像哈希与是否 debug 模式。
5. **联邦训练**：把通信量算出来（参数量 × 轮次 × 参与方数），看它在你网络条件下的耗时。
6. **RAG 出口**：数两周内同一条敏感内容被不同查询拼凑出来的次数。

### 5.5 被过度宣传的部分

**「联邦学习本身就是隐私保护」**——实际是：FL 保证的是**原始数据不出域**，它不提供隐私度量；梯度与更新量本身就是泄漏面（Deep Leakage from Gradients, NeurIPS 2019；成员推断更早，IEEE S&P 2017）。**为什么会这样**：FL 是一个**数据放置**的架构决定，不是一个隐私参数；没有 DP 就没有 ε 可陈述，而"我们只交换梯度"在合规面前等于没有保证。**它什么时候才会成真**：FL 默认叠加 DP，且项目能报出 ε 与效果损失这一对数字。**判定方法**：问一句"你们的 ε 是多少、记账怎么做的"——答不出来，就不是隐私方案。

**「机密计算（TEE）等于合规通过」**——实际是：TEE 把信任从运营方转移到硬件厂商与固件，**信任没有消失只是换了对象**，而这一类攻击面是被持续公开的（2018 年前后起针对 SGX 的瞬态执行类攻击如 Foreshadow）。**为什么会这样**：隔离回答的是"谁能看到明文"，而合规还要回答目的限定、留存期限、可举证与责任划分；技术隔离是其中一个环节，不是结论。**它什么时候才会成真**：远程证明成为可被第三方独立复核的审计物，且监管口径明确承认它。**判定方法**：看你手里的证明能覆盖到哪一层（镜像 / 启动配置 / 整机），覆盖不到的层就是信任缺口。

**「同态加密让密文计算可用了」**——实际是：FHE 的开销由密文膨胀与自举主导，适用域仍限在**低计算深度、小数据量**的函数（Gentry 2009 证明的是可行性，不是可用性）；真正天天在用的是**部分同态**那一类（加法同态、秘密分享），它们早就在 PSI 与联合统计里跑着。**为什么会这样**：把"某类函数可以算"读成"任意场景都可用"，是两个不同量级的断言。**它什么时候才会成真**：公开材料开始给出"多项式深度 + 参数 + 吞吐"的组合条件，而不是"支持 XX 场景"的口号。

这三条的共性：**它们都把"某个技术环节成立"当成了"整套隐私保证成立"**——FL 成立的是数据放置，TEE 成立的是隔离，HE 成立的是某类函数的可行性。而本主题的判据始终只有一条：**你能不能写出一组可被第三方复核的隐私参数，并说明它们保护了什么、没保护什么。**

### 5.6 未来 3–5 年：可证伪的预测

| 预测 | 会成真的信号 | 会证伪的信号 |
| --- | --- | --- |
| 机密推理会先在"受监管行业 + 单一模型 + 单租户"落地，公共多租户服务不是主战场 | 公开案例都带"专用实例 / 自有密钥 / 单租户"限定；证明与审计流程被写进采购条件 | 公共多租户服务把机密推理作为默认形态，且价格无溢价、不要求专用实例 |
| 联邦大模型训练不会成为通用做法，它会在"参数高效 + 少量参与方 + 强监管"的垂直场景存活 | 公开材料给出参与方数量与通信量的组合，且模型规模停在适配器级 | 出现 10 家以上参与方、全参数规模、并披露通信量与收敛差距的公开生产案例 |
| 差分隐私的采纳会集中在"聚合统计与端侧上报"，模型训练侧仍以论文为主 | 公开的 ε 口径集中在统计发布与端侧聚合；端侧预算分档成为常规做法 | 出现公开披露 ε 与效果损失的 DP 大模型生产部署 |
| "RAG 隐私"的讨论会从"密文检索"回到"出口审计与查询预算" | 检索服务把查询预算、出口审计、成员推断评测做成正式功能条目 | 密文 ANN 检索出现可核验的生产部署与性能数据（含召回率与硬件条件） |

写这四条时的共同约定：**信号必须是外部可观察的**（正式功能条目、发布说明、带口径的公开案例），而不是"我觉得会"。**被检验得最快的是第四条**——检索服务下一个版本的功能列表里有没有"查询预算 / 出口审计"，一年内就能看到；**最慢的是第二条**——它是一种否定式预测，需要有人长期公开参与方规模与通信量对比。

### 5.7 给架构师的行动建议

| 你的处境 | 现在就该做 | 一年内观察 | 明确不要做 |
| --- | --- | --- | --- |
| 两个机构要联合建模 | 先做样本对齐（PSI），再把"交集不泄露独有名单"写进方案 | 观察交集计算的协议出处与参与方数量变化 | 不要先交换原始数据再做"脱敏后比对"——交集过程本身就泄露名单 |
| 要上"差分隐私" | 先定 ε 与记账方式，再定用途分档 | 观察 ε 与效果损失的成对数字是否出现 | 不要把"加了噪声"当差分隐私；不要用通用建议值代替自己的口径 |
| 想训练联邦大模型 | 先把通信量算出来（参数量 × 轮次 × 参与方数） | 观察是否把全参数训练降级为参数高效微调 | 不要在参与方多、模型大的组合里做全参数联邦训练 |
| 要把数据交给外部模型 | 先做合同与访问审计；确需隔离再评估机密推理 | 观察远程证明能覆盖到哪一层、开销比是多少 | 不要把 TEE 当合规结论；不要在无专用实例时宣称机密 |
| 想让模型读私有语料 | 先做检索出口审计与查询预算，并把权限过滤放在召回前 | 观察同一条内容被拼凑出来的次数 | 不要在粒度的权限控制都没做时先上密文检索 |
| 端侧有数据但不想上收 | 先把"能否端侧闭环"逐项过一遍，再定加噪档位与效果回归 | 观察按用途分档后的效果损失是否被量化 | 不要一刀切把预算收到最紧（数据会不可用）；不要"能收就收" |
| 要给监管一份说明 | 写成参数：参与方 / 协议 / ε / 证明摘要 / 处理位置 | 观察这份说明能否被第三方按参数复核 | 不要用"我们做了隐私计算"这种描述代替参数 |
| 有人提议"隐私计算 + 上链" | 先问区块链要解决的是存证还是保密 | 观察协作过程的存证是否真的被第三方核对 | 不要为上链而上链——它不产生新的隐私保证 |
| 预算有限、要选一条路线 | 按处理位置排序：端侧闭环 → PSI + 纵向联邦 → 加密计算 → 隔离环境 | 观察每条路线的开销比与参与方数量是否落在可接受区间 | 不要一上来选最重的密码学方案 |

「明确不要做」这一列的共同逻辑：**这些动作的代价是确定的**（改数据处理位置、动参与方边界、引入新运维面），**而收益依赖一个尚未成立的假设**（模型方会守约 / 证明能覆盖全部层 / 密文检索开销可接受）。等 §5.6 的信号出现再投入，损失的只是时间。

### 5.8 小结

> 本节小结：本主题下 AI 真正改变的**唯一那条机制**是**保护对象的边界**——敏感物从"数据集"扩展到了**计算过程本身**（prompt、梯度、权重、上下文里的检索结果）。由此才有"机密推理"与"检索出口"成为独立的隐私问题，也才有必要把 DP 与 TEE 从辅助技术提到主线位置。它**没有**改变的是技术体系原有的分层：本章 [§1.1](08-privacy-computing.md) 把体系分成联邦学习（FL）、安全多方计算（MPC）、可信执行环境（TEE）三大方向，差分隐私（DP）与同态加密（HE）列为辅助技术；本节按**信任锚**把这份清单重新归一次组——**隐私保证仍然只能来自三种信任锚：密码学的（MPC / HE）、硬件的（TEE）、统计的（DP）；AI 没有产生第四种**，也没有改变成本曲线（MPC 的相对开销、DP 的效用代价、TEE 的信任转移）。
>
> 判断本主题下任何新提法的快捷方式：**它改变的是"什么被保护"——以及这条边界落在哪一层（信任假设 / 被保护对象 / 接口 / 架构）——还是只把旧机制套到一个新对象上？** 前者立刻改变风险（本节判 L1 / L2 的那几条），后者先要付效用与成本（本节判 L3 的那几条）。第二条同样快的判断：**这个方向能不能写出一组可被第三方复核的隐私参数**——写不出来，它就还停在"技术描述"，不是隐私保证。
>
> 如果只能带走一句话：**先把处理位置与参数口径定下来（能端侧就端侧、能求交就不出列、能报 ε 就报 ε），再谈用哪一层密码学或硬件去加强它**；顺序反过来，就是把最贵的方案用在一个本来就不该出域的问题上。
>
> 💡 **思考锚点**：按 §5.2.3 数两周的检索日志——你的检索库里混了几个密级、同一条内容被不同查询"拼"出来的次数是多少？这个数不为零时，你该排进路线图的是查询预算 + 召回前密级过滤（今天就能落、不依赖密码学），还是 TEE / 密文检索（L2/L3、算子覆盖受限）？两者投入差一个数量级，先答"出口"这件事，再谈用哪层密码学去加强它。
