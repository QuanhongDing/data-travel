### 6.1 某金融银行"EAST 报送自动化"4 年（2020-2024）

**背景（Why）**

某全国性股份制商业银行 2020 年面临**EAST 报送**（银保监监管标准化数据）压力：

- **手工报送**——**5 人/ 月**——**1 周时间**
- **人工校验**——**准确率 98%**——**2% 返工**

**触发点（What）**

2020 年**银保监**加大监管力度——**EAST 5.0 标准**发布——**字段增加 30%**——**手工报送不可持续**。银行启动**EAST 报送自动化平台**项目。

### 6.2 阿里"GDPR 合规平台"4 年（2020-2024）

**背景（Why）**

阿里 2020 年面临**欧盟 GDPR 合规**压力——**速卖通 / Lazada / Trendyol**等欧盟业务**日均 1 亿+ 欧盟用户数据**：
- **GDPR 罚款最高 4% 全球营收**——**年潜在罚款 200 亿+ 美元**
- **被遗忘权**——**用户要求删除**——**5 万+/ 月**
- **数据出境**——**受 GDPR 限制**——**必须本地化**

**触发点（What）**

2020 年**阿里启动 GDPR 合规平台**——**目标：100% GDPR 合规**。

**详细做法（How）**

阿里 GDPR 合规的**5 大核心组件**：

1. **数据分类分级（核心基础）**
   - 关键设计：字段级标签（**PII / 敏感 / 公开**）
   - 关键代码：
     ```sql
     -- 阿里 GDPR 字段级标签
     CREATE TABLE users_eu (
         user_id        BIGINT,
         name           STRING COMMENT 'PII',
         email          STRING COMMENT 'PII',
         phone          STRING COMMENT 'PII',
         address        STRING COMMENT 'PII',
         nationality    STRING,
         purchase_hist  STRING COMMENT 'PII-conditional',
         preferences    STRING
     ) WITH (
         'data_classification' = 'PII-strict',
         'gdpr_scope' = 'EU-only'
     );
     ```

2. **数据删除（被遗忘权）**
   - 关键设计：**用户要求删除**——**自动定位 + 自动删除**
   - 关键能力：**5 万+/ 月**——**30 天内**完成
   - 关键代码：
     ```java
     // GDPR 数据删除引擎
     public class GDPRDeleteEngine {
         public DeleteResult delete(UserDeleteRequest req) {
             // 1. 定位所有含 user_id 的表
             List<TableRef> tables = lineageService.findByUserId(req.userId);
             // 2. 计算级联
             List<TableRef> cascade = lineageService.cascade(tables);
             // 3. 软删除 + 30 天后硬删除
             for (TableRef t : cascade) {
                 softDelete(t, req.userId);
                 scheduleHardDelete(t, req.userId, 30_days);
             }
             return new DeleteResult(cascade.size());
         }
     }
     ```

3. **数据访问权（Right to Access）**
   - 关键设计：**用户要求导出个人数据**——**1 键导出**
   - 关键能力：**30 天内**——**完整导出**——**JSON / CSV 格式**

4. **数据出境控制**
   - 关键设计：**EU 数据**——**「**不出境**」**——**本地存储 + 本地处理**
   - 关键能力：**EU 用户数据**——**全部在 EU region**

5. **GDPR 影响评估（DPIA）自动化**
   - 关键设计：每次**新业务上线**——**自动 DPIA 报告**
   - 关键能力：**30 天内**自动生成 + 监管备案

**阿里 GDPR 关键数字**（[DAMA 2023 演讲]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **GDPR 罚款** | 0（避免 200 亿+ 潜在） | 0 | **避免巨额** |
| **被遗忘权响应** | 5 天 | 1 天 | **5 倍** |
| **数据访问权响应** | 7 天 | 1 天 | **7 倍** |
| **DPIA 出具** | 30 天 | 7 天 | **4 倍** |
| **业务覆盖** | 100% 欧盟业务 | 100% | **合规零事故** |

**具体数字（How much）**

- 团队规模：阿里 GDPR 团队 20+ 人
- 关键数字：
  - **1 亿+ 欧盟用户/天**
  - **5 万+ 被遗忘权/月**
  - **100% 合规**——**0 罚款**
  - 服务**10+ 欧盟业务**

**失败教训**

- **跨业务数据**——倒逼**「**跨域定位**」**

### 6.3 字节跳动"数据合规"3 年（2021-2024）

**触发点**

2021 年**字节启动数据合规项目**——**目标：100% 合规**。

**详细做法**

字节合规**4 大组件**：

1. **数据本地化**（核心）
   - 关键设计：**每个国家**——**独立存储**——**数据不出境**
   - 关键能力：**100% 数据本地化**——**零跨境**

2. **数据访问审计（核心）**
   - 关键设计：**每条数据访问**——**记录 + 审计**
   - 关键能力：**可追溯**——**100% 透明**
   - 关键代码：
     ```java
     // 字节数据访问审计
     public class DataAccessAuditor {
         public AccessLog audit(AccessRequest req) {
             return new AccessLog(
                 userId = req.userId,
                 dataId = req.dataId,
                 action = req.action,  // READ / WRITE / DELETE
                 purpose = req.purpose, // 业务 / 客服 / 风控
                 timestamp = now(),
                 trace = req.trace
             );
             // 写 Append-only 日志
         }
     }
     ```

3. **合规检查自动化**
   - 关键设计：每次**新业务上线**——**自动合规检查**——**GDPR / CCPA / 各国法律**
   - 关键能力：**自动拦截**——**不合规无法上线**

4. **跨境数据传输监控**
   - 关键设计：**每次跨境**——**自动审批**——**记录 + 监控**
   - 关键能力：**100% 透明**——**0 违规**

  - **10 亿+ 美国用户**
  - **0 数据出境违规**
- 业务覆盖：TikTok / 抖音 / 西瓜 / 今日头条 等
