### 6.2 阿里巴巴"**OneData 维度建模**"8+ 年（2016-2024）

- **「**5+ BU**」**——**「**5 套独立数仓**」**——**「**OneData 统一**」**

**触发点（What）**

2016 年**阿里启动 OneData 维度建模**（[阿里《大数据之路》2017]）——**目标**：「**5 套 → 1 套**」**。

**详细做法（How）：

阿里 OneData 维度建模的**5 大核心组件**：

1. **「**OneData 公共层**」**（核心创新）
   - 关键设计：**「**业务域 + 公共层**」**——**「**5 套 → 1 套**」**——**「**统一模型**」**
   - 关键代码：
     ```sql
     -- 阿里 OneData DWS 公共层
     CREATE TABLE dws_user_1d (
         user_id        BIGINT,
         city           STRING,
         category       STRING,
         gmv_1d         DECIMAL(18,2),  -- 公共指标
         order_cnt_1d   BIGINT
     ) PARTITIONED BY (dt STRING)
     LIFECYCLE 365;
     -- 5 个 BU 共用一张表
     ```
2. **「**OneData 公共层**」**（核心）
3. **「**业务域 + 公共层**」**（核心）
4. **「**代理键 + SCD**」**（核心）

> **本节小结**：
> - 4 个真实案例（Kimball / 阿里 / 字节 / 美团）印证：**维度建模不是「**凭感觉**」，是「**OneData + SCD 2 + 代理键 + 总线矩阵 + 自助**」**5 件套。
> - 关键时间线：Kimball 40+ 年 / 阿里 8+ 年 / 字节 5+ 年 / 美团 4+ 年 —— **维度建模是 40+ 年长期工程**。
> - 选型第一原则：**「**OneData 公共层**」**（**最简单**）——**10+ 张表** → **「**维度代理键 + SCD 2**」**（**必须**）→ **「**总线矩阵 + 自助查询**」**（**生产**）→ **「**实时维度 + OneData 商业化**」**（**AI 时代**）。
> - 99% 的失败来自「**数据建模混乱 + 5 套数仓 + 维度不一致**」——必须有**维度建模 + OneData + 统一 DW/BI**。
> - 真正的 ROI 来自「**5 套 → 1 套 + 95% 维度统一 + 100 万+ 企业**」——是**大厂核心 DW/BI 基础设施的命脉**。
