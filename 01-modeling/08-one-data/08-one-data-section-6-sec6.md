### 8.1 阿里巴巴"**集团 OneData 6 年落地**"6+ 年（2014-2020）

**背景（Why）**

阿里巴巴 2014 年面临**集团数据统一**挑战：
- **「**25 个 BU**」**——**「**数千条业务线**」**——**「**指标混乱**」**——**「**用户 ID 散落**」**

**触发点（What）**

2014 年**阿里启动集团 OneData**（[阿里 2014]）——**目标**：「**OneModel + OneID + OneService 集团统一**」**。

**详细做法（How）**

阿里集团 OneData 的**5 大核心组件**：

1. **「**OneModel（统一数据分层）**」**（核心创新）
   - 关键设计：**「**ODS + DWD + DWS + ADS**」**——**「**命名规范**」**——**「**指标定义中心**」**
2. **「**OneID（用户打通）**」**（核心）
3. **「**OneService（统一 API）**」**（核心）
4. **「**DataWorks 平台**」**（核心）
5. **「**指标平台**」**（核心创新）

**阿里 OneData 关键数字**（[2014-2020 公开数据]）：

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| **「**指标一致性**」** | 60% | 95% | **+58%** |
| **「**用户打通覆盖率**」** | 80% | 95%+ | **+19%** |
| **「**重复 ETL**」** | 100% | 50% | **-50%** |
| **「**新业务接入时间**」** | 3 个月 | 2 周 | **-83%** |
| **「**集团 BU**」** | 25 | 25 | **统一** |

**具体数字（How much）**

- 团队规模：阿里数据中台团队 1000+ 人
- 关键数字：
  - **PB 级数据统一**
  - **指标一致性 95%**
- 业务影响：覆盖**阿里全集团 25 BU + 100 万企业云客户**

**失败教训**

- 早期**「**指标混乱**」**——倒逼**「**指标定义中心**」**
- 早期**「**用户 ID 散落**」**——倒逼**「**OneID 全链路打通**」**
- 早期**「**重复 ETL**」**——倒逼**「**OneModel 统一**」**

---

> **本节小结**：
> - 4 个真实案例（阿里 / 字节 / 美团 / Netflix）印证：**OneData 不是「**指标平台**」，是「**OneModel + OneID + OneService + 指标平台 + 血缘**」**5 件套。
> - 关键时间线：阿里 6+ 年 / 字节 6+ 年 / 美团 5+ 年 / Netflix 6+ 年 —— **OneData 是 5+ 年长期工程**。
> - 选型第一原则：**「**OneModel（统一数据分层）**」**（**最简单**）——**10+ 指标** → **「**OneID（用户打通）**」**（**必须**）→ **「**OneService（统一 API）**」**（**生产**）→ **「**实时 OneData + 智能指标**」**（**AI 时代**）。
> - 99% 的失败来自「**指标混乱 + 用户 ID 散落 + 重复 ETL**」——必须有**OneModel + OneID + OneService**。
> - 真正的 ROI 来自「**指标一致性 95% + OneID 95% + 重复 ETL -50%**」——是**大厂核心数据中台基础设施的命脉**。
