## 7. 与其他方法对比

### 7.1 先立判据：为什么打分表会误导

打分表把「图推理（GNN/GFM） / 关系型数仓 / 向量检索 / LLM 微调 / 规则系统」放进同一张 1–5 分表，用「多跳关系建模 / 结构化推理 / 自然语言交互 / 冷启动 / 解释性 / 训练成本 / 推理成本 / 大规模扩展性 / 持续学习 / 数据效率 / 多模态融合 / 部署复杂度」十二个维度打分。这个做法有三个结构性错误。

**错误一：这五列不是同一层的选项。** 图推理是**建模与学习层**，关系型数仓是**存储与聚合层**，向量检索是**召回层**，LLM 微调是**生成与语言层**，规则系统是**判定层**。一条真实的风控或问答链路里，这五者**同时存在、各管一段**：数仓出事实流，向量库出语义候选，图出关系与证据，规则或模型出判定，LLM 把结论讲成人话。给不同层的东西打同一张分表，等价于比较「引擎 / 油箱 / 仪表盘」谁更好——它们不是替代关系。**真正的替代关系只发生在同一层内**（判定层里的规则 / 路径推理 / 子图匹配 / LLM 才是互斥或组合选项）。

**错误二：「解释性」这一维没有指定解释给谁看。** 打分表给规则系统 5 分、给图推理 4 分、给向量检索 1 分。但解释至少有三种读者，三者的判据完全不同：**给监管或合规看的解释**必须是可逐条复核的证据链，只有规则与路径推理给得出；**给算法工程师看的解释**是注意力权重与子图重要性，GNN 给得出而规则给不出；**给业务方看的解释**是「为什么这个用户有风险」这样一句自然语言，LLM 给得出而前两者都给不出。同一格里的 1 分与 5 分，换一个读者就会翻转——**打分表把「解释给谁」这个前提丢掉了**。

**错误三：「冷启动 5 分」的符号取决于攻击方是否在变化。** 打分表给规则系统的冷启动打 5 分（不需要数据），图推理 3 分。在**攻击模式稳定**的场景里（对账、额度校验），这个 5 分是实实在在的优势；但在**对手持续换手法**的场景里（欺诈、洗钱），规则系统冷启动满分恰好意味着**它只能覆盖已经写下来的模式**——对手换一个手法，规则分归零，而那 5 分不会告诉你这件事。**同一个数值在不同场景里符号相反，这正是打分表的症状。**

打分表输出的是**名次**；选型要回答的是「**在我的关系形态、信号单位与举证要求的约束下，下一步该建哪一层、建到什么粒度，以及它在什么条件下失效**」。

**本章采用的 6 条判据**（已针对图推理主题具体化）：

| 判据 | 问的问题 | 为什么它决定了选型 |
| --- | --- | --- |
| 关系是不是信号 | 关系本身是判别依据，还是可归结为语义相似 | 不是，就根本不该建图；这一条分错，后面全部作废（见 7.2、7.3.2） |
| 信号的最小单位 | 节点邻域 / 一条边 / 一组实体的形状 / 一条路径 / 一段文本 | 建模单元与业务单元不一致时，模型指标再好也接不住业务动作（见 7.3.2） |
| 结论要不要被逐条复核 | 结论进不进入需要举证、审计或监管的流程 | 决定能不能只用「学出来的」方法，或必须配一条可复核的证据链（见 7.3.3） |
| 查询是遍历还是聚合 | 沿关系走，还是过滤 + 统计 | 决定要不要上图库：代价与跳数解耦只在原生图存储上成立（见 7.3.1） |
| 实体在推理时是否已存在 | 新用户、新商品、新账号是否持续产生 | 决定转导式还是归纳式；离线指标结构上看不见这一项（见 7.3.2） |
| 索引期与在线期的成本分配 | 抽取与归一的成本付在离线，还是查询成本付在在线 | 决定这套链路的成本随「新增文档量」还是随「查询量」增长（见 7.4） |

打分表的十二个维度一个未丢，只是位置变了：**多跳关系建模** → 判据 1、判据 4 与 7.3.1；**结构化推理** → 判据 2 与 7.3.2；**自然语言交互** → 判据 3（谁来做解释）与 7.6 的 GraphRAG 组合；**冷启动** → 判据 5；**解释性** → 判据 3；**训练成本 / 推理成本** → 7.4；**大规模扩展性** → 7.3.1 与 7.4；**持续学习** → 7.3.2 的归纳性与 7.7 的图 schema 重建代价；**数据效率** → 判据 5；**多模态融合** → 7.6 的「多模态信号要一起用」一行与组合 5（异构图 + 多模态嵌入），模式层面见 [§3.2.5 模式 E（异构图 + 元路径）](07-graph-reasoning-section-3-sec3.md)；**部署复杂度** → 7.2 的族划分与 7.7 的迁移表。

判据的顺序对应一个筛选顺序：**判据 1、2 是结构性的**（关系是不是信号、信号的最小单位，选错要从头重做），**判据 3、4 是架构层面的**（决定要不要多一层证据链、要不要换存储），**判据 5、6 是运行层面的**（多数可以通过改评估口径或调度缓解）。**打分表的根本问题在于把这三类混在一根尺子上**：「多跳关系建模 5 分 vs 1 分」这种结构性差异，和「部署复杂度 2 分 vs 5 分」这种换一套部署方式就能抹平的差异，在表里长得一样重。

### 7.2 候选方案全景

| 族 | 代表 | 层次 | 核心机制（一句话） | 典型使用者 | 依赖 / 许可 |
| --- | --- | --- | --- | --- | --- |
| 图存储与遍历族 | Neo4j、NebulaGraph、TigerGraph、ArangoDB、Memgraph、阿里 GraphScope / Ant Graph | 承载层 | 关系以物理指针存储，遍历是跟随指针而非索引查找 | 风控、供应链、知识图谱 | 多为开源核心 + 商业企业版；许可以各项目当前 LICENSE 为准 |
| 关系型数仓族 | 列存 + SQL | 承载层 | 按列存、按分区与排序键裁剪，擅长过滤与聚合 | 指标统计、明细分析 | 已有资产；本目录 §6 案例的上游 |
| 向量检索族 | 近似最近邻索引 | 承载层 / 召回层 | 把对象压成向量，按距离找近邻，**关系在这一步被压掉** | 语义搜索、RAG 召回 | Faiss / Milvus 一类开源库与引擎 |
| 图算法族 | PageRank / Personalized PageRank、Louvain / Leiden、最短路、连通分量、三角形计数 | 学习层（无参数） | 用图的结构量直接产出可解释特征 | 分群、重要度、团伙初筛 | 图计算引擎或库内算法 |
| 图嵌入族 | DeepWalk、node2vec、LINE、Struc2Vec | 学习层 | 随机游走当句子、节点当词，学出向量；**转导式** | 相似度初筛、baseline | 训练脚本 + 向量服务 |
| GNN 族 | GCN、GraphSAGE、GAT、R-GCN、GIN、PinSage、GraphSAINT、Cluster-GCN、APPNP、JK-Net、Graphormer、GraphGPS | 学习层 | 消息传递：聚合邻居再更新自身；采样机制决定归纳性 | 推荐召回、欺诈评分 | PyG / DGL 一类框架 + 图存储 |
| 路径推理族 | PRA / PathRank、DeepPath / MINERVA、DRUM / RNNLogic、ToG / RoG | 学习层 / 判定层 | 用路径本身作为输出单元，路径即证据 | 反洗钱、合规、根因定位 | 图查询 + 路径打分器 |
| 子图匹配族 | 精确同构（Ullmann / VF2 / VF3 一类）、学习式子图分类、子图向量检索、Motif / Graphlet 频次 | 学习层 / 判定层 | 以「一组实体连成的形状」为判别单元 | 团伙识别、分子子结构 | 图查询 + 子图嵌入 |
| 符号推理 / 规则族 | 规则引擎、Cypher / SPARQL / Datalog | 判定层 | 结论由已写下的模式推导，**可逐条复现** | 风控硬规则、数据血缘校验 | 图查询语言与规则引擎 |
| LLM 与 GraphRAG 族 | LLM 微调、Microsoft GraphRAG、Neo4j NaLLM、NebulaGraph GraphRAG、LLM-as-Reasoner over KG（ToG / RoG） | 判定层 / 生成层 | LLM 把问题翻译成图查询或组织图结果，**事实来自图而非来自参数** | 企业知识问答、Agent 记忆 | LLM 调用 + 图库 + 向量库 |
| GFM 族 | OpenGraph、OFA、G-Retriever、LLaGA、GraphGPT、UniGraph | 学习层（预训练） | 在大规模图上预训练骨干，下游微调或零样本 | 多任务图团队 | 公开骨干 + 微调管线 |

这十一族分**三层**：**承载层**（图存储、数仓、向量索引）、**学习层**（图算法、嵌入、GNN、GFM）、**判定层**（规则、路径推理、子图匹配、LLM）。**同一层内才是替代关系**（判定层里规则 / 路径推理 / 子图匹配 / LLM 之间才是互斥或组合关系），跨层是上下游关系（承载层供数据、学习层出模型、判定层出结论）。**先分层、再在层内选，能省掉一半比较**——打分表把三层混在十二个维度里，所以才会出现「GNN 训练成本 3 分 vs 数仓 5 分」这种没有对价的比较。

**上表只列机制，不断言「某产品在某个版本里是否支持某特性」**：图生态迭代很快，写死会产生过期断言。凡涉及具体能力，用下面三种判定方法自查：

- **某条多跳查询该不该上原生图存储**：看查询的实际代价随跳数怎么变。在关系型存储上，代价随「查找次数」增长（每次查找是随机 IO）；在原生图存储上，代价随「实际遍历到的边数」增长。跑同一个 3 跳与 6 跳查询、对比耗时曲线的斜率，斜率陡的那一侧就是你的答案。
- **某个 GNN 架构在你的图上是不是归纳式**：把训练时不存在的新节点单独切出来当评估集。能对新节点直接打分的是归纳式（GraphSAGE / PinSage 一类邻居采样机制），只能对新节点给默认分的是转导式。**这个实验比读任何文档都可靠。**
- **某个图库或 GraphRAG 实现的能力边界**：以各自官方文档与仓库的当前版本为准——本节的判定方法可自行核验，具体版本行为请以官方文档当前版本为准。

### 7.3 机制差异：为什么它们表现不同（核心节）

十一族候选（分属三层）的全部差异可以归因到四个机制维度。选这四个，是因为它们分别回答选型时必然要问的四件事：**遍历一份关系要付什么代价（7.3.1）· 模型在学什么形状（7.3.2）· 结论是查出来的还是学出来的（7.3.3）· 多跳问题靠哪条通路回答（7.3.4）**。

#### 7.3.1 关系的存储方式：代价是跳数的函数还是结果集的函数

**机制是什么**：关系存放在「索引 + 外键」里，还是存放在「节点记录中的物理指针」里。这不影响能不能查到，只影响**每多走一跳要再付一次什么代价**。

**主要族的实现差异**：

| 族 | 关系存在哪 | 走一跳的代价 | 跳数增加时的代价形状 |
| --- | --- | --- | --- |
| 关系型数仓族 | 外键列 + 索引 | 一次索引查找（随机 IO） | 每跳再乘一次查找次数 |
| 图存储与遍历族 | 节点记录里的相邻关系指针 | 跟随一次指针（局部性友好） | 近似与跳数无关 |
| 向量检索族 | 不存关系，只存距离 | 一次近邻检索 | 跳数这个概念不存在 |
| 图算法族 | 不另存一份关系，直接读承载层那一份图 | 不按跳付费：每轮迭代重扫一遍全图边 | 与跳数解耦，代价随「迭代轮数 × 全图边数」增长 |
| GNN 族 | 训练前落成邻接表 / 采样器 | 一次邻居采样 | 采样量按 fanout 的层数次幂增长 |

**由此必然导出的性质**：**因为**关系型存储里"关系"只是一个普通列，走一跳等价于「用索引再找一次」，**所以**多跳代价随跳数按查找次数的幂增长；**而因为**原生图存储把相邻关系的地址直接放进节点记录，**所以**走一跳只是一次指针跟随，代价与跳数基本解耦，转而由**结果集大小**决定。**代价是**：这套结构为「沿关系走」优化，对「过滤 + 聚合统计」几乎没有帮助——图库上跑大范围聚合会比列存慢一个量级【经验】（[§3.5 反模式表](07-graph-reasoning-section-3-sec3.md) 的「图数据库当万能存储」一行给出这一量级；本目录 §6 的 Neo4j 案例把「图库做全表聚合统计性能极差」与「图库遍历 + OLAP 聚合分工」列为失败教训之一，同口径）。**另一条代价在超级节点上**：**因为**遍历的代价正比于实际走过的边数，**所以**一个度数远高于均值的节点会让一次本应很浅的遍历付出与它的度数成正比的代价——**超级节点与存储选型无关，它是遍历范式的固有成本**。

**算一次多跳的量级**【推算】：设平均度数 50、跳数 3，则关系型路线上「查找次数」的上界约为 $50^3 = 1.25\times10^5$ 次（推导链：每跳把候选集合乘一次平均度数，此处不考虑去重与结果集收敛，是上界估计）；同一张图在原生图存储上，若目标路径只有少数几条，代价只与「实际走过的边数 + 结果集大小」相关，与 50³ 这个量级无关。**两者差别的本质不是快慢，而是"下界由什么决定"**：一侧由查找次数决定，另一侧由结果集大小决定。这也解释了为什么「多跳」在图上是先决条件，而在关系型存储上是需要预先展平的负担。

**公开证据**：上面这条存储差异在公开材料里有明确命名——关系型侧是「外键 + 索引查找」，原生图侧是**无索引邻接（index-free adjacency）**：相邻关系的地址直接写在节点记录里，走一跳只是指针解引用。这套命名与描述可见于图数据库主题的公开著作与主流图库官方文档（例如 Robinson / Webber / Eifrem《Graph Databases》，O'Reilly，第 1 版 2013、第 2 版 2015）【公开，2013 / 2015，可按书名与「index-free adjacency」关键词核验】；各家图库对该结构的实现范围与措辞有别，具体以各自官方文档当前版本为准。**可自行核验的判据**：在同一个数据集上跑同一个 3 跳查询，把图库的耗时曲线与关系型存储的耗时曲线画在一张图上——两条曲线的斜率差，就是你为「关系能不能便宜地走」付的价。

**失效条件**：当查询没有明确起点（全图扫描式的统计）时，指针结构的优势归零，此时正确的动作是换到列存或图计算引擎，而不是优化图库。第二种失效发生在**超级节点密集**的图上：遍历的代价被少数高度数节点主导，此时要做的不是换存储，而是识别超级节点并对其关系分桶（主文件 §2.3.5 的「图算法 + GNN 组合拳」与 [§3.7 自检清单](07-graph-reasoning-section-3-sec3.md) 里的超级节点一条都指向同一个动作）。

#### 7.3.2 建模单元：信号到底住在哪个形状里

**机制是什么**：模型把什么当作判别单元——单个节点的邻域、一条边、一组实体的整体形状、一条路径，还是一段文本。这是图推理里**最容易选错、且选错后指标看不出来**的一维。

**主要族的实现差异**：

| 族 | 判别单元 | 学/算了什么 | 归纳性 |
| --- | --- | --- | --- |
| GNN 族（节点分类） | 单节点及其 K 跳邻域 | 把邻域聚合成节点表示 | 取决于聚合机制：邻居采样可归纳，全图归一化转导 |
| 图嵌入族 | 单节点的向量表示 | 共现关系压成向量 | 转导式，新节点没有向量 |
| 图算法族 | 图上的结构量（度数 / 中心性 / 社区标签 / 三角形计数） | 直接算结构统计量，无参数 | 可归纳（新节点直接参与计算），但重算会改动已有节点的量 |
| 路径推理族 | 一条路径 | 路径的打分与排序 | 可归纳（路径是新拼出来的） |
| 子图匹配族 | 一组实体连成的形状 | 整块形状的相似度或类别 | 可归纳（形状可在新实体上匹配） |
| GFM 族 | 多张图、多任务共用骨干 | 结构与文本属性的联合预训练 | 以归纳为设计目标 |

**由此必然导出的性质**：**因为**消息传递的每一层都做「聚合邻居再更新自身」，**所以**节点分类器看到的是每个节点自己的**邻域统计**——如果判别依据是「成员之间怎么连」这样的整体形状，社区结构信息在聚合那一步就被平均掉了，**代价是**模型指标看起来不错，但业务拿到高分名单后仍要人工重新攒团伙（这正是 [§3.3 模式选择决策表](07-graph-reasoning-section-3-sec3.md) 记下的最高频误配：把团伙识别当成节点分类来做）。**反过来，因为**点分类器只需要展开一个节点的邻域，**所以**它在实体数量大的场景下成本可控，**而**子图匹配要为每个候选实体展开邻域或做匹配，规模上一开始就吃亏。**第三，因为**归纳式架构只看「邻居怎么采样」，**所以**它能对新节点直接打分；**而因为**转导式嵌入学的是「全图的归一化结构」本身，**所以**新节点没有可用的向量、被统一打到默认分——**而这个退化在离线评估里看不见**，因为离线评估用的正是训练时已经存在的节点（主文件 §2.2 的关键数学事实 3 与 [§3.5 反模式表](07-graph-reasoning-section-3-sec3.md) 的「忽视归纳性」）。

**算一次邻域展开的量级**【推算】：设每层采样 fanout = 10，则 K 层后单节点的采样量约为 $10^K$（推导链：每加一层把候选邻域乘一次 fanout；此处按未去重计，是上界，与 [§3.2.1](07-graph-reasoning-section-3-sec3.md) 同口径）。$K=2$ 约 $10^2$，$K=4$ 约 $10^4$——**层数每加 1，采样成本乘一次 fanout**，这就是「不能盲目加深」的算术依据，而不是风格建议。

**公开证据**：GCN（2017）、GraphSAGE（2017）、GAT（2018）、R-GCN（2018）与 PinSage（2018）均为公开方法，题名与年份可按论文标题核验【公开，2017 / 2018，可按论文标题核验】；另外两类判别单元的公开出处是：图算法族（以结构量为判别单元，PageRank 1998、社区发现 Louvain 2008）与子图匹配族（以整体形状为判别单元，精确子图同构 Ullmann 1976、VF2 2004），可按原始论文题名核验【公开，1976 / 1998 / 2004 / 2008，可按论文题名核验】；归纳式与转导式的分界（GraphSAGE 的邻居采样使其可泛化到新节点，GCN 学的是全图归一化邻接）在主文件 §2.2 已给出一致表述。图上的「预训练 + 下游」口径在 2023 年后出现了一批公开工作（OpenGraph、G-Retriever、LLaGA、GraphGPT 等），名称与年份可按论文标题检索核验【公开，2023 年及以后，可按论文标题核验】。**可自行核验的判据**：评估集是否**按时间切分**，并单独统计「训练时不存在的新节点」上的表现——不切分时间的离线指标对本条判据没有信息量。

**失效条件**：当「新实体在推理时必然大量出现」（新用户、新商品、新账号是常态）时，转导式路线的全部离线优势都不可兑现，必须换归纳式；当业务关心的判别单元本身是**整体形状**时，换更深的 GNN 也补不回来，必须换建模单元（子图一族）。**两条失效的共同点是：它们都不能靠调参解决**——一个是评估口径问题，一个是建模单元问题。

#### 7.3.3 结论是查出来的还是学出来的：可复核性的分界

**机制是什么**：结论由已写下的模式推导（规则、图查询、路径推理），还是由参数化的模型算出来（GNN、嵌入），还是由语言模型组织出来（LLM / GraphRAG）。这条机制决定**结论能被复核到什么粒度**。

**主要族的实现差异**：

| 族 | 结论怎么产生 | 能否逐条复现 | 能覆盖的范围 |
| --- | --- | --- | --- |
| 符号推理 / 规则族 | 匹配已写下的模式后推导 | 能，规则与事实都可打印 | 只覆盖已写下的模式 |
| 路径推理族 | 打分并排序候选路径 | 能，输出单元就是路径 | 覆盖已知关系类型的组合，**能覆盖没写死的路径** |
| GNN 族 | 前向算出一个分数 | 到「哪些邻居贡献了多少」这一粒度（注意力 / 子图重要性） | 覆盖训练分布内的模式 |
| 向量检索族 | 距离排序 | 能（给出相似片段） | 只覆盖语义相似，**关系不可复核** |
| LLM 族 | 语言模型组织答案 | 可给出处，但推理链本身不可逐条复现 | 覆盖面最广，也最容易外推 |

**由此必然导出的性质**：**因为**规则与图查询的结论由「模式匹配 + 事实」两步构成，**所以**它可逐条复现、能直接进举证流程，**代价**是只能覆盖已经写下来的模式——对手换手法，覆盖率立即归零，而这一点在指标上表现为「召回突然掉」，不表现为任何训练异常。**而因为** GNN 的结论来自参数化的聚合，**所以**它能覆盖训练分布内没被显式写下的模式，**代价**是解释只能做到「注意力 / 子图重要性」这个粒度，接不住需要逐条证据的流程。**第三，因为** LLM 组织的是已有事实（图查询返回的结果），**所以**它能把结论讲成任意读者能懂的话，**代价**是必须把「LLM 不负责凭空推理关系、只负责翻译与解释」这条边界写死；一旦让 LLM 自己组织关系，得到的答案无法被图查询证伪，也就回到了不可复核——**GraphRAG 的价值恰恰在于它把事实来源钉在图这一侧**。

**公开证据**：图查询语言（Cypher / SPARQL 一类）与图上的声明式模式表达，是各家图库官方文档的一等能力，可按各自官方文档当前版本核验【公开，Cypher / SPARQL 相关官方文档，以各项目官方文档当前版本为准】。Microsoft 于 2024 年公开 GraphRAG 的实现（社区发现 + LLM 总结的路线），可按其官方仓库当前版本与发布记录核验；把 LLM 生成的图查询交给图库执行、再回到自然语言生成的路线，与 Neo4j、NebulaGraph 等公开的 GraphRAG 工作相关【公开，2024，可按各自官方仓库当前内容核验】。**可自行核验的判据**：抽一批结论去问「这条结论依赖哪几条事实」，答得出来的是可复核的链路，答不出来的是不可复核的——**这条判据比任何解释性打分都直接**。

**失效条件**：当业务进入需要举证、审计或监管的流程时，「学出来的」结论单独不可用，必须补一条可复核的证据链（路径 / 子图 / 命中规则），否则模型再好也进不了流程。第二种失效方向相反：当对手持续变化时，「查出来的」结论覆盖率衰减且不报警，必须同时保留一条能覆盖新模式的通路（GNN 打分或异常检测）来触发人工复核——**两条通路负责的是两件不同的事，缺一条都会以一种"看不出来"的方式失效**。

#### 7.3.4 结构与语义的两条召回通路：多跳问题靠哪条路回答

**机制是什么**：回答一个问题需要「沿关系可达」还是「语义相近」。向量检索把对象压成向量，**关系在这一步被压掉了**；图保留了关系，但要求实体已经被归一成同一个身份。

**主要族的实现差异**：

| 族 | 检索通路 | 回答「A 的供应商的母公司是谁」 | 前提条件 |
| --- | --- | --- | --- |
| 向量检索族 | 语义近邻 | 结构上不可答，除非两段事实恰好落在同一片段 | 无 |
| 图存储 + 路径推理族 | 沿关系逐跳可达 | 可答，且能给出中间路径 | 实体已归一；边上带出处 |
| LLM 与 GraphRAG 族 | 两路并用（实体识别 → 双路召回 → 融合重排 → 生成） | 可答，答案带出处链 | 同图一侧；且实体识别这一步不能错 |
| GNN / GFM 族 | 不直接检索 | 不适用（它出的是分数与表示，不是证据） | 训练数据覆盖到这些实体 |

**由此必然导出的性质**：**因为**向量检索把「关系」压成了一个标量距离，**所以**需要跨两个片段把事实串起来的问题在结构上不可答——不是检索参数没调好，而是那条通路不存在；**而因为**图上的多跳可达要求「同一实体只有一种表示」，**所以**实体归一没做好的时候，图会碎成互不相连的孤岛，**加了图以后回答质量与纯向量检索持平，却付出了索引期成本**（[§3.2.6](07-graph-reasoning-section-3-sec3.md) 已把这条列为 GraphRAG 的主要失效点）。**第三条性质关于成本的位置**：**因为**GraphRAG 的实体关系抽取与归一发生在索引期，**所以**它的成本随「新增文档量」增长，而不是随「查询量」增长——**这个成本形状决定了它的适用前提是"知识库相对稳定、查询频次高"**；反过来，知识库每天大量新增而查询稀疏的场景，索引期成本永远摊不平（量级见 7.4）。

**公开证据**：主文件 §1.1 给出的三条路线（符号推理 / 神经推理 / LLM 推理）与 §1.3 的路线判断表是本节分层的依据；[§5 前沿演进](07-graph-reasoning-section-5-ai.md) 的 §5.2 给出的三种 RAG 路线对比（纯向量 / 混合 / GraphRAG）与本节的「两条召回通路」是同一件事的两种写法。**可自行核验的判据**：抽一批问题看答案里引用的实体，检查这些实体在图上是否连成一条可达路径——连不起来，就是实体归一的问题，不是模型能力的问题（[§3.2.6](07-graph-reasoning-section-3-sec3.md) 的判定方法）。

**失效条件**：当问题确实只是「找语义相近的片段」（FAQ、释义、同义改写）时，上图是净成本，因为那条通路本来就不需要关系。第二种失效在**实体识别这一步**：GraphRAG 的在线链路是「实体识别 → 双路召回 → 融合 → 生成」，第一步错了后面全错，而这一步的错误率与业务词典、别名表的质量直接相关——**它不是模型问题，是主数据问题**（这也是主文件把 OneData / OneID 放在图推理下面的原因）。

### 7.4 成本结构对比（不是价格表，是成本函数）

十一族的成本**随什么变量增长**：

```
总成本 ≈ 承载层（存储与索引：数据量 × 副本 × 保留期 + 图构建/归一的一次性投入）
       + 学习层（训练：图采样量 × 层数 + 调参与重复实验；预训练则是另一条曲线）
       + 判定层（推理：每步决策算力 × 请求量；路径与子图查询的代价随跳数与度数增长）
       + 索引期（GraphRAG 类：实体抽取调用次数 × 新增文档量）
       + 人力（图构建口径维护 + 实体归一 + 证据链维护 + 版本与血缘）
```

**主导项与隐性成本**：

| 族 | 主导项 | 隐性成本 |
| --- | --- | --- |
| 图存储与遍历族 | 常驻存储 + 遍历查询的算力 | 超级节点上的遍历代价；图构建口径的长期维护 |
| 关系型数仓族 | 常驻计算 + 存储 | 多跳需求会被迫改写成展平宽表，冗余随需求增长 |
| 向量检索族 | 索引存储 + 近邻检索算力 | 关系信息在向量化那一步永久丢失，补不回来 |
| 图算法族 | 图计算作业的算力 | 无参数不等于零成本：每次图更新要重算，且要有人解释特征含义 |
| 图嵌入族 | 训练作业 + 向量服务 | 转导式：图一变就要重训，成本随图更新频率线性累积 |
| GNN 族 | 采样量（$fanout^{层数}$）+ 训练算力 | 评估口径要做两套（离线 + 新节点）；样本质量决定上限 |
| 路径推理族 | 在线路径查询算力 | 路径爆炸与超级节点；证据链的长度本身要设上限 |
| 子图匹配族 | 匹配或展开算力（随候选实体数增长） | 精确同构的组合代价；近似匹配的漏召 |
| 符号推理 / 规则族 | 规则维护的人力（**不是算力**） | 覆盖率随对手变化衰减，且衰减不报警 |
| LLM 与 GraphRAG 族 | 索引期抽取调用 + 在线生成 | 实体归一与出处维护；LLM 版本更新会让答案分布变化 |
| GFM 族 | 预训练算力（一次）+ 下游微调 | 骨干更新波及所有下游任务，需要统一回归验证 |

**【推算】数量级示例**（推导链写全，便于换参数重算）：

- **GraphRAG 的索引期调用次数**【推算】：设知识库 10 万篇文档、每篇切 20 片、每片做一次实体关系抽取调用，则索引期需要约 $10^5 \times 20 = 2\times10^6$ 次抽取调用（推导链：文档数 × 每篇切片数 × 每片一次调用）。**增量更新时只有新增文档进入这条链路**——所以这条成本的形状是「随新增文档量线性增长、与查询量无关」。对照之下，纯向量检索的索引期只是「切片 + 向量化」，同样按文档量增长但常数更小；**两者的差别不在量级，而在是否需要一个"实体归一"的环节**，而那个环节是 GraphRAG 能不能答多跳的前提（7.3.4）。
- **多跳遍历的量级**【推算】：平均度数 50 时，关系型路线上 3 跳的查找次数上界约 $50^3 \approx 1.25\times10^5$ 次（推导链见 7.3.1）；同图在原生图存储上，代价正比于实际走过的边数与结果集大小。**这条推算回答的是"该不该换存储"，不是"图库有多快"**——判断方法是用你自己的图跑 3 跳与 6 跳，看两条耗时曲线的斜率。
- **GFM 摊平成本的条件**【推算】：设下游任务数为 $n$、单任务从零训练成本 $T$、预训练成本 $P$、微调成本 $F$，则自建预训练划算的条件是 $n \times T > P + n \times F$，即 $n > P/(T-F)$。取 $P = 5T$、$F = 0.1T$（示例参数，读者可换成本组织的实测值），得 $n > 5/(1-0.1) \approx 5.6$，即**下游任务数超过约 6 个时自建才摊得平**（推导链：$5T/(T-0.1T) = 5/0.9 \approx 5.6$）。任务只有一两个时，正确动作是用公开骨干做零样本并**与「图特征 + 梯度提升树」基线对比**，而不是进入预训练投入。
- **人力项**【经验】：图构建口径的维护、实体归一、证据链的产出，是**与图规模无关、与实体类型数与业务域数成正比**的固定项。常见观察是：实体归一（同一实体多种写法未合并）是企业私有知识图谱落地的实际瓶颈，而它通常不在任何模型评估指标里。

**主导项随场景切换，所以「先省哪一项」不是固定的**：

| 你的场景 | 成本公式里的主导项 | 因此第一优先 |
| --- | --- | --- |
| 图谱刚建、实体类型多 | 人力（图构建口径 + 归一） | 先把边语义与实体口径写清，再谈模型 |
| 实体高速新增（新用户/新商品） | 嵌入或 GNN 的重训成本 | 先换成归纳式架构，别优化训练脚本 |
| 知识库稳定、查询频次高 | 索引期抽取（一次摊多次） | 值得上 GraphRAG |
| 知识库每天新增、查询稀疏 | 索引期抽取（摊不平） | 先用向量 + 关键词，图这条路先不做 |
| 结论要进监管流程 | 证据链的产出与维护 | 先把路径/子图做成一等输出 |
| 多业务、多任务 | 预训练与骨干回归验证 | 先用公开骨干零样本，够了就不自建 |

### 7.5 决策树（每个分支都要有阈值依据）

```
把问题写成一句话，然后量四个数：关系是不是信号本身 / 信号的最小单位 /
结论要不要被逐条复核 / 查询是遍历还是聚合
│
├─ ① 主要问题不是「实体之间的关系」，而是过滤、聚合或语义相似
│    → 关系型数仓（过滤 + 聚合）或向量检索 + Embedding（语义相似）
│
├─ ② 关系是「语义相似」而不是「显式结构」
│    → 向量检索 / Embedding
│      前置判据：问题是否需要把分散在两个片段里的事实串起来
│
├─ ③ 关系是显式结构，但查询是「过滤 + 聚合统计」
│    → 列存 / 数仓；不要上图库——聚合是遍历型存储的弱项
│
├─ ④ 显式结构 + 查询是「沿关系遍历」+ 跳数会变
│    → 图数据库（原生图存储）+ 图算法
│      前置判据：是否存在度数远高于均值的超级节点
│
├─ ⑤ 结论要进需要举证或监管的流程（要证据链）
│    → 路径推理（PRA / ToG / RNNLogic 一类）+ 子图匹配 + 规则，额外补一条模型通路触发复核
│
├─ ⑥ 判别单元是「一组实体的整体形状」（团伙、分子子结构）
│    → 子图分类 / 子图检索，而不是节点分类
│
├─ ⑦ 只需要出分数或候选，且实体在推理时会持续新增
│    → 归纳式 GNN（GraphSAGE / PinSage 一类）+ 先跑图特征基线
│      前置判据：评估集是否按时间切分并单独统计新节点
│
├─ ⑧ 需要自然语言问答，答案要跨片段多跳串联
│    → GraphRAG（KG + 向量双路召回 + LLM 生成 + 出处链）
│      前置判据：实体归一是否与主数据（OneID）口径一致
│
├─ ⑨ 下游任务多、标签少，且你的图与公开预训练语料分布接近
│    → GFM 预训练骨干 + 下游微调
│
└─ ⑩ 图上存在敏感属性或越权访问风险
     → 先把边级权限与敏感边过滤做进遍历路径本身，再谈模型
```

**阈值依据**（与树上每个判断节点一一对应）：

- **①「主要问题是不是关系」**：这是**结构判据**而非数值阈值——判据是关系本身是不是判别依据。由 7.3.2 导出：建模单元选错要从头重做，而它的返工代价远高于后面任何一步调优。判定方法：先跑「图特征 + 梯度提升树」基线，如果度数、社区标签这类一阶统计就能拿到大部分收益，说明信号不在关系上，不必进入 GNN（[§3.5 反模式表](07-graph-reasoning-section-3-sec3.md) 把「GNN 一定能跑赢 XGBoost」列为三条最危险的展开之一；[§3.8 小结](07-graph-reasoning-section-3-sec3.md) 把「图特征基线没跑过就上 GNN」称为本节记录的最高频失效）。
- **②「是否需要把两个片段里的事实串起来」**：由 7.3.4 导出——向量检索把关系压成距离，需要跨片段串联的问题在那条通路上结构上不可答，与检索参数无关。判定方法：抽一批问题，看正确答案是否必须由两个不同片段里的事实拼接而成。
- **③「过滤 + 聚合 vs 沿关系遍历」**：由 7.3.1 导出——原生图存储为指针跟随优化，对全范围聚合没有帮助，图库上跑聚合会比列存慢一个量级【经验】（[§3.5 反模式表](07-graph-reasoning-section-3-sec3.md) 的「图数据库当万能存储」一行给出这一量级；本目录 §6 的 Neo4j 案例同口径，把它列为失败教训）。这条是**分工判据**：满足它就该把两类查询拆到两套存储上，而不是在图库里加索引。
- **④「是否存在超级节点」**：由 7.3.1 导出——遍历代价正比于走过的边数，一个高度数节点会让浅遍历付出与它度数成正比的代价。判定方法是看度数分布的长尾：**若一次遍历的主要代价落在少数几个节点上**，就该做超级节点识别与关系分桶，这与选哪家图库无关（[§3.7 自检清单](07-graph-reasoning-section-3-sec3.md) 同口径）。
- **⑤「结论要不要被逐条复核」**：这是**流程判据**，不是技术阈值。由 7.3.3 导出：「学出来的」方法解释只到注意力 / 子图重要性这一粒度，接不住逐条举证的流程。注意本条给的是**两条通路并存**的方案而不是二选一——因为查出来的通路覆盖率会随对手变化衰减且不报警（7.3.3 失效条件）。
- **⑥「判别单元是不是整体形状」**：由 7.3.2 导出——消息传递会把社区结构在聚合那一步平均掉，所以形状类判据不能用节点分类代替，换更深的网络也补不回来（[§3.3](07-graph-reasoning-section-3-sec3.md) 记的 A / D 误配即此）。
- **⑦「评估集是否按时间切分并单独统计新节点」**：由 7.3.2 导出，是**评估口径判据**。它的地位是「阈值」而不是「建议」，因为**不切分时间的离线指标对本条判据提供的信息量是零**：离线评估用的正是训练时已存在的节点，所以转导式退化在离线阶段看不出来。判定方法：评估集按时间切分，并单独报告新节点占比及这部分的表现。
- **⑧「实体归一是否与 OneID 口径一致」**：由 7.3.4 导出——多跳可达依赖「同一实体只有一种表示」。这条是**前提判据**：不成立时，加了图以后回答质量与纯向量检索持平，却付出了索引期成本。判定方法：抽查图上被引用的实体是否连成一条可达路径。
- **⑨「下游任务数是否够多」**：由 7.4 的推算导出——$n > P/(T-F)$，示例参数下约为 6 个任务；同时还有一条分布前提：**你的图与公开预训练语料的分布接近**，否则零样本结果不能作为选型依据（[§3.2.7](07-graph-reasoning-section-3-sec3.md) 已给出同口径的判定顺序：先零样本对比基线，赢不了就不要进入预训练投入）。
- **⑩「图上是否有敏感属性或越权风险」**：这是**合规约束**而非数值阈值——数据出域与访问权限是硬约束时，权限检查必须进入遍历路径本身，而不是留在应用层的事后过滤。判定方法：看遍历算子有没有把访问约束下推到执行侧（本目录 §6 的 Meta 社交图案例把「不能在遍历中越权」列为核心约束）【经验】（来源：本目录 §6 汇总的公开案例，其标注的数字与年份以该节为准）。

### 7.6 选型矩阵与组合

| 场景 | 首选 | 备选 | 不选它的原因 |
| --- | --- | --- | --- |
| 过滤 + 聚合统计为主 | 列存 / 数仓 | 图计算引擎 | 图计算引擎：作业按全图迭代跑，带过滤条件的聚合拿不到列存那样的分区 / 排序键裁剪 |
| 语义相似召回 | 向量检索 + Embedding | 关键词 + 重排 | 关键词 + 重排：只覆盖字面命中，同义改写的目标召不回来；重排只能重排已召回的候选 |
| 沿关系遍历、跳数会变 | 图数据库（原生图存储） | 预展平的宽表 | 留在关系型存储：多跳代价随跳数按查找次数增长 |
| 团伙识别、整体形状判别 | 子图匹配 / 子图分类 + 社区发现 | 节点分类 + 事后攒团 | 用节点分类代替：社区结构在聚合那步被平均掉 |
| 结论要进举证流程 | 路径推理 + 规则 + 图查询 | 注意力/子图重要性解释 | 只给分数：进不了需要逐条复核的流程 |
| 实体持续新增、要出分数 | 归纳式 GNN + 图特征基线 | 转导式嵌入 + 特征查找服务 | 直接上转导式：新节点没有向量，且离线看不出来 |
| 跨片段多跳问答 | GraphRAG（KG + 向量双路） | 纯向量 + 长上下文 | 只上向量：多跳在结构上不可答 |
| 多任务、标签少、图分布接近公开语料 | 公开 GFM 骨干 + 微调 | 每任务从零训练 | 任务只有一两个时自建预训练摊不平（自建 GFM 的成熟度按 §5.1 记 L3） |
| 多模态信号要一起用 | 异构图 + 多模态嵌入 + GNN | 各路各自建模后融合 | 各路各自建模后融合：跨模态关系没有承载物，融合那一步只能靠特征拼接近似 |

1. **图推理 + 规则系统**：GNN 给出风险分，规则给出可解释证据，业务做最终审核。边界是**规则负责可解释与硬约束、GNN 负责在规则之外发现新模式**；风控反欺诈里常见的形态是规则占大头、模型概率分占小头，例如以「规则为主 + 模型概率分为辅」的量级划分起步（具体比例各组织差异很大，例如常被提到的「70% 规则 + 30% 模型分」应当读作该组织的经验值，而不是行业常数）【经验】。运维代价：两条通路的阈值要一起调，规则收紧会掩盖模型退化、模型放量会掩盖规则失效——**所以两者必须分别监控召回，否则一个的进步会被另一个的退步吃掉**。
2. **图推理 + 向量检索**：向量负责语义召回，图负责结构精排与解释，两路各自出候选后统一排序。边界是**向量覆盖「语义相近但图上不相连」、图覆盖「有关系但语义不同」**。运维代价：两套索引都要与主数据同步，融合权重需要长期维护；且两路的候选集不是同一时刻的快照，排序时要接受这一点。
3. **图推理 + LLM（GraphRAG）**：LLM 抽取实体关系建 KG，检索期用「向量 + 图查询」双路召回，LLM 组织答案并给出处。边界必须写死：**LLM 不负责凭空推理关系，只负责把问题翻译成查询、把结果讲成人话**。运维代价：索引期成本按新增文档量增长（7.4 的推算）；实体归一必须与主数据一致；LLM 版本更新会让答案分布变化，需要把版本纳入回归验证。
4. **图推理 + 数仓（OneData / OneID）**：数仓出 OneID 主数据与业务过程事件，图侧做实体对齐、边对齐与图推理。边界是**数仓负责实体与事件的口径、图负责关系的推理**。运维代价：图与数仓之间要有一条口径同步机制——**因为**图的每一条边本质上都是数仓里某个业务过程的投影，**所以**口径变更必须同时落到两侧，否则会出现「同一件事两边算法不同」的静默分叉（主文件 §1.3 已把这条列为向下衔接的关键定位点）。
5. **图推理 + 多模态**：图像 / 文本 / 表格 / 时间序列各出嵌入，汇成异构图后用 GNN 推理。边界是**各路负责把自己的模态编码成节点特征，图负责跨模态关系的推理**。运维代价：多模态嵌入的对齐质量直接决定图的可用性，且每种模态的更新节奏不同——**这会让「图的最新时间戳」这个数字失去单一含义**，必须按模态分别记录新鲜度。

**组合的共同原则**：每个组合都要能回答「哪一件负责事实、哪一件负责关系、哪一件负责判定」。**因为**关系的推理必须落在「事实已经被归一」的前提上（7.3.4），**所以**组合里必须有一个**唯一的主数据权威源**——它不是图，也不是模型，是 OneID 与 OneData 的口径；缺了它，多件组合会退化成「同一实体在几处各有一套表示」，而图的碎片化正是从这里开始的。

### 7.7 选错的代价与迁移成本

**反模式：在「关系不是信号」的场景硬上图** —— 为技术选型而建图，图建好了，离线指标与「图特征 + 梯度提升树」基线持平甚至略输 → **因为** GNN 的收益来自关系结构本身携带的信息，**所以**当度数、社区标签这类一阶统计已经覆盖了大部分区分度时，多出来的那部分收益要靠更长的迭代期与更重的推理链路去换，而它换不回来（[§3.5 反模式表](07-graph-reasoning-section-3-sec3.md) 把「GNN 一定能跑赢 XGBoost」列为三条最危险的展开之一；「最高频失效」这一措辞见 [§3.8 小结](07-graph-reasoning-section-3-sec3.md)）→ **正确做法**：建图之前先跑图特征基线（度、PageRank、社区标签、三角形计数），**基线赢不了就不上 GNN**；判断依据不是 GNN 与基线的差距，而是**结构信号本身有多强**——如果只把图特征喂给梯度提升树就能拿到大部分收益，剩下的差距不值得那条链路。

**反模式：用图库承接聚合统计** —— 图库上了以后，顺手把全表聚合、大范围统计也放进去，随后出现「这个报表要跑几分钟」→ **因为** 原生图存储为「沿关系跟随指针」优化，聚合要扫过的边数不受指针结构帮助，**所以**遍历与聚合对存储的要求是相反的，同一套存储不可能同时最优（7.3.1）→ **正确做法**：把两类查询拆开——**遍历归图库、聚合归列存或图计算引擎**，并在选型文档里把这条分工写死；缺了这条分工，图库会因为「什么都要查」而被判定为不合适，实际是用法问题（本目录 §6 的 Neo4j 案例把这条列为失败教训之一）【经验】（来源：本目录 §6 汇总的公开案例）。

**反模式：把实体归一当成工程细节** —— 图建起来了，但同一实体有几种写法，或两个团队画的图对不上、同一条边的语义各不相同 → **因为** 图上的多跳可达依赖「同一实体只有一种表示」，**所以**归一没做时图会碎成互不相连的孤岛，多跳在结构上退化成单跳——**表现是"加了图以后和纯向量检索持平"**；**又因为** 遍历不看边的语义叫什么，只看边存在，**所以**语义不一的边会让本来无关的实体被连上，风控名单里出现业务上不相关的对象，而团队会先去怀疑模型（[§3.5 反模式表](07-graph-reasoning-section-3-sec3.md) 的「图越大越好」与「图构建不规范」两条反模式）→ **正确做法**：实体归一必须与 OneID 口径一致；每一条边都要能说出它的语义、口径与生命周期，并在元数据中声明；**图是业务过程的图投影，所以图构建属于数据建模，不属于工程细节**。

**换成另一条路线要动什么**：

| 迁移方向 | 数据迁移 | 查询 / 模型改写 | 运维重建 | 团队再学习 | 工作量量级 |
| --- | --- | --- | --- | --- | --- |
| 数仓 → 图库（新增遍历能力） | 中：事实要重新组织成节点与边 | 中：多跳写成图查询，聚合留在数仓 | 中：新增图库与同步链路 | 图 schema 与查询语言 | 3–6 人月 |
| 向量检索 → GraphRAG | 大：要补实体抽取与实体归一 | 中：召回路径从一路变两路 | 大：新增索引期管线与出处维护 | 归一、出处链、双路融合 | 6–12 人月 |
| 转导式嵌入 → 归纳式 GNN | 中：特征服务要重建 | 大：训练范式与采样器全换 | 中：新增采样训练与在线特征 | 采样、fanout、归纳性评估 | 3–6 人月 |
| 节点分类 → 子图判别 | 中：标签要按整体重新给 | 大：判别单元换了，模型与评估都要重做 | 中：新增子图展开与检索 | 子图表示与匹配代价 | 3–9 人月 |
| 每任务从零训练 → 公开 GFM 骨干 + 微调 | 小：数据不动 | 中：下游改成微调任务头 | 中：骨干版本与统一回归 | 预训练与微调口径 | 3–6 人月 |
| 事后解释 → 路径 / 子图作为一等输出 | 小：图数据可复用 | 大：要新增路径查询与证据链接口 | 中：查询成本上升，超级节点要处理 | 路径爆炸与证据链裁剪 | 4–8 人月 |

> 量级按「一个熟悉本系统的 3–5 人小组」估算【经验】。按上表区间中值排序，最贵的一条是「向量检索 → GraphRAG」（中值 9.0 人月）：它要新建一条索引期管线，而这条管线里**最难的一步不是抽取，是实体归一**——归一是主数据问题，不是模型问题，所以它无法靠换一个更好的模型来加速。而真正「写入时就锁死、事后只能靠重建图来改」的是**图的 schema 与边语义**：它们不在上表的任何一行里，因为改它们的代价不是"迁移"，是"重建整张图"。这也解释了为什么「先把边语义与实体口径定清楚」比「先选一个图库」更值钱。

### 7.8 小结

| 你的处境 | 建议 | 关键理由（机制层面） |
| --- | --- | --- |
| 主要是过滤与聚合 | 列存 / 数仓 | 布局决定扫描量，遍历型存储在这里不给帮助 |
| 主要是语义相似 | 向量检索 + Embedding | 距离可直接算，不需要先造出关系 |
| 沿关系遍历、跳数会变 | 原生图存储 + 图算法 | 关系以指针存储，代价由结果集大小决定而非跳数 |
| 判别依据是整体形状 | 子图匹配 / 子图分类 | 建模单元与业务单元对齐，形状信息不会被邻域聚合平均掉 |
| 结论要逐条举证 | 路径推理 + 规则，另留模型通路 | 输出单元就是路径，人工可逐条复核；模型通路防覆盖率静默衰减 |
| 实体持续新增 | 归纳式 GNN + 图特征基线 | 邻居采样机制使新节点可直接打分；基线决定值不值得上 GNN |
| 跨片段多跳问答 | GraphRAG（双路召回 + 出处链） | 多一条「沿关系可达」的通路，不依赖语义巧合 |
| 知识库每天新增、查询稀疏 | 先不做图，用向量 + 关键词 | 索引期成本按新增文档量增长，查询稀疏时摊不平 |
| 多任务、标签少 | 公开 GFM 骨干 + 微调（先零样本比基线；自建预训练按 §5.1 记 L3） | 把「每任务一次训练」换成「一次预训练 + 多次微调」 |
| 边语义说不清 / 实体有几种写法 | 先停下来做归一与 schema | 多跳可达的前提是同一实体只有一种表示，缺了图就是孤岛 |
| GNN 指标与图特征基线持平 | 不要加深网络，先确认关系是不是信号 | 信息不在关系上时，加层只会增加采样量与过平滑风险 |
| 图上要防越权 | 把权限下推进遍历路径 | 应用层事后过滤挡不住"遍历过程中已经越权读到" |

> 本节小结：本节所比的十一族候选之间**唯一真正起决定作用的差异**是——**关系本身是不是信号，如果是，它承载在哪个最小单位上**。它一条就把全部候选切干净：关系不是信号，就只剩数仓与向量；信号在单节点邻域上，是 GNN 一族；在一条路径上，是路径推理；在一组实体的整体形状上，是子图匹配；在文本片段上，是 GraphRAG。**承载层的差异（存储与索引）只改变代价，建模与判定层的差异（规则 / 路径推理 / GNN / LLM）只改变结论能被复核到什么粒度**——它们都不是"谁更强"，而是"在哪个条件下、按哪条通路付费"。选型的正确顺序是：**先确认关系是不是信号（决定要不要建图）→ 再定信号的最小单位（决定模型）→ 最后才谈存储、可复核性与成本分配**。
>
