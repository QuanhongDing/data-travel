## 1. 概念与定位

### 1.1 是什么

**能力地图（Capability Model）** 在数据架构师语境下，特指**用结构化方法描述 AI 时代数据架构师应当具备的全部能力**，并把能力分层、分级、映射到可执行的成长路径。它回答三个核心问题：

- **学术定义**：源自人力资源管理（HRM）与能力素质模型（KSAO = Knowledge / Skills / Abilities / Others），由 McClelland（1973）的「胜任力运动」奠基。
- **工程定义**：在本项目里，能力 = 4 能力域 × N 等级 × 4 横线，是 [README](../../README.md) 中「目标画像」的细化拆解。
- **核心问题**：在 AI 重塑数据栈的速度下，如何让一个数据架构师的能力成长「可衡量、可比较、可指导」？

### 1.2 为什么需要

- **业务驱动力**：AI 时代数据栈迭代周期从年压缩到月，能力模型必须可更新、可对照。
- **典型痛点**：没有能力地图 → 招聘画像模糊、培训缺乏方向、晋升无标准、跨团队评估难对齐。
- **AI 时代新诉求**：Agent 平台要求架构师同时懂「数据语义」「模型能力」「工程化」三类技能，传统"懂数仓+懂 Hadoop"的画像已不够用。

### 1.3 在 AI 时代数据架构中的位置

```
       能力地图（本章）
              ↓ 映射
       4 能力域（基础 / AI 平台 / AI 应用 / 横切与软技能）
              ↓ 拆分
       8 任职要求 + 加分项
              ↓ 转化
       个人成长路径（Ch14 / 99-outro）
              ↓ 实施
       团队组建 + 绩效 + 晋升（Ch14）
```

| Ch99 后记 | 3-5 年能力演化方向 + 资深架构师的成长建议 |

### 1.4 演进历程

- **传统阶段（1990s–2010s）**：以 ETL / 数据仓库为核心，能力 = SQL + 数据建模 + Hadoop。
- **大数据阶段（2010s–2020）**：Lambda / Kappa 架构 + 实时计算，能力增加 Flink / Kafka / Spark。
- **AI 原生阶段（2020+，LLM + Agent 驱动）**：能力 = 数据语义 + LLM / RAG / Agent 工程 + MLOps + 治理 + 跨团队叙事。能力模型必须"可被 AI 增强但不被 AI 替代"。

## 2. 核心原理

### 2.1 关键概念定义

| 概念 | 定义 | 一句话解释 |
| --- | --- | --- |
| **能力域（Capability Domain）** | 一类相互关联、可独立成型的能力集合 | 本书 4 域：基础 / AI 平台 / AI 应用 / 横切与软技能 |
| **横切线（Cross-cutting Line）** | 跨能力域都需要的能力 | 可治理 / 可观测 / 可计量 / 可演进 |
| **等级（Level）** | 能力的高低分级 | P5→P6→P7→P8 / 2-1→2-2→3-1 / L6→L7→L8 |
| **画像（Profile）** | 一个岗位的典型能力组合 | "AI 平台架构师画像" = 4 域中 3 域强 + 1 域合格 |
| **路径（Path）** | 从当前等级到目标等级的成长路线 | 见 [Ch99 成长建议](../../99-outro/02-growth-advice/02-growth-advice.md) |
| **KSAO** | Knowledge / Skills / Abilities / Others | 经典能力素质四元组 |
| **T 型人才** | 一专多能 | 1 个领域深入 + 多领域了解 |
| **π 型人才** | 两专多能 | 2 个领域深入 + 多领域了解，AI 时代更倾向此型 |
| **能力成熟度（Capability Maturity）** | 从 L1 初始级到 L5 优化级 | 借鉴 CMM / DMM |

### 2.2 数学 / 形式化基础

能力地图可被形式化为**多维矩阵 M(C, L, S)**：

```
M ∈ R^(4 能力域 × 4 等级 × N 子能力)
其中 C ∈ {基础, AI平台, AI应用, 横切与软技能}
     L ∈ {初级, 高级, 资深, 专家}
     S = 评分 ∈ [0, 5]
```

一个画像定义为 P = (C, L, S) 向量集合，路径规划 = 在 M 上求最优移动路径。

### 2.3 关键方法 / 框架

- **McClelland 胜任力冰山模型**：知识 / 技能在水上，自我概念 / 特质 / 动机在水下。
- **SFIA（Skills Framework for the Information Age）**：国际通用的 IT 能力框架，7 级。
- **DAMA-DMBOK 数据管理知识体系**：数据治理领域的事实标准。
- **DMM（Data Maturity Model）**：CMMI 协会的数据管理成熟度模型，5 级。

### 2.4 与相邻概念的关系

| 相邻概念 | 与能力地图的关系 |
| --- | --- |
| 招聘画像（Job Description） | 能力地图 → 招聘画像的下游产物 |
| 培训路径（Learning Path） | 能力地图 → 培训路径的输入 |
| 绩效评估（Performance Review） | 能力地图 → 绩效标准的来源 |
| 薪酬带宽（Comp Band） | 能力地图 → 薪酬级别对齐 |

## 3. 设计模式与范式

### 3.1 主要模式

- **3 维能力矩阵**：能力域 × 等级 × 子能力 — 最常见的组织形式。
- **画像组合法**：从若干标准画像中"组合"出实际岗位 — 例如 "数据 + AI + 工程" → Agent 平台架构师。
- **能力差距图（Gap Analysis）**：当前能力 vs 目标能力 → 培训 / 招聘 / 晋升的输入。
- **O*NET 网络版**：美国劳工部 O*NET 数据库，提供 1000+ 岗位的能力画像。

### 3.2 适用场景决策表

| 场景 | 推荐模式 |
| --- | --- |
| 大厂（5+ 团队） | 3 维矩阵 + 自研能力云 |
| 创业公司（5-50 人） | 简化画像 + 灵活组合 |
| 跨 BU 协作 | 能力差距图 + 共享画像 |
| 个人成长 | O*NET / SFIA 对照 + 自我评估 |

### 3.3 反模式与陷阱

- **画像复制**：直接照搬 Google / Netflix 画像，忽视自身业务阶段。
- **能力过载**：把画像做得太大，要求"既懂数仓又懂 LLM 又懂前端又懂产品"，招不到人。
- **静态模型**：一年不更新，画像与实际需求脱节。

## 4. 工程实现

### 4.1 落地步骤

1. **画岗位画像**：列出 4 域中每域的目标等级。
2. **拆解子能力**：每域拆出 3-5 个子能力，每子能力可独立评估。
3. **定义行为锚点（Behavior Anchor）**：每个等级配 2-3 个可观察的行为。
4. **建立评估机制**：招聘 / 晋升 / 培训中嵌入能力评估。
5. **定期迭代**：每 6 个月根据业务变化重审。

### 4.2 关键技术点

- **画像卡片模板**：建议字段 = 画像名 / 4 域目标等级 / 关键子能力 / 招聘画像 / 晋升标准 / 培训路径。
- **能力云（Capability Cloud）**：用内部工具（如 Workday / 自研 HRIS）维护画像。
- **自评 + 同事评 + 上级评三方评估**：每个子能力 0-5 分。
- **能力发展 IDP（Individual Development Plan）**：针对低分项，6 个月可执行的提升计划。

### 4.3 工具链与平台

- **SFIA 官方工具**：sfia.org 提供参考画像。
- **LinkedIn Talent Insights**：外部市场能力画像参考。
- **DAMA / IIBA 官方资料**：DMBOK / BABOK 知识体系。
- **自研 HRIS**：阿里 / 字节 / 美团 / 腾讯的内部能力云系统。

### 4.4 代码 / 配置示例

```yaml
# capability_model.yaml — 4 域 × 4 级（P5-P8）的能力地图
domains:
  - name: 基础（数据基础域）
    levels:
      P5: 独立完成 ODS/DWD 建模
      P6: 主导 1 个主题域建模
      P7: 主导全链路 + 湖仓一体
      P8: 主导跨 BU 数据架构
  - name: AI 平台（AI 平台域）
    levels:
      P5: 熟悉 LLM API + Embedding
      P6: 主导 RAG / Agent 平台
      P7: 主导大模型选型 + Agent 演进
      P8: 主导企业级 AI 平台 0→1
  - name: AI 应用（AI 应用域）
    levels:
      P5: 熟悉 Prompt 工程
      P6: 主导智能体业务落地
      P7: 主导 AI 产品方法论
      P8: 主导企业 AI 战略
  - name: 横切与软技能
    levels:
      P5: 能完成被分配任务
      P6: 能独立推动跨团队
      P7: 能影响跨 BU 决策
      P8: 能定义行业级实践
```

## 5. 前沿演进（AI 时代）

### 5.1 LLM / Agent 时代的演进方向

- **能力可被 AI 增强**：CRUD 类能力 → 「会用 AI 工具」即可；架构设计 → 「能用 AI 辅助决策」即可。
- **能力不可被 AI 替代**：跨团队叙事 / 业务翻译 / 价值观判断 / 风险权衡 — 这些「人味儿」能力反而更值钱。
- **画像动态化**：基于项目经历 + 代码提交 + 文档贡献的"实时画像"，由 LLM 辅助生成。

### 5.2 与 RAG / 向量库 / GraphRAG 的结合

- 能力画像可存为向量，结合项目经历做"智能画像助手"。
- 招聘场景：JD → 自动匹配候选人画像 → 给出面试问题建议。
- 内部晋升：项目经历 + 文档贡献 → 自动评估各域子能力。

### 5.3 学术与工业最新进展（2024-2025）

- **Skills-based organizations (SBO)**：替代传统职级体系，GitLab / Valve 等公司已实践。
- **AI-Augmented Career Coaching**：Anthropic / OpenAI 已发布 Career Coach Agent。
- **动态能力评估 (Dynamic Skill Graph)**：LinkedIn 2024 年发布的 Economic Graph 能力子图。

### 5.4 未来 3-5 年趋势

- 传统职级体系（P5-P8）将与 Skills-based 体系并存。
- 能力评估由 LLM 辅助，但最终决策权在管理者。
- "能力元数据"（每个工程师的画像 = 文档/代码/项目的向量化表示）成为企业的核心资产。

## 6. 落地实践

### 6.1 真实案例

- **阿里 P 序列**：技术 P + 管理 M 双通道；评估基于 361 强制分布。
- **字节 2-1 到 4-1**：技术 6 级 + 职级 4 段；评估基于 OKR + 360 评估。
- **美团 L6-L9**：4 级技术通道；L8/L9 是资深架构师，对应本项目目标画像。
- **Netflix P-Track**：Senior / Staff / Senior Staff / Principal / Distinguished 5 级。

### 6.2 踩坑与经验

- **画像滞后**：业务快速变化时画像来不及更新 → 每 6 个月重审。
- **画像过细**：100+ 子能力 → 评估成本爆炸 → 控制在 30-50 个子能力。
- **评估主观**：同级评估的分数差异大 → 引入「行为锚点」+ 跨级校准。

### 6.3 落地路径

- **小型团队（5-20 人）**：直接用 SFIA 7 级框架 + 1 套画像模板。
- **中型团队（20-100 人）**：自研能力云（Notion / 飞书多维表格），3 域画像。
- **大型组织（100+ 人）**：3 维矩阵 + HRIS 系统 + 能力评估委员会。

### 6.4 ROI 评估

- **正向**：招聘匹配度提升 20-30%，培训精准度提升 30%，晋升争议减少 50%。
- **风险**：维护成本（HR + Tech Lead 季度评审），每年约 0.5-1 FTE。

## 7. 与其他方法对比

### 7.1 对比维度

| 维度 | SFIA | O*NET | DAMA DMBOK | 自研能力地图 |
| --- | --- | --- | --- | --- |
| 覆盖范围 | IT 通用 | 全行业 | 数据领域 | 公司定制 |
| 等级粒度 | 7 级 | 5 级 | 11 知识域 | 灵活 |
| 维护成本 | 低（标准） | 低 | 低 | 高 |
| 适配性 | 中 | 低 | 中 | 高 |

### 7.2 决策树

- 通用 IT 团队 → SFIA
- 数据治理优先 → DAMA DMBOK
- AI 优先 → 自研 + 持续迭代
- 跨行业招聘 → O*NET

### 7.3 组合使用

- **SFIA + DAMA**：通用 IT 能力 + 数据领域能力。
- **O*NET + 自研**：外部市场画像参考 + 内部定制。
- **DAMA + 自研**：行业标准 + 公司战略。

> 💡 **思考锚点**：数一下你团队当前能力画像的子能力数量——如果已越过「100+ ≈ 评估成本爆炸」这一档，按本节给出的 30-50 目标区间回退，你准备先合并哪几个域，把每年 0.5-1 FTE 的维护预算压到什么水平？

### 8.2 分主题展开

#### 序.1 资深数据架构师与高级数据工程师的核心差异是什么？请用能力地图语言回答。

**1. 考察点**：是否理解从「写代码」到「设计体系」的能力跃迁。

**2. 参考答案框架**
- **第一层：行为差异**：高级写 SQL / 调性能，资深写架构 / 培养人。
- **第二层：能力域差异**：高级 P5-P6，资深 P7-P8，4 域均强。
- **第三层：思维差异**：高级是"解决具体问题"，资深是"防止一类问题"。

**3. 常见陷阱**：只答"经验多几年"（不对，能力是结构化差异）。

**4. 追问预测**：横向扩（多域）与纵向深（一域）哪个更重要？

**5. 参考资料**：DAMA DMBOK 第 1 章 / SFIA 7 级框架 / 阿里 P 序列公开介绍。

---

#### 序.2 AI 时代数据架构师最容易被替代的能力是什么？最不可被替代的是什么？

**1. 考察点**：是否理解 AI 时代的能力重构。

**2. 参考答案框架**
- **易被替代**：写 ETL、调 SQL、画 ER 图 — 这些可由 LLM 辅助完成。
- **部分替代**：架构选型 — LLM 给出建议，但需人类最终判断。
- **不可替代**：跨团队叙事 / 业务翻译 / 价值观权衡 / 风险判断。

**3. 常见陷阱**：把所有能力都说成不可替代（自吹）或所有都易被替代（焦虑）。

**4. 追问预测**：未来 3 年画像会怎么变？

**5. 参考资料**：Anthropic / OpenAI 关于 AI 与就业的公开报告。

---

#### 序.3 你认为本书目标画像中哪一项最被低估？为什么？

**1. 考察点**：是否对画像有批判性思考。

**2. 参考答案框架**（开放题）
- 候选人最常回答：「跨团队叙事」/「业务翻译」/「价值观权衡」。
- 关键：能给出具体场景 + 真实案例，而非泛泛而谈。

**3. 常见陷阱**：只答"软技能"没有具体场景。

**4. 追问预测**：如何补足被低估的能力？

**5. 参考资料**：Ch14 团队管理章节 / 99-outro 成长建议。

### 8.3 本章小结

能力地图是数据架构师成长的"GPS"：没有它，成长是盲目的；只有它，成长是可量化、可迭代的。AI 时代的能力地图必须**每 6 个月重审**——画像越动态，越能跟上工具迭代。
