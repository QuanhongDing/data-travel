## 1. 背景

### 1.1 公司 / 业务 / 时间

字节跳动（ByteDance）成立于 2012 年 3 月，至今 14 年。数据架构演进的关键时间节点：

- **2012–2014：今日头条起步**。第一版推荐系统 + 数据栈，MySQL + Hadoop 为主。
- **2015：AB 实验平台 V1**。今日头条是字节第一个大规模 AB 实验的产品，2015 年正式建平台。
- **2016：抖音上线**。短视频推荐对实时计算要求极高。
- **2017：ByteHouse 立项**。基于 ClickHouse 自研改造，针对字节场景优化。
- **2018：DataLeap 立项**。数据集成 + 数据开发 + 数据治理的统一工作台。
- **2019：火山引擎成立**。字节 ToB 商业化平台正式成立，数据中台对外销售。
- **2020：Lakehouse 实践**。基于 Iceberg + Spark/Flink 的湖仓一体架构。
- **2021：Feature Store 平台化**。字节特征平台化，覆盖推荐 / 广告 / 搜索。
- **2022：抖音电商发力**。电商对实时数仓 + 实时推荐 + 实时风控提出新要求。
- **2023：豆包大模型发布**。字节大模型入场，数据栈向 AI Native 演进。
- **2024：Coze（扣子）智能体平台发布**。智能体应用爆款，数据中台成为"AI 中台"。
- **2025：豆包 1.5 Pro + 多模态**。大模型全面赋能业务。

**业务特点**：

- **多 App 矩阵**：今日头条、抖音、西瓜视频、番茄小说、剪映、CapCut、TikTok、Lemon8、PICO 等 20+ App。
- **算法驱动**：推荐算法是核心竞争力，AB 实验是验证算法的唯一手段。
- **全球化**：TikTok 全球月活 15 亿+，数据合规要求跨多个法域。
- **数据规模**：抖音日活 7 亿+，每天产生 PB 级数据。

### 1.2 行业与监管

- **内容行业**：内容审核、合规、版权、青少年保护等强监管。
- **金融**：抖音支付、合规要求严格。
- **跨境监管**：TikTok 在美国、欧盟、东南亚多国运营，需要符合 GDPR / COPPA / CCPA 等多法规。

### 1.3 团队规模与组织

- **字节数据团队**巅峰期约 **3000+ 人**。
- **数据平台部**（基础平台）：约 500+ 人，负责 ByteHouse / DataLeap / AB 平台。
- **应用数据团队**：约 1500+ 人，分散在抖音 / 电商 / TikTok / 商业化 / 游戏。
- **算法工程师**：约 3000+ 人，与数据团队紧密协同。
- **组织文化**：**"始终创业"** + **"数据驱动"** + **"AB 实验优先"**。

## 2. 挑战

### 2.1 业务挑战

#### 2.1.1 多 App 数据打通

字节有 20+ App，每个 App 数据栈独立建设，"用户、内容、关系"等核心数据需要打通——OneID 需求强烈。

#### 2.1.2 推荐系统的实时性

抖音推荐延迟 < 200ms，AB 实验流量分配延迟 < 1 秒，这对实时计算 + 实时数仓要求极高。

#### 2.1.3 数据规模爆炸

抖音日活 7 亿+，单日用户行为数据 TB 级，单日推荐请求百亿级，存储成本与计算成本压力巨大。

#### 2.1.4 AB 实验的"小步快跑"

字节内部产品迭代极快（"AB 实验每天 1000+ 个"），对 AB 平台的要求是"分钟级启动、亿级流量稳定分流"。

### 2.2 技术挑战

#### 2.2.1 多模数据

抖音 / TikTok 是视频流，需要处理**视频、音频、文本、图片**多模态数据，对象存储 + CDN + AI 推理栈要求高。

#### 2.2.2 实时计算复杂度

推荐系统延迟 < 200ms，需要"**用户行为 → 实时特征 → 模型推理 → 推荐结果**"全链路实时。

#### 2.2.3 数据合规

TikTok 面临全球多法域合规，**GDPR（欧洲）、CCPA（加州）、COPPA（儿童）**等要求数据本地化、用户删除权。

#### 2.2.4 算法工程化

字节有 3000+ 算法工程师，每个工程师都有自己的模型、特征、AB 实验。如何**让算法工程化**——特征共享、模型共享、AB 平台共享——是核心挑战。

### 2.3 组织挑战

#### 2.3.1 AB 实验文化

字节"AB 实验优先"的文化渗透到每个角落，任何产品决策都需要 AB 验证。这要求所有产品经理 / 工程师都必须会用 AB 平台。

#### 2.3.2 数据驱动决策

字节内部不允许"凭经验决策"——必须用数据说话。这要求**数据查询速度**必须快（自助分析），否则无法驱动决策。

#### 2.3.3 全球化数据团队

TikTok 全球运营需要全球多区域数据团队，跨语言、跨时区、跨法规协同难度大。

> 💡 **思考锚点**：把你自己的组织往 §2 的三类挑战上套——你有几个「App / 业务线」要打通（字节是 20+），你的决策 / 推荐链路延迟要求是多少毫秒（抖音是 < 200ms、AB 分流 < 1 秒），你的日活与单日请求量落在哪个量级（字节是 7 亿日活、百亿级推荐请求）？三个数里，哪一个先把你「各建各的」这条路堵死？
