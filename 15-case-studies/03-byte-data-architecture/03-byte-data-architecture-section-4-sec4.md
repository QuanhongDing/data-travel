## 4. 关键决策

### 4.1 决策 1：为什么 ClickHouse 而不是 Hive / Spark？

**背景**：2017 年字节推荐场景需要毫秒级 OLAP 查询，Hive / Spark 延迟秒级，ClickHouse 延迟毫秒级。

**决策路径**：

- **方案 A：Hive / Spark**：SQL 兼容、生态成熟。
  - 优点：开发成本低。
  - 缺点：延迟高。
- **方案 B：Presto / Impala**：MPP 架构。
  - 优点：相对快。
  - 缺点：并发能力有限。
- **方案 C（最终选择）：ClickHouse + 自研改造**（ByteHouse）。
  - 优点：延迟毫秒级，并发能力强。
  - 缺点：运维复杂、SQL 兼容性差、生态弱。

**Trade-off**：

| 维度 | ClickHouse | Hive / Spark |
| --- | --- | --- |
| 查询延迟 | 毫秒级 | 秒级 |
| SQL 兼容性 | 差 | 好 |
| 生态 | 弱 | 强 |
| 运维 | 复杂 | 一般 |
| 成本 | 低 | 高 |

**决策**：基于 ClickHouse 自研 ByteHouse。

**验证**：ByteHouse 2024 年承载字节 90%+ OLAP 查询，是火山引擎核心商业产品。

### 4.2 决策 2：AB 实验平台怎么设计？

#### 4.2.1 流量分桶

```
User ID → Hash(User ID) → Bucket 0-9999
Experiment → 100 流量 → Bucket 1000-2000
```

#### 4.2.2 互斥分层

不同实验层互斥，**避免实验相互干扰**：

- **Layer 1：推荐算法**（互斥）
- **Layer 2：UI 样式**（互斥）
- **Layer 3：广告策略**（互斥）

#### 4.2.3 流量调拨

支持把"未分配的流量"动态调拨到"高优先级实验"。

#### 4.2.4 显著性检验

- **P-value 计算**：自动计算显著性。
- **置信区间**：自动计算指标置信区间。
- **早停**：支持"达到显著性后自动停止实验"。

#### 4.2.5 关键技术

- **哈希分流**：基于用户 ID + 实验 ID 的稳定哈希。
- **实时分流**：RPC 调用毫秒级决策。
- **流量回放**：录制历史流量回放分析。
- **统一指标**：所有实验接入统一指标平台。

### 4.3 决策 3：DataLeap 怎么设计？

**DataLeap 是字节的数据开发平台**，对标阿里 DataWorks：

#### 4.3.1 核心模块

- **数据集成**：DataX 字节版（基于 Flink CDC + Spark）。
- **数据开发**：可视化 DAG + Spark/Flink 任务。
- **数据治理**：数据地图 + 血缘 + 质量监控。
- **数据服务**：OneAPI（数据服务网关）。

#### 4.3.2 关键能力

- **可视化开发**：拖拽即可完成数据集成 / 数据开发。
- **智能优化**：自动识别慢 SQL、自动优化 Spark 任务。
- **数据质量**：自动监控、告警。
- **一键回滚**：任务失败一键回滚。

### 4.4 决策 4：实时推荐架构怎么设计？

#### 4.4.1 抖音实时推荐链路

```
[用户行为] → [Kafka] → [Flink] → [特征存储] → [模型推理] → [推荐结果]
   (实时)    (毫秒)    (毫秒)    (毫秒)        (毫秒)       (毫秒)
```

**端到端延迟 < 200ms**。

#### 4.4.2 实时特征类型

- **行为特征**：最近 1 分钟点击、加购。
- **画像特征**：年龄、性别、地域。
- **场景特征**：时段、节日、热点。
- **物品特征**：商品属性、视频属性。

#### 4.4.3 实时特征平台

- **字节特征平台**：基于 Redis + ClickHouse + 自研 KV 混合存储。
- **特征血缘**：每个特征可追溯到上游 DWD 表。
- **特征回填**：支持历史时间点特征回填（用于模型训练）。

### 4.5 决策 5：推荐中台怎么搭？

#### 4.5.1 推荐中台能力

- **召回引擎**：向量召回 + 倒排索引 + 知识图谱。
- **粗排**：轻量模型快速过滤。
- **精排**：深度模型精细排序。
- **重排**：业务规则调整（去重、多样性）。

#### 4.5.2 多业务复用

抖音 / 今日头条 / 西瓜视频 / TikTok 都复用同一套推荐中台，业务方只需：

- 准备训练数据。
- 选择模型（系统提供 10+ 种）。
- 一键部署。

#### 4.5.3 效果

- 推荐中台覆盖 100%+ 业务方。
- 算法工程师无需重复造轮子，专注于业务。

### 4.6 决策 6：大模型 + 数据中台

#### 4.6.1 数据栈 AI 化

- **数据 → 训练数据**：OneID 自动生成训练数据。
- **特征 → 模型特征**：Feature Store 直接对接训练。
- **指标 → 评估指标**：指标平台自动计算模型评估指标。
- **AB → 模型评估**：AB 平台自动评估大模型效果。

#### 4.6.2 扣子（Coze）智能体平台

- **Coze Studio**：智能体应用开发平台。
- **Coze 商店**：智能体应用商店。
- **Coze API**：模型托管 + 推理 API。
- **2024 年爆款**：扣子成为字节 AI 应用入口。

#### 4.6.3 豆包大模型

- **豆包通用模型**：对标 GPT-4 / Claude 3.5。
- **豆包视觉模型**：视频理解、图像理解。
- **豆包语音模型**：语音识别、合成。
- **豆包多模态**：跨模态理解。

### 4.7 决策 7：火山引擎 ToB 怎么做？

#### 4.7.1 产品策略

- **不做基础设施**（不抢阿里云、AWS 的市场）。
- **不做操作系统**（不抢华为鸿蒙的市场）。
- **做应用 PaaS**（基于字节内部能力：推荐、AB、视频、AI）。

#### 4.7.2 核心产品

- **智能推荐**：基于字节抖音、今日头条的推荐能力。
- **A/B 测试**：基于字节内部 AB 平台。
- **ByteHouse**：公有云 OLAP。
- **DataFinder / DataLeap / DataWind**：数据中台套件。
- **豆包大模型 + 一站式 AI 服务**。

#### 4.7.3 商业化效果

- 2024 年火山引擎营收数百亿元（字节 ToB 业务核心增长点）。
- 客户：小米、京东、长安汽车、中国移动等头部企业。
