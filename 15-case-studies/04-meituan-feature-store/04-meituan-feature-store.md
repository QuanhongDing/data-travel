## 1. 背景

### 1.1 公司 / 业务 / 时间

美团成立于 2010 年，至今 15 年。特征平台演进的关键时间节点：

- **2010–2014：千团大战 + 美团起步**。早期数据栈为 MySQL + Hadoop，特征散落在各团队。
- **2015：外卖业务崛起**。美团外卖成为核心业务，特征需求爆发（用户特征、商户特征、配送特征）。
- **2016：酒店旅游 + 到店业务**。新业务带来新的特征需求。
- **2017：美团 ML 平台 V1 立项**。开始系统化建设特征平台。
- **2018：Feature Store V1 上线**。覆盖外卖推荐、广告投放。
- **2019：Feature Store V2 升级**。支持实时特征 + 特征血缘。
- **2020：Feature Store 全面覆盖推荐 / 搜索 / 广告 / 风控**。
- **2021：ML 平台 V3 改造**。与 Lakehouse 架构对齐。
- **2022：美团 ToB 商业化**。美团零售 + 美团企业版对外输出。
- **2023：特征平台 + 大模型融合**。支持 LLM 训练数据管理。
- **2024：美团 ML 平台与教育认证**。

**业务特点**：

- **多业态协同**：外卖、到店餐饮、酒店旅游、电影、买菜、闪购、共享单车、共享汽车。
- **超大规模**：外卖日单量 7000 万+（峰值），商户 1000 万+，骑手 700 万+。
- **强实时**：推荐延迟 < 100ms，配送调度延迟 < 1 秒。
- **多端联动**：C 端用户 + B 端商户 + 配送骑手三方联动。

### 1.2 行业与监管

- **本地生活行业**：商家准入、消费者权益、配送员权益。
- **金融业务**：美团支付 / 美团金融，合规要求严格。
- **数据合规**：《数据安全法》、《个人信息保护法》。
- **等保 2.0 / 3.0**：合规要求。

### 1.3 团队规模与组织

- **美团数据团队**巅峰期约 **2000+ 人**（量级表述，按【经验】档处理；此处计的是**美团数据团队的巅峰期规模**，本书其它章节若出现更小的数字，多为**特定业务线或特定年份**的口径，引用时请带上主语与年份）。
- **数据平台部**（基础平台）：约 300+ 人。
- **ML 平台团队**：约 200+ 人（核心团队）。
- **业务算法团队**：约 3000+ 人（与数据团队紧密协同）。
- **组织文化**：**"以客户为中心"** + **"技术驱动业务"**。

## 2. 挑战

### 2.1 业务挑战

#### 2.1.1 多业务特征复用难

美团有外卖、到店、酒店、旅游、电影、买菜、闪购等 10+ 业务，每个业务都有自己的特征团队（"特征生产高度重复"是当时的核心痛点）。

#### 2.1.2 实时特征复杂度高

外卖推荐需要"实时特征"——用户最近 1 分钟点击、最近 5 分钟加购、骑手当前位置、商户当前出餐速度。**实时特征延迟 < 1 秒**，否则推荐效果断崖式下降。

#### 2.1.3 特征一致性难题

**训练时用离线特征，推理时用在线特征**，二者往往不一致（"训练 - 推理偏差" / "Train-Serving Skew"）。这是 ML 工程化的头号难题。

#### 2.1.4 特征血缘难以追溯

业务方想知道"这个特征从哪来？怎么计算？覆盖度如何？"，但特征散落在各团队，**血缘关系复杂**。

### 2.2 技术挑战

#### 2.2.1 海量特征管理

美团有 **10 万+ 个特征**，分布在推荐 / 搜索 / 广告 / 风控 / 配送 / 调度 / 客服 / 营销等多个场景。如何管理？

#### 2.2.2 高 QPS 在线服务

外卖推荐 QPS 数十万级，特征服务必须支撑**毫秒级延迟 + 高并发**。

#### 2.2.3 多源异构数据

特征来源包括：MySQL（用户基本信息）、Kafka（用户行为）、Hive（离线 DWD）、Redis（实时缓存）、日志（用户行为流）——**特征计算横跨多种数据源**。

#### 2.2.4 特征回填

训练数据需要"任意时间点的特征"——比如"用户 2024-01-01 12:00 的特征"，必须能回填。

### 2.3 组织挑战

#### 2.3.1 跨团队协作

美团算法工程师分散在 30+ 个业务团队，每个团队都有自己的特征生产代码。如何让大家都用同一套平台？

#### 2.3.2 平台 vs 业务边界

平台团队提供"通用特征能力"，但业务团队经常有"特殊需求"。如何平衡？

#### 2.3.3 投入 vs 收益

特征平台建设投入大，但短期收益不明显——业务团队看不到价值，平台团队被质疑"过度设计"。

> 💡 **思考锚点**：把美团这四个痛点对到你自己的现状——§2.2.1 的 10 万+ 特征量级、§2.1.2 的「实时特征 < 1 秒」门槛、§2.1.3 的训练-推理偏差、§2.2.4 的任意时间点回填。你的特征体量落在哪一档？如果连「任意时间点回填」都还答不出，那 §2.3.3 里那条「投入大、短期看不见收益」的质疑，是不是正因为连最容易量化的复用率你都还没测？
