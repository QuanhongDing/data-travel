## 6. 复用经验

### 6.1 适合谁学

#### 6.1.1 强 ML 需求的企业

- **典型**：电商、金融、内容、广告、社交。
- **原因**：Feature Store 是 ML 工程化的核心基础设施。

#### 6.1.2 多业务线协同

- **典型**：平台型公司、生态型企业。
- **原因**：特征跨业务复用价值巨大。

#### 6.1.3 实时决策场景

- **典型**：外卖、出行、推荐、调度、风控。
- **原因**：实时特征是核心竞争力。

#### 6.1.4 数据规模大

- **典型**：日活 1000 万+、订单 100 万+。
- **原因**：小规模不值得做 Feature Store。

### 6.2 不适合谁学

#### 6.2.1 数据规模小的初创公司

- **反例**：日活 < 10 万 的初创公司。
- **原因**：特征数量 < 1000，Excel / 文档管理即可。

#### 6.2.2 弱 ML 需求的业务

- **反例**：传统 OA、企业内部系统。
- **原因**：基本不用 ML，不需要 Feature Store。

#### 6.2.3 业务流程复杂但 ML 应用少的业务

- **反例**：传统金融的核心交易系统。
- **原因**：规则引擎主导，不需要 ML。

### 6.3 关键可复用资产

#### 6.3.1 开源 Feature Store

- **[Feast](https://feast.dev/)**：最流行的开源 Feature Store。
- **[Tecton](https://www.tecton.ai/)**：商业版 Feature Store（基于 Feast）。
- **[Hopsworks](https://www.hopsworks.ai/)**：开源 + 商业。
- **[Databricks Feature Store](https://www.databricks.com/product/feature-store)**：Databricks 一体化方案。

#### 6.3.2 关键技术

- **离线特征计算**：Hive / Spark / Iceberg。
- **实时特征计算**：Flink / Kafka / Redis。
- **特征服务**：自研 RPC / gRPC + Redis。
- **特征血缘**：基于图数据库。
- **特征回填**：基于 Spark SQL 重跑。

#### 6.3.3 美团 ML 平台核心

- **DataFinder**：数据集成。
- **Feature Store**：特征平台。
- **PAI**：模型训练与部署。
- **AB 平台**：A/B 测试。
- **Serving**：在线服务。
