## 4. 关键决策

### 4.1 决策 1：Feature Store 核心架构

#### 4.1.1 三大组件

```
[特征生产（Producer）] → [特征存储（Storage）] → [特征消费（Consumer）]
```

- **特征生产**：
  - **离线特征**：基于 Hive / Spark SQL 跑批。
  - **实时特征**：基于 Flink / Kafka 流处理。
  - **请求服务**：基于原始数据按需计算（如实时查询用户当前 LBS）。

- **特征存储**：
  - **离线存储**：Iceberg / Hive 表。
  - **在线存储**：Redis + 自研 KV 存储。
  - **向量存储**：Milvus / Faiss（用于 embedding 检索）。

- **特征消费**：
  - **训练消费**：从离线表读取，生成训练样本。
  - **在线消费**：从在线 KV 读取，用于推理。
  - **回填消费**：从离线 + 在线混合读取，用于回填。

#### 4.1.2 关键技术

- **统一特征 Schema**：每个特征有"特征名 + 特征类型 + 特征计算逻辑 + Owner + 版本"。
- **特征注册中心**：所有特征先注册后使用。
- **特征版本管理**：支持 v1 / v2 / v3 多版本并存，平滑过渡。

### 4.2 决策 2：实时特征怎么实现？

#### 4.2.1 实时特征分类

- **行为实时特征**：用户最近点击、加购、下单（基于 Flink / Kafka）。
- **画像实时特征**：用户当前位置、商户当前出餐速度（基于 RPC + Redis）。
- **场景实时特征**：当前时段、天气、热点（基于规则 + 实时计算）。
- **设备实时特征**：设备电量、网络状态（基于客户端 SDK）。

#### 4.2.2 实时特征实现

```
[用户行为] → [Kafka] → [Flink] → [Redis / 自研 KV] → [在线服务]
   (毫秒)    (毫秒)    (毫秒)    (毫秒)        (毫秒)
```

**关键技术**：

- **Flink State**：用于维护"用户最近行为窗口"。
- **Redis Sorted Set**：用于存储"时间窗口内的行为"。
- **自研 KV 存储**：用于存储"用户画像实时特征"。

#### 4.2.3 实时特征 SLA

- **延迟 SLA**：< 1 秒。
- **可用性 SLA**：99.99%。
- **准确性 SLA**：覆盖率 > 99%。

### 4.3 决策 3：特征回填怎么实现？

#### 4.3.1 回填场景

- **训练数据准备**：生成"用户 2024-01-01 12:00 的特征"用于训练。
- **A/B 实验后评估**：评估"实验组用户在 2024-01-01 的特征分布"。
- **离线模型调试**：调试模型时需要历史特征。

#### 4.3.2 回填架构

```
[历史 DWD 表] → [Spark / Hive] → [特征计算 SQL] → [回填特征表]
```

#### 4.3.3 关键技术

- **特征计算 SQL 化**：所有特征都用 SQL 定义，离线 + 在线复用同一份 SQL。
- **时间窗口支持**：特征计算支持任意时间窗口。
- **回填调度**：美团 Dolphin 调度系统（基于 Airflow 改造）。

### 4.4 决策 4：特征血缘怎么实现？

#### 4.4.1 血缘层次

```
[源表] → [DWD] → [特征计算 SQL] → [特征注册] → [模型应用]
```

- **源表层**：MySQL / Kafka / OSS。
- **DWD 层**：基于源表清洗的明细表。
- **特征计算层**：基于 DWD 计算特征。
- **特征注册层**：特征注册中心。
- **模型应用层**：模型使用特征。

#### 4.4.2 血缘采集

- **自动解析 SQL**：从特征计算 SQL 自动解析血缘。
- **血缘存储**：基于图数据库（GDB / Neo4j）。
- **血缘展示**：可视化工具展示血缘。

#### 4.4.3 血缘应用

- **影响分析**：上游表变更影响哪些特征、哪些模型。
- **溯源分析**：模型效果下降，溯源到特征质量。
- **数据治理**：发现重复特征、孤儿特征。

### 4.5 决策 5：特征质量监控怎么实现？

#### 4.5.1 监控维度

- **延迟监控**：特征生产延迟（P50 / P99 / P999）。
- **覆盖率监控**：特征覆盖率（应该有的样本中，实际有的比例）。
- **分布监控**：特征值分布变化（漂移检测）。
- **一致性监控**：离线 / 在线特征一致性。

#### 4.5.2 漂移检测

- **KS 检验**：比较两个时间点的特征分布。
- **PSI（Population Stability Index）**：监控特征稳定性。
- **自动告警**：漂移 > 阈值自动告警。

### 4.6 决策 6：美团 ML 平台整体

#### 4.6.1 平台架构

```
[数据集成] → [特征平台] → [模型训练] → [模型部署] → [在线推理]
    (DataX)     (Feature    (Spark /    (PAI /      (PAI /
                 Store)      TF / Pytorch) Custom)    TF Serving)
```

#### 4.6.2 核心模块

- **DataFinder**：数据集成（美团版 DataX）。
- **Feature Store**：特征平台。
- **PAI**：模型训练与部署平台。
- **MLeap**：实验管理 + 模型版本。
- **AB 平台**：A/B 测试。
- **Serving**：在线服务。

### 4.7 决策 7：外卖配送的数据架构特殊性

#### 4.7.1 配送核心问题

- **30 分钟送达**：意味着从下单到送达 30 分钟内必须完成。
- **实时调度**：系统实时决定"哪个骑手送哪个订单"。
- **ETA 预估**：实时预估骑手到达时间。
- **路径规划**：实时规划骑手路线。

#### 4.7.2 配送数据栈

```
[订单事件] → [Kafka] → [Flink] → [实时特征] → [调度模型] → [骑手 App]
              (毫秒)    (毫秒)    (毫秒)      (毫秒)        (毫秒)
```

**端到端延迟 < 1 秒**。

#### 4.7.3 配送特征

- **骑手特征**：当前位置、当前订单数、电量、熟悉度。
- **商户特征**：当前出餐速度、订单积压。
- **用户特征**：地址准确度、历史投诉。
- **环境特征**：天气、时段、路况。

#### 4.7.4 关键技术

- **Flink CEP**：复杂事件处理（识别"骑手拥堵"、"商户积压"等异常）。
- **GIS 实时计算**：基于 Redis Geo + 自研算法计算骑手 - 商户 - 用户三方距离。
- **路径规划算法**：基于 A*、Dijkstra + 实时路况。

### 4.8 决策 8：与 OneID / 推荐 / 广告的协同

#### 4.8.1 OneID 协同

美团有"用户 OneID"——同一手机号 / 设备 ID 在外卖、到店、酒店等业务统一识别。

- **跨业务特征**：基于 OneID 关联跨业务特征（"用户在外卖 + 到店的综合画像"）。

#### 4.8.2 推荐协同

- **统一特征**：外卖推荐、酒店推荐、电影推荐共享"用户基础特征"。

#### 4.8.3 广告协同

- **CTR 预估特征**：用户历史点击 + 商户特征 + 广告特征。
- **CVR 预估特征**：用户历史转化 + 商户特征 + 商品特征。
