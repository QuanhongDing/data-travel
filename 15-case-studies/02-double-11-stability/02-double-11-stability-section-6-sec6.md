## 6. 复用经验

### 6.1 适合谁学

#### 6.1.1 任何有大促 / 高并发场景的企业

- **典型**：电商、金融、出行、游戏、社交平台。
- **原因**：高并发稳定性是普适需求。

#### 6.1.2 强实时业务

- **典型**：实时推荐、实时风控、实时调度。
- **原因**：实时 + 高并发是最大挑战。

#### 6.1.3 多端联动的复杂业务

- **典型**：跨多个子业务、跨多个客户端。
- **原因**：全链路稳定性需要。

#### 6.1.4 强监管业务

- **典型**：金融、医疗、政企。
- **原因**：稳定性 = 合规的一部分。

### 6.2 不适合谁学

#### 6.2.1 流量小的业务

- **反例**：B 端 SaaS、企业内部系统。
- **原因**：没有高并发场景，学了也没用。

#### 6.2.2 单一系统的业务

- **反例**：单一产品的 SaaS。
- **原因**：不需要全链路稳定性。

#### 6.2.3 业务尚未稳定的早期公司

- **反例**：业务模式每周变化。
- **原因**：稳定性体系需要业务稳定。

### 6.3 关键可复用资产

#### 6.3.1 容量规划

- **流量预测模型**：基于历史 + 业务目标 + 行业大盘 + 安全系数。
- **容量评估清单**：每个系统的容量评估 SOP。

#### 6.3.2 全链路压测

- **影子表 + 影子链路**：阿里 PTS 验证。
- **PTS 平台**：阿里云对外销售的商业产品。

#### 6.3.3 单元化 + 异地多活

- **路由层**：基于 ID 哈希的单元路由。
- **数据层**：单元独立数据库 + 跨单元数据同步。
- **GSLB**：基于 LBS / 运营商的流量调度。

#### 6.3.4 限流降级熔断

- **Sentinel**：阿里开源的限流熔断组件（Java 生态标准）。
- **AHAS**：阿里云商业版的 HA 服务。

#### 6.3.5 实时大屏

- **Blink + Hologres + 自研可视化**：阿里内部栈。
- **Databricks / Snowflake + Superset**：海外替代方案。

#### 6.3.6 值班机制

- **三级指挥体系**：集团总指挥 + 业务域指挥 + 系统 owner。
- **应急手册**：每个系统的应急预案。
- **沟通工具**：钉钉 / 飞书 / 企微。

### 6.4 复用清单（Checklist）

#### 6.4.1 战略层

- [ ] 是否定义了"大促稳定性 SLA"？
- [ ] 是否有"集团总指挥 + 业务域指挥 + 系统 owner"三级组织？
- [ ] 是否有"应急响应流程"（5 分钟响应 / 10 分钟预案）？

#### 6.4.2 容量层

- [ ] 是否有"容量预测模型"？
- [ ] 是否有"安全系数"（1.5x–2x）？
- [ ] 是否有"容量评估 SOP"？

#### 6.4.3 压测层

- [ ] 是否有"全链路压测平台"（PTS / 自研）？
- [ ] 是否覆盖所有核心系统？
- [ ] 是否有"压测报告"流程？

#### 6.4.4 稳定性层

- [ ] 是否有"限流"机制（Sentinel）？
- [ ] 是否有"降级"预案？
- [ ] 是否有"熔断"机制（Hystrix）？
- [ ] 是否有"混沌工程"演练？

#### 6.4.5 实时层

- [ ] 是否有"实时大屏"？
- [ ] 是否有"实时告警"？
- [ ] 是否有"实时决策"（AI 辅助）？

#### 6.4.6 组织层

- [ ] 是否有"三级指挥体系"？
- [ ] 是否有"应急手册"？
- [ ] 是否有"值班表"？
