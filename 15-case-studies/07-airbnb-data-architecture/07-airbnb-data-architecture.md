## 1. 背景

### 1.1 公司 / 业务 / 时间

Airbnb 成立于 2008 年，至今十余年。数据架构演进的关键时间节点：

- **2008–2012：起步阶段**。从 MySQL + Ruby on Rails 起步，数据栈简单。
- **2013：数据基础设施立项**。开始系统化建设数据栈。
- **2014：Airflow 立项**。Airbnb 自研工作流调度，2015 年开源。
- **2015：Minerva 立项**。开始研发指标平台。
- **2016：Minerva V1 + Dataportal V1**。
- **2017：Airbnb Data University 成立**。开始系统化培养数据文化。
- **2018：Minerva V2 + Dataportal V2**。
- **2019：Minerva 全面铺开**。Airbnb 内部所有 BI 报表基于 Minerva。
- **2020：疫情冲击 + 远程办公适应**。
- **2021：Dataportal 成为元数据核心**。
- **2022：ML Platform V3（Bighead）+ 实时数仓**。
- **2023：数据质量平台 + GenAI 应用**。
- **2024：AI Native 数据栈**。
- **2025：实时 AI + Agent 化数据**。

### 1.2 行业与监管

- **共享住宿行业**：监管复杂（许多城市对短租有严格法规）。
- **金融监管**：Airbnb 支付合规要求严格。
- **数据合规**：GDPR / CCPA / 全球多法域。
- **等保**：对外服务合规要求。

### 1.3 团队规模与组织

- **Airbnb 数据团队**约 **500+ 人**。
- **数据平台部**：约 100+ 人。
- **数据分析部**：约 200+ 人。
- **数据科学家**：约 100+ 人。
- **业务数据分析师**：约 100+ 人。
- **组织文化**：**"数据科学家 + 协作"** + **"Belong Anywhere"**（文化包容）+ **"Chinless"（去层级化）**。

## 2. 挑战

### 2.1 业务挑战

#### 2.1.1 双边市场与全球化

Airbnb 是典型的双边市场——房客 + 房东，跨 220+ 国家运营。

#### 2.1.2 业务多形态

房客住宿、Experiences（体验）、餐厅预订、长租——业务多样化。

#### 2.1.3 季节性峰值

夏季、节假日、特殊活动期间，Airbnb 流量峰值是日常的 5–10 倍。

#### 2.1.4 用户体验敏感

房客 + 房东对"信息一致性"敏感——同一房源在不同国家 / 不同时间显示必须一致。

### 2.2 技术挑战

#### 2.2.1 海量数据

- 全球 1.5 亿+ 用户。
- 700 万+ 房源。
- 日均数百万次预订。

#### 2.2.2 元数据治理难题

2015 年以前 Airbnb 内部有"指标泛滥"——"GMV"在 50 个团队有 50 种定义。

#### 2.2.3 实时数据

- 房客实时搜索。
- 房东实时定价。
- 实时推荐。

#### 2.2.4 数据质量

Airbnb 对"数据质量"要求极高——一个错误的房源价格可能让房东损失大量订单。

### 2.3 组织挑战

#### 2.3.1 数据驱动文化

Airbnb 是"数据驱动文化"的代表公司，所有决策必须基于数据。

#### 2.3.2 数据科学家协作

100+ 数据科学家需要高效协作——共享工具、共享数据、共享最佳实践。

#### 2.3.3 跨团队数据共享

Airbnb 内部有 50+ 团队需要共享数据——必须有"中央协作层"。

> 💡 **思考锚点**：翻你自己的指标资产：核心口径（比如营收 / 活跃用户）在几个团队里各有几套定义——离 Airbnb 那种「50 个团队 50 种定义」（§2.2.2）还有多远？再叠加 §2.1.3 的 5–10 倍季节峰值，你打算先收口径，还是先扛规模？
