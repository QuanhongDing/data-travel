## 4. 关键决策

### 4.1 决策 1：为什么 Minerva？

#### 4.1.1 决策路径

- **方案 A：传统 BI 工具**——Tableau / Looker。
  - 优点：成熟。
  - 缺点：指标定义分散，无法治理。
- **方案 B：自研指标平台**（Minerva）——统一指标定义。
  - 优点：指标集中、口径统一。
  - 缺点：开发成本高。
- **方案 C：商业指标平台**——如 Looker / Sisense。
  - 优点：快速。
  - 缺点：定制化能力弱。

**决策**：自研 Minerva。

#### 4.1.2 Minerva 核心

```
[指标定义] → [OLAP 引擎] → [BI / API]
   (元数据)   (Presto /      (消费)
              Druid)
```

- **指标定义**：每个指标有"业务定义 + 计算逻辑 + 数据来源 + Owner + 版本"。
- **指标分类**：
  - 原子指标（不可拆分）。
  - 派生指标（基于原子指标计算）。
  - 复合指标（多个原子指标组合）。
- **指标血缘**：从指标可以追溯到 Hive 表。

#### 4.1.3 Minerva 价值

- **统一口径**：所有指标有唯一来源。
- **自助分析**：业务分析师可以自助使用指标。
- **变更追溯**：指标变更可追溯。

### 4.2 决策 2：为什么 Dataportal？

#### 4.2.1 Dataportal 定位

Dataportal 是 Airbnb 的元数据管理平台，是 Minerva / 数据地图 / 数据血缘的核心。

#### 4.2.2 核心能力

- **数据目录**：所有数据资产注册到 Dataportal。
- **数据血缘**：从 Hive 表到指标的可视化血缘。
- **数据 Owner**：每个数据集有 Owner。
- **数据 SLA**：每个数据集有 SLA。
- **数据质量**：集成数据质量监控。

#### 4.2.3 Dataportal 架构

```
[数据资产] → [Dataportal 注册] → [统一目录] → [业务使用]
   (Hive)     (元数据采集)        (可视化)     (消费)
```

#### 4.2.4 Dataportal 价值

- **数据可发现**：分析师可以快速找到需要的数据。
- **数据可治理**：数据 Owner 明确，治理有抓手。
- **数据可信任**：基于血缘 + 质量，数据可信任。

### 4.3 决策 3：ER 模型与维度建模

#### 4.3.1 ER 模型

Airbnb 使用 ER 模型定义业务实体：

- **核心实体**：用户 / 房源 / 预订 / 房东 / 评论。
- **实体关系**：用户 - 预订 - 房源、房东 - 房源、用户 - 评论。

#### 4.3.2 维度建模

基于 ER 模型构建维度模型：

- **DWD 层**：基于 ER 实体的明细数据。
- **DWS 层**：基于主题域的聚合数据。
- **ADS 层**：基于业务场景的应用数据。

#### 4.3.3 关键经验

- **ER 模型必须稳定**——核心实体（如用户、房源）的定义不能频繁变化。
- **维度建模必须灵活**——支持业务快速变化。
- **ER 与维度模型必须联动**——ER 是"骨架"，维度模型是"肌肉"。

### 4.4 决策 4：实时数据架构

#### 4.4.1 实时场景

- 实时搜索。
- 实时定价。
- 实时推荐。
- 实时反欺诈。

#### 4.4.2 实时架构

```
[业务事件] → [Kafka] → [Flink / Spark Streaming] → [Hive / Druid] → [在线服务]
```

#### 4.4.3 关键技术

- **Kafka**：事件流。
- **Flink / Spark Streaming**：实时计算。
- **Druid**：实时 OLAP。
- **Iceberg**：表格式（2022 后）。

### 4.5 决策 5：ML Platform（Bighead）

#### 4.5.1 Bighead 架构

```
[数据] → [特征] → [训练] → [部署] → [推理]
```

#### 4.5.2 核心模块

- **Deep Learning**：基于 TensorFlow / PyTorch。
- **Classical ML**：基于 Spark MLlib / scikit-learn。
- **Feature Store**：基于 Hive + Redis。
- **Model Serving**：基于 Kubernetes。
- **Notebook**：基于 Jupyter + 内部工具。

#### 4.5.3 Bighead 应用

- **搜索**：实时搜索排序。
- **推荐**：房源推荐。
- **定价**：智能定价。
- **反欺诈**：实时反欺诈。

### 4.6 决策 6：数据质量保障

#### 4.6.1 数据质量维度

- **准确性**：数据值是否正确。
- **完整性**：数据是否缺失。
- **一致性**：数据是否一致。
- **及时性**：数据是否及时。
- **唯一性**：数据是否重复。

#### 4.6.2 数据质量工具

- **断言（Assertions）**：每个数据集有断言规则。
- **监控**：实时监控 + 告警。
- **修复**：自动 / 人工修复。

#### 4.6.3 数据质量流程

- **事前**：数据进入前校验。
- **事中**：数据处理中校验。
- **事后**：数据入库后校验。

### 4.7 决策 7：Airflow 调度

#### 4.7.1 Airflow 核心

```
[DAG] = [Tasks] + [依赖关系] + [调度规则]
```

#### 4.7.2 Airflow 价值

- **Python 优先**：用 Python 写 DAG，开发效率高。
- **可扩展**：Operator 机制支持各种数据源。
- **可视化**：Web UI 可视化。
- **社区**：Apache 大社区。

#### 4.7.3 Airbnb 使用 Airflow 的演进

- 2014：内部版本（Airbnb 自研）。
- 2015：开源，捐给 Apache 基金会。
- 2016+：成为 Apache 顶级项目。
- 2024：Airflow 是业界最流行的调度系统之一。
